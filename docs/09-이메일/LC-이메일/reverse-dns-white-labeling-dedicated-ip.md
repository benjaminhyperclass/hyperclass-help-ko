# 전용 IP의 역방향 DNS(rDNS) 화이트라벨 설정

받는 사람의 메일함에 제3자 서비스 이름 대신 회사 이름이 발신자로 보이게 하는 방법이에요. 전용 IP에 역방향 DNS(rDNS)를 설정하면 이메일 전달률과 신뢰도, 브랜드 일관성을 높일 수 있어요. 이 설정은 **에이전시 설정**에서 하기 때문에 에이전시 관리자만 할 수 있어요.

## 개요

받는 사람이 이메일을 열었을 때 "보낸 사람" 또는 "발신자" 항목에 "Sent by Mailgun" 같은 제3자 서비스 이름이 보이면 신뢰하기 어려워요. 회사 이름이 보이면 훨씬 전문적이고 믿음이 가요. 전용 IP에 역방향 DNS(rDNS)를 설정하면 회사 이름이 보이게 할 수 있어요.

rDNS를 올바르게 설정하면 이메일 전달률이 좋아지고 스팸으로 분류될 가능성이 줄어요. 발송하는 모든 캠페인에서 브랜드도 일관되게 유지돼요.

## 역방향 DNS(rDNS)란?

역방향 DNS는 일반적인 DNS 조회와 반대로 동작해요. 일반 DNS는 도메인 이름을 IP 주소에 연결하지만, rDNS는 IP 주소를 그 IP와 연결된 호스트 이름으로 바꿔요. IPv4와 IPv6 주소 모두에서 쓸 수 있고, 이메일을 보내는 서버가 진짜인지 확인하는 데 사용해요.

실제로는 발송 메일 서버의 IP 주소를 호스트 이름(예: mail.yourcompany.com)으로 바꿔 줘요. 메일함 제공업체는 이 조회로 해당 IP가 정상적인 도메인의 것인지 확인해요. 그래서 받는 사람의 받은편지함에 "Sent by Mailgun.com" 대신 회사 이름이 발신자로 보여요.

{% hint style="warning" %}
**꼭 구분하세요**

전용 IP의 rDNS 설정은 DNS 설정에서 mailgun.org의 CNAME을 가리는 작업과 다릅니다. 두 가지는 서로 다른 설정이에요. rDNS는 메일함 제공업체가 발송 IP 주소를 조회할 때 어떤 호스트 이름이 보일지를 정해요.
{% endhint %}

{% hint style="info" %}
**설정하면 좋은 점**

rDNS를 올바르게 설정하면 회사 이름이 발신자로 표시되고, 받은편지함 도달률이 좋아지고, 받는 사람의 신뢰도 쌓여요. 받는 사람에게는 뒤에서 쓰이는 발송 인프라가 보이지 않아요.
{% endhint %}

## rDNS 설정 시 흔한 실수

rDNS를 정확하게 설정하는 것은 이메일 전달률과 발신자 평판에 중요해요. 특히 자주 하는 실수 세 가지를 알아 두세요.

### 실수 1. PTR 레코드가 잘못되었거나 없는 경우

PTR(Pointer) 레코드는 발송 메일 서버가 이메일에 표시된 IP 주소와 일치하는지 확인하는 데 필요해요. 올바른 PTR 레코드가 없으면 메일함 제공업체가 발신자를 확인할 수 없어요. PTR 레코드를 올바르게 설정하고, 조회한 IP에 대해 유효한 호스트 이름이 반환되는지 확인하세요.

### 실수 2. 호스트 이름이 일치하지 않는 경우(Forward-Confirmed rDNS 실패)

PTR 레코드가 반환한 호스트 이름을 조회하면 같은 IP 주소가 나와야 하고, 반대 방향도 마찬가지예요. 이렇게 양방향으로 확인하는 것을 Forward-Confirmed Reverse DNS(FCrDNS)라고 해요. 두 방향이 맞지 않으면 조회가 실패하고 신뢰도가 떨어져요.

**예시:** IP 8.8.8.8에 대해 PTR 레코드가 mail.yourwebsite.com을 반환한다면, mail.yourwebsite.com을 정방향으로 조회했을 때도 8.8.8.8이 나와야 해요.

### 실수 3. 호스트 이름이 IP로 확인되지 않는 경우

PTR 레코드의 호스트 이름이 어떤 IP로도 확인되지 않으면 메일함 제공업체가 심각한 신뢰 문제로 판단해요. 그러면 전달에 실패할 수 있어요. rDNS용 호스트 이름을 제출하기 전에 A 레코드가 제대로 게시되었는지 꼭 확인하세요.

{% hint style="info" %}
**핵심 정리**

PTR 레코드는 유효한 호스트 이름을 가리켜야 하고, 그 호스트 이름의 A 레코드는 같은 IP로 확인되어야 해요. 양방향이 모두 일치하고 조회되어야 해요.
{% endhint %}

## rDNS 설정 방법

{% hint style="warning" %}
**전용 IP가 필요해요**

rDNS는 전용 IP에서만 설정할 수 있어요. rDNS는 IP 주소 하나당 호스트 이름 하나로만 확인되기 때문에 공유 IP에서는 지원하지 않아요. 이 설정에는 전용 IP가 꼭 필요해요.
{% endhint %}

다음 단계를 따라 전용 IP에 rDNS를 설정하세요.

### 1단계. 호스팅 업체에서 A 레코드 추가하기

DNS 호스팅 업체에 로그인해서, 사용할 호스트 이름이 전용 IP 주소를 가리키는 A 레코드를 추가하세요. 레코드 형식은 다음과 같아요.

```
A    mail.yourcomain.com    123.45.67.89
```

### 2단계. 에이전시 설정으로 이동하기

1. **에이전시 설정 > 이메일 서비스**로 이동하세요.

### 3단계. 전용 도메인 및 IP 열기

1. **SMTP 서비스** 탭의 하이퍼클래스 섹션에서 **Dedicated Domain And IP**(전용 도메인 및 IP)를 클릭하세요.

![SMTP 서비스 탭에서 전용 도메인 및 IP 버튼이 보이는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155009612052/original/IUIljk9XIJS27U3BT_o4jUzNTpWR7LasGg.png?1696855911)

하이퍼클래스 SMTP 섹션에서 Dedicated Domain And IP를 클릭하세요.

### 4단계. 역방향 DNS(PTR) 설정 열기

1. **전용 IP** 섹션에서 사용할 전용 IP 옆의 점 세 개 메뉴를 클릭하세요.
2. **Reverse DNS (PTR)**(역방향 DNS(PTR))를 선택하세요.

![전용 IP의 점 세 개 메뉴에서 Reverse DNS (PTR) 항목이 보이는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155009612160/original/cwkp94jqGl-jc1vsViWXa2bvRMaphEwmkw.png?1696855977)

전용 IP의 점 세 개 메뉴에서 Reverse DNS (PTR)를 선택하세요.

### 5단계. A 레코드의 호스트 이름 입력하기

1. A 레코드에 사용한 호스트 이름(예: mail.yourcompany.com)을 똑같이 입력하세요. 입력한 호스트 이름을 가리키도록 PTR 레코드가 내부적으로 업데이트돼요.

![호스트 이름 입력란이 있는 Reverse DNS (PTR) 설정 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155009613038/original/Oge0tXLX2gyJh_WWlLh5Xdb0TiEVuC-AJA.png?1696856251)

A 레코드와 같은 호스트 이름을 입력하면 PTR 설정이 끝나요.

### 설정 완료

PTR 레코드가 업데이트되면 전용 IP가 설정한 호스트 이름으로 확인돼요. 이제 메일함 제공업체에는 제3자 서비스 이름 대신 회사 이름이 발신자로 표시돼요.

## 자주 묻는 질문

### 공유 IP에도 rDNS를 설정할 수 있나요?

아니요. rDNS는 IP 주소 하나당 호스트 이름 하나로만 확인되기 때문에 전용 IP에서만 지원해요. 공유 IP는 여러 발신자가 함께 쓰므로 내 도메인의 호스트 이름만 따로 지정할 수 없어요.

### PTR 레코드가 무엇이고, 왜 중요한가요?

PTR(Pointer) 레코드는 IP 주소를 다시 호스트 이름에 연결하는 레코드예요. 메일함 제공업체는 이 레코드로 이메일을 보낸 서버가 자신이 밝힌 서버가 맞는지 확인해요. PTR 레코드가 없거나 잘못되면 이메일이 거부되거나 스팸으로 분류되는 경우가 많아요.

### rDNS를 설정하면 DKIM이나 SPF 인증은 하지 않아도 되나요?

아니요. rDNS, DKIM, SPF는 각각 목적이 다르고 서로 보완해요. DKIM은 이메일 내용에 서명하고, SPF는 발송을 허용할 IP를 지정하고, rDNS는 발송 서버 IP의 신원을 확인해요. 전달률을 최대한 높이려면 세 가지를 모두 올바르게 설정하세요.

### rDNS 변경 사항이 적용되는 데 시간이 얼마나 걸리나요?

PTR 레코드의 내부 업데이트는 보통 빠르게 반영돼요. 다만 DNS 전파는 TTL 설정과 리졸버가 레코드를 캐시하는 주기에 따라 몇 분에서 최대 48시간까지 걸릴 수 있어요.

### rDNS가 제대로 설정되었는지 어떻게 확인하나요?

MXToolbox 같은 도구나 명령줄(nslookup / dig -x)로 전용 IP의 역방향 DNS를 조회해 보세요. 설정한 호스트 이름이 결과로 나와야 해요. 그다음 그 호스트 이름을 정방향으로 조회했을 때 내 IP가 나오는지도 확인하세요.

### rDNS를 설정하면 받는 사람에게 이메일이 다르게 보이나요?

네. rDNS를 올바르게 설정하면 "발신자" 항목이나 기술 헤더에 제3자 서비스 제공업체 이름 대신 회사 이름이나 도메인이 표시돼요. 그러면 발신자를 더 믿을 수 있게 되고 브랜드도 더 잘 알려져요. 특히 발송 서버 정보를 보여 주는 메일 클라이언트에서 그래요.

### 아무 호스트 이름이나 써도 되나요, 아니면 발송 도메인과 같아야 하나요?

호스트 이름이 "보낸 사람" 도메인과 완전히 같을 필요는 없어요. 하지만 내가 소유하고 관리하며 IP로 완전히 확인되는 유효한 호스트 이름이어야 해요. 일관성과 신뢰를 위해 주 발송 도메인의 서브도메인(예: mail.yourcompany.com)을 쓰는 것이 좋아요.
