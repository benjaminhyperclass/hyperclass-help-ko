# 여러 이메일 발송 문제가 겹쳤을 때 복구하는 방법

평판, 인증, 콘텐츠 문제가 한꺼번에 겹쳐 이메일이 막힐 때 쓰는 단계별 복구 가이드예요. 어떤 문제부터 풀어야 하는지 우선순위와 일정을 함께 안내해요.

## 무슨 일이 일어나고 있나요?

지금 여러 가지 이메일 발송 문제가 동시에 생겨서, 여러 요인이 함께 작용해 이메일을 막고 있어요. 이메일 발송의 기반이 되는 인프라 문제가 시간이 지나면서 쌓이면 이런 일이 생기곤 해요. 그 결과 발신자 평판 저하, 인증 실패, 콘텐츠로 인한 차단이 한꺼번에 나타나요.

## 빠른 진단: 여러 문제가 겹쳤는지 확인하기

### 자주 보이는 바운스 메시지 조합

- 서로 다른 문제가 여러 개 나타나요: 수신자별 발송 제한, 낮은 도메인 평판, 스팸처럼 보이는 콘텐츠, PTR 누락, DMARC/인증 실패

## 여러 발송 문제를 이해하기

### 핵심 개념

- 문제가 여러 개면 서로 영향을 주어 각각이 다른 문제를 더 나쁘게 만들어요.
- 올바른 우선순위 순서로 문제를 해결해야 복구할 수 있어요.
- 어떤 조치는 먼저 끝내야 다른 조치가 효과를 내요.
- 문제가 여러 개일수록 복구 기간이 훨씬 길어져요.
- 문제를 끝까지 해결하지 않고 일부만 고치면 전체 평판이 더 나빠질 수 있어요.

### 문제 유형과 우선순위

인프라 문제 — 가장 높은 우선순위

- PTR 레코드가 없거나 잘못됨
- DMARC 인증 실패
- SPF, DKIM 설정 오류

평판 문제 — 높은 우선순위

- 낮은 도메인 평판 점수
- IP 평판 문제
- 스팸 신고로 인한 수신자별 발송 제한

콘텐츠 문제 — 중간 우선순위

- 스팸처럼 보이는 콘텐츠 패턴
- 스팸 유발 단어와 문구
- 맞지 않는 텍스트와 이미지 비율

## 단계별 해결 방법

### 1단계 · 1주차 — 인프라 기반 다지기

우선순위 순서대로 진행하고, 아래 작업을 모두 마친 뒤에 2단계로 넘어가세요.

1. 인증 문제 고치기
   - **설정 > 이메일 서비스 > Sending Domain & IP**(발신 도메인 및 IP)로 이동해요.
   - 모든 DNS 레코드의 상태가 "인증됨"으로 나오는지 확인해요.
   - "대기 중" 또는 "실패"로 나오는 레코드가 있으면 DNS 제공업체에서 해당 레코드를 수정해요.
   - DNS 전파까지 24~48시간 기다려요.
2. PTR 레코드 설정하기
   - 호스팅 업체나 IT 담당자에게 문의해요.
   - 발송 IP에 PTR 레코드를 설정해 달라고 요청해요.
   - MXToolbox의 PTR 조회 도구로 설정이 맞는지 확인해요.
3. DMARC 정책 설정하기
   - DNS에 다음 DMARC 레코드를 추가해요: `v=DMARC1; p=quarantine; rua=mailto:dmarc@yourdomain.com`
   - DMARC 리포트에서 인증 실패가 있는지 살펴봐요.

인프라가 해결됐다는 신호

- 모든 DNS 레코드의 상태가 "인증됨"으로 나와요.
- MXToolbox에서 PTR 레코드가 올바르게 조회돼요.
- DMARC 리포트에서 인증이 통과로 나와요.
- "authentication failure" 바운스 메시지가 더 이상 오지 않아요.

### 2단계 · 2주차 — 콘텐츠 최적화

1. 이메일 템플릿 점검하기
   - **마케팅 > 이메일 템플릿**으로 이동해요.
   - 사용 중인 모든 템플릿에서 스팸 유발 단어가 있는지 검토해요.
   - 과도한 대문자와 여러 개의 느낌표를 없애요.
   - 텍스트와 이미지 비율을 알맞게 맞춰요(텍스트 80%, 이미지 20%).
2. 콘텐츠 품질 테스트하기
   - Mail-Tester.com으로 이메일 점수를 확인해요.
   - 10점 만점에 8점을 넘기는 것을 목표로 해요.
   - 지적된 콘텐츠 문제를 모두 고쳐요.

### 3단계 · 3~8주차 — 평판 회복

1. 발송량을 천천히 늘리기
   - 참여도가 가장 높은 연락처에게 하루 50~100통부터 보내요.
   - 발송 성공률이 좋아질 때만 매주 25%씩 늘려요.
   - 바운스율과 스팸 신고를 면밀히 지켜봐요.
2. 평판 지표 확인하기
   - senderscore.org에서 Sender Score를 매주 확인해요.
   - Talos Intelligence의 평판을 확인해요.
   - MXToolbox 블랙리스트 모니터링을 사용해요.

### 4단계 · 계속 — 목록 정리와 재참여 유도

1. 목록 나누기
   - **연락처 > 스마트 리스트**로 이동해요.
   - 참여 수준에 따라 세그먼트를 만들어요.
   - 처음에는 참여도가 높은 연락처에게만 보내요.
2. 문제가 있는 연락처 정리하기
   - 바운스나 스팸 신고가 여러 번 있었던 연락처를 찾아요.
   - 이런 연락처는 캠페인에서 제거하거나 발송 대상에서 제외해요.
   - 새 구독자에게는 이중 수신 동의(double opt-in)를 적용해요.

## 복구 일정과 기대 결과

| 단계 | 작업 | 기대 결과 | 성공 기준 |
| --- | --- | --- | --- |
| 1단계: 인프라(1~2주차) | 인증과 DNS 문제를 모두 해결 | 인증 관련 바운스가 사라짐 | 모든 DNS 레코드 인증 완료 |
| 2단계: 콘텐츠 및 초기 복구(3~4주차) | 콘텐츠 정리와 소량 발송 테스트 | 콘텐츠로 인한 차단 감소 | Mail-Tester 점수 8/10 초과 |
| 3단계: 평판 쌓기(5~12주차) | 참여도 높은 연락처 중심으로 발송량을 천천히 늘림 | 발송 성공률이 꾸준히 개선됨 | Sender Score 80 초과, 발송 성공률 95% 초과 |
| 4단계: 완전 복구(13~16주차) | 평소 발송량으로 복귀 | 높은 발송 성공률이 일정하게 유지됨 | 98% 이상의 발송 성공률 유지 |

## 복구 중 꼭 챙겨야 할 모니터링

### 처음 4주: 매일 확인하기

- **분석**: 바운스율과 발송 통계를 확인해요.
- 바운스 메시지 분석: 바운스 사유를 분류하고 사유가 어떻게 바뀌는지 기록해요.
- 신고 모니터링: 스팸 신고가 늘어나는지 지켜봐요.

### 이후: 매주 확인하기

- Sender Score: 평판 점수가 좋아지고 있는지 추적해요.
- 블랙리스트 상태: 주요 블랙리스트 데이터베이스를 확인해요.
- DMARC 리포트: 인증 성공률을 검토해요.

## 주의해야 할 신호

{% hint style="warning" %}
다음 중 하나라도 보이면 즉시 발송을 멈추세요.

- 이틀 연속 바운스율이 5%를 넘어요.
- 새로운 블랙리스트 등재가 나타나요.
- 스팸 신고율이 0.1%를 넘어요.
- Sender Score가 현재 수준 아래로 떨어져요.
- 주요 ISP가 일시적으로 수신을 지연시켜요.

## 그래도 문제가 해결되지 않나요?

이 방법을 차례대로 따랐는데도 여러 발송 문제가 계속되면 다음을 해 보세요.

1. 모든 내용 기록하기: 바운스 메시지, 평판 점수, 지금까지 한 조치를 자세히 기록해 두세요.
2. 전문가 진단 고려하기: 문제가 여러 개일 때는 숨은 원인을 찾으려면 전문가의 분석이 필요한 경우가 많아요.
3. 인프라 점검하기: 상황에 따라 전용 IP나 고급 설정이 필요할 수 있어요.

## 자주 묻는 질문

### 우선순위 순서를 따르지 않고 여러 문제를 한꺼번에 고쳐도 되나요?
한꺼번에 모두 고치려다 복구가 멈추는 경우가 가장 많아요. 밑바탕의 인증이 여전히 깨져 있으면 콘텐츠와 평판을 고쳐도 효과가 오래가지 않아요. 그래서 인프라 문제를 먼저 해결해야 해요.

### 어떤 문제가 가장 큰 피해를 주는지 어떻게 알 수 있나요?
바운스 메시지부터 확인하세요. 인증 실패(SPF, DKIM, DMARC, PTR 누락)는 콘텐츠나 평판이 아무리 좋아도 발송을 아예 막을 수 있어서, 거의 항상 가장 먼저 고쳐야 해요.

### 새 발송 IP로 바꾸면 더 빨리 해결되나요?
그것만으로는 해결되지 않아요. 새 IP는 평판이 전혀 없어서 처음부터 많은 양을 보내면 새로운 문제가 생길 수 있어요. 인증, 콘텐츠, 목록 정리를 먼저 하지 않고 건너뛰는 지름길이 되기는 어려워요.

### 4주가 지나도 Sender Score가 오르지 않으면 어떻게 하나요?
1단계의 인프라 조치가 모두 제출만 된 것이 아니라 실제로 인증까지 됐는지 다시 확인하세요. 레코드 하나만 잘못돼 있어도 전체 복구가 멈출 수 있어요. 모두 문제가 없다면 전문가 진단을 받아 볼 때예요.

### 복구하는 동안 모든 발송을 멈춰야 하나요?
전부 멈추지는 않아도 돼요. 인프라를 고치는 동안 대량 캠페인은 멈추는 편이 좋아요. 하지만 참여도가 높은 연락처에게 소량으로 조절해서 보내는 일은 3단계에서 평판을 다시 쌓는 과정의 일부예요.

### 여러 문제에서 복구하려면 전용 IP가 꼭 필요한가요?
항상 필요한 건 아니에요. 인증, 콘텐츠, 목록 정리를 해결하면 공유 인프라나 지금 쓰는 전용 인프라에서도 해결되는 경우가 많아요. 전용 IP는 발송량이 많고 꾸준할 때 주로 고려할 만해요.
