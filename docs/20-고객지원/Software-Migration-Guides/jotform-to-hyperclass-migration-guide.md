# JotForm에서 하이퍼클래스로 옮기기 (마이그레이션 가이드)

JotForm에서 쓰던 폼, 데이터, 워크플로우를 하이퍼클래스로 옮기는 순서를 안내해요. 업무가 끊기지 않게 옮기면서, 하이퍼클래스에 통합된 마케팅·CRM 기능을 충분히 활용하는 것이 목표예요.

## 마이그레이션 준비

### 1단계: 현재 JotForm 설정 살펴보기

- 주요 폼과 데이터 파악: JotForm에서 사용 중인 폼을 모두 나열해요. 제출 내역, 이메일 알림, 연동처럼 폼에 딸린 데이터도 함께 적어요.
- 폼 워크플로우 기록: 각 폼이 현재 워크플로우, 이메일 알림, 외부 서비스 연동과 어떻게 연결되는지 기록해요.
- 데이터 양 확인: 옮길 데이터(폼 제출, 연락처 정보 등)가 얼마나 되는지 확인해요.

### 2단계: 마이그레이션 목표 정하기

- 목표 구체화: 하이퍼클래스로 옮겨서 얻고 싶은 결과를 정해요. 예를 들어 자동화 강화, CRM 도구와의 연계 개선, 비용 절감이 있어요.
- 우선순위 정하기: 먼저 옮겨야 할 가장 중요한 폼과 데이터를 정해요.

### 3단계: 백업 준비하기

- JotForm 데이터 내보내기: 폼 제출, 템플릿, 설정 등 필요한 데이터를 모두 JotForm에서 내보내요.
- 데이터 백업: 마이그레이션을 시작하기 전에 모든 데이터를 안전하게 백업해 두세요.

## 데이터 옮기기

### 1단계: JotForm에서 데이터 내보내기

- 폼 제출 내보내기: JotForm에서 각 폼으로 이동해 폼 제출 내역을 선택하고 CSV 파일로 내보내요.
- 폼 템플릿 저장: 하이퍼클래스에서 폼을 다시 만들 때 참고할 수 있도록 JotForm 템플릿을 복사해 저장해 두세요.

### 2단계: 하이퍼클래스로 데이터 가져오기

- 하이퍼클래스에서 폼 다시 만들기:
  - 하이퍼클래스에서 **사이트 > 폼**으로 이동해요.
    - 폼 빌더로 폼을 다시 만들어요. 이때 JotForm의 모든 필드와 같게 구성하세요.
- 연락처 가져오기: JotForm에 저장된 연락처 정보가 있다면 **연락처 > Import Contacts**(연락처 가져오기)로 이동해 CSV 파일을 올려서 하이퍼클래스로 가져와요.
- 커스텀 필드 설정: JotForm에서 수집하던 데이터에 맞춰, 하이퍼클래스에서 필요한 커스텀 필드를 만들어요.

## 폼과 워크플로우 옮기기

### 1단계: 기존 JotForm 워크플로우 검토하기

- 사용 중인 워크플로우 정리: JotForm에서 폼 제출로 실행되는 워크플로우를 모두 찾아 기록해요. 이메일 알림, 데이터 전달, 다른 도구와의 연동이 여기에 포함돼요.
- 복잡도 평가: 각 워크플로우가 얼마나 복잡한지 살펴보고, 하이퍼클래스에서 어떻게 재현할지 정해요.

### 2단계: 하이퍼클래스에서 워크플로우 다시 만들기

- 자동화 트리거 만들기:
  - 하이퍼클래스에서 **자동화 > 워크플로우**로 이동해요.
  - 폼 제출마다 트리거를 설정해서 JotForm 워크플로우의 로직을 그대로 재현해요. 예를 들면 알림 보내기, 연락처 정보 업데이트가 있어요.
- 액션과 조건 다시 만들기:
  - 확인 이메일 보내기, 연락처에 태그 추가하기, CRM 정보 업데이트하기 같은 액션을 다시 만들어요.
  - 기존 워크플로우와 같게 동작하도록 필요한 조건이나 분기 로직도 설정해요.

### 3단계: 워크플로우 테스트하기

- 테스트 실행: 워크플로우를 활성화하기 전에, 의도한 대로 동작하는지 꼼꼼히 테스트해요.
- 설정 조정: 테스트 결과에 따라 필요한 부분을 고쳐서 문제없이 동작하게 해요.

## 연동과 알림 옮기기

### 1단계: 하이퍼클래스에서 연동 다시 설정하기

- 필요한 연동 파악: JotForm과 연결해 쓰던 외부 도구를 확인해요. 예를 들어 결제 게이트웨이, 이메일 마케팅 도구, 다른 CRM이 있어요.
- 하이퍼클래스에서 연동 설정:
  - 하이퍼클래스에 기본 제공되는 연동이나 Zapier로 외부 애플리케이션과 연결해요.
  - **설정 > 연동**으로 이동해 필요한 연결을 설정해요.

### 2단계: 이메일 알림 다시 설정하기

- 내부 알림 설정:
  - 하이퍼클래스에서 **자동화 > 워크플로우**로 이동해, 폼이 제출될 때 보낼 내부 알림을 설정해요.
- 자동 응답 설정: JotForm에서 자동 응답을 썼다면, 폼 제출 시 실행되는 자동 이메일 시퀀스를 만들어 하이퍼클래스에서 똑같이 설정해요.

## 최종 점검과 교육

### 1단계: 데이터 최종 검증하기

- 데이터 교차 확인: 모든 데이터가 제대로 옮겨졌는지, JotForm과 하이퍼클래스의 기록이 서로 어긋나지 않는지 확인해요.
- 폼과 워크플로우 검증: 하이퍼클래스에서 모든 폼과 워크플로우가 정상적으로 동작하는지 확인해요.

### 2단계: 팀원 교육하기

- 하이퍼클래스 교육: 팀원에게 하이퍼클래스의 폼 빌더와 자동화 도구 사용법을 알려 주세요. JotForm과 다른 점을 중심으로 설명하면 좋아요.
- 하이퍼클래스 고객지원 활용: 팀원이 하이퍼클래스 고객지원 자료와 커뮤니티 포럼을 활용해 꾸준히 배우도록 안내해요.

### 3단계: 모니터링하고 개선하기

- 성과 모니터링: 하이퍼클래스에서 새로 구성한 설정의 성과를 확인하고, 필요하면 조정해요.
- 지속적인 개선: 폼, 워크플로우, 연동이 비즈니스 목표에 맞는지 정기적으로 점검하고 다듬어요.

## JotForm 정리하기

### 1단계: 전환 기간 두기

- 병행 운영: 전환하는 동안 JotForm과 하이퍼클래스를 함께 운영해서 놓치는 핵심 업무가 없도록 하는 방법을 고려해 보세요.
- 단계적 종료: 하이퍼클래스가 완전히 자리 잡으면 JotForm 의존도를 조금씩 줄여요.

### 2단계: JotForm 구독 해지하기

- 최종 데이터 백업: JotForm 구독을 해지하기 전에 모든 데이터가 안전하게 백업되었는지 확인해요.
- 공식 해지 절차 진행: JotForm의 절차에 따라 구독을 해지하고 서비스를 종료해요.

### 3단계: 마이그레이션 후 검토하기

- 성과 검토: 마이그레이션이 얼마나 잘 되었는지 평가하고, 배운 점을 기록해 두세요.
- 지속적인 모니터링: 마이그레이션이 끝난 뒤에도 문제가 생기지 않는지 계속 살펴봐요.
