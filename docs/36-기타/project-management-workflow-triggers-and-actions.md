# 프로젝트 관리 워크플로우 — Task Added(작업 추가됨)·Task Completed(작업 완료됨)·Task Reminder(작업 알림) 트리거와 Add Task(작업 추가) 액션

하이퍼클래스에서는 워크플로우 트리거와 액션으로 **프로젝트 관리**의 작업을 자동화할 수 있어요. 작업이 추가되거나 완료될 때 워크플로우를 시작하고, 알림을 예약하고, 필요한 정보가 담긴 작업을 자동으로 만들 수 있어요. 이 문서에서는 각 기능이 어떻게 동작하는지, 워크플로우 빌더에서 어떻게 설정하는지 알려 드려요.

{% hint style="info" %}
문서에 나온 금액(달러)과 요금제 이름은 참고용이에요. 하이퍼클래스에서 실제로 적용되는 요금은 [요금제 안내](../00-자주묻는질문/pricing-plans.md)와 [AI·SMS·음성 사용료](../00-자주묻는질문/usage-costs.md)를 확인하세요.
{% endhint %}

{% hint style="info" %}
프로젝트 관리는 이제 $497 플랜을 쓰는 에이전시에서 사용할 수 있어요. 켜려면 에이전시 설정 또는 **서브 계정 설정**에서 **실험실**로 이동한 뒤 **프로젝트 관리**를 켜세요.
{% endhint %}

## 프로젝트 관리 워크플로우 트리거와 액션이란?

프로젝트 관리 워크플로우 트리거와 액션은 작업과 관련된 업무를 자동화해 줘요.

트리거는 특정 이벤트가 일어날 때 워크플로우를 시작해요. 액션은 워크플로우가 시작된 뒤 어떤 일을 실행해요.

예를 들어 디자인 작업이 완료되면 워크플로우가 개발 작업을 자동으로 만들고, 팀원에게 할당하고, 마감일까지 정해 줄 수 있어요.

하이퍼클래스는 다음 프로젝트 관리 워크플로우 기능을 지원해요.

| 유형 | 기능 | 용도 |
| --- | --- | --- |
| 트리거 | **Task Added**(작업 추가됨) | 작업이 만들어지면 시작해요 |
| 트리거 | **Task Completed**(작업 완료됨) | 작업이 완료되면 시작해요 |
| 트리거 | **Task Reminder**(작업 알림) | 작업과 관련된 날짜 전이나 후에 시작해요 |
| 액션 | **Add Task**(작업 추가) | 작업을 자동으로 만들어요 |

사용 가능 여부: 프로젝트 관리는 현재 비공개 베타예요. 서브 계정에서 워크플로우 기능을 사용할 수 있어야 해요.

---

## 프로젝트 관리 워크플로우 자동화의 장점

이 기능을 쓰면 작업을 일일이 관리하는 수고가 줄고, 팀이 일관된 절차를 따르기 쉬워져요.

- 작업 자동 생성: 특정 이벤트가 일어나면 후속 작업을 만들어요.
- 맞춤 자동화: 필터를 써서 조건에 맞는 작업에만 워크플로우를 실행해요.
- 알맞은 시점의 알림: 중요한 작업 날짜를 기준으로 워크플로우를 예약해요.
- 유연한 할당: 특정 사용자에게 할당하거나 동적 값을 사용해요.
- 일관된 작업 정보: 우선순위, 상태, 날짜, 설명, 커스텀 필드를 자동으로 채워요.
- 정돈된 작업 관리: 알맞은 **Space**(스페이스), **Folder**(폴더), **List**(목록)에 작업을 만들어요.

## Task Added와 Task Completed 트리거

이 트리거는 작업이 만들어지거나 완료될 때 워크플로우를 시작해요. 어떤 작업이 해당하는지는 필터로 정해요.

**Task Added**

새 작업이 선택한 조건과 맞으면 워크플로우를 시작해요.

예: 웹사이트 디자인 List에 우선순위가 높은 작업이 추가되면 워크플로우를 시작해요.

**Task Completed**

작업이 완료되고 선택한 조건과 맞으면 워크플로우를 시작해요.

예: 디자인 작업이 완료되면 개발 작업을 만들어요.

**Status** 필터를 쓰면 특정 완료 상태의 작업만 골라낼 수 있어요.

## Task Reminder 트리거

**Task Reminder** 트리거는 선택한 작업 날짜의 전이나 후에 워크플로우를 실행해요. 알림과 후속 업무를 자동화할 때 유용해요.

다음 기준으로 알림을 예약할 수 있어요.

- **Due Date**(마감일): 작업을 끝내야 하는 날짜예요.
- **Start Date**(시작일): 작업을 시작하기로 한 날짜예요.
- **Custom Date Field**(커스텀 날짜 필드): 작업의 커스텀 필드에 저장된 날짜예요.

선택한 날짜의 며칠 전 또는 며칠 후에 워크플로우를 실행할지 정해요.

상태, 담당자, 우선순위, 이름으로 작업을 걸러 낼 수도 있어요.

예를 들어 이미 완료된 작업은 제외하고, 우선순위가 높은 작업의 마감일 하루 전에 알림을 보내는 워크플로우를 만들 수 있어요.

## 워크플로우 트리거 필터

필터는 어떤 프로젝트 관리 작업이 워크플로우를 시작할 수 있는지 정해요. 필요한 조건이 맞을 때만 자동화가 실행되도록 해 줘요.

| 필터 | 사용할 수 있는 조건 |
| --- | --- |
| **Location**(위치) | **Space**, **Folder**, **List** 중에서 선택해요 |
| **Assignee**(담당자) | 사용자를 포함하거나 제외해요. 담당자가 지정되어 있는지 확인할 수도 있어요 |
| **Priority**(우선순위) | 우선순위를 포함하거나 제외해요. 우선순위가 지정되어 있는지 확인할 수도 있어요 |
| **Status**(상태) | 선택한 상태를 포함하거나 제외해요 |
| **Task Name**(작업 이름) | **contains**(포함), **does not contain**(포함하지 않음), **equals**(같음), **does not equal**(같지 않음), **regex**(정규식) 중에서 선택해요 |
| **Task Custom Fields**(작업 커스텀 필드) | 지원되는 커스텀 필드 값과 일치하는 작업을 골라요 |

{% hint style="info" %}
**Folder**와 **List** 옵션은 선택한 위치에 따라 달라져요. 트리거에 따라 사용할 수 있는 필터도 다를 수 있어요.
{% endhint %}

## Add Task 워크플로우 액션

**Add Task** 액션은 워크플로우가 해당 단계에 도달하면 프로젝트 관리 작업을 새로 만들어요. 작업을 만들 위치와 세부 내용을 정할 수 있어요.

| 설정 | 기능 |
| --- | --- |
| **Task Name**(작업 이름) | 작업 제목을 정해요 |
| **Space**, **Folder**, **List** | 작업을 만들 위치를 정해요 |
| **Status**(상태) | 선택한 List에서 사용할 수 있는 상태 중 하나를 골라요 |
| **Assignee**(담당자) | 특정 사용자나 지원되는 동적 값으로 할당해요 |
| **Priority**(우선순위) | **Urgent**(긴급), **High**(높음), **Medium**(보통), **Low**(낮음) 중에서 우선순위를 정해요 |
| **Start Date**, **Due Date** | 워크플로우가 실행된 시점을 기준으로 날짜를 정해요 |
| **Description**(설명) | 리치 텍스트 편집기로 작업 내용을 적어요 |
| **Custom Fields**(커스텀 필드) | 작업에 추가 정보를 저장해요 |

예를 들어 이 액션으로 "웹사이트 개발 시작"이라는 작업을 만들어 개발자에게 할당하고, 마감일을 워크플로우가 실행되고 2일 뒤로 정할 수 있어요.

## 동적 값과 커스텀 필드 사용하기

동적 값을 쓰면 정해진 글자를 입력하는 대신 워크플로우에서 쓸 수 있는 데이터를 넣을 수 있어요. 커스텀 필드에는 새로 만드는 작업의 추가 정보를 저장할 수 있어요.

**동적 값**

**Task Name**, **Description**, 지원되는 할당 필드에서 동적 값을 쓸 수 있어요.

사용할 수 있는 작업 관련 값은 다음과 같아요.

- **Task ID**(작업 ID)
- **Title**(제목)
- **Description**(설명)
- **Due Date**(마감일)
- **Assigned User**(할당된 사용자)

**작업 커스텀 필드**

작업의 커스텀 필드를 채우려면 다음과 같이 하세요.

1. **Add Task** 액션을 열어요.
2. **Add custom field**(커스텀 필드 추가)를 클릭해요.
3. 채울 필드를 선택해요.
4. 정해진 값을 입력하거나 지원되는 동적 값을 선택해요.
5. 필드가 더 필요하면 같은 방법으로 반복해요.

## 작업 날짜 설정과 주말 건너뛰기

**Add Task** 액션에서는 워크플로우가 실행된 시점을 기준으로 시작일과 마감일을 정할 수 있어요. 덕분에 작업 일정이 자동으로 잡혀요.

날짜를 설정하려면 다음과 같이 하세요.

1. **Value**(값)에 숫자를 입력해요.
2. **Unit**(단위)을 선택해요. **Days**(일), **Weeks**(주), **Months**(개월), **Years**(년) 중에서 고를 수 있어요.
3. 시간을 선택해요.
4. 필요하면 **Skip weekends**(주말 건너뛰기)를 켜요.

계산된 날짜가 주말이고 **Skip weekends**가 켜져 있으면, 날짜가 다음 평일로 넘어가요.

예를 들어 작업의 마감일을 워크플로우가 실행되고 2일 뒤로 정할 수 있어요.

## 프로젝트 관리 워크플로우 자동화 설정하기

프로젝트 관리 트리거와 **Add Task** 액션을 함께 쓰면 후속 업무를 자동화할 수 있어요.

아래 예시는 웹사이트 디자인 List에서 작업이 완료되면 웹사이트 개발 List에 작업을 만드는 워크플로우예요.

### 1단계: 워크플로우 만들기 또는 열기

1. 하이퍼클래스 서브 계정에서 **자동화 > 워크플로우**로 이동해요.
2. 워크플로우를 새로 만들거나 기존 워크플로우를 열어요.
3. 워크플로우 빌더를 열어요.

### 2단계: Task Completed 트리거 추가하기

1. **Add New Trigger**(새 트리거 추가)를 클릭해요.
2. **Task Completed**를 검색해서 선택해요.  
   ![Task Completed 트리거 선택 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083620352/original/7Q50u0YYf7uodJiXxdhBAmsFk9WEOrz-Bw.png?1792396086)
3. 알맞은 **Space**를 선택해요.
4. 웹사이트 디자인 **List**를 선택해요. 필요하면 먼저 **Folder**를 선택하세요.
5. **Status**나 **Priority** 같은 필터가 더 필요하면 추가해요.
6. 트리거를 저장해요.

![Task Completed 트리거 필터 설정 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083620457/original/L9R2bx75sZPJY686ZzBLoMVMqvizXCKLQQ.png?1792396179)

### 3단계: Add Task 액션 설정하기

1. 트리거 아래의 **+** 아이콘을 클릭해요.
2. **Add Task**를 검색해서 선택해요.
3. **Task Name**에 "웹사이트 개발 시작"을 입력해요.
4. 작업을 만들 **Space**와 웹사이트 개발 **List**를 선택해요.
5. 필요에 맞게 **Status**, **Priority**, **Assignee**를 설정해요.
6. 필요하면 **Description**이나 작업 커스텀 필드를 추가해요.

![Add Task 액션 설정 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083620164/original/_0QpLln4JreQjb3FEZfb8qey9H4Puy4hyA.png?1792395998)

### 4단계: 마감일 설정하기

1. **Due Date**에서 **Value**에 `2`를 입력해요.
2. **Unit**에서 **Days**를 선택해요.
3. 원하는 시간을 선택해요.
4. 필요하면 **Skip weekends**를 켜요.
5. **Save action**(액션 저장)을 클릭해요.

새 작업의 마감일은 워크플로우가 실행될 때 계산돼요.

### 5단계: 저장, 테스트, 게시하기

1. 워크플로우 빌더에서 **Save**(저장)를 클릭해요.
2. 지원되는 경우 **Test workflow**(워크플로우 테스트)를 사용해요.
3. 워크플로우가 올바른 List에 원하는 내용으로 작업을 만드는지 확인해요.
4. 준비가 끝나면 워크플로우를 **Draft**(임시 저장)에서 **Publish**(게시)로 바꿔요.

{% hint style="warning" %}
워크플로우를 저장해도 자동으로 게시되지는 않아요.
{% endhint %}

## 자주 묻는 질문

### Task Added와 Add Task는 무엇이 다른가요?
**Task Added**는 워크플로우를 시작하는 트리거이고, **Add Task**는 새 작업을 만드는 액션이에요.

### 다른 List에 작업을 만들 수 있나요?
네. **Add Task** 액션에서 작업을 만들 **Space**, **List**를 선택하세요. **Folder**는 필요할 때 선택하면 돼요.

### 우선순위가 높은 작업에만 워크플로우를 실행할 수 있나요?
네. 지원되는 트리거에서 **Priority** 필터를 사용하세요.

### 작업 시작일 전에 알림을 예약할 수 있나요?
네. **Task Reminder**는 시작일, 마감일, 지원되는 커스텀 날짜 필드를 기준으로 쓸 수 있어요.

### 작업을 자동으로 할당할 수 있나요?
네. 특정 사용자를 선택하거나 지원되는 동적 값을 쓸 수 있어요.

### 새 작업의 이름이나 설명에 기존 작업 정보를 넣을 수 있나요?
네. 동적 값을 쓰면 지원되는 작업 정보를 넣을 수 있어요.

### 마감일이 주말이면 어떻게 되나요?
**Skip weekends**가 켜져 있으면 마감일이 다음 평일로 넘어가요.

### 워크플로우가 실행되지 않아요.
워크플로우가 게시되어 있는지, 트리거 필터가 작업과 맞는지, 필요한 프로젝트 관리 기능을 사용할 수 있는지 확인하세요.
