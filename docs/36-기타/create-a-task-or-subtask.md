# 작업과 하위 작업 만들기

작업은 **프로젝트 관리**(Project Management)에서 일을 나누는 기본 단위이고, 하위 작업은 큰 작업을 여러 단계로 쪼갠 것이에요. 이 문서에서는 작업을 만드는 두 가지 방법, 작업에 담을 수 있는 내용, 하위 작업 추가 방법, 특정 작업의 링크를 공유하는 방법을 안내해요.

{% hint style="info" %}
**프로젝트 관리**는 이제 $497 요금제를 쓰는 에이전시에서 사용할 수 있어요. 켜려면 **에이전시 설정** 또는 **서브 계정 설정** > **실험실**로 이동해서 **프로젝트 관리** 토글을 켜세요.
{% endhint %}

## 작업을 만드는 두 가지 방법

어느 방법으로 만들어도 같은 종류의 작업이 만들어져요. 만드는 순간 얼마나 채워 넣느냐만 달라요.

1. 도구 모음의 **작업 추가**: 보드 위 도구 모음 오른쪽에 있는 버튼이에요. 작업을 어떤 상태에서 시작할지 아직 정하지 않았을 때 쓰세요.
2. 열 맨 아래의 **작업 추가**: 칸반 보기에서는 상태 열마다 **작업 추가**가 따로 있어요. 작업이 속할 단계를 이미 알고 있을 때 쓰세요. 작업이 그 열의 상태로 만들어져요.

## 작업에 담을 수 있는 내용과 작업 만드는 순서

작업을 열면 오른쪽 패널이나 모달 중 원하는 방식으로 볼 수 있어요. 선택한 보기 방식은 저장돼서, 다음에 작업을 열 때 마지막으로 선택한 방식으로 자동으로 열려요. 맨 위의 경로 표시(breadcrumb)에는 작업이 있는 위치가 **Space**/**List** 형태로 나와요.

1. **Task name**(작업 이름): 패널에서 바로 수정할 수 있어요.
2. **설명**: 작업 내용을 자세히 적는 서식 편집기예요. 서식 도구 모음과 실행 취소·다시 실행 버튼이 있고, 비어 있을 때는 **작업 설명 입력** 문구가 보여요.
3. **Status**(상태): 작업이 어느 단계에 있는지를 나타내요. **Space**에 설정된 상태 중에서 골라요.
4. **Assignee**(담당자): 책임지는 사람 한 명이에요. 여러 명을 고르는 목록이 아니라 한 명만 선택해요.
5. **Dates**(날짜): 날짜 하나 또는 기간을 지정해요. 표시 기준이 되는 시간대도 함께 나와요.
6. **우선순위**: **Low**(낮음), **Normal**(보통), **High**(높음), **Urgent**(긴급) 중에서 골라요. 우선순위를 지정하지 않은 채로 둘 수도 있어요.
7. **모든 필드**: **Space**에 설정된 커스텀 필드와 필드 개수가 보여요. 값이 없는 필드에는 대시(-)가 표시돼요.
8. **연결된 객체**: 작업에 연결된 CRM 레코드와 그 개수가 보여요.
9. **하위 작업**: 이 작업 아래에 속한 작업, 그 개수, 하위 작업을 더 추가하는 버튼이 보여요.
10. **Comments**(댓글): 패널 맨 아래에 있는 입력란이에요. **Write a comment...**(댓글 입력)라는 문구가 보여요.

## 작업을 빠르게 만드는 방법

1. 작업을 넣을 **List**를 여세요. 왼쪽 패널에서 **List**를 클릭해요.
2. 새 작업을 시작하세요. 도구 모음의 **작업 추가**를 클릭하거나, 작업을 시작할 상태 열 맨 아래의 **작업 추가**를 클릭하세요.

   ![빠른 작업 만들기 시연](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155078830206/original/MRzxnbRCYyWkB7HoL-Eztvu4Y3tl51X_tg.gif?1787155013)

3. 작업 이름을 입력하세요. 해야 할 일이 드러나는 이름을 쓰세요. 주제를 설명하는 이름보다 결과를 설명하는 이름이 다루기 쉬워요.
4. 담당자, 날짜, 우선순위를 정하세요. 입력 창에서 **담당자 추가**, **날짜 선택**, **우선순위**를 쓸 수 있어요. 담당자가 없는 작업은 주인이 없어서 놓치기 쉬우니, 바로 정해 두는 걸 추천해요.
5. **저장**을 클릭하세요. 작업이 열에 카드로 나타나요.

## 하위 작업을 추가하는 방법

하나의 작업에 서로 다른 단계가 여러 개 있을 때, 특히 단계마다 맡은 사람이 다를 때 하위 작업이 유용해요. 작업에는 담당자를 한 명만 지정할 수 있어서, 하나의 일을 여러 사람에게 나눌 때도 하위 작업을 쓰면 돼요.

1. 상위 작업을 여세요. 작업 카드를 클릭하면 상세 패널이 열려요.
2. **하위 작업** 섹션을 찾으세요. 패널 아래쪽의 **하위 작업** 섹션으로 스크롤해요. 섹션 제목에 현재 하위 작업 개수가 표시돼요.

   ![하위 작업 섹션](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155078461361/original/dEltK1UZRc7HA63D_159u0X8vlUF5w2_lg.png?1786717975)

3. **작업 추가**를 클릭하세요. 하위 작업 이름을 입력하고 저장하면 상위 작업 아래 목록에 나타나요.

   ![하위 작업 추가](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155078461351/original/3LdQMzzPLHyMjKa5-2IZoGw63NQVbaf6Dg.png?1786717975)

4. 단계마다 반복하세요. 단계 하나에 하위 작업 하나씩 추가해요. 작업에 하위 작업이 생기면 보드의 카드에 하위 작업 개수가 표시돼요. 어떤 작업이 쪼개져 있는지 한눈에 볼 수 있어요.

## 작업에 댓글 남기기

### 특정 작업 링크 공유하기

작업을 열면 브라우저 주소에 작업 식별자가 붙어요. 그 주소를 복사해서 공유하면, **Space**에 접근할 수 있는 사람이 링크를 열었을 때 바로 그 작업으로 이동해요. 작업 위치를 말로 설명하는 것보다 빨라요.

## 작업을 다른 List로 옮기는 방법

작업은 하나의 **List**에 속하지만, 계속 거기에 있을 필요는 없어요. 같은 **Space**에 있든 다른 **Space**에 있든, 어떤 **List**로든 옮길 수 있어요.

옮기기는 복사가 아니라 위치 이동이에요. 이동이 끝나면 작업은 원래 **List**에서 사라져요. 작업의 소속이 하나이고, 그 소속이 바뀌는 거예요.

1. 옮길 작업을 여세요.
2. 이동 옵션을 선택하고 옮길 **List**를 고르세요. 다른 **Space**에 있는 **List**를 포함해 워크스페이스 안의 어느 **List**든 고를 수 있어요.

   ![이동할 List 선택](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155078941651/original/ph79P9IpWuv39ATYel6hIpX9DHlcWz8exg.png?1787247504)

3. 상태 매핑 확인 창이 나오면 확인하세요. 상태는 **Space**마다 따로 설정돼요. 그래서 상태 구성이 다른 **Space**로 작업을 옮기면, 작업의 현재 상태가 옮겨 간 곳에 없을 수 있어요. 이럴 때는 작업이 도착한 뒤 어떤 상태가 될지 확인하라는 창이 나와요. 이 선택에 따라 작업이 놓일 열이 정해지니, 기본값을 그냥 받아들이지 말고 꼭 살펴보세요.

   상태 구성이 다른 **Space** 사이에서 작업을 옮길 때 나오는 상태 매핑 확인 창

   ![상태 매핑 확인 창](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155078940995/original/381mSQSTo96TFGpT6BPiqyWvpic0OddLvQ.png?1787246771)

4. 이동을 확인하세요. 작업이 옮겨 간 **List**에 나타나고 원래 **List**에서는 사라져요.

{% hint style="info" %}
같은 **Space** 안의 두 **List** 사이에서는 상태가 같아서 매핑할 것이 없으니 간단하게 옮겨져요. 확인 단계는 옮겨 갈 **Space**의 상태 구성이 다를 때만 나와요.
{% endhint %}

## 작업을 여러 List에 추가하는 방법

하나의 일이 정말로 여러 곳에 속해야 할 때가 있어요. 예를 들어 제공팀과 고객 응대팀이 둘 다 봐야 하는 작업이에요. 작업을 복제해서 두 개를 동기화하는 대신, 작업 하나를 같은 **Space** 또는 다른 **Space**의 여러 **List**에 한꺼번에 추가할 수 있어요.

이동과는 달라요. 작업은 원래 속한 **List**에 그대로 있고, 다른 **List**에서도 보이게 될 뿐이에요. 작업은 여전히 하나라서, 어디에서 업데이트하든 모든 곳에 똑같이 반영돼요.

---

## 상태는 어떻게 적용되나요

시작하기 전에 알아 두면 좋은 내용이에요.

다른 **List**에 추가된 작업은 원래 속한 **List**의 상태 워크플로우를 그대로 따라요. 추가된 **List**가 완전히 다른 상태 구성의 **Space**에 있어도, 그 **List**의 상태를 쓰지 않아요. 어디에 보이든 원래 **Space**의 워크플로우가 작업을 관리해요.

이렇게 하려고, 추가된 **List**가 있는 **Space**의 상태 워크플로우에 그 작업의 상태가 추가돼요. 그래서 다른 **Space**로 작업을 추가하면 그 **Space**의 구성에 새 상태가 생길 수 있어요.

---

## 추가된 List에서 작업할 때 알아 둘 점

동료가 작업의 상태를 추가된 **List**에 있는 상태 중 하나로 바꾸려고 하면 문제가 생겨요. 상태를 선택할 수는 있지만, 저장하려고 하면 오류가 나요. 작업은 원래 속한 **List**에 정의된 상태 사이에서만 옮길 수 있어요.

의도된 동작이에요. 작업의 워크플로우는 하나이고, 그건 작업이 속한 곳의 워크플로우예요. 다른 **Space**의 상태로 끌어다 놓을 수 있게 하면, 원래 팀이 알아볼 수 없는 단계에 작업이 놓이게 돼요.

팀에 미리 알려 두면 좋아요. 작업이 원래 속한 **List**가 아니라 추가된 **List**에서 일하는 사람은 작업을 창문 너머로 보는 것이지, 손에 쥔 것이 아니에요. 업데이트하고, 댓글을 남기고, 작업의 고유한 단계 사이에서 옮길 수는 있지만, 그 단계 자체는 다른 곳에서 정해져요.

다른 **Space**에서 추가된 작업에 추가된 **List**의 상태를 지정하려 할 때 나타나는 오류

## 작업을 다른 List에 추가하는 순서

1. 작업을 여세요.
2. 다른 **List**에 추가하는 옵션을 선택하고 추가할 **List**를 고르세요.
3. 작업이 나타나야 하는 다른 **List**가 더 있으면 반복하세요.

이제 작업은 추가된 모든 **List**에 보이고, 상태는 계속 원래 **List**의 상태를 따라요.

{% hint style="info" %}
작업이 처음 있던 곳에서 아예 떠나기를 원하면 추가 대신 이동하세요. 다른 **List**에 추가하면 원래 위치는 그대로 남아요.
{% endhint %}

## 자주 묻는 질문

### 작업을 만들려면 최소한 무엇이 필요한가요?
이름과 마감일이에요. 담당자와 우선순위는 나중에 추가해도 되지만, 담당자는 일찍 정해 두는 편이 좋아요.
### 마감일 말고 시작일도 지정할 수 있나요?
네, 있어요. **Dates**(날짜)에서는 날짜 하나 또는 기간을 지정할 수 있어요.

### 작업 필드 중 일부에 대시(-)가 보여요. 왜 그런가요?
커스텀 필드에 아직 값이 없다는 뜻이에요. 쓸 수 있는 필드는 작업이 속한 **Space**에서 가져와요.

### 작업을 이동하는 것과 다른 List에 추가하는 것은 어떻게 다른가요?
이동은 작업의 위치를 바꾸는 것이라 작업이 원래 **List**에서 완전히 사라져요. 다른 **List**에 추가하면 원래 위치는 그대로 남고, 같은 작업이 여러 곳에서 보여요.

### 작업을 옮길 때 상태를 확인하라는 창이 나와요. 왜 그런가요?
상태는 **Space**마다 따로 설정돼요. 상태 구성이 다른 **Space**로 작업을 옮기면 현재 상태가 그곳에 없을 수 있어서, 도착할 때 어떤 상태가 될지 묻는 거예요.

### 다른 Space의 List에 작업을 추가하면 어떤 상태가 적용되나요?
원래 속한 **List**의 상태 워크플로우를 따라요. 추가된 **List**의 상태 구성은 무시하고, 처음 시작한 워크플로우를 계속 따라요.

### 이 작업의 상태를 내 List의 상태로 바꿀 수가 없어요. 왜 그런가요?
작업이 다른 **List**에 속해 있어서 그 **List**의 워크플로우를 따르기 때문이에요. 원래 속한 **List**의 상태 사이에서는 옮길 수 있지만, 지금 보고 있는 **List**의 상태로는 옮길 수 없어요. 작업이 정말로 내 워크플로우를 따라야 한다면 추가가 아니라 이동해야 해요.

### 내 Space에 새 상태가 생겼어요. 왜 그런가요?
다른 **Space**의 작업이 내 **List** 중 하나에 추가됐기 때문이에요. 작업은 원래 상태를 유지하므로, 그 상태가 제대로 표시되도록 내 **Space**의 워크플로우에 추가돼요.

### 한 List에서 작업을 업데이트하면 다른 List에도 반영되나요?
네, 반영돼요. 작업이 몇 개의 **List**에 보이든 작업은 하나뿐이에요.
