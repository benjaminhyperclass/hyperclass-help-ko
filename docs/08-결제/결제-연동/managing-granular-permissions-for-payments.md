# 결제 세부 권한 관리

결제 세부 권한을 쓰면 결제 영역별로 누가 보고, 만들고, 수정하고, 환불하고, 내보내고, 구성할 수 있는지 정할 수 있어요. 이 문서에서는 권한 카테고리를 하나씩 설명하고, 자주 쓰는 역할별 권한 구성 예시와 설정 방법을 안내해요. 새 팀원을 빠르게 적응시키면서도 매출 관련 업무와 변경 이력은 안전하게 지킬 수 있어요.

## 결제 세부 권한이란?

예전에는 결제 접근 권한이 하나뿐이었어요. 결제 세부 권한은 이를 **주문**, **구독**, **거래 내역**, **세금**, **상품**, **결제 설정**이라는 카테고리로 나누고, 카테고리마다 같은 종류의 작업 권한을 둔 방식이에요. 관리자는 팀원에게 업무에 필요한 권한만 줄 수 있고, 민감한 작업은 노출되지 않아요.

결제 세부 권한은 서브 계정(위치) 수준의 역할 기반 접근 제어예요. 결제 메뉴 전체에서 어떤 사용자가 **보기**, **만들기**, **업데이트**, **삭제**, **내보내기**, **구성**을 할 수 있는지 정해요. 카테고리를 조합해 고객 지원, 회계, 출고, 경영진 팀에 맞게 접근 범위를 조정할 수 있어요.

---

## 결제 세부 권한의 장점

팀별로 어떤 작업을 허용할지 정할 때 아래 장점을 기준으로 생각해 보세요. 위험은 줄이면서 평소 업무는 느려지지 않게 하는 것이 목표예요.

- **위험 최소화:** 환불, 상품 삭제, 세금 설정처럼 영향이 큰 작업은 신뢰할 수 있는 사용자에게만 허용해요.
- **빠른 온보딩:** 역할에 필요한 카테고리와 작업만 지정하면 새 팀원이 안전하게 업무를 시작할 수 있어요.
- **명확한 감사:** 권한이 좁을수록 **감사 로그**에서 누가 언제 무엇을 바꿨는지 추적하기 쉬워요.
- **업무 구분 명확화:** 카테고리가 나뉘어 있어 환불과 주문 수정처럼 작업이 어디에 있는지 헷갈리지 않아요.
- **작업 통제:** 일괄 작업, 가져오기, 내보내기는 사용자 권한에 따라 제한될 수 있어서 데이터 품질을 지킬 수 있어요.

## 결제 권한에서 달라진 점

기존의 단일 결제 토글에서 무엇이 바뀌었는지 알아 두면 관리자가 안심하고 옮겨 갈 수 있고, 스태프에게도 정확히 안내할 수 있어요. 이번 변경으로 권한 지정이 간단해지고, 감사가 쉬워지고, 과도한 권한을 주는 위험이 줄어들어요.

- **권한 위치 이동:** **Refund Transactions**(거래 환불), **Manage Subscriptions**(구독 관리) 같은 기존 기능은 이제 각각 **거래 내역**과 **구독** 카테고리 안에 있어요. 환불 권한 없이 조회 권한만 주거나, 결제 전체 권한 없이 구독 관리 권한만 줄 수 있어요.
- **통일된 작업 구성:** 모든 카테고리가 **보기**, **만들기**, **업데이트**, **삭제**, **내보내기**, **구성**이라는 같은 작업 구성을 써요. 역할을 비교하고, 교육하고, 감사하기 쉬워졌어요.
- **화면에서 적용되는 종속 관계:** 영향이 큰 일부 도구는 기본 권한이 있어야 쓸 수 있어요. 예를 들어 상품 일괄 작업과 CSV 가져오기는 **만들기**/**업데이트** 권한이 필요해요. 읽기 전용 사용자가 실수로 여러 건을 바꾸는 일을 막아 줘요.
- **민감한 작업 통제 강화:** 환불, 구독 수정, 세금 설정 변경을 누가 할 수 있는지 관리자가 직접 정해요. 평소 업무 효율은 유지하면서 재무 통제를 강화할 수 있어요.

## 주문 권한

**주문** 권한은 **결제 링크**, 체크아웃 페이지, 스토어, POS에서 만들어진 일회성 주문과 결제를 관리해요. 주문을 처리하면서 조회와 내보내기가 필요한 팀에 쓰고, 수정 권한은 책임 있는 담당자에게만 주세요.

**추천 역할:** 주문을 조회하고, 목록을 내보내고, 제한적으로 수정해야 하는 출고팀이나 지원팀

## 구독 권한

**구독** 권한은 반복 결제의 전 과정을 다뤄요. 플랜 만들기, 연락처에 구독 지정, 일시중지·재개·취소, 결제 수단 변경 같은 업데이트가 여기에 속해요. 구독 상태 관리와 이탈 방지를 맡은 역할에 주세요.

![구독 권한 설정 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155054980224/original/MTdvdd83enOr1SWGs093SwXj7FwhTPpzgQ.png?1759303088)

**추천 역할:** 구독 상태와 고객 유지를 책임지는 재무·결제 팀과 어카운트 매니저예요. 지원팀에는 **보기**를 주고, **만들기**/**업데이트**/**취소**는 지정된 담당자에게만 허용하세요.

## 거래 내역 권한

**거래 내역** 권한은 완료된 결제와 환불에 적용돼요. 환불 처리와 공식 영수증 다운로드가 가능하므로 민감한 권한이에요. 가능하면 조회 권한과 환불 권한을 분리해서 엄격하게 관리하세요.

![거래 내역 권한 설정 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155054980262/original/CEv-bTfSxhXMNMpepwR9iGHDg3HDDXtWcg.png?1759303119)

**추천 역할:** 내역 조회(**보기**/**내보내기**/영수증)는 **결제 지원** 담당에게, 환불은 재무 책임자와 **회계사**에게 맡기세요. 환불 권한은 재무 책임자에게만 주세요.

## 세금 권한

**세금** 권한은 수동 세율과 자동 세금 계산 기능을 포함해 세금 처리 방식을 누가 구성하고 조정할 수 있는지 정해요. 세금 설정은 규정 준수에 영향을 주므로 재무 담당자에게만 주세요.

![세금 권한 설정 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155054980290/original/a3uGaX2G3hQpnn4Sk4ykQIySDI12G-DDnA.png?1759303154)

**추천 역할:** 규정 준수를 책임지는 **회계사**/컨트롤러 또는 재무 관리자예요. 재무 담당이 아닌 사용자에게는 **구성**/**삭제** 권한을 주지 마세요.

## 상품 권한

**상품** 권한은 상품을 만들고, 편집하고, 복제하고, 가져오기/내보내기 하고, 삭제할 수 있는 사용자를 정해요. 상품을 바꾸면 **결제 링크**, 스토어, 체크아웃 페이지에도 그대로 반영돼요. 삭제처럼 되돌리기 어려운 작업은 제한하고, 카탈로그를 바꿀 때는 검토를 거치게 하세요.

![상품 권한 설정 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155054980302/original/m0yCgNs6TIOEizAmaLnY5pRWhxz0LZEeDA.png?1759303170)

**추천 역할:** 일상적인 업데이트는 스토어 매니저나 상품/카탈로그 담당자가 맡아요. **가져오기**/**내보내기**/**삭제**는 관리자에게만 주세요.

## 결제 세부 권한 설정하기

설정을 제대로 해 두면 사용자가 불필요한 위험 없이 업무를 마칠 수 있어요. 다음 단계를 따라 필요한 권한만 지정하고 결과를 확인하세요.

1. **서브 계정 설정 > 스태프 관리**로 이동해 사용자를 찾고 연필(편집) 아이콘을 클릭하세요.

   ![스태프 관리에서 사용자 편집](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155054983320/original/pzOCaMK00vyyHdOiYXEe4eS7DqNlSqKbJg.png?1759305479)
2. **Roles & Permissions**(역할 및 권한) 섹션을 펼치고 설정할 카테고리를 선택하세요.
3. **주문**, **구독**, **거래 내역**, **세금**, **상품**, **결제 설정** 카테고리마다 역할에 필요한 작업(**보기**, **만들기**, **업데이트**, **삭제**, **내보내기**, **구성**)을 켜세요. 만들기/업데이트 권한이 없는 사용자는 일부 일괄 작업, 가져오기, 내보내기를 쓸 수 없을 수 있어요.

   ![카테고리별 작업 권한 켜기](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155054983292/original/5gFD7-EtbDhYb0b116gpfk6T53-hd9Ls4A.gif?1759305452)
4. **저장**을 클릭하세요.
5. (선택) 같은 설정을 다른 사용자에게 적용하려면 **권한 복사**를 클릭하세요.

   ![권한 복사 버튼](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155054983497/original/mQbtdjcgooi4l3d8pUvrgNs21eFVj_wEgw.png?1759305624)
6. 필요하면 사용자가 로그아웃했다가 다시 로그인하게 하세요. 그런 다음 테스트용 데이터로 접근 권한을 확인하세요. 예를 들어 상품을 열어 보거나 거래 내역을 확인해 보세요.

## 역할별 권한 구성 예시

아래 구성 예시는 강제 사항이 아니라, 흔한 업무 역할에 비교적 안전한 권한 조합을 연결해 둔 추천안이에요. 조직의 정책에 맞게 조정해서 쓰세요.

권한 구성 예시 요약

| 역할 | 설정 카테고리 | 세부 설정(작업) | 비고 |
| --- | --- | --- | --- |
| **결제 지원** | **거래 내역** | **보기**, **내보내기**, **Download Receipt**(영수증 다운로드) *(**Refund**(환불) 끔)* | 환불 권한 없이 내역 조회와 영수증 다운로드만 할 수 있어요. 감독하에 환불이 필요하면 일시적으로 권한을 올려 주세요. |
|  | **구독** | **보기**, **Pause**(일시중지)/**다시 시작**/**취소** | 구독 상태 변경을 관리하도록 교육받은 팀이 아니라면 **만들기**/**업데이트**/**취소**는 주지 마세요.|
|  | **주문** | **보기**, **내보내기** | 주문 상태 문의에 답할 때 유용해요. **업데이트**는 선임 상담원에게만 주는 것을 고려하세요. |
|  | **상품** | **보기** | 카탈로그 조회만 가능하고 편집은 할 수 없어요. |
|  | **결제 설정** | — | 구성은 관리자/재무 담당이 맡으세요. |
| **출고 / 스토어 매니저** | **주문** | **보기**, **내보내기**, **업데이트** *(**만들기**는 선택, **삭제**는 끔)* | 배송과 주문 조정을 지원해요. **삭제**는 관리자에게만 두세요. |
|  | **상품** | **보기**, **업데이트** *(**만들기**는 카탈로그 담당자만, **가져오기**/**내보내기**는 끔, **삭제**는 끔)* | 일괄 작업이나 가져오기에는 **만들기**/**업데이트** 권한이 필요할 수 있어요. 교육받은 담당자에게만 허용하세요. |
|  | **거래 내역** | **보기** | 환불은 할 수 없어요. 환불 요청은 재무 담당에게 넘기세요. |
|  | **구독** | **보기**(선택) | 참고용이에요. 구독 상태 변경은 어카운트 매니저나 재무 담당이 처리해요. |
| **어카운트 매니저** | **구독** | **보기**, **만들기**, **업데이트**, **Pause**(일시중지)/**다시 시작**/**취소**, **내보내기** | 구독 상태, 갱신, 이탈 방지를 맡아요. 필요하면 카드 정보 업데이트도 관리해요. |
|  | **거래 내역** | **보기** | 결제 내역은 조회할 수 있지만 환불은 할 수 없어요. |
|  | **주문** | **보기** | 고객과 대화할 때 참고할 정보예요. |
|  | **상품** | **보기**(선택) | 가격 논의에 쓸 읽기 전용 상품 정보예요. |
| **회계사** / 컨트롤러 | **거래 내역** | **보기**, **내보내기**, **Refund**(환불) | 환불은 재무 책임자에게만 허용하고, **감사 로그**로 확인하세요. |

|  | **결제 설정** | **구성**, **업데이트** | 영수증, 기본값, 결제 알림을 제어해요. |

## 자주 묻는 질문

### 결제의 CSV 가져오기/내보내기도 권한에 영향을 받나요?
네. 가져오기/내보내기는 사용자에게 지정된 작업과 역할에 따라 제한될 수 있어요. 사용자에게 일괄 작업 도구가 보이지 않으면, 관리자가 해당 카테고리의 **만들기**/**업데이트**/**내보내기** 권한을 확인해 보세요.

### 환불 권한 없이 거래 내역만 조회할 수 있나요?
네. **거래 내역**의 **보기** 권한(필요하면 **내보내기**도)을 주고, 환불 권한은 재무 책임자에게만 두세요.

### 상품 권한을 끄면 기존 체크아웃이나 결제 링크가 작동하지 않나요?
아니요. 이미 운영 중인 체크아웃은 설정된 대로 계속 판매돼요. 다만 해당 사용자는 기반이 되는 상품이나 링크를 편집할 수 없어요.

### 상품, 세금 설정, 결제 환경설정을 누가 바꿨는지 어디서 확인하나요?
**감사 로그**에서 사용자의 작업과 변경 내역을 확인할 수 있어요. 에이전시 관리자는 에이전시 수준의 로그를 볼 수 있고, 퍼널·웹사이트·스토어는 각 자산별 감사 로그도 쓸 수 있어요.

### 결제 세부 권한을 에이전시 수준에서도 쓸 수 있나요?
결제 권한은 서브 계정(위치) 수준에서 지정해요. 에이전시 사용자는 에이전시 범위에서 사용자와 역할을 관리하며, 설정에 따라 이 지정이 서브 계정(위치) 역할과 함께 적용되거나 우선할 수 있어요.

### 사용자가 결제 화면의 버튼이 회색으로 비활성화돼 있다고 해요.
해당 카테고리의 만들기/업데이트 또는 내보내기 권한이 부족하다는 뜻인 경우가 많아요. 사용자의 역할 구성을 확인하거나, 관리자 역할로 잠시 테스트해서 확인해 보세요.

### 세금 권한에 자동 계산 기능도 포함되나요?
네, 사용할 수 있는 경우에는 포함돼요. 재무 책임자가 자동 세금 계산을 켜고 관리할 수 있어요. 정확한 계산을 위해 결제 화면에서 주소를 입력받도록 설정하세요.
