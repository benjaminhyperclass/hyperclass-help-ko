# WordPress 스테이징 환경 사용하기

하이퍼클래스 WordPress 스테이징을 쓰면 운영 중인 사이트에 영향을 주지 않고 업데이트를 미리 테스트할 수 있어요. 이 문서에서는 스테이징 사이트를 만드는 방법, 환경을 전환하는 방법, 스테이징 환경 표시를 확인하는 방법, 변경 사항을 라이브에 게시하는 방법을 안내해요.

{% hint style="info" %}
서브 계정에 WordPress Hosting 구독이 활성화되어 있어야 해요.
{% endhint %}

## WordPress 스테이징 환경이란?

웹 개발에서 스테이징 환경은 개발과 테스트 과정에 꼭 필요한 요소예요. 운영 중인 웹사이트를 그대로 복제해 별도의 서버나 디렉터리에 두고, 웹사이트 개발과 유지 관리에 필요한 여러 작업을 할 수 있게 만든 환경이에요.

스테이징은 라이브 사이트와 분리된 안전한 WordPress 사이트 복사본을 제공해요. 이 안에서 플러그인, 테마, 콘텐츠 변경을 마음껏 시험해 본 뒤, 확인이 끝난 업데이트를 라이브 사이트에 게시할 수 있어요.

스테이징 환경의 핵심 요소는 다음과 같아요.

- 복제: 스테이징 환경은 파일, 데이터베이스, 설정을 포함해 라이브 웹사이트를 그대로 복제해요. 그래서 실제 사이트와 똑같은 복사본으로 작업할 수 있어요.
- 격리: 스테이징 환경은 라이브 사이트와 별개로 동작해요. 덕분에 변경 사항을 실험하거나 새 기능을 테스트하거나 문제를 점검해도 라이브 사이트의 성능과 기능에는 영향이 없어요.
- 테스트 공간: 스테이징 환경은 안전하게 통제되는 테스트 공간이에요. 변경, 새 플러그인 설치, 테마 업데이트, 콘텐츠 수정을 위험 부담 없이 해 볼 수 있어요. 라이브 사이트에 적용하기 전에 문제를 찾아 해결하는 데 도움이 돼요.

## 스테이징 환경을 쓰면 좋은 점

- 위험 줄이기: 웹사이트 작업에는 라이브 사이트에 문제를 일으킬 수 있는 큰 변경이 많아요. 스테이징 환경에서 먼저 충분히 테스트하면 이런 위험을 줄일 수 있어요.
- 워크플로우 개선: 업데이트를 테스트하고 다듬는 전용 공간이 있어서, 완성도 높고 오류 없는 변경만 라이브 사이트에 반영할 수 있어요.
- 협업: 개발자, 디자이너, 콘텐츠 제작자가 함께 일할 때 효율적인 작업 공간이 돼요. 여러 팀원이 서로의 작업을 방해하지 않고 동시에 사이트의 다른 부분을 작업할 수 있어요.
- 품질 관리: 디자인, 기능, 콘텐츠 문제를 방문자가 라이브 사이트에서 보기 전에 찾아 고칠 수 있어요.

## 환경별로 쓸 수 있는 기능

라이브와 스테이징 모두에서 쓸 수 있는 기능이에요.

- **플러그인**
- **테마**
- **사용자**
- **WordPress Debugging**(WordPress 디버깅)
- **Server Settings**(서버 설정: phpMyAdmin, PHP 버전)
- **WordPress Management**(WordPress 관리: 자동 업데이트, SEO 색인)

라이브에서만 쓸 수 있는 기능이에요.

- **Domain Management**(도메인 관리)
- **Production Analytics**(운영 사이트 분석)
- **구독 취소**

스테이징에서만 쓸 수 있는 기능이에요.

- 전용 스테이징 URL과 관리자 접속
- 스테이징 전용으로 표시된 비활성 영역
- 격리된 환경에서 추가한 사용자 (게시할 때 안내 메시지가 표시돼요)

## 스테이징 환경 만들고 사용하기

아래 순서대로 하면 스테이징 사이트를 제대로 준비하고, 준비가 끝났을 때만 게시할 수 있어요. 게시하면 스테이징의 모든 변경 사항이 라이브에 적용되고, 되돌릴 수 없어요.

1. 서브 계정에 로그인하세요.
2. **사이트 > WordPress**로 이동하세요.

   ![사이트 메뉴의 WordPress 화면](https://jumpshare.com/share/NGK21FCbtFdfuiqL3xej+/Screen+Shot+2026-02-11+at+5.15.43+PM.png)
3. 스테이징 환경을 켜려는 사이트에서 **Manage Website**(웹사이트 관리) 버튼을 클릭하세요.

   ![Manage Website 버튼](https://jumpshare.com/share/ZUR1k8q62GCmfoC2wPcp+/Screen+Shot+2026-02-11+at+5.17.23+PM.png)
4. **+ Create Environment**(환경 만들기)를 클릭하세요. 준비하는 데 시간이 걸릴 수 있어요.

   ![스테이징 환경 만들기 진행 화면](https://jumpshare.com/share/epbl6lAAIipriHIek0tr+/GIF+Recording+2026-02-11+at+5.28.58+PM.gif)
5. 준비가 끝나면 스테이징 URL, 스테이징 관리자 접속 정보(스테이징 사이트에 들어가 변경하는 데 쓰는 정보), 관련 세부 정보가 표시돼요. 여기서 사이트에 필요한 변경을 모두 하고 테스트한 뒤 라이브 사이트에 게시할 수 있어요.

   ![스테이징 URL과 관리자 접속 정보 화면](https://jumpshare.com/share/ui4lB9UzQFKPrGpUoNlB+/Screen+Shot+2026-02-11+at+5.30.23+PM.png)
6. 환경을 전환하려면 오른쪽 위 헤더의 **Live | Staging** 선택기(라이브와 스테이징 전환)를 사용하세요.

   ![라이브와 스테이징 전환 선택기](https://jumpshare.com/share/cVt1b50U4HGlQrebLVyB+/GIF+Recording+2026-02-11+at+6.16.42+PM.gif)
7. 변경 사항에 만족하면 **게시**를 클릭해 라이브 환경에 반영하세요. 스테이징의 모든 변경 사항이 라이브로 적용되며, 되돌릴 수 없어요. 게시하기 전에 변경 내용을 꼼꼼히 확인하세요. 게시를 확인하면 2~5분 안에 사이트에 게시돼요.

   ![라이브 환경에 게시하는 화면](https://jumpshare.com/share/6L2hHAyBpD31Fe1e3s60+/GIF+Recording+2026-02-11+at+5.52.58+PM.gif)
8. 기존 스테이징 환경을 없애고 처음부터 다시 시작하려면 **삭제** 버튼을 클릭해 삭제를 진행하세요.

   ![스테이징 환경 삭제 화면](https://jumpshare.com/share/HEmS8M9kDDzNKrEMijHa+/GIF+Recording+2026-02-11+at+5.55.20+PM.gif)

## 스테이징 환경 활용 팁

{% hint style="info" %}
라이브 사이트에서 직접 한 변경은 스테이징 환경 사이트에 반영되지 않아요.
{% endhint %}

1. 정기 백업: 스테이징 환경에서 큰 변경을 하기 전에 라이브 사이트의 최신 백업을 확인하세요. 테스트 중 문제가 생기면 백업으로 사이트를 복원할 수 있어요.
2. 테스트 체크리스트: 테스트할 요소, 기능, 동작을 정리한 체크리스트를 만들어 두세요. 빠뜨리지 않고 꼼꼼히 테스트하는 데 도움이 돼요.
3. 콘텐츠 검토: 텍스트, 이미지, 멀티미디어 등 모든 콘텐츠 변경을 꼼꼼히 검토해 정확성, 일관성, 적합성을 확인하세요.
4. 차이 조정: 라이브 사이트에 게시하기 전에 스테이징 환경과 라이브 환경 사이의 차이나 충돌을 조정하세요. 필요한 업데이트가 모두 동기화되었는지 확인하세요.
5. 정리: 오래되었거나 필요 없는 파일, 데이터베이스, 설정을 지워 스테이징 환경을 주기적으로 정리하세요. 작업 공간을 깔끔하고 효율적으로 유지할 수 있어요.

## 자주 묻는 질문

### 스테이징에서 수정하면 라이브 사이트에도 영향이 있나요?

아니요. 스테이징에서 한 수정은 라이브에 게시하기 전까지 라이브에 영향을 주지 않아요.

### 스테이징에서 라이브로 게시하면 어떻게 되나요?

스테이징의 모든 변경 사항이 라이브에 적용돼요. 이 작업은 되돌릴 수 없어요.

### 스테이징에서 일부 영역이 비활성화되어 있어요. 왜 그런가요?

라이브에서만 쓸 수 있는 기능이기 때문이에요. 해당 영역을 쓰려면 라이브로 전환하라는 안내 메시지가 표시돼요.

### 스테이징 환경을 만드는 데 시간이 얼마나 걸리나요?

준비하는 데 시간이 걸릴 수 있고, 소요 시간은 달라질 수 있어요.
