# 하이퍼클래스 사이트에 루트 도메인 또는 서브도메인 설정하기

루트 도메인이나 서브도메인(Subdomain)을 하이퍼클래스에 연결하면 퍼널(Funnel), 웹사이트(Website), 스토어(Store), 블로그(Blog), 웨비나(Webinar)를 고유한 브랜드 웹 주소로 게시할 수 있어요. Domain Connect를 통해 지원 도메인을 자동으로 연결하거나, DNS 레코드를 직접 설정하는 방식으로 수동 연결할 수도 있습니다. 도메인을 연결한 후에는 올바른 랜딩 페이지를 지정하고, 기본 페이지와 404/오류 페이지를 설정해서 방문자에게 일관된 경험을 제공할 수 있어요. 이 가이드에서는 도메인 연결, DNS 설정, 페이지 구성, 도메인 삭제, 그리고 주요 문제 해결 방법을 안내합니다.

# 하이퍼클래스에서 루트 도메인/서브도메인이란?

루트 도메인은 example.com처럼 사이트의 기본 웹 주소를 말해요. 서브도메인은 루트 도메인 앞에 접두사를 붙인 주소로, www.example.com이나 offers.example.com처럼 사용됩니다.

하이퍼클래스에서는 루트 도메인과 서브도메인을 지원되는 사이트(Sites) 제품에 연결할 수 있어서, 방문자가 브랜드 URL을 통해 퍼널, 웹사이트, 스토어, 블로그, 웨비나에 접속할 수 있어요. DNS 제공업체에 따라 Domain Connect를 사용하거나 필요한 DNS 레코드를 직접 설정할 수 있습니다.


## 루트 도메인/서브도메인 연결의 주요 장점

올바른 도메인을 연결하면 방문자에게 브랜드화된 접속 경로를 제공하면서, 하이퍼클래스가 해당 사이트 콘텐츠로 트래픽을 정확히 연결해줘요.

- **브랜드화된 방문자 경험:** 비즈니스와 연결된 도메인이나 서브도메인을 사용해 하이퍼클래스 콘텐츠를 게시할 수 있어요.
- **유연한 연결 방식:** 지원되는 경우 Domain Connect를 사용하거나, 필요할 때 DNS를 수동으로 설정할 수 있어요.
- **자동 SSL:** 도메인 연결이 성공하면 하이퍼클래스가 SSL을 자동으로 발급해줘요.
- **랜딩 경험 제어:** 방문자가 추가 경로 없이 도메인에 접속했을 때 보여줄 퍼널 단계(Funnel Step)나 웹사이트 페이지를 지정할 수 있어요.
- **커스텀 오류 처리:** 유효하지 않은 URL에 접속한 방문자를 위한 브랜드화된 404/오류 페이지를 설정할 수 있어요.
- **설정 알림:** 조건을 충족하는 연결된 도메인은 기본 페이지 설정이 완료되지 않았을 때 **Action Required(조치 필요)** 알림을 표시해줘요.


## 사전 준비 사항 및 제한 사항

도메인을 준비하고 DNS 관리 위치를 미리 확인해두면 연결 충돌을 예방하고 확인 지연을 줄일 수 있어요.

**시작하기 전에:**

- 연결하려는 루트 도메인 또는 서브도메인에 대한 소유권 또는 접근 권한이 있어야 해요.
- 수동 설정이 필요한 경우, 현재 사용 중인 DNS 제공업체에 접근할 수 있어야 해요.
- 방문자가 example.com 같은 루트 도메인을 사용할지, www.example.com이나 offers.example.com 같은 서브도메인을 사용할지 결정하세요.
- 해당 호스트네임이 유지해야 하는 다른 웹사이트나 서비스에 이미 사용 중이라면, 해당 주소를 재설정하지 말고 사용 가능한 다른 서브도메인을 사용하세요.

**현재 제한 사항 및 동작 방식:**

- 하나의 호스트네임은 동시에 여러 플랫폼이나 서버를 가리킬 수 없어요.
- 동일한 호스트네임에 A 레코드와 CNAME 레코드를 함께 생성하지 마세요.
- Cloudflare에서 DNS를 관리하는 경우, 하이퍼클래스 A 또는 CNAME 레코드를 Proxied가 아닌 **DNS only**로 설정해야 해요.
- DNS 변경 사항이 전파되기까지 시간이 걸릴 수 있으며, 최대 24시간이 소요될 수 있어요.
- **Action Required(조치 필요)** 알림은 연결된 도메인에 기본 페이지 또는 기본 404/오류 페이지가 설정되지 않은 경우 표시돼요.
- **Action Required(조치 필요)** 알림은 도메인이 처음 연결된 하위 계정(Sub-account)에서만 표시돼요.

## 루트 도메인 또는 서브도메인 설정 방법

올바른 순서로 도메인을 연결하면 하이퍼클래스가 DNS를 확인하고, 해당 주소를 콘텐츠와 연결한 뒤 SSL을 성공적으로 발급할 수 있어요.

### 1단계: 루트 도메인 또는 서브도메인 선택하기

DNS를 변경하기 전에 올바른 호스트네임을 결정해두면 기존 웹사이트나 서비스가 의도치 않게 교체되는 것을 방지할 수 있어요.

루트 도메인은 기본 주소를 사용해요:
example.com

서브도메인은 접두사를 추가해요:

www.example.com
offers.example.com
go.example.com


**중요:** 루트 도메인에 이미 유지해야 할 다른 웹사이트나 서비스가 운영 중이라면, 루트 도메인을 재설정하지 말고 사용 가능한 서브도메인을 사용하세요.


### 2단계: 하이퍼클래스에서 도메인 연결 시작하기

Domains(도메인) 영역에서 시작하면 하이퍼클래스가 사이트(Sites) 연결 유형을 인식하고 적절한 자동 또는 수동 DNS 설정 절차를 안내해줘요.

- **Sub-Account(하위 계정)** 화면에서 **Settings(설정)**를 클릭하세요.
- **Domains & URL Redirects(도메인 및 URL 리다이렉트)**를 선택하세요.
- **+ Connect a domain(도메인 연결)**을 클릭하세요.
- **Funnel/Website/Store/Blog/Webinar**를 찾아 **Connect(연결)**를 클릭하세요.
- **Domain URL(도메인 URL)** 필드에 루트 도메인 또는 서브도메인을 입력하세요.
- 연결 방식을 선택하세요:
- **Continue(계속):** Domain Connect로 자동 설정을 시도해요.
- **Add record manually(레코드 직접 추가):** 필요한 DNS 레코드를 직접 설정해요.

![](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155081934193/original/muqW-oNc1TuA6yl0jyGO1pGnxCf0k5HmJw.png?1790491150)


루트 도메인을 연결할 때 하이퍼클래스는 www 버전도 함께 추가하고 301 리다이렉트를 설정해서, www 주소로 들어온 트래픽을 루트 도메인으로 보낼 수도 있어요.

### 3단계: 도메인을 자동 또는 수동으로 설정하기

DNS 제공업체가 자동 설정을 지원하는 경우 Domain Connect를 사용하고, 자동 설정이 지원되지 않거나 선호하지 않는 경우 필요한 DNS 레코드를 직접 추가하세요.

#### Domain Connect를 통한 자동 설정

Domain Connect는 지원되는 DNS 제공업체에 대한 권한을 승인받아 연결에 필요한 레코드를 자동으로 생성해줘요.

- 연결 절차에서 도메인을 입력하고 **Continue(계속)**를 클릭하세요.
- 하이퍼클래스가 지원되는 제공업체를 인식하면 **Authorize(승인)**를 클릭하세요.
- 안내에 따라 도메인 제공업체에 로그인하세요.
- 요청된 DNS 연결을 승인하세요.
- 승인이 완료되면 제공업체 탭을 닫고 하이퍼클래스로 돌아오세요.
- 하이퍼클래스가 DNS 설정을 확인할 수 있도록 기다리세요.

![](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155081934194/original/xTl7bK3vxo1_kaENf0c58nppkg4DYtT3HA.png?1790491171)


#### DNS 수동 설정

수동 설정에서는 현재 도메인의 DNS를 관리하는 제공업체에서 직접 필요한 레코드를 추가할 수 있어요.

- 하이퍼클래스에 도메인을 입력하고 **Add record manually(레코드 직접 추가)**를 클릭하세요.
- 해당 도메인의 활성 DNS를 관리하는 제공업체에 로그인하세요.
- 아래 표에 표시된 지원 레코드 중 하나를 추가하세요.

| 사용 사례 | 타입 | Host / Name | Value / Target |
|---|---|---|---|
| 루트 도메인 | **A** | @ | 162.159.140.166 |
| 서브도메인 | **CNAME** | www 또는 offers 등 서브도메인 부분만 | sites.ludicrous.cloud |
| 서브도메인 지원 대안 | **A** | 서브도메인 부분만 | 162.159.140.166 |


**중요:** 지원되는 서브도메인 설정에는 A 레코드 또는 CNAME 레코드 중 하나만 사용하고, 같은 호스트네임에 둘 다 설정하지 마세요. Cloudflare를 사용하는 경우, 해당 A 또는 CNAME 레코드를 **DNS only**로 설정하세요.


![](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155081933176/original/VRdAkUx76Uel-RcfwUyc8NHqDXMKIDytjA.png?1790486871)


### 4단계: 도메인을 사이트 콘텐츠와 연결하기

확인된 도메인을 연결하면 방문자가 해당 주소로 접속했을 때 어떤 퍼널 또는 웹사이트 콘텐츠를 불러올지 하이퍼클래스에 알려줄 수 있어요.

- 하이퍼클래스가 필요한 DNS 레코드를 확인할 때까지 기다리세요.
- 도메인 연결 화면에서 해당하는 **Funnel(퍼널)** 또는 **Website(웹사이트)**를 선택하세요.
- 기본 랜딩 페이지로 사용할 퍼널 단계 또는 웹사이트 페이지를 선택하세요.
- **Link Domain(도메인 연결)**을 클릭하세요.

도메인이 연결되면 하이퍼클래스가 자동으로 SSL 발급을 시작해요. SSL 발급에는 몇 분 정도 소요될 수 있어요.


![](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155081933948/original/Sk3yZhm_VT6h8wKmex7_qFxnERX4koZuQA.png?1790490067)


### 5단계: 기본 페이지 및 404/오류 페이지 설정하기

기본 페이지 설정은 방문자가 메인 도메인에서 무엇을 보게 될지, 그리고 잘못되거나 존재하지 않는 URL을 요청했을 때 어디로 이동할지를 결정해요.

- **Settings(설정) → Domains & URL Redirects(도메인 및 URL 리다이렉트)**로 이동하세요.
- 연결된 도메인을 찾아 **Manage(관리)**를 클릭하세요.
- 도메인의 **Connected Products(연결된 제품)**를 확인하세요.
- **Action Required(조치 필요)** 알림이 표시되면 클릭하세요.
- **Default Page(기본 페이지)** 드롭다운에서 조건을 충족하는 페이지를 선택하세요.
- **Default 404/Error Page(기본 404/오류 페이지)** 드롭다운에서 조건을 충족하는 페이지를 선택하세요.

![](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155081934079/original/kXLKvQ6Fu6NLymPaXia8-Ov7P1d4VrzVhQ.png?1790490589)


![](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155081934077/original/nwWcdEBEdalWmHpDaRGVMGQc3Hm7TOYUGQ.png?1790490574)


**참고:** Action Required(조치 필요) 알림은 도메인이 처음 연결된 하위 계정(Sub-account)에서만 표시돼요.


기존의 Edit Domain(도메인 편집) 절차를 통해서도 기본 페이지 및 404/오류 페이지 설정을 관리할 수 있어요.

- **Settings(설정) → Domains & URL Redirects(도메인 및 URL 리다이렉트)**로 이동하세요.
- 해당 도메인의 **Manage(관리)**를 클릭하세요.
- 해당 도메인 또는 연결된 제품의 세 점(⋮) 메뉴를 여세요.
- **Edit(편집)**를 선택하세요.
- 기본 페이지 또는 **Set default 404/Error Page(기본 404/오류 페이지 설정)** 항목을 업데이트하세요.
- **Save(저장)**를 클릭하세요.

![](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155081934089/original/UgJbal1vh5-IWUX1zQw4CWKNRIazEnwMNg.png?1790490618)


## DNS 레코드 확인 방법

공개 DNS 조회 도구를 사용하면 하이퍼클래스에서 연결 문제를 추가로 해결하기 전에, 예상된 A 또는 CNAME 레코드가 실제로 전파됐는지 확인할 수 있어요.

- MXToolbox 같은 공개 DNS 조회 도구를 여세요.
- DNS 조회 또는 CNAME 조회 등 해당하는 조회 유형을 선택하세요.
- 연결한 루트 도메인 또는 서브도메인을 입력하세요.
- 조회를 실행하세요.
- 예상된 하이퍼클래스 레코드가 공개적으로 표시되는지 확인하세요.
- **CNAME:** sites.ludicrous.cloud
- **A 레코드:** 162.159.140.166


**DNS 전파:** 최근에 변경한 DNS 레코드는 즉시 반영되지 않을 수 있어요. 설정이 실패했다고 판단하기 전에 최대 24시간까지 기다려 보세요.


## 도메인 삭제 방법

도메인을 삭제하면 해당 하위 계정(Sub-account)과의 연결이 끊어지므로, 삭제하기 전에 그 주소가 현재 운영 중인 사이트 콘텐츠에 더 이상 필요하지 않은지 반드시 확인하세요.

- **Settings(설정) → Domains & URL Redirects(도메인 및 URL 리다이렉트)**로 이동하세요.
- 해당 도메인을 찾아 **Manage(관리)**를 클릭하세요.
- 세 점(⋮) 메뉴를 여세요.
- **Delete(삭제)**를 선택하세요.
- 확인 대화상자에서 삭제를 확인하세요.

## 도메인 연결 문제 해결

대부분의 연결 문제는 잘못된 DNS 제공업체에 레코드를 추가했거나, 레코드가 충돌하거나, 전파가 지연되거나, Cloudflare 프록시 설정 때문에 발생해요.

### 하이퍼클래스가 CNAME 또는 A 레코드를 찾지 못함

이 오류는 하이퍼클래스가 연결하려는 호스트네임에서 예상된 DNS 레코드를 감지하지 못했다는 의미예요.

- 네임서버를 확인해서 해당 도메인의 활성 DNS를 관리하는 제공업체가 어디인지 확인하세요.
- DNS 레코드가 해당 제공업체에 추가되었는지 확인하세요.
- 호스트네임에 이미 다른 곳을 가리키는 A 또는 CNAME 레코드가 있는지 확인하세요.
- 해당 호스트네임에는 지원되는 레코드 하나만 사용하세요:
  - CNAME → sites.ludicrous.cloud
  - A 레코드 → 162.159.140.166
- 제공업체에서 요구하는 경우, Host/Name 필드에는 www나 offers처럼 호스트네임 부분만 입력하세요.
- DNS 변경 사항을 저장하고 전파될 시간을 기다리세요.
- 하이퍼클래스로 돌아와 다시 확인을 시도하세요.

### 도메인에 SSL 또는 개인정보 보호 오류가 표시됨

하이퍼클래스가 호스트네임을 확인할 수 없거나, 충돌하는 DNS 레코드가 트래픽을 다른 목적지로 보내고 있으면 SSL이 안정적으로 발급되지 않을 수 있어요.

- 해당 호스트네임의 충돌하는 A 또는 CNAME 레코드를 제거하세요.
- 필요한 하이퍼클래스 A 또는 CNAME 레코드가 존재하는지 확인하세요.
- 호스트네임을 다른 플랫폼으로 연결하는 예상치 못한 레코드가 있는지 검토하세요.
- Cloudflare를 사용하는 경우, 하이퍼클래스 레코드가 **DNS only**로 설정되어 있는지 확인하세요.
- DNS를 수정한 후, 전파와 SSL 발급에 시간이 걸릴 수 있으니 기다려 주세요.

### Cloudflare 도메인이 제대로 연결되지 않음

Cloudflare 프록시 기능이 활성화되어 있으면 퍼널과 웹사이트에 사용되는 A 또는 CNAME 레코드를 하이퍼클래스가 확인하지 못할 수 있어요.

- Cloudflare에 로그인하세요.
- 해당 도메인을 열고 **DNS**로 이동하세요.
- 하이퍼클래스에 사용되는 A 또는 CNAME 레코드를 찾으세요.
- **Proxy status(프록시 상태)**를 **DNS only**로 변경하세요.
- 변경 사항을 저장하세요.
- DNS가 업데이트된 후 하이퍼클래스로 돌아와 다시 연결을 시도하세요.

### 도메인이 간헐적으로 404 페이지를 표시함

간헐적인 404 오류는 루트 도메인과 www 버전이 일관되지 않게 라우팅되거나, 도메인에 의도된 기본 페이지 설정이 없을 때 발생할 수 있어요.

- 방문자가 루트 버전과 www 버전을 모두 사용하고 있는지 확인하세요.
- 한 버전이 항상 다른 버전으로 연결되어야 한다면 적절한 301 리다이렉트를 설정하세요.
- 의도한 퍼널 단계나 웹사이트 페이지가 기본 페이지로 설정되어 있는지 확인하세요.
- **Default 404/Error Page(기본 404/오류 페이지)**를 설정해서 잘못된 경로가 의도된 브랜드 오류 페이지로 연결되도록 하세요.

## 자주 묻는 질문

**Q: 같은 도메인을 에이전시 내 여러 하위 계정에 추가할 수 있나요?**

네, 가능해요. 하이퍼클래스는 같은 에이전시 내 여러 하위 계정에 동일한 도메인을 추가하는 것을 지원해요.

**Q: 하나의 하위 계정에 도메인을 몇 개까지 추가할 수 있나요?**

현재 하이퍼클래스는 추가할 수 있는 도메인 수에 별도의 제한을 두고 있지 않아요.

**Q: SSL 인증서를 별도로 구매해야 하나요?**

아니요. 도메인이 성공적으로 연결되면 하이퍼클래스가 자동으로 SSL을 발급해줘요.

**Q: 하나의 도메인을 여러 퍼널이나 웹사이트에서 함께 사용할 수 있나요?**

네, 가능해요. 하이퍼클래스에서는 여러 퍼널과 웹사이트가 동일한 도메인을 사용할 수 있어요. 각 URL이 방문자를 올바르게 안내하도록 해당 경로와 기본 페이지 설정을 구성하세요.

**Q: 하이퍼클래스를 통해 직접 도메인을 구매할 수 있나요?**

네, 가능해요. 자격을 갖춘 계정은 하이퍼클래스의 Domain Purchase(도메인 구매) 기능을 통해 도메인을 구매하고 관리할 수 있어요.

**Q: Domain Connect 대신 DNS를 직접 설정할 수 있나요?**

네, 가능해요. 레코드를 직접 관리하고 싶거나 사용 중인 DNS 제공업체가 Domain Connect 자동 설정을 지원하지 않는 경우, 수동 DNS 설정 방식을 계속 사용할 수 있어요.
