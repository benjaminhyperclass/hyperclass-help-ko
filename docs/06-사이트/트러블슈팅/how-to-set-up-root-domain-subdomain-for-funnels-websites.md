# 퍼널·웹사이트에 루트 도메인과 서브도메인 연결하기

내 도메인으로 퍼널, 웹사이트, 스토어, 블로그, 웨비나를 게시하려면 루트 도메인이나 서브도메인을 하이퍼클래스에 연결하세요. 이 문서에서는 도메인 연결, DNS 설정, 기본 페이지와 404/오류 페이지 설정, 도메인 삭제, 문제 해결 방법을 안내해요.

## 루트 도메인과 서브도메인이란?

루트 도메인은 사이트의 대표 주소예요. 예를 들면 `example.com`이에요. 서브도메인은 루트 도메인 앞에 이름을 붙인 주소예요. 예를 들면 `www.example.com`, `offers.example.com`이에요.

루트 도메인이나 서브도메인을 연결하면 방문자가 내 도메인 주소로 퍼널, 웹사이트, 스토어, 블로그, 웨비나에 들어올 수 있어요. 사용하는 DNS 업체에 따라 Domain Connect로 자동 설정하거나, 필요한 DNS 레코드를 직접 추가할 수 있어요.

### 도메인을 연결하면 좋은 점

- 내 비즈니스 도메인이나 서브도메인으로 하이퍼클래스 콘텐츠를 게시할 수 있어요.
- 지원되는 경우 Domain Connect를 쓰고, 그렇지 않으면 DNS를 직접 설정할 수 있어요.
- 도메인이 정상적으로 연결되면 SSL이 자동으로 적용돼요.
- 추가 경로 없이 도메인만 열었을 때 보여 줄 퍼널 단계나 웹사이트 페이지를 고를 수 있어요.
- 없는 주소로 들어온 방문자에게 보여 줄 404/오류 페이지를 직접 꾸밀 수 있어요.
- 기본 페이지 설정이 끝나지 않은 도메인에는 **조치 필요** 알림이 표시될 수 있어요.

## 시작하기 전에

연결할 도메인과 DNS를 관리하는 곳을 미리 확인하면 연결 충돌과 인증 지연을 줄일 수 있어요.

**시작하기 전에** 아래 내용을 확인하세요.

- 연결하려는 루트 도메인이나 서브도메인을 소유하고 있거나 접근 권한이 있어야 해요.
- 수동으로 설정하려면 현재 사용 중인 DNS 업체에 접근할 수 있어야 해요.
- 루트 도메인(`example.com`)을 쓸지, 서브도메인(`www.example.com`, `offers.example.com`)을 쓸지 정하세요.
- 연결하려는 주소가 이미 다른 웹사이트나 서비스에 쓰이고 있고 계속 유지해야 한다면, 그 주소를 바꾸지 말고 사용 가능한 다른 서브도메인을 쓰세요.

**알아 두어야 할 제한 사항과 동작은 다음과 같아요.**

- 주소 하나를 여러 플랫폼이나 서버에 동시에 연결할 수 없어요.
- 같은 주소에 A 레코드와 CNAME 레코드를 함께 만들지 마세요.
- DNS를 Cloudflare에서 관리한다면 하이퍼클래스용 A 또는 CNAME 레코드를 Proxied가 아닌 **DNS only**(DNS 전용)로 설정하세요.
- DNS 변경 내용이 반영되는 데 최대 24시간이 걸릴 수 있어요.
- **조치 필요** 알림은 연결된 도메인에 기본 페이지나 기본 404/오류 페이지가 없을 때 표시돼요.
- **조치 필요** 알림은 도메인을 처음 연결한 서브 계정에서만 표시돼요.

{% hint style="info" %}
하이퍼클래스에서 직접 구매한 도메인이라면 외부 도메인 등록 업체에 로그인하지 않고 **구매한 도메인** 영역에서 DNS 레코드를 관리할 수 있어요. 설정 순서는 '구매한 도메인 설정 및 연결(Configure & Connect Purchased Domains)' 문서를 참고하세요.
{% endhint %}

## 루트 도메인 또는 서브도메인 연결하기

아래 순서대로 연결하면 하이퍼클래스가 DNS를 확인하고, 주소와 콘텐츠를 이어 주고, SSL을 적용해요.

### 1단계: 루트 도메인과 서브도메인 중 고르기

DNS를 바꾸기 전에 어떤 주소를 쓸지 먼저 정하면, 이미 쓰고 있던 웹사이트나 서비스가 의도치 않게 바뀌는 일을 막을 수 있어요.

루트 도메인은 대표 주소를 그대로 써요.

`example.com`

서브도메인은 앞에 이름을 붙여요.

`www.example.com`  
`offers.example.com`  
`go.example.com`

{% hint style="warning" %}
루트 도메인이 이미 다른 웹사이트나 서비스에 쓰이고 있고 계속 유지해야 한다면, 루트 도메인을 바꾸지 말고 사용 가능한 서브도메인을 쓰세요.
{% endhint %}

### 2단계: 하이퍼클래스에서 도메인 연결 시작하기

도메인 설정 화면에서 시작하면 사이트 상품 종류에 맞는 자동 또는 수동 DNS 설정 방법이 안내돼요.

1. **서브 계정** 화면에서 **설정**을 클릭하세요.
2. **도메인 & URL 리다이렉트**를 선택하세요.
3. **+ 도메인 연결**을 클릭하세요.
4. **퍼널/웹사이트/스토어/블로그/웨비나** 항목을 찾아 **연결**을 클릭하세요.
5. **도메인 URL** 필드에 루트 도메인이나 서브도메인을 입력하세요.
6. 연결 방법을 고르세요.
   - **계속**: Domain Connect로 자동 설정을 시도해요.
   - **레코드 수동 추가**: 필요한 DNS 레코드를 직접 추가해요.

![도메인 URL 필드와 연결 방법 선택지가 보이는 도메인 연결 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155081934193/original/muqW-oNc1TuA6yl0jyGO1pGnxCf0k5HmJw.png?1790491150)

루트 도메인을 연결하면 하이퍼클래스가 `www` 버전도 함께 추가하고, `www` 주소로 들어온 방문자를 루트 도메인으로 보내는 301 리다이렉트도 설정할 수 있어요.

{% hint style="info" %}
**도메인 연결** 화면에는 AI 스튜디오 같은 다른 상품도 나타날 수 있어요. 도메인을 AI 스튜디오 프로젝트에 바로 연결하려면 **AI 스튜디오 > 연결**을 선택한 뒤 AI 스튜디오의 커스텀 도메인 설정 방법을 따르세요.
{% endhint %}

### 3단계: 자동 또는 수동으로 도메인 설정하기

DNS 업체가 자동 설정을 지원하면 Domain Connect를 쓰세요. 자동 설정이 안 되거나 직접 하고 싶다면 필요한 DNS 레코드를 수동으로 추가하세요.

#### Domain Connect로 자동 설정하기

Domain Connect는 지원되는 DNS 업체를 승인하고, 연결에 필요한 레코드를 자동으로 만들어 줘요.

1. 연결 화면에 도메인을 입력하고 **계속**을 클릭하세요.
2. 하이퍼클래스가 지원되는 업체를 인식하면 **승인**을 클릭하세요.
3. 안내에 따라 도메인 업체에 로그인하세요.
4. 요청된 DNS 연결을 승인하세요.
5. 승인이 끝나면 업체 탭을 닫고 하이퍼클래스로 돌아오세요.
6. 하이퍼클래스가 DNS 설정을 확인할 때까지 기다리세요.

![지원되는 DNS 업체의 Domain Connect 승인 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155081934194/original/xTl7bK3vxo1_kaENf0c58nppkg4DYtT3HA.png?1790491171)

#### DNS 수동 설정하기

수동 설정은 현재 도메인의 DNS를 관리하는 업체에서 필요한 레코드를 직접 추가하는 방법이에요.

1. 하이퍼클래스에 도메인을 입력하고 **레코드 수동 추가**를 클릭하세요.
2. 도메인의 DNS를 실제로 관리하는 업체에 로그인하세요.
3. 아래 표에 나온 레코드 중 하나를 추가하세요.

| 용도 | 유형 | 호스트 / 이름 | 값 / 대상 |
| --- | --- | --- | --- |
| 루트 도메인 | **A** | `@` | `162.159.140.166` |
| 서브도메인 | **CNAME** | `www`, `offers`처럼 서브도메인 부분만 입력 | `sites.ludicrous.cloud` |
| 서브도메인 대체 방법 | **A** | 서브도메인 부분만 입력 | `162.159.140.166` |

{% hint style="warning" %}
지원되는 서브도메인 설정에서는 A 레코드와 CNAME 중 하나만 쓰세요. 같은 주소에 둘 다 만들면 안 돼요. Cloudflare를 쓴다면 해당 A 또는 CNAME 레코드를 **DNS only**(DNS 전용)로 설정하세요.
{% endhint %}

![필요한 도메인 레코드 값이 표시된 DNS 수동 설정 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155081933176/original/VRdAkUx76Uel-RcfwUyc8NHqDXMKIDytjA.png?1790486871)

### 4단계: 도메인에 사이트 콘텐츠 연결하기

인증이 끝난 도메인에 콘텐츠를 연결하면, 방문자가 그 주소로 들어왔을 때 어떤 퍼널이나 웹사이트가 열릴지 정해져요.

1. 하이퍼클래스가 필요한 DNS 레코드를 확인할 때까지 기다리세요.
2. 콘텐츠를 연결하는 화면에서 해당하는 **퍼널** 또는 **웹사이트**를 선택하세요.
3. 기본 랜딩 페이지로 쓸 퍼널 단계나 웹사이트 페이지를 선택하세요.
4. **Link Domain**(도메인 연결)을 클릭하세요.

도메인이 연결되면 하이퍼클래스가 SSL을 자동으로 적용하기 시작해요. SSL 적용에는 몇 분이 걸릴 수 있어요.

![연결된 도메인에 선택한 사이트 콘텐츠가 표시된 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155081933948/original/Sk3yZhm_VT6h8wKmex7_qFxnERX4koZuQA.png?1790490067)

### 5단계: 기본 페이지와 404/오류 페이지 설정하기

기본 페이지 설정은 방문자가 메인 도메인에서 보게 될 화면과, 잘못되었거나 없는 주소로 들어왔을 때 이동할 화면을 정해요.

1. **설정 > 도메인 & URL 리다이렉트**로 이동하세요.
2. 연결된 도메인을 찾아 **관리**를 클릭하세요.
3. 도메인의 **연결된 상품**을 확인하세요.
4. **조치 필요** 알림이 보이면 클릭하세요.
5. **Default Page**(기본 페이지) 드롭다운에서 사용할 수 있는 페이지를 선택하세요.
6. **Default 404/Error Page**(기본 404/오류 페이지) 드롭다운에서 사용할 수 있는 페이지를 선택하세요.

![기본 페이지 설정이 없을 때 조치 필요 알림이 표시된 연결된 상품 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155081934079/original/kXLKvQ6Fu6NLymPaXia8-Ov7P1d4VrzVhQ.png?1790490589)
![기본 페이지와 기본 404 오류 페이지 드롭다운이 있는 조치 필요 창](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155081934077/original/nwWcdEBEdalWmHpDaRGVMGQc3Hm7TOYUGQ.png?1790490574)

{% hint style="info" %}
**조치 필요** 알림은 도메인을 처음 연결한 서브 계정에서만 표시돼요.
{% endhint %}

기존 **Edit Domain**(도메인 편집) 화면에서도 기본 페이지와 404/오류 페이지를 설정할 수 있어요.

1. **설정 > 도메인 & URL 리다이렉트**로 이동하세요.
2. 해당 도메인에서 **관리**를 클릭하세요.
3. 해당 도메인이나 연결된 상품의 점 세 개 메뉴를 여세요.
4. **편집**을 선택하세요.
5. 기본 페이지 또는 **Set default 404/Error Page**(기본 404/오류 페이지 설정) 항목을 수정하세요.
6. **저장**을 클릭하세요.

![기본 페이지와 기본 404 오류 페이지 설정이 보이는 도메인 편집 창](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155081934089/original/UgJbal1vh5-IWUX1zQw4CWKNRIazEnwMNg.png?1790490618)

## DNS 레코드 확인하기

하이퍼클래스에서 문제를 더 살펴보기 전에, 공개 DNS 조회 도구로 A 또는 CNAME 레코드가 제대로 반영되었는지 확인할 수 있어요.

1. MXToolbox 같은 공개 DNS 조회 도구를 여세요.
2. DNS 조회나 CNAME 조회처럼 알맞은 조회 유형을 선택하세요.
3. 연결한 루트 도메인이나 서브도메인을 입력하세요.
4. 조회를 실행하세요.
5. 하이퍼클래스용 레코드가 공개적으로 보이는지 확인하세요.

**CNAME:** `sites.ludicrous.cloud`

**A 레코드:** `162.159.140.166`

**DNS 반영 시간:** 방금 바꾼 DNS 레코드는 바로 보이지 않을 수 있어요. 설정이 실패했다고 판단하기 전에 최대 24시간을 기다려 주세요.

## 도메인 삭제하기

도메인을 삭제하면 서브 계정과의 연결이 끊겨요. 삭제하기 전에 이 주소가 지금 운영 중인 사이트 콘텐츠에 더 이상 필요하지 않은지 확인하세요.

1. **설정 > 도메인 & URL 리다이렉트**로 이동하세요.
2. 도메인을 찾아 **관리**를 클릭하세요.
3. 점 세 개 메뉴를 여세요.
4. **삭제**를 선택하세요.
5. 확인 창에서 삭제를 확인하세요.

![삭제 옵션이 보이는 도메인 관리 메뉴](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155081933769/original/iJVuAZOrjhSj4zTjcoBj8sOr45R5TUXDMw.png?1790489416)

## 도메인 연결 문제 해결

연결 문제는 대부분 DNS 레코드를 다른 업체에 추가했거나, 충돌하는 레코드가 있거나, 반영이 늦거나, Cloudflare 프록시 설정 때문에 생겨요.

### 하이퍼클래스에서 CNAME 또는 A 레코드를 찾지 못한다고 나와요

연결하려는 주소에서 필요한 DNS 레코드를 하이퍼클래스가 찾지 못할 때 나타나는 오류예요.

1. 네임서버를 확인해서 도메인의 DNS를 실제로 어느 업체가 관리하는지 확인하세요.
2. 그 업체에 DNS 레코드를 추가했는지 확인하세요.
3. 같은 주소에 다른 곳을 가리키는 A 또는 CNAME 레코드가 이미 있는지 확인하세요.
4. 같은 주소에는 지원되는 레코드 하나만 쓰세요.
   - CNAME → `sites.ludicrous.cloud`
   - A 레코드 → `162.159.140.166`
5. 업체에서 요구한다면 호스트/이름 필드에 `www`나 `offers`처럼 주소의 앞부분만 입력하세요.
6. DNS 변경 내용을 저장하고 반영될 때까지 기다리세요.
7. 하이퍼클래스로 돌아와 인증을 다시 시도하세요.

### 도메인에 SSL 또는 개인정보 보호 오류가 표시돼요

하이퍼클래스가 주소를 확인하지 못하거나, 충돌하는 DNS 레코드가 트래픽을 서로 다른 곳으로 보내면 SSL이 제대로 적용되지 않아요.

- 해당 주소에 충돌하는 A 또는 CNAME 레코드가 있으면 삭제하세요.
- 하이퍼클래스용 A 또는 CNAME 레코드가 있는지 확인하세요.
- 주소를 다른 플랫폼으로 보내는 낯선 레코드가 없는지 살펴보세요.
- Cloudflare를 쓴다면 하이퍼클래스용 레코드가 **DNS only**(DNS 전용)로 설정되어 있는지 확인하세요.
- DNS를 바로잡은 뒤에는 반영과 SSL 적용에 시간이 걸릴 수 있어요.
- 예상치 못한 AAAA 레코드나, 주소를 하이퍼클래스가 아닌 다른 곳으로 보낼 수 있는 DNS 레코드가 있는지 확인하세요. 충돌하는 DNS 레코드는 도메인 인증이나 SSL 적용을 방해할 수 있어요.

### Cloudflare 도메인이 제대로 연결되지 않아요

Cloudflare 프록시를 켜 두면 하이퍼클래스가 퍼널과 웹사이트에 쓰는 A 또는 CNAME 레코드를 확인하지 못할 수 있어요.

1. Cloudflare에 로그인하세요.
2. 해당 도메인을 열고 **DNS**로 이동하세요.
3. 하이퍼클래스에 쓰는 A 또는 CNAME 레코드를 찾으세요.
4. **Proxy status**(프록시 상태)를 **DNS only**(DNS 전용)로 바꾸세요.
5. 변경 내용을 저장하세요.
6. DNS가 업데이트된 뒤 하이퍼클래스로 돌아와 연결을 다시 시도하세요.

### 도메인에서 가끔 404 페이지가 나와요

도메인 버전별로 연결이 일정하지 않거나 기본 페이지가 설정되어 있지 않으면 404가 간헐적으로 나올 수 있어요.

- 방문자가 루트 도메인과 `www` 버전을 모두 쓰고 있는지 확인하세요.
- 한쪽 버전이 항상 다른 쪽으로 이동해야 한다면 알맞은 301 리다이렉트를 설정하세요.
- 의도한 퍼널 단계나 웹사이트 페이지가 기본 페이지로 설정되어 있는지 확인하세요.
- **Default 404/Error Page**(기본 404/오류 페이지)를 설정해 잘못된 경로로 들어온 방문자가 의도한 오류 페이지를 보게 하세요.

## 자주 묻는 질문

### 같은 에이전시 안에서 같은 도메인을 여러 서브 계정에 추가할 수 있나요?
네. 같은 에이전시 안에서는 같은 도메인을 여러 서브 계정에 추가할 수 있어요.

### 서브 계정에 도메인을 몇 개까지 추가할 수 있나요?
현재 추가할 수 있는 도메인 수에 대한 제한은 따로 안내되어 있지 않아요.

### SSL 인증서를 따로 구매해야 하나요?
아니요. 도메인이 정상적으로 연결되면 하이퍼클래스가 SSL을 자동으로 적용해요.

### 퍼널이나 웹사이트 여러 개가 같은 도메인을 쓸 수 있나요?
네. 퍼널과 웹사이트 여러 개가 같은 도메인을 쓸 수 있어요. 각 주소가 방문자를 올바르게 안내하도록 경로와 기본 페이지 설정을 맞춰 주세요.

### 하이퍼클래스에서 도메인을 바로 구매할 수 있나요?
네. 구매 가능한 계정이라면 하이퍼클래스의 **도메인 구매**에서 도메인을 구매하고 관리할 수 있어요.

### Domain Connect 대신 DNS를 직접 설정할 수 있나요?
네. 레코드를 직접 관리하고 싶거나, 사용하는 DNS 업체가 Domain Connect 자동 설정을 지원하지 않아도 수동 DNS 설정을 쓸 수 있어요.
