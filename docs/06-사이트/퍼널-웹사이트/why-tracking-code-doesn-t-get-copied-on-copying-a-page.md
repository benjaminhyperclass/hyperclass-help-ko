# 페이지를 복사하면 트래킹 코드가 따라오지 않는 이유

퍼널 단계나 웹사이트 페이지를 복사하면 페이지에 직접 넣은 트래킹 코드는 일부러 복사되지 않아요. 이렇게 하면 이전 픽셀, 분석 스크립트, 페이지 전용 이벤트가 엉뚱한 페이지로 넘어가는 일을 막을 수 있어요. 이 문서에서는 복사 시 트래킹 코드가 어떻게 되는지, 그 이유가 무엇인지, 페이지 단위 추적과 사이트 전체 추적은 어떻게 다른지 알려 드려요. 복사한 페이지에 알맞은 트래킹 코드를 다시 넣고 테스트하는 방법도 안내해요.

{% hint style="warning" %}
복사한 페이지에 트래킹 코드를 직접 넣기 전에, 같은 스크립트가 퍼널이나 웹사이트 수준에 이미 설정되어 있는지 먼저 확인하세요. 같은 추적 스크립트를 두 곳에 모두 넣으면 페이지뷰, 이벤트, 전환이 중복으로 집계될 수 있어요.
{% endhint %}

## 페이지를 복사하면 트래킹 코드는 어떻게 되나요?

퍼널 단계나 웹사이트 페이지에 트래킹 코드를 직접 넣어 두었더라도, 페이지를 복사하면 그 페이지 단위 트래킹 코드는 복사되지 않아요. 페이지 디자인과 복사할 수 있는 콘텐츠는 그대로 복제되지만, 복사된 페이지에는 원본 페이지의 추적 스크립트가 없는 상태로 시작해요.

## 페이지 단위 트래킹 코드를 복사하지 않을 때의 장점

복사된 페이지에 트래킹 코드가 따라오지 않으면, 분석이나 광고 이벤트가 작동하기 전에 이 페이지에도 같은 추적 설정을 써도 되는지 먼저 확인할 수 있어요.

- 이벤트 중복 방지: 같은 페이지뷰나 전환 스크립트가 실수로 여러 번 실행되는 일을 줄여 줘요.
- 페이지 전용 추적 보호: 특정 페이지용 스크립트가 다른 페이지에서 저절로 실행되지 않아요.
- 잘못된 기여도 집계 감소: 분석과 광고 이벤트가 의도한 페이지나 퍼널 단계에 연결되도록 도와줘요.
- 더 안전한 공유: 페이지를 복사하거나 공유할 때 계정 전용 픽셀이나 추적 ID가 의도치 않게 함께 넘어갈 가능성을 줄여 줘요.
- 의도적인 설정 유도: 추적을 페이지 단위로 둘지, 퍼널이나 웹사이트 전체에 둘지 직접 고를 수 있어요.

## 트래킹 코드가 복사되지 않는 이유

페이지 단위 추적 스크립트는 특정 페이지, 캠페인, 전환 이벤트, 분석 속성, 광고 계정, 비즈니스와 연결되어 있는 경우가 많아요. 이런 스크립트가 복사된 페이지로 자동으로 넘어가면 리포트가 부정확해지거나, 쓰지 않아야 할 곳에 추적 설정이 노출될 수 있어요.

다른 퍼널, 웹사이트, 로케이션, 에이전시에서 페이지를 재사용할 때 특히 중요해요. 복사한 페이지는 새 용도에 맞는 추적 설정을 직접 검토해서 지정하세요.

## 페이지 단위 추적과 사이트 전체 추적의 차이

알맞은 추적 수준을 고르면 불필요한 중복을 막을 수 있어요. 스크립트를 한 페이지에서만 실행하려면 페이지 단위 추적을, 퍼널이나 웹사이트 전체에서 실행하려면 사이트 전체 추적을 쓰세요.

| 추적 유형 | 적합한 경우 | 추가하는 위치 |
| --- | --- | --- |
| 페이지 단위 추적 | 특정 퍼널 단계나 웹사이트 페이지에서만 실행해야 하는 스크립트나 이벤트 | 빌더에서 페이지를 열고 **추적 코드**/코드 아이콘을 눌러 **헤더 추적** 또는 **푸터 추적**으로 이동해요. |
| 사이트 전체 추적 | 선택한 퍼널이나 웹사이트의 모든 페이지·단계에서 실행해야 하는 스크립트 | 퍼널이나 웹사이트 **설정**을 열고 **헤드 트래킹 코드** 또는 **본문 추적 코드** 필드를 써요. |

예를 들어 Google Analytics나 Meta Pixel 기본 스크립트를 모든 페이지에서 실행해야 한다면 퍼널이나 웹사이트 수준에 넣는 편이 알맞아요. 감사 페이지에서만 실행해야 하는 전환 이벤트는 해당 페이지에 따로 넣는 편이 더 잘 맞아요.

## 페이지를 복사한 뒤 트래킹 코드 추가하기

복사한 페이지가 무엇을 측정해야 하는지 확인한 다음에 추적을 다시 추가하세요. 그래야 새 페이지가 원본 페이지에 속한 추적 ID, 전환 이벤트, 스크립트를 그대로 물려받는 일을 막을 수 있어요.

### 한 페이지에만 추가하기

1. **사이트**로 이동해요.
2. 복사한 페이지가 있는 위치에 따라 **퍼널** 또는 **웹사이트**를 열어요.
3. 복사한 페이지가 들어 있는 퍼널이나 웹사이트를 열어요.
4. 빌더에서 복사한 페이지를 열어요.
5. 빌더에서 **추적 코드** 또는 코드 아이콘을 클릭해요.
6. 스크립트 제공업체의 안내에 따라 이 페이지 전용 스크립트를 **헤더 추적** 또는 **푸터 추적**에 붙여 넣어요.
7. **저장**을 클릭해요.
8. 실제 트래픽을 보내기 전에 페이지를 미리보기로 열어 테스트해요.

### 퍼널이나 웹사이트 전체에 추가하기

1. 해당 퍼널이나 웹사이트를 열어요.
2. **설정**을 열어요.
3. **헤드 트래킹 코드** 또는 **본문 추적 코드**를 찾아요.
4. 제공업체가 안내하는 위치에 맞춰 추적 스크립트를 붙여 넣어요.
5. 변경 사항을 **저장**해요.
6. 이 스크립트를 써야 하는 게시된 페이지에서 스크립트가 작동하는지 확인해요.

같은 기본 추적 스크립트가 퍼널이나 웹사이트 **설정**에 이미 있다면, 페이지 단위로 같은 스크립트를 또 넣지 마세요. 필요한 경우에만 그 페이지에 필요한 페이지 전용 이벤트 코드만 추가하세요.

## 추적이 제대로 작동하는지 확인하기

페이지를 복사한 뒤에 테스트하면 올바른 스크립트가 올바른 페이지에서 실행되는지, 이벤트가 두 번 이상 기록되지 않는지 확인할 수 있어요.

1. 복사한 페이지를 테스트할 준비가 되면 **저장 및 게시**를 눌러요.
2. 새 브라우저 세션에서 게시된 페이지를 열어요.
3. 페이지 보기, 폼 제출, 확인 페이지 도달처럼 추적하려는 동작을 해 봐요.
4. 분석 또는 광고 제공업체의 테스트 도구가 있으면, 그 도구로 예상한 이벤트가 수신됐는지 확인해요.
5. 이벤트가 올바른 페이지나 URL에 연결되어 있는지 확인해요.
6. 이벤트가 의도한 횟수만큼만 실행되는지 확인해요.
7. 추가로 문제를 파악해야 하면 브라우저 개발자 도구와 네트워크 활동을 활용해요.

헤드 및 본문 트래킹 코드는 브라우저에서 동적으로 삽입될 수 있어서, 정적 페이지 소스에는 나타나지 않을 수 있어요. 스크립트를 확인할 때는 페이지 소스 보기만 믿지 말고, 제공업체의 테스트 도구나 브라우저 네트워크 활동을 쓰세요.

## 추적이 빠지거나 중복될 때 점검하기

데이터가 빠지거나 이벤트가 중복되는 문제는 대개 스크립트를 설치한 위치, 복사한 페이지의 설정 여부, 같은 코드가 여러 추적 수준에 있는지 여부에서 비롯돼요.

| 증상 | 확인할 내용 |
| --- | --- |
| 페이지를 복사한 뒤 추적이 사라졌어요 | 페이지 단위 추적은 원래 복사되지 않아요. 복사한 페이지를 열어서, 아직 필요하다면 알맞은 페이지 전용 스크립트를 추가하세요. |
| 복사한 페이지에서 분석 이벤트가 기록되지 않아요 | 복사한 페이지의 **추적 코드** 영역과 퍼널 또는 웹사이트 **설정**을 모두 확인해서 스크립트가 어디에 설치되어 있는지 확인하세요. |
| 이벤트가 두 번 실행돼요 | 같은 스크립트가 페이지 수준과 퍼널 또는 웹사이트 수준에 모두 설치되어 있는지 확인하세요. |
| 복제한 페이지에서 엉뚱한 전환이 실행돼요 | 복사한 페이지에 올바른 이벤트 코드, 추적 ID, 분석 속성, 픽셀, 대상 URL이 쓰였는지 확인하세요. |
| 페이지 소스 보기에서 코드가 보이지 않아요 | 트래킹 코드는 동적으로 삽입될 수 있어요. 브라우저 네트워크 도구나 추적 제공업체의 진단 도구로 테스트하세요. |
| 사용자 지정 코드가 페이지 표시에 영향을 줘요 | 사용자 지정 코드, 페이지 단위 트래킹 코드, 사용자 지정 CSS를 잠시 제거해서 문제를 일으키는 스크립트를 찾아내세요. |

## 자주 묻는 질문

### 퍼널 단계나 웹사이트 페이지를 복제하면 페이지 단위 트래킹 코드도 같이 복사되나요?
아니요. 페이지 단위 트래킹 코드는 복사된 페이지에서 일부러 제외돼요.

### 복사할 때마다 추적 스크립트를 다시 추가해야 하나요?
아니요. 먼저 퍼널이나 웹사이트 수준에 이미 스크립트가 설정되어 있는지 확인하세요. 사이트 전체에 설정되어 있다면 페이지 단위로 따로 복사하지 않아도 복사한 페이지에 필요한 기본 추적이 이미 적용될 수 있어요.

### 전환 페이지나 감사 페이지에 페이지 단위 추적을 쓸 수 있나요?
네. 이벤트나 스크립트를 퍼널이나 웹사이트 전체가 아니라 특정 페이지에서만 실행해야 할 때 페이지 단위 추적이 유용해요.

### Google Analytics나 Meta Pixel을 사이트 전체에 설정할 수도 있나요?
네. 기본 스크립트를 모든 페이지에서 실행해야 한다면 퍼널이나 웹사이트의 추적 설정을 쓰세요. 페이지 전용 이벤트는 필요한 페이지에만 따로 추가하세요.

### 코드를 다시 추가했는데 이벤트가 중복으로 잡혀요. 왜 그런가요?
같은 추적 스크립트가 사이트 전체와 개별 페이지에 모두 설치되어 있는지 확인하세요. 중복 설치되면 같은 이벤트가 여러 번 실행될 수 있어요.

### 페이지 소스에서 추적 스크립트를 찾을 수 없어요. 왜 그런가요?
트래킹 코드는 브라우저에서 동적으로 삽입될 수 있어요. 분석 제공업체의 테스트 도구나 브라우저 개발자 도구로 스크립트와 이벤트가 실행되는지 확인하세요.

### 페이지를 복사하면 분석 기록도 같이 복사되나요?
아니요. 복사된 페이지는 별도의 페이지이자 단계예요. 원본 페이지의 과거 통계는 새 페이지로 옮겨지지 않아요.
