# 301 URL 리디렉션 설정

301 리디렉션은 방문자와 검색엔진을 예전 URL에서 새 목적지로 영구적으로 보내 주는 기능이에요. 하이퍼클래스에서는 도메인 전체 또는 특정 URL 경로를 리디렉션할 수 있고, 목적지는 사용자 지정 URL, 퍼널 단계, 웹사이트 페이지 중에서 고를 수 있어요.

이 문서에서는 301 리디렉션을 만들고 관리하는 방법과 사용하면 좋은 경우, 자주 생기는 문제의 해결 방법을 안내해요.

---

## 301 URL 리디렉션이란?

301 URL 리디렉션은 한 URL에서 다른 URL로 영구적으로 이동시키는 설정이에요. 원래 URL이 영구적으로 옮겨졌다는 사실을 브라우저와 검색엔진에 알려 주기 때문에, 방문자가 예전 링크를 눌러도 올바른 페이지에 도착해요. 하이퍼클래스에서는 선택한 도메인이나 경로의 트래픽을 사용자 지정 URL, 퍼널 단계, 웹사이트 페이지로 보낼 수 있어요.

페이지 이름을 바꿨을 때, 퍼널이나 웹사이트의 경로를 바꿨을 때, 콘텐츠를 다른 곳으로 옮겼을 때, 수정한 뒤에도 예전 URL이 계속 동작하게 하고 싶을 때 주로 써요.

---

## 301 URL 리디렉션의 장점

- 방문자 경험 개선: 예전 URL로 들어온 방문자를 올바른 목적지로 자동으로 보내 줘요.
- 깨진 링크 감소: 페이지 이름을 바꾸거나 삭제하거나 옮겼을 때 생기는 404 오류를 줄여 줘요.
- SEO 연속성: URL이 영구적으로 옮겨졌음을 검색엔진에 알려 주고, URL을 바꿔도 SEO가 이어지도록 도와줘요.
- 도메인 통합: `www` 버전을 루트 도메인으로 보내는 것처럼, 한 도메인 버전의 트래픽을 다른 버전으로 보낼 수 있어요.
- 다양한 목적지: 사용자 지정 URL, 하이퍼클래스의 퍼널 단계, 웹사이트 페이지로 리디렉션할 수 있어요.

---

## 301 리디렉션을 써야 하는 경우

URL이 영구적으로 바뀌어서 방문자를 새 목적지로 자동으로 보내야 할 때 301 리디렉션을 사용하세요.

주로 이런 경우에 써요.

- 퍼널 단계나 웹사이트 페이지의 경로 이름을 바꿀 때
- 콘텐츠를 다른 URL로 옮길 때
- 페이지를 교체하거나 삭제하면서 기존 링크로 들어오는 트래픽을 유지하고 싶을 때
- 콘텐츠를 다른 도메인으로 옮길 때
- 예전 캠페인이나 랜딩 페이지 URL을 현재 페이지로 보낼 때
- 한 URL이 다른 URL을 영구적으로 가리켜야 해서 도메인 버전을 통합할 때

{% hint style="info" %}
여러 URL에 계속 접속할 수 있어야 하고, 검색엔진에는 그중 하나만 대표 URL로 알리고 싶다면 301 리디렉션 대신 캐노니컬 URL을 사용해 보세요.
{% endhint %}

## 하이퍼클래스에서 301 리디렉션 설정하기

다음 단계에 따라 도메인의 301 리디렉션을 설정하세요.

### 1단계: URL 리다이렉트로 이동하기

1. **설정** > **도메인 & URL 리다이렉트**로 이동하세요.
2. 페이지 위쪽에서 **URL 리다이렉트** 탭을 선택하세요. 리디렉션을 만들고, 검색하고, 편집하고, 삭제할 수 있는 관리 화면이 열려요.

![URL 리다이렉트 탭으로 이동하는 화면](https://jumpshare.com/share/fjz9BYWVCmnfkIqeeTxq+/GIF+Recording+2026-06-18+at+17.19.48.gif)

### 2단계: 새 리디렉션 추가하기

1. 오른쪽 위에서 **+ Add Redirect**(리디렉션 추가)를 클릭하세요.

   기존 리디렉션이 없으면 리디렉션 메인 화면에서 첫 리디렉션을 추가하는 옵션이 보일 수도 있어요.
2. **Add Redirect** 설정 창이 열려요.

![리디렉션 추가 설정 창이 열리는 화면](https://jumpshare.com/share/BypLYCyFq3lrw5qXbNhi+/GIF+Recording+2026-06-18+at+18.10.26.gif)

### 3단계: 출발지 도메인 선택하기

{% hint style="info" %}
출발지 도메인은 하이퍼클래스 서브 계정에 미리 추가되어 있어야 해요.
{% endhint %}

1. **출처** 섹션에서 **리디렉션 출발지** 드롭다운을 클릭하세요.
2. 리디렉션할 출발지 도메인을 선택하세요.

   드롭다운에는 현재 계정에 있는 도메인이 표시돼요.

![리디렉션 출발지 드롭다운에서 도메인을 선택하는 화면](https://jumpshare.com/share/O1tsuhiz8XnXJQShOVwP+/Screenshot+2026-06-18+at+18.11.54.png)

### 4단계: 리디렉션할 대상 선택하기

출발지 도메인을 선택한 다음에는 도메인 전체를 리디렉션할지, 특정 경로만 리디렉션할지 고르세요.

다음 두 가지 옵션 중에서 선택할 수 있어요.

옵션 1: **특정 경로**

도메인에서 페이지 하나 또는 경로 하나만 리디렉션하고 싶을 때 선택하세요.

예를 들어 `yourdomain.com/contact`를 리디렉션하려면 다음처럼 특정 경로를 입력해요.

`/contact`

홈 페이지, 문의 페이지, 감사 페이지처럼 개별 페이지를 리디렉션할 때 사용하세요.

{% hint style="warning" %}
리디렉션 경로에 특수문자를 넣지 마세요.

특정 경로의 리디렉션을 만들 때는 `?`, `%`, `&`, `=`, `#` 같은 특수문자를 경로에 넣지 마세요. 이런 문자가 있으면 리디렉션이 의도대로 동작하지 않을 수 있어요.

가장 안정적으로 동작하게 하려면 영문 소문자, 숫자, 하이픈(-)으로 이루어진 깔끔한 URL 슬러그를 쓰고, 지원되는 중첩 경로에는 슬래시(/)를 사용하세요.

중첩 경로: 하이퍼클래스는 중첩 URL 경로를 지원해요. 중첩된 페이지의 리디렉션을 만들 때는 `/resources/guides/getting-started`처럼 지원되는 전체 경로를 입력하세요.

권장: `/special-offer`

피해야 할 예: `/special?offer=summer&utm_source=email`

원래 URL에 쿼리 파라미터가 있다면, 리디렉션을 설정할 때 쿼리 문자열은 빼고 깔끔한 URL 경로만 입력하세요.
{% endhint %}

옵션 2: **전체 도메인**

도메인 전체를 다른 목적지로 리디렉션하고 싶을 때 선택하세요.

예를 들어 `yourdomain.com`으로 들어오는 모든 트래픽이 선택한 타겟으로 이동해요.

![전체 도메인 리디렉션을 선택하는 화면](https://jumpshare.com/share/Ua1jVlxEuUOqaZ5if6BL+/Screen+Shot+2026-06-18+at+18.19.01.png)

### 5단계: 리디렉션 타겟 선택하기

**타겟** 섹션에서 방문자를 보낼 목적지를 고르세요.

목적지 유형은 다음 중에서 선택할 수 있어요.

옵션 1: **사용자 지정 URL**

외부 URL이나 원하는 URL로 방문자를 보내고 싶을 때 사용하세요.

1. **사용자 지정 URL**을 선택하세요.
2. 목적지 URL 전체를 입력하세요.
3. **Add Redirect**를 클릭하세요.

감사 페이지, 외부 웹사이트 등 어떤 URL로든 방문자를 보낼 수 있어요.

![사용자 지정 URL로 리디렉션을 추가하는 화면](https://jumpshare.com/share/DWSZTFL7e5eXxvd35cJR+/GIF+Recording+2026-06-18+at+18.29.10.gif)

옵션 2: **퍼널**

선택한 도메인에 연결된 퍼널로 방문자를 보내고 싶을 때 사용하세요.

1. **퍼널**을 선택하세요.
2. 드롭다운에서 퍼널을 고르세요.

   선택한 도메인에 연결된 퍼널만 표시돼요.
3. 방문자가 도착할 퍼널 단계를 선택하세요.

   한 번에 퍼널 단계 하나만 선택할 수 있어요.
4. **Add Redirect**를 클릭하세요.

![퍼널 단계로 리디렉션을 추가하는 화면](https://jumpshare.com/share/3tD1Jh3Xe2dEVvJPDuIP+/GIF+Recording+2026-06-18+at+18.31.06.gif)

옵션 3: **웹사이트**

선택한 도메인에 연결된 웹사이트 페이지로 방문자를 보내고 싶을 때 사용하세요.

1. **웹사이트**를 선택하세요.
2. 드롭다운에서 웹사이트를 고르세요.

   선택한 도메인에 연결된 웹사이트만 표시돼요.
3. 방문자가 도착할 웹사이트 페이지를 선택하세요.
4. **Add Redirect**를 클릭하세요.

![웹사이트 페이지로 리디렉션을 추가하는 화면](https://jumpshare.com/share/ZoRHwjsNLXcQXTCpWTJd+/GIF+Recording+2026-06-18+at+18.33.36.gif)

## 301 리디렉션과 캐노니컬 URL의 차이

예전 URL을 더 이상 쓰지 않고 방문자를 새 목적지로 자동으로 보내야 한다면 301 리디렉션을 사용하세요. 여러 URL에 계속 접속할 수 있어야 하지만 검색엔진이 그중 하나를 대표 URL로 인식하게 하고 싶다면 캐노니컬 URL을 사용하세요.

| 용도 | 301 리디렉션 | 캐노니컬 URL |
| --- | --- | --- |
| 방문자를 다른 곳으로 자동으로 보내야 할 때 | 예 | 아니요 |
| 예전 URL을 새 URL로 영구적으로 옮길 때 | 예 | 아니요 |
| 여러 URL에 계속 접속할 수 있어야 할 때 | 아니요 | 예 |
| 접속 가능한 URL 중 대표 URL을 검색엔진에 알릴 때 | 이동을 통해 간접적으로 알림 | 예 |
| 브라우저의 URL이 바뀌는지 | 예 | 아니요 |

---

## 301 리디렉션 모범 사례

- 오류를 막으려면 절대 URL(예: https://newsite.com/page)을 사용하세요.
- 리디렉션 체인을 피하세요. 가능하면 원래 URL을 최종 목적지로 바로 리디렉션하세요. 예를 들어 `Page A → Page B → Page C`로 설정하지 말고 `Page A → Page C`로 설정하세요.
- 깨진 리디렉션이 없는지 정기적으로 확인해서 제대로 동작하는지 점검하세요.

## 자주 생기는 문제와 해결 방법

| 문제 | 확인할 내용 |
| --- | --- |
| 리디렉션이 동작하지 않아요 | 출발지 도메인이 연결되어 있는지, 출발지 경로가 접속하는 URL과 정확히 일치하는지 확인하세요. |
| 리디렉션 루프가 생겨요 | 목적지가 다시 출발지 URL로 리디렉션되지 않는지 확인하세요. |
| 페이지 경로를 바꾼 뒤 404가 떠요 | 예전 경로에서 새 페이지로 가는 리디렉션이 있는지, 목적지 페이지가 게시되어 있는지 확인하세요. |
| 타겟에서 퍼널이 보이지 않아요 | 퍼널이 선택한 출발지 도메인에 연결되어 있는지 확인하세요. |
| 타겟에서 웹사이트가 보이지 않아요 | 웹사이트가 선택한 출발지 도메인에 연결되어 있는지 확인하세요. |
| 특정 경로 리디렉션이 실패해요 | 쿼리 파라미터나 지원되지 않는 특수문자를 지우고 깔끔한 URL 경로를 사용하세요. |
| 리디렉션이 예상과 다르게 동작해요 | 같은 출발지나 목적지에 영향을 주는 다른 리디렉션이 없는지 확인하세요. |
| Google에 예전 URL이 계속 표시돼요 | 검색엔진이 페이지를 다시 수집하는 데 시간이 걸릴 수 있어요. 필요하면 Google Search Console에서 URL을 검사하고 색인 생성을 요청하세요. |

## 자주 묻는 질문

### 301 리디렉션이 뭔가요?
301 리디렉션은 한 URL에서 다른 URL로 영구적으로 이동시키는 설정이에요. URL이 바뀌었을 때 방문자와 검색엔진을 올바른 웹페이지로 보내 줘요.

### 리디렉션을 만든 뒤에 편집하거나 삭제할 수 있나요?
네. **설정** > **도메인 & URL 리다이렉트** > **URL 리다이렉트**로 돌아가서 기존 리디렉션을 관리하세요.

### 301 리디렉션은 왜 쓰나요?
301 리디렉션을 쓰면 SEO 순위를 유지하고, 깨진 링크를 막고, 방문자 경험을 개선할 수 있어요. 또 도메인 버전을 통합하고, 오래된 링크도 관련 페이지로 연결되게 할 수 있어요.

### 출발지 도메인을 하이퍼클래스에 먼저 추가해야 하나요?
네. 리디렉션을 만들려면 출발지 도메인이 하이퍼클래스 서브 계정에 미리 추가되어 있어야 해요.

### 도메인 전체를 리디렉션할 수 있나요?
네. 리디렉션을 만들 때 도메인 전체를 리디렉션하도록 선택하면, 그 도메인으로 들어오는 모든 트래픽이 선택한 타겟 목적지로 이동해요.

### 페이지 하나나 특정 경로만 리디렉션할 수 있나요?
네. 페이지 하나나 URL 경로 하나만 리디렉션하려면 특정 경로를 선택하세요. 예를 들어 yourdomain.com/test-one을 리디렉션하려면 test-one처럼 특정 경로를 입력하면 돼요.

### 리디렉션 타겟으로 어떤 옵션을 쓸 수 있나요?
방문자를 사용자 지정 URL, 퍼널 단계, 웹사이트 페이지로 보낼 수 있어요. 퍼널과 웹사이트 옵션에는 선택한 도메인에 연결된 항목만 표시돼요.

### 301 리디렉션과 캐노니컬 URL 중 무엇을 써야 하나요?
방문자를 예전 URL에서 새 목적지로 영구적으로 옮겨야 한다면 301 리디렉션을 사용하세요. 여러 URL에 계속 접속할 수 있어야 하고 검색엔진이 그중 하나를 대표 URL로 보게 하고 싶다면 캐노니컬 URL을 사용하세요.

### 퍼널이나 웹사이트 페이지 경로를 바꾼 뒤에 리디렉션을 만들어야 하나요?
네, 이전 URL을 이미 사용하고 있었다면 만드는 것이 좋아요. 리디렉션이 있으면 예전 링크로 들어온 방문자가 새 페이지에 도착하고, 접속할 수 없는 URL로 가지 않아요. 하이퍼클래스의 중첩 경로 관련 문서에서도 운영 중인 URL을 바꾼 뒤에는 301 리디렉션을 추가하도록 권장해요.

### 리디렉션 타겟 드롭다운에 퍼널이나 웹사이트가 보이지 않아요
도메인에 연결된 퍼널과 웹사이트만 목록에 표시돼요.

### 리디렉션 문제는 왜 생기나요?
리디렉션 루프, 404 오류, 느린 로딩 속도가 흔한 원인이에요. 이를 막으려면 URL을 자기 자신으로 리디렉션하지 않았는지, 타겟 페이지가 존재하는지 확인하고, 리디렉션을 너무 많이 쓰지 않도록 하세요.

### 301 리디렉션을 설정할 때 지키면 좋은 모범 사례가 있나요?
절대 URL을 쓰고, 리디렉션 체인을 피하고, 깨진 리디렉션이 없는지 정기적으로 확인하세요. REGEX 리디렉션은 잘못된 리디렉션이 생기지 않도록 신중하게 사용하세요.
