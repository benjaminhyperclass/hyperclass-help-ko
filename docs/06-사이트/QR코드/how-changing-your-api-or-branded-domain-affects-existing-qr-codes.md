# API 또는 브랜드 도메인 변경이 기존 QR코드에 미치는 영향

하이퍼클래스에서 API, 브랜드(branded), 또는 화이트라벨 도메인을 변경하면 기존에 생성된 QR코드가 작동하지 않을 수 있어요. 도메인 변경이 QR코드에 어떤 영향을 미치는지, 변경 전에 무엇을 확인해야 하는지, 그리고 QR코드에 문제가 생겼을 때 어떻게 복구할 수 있는지 안내해 드릴게요.

## 도메인을 변경하면 QR코드에 어떤 일이 생기나요?

하이퍼클래스에서 생성된 QR코드는 설정된 API, 브랜드, 또는 화이트라벨 도메인과 연결된 URL을 사용해요. 이 도메인을 변경하거나 삭제하면 기존 QR코드의 URL이 더 이상 유효하지 않게 되어, 스캔 시 400(Bad Request) 오류가 발생할 수 있어요.

이는 커스텀 도메인을 사용해 QR코드를 생성한 사용자, 특히 인쇄물, 간판, 패키지, 명함, 또는 마케팅 캠페인을 통해 QR코드를 배포한 경우에 영향을 미쳐요.

도메인 변경 전에 생성된 QR코드는 계속 이전 도메인을 가리키기 때문에, 해당 도메인이 비활성화되면 작동하지 않아요. 반면 변경 후에 생성된 QR코드는 새 도메인을 사용하므로 정상적으로 작동해요. 기존 QR코드를 다시 사용하려면 새 도메인으로 QR코드를 재생성하고, 이미 배포된 버전을 교체해야 해요.

**참고: **이미 인쇄되어 배포된 QR코드는 쉽게 회수하거나 재인쇄할 수 없어요. 그래서 도메인 변경이 특히 큰 영향을 미칠 수 있으니 주의가 필요해요.

---

## 도메인 변경 전 준비해야 할 사항

영향을 받는 QR코드를 미리 파악하고, 진행 중인 캠페인이나 고객 대상 자료에 차질이 생기지 않도록 사전에 계획을 세워 보세요.

- 기존에 사용 중인 QR코드가 있는지 확인하세요. QR코드를 사용하지 않는다면 안전하게 변경을 진행할 수 있어요.

- 특히 인쇄물, 간판, 패키지 등 고객 대상 자료에 배포된 QR코드 목록을 정리하세요.

- 영향을 받는 QR코드를 재생성하고 재배포할 계획을 세우세요. 기존 QR코드는 새 도메인으로 자동 이전되지 않아요.

- 꼭 필요한 경우가 아니라면 기존 도메인을 삭제하지 마세요. 새 도메인만 추가하면 되는 상황이라면, 기존 도메인을 그대로 유지할 수 있는지 검토해 보세요.

- 영향을 최소화하기 위해 트래픽이 적은 시간대에 도메인 변경을 진행하는 것이 좋아요.

## 도메인 변경 후 QR코드 교체하는 방법

새 도메인 설정이 완료되면, 교체용 QR코드를 생성하고 기존 버전이 사용되던 위치를 업데이트해야 해요.

- 
새 도메인을 사용해 QR코드를 재생성하세요.


- 
새로 생성한 QR코드를 스캔해서 400 오류 없이 올바른 페이지로 연결되는지 확인하세요.


- 
웹사이트, 이메일, PDF, 디지털 간판 등에 있는 기존 QR코드를 교체하세요.


- 
영향을 받는 QR코드가 포함된 인쇄물은 재인쇄하여 다시 배포하세요.


QR코드 생성 방법에 대한 자세한 안내는 [QR코드 생성 및 다운로드 가이드](https://hyperclass.gitbook.io/hyperclass-docs/en/support/solutions/articles/155000004583)를 참고하세요.

## 자주 묻는 질문

**Q: 이미 도메인을 변경했는데 QR코드에서 400 오류가 나요. 복구할 수 있나요?**

가능하지만, 중요한 트레이드오프가 있다는 점을 알아두세요. 이전 도메인을 다시 추가하고 해당 DNS 레코드를 복원하면, 그 도메인에서 원래 생성됐던 QR코드는 다시 작동할 수 있어요.

하지만 이렇게 하면 문제가 반대로 발생해요. 도메인 변경 후 새 도메인으로 새로운 QR코드를 생성했다면, 이전 도메인을 다시 추가하는 순간 그 새 QR코드들이 작동을 멈추고 대신 400 오류가 발생하게 돼요.

즉, 어느 시점이든 QR코드는 현재 활성화된 도메인에서만 작동해요. 이전 도메인을 다시 추가하면 기존 QR코드는 복구되지만 새 QR코드는 깨지고, 반대의 경우도 마찬가지예요. 이전 도메인과 새 도메인의 QR코드가 동시에 작동하는 설정은 불가능해요.

이런 상황에 처해 있다면, 추가 변경을 하기 전에 [하이퍼클래스 고객지원](https://hyperclass.gitbook.io/hyperclass-docs/en/support/solutions/articles/155000000969)에 문의해서 영향을 최소화할 수 있는 방법을 함께 찾아보세요.

**Q: 변경 후 새로 만든 QR코드는 정상 작동하나요?**

네. 도메인 변경 이후에 생성된 QR코드는 새 도메인을 사용하므로 정상적으로 작동해요.

**Q: QR코드에 영향을 주지 않고 도메인을 변경할 수 있나요?**

아니요. API/브랜드/화이트라벨 도메인을 변경하거나 삭제하면 QR코드가 의존하는 DNS 레코드에 영향을 미쳐요. 현재 기존 QR코드를 새 도메인으로 자동 이전하는 기능은 제공되지 않아요.

**Q: QR코드 외에 다른 것에도 영향이 있나요?**

도메인을 변경하면 기존 도메인의 DNS 레코드에 의존하는 다른 서비스에도 영향을 줄 수 있어요. 이 문서는 QR코드를 중심으로 다루고 있지만, 변경 전에 연동된 모든 서비스를 함께 점검해 보시길 권장해요.
