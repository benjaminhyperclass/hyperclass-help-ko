# RCS 메시징 요금과 과금 기준

RCS 요금이 메시지 유형, 방향, 국가에 따라 어떻게 계산되는지 설명해요. 세그먼트, 통신사 수수료, 미국 발신자 등록 비용도 함께 다뤄요.

## 개요

RCS 요금은 세 가지 기준으로 정해져요.

- 메시지 분류: 기본 RCS 또는 단일 RCS
- 메시지 방향: 발신 또는 수신
- 국가: 메시지 방향에 따라 상대방 전화번호로 정해요.

요금 계산 방식은 **미국**과 미국 외 국가가 달라요. 미국에서 발신하려면 서비스를 시작하기 전에 1회성 등록 비용과 연간 등록 비용도 내야 해요.

## 세그먼트란?

세그먼트는 메시지 본문을 160 UTF-8 바이트 단위로 나눈 것이에요. 나누어떨어지지 않으면 올림해요. 글자 수가 아니라 바이트 길이로 계산하기 때문에, 이모지나 라틴 문자가 아닌 글자는 한 글자에 더 많은 바이트를 써요.

세그먼트 수는 항상 메시지 본문을 기준으로 다시 계산해요. Twilio가 알려 주는 세그먼트 수는 RCS에서는 정확하지 않아서 쓰지 않아요. 본문이 비어 있어도 1세그먼트로 계산해요.

## RCS 메시지 유형

RCS 메시지는 기본 RCS와 단일 RCS 두 가지로 나뉘어요.

어느 쪽이냐에 따라 세그먼트당으로 과금할지 메시지당으로 과금할지, 그리고 어떤 RCS 요금을 적용할지가 달라져요.

### 기본 RCS

텍스트만 있는 메시지이고, 분류 기준은 국가마다 달라요.

텍스트만 있는 RCS 메시지는 기본으로 분류될 수 있어요. 정확한 기준은 국가에 따라 달라요.

- 미국: 텍스트만 있는 RCS 메시지는 길이와 관계없이 항상 기본이에요. 160 UTF-8 바이트를 넘어도 기본으로 남고, 과금 대상 세그먼트 수만 늘어나요.
- 미국 외 국가: 본문이 160 UTF-8 바이트 이하이면 기본이에요. 160 UTF-8 바이트를 넘으면 단일 RCS로 분류해 과금해요. 과금할 때 세그먼트로 나누지 않아서, 긴 메시지는 여러 세그먼트가 아니라 메시지 1건으로 봐요.

요약 표

| 지역 | 기본 RCS 기준 | 세그먼트 구분 / 과금 |
| --- | --- | --- |
| 미국 | 텍스트만 있으면 길이 무관 | 160바이트 단위로 나눠 세그먼트당 과금 |
| 미국 외 | 텍스트만 있고 160 UTF-8 바이트 이하 | 세그먼트로 나누지 않음, 160바이트 초과 시 단일 RCS |

### 단일 RCS

미디어가 있거나, 미국 외 국가에서 긴 텍스트인 경우예요.

다음 중 하나에 해당하면 단일 RCS로 분류해요.

- 메시지에 첨부파일이나 카드 미디어가 있어요.
- 미국 외 국가에서 텍스트만 있는 메시지가 160 UTF-8 바이트를 넘어요.

첨부파일이나 카드 미디어가 있으면 국가나 텍스트 길이와 관계없이 단일로 분류해요.

{% hint style="warning" %}
미국에서 텍스트만 있는 메시지는 길이가 길어도 단일이 되지 않아요. 기본으로 남고 세그먼트 수에 따라 과금해요.
{% endhint %}

## RCS 세그먼트 계산

RCS 세그먼트는 문자 메시지 본문을 160바이트씩 나눈 단위로, 요금 계산에 쓰여요. 미국의 기본 RCS 메시지는 세그먼트 기준으로 과금해요.

1세그먼트는 메시지 본문의 160 UTF-8 바이트예요. 본문의 UTF-8 바이트 길이를 160으로 나눈 뒤 올림하면 세그먼트 수가 나와요.

```
Segments = max(1, ceil(UTF-8 byte length ÷ 160))
```

예시

| 메시지 본문 | 과금 세그먼트 |
| --- | --- |
| 빈 본문 | 1 |
| 1–160 UTF-8 바이트 | 1 |
| 161–320 UTF-8 바이트 | 2 |
| 321–480 UTF-8 바이트 | 3 |
| 481–640 UTF-8 바이트 | 4 |

#### 예시 1

메시지가 "Hello, this is a test."(22자, 모두 1바이트)예요. 총 22바이트이므로 세그먼트는 1개예요.

#### 예시 2

영문 200자(200바이트)예요. ceil(200 / 160) = 2이므로 세그먼트는 2개예요.

#### 예시 3

이모지 80개(이모지 하나가 4바이트라서 320바이트)예요. ceil(320 / 160) = 2이므로 세그먼트는 2개예요.

### 바이트와 글자 수의 차이

세그먼트는 글자 수가 아니라 UTF-8 바이트 기준으로 계산해요. 글자에 따라 필요한 바이트 수가 다르기 때문이에요.

- 일반적인 영문 글자는 대부분 1바이트예요.
- 라틴 문자가 아닌 글자는 대부분 여러 바이트를 써요.
- 이모지도 보통 여러 바이트를 써요.

그래서 눈에 보이는 글자 수가 같아도 세그먼트 수는 다를 수 있어요.

### 세그먼트를 계산하는 방식

하이퍼클래스는 메시지 본문에서 직접 세그먼트 수를 다시 계산해요. Twilio가 알려 주는 세그먼트 수는 RCS 과금 세그먼트 수를 정확히 나타내지 못할 수 있어서 RCS 세그먼트 과금에는 쓰지 않아요. 메시지 본문이 비어 있어도 1세그먼트로 계산해요.

## 과금 기준 국가 정하기

RCS 요금에 적용하는 국가는 메시지 방향에 따라 달라요.

### RCS 발신

받는 번호의 국가를 기준으로 해요.

예시: 하이퍼클래스 → 영국 고객이면 영국 RCS 요금을 적용해요.

### RCS 수신

보내는 사람(휴대폰)의 국가를 기준으로 해요.

예시: 미국 고객 → 하이퍼클래스이면 미국 RCS 요금을 적용해요.

#### 왜 중요한가요?

국가를 먼저 정한 뒤에 기본 또는 단일 과금 규칙을 적용하기 때문이에요.

## 미국 RCS 요금

미국 RCS 요금은 미국 외 국가와 방식이 달라요. 미국에서는 이렇게 과금해요.

- 기본 발신: 세그먼트당
- 기본 수신: 세그먼트당
- 단일 / 리치 발신: 메시지당
- 단일 / 리치 수신: 메시지당

하이퍼클래스의 현재 미국 요금 안내에도 RCS 리치 텍스트는 세그먼트당, RCS 리치 미디어는 메시지당 과금한다고 되어 있어요.
| 지역 | 메시지 유형 | 방향 | 과금 단위 | 가격(USD $) |
| --- | --- | --- | --- | --- |
| 미국 | 기본 RCS 텍스트 | 발신 | 세그먼트당(160 UTF-8 바이트) | $0.0083 |
| 미국 | 기본 RCS 텍스트 | 수신 | 세그먼트당(160 UTF-8 바이트) | $0.0083 |
| 미국 | 리치 / 단일 RCS | 수신 | 메시지당 | $0.0165 |
| 미국 | 리치 / 단일 RCS | 발신 | 메시지당 | $0.0220 |

{% hint style="warning" %}
미국의 기본 RCS는 수신과 발신 모두 세그먼트당 과금해요.
{% endhint %}

### 미국 과금 예시

#### 예시 1 — 짧은 텍스트 메시지

미국으로 보내는 RCS 메시지가 120 UTF-8 바이트이고 미디어가 없어요. 텍스트만 있는 미국 기본 RCS이고 1세그먼트예요. 요금은 1 × $0.0083 = $0.0083이에요.

#### 예시 2 — 긴 텍스트 메시지

미국으로 보내는 메시지가 350 UTF-8 바이트이고 미디어가 없어요. 미국에서 텍스트만 있는 메시지이므로 길이와 관계없이 기본 RCS로 남아요. 세그먼트는 ceil(350 ÷ 160) = 3개예요. 요금은 3 × $0.0083 = $0.0249예요. 160바이트를 넘었다는 이유만으로 단일이 되지는 않아요.

#### 예시 3 — 미디어가 있는 메시지

미국으로 보내는 RCS 메시지에 텍스트와 이미지가 들어 있어요. 미디어가 있으므로 단일 / 리치 RCS로 분류하고 메시지당 1회 과금해요. 요금은 $0.0220이에요. 이 단일 메시지는 텍스트 길이 때문에 RCS 세그먼트가 추가로 과금되지 않아요.

## 미국 외 국가 RCS 요금

미국 외 국가는 분류 방식이 달라요. 미국 외 국가에서는 이렇게 과금해요.

- 기본: 160 UTF-8 바이트 이하이면 메시지당
- 단일: 메시지당
- 수신: 메시지당

적용하는 고정 요금은 국가마다 달라요. 하이퍼클래스의 국가별 요금 안내에서도 미국 외 RCS 발신을 기본과 단일 요금으로 나누어 보여 줘요.

### 텍스트만 있는 메시지

160 UTF-8 바이트 이하이면 기본이고, 160 UTF-8 바이트를 넘으면 단일이에요. 그래서 미국 밖에서는 메시지 길이에 따라 실제 요금이 달라질 수 있어요.

### 미디어가 있는 메시지

첨부파일이나 카드 미디어가 있으면 텍스트 길이와 관계없이 단일로 분류해요.

### 미국 외 국가 예시

#### 예시 1 — 짧은 텍스트 메시지

미국 외 국가로 보내는 메시지가 100 UTF-8 바이트이고 첨부파일이나 카드 미디어가 없어요. 이 메시지는 기본 RCS이고, 해당 국가의 기본 요금으로 1회 과금해요.

#### 예시 2 — 긴 텍스트 메시지

미국 외 국가로 보내는 메시지가 250 UTF-8 바이트예요. 첨부파일이나 미디어가 없어도 기본 한도인 160바이트를 넘어요. 그래서 단일 RCS이고, 해당 국가의 단일 요금으로 1회 과금해요. 기본 세그먼트 2개로 과금하지 않아요.

#### 예시 3 — 미디어가 있는 메시지

미국 외 국가로 보내는 메시지가 텍스트는 50 UTF-8 바이트뿐이지만 이미지도 들어 있어요. 미디어가 있으므로 단일 RCS이고, 해당 국가의 단일 요금으로 1회 과금해요.

| 카드 미디어 있음 | 단일 | 단일 |

{% hint style="info" %}

{% endhint %}

## RCS 통신사 수수료

기본 RCS 메시지 요금과 별도로 통신사 수수료가 붙을 수 있어요. Twilio는 통신사별 RCS 수수료를 공개하고 있고, 이 수수료는 통신사, 메시지 유형, 방향에 따라 달라요.

하이퍼클래스에서는 통신사 수수료를 다음과 같이 청구해요.

| 계정 / 사용 범주 | 통신사 수수료 청구 방식 |
| --- | --- |
| 사용 범주 | Twilio에서 직접 청구 |
| 에이전시 계정 | Twilio와 같은 요금 |
| 서브 계정 | Twilio 요금 + 5% 가산 |

{% hint style="info" %}
메시지당 통신사 수수료는 기본 RCS 메시지 요금과 따로 봐야 해요. 다음 섹션에서 설명하는 미국 발신자 등록의 1회성·연간 비용과도 별개예요.
{% endhint %}

## 미국 RCS 발신자 등록 비용과 소요 기간

RCS 발신자가 미국 수신자에게 메시지를 보내려면 Google RCS 등록과 별도로 미국 등록을 마쳐야 해요. 미국 등록에는 메시지당 요금과는 별개인 외부 업체 비용이 들어요. 이 비용은 Twilio가 정하는 것이 아니라 브랜드 인증 업체와 미국 통신사에서 부과해요.

| 비용 | 청구 주체 | 금액(USD) | 주기 |
| --- | --- | --- | --- |
| 브랜드 인증 | Aegis(미국 브랜드 인증 외부 업체) | $200 | 매년 |
| 통신사 온보딩(T-Mobile 제출) | T-Mobile 등 미국 통신사 | $500 | 새 RCS 발신자마다 1회 |

예시 — 첫해 비용

브랜드 하나가 새 미국 RCS 발신자를 1개 등록해요. 첫해 등록 비용은 $200 + $500 = $700이에요. 이후 매년 브랜드 인증 갱신 비용으로 $200이 들어요. 메시지당 RCS 요금과 통신사 수수료는 여기에 별도로 청구돼요.

### 비용이 청구되는 시점

- 동의 필요: 등록을 제출하려면 먼저 미국 RCS 온보딩 비용에 동의해야 해요.
- Aegis 브랜드 인증 비용은 Twilio가 제출 데이터를 검토하기 전까지는 청구되지 않아요.
- 통신사 온보딩 비용은 제출이 승인된 경우에만 청구돼요. 미국 등록 중에 표시되는 총액은 승인 시점에 청구돼요.
- 승인은 보장되지 않아요. 비용을 내더라도 최종 승인과 서비스 시작이 보장되지는 않아요.

{% hint style="warning" %}
발신자 프로필이 승인되어 라이브로 전환되면 Aegis 비용과 통신사 등록 비용은 환불되지 않아요.
{% endhint %}

## RCS 과금 판단 순서

RCS 메시지가 어떻게 과금되는지 아래 순서로 따져 보세요.

### 1단계 — 국가 확인

발신 메시지는 받는 번호의 국가를 기준으로 해요. 수신 메시지는 보내는 사람(휴대폰)의 국가를 기준으로 해요.

### 2단계 — 미디어 확인

메시지에 첨부파일이나 카드 미디어가 있나요? 예이면 단일 RCS예요. 해당 국가의 단일 / 리치 요금으로 1회 과금해요. 아니오이면 3단계로 가세요.

### 3단계 — 미국인지 확인

미국이면 텍스트만 있는 메시지는 길이와 관계없이 기본 RCS예요. Segments = max(1, ceil(UTF-8 byte length ÷ 160))로 세그먼트 수를 구한 뒤, RCS 요금 = 세그먼트 수 × 미국 기본 요금으로 계산해요.

미국 외 국가이면 UTF-8 바이트 길이를 확인해요. 160바이트 이하이면 기본 RCS이고, 해당 국가의 기본 요금으로 1회 과금해요. 160바이트를 넘으면 단일 RCS이고, 해당 국가의 단일 요금으로 1회 과금해요.

### 4단계 — 통신사 수수료 적용

해당하는 Twilio 통신사 수수료와 하이퍼클래스 가산 규칙을 적용해요. 미국 발신자 등록 비용(브랜드 인증, 통신사 온보딩)은 메시지마다 붙지 않고 따로 청구돼요.

## 자주 묻는 질문

### 세그먼트 수가 Twilio에서 보이는 수와 왜 달라요?

세그먼트는 항상 메시지 본문의 UTF-8 바이트 길이로 직접 다시 계산해요. Twilio가 알려 주는 세그먼트 수는 RCS 과금 세그먼트 수를 정확히 나타내지 못할 수 있어서 RCS 세그먼트 과금에는 쓰지 않아요.

### 미국에서 긴 문자 메시지를 보내면 여러 건으로 과금되나요?

아니요. 미국에서 텍스트만 있는 메시지는 길이와 관계없이 기본 RCS로 남아요. 길이가 늘면 과금 대상 세그먼트 수만 늘어나요. 단일로 바뀌지도 않고, 여러 건의 메시지로 따로 과금되지도 않아요.

### 글자 수가 같은데 요금이 다른 이유가 뭐예요?

요금은 눈에 보이는 글자 수가 아니라 UTF-8 바이트를 기준으로 계산해요. 일반 영문은 보통 1바이트인 반면, 라틴 문자가 아닌 글자와 이모지는 여러 바이트를 써요. 그래서 글자 수가 같아도 바이트 길이가 달라지고, 세그먼트 수도 달라질 수 있어요.

### 이미지나 첨부파일을 넣으면 과금 방식이 바뀌나요?

네. 첨부파일이나 카드 미디어가 있으면 국가나 텍스트 길이와 관계없이 단일 / 리치 RCS로 분류돼요. 단일 메시지는 세그먼트당이 아니라 메시지당 1회 과금해요.

### 주고받는 두 사람이 서로 다른 나라에 있으면 국가는 어떻게 정해요?

방향에 따라 달라요. 발신 메시지는 받는 번호의 국가를 쓰고, 수신 메시지는 보내는 사람(휴대폰)의 국가를 써요. 이 국가를 먼저 정한 뒤에 기본 또는 단일 과금 규칙을 적용해요.

### 통신사 수수료는 메시지 요금에 포함되나요, 따로 내나요?

통신사 수수료는 기본 RCS 메시지 요금과 별개로 추가돼요. 서브 계정은 Twilio 통신사 요금에 5%가 가산되고, 에이전시 계정은 Twilio와 같은 요금을 내요.

### 미국에서 RCS 발신자를 등록하려면 어떤 비용이 드나요?

외부 업체 비용 두 가지가 들어요. Aegis가 부과하는 연 $200 브랜드 인증 비용과, T-Mobile 같은 미국 통신사가 새 RCS 발신자마다 1회 부과하는 $500 통신사 온보딩 비용이에요. 이 비용은 메시지당 요금과 별개예요.

### 미국 등록 비용은 언제 청구되고, 환불받을 수 있나요?

Aegis 인증 비용은 Twilio가 제출 내용을 검토하기 전까지는 청구되지 않아요. 통신사 온보딩 비용은 제출이 승인된 경우에만 청구돼요. 발신자가 승인되어 라이브가 되면 이 비용은 환불되지 않고, 비용을 냈다고 승인이 보장되지도 않아요.

### 미국 RCS 발신자 승인에는 얼마나 걸려요?

대부분의 발신자는 약 5–9주 안에 마쳐요. Twilio 검토 2–8주, Aegis 브랜드 인증 약 1주, 통신사 검토 3–6주가 걸려요. 통신사 네트워크 동결 기간이나 연휴가 있으면 더 늦어질 수 있어요.

### 여기에 나온 요금이 최종 요금인가요?

RCS 요금은 국가마다 다르고 시간이 지나면서 바뀔 수 있어요. Twilio도 메시징 요금과 통신사 수수료가 바뀔 수 있다고 안내해요. 정확한 요금이 필요하면 최신 국가별 요금을 확인하세요.
