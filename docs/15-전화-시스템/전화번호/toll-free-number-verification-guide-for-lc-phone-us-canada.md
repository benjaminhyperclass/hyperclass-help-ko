# 수신자 부담 번호 인증 가이드 (하이퍼클래스 전화, 미국/캐나다)

미국과 캐나다의 수신자 부담 번호(Toll-Free)로 SMS/MMS를 보내려면 먼저 인증을 받아야 해요. 이 문서에서는 인증 신청 절차, 수신 동의 증빙을 준비하는 방법, 승인 상태 확인 방법, 자주 생기는 문제의 해결 방법을 안내해요.

## 개요

수신자 부담 번호 인증은 번호, 번호를 사용하는 실제 사업자, 그 사업자의 메시징 사용 사례를 통신사에 등록하는 절차예요. 하이퍼클래스 전화의 수신자 부담 번호로 미국 또는 캐나다 수신자에게 SMS나 MMS를 보내려면 인증이 필요해요.

신청이 승인되려면 다음 항목이 모두 갖춰져야 해요.

- 일관된 사업자 정보
- 누구나 볼 수 있는 웹사이트 또는 공개 프로필
- 구체적인 사용 사례 설명
- 실제 발송할 메시지와 비슷한 샘플
- 수신자가 어떻게 메시지 수신에 동의했는지 확인할 수 있는 증빙

이 문서는 앱 안의 인증 절차를 처음부터 끝까지 다루고, 아래 부록에 A2P 수신 동의 가이드도 담았어요. 별도 문서를 열지 않고도 수신 동의 증빙을 준비할 수 있어요.

{% hint style="warning" %}
**Verified (Approved)**(인증 완료(승인됨)) 상태인 수신자 부담 번호만 미국과 캐나다 수신자에게 SMS/MMS를 보낼 수 있어요. **Restricted (Unverified)**(제한됨(미인증)), **Pending Verification**(인증 대기 중), **거절됨** 상태의 번호는 승인될 때까지 메시지 발송이 차단돼요.

인증되지 않은 수신자 부담 번호로 발송하면 **Error 30032**가 나타날 수 있어요. **Error 30007**은 통신사 필터링을 뜻해요. 메시지 내용, 수신 동의, 발신자 식별 등이 통신사 기준에 맞지 않을 때도 나타날 수 있어요. 발송 시도가 접수되었다면 해당 메시지 요금이 청구될 수 있어요.

수신자 부담 번호 인증은 메시징에만 적용돼요. 음성 통화에는 영향이 없어요.
{% endhint %}

## 수신자 부담 번호 인증이란?

수신자 부담 번호 인증은 누가 이 번호로 비즈니스 메시지를 보내는지, 수신자가 어떤 메시지를 받는지, 수신자가 어떻게 동의했는지를 확인하는 절차예요. 통신사는 이 심사를 통해 정상적인 앱 기반 메시지와 원치 않는 스팸·악용 트래픽을 구분해요.

이 요건은 미국 또는 캐나다 수신자 부담 번호에서 미국·캐나다 수신자에게 보내는 SMS와 MMS에 적용돼요. 메시징을 켜려면 번호마다 승인된 인증 기록이 따로 있어야 해요.

수신자 부담 번호 인증은 A2P 10DLC 등록과 달라요. A2P 10DLC는 조건에 맞는 미국 로컬 10자리 번호에 적용되고, 수신자 부담 번호 인증은 수신자 부담 번호의 메시징에 적용돼요. 두 절차 모두 정확한 발신자 정보, 투명한 메시징 사용 사례, 수신자 동의 기록이 필요해요.

## 인증을 받으면 좋은 점

인증을 받으면 통신사가 발송 전에 발신자와 메시징 프로그램을 평가할 수 있어요. 정보를 빠짐없이 정확하게 제출하면 피할 수 있는 심사 지연도 줄어요.

- 메시징 자격: 승인된 수신자 부담 번호로 미국·캐나다 수신자에게 SMS/MMS를 보낼 수 있어요.
- 전달률 개선: 번호가 미인증이라는 이유만으로 메시지가 차단될 위험이 줄어요.
- 통신사에 투명하게 공개: 실제 사업자, 사용 사례, 메시지 샘플, 수신 동의 방식이 발신 번호와 연결돼요.
- 수신 동의 책임 확인: 수신자가 제출한 내용의 메시지 수신에 어떻게 동의했는지 기록으로 남아요.
- 빠른 문제 해결: 메시지가 차단되거나 인증이 거절되었을 때 상태와 인증 기록을 확인할 수 있어요.
- 브랜드 신뢰도: 수신자와 발신 번호의 평판을 지키는 책임 있는 메시징을 뒷받침해요.

## 시작하기 전에 준비할 것

수신자 부담 번호 인증에는 사업자 세금 번호나 EIN이 필요하지 않아요.

다음 정보를 미리 준비하세요.

- 실제 사업자의 법적 명칭
- 공개 웹사이트 또는 공개 소셜 프로필
- 사업자 연락처
- 사업장 실제 주소
- 메시징 사용 사례
- 수신 동의 증빙
- 대표 샘플 메시지

| 준비물 | 심사자가 확인하는 내용 |
| --- | --- |
| 하이퍼클래스 전화 수신자 부담 번호 | 올바른 서브 계정에 번호가 있고 **인증 필요**로 표시돼요. |
| 법인명 또는 실제 사업자명 | 입력한 사업자가 수신자가 실제로 거래하는 조직이고, 제출 내용 전체에서 일관돼요. |
| 누구나 볼 수 있는 웹사이트 또는 공개 소셜 프로필 | 공개 페이지가 같은 사업자를 나타내고, 기재한 상품·서비스·메시징 사용 사례와 맞아요. |
| 사업자 연락처와 소재지 | 실제 담당자와 사업장 주소를 발신자와 연결할 수 있어요. |
| 월 예상 발송량과 사용 사례 카테고리 | 선택한 카테고리와 발송량이 예상 트래픽을 정확하게 보여 줘요. |
| 수신 동의 방식과 공개 증빙 URL | 증빙에 수신자가 어디서 어떻게 해당 메시지 유형에 동의하는지 분명히 나타나요. |
| 상세한 사용 사례 설명 | 수신 대상, 메시지 목적, 수신 동의를 받는 경로, 발송 흐름이 설명에 담겨 있어요. |
| 대표 샘플 메시지 | 샘플이 선택한 카테고리와 맞고, 사업자명, 맥락, 해당하는 경우 수신거부 문구가 들어 있어요. |
| 화면에서 요청하는 경우의 추가 사업자 항목 | 절차에서 요구하면 DBA, 사업자 유형, 등록 기관, 등록 번호, 등록 국가를 입력할 수 있어요. |

모든 수신자 부담 번호 인증 신청에 사업자 세금 번호가 필요한 것은 아니에요. 사업자 유형과 인증 내용에 따라 하이퍼클래스가 추가 등록 정보를 요청할 수 있어요.

에이전시, 소프트웨어 플랫폼, 재판매 업체는 법인으로 입력하지 마세요. 단, 그 조직이 실제 발신자이고 메시지 내용을 직접 만들어 자기 이름으로 보내는 경우는 예외예요.

이전에 별도 문서로 안내하던 A2P 수신 동의 가이드는 아래 [부록 A: A2P 수신 동의 가이드](#부록-a-a2p-수신-동의-가이드)에 포함되어 있어요.

## 수신자 부담 번호 인증하기

앱 안의 인증 절차는 사업자 정보, 소재지, 메시징 사용 사례, 수신 동의 증빙, 샘플 메시지를 세 단계에 걸쳐 받아요. 모든 항목을 정확하고 공개된 정보로, 실제 사업자와 일치하게 입력하세요.

### 1단계: 수신자 부담 번호 인증 폼 열기

1. 수신자 부담 번호가 있는 서브 계정을 열어요.
2. **설정 > 전화 시스템**으로 이동해요.
3. **번호 관리**를 열어요.
4. 인증할 수신자 부담 번호 아래의 **인증 필요**를 클릭해요.

![서브 계정에서 설정, 전화 시스템, 번호 관리로 이동하는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155046270449/original/3K-C0zI-z1OND0dDXKxBJTAFEGHDQvOfcw.gif?1746634699)

서브 계정의 **설정**에서 **전화 시스템**을 연 다음 **번호 관리**를 선택하세요.

![번호 관리에서 수신자 부담 번호 아래에 인증 필요가 표시된 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155046270937/original/w_lzeGYIQ8d8DXqxYg4BRIL38uFANvywBg.png?1746634966)

등록하려는 수신자 부담 번호의 **인증 필요**를 선택하세요.

### 2단계: 사업자 정보와 연락처 입력하기

수신자가 발신자로 알아보는 실제 사업자의 정보와 연락처를 입력해요.

1. **Legal Entity Name**(법인명)에 공개 웹사이트에 나와 있는 사업자명을 입력해요.
2. **웹사이트 URL**에 실제 사업자의 공개 웹사이트 주소를 입력해요. 웹사이트가 없으면 인정되는 공개 비즈니스 프로필을 사용하세요.
3. **연락처**에 담당자의 이름, 성, 이메일, 국가 코드, 전화번호를 입력해요.

이 단계에서는 EIN이나 사업자 등록 번호가 필요하지 않아요.

{% hint style="warning" %}
브랜드 정보가 서로 다르면 안 돼요. 웹사이트가 비공개이거나, 운영되지 않거나, 사업자와 관련이 없거나, 재판매 업체의 브랜드를 쓰고 있으면 심사자가 실제 사업자를 확인하지 못해 거절될 수 있어요.
{% endhint %}

![사업자 법적 정보, 공개 웹사이트, 담당자 연락처를 입력하는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155081210122/original/0UrvlBZrITi2uRhO7SKBddbL-8CFDx504g.png?1789659337)

실제 사업자의 법적 정보, 공개 웹사이트, 담당자 연락처를 입력하세요.

### 3단계: 사업장 소재지 입력하기

수신자가 거래하는 실제 사업자의 소재지를 입력해요. 앞 단계에서 입력한 사업자와 연결되는 전체 주소를 쓰세요.

1. **국가**를 선택해요.
2. **State, province, or region**(주/도/지역)을 입력해요.
3. **주소 1**을 입력해요.
4. **도시**를 입력해요.
5. **Postal or ZIP code**(우편번호)를 입력해요.
6. **Continue to Messaging Use Case**(메시징 사용 사례로 계속)를 클릭해요.

![메시징 수신자 부담 번호 인증의 사업장 소재지 입력 항목](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155046277556/original/hIG-rvXKOUsCL0awJuI4zX1CViN1DLsHfQ.png?1746643001)

사업장 소재지를 모두 입력한 다음 메시징 사용 사례로 넘어가세요.

### 4단계: 메시징 사용 사례와 수신 동의 설명하기

이 단계에서는 무엇을 보내는지, 누가 받는지, 수신 동의를 어떻게 받는지, 그 과정을 무엇으로 증명하는지 설명해야 해요. 선택하는 항목은 모두 이 수신자 부담 번호에서 실제로 운영할 프로그램과 맞아야 해요.

1. 예상 발송량에 맞게 **Estimated Monthly Volume**(월 예상 발송량)을 선택해요.
2. 실제 수신 동의 방식에 맞게 **Opt-In Type**(수신 동의 유형)을 선택해요. 선택지는 **Mobile/QR Code**(모바일/QR 코드), **Paper Form**(종이 양식), **Verbal**(구두), **Via Text**(문자), **Web Form**(웹 폼)이에요.
3. 해당하는 **Use Case Category**(사용 사례 카테고리)를 모두 선택해요. 프로모션 내용을 보낸다면 **마케팅**도 포함하세요.
4. 수신 동의 전체 과정을 보여 주는 공개 이미지 URL을 **Opt-In Workflow Image URL**(수신 동의 흐름 이미지 URL)에 입력해요.
5. **사용 사례 설명**에 수신 대상, 메시지 목적, 수신 동의를 받는 경로, 발송 흐름이 드러나도록 구체적으로 써요.
6. **메시지 내용**에 선택한 카테고리와 맞는 대표 메시지를 입력해요. 알아볼 수 있는 사업자명을 넣고, 해당하는 경우 수신거부 문구도 넣으세요.

![사용 가능한 수신 동의 유형이 표시된 메시징 사용 사례 폼](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155048688548/original/OCr0wofU63tEey-zYvKaTQH5ocCRZcFGFw.png?1750664974)

제출하는 증빙 및 수신 동의 과정과 맞는 수신 동의 유형을 선택하세요.

#### 좋은 사용 사례 설명 예시

"이 수신자 부담 번호는 공개 예약 폼에서 직접 수신에 동의한 [사업자명] 고객에게 예약 확인, 일정 변경 안내, 서비스 후속 안내를 보냅니다. 메시지는 예약이나 서비스 이벤트가 생기면 하이퍼클래스에서 발송됩니다. 수신자는 HELP를 보내 도움을 받거나 STOP을 보내 수신을 거부할 수 있습니다."

#### 좋은 샘플 메시지 예시

"[사업자명]: [날짜/시간] 예약이 확정되었습니다. 확인하려면 C를 보내시거나 [지원 번호]로 문의하세요. 수신을 거부하려면 STOP을 보내세요."

### 5단계: 검토하고 제출하기

1. 사업자 정보, 웹사이트, 소재지, 카테고리, 수신 동의 증빙, 설명, 샘플 메시지가 모두 서로 맞는지 확인해요.
2. 수신 동의 증빙 URL을 시크릿 창(비공개 브라우저 창)에서 열어, 로그인 없이 열리는지 확인해요.
3. **서비스 이용약관** 동의 체크박스를 선택해요.
4. **Send Information for Verification**(인증 정보 보내기)을 클릭해요.
5. 하이퍼클래스가 권한이 있는 사용자에게 KYC 또는 본인 인증을 요청하면 **KYC 인증**을 완료해요.

![수신자 부담 번호 인증 폼을 검토하고 제출하는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155046281345/original/eiS5vEPfdMRq19OZh7YuWJF5Gu6Ew8Rlew.gif?1746648641)

입력한 사용 사례를 검토하고, **서비스 이용약관**에 동의한 다음 인증 정보를 보내세요.

## 부록 A: A2P 수신 동의 가이드

앱을 통해 보내는 비즈니스 메시지는 A2P(application-to-person) 트래픽이에요. 수신자 부담 번호 인증도 같은 기본 질문을 심사해요. 누가 보내는지, 수신자가 무엇을 받는지, 수신자 한 명 한 명이 해당 메시지에 알고 동의했다는 것을 사업자가 어떻게 증명하는지예요.

### 수신 동의 기본 규칙

- 수신 동의는 실제 사업자가 직접 받은 것이어야 해요. 구매, 대여, 공유, 이전한 연락처 목록을 수신 동의 증거로 쓰지 마세요.
- 수신 동의는 적극적이어야 해요. 수신자가 메시지 수신에 동의하는 분명한 행동을 해야 해요.
- 수신 동의는 선택 사항이어야 해요. 프로모션 메시지 수신에 동의하지 않아도 폼을 제출하거나 구매를 완료할 수 있어야 해요.
- 체크박스를 미리 선택해 두면 안 돼요. 수신자가 원하는 동의 항목을 직접 선택해야 해요.
- 마케팅 수신 동의와 비마케팅 수신 동의는 따로 받아야 해요. 두 가지 메시지를 모두 보낸다면 별도의 선택지를 쓰세요.
- 고지 내용이 완전해야 해요. 사업자를 밝히고, 메시지 유형을 설명하고, 발송 빈도를 알리고, 메시지 및 데이터 요금이 부과될 수 있음을 안내하세요. 해당하는 경우 HELP와 STOP 안내도 넣으세요.
- 제출한 방식이 실제와 같아야 해요. 선택한 수신 동의 유형, 증빙 URL, 사용 사례 설명, 웹사이트, 실제 운영 흐름이 같은 이야기를 해야 해요.
- 수신거부를 지켜야 해요. 유효한 수신거부가 접수되면 메시지 발송을 멈추세요. 수신자가 나중에 유효한 재가입 절차를 완료한 경우에만 다시 보낼 수 있어요.

{% hint style="info" %}
아래 문구는 운영 예시일 뿐 법률 자문이 아니에요. 실제 발신자, 메시지 유형, 발송 빈도, 지원 절차, 관련 법률에 맞게 고지 문구를 조정하세요.
{% endhint %}

### 웹 폼 수신 동의

웹 폼에는 전화번호를 받는 곳 옆에 SMS 수신 동의 선택지를 보여 주세요. 사업자의 개인정보처리방침과 이용약관으로 가는 링크도 눈에 띄게 넣으세요. 전화번호 입력란은 필수로 해도 되지만, SMS 수신 동의는 선택 사항이어야 해요.

| 동의 유형 | 문구 예시 |
| --- | --- |
| 마케팅 | 저는 제공한 전화번호로 [사업자명]이 보내는 특별 혜택, 할인, 서비스 소식에 관한 마케팅 문자 메시지를 받는 데 동의해요. 메시지 발송 빈도는 달라질 수 있어요. 메시지 및 데이터 요금이 부과될 수 있어요. 도움이 필요하면 HELP를 보내세요. 수신을 거부하려면 STOP으로 답장하세요. |
| 비마케팅 | 저는 [예: 예약 알림, 주문 업데이트 등 구체적인 사용 사례]에 관해 [사업자명]이 보내는 비마케팅 문자 메시지를 받는 데 동의합니다. 메시지 발송 빈도는 달라질 수 있습니다. 메시지 및 데이터 요금이 부과될 수 있습니다. 도움이 필요하면 HELP를 보내세요. 수신을 거부하려면 STOP으로 답장하세요. |

- 마케팅 동의와 비마케팅 동의는 선택되지 않은 별도의 체크박스로 나눠 두세요.
- 각 동의 체크박스는 선택 사항으로 두고, 폼 제출 조건으로 만들지 마세요.
- 개인정보처리방침과 이용약관 링크를 폼 근처나 하단에 눈에 띄게 두세요.
- 개인정보처리방침에 모바일 정보 이용 방식을 설명하고, 문자 메시지 수신 동의 데이터나 동의 내역을 제3자가 마케팅에 쓰도록 공유할 수 있다고 쓰지 마세요.
- 폼, 인증 신청서, 웹사이트, 샘플 메시지에서 같은 사업자명과 메시지 카테고리를 쓰세요.

![마케팅과 비마케팅 SMS 수신 동의 체크박스가 나뉘어 있는 웹 폼 예시](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155047335618/original/5kprFJidPYVswryBqLoLLfpEBx5jpQUcgg.png?1748418112)

법적 정책 링크가 눈에 띄는, 별도의 선택형 SMS 수신 동의 선택지 예시예요.

### 구두 수신 동의

동의를 구하기 전에 상담원이나 IVR(자동 응답 시스템)이 다음 내용을 안내해야 해요.

- 사업자 이름
- 메시지 유형과 예상 발송 빈도
- 메시지 및 데이터 요금
- HELP와 STOP 안내
- 이용약관과 개인정보처리방침 위치

**예시:** "[사업자명]에서 예약 알림과 서비스 소식을 문자로 보내 드릴 수 있습니다. 메시지 발송 빈도는 달라집니다. 메시지 및 데이터 요금이 부과될 수 있습니다. 도움이 필요하면 HELP를, 수신을 거부하려면 STOP을 보내세요. 이용약관은 [이용약관 URL]에서, 개인정보처리방침은 [개인정보처리방침 URL]에서 확인하실 수 있습니다. 이 메시지를 받는 데 동의하시겠습니까?"

다음 항목은 증빙 자료로 기록해 두세요.

- 전화번호
- 날짜와 시간
- 상담원 또는 IVR 흐름
- 고지 문구 버전
- 수신자의 응답
- 증빙으로 쓰는 통화 녹음이나 시스템 로그

### 종이 양식 수신 동의

종이 양식에도 같은 필수 고지 내용을 넣고, 수신자가 동의를 확인하는 칸을 분명하게 두세요. 날짜가 적힌 사본이나 스캔본을 보관하고, 개인정보를 가린 샘플을 누구나 볼 수 있게 공개해 인증 증빙으로 제출하세요.

### 문자 및 모바일/QR 코드 수신 동의

홍보물에는 다음 내용이 들어가야 해요.

- 키워드 또는 QR 코드로 해야 할 행동
- 사업자 이름
- 메시지 프로그램 설명
- 발송 빈도와 요금 안내
- HELP와 STOP 안내
- 이용약관과 개인정보처리방침으로 가는 안내

- 웹 폼을 여는 QR 코드는 위의 웹 폼 규칙을 따르는 폼으로 연결되어야 해요.
- 휴대폰 메시지 앱을 여는 QR 코드는 의도한 키워드나 수신 동의 메시지만 미리 채워 주세요.
- 수신 동의 안내가 모두 담긴 인쇄 간판, 광고, 랜딩 페이지 등 홍보물의 공개 이미지를 제공하세요.

### 수신 동의 증빙과 기록 보관

심사자가 로그인하지 않고도 인증 URL에 접근할 수 있어야 해요. 잘라낸 체크박스나 전화번호 입력란만 보여 주지 말고, 수신 동의의 전체 맥락을 보여 주세요.

- 수신자에게 보여 준 동의 문구 전체를 저장하세요.
- 수신자 전화번호와 동의한 날짜·시간을 저장하세요.
- 수신 동의 방식과 출처(페이지, 폼, 캠페인, 통화, 종이 기록, 키워드, QR 코드)를 저장하세요.
- 가능하면 IP 주소, 폼 제출 ID, 통화 녹음 등 비슷한 증거를 저장하세요.
- 운영 방식이 지원한다면 연락처 기록에 동의 기록 링크나 참조 정보를 남기세요.
- 수신거부와 재가입 이력을 보관해서 현재 동의 상태를 증명할 수 있게 하세요.

하이퍼클래스에서 증빙 올리기: 스크린샷이나 문서를 **미디어 저장소**에 업로드하고, 파일 메뉴를 열어 **링크 받기**를 선택하세요. 인증 폼에 넣기 전에 시크릿 창에서 URL이 열리는지 확인하세요.

![미디어 저장소에서 새로 업로드하기와 링크 받기가 표시된 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155080151982/original/RkiuEBE-25vMnjDDVrOELIavOA3CMkb3Dg.png?1788551205)

**미디어 저장소**에 수신 동의 증빙을 업로드하고, 인증 신청에 쓸 공개 링크를 받으세요.

## 인증 상태 확인하기

수신자 부담 번호 아래에 표시되는 상태에 따라 미국·캐나다 메시징을 쓸 수 있는지가 정해져요. 심사에는 최대 4~6주가 걸릴 수 있어요. 더 빨리 끝나는 경우도 있지만 승인 시점은 보장되지 않아요.

| 인증 상태 | 미국/캐나다 메시징 | 의미 |
| --- | --- | --- |
| **Restricted (Unverified)** | 차단 | 번호를 아직 신청하지 않았거나 승인된 인증이 없어요. |
| **Pending Verification** | 차단 | 요청을 심사하고 있어요. 승인될 때까지 기다린 뒤에 SMS/MMS를 보내세요. |
| **Verified (Approved)** | 허용 | 현재 통신사, 플랫폼, 수신 동의, 콘텐츠 정책을 지키는 범위에서 SMS/MMS를 보낼 수 있어요. |
| **거절됨** | 차단 | 거절 사유를 확인하고, 신청 내용을 고쳐서 다시 제출하거나 가능한 경우 재심사를 요청하세요. |

상태가 **Restricted (Unverified)**, **Pending Verification**, **거절됨**일 때는 실제 메시지를 테스트로 보내지 마세요. 먼저 인증 요건을 해결하고, 번호가 **Verified** (Approved)로 표시된 뒤에 제한된 범위에서 테스트 메시지를 보내세요.

## 정치 선거 캠페인 사용 사례

정치 선거 캠페인 메시징에는 신원 인증이 추가로 필요해요. 이 추가 자격 증명이 수신자 부담 번호 메시징 프로그램을 인증된 정치 조직과 연결해 줘요.

2026년 2월 17일부터 새로 신청하는 정치 목적의 수신자 부담 번호 인증과, 이미 승인되어 정치 선거 메시징에 쓰는 수신자 부담 번호는 유효한 Campaign Verify Auth Token이 필요해요. 하이퍼클래스는 이 토큰을 발급하지 않아요. Campaign Verify에서 받아서, **Political Election Campaign**(정치 선거 캠페인) 카테고리를 선택할 때 입력해야 해요.

## 문제 해결과 거절 예방

인증 문제의 대부분은 다음과 같은 이유로 생겨요.

- 사업자 정보가 서로 달라요.
- 웹사이트나 증빙 URL에 접근할 수 없어요.
- 수신 동의 고지가 불완전해요.
- 사용 사례가 서로 맞지 않아요.
- 샘플 메시지가 실제 프로그램을 보여 주지 못해요.

| 문제 | 확인할 것 | 권장 조치 |
| --- | --- | --- |
| **인증 필요**가 보이지 않아요 | 올바른 서브 계정인지, 수신자 부담 번호 유형인지, 하이퍼클래스 전화 소유 여부, 페이지 새로고침 | 번호가 해당 서브 계정에 속해 있고 **Toll Free**(수신자 부담)로 표시되는지 확인한 다음 **번호 관리**를 새로고침하세요. |
| 웹사이트를 확인할 수 없어요 | 페이지가 운영 중이고, 공개되어 있고, 사업자와 일치하고, 비밀번호로 보호되지 않았는지 | 사이트를 게시하거나 고치세요. 정식 웹사이트가 없을 때만 공개 비즈니스 소셜 프로필을 쓰세요. |
| 수신 동의 증빙 URL이 거절돼요 | 링크가 공개되어 있고, 바로 열리고, 동의 흐름 전체가 보이고, 선택한 수신 동의 유형과 맞는지 | 선명한 스크린샷이나 문서를 **미디어 저장소**에 올리고, 공개 링크를 복사한 다음 시크릿 모드에서 열어 확인하세요. |
| 수신 동의 흐름이 규정에 맞지 않아요 | 선택되지 않은 선택형 체크박스, 마케팅·비마케팅 동의 분리, 발신자 이름, 메시지 유형, 발송 빈도, 요금, HELP, STOP, 이용약관, 개인정보처리방침 | 운영 중인 수신 동의 자료를 고치고, 증빙 URL을 교체한 뒤에 다시 제출하세요. |
| 사용 사례와 샘플이 서로 맞지 않아요 | 카테고리, 설명, 수신 동의 문구, 웹사이트, 샘플 메시지가 같은 프로그램을 설명하는지 | 모호한 설명을 다시 쓰고, 발신자 정보나 맥락, 해당하는 수신거부 문구가 빠진 샘플을 교체하세요. |
| **Error 30032** | 발송에 쓴 수신자 부담 번호가 **Verified (Approved)** 상태가 아니에요. | 수신자 부담 번호 인증을 완료하거나 수정하고, 승인될 때까지 기다린 뒤에 다시 시도하세요. |
| **Error 30007** | 메시지 내용, 발신자 식별, 수신 동의 또는 다른 정책 신호 때문에 통신사가 필터링했어요. | 다시 보내기 전에 실제 메시지, 수신 동의 증빙, 발신자 식별, 링크, 현재 메시징 정책을 확인하세요. |
| **거절됨** 상태인데 재제출할 수 없어요 | 거절 사유, 번호, 사업자 정보, 증빙 URL, 제출한 사용 사례 | 하이퍼클래스 고객지원에 문의하세요. 제목은 "Toll-Free Verification Rejection Appeal for [사업자명 또는 번호]"로 쓰세요. |

#### 고객지원에 문의할 때 함께 알려 주세요

- 서브 계정 이름과 Location ID
- 문제가 생긴 수신자 부담 번호(E.164 형식)
- 현재 인증 상태와 거절 사유
- 법인명과 공개 사업자 URL
- 공개 수신 동의 증빙 URL
- 문제가 나타나는 화면의 스크린샷 또는 화면 녹화
- 메시지 발송을 시도했다면 실패한 메시지 예시와 오류 코드

## 자주 묻는 질문

### 인증이 진행 중일 때도 SMS나 MMS를 보낼 수 있나요?
아니요. **Pending Verification** 상태의 번호는 상태가 **Verified** (Approved)로 바뀔 때까지 미국·캐나다 수신자에 대한 메시징이 차단돼요.

### 수신자 부담 번호 인증이 음성 통화에도 영향을 주나요?
아니요. 여기서 설명하는 인증 요건은 SMS/MMS에만 적용돼요. 수신자 부담 번호 메시징 인증 상태가 음성 통화를 막지는 않아요.

### 수신자 부담 번호 여러 개를 한 번에 인증할 수 있나요?
아니요. 번호마다 따로 인증 기록과 상태가 있어야 하므로 한 번호씩 신청해야 해요.

### 개인사업자나 소규모 사업자도 인증을 받아야 하나요?
네. 수신자 부담 번호로 미국 또는 캐나다 수신자에게 SMS나 MMS를 보내는 사업자라면 규모와 관계없이 인증이 필요해요. 인증에 EIN이나 사업자 세금 번호는 필요하지 않아요.

### 사업자가 미국에 있어야 하나요?
아니요. 실제 사업자를 정확하게 나타내고 확인할 수 있는 정보라면 다른 나라의 사업장 주소도 쓸 수 있어요.

### 웹사이트 대신 소셜 미디어 페이지를 써도 되나요?
실제 사업자에게 정식 웹사이트가 없다면 공개 비즈니스 소셜 프로필을 쓸 수 있어요. 로그인하지 않아도 접근할 수 있어야 하고, 신청서에 적은 사업자와 같은 사업자임을 분명하게 보여 줘야 해요.

### 수신 동의 페이지가 로그인 뒤에 있거나 아직 열리지 않았어요. 어떻게 하나요?
수신 동의 흐름 전체가 담긴 스크린샷이나 녹화 파일을 하이퍼클래스 **미디어 저장소** 같은 공개 접근 가능한 곳에 올리고, 그 공개 URL을 제출하세요. 증빙에는 동의 문구 전체와 수신자가 어떻게 동의하는지가 보여야 해요.

### 메시지가 실패해도 요금이 청구되나요?
공급업체로 제출하기 전에 하이퍼클래스 내부 검증에서 실패한 경우는 접수된 발송 시도와 다르게 처리돼요. 일단 발송을 위해 메시지가 제출되었다면, 나중에 전달되지 않거나 필터링되더라도 해당 요금이 청구될 수 있어요.

### 인증이 거절되면 어떻게 하나요?
거절 사유를 확인하고, 사업자 정보, 웹사이트, 사용 사례, 수신 동의 증빙, 샘플 메시지 중 문제가 된 부분을 고친 다음 재제출이 가능할 때 다시 제출하세요. 재제출이 불가능하면 하이퍼클래스 고객지원에 문의해서 수신자 부담 번호 인증 거절 재심사를 요청하세요.

### 번호로 메시지를 보낼 준비가 되었는지 어떻게 알 수 있나요?
**번호 관리**에 **Verified** (Approved)가 표시되면 미국·캐나다 SMS/MMS를 보낼 수 있어요. 승인 이후에도 수신 동의, 발신자 식별, 콘텐츠, 수신거부 요건을 계속 지키세요.
