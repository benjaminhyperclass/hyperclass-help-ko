# 지식 베이스 웹 크롤러 사이트맵 기반 URL 선택

지식 베이스(Knowledge Base)

## 지식 베이스 웹 크롤러 사이트맵 기반 URL 선택

사이트맵 프리뷰, 실시간 쿼터 추적, 전체 탐색 크롤링 옵션으로 지식 베이스에 학습시킬 웹사이트 페이지를 정확하게 선택하세요

**배우게 될 내용**

이 가이드에서는 사이트맵 기반 URL 선택 기능이 하이퍼클래스 지식 베이스에 어떤 웹사이트 페이지를 학습시킬지 정밀하게 제어하는 방법을 설명합니다. 사이트맵 프리뷰 모달, 탐색 크롤링(Discovery Crawl), URL 쿼터 도구가 웹 학습을 더 빠르고, 명확하고, 효율적으로 만들어주는 방법을 알아보세요.

이 아티클을 다 읽으시면 발견된 URL을 미리보고, 학습시킬 페이지를 정확히 선별하고, 실시간 작업 카드로 크롤링 및 학습 진행 상황을 모니터링하고, 전체 크롤링을 다시 실행하지 않고도 실패한 URL을 복구할 수 있게 됩니다.

## 사이트맵 기반 URL 선택이란?

사이트맵 기반 URL 선택은 지식 베이스에 학습시키기 전에 웹사이트 페이지를 미리 보고 선택할 수 있도록 개선된 웹 크롤러(Web Crawler) 워크플로우입니다. 하이퍼클래스가 웹사이트의 사이트맵 URL을 찾으면 "학습할 페이지 선택" 모달에 사용 가능한 페이지들이 표시되므로, 지식 베이스 콘텐츠로 사용해야 할 URL만 선택할 수 있습니다.

이 기능은 웹사이트에 페이지가 많지만 그중 일부만 AI 답변에 관련이 있을 때 유용합니다. 하나의 모달에서 검색, 페이지 넘기기, 개별 URL 선택, 사용 가능한 페이지 쿼터 확인, 선택한 페이지 학습을 모두 처리할 수 있습니다. 필요한 페이지가 사이트맵 결과에 없다면, "크롤링으로 탐색하기(Discover by Crawling)"를 대안으로 사용하여 웹사이트의 링크를 따라가며 페이지를 찾을 수 있습니다.

## 주요 장점

특정 웹사이트 페이지를 선택하면 지식 베이스가 무엇을 학습하는지 더 잘 제어할 수 있습니다. 이는 관련 없는 콘텐츠를 줄이고, 불필요한 페이지 사용을 방지하며, 웹사이트 학습 모니터링을 더 쉽게 만들어줍니다.

**정밀한 페이지 선택** — 무작정 페이지를 학습시키는 대신 학습시키고 싶은 정확한 웹사이트 URL을 선택하세요.

**더 빠른 설정** — 사이트맵 결과, 검색, 페이지 넘기기, 행(Row) 컨트롤을 사용해서 관련 페이지를 빠르게 찾으세요.

**향상된 쿼터 가시성** — 학습 전에 몇 개의 페이지가 선택됐고 몇 개가 사용 가능한지 확인하세요.

**대안 탐색 기능** — 사이트맵 결과에 페이지가 빠져 있을 때 "크롤링으로 탐색하기"를 사용하세요.

**더 명확한 진행 상황 추적** — 작업 카드에서 크롤링과 학습 진행 상황을 모니터링하세요.

**수동 재시도 지원** — 학습이 성공적으로 완료되지 않으면 실패한 URL을 재시도하세요.

## 웹 크롤러 찾는 방법

웹 크롤러(Web Crawler)는 지식 베이스 안에서 사용할 수 있으며 웹사이트 콘텐츠를 학습시키는 데 사용됩니다. 웹사이트 소스는 AI 도구가 선택된 공개 웹사이트 페이지를 사용하여 질문에 답변하도록 돕습니다.

웹 크롤러를 찾는 방법:

- 하이퍼클래스에서 **AI Agents(AI 에이전트)** 메뉴로 이동하세요
- **Knowledge Base(지식 베이스)** 를 여세요
- 업데이트할 지식 베이스를 선택하세요
- **Web Crawler(웹 크롤러)** 탭을 클릭하세요
- 새 웹사이트 소스를 추가하려면 **Add Website(웹사이트 추가)** 를 클릭하세요

웹 크롤러 탭에는 웹사이트 소스, 학습된 페이지 상태, 업데이트 시각, 페이지 단위 작업이 표시됩니다.

## URL 선택 모드

URL 선택 모드는 입력한 URL과 관련된 페이지를 하이퍼클래스가 어떻게 찾을지 결정합니다. 올바른 모드를 선택하면 학습시킬 URL을 고르기 전에 페이지 목록을 좁힐 수 있습니다.

**Exact URL(정확한 URL)** — 단일 페이지 학습

특정 페이지 URL 하나를 사용합니다. 더 큰 목록을 탐색할 필요 없이 특정 페이지 하나만 학습시킬 때 적합합니다.

**All URLs with this Path(이 경로의 모든 URL)** — 경로 기반 탐색

특정 웹사이트 경로(예: /help, /docs, /support) 아래의 페이지를 찾습니다. 특정 섹션만 지식 베이스 학습에 사용해야 할 때 유용합니다.

**All URLs in this Domain(이 도메인의 모든 URL)** — 도메인 전체 탐색

선택한 도메인 전체에서 페이지를 찾습니다. 사이트 대부분이 관련이 있을 때(예: 문서 사이트, 소규모 마케팅 웹사이트) 적합합니다. 사이트맵 모달에서 관련 없는 하위 영역은 선택 해제할 수 있습니다.

## 학습할 페이지 선택 모달

"학습할 페이지 선택(Select Pages to Train)" 모달은 사이트맵 기반 URL 선택의 핵심 인터페이스입니다. 발견된 모든 URL을 구조화된 표로 보여주므로 학습이 시작되기 전에 어떤 페이지를 지식 베이스에 포함할지 빠르게 검토, 필터링, 선택할 수 있습니다.

이 모달 안에서 "전부 학습시키기" 방식에서 의도적으로 선별된 URL 세트로 전환할 수 있습니다. 이는 일부 페이지만 고객에게 관련이 있는 크거나 복잡한 사이트에 특히 중요합니다.

**모달에서 볼 수 있는 항목**

모달에는 다음이 포함됩니다:

- 사이트맵에서 발견된 페이지 수(예: "Sitemap found — 426 pages")
- 선택된 페이지 카운터(예: "0 selected of 3995 available")
- 키워드나 경로로 URL을 필터링하는 검색 필드
- 선택을 위한 개별 페이지 체크박스
- 나열된 모든 URL을 빠르게 선택하는 전체 선택 옵션
- 페이지당 행 수 선택기(예: 10, 25, 50)
- 큰 목록을 탐색하기 위한 페이지네이션 컨트롤
- 더 깊은 탐색을 위한 "크롤링으로 탐색하기(Discover by Crawling)" 버튼
- 선택한 URL 학습을 시작하는 "선택 항목 학습(Train Selected)" 버튼

**UI 성능 개선**

페이지 번호를 변경하거나, 페이지당 행 수를 조정하거나, 검색어를 업데이트하면 URL 목록만 새로고침됩니다. 모달 자체는 열려 있고 반응성을 유지하며, 수천 개의 URL로 구성된 긴 목록도 몇 초 만에 처리할 수 있습니다.

## 페이지 쿼터 카운터

쿼터 카운터는 학습이 시작되기 전에 예상치 못한 상황을 방지하는 데 도움을 줍니다. 몇 개의 페이지가 선택됐는지, 지식 베이스 제한에 따라 몇 개의 페이지를 학습시킬 수 있는지 보여줍니다.

URL 쿼터를 관리하는 것은 건강한 지식 베이스를 유지하는 데 매우 중요합니다. 하이퍼클래스는 지식 베이스마다 정해진 수(예: 4,000개 URL)까지 웹 URL을 학습시킬 수 있게 하며, 이미 학습 데이터에 포함된 URL을 추적합니다. 실시간 쿼터 카운터를 통해 추측 없이 이 제한 내에서 작업할 수 있습니다.

**쿼터 카운터 작동 방식**

카운터는 "120 of 3,995 available"처럼 진행 현황을 표시합니다.

다음 상황에서 즉시 업데이트됩니다:

- 모달에서 URL을 선택하거나 선택 해제할 때
- 이미 학습된 URL을 포함하거나 제외할 때

카운터는 지식 베이스에 이미 존재하는 URL을 자동으로 반영하여, 새 페이지를 위해 남은 용량이 얼마인지 보여줍니다.

**실용적인 장점**

- URL 제한을 초과해서 발생하는 학습 중간 오류를 방지합니다
- 기본적으로 도메인 전체를 학습시키는 대신 가치 있는 URL만 선별하도록 유도합니다
- 향후 추가할 신규 제품 페이지나 문서를 위한 쿼터를 미리 계획하기 쉽게 해줍니다

## 크롤링으로 탐색하기

"크롤링으로 탐색하기(Discover by Crawling)"는 사이트맵 결과에 페이지가 빠져 있거나 사이트맵이 필요한 모든 것을 포함하지 않을 때 사용하는 대안 옵션입니다. 사이트맵 결과에만 의존하는 대신, 이 옵션은 웹사이트의 링크를 따라가며 추가 페이지를 찾습니다.

이 옵션은 Enhanced Web Crawler(향상된 웹 크롤러)의 고급 링크 탐색 기능과 함께 작동하며, 재귀적 사이트맵 크롤링, 압축된(zip) 사이트맵 파일, 동적 링크 감지를 지원합니다.

**"크롤링으로 탐색하기"를 사용해야 할 때**

- 필요한 페이지가 사이트맵 목록에 없을 때
- 사이트에 사이트맵이 없거나 불완전할 때
- 주요 페이지가 내비게이션 메뉴, 아코디언, 기타 인터랙티브 요소를 통해서만 접근 가능할 때
- 사이트맵에 아직 반영되지 않은 새 섹션을 최근에 추가했을 때
- URL 제한까지 최대한 많은 페이지를 확보하고 싶을 때

**"크롤링으로 탐색하기" 작동 방식**

- 도메인이나 경로 시드에서 시작하여 허용된 범위 내 내부 링크를 따라갑니다
- 크롤러가 벗어나지 않도록 내비게이션 경계와 루트 도메인 규칙을 준수합니다
- 추가 페이지가 발견될 때마다 모달의 URL 목록을 업데이트합니다
- 작업 카드에 "Crawling — 42 pages found so far"와 같은 진행 상황이 표시됩니다
- 링크를 능동적으로 탐색하기 때문에 사이트맵 기반 선택보다 시간이 더 걸릴 수 있습니다

## 크롤링 및 학습 진행 상황 모니터링

작업 카드(Operation Card)는 웹 크롤러가 무엇을 하고 있는지, 학습 작업이 어떻게 진행되는지 실시간으로 보여줍니다. 이러한 투명성은 대규모 사이트나 깊은 탐색 크롤링에서 특히 중요합니다.

추측하게 만드는 대신, UI는 페이지 새로고침이나 탭 전환에도 유지되는 상태 메시지와 카운트를 보여줍니다.

**작업 카드에 일반적으로 표시되는 항목**

- 상태 메시지가 포함된 크롤링 진행 상황
- 학습 진행 상황(예: "Training 5 of 5")
- 크롤링 중 발견된 페이지 수
- 성공적으로 학습된 페이지 수
- 현재 작업 상태(진행 중, 완료됨, 실패함)
- 완료율을 보여주는 시각적 진행 표시기

**왜 중요할까요**

- 크롤링을 중단하거나 가시성을 잃지 않고도 안전하게 페이지를 벗어나거나 탭을 전환할 수 있습니다
- 문제를 진단할 때, 문제가 탐색 단계에서 발생했는지, 학습 단계에서 발생했는지, 혹은 둘 다인지 빠르게 확인할 수 있습니다
- 비기술적인 팀원도 지식 베이스 학습이 "현재 어떤 상태인지" 쉽고 읽기 편하게 확인할 수 있습니다

## 실패한 URL 재시도

모든 URL이 첫 시도에서 성공적으로 학습되는 것은 아닙니다. 페이지가 타임아웃되거나, 응답이 느리거나, 외부 조건 때문에 일시적으로 실패할 수 있습니다. 수동 재시도 도구를 사용하면 전체 크롤링을 다시 실행하지 않고도 이런 실패에서 복구할 수 있습니다.

작업 결과는 문제가 있는 페이지를 식별하고 선택적으로 재시도할 수 있는 신뢰할 만한 방법을 제공합니다.

**수동 재시도 작동 방식**

크롤링이나 학습 중 페이지가 실패한 경우:

- 지식 베이스를 열고 웹 크롤러(Web Crawler) 탭으로 이동하세요
- 실패한 URL에 대해 웹사이트 소스나 페이지 목록을 확인하세요
- 사용 가능한 경우 페이지 단위 재시도(retry) 또는 새로고침(refresh) 작업을 사용하세요
- 재시도가 완료될 때까지 작업 카드를 모니터링하세요

**실패 처리 모범 사례**

**먼저 URL 자체를 확인하세요**

브라우저에서 페이지가 정상적으로 로드되는지 확인하세요(404 오류, 리다이렉트 루프, 로그인 벽이 없는지).

**작은 단위로 나눠서 재시도하세요**

여러 URL이 실패했다면, 일부만 다시 학습시켜 패턴을 확인해보세요.

**자동 새로고침(Auto Refresh)과 함께 사용하세요**

URL이 성공적으로 학습되면 자동 새로고침(Auto Refresh)을 활성화해서 자동으로 최신 상태를 유지할 수 있습니다.

## 사이트맵 기반 URL 선택으로 웹사이트 페이지 학습하는 방법

올바른 설정을 하면 지식 베이스가 AI 답변에 유용한 페이지만 학습하게 됩니다. 웹사이트 소스를 선택하고, 올바른 URL 모드를 고른 다음, 학습 전에 사이트맵 기반 페이지 목록을 검토하는 것부터 시작하세요.

**1단계: 지식 베이스 열기**

- 하위 계정(Sub-account)에서 **AI Agents(AI 에이전트) → Knowledge Base(지식 베이스)** 로 이동하세요
- 기존 지식 베이스를 열거나 새로 만드세요
- **Web Crawler(웹 크롤러)** 탭을 선택하세요

**2단계: 웹사이트 소스 추가하기**

- **+ Add Website(웹사이트 추가)** 를 클릭하세요
- URL 선택 모드를 고르세요:
  - Exact URL(단일 페이지용)
  - All URLs with this Path(경로 기반 학습용)
  - All URLs in this Domain(도메인 전체 학습용)
- 시작 URL을 입력하세요(https:// 포함)
- **Select Pages to Train(학습할 페이지 선택)** 을 클릭하세요

**3단계: 사이트맵 프리뷰 모달 검토하기**

- 하이퍼클래스가 사이트맵을 가져와서 발견된 URL을 표시합니다
- 모달에는 사이트맵에서 발견된 페이지 수가 표시됩니다(예: "Sitemap found — 426 pages")
- URL 목록을 검토하여 어떤 페이지가 사용 가능한지 확인하세요

**4단계: URL 검색, 필터링, 선택하기**

- 검색창을 사용해서 키워드나 경로로 URL을 찾으세요
- 대규모 사이트를 다룰 때는 페이지당 행 수를 조정하세요
- 페이지네이션 컨트롤로 전체 목록을 탐색하세요
- 학습시키고 싶은 URL 옆의 체크박스를 선택하세요
- 필요한 경우 "전체 선택(Select all)" 체크박스로 일괄 선택하세요
- 관련 없는 URL은 선택 해제하세요
- 쿼터 카운터(예: "120 of 3,995 available")를 확인해서 제한을 넘지 않도록 하세요

**5단계 (선택 사항): 크롤링으로 탐색하기 실행하기**

필요한 페이지가 사이트맵에 없거나 사이트맵이 불완전한 경우:

- **Discover by Crawling(크롤링으로 탐색하기)** 을 클릭하세요
- 크롤러가 내부 링크를 탐색할 시간을 주세요
- 표에 새 URL이 나타나면 검색과 체크박스로 선택 항목을 다시 정리하세요
- 크롤링 진행 메시지를 확인하기 위해 작업 카드를 모니터링하세요

**6단계: 선택한 URL 학습시키기**

- URL 선택 내용을 확인하고 쿼터 카운터를 검토하세요
- **Train Selected(선택 항목 학습)** 를 클릭하세요
- 학습 진행 상황을 보여주는 작업 카드가 나타납니다
- 작업이 백그라운드에서 계속되므로 다른 탭으로 안전하게 이동할 수 있습니다

**7단계: 결과 검토 및 실패한 URL 재시도하기**

- 학습이 완료되면 학습된 URL 목록을 검토하세요
- 실패한 URL이 있는지 확인하세요
- URL이 실패했다면, 사용 가능한 경우 페이지 단위 재시도/새로고침 작업을 사용하세요
- 검색 테스터(Retrieval Tester)를 사용해서 콘텐츠가 정상적으로 검색되는지 지식 베이스를 테스트하세요

## 자주 묻는 질문

**Q: 사이트맵 기반 URL 선택이란 무엇인가요?**

A: 사이트맵에서 사용 가능한 웹사이트 URL을 보여줘서, 지식 베이스에 학습시킬 페이지를 선택할 수 있도록 하는 웹 크롤러 워크플로우입니다.

**Q: 사이트맵 기반 URL 선택이 지식 베이스당 URL 제한을 바꾸나요?**

아니요. 지식 베이스당 전체 URL 제한은 동일하게 유지됩니다(예: 최대 4,000개 웹 URL). 새로운 방식은 단지 남은 URL 수를 더 쉽게 확인하고, 페이지를 선택하는 동안 제한을 초과하지 않도록 도와줍니다.

**Q: 사이트맵 프리뷰와 "크롤링으로 탐색하기" 중 언제 무엇을 사용해야 하나요?**

웹사이트의 사이트맵이 정확하고 관심 있는 섹션을 모두 다루고 있다면 사이트맵 프리뷰를 사용하세요. 이 방식이 보통 더 빠르고 가볍습니다. 사이트맵에 섹션이 빠져 있다고 의심되거나, 사이트가 매우 동적이거나, 중요한 콘텐츠가 내비게이션이나 인터랙티브 요소를 통해서만 접근 가능할 때는 "크롤링으로 탐색하기"를 사용하세요.

**Q: 학습 전에 페이지 목록을 검색할 수 있나요?**

네. "학습할 페이지 선택" 모달의 검색 필드를 사용해서 특정 페이지나 URL 경로를 찾을 수 있습니다.

**Q: 모든 페이지를 한 번에 선택할 수 있나요?**

네. 모달의 "전체 선택(Select all)" 체크박스를 사용하세요. 모든 페이지를 학습시키기 전에 사용 가능한 쿼터를 먼저 확인하세요.
