# 하이퍼클래스 MCP를 Muse에 연결하기

하이퍼클래스 MCP가 이제 Muse의 공식 앱으로 제공되어, Muse가 Model Context Protocol(MCP)을 통해 승인된 하이퍼클래스 CRM 기능에 접근할 수 있게 되었어요. 이 연결은 OAuth 방식을 사용하기 때문에, 연결하고 싶은 CRM 하위 계정(Sub-account)을 직접 선택하고 접근 권한을 부여하기 전에 요청된 권한을 검토할 수 있어요. 인증이 완료되면, Muse는 승인한 범위(scope)에 따라 4개의 통합 MCP 도구를 통해 38개 CRM 도메인에 걸친 600개 이상의 지원 작업에 접근할 수 있어요.

## **Muse용 하이퍼클래스 MCP란 무엇인가요?**

Muse용 하이퍼클래스 MCP는 Muse와 하이퍼클래스 사이에 안전한 연결을 만들어, Muse가 Model Context Protocol을 사용해 지원되는 CRM 서비스와 상호작용할 수 있게 해줘요. MCP는 호환되는 AI 클라이언트가 사용 가능한 기능을 파악하고, 정보를 조회하고, 승인된 작업을 수행할 수 있는 표준화된 방식을 제공해서, 사용자가 CRM 기능마다 별도의 연동을 구축할 필요가 없도록 해줘요. 하이퍼클래스의 MCP 서버는 연락처(Contacts), 대화(Conversations), 캘린더(Calendars), 기회 관리(Opportunities), 결제(Payments), 로케이션(Locations), 커스텀 필드(Custom Fields) 등의 CRM 서비스를 지원해요.

Muse 연동에서는 전용 하이퍼클래스 MCP 엔드포인트를 통해 OAuth로 인증이 완료돼요:

https://services.leadconnectorhq.com/mcp/muse/v2/

인증 과정에서는 Muse가 연결할 수 있는 CRM 하위 계정을 선택하고, 요청된 범위(scope)를 승인하게 돼요. 이 범위에 따라 Muse가 접근할 수 있는 하이퍼클래스 데이터와 기능이 결정돼요.

## **Muse용 하이퍼클래스 MCP의 주요 장점**

하이퍼클래스를 Muse에 연결하면, 요청되는 권한을 그대로 확인하면서도 지원되는 CRM 기능을 Muse가 사용할 수 있도록 통제된 방식으로 제공할 수 있어요. OAuth 범위를 통해 설정 과정에서 승인한 특정 하이퍼클래스 리소스와 작업으로 접근을 제한할 수 있어요.

- **OAuth 기반 연결**: Muse 연결을 위한 자격 증명을 직접 설정할 필요 없이 하이퍼클래스를 통해 인증할 수 있어요.

- **하위 계정 선택**: 인증 과정에서 사용할 수 있게 할 CRM 하위 계정을 직접 선택할 수 있어요.

- **세밀한 접근 제어**: Muse가 접근할 수 있는 하이퍼클래스 리소스와 작업을 결정하는 OAuth 범위를 승인할 수 있어요.

- **폭넓은 CRM 커버리지**: 38개 CRM 도메인에 걸쳐 600개 이상의 지원 작업에 접근할 수 있어요.

- **통합된 MCP 접근**: 지원되는 작업은 4개의 통합 MCP 도구를 통해 제공되어, Muse가 하이퍼클래스와 상호작용하는 방식을 단순화해줘요.

- **권한 가시성**: 하이퍼클래스의 OAuth 화면에서는 요청된 범위를 표시해주기 때문에, 외부 애플리케이션에 권한을 부여하기 전에 요청 내용을 검토할 수 있어요.

## **Muse에서 OAuth 권한이 작동하는 방식**

OAuth를 사용하면 외부 애플리케이션이 특정 하이퍼클래스 리소스에 접근 권한을 요청할 수 있으며, 이때 계정 자격 증명을 해당 애플리케이션에 직접 공유할 필요가 없어요. 인증 전에 요청된 범위를 검토하면 Muse가 하이퍼클래스의 어떤 영역을 사용할 수 있게 되는지, 그리고 어떤 종류의 작업이 가능해지는지 이해하는 데 도움이 돼요.

하이퍼클래스를 Muse에 연결할 때, OAuth 인증 흐름에서는 요청되는 권한, 즉 **OAuth 범위(Scope)**를 보여줘요. 하이퍼클래스의 OAuth 동의 화면은 사용자에게 요청된 권한을 보여주고, 접근 권한이 부여되기 전에 해당 권한이 허용하는 내용을 설명하도록 설계되어 있어요.

OAuth 범위는 하이퍼클래스 사용자 권한과 혼동하면 안 돼요:

- OAuth 범위는 Muse 연결이 접근할 수 있는 권한을 제어해요.

- 사용자 역할(User Role)과 권한(Permission)은 하위 계정 내에서 개별 하이퍼클래스 사용자가 접근할 수 있는 범위를 제어해요.

- 본인 데이터만 보기(Assigned Data) 제한은 하이퍼클래스 사용자가 조회하거나 관리할 수 있는 레코드를 추가로 제한할 수 있어요. 하이퍼클래스는 관리자(Admin)와 일반 사용자(User) 역할뿐만 아니라, 세부 모듈 권한과 본인 데이터만 보기 제한도 지원해요.

연결을 승인하기 전에 반드시 요청된 OAuth 범위를 검토하세요.

## **지원되는 하이퍼클래스 작업**

MCP를 사용하면 호환되는 AI 클라이언트가 지원되는 CRM 기능마다 별도의 연동을 구축하지 않고도 표준화된 연결을 통해 하이퍼클래스 서비스와 작업할 수 있어요. Muse 연동은 4개의 통합 MCP 도구를 통해 38개 CRM 도메인에 걸친 600개 이상의 지원 작업에 접근할 수 있게 해주며, 실제 접근 가능 범위는 승인한 OAuth 범위에 따라 결정돼요.

하이퍼클래스의 일반 MCP 서버는 다음과 같은 서비스를 지원해요:

- 연락처(Contacts)

- 대화(Conversations)

- 캘린더(Calendars)

- 기회 관리(Opportunities)

- 결제(Payments)

- 로케이션(Locations)

- 커스텀 필드(Custom Fields)

하이퍼클래스의 MCP 문서에서는 적절한 접근 권한이 있을 경우, MCP 호환 클라이언트가 레코드를 조회하고, 데이터를 업데이트하고, 메시지를 보내고, 기회를 검색하고, 캘린더 정보에 접근하는 등 다른 지원 작업도 수행할 수 있다고 설명하고 있어요.

Muse가 실제로 사용할 수 있는 정확한 작업 범위는 연결에 부여된 권한에 따라 달라져요. 필요한 범위만 승인하면 접근 권한을 의도한 사용 목적에 맞게 유지하는 데 도움이 돼요.

## **Muse용 하이퍼클래스 MCP 설정 방법**

올바른 설정을 위해서는 하이퍼클래스의 OAuth 인증 흐름을 완료하고, 올바른 CRM 하위 계정을 선택하고, Muse가 요청하는 범위를 검토해야 해요. 설정 과정에서 이러한 설정을 확인하면 Muse가 의도한 수준의 CRM 접근 권한을 받을 수 있어요.

- Muse를 열고 앱이나 MCP 서비스를 연결하는 옵션을 찾으세요.

- 연결할 앱으로 **하이퍼클래스**를 선택하세요.

- 하이퍼클래스 MCP 연결을 묻는 메시지가 나타나면, Muse 전용 엔드포인트를 사용하세요:

[https://services.leadconnectorhq.com/mcp/muse/v2/](https://services.leadconnectorhq.com/mcp/muse/v2/)

- 하이퍼클래스 인증 절차를 시작하세요.

- 메시지가 나타나면 하이퍼클래스에 로그인하세요.

- 하이퍼클래스 OAuth 인증 화면을 검토하세요.

하이퍼클래스의 OAuth 동의 화면은 애플리케이션이 요청하는 범위를 표시해서, 접근 권한을 승인하기 전에 요청되는 내용을 이해할 수 있도록 도와줘요.

- Muse에 연결할 CRM 하위 계정을 선택하세요.

- 요청된 OAuth 범위를 검토하고, Muse에 부여하려는 접근 권한과 일치하는지 확인하세요.

- 인증 요청을 승인하세요.

- Muse로 돌아가서 하이퍼클래스가 연결됨으로 표시되는지 확인하세요.

이제 Muse는 승인한 범위를 통해 사용 가능한 하이퍼클래스 작업을 사용할 수 있어요.

## **자주 묻는 질문**

**Q: 하이퍼클래스를 Muse에 연결하려면 Private Integration Token이 필요한가요?**
여기서 설명하는 Muse 연결은 전용 하이퍼클래스 MCP 엔드포인트와 OAuth 인증 흐름을 사용해요. 다른 하이퍼클래스 MCP 클라이언트 설정에 문서화된 일반적인 토큰 기반 설정 대신, Muse에서 제공하는 OAuth 절차를 따라 진행하세요.

**Q: Muse가 사용할 수 있는 하이퍼클래스 작업은 무엇에 의해 결정되나요?**
사용 가능한 작업은 인증 과정에서 승인한 OAuth 범위에 따라 달라져요. 범위는 외부 애플리케이션이 접근할 수 있는 하이퍼클래스 리소스와 작업을 정의해요.

**Q: Muse가 하이퍼클래스의 데이터를 변경할 수 있나요?**
하이퍼클래스의 MCP 서버는 필요한 접근 권한이 있을 경우, 정보 조회뿐만 아니라 데이터 업데이트를 포함한 지원 작업도 수행할 수 있어요. 특정 작업이 Muse를 통해 사용 가능한지 여부는 승인된 범위와 지원되는 작업에 따라 달라져요.

**Q: 연결하기 전에 OAuth 범위를 검토해야 하는 이유는 무엇인가요?**
OAuth 범위는 외부 애플리케이션이 요청하는 하이퍼클래스 리소스와 작업을 명시해요. 이를 검토하면 인증을 완료하기 전에 부여하게 될 접근 권한을 이해하는 데 도움이 돼요.

**Q: 연결하고 싶은 하이퍼클래스 하위 계정이 보이지 않아요**
먼저 인증을 진행하는 하이퍼클래스 사용자가 원하는 하위 계정에 접근 권한이 있는지 확인하세요. 하이퍼클래스 사용자 역할과 권한에 따라 개별 하위 계정 내에서 사용자가 접근할 수 있는 범위가 결정돼요.

**Q: OAuth 범위와 하이퍼클래스 사용자 권한은 같은 건가요?**
아니요. OAuth 범위는 외부 애플리케이션에 부여되는 권한을 제어하는 반면, 하이퍼클래스 사용자 역할과 권한은 하위 계정 내에서 개별 사용자가 접근할 수 있는 범위를 제어해요.

**Q: 나중에 Muse의 접근 권한을 취소할 수 있나요?**
하이퍼클래스는 연결된 애플리케이션을 정기적으로 검토하고, 더 이상 필요하지 않은 애플리케이션의 접근 권한을 취소할 것을 권장해요. 연결된 애플리케이션의 접근 권한은 하이퍼클래스의 **Settings(설정) > Connected Apps(연결된 앱)**에서 확인할 수 있어요.

**Q: 모든 Muse 연결이 자동으로 600개 이상의 하이퍼클래스 작업 전체에 접근할 수 있나요?**
아니요. 이 연동은 38개 CRM 도메인에 걸쳐 600개 이상의 작업을 지원하지만, 연결에서 실제로 사용 가능한 작업은 인증 과정에서 승인한 범위에 따라 결정돼요.
