# 사용자 접근 권한 관리

하이퍼클래스 계정에 누가 접근할 수 있는지 관리하는 방법을 안내해요. 에이전시와 서브 계정 각각에서 사용자를 관리하는 방법, 역할과 권한 설정, 다른 사용자로 로그인하는 권한, 로그인 이메일 변경 인증, 이메일 변경 보안 알림과 이전 이메일 복원 방법을 다뤄요.

## 에이전시 사용자 관리

에이전시 소유자와 관리자가 직원이나 고객사 담당자에게 여러 서브 계정의 접근 권한을 줄 때 쓰는 기능이에요. 에이전시 관리자만 쓸 수 있어요.

### 사용자 화면 열기

1. **에이전시 보기**에서 **설정**으로 이동하세요.
2. **사용자**를 선택하세요.

![에이전시 보기의 설정 > 사용자 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084892627/original/4rksi5CiFQLIU1TZgVjxi5mqcDZ8GwbX0w.png?1793760886)

### 할 수 있는 일

**사용자** 화면에서는 사용자 목록 검색, 새 사용자 추가, 기존 사용자 편집, 역할과 권한 관리, 필요한 경우 소유권 이전, 서브 계정 접근 관리, 사용자 삭제를 할 수 있어요.

사용자를 추가하거나 편집할 때 다음 항목을 설정할 수 있어요.

- **Personal logo**(개인 로고): 사용자 프로필에 표시돼요.
- **이름**
- **성**
- **이메일 주소**: 로그인 이메일로 쓰여요.
- **전화번호**
- **비밀번호**
- **권한**
- **사용자 유형**
  - **에이전시**: 에이전시 아래 모든 서브 계정에 접근할 수 있어요.
  - **계정**: 선택한 서브 계정에만 접근할 수 있어요.

![사용자 추가·편집 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084892665/original/qLJ4wK_PYrvt4YfLprnzkltoFCSAqItSFg.png?1793760946)

### 서브 계정 지정

- **에이전시** 사용자 유형이면, 알림을 받을 서브 계정을 지정하세요.
- **계정** 사용자 유형이면, 사용자가 접근할 수 있는 서브 계정을 선택하세요.

새로 바뀐 **사용자** 화면에서는 다음 기능도 쓸 수 있어요.

- 사용자 검색
- 소유자 역할에 대한 더 명확한 안내
- 소유권 이전
- 중복 이메일에 대한 개선된 안내
- 사용자를 만들 때 통화 착신 전환 및 음성사서함 옵션 설정

이메일 주소가 이미 에이전시에 있으면, 하이퍼클래스가 다음에 할 일을 안내해요. 예를 들어 에이전시 관리자에게 문의하거나 **사용자**에서 기존 사용자를 추가하도록 안내해요.

### 다른 사용자로 로그인하는 권한

다른 사용자로 로그인하는 기능(**로그인**, Login As)은 관리자마다 권한으로 제어돼요. 사용자에게 **Enable Login As**(로그인 활성화)를 끄면 로그인 옵션이 보이지 않아요.

이 권한은 **에이전시 보기 > 설정 > 사용자 > Edit User**(사용자 편집) **> Roles & Permissions**(역할 및 권한) **> 사용자 관리**에서 관리해요.

![로그인 권한을 설정하는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084892676/original/xijOIpReWYClm8pFCkp4ZdfuOn-98BT5YQ.png?1793760989)

## 서브 계정 사용자 관리

특정 하이퍼클래스 서브 계정 안에서 접근 권한을 관리하는 관리자와 사용자를 위한 내용이에요. 여기서 추가한 사용자는 에이전시의 **사용자** 화면에도 보여요.

### 사용자 화면 열기

1. 해당 **서브 계정**을 여세요.
2. **설정 > 사용자**로 이동하세요.

![서브 계정의 설정 > 사용자 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084892689/original/Pf6MO6sJ3-OpPXhZFxRB4SdaxEHV4RGeRA.png?1793761093)

### 할 수 있는 일

**사용자** 화면에서 사용자를 검색, 추가, 편집, 제거할 수 있고, 사용 가능한 역할·권한·접근 설정도 관리할 수 있어요.

설정할 수 있는 사용자 정보는 다음과 같아요.

- **Personal logo**(개인 로고)
- **이름**
- **성**
- **이메일**: 로그인에 쓰여요.
- **전화번호**
- **비밀번호**
- **권한**

사용자를 만들 때는 새 화면에서 통화 착신 전환 기본값과 음성사서함도 설정할 수 있어요.

이메일 주소가 이미 에이전시에 있으면, 하이퍼클래스가 다음에 할 일을 안내해요. 예를 들어 에이전시 관리자에게 문의하거나 **사용자**에서 기존 사용자를 추가하도록 안내해요.

서브 계정에 새 사용자를 추가할 때 개인 예약 캘린더가 자동으로 만들어질지는, 에이전시 수준의 **Preloaded Example Data**(미리 불러온 예시 데이터) 설정에 따라 달라져요. 이 설정은 **설정 > 회사**에 있어요.

![서브 계정 사용자 추가·편집 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084892695/original/5CEQ_LbCCLMVWvt-gnLVypDxvyxrqcwgYA.png?1793761137)

## 권한과 역할 개요

역할과 권한 범위를 알맞게 지정하면 사용자별로 접근할 수 있는 범위와 할 수 있는 작업을 정할 수 있어요.

권한으로 하이퍼클래스에서 사용자가 접근할 수 있는 영역, 할 수 있는 작업, 다룰 수 있는 계정이나 배정된 데이터를 정할 수 있어요.

자세한 내용은 아래 문서를 참고하세요.

## 이메일 변경 인증(멀티채널 OTP)

로그인 이메일을 바꾸는 일은 보안에 민감한 변경이에요. 하이퍼클래스는 멀티채널 OTP 인증을 지원해서, 기존 이메일 주소에 접근할 수 없어도 본인 확인을 할 수 있어요.

사용할 수 있는 인증 방법은 다음과 같아요.

- 이메일 OTP
- 전화(SMS) OTP
- TOTP(**인증 앱**)

화면에 표시되는 인증 방법은 사용자가 인증을 마친 2단계 인증(2FA) 방법에 따라 달라요.

### 내 이메일을 직접 바꿀 때

**내 프로필 > 보안**에서 내 로그인 이메일을 직접 관리할 수 있어요.

![내 프로필의 보안 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084892699/original/EjJfKk-J4xzmUEVicD5nSUG8lfzHmscD0w.png?1793761169)

- 시스템이 SMS나 **인증 앱** 같은 다른 2단계 인증 방법으로 인증하라고 안내해요.
- 인증을 마친 다른 방법이 없으면 인증 앱을 설정하라고 안내해요.

### 관리자가 다른 사용자의 이메일을 바꿀 때

해당 사용자가 쓸 수 있는 인증 방법이 화면에 표시돼요. 이메일, SMS, 인증 앱 중 일부 또는 전부가 나올 수 있어요.

## 이메일 변경 보안 알림과 되돌리기

하이퍼클래스는 사용자의 로그인 이메일 주소가 바뀔 때마다 보안 알림을 보내요. 이 알림으로 예상하지 못한 계정 변경을 알아차리고, 관리자에게 연락하지 않고도 이전 이메일 주소로 되돌릴 수 있어요. 이메일 변경 인증 절차에 더해 한 겹 더 보호해 주는 기능이에요.

### 보안 알림 작동 방식

본인이 직접 바꾸든 관리자가 대신 바꾸든, 로그인 이메일 주소가 바뀌면 보안 알림으로 알려 줘요. 알림에는 예상하지 못한 변경을 알아보고 대응하는 데 필요한 정보가 담겨 있어요.

사용자의 로그인 이메일 주소가 바뀌면 다음과 같이 알려 줘요.

- 이메일 알림: 이전 이메일 주소로 보안 알림을 보내요. 로그인 이메일을 쓰던 사람이 변경 사실을 알 수 있어요.
- 인앱 알림: 해당 사용자에게 하이퍼클래스 안에서도 보안 알림이 와요.
- 변경 내용: 무엇이 언제 바뀌었는지 알려 줘요. 시간은 사용자의 시간대로 표시돼요.
- 변경한 사람: 변경한 주체가 "본인"인지 "관리자"인지 알려 줘요. 내가 바꾼 것인지 관리자가 바꾼 것인지 구분할 수 있어요.
- 관리자가 변경한 경우: 관리자나 대리 로그인 등 지원되는 방식으로 사용자 대신 이메일 주소를 바꿨을 때도 알림이 가요.

직접 바꿨거나 변경 사실을 알고 있다면 따로 할 일은 없어요.

![보안 알림 이메일 예시](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084892100/original/Lbv_d2AIt8U1afANz0Z8Lh0c_q0tCogl9w.png?1793759095)

*날짜, 변경 내용, 되돌리기 버튼이 표시된 보안 알림 이메일 예시예요.*

### 예상하지 못한 이메일 변경 되돌리기

모르는 사이에 로그인 이메일 주소가 바뀌었다면, 보안 이메일에 있는 되돌리기 링크로 이전 이메일을 복원할 수 있어요. 로그인하지 않아도 되기 때문에 계정 접근에 문제가 생겼어도 되돌릴 수 있어요.

1. 이전 로그인 이메일 주소의 받은편지함을 여세요.
2. 이메일 주소가 변경되었다는 보안 알림을 찾아 여세요.
3. 변경이 언제 일어났는지, 본인이 한 것인지 관리자가 한 것인지 등 변경 내용을 확인하세요.
4. 보안 이메일의 되돌리기 링크를 클릭하세요. 로그인하지 않아도 하이퍼클래스가 이전 로그인 이메일 주소를 복원해요.
5. 확인 페이지에서 이전 이메일 주소가 복원되었는지 확인하세요.

{% hint style="warning" %}
되돌리기 링크는 30일 동안 유효하고 한 번만 사용할 수 있어요. 이메일 변경이 예정된 일이었다면 되돌리기 링크를 쓰지 않아도 돼요.
{% endhint %}

이전 이메일 주소가 복원되면 하이퍼클래스가 되돌리기가 끝났다는 확인 페이지를 보여 줘요.

![이전 로그인 이메일 복원 후 표시되는 확인 페이지](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084892051/original/K5xKFBJafkDVs72k9tDyMubpst2j0BlRsw.png?1793758839)

*이전 로그인 이메일 주소를 복원한 뒤 표시되는 확인 페이지 예시예요.*

![로그인 이메일이 복원되었음을 알리는 이메일 예시](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084892098/original/emT_cSBNnacURr9KjwSBYSqnphmYsVTvTw.png?1793759062)

*로그인 이메일 주소가 복원되었음을 알리는 이메일 예시예요.*

되돌리기 링크는 한 번만 쓸 수 있어요. 이미 사용한 링크로는 다시 되돌릴 수 없어요. 도움이 필요하면 에이전시에 문의하세요.

![이미 사용한 되돌리기 링크를 열었을 때의 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084892070/original/jGbpHtq4_WNtkwBQc3KcEHYmBufO6a_-WQ.png?1793758899)

*이미 사용한 되돌리기 링크를 열었을 때의 화면 예시예요.*

전화번호가 바뀔 때의 보안 알림과 되돌리기는 [전화번호 변경 보안 알림 및 되돌리기](../15-전화-시스템/전화번호/phone-number-change-security-alerts-and-reversal.md)를 참고하세요.

### 보안, 브랜딩, 언어 지원

이메일 변경 보안 알림은 계정 접근을 보호하면서, 에이전시와 언어에 상관없이 일관된 경험을 제공해요. 알림과 복구 페이지는 에이전시 브랜딩과 현지화를 지원하고, 완료된 되돌리기는 기록으로 남아요.

- 에이전시 브랜딩: 보안 알림에 에이전시의 로고와 도메인이 사용돼서 에이전시 브랜드 경험이 유지돼요.
- 언어 지원: 보안 알림과 되돌리기 페이지는 12개 로캘(언어·지역 설정)을 지원해요. 번역이 없는 문구는 영어로 표시돼요.
- 기록 관리: 완료된 이메일 주소 되돌리기는 모두 기록돼요.
- 자동 알림: 사용자가 직접 바꾸거나 다른 사람이 대신 바꾼 경우를 포함해, 지원되는 로그인 이메일 변경이 있으면 알림이 자동으로 가요.

이메일 변경 보안 알림은 기존 멀티채널 OTP 인증과 함께 작동해요. 인증은 이메일 변경 자체를 안전하게 지켜 주고, 보안 알림은 변경 후에 상황을 알려 주고 복구할 수 있게 해 줘요.

## 권장 사용 방법

- 최소 권한 원칙: 사용자에게 필요한 권한만 주세요. 꼭 필요한 경우가 아니면 에이전시 전체 접근 권한은 주지 마세요.
- 제한된 접근에는 **계정** 유형 사용자: 선택한 서브 계정에만 접근해야 하는 사람에게는 이 사용자 유형을 고르세요.
- 변경 내역 관리: 누가 접근할 수 있는지, 접근 권한이 언제 바뀌었는지 분명히 기록해 두세요.
- 주기적인 접근 권한 검토: 담당 업무가 바뀌었거나 접근이 더 이상 필요 없으면 권한을 수정하거나 사용자를 제거하세요.

## 자주 묻는 질문

### 에이전시 사용자 유형과 계정 사용자 유형은 뭐가 다른가요?

**에이전시** 사용자 유형은 에이전시 아래 모든 서브 계정에 접근할 수 있어요. **계정** 사용자 유형은 직접 선택한 서브 계정에만 접근할 수 있어요.

### 서브 계정의 사용자에서 추가한 사용자가 에이전시 사용자 관리에도 보이나요?

네, 보여요. 서브 계정에서 추가한 사용자는 에이전시의 **사용자** 목록에도 표시돼요.

### 사용자마다 다른 권한 수준을 줄 수 있나요?

네, 할 수 있어요. 권한 설정으로 각 사용자가 접근할 수 있는 기능과 작업을 정할 수 있어요.

### 역할이 바뀌면 나중에 접근 권한을 어떻게 바꾸나요?

에이전시나 서브 계정의 **사용자**에서 해당 사용자를 열고, 필요에 따라 사용자 유형, 배정된 계정, 역할, 권한을 수정하세요.
