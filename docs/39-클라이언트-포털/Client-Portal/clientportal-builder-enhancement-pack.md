# 클라이언트 포탈 빌더 개선 패키지

**클라이언트 포탈 빌더**(ClientPortal Builder)에 기능이 여러 개 추가되어, 브랜디드 앱을 더 빨리 출시하고 이탈을 줄일 수 있어요. 에이전시는 **통화 예약**으로 안내형 온보딩을 받을 수 있어요. 구독이 일시중지되거나 취소되면 앱 사용자에게 **Cancelled from Live**(라이브에서 취소됨) 화면이 보여요. 구독 자동화에는 웹훅 개선, 구독 자동 생성, 재구독 처리가 더해졌어요.

![클라이언트 포탈 빌더 개선 패키지 소개 이미지](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155051363915/original/h_Pn8sjSoAl-p4QFE3lQbuOotnQ9xa8PKg.png?1754926363)

## 클라이언트 포탈 빌더 개선 패키지(브랜디드 앱)란?

에이전시가 화이트라벨 브랜디드 앱을 출시하고 관리하는 과정을 개선한 기능 모음이에요. 안내형 온보딩(**통화 예약**), 일시중지·취소된 구독을 앱 안에서 알려 주는 상태 화면(**Cancelled from Live** 화면), 운영 개선 기능(재구독, 웹훅 연동, 구독 자동 생성)이 들어 있어요. 덕분에 설정부터 라이브까지 더 빨리 진행하고, 앱을 안정적으로 운영할 수 있어요.

## 개선 패키지의 주요 장점

라이브 시점을 앞당기고, 구독 상태 안내를 분명하게 하고, 자동화를 강화하는 데 초점을 맞췄어요. 에이전시와 고객이 문제 해결에 쓰는 시간을 줄이고 사용자와 소통하는 시간을 늘릴 수 있어요.

- 빠른 라이브 전환: 안내형 온보딩으로 스토어 등록과 브랜딩 단계를 빠르게 마칠 수 있어요.
- 선제적인 이탈 관리: **Cancelled from Live** 화면이 눈에 띄게 보여서 제때 갱신하도록 유도하고, 앱이 중단되는 기간을 줄여요.
- 자동화 대응: 개선된 웹훅과 구독 자동 생성으로 재판매와 프로비저닝(계정·구독을 자동으로 준비하는 일)이 쉬워져요.
- 유지율 지원: 재구독 처리로 이탈한 앱을 다시 살리기 쉬워져요.
- 운영 명확성: 취소 사유를 모아서 코칭과 프로세스 개선에 활용할 수 있어요.

## 통화 예약(에이전시용) — 안내형 온보딩

하이퍼클래스 전문가와 연결되어 브랜디드 앱 설정을 빠르게 진행할 수 있어요. 처음 출시하거나 내부 인력이 부족할 때 알맞아요.

### 하는 일

- 에이전시가 **클라이언트 포탈 빌더**에서 바로 설정 통화를 예약할 수 있어요. 에이전시 계정에서만 쓸 수 있어요.
- 필요한 단계와 모범 사례를 함께 짚어 주어, 도입과 라이브까지 걸리는 시간을 줄여 줘요.
- 작업을 시작하기 전에 스토어 요건, 필요한 자산, 제출 일정을 확인해 줘요.

### 준비할 것

- 앱 이름, 브랜드 색상, 로고와 앱 아이콘(필요한 크기), 스플래시 화면
- Apple App Store / Google Play 개발자 계정 접근 권한
- 법적 정보, 번들 ID, 필요한 규정 준수 관련 정보

## Cancelled from Live 화면 — 선제적인 이탈 관리

앱 구독이 일시중지되거나 취소되면 사용자에게 앱 안에서 상태 화면이 보여요. 지금 상태를 한눈에 알 수 있고, 계정 소유자가 서비스를 빠르게 다시 시작하도록 안내해 줘요.

### 작동 방식

- 앱이 더 이상 라이브 상태가 아니라는 상태 화면을 보여 줘요.
- 접근을 되돌리려면 조치가 필요하다고 알려 줘요.
- 고객에게 미치는 영향을 강조해서 갱신을 서두르게 해요.

### 사용자가 할 수 있는 일

- 화면의 안내에 따라 구독을 갱신하거나 다시 시작할 수 있어요.
- 필요하면 화면에 제공된 링크로 에이전시나 고객지원에 문의할 수 있어요.

## 이탈 사용자의 재구독 처리

이탈한 앱을 되살리기가 쉬워졌어요. 접근 권한을 복구하고 결제를 맞춰서, 브랜디드 앱을 고객에게 빠르게 다시 제공할 수 있어요.

### 핵심 내용

- 일시중지나 취소 후 다시 활성 상태로 돌아갈 수 있어요.
- 결제가 성공하면 구독 상태, 결제, 접근 권한이 서로 맞춰져요.
- 앱을 다시 켤 때 팀이 직접 처리할 단계가 줄어요.

## 웹훅 자동화 및 재판매 개선

재판매용 웹훅이 개선되었고, 웹훅으로 구독을 자동 생성하는 옵션도 생겼어요. 사람이 손대지 않아도 프로비저닝이 이루어져요.

### 개선된 점

- 클라이언트 포탈 브랜디드 앱과 연동되는 재판매 웹훅이 개선되어, 파트너 워크플로우가 더 깔끔해졌어요.
- 웹훅으로 구독을 자동 생성하므로, 새 고객을 수동 설정 없이 바로 준비할 수 있어요.
- 생성 → 일시중지/취소 → 재개까지 전체 흐름을 더 폭넓게 지원해요.

### 구현 팁

- 보안이 적용된 멱등성 웹훅 엔드포인트를 사용하세요. 멱등성이란 같은 요청이 여러 번 들어와도 결과가 한 번 처리한 것과 같다는 뜻이에요.
- 감사와 지원에 쓸 수 있도록 페이로드와 응답을 로그로 남기세요.
- 실제 운영에 적용하기 전에 스테이징 환경에서 생성·재개·취소 흐름을 테스트하세요.

## 취소 사유 수집

고객이 왜 취소하는지 알면 코칭, 가격, 상품 결정에 도움이 돼요. 이탈을 줄이는 과정을 마무리하는 단계예요.

### 작동 방식

- 사용자가 브랜디드 앱 안에서 취소 사유를 입력해요.
- 입력된 응답은 리포팅, 고객 접촉, 프로세스 개선에 쓸 수 있어요.
- 정성적인 의견과 구독 이벤트를 함께 보면 패턴을 찾기 쉬워요.

## 설정 및 사용 방법

아래 단계는 에이전시가 안내형 온보딩을 이용하고, 구독 상태를 관리하고, 자동화를 켜서 라이브 시점을 앞당기고 이탈을 줄이는 방법이에요.

### A. 통화 예약(에이전시용)

1. 에이전시 계정에서 **클라이언트 포탈 빌더**를 엽니다.
2. 브랜디드 앱 프로젝트를 선택하고 **통화 예약**을 클릭합니다.
3. 날짜와 시간을 고르고, 연락처 정보를 확인한 뒤 제출합니다.
4. 통화 전에 필요한 자산(로고, 아이콘, 스토어 접근 권한)을 준비합니다.
5. 통화에 참여해 설정을 마무리하고, 앱 제출을 위한 다음 단계를 정합니다.

### B. Cancelled from Live 상태 처리

1. **Cancelled from Live** 화면이 나타나면 메시지와 영향 안내를 확인합니다.
2. 화면에 제공된 CTA(행동 유도 버튼)로 구독을 갱신하거나 다시 시작합니다.
3. 결제가 성공하면 앱을 다시 실행해서 상태 화면이 사라졌는지 확인합니다.
4. 의도적으로 취소했다면, 취소 사유 입력 창이 나올 때 사유를 남겨서 이후 전략에 활용하세요.

### C. 웹훅 기반 자동화 켜기(재판매/자동 생성)

1. 사용 중인 연동 환경에서, 생성·일시중지/취소·재개 이벤트를 처리할 수 있는 웹훅 엔드포인트를 설정합니다.
2. 페이로드 필드를 결제·프로비저닝 시스템에 매핑하고, 멱등성을 구현합니다.
3. 구독 자동 생성 흐름을 처음부터 끝까지 테스트합니다.
4. 로그와 지표를 모니터링하고, 실패와 재시도에 대한 알림을 추가합니다.

## 자주 묻는 질문

### 통화 예약은 누가 쓸 수 있나요?
에이전시 전용 기능이에요. 사용 자격이 있는 계정의 **클라이언트 포탈 빌더**에 표시돼요.

### 안내형 온보딩을 받으면 가격이 달라지나요?
아니요. 이 기능은 라이브까지 걸리는 시간을 줄여 줄 뿐, 가격은 바꾸지 않아요.

### Cancelled from Live 화면은 언제 나타나나요?
브랜디드 앱 구독이 일시중지되거나 취소되었을 때 나타나요. 앱이 라이브 상태가 아니라고 알리고 조치를 안내해요.

### Cancelled from Live 화면을 없애려면 어떻게 하나요?
구독을 갱신하거나 다시 시작하세요. 구독이 활성화되면 화면이 사라져요.

### 취소 화면의 문구나 브랜딩을 바꿀 수 있나요?
브랜딩은 앱 테마를 따라가요. 더 세부적으로 바꾸고 싶으면 하이퍼클래스 고객지원이나 계정 담당 팀에 문의하세요.

### 재구독은 이제 무엇이 달라졌나요?
이탈 상태에서 돌아오는 과정이 더 매끄러워졌어요. 결제가 성공하면 결제와 접근 권한이 빠르게 다시 맞춰져요.

### 재판매와 자동 생성을 지원하는 웹훅은 무엇인가요?
생성, 일시중지/취소, 재개 이벤트에 대한 클라이언트 포탈 웹훅 패턴을 사용하세요. 보안이 적용된 엔드포인트를 설정하고 멱등성을 갖추세요.

### 취소 사유는 나중에 어디서 볼 수 있나요?
앱 안에서 입력된 사유는 계정의 **리포팅**·**청구/결제** 영역에서 확인할 수 있어요. 코칭과 유지 전략에 활용하세요.

### 출시하려면 꼭 웹훅을 써야 하나요?
아니요. 웹훅은 선택 사항이에요. 다만 프로비저닝과 재판매를 대규모로 자동화하는 파트너에게는 권장해요.

### 통화 예약 세션 전에 무엇을 준비해야 하나요?
브랜드 자산, 개발자 스토어 접근 권한, 번들 ID 같은 규정 준수 관련 정보를 준비하세요. 그러면 바로 제출 단계로 넘어갈 수 있어요.
