# 클라이언트 포털의 앱 권한 설정: 하위 앱과 로그인 방식 켜고 끄기

서브 계정별로 **앱 권한**을 설정해서, 연락처가 클라이언트 포털에서 보게 될 앱과 로그인 방식을 정하는 방법을 안내해요.

**앱 권한**은 클라이언트 포털 화면을 조정하는 중앙 설정 화면이에요. 코스, 커뮤니티, 제휴 같은 하위 앱을 연락처에게 보여 줄지 정하고, Google 로그인 같은 인증 방식도 여기서 관리해요. 이 문서에서는 하위 앱과 인증 권한을 켜고 끄는 방법을 알려 드려요. 비즈니스와 규정 준수 요건에 맞게 포털을 구성할 때 참고하세요.

## 클라이언트 포털의 앱 권한이란?

**앱 권한**은 **클라이언트 포털 설정** 안에 있는 설정 화면이에요. 연락처가 쓸 수 있는 기능과 인증 방식을 한곳에서 관리해요. 역할은 크게 두 가지예요.

- **하위 앱 표시 여부**: 코스, 커뮤니티, 제휴 같은 포털 앱을 클라이언트 포털 내비게이션에 보여 줄지, 연락처가 접근할 수 있게 할지 정해요.
- **인증 방식**: Google 로그인 같은 로그인 방식을 관리해요. 연락처가 포털에 들어올 때 어떻게 인증할지 정하는 거예요.

앱 권한은 서브 계정마다 따로 설정해요. 그래서 고객사의 상황, 규정 준수 요건, 비즈니스 모델에 맞게 포털을 구성할 수 있어요.

앱 권한에서 바꾼 내용은 해당 서브 계정의 클라이언트 포털에 있는 모든 연락처에게 똑같이 적용돼요.

## 하위 앱과 인증 권한의 차이

두 가지를 구분해 두면 클라이언트 포털을 더 쉽게 설정할 수 있어요.

### 하위 앱

연락처가 클라이언트 포털에 로그인한 뒤 쓸 수 있는 개별 앱과 기능이에요. 예를 들면 다음과 같아요.

- 코스: 교육 콘텐츠 제공
- 커뮤니티: 토론 게시판과 회원 간 소통
- 제휴: 추천 프로그램 관리
- 비즈니스에 맞는 그 밖의 포털 모듈

### 인증 권한

연락처가 포털에 로그인하는 방식을 정하는 권한이에요. 하위 앱과는 별개이고, 다음과 같은 방식이 있어요.

- **Google Sign-In**(Google 로그인): 로그인·회원가입 페이지의 **Google로 로그인** 버튼을 켜거나 꺼요.
- 이메일 + 비밀번호: 일반적인 계정 생성과 로그인 방식이에요. 항상 사용할 수 있어요.
- 보안 코드 로그인: 이메일로 받은 일회용 코드로 로그인해요. 코드에는 유효 시간이 있어요. 항상 사용할 수 있어요.
- **매직 링크**: 연락처에게 만들어 보내는 원클릭 접속 링크예요. 항상 사용할 수 있어요.

### 핵심 차이

하위 앱 토글은 연락처가 로그인한 뒤 포털 안에서 무엇을 할 수 있는지를 정해요. 인증 권한은 연락처가 처음에 어떻게 로그인하는지를 정해요.

## 앱 권한 열기

서브 계정의 클라이언트 포털에서 **앱 권한** 설정 화면을 여는 방법이에요.

1. **Agency View**(에이전시 보기)에서 설정하려는 클라이언트 포털이 있는 서브 계정으로 전환해요. 앱 권한은 전체 공통이 아니라 서브 계정별로 설정해요.
2. 왼쪽 사이드바에서 **멤버십**(또는 클라이언트 포탈이 표시된 메뉴)을 클릭해요.
3. **클라이언트 포탈**을 클릭한 다음 **설정**을 열어요.

   ![클라이언트 포탈 설정 메뉴로 이동하는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155077250174/original/ANplb3wMKp1EMnBNDVudlkWtygUBIC836Q.png?1785418366)

4. **클라이언트 포털 설정** 안에서 **앱 권한** 탭(또는 메뉴 항목)을 클릭해요. 사용할 수 있는 모든 하위 앱과 인증 옵션 목록이 보여요.

   ![앱 권한 탭을 여는 과정](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155077250470/original/fLntzdiGGIC4lFLBoyfSgbK3IIULuZABUg.gif?1785418449)

{% hint style="info" %}
서브 계정을 여러 개 관리한다면 이동 경로를 북마크하거나 따로 적어 두세요. 고객사별로 클라이언트 포털을 설정할 때 더 빨리 찾아갈 수 있어요.
{% endhint %}

## 하위 앱 켜고 끄기

**앱 권한** 화면에서는 토글을 켜거나 꺼서 클라이언트 포털에 보일 하위 앱을 정할 수 있어요. ▶ 영상 [5강 27:44](https://www.youtube.com/watch?v=g2fcpLnUI8M&t=1664s)

1. **앱 권한** 목록에서 켜거나 끄려는 하위 앱(예: 코스, 커뮤니티, 제휴)을 찾아요. 앱마다 토글 스위치가 따로 있어요.
2. 원하는 상태로 설정해요.
   - 토글을 **켜면** 하위 앱이 클라이언트 포털 내비게이션에 표시되고, 연락처가 접근할 수 있어요.
   - 토글을 **끄면** 클라이언트 포털에서 하위 앱이 숨겨져요. 연락처는 내비게이션에서 앱을 볼 수 없고 콘텐츠에도 접근할 수 없어요.
3. **저장**을 클릭해서 새 설정을 적용해요. 클라이언트 포털에 접속하는 모든 연락처에게 바로 적용돼요.

{% hint style="info" %}
하위 앱을 끄면 포털 내비게이션에서만 숨겨져요. 그 앱의 콘텐츠나 데이터는 삭제되지 않아요. 앱을 다시 켜면 연락처가 언제든 다시 접근할 수 있어요.
{% endhint %}

## Google 로그인 켜고 끄기

**Google Sign-In** 토글은 클라이언트 포털 웹의 로그인·회원가입 페이지에 **Google로 로그인** 버튼을 보여 줄지 정해요. 이 인증 권한은 하위 앱과 같은 **앱 권한** 화면에서 함께 관리해요.

1. **앱 권한** 목록에서 **Google Sign-In** 옵션을 찾아요. 하위 앱 토글들과 같은 목록에 있어요.

   ![앱 권한 목록의 Google Sign-In 토글](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155077249665/original/Jim7b1JcHFRherWJHL9OC0rwdH2wwaZ-3w.png?1785418154)

2. 원하는 상태로 설정해요.
   - 토글을 **켜면** 클라이언트 포털 웹의 로그인·회원가입 페이지에 **Google로 로그인** 버튼이 보여요. 연락처는 Google 계정으로 인증할 수 있어요.
   - 토글을 **끄면** Google 버튼이 숨겨져요. 연락처는 이메일 + 비밀번호, 보안 코드 로그인, 또는 보내 준 **매직 링크**로 인증해요.
3. **저장**을 클릭해서 인증 설정을 적용해요.
4. 시크릿 모드(비공개) 브라우저 창에서 **클라이언트 포탈 URL**을 열어요. 설정대로 **Google로 로그인** 버튼이 보이거나 숨겨져 있는지 확인하세요.

### Google 로그인을 꺼야 하는 경우

GDPR 같은 규정 준수 요건, 사내 보안 정책, 고객사와의 데이터 처리 계약 때문에 Google 로그인을 끄는 비즈니스가 많아요. Google 로그인을 끄면 외부 서비스를 거치는 인증 단계가 사라지고, 클라이언트 포털의 다른 로그인 방식은 모두 그대로 쓸 수 있어요.

{% hint style="warning" %}
Google 로그인을 꺼도 로그인·회원가입 페이지에서 Google 버튼만 숨겨져요. 기존 연락처 정보는 삭제되지 않고, 매직 링크, 보안 코드, 이메일 + 비밀번호 같은 다른 로그인 방식에도 영향이 없어요.
{% endhint %}

## 앱 권한 관리 모범 사례

아래 내용을 참고하면 앱 권한을 더 안전하고 효율적으로 설정할 수 있어요.

### 1. 오픈 전에 점검하세요

연락처에게 **클라이언트 포탈 URL**을 공유하기 전에 모든 하위 앱과 인증 옵션이 제대로 설정됐는지 확인하세요. 시크릿 창에서 로그인 과정을 직접 테스트하면 연락처가 실제로 보게 될 화면을 확인할 수 있어요.

### 2. 컴플라이언스 담당자와 먼저 상의하세요

GDPR 같은 규정 준수 때문에 Google 로그인을 끄려면, 변경하기 전에 법무, 보안, 개인정보 보호 책임자와 먼저 상의하세요. 결정 내용은 사내 컴플라이언스 문서에 기록해 두세요.

### 3. 변경 내용을 연락처에게 알리세요

연락처가 이미 포털을 쓰고 있는 상태에서 하위 앱을 끄거나 인증 옵션을 바꾼다면, 변경 내용과 대신 써야 할 접속 방법을 간단히 공지하세요.

### 4. 관리자 권한을 제한하세요

팀원의 역할과 권한을 신중하게 관리해서 **앱 권한**을 바꿀 수 있는 사람을 제한하세요. 계정 소유자나 운영 책임자처럼 믿을 수 있는 관리자만 포털 설정을 바꾸게 하는 게 좋아요.

### 5. 서브 계정별 설정을 활용하세요

여러 고객사를 관리한다면 서브 계정별로 따로 설정할 수 있다는 점을 활용하세요. 모든 고객사에 같은 설정을 쓰지 말고, 고객사마다 필요한 하위 앱과 인증 옵션을 켜 주세요.
