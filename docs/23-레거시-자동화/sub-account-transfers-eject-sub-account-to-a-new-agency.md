# 서브 계정 전송 — 서브 계정을 새 에이전시로 분리(Eject)하기

내 에이전시 안의 서브 계정을 독립된 에이전시 계정으로 전환하는 방법을 안내해요. 기존 서브 계정을 별도의 에이전시로 내보내고 싶을 때 쓰세요.

서브 계정 분리 기능을 쓰면 에이전시 안의 서브 계정을 별도의 독립 에이전시 계정으로 바꿀 수 있어요. 이 과정에서 서브 계정의 사용자 한 명을 새 에이전시의 소유자로 지정해요. 지정된 사용자는 이메일로 월 $97 요금제 가입 초대를 받아요. 이 사용자가 가입을 마치면, 이후 갱신 때마다 제휴 수수료 40%를 받아요.

제휴 프로그램 운영 방식이 궁금하면 하이퍼클래스 고객지원에 문의하세요. 분리한 서브 계정의 추천 현황은 **제휴 포털**(Affiliate Portal)에서 확인할 수 있어요.

## 서브 계정을 새 에이전시로 분리하기 (보내는 쪽)

1. **Agency Level**(에이전시 레벨) > **서브 계정**으로 이동해요. 새 에이전시로 분리할 서브 계정에서 **고객 관리**를 클릭해요.

   ![서브 계정 목록에서 고객 관리 선택](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155032998542/original/TG4fKh8CtFpKC0Wn__uFyn7obgUpmLp7TA.jpeg?1726567855)
2. **작업 > Transfer Sub-account**(서브 계정 전송)를 선택해요.

   ![작업 메뉴에서 서브 계정 전송 선택](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155032998546/original/E201sZHWG-zKBD6avJRZq3_1FXiQSwibiA.jpeg?1726567855)
3. **Transfer to an Existing Agency**(기존 에이전시로 전송)와 **Eject to a New Agency**(새 에이전시로 분리) 두 가지 옵션이 나와요. 이 중 **Eject to a New Agency**를 선택해 계속해요.

   기존 에이전시로 전송하려면 별도 상세 가이드를 참고하세요.

   ![전송 옵션 선택 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155033682586/original/MAnai5Tm9gM9rMKlrZ6nIGsP9NKCyibGvg.png?1727439253)
4. 새 에이전시의 **에이전시 소유자**를 지정해요.

   여기서 선택한 사용자는 새 에이전시 계정을 설정할 수 있는 가입 링크를 이메일로 받아요. 가입을 마치면 새로 만들어진 에이전시 계정의 소유자로 지정돼요.

   ![에이전시 소유자 지정 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155033000784/original/qPzIvJKRJW7MHUC3SgjSA40kwNd4MFDTXw.png?1726569252)
5. 서브 계정 분리 안내 사항을 확인하고 **전송 확인**을 클릭해요.

   ![서브 계정 분리 안내와 전송 확인 버튼](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155033000844/original/zZQoRaO0NM5sS-KYX8wsUoeIp8kBOlLSIA.png?1726569311)
6. **비밀번호를 입력하세요** 입력란에 비밀번호를 입력해 전송을 확인해요. 확인하면 지정된 사용자에게 새 에이전시 계정 설정 방법이 담긴 이메일이 발송돼요.

   ![비밀번호 입력으로 전송 확인](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155033000911/original/MDp5BR8xjYdjZmzMU33ZGElC_GzxXokOog.png?1726569341)
7. 서브 계정 전송 요청 현황을 추적하려면 **Agency Level > 서브 계정**으로 이동해 **Sub-account Transfers**(서브 계정 전송)를 선택해요. 그다음 **Eject**(분리) 탭으로 이동해요.

   ![분리 탭에서 전송 요청 확인](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155033650867/original/7bEJje8hMbFqnNXpjtqwhhR_eEyTIdKVhw.png?1727417054)

## 서브 계정을 받고 새 에이전시로 가입하기 (지정받은 사용자)

지정받은 사용자(새 에이전시 소유자)는 제목이 "Access your account"인 이메일을 받아요. 이메일 안의 버튼이나 링크를 클릭해 설정을 시작하세요.

1. `Location Eject request from - {Agency Name}`을 클릭해요. 새 창에서 로그인 페이지가 열려요.

   ![이메일의 분리 요청 링크](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155033340768/original/G-AjgDtsmqxR3tIAA2vEZ2X2Ch0NWxPDIQ.png?1727077451)
2. 새 브라우저 창에서 로그인 페이지가 열리면, 하이퍼클래스 계정에 연결된 이메일 주소와 비밀번호로 로그인해요.

   ![로그인 페이지](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155033003850/original/YF5BRiNfCfBQ_eHr9P7d0RVoRpk0tIcugA.png?1726571251)
3. 새 에이전시 계정의 **Company Details**(회사 정보)와 **청구지 주소**를 입력해요. 대부분 미리 채워져 있으니 확인하고 필요하면 수정하세요.

   ![회사 정보 입력 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155033003951/original/8zqp6Vfm6rfB9uAguynOBFxGjyTmagVZ6Q.png?1726571293)
   ![청구지 주소 입력 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155033004009/original/ayMBw38RWYLBIWJNgeNfU73Vl9kSsFAvKg.png?1726571323)
4. 가입 과정은 기본적으로 월 $97 요금제로 진행돼요. **Continue to Payment**(결제 계속)를 클릭해 결제 정보 입력으로 넘어가요.

   ![요금제 확인과 결제 계속 버튼](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155033870147/original/1QHYjLT2Mwk2pKIxYOQvpxaQ2WutzhG0_g.png?1727781395)
5. 주문 요약을 확인하고 카드 정보를 입력한 뒤, 확인해서 가입을 마쳐요.

   ![주문 요약과 카드 정보 입력](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155033340214/original/yqcRpXSZaC3jMg6V9xgdYe9dWjUzHx5HUg.png?1727077168)
6. 결제와 가입이 끝나면 환영 이메일을 받아요. 이메일에 있는 링크로 새 계정의 비밀번호를 설정하고 로그인하세요.

   ![환영 이메일](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155033340845/original/Xw7MgpWACdSjmcwCUdD9DrGfEwo1G9EKvw.png?1727077502)

원래 에이전시에서 분리된 서브 계정은 새 에이전시 계정이 만들어지면 자동으로 새 에이전시 계정으로 전송돼요.
{% endhint %}

## 함께 전송되는 정보와 자산

- 웹사이트와 퍼널이 모두 전송돼요.
- 캘린더가 전송돼요.
  {% hint style="info" %}
  외부 캘린더 연동은 연결이 끊어져요.
  {% endhint %}
- 모든 자동화가 전송돼요.
  {% hint style="info" %}
  자동화는 모두 **Draft**(초안) 상태로 설정돼요.
  {% endhint %}
- 연락처와 연락처의 대화, 예약, 기회, 이력이 전송돼요.
- **User Type**(사용자 유형)이 **Account**이면서 해당 서브 계정에만 배정되고 다른 서브 계정에는 배정되지 않은 사용자가 모두 전송돼요.
- 연락처는 워크플로우에 그대로 남아 있어요.
- 워크플로우에 등록된 데이터도 그대로 유지돼요.
- 서브 계정 단위 API 키는 그대로 유지돼요.

## 중요: 전송되지 않는 정보와 자산

- 모든 인증 연결이 삭제돼요. (예: Google, Facebook, Instagram, Quickbooks, Clio, DrChrono, Yext)
- Facebook과 Google 설정이 모두 초기화돼요.
- 서브 계정 단위 Stripe 필드가 초기화돼요.
- SaaS 설정은 전송되지 않아요.
  {% hint style="info" %}
  전송이 이루어지기 전에 SaaS 모드가 자동으로 비활성화돼요.
  {% endhint %}
- 스마트 리스트는 현재 서브 계정과 함께 전송되지 않아요.
- Mailgun/SMTP는 전송되지 않아요.
- WordPress, Yext, WhatsApp, **전용 IP** 같은 활성 구독은 전송되지 않아요. 전송하기 전에 먼저 해지해야 해요.

## 전화번호 전송

**두 에이전시 모두 하이퍼클래스 전화를 사용하는 경우**

- 보내는 에이전시, 받는 에이전시, 전송할 서브 계정이 모두 하이퍼클래스 전화를 사용하면 전화번호가 서브 계정과 함께 자동으로 전송돼요.
- A2P DLC 상태는 그대로 유지돼요. 이미 등록한 전화번호는 서브 계정에서 다시 등록하지 않아도 돼요.
- 이후 발생하는 전화 사용 요금은 모두 받는 에이전시에 청구돼요.

**두 에이전시가 모두 하이퍼클래스 전화를 사용하지 않는 경우 (한쪽 또는 양쪽이 Twilio)**

하이퍼클래스에서는 전화번호를 전송하지 않아요. 전송된 서브 계정에 계속 연결해 두고 싶은 전화번호가 있다면, 이전 계정 소유자와 Twilio에 직접 요청해 옮겨야 해요.

궁금한 점은 하이퍼클래스 고객지원에 문의하세요.

## 도메인 전송

서브 계정을 새 에이전시로 분리할 때 도메인(서브도메인 포함)이 어떻게 처리되는지 정리했어요. 서브 계정 분리 문서와 하이퍼클래스의 도메인 설정 흐름을 기준으로 해요.

1. **도메인은 자동으로 넘어가지 않아요.**
   서브 계정 분리 문서의 "새 에이전시는 전송 후 어떤 설정이 필요한가요?" 항목에 다음과 같이 명시되어 있어요.

   > "도메인을 다시 추가해야 합니다."
   > 즉 루트 도메인(예: mybusiness.com)이든 서브도메인(예: marketing.mybusiness.com)이든, 사용 중인 커스텀 URL은 새로 만들어진 에이전시에서 다시 설정해야 해요. 기존 DNS 레코드는 자동으로 "이동"하지 않아요.
2. **여기서 말하는 "도메인"에는 루트 도메인과 서브도메인이 모두 포함돼요.**
   하이퍼클래스에서 도메인을 연결할 때는 루트 도메인이나 서브도메인 중 하나를 입력할 수 있어요. 두 경우 모두 과정은 거의 비슷해요.

- 루트 도메인(예: `mydomain.com`)은 **도메인** 입력란에 그대로 입력해요. 그다음 안내되는 레코드(주로 A 레코드, 또는 하이퍼클래스를 가리키는 `www` CNAME)로 DNS 제공업체 설정을 업데이트해요.
- 서브도메인(예: `funnels.mydomain.com`, `pages.mydomain.com`)은 전체 서브도메인 주소를 **도메인** 입력란에 입력해요. 그러면 하이퍼클래스가 DNS 레코드(대부분 CNAME)를 만들어 주는데, 이를 DNS 호스트에 복사해 넣으면 돼요.

  두 경우 모두 DNS가 반영되면 하이퍼클래스가 도메인을 검증하고 SSL 인증서를 자동으로 발급해요.

분리 과정에서 도메인(서브도메인 포함)은 "상속"되지 않아요. 새 소유자가 서브 계정을 수락하면 바로 도메인을 다시 설정하세요. 그래야 기존 퍼널, 웹사이트, 브랜드 링크가 끊기지 않고 계속 연결돼요.

## 서브 계정 전송 FAQ

### 분리하기 전에 서브 계정에서 미리 준비할 일은 무엇인가요?

- 함께 전송하려는 사용자는 모두 **User Type**을 **Account**로 설정하고, 전송할 이 서브 계정에만 배정해 두세요.
- SaaS 서브 계정은 SaaS를 비활성화해야 해요.
- WordPress, Yext, WhatsApp, **전용 IP** 같은 활성 구독은 전송을 요청하기 전에 모두 해지해야 해요.

### 전송이 끝난 뒤 새 에이전시에서 어떤 설정이 필요한가요?

- 인증 연결을 모두 다시 연결해야 해요. (예: Google, Facebook, Quickbooks, Clio, DrChrono)
- Facebook과 Google을 다시 연동해야 해요.
- 서브 계정 단위 Stripe를 설정해야 해요.
- 하이퍼클래스 이메일, Mailgun/SMTP, Twilio를 다시 추가해야 해요.
- 도메인을 다시 추가해야 해요.
- SaaS 서브 계정은 SaaS를 다시 활성화해야 해요.

### HIPAA가 활성화된 서브 계정도 분리할 수 있나요?

네, HIPAA가 활성화된 서브 계정도 분리할 수 있어요. 다만 새 에이전시는 가입 과정에서 HIPAA 애드온을 구매해야 해요. 이 애드온은 결제 단계의 주문 요약에 자동으로 포함되어, 새 에이전시도 HIPAA 규정 준수를 유지할 수 있어요.

### 위치를 전송하면 삭제된 워크플로우가 **삭제됨** 탭에 보이나요?

이전 위치에서 삭제한 워크플로우는 새 위치에서 보이지 않아요. **삭제됨** 탭에는 새 위치에서 삭제한 워크플로우만 표시돼요.

### 화이트라벨(앱) 서브도메인은 어떻게 되나요?

에이전시에 `app.yourbrand.com` 같은 화이트라벨 도메인이 있어도 이 도메인 역시 자동으로 전송되지 않아요.
