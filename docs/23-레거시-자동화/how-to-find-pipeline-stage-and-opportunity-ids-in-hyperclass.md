# 파이프라인 ID, 단계 ID, 기회 ID 찾기

파이프라인 ID, 단계 ID, 기회 ID는 API, 웹훅, 가져오기, 외부 연동, 감사 로그 같은 기술 작업에서 쓰는 고유 식별자예요. 이 문서에서는 각 ID가 무엇인지, 언제 필요한지, 어디서 찾는지 알려 드려요.

하이퍼클래스 화면 안에서 작업할 때는 보통 이 ID를 직접 입력하지 않아요. 파이프라인과 단계를 이름으로 고를 수 있기 때문이에요. 다른 시스템이나 작업에서 ID를 콕 집어 요구할 때 이 문서가 도움이 돼요.

---

# 파이프라인 ID, 단계 ID, 기회 ID란?

세 ID는 하이퍼클래스 기회 관리 구조의 각기 다른 부분을 가리켜요. 각 ID가 무엇을 뜻하는지 알면 연동을 설정하거나, 기록을 업데이트하거나, 기회 활동을 점검할 때 알맞은 ID를 쓸 수 있어요.

- 파이프라인 ID: 특정 파이프라인을 구분해요.
- 단계 ID: 파이프라인 안의 특정 단계를 구분해요.
- 기회 ID: 기회 기록 하나를 구분해요.

이 ID는 하이퍼클래스 화면에 보이는 이름과 달라요. 예를 들어 파이프라인 이름이 영업 파이프라인이어도, 파이프라인 ID는 그 파이프라인에 붙은 고유한 시스템 식별자예요.

마찬가지로 단계 이름이 적격 리드여도, 단계 ID는 그 파이프라인 안의 해당 단계를 구분하는 값이에요.

---

## ID를 알아 두면 좋은 점

고유 ID를 쓰면 표시 이름이 바뀌거나 다른 곳에서 이름이 겹쳐도 시스템이 올바른 파이프라인, 단계, 기회를 정확히 가리킬 수 있어요. 하이퍼클래스가 다른 시스템과 데이터를 주고받을 때 특히 유용해요.

- 정확한 기록 식별: 기술 작업에서 정확한 식별자가 필요할 때 알맞은 파이프라인, 단계, 기회를 가리킬 수 있어요.
- API·연동 지원: 필요할 때 지원되는 API 엔드포인트, 웹훅 처리, 외부 연동에 ID를 전달할 수 있어요.
- 기회 업데이트: 지원되는 업데이트 작업에서 기존 기회를 구분할 수 있어요.
- 문제 해결: 지원되는 감사·진단 작업에서 특정 파이프라인이나 기회를 조사할 수 있어요.
- 안정적인 자동화: 외부 시스템이 특정 하이퍼클래스 기록을 가리켜야 할 때 헷갈리지 않아요.

---

## 파이프라인 ID, 단계 ID, 기회 ID가 필요한 경우

하이퍼클래스 안의 일상적인 작업은 대부분 ID를 직접 입력할 필요가 없어요. 화면에서 더 쉬운 방법을 이미 제공하는데도 기술적인 값을 찾느라 시간을 쓰지 않도록, 언제 ID가 필요한지 알아 두세요.

다음 작업에서는 ID가 필요할 수 있어요.

- 하이퍼클래스 API
- 웹훅
- Zapier 또는 지원되는 다른 외부 연동
- 기회 가져오기 또는 업데이트
- **감사 로그**
- 맞춤 기술 워크플로우
- 특정 기회로 연결되는 리다이렉트나 링크

하이퍼클래스 안에서 일반적으로 기회를 만들 때는 **파이프라인**과 **파이프라인 단계**를 선택 가능한 값 중에서 바로 골라요.

일반적인 하이퍼클래스 워크플로우 액션도 마찬가지예요. 예를 들어 **Create Opportunity**(기회 만들기) 워크플로우 액션에서는 파이프라인과 파이프라인 단계를 바로 선택할 수 있어서, 이 경우에는 단계 ID를 직접 입력하지 않아도 돼요.

{% hint style="warning" %}
모든 연동이나 API 요청에 세 가지 ID가 전부 필요하다고 생각하지 마세요. 설정하려는 엔드포인트, 웹훅, 가져오기, 연동의 요구 사항을 항상 확인하세요.
{% endhint %}

---

## 세 ID의 관계

파이프라인, 단계, 기회는 계층 구조로 이어져 있어요. 이 관계를 알면 외부 작업이 어떤 ID를 요구하는지 판단하기 쉬워요.

일반적인 구조는 다음과 같아요.

- 파이프라인
  - 단계
  - 단계
  - 단계
    - 기회
    - 기회

예를 들면 이래요.

- 파이프라인: 영업 파이프라인
- 단계: 적격 리드
- 기회: ACME 웹사이트 리뉴얼

파이프라인 ID는 영업 파이프라인을 가리켜요.

단계 ID는 그 파이프라인 안의 적격 리드 단계를 가리켜요.

기회 ID는 ACME 웹사이트 리뉴얼이라는 개별 기회를 가리켜요.

단계 ID와 단계 이름을 혼동하지 마세요. 이름은 사용자에게 보이는 표시용 라벨이고, ID는 그 단계에 붙은 시스템 식별자예요.

---

## 파이프라인 ID와 단계 ID 찾기

파이프라인 ID와 단계 ID는 기술 작업에서 시스템 식별자가 필요할 때만 쓰는 값이에요. 일반 화면에서는 파이프라인과 단계를 이름으로 고를 수 있으므로, 평소 파이프라인이나 기회를 관리할 때는 이 ID가 필요 없어요.

지원되는 API 응답이나 연동 밖에서 파이프라인 ID나 단계 ID가 필요하다면, 하이퍼클래스 문서에서는 기회 내보내기를 기본 방법으로 안내해요.

기회를 내보내려면 다음과 같이 하세요.

1. **기회 관리**(Opportunities)로 이동하세요.
2. 오른쪽 위에 있는 점 세 개 메뉴를 클릭하세요.
3. **Export Opportunities**(기회 내보내기)를 선택하세요.
4. 하이퍼클래스가 내보내기를 처리할 때까지 기다리세요.
5. 내보낸 파일을 열어 필요한 기회, 파이프라인, 단계 데이터를 확인하세요.

API, 웹훅, Zapier 등 외부 연동을 쓴다면 해당 작업에서 필요한 파이프라인 ID나 단계 ID를 반환하거나 요구할 수도 있어요. ID 형식을 미리 짐작하지 말고, 해당 엔드포인트나 연동의 최신 문서를 따르세요.

{% hint style="warning" %}
예전에 안내하던 Zapier 전용 방법만이 유일한 방법은 아니에요. 사용하는 연동이나 API 작업에 따라 정확한 단계가 달라질 수 있어요.
{% endhint %}

## 파이프라인 ID

파이프라인 ID는 하이퍼클래스 서브 계정 안의 파이프라인 하나를 고유하게 구분해요. 파이프라인 이름을 화면에 표시하거나 선택하는 것이 아니라, 파이프라인 자체를 가리켜야 하는 기술 작업에서 유용해요.

파이프라인 ID는 다음과 같은 곳에 쓰일 수 있어요.

- 특정 파이프라인을 대상으로 하는 API 요청
- 파이프라인 식별이 필요한 외부 연동
- 웹훅 또는 데이터 처리 워크플로우
- 지원되는 감사 로그·문제 해결 용도

일반적인 파이프라인 관리에는 파이프라인 ID가 필요하지 않아요.

하이퍼클래스에서 파이프라인을 직접 관리하려면 다음 경로로 이동하세요.

**기회 관리 > 파이프라인**

여기서 ID 없이도 파이프라인을 만들고, 이름을 바꾸고, 순서를 바꾸고, 파이프라인 단계를 관리할 수 있어요.

---

## 단계 ID

단계 ID는 파이프라인 안의 특정 단계를 고유하게 구분해요. API나 외부 연동에서 단계의 표시 이름이 아니라 시스템 식별자를 요구할 때 가장 유용해요.

예를 들어 한 파이프라인에 다음과 같은 단계가 있다고 해 볼게요.

- 신규 리드
- 적격
- 제안서 발송
- 종료

각 단계는 저마다 시스템 식별자를 가지고 있어요.

하이퍼클래스 안에서 직접 작업할 때는 대개 단계 ID가 필요 없어요. 일반적인 기회 설정이나 워크플로우 설정에서는 단계를 이름으로 고를 수 있어요.

예를 들어 기회를 직접 만들 때는 다음 순서로 선택해요.

1. **파이프라인**
2. **파이프라인 단계**
3. 기회의 나머지 상세 정보

**Create Opportunity** 워크플로우 액션에서도 파이프라인과 파이프라인 단계를 바로 선택할 수 있어요.

설정하려는 외부 작업에서 단계 ID를 명확히 요구할 때만 단계 ID를 쓰세요.

---

## 기회 ID 찾기

기회 ID는 기회 기록 하나를 고유하게 구분해요. 파이프라인 ID나 단계 ID와 달리, 기회 ID는 기회 화면에서 바로 볼 수 있어요. **감사 로그**, 직접 링크, 가져오기, 기술 연동에서 자주 쓰여요.

기회 ID를 찾으려면 다음과 같이 하세요.

1. **기회 관리**로 이동하세요.
2. 확인하려는 기회를 여세요.
3. 기회 화면 왼쪽 아래에 표시된 **기회 ID**를 찾으세요.
4. 관련 **감사 로그** 활동을 보려면 **기회 ID**를 클릭하세요.

하이퍼클래스의 최신 기회 관리 문서에 따르면, **기회 ID**를 선택하면 해당 기회의 **감사 로그**로 이동할 수 있어요.

![기회 화면 왼쪽 아래의 기회 ID](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155078987104/original/_ztAia7mW8C0vFu-xay8IJxrKwmq-rxpuA.png?1787307250)

### URL에서 기회 ID 찾기

기회의 URL에서도 기회 ID를 확인할 수 있어요.

1. 특정 기회를 여세요.
2. 브라우저 주소창의 URL을 확인하세요.
3. 기회 URL 끝에 있는 식별자가 해당 기회 기록의 ID예요.

이 방법은 권한이 있는 다른 하이퍼클래스 사용자에게 특정 기회의 직접 링크를 공유할 때도 유용해요.

![브라우저 주소창에 표시된 기회 URL](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155078986548/original/nckxmCwRA1f7zoM6gGsEOo4QQSuE3rXLXg.jpeg?1787306931)

## 기회 ID를 쓰는 대표적인 경우

파이프라인이나 단계 전체가 아니라 기회 하나를 정확히 가리켜야 할 때 기회 ID가 유용해요. 기존 기회 기록을 업데이트하거나 문제를 점검할 때 특히 중요해요.

대표적인 사용 예는 다음과 같아요.

- **감사 로그**: 특정 기회와 관련된 활동을 추적해요.
- 기회 직접 링크: 기회 하나를 가리키는 링크를 열거나 공유해요.
- 기회 가져오기: 업데이트할 때 기존 기회를 구분해요.
- API 요청: 엔드포인트에서 요구할 때 특정 기회를 지정해요.
- 외부 연동: 외부 기록을 그에 해당하는 하이퍼클래스 기회와 맞춰 봐요.

기회를 가져올 때 기존 기회를 업데이트하는 것이 목적이라면 **기회 ID**를 포함하세요. 업데이트 상황에서 기회 ID를 넣지 않으면, 하이퍼클래스가 기존 기회를 업데이트하지 않고 새 기회를 만들 수 있어요.

---

## 기회 가져오기에서 ID 사용하기

CSV 가져오기로 기존 기회를 업데이트할 때 기회 ID를 쓸 수 있어요. 올바른 식별자를 넣으면 하이퍼클래스가 가져온 행을 업데이트할 기회와 정확히 연결할 수 있어요.

기회를 가져올 때는 다음과 같이 지원되는 필드가 필요해요.

- **Contact ID**(연락처 ID)
- **기회명**
- **파이프라인**

기존 기회를 업데이트할 때는 매핑하는 데이터에 **기회 ID**를 포함하세요.

전체 과정은 [하이퍼클래스에서 CSV 파일로 기회 가져오기](../05-기회-파이프라인/시작하기/importing-opportunities-using-a-csv-file.md)를 참고하세요.

---

## API와 외부 연동에서 ID 사용하기

API와 외부 연동은 표시 이름에 의존하지 않고 ID로 하이퍼클래스 기록을 가리킬 수 있어요. 어떤 식별자가 필요한지는 수행하는 작업에 따라 달라요.

예를 들면 이래요.

- 파이프라인 관련 요청에는 파이프라인 ID가 필요할 수 있어요.
- 단계 관련 요청에는 단계 ID가 필요할 수 있어요.
- 기회 업데이트에는 기회 ID가 필요할 수 있어요.

ID를 넣기 전에 해당 API 엔드포인트나 연동의 최신 문서를 꼭 확인하세요.

하이퍼클래스의 최신 API 안내는 마켓플레이스 API 문서로 관리돼요. 자세한 내용은 [하이퍼클래스 API 문서](../35-개발자/Developer-Resources/hyperclass-api-documentation.md)를 참고하세요. 예전(레거시) API 동작을 새 연동의 기준으로 삼지 마세요.

{% hint style="warning" %}
파이프라인 ID, 단계 ID, 기회 ID는 서로 바꿔 쓸 수 없어요. 잘못된 식별자를 넣으면 연동이나 API 요청이 실패하거나 엉뚱한 리소스를 가리킬 수 있어요.
{% endhint %}

## 알맞은 ID 찾아서 쓰기

외부 작업이 하이퍼클래스의 어떤 대상을 가리켜야 하는지부터 파악하면 알맞은 식별자를 쉽게 찾을 수 있어요. 올바른 ID를 쓰면 불필요한 문제 해결을 줄이고, 업데이트가 의도한 기록에 적용돼요.

1. 작업이 **파이프라인**, **단계**, 개별 **기회** 중 무엇을 가리키는지 확인하세요.
2. ID 대신 이름을 바로 쓸 수 있는지 확인하세요.
3. 파이프라인 ID나 단계 ID가 필요하면, 사용 중인 내보내기, API, 웹훅, 연동 중 지원되는 방법으로 식별자를 가져오세요.
4. 기회 ID가 필요하면, 기회를 열어 기회 기록이나 URL에서 ID를 확인하세요.
5. 최신 연동 문서나 API 문서에서 ID 요구 사항이 맞는지 확인하세요.
6. 넓게 적용하기 전에 워크플로우를 먼저 테스트하세요.

---

## 자주 묻는 질문

### 하이퍼클래스 안에서 기회를 만들 때 파이프라인 ID가 필요한가요?

아니요. 하이퍼클래스 화면에서 기회를 만들 때는 선택 가능한 옵션에서 파이프라인을 바로 고르면 돼요.

### 기회를 만들 때 단계 ID가 필요한가요?

하이퍼클래스에서 일반적으로 기회를 만들 때는 필요 없어요. 파이프라인 단계를 이름으로 고르면 돼요. 단계 ID는 보통 API나 외부 연동에서 특별히 요구할 때만 필요해요.

### 단계 ID와 단계 이름은 같은 건가요?

아니요. 단계 이름은 하이퍼클래스에 표시되는 라벨이고, 단계 ID는 그 단계에 붙은 고유한 시스템 식별자예요.

### 서로 다른 파이프라인에 비슷한 이름의 단계가 있을 수 있나요?

네, 있을 수 있어요. 단계는 파이프라인에 속해 있으므로, 외부 연동에서는 단계 이름이 올바른 단계를 유일하게 가리킨다고 가정하지 말고 설정에서 요구하는 식별자를 쓰세요.

### 기회 ID는 어디서 찾나요?

기회를 열고 기회 상세 정보에서 기회 ID를 찾으세요. 기회 URL 끝부분에서도 ID를 확인할 수 있어요.

### 가져오기에서 기회 ID가 왜 필요한가요?

가져오기로 기존 기회를 업데이트할 때, 기회 ID가 있으면 하이퍼클래스가 새로 만들지 않고 어떤 기존 기회를 업데이트할지 알 수 있어요.

### 모든 API와 연동에 파이프라인 ID, 단계 ID, 기회 ID가 필요한가요?

아니요. 엔드포인트나 연동에 따라 요구 사항이 달라요. 이름을 선택하거나 입력할 수 있는 작업도 있고, 고유 ID가 꼭 필요한 작업도 있어요.

### ID 대신 파이프라인 이름이나 단계 이름을 쓸 수 있나요?

하이퍼클래스 화면과 일반적인 하이퍼클래스 워크플로우에서는 보통 이름을 바로 선택할 수 있어요. API나 외부 연동에서는 해당 문서가 요구하는 정확한 필드 형식을 따르세요.
