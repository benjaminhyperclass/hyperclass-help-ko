# AI 스튜디오 풀스택 프로젝트: SSR, 서버 함수, REST API, 비밀 값

새로 만드는 모든 **AI 스튜디오** 프로젝트에서 서버 사이드 렌더링(SSR), 서버 함수, REST API, 비밀 값(Secrets)을 쓸 수 있어요. 프라이빗 베타는 끝났고, 이제 모든 새 프로젝트가 TanStack Start 구조를 사용해요.

같은 프로젝트 안에서 프런트엔드 화면과 지원되는 백엔드 기능을 함께 만들고, **AI 스튜디오**의 게시 흐름으로 한 번에 게시할 수 있어요.

## 이 문서에서 알려드려요

새 **AI 스튜디오** 프로젝트는 TanStack Start를 사용하고, 한 프로젝트 안에서 SSR, 서버 함수, REST API, 비밀 값을 지원해요.

이 문서에서는 다음 내용을 설명해요.

- 각 기능이 어떻게 동작하는지
- 서버 함수와 REST API 중 무엇을 써야 하는지
- 인증 정보를 안전하게 보관하는 방법
- 기존 프로젝트에는 어떤 영향이 있는지
- 풀스택 애플리케이션을 게시하는 방법

## 기존 AI 스튜디오 프로젝트

새로운 풀스택 구조는 새로 만드는 **AI 스튜디오** 프로젝트에 적용돼요. 기존 Vite/React 프로젝트는 지금 쓰는 구조를 그대로 유지하고, TanStack Start로 자동 전환되지 않아요. 기존 프로젝트에서 새 구조를 쓰려면 별도의 마이그레이션 과정이 필요해요.

## AI 스튜디오의 SSR, 서버 함수, REST API, 비밀 값이란?

**AI 스튜디오**의 풀스택 구조를 쓰면 프런트엔드만 있는 애플리케이션을 넘어서 만들 수 있어요. 새 프로젝트에서는 서버에서 페이지를 렌더링하고, 비공개 로직을 실행하고, HTTP 엔드포인트를 열고, 민감한 인증 정보를 브라우저 코드 밖에 보관할 수 있어요.

이 기능은 네 가지로 이루어져 있어요.

- 서버 사이드 렌더링(SSR): 브라우저로 보내기 전에 서버에서 페이지 HTML을 만들어요.
- 서버 함수(Server Functions): 비공개 애플리케이션 로직을 서버에서 실행해요. 애플리케이션의 프런트엔드에서 호출할 수 있어요.
- REST API: 연동, 웹훅, 외부 애플리케이션에서 쓸 `/api/...` 같은 HTTP 엔드포인트를 만들어요.
- 비밀 값(Secrets): API 키, 토큰, 웹훅 시크릿 같은 민감한 값을 클라이언트 코드 밖에 보관해요.

## AI 스튜디오 풀스택 프로젝트의 장점

풀스택을 지원하면 고객에게 보이는 화면과 그 화면을 움직이는 서버 기능을 **AI 스튜디오**에서 함께 만들 수 있어요. 지원되는 범위에서는 프런트엔드와 백엔드 프로젝트를 따로 관리하지 않아도 돼요.

- 서버 렌더링 콘텐츠: 방문자, 검색 엔진, 소셜 미리보기를 만드는 서비스에 의미 있는 HTML을 전달해요.
- 비공개 백엔드 로직: 민감한 애플리케이션 로직을 브라우저 코드와 분리해요.
- 안전한 인증 정보: API 키와 토큰을 클라이언트 번들에 노출하지 않고 비밀 값으로 저장해요.
- 외부 연동: 웹훅, 서드파티 서비스, 외부 애플리케이션을 위한 REST 엔드포인트를 만들어요.
- 통합 개발: 같은 프로젝트에서 프런트엔드와 지원되는 백엔드 기능을 함께 만들어요.
- 통합 게시: 애플리케이션과 지원되는 서버 기능을 같은 흐름으로 게시해요.
- 하위 호환성: 기존 Vite/React 프로젝트는 자동으로 변환되지 않고 그대로 동작해요.

## 풀스택 구조는 어떻게 동작하나요?

기능마다 맡는 역할이 달라요. 페이지 렌더링, 비공개 백엔드 로직, 공개 HTTP 엔드포인트, 보호된 설정을 나눠 두면 프로젝트를 이해하고 관리하기가 쉬워져요.

| 기능 | 주된 목적 | 주로 쓰는 곳 |
| --- | --- | --- |
| SSR | 서버에서 페이지를 렌더링해요. | SEO, 공개 페이지, 소셜 미리보기 |
| 서버 함수 | 비공개 애플리케이션 로직을 실행해요. | 내부 백엔드 작업, 보호가 필요한 연동 |
| REST API | HTTP 엔드포인트를 열어요. | 웹훅, 연동, 외부 애플리케이션 |
| 비밀 값 | 민감한 설정을 보호해요. | API 키, 토큰, 인증 정보 |

### 서버 사이드 렌더링(SSR)

SSR은 방문자에게 응답하기 전에 서버에서 페이지 HTML을 만들어요. 그래서 검색 엔진, 소셜 플랫폼, 브라우저가 클라이언트 측 JavaScript로 페이지가 만들어지기를 기다리지 않고도 페이지 콘텐츠를 받을 수 있어요.

SSR은 다음과 같은 경우에 특히 유용해요.

- 마케팅 웹사이트와 랜딩 페이지
- 여러 페이지로 이루어진 웹사이트
- 공개 애플리케이션 페이지
- 고유한 URL과 메타데이터가 있는 페이지
- 검색 노출이 중요한 콘텐츠
- 링크 미리보기를 만드는 서비스에 공유되는 페이지

### 서버 함수

서버 함수를 쓰면 구현 코드를 브라우저 번들에 넣지 않고도 프런트엔드에서 서버 작업을 요청할 수 있어요. 애플리케이션에 속하지만 비공개로 유지해야 하는 작업에 알맞아요.

- 비공개 인증 정보를 사용해 외부 서비스 호출
- 보호가 필요한 데이터 불러오기
- 제출된 정보 검증
- 서버에서 계산 수행
- 프런트엔드로 돌려주기 전에 데이터 변환
- 민감한 애플리케이션 로직을 클라이언트 밖에 유지

{% hint style="info" %}
**보안 팁:** 서버 함수를 쓰면 구현 내용을 서버에 둘 수 있지만, 민감한 인증 정보는 여전히 비밀 값으로 저장하세요. 브라우저에는 꼭 필요한 정보만 돌려주세요.
{% endhint %}

### REST API

REST API 라우트는 **AI 스튜디오** 애플리케이션 밖의 서비스가 호출할 수 있는 HTTP 엔드포인트를 만들어요. `/api/...` 같은 경로를 쓸 수 있고, 애플리케이션에 따라 GET, POST 같은 메서드를 지원할 수 있어요.

- 웹훅 수신
- 서드파티 애플리케이션 연결
- 공개 API 또는 인증이 필요한 API 구축
- 다른 서비스에서 보낸 정보 수신
- JSON 같은 구조화된 데이터 반환

### 비밀 값

비밀 값은 프런트엔드 코드에 들어가면 안 되는 정보를 서버 쪽에 보관해요. 서버 측 기능이 민감한 값을 쓰면서도, 그 값이 클라이언트 번들에 노출되지 않게 할 수 있어요.

- API 키
- 인증 토큰
- 웹훅 서명 시크릿
- 연동 인증 정보
- 비공개 서비스 설정

## 서버 함수와 REST API 중 무엇을 쓸까요?

알맞은 서버 인터페이스를 고르면 애플리케이션이 단순해지고 불필요한 공개 엔드포인트도 줄어요. 애플리케이션 자체 프런트엔드가 호출하는 비공개 로직에는 서버 함수를, 외부 시스템이 호출할 HTTP 엔드포인트가 필요하면 REST API를 쓰세요.

| 필요한 상황 | 권장 방식 |
| --- | --- |
| 프런트엔드가 자체 백엔드 로직을 안전하게 호출 | 서버 함수 |
| 외부 서비스가 애플리케이션으로 데이터를 보냄 | REST API |
| 서드파티 시스템에 HTTP 엔드포인트가 필요함 | REST API |
| 내부 작업에 비공개 API 키가 필요함 | 서버 함수 + 비밀 값 |
| 웹훅 제공업체에 콜백 URL이 필요함 | REST API |
| 민감한 값을 브라우저 코드 밖에 둬야 함 | 비밀 값 |

## 새 프로젝트와 기존 Vite/React 프로젝트의 차이

**AI 스튜디오**는 기존 프로젝트의 기반 프레임워크를 자동으로 바꾸지 않고 그대로 보존해요. 내 프로젝트가 어떤 구조인지 알면 어떤 백엔드, SEO, 마이그레이션 안내가 적용되는지 알 수 있어요.

새로 만드는 모든 **AI 스튜디오** 프로젝트는 기본적으로 TanStack Start 풀스택 구조를 사용해요.

| 프로젝트 유형 | 동작 |
| --- | --- |
| 새 AI 스튜디오 프로젝트 | 현재의 TanStack Start 풀스택 구조를 사용해요. |
| 기존 Vite/React 프로젝트 | 기존 구조를 그대로 사용해요. |
| 새 구조가 필요한 기존 프로젝트 | 자동으로 변환되지 않고, 별도의 마이그레이션 과정이 필요해요. |

{% hint style="info" %}
**권장 사항:** 새 구조가 나왔다는 이유만으로 기존 프로젝트를 다시 만들지는 마세요. 먼저 애플리케이션에 SSR, 비공개 서버 로직, REST 엔드포인트, 비밀 값이 실제로 필요한지 확인하세요.
{% endhint %}

## SSR, 서버 함수, REST API, 비밀 값 설정하고 사용하기

각 기능을 어떻게 구현할지 정하기 전에 애플리케이션에 필요한 기능부터 정리하세요. 비공개로 처리할 작업, 외부 연동, 민감한 인증 정보를 미리 분명히 해 두면 **AI 스튜디오**가 기능을 알맞은 위치에 배치하는 데 도움이 돼요.

### 1단계: 새 AI 스튜디오 프로젝트 만들기

새 **AI 스튜디오** 프로젝트는 현재의 풀스택 구조를 사용해요. 프런트엔드 페이지와 지원되는 서버 측 기능을 함께 만들 수 있어요.

1. 사용할 하이퍼클래스 서브 계정을 엽니다.
2. 왼쪽 메뉴에서 **AI 스튜디오**를 엽니다.
3. 새 프로젝트를 만듭니다.
4. **AI 스튜디오**가 만들어 주길 바라는 웹사이트나 애플리케이션을 설명합니다.

### 2단계: 애플리케이션의 전체 동작 설명하기

디자인만 설명하지 말고 애플리케이션이 해야 할 일을 설명하세요. 해당하는 경우 외부 서비스, 비공개 인증 정보, 들어오는 웹훅, 보호가 필요한 처리, 공개 API 요구 사항도 함께 적어 주세요.

예시 프롬프트

> 공개 랜딩 페이지, 서버에서 실행되는 비공개 계정 조회 기능, 주문 상태 웹훅을 받는 API 엔드포인트가 있는 주문 상태 포털을 만들어 줘.

### 3단계: 보호가 필요한 인증 정보를 비밀 값으로 추가하기

서버 기능에 브라우저 코드에 노출되면 안 되는 값이 필요하면 비밀 값을 설정하세요.

1. 연동에 필요한 비공개 인증 정보를 확인합니다.
2. 안내가 나오면 **비밀 값** 절차에 따라 추가합니다.
3. 비밀 값에 알아보기 쉬운 이름을 붙입니다.
4. 그 값이 필요한 서버 측 기능에서만 비밀 값을 참조합니다.
5. 비공개 인증 정보를 브라우저로 돌려주지 않고 연동을 테스트합니다.

### 4단계: 서버 함수 만들고 검토하기

애플리케이션의 프런트엔드에 비공개로 유지해야 하는 백엔드 기능이 필요하면 서버 함수를 사용하세요.

1. 민감한 처리가 서버에서 실행되는지 확인합니다.
2. 비공개 인증 정보를 비밀 값에서 가져오는지 확인합니다.
3. 프런트엔드에 필요한 정보만 돌려줍니다.
4. 성공하는 요청과 실패하는 요청을 모두 테스트합니다.
5. 추가 검증이나 수정이 필요하면 생성된 코드를 검토합니다.

### 5단계: 외부 요청을 받을 REST API 만들기

다른 서비스나 애플리케이션이 HTTP로 **AI 스튜디오** 프로젝트와 통신해야 하면 REST API 라우트를 사용하세요.

1. 엔드포인트 경로를 정합니다.
2. 지원할 HTTP 메서드를 정합니다.
3. 받을 요청 페이로드 형식을 정합니다.
4. 필요하면 인증이나 서명 검증을 추가합니다.
5. 서버에서 요청을 처리합니다.
6. 알맞은 응답을 돌려줍니다.

{% hint style="warning" %}
**웹훅 보안:** 웹훅 제공업체가 인증이나 서명을 지원하면, 보호가 필요한 작업을 처리하기 전에 먼저 검증하세요.
{% endhint %}

### 6단계: 미리 보고 테스트하기

게시하기 전에 프런트엔드와 백엔드 동작을 모두 테스트하면 페이지 디자인만 봐서는 드러나지 않는 문제를 찾을 수 있어요.

- 공개 페이지가 정상적으로 불러와지는지 확인합니다.
- 서버 함수를 예상한 입력과 예상 밖의 입력으로 테스트합니다.
- REST 엔드포인트를 실제로 쓸 요청으로 테스트합니다.
- 비밀 값이 브라우저에서 보이는 출력에 노출되지 않는지 확인합니다.
- 중요한 오류 상태가 안전하게 처리되는지 확인합니다.
- 페이지 제목, 제목 구조(헤딩), 메타데이터를 검토합니다.

### 7단계: 애플리케이션 게시하기

게시하면 **AI 스튜디오**의 라이브 URL로 애플리케이션을 이용할 수 있고, 지원되는 애플리케이션 런타임도 함께 배포돼요.

1. **게시**를 클릭합니다.
2. 생성된 웹사이트 주소를 확인하거나 수정합니다.
3. 게시를 확정합니다.
4. 게시된 URL을 열어 실제 애플리케이션을 테스트합니다.

![게시 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155080660298/original/sBAV36e4SOlTJmYOOAZMWveDqPTmeZlfOA.jpeg?1789100104)

### 8단계: 사용자 지정 도메인 연결하기

생성된 프로젝트 URL 대신 내 도메인으로 방문자가 접속하게 하고 싶다면, 게시한 뒤에 사용자 지정 도메인을 연결할 수 있어요.

1. **게시**를 엽니다.
2. **Add Custom Domain**(사용자 지정 도메인 추가)을 선택합니다.
3. 사용할 도메인을 입력합니다.
4. 필요하면 **AI 스튜디오**가 안내한 DNS 레코드를 도메인 제공업체에서 추가합니다.
5. **Verify DNS**(DNS 인증)를 클릭합니다.
6. 인증서 발급이 끝날 때까지 기다립니다.
7. 연결된 도메인으로 애플리케이션을 테스트합니다.

**설정 > 도메인 & URL 리다이렉트 > 도메인 연결 > AI 스튜디오**에서도 **AI 스튜디오** 프로젝트에 사용자 지정 도메인을 연결할 수 있어요. 도메인 허브 흐름에서는 DNS 인증을 먼저 진행한 다음, 연결할 **AI 스튜디오** 프로젝트를 선택해요.

![사용자 지정 도메인 연결 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155080660313/original/b_NQ-jU2huRL8l7XCuxWaoYiTiR9DFH4Ww.png?1789100124)

## AI 스튜디오 프로젝트의 SEO 고려 사항

SEO 동작은 프로젝트가 쓰는 구조에 따라 달라요. 새 풀스택 프로젝트는 서버 사이드 렌더링을 사용하고, 기존 Vite/React 프로젝트는 지금의 구조와 그 프로젝트 유형에 맞는 SEO 도구를 계속 사용해요.

중요한 공개 페이지를 게시하기 전에 다음을 검토하세요.

- 페이지 제목
- 메타 설명
- 제목 구조(헤딩)
- 해당하는 경우 캐노니컬 URL
- 소셜 미리보기 정보
- 해당하는 경우 사이트맵 동작
- 게시된 실제 페이지에 렌더링된 콘텐츠

## 문제 해결

풀스택 애플리케이션의 문제는 프런트엔드 코드, 서버 로직, 엔드포인트 설정, 비밀 값, 게시, DNS 중 어느 곳에서든 생길 수 있어요. 어느 단계에서 실패하는지 먼저 파악하면 문제를 더 빨리 해결하고 불필요한 프로젝트 변경도 피할 수 있어요.

| 문제 | 확인할 내용 |
| --- | --- |
| 서버 함수가 실패해요 | 함수 입력값, 필요한 비밀 값, 서버 측 오류, 프런트엔드로 돌려주는 데이터를 검토하세요. |
| REST 엔드포인트를 호출할 수 없어요 | 엔드포인트 경로, HTTP 메서드, 애플리케이션의 게시 상태, 요청 형식, 인증 요구 사항을 확인하세요. |
| 외부 API 인증이 실패해요 | 올바른 비밀 값이 있는지, 서버 측 코드가 의도한 값을 참조하는지 확인하세요. |
| 웹훅 요청이 검증에 실패해요 | 서명 비밀 값, 요청 헤더, 서명 검증 로직, 콜백 URL을 확인하세요. |
| 사용자 지정 도메인이 열리지 않아요 | DNS 레코드가 **AI 스튜디오**가 안내한 값과 정확히 일치하는지 확인하고, 전파가 끝난 뒤 **Verify DNS**를 완료하세요. |
| 기존 프로젝트에서 새 구조의 동작이 보이지 않아요 | 프로젝트를 이전 Vite/React 구조로 만들었는지 확인하세요. 기존 프로젝트는 자동으로 마이그레이션되지 않아요. |

## 자주 묻는 질문

### 기존 AI 스튜디오 프로젝트도 자동으로 TanStack Start로 바뀌나요?

아니요. 기존 Vite/React 프로젝트는 기존 구조를 그대로 사용하고, 자동으로 마이그레이션되지 않아요.

### 서버 함수와 REST API는 무엇이 다른가요?

서버 함수는 주로 애플리케이션 자체 프런트엔드에 비공개 백엔드 로직이 필요할 때 써요. REST API는 외부 시스템이나 애플리케이션이 호출할 수 있는 HTTP 엔드포인트를 열어요.

### 서버 함수에서 비밀 값을 쓸 수 있나요?

네. 서버 측 애플리케이션 로직에 비공개 API 키, 인증 토큰 등 보호가 필요한 인증 정보가 필요할 때 흔히 쓰는 방식이에요.

### AI 스튜디오에서 웹훅 엔드포인트를 만들 수 있나요?

네. REST API 라우트로, 지원되는 웹훅 제공업체가 호출할 수 있는 HTTP 엔드포인트를 만들 수 있어요.

### 비밀 값을 프런트엔드 코드에 직접 넣어도 되나요?

아니요. 민감한 인증 정보는 비밀 값에 보관하고, 그 값이 필요한 서버 측 기능에서만 참조하세요.

### 새 프로젝트의 SSR이 기존 AI 스튜디오 프로젝트의 고급 SEO 기능을 대체하나요?

아니요. 기존 프로젝트는 기존 구조를 그대로 유지하므로, 그 프로젝트에 맞는 [고급 SEO(Advanced SEO) 도구](advanced-seo-support-for-ai-studio.md)를 계속 사용하게 돼요.

### 생성된 백엔드 코드를 직접 수정할 수 있나요?

네. [**Code Editor**(코드 편집기)](code-editor-in-ai-studio.md)에서 프로젝트 코드에 직접 접근해, 지원되는 범위의 수동 수정과 검증을 할 수 있어요.

### AI 스튜디오 프로젝트 코드를 내려받을 수 있나요?

네. 프로젝트 코드베이스를 ZIP으로 [내려받을 수 있어요](download-ai-studio-codebase-as-zip.md). **버전 기록**에서 이용할 수 있는 지원 버전도 포함돼요.
