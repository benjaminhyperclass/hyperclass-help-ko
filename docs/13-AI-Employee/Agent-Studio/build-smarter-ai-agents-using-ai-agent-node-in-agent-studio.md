# 에이전트 스튜디오의 AI Agent Node로 더 똑똑한 AI 에이전트 만들기

**AI Agent Node**(AI 에이전트 노드)는 **에이전트 스튜디오**의 플로우 기반 에이전트에서 판단을 맡는 노드예요. 입력을 이해하고, 지침을 따르고, 도구를 고르고, 정보를 모으고, 결과를 다음 노드로 넘겨요. 이 문서에서는 프롬프트, 모델, 모드, 도구, 변수, 연결을 설정하는 방법을 안내해요. 기존 **에이전트 스튜디오** 플로우를 더 안정적으로 동작시킬 때 참고하세요.

{% hint style="warning" %}
**에이전트 스튜디오**는 이미 만들어 둔 플로우 기반 에이전트를 관리하는 용도로 사용해요. 새 에이전트를 만들 때는 계정에서 제공하는, 하이퍼클래스가 현재 권장하는 방식을 따르세요.
{% endhint %}

---

## AI Agent Node란

**AI Agent Node**는 AI 에이전트가 어떻게 생각하고, 답하고, 행동할지 정하는 **에이전트 스튜디오**의 핵심 구성 요소예요. 들어온 입력을 처리하고 의도를 파악한 뒤, 다음에 할 일을 정해요. 답변을 만들거나, 도구를 쓰거나, 정보를 모으거나, 결과를 다음 노드로 보내는 식이에요.

**AI Agent Node**는 **Start Trigger**(시작 트리거)나 연결된 다른 노드에서 입력을 받으면 실행돼요. 고정된 로직과 달리 프롬프트 지침, 사용할 수 있는 도구, 사용자 입력, 맥락에 따라 동작을 바꿀 수 있어요.

그래서 입력을 예측하기 어렵거나, 대화가 필요하거나, 맥락에 따라 판단해야 하는 상황에 특히 잘 맞아요.

**AI Agent Node**는 다섯 가지 요소로 이루어져 있어요. 이 요소를 이해하면 에이전트를 효과적으로 설정할 수 있어요.

- 프롬프트
- 모델
- 모드
- 도구
- 변수

이 요소들이 함께 작동해서 실행 중 에이전트의 행동을 결정해요.

## AI Agent Node의 핵심 요소

**AI Agent Node**는 함께 작동하는 여러 설정 요소로 이루어져 있어요. 명확한 프롬프트, 알맞은 모델, 올바른 모드, 필요한 도구, 잘 정의한 변수, 깔끔한 노드 연결이 갖춰지면 에이전트가 일관되게 동작해요.

### 프롬프트

프롬프트는 에이전트의 역할, 말투, 업무, 도구를 쓸 시점을 정해서 **AI Agent Node**의 동작을 결정해요. 에이전트는 이 지침을 바탕으로 입력을 해석하고 판단해요.

덕분에 에이전트가 정해 둔 방식대로 일관되게 답해요. 예를 들어 고객 지원 에이전트의 프롬프트에 가격 문의에 답하고 필요하면 지식 베이스를 사용하라고 적어 두면 "프리미엄 요금제에는 무엇이 포함되나요?" 같은 질문을 가격 문의로 알아보고 알맞게 답해요.

좋은 프롬프트에는 다음 내용이 들어가요.

- 에이전트의 역할
- 노드의 목표
- 에이전트가 해야 할 일과 하지 말아야 할 일
- 말투나 스타일 요구 사항
- 도구를 사용할 시점
- 수집할 정보
- 다음 단계로 넘길 결과

**예시:**

> 당신은 고객 지원 분류 도우미입니다. 필요하면 확인 질문을 하고, 고객의 문의 유형을 파악하세요. 문의 카테고리는 런타임 변수로 저장하고, 고객이 상품 관련 질문을 하면 지식 베이스 검색 도구를 사용하세요.

### 모델

모델에 따라 **AI Agent Node**가 입력을 얼마나 잘 이해하고 답을 만드는지가 달라져요. GPT-5나 GPT-4.1 같은 고성능 모델은 추론 능력이 더 뛰어나요. Mini와 Nano 모델은 더 빠르고 가볍고, GPT-4o는 응답 지연 시간이 짧아요.

모델은 에이전트가 사용자 의도를 해석하고 답하는 방식에 바로 영향을 줘요. 예를 들어 사용자가 "제 사업에 맞는 방법을 알아보고 있어요"라고 하면, 고성능 모델은 이를 잠재 리드로 알아볼 수 있어요. 가벼운 모델은 더 일반적인 답을 할 수 있어요.

### 모드

모드는 **AI Agent Node**가 사용자와 대화하는지, 조용히 작업만 실행하는지를 정해요. **Conversational Mode**(대화 모드)에서는 에이전트가 직접 답하며 상호작용을 처리해요. **Task Based Mode**(작업 기반 모드)에서는 사용자에게 보이는 답변 없이 작업만 수행해요.

덕분에 용도에 맞게 에이전트의 동작을 바꿀 수 있어요. 예를 들어 **Conversational Mode**에서는 가격 질문에 답하고, **Task Based Mode**에서는 답변을 보내지 않고 이메일 같은 사용자 정보를 추출해 CRM을 업데이트해요.

### 도구

도구를 쓰면 **AI Agent Node**가 답변을 만드는 것 이상의 일을 할 수 있어요. 정보를 가져오거나 플로우의 방향을 정하는 일 등이에요. 에이전트는 프롬프트와 맥락을 보고 도구가 필요한 때를 판단해서 알맞은 도구를 골라요.

사용할 수 있는 도구는 다음과 같아요.

- 라우터
- 지식 베이스 검색
- **Search the Web**(웹 검색)
- MCP 서버
- 작업
- **API Call**(API 호출)
- 텍스트 생성, 이미지 생성, 동영상 생성, 오디오 생성

덕분에 에이전트가 판단과 실행을 실시간으로 함께 할 수 있어요. 예를 들어 사용자가 "해외 결제를 지원하나요?"라고 물으면, 에이전트는 지식 베이스 검색 도구로 정확한 정보를 찾아서 답할 수 있어요. 사용자 의도가 분명하지 않을 때는 라우터 도구로 플로우의 방향을 정할 수 있어요.

### 변수

변수를 쓰면 **AI Agent Node**가 데이터를 다룰 수 있어요. 이미 있는 입력은 맥락으로 활용하고, 실행 중에는 새 정보를 추출해요. 입력 변수는 에이전트에 맥락을 알려 주고, 런타임 변수는 상호작용 중에 구조화된 데이터를 수집해요.

덕분에 에이전트가 의미 있는 정보를 플로우 전체에서 기억하고 다음 작업으로 넘길 수 있어요. 예를 들어 사용자가 "안녕하세요, 저는 Rahul이에요. 데모가 필요해요"라고 하면, 에이전트는 이름 = Rahul, 요구 사항 = 데모처럼 정보를 수집해요. 이 정보는 CRM 업데이트나 후속 연락에 쓸 수 있어요.

### 노드 연결

**AI Agent Node**는 연결된 트리거나 노드에서 입력을 받으면 실행돼요. 설정해 둔 프롬프트, 모델, 도구, 변수로 데이터를 처리해요. 맥락을 살펴 알맞은 동작이나 답변을 정한 뒤, 결과를 플로우의 다음 연결된 노드로 내보내요.

에이전트 플로우 안에서 구조화된 결과를 다음 작업으로 넘겨 성과로 이어지게 해요. 예를 들어 리드를 분류한 뒤 이름, 요구 사항 같은 정보를 CRM 노드로 보내 후속 조치를 할 수 있어요.

## AI Agent Node의 장점

**AI Agent Node**를 쓰면 **에이전트 스튜디오** 플로우가 더 유연해지고 맥락을 잘 반영해요. 프롬프트, 도구, 변수, 노드 연결을 조합하면 정해진 경로만 따르지 않고 입력에 맞춰 달라지는 에이전트를 만들 수 있어요.

- 동적인 대화 처리: 에이전트가 사용자 입력을 해석하고 맥락에 맞게 답해요.
- 도구의 지능적 활용: 프롬프트와 사용자 입력에서 필요하다고 판단하면 연결된 도구를 골라 써요.
- 구조화된 데이터 수집: 이름, 이메일, 요청 유형, 의도 같은 런타임 변수를 추출해요.
- 유연한 라우팅: 결과를 뒤따르는 노드로 넘겨 후속 작업을 하거나 분기해요.
- 자동화 품질 향상: 프롬프트, 도구, 변수, 연결을 조합해 더 유연한 플로우를 만들어요.
- 수동 로직 감소: 고정된 조건만으로 부족할 때 맥락을 보고 판단해요.

## AI Agent Node를 쓰면 좋은 경우

**AI Agent Node**는 에이전트가 맥락을 이해하고, 자연스럽게 답하고, 도구를 고르고, 사용자 입력을 바탕으로 판단해야 할 때 가장 잘 맞아요. 입력을 예측하기 어렵거나 다음 단계가 의도에 따라 달라질 때 특히 유용해요.

AI Agent Node를 쓰기 좋은 경우는 다음과 같아요.

- 대화형 응답
- 리드 분류
- 지원 문의 분류
- 지식 베이스 조회
- 웹 검색
- 데이터 추출
- CRM 업데이트
- 도구 선택
- 동적 라우팅
- 맥락 기반 의사 결정

판단이 맥락에 따라 달라질 때는 **AI Agent Node**를 쓰세요. 미리 정한 단계를 정해진 순서대로 실행하는 플로우에는 **Sequential Node**(순차 노드)를 쓰세요.

## AI Agent Node 설정하기

**AI Agent Node**는 명확한 프롬프트, 알맞은 모델, 적절한 모드, 꼭 필요한 도구, 잘 정의한 변수를 갖추면 잘 작동해요. 이 요소를 올바르게 설정하면 에이전트가 정확하게 답하고, 작업을 효율적으로 실행하고, 깔끔한 구조의 로직을 유지해요.

### 1단계: AI Agent Node 추가하기

**에이전트 스튜디오**에서 **Nodes panel**(노드 패널)을 열고 에이전트 플로우에 **AI Agent Node**를 추가하세요. 캔버스에 놓은 뒤 **Start Trigger**나 앞 노드에 연결하세요.

![노드 패널에서 AI Agent Node를 추가하는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155069133970/original/34nDdfnwzDQFevymcxYAbIUhLtH9x2tu7g.png?1776180734)

### 2단계: 프롬프트 작성하기

설정 패널에 명확하고 구조화된 프롬프트를 입력하세요. 에이전트의 역할, 책임, 말투, 도구를 쓸 시점을 적어 주세요. 프롬프트가 실행 중 에이전트의 행동을 결정해요.

![설정 패널에서 프롬프트를 입력하는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155069134884/original/OABGsIZZI-Lg9Tp2xXIIPPz6EeO6o827fA.png?1776181029)

### 프롬프트에 변수 넣기

프롬프트 입력란의 {} 아이콘으로 동적 변수를 넣을 수 있어요. 에이전트가 답변을 만들 때 실시간 데이터와 맥락을 활용하므로 상호작용이 더 개인화되고 알맞아져요. 변수를 추가하면 에이전트가 실행할 때 이를 실제 데이터로 바꿔요. 예를 들어 "사용자를 이름으로 부르며 요청을 도와주세요"라는 프롬프트에 `{{contact.name}}`을 쓰면, 연락처 이름이 Rahul일 때 에이전트가 "안녕하세요 Rahul님, 무엇을 도와드릴까요?"라고 답해요.

변수를 잘 쓰면 에이전트가 답변을 개인화하고, 실시간 데이터를 활용하고, 플로우 전반에서 맥락을 유지하고, 정확도를 높일 수 있어요. 사용자별 데이터, 시간 관련 맥락, 다른 노드에서 넘어온 정보를 다룰 때 특히 유용해요. 다만 변수는 신중하게 쓰세요. 꼭 필요한 것만 넣어야 프롬프트가 명확하고 결과도 더 안정적이에요.

### 사용할 수 있는 변수 종류

- **전역 설정**: 에이전트 전체에 적용되는 시스템 수준 설정을 가져와요. 일관된 동작과 공통 값을 유지할 때 유용해요.

- **입력 변수**: 이전 노드나 트리거에서 넘어온 데이터를 사용해요. 플로우의 앞 단계에서 맥락을 이어받을 때 알맞아요.

- **런타임 변수**: 실행 중 에이전트가 추출한 데이터를 저장하고 다시 사용해요. 사용자와 상호작용하며 모은 정보를 저장하고 재사용할 때 도움이 돼요.

- **계정**: 회사 정보 같은 비즈니스 수준 정보를 가져와요. 브랜드나 계정 관련 데이터로 답변을 개인화할 때 유용해요.

- **커스텀 값**: 반복해서 쓸 고정 값을 직접 정해요. 프롬프트에 고정 지침이나 상수를 넣을 때 도움이 돼요.

- **Right Now**(현재 시각): 실시간 날짜와 시간 정보를 넣어요. 시간에 민감한 답변이나 맥락 있는 메시지에 유용해요.

- **연락처**: 이름, 이메일, 전화번호 같은 연락처별 정보를 사용해요. 사용자와 개인화되고 맥락에 맞는 상호작용을 할 수 있어요.

![프롬프트에 넣을 수 있는 변수 종류 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155069161366/original/3sh4c2TSkZW5Nwp_W2Rx8IFlAG6ALp6Ivw.png?1776218877)

### 프롬프트 개선

**프롬프트 개선** 옵션은 프롬프트를 더 명확하고 구조화된 버전으로 다듬어서 AI 에이전트를 효과적으로 안내하도록 도와줘요. 개선이 끝나면 제안된 프롬프트를 확인한 뒤 수락하거나, 거부하고 원래 프롬프트를 그대로 둘 수 있어요. 프롬프트 품질을 계속 다듬으면서도 에이전트가 실제로 쓰는 최종 지침은 직접 정할 수 있어요.

### 3단계: 모델 선택하기

- **Task Based Mode**(작업 기반 모드): 조용히 실행할 때 써요.

에이전트가 사용자에게 답해야 하는지, 백그라운드 작업을 해야 하는지에 따라 고르세요.

### 5단계: 도구 연결하기

용도에 꼭 필요한 도구만 추가하세요. 지식 베이스, 라우터, **Search the Web**(웹 검색) 등이 있어요. 이 도구들을 연결하면 에이전트가 필요할 때 정보를 가져오거나 작업을 실행할 수 있어요.

### 도구별 알아보기

각 도구는 맥락과 사용자 입력에 따라 특정 작업을 할 수 있게 해서 **AI Agent Node**의 기능을 넓혀 줘요. 도구를 언제, 어떻게 쓰는지 알아 두면 에이전트가 정확하게 판단하고 의미 있는 작업을 수행하는 데 도움이 돼요.

- **라우터**: 사용자 의도나 에이전트의 판단에 따라 알맞은 경로로 플로우를 보내요. 분기 로직을 만들 수 있어서 에이전트 하나로 여러 상황을 처리할 때 꼭 필요해요. 사용자를 영업, 지원, 대체 경로 같은 서로 다른 플로우로 보내야 할 때 쓰세요.

- **지식 베이스 검색**: 설정해 둔 지식 베이스에서 정보를 가져와요. 추측이 아니라 미리 정리한 데이터를 바탕으로 정확하고 일관되게 답할 수 있어요. 자주 묻는 질문, 상품 정보, 가격, 지원 문의에 답해야 할 때 쓰세요.

- **Search the Web**(웹 검색): 인터넷에서 실시간 정보를 가져와요. 내부 지식 베이스에 없는 최신 정보나 외부 데이터가 필요한 질문을 처리할 때 유용해요. 시장 동향이나 최근 뉴스처럼 일반적이거나 계속 바뀌는 질문에 답해야 할 때 쓰세요.

- **MCP 서버**: Model Context Protocol로 에이전트를 외부 시스템이나 서비스에 연결해요. 커스텀 도구, API, 외부 플랫폼과 연동해서 에이전트의 기능을 넓혀 줘요. 데이터베이스나 커스텀 연동처럼 외부 시스템과 상호작용해야 할 때 쓰세요.

- **작업**: 시스템 안에서 미리 정의된 작업을 실행해요. 판단을 레코드 업데이트나 프로세스 실행 같은 실제 결과로 바꾸는 데 중요해요. CRM 데이터 업데이트, 알림 전송, 워크플로우 실행 같은 일을 해야 할 때 쓰세요.

- **API Call**(API 호출): AI 에이전트가 외부 시스템에 요청을 보내고 응답을 받아요. 외부 플랫폼이나 내부 서비스와 실시간으로 데이터를 주고받을 수 있어요.

  CRM, 데이터베이스, API 같은 외부 애플리케이션과 상호작용해야 할 때 쓰세요. 엔드포인트를 설정하고 변수로 동적 데이터를 전달하면, 그 결과를 이후 단계에서 쓸 수 있어요.

- **텍스트 생성**: AI 에이전트가 맥락에 맞춰 글을 동적으로 만들어요. 상호작용 중에 답변, 요약, 구조화된 결과물을 만들 수 있어요.

  사용자에게 맞춤 콘텐츠를 만들어 줘야 할 때 쓰세요. 프롬프트를 설정하고 변수로 결과를 개인화한 뒤 다음 단계로 넘기세요.

- **이미지 생성**: AI 에이전트가 정해 둔 프롬프트를 바탕으로 이미지를 만들어요. AI 모델로 시각 콘텐츠를 동적으로 생성해요.

  상호작용 중에 이미지를 만들어야 할 때 쓰세요. 프롬프트를 명확하게 설정하고 변수로 결과를 맞춤 설정하세요.

- **동영상 생성**: AI 에이전트가 주어진 프롬프트를 바탕으로 동영상을 만들어요. 해상도, 화면 비율 같은 설정을 지원해요.

  답변의 일부로 동영상 콘텐츠를 만들어야 할 때 쓰세요. 프롬프트를 설정하고, 결과를 동적으로 바꿔야 하면 변수를 사용하세요.

- **오디오 생성**: AI 기반 음성 합성(TTS) 모델로 텍스트를 음성 오디오로 바꿔요. 에이전트가 음성 결과물을 동적으로 만들 수 있어요. 오디오 답변을 제공해야 할 때 쓰세요. 텍스트와 음성 설정을 구성하고, 변수로 결과를 개인화하세요.

![도구를 설정하는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155069885864/original/8dCOLuakf3U1PPFfCwp1wQ8Gnv-7YA9QgA.gif?1777032074)

### 6단계: 런타임 변수 정의하기

실행 중에 사용자 이름, 이메일, 요구 사항 같은 중요한 데이터를 수집하려면 런타임 변수를 만드세요. 이 데이터는 에이전트 플로우의 이후 단계에서 쓸 수 있어요.

![런타임 변수를 만드는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155069135452/original/bO2johj7qeiStjKYeaICkPDnfl0aZzvCDA.png?1776181312)

AI 에이전트는 **이름**과 **설명**을 보고 대화에서 어떤 정보를 찾아야 하는지 파악해요. 그리고 실행 중에 그 정보를 자동으로 추출해요.

변수마다 다음을 정의하세요.

- **이름**: 수집하려는 데이터의 식별자예요(예: `user_name`, `email`, `requirement`).
- **유형**: 데이터 형식이에요.

  - **문자열**: 텍스트 값이에요(예: 이름, 이메일, 질문).
  - **숫자**: 숫자 값이에요(예: 예산, 수량).
  - **불리언**: 참/거짓 값이에요(예: 관심 있음: 예/아니요).
  - **JSON**: 구조화된 데이터예요(복잡한 데이터를 수집할 때 써요).
- **설명**: 에이전트가 무엇을 추출해야 하는지 알려 주는 명확한 지침이에요.

## 자주 묻는 질문

### AI Agent Node는 어떤 일을 하나요?
**AI Agent Node**는 입력을 처리하고, 프롬프트 지침을 따르고, 필요할 때 연결된 도구를 사용하고, 정보를 수집해서 **에이전트 스튜디오** 플로우의 다음 노드로 결과를 넘겨요.

### Sequential Node 대신 AI Agent Node를 써야 하는 때는 언제인가요?
플로우에 맥락 기반 판단, 대화, 도구 선택, 데이터 추출이 필요하면 **AI Agent Node**를 쓰세요. 작업을 정해진 순서대로 실행해야 하면 **Sequential Node**를 쓰세요.

### AI Agent Node 하나가 여러 작업을 처리해도 되나요?
**AI Agent Node** 하나는 주된 역할 하나에 집중시키는 게 좋아요. 관련 없는 작업이 너무 많으면 노드를 제어하고 테스트하기 어려워질 수 있어요.

### 대화 모드와 작업 기반 모드는 어떻게 다른가요?
**Conversational Mode**는 사용자에게 보이는 답변을 보내요. **Task Based Mode**는 사용자에게 직접 답변을 보내지 않고 백그라운드 작업이나 데이터 추출을 해요.

### AI Agent Node는 어떤 도구를 쓸지 어떻게 정하나요?
노드는 프롬프트, 연결된 도구, 사용자 입력, 맥락을 보고 도구가 필요한 때를 판단해요. 프롬프트 지침이 명확할수록 도구를 더 잘 골라요.

### AI Agent Node에서 지식 베이스를 쓸 수 있나요?
네, 쓸 수 있어요. 지식 베이스 검색 도구를 연결하고, 프롬프트에 노드가 언제 이 도구를 써야 하는지 설명해 두세요.

### AI Agent Node가 외부 시스템을 호출할 수 있나요?
네, 가능해요. **API Call**이나 MCP 서버 같은 지원되는 도구를 설정하고 연결하면 돼요.

### AI Agent Node가 사용자 정보를 수집할 수 있나요?
네, 가능해요. 런타임 변수로 이름, 이메일, 요청 유형, 의도 등 구조화된 정보를 실행 중에 수집할 수 있어요.

### 런타임 변수가 비어 있어요. 왜 그런가요?
사용자 입력에 해당 값이 없거나, 변수 설명이 명확하지 않거나, 프롬프트에서 그 값을 수집하라고 안내하지 않았을 수 있어요. 프롬프트와 변수 설명을 수정한 뒤 다시 테스트하세요.

### AI Agent Node를 바꾼 뒤에 테스트해야 하나요?
네, 해야 해요. 프롬프트, 모델, 모드, 도구, 변수, 연결을 바꾼 뒤에는 노드가 제대로 동작하는지 테스트하세요.
