# 에이전트 스튜디오로 멀티 에이전트 시스템 만들기

**에이전트 스튜디오**(Agent Studio)는 코드 없이, 또는 최소한의 코드로 AI 멀티 에이전트 시스템을 만드는 하이퍼클래스의 비주얼 빌더예요. 노드를 끌어다 놓고, 조건부 라우팅을 설정하고, 내장 테스트까지 해 볼 수 있어요. AI가 스스로 판단하는 단계와 정해진 규칙대로 움직이는 단계를 한 흐름에 섞어서 만들 수 있어요.

## 에이전트 스튜디오란?

에이전트 스튜디오는 캔버스 형태의 빌더예요. 하나의 워크플로우 안에서 여러 AI 에이전트와 규칙 기반 단계를 함께 조율할 수 있어요. 각 에이전트는 LLM, 지식 베이스, 웹 검색, 외부 API 등을 사용할 수 있어요. 검증이나 폼 입력 수집처럼 결과가 예측되는 작업은 순차 노드가 맡아요. 이렇게 만든 하나의 자동화가 스스로 생각하고, 판단하고, 대신 실행해 줘요.

## 에이전트 스튜디오의 장점

- 끌어다 놓기만 하면 만들 수 있어요. 코드는 필요 없어요.
- AI의 추론과 정해진 규칙을 섞은 하이브리드 자동화를 만들 수 있어요.
- 변수나 AI가 파악한 의도에 따라 흐름이 알아서 갈라져요.
- 한 번의 클릭으로 게시하고 이전 버전으로 되돌릴 수 있어서, 안전하게 고쳐 나갈 수 있어요.
- 내장 테스트로 실제 운영 전에 로직을 확인할 수 있어요.
- 에이전트를 무제한으로 무료 사용할 수 있고, LLM 토큰 사용분만 내면 돼요.

## 비주얼 에이전트 빌더

**캔버스**에서는 전체 워크플로우를 한눈에 그릴 수 있어요. 노드를 격자 위로 끌어다 놓고, 선(엣지)으로 연결하세요. 마우스 오른쪽 클릭 메뉴로 이름을 바꾸거나 순서를 바꿀 수도 있어요. 노드 배치가 깔끔해지고 연결선도 새로워져서, 규모가 큰 시스템도 쉽게 파악할 수 있어요.

## 노드 종류

에이전트 스튜디오에는 자유롭게 조합해 쓸 수 있는 핵심 노드가 두 가지 있어요.

- **AI 에이전트** 노드: LLM 프롬프트를 **Web Search**(웹 검색), **지식 베이스 검색**, **GenAI**(생성형 AI), 외부 API 같은 도구와 연결해요. 상황에 맞는 추론, 콘텐츠 생성, 데이터 조회에 쓰세요.
- **Sequential Node**(순차 노드): API 호출, 폼 검증, 웹훅 트리거처럼 규칙 기반 작업을 수행해요. 항상 똑같이 반복해서 정확히 통제해야 할 때 쓰세요.

## 조건부 라우팅

별도의 '라우터' 블록은 없어요. 엣지(연결선) 자체가 조건을 가지고 있어요. `orderTotal > 500` 같은 간단한 표현식을 쓰거나 AI의 의도 파악 기능으로 다음에 실행할 노드를 정해요. 흐름이 간결하면서도 세밀하게 분기할 수 있어요.

## RAG를 위한 지식 베이스

PDF, CSV, FAQ, 웹사이트 전체 같은 여러 지식 소스를 모든 **AI 에이전트** 노드에 연결할 수 있어요. 검색 증강 생성(RAG)을 쓰면 LLM의 창의성은 그대로 살리면서, 답변이 내 콘텐츠를 근거로 나와요. 소스별 필터를 설정하면 훨씬 정확하게 답을 가져오게 할 수도 있어요.

## 전역 변수와 런타임 입력

API 키, 환경 상수, 브랜드 가이드라인을 한 번만 저장해 두면 워크플로우 어디서든 불러 쓸 수 있어요. 호출하는 앱이나 채팅 세션에서 `locationId`, `userId` 같은 런타임 변수를 넘기면, 실행할 때마다 사용자에게 맞춘 응답이 나가요.

## 버전 관리

저장할 때마다 초안이 만들어져요. 준비가 되면 한 번의 클릭으로 **프로덕션**에 게시하세요. 문제가 생기면 이전 버전 중 원하는 곳으로 바로 되돌릴 수 있어요. 별도의 Git 작업은 필요 없어요.

## 테스트와 배포

**테스트** 패널에서는 LLM 호출과 도구 호출을 포함한 에이전트 전체를 실행해 볼 수 있어요. 최종 사용자가 보기 전에 미리 확인하세요. 확인이 끝나면 **AI에게 문의**에 바로 배포할 수 있어요. 웹 위젯, API 엔드포인트 같은 다른 채널은 출시 예정이에요.

## 가격

- 무료 사용: 에이전트 수 제한이 없어요. 지식 베이스와 AI를 쓰지 않는 실행은 무료예요.
- 유료 사용: LLM 토큰 사용분만 공개된 API 요금대로 내요.

## 에이전트 스튜디오 설정하기

첫 멀티 에이전트 워크플로우는 어렵지 않게 만들 수 있어요.

### Step 1: 에이전트 스튜디오로 이동하기

1. 하이퍼클래스 왼쪽 메뉴에서 **AI 에이전트**를 클릭하세요.
2. **에이전트 스튜디오** 탭을 선택하세요.

만든 에이전트가 모두 나열된 에이전트 스튜디오 대시보드가 열려요.

![에이전트 스튜디오 대시보드 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155068691956/original/oM306XL0CLGv43shlHNkdwRI8W9yP5nnWA.png?1775648710)

### Step 2: 새 에이전트 만들기

1. 오른쪽 위의 **+ 에이전트 만들기**를 클릭하세요.

워크플로우를 만드는 작업 공간인 **캔버스**가 열려요.

화면은 이렇게 구성돼요.

- 왼쪽 패널: 사용할 수 있는 노드(구성 요소)
- 가운데: **캔버스** (워크플로우를 만드는 곳)
- 오른쪽 패널: **설정** (각 단계를 설정하는 곳)

**에이전트 만들기**를 클릭하면 빈 캔버스가 열려요.

![빈 캔버스가 열린 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155068692017/original/8yryGHr1gcrGUVwlxlaKSkmXNoZHxKDsFA.png?1775648766)

### Step 3: AI 에이전트 노드 추가하기

**AI 에이전트** 노드는 워크플로우의 핵심이에요. 에이전트가 생각하고, 응답을 만들고, 지식 베이스나 웹 검색 같은 도구를 쓸 수 있게 해 줘요.

1. 왼쪽 패널에서 **AI 에이전트**를 캔버스로 끌어다 놓으세요.

이 노드가 대화와 판단을 맡아요.

### Step 4: AI 에이전트 설정하기

**AI 에이전트** 노드를 클릭하면 설정 패널이 열려요.

아래 항목을 입력하세요.

- **모델**: 권장 모델을 선택하세요(예: GPT-4.1).
- **프롬프트**: 에이전트가 어떻게 행동할지 적어 주세요.

**프롬프트 예시**

> 당신은 비즈니스를 돕는 어시스턴트입니다. 사용자의 질문에 명확하고 공손하게 답하세요. 답을 모르면 더 자세한 내용을 물어보세요.

프롬프트는 AI 에이전트에게 주는 '지시문'이에요. 에이전트가 어떻게 응답할지를 직접 좌우해요.

![AI 에이전트 노드 설정 패널 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155068695833/original/WdcKZtDBJdclP99zJGfyc2KoPxK1Kpdyag.png?1775650445)

### Step 6: 흐름 연결하기

워크플로우는 연결선을 따라 한 단계에서 다음 단계로 실행돼요.

1. 노드의 작은 연결 점을 클릭한 채 끌어 오세요.
2. 다음 단계에 연결하세요. 지금은 노드가 하나뿐인 흐름으로 두어도 괜찮아요.

조건을 추가하지 않으면, 흐름은 자동으로 다음 단계로 이어져요.

### 순차 노드

**Sequential Node**(순차 노드)는 API 호출이나 검증처럼 구조화된 규칙 기반 작업에 써요.

1. 필요하면 왼쪽 패널에서 **Sequential Node**를 끌어다 놓으세요.

### Step 8: 변수 추가하기 (선택이지만 유용해요)

변수를 쓰면 이름, ID, API 키 같은 값을 워크플로우 전체에서 다시 쓸 수 있어요.

1. 화면 위쪽의 **변수**를 클릭하세요.
2. **전역** 탭에서 새 변수를 추가하세요.

이런 경우에 써요.

- API 키 저장
- 사용자별 데이터 전달
- 응답 개인화

![변수 화면의 전역 탭](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155068780592/original/1EqRgv45V7WIqYy6nHiVxlARwFeIfSKLkw.png?1775731777)

![전역 변수 추가 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155068780696/original/fYooQZNYO0pXaMWPQksXYxh5B9OisBsRtA.png?1775731814)

### Step 9: 에이전트 테스트하기

게시 전에 에이전트가 제대로 작동하는지 확인하세요.

1. 위쪽의 **테스트** 버튼을 클릭하세요.
2. 예시 질문을 입력하세요(예: "어떤 서비스를 제공하나요?").

아래 항목을 확인하세요.

- 응답 품질
- 도구 사용 여부(도구를 추가한 경우)
- 흐름이 의도대로 진행되는지

### Step 10: 에이전트 게시하기

결과가 마음에 들면 게시하세요.

1. **게시 > 프로덕션**을 클릭하세요.

## 자주 묻는 질문

### 내 계정에서 에이전트 스튜디오를 쓸 수 있는 사람은 누구인가요?

적절한 역할 권한이 있는 에이전시 관리자·사용자와 서브 계정 관리자·사용자가 에이전트를 만들고 관리할 수 있어요.

### 모든 엣지에 조건이 꼭 있어야 하나요?

아니요. 조건을 넣지 않으면 엣지는 기본 '다음' 단계처럼 작동해요.

### 에이전트가 다른 에이전트를 호출할 수 있나요?

네. 두 번째 에이전트를 **AI 에이전트** 노드 안에 하위 워크플로우로 넣거나, **Sequential Node**에서 API로 실행하면 돼요.

### LLM 토큰 사용량은 어디에서 확인하나요?

에이전트가 프로덕션에서 실행되면 **설정 > 청구/결제 > AI Usage**(AI 사용량)에서 확인할 수 있어요.

### 지식 베이스의 데이터가 LLM으로 전송되나요?

문서 전체가 아니라 검색된 일부 내용만 전달돼요. 그래서 컨텍스트가 간결하게 유지되고 비용도 낮아져요.

### Sequential Node에서 외부 API가 실패하면 어떻게 되나요?

오류가 실행 로그에 표시돼요. 조건부 엣지(예: 오류 코드 기준)로 대체 노드로 분기할 수도 있어요.

### 에이전트를 다른 서브 계정으로 내보낼 수 있나요?

내보내기/가져오기 기능은 로드맵에 있어요. 지금은 같은 계정 안에서 직접 다시 만들거나 복제해야 해요.

### 한 에이전트의 여러 버전이 각각 과금되나요?

아니요. 토큰은 프로덕션 실행에서만 소모돼요. 초안과 테스트는 샌드박스 할당량을 사용해요.
