# 에이전트 스튜디오에서 관리형 에이전트 설정하고 사용하기

하고 싶은 일을 평소 쓰는 말로 설명하면 하이퍼클래스가 AI 에이전트를 만들어 줘요. 지식 베이스를 연결하고, CRM 액션과 트리거를 설정한 뒤, 게시하기 전에 에이전트를 테스트할 수 있어요. **컴퓨터**를 쓰면 에이전트별 전용 환경, 병렬 브라우저 작업, 안전한 웹사이트 로그인, 더 부드러운 **Take Control**(직접 제어) 전환을 이용할 수 있어요.

## 관리형 에이전트 빌더란?

**관리형 에이전트**(Managed Agents) 빌더는 이전 이름이 슈퍼 에이전트(Super Agents)예요. 직접 구성하는 순서도 대신 대화형 지시문으로 AI 에이전트를 만들어요. 에이전트는 **에이전트 스튜디오**(Agent Studio) 엔진으로 질문에 답하고, 지식 베이스를 활용하고, CRM 액션을 수행해요. 모든 에이전트는 임시 저장, 테스트, 게시 순서로 진행돼요.

관리형 에이전트에는 **Unified Workspace**(통합 워크스페이스)도 있어요. 에이전트 찾기, 테스트, 대화, 활동, 설정을 한 화면에 모아 둔 곳이에요. Unified Workspace는 현재 **실험실**을 통해 쓸 수 있어요. 실험실 기능이 켜져 있지 않은 서브 계정은 기존 관리형 에이전트 화면을 계속 사용해요.

---

## 관리형 에이전트의 장점

지시문, 비즈니스 지식, 자동화 도구를 함께 써서 반복 업무를 줄이면서, 에이전트가 목표에 맞게 움직이도록 관리할 수 있어요.

- 자연어로 설정: 워크플로우 노드를 직접 연결하지 않고 에이전트의 역할과 행동을 말로 설명하면 돼요.
- CRM 자동화: 레코드를 업데이트하고, 워크플로우를 실행하고, 설정한 이벤트에 응답해요.
- 지식 기반 응답: 하이퍼클래스 지식 베이스로 승인된 비즈니스 정보를 연결해요.
- 동시 브라우저 작업: 전용 컴퓨터 환경과 안전하게 저장된 웹사이트 로그인 정보로 브라우저 작업을 병렬로 실행해요.
- 배포 전 테스트: 에이전트를 실제 활동에 연결하기 전에 테스트 패널에서 응답과 액션을 확인해요.
- 에이전트 통합 관리: 여러 페이지를 오가지 않고 한 곳에서 관리형 에이전트를 찾고, 테스트하고, 모니터링하고, 설정하고, 게시해요.

---

## 사전 준비와 제한 사항

에이전트가 작업에 필요한 정보와 도구를 쓸 수 있도록, 설정하기 전에 접근 권한과 연결된 리소스를 확인하세요.

### 사전 준비

- 사용자에게 **관리형 에이전트**에 접근하고 관리할 수 있는 권한이 있어야 해요.
- 에이전트가 쓸 지식 베이스, 워크플로우, 캘린더를 미리 설정하고 테스트하세요.
- Facebook 리드 폼 트리거를 쓰려면 리드 동기화용 Facebook 페이지를 연결하고, 페이지 관리자가 Meta의 리드 광고 서비스 이용약관에 동의해야 해요.

### 제한 사항

- 사용할 수 있는 채널과 이벤트는 계정에 설정된 트리거와 연동에 따라 달라요.
- **Unified Workspace**는 **실험실**을 통해 쓸 수 있어요. 실험실 기능이 켜져 있지 않은 서브 계정은 기존 관리형 에이전트 화면을 계속 사용해요.

## 자연어로 에이전트 만들기

프롬프트가 분명할수록 빌더가 쓸 만한 초안을 만들 수 있어요. 에이전트의 역할, 지원할 채널, 지식 베이스, 허용할 CRM 액션, 행동 방식을 설명하세요. 미리 준비된 사용 사례에서 시작해도 돼요.

```
예시 프롬프트: “소셜 미디어 어시스턴트를 만들어 줘. Facebook, Instagram, LinkedIn에 브랜드 톤에 맞는 게시물을 작성하고 예약해 줘. 상품 정보는 마케팅 지식 베이스를 참고하고, 우리 브랜드 말투를 따라 줘.”
```

빌더는 행동 방식, 트리거, 액션을 제안하는 초안을 만들어요. “어조를 더 격식 있게 바꿔 줘”, “플랫폼당 일주일에 게시물을 세 개로 제한해 줘”처럼 추가로 지시해서 다듬을 수 있어요.

Facebook 리드 폼이나 설문 트리거도 자연어로 설명한 뒤, 사용할 수 있는 페이지, 리드 폼, 설문 중에서 고르면 돼요. ID를 직접 찾아볼 필요는 없어요.

## 똑똑한 CRM 에이전트

관리형 에이전트는 AI의 추론 능력에 비즈니스 정보와 설정된 도구를 결합해서, 하이퍼클래스 안에서 질문에 답하고 작업을 처리해요.

- 지식 베이스 답변: 문서, 서식 있는 텍스트, 표, CSV, 크롤링한 웹 콘텐츠를 활용해 비즈니스 정보를 근거로 답해요.
- CRM 액션: 에이전트의 지시문과 사용 가능한 도구에 따라 연락처 필드와 태그를 업데이트하고, 워크플로우를 실행하고, 작업, 메모, 예약을 만들어요.
- 미디어 생성: 이미지, 오디오, 동영상을 생성하고, 기존 PNG 이미지를 편집하고, 생성한 자산을 **미디어 저장소**에 저장해요. 같은 대화에서 이어서 요청하면 이미지를 다듬을 수 있어요.

자주 쓰는 사용 사례는 소셜 미디어 지원, 지식 베이스 지원, 커뮤니티 운영, 이메일 캠페인, 일상적인 CRM 업무예요. 에이전트 스튜디오는 외부 API 호출과 그 밖의 사용 가능한 도구도 지원해요.

## 관리형 에이전트의 컴퓨터

**컴퓨터**를 쓰면 관리형 에이전트가 웹사이트와 상호작용하며 브라우저 기반 작업을 할 수 있어요. 전용 환경, 병렬 실행, 안전한 인증, 개선된 브라우저 제어 덕분에 작업이 대기 시간 없이 진행돼요.

### 에이전트별 전용 컴퓨터 환경

관리형 에이전트마다 자기만의 컴퓨터 환경이 있어요. 여러 에이전트가 서로의 환경에 영향을 주지 않고 독립적으로 일해요. 그래서 격리, 성능, 실행 안정성이 좋아져요.

### 병렬 브라우저 대화

관리형 에이전트 하나가 브라우저 대화를 8~10개까지 동시에 실행할 수 있어요. 대화마다 전용 브라우저 탭을 써요. 동시 처리가 개선되어 서로 간섭이 줄고, 다른 대화가 끝나기를 기다리지 않고 브라우저 자동화가 진행돼요.

### 하이퍼클래스 키체인으로 안전하게 로그인

**하이퍼클래스 키체인**은 웹사이트 로그인 정보를 안전하게 저장해요. 에이전트가 민감한 로그인 정보를 노출하지 않고도 인증할 수 있어요. 로그인이 필요한 웹사이트에서 하는 브라우저 작업에 도움이 돼요.

### 더 빨라진 상호작용과 개선된 Take Control

새로 바뀐 **컴퓨터** 화면에서는 진행 중인 브라우저 활동을 더 분명하게 볼 수 있고, 브라우저 반응도 더 빨라요. **Take Control**을 쓰면 에이전트가 제어하던 브라우저 활동과 사용자가 제어하는 활동 사이를 더 부드럽게 오갈 수 있어요.

## 이벤트 기반 자동화

트리거는 설정한 이벤트가 발생할 때 에이전트를 시작해요. 작업마다 직접 시작하지 않아도 돼요. 미디어 생성을 켜 두면, 트리거로 실행된 경우에도 활성 채팅 세션 없이 미디어를 만들 수 있어요.

- **Tag Changed**(태그 변경): 연락처가 지정한 태그를 얻거나 잃을 때 에이전트를 실행해요.
- **폼 제출**: 지정한 폼이 제출된 뒤 에이전트를 실행해요.
- **Chat Interface**(채팅 인터페이스): 지원되는 채팅 채널로 에이전트와의 대화를 시작해요.
- **Facebook lead form**(Facebook 리드 폼): 연락처가 선택한 Facebook 페이지의 리드 폼을 제출하면 에이전트를 실행해요. 에이전트는 연락처와 제출된 답변을 받아요.
- **설문이 제출되었습니다**: 선택한 설문 중 하나라도 응답을 받으면 에이전트를 실행해요. 에이전트는 설문 이름과 제출된 답변을 받아요.

그 밖에 일정, 예약, 연락처나 기회 이벤트도 지원될 수 있어요. 폼의 파일 업로드 필드로 제출된 PNG 이미지를 트리거 정보의 일부로 에이전트에 전달할 수도 있어요.

### 관리형 에이전트 Unified Workspace

**Unified Workspace**는 에이전트 찾기, 대화, 테스트, 활동, 설정을 한곳에 모아 줘요. 자주 하는 작업을 화면을 계속 벗어나지 않고 처리할 수 있어요.

- **에이전트 목록**: 에이전트를 검색, 필터, 정렬하고 전환해요. 상태, 설명, 최근 업데이트도 확인할 수 있어요.
- **Agent Workspace**(에이전트 워크스페이스): 에이전트와 채팅하고, 동작을 테스트하고, 이전 대화를 이어서 해요.
- **에이전트 상세 정보**: 접을 수 있는 패널에서 설정, 게시, 활동, 사용할 수 있는 액션을 관리해요.

## 관리형 에이전트 설정하기

초안을 만들고, 도구와 트리거를 설정한 다음, 테스트로 응답을 확인하고 게시해서 실제 이벤트에 쓰세요.

### 1단계: 관리형 에이전트 열기

에이전트가 비즈니스 정보와 자동화를 쓸 서브 계정에서 시작하세요.

1. 하이퍼클래스에서 **서브 계정**을 엽니다.
2. **AI 에이전트**를 클릭합니다.
3. **에이전트 스튜디오**를 선택합니다.
4. **관리형 에이전트** 탭을 엽니다.

![관리형 에이전트 탭으로 이동하는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084333510/original/kPLZxLRGDy2jE-iMfmn95k5hNhst0GHP4Q.png?1793116472)

### 2단계: 에이전트 만들기

자동화하려는 일에 맞게 초안이 만들어지도록 빌더에 목표와 범위를 분명하게 알려 주세요.

1. **+ 에이전트 만들기**를 클릭합니다.
2. 에이전트의 목표, 채널, 지식 베이스, 허용할 CRM 액션을 설명합니다. 미리 준비된 사용 사례를 골라도 돼요.
3. 설명을 제출하면 에이전트 초안이 만들어져요.

![관리형 에이전트 만들기](https://jumpshare.com/share/dJvsE22mSIMLoH0Bcbcg+/GIF+Recording+2026-07-28+at+19.46.17.gif)

### 3단계: 에이전트 검토하고 트리거 설정하기

만들어진 행동 방식과 연결된 도구를 확인한 뒤, 어떤 이벤트에서 에이전트를 시작할지 정하세요. **chat-based editing sidebar**(채팅 기반 편집 사이드바)에서 어조, 규칙, 액션을 다듬을 수 있어요. 에이전트 하나에 지원되는 트리거를 여러 개 설정할 수도 있어요.

#### Facebook 리드 폼 트리거 설정하기

연결된 Facebook 페이지의 리드에 응답할 때 쓰는 트리거예요. 페이지의 모든 리드 폼을 선택하거나, 특정 폼만 지정할 수 있어요.

1. **서브 계정** 화면에서 **AI 에이전트**를 클릭하고, **에이전트 스튜디오**를 선택한 다음 **관리형 에이전트**를 선택합니다.
2. 설정할 에이전트를 엽니다.
3. **트리거**를 열고 **+ Add Trigger**(트리거 추가)를 클릭합니다.
4. **커뮤니케이션** 아래에서 **Facebook lead form**을 선택합니다.
5. **Facebook 페이지**를 선택합니다. 페이지 수준으로 두면 그 페이지의 모든 리드 폼에 적용되고, 특정 리드 폼을 골라도 돼요.
6. 필요하면 검색을 쓰세요. 리드 폼 검색은 선택한 페이지 안에서만 돼요.
7. 설정과 테스트가 끝나면 에이전트를 게시합니다.

![Facebook 리드 폼 트리거를 설정하는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084106816/original/AXC0_Pne42vheEj5gHpRuYuuL31KNJshWg.png?1792812660)

#### 설문 제출 트리거 설정하기

선택한 설문 하나 이상의 응답을 처리할 때 쓰는 트리거예요. 선택한 설문 중 어느 것에든 응답이 들어오면 에이전트가 시작돼요.

1. **서브 계정** 화면에서 **AI 에이전트**를 클릭하고, **에이전트 스튜디오**를 선택한 다음 **관리형 에이전트**를 선택합니다.
2. 설정할 에이전트를 엽니다.
3. **트리거**를 열고 **+ Add Trigger**를 클릭합니다.
4. **폼 및 설문** 아래에서 **설문이 제출되었습니다**를 선택합니다.
5. 설문을 하나 이상 선택합니다. 필요하면 검색을 쓰세요.
6. 설정과 테스트가 끝나면 에이전트를 게시합니다.

게시하면 하이퍼클래스가 선택한 페이지, 리드 폼, 설문이 아직 있는지 확인하고, 올바르지 않은 선택이 있으면 알려 줘요. Facebook 리드 폼은 선택한 페이지와 폼의 조합으로 에이전트를 실행할 수 있는지도 함께 확인해요.

![관리형 에이전트를 검토하고 설정하는 화면](https://jumpshare.com/share/sk0B1OiH6f8FcvzjzfYU+/GIF+Recording+2026-07-28+at+20.11.06.gif)

### 4단계: 미디어 생성 설정하기

에이전트 작업에 필요한 미디어 기능을 켠 다음, 이미지나 오디오 관련 설정을 고르세요.

1. **서브 계정** 화면에서 **AI 에이전트**를 클릭하고, **에이전트 스튜디오**를 선택한 다음 **관리형 에이전트**를 선택합니다.
2. 에이전트를 열고 **기능**을 선택합니다.
3. 필요에 따라 **이미지 생성**, **오디오 생성**, **동영상 생성**을 켭니다.

![미디어 생성 기능을 켜는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084106906/original/lsDN9grQjg4iZfJqNz5JKGG_ow4FN9xhsQ.png?1792813085)

#### 이미지 생성과 편집

- 이미지 품질은 **낮음**, **미디엄**, **높음** 중에서 선택해요. 기본값은 미디엄이에요.
- 이미지 모양은 프롬프트에 직접 적어 주세요. 지원하는 비율은 1:1, 4:5, 2:3, 3:2, 9:16, 3:4, 4:3, 5:4, 16:9, 21:9예요.
- 세로형, 와이드스크린, 정사각형, 배너처럼 말로 설명해도 돼요. 모양을 지정하지 않으면 에이전트가 정사각형 이미지를 만들어요.
- 기존 이미지를 편집해 달라고 분명히 요청하지 않으면, 생성 요청마다 새 이미지를 만들어요.
- 기존 PNG를 편집하려면 바꾸고 싶은 내용을 설명하세요. 같은 대화에서 이어서 요청하면 이미지를 다시 제공하지 않아도 가장 최근에 편집한 이미지를 계속 다듬을 수 있어요.
- 생성하거나 편집한 이미지는 대화 맥락에 남아 있어서 다음 요청에서도 쓸 수 있어요.

예시: `9:16 세로형 커피숍 이미지를 만들어 줘. Instagram 스토리에 쓸 거야.`

이미지 생성 환경이 개선되어 속도가 빨라졌고, 작은 글자와 세밀한 부분도 더 잘 표현돼요. 지원하는 화면 비율 전반에서 이미지 생성 결과가 일관돼요. 기존 설정과 프롬프트는 그대로 쓸 수 있어요.

![관리형 에이전트 이미지 편집 예시](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083288624/original/20AcwRxYq0pyeWCJd5t_OFMsQdua_9g10g.png?1791973476)

#### 오디오 생성

지원되는 음성을 선택하고, **어조** 필드에 오디오가 어떻게 들려야 하는지 적으세요. 원본 텍스트는 에이전트가 말하게 할 언어로 작성하세요.

#### 동영상 생성과 저장

관리형 에이전트는 16:9 비율의 8초짜리 동영상을 만들어요. 오디오와 동영상은 따로 생성돼요. 생성된 미디어는 **미디어 저장소**에 저장되어 다시 쓸 수 있어요.

### 5단계: 에이전트 테스트하기

실제로 쓰기 전에, 대표적인 요청으로 에이전트의 응답, 액션, 설정된 범위를 확인하세요.

1. 에이전트의 **testing panel**(테스트 패널)을 엽니다.
2. 지식 베이스, CRM 액션, 설정한 지시문이 동작하는지 확인할 수 있는 요청을 실행합니다.
3. 웹 검색 응답은 **출처**를 살펴보고 인용을 열어 정보가 맞는지 확인합니다.
4. 미디어 생성을 켰다면 샘플 자산도 테스트합니다.
5. 채팅 기반 편집으로 에이전트를 다듬고, 필요하면 테스트를 반복합니다.

![관리형 에이전트 테스트하기](https://jumpshare.com/share/ZgE8Qkpr9HRbl8z5xyvT+/GIF+Recording+2026-07-28+at+20.17.45.gif)

### 6단계: 에이전트 게시하기

게시하면 설정한 에이전트가 실제 이벤트에 쓰여요. 테스트가 끝나면 상태를 **임시 저장**에서 **게시됨**으로 바꾸세요.

![관리형 에이전트 게시하기](https://jumpshare.com/share/BqnrNRu9gO0lgHT3FvyN+/Screen+Shot+2026-07-28+at+20.23.40.png)

### 7단계: 모니터링하고 개선하기

**에이전트 스튜디오**와 관련 리포팅에서 에이전트 성과를 확인하고 개선할 점을 찾으세요. 필요하면 지시문을 고치고, 연결된 지식 베이스를 최신으로 유지하세요. **Knowledge Base Retrieval Tester**(지식 베이스 검색 테스터)로 중요한 콘텐츠가 제대로 검색되는지 확인할 수 있어요.

## 자주 묻는 질문

### 관리형 에이전트와 플로우 기반 에이전트는 어떻게 다른가요?
관리형 에이전트는 대화형 지시문으로 만들어요. 플로우 기반 에이전트는 직접 구성하는 시각적 캔버스를 사용해요. 새 에이전트는 관리형 에이전트로 만드세요. 기존 플로우 에이전트는 계속 실행되고, 편집과 관리도 할 수 있어요.

### 관리형 에이전트를 게시한 뒤 지식 베이스 내용이 바뀌면 어떻게 되나요?
바뀐 콘텐츠의 인덱싱이 끝나면, 에이전트가 다음 실행부터 업데이트된 정보를 쓸 수 있어요. 중요한 변경 사항은 실제 대화에서 믿고 쓰기 전에 **Knowledge Base Retrieval Tester**로 확인하세요.

### 관리형 에이전트가 CRM을 원치 않게 바꾸지 않게 하려면 어떻게 하나요?
에이전트의 지시문에 분명한 한계를 정해 두세요. 예를 들어 제안한 변경 사항은 사람이 승인해야 하도록 적을 수 있어요. 게시하기 전에 그 지시문을 테스트하고, 에이전트의 액션을 확인하세요.

### 관리형 에이전트 요금과 사용량 한도는 어디서 확인하나요?
관리형 에이전트 요금제, 포함된 실행 횟수, 사용량 기반 과금은 [**AI 상품 가격**](../ai-product-pricing-update.md)에서 확인하세요.
