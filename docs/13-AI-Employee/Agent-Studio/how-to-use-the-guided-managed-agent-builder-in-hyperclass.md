# 가이드형 관리형 에이전트 빌더 사용하기

가이드형 관리형 에이전트 빌더를 쓰면 자연어로 지시해서 AI 에이전트를 만들고 고칠 수 있어요. 필요한 부분만 수정하고, 되묻는 질문에 답하고, 실시간 구성 패널에서 결과를 바로 확인할 수 있어서 에이전트를 처음부터 다시 만들 필요가 없어요. 이 문서에서 각 기능의 작동 방식과 활용법을 알려 드려요.

## 가이드형 관리형 에이전트 빌더란?

가이드형 관리형 에이전트 빌더는 **에이전트 스튜디오**(Agent Studio)에서 대화하듯 **관리형 에이전트**(이전 이름: 슈퍼 에이전트)를 만들고 수정할 수 있는 AI 기반 기능이에요. 설정을 하나하나 직접 바꾸지 않아도 돼요. 원하는 변경 사항을 말로 설명하고, 실시간 구성 패널에서 결과를 확인한 뒤, 지원되는 필드는 패널에서 바로 고치면 돼요.

빌더는 질문과 요청을 구분하고, 정보가 부족하면 되물어요. 또 일부만 수정할 때는 관련 없는 설정을 그대로 유지해요. 이 기능은 **에이전트 스튜디오**의 관리형 에이전트에서 별도 설정 없이 쓸 수 있어요.

---

## 가이드형 관리형 에이전트 빌더의 장점

가이드형 관리형 에이전트 빌더는 에이전트를 만들고 고치는 과정을 단순하게 해 주고, 설정 변경을 더 세밀하게 다룰 수 있게 해 줘요.

- 부분 수정: 관련 없는 설정은 건드리지 않고 특정 에이전트 설정만 바꿔요.
- 가이드형 확인: 요청이 불분명하면 빌더가 추측하지 않고, 올바른 리소스를 직접 고르도록 물어봐요.
- 의도 인식: 질문을 하거나 변경을 요청해도 에이전트가 의도치 않게 바뀌지 않아요.
- 실시간 구성 반영: **안내**, **트리거**, **도구**, **스킬**, **지식 베이스**가 바뀌는 모습을 실시간으로 볼 수 있어요.
- 인라인 편집: 구성 패널에서 지원되는 필드를 바로 세밀하게 고칠 수 있어요.
- 스마트 캐스케이드: **트리거**, **플러그인**, **지식 베이스**가 바뀌면 관련 안내가 자동으로 맞춰져요.
- 계정 기반 리소스: 서브 계정에 있는 폼, 캘린더, 파이프라인, 지식 베이스, 연결된 앱을 사용해 에이전트를 설정해요.

---

## 부분 구성 수정

부분 수정을 쓰면 기존 관리형 에이전트의 전체 구성을 다시 만들지 않고 필요한 부분만 정확하게 바꿀 수 있어요. 잘 작동하는 안내, 트리거, 연결된 리소스를 유지한 채 특정 동작만 다듬을 수 있어요.

예를 들어 기존 에이전트가 좀 더 대화하듯 말하게 하려면 이렇게 입력해요.

"이 에이전트의 말투를 더 친근하게 바꿔 줘. 기존 트리거와 지식 베이스는 그대로 두고."

빌더는 관련 안내만 수정하고, 관련 없는 설정은 그대로 둬요.

다른 예시도 있어요.

- "문의하기 폼에 대한 트리거를 추가해 줘."
- "에이전트의 답변을 더 짧게 해 줘."
- "작업을 만들기 전에 이메일 주소를 먼저 묻도록 안내를 수정해 줘."

수정한 내용이 관련 구성 요소에 영향을 주면, 빌더가 그에 맞는 안내도 함께 맞출 수 있어요.

---

## 되묻는 질문과 의도 인식

빌더는 입력한 내용이 질문인지, 구성 변경 요청인지, 불분명한 지시인지 구분해요. 덕분에 의도치 않은 수정을 막고 올바른 리소스를 고를 수 있어요. 요청에 빠진 정보가 있거나 모호하면, 빌더가 추측하지 않고 핵심을 짚어 되물어요.

예를 들어 서브 계정에 "문의하기"라는 이름의 폼이 여러 개 있을 때 이렇게 입력하면,

"문의하기 폼에 대한 트리거를 추가해 줘."

빌더가 어느 폼을 쓸지 물어봐요.

빌더는 하이퍼클래스 서브 계정에 있는 리소스를 기준으로 선택하기 때문에, 잘못된 리소스를 고르는 일을 줄일 수 있어요.

| 요청 | 빌더의 동작 |
| --- | --- |
| "이 에이전트는 뭘 할 수 있어?" | 구성을 바꾸지 않고 에이전트의 기능을 설명해요. |
| "말투를 더 친근하게 해 줘." | 관련 에이전트 안내를 수정해요. |
| "이 에이전트를 개선해 줘." | 변경하기 전에 먼저 되물어요. |
| "문의하기 폼에 대한 트리거를 추가해 줘." | 일치하는 폼을 선택하고, 일치하는 폼이 여러 개면 어느 폼을 쓸지 물어요. |
| "고객지원 지식 베이스를 사용해 줘." | 사용할 수 있는 리소스를 쓰고, 찾을 수 없으면 되물어요. |

새 에이전트를 만들 때도 같은 의도 인식이 적용돼요. 만들기 지시 대신 질문을 입력하면, 빌더는 에이전트를 만들지 않고 질문에 답해요.

---

## 실시간 편집 구성 패널

실시간 구성 패널에는 빌더가 요청을 처리하는 동안 에이전트 설정이 표시돼요. 구성이 바뀌는 모습을 바로 볼 수 있고, 게시하기 전에 지원되는 필드를 검토하거나 조정할 수 있어요.

패널에는 다음과 같은 주요 구성이 표시돼요.

- **안내**: 에이전트의 동작 방식과 소통 지침을 정해요.
- **트리거**: 어떤 이벤트가 에이전트를 시작할지 정해요.
- **도구**: 지원되는 액션과 연동을 사용할 수 있게 해요.
- **스킬**: 에이전트가 특정 작업을 수행할 수 있게 해요.
- **지식 베이스**: 에이전트가 참고할 정보를 제공해요.

빌더가 요청을 처리하는 동안 **안내**는 패널에 실시간으로 채워지고, 나머지 구성 요소는 확정되는 대로 표시돼요. 또 대화로 다시 요청하는 대신 지원되는 필드를 직접 수정할 수도 있어요.

---

## 스마트 캐스케이드와 안내 동기화

스마트 캐스케이드는 에이전트의 안내가 구성과 계속 맞도록 자동으로 조정해 줘요. **트리거**, **플러그인**, **지식 베이스**를 바꾸면, 빌더가 필요한 경우 관련 안내를 업데이트하고 관련 없는 설정은 그대로 둬요.

예를 들어 이렇게 입력해요.

"현재 지식 베이스를 고객지원 절차 지식 베이스로 바꿔 줘."

빌더는 선택한 **지식 베이스**를 바꾸고, 변경 내용에 맞게 관련 안내도 조정해요. 같은 방식으로 트리거를 바꾸면 에이전트가 언제, 왜 실행되는지에 관한 안내도 업데이트될 수 있어요.

스마트 캐스케이드는 다음 항목에 적용돼요.

- **트리거**: 에이전트를 시작하는 이벤트에 맞춰 안내를 유지해요.
- **플러그인**: 사용할 수 있는 연동과 기능의 변경 사항을 반영해요.
- **지식 베이스**: 에이전트의 정보 출처와 안내가 일관되도록 유지해요.

게시하기 전에 업데이트된 구성을 검토해서, 변경 내용이 의도한 동작과 맞는지 확인하세요.

## 가이드형 관리형 에이전트 빌더 사용 방법

가이드형 관리형 에이전트 빌더로 에이전트를 만들거나 수정하고, 변경 내용을 바로 확인하고, 게시하기 전에 동작을 테스트할 수 있어요. 아래 순서대로 따라 하면 기존 설정을 유지하면서 에이전트를 올바르게 구성할 수 있어요.

### 1단계: 관리형 에이전트 빌더 열기

1. 하이퍼클래스 서브 계정에 로그인하세요.
2. **AI 에이전트 > 에이전트 스튜디오**로 이동하세요.
3. **관리형 에이전트** 탭을 여세요.
4. 새 관리형 에이전트를 만들거나, 수정할 기존 에이전트를 여세요.

   ![관리형 에이전트 빌더 열기 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083871970/original/JY6jHQA9GwLydXPVAlAJ5JJtLEo0h8Iw2w.png?1792589210)

### 2단계: 지시 내용 입력하기

빌더의 대화형 입력창에 만들거나 바꾸고 싶은 내용을 설명하세요.

예를 들면 이렇게 입력해요.

"기존 도구와 지식 베이스는 그대로 두고, 데모 요청 폼에 대한 폼 제출 트리거를 추가해 줘."

입력한 요청을 제출하세요.

![지시 내용을 입력하는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083872079/original/HiAtlRAyYGeNYQ-W04o4fwFuPK8diapFsA.png?1792589257)

### 3단계: 되묻는 질문에 답하기

빌더가 확인 질문을 하면, 알맞은 리소스를 선택하거나 빠진 정보를 입력하세요. 그러면 빌더가 요청한 변경을 이어서 적용해요.

### 4단계: 구성 검토하고 조정하기

실시간 구성 패널에 변경 사항이 나타나는 모습을 확인하세요. 업데이트된 **안내**, **트리거**, **도구**, **스킬**, **지식 베이스**를 살펴보세요.

필요하면 추가로 요청하거나, 지원되는 필드를 인라인으로 직접 수정하세요.

### 5단계: 테스트하고 게시하기

1. 사용할 수 있는 **테스트** 옵션으로 에이전트의 동작을 확인하세요.
2. 요청한 변경 사항이 기대한 대로 작동하는지 확인하세요.
3. 관련 없는 설정과 기능이 그대로인지 확인하세요.
4. 필요한 부분을 조정하세요.
5. 구성이 준비되면 **게시**를 선택하세요.

## 자주 묻는 질문

### 가이드형 빌더 개선 기능을 따로 켜야 하나요?

아니요. **에이전트 스튜디오**의 관리형 에이전트에서 별도 설정 없이 쓸 수 있어요.

### 에이전트를 바꾸지 않고 질문만 할 수 있나요?

네. 빌더는 정보를 묻는 질문과 수정 요청을 구분해요. 질문에는 구성을 의도적으로 바꾸지 않고 답해요.

### 요청한 폼이나 리소스를 찾을 수 없으면 어떻게 되나요?

빌더는 잘못된 리소스나 만들어 낸 리소스를 쓰지 않고 되물어요. 해당 리소스가 서브 계정에 있는지 확인해 보세요.

### 프롬프트를 쓰지 않고 구성을 직접 수정할 수 있나요?

네. 실시간 구성 패널에서 사용할 수 있는 필드를 인라인으로 직접 수정할 수 있어요.

### 트리거나 지식 베이스를 바꾸면 안내 전체가 덮어써지나요?

아니요. 스마트 캐스케이드는 필요한 만큼만 관련 안내를 업데이트하고, 관련 없는 구성은 그대로 둬요.

### 계정 기반 리소스를 쓰면 에이전트가 반드시 제대로 작동하나요?

아니요. 계정 기반 선택은 잘못된 리소스를 참조하는 일을 줄여 줘요. 그래도 게시하기 전에 에이전트를 직접 검토하고 테스트해야 해요.
