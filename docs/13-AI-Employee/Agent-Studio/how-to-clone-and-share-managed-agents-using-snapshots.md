# 스냅샷으로 관리형 에이전트 복제하고 공유하기

관리형 에이전트(이전 이름: 슈퍼 에이전트)는 하이퍼클래스 **계정 스냅샷**에 담아 여러 서브 계정에 배포할 수 있어요. 검증된 AI 설정을 재사용하고, 에이전트를 일일이 다시 만들지 않고도 같은 동작을 유지할 수 있어요. 관리형 에이전트는 스냅샷을 만들 때, 새로고침할 때, 불러올 때 모두 **에이전트 스튜디오** 자산 카테고리 아래에 나타나요.

## 스냅샷 속 관리형 에이전트란?

스냅샷 속 관리형 에이전트는 **에이전트 스튜디오** 자산이에요. 원본 서브 계정에서 다른 서브 계정으로 복사할 수 있어요. 스냅샷에는 선택한 에이전트 설정이 함께 담겨요. 에이전시는 이 스냅샷으로 같은 AI 경험을 여러 고객, 지점, 표준 계정 템플릿에 배포할 수 있어요.

스냅샷에 관리형 에이전트를 넣으면 하이퍼클래스는 에이전트 구조, 설정, 연결된 **지식 베이스**, 버전 상태를 그대로 보존해요. 에이전트에 필요한 보조 자산은 따로 선택해야 해요.

## 스냅샷에 관리형 에이전트를 넣으면 좋은 점

관리형 에이전트를 스냅샷에 담아 두면 반복 설정이 줄고, 여러 계정에서 일관된 AI 경험을 제공할 수 있어요.

- 빠른 고객 온보딩: 새 고객마다 설정을 다시 만들 필요 없이 미리 만든 관리형 에이전트를 배포해요.
- 일관된 AI 경험: 검증된 프롬프트, 지침, 트리거, 기능, 에이전트 동작을 서브 계정 전반에 재사용해요.
- 손쉬운 확장: 관리형 에이전트를 하나 이상 골라 여러 고객이나 사업장에 배포해요.
- 유연한 자산 선택: 관리형 에이전트만 따로 담거나 다른 스냅샷 자산과 함께 담을 수 있어요.
- 간편한 업데이트: 원본 서브 계정에서 에이전트를 수정한 뒤 스냅샷을 새로고침하면, 업데이트된 자산을 연결된 계정에 배포할 수 있어요.
- 재사용 가능한 에이전시 솔루션: 설정을 마친 에이전트를 스냅샷 링크로 공유하거나 더 큰 계정 템플릿에 포함할 수 있어요.

## 관리형 에이전트와 함께 옮겨지는 것

스냅샷이 무엇을 보존하는지 알면 원본 서브 계정을 준비하고, 따로 선택해야 하는 보조 자산을 챙기기 쉬워요.

관리형 에이전트 스냅샷에는 다음이 보존돼요.

- 에이전트 플로우 구조
- 노드 설정
- 프롬프트와 지침
- 트리거
- 스킬과 기능
- 필요한 지식 베이스 자산을 선택한 경우, 연결된 **지식 베이스**
- 초안(Draft), 스테이징(Staging), 프로덕션(Production) 같은 에이전트 버전 상태
- 선택한 보조 자산

스냅샷은 선택한 설정 자산을 옮기는 기능이에요. 계정에서 일어난 실제 활동이나 고객 기록은 옮기지 않아요. 연동, 외부 서비스 연결, 자격 증명처럼 계정마다 다른 리소스는 대상 서브 계정에서 추가로 설정해야 할 수 있어요.

{% hint style="warning" %}
중요: 스냅샷을 만들기 전에 에이전트가 의존하는 항목을 확인하세요. 관리형 에이전트가 **지식 베이스**, 워크플로우, **커스텀 값** 등 선택할 수 있는 다른 자산을 사용한다면, 그 보조 자산도 스냅샷에 포함하세요.
{% endhint %}

## 스냅샷 자산 선택기에서 보이는 관리형 에이전트

스냅샷 자산 선택기는 지원하는 자산을 제품 카테고리별로 보여 줘요. 관리형 에이전트는 **에이전트 스튜디오** 아래에 있어요. 카테고리를 펼쳐서 이번 배포에 필요한 에이전트만 고를 수 있어요.

자산 선택기는 다음 경우에 쓸 수 있어요.

- 새 스냅샷을 만들 때
- 기존 스냅샷을 새로고침할 때
- 스냅샷을 서브 계정에 불러올 때
- 선택한 스냅샷 자산을 연결된 서브 계정에 푸시할 때

스냅샷에 담긴 자산을 모두 불러오지 않고, 자산을 하나씩 골라서 불러올 수도 있어요.

![스냅샷 자산 선택기의 에이전트 스튜디오 카테고리](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155076472939/original/W8W6GVxjQGXSa7Q9SG6CuMx2LnD-Bk6FLw.png?1784628209)

## 관리형 에이전트를 불러올 때 충돌 확인하기

충돌 확인을 하면 선택한 스냅샷 자산 중 대상 서브 계정에 이미 있는 자산과 겹칠 수 있는 항목을 찾아 줘요. 불러오기 전에 충돌을 살펴보면 기존 설정을 의도치 않게 덮어쓸 위험이 줄어요.

자산 선택 화면에는 두 가지 옵션이 있어요.

- **Proceed to check conflicts**(충돌 확인 후 계속): 선택한 관리형 에이전트를 불러오기 전에 충돌 검토 단계로 넘어가요.
- **Proceed without conflict check**(충돌 확인 없이 계속): 충돌을 먼저 검토하지 않고 바로 불러오기를 시작해요.

이미 사용 중인 서브 계정에 관련 에이전트나 이전 버전이 있을 수 있다면 충돌 확인을 사용하세요. 스냅샷을 일반적으로 불러올 때는 충돌하는 자산을 검토하고, 선택한 항목 중 어떤 것을 적용할지 정할 수 있어요.

![충돌 확인 옵션이 보이는 자산 선택 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155076473369/original/BFlJGmzaZi2z-raffc0oC2RaiMcyILsSxw.png?1784628379)

충돌 확인을 선택한 뒤 대상 서브 계정을 펼치면 확인된 항목이 보여요. 여기서 적용할 자산을 선택하세요.

![대상 서브 계정을 펼쳐 충돌 항목을 확인하는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155076473649/original/JyEnlZza1H6n80C1GxTQAozsV6cK_qkqOQ.png?1784628471)

## 관리형 에이전트를 수정한 뒤 스냅샷 새로고침하기

원본 서브 계정에서 에이전트를 바꿔도 스냅샷은 자동으로 업데이트되지 않아요. 스냅샷을 새로고침하면 선택한 최신 설정이 담기고, 이후 불러오기나 푸시에 쓸 업데이트된 스냅샷 버전이 만들어져요.

**관리형 에이전트를 새로고침하려면:**

1. 원본 서브 계정에서 에이전트를 필요한 대로 수정하세요.
2. **에이전시 보기 > 계정 스냅샷**으로 돌아가세요.
3. 해당 스냅샷을 찾아 **새로고침** 아이콘을 클릭하세요.
4. **에이전트 스튜디오**를 펼치세요.
5. 업데이트한 관리형 에이전트를 선택하세요.
6. 새로 추가했거나 수정한 보조 자산도 선택하세요.
7. **새로고침**을 클릭하세요.
8. 하이퍼클래스가 선택한 자산을 모두 가져올 때까지 기다리세요.

![스냅샷 새로고침 아이콘을 클릭하는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155076473857/original/gZ1q_wBrMO7jXd5VKpRDQLkUDg3-EQ98Kw.png?1784628576)

![새로고침할 관리형 에이전트를 선택하는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155076474098/original/XthFMSkWPAS-1Y6T_wbaPGkMxfZYRAp0LQ.png?1784628720)

새로고침한 뒤에는 스냅샷 불러오기나 푸시 업데이트 방법으로 선택한 변경 사항을 배포하세요. 에이전시 스냅샷에서 푸시한 업데이트는 같은 에이전시 안의 연결된 서브 계정에서 받을 수 있어요. 외부 수신자에게는 보통 업데이트된 공유 스냅샷이 필요해요.

## 스냅샷에서 관리형 에이전트 설정하기

원본 에이전트를 미리 점검하고 필요한 자산을 함께 선택하면, 대상 서브 계정에서 완성된 설정을 바로 쓸 수 있어요. 스냅샷을 만들기 전에 에이전트를 점검하고, 불러온 뒤에는 설정을 확인하세요.

### 관리형 에이전트가 포함된 스냅샷 만들기

1. 원본 서브 계정을 열고, 관리형 에이전트에 재사용하려는 설정이 들어 있는지 확인하세요.
2. **에이전시 보기**로 전환하세요.
3. **계정 스냅샷**으로 이동하세요.
4. **새 스냅샷 생성**을 클릭하세요.
5. **스냅샷 이름**에 알아보기 쉬운 이름을 입력하세요.
6. 관리형 에이전트가 있는 원본 서브 계정을 선택하세요.
7. 자산 선택 단계로 넘어가세요.
8. **에이전트 스튜디오**를 펼치세요.
9. 포함할 관리형 에이전트를 하나 이상 선택하세요.
10. 에이전트에 필요한 보조 자산을 선택하세요. 해당하는 **지식 베이스**, 워크플로우, **커스텀 값** 등이 있어요.
11. 선택한 자산을 검토하세요.
12. **만들기**를 클릭해 스냅샷을 저장하세요.

하이퍼클래스는 원본 서브 계정에 이미 설정된 자산으로 스냅샷을 만들어요. 스냅샷을 처음부터 따로 구성하는 방식은 아니에요.

![새 스냅샷을 만들 때 자산을 선택하는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155076474265/original/OE0JF1k_PgdFextNgRGehvtzC1_ik7UvCQ.png?1784628816)

### 관리형 에이전트를 다른 서브 계정에 불러오기

1. **에이전시 보기**에서 **서브 계정**을 여세요.
2. 대상 서브 계정을 찾으세요.
3. 해당 서브 계정의 점 세 개 메뉴를 열고 **고객 관리**를 선택하세요.
4. **작업**을 열고 **Load Snapshot**(스냅샷 불러오기)을 선택하세요.
5. 관리형 에이전트가 들어 있는 스냅샷을 선택하세요.
6. 안내가 나오면 대상 서브 계정을 선택하세요.
7. **자산** 단계에서 **에이전트 스튜디오**를 펼치세요.
8. 불러올 관리형 에이전트를 선택하세요.
9. 다음 중 하나를 선택하세요.

   - 충돌 가능성을 검토하려면 **Proceed to check conflicts**를 클릭하세요.
   - 바로 진행하려면 **Proceed without conflict check**를 클릭하세요.
10. 충돌 확인을 선택했다면 대상 서브 계정을 펼쳐서 선택할 수 있는 항목을 검토하세요.
11. **계속하기**를 클릭해 선택한 자산을 불러오기 시작하세요.
12. 불러오기가 끝날 때까지 기다리세요.

![스냅샷을 서브 계정에 불러오는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155076474600/original/vIP43johIVbtdDc7cSES06LkXe3IninAQw.png?1784628984)

### 대상 서브 계정에서 관리형 에이전트 확인하기

1. 대상 서브 계정을 여세요.
2. **AI 에이전트 > 에이전트 스튜디오**로 이동하세요.
3. **관리형 에이전트** 탭을 여세요.
4. 옮겨 온 에이전트가 목록에 있는지 확인하세요.
5. 에이전트를 열고 다음 항목을 검토하세요.

   - **이름 및 설명**
   - 트리거
   - 스킬
   - 기능
   - **지식 베이스** 설정
   - 지침
   - 필요한 연동 또는 계정별 연결
6. 대상 계정에서 에이전트를 테스트하세요.
7. 사용할 준비가 되면 게시하거나 활성화하세요.

복사된 자산 중에는 제대로 작동하려면 연동, 권한, 승인, 자격 증명, 대상 계정별 설정이 필요한 것도 있어요.

## 자주 묻는 질문

### 스냅샷에 관리형 에이전트를 여러 개 넣을 수 있나요?
네. **에이전트 스튜디오** 카테고리를 펼쳐서 담을 에이전트를 각각 선택하세요.

### 관리형 에이전트를 복사할 때 스냅샷 자산을 전부 포함해야 하나요?
아니요. 스냅샷 자산은 하나씩 골라서 선택할 수 있어요. 관련 없는 자산을 불러오지 말고, 관리형 에이전트와 그 에이전트에 필요한 보조 자산만 선택하세요.

### 옮긴 에이전트에 지식 베이스 내용이 없어요. 왜 그런가요?
스냅샷을 만들거나 새로고침할 때 필요한 **지식 베이스**를 선택했는지 확인하세요. 스냅샷에는 자산 선택기에서 고른 자산만 담겨요.

### 관리형 에이전트를 불러올 때 충돌 확인을 사용해야 하나요?
대상 계정에 관련 에이전트나 이전 버전이 이미 있을 수 있다면 충돌 확인을 권장해요. 선택한 자산을 적용하기 전에 겹치는 항목을 살펴볼 수 있어요.

### 원본 관리형 에이전트를 수정하면 스냅샷도 자동으로 업데이트되나요?
아니요. 스냅샷을 새로고침하고 수정한 에이전트를 선택해야 최신 설정이 담겨요.

### 옮겨 온 관리형 에이전트는 바로 실행되나요?
불러온 뒤에 에이전트를 검토하고 테스트하세요. 계정별 연동, 권한, 자격 증명 등 다른 연결을 대상 서브 계정에서 설정해야 에이전트가 의도대로 작동할 수 있어요.

### 업데이트한 관리형 에이전트를 여러 서브 계정에 푸시할 수 있나요?
네. 스냅샷을 새로고침한 뒤 푸시 업데이트로 연결된 서브 계정과 업데이트를 받을 자산을 선택하세요.

### 공유 스냅샷으로 관리형 에이전트를 배포할 수 있나요?
에이전트 스튜디오의 에이전트는 스냅샷 링크로 배포하도록 담을 수 있어요. 에이전트 스튜디오 전용 스냅샷 방식으로 더 넓은 공유나 마켓플레이스 사용도 가능해요. 스냅샷을 배포하기 전에 모든 의존 항목을 확인하세요.
