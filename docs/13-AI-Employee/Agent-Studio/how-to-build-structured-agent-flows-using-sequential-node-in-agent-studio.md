# 에이전트 스튜디오에서 Sequential Node로 단계별 에이전트 플로우 만들기

**에이전트 스튜디오**(Agent Studio)의 **Sequential Node**(순차 노드)가 어떻게 동작하는지, 그리고 이 노드로 정해진 순서대로 실행되는 플로우를 만드는 방법을 안내해요. 노드 설정 방법, 사용하기 좋은 상황, 안정적으로 실행되고 사용자가 편하게 쓸 수 있는 플로우를 설계하는 방법을 다뤄요.

## 에이전트 스튜디오의 Sequential Node란

**Sequential Node**는 에이전트 스튜디오의 핵심 구성 요소예요. 하나의 노드 안에서 여러 작업을 정해진 순서대로 차례차례 실행할 수 있어요. 에이전트의 실행을 맡는 부분이고, 각 단계는 미리 정해져 있어서 상황을 판단하지 않고 순서대로 실행돼요.

에이전트 스튜디오에서는 트리거와 노드로 에이전트를 만들어요. **Sequential Node**는 트리거나 다른 노드에서 입력을 받으면 설정된 단계를 위에서 아래로 실행해요.

**Sequential Node**는 상황에 따라 방향을 바꾸지 않고 정해진 경로를 따라가요. 그래서 흐름을 예측할 수 있고 통제해야 하는 경우에 알맞아요. 사용자 정보 수집, API 호출, 여러 작업의 순차 실행이 대표적이에요.

**Sequential Node**는 **처리 노드**로 만들어져요. 처리 노드 하나가 순서의 한 단계예요.

{% hint style="info" %}
**Sequential Node**를 쓰기 전에 에이전트를 시작할 트리거가 설정되어 있는지 확인하세요.
{% endhint %}

## Sequential Node의 장점

일관성과 통제가 중요한 에이전트 플로우를 체계적으로 설계할 수 있어요.

- 정해진 순서대로 단계를 명확하게 실행해요.
- 결과를 예측할 수 있고 같은 결과를 반복해서 얻을 수 있어요.
- 여러 단계를 노드 하나로 묶어서 플로우 설계가 간단해져요.
- 데이터를 깔끔하고 체계적으로 수집할 수 있어요.
- 노드를 여러 개로 나눠 관리할 때보다 구조가 덜 복잡해요.

## Sequential Node의 핵심 요소

### 처리 노드

**Sequential Node** 안의 각 단계는 **처리 노드**로 만들어요. 처리 노드는 순서대로 실행될 개별 작업을 정해요. 입력 수집, API 호출, 콘텐츠 생성 같은 작업이 있어요.

### 단계 실행 순서

**Sequential Node**는 추가한 순서대로 모든 **처리 노드**를 위에서 아래로 실행해요. 한 단계가 끝나야 다음 단계가 시작되기 때문에 흐름을 예측하고 통제할 수 있어요.

### 처리 노드 유형 개요

사용 목적에 따라 **Sequential Node** 안에 여러 유형의 단계를 만들 수 있어요.

- **정보 수집** → 이메일, 전화번호, 선택 항목 같은 사용자 입력을 수집해요.
- **Actions & API**(작업과 API) → 작업을 수행하거나 외부 시스템으로 데이터를 보내요.
- **AI Generation**(AI 생성) → 텍스트, 이미지, 동영상, 오디오를 생성해요.

## Sequential Node의 처리 노드 유형

### 이메일 주소

**이메일 주소** 처리 노드는 순서 진행 중에 사용자에게 올바른 이메일을 받아요. 입력 형식을 검증해서 올바른 형식의 이메일 주소만 다음 단계로 넘어가요.

신뢰할 수 있는 사용자 식별 정보나 연락처가 필요한 플로우에 쓰세요. 안내 메시지는 자연스럽게 쓰고 오류 메시지도 정해 두세요. 수집한 이메일은 나중에 쓸 수 있도록 런타임 변수로 저장돼요.

### 전화번호

**전화번호** 처리 노드는 사용자의 전화번호를 검증하면서 받아요. 정확성을 위해 보통 국가 코드가 필요해요. 번호 형식이 맞아야 다음으로 넘어가기 때문에 깔끔하고 쓸 수 있는 데이터를 유지할 수 있어요.

후속 연락이나 자동화를 위해 직접 연락할 수 있는 정보가 필요할 때 쓰세요. 안내 메시지는 분명하게 쓰고 오류 메시지도 넣으세요. 수집한 번호는 나중에 쓸 수 있도록 런타임 변수가 돼요.

### 텍스트 입력

**텍스트 입력** 처리 노드는 사용자가 자유롭게 답변을 입력하게 해요. 최소·최대 글자 수를 설정할 수 있어서 입력 분량을 조절할 수 있어요.

미리 정해 둘 수 없는 자유로운 입력이 필요할 때 쓰세요. 안내 메시지를 분명하게 쓰고, 필요하면 글자 수 제한을 설정하세요. 답변은 이후 단계에서 쓸 수 있도록 런타임 변수로 저장돼요.

### 단일 선택

**단일 선택** 처리 노드는 미리 정해 둔 선택지 중에서 사용자가 하나를 고르게 해요. 선택지가 버튼으로 표시되어 입력이 명확하고 체계적이에요.

서비스 유형이나 선호 사항처럼 정해진 선택지에서 고르게 하고 싶을 때 쓰세요. 선택지와 안내 메시지를 설정하세요. 선택한 항목은 분기나 후속 처리에 쓸 수 있도록 런타임 변수로 저장돼요.

### API 호출

**API 호출** 처리 노드는 외부 시스템에 요청을 보내고 응답을 받아요. AI의 해석 없이 플로우 안에서 데이터를 주고받을 수 있어요.

CRM이나 타사 플랫폼 같은 외부 서비스와 연동할 때 쓰세요. 엔드포인트, 헤더, 요청 본문을 설정하고, 변수를 활용해서 요청 내용을 동적으로 만들 수 있어요.

### 작업

**작업** 처리 노드는 시스템 안에서 미리 정해진 동작을 수행해요. 수집한 데이터를 업데이트나 트리거 같은 실제 시스템 변경으로 바꿔 줘요.

데이터를 처리한 뒤 플로우가 어떤 동작을 하게 하고 싶을 때 쓰세요. 원하는 결과에 맞게 작업을 설정하면 플로우가 의미 있는 일을 실행해요.

### 텍스트 생성

**텍스트 생성** 처리 노드는 주어진 프롬프트나 입력을 바탕으로 AI가 글을 만들어요. 입력을 수집하는 노드가 아니라 동적인 결과물을 만드는 노드예요.

답변이나 요약 같은 콘텐츠를 생성할 때 쓰세요. 프롬프트를 설정하고, 변수를 활용해 결과물을 개인에 맞게 만든 뒤 다음 단계로 넘기세요.

### 이미지 생성

**이미지 생성** 처리 노드는 정해진 프롬프트를 바탕으로 AI 모델이 이미지를 만들어요. 결과물은 보통 URL이나 시각 자산으로 반환돼요.

플로우에 동적인 시각 콘텐츠가 필요할 때 쓰세요. 프롬프트를 분명하게 쓰고, 변수를 활용해 생성되는 이미지를 상황에 맞게 조정하세요.

### 동영상 생성

**동영상 생성** 처리 노드는 정해진 프롬프트를 바탕으로 AI 모델이 동영상을 만들어요. 해상도와 화면 비율 같은 설정을 지원해요.

플로우 안에서 동영상 콘텐츠를 생성할 때 쓰세요. 프롬프트와 설정을 지정하고, 결과물을 동적으로 만들어야 하면 변수를 활용하세요.

### 오디오 생성(텍스트 음성 변환)

**오디오 생성** 처리 노드는 텍스트 음성 변환 모델로 텍스트를 음성 오디오로 바꿔요. 플로우 안에서 음성 결과물을 동적으로 만들어요.

음성 응답을 제공하고 싶을 때 쓰세요. 텍스트와 음성 설정을 지정하고, 필요하면 변수를 활용해 결과물을 개인에 맞게 만드세요.

### 변수(단계 간 데이터 흐름)

각 처리 노드는 자신의 결과물을 저장하는 런타임 변수를 자동으로 만들어요. 이 변수는 이후 단계에서 쓸 수 있어서 데이터가 순서를 따라 이어져요.

예를 들어 한 단계에서 사용자가 이메일을 입력하면, 그 값을 다음 단계의 확인 메시지나 API 요청에서 다시 쓸 수 있어요.

### 노드 연결

모든 단계가 실행되면 **Sequential Node**가 결과물을 에이전트 플로우의 다음 노드로 넘겨서 이어서 처리해요.

### 5단계: 단계 간 변수 사용

사용자가 한 단계에서 입력한 정보는 사라지지 않고 런타임 변수로 저장돼요. 이 변수를 이후 단계에서 쓰면 메시지를 개인에 맞게 만들거나, API로 데이터를 넘기거나, 작업을 수행할 수 있어요.

1단계에서 데이터 수집 → 2단계에서 그 데이터 사용

### 작동 방식

모든 처리 노드는 결과물을 바탕으로 변수를 자동으로 만들어요. API 호출 같은 단계의 결과물도 여기에 포함되어서 이후 단계에서 다시 쓸 수 있어요.

예를 들면 다음과 같아요.

- 이메일 단계 → 사용자 이메일을 저장해요.
- 전화번호 단계 → 전화번호를 저장해요.
- 텍스트 입력 단계 → 사용자 답변을 저장해요.

이 값들은 변수 선택기({})에 나타나고, 이후 단계에 삽입할 수 있어요.

### 사용 방법

1. 입력을 수집하는 처리 노드를 추가하세요. 예: **이메일 주소**, **텍스트 입력**
2. 노드를 저장하세요. 런타임 변수가 자동으로 만들어져요.
3. 다음 단계에서 프롬프트나 API 본문 같은 입력란을 클릭하세요.
4. {} 아이콘을 클릭해서 변수 선택기를 여세요.
5. 이전 단계의 변수를 선택하세요.

### 예시

1단계(이메일 주소):

사용자가 rahul@email.com을 입력해요.

2단계(**문자 메시지**):

프롬프트:

“감사합니다! 곧 {{email}}(으)로 연락드릴게요.”

### 6단계: 작업 또는 API 호출 추가

앞선 단계에서 데이터를 수집하거나 생성한 뒤에는 그 데이터로 무언가를 해야 할 때가 많아요. **작업**과 **API 호출**을 쓰면 **Sequential Node**가 정보 저장, 다른 시스템으로 데이터 전송, 프로세스 실행 같은 동작을 수행할 수 있어요.

앞 단계에서 데이터 수집 → 이 단계에서 그 데이터로 작업 수행

### 작동 방식

- **작업**은 플랫폼 안에서 미리 정해진 동작을 수행해요. 예: 레코드 업데이트, 워크플로우 실행
- **API 호출**은 외부 시스템으로 데이터를 보내고, 필요하면 응답을 받아요.

두 유형 모두 이전 단계의 런타임 변수를 쓸 수 있어서 상황에 맞게 동적으로 동작해요.

### 이후 단계에서 API 호출 결과 사용하기

**API 호출** 단계를 추가하면 그 응답이 런타임 변수로 자동 저장돼요. 그래서 순서 안의 이후 단계에서 반환된 데이터를 다시 쓸 수 있어요.

이 데이터를 쓰려면 프롬프트 메시지, API 요청 본문, 작업 같은 입력란에서 {} 변수 선택기로 변수를 삽입하세요. 이렇게 하면 API 응답 데이터를 플로우 전체에 동적으로 넘길 수 있어요.

{% hint style="info" %}
**Sequential Node**의 **API 호출** 단계는 AI의 해석 없이 바로 실행돼요. 응답은 그대로 반환되기 때문에 이후 단계에서 직접 사용하도록 지정해야 해요.
{% endhint %}

### 작업 또는 API 호출 추가 방법

1. **처리 노드 추가**를 클릭하세요.
2. 다음 중 하나를 선택하세요.

   - **작업** (내부 작업용)
   - **API 호출** (외부 연동용)
3. 필요한 항목을 설정하세요.

   - **작업**: 수행할 동작을 선택하세요.
   - **API 호출**: 엔드포인트, 헤더, 요청 본문을 입력하세요.
4. {} 변수 선택기로 이전 단계의 데이터를 삽입하세요.
5. 노드를 저장하세요.

### 예시

1단계: 이메일 수집

사용자가 rahul@email.com을 입력해요.

2단계: **API 호출**

- 엔드포인트: CRM으로 데이터 전송
- 요청 본문에 이메일 변수를 포함

결과:

시스템이 Rahul의 이메일을 외부 CRM으로 자동 전송해요.

## 자주 묻는 질문

### AI Agent Node 대신 Sequential Node는 언제 쓰나요?

체계적이고 예측 가능한 플로우가 필요할 때는 **Sequential Node**를 쓰세요. 상황에 따라 판단하거나 대화가 필요한 상호작용에는 **AI Agent Node**(AI 에이전트 노드)를 쓰세요.

### API 호출이 AI 응답처럼 생각하거나 상황에 맞게 바뀌지 않는 이유는 뭔가요?

**Sequential Node**의 API 호출은 해석 없이 바로 실행돼요. 요청을 보내고 응답을 돌려줄 뿐이에요. 추론이나 맥락에 맞는 처리가 필요하면 그 로직은 **AI Agent Node**에서 처리해야 해요.

### 단계에서 변수를 쓰지 않으면 어떻게 되나요?

변수를 쓰지 않으면 플로우가 고정되어서 매번 같은 결과가 나와요. 변수를 쓰면 사용자 입력과 단계별 결과물이 이후 동작에 영향을 주기 때문에 순서가 동적으로 바뀌어요.

### 단계를 추가한 뒤에 순서를 바꿀 수 있나요?

**Sequential Node**는 순서대로 실행되도록 설계되어 있어서, 단계 순서를 바꾸는 것이 항상 지원되거나 간단하지는 않을 수 있어요. 다시 작업하는 일이 없도록 순서를 미리 계획하고, 올바른 순서로 단계를 추가하는 것이 좋아요.
