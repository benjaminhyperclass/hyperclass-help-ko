# 음성 AI 프롬프트 최적화 도구 사용하기

**프롬프트 최적화 도구**(Prompt Optimizer)는 실제 통화와 비슷한 시나리오로 [Voice AI 에이전트](../how-to-create-voice-ai-agents.md)의 프롬프트를 테스트하고 개선하는 기능이에요. 시나리오를 만들어 음성 통화로 테스트하고, 결과를 확인한 뒤, 최적화된 프롬프트 버전을 비교해서 운영 중인 에이전트에 적용할 수 있어요. 실제 고객 통화를 음성 AI에 연결하기 전에 에이전트의 동작을 검증하고 통화 결과를 개선하는 데 도움이 돼요.

## 음성 AI의 프롬프트 최적화 도구란?

프롬프트 최적화 도구는 Voice AI 에이전트를 대상으로 시나리오별 통화 테스트를 실행하는 도구예요. 시나리오마다 에이전트가 기대한 대로 동작하는지 평가하고, 테스트 결과를 바탕으로 개선된 프롬프트 버전도 만들어 줘요.

테스트 통화를 한 번씩 해 보는 데서 그치지 않고, 발신자의 말, 업무 흐름, 반론, 도구 사용, 기대 결과를 에이전트가 얼마나 잘 처리하는지 측정할 수 있어요. 시나리오를 생성하거나 직접 만들어서 최적화를 시작하는 방법이 있어요. **Trial Call Prompt Optimizer**(테스트 통화 프롬프트 최적화 도구)를 쓸 수 있을 때는 Voice AI 에이전트 빌더에서 완료된 테스트 통화로 바로 시작할 수도 있어요.

## 프롬프트 최적화 도구의 주요 장점

런칭 전후에 Voice AI 에이전트의 동작을 체계적으로 테스트하고, 측정하고, 개선할 수 있어요. 프롬프트가 잘 동작하는지 짐작하는 대신, 시나리오 결과와 통화 내용, 테스트한 프롬프트 버전을 확인한 뒤 에이전트를 수정할지 결정할 수 있어요.

- 시나리오 자동 생성: Voice AI 에이전트와 테스트 흐름에 맞는 테스트 시나리오를 만들어 줘요.
- 완료된 테스트 통화로 최적화: 조건에 맞는 완료된 테스트 통화를 시나리오를 다시 짜지 않고 바로 새 최적화 실행으로 바꿀 수 있어요.
- 실제 음성 통화 테스트: 음성으로 테스트하므로 실제 대화에서 에이전트가 어떻게 동작하는지 확인할 수 있어요.
- 액션 검증: 예약, SMS, 이메일, 지식 베이스 조회, CRM 업데이트 같은 설정된 액션이 기대한 대로 동작하는지 테스트해요.
- AI 점수와 판단 근거: 기대 결과를 기준으로 통화를 평가하고, 통과·실패한 이유를 설명해 줘요.
- 녹취록과 녹음 확인: 프롬프트를 바꾸기 전에 통화 전체를 살펴볼 수 있어요.
- 프롬프트 버전 테스트: 기존 프롬프트를 개선해야 할 때 개선된 프롬프트 버전을 만들고 평가해요.
- 통제된 프롬프트 업데이트: 결과를 확인한 뒤에 최적화된 프롬프트를 적용할 수 있어요.
- 다국어 테스트: 선택한 언어로 시나리오 생성, 통화, 평가를 진행해요.

## 프롬프트 최적화 도구를 쓰면 좋은 때

중요하거나 문제가 되는 통화 시나리오를 체계적으로 테스트해야 할 때 가장 유용해요. 새 에이전트를 런칭하기 전에 검증하거나, 설정을 바꾼 뒤 다시 테스트하거나, 완료된 테스트 통화의 결과가 기대에 못 미칠 때 프롬프트를 개선하는 데 쓸 수 있어요.

이런 경우에 사용하세요.

- Voice AI 에이전트에 실제 고객 통화를 연결하기 전
- 프롬프트, 목표, 도구, 액션, 지식 소스를 바꾼 후
- **Web Call**(웹 통화) 또는 **Phone Call**(전화 통화) 테스트가 실패했거나 예상과 다르게 진행된 후
- 예약 부킹, 통화 전환, SMS, 이메일, CRM 업데이트, 지식 베이스 동작을 검증할 때
- 다국어 시나리오나 예외 상황을 테스트할 때
- 같은 시나리오를 반복해서 프롬프트 버전을 비교할 때
- 정확도나 기대 동작을 측정해야 할 때
- 조건에 맞는 완료된 빌더 테스트 통화에서 바로 최적화를 시작하고 싶을 때

프롬프트 최적화 도구는 다른 Voice AI 프롬프트 도구와 역할이 달라요.

- **Prompt Evaluator**(프롬프트 평가 도구): 프롬프트를 검토하고 개선할 만한 부분을 찾아 줘요.
- **Edit Prompts with AI**(AI로 프롬프트 편집): 입력한 지시에 따라 선택한 프롬프트 문구를 다시 쓰거나 다듬어 줘요.
- 프롬프트 최적화 도구: 시나리오 기반 음성 테스트를 실행하고, 결과를 평가하고, 최적화된 프롬프트 버전을 테스트해요.
- **Trial Call Prompt Optimizer**: 조건에 맞는 완료된 테스트 통화를 시작점으로 프롬프트 최적화를 실행해요.

시나리오 테스트 없이 프롬프트에서 고칠 부분을 이미 알고 있다면, 하이퍼클래스의 [Edit Prompts with AI](voice-ai-edit-prompts-with-ai.md)를 쓰면 돼요.

## 사용 전에 알아 두세요

프롬프트 최적화 도구는 Voice AI 테스트 통화를 여러 번 실행하고, 에이전트에 연결된 액션을 실행할 수도 있어요. 시작하기 전에 현재 프롬프트, 테스트에 쓸 리소스, 사용량 정보를 확인해 두면 의도하지 않은 동작을 막고 결과도 더 쉽게 해석할 수 있어요.

- 테스트 통화는 텍스트로만 하는 시뮬레이션이 아니라 음성 테스트예요.
- 테스트 중에 예약, SMS, 이메일, [지식 베이스](knowledge-base-integration-for-voice-ai-agents.md) 조회, CRM 업데이트 같은 설정된 액션이 실행될 수 있어요.
- 가능하면 테스트용 연락처, 캘린더, 수신 대상, 연결된 리소스를 쓰세요.
- 프롬프트 최적화 도구의 개별 테스트 통화에는 현재 음성 AI 화면에 안내된 테스트 한도가 적용될 수 있어요.
- AI 평가와 프롬프트 동작은 결과가 항상 같지 않으므로, 정확도는 방향을 가늠하는 참고 지표로 보세요.
- 점수와 함께 녹취록, 녹음, 도구 실행 결과, 평가 근거를 확인하세요.
- 프롬프트 최적화 도구는 현재 Voice AI 에이전트 구조를 지원해요.
- 프롬프트 변경은 자동으로 적용되지 않아요. 최적화된 버전을 검토한 뒤에 적용하세요.

{% hint style="warning" %}
프롬프트 최적화 도구 사용량은 하이퍼클래스 AI 요금제에 따라 달라요. 현재 AI 요금 안내 문서에는 음성 AI 프롬프트 최적화 도구가 Pay-Per-Use 서브 계정은 사용한 만큼 과금, AI 직원 Growth는 월 100분 포함, AI 직원 Unlimited는 공정 사용 범위 내 무제한으로 안내되어 있어요. 실행을 시작하기 전에 하이퍼클래스에 표시되는 사용량 정보를 확인하세요.
{% endhint %}

## 음성 AI에서 프롬프트 최적화 도구 사용하기

설정을 제대로 해 두면 올바른 시나리오를 테스트하고 쓸모 있는 프롬프트 제안을 받을 수 있어요. 프롬프트 최적화 도구는 테스트 계획 설정, 실제 통화 실행, 결과 검토, 필요할 때 프롬프트 버전 개선 순서로 진행돼요.

1. **AI 에이전트 > 음성 AI > 에이전트 목록**으로 이동하세요.

   ![AI 에이전트 메뉴에서 음성 AI 에이전트 목록으로 이동하는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155074414371/original/n0peHYpI26PonvjGlwXag3_UKZlX-y5P3A.png?1782310315)
2. 테스트할 Voice AI 에이전트를 여세요.
3. 에이전트 빌더에서 **프롬프트 최적화 도구**를 클릭하세요.

   프롬프트 최적화 도구는 Voice AI 에이전트 빌더에서 열려요. 선택한 에이전트의 기존 프롬프트, 언어, 통화 방향, 설정된 액션을 가져와 테스트 흐름을 준비해요. 테스트할 때는 운영 중인 에이전트를 복제해서 쓰기 때문에, 테스트나 최적화 과정에서 운영 중인 에이전트는 바뀌지 않아요.

   ![에이전트 빌더에서 프롬프트 최적화 도구를 여는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155074414510/original/1XrancvLBeJtrTSw5AgmvSR_ntLk-dszWw.gif?1782310421)
4. **시나리오 생성**을 클릭하고, 자동으로 만들어진 시나리오를 확인하세요.

   프롬프트 최적화 도구는 에이전트 설정을 바탕으로 테스트 시나리오를 자동으로 만들어요. 이 시나리오로 에이전트가 실제 같은 발신자 요청에 어떻게 응답하는지, 기대한 동작을 끝까지 수행하는지 테스트할 수 있어요.

   생성된 시나리오에는 다음 내용이 들어갈 수 있어요.

   - 발신자 페르소나 또는 발신자 상황
   - 발신자 입력(발신자가 하는 질문이나 요청)
   - 기대하는 에이전트 동작
   - 기대하는 도구 또는 액션 사용
   - 시나리오 우선순위: **Critical**(긴급), **High**(높음), **Medium**(보통), **Low**(낮음)

   ![자동 생성된 시나리오 목록 화면](https://jumpshare.com/share/L6ep7mSHpYLSXUrgcUtb+/GIF+Recording+2026-04-28+at+20.41.18.gif)
5. 실행할 시나리오를 선택하세요.

   검증하려는 업무 흐름에 맞는 시나리오를 고르면 돼요. 예를 들어 에이전트가 지식 베이스로 답변하는지, 발신자를 확인하는지, 예약을 잡는지, SMS나 이메일을 보내는지, 특정 예외 상황을 처리하는지 테스트할 수 있어요.

   ![실행할 시나리오를 선택하는 화면](https://jumpshare.com/share/HdgujWhPHeA2k34ePs6K+/GIF+Recording+2026-04-28+at+20.43.03.gif)
6. 필요하면 시나리오를 편집하거나 직접 만드세요.

   특정 업무 흐름, 예외 상황, 발음 문제, 지역 관련 질문, 필수 응답, 액션 순서를 테스트해야 할 때 사용자 지정 시나리오가 유용해요. 기대 동작을 분명하게 적어 두면 에이전트가 의도한 통화 흐름을 따랐는지 더 정확하게 평가할 수 있어요.

   시나리오를 만들거나 편집할 때 다음 항목을 설정해요.

   - **시나리오 이름**
   - **설명**
   - **Caller input**(발신자 입력)
   - **Expected behaviors**(기대 동작)
   - **Priority**(우선순위)

   기대 동작 예시로는 발신자 정보 확인, 지원하지 않는 요청 거절, 예약 잡기, SMS 보내기, 이메일 보내기, 지식 베이스로 답변하기가 있어요.

   ![시나리오를 만들고 기대 동작을 입력하는 화면](https://jumpshare.com/share/5Q8wd7RsvkUKMs3qDQBA+/GIF+Recording+2026-04-28+at+20.46.59.gif)
7. 이전 실행의 시나리오를 다시 쓸 수 있다면 불러오세요.

   지난 시나리오를 다시 쓰면 테스트 계획을 새로 짜지 않고 같은 업무 흐름을 다시 테스트할 수 있어요. 프롬프트를 바꾼 뒤, 같은 시나리오에서 최적화 후 결과가 더 좋아졌는지 비교할 때 유용해요.
8. 테스트에 쓸 언어를 선택하세요.

   프롬프트 최적화 도구는 다국어 테스트를 지원해요. 선택한 언어로 시나리오 생성, 통화, 평가가 이루어지므로 실제 발신자가 쓰는 언어에서 에이전트가 어떻게 동작하는지 확인할 수 있어요.
9. 시나리오당 통화 횟수를 선택하세요.

   시나리오마다 몇 번 통화할지 정해요. AI 동작은 통화마다 조금씩 달라질 수 있어서, 여러 번 통화하면 일관성을 확인하는 데 도움이 돼요. 시나리오당 1~10회까지 지원해요.
10. 사용량과 하루 테스트 시간을 확인하세요.

    실행을 시작하기 전에 사용량 대시보드에서 오늘 사용한 무료 테스트 시간과 남은 시간을 확인하세요. 서브 계정마다 하루 20분의 무료 테스트 시간이 제공되고, 무료 시간을 다 쓰면 추가 사용량이 발생할 수 있어요.
11. 테스트 연락처와 실행 전 체크리스트를 확인하세요.

    프롬프트 최적화 도구는 통화에 전용 테스트 연락처를 사용해요. 테스트를 시작하기 전에 이름, 전화번호, 이메일 같은 테스트 연락처 정보와 캘린더, 액션, 사용량 관련 경고를 확인하세요.

    테스트 통화는 실제 통화라서 설정된 액션이 테스트 중에 실행될 수 있어요. 예약 부킹, SMS, 이메일, 지식 베이스 조회, CRM 업데이트 등이 해당돼요. 가능하면 테스트 연락처와 안전한 테스트 환경을 쓰세요. 예약 업무 흐름이라면 의도하지 않은 예약을 막기 위해 테스트용 캘린더를 쓰는 것도 좋아요.
12. **Run Calls**(통화 실행)를 클릭하세요.

    선택한 시나리오와 통화 횟수에 따라 실제 음성 통화가 시작돼요. 텍스트로만 하는 시뮬레이션이 아니에요. 에이전트가 전화를 받고 테스터와 대화하며, 설정된 액션을 처음부터 끝까지 실행해요.

13. 통화 진행 상황을 확인하세요.

    통화는 **Waiting**(대기 중), **In Progress**(진행 중), **Evaluating**(평가 중), **Completed**(완료), **Failed**(실패) 같은 상태를 거쳐요. 화면을 벗어나도 통화는 백그라운드에서 계속 처리되니, 나중에 다시 돌아와서 확인해도 돼요.

14. 통과·실패 요약을 확인하세요.

    통화가 끝나면 통과한 통화 수, 실패한 통화 수, 테스트한 시나리오 전체의 정확도(%)가 표시돼요. 정확도 점수는 성공 여부를 가늠하는 참고 지표로만 쓰고, 이것만으로 판단하지 마세요.

    테스트 중과 테스트 후에 다음 정보가 표시돼요.

    - 통화 상태와 진행 상황
    - 테스트한 시나리오 수와 통화 수
    - 통과·실패 결과
    - 전체 정확도(%)
    - AI 평가 근거
    - 도구 호출과 도구 실행 결과
    - 화자 구분과 시간 표시가 있는 **전체 녹취록**
    - **통화 녹음** 재생

15. 통화별 녹취록과 녹음을 확인하세요.

    개별 통화 결과를 열면 녹취록을 읽고 녹음을 들을 수 있어요. 녹취록에는 화자 구분과 시간이 표시되어 있어서, 테스터가 어떤 말을 했는지, 에이전트가 어떻게 답했는지, 어느 지점에서 성공하거나 실패했는지 따라가기 쉬워요.

16. AI 점수와 판단 근거를 확인하세요.

    프롬프트 최적화 도구는 시나리오에 설정한 기대 결과를 기준으로 통화마다 평가해요. AI 판단 근거는 통과하거나 실패한 이유를 설명해 줘서, 에이전트가 단계를 빠뜨렸는지, 발신자의 말을 잘못 이해했는지, 필수 액션을 건너뛰었는지, 불완전한 정보로 답했는지 파악하기 쉬워요.

    평가가 엄격할 수 있어요. 실패 결과가 대화 전체가 실패했다는 뜻은 아니지만, 살펴볼 만한 부분이 있다는 뜻이에요.

    ![AI 점수와 판단 근거를 확인하는 화면](https://jumpshare.com/share/ZYLW0Dv8GNg92bjvyPaI+/GIF+Recording+2026-04-28+at+21.06.30.gif)
17. 도구 호출과 액션 결과를 확인하세요.

    도구 호출 기록에서 테스트 통화 중 어떤 액션이 실행됐는지 볼 수 있어요. 예약, 메시지 발송, 지식 베이스 답변, CRM 액션이 걸린 업무 흐름을 테스트할 때, 에이전트가 올바른 시점에 올바른 도구를 쓰는지 확인하는 데 도움이 돼요.

    프롬프트 최적화 도구로 테스트할 수 있는 업무 흐름은 다음과 같아요.

    - 지식 베이스 조회
    - [예약 부킹](appointment-booking-for-voice-ai-agents-in-hyperclass.md)
    - SMS 메시지 발송
    - 이메일 발송
    - 발신자 확인
    - CRM 관련 업데이트 또는 액션

18. 프롬프트를 바꾸기 전에 **실패한 통화**를 먼저 확인하세요.

    프롬프트를 바꿔야 하는지는 실패한 통화를 살펴본 뒤에 결정하세요. 실패 결과는 에이전트가 기대한 동작을 놓쳤거나, 단계를 잘못된 순서로 진행했거나, 액션을 잘못 썼거나, 시나리오 요건을 충족하지 못했다는 뜻일 수 있어요.

    실패한 통화를 확인할 때는 다음을 살펴보세요.

    - AI 평가 이유
    - 녹취록
    - 통화 녹음
    - 도구 호출 상세 내용
    - 기대 동작이 충분히 명확하게 작성되었는지
    - 에이전트 프롬프트에 더 구체적인 지시가 필요한지
19. **즉흥 대응**을 클릭해 최적화된 프롬프트 버전을 하나 만드세요.

    **즉흥 대응**은 실패한 통화를 분석해 원인으로 보이는 부분을 찾고, 수정한 프롬프트 버전을 만들어 테스트해요. 운영 중인 에이전트에 적용하기 전에 성능을 비교할 수 있어요.

20. 여러 버전을 테스트하고 싶다면 **자동**을 사용하세요.

    **자동** 최적화는 프롬프트 버전을 최대 5개까지 자동으로 실행해요. 목표에 도달했을 때, 최대 버전 수에 도달했을 때, 개선이 없을 때, 시간 초과가 발생했을 때, 청구 한도에 도달했을 때 중단될 수 있어요.
21. 버전별 결과와 프롬프트 변경 내용 비교(diff)를 확인하세요.

    각 버전에는 다음 정보가 포함될 수 있어요.

    - 테스트 결과

## 프롬프트 최적화 결과 확인하기

정확도 점수가 높아졌다면 개선되었다는 신호일 수 있어요. 하지만 점수만으로는 테스트한 모든 시나리오에서 에이전트가 적절하게 동작했는지 알 수 없어요. 통화 내용과 프롬프트 차이를 함께 확인하면 에이전트를 업데이트할지 더 정확하게 판단할 수 있어요.

프롬프트 최적화 결과에는 다음 정보가 포함될 수 있어요.

- 통화 상태와 진행 상황
- 테스트한 시나리오 수와 통화 수
- 통과·실패 결과
- 전체 정확도
- AI 평가 근거
- 도구 호출과 결과
- **전체 녹취록**
- **통화 녹음**
- 프롬프트 버전 기록
- 프롬프트 차이
- 해당하는 경우 가장 성능이 좋은 버전

실패한 통화는 프롬프트 변경이 필요하다고 결정하기 전에 평가 이유, 녹취록, 녹음, 도구 활동, 기대 동작, 현재 프롬프트 지시를 함께 확인하세요.

## 자주 묻는 질문

### 프롬프트 최적화 도구는 어떻게 과금되나요?
청구 정보는 AI Product Pricing 문서에서 확인하세요.

### 프롬프트 최적화 도구가 운영 중인 Voice AI 에이전트를 자동으로 바꾸나요?
아니요. 프롬프트 최적화 도구는 에이전트를 복제한 버전으로 테스트해요. 버전을 검토하고 **프롬프트 사용**을 클릭하기 전에는 운영 중인 에이전트가 업데이트되지 않아요.

### 프롬프트 최적화 도구와 Prompt Evaluator는 어떻게 다른가요?
Prompt Evaluator는 프롬프트를 검토하고 제안을 줘요. 프롬프트 최적화 도구는 실제 테스트 통화를 실행하고, 결과를 평가하고, 실패한 동작을 찾아내고, 테스트를 거친 프롬프트 버전을 만들어 줘요.

### 프롬프트 최적화 도구의 통화는 실제 통화인가요?
네. 실제 음성 통화를 실행해서 대화 동작과 설정된 액션을 처음부터 끝까지 테스트해요.

### 테스트 통화가 실제 액션을 실행할 수 있나요?
네. 테스트 중에 예약 부킹, SMS, 이메일, 지식 베이스 조회, CRM 업데이트 같은 액션이 실행될 수 있어요. 가능하면 테스트 연락처와 안전한 테스트 환경을 쓰세요.

### 대화는 괜찮아 보였는데 통화가 실패한 이유는 뭔가요?
평가는 시나리오에 정의한 기대 동작을 기준으로 통화를 비교해요. 필수 단계를 놓쳤거나, 순서가 틀렸거나, 액션을 건너뛰었거나, 기대 결과와 충분히 일치하지 않으면 통화가 실패할 수 있어요.

### 정확도 점수만 믿으면 되나요?
아니요. 점수는 방향을 가늠하는 참고 지표로 쓰고, 프롬프트를 업데이트할지 결정하기 전에 녹취록, 녹음, 도구 호출, AI 판단 근거를 확인하세요.

### **자동** 최적화는 버전을 몇 개까지 실행하나요?
**자동** 최적화는 세션당 최대 5개 버전까지 실행해요.

### 여러 언어로 테스트할 수 있나요?
네. 선택한 언어로 시나리오 생성, 통화, 평가를 할 수 있어요.

### 이전 테스트 실행의 시나리오를 다시 쓸 수 있나요?
네. 지난 시나리오를 불러오면 테스트 계획을 새로 짜지 않고 자주 쓰는 업무 흐름을 다시 테스트할 수 있어요.

### **프롬프트 사용**을 클릭하면 어떻게 되나요?
업데이트를 확인하면 선택한 최적화 프롬프트가 해당 에이전트에 적용돼요.
