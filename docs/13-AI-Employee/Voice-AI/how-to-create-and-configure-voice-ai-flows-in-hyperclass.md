# 음성 AI 플로우 만들기와 설정

하이퍼클래스의 **플로우 기반 빌더**에서는 캔버스 위에서 에이전트, 라우터, 액션을 연결해 AI 통화 흐름을 만들 수 있어요. 에이전트마다 맡길 일을 따로 정하고, 지원되는 작업을 자동화하고, 통화 처리 방식을 원하는 대로 바꿀 수 있어요. 이 문서에서는 음성 AI 플로우를 만들고, 설정하고, 테스트하고, 실제로 운영하기까지의 과정을 안내해요.

---

## 음성 AI 플로우란?

음성 AI 플로우는 서로 연결된 노드의 순서예요. AI 통화가 어떻게 진행될지 이 순서로 정해져요. 노드마다 맡은 역할이 있고, 연결과 라우팅 조건이 다음에 일어날 일을 결정해요.

예를 들어 리드 자격 확인 플로우는 이런 구조로 만들 수 있어요.

**Start Call**(통화 시작) → 인사 에이전트 → **라우터** → 자격 확인 에이전트 → CRM 액션 → **통화 종료**

사용할 수 있는 노드와 기능이 궁금하면 [음성 AI 플로우 기반 빌더 시작하기](getting-started-with-the-flow-based-builder-for-voice-ai.md)를 참고하세요.

---

## 음성 AI 플로우를 설정하면 좋은 점

플로우를 설정하면 단계마다 대화를 직접 조절할 수 있어요. 에이전트는 각자 맡은 역할에만 집중하고요.

- 목적별 에이전트 지침: 작업마다 프롬프트, 모델, 도구를 따로 설정해요.
- 조건부 라우팅: 통화자의 요청에 맞는 에이전트로 연결해요.
- 작업 자동화: 기본 제공 도구, MCP, 커스텀 API 연동으로 지원되는 작업을 실행해요.
- 맞춤 통화 환경: 음성, 언어, 인사말, 통화 설정을 직접 정해요.
- 안정적인 운영: 실제 통화를 받기 전에 대화 경로와 연동을 테스트해요.

---

## 시작하기 전에

미리 준비해 두면 설정이 빠지거나 테스트 중에 작업이 실패하는 일을 줄일 수 있어요.

다음 항목을 확인하세요.

- 음성 AI 에이전트를 관리할 권한이 있는 서브 계정
- 통화 시나리오, 그리고 각 에이전트가 수집하거나 안내할 정보
- 필요한 캘린더, 지식 자료, **API 자격 증명**, MCP 연결
- 실제 전화로 운영할 때 쓸 수 있는 전화번호 또는 **Number Pool**(번호 풀)
- 아웃바운드 통화를 쓸 경우 해당하는 발신 인증과 규정 준수 설정

---

## 음성 AI 플로우 설정하기

음성 AI 플로우에는 서로 연결된 대화 경로, 설정을 마친 에이전트, 정상 작동하는 액션이 필요해요. 아래 순서대로 따라 하면 처음부터 플로우를 만들고 테스트할 준비까지 마칠 수 있어요.

### 1단계: 플로우 기반 음성 AI 에이전트 만들기

1. **AI 에이전트 > 음성 AI > 에이전트 목록**으로 이동하세요.
2. **+ 에이전트 만들기**를 클릭하세요.
3. **플로우 기반 빌더**를 선택하세요.
4. **계속**을 클릭하세요.

빌더가 열리면 **Start Call** 노드가 **AI 에이전트** 노드에 연결된 상태로 보여요.

**![플로우 기반 빌더의 시작 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083210171/original/6MRnO8ncwTM9e8QoIka072wHBwqN3Gt_6g.png?1791899514)**

{% hint style="info" %}
에이전트를 저장해야 기본으로 만들어진 플로우가 유지돼요.
{% endhint %}

### 2단계: 첫 번째 AI 에이전트 설정하기

**AI 에이전트** 노드마다 프롬프트, 지원되는 AI 모델, 도구를 따로 설정할 수 있어요. 먼저 첫 대화를 맡을 에이전트부터 설정해 보세요.

1. 기본으로 있는 **AI 에이전트** 노드를 선택하세요.
2. *인사 에이전트*처럼 역할을 알 수 있는 이름을 붙이세요.
3. 에이전트의 역할, 대화 목표, 기대하는 응답을 프롬프트에 입력하세요.
4. 선택할 수 있는 모델 중에서 알맞은 모델을 고르세요.
5. 이 에이전트에 필요한 도구를 설정하세요.

![첫 번째 AI 에이전트 설정 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083210513/original/lct2gQ5lb_XFnIi-UNVidhydP17qce9J4w.png?1791899686)

인사 에이전트의 프롬프트에는 통화자를 어떻게 맞이할지, 용건을 어떻게 파악할지, 다음 대화 단계로 어떻게 안내할지를 적어 주세요.

### 3단계: AI 에이전트 추가하고 라우팅 설정하기

**AI 에이전트** 노드를 여러 개 두면 자격 확인, 지원, 예약처럼 작업별로 역할을 나눌 수 있어요. 통화자가 어느 경로로 갈지는 **라우터** 노드가 정해요.

1. 노드 라이브러리에서 **AI 에이전트** 노드를 하나 더 추가하세요.
2. 이름, 프롬프트, 모델, 필요한 도구를 설정하세요.
3. 대화가 갈라지는 지점에 **라우터** 노드를 추가하세요.
4. 앞 단계의 에이전트를 **라우터**에 연결하세요.
5. 사용할 수 있는 설정 항목으로 라우팅 조건을 설정하세요.
6. 각 경로를 알맞은 **AI 에이전트** 노드나 다음 노드에 연결하세요.
7. 대화를 끝내야 하는 곳에 **통화 종료** 노드를 추가하세요.

예를 들면 이렇게 연결해요.

- 영업 문의: 인사 에이전트 → 라우터 → 자격 확인 에이전트
- 지원 요청: 인사 에이전트 → 라우터 → 지원 에이전트

모든 경로에 올바른 연결 대상이 있는지 확인하세요. 예상한 경로와 분명하게 맞지 않는 요청을 처리할 경로도 만들어 두세요.

**![AI 에이전트와 라우터를 연결한 플로우 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083210863/original/I2j6XZnA4ucVA8ixDycQ845oEUhJrqJ8kA.png?1791899804)**

### 4단계: 액션과 연동 설정하기

액션을 쓰면 음성 AI 에이전트가 대화 중에 메시지를 보내거나, 연결된 시스템의 정보를 업데이트하는 등의 작업을 할 수 있어요.

1. 플로우에서 실행해야 할 작업이 무엇인지 정하세요.
2. 지원되는 액션이나 연동 노드 중 알맞은 것을 추가하세요.
3. 필수 입력 항목, 연결 정보, 실행 조건을 설정하세요.
4. 해당 대화 경로에 연결하세요.
5. 설정을 저장하세요.

빌더에서 사용할 수 있는 옵션에 따라 다음 방법을 쓸 수 있어요.

| 방법 | 용도 |
| --- | --- |
| **Native Actions**(기본 제공 액션) | 메시지 보내기, 사용할 수 있는 CRM 액션 등 지원되는 기본 제공 작업이에요. |
| **Custom API**(커스텀 API) | 설정한 API 엔드포인트로 외부 서비스에 요청을 보내요. |
| **MCP 서버** | 연락처, 캘린더, 예약 등에 쓰는 지원 도구를 사용해요. |

![액션과 연동 설정 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083211478/original/9QqXSRIUN1w_a3RlA1Rk5E1ky28LCguCeA.gif?1791900056)

#### 연락처 업데이트와 예약 설정

연락처 업데이트와 예약 작업은 지원되는 기본 제공 액션이 있으면 그것으로 설정할 수 있어요. 없으면 알맞은 MCP나 API 연동으로 설정해요.

MCP 연동을 쓴다면 테스트하기 전에 서버 연결, 인증 정보, 허용할 도구, 실행 조건을 먼저 설정하세요.

MCP 설정 방법은 [음성 AI 에이전트의 Model Context Protocol(MCP) 연동](model-context-protocol-mcp-integration-for-voice-ai-agents.md)에서 자세히 볼 수 있어요.

![MCP 연동 설정 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083211537/original/Dzab3UA3LtcZVhyfjstdnZ4de3G6dG4L0w.png?1791900090)

{% hint style="warning" %}
에이전트가 통화자에게 작업이 끝났다고 말하기 전에, CRM 업데이트나 예약이 실제로 성공했는지 확인하세요.
{% endhint %}

### 5단계: 음성과 통화 설정하기

음성 설정과 통화 설정에 따라 대화 중 에이전트의 목소리와 응답 방식이 달라져요. 통화를 받는 대상과 플로우가 처리할 통화 유형에 맞게 조정하세요.

1. 사용할 수 있는 음성 AI 설정을 여세요.
2. 원하는 **언어**를 선택하세요.
3. 필요에 따라 **Inbound and Outbound Welcome Messages**(인바운드·아웃바운드 환영 메시지)를 설정하세요.
4. **음성 설정**에서 음성을 고르고 미리 들어 보세요.
5. **통화 설정**을 확인하세요. 지원되는 무음 처리와 소음 제거 옵션도 여기에 있어요.
6. 필요하면 **전사 & 음성**과 **번역**을 설정하세요.
7. **통화 후** 설정과 해당하는 **아웃바운드 설정**을 확인하세요.
8. **변경사항 저장**을 클릭하세요.

**![음성과 통화 설정 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083211602/original/SiskQqjZ6ByvlUKq8_T7x20Jv3NEyIxAxg.png?1791900138)**

### 6단계: 음성 AI 플로우 테스트하기

운영하기 전에 테스트하면 잘못된 라우팅, 빠진 지침, 액션 실패를 미리 찾을 수 있어요.

1. 최신 플로우 설정을 저장하세요.
2. **에이전트 테스트하기**를 여세요.
3. **웹 통화** 또는 **전화 통화**를 선택하세요.
4. 선택할 수 있는 인바운드 또는 아웃바운드 시나리오를 고르세요.
5. 테스트 대화를 시작하세요.
6. 경로를 하나씩 테스트하면서 알맞은 에이전트가 응답하는지 확인하세요.
7. 설정한 액션이 실행되고 기대한 결과가 나오는지 확인하세요.
8. 확인할 수 있는 전사본, 통화 기록, 액션 상세 내용을 살펴보세요.
9. 필요한 부분을 고치고 다시 테스트하세요.

**웹 통화**는 브라우저에서 바로 대화 동작을 테스트할 때 편해요. 실제 전화에서의 동작을 확인하려면 **전화 통화**로 테스트하는 것을 권장해요.

![에이전트 테스트하기 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083211762/original/Pk0tVvssfORskDi5N3_GBNQTD3wjhjiW-Q.png?1791900218)

{% hint style="info" %}
**웹 통화** 테스트에서는 **통화 전환**을 지원하지 않아요. 통화 전환 기능을 확인해야 한다면 **전화 통화**로 테스트하세요.
{% endhint %}

더 자세한 내용은 [음성 AI 에이전트 테스트하기](how-to-test-voice-ai-agents.md)를 참고하세요.

## 자주 묻는 질문

### 빌더에 다시 들어왔더니 새로 만든 플로우가 없어요.
처음 만들어지는 기본 플로우는 저장해야 유지돼요. 에이전트를 만든 직후에 한 번, 설정을 바꿀 때마다 다시 저장하세요.

### 통화자가 엉뚱한 에이전트로 연결돼요.
**라우터**의 조건, 앞 단계 에이전트의 지침, 노드 사이의 연결을 확인하세요. 여러 가지 말로 테스트해서 의도한 대로 라우팅되는지 살펴보세요.

### MCP나 API 액션이 실패하면 무엇을 확인해야 하나요?
엔드포인트나 서버 연결, 인증, 허용된 도구, 요청 설정, 실행 조건을 확인하세요. 확인할 수 있는 액션 결과를 보면 문제가 어디서 생겼는지 알 수 있어요.

### 액션이 완료됐다는데 CRM에는 반영되지 않았어요.
액션이 정상적으로 실행됐는지, 필요한 데이터가 전달됐는지, 연동이 해당 레코드에 접근할 수 있는지 확인하세요. 설정을 바꾸기 전에 CRM 활동 내역과 테스트 로그부터 살펴보세요.

### 전화번호를 지정하기 전에 플로우를 테스트할 수 있나요?
네, 할 수 있어요. **웹 통화**를 쓰면 전화번호를 지정하지 않아도 브라우저에서 대화와 지원되는 액션을 테스트할 수 있어요.

### 운영 중인 에이전트가 전화를 받지 않아요.
지정한 전화번호, **통화 라우팅** 모드, **근무 시간**, 인바운드 통화 플로우, 착신 전환, 음성사서함 설정을 확인하세요.
