# 음성 AI 플로우 기반 빌더 시작하기

음성 AI의 **플로우 기반 빌더**는 노드를 연결하는 시각적 캔버스에서 AI 통화 환경을 설계하는 도구예요. 여러 AI 에이전트를 연결하고, 발신자가 원하는 내용에 따라 대화를 나누고, 작업과 연동으로 업무를 자동화할 수 있어요. 에이전트 프롬프트 하나에 의존하지 않고도 복잡한 대화를 더 쉽게 만들고 관리할 수 있어요.

{% hint style="info" %}
이 문서는 음성 AI **플로우 기반 빌더**의 주요 기능, 사용할 수 있는 노드, 연동을 간략히 소개해요. 음성 AI 플로우를 만들고, 설정하고, 테스트하고, 배포하는 단계별 방법은 "플로우 기반 빌더로 음성 AI 플로우 만들고 설정하는 방법" 문서를 참고하세요.
{% endhint %}

---

## 음성 AI 플로우 기반 빌더란?

**플로우 기반 빌더**는 연결된 노드로 구조화된 음성 AI 대화를 만드는 시각적 도구예요. 노드는 각각 하나의 역할을 맡아요. 예를 들어 발신자와 대화하거나, 대화 경로를 고르거나, 작업을 실행해요.

기존 프롬프트 기반 빌더와 달리, 플로우 하나 안에서 여러 AI 에이전트에게 서로 다른 역할을 맡길 수 있어요.

예를 들어 통화가 인사 에이전트 → 자격 검증 에이전트 → 예약 에이전트 순서로 이어지고, 에이전트마다 대화의 다른 단계를 맡을 수 있어요.

---

## 플로우 기반 빌더의 주요 장점

**플로우 기반 빌더**를 쓰면 대화를 작고 관리하기 쉬운 단계로 나눌 수 있어요. 그래서 통화를 처리하는 방식과 에이전트가 일하는 방식을 더 세밀하게 조절할 수 있어요.

- 시각적 플로우 설계: 하나의 캔버스에서 노드를 연결해 대화를 만들고 관리해요.
- 멀티 에이전트 대화: 에이전트마다 다른 프롬프트, AI 모델, 도구를 지정할 수 있어요.
- 유연한 라우팅: 발신자가 원하는 내용에 따라 서로 다른 대화 경로로 안내해요.
- 작업 자동화: 메시지를 보내고, API와 연동하고, 지원되는 CRM 작업을 수행해요.
- MCP 연동: 연락처, 캘린더, 예약 등 지원되는 작업을 관리하는 도구에 에이전트를 연결해요.
- 기본 제공 테스트: 배포 전에 **Web Call**(웹 통화) 또는 **Phone Call**(전화 통화)로 대화를 테스트해요.

---

## 플로우 기반 빌더 화면 살펴보기

빌더는 대화를 설계하고, 각 구성 요소를 설정하고, 서로 어떻게 작동하는지 테스트하는 시각적 작업 공간이에요. 프롬프트 하나로 모든 것을 관리하지 않고 이 영역들로 플로우를 정리할 수 있어요.

- **캔버스**: 노드를 추가하고, 연결하고, 배치하는 작업 공간이에요.
- **Node Library**(노드 라이브러리): 사용할 수 있는 AI 에이전트, 라우팅 제어, 작업, 연동이 모여 있어요.
- **Node Configuration**(노드 설정): 각 노드에서 지원하는 설정을 바꿀 수 있어요.
- **Build and Deploy**(빌드 및 배포): 플로우 편집과 배포 설정으로 이동해요.
- **에이전트 테스트하기**: **Web Call** 또는 **Phone Call**로 대화를 테스트해요.

## 플로우 기반 빌더의 노드 종류

노드는 대화가 어떻게 시작되고, 진행되고, 끝나는지를 정해요. 대화 노드, 라우팅 노드, 작업 노드를 조합하면 비즈니스에 맞는 통화 환경을 만들 수 있어요.

| 노드 | 용도 |
| --- | --- |
| **Start Call**(통화 시작) | 대화가 시작되는 지점이에요. |
| **AI 에이전트** | 자체 프롬프트, 모델, 지정된 도구로 대화를 처리해요. |
| **라우터** | 설정한 라우팅 로직에 따라 대화를 서로 다른 경로로 보내요. |
| **통화 종료** | 대화 경로를 마무리해요. |
| **지식 베이스 검색** | 연결된 지식 자료에서 정보를 가져와요. |
| **Search the Web**(웹 검색) | 지원되는 용도에서 웹 정보를 가져와요. |
| **MCP 서버** | 에이전트를 외부 도구와 하이퍼클래스에서 지원하는 작업에 연결해요. |
| **작업** | SMS 보내기, 이메일 보내기, Custom API 요청 같은 작업을 수행해요. |

새로운 음성 AI 기능이 추가되면서 사용할 수 있는 노드와 작업이 달라질 수 있어요.

## 멀티 에이전트 플로우

멀티 에이전트 플로우에서는 여러 **AI 에이전트** 노드가 하나의 대화에서 함께 일해요. 에이전트마다 자체 프롬프트, 모델, 도구, 역할을 가질 수 있고, **라우터** 노드가 대화가 어느 경로로 갈지 정해요.

자주 쓰는 사례는 다음과 같아요.

- 리드 자격 검증: 인사 → 자격 검증 에이전트 → CRM 업데이트
- 예약 일정 잡기: 인사 → 예약 에이전트 → 캘린더 연동
- 고객 지원: 인사 → 라우터 → 지원 상담원

이렇게 하면 에이전트별 지침을 간결하게 유지하면서 더 복잡한 통화 환경도 만들 수 있어요.

## 기본 제공 작업, Custom API, MCP 연동

작업과 연동을 쓰면 음성 AI가 질문에 답하는 데서 그치지 않고 더 많은 일을 할 수 있어요. 에이전트가 대화 중에 연락처와 상호작용하고, 메시지를 보내고, 정보를 가져오고, 지원되는 작업을 처리해요.

### 1. 기본 제공 작업

빌더 안에 기본으로 들어 있어서 바로 설정해 쓸 수 있는 작업이에요. 처음 출시했을 때는 다음 작업이 포함되었어요.

- **Send SMS**(SMS 보내기)
- **Send Email**(이메일 보내기)
- **Custom API**(커스텀 API)

출시 이후에 음성 AI 작업이 더 추가되었어요. **플로우 기반 빌더**에서 지원하는 작업은 현재 **작업** 목록에서 확인하세요.

### 2. Custom API

**Custom API**를 쓰면 에이전트가 API 요청으로 외부 시스템과 통신할 수 있어요. 필요한 작업이 기본 제공 작업에 없을 때 유용해요.

### 3. MCP 서버

Model Context Protocol(MCP) 연동은 에이전트를 지원되는 도구와 서비스에 연결해요. 다음과 같은 작업을 할 수 있어요.

- 연락처 및 CRM 레코드
- 캘린더 및 예약 가능 시간
- 예약 생성
- 하이퍼클래스에서 지원하는 기타 기능

예를 들어 연락처 정보는 지원되는 기본 제공 작업이 있으면 그것으로 업데이트할 수 있고, 없으면 MCP나 **Custom API** 연동으로 업데이트할 수 있어요.

MCP와 **Custom API** 연동은 추가 인증과 설정이 필요할 수 있어요.

고급 설정 방법은 [음성 AI 에이전트용 Model Context Protocol(MCP) 연동](model-context-protocol-mcp-integration-for-voice-ai-agents.md)을 참고하세요.

## 음성 AI 설정과 지원 기능

**플로우 기반 빌더**에는 에이전트가 발신자와 소통하는 방식을 조절하는 기본 음성 AI 설정이 들어 있어요. 플로우 구조는 그대로 두고 통화 환경만 원하는 대로 바꿀 수 있어요.

지원하는 기능은 다음과 같아요.

- 인바운드 및 아웃바운드 통화
- 음성 및 언어 선택
- 인바운드 및 아웃바운드 환영 메시지
- 통화 설정 및 노이즈 캔슬링
- 음성 기록 및 번역
- 통화 후 설정
- 아웃바운드 컴플라이언스 설정
- **Web Call** 및 **Phone Call** 테스트

## 플로우 기반 빌더 열기

새 음성 AI 에이전트를 만들 때 시각적 빌더를 열 수 있어요. **플로우 기반 빌더**를 선택하면 대화 설계를 시작할 수 있는 캔버스가 열려요.

1. 하이퍼클래스 서브 계정에서 **AI 에이전트 > 음성 AI**로 이동하세요.
2. **에이전트 목록**을 열고 **+ 에이전트 만들기**를 클릭하세요.
3. **플로우 기반 빌더**를 선택하세요.
4. **계속**을 클릭하면 빌더가 열려요.

![플로우 기반 빌더 선택 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083206779/original/fcY7rWoRPFrLgzTj4Gh1_XaQsTjE8937ww.png?1791898162)

새 플로우는 **Start Call** 노드와 연결된 **AI 에이전트** 노드로 시작해요. 작업 내용을 유지하려면 에이전트를 **저장**하세요.

노드 추가, 라우팅 설정, 연동 설정, 플로우 배포에 대한 자세한 방법은 "플로우 기반 빌더로 음성 AI 플로우 만들고 설정하는 방법" 문서를 참고하세요.

## 자주 묻는 질문

### AI 에이전트 노드마다 다른 AI 모델을 쓸 수 있나요?
네. **AI 에이전트** 노드마다 지원되는 AI 모델, 프롬프트, 도구를 따로 지정할 수 있어요.

### 플로우 기반 빌더를 쓰려면 MCP가 꼭 필요한가요?
아니요. MCP 없이도 **AI 에이전트** 노드, 라우터, 기본 제공 작업으로 대화를 만들 수 있어요. 플로우에 지원되는 외부 도구나 추가 연동이 필요할 때 MCP를 쓰세요.

### 플로우 기반 음성 AI 에이전트도 스냅샷에 포함할 수 있나요?
네. 플로우 기반 음성 AI 에이전트를 스냅샷에 포함할 수 있어요. 그러면 지원되는 플로우 설정을 여러 서브 계정에서 다시 사용할 수 있어요. 전화번호와 실시간 통화 데이터는 옮겨지지 않아요. 자세한 내용은 [플로우 기반 음성 AI 에이전트의 스냅샷 지원](../../29-스냅샷/snapshot-support-for-flow-based-voice-ai-agents.md)을 참고하세요.

### 플로우 기반 빌더로 만든 에이전트가 예약을 잡을 수 있나요?
설정한 연동이나 사용 가능한 기본 제공 작업으로 예약을 지원할 수 있어요. 설정 방법은 빌더에서 사용할 수 있는 기능에 따라 달라요.

### 플로우 기반 빌더로 아웃바운드 통화도 할 수 있나요?
네. **플로우 기반 빌더**는 인바운드와 아웃바운드 통화를 모두 지원해요. 단, 해당 설정과 아웃바운드 컴플라이언스 요건을 따라야 해요.

### 멀티 에이전트 플로우와 에이전트 전환은 같은 건가요?
아니요. 멀티 에이전트 플로우는 하나의 시각적 대화 안에서 **AI 에이전트** 노드를 연결해요. **에이전트 전환**은 진행 중인 실시간 대화를 다른 음성 AI 에이전트에게 넘기는 별도 기능이에요.
