# AI 스튜디오 Cloud 백엔드

Cloud는 AI 스튜디오 앱에 기본으로 붙는 백엔드예요. 별도 백엔드 서비스를 연결하지 않아도 데이터를 저장하고, 앱 사용자 계정을 관리하고, 파일 업로드를 처리할 수 있어요. 이 문서에서는 Cloud를 켜는 방법과 데이터베이스, 인증, 저장 공간, 보안, 고급 설정을 관리하는 방법을 안내해요.

---

## AI 스튜디오의 Cloud란?

Cloud는 하이퍼클래스 AI 스튜디오로 만든 앱을 위한 관리형 백엔드예요. 정보를 저장하는 데이터베이스, 앱 사용자를 관리하는 인증, 이미지나 문서 같은 업로드 파일을 보관하는 파일 저장소를 제공해요.

Cloud는 프로젝트마다 따로 만들어지고 AI 스튜디오 빌더에서 관리해요. 저장된 정보를 확인하고, 접근 권한을 설정하고, 리소스를 관리할 수 있어요. 별도 백엔드를 설정하지 않아도 AI 스튜디오에 데이터베이스 테이블이나 정책을 만들어 달라고 요청할 수 있어요.

AI 스튜디오는 Cloud를 쓰는 기능을 만들기 전에 먼저 확인을 요청해요.

---

## AI 스튜디오에서 Cloud 켜기

AI 스튜디오 프로젝트에서 바로 Cloud를 켤 수 있어요. 켜면 하이퍼클래스가 앱에 필요한 백엔드 서비스를 준비해요. 보통 1분 정도 걸려요.

{% hint style="info" %}
사전 조건: Cloud는 TanStack Start로 만든 프로젝트를 지원해요. 기존 React 프로젝트가 있다면 먼저 **Project Settings > Migrate to SSR**(프로젝트 설정 > SSR로 이전)로 이동하세요. 이전하면 업그레이드된 사본이 만들어지고, 원래 운영 중인 프로젝트는 그대로 유지돼요. 이전한 뒤에 Cloud를 따로 켜야 해요.
{% endhint %}

1. 계정에 로그인하세요.
2. 왼쪽 메뉴에서 **AI 스튜디오**를 선택하세요.
3. 만들 앱을 설명하는 프롬프트를 입력해 새 프로젝트를 만들거나, 기존 프로젝트를 여세요.
4. 프로젝트가 준비되면 AI 스튜디오 빌더에서 **더보기 > Cloud**를 클릭하세요.
5. **개요**를 열고 **Enable Cloud**(Cloud 켜기)를 클릭하세요.
6. Cloud 준비가 끝날 때까지 기다리세요. 설정이 진행되는 동안에도 프로젝트 작업을 계속할 수 있어요.
7. 연결이 끝나면 Cloud 대시보드에 **Database**(데이터베이스), **사용자**, **저장 공간**, **Secrets**(시크릿) 옵션이 나타나요.

{% hint style="info" %}
Cloud 설정에 실패해도 기존 앱은 그대로예요. **다시 시도**를 클릭하면 설정을 이어서 진행해요.
{% endhint %}

## Cloud 개요 대시보드

Cloud 개요 대시보드에서는 프로젝트 백엔드의 상태를 한곳에서 확인하고 각 서비스로 이동할 수 있어요. 현재 연결 상태, 데이터베이스 인스턴스, 리소스 사용량이 표시되어 백엔드 상태를 빠르게 점검할 수 있어요.

Cloud를 켠 뒤 **Cloud > 개요**로 이동하면 다음을 볼 수 있어요.

- **Connection Status**(연결 상태): Cloud 인스턴스가 연결되어 있는지 보여 줘요.
- **Database**: 기존 테이블과 각 테이블의 레코드 수를 보여 줘요.
- **사용자**: 가입한 사용자 수와 인증 설정을 보여 줘요.
- **저장 공간**: 앱에서 사용하는 스토리지 버킷을 보여 줘요.
- **Secrets**: 프로젝트의 Secrets 영역으로 연결해 줘요.

섹션을 클릭하면 상세 관리 페이지로 이동해요.

## 데이터베이스

Database 기능은 사용자 프로필, 주문 같은 앱의 정형 데이터를 저장해요. 앱이 저장한 정보를 관리할 수 있고, 행 수준 보안(RLS) 정책으로 사용자가 접근할 수 있는 레코드를 제어할 수 있어요.

데이터베이스를 관리하려면 **Cloud > Database**로 이동하세요.

#### 데이터베이스 최적화

Database 페이지에서 **Optimize**(최적화)를 클릭하면 데이터베이스 상태 점검 요청이 AI 스튜디오 채팅으로 전달돼요. 성능이나 효율을 개선할 부분을 찾는 데 도움이 돼요.

{% hint style="info" %}
데이터베이스 최적화도 다른 채팅 요청처럼 AI 스튜디오 크레딧을 사용해요.
{% endhint %}

#### 데이터베이스 테이블과 레코드 관리

Database 페이지에는 프로젝트의 public 스키마에 있는 테이블, 대략적인 행 개수, RLS 정책 상태가 표시돼요.

- 레코드 보기: 테이블을 선택하면 데이터가 열려요.
- **레코드 추가**: 테이블을 열고 새 행을 추가해요.
- 레코드 수정: 셀을 더블 클릭해 값을 바꿔요.
- 레코드 삭제: 지울 행을 선택한 뒤 삭제해요.
- 스키마 변경: 채팅에서 AI 스튜디오에 테이블이나 정책을 만들거나 바꿔 달라고 요청하세요. 스키마 변경은 데이터베이스 브라우저에서 직접 고치지 않고 AI 스튜디오를 통해 처리해요.

#### 행 수준 보안(RLS) 정책 관리

RLS 정책은 사용자별로 접근하거나 수정할 수 있는 데이터베이스 레코드를 제어해요. 예를 들어 로그인한 사용자가 자기 주문만 보거나 수정하도록 정책을 만들 수 있어요.

1. **Cloud > Database**를 여세요.
2. **RLS policies**(RLS 정책)를 클릭하세요.
3. 테이블별 정책을 확인하세요. 정책 이름, 명령, 적용 대상 사용자 역할, 규칙 표현식이 표시돼요.
4. 정책을 바꾸려면 필요한 접근 방식을 채팅에서 AI 스튜디오에 설명하세요.

#### 데이터베이스 백업 관리

Cloud는 데이터베이스 스키마와 레코드를 매일 자동으로 백업해요.

1. **Cloud > Database > 백업**으로 이동하세요.
2. 사용할 수 있는 데이터베이스 스냅샷을 확인하세요.
3. 이전 데이터베이스 상태로 되돌려야 할 때는 스냅샷을 선택하고 **복원**을 클릭하세요.

{% hint style="warning" %}
백업을 복원하면 현재 운영 중인 데이터베이스가 선택한 스냅샷으로 교체돼요. 복원하는 몇 분 동안은 데이터베이스 접근이 일시적으로 중단돼요. 백업에는 업로드한 저장소 파일과 앱 코드가 포함되지 않아요. 복원한 스키마가 앱과 맞지 않으면 AI 스튜디오에 코드를 업데이트해 달라고 요청하세요.
{% endhint %}

![데이터베이스 백업 복원 과정을 보여 주는 화면 녹화](https://jumpshare.com/share/IIIXNcPSJsFSh2m34Pov+/GIF+Recording+2026-10-09+at+20.13.41.gif)

## 사용자와 인증

Cloud에는 사용자 관리와 인증 설정이 들어 있어서 사람들이 앱에 접근하는 방식을 제어할 수 있어요. 가입 현황을 확인하고, 개별 계정을 관리하고, 로그인과 비밀번호 보안 요건을 설정할 수 있어요.

#### 앱 사용자 관리

**Cloud > 사용자**로 이동하면 사용자 관리 대시보드가 열려요.

- 가입 현황 확인: Signups 차트와 기간 필터로 가입 활동을 확인해요.
- **사용자 검색**: 이메일 주소로 가입한 사용자를 찾아요.
- **사용자 추가**: 클릭하면 이메일을 보내지 않고 이미 인증된 계정을 만들어요.
- 사용자 초대: **초대 보내기**를 사용하면 사용자에게 비밀번호를 설정할 수 있는 링크를 이메일로 보내요.
- 사용자 상세 정보 보기: 사용자를 선택하면 로그인 방법과 계정 정보를 확인할 수 있어요.
- 사용자 삭제: 사용자 계정을 열고 **Delete user**(사용자 삭제)를 선택하면 계정이 영구적으로 삭제돼요.

  ![사용자 관리 대시보드 화면](https://jumpshare.com/share/XLTo5fwkWhs3Iv7hOsku+/image+%286%29+%281%29.png)

#### 인증 설정 구성

**Cloud > 사용자 > Auth settings**(인증 설정)에서 사용자가 로그인하고 가입하는 방식을 제어해요.

| 설정 | 기능 |
| --- | --- |
| **Sign-in methods**(로그인 방법) | 지원하는 인증 방법을 설정해요. 출시 초기에는 이메일과 비밀번호 방식을 지원해요. |
| **Allow new sign-ups**(신규 가입 허용) | 이미 로그인한 사용자는 로그아웃시키지 않고 신규 가입을 켜거나 꺼요. |
| **Anonymous users**(익명 사용자) | 켜면 익명 사용자 인증을 허용해요. |
| **고급** | 추가 인증 설정 옵션을 열어요. |

![인증 설정 화면 녹화](https://jumpshare.com/share/4MO5tTLLFpB9v8Ey5qHA+/GIF+Recording+2026-10-09+at+20.19.31.gif)

#### 이메일·비밀번호 보안 설정

**Auth settings > 이메일**에서 다음 옵션을 설정할 수 있어요.

- **Minimum password length**(최소 비밀번호 길이): 필요한 비밀번호 길이를 정해요. 최소 6자이고, 8자 이상을 권장해요.
- **Required password characters**(필수 비밀번호 문자): 비밀번호에 꼭 포함해야 하는 문자 종류를 정해요.
- **Check against known breaches**(유출 이력 확인): 공개적으로 알려진 데이터 유출에서 발견된 비밀번호는 거부해요.
- **Re-authenticate to change password**(비밀번호 변경 시 재인증): 새 비밀번호를 설정하기 전에 현재 비밀번호를 입력하도록 해요.
- **Auto-confirm email**(이메일 자동 인증): 테스트 용도로만 이메일 인증을 건너뛰어요.
- **Secure email change**(안전한 이메일 변경): 기존 이메일 주소와 새 이메일 주소 양쪽에서 모두 확인을 받도록 해요.
- **고급**: 사용할 수 있는 일회용 코드의 만료 시간과 길이를 설정해요.

{% hint style="warning" %}
이메일 인증은 기본으로 필수예요. 운영 중인 앱에서는 **Auto-confirm email**을 꺼 두세요.
{% endhint %}

![이메일·비밀번호 보안 설정 화면 녹화](https://jumpshare.com/share/Or6fqH0DZhMdArpYDdut+/GIF+Recording+2026-10-09+at+20.22.30.gif)

#### 인증 URL 설정

인증 URL은 로그인, 가입, 계정 복구 중에 사용자가 이동할 위치를 정해요.

- **사이트 URL**: 앱의 기본 URL을 설정해요.
- **Redirect URLs**(리디렉션 URL): 인증이 끝난 뒤 사용자가 돌아올 수 있는 URL을 추가해요. `myapp://callback` 같은 모바일 딥링크도 지원해요.

미리보기 URL은 AI 스튜디오가 자동으로 처리해요. 설정한 URL이 실제 앱 URL과 다르면 인증이 실패할 수 있으니 서로 맞는지 확인하세요.

## 저장 공간

Cloud 저장 공간은 앱에서 업로드하고 사용하는 이미지, 문서 같은 파일을 관리해요. 파일은 버킷 단위로 정리되고, 버킷의 공개 범위와 행 수준 보안 정책으로 접근을 제어해요.

#### 스토리지 버킷 만들기와 관리

1. **Cloud > 저장 공간**으로 이동하세요.
2. **New bucket**(새 버킷)을 클릭하세요.
3. 버킷 이름을 입력하세요. 3~63자이고, 영문 소문자, 숫자, 하이픈을 쓸 수 있어요.
4. 버킷의 공개 범위를 선택하세요.

   - **공개**: 파일 링크를 아는 사람은 누구나 파일에 접근할 수 있어요.
   - **비공개**: 접근 정책에 따라 로그인한 사용자만 파일에 접근할 수 있어요.
5. 버킷을 만들어 파일 저장을 시작하세요.

{% hint style="info" %}
버킷 이름은 만든 뒤에 바꿀 수 없어요.
{% endhint %}

![스토리지 버킷 만들기 화면 녹화](https://jumpshare.com/share/QcUof19XbzX89Jughwps+/GIF+Recording+2026-10-09+at+20.25.28.gif)

#### 파일 관리

기존 버킷을 열면 다음 작업을 할 수 있어요.

- **파일 업로드**로 파일과 미디어를 올려요.
- 폴더를 만들어 저장한 파일을 정리해요.
- 파일을 다운로드하거나 삭제해요.
- 파일 이름을 바꿔요.
- 앱에서 쓸 수 있도록 파일 URL을 복사해요.

{% hint style="warning" %}
파일 이름을 바꾸면 URL도 바뀌어요. 이전 URL을 쓰고 있는 곳이 있다면 모두 업데이트하세요.
{% endhint %}

![파일 관리 화면 녹화](https://jumpshare.com/share/IwD0LTFTxcqqFQcgTvQt+/GIF+Recording+2026-10-09+at+20.27.12.gif)

#### 업로드 제한과 접근 설정

**저장 공간** 페이지에서 다음 작업을 할 수 있어요.

- **Upload size limit**(업로드 크기 제한)으로 버킷이 받을 수 있는 가장 큰 파일 크기를 정해요. 기본값은 2GB이고 최대 5GB예요.
- 제한을 바꾼 뒤에는 **저장**을 클릭하세요.
- **RLS policies**를 열면 저장 공간 접근을 제어하는 규칙을 확인할 수 있어요.

![업로드 제한 설정 화면 녹화](https://jumpshare.com/share/oUwMX7WmM9ceBbqPsb02+/GIF+Recording+2026-10-09+at+20.28.21.gif)

## 고급 설정

**고급 설정**에서는 Cloud 백엔드에 할당된 리소스를 제어해요. 데이터베이스 용량을 늘리거나, 저장 공간을 관리하거나, 쓰지 않는 리소스를 일시정지하거나, 프로젝트에서 Cloud를 완전히 제거할 수 있어요.

**Cloud > 개요 > 고급 설정**으로 이동하세요.

#### 데이터베이스 크기 관리

Cloud는 무료 **Tiny** 데이터베이스 인스턴스로 시작해요. 앱에 필요한 리소스에 맞춰 인스턴스 크기를 바꿀 수 있어요.

선택할 수 있는 크기는 다음과 같아요.

- **Tiny**
- **Mini**
- **Small**
- **Medium**
- **Large**
- **X-Large**

**Database size**(데이터베이스 크기) 옆의 **관리**를 클릭하면 선택할 수 있는 옵션과 시간당 요금을 확인할 수 있어요.

데이터베이스 크기는 1시간에 한 번 늘리거나 줄일 수 있어요. 변경하는 데 몇 분이 걸리고, 그동안 앱이 잠시 다시 시작돼요.

#### 데이터베이스 저장 용량 관리

**Database storage**(데이터베이스 저장 용량) 옆의 **관리**를 클릭하면 할당된 데이터베이스 공간을 늘릴 수 있어요.

- 데이터베이스 저장 용량은 하루에 최대 네 번까지 늘릴 수 있어요.
- 할당된 데이터베이스 저장 용량은 줄일 수 없어요.
- 요금은 할당된 공간 기준으로 부과되고, Cloud를 일시정지해도 계속 부과돼요.

파일 저장 공간은 요금 방식이 달라요. 저장한 파일에 따라 사용량이 늘거나 줄고, 실제로 저장한 양을 기준으로 요금이 부과돼요.

#### Cloud 일시정지와 다시 켜기

**Pause Cloud**(Cloud 일시정지) 아래의 **일시정지**를 클릭하면 데이터는 그대로 두고 Cloud 백엔드 접근을 멈춰요.

일시정지한 Cloud 인스턴스를 다시 켜려면 프로젝트의 **Cloud** 탭을 열고 **Wake up**(깨우기)을 클릭하세요.

지갑 잔액이 Cloud 요금을 내기에 부족하면 데이터는 삭제되지 않은 채 Cloud가 자동으로 일시정지될 수 있어요. 지갑 잔액이 다시 충분해지면 Cloud가 자동으로 켜져요. 다만 시간이 좀 걸릴 수 있어요.

자동 복구를 기다리지 않고 프로젝트의 **Cloud** 탭에서 **Wake up**을 클릭해 바로 접근을 복구할 수도 있어요.

#### Cloud 제거

**Remove Cloud**(Cloud 제거) 아래의 **제거**를 클릭하면 프로젝트의 Cloud 백엔드가 영구적으로 삭제돼요.

{% hint style="warning" %}
Cloud를 제거하면 프로젝트의 데이터베이스, 사용자, 저장한 파일이 영구적으로 삭제돼요. 제거하기 전에 데이터베이스 테이블을 CSV 파일로 내보내고, 필요한 파일은 미리 다운로드하세요. 다른 AI 스튜디오 프로젝트에는 영향이 없어요.
{% endhint %}

## 자주 묻는 질문

### Cloud를 켜면 이미 게시한 앱도 자동으로 업데이트되나요?

아니요. 기존에 게시한 앱은 업데이트된 프로젝트를 다시 게시하기 전까지 그대로예요.

### AI 스튜디오 프로젝트를 공유하거나 리믹스하면 Cloud 데이터는 어떻게 되나요?

AI 스튜디오 프로젝트를 공유하거나 리믹스하면 사본은 원본 프로젝트의 Cloud 백엔드와 연결이 끊어지고, 원본으로 요청을 보내지 않아요. 사본에서 Cloud를 켜면 같은 데이터베이스 테이블 구조로 새 백엔드가 만들어져요. 원본 프로젝트의 레코드, 사용자, 파일은 들어 있지 않아요.

### 하이퍼클래스 CRM과 연결한 AI 스튜디오 폼의 제출 내용도 Cloud에 자동으로 저장되나요?

아니요. 하이퍼클래스 CRM과 연결한 AI 스튜디오 폼의 제출 내용은 연결된 서브 계정의 CRM으로 전송돼요. Cloud 데이터베이스 저장 기능은 별개예요.

### 인증 이메일은 어디에서 발송되나요?

가입 확인, 초대, 비밀번호 재설정 이메일은 계정에 설정된 이메일 구성으로 발송돼요. 이메일 안의 링크를 누르면 사용자가 앱으로 돌아와요.
