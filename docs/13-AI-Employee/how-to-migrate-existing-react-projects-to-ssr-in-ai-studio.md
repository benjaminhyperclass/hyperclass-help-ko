# AI 스튜디오에서 기존 React 프로젝트를 SSR로 마이그레이션하기

하이퍼클래스 **AI 스튜디오**(AI Studio)의 기존 React 프로젝트를 TanStack Start 기반의 서버 사이드 렌더링(SSR) 구조로 옮기는 방법을 안내해요. 마이그레이션 진행 상황을 확인하는 방법과 새 프로젝트를 게시하기 전에 점검할 내용도 함께 설명해요.

**Migrate to SSR**(SSR로 마이그레이션) 기능은 프로젝트의 복사본을 따로 만들어요. 그래서 이미 게시한 웹사이트에는 영향을 주지 않고, 복사본에 서버 함수, 보안 시크릿 같은 백엔드 기능을 추가할 수 있어요.

마이그레이션하는 동안에도 원래 프로젝트, 연결된 도메인, **버전 기록**은 그대로 유지돼요.

## Migrate to SSR이란?

**Migrate to SSR**은 기존 React/Vite 프로젝트를 TanStack Start 구조로 바꿔 주는 고급 기능이에요. AI 스튜디오는 원래 프로젝트를 직접 수정하지 않고, 별도의 초안을 만든 뒤 AI 에이전트가 변환을 진행해요. 덕분에 기존 웹사이트는 그대로 운영하면서 풀스택 기능을 써 볼 수 있어요.

서버 사이드 렌더링(SSR)은 방문자의 브라우저로 보내기 전에 서버에서 페이지 HTML을 만들어 두는 방식이에요. TanStack Start는 서버 함수, REST API, 시크릿도 지원해요. 그래서 백엔드 작업과 민감한 인증 정보를 브라우저 코드 밖에서 처리할 수 있어요.

다음과 같은 기능이 필요한 기존 프로젝트에 특히 유용해요.

- 서버 사이드 렌더링: 공개 페이지와 콘텐츠의 HTML을 서버에서 만들어요.
- 서버 함수: 구현 내용을 브라우저에 노출하지 않고 백엔드 로직을 실행해요.
- REST API: 연동, 웹훅, 외부 서비스를 위한 HTTP 엔드포인트를 만들어요.
- 시크릿: API 키, 인증 토큰 등 민감한 값을 저장해 서버 쪽 기능에서 사용해요.

마이그레이션은 선택 사항이에요. 이런 기능이 필요 없는 기존 React 프로젝트는 지금 구조 그대로 계속 쓸 수 있어요.

이 기능들에 대한 자세한 설명은 [AI 스튜디오: SSR, 서버 함수, REST API, 시크릿](ai-studio-ssr-server-functions-rest-apis-and-secrets.md)을 참고하세요.

## Migrate to SSR의 장점

기존 React 프로젝트를 SSR로 옮기면 풀스택 기능을 쓸 수 있고, 게시 중인 애플리케이션을 바꿀 때의 위험도 줄일 수 있어요. AI 스튜디오가 별도 프로젝트를 만들어 주기 때문에, 변환된 결과를 먼저 확인한 뒤 게시할지, 기존 도메인을 연결할지 정할 수 있어요.

- 게시한 웹사이트 유지: 마이그레이션하는 동안 원래 React 프로젝트, 운영 중인 웹사이트, 연결된 도메인이 그대로 유지돼요.
- 서버 기능 사용: TanStack Start 구조에서 SSR, 서버 함수, REST API, 시크릿을 쓸 수 있어요.
- 처음부터 다시 만들 필요 없음: 기존 프로젝트의 페이지를 새 초안으로 가져오기 때문에 앱 전체를 직접 다시 만들지 않아도 돼요.
- AI의 도움: AI 스튜디오 에이전트가 프로젝트를 분석하고, 채팅으로 프레임워크 변환을 진행해요.
- 게시 전 테스트: 운영 중인 웹사이트를 바꾸기 전에 마이그레이션된 프로젝트를 따로 확인할 수 있어요.
- 기존 프로젝트 기록 보존: 이전 버전은 원래 프로젝트에 남고, 마이그레이션된 복사본은 새로 시작해요.
- 전환 시점 선택: 준비가 되었을 때 새 프로젝트를 게시하거나 도메인을 옮기면 돼요.

## 마이그레이션 조건

마이그레이션은 더 새로운 TanStack Start 구조가 필요한 기존 React/Vite 프로젝트를 위한 기능이에요. 조건을 먼저 확인하면 마이그레이션할 수 있는지 알 수 있고, 이미 서버 기능을 지원하는 프로젝트를 불필요하게 바꾸는 일도 피할 수 있어요.

다음 조건을 모두 충족하면 **Migrate to SSR** 옵션을 쓸 수 있어요.

- 프로젝트가 기존 React/Vite 구조를 사용해요.
- 프로젝트를 편집할 권한이 있어요.
- 프로젝트 설정에서 마이그레이션 기능에 접근해요.

이 옵션은 **Project Settings**(프로젝트 설정)에서 **고급**으로 표시돼요.

## 원래 프로젝트는 어떻게 되나요?

AI 스튜디오는 기존 웹사이트를 보호하기 위해 마이그레이션과 게시를 분리해요. 마이그레이션을 시작하면 운영 중인 프로젝트를 직접 변환하지 않고, 원래 프로젝트 옆에 새 프로젝트를 만들어요. 무엇이 원래 프로젝트에 남고 무엇이 복사본으로 옮겨지는지 알아 두면 안전하게 전환을 계획할 수 있어요.

마이그레이션을 시작하면 다음 순서로 진행돼요.

1. AI 스튜디오가 같은 서브 계정 안에 새 프로젝트를 만들어요.
2. 원래 프로젝트의 페이지가 새 프로젝트로 복사돼요.
3. AI 스튜디오가 `{project name} (TanStack)`이라는 이름을 제안해요. 복사본을 만들기 전에 이름을 바꿀 수 있어요.
4. 새 프로젝트는 초안 상태로 시작하고, 자동으로 게시되지 않아요.
5. 원래 프로젝트는 기존 **버전 기록**을 그대로 유지해요.
6. 새 프로젝트는 별도의 AI 스튜디오 채팅으로 시작해요.
7. 원래 게시된 사이트와 연결된 도메인은 그대로 유지돼요.

두 프로젝트의 차이는 아래 표와 같아요.

| 프로젝트 구성 요소 | 원래 React 프로젝트 | 마이그레이션된 프로젝트 |
| --- | --- | --- |
| 구조 | React/Vite 유지 | TanStack Start로 변환 |
| 프로젝트 페이지 | 그대로 유지 | 새 프로젝트로 복사 |
| 프로젝트 이름 | 변경 없음 | 마이그레이션 전에 직접 지정 가능 |
| 게시 상태 | 변경 없음 | 초안으로 시작 |
| 연결된 도메인 | 계속 연결됨 | 자동으로 옮겨지지 않음 |
| 버전 기록 | 유지 | 별도로 새로 시작 |
| AI 스튜디오 채팅 | 기존 채팅 유지 | 새 채팅으로 시작 |
| 워크플로우 연결 | 기존 연결 유지 | 검토하고 필요한 부분은 업데이트해야 함 |

{% hint style="warning" %}
SSR로 마이그레이션해도 게시된 사이트가 자동으로 바뀌거나 커스텀 도메인이 옮겨지지 않아요. 변환된 프로젝트를 게시하는 것과 기존 도메인을 옮기는 것은 별개의 작업이에요. 마이그레이션된 프로젝트를 쓰지 않기로 해도 원래 React 프로젝트는 그대로 남아 있어요.
{% endhint %}

## 마이그레이션 상태와 사용할 수 있는 기능

에이전트가 복사된 애플리케이션을 TanStack Start로 변환하는 동안에는 일부 프로젝트 기능을 잠시 쓸 수 없어요. 업그레이드 중 변경 사항이 서로 충돌하는 것을 막기 위해서예요. 그래도 채팅으로 진행 상황을 확인하고 마이그레이션에 대해 대화할 수는 있어요.

마이그레이션이 시작되면 새 프로젝트의 대시보드 카드에 **Migrating to SSR**(SSR로 마이그레이션 중) 상태가 표시돼요. 이 상태에서 쓸 수 있는 기능은 다음과 같아요.

| 기능 | 마이그레이션 중 사용 가능 여부 |
| --- | --- |
| 프로젝트 **미리보기** | 사용 가능 |
| AI 스튜디오 채팅 사용 | 사용 가능 |
| 마이그레이션된 프로젝트 삭제 | 사용 가능 |
| 프로젝트 게시 | 사용 불가 |
| 코드 변경 저장 | 사용 불가 |
| 이전 버전 복원 | 사용 불가 |
| 도메인 설정 변경 | 사용 불가 |
| 슬러그 변경 | 사용 불가 |
| 프로젝트 리믹스 | 사용 불가 |

이 제한은 마이그레이션이 끝나기 전까지 복사본에만 적용돼요. 원래 프로젝트는 바뀌지 않아요.

#### 마이그레이션 완료

마이그레이션이 정상적으로 끝나면 **Migrating to SSR** 상태가 사라지고, 새 프로젝트는 일반 TanStack Start 애플리케이션이 돼요.

#### 마이그레이션이 중간에 멈춘 경우

마이그레이션이 완료되기 전에 멈추면 마이그레이션 상태가 계속 표시돼요. 이때는 마이그레이션된 프로젝트의 채팅을 열고 `continue the migration`을 입력하세요.

AI 스튜디오가 같은 복사본으로 변환을 이어서 진행해요.

{% hint style="warning" %}
원래 React 프로젝트에서 마이그레이션을 다시 시작하면 복사본이 하나 더 만들어져요. 중단된 마이그레이션을 이어 가려면 이미 만들어진 마이그레이션 프로젝트의 채팅을 사용하세요.
{% endhint %}

## 기존 React 프로젝트를 SSR로 마이그레이션하기

프로젝트 설정에서 마이그레이션하면 운영 중인 웹사이트를 멈추지 않고 기존 React 애플리케이션을 업그레이드할 수 있어요. 별도의 복사본을 만들고 AI 기반 변환을 시작하며, 게시하기 전에 결과를 확인할 수 있어요.

### 1단계. 기존 React 프로젝트 열기

1. 하이퍼클래스 계정에 로그인하세요.
2. React 프로젝트가 있는 서브 계정을 여세요.
3. **AI 스튜디오**로 이동하세요.
4. 마이그레이션할 기존 React/Vite 프로젝트를 여세요.

   ![AI 스튜디오에서 기존 React 프로젝트를 연 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083385698/original/0cSVPpMQoflw8C2Tz1cZ6cFfLSY2DxxjJg.png?1792056092)

### 2단계. 프로젝트 설정 열기

1. **Project Settings**로 이동하세요.

   ![프로젝트 설정으로 이동하는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083385443/original/_ac6BRS9nnbip72dkq_5RXhQiHRinGGv1w.png?1792055978)
2. **Migrate to SSR**을 찾으세요.

   ![프로젝트 설정에서 Migrate to SSR 항목을 찾은 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083385500/original/s0MWvHbFNpFHNE3-FQPdVC9GiAOPLt1_cw.png?1792056004)

### 3단계. 새 프로젝트 이름 확인하기

AI 스튜디오가 새로 만들 프로젝트의 이름을 확인해 달라고 안내해요.

1. 제안된 이름 `{project name} (TanStack)`을 확인하세요.
2. 다른 이름을 쓰고 싶으면 이름을 수정하세요.
3. 새 프로젝트가 원래 프로젝트와 별도로 만들어진다는 점을 확인하세요.

알아보기 쉬운 이름을 쓰면 변환된 애플리케이션과 원래 React 프로젝트를 구분하기 쉬워요.

![새 프로젝트 이름을 확인하는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083385859/original/Pf1LkU4sW1U1zmzXTwL_hY4WI1SDcM1gRw.png?1792056145)

### 4단계. 마이그레이션 안내 확인하기

변환을 시작하기 전에 AI 스튜디오가 보여 주는 마이그레이션 안내를 확인하세요. 특히 다음 내용을 눈여겨보세요.

- 새 프로젝트는 초안으로 만들어져요.
- 원래 게시된 웹사이트는 그대로 유지돼요.
- 기존 도메인은 원래 프로젝트에 계속 연결돼 있어요.
- 이전 버전은 원래 프로젝트의 기록에 남아 있어요.
- 새 프로젝트는 별도의 채팅으로 시작해요.
- 마이그레이션이 진행되는 동안에는 일부 기능을 쓸 수 없어요.

안내를 확인하고 동의하면 다음으로 넘어갈 수 있어요.

### 5단계. 마이그레이션 시작하기

1. **마이그레이션**을 클릭해 확인하세요.
2. AI 스튜디오가 같은 서브 계정 안에 새 프로젝트를 만들어요.
3. 새로 만든 프로젝트가 열려요.
4. AI 스튜디오가 프로젝트 채팅에서 변환을 시작해요.

![마이그레이션 버튼을 클릭하는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083386018/original/86FIjx6TY9jiUfocguDTeTXvkOhYwK-tvQ.png?1792056199)

### 6단계. 마이그레이션 진행 상황 확인하기

1. 마이그레이션된 프로젝트의 채팅에서 진행 상황을 확인하세요.
2. 대시보드에서 **Migrating to SSR** 상태를 확인하세요.
3. **미리보기**를 쓸 수 있게 되면 프로젝트를 살펴보세요.
4. 게시하거나 제한된 기능을 쓰기 전에 AI 기반 변환이 끝날 때까지 기다리세요.

프로젝트가 TanStack Start 애플리케이션으로 준비되면 상태가 사라져요. 변환이 끝나기 전에 멈추면 마이그레이션된 프로젝트의 채팅에 `continue the migration`을 입력하세요. 복사본을 하나 더 만들려는 것이 아니라면, 원래 프로젝트에서 마이그레이션을 다시 시작하지 마세요.

### 7단계. 완료된 프로젝트 점검하기

마이그레이션 상태가 사라진 뒤에는 다음과 같이 점검하세요.

1. 변환된 프로젝트를 여세요.
2. 페이지와 내비게이션을 **미리보기**로 확인하세요.
3. 생성된 애플리케이션에서 빠진 기능이나 의도하지 않은 변경이 없는지 살펴보세요.
4. SSR이나 서버 기능이 필요했던 기능을 테스트하세요.
5. 남은 문제는 AI 스튜디오 채팅이나 지원되는 편집 도구로 수정하세요.

{% hint style="warning" %}
마이그레이션이 끝났다고 해서 애플리케이션의 모든 부분이 이전과 똑같이 동작한다고 보장하지는 않아요. 게시하기 전에 변환된 프로젝트를 점검하고 테스트하세요.
{% endhint %}

## 폼, 캘린더, 워크플로우 연결 점검하기

프로젝트를 마이그레이션해도 원래 프로젝트의 워크플로우 트리거가 새 프로젝트로 자동 전환되지는 않아요. 마이그레이션된 웹사이트로 바꾸기 전에 기존 연동을 점검하세요.

1. 원래 애플리케이션에서 쓰는 폼과 캘린더를 확인하세요.
2. 마이그레이션된 프로젝트의 폼과 캘린더가 제대로 동작하는지 확인하세요.
3. 해당 구성 요소가 사용하는 CRM 연결을 점검하세요.
4. **자동화 > 워크플로우**로 이동하세요.
5. 원래 AI 스튜디오 프로젝트와 연결된 워크플로우를 여세요.
6. 프로젝트, 폼, 페이지 경로, 도메인에 대한 트리거 필터를 확인하세요.
7. 마이그레이션된 프로젝트로 전환할 때 해당 필터나 연결을 업데이트하세요.
8. 게시한 뒤에는 테스트 제출을 보내고, 워크플로우가 예상대로 실행되는지 확인하세요.

프로젝트별 워크플로우 트리거는 설정을 업데이트하기 전까지 원래 프로젝트와 연결된 상태로 남아 있어요.

자세한 내용은 [AI 스튜디오 폼 제출 워크플로우 트리거](ai-studio-form-submitted-workflow-trigger.md)를 참고하세요.

### 게시와 도메인 연결 점검하기

마이그레이션된 프로젝트를 게시할지는 프레임워크 변환을 마치는 것과는 별개로 결정해요.

게시하기 전에 다음을 확인하세요.

- 마이그레이션된 프로젝트가 제대로 동작하는지 확인하세요.
- 사용할 도메인이나 게시 URL을 정하세요.
- 관련된 워크플로우와 연동을 모두 확인하세요.
- 중요한 페이지 제목, 메타데이터, SEO 설정을 점검하세요.
- 운영 중인 웹사이트에 지장이 없도록 도메인 전환은 따로 계획하세요.

게시나 도메인 설정을 따로 바꾸기 전까지는 원래 웹사이트와 연결된 도메인이 그대로 유지돼요.

더 자세한 안내는 [하이퍼클래스의 AI 스튜디오](ai-studio-in-hyperclass.md)를 참고하세요.

## 자주 묻는 질문

### TanStack Start를 쓸 수 있다는 이유만으로 React 프로젝트를 마이그레이션해야 하나요?

아니요. 마이그레이션은 선택 사항이에요. 기존 React 프로젝트가 요구 사항을 충족하고 서버 사이드 렌더링이나 풀스택 기능이 필요 없다면, 마이그레이션하지 않고 계속 쓰셔도 돼요.

### 같은 원래 React 프로젝트를 여러 번 마이그레이션할 수 있나요?

네, 할 수 있어요. 원래 프로젝트에서 마이그레이션을 다시 시작하면 별도의 복사본이 하나 더 만들어져요. 중단된 변환을 마무리하려는 거라면 새 복사본을 만들지 말고 이미 만들어진 마이그레이션 프로젝트에서 이어서 진행하세요.

### 마이그레이션된 애플리케이션이 원래 웹사이트와 다르게 보여요.

**미리보기**에서 차이점을 확인하고, 마이그레이션 후에 AI 스튜디오 채팅이나 사용할 수 있는 편집 도구로 수정하세요. AI 기반 변환은 새 애플리케이션을 게시하기 전에 추가 수정이 필요할 수 있어요.

### 마이그레이션이 끝났는지 어떻게 알 수 있나요?

변환된 애플리케이션이 일반 TanStack Start 프로젝트가 되면 프로젝트의 **Migrating to SSR** 상태가 사라져요. 그래도 게시하기 전에 애플리케이션이 제대로 동작하는지 테스트하세요.

### 기존 워크플로우 자동화를 마이그레이션된 프로젝트에서도 쓸 수 있나요?

네, 쓸 수 있어요. 다만 프로젝트별 워크플로우 설정은 업데이트해야 할 수 있어요. 원래 프로젝트의 트리거와 필터를 확인하고, 필요하면 마이그레이션된 프로젝트에 맞게 설정한 뒤 게시 후에 테스트 제출로 확인하세요.

### 마이그레이션한 뒤 API 키와 연동을 다시 만들어야 하나요?

모든 연동이나 자격 증명 설정이 자동으로 옮겨진다는 보장은 없어요. 마이그레이션된 애플리케이션에 필요한 연동 사항을 확인하고, 게시하기 전에 필요한 시크릿이나 연결을 설정하세요.
