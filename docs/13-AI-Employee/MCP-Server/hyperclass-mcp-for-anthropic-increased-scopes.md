# 하이퍼클래스 MCP for Anthropic — 확대된 권한 범위

OAuth 인증으로 Claude를 하이퍼클래스에 연결하고, 40개 영역의 전체 오퍼레이션을 사용하는 방법을 안내해요.

## 이 문서에서 알 수 있는 내용

Anthropic용 하이퍼클래스 MCP 엔드포인트를 쓰면 Claude 클라이언트가 OAuth 인증으로 40개 영역(domain)의 오퍼레이션 625개에 접근할 수 있어요. 기존 범용 MCP 엔드포인트는 제한된 권한 범위만 제공했는데, 이보다 크게 늘어난 범위예요.

이 문서에서는 다음 내용을 설명해요.

- 주요 기능
- 설정 방법
- 기술 구조: 사용자가 직접 고르는 권한 범위, 5개 도구로 구성된 파사드 패턴, 클라이언트별 OAuth 분리

더 자세한 내용은 하이퍼클래스 고객지원에 문의하세요.

## Anthropic용 하이퍼클래스 MCP란?

Anthropic용 하이퍼클래스 MCP는 Claude 클라이언트 전용 OAuth 기반 Model Context Protocol 엔드포인트예요. MCP(Model Context Protocol)는 Claude 같은 AI 어시스턴트가 표준화된 방식으로 외부 데이터 소스와 도구에 연결하도록 해 주는 규약이에요.

이 엔드포인트로 하이퍼클래스의 전체 오퍼레이션 카탈로그(40개 영역, 625개 오퍼레이션)를 쓸 수 있어요. 기존 범용 MCP 엔드포인트의 제한된 범위보다 훨씬 넓어요. 전용 OAuth 앱이 사용 가능한 가장 넓은 권한 범위를 제공하지만, 어떤 권한을 허용할지는 사용자가 직접 정해요.

이 엔드포인트는 클라이언트별 MCP 방식을 따르며, URL 구조는 다음과 같아요.

```
https://services.leadconnectorhq.com/mcp/anthropic/v2
```

이 방식에서는 AI 클라이언트마다 OAuth 승인이 따로 관리돼요. Claude에 허용한 권한 범위는 ChatGPT 같은 다른 클라이언트나 앞으로 추가될 연동에 허용한 권한과 섞이지 않아요.

## 주요 기능

Anthropic용 하이퍼클래스 MCP는 보안과 효율을 유지하면서 폭넓은 API 접근을 제공해요.

- 확대된 권한 범위: 40개 영역의 전체 오퍼레이션 카탈로그에 걸친, 사용 가능한 가장 넓은 권한 범위를 쓸 수 있어요. 기존 엔드포인트는 제한된 범위만 제공했어요.
- 사용자가 직접 고르는 권한 범위: OAuth 동의 화면에서 연동이 접근할 권한 범위를 사용자가 정확히 승인해요. 권한은 사용자가 모두 통제해요.
- 5개 도구 파사드 패턴: 수백 개의 개별 도구 대신 핵심 도구 5개(`search`, `fetch`, `search_operations`, `describe_operation`, `execute_operation`)만 둬요. 모델이 다루는 컨텍스트는 작게 유지하면서 전체 카탈로그에 접근할 수 있어요.
- 클라이언트별 OAuth 분리: 공식 클라이언트마다 전용 OAuth 앱을 두므로, Claude에 허용한 권한 범위는 다른 AI 클라이언트와 분리돼요.
- 최신 v3 API 문서 기반: 모든 오퍼레이션은 최신 하이퍼클래스 v3 API를 기반으로 하며, 역할 기반 접근 제어(RBAC)가 완전히 적용돼요.
- 서브 계정 단위 연결: 모든 연결은 서브 계정(location) 단위로 동작해요. 연결 하나는 서브 계정 하나에 해당하며, 에이전시 전체에는 연결되지 않아요.

### 5개 도구 파사드의 동작 방식

에이전트는 `search_operations → describe_operation → execute_operation` 순서로 오퍼레이션을 찾고 실행해요. 이 구조 덕분에 모델의 컨텍스트 창을 효율적으로 쓰면서도 전체 오퍼레이션 카탈로그에 접근할 수 있어요.

## 지원하는 Claude 클라이언트

Anthropic용 하이퍼클래스 MCP 엔드포인트는 다음 Claude 클라이언트를 지원해요.

- Claude.ai: Anthropic의 웹 기반 Claude 화면
- Claude Code: 코드 작업에 맞춘 Claude 개발 환경
- Claude Cowork: Claude의 협업 작업 환경

### 지원 예정 클라이언트

OpenAI, Cursor, Windsurf, VS Code 등 다른 AI 클라이언트도 지원을 준비하고 있어요. 이 클라이언트들도 같은 클라이언트별 방식으로, OAuth 승인이 분리돼요.

### 기존 범용 엔드포인트

`https://services.leadconnectorhq.com/mcp/` 에 있는 기존 범용 엔드포인트도 그대로 지원해요. OAuth 또는 비공개 연동 토큰으로 모든 MCP 클라이언트와 계속 쓸 수 있어요. 다만 기존처럼 제한된 권한 범위만 제공해요.

## 오퍼레이션 범위와 권한

Anthropic용 하이퍼클래스 MCP는 하이퍼클래스 오퍼레이션 전반에 폭넓게 접근할 수 있어요. 전체 오퍼레이션 카탈로그는 아래 표와 같아요.

| 항목 | 값 |
| --- | --- |
| 카탈로그 전체 오퍼레이션 | 625 |
| 활성 오퍼레이션 | 571 |
| 읽기 오퍼레이션 | 243 |
| 쓰기 오퍼레이션 | 244 |
| 삭제 오퍼레이션 | 84 |
| 포함된 영역 | 40 |

오퍼레이션 범위의 주요 특징은 다음과 같아요.

- 자동 필터링: 사용자의 OAuth 승인 내용에 따라 오퍼레이션이 자동으로 걸러져요. 허용된 리소스에만 접근할 수 있어요.
- 가장 넓은 권한 범위: Anthropic OAuth 앱은 전체 카탈로그에 걸친 모든 권한 범위를 제공해요.
- 서브 계정 단위 연결: 모든 연결은 서브 계정(location) 단위로 동작해요. 연결 하나는 서브 계정 하나에 해당하며, 에이전시 전체에는 연결되지 않아요.
- 사용자가 직접 선택: OAuth 동의 화면이나 비공개 연동 토큰을 만들 때 허용할 권한 범위를 사용자가 골라요.

### 기존 엔드포인트와 비교

기존 `/mcp/` 엔드포인트는 비공개 연동 토큰 방식으로 일부 오퍼레이션만 제공해요. Claude 클라이언트에서 전체 카탈로그를 쓰려면 Anthropic 전용 엔드포인트를 사용하세요.

## Anthropic용 하이퍼클래스 MCP 설정하기

Claude 클라이언트에서 Anthropic 전용 엔드포인트에 연결하고 OAuth 승인을 마치면 설정이 끝나요.

1. 지원되는 Claude 클라이언트(Claude.ai, Claude Code, Claude Cowork) 중 하나를 열어요. 클라이언트 안에서 MCP 또는 연동 설정 화면으로 이동하세요.
2. 아래 Anthropic 전용 엔드포인트 URL로 MCP 연결을 설정하세요.

   ```
   https://services.leadconnectorhq.com/mcp/anthropic/v2
   ```

3. 연결(connect) 또는 승인(authorize) 버튼을 눌러 OAuth 절차를 시작하세요. 하이퍼클래스 승인 페이지로 이동해요.
4. OAuth 동의 화면에서 요청된 권한 범위를 확인하세요. Claude 연동에 허용할 권한만 정확히 선택하세요. AI가 접근할 오퍼레이션은 사용자가 정해요.
5. 연결할 서브 계정(location)을 선택하세요. 연결은 에이전시 전체가 아니라 서브 계정 단위로 동작해요.
6. **승인** 또는 **허용**을 눌러 OAuth 절차를 마무리하세요. 보안 인증에는 PKCE(Proof Key for Code Exchange)를 함께 쓰는 인증 코드(Authorization Code) 방식을 사용하고, 리프레시 토큰도 지원해요.
7. Claude 클라이언트로 돌아오면, 활성 연동 목록에 하이퍼클래스 MCP 연결이 보이는지 확인하세요. 이제 Claude로 하이퍼클래스 데이터를 다룰 수 있어요.

승인이 끝나면 Claude가 5개 도구 파사드 패턴으로 오퍼레이션을 찾아 실행할 수 있어요. 모든 API 호출에는 OAuth 승인 정보의 `locationId`가 자동으로 들어가요.

## 기술 구조

Anthropic용 하이퍼클래스 MCP는 안전하고 확장 가능하며 효율적인 AI 연동을 위해 다음과 같은 구조를 갖추고 있어요.

### 구성 요소 1. 호스팅 오퍼레이션 레지스트리

호스팅되는 모든 CRM 오퍼레이션을 담은 레지스트리를 자동으로 생성해요. 덕분에 오퍼레이션을 더 빨리 찾고, 순위를 더 잘 매기고, 실행 경로를 일관되게 유지하고, AI가 도구를 더 정확하게 고를 수 있어요.

### 구성 요소 2. 클라이언트별 OAuth 앱 레지스트리

상위 OAuth 앱 레지스트리가 `/mcp/{client}/v2` 패턴 뒤에 있는 공식 클라이언트마다 전용 OAuth 앱을 지정해요. 클라이언트는 origin과 리디렉션 신호로 식별해요. 경로가 맞지 않는 요청은 거부하고, 클라이언트별 OAuth 디스커버리 메타데이터를 제공해요.

### 구성 요소 3. 보안 강화

리디렉션 URI 허용 목록을 적용하고, DNS 리바인딩 공격을 막기 위해 MCP origin을 검증해요. 민감한 토큰과 시크릿은 가려서 처리하고, 내부 관리자·디버그 화면은 공개 런타임 엔드포인트와 분리해요.

### 구성 요소 4. 인프라와 안정성

MCP 서비스 전용 Redis 인프라를 쓰고, OAuth 시크릿은 AWS Secrets Manager로 관리해요. OAuth 승인 정보의 `locationId`는 API 호출에 자동으로 넣어 줘요.

### 구성 요소 5. RBAC 적용

모든 오퍼레이션은 최신 v3 API 문서를 기반으로 하며, 역할 기반 접근 제어(RBAC)가 완전히 적용돼요. RBAC 검사를 통과하지 못한 오퍼레이션은 차단되므로, 사용자의 역할과 OAuth 승인 범위에서 허용된 리소스에만 접근할 수 있어요.

{% hint style="info" %}
인증에는 PKCE(Proof Key for Code Exchange)를 함께 쓰는 인증 코드 방식을 사용해 가로채기 공격을 막아요. 리프레시 토큰을 지원하므로, 다시 승인하지 않아도 오래 연결을 유지할 수 있어요.
{% endhint %}
