# SaaS 구독 취소 흐름 사용자 지정하기

**SaaS 구성기**(SaaS Configurator)에서 서브 계정의 구독 취소 과정을 직접 꾸밀 수 있어요. 에이전시 관리자만 쓸 수 있어요. 이 문서에서는 취소 사유 수집, 할인 제안, 외부 페이지 이동, 취소 기록 확인 방법을 알려드려요.

## 커스텀 SaaS 취소 흐름이란?

기본 설정에서는 버튼 한 번으로 바로 취소돼요. 커스텀 취소 흐름은 이 과정을 여러 단계로 바꿔요. 취소 사유 수집, 할인 제안, 외부 페이지 이동 단계마다 문구와 혜택, 다음 동작을 직접 정할 수 있어요. 고객사가 갑자기 떠나지 않고, 한 번 더 머물 이유를 만나게 돼요.

## 커스텀 취소 흐름의 장점

- 이탈 사유 파악: 선택형과 직접 입력형 취소 사유를 모아 제품, 요금, 온보딩 개선에 활용할 수 있어요.
- 이탈 줄이기: 취소 과정에서 기간 한정 할인율을 보여 주어, 망설이는 고객사가 구독을 유지하도록 유도할 수 있어요.
- 직접 관리형 방어: 취소 버튼을 누른 고객사를 전담 상담 페이지, 설문, 예약 링크 같은 외부 페이지로 보내 맞춤형으로 붙잡을 수 있어요.
- 전체 현황 파악: 모든 취소 시도와 취소 방어 결과를 **Activity Logs**(활동 로그)에서 실시간으로 확인할 수 있어요.
- 코딩 없이 수정: 사유, 혜택, 문구를 필요할 때 바로 바꿀 수 있어요. 코딩 없이 유지 전략을 빠르게 A/B 테스트할 수 있어요.

## 전역 토글 — 클라이언트의 구독 취소 허용

**Allow Clients to Cancel Subscription**(클라이언트의 구독 취소 허용)은 전체를 한 번에 켜고 끄는 스위치예요. **켜짐**으로 바꾸면 모든 서브 계정의 **청구 대시보드**에 **수정 / 취소** 버튼이 나타나요. **끄기**로 두면 취소 옵션이 모두 숨겨지고, 취소는 에이전시가 직접 관리해요.

- 위치: **에이전시 보기 > SaaS 구성기 > Cancellation Settings**(취소 설정)
- 새 SaaS 비즈니스의 기본 상태: **끄기**
- 변경 내용은 **저장**을 누르면 바로 적용돼요.

## 취소 사유 관리하기

취소 사유를 구체적으로 모으면 가격 불만, 부족한 기능, 온보딩 문제를 파악하는 데 도움이 돼요. 고객사가 SaaS 구독을 취소하려 할 때 보게 될 사유 목록을 여기서 설정해요.

사유를 설정하는 방법이에요.

1. **SaaS 구성기 > Cancellation Settings**로 이동하세요.
2. **Manage Cancellation Reason**(취소 사유 관리)에서 기본 사유를 고르거나 새 사유를 추가하세요.
3. 목록의 사유를 고치려면 ✏️ 아이콘을, 새 사유를 추가하려면 ➕ 아이콘을 클릭하세요.
4. **Other**(기타) 옵션은 항상 포함돼요. 고객사가 직접 입력해서 답할 수 있어요.

![취소 사유 관리 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155049081667/original/MsrKuMGjwHgpVQ80DEG8labRPshCYJaXRQ.png?1751285152)

## 할인 혜택으로 고객사 붙잡기

취소를 확정하기 전에 할인을 제안해 고객사를 붙잡아 볼 수 있어요. 적절한 때에 가격 혜택을 주면, 고객사가 더 많은 가치를 경험해 보고 결정하도록 유도할 수 있어요. 하이퍼클래스가 다음 결제 주기에 쿠폰을 자동으로 적용해요.

할인 제안을 켜는 방법이에요.

1. **Enable Discount Offer**(할인 제안 활성화) 토글을 켜세요.
2. 아래 항목을 설정하세요.

   - **Discount %**(할인율): 예) 25%
   - **Discount Duration**(할인 기간): 예) 월 결제 요금제는 3개월
3. 필요하면 **receive the offer more than once**(제안을 여러 번 받도록 허용) 옵션을 켜세요.
4. 고객사가 제안을 수락하면 다음 결제 주기에 할인이 자동으로 적용돼요.
5. 제안을 수락한 고객사는 취소 대상에서 빠져요(**Deflected**, 취소 방지됨).

```
⚠️ 이 기능은 현재 V1 서브 계정에서만 쓸 수 있어요.
```

## 외부 페이지로 이동시키기

취소 처리를 플랫폼 밖, 예를 들어 내 사이트에서 하고 싶다면 고객사를 외부 페이지로 보낼 수 있어요. 더 세밀한 이탈 관리 과정, 설문, 붙잡기 시도에 활용해 보세요.

설정 방법이에요.

1. **Redirect to External Page**(외부 페이지로 이동)에 유효한 URL을 입력하세요.
2. 이 옵션을 켜 두면 고객사가 취소 사유를 고른 직후 입력한 페이지로 이동해요.
3. 이 경우 하이퍼클래스 안에서는 취소가 완료되지 않아요.

![외부 페이지 이동 설정 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155049081726/original/-5esIHLnV47gNyPYzxPDy7xvKMNIN-H_mA.png?1751285207)

## Activity Logs로 취소 기록 확인하기

모든 취소 시도가 기록되어, 이탈 패턴과 유지 성과를 분석하는 데 쓸 수 있어요.

기록을 확인하는 방법이에요.

1. **Activity Logs**(활동 로그) 섹션까지 스크롤하세요.
2. 아래 항목을 확인하세요.

   - **서브 계정 이름**과 사용자
   - **타임스탬프**
   - **요금제 세부 정보**
   - **취소 사유**
   - **Outcome**(결과): Cancelled(취소됨) / Deflected(취소 방지됨)
   - **Detection type**(감지 유형): 예) 쿠폰, 리디렉션
3. 로그를 내보내려면 **다운로드** 버튼을 클릭하세요.

![활동 로그 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155049081746/original/I-GIi7zy9SRof0upqSDhtKr5zKGvDSSQmQ.png?1751285223)

## 취소 흐름 미리 보기

고객사에게 적용하기 전에 **미리보기 모드**로 흐름을 미리 확인할 수 있어요. 미리보기 모드는 고객사가 겪는 전체 과정을 안전한 테스트 환경에서 그대로 보여 줘요. 문구, 쿠폰 계산, 이동할 페이지를 다시 점검할 수 있어요. 미리보기 중에는 쿠폰이 발급되지 않고 로그도 남지 않아요. 실제로 적용하기 전에 취소 과정을 깔끔하게 다듬을 수 있어요.

미리 보는 방법이에요.

1. **Cancellation Settings** 오른쪽 위의 **미리보기**를 클릭하세요.
2. 고객사가 보게 될 순서대로 각 단계를 넘겨 보세요.
3. 문구, 혜택, 흐름이 맞는지 확인하세요.

## 자주 묻는 질문

### 고객사가 할인 제안을 두 번 이상 받을 수 있나요?
네. 할인 설정에서 **Allow Sub-Accounts to receive discount offer more than once**(서브 계정이 할인 제안을 여러 번 받도록 허용)를 확인하세요.

### 외부 페이지 이동을 켰는데 사용자가 브라우저를 닫으면 어떻게 되나요?
앱 안의 취소 단계를 거치지 않았기 때문에 구독은 그대로 유지돼요. **Activity Logs**에는 Deflected – External Link로 기록돼요.

### 어느 팀원이 취소를 시도했는지 어디서 볼 수 있나요?
**Activity Logs**의 **User**(사용자) 열에서 해당 서브 계정 관리자를 확인할 수 있어요.

### 취소 활동 로그를 감사나 리포트용으로 내보낼 수 있나요?
네. **Activity Logs**에서 **다운로드**를 클릭하면 CSV 파일로 내보내져요. 모든 취소와 취소 방지 이벤트, 사유, 사용자 정보가 들어 있어요.

### 미리보기 모드에서 실제 쿠폰이 발급되거나 로그가 남나요?
아니요. 미리보기는 테스트 환경에서 실행돼요. 전체 흐름을 보여 주지만 쿠폰을 발급하거나 구독 상태를 바꾸지 않고, **Activity Logs**에도 기록하지 않아요.

### 고객사가 결국 구독을 유지해도 취소 방지 이벤트가 기록되나요?
네. **Activity Logs**에는 할인 수락이나 외부 페이지 이동으로 취소가 방지된 경우를 포함해 모든 시도가 기록돼요. 그래서 전체 이탈 압력이 얼마나 되는지 항상 확인할 수 있어요.
