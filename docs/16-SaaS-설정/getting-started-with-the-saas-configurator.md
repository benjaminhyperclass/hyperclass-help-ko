# SaaS 구성기 시작하기

**SaaS 구성기**(SaaS Configurator)를 쓰면 에이전시가 고객 서브 계정용 정기 SaaS 플랜을 구성하고, 가격을 정하고, 판매하고, 관리할 수 있어요. Stripe 기반의 SaaS V1과 에이전시 서브 계정 기반의 SaaS V2를 모두 지원해요. 이 문서에서는 알맞은 구조를 고르는 방법, 플랜 만들기, 구독 판매, 고객 온보딩을 안내해요.

## 이 문서에서 알아볼 내용

SaaS V1과 V2의 차이, 결제 제공업체 연결, 플랜 카테고리와 SaaS 플랜 만들기, 퍼널이나 결제 링크로 판매하기, 고객 온보딩, 첫 판매 이후의 구독 관리를 다뤄요. 지원되는 플랜 변경 뒤에 해당하는 SaaS V1 구독이 어떻게 같은 상태로 유지되는지도 설명해요.

{% hint style="warning" %}
SaaS V1과 SaaS V2는 서로 별개의 청구 구조예요. SaaS V1은 계속 Stripe를 기반으로 하고, SaaS V2는 에이전시 서브 계정을 청구 기준 시스템으로 써요. 이 문서에서 설명하는 SaaS V1 구독 브리지는 지원되는 업그레이드·다운그레이드 이후에 해당하는 판매용 서브 계정의 구독을 같은 상태로 맞춰 주는 기능이에요. V1 구독을 V2로 바꿔 주지는 않아요.
{% endhint %}

## SaaS 구성기란?

SaaS 구성기는 플랫폼 이용 권한을 정기 SaaS 구독 플랜으로 묶어 주는 하이퍼클래스 기본 도구예요. 에이전시는 가격, 기능, 스냅샷, 애드온, 사용량 기반 청구 같은 플랜 설정을 정하고, 고객이 서브 계정을 어떻게 구매하고 이용할지도 관리할 수 있어요.

하이퍼클래스는 SaaS V1과 SaaS V2, 두 가지 청구 구조를 지원해요. 둘 다 SaaS 구성기에서 관리할 수 있지만, 상품·구독·청구 기록을 보관하는 위치가 달라요.

### SaaS 구성기의 주요 장점

SaaS 구성기에는 소프트웨어 이용권을 정기 판매하는 데 필요한 핵심 요소가 모여 있어요. 서비스 구성, 온보딩 자동화, 청구 구조 관리를 한 곳에서 반복해서 처리할 수 있어요.

정기 매출: 고객마다 직접 청구하지 않고, 이용 권한을 월간 또는 연간 SaaS 플랜으로 묶어 판매해요.

유연한 청구 구조: 결제 제공업체와 청구 방식에 맞춰 Stripe 기반 SaaS V1과 에이전시 서브 계정 기반 SaaS V2 중에서 골라 쓸 수 있어요.

자동 온보딩: SaaS 결제가 완료되면 고객 서브 계정을 만들고, 스냅샷을 적용하고, 플랜 이용 권한을 설정해요.

플랜 관리: SaaS 플랜 설정에서 기능, 가격, 카테고리, 체험 기간, 크레딧, 애드온, 사용량 기반 청구를 정해요.

구독 정확성: 판매용 서브 계정을 통해 판매한 SaaS V1 구독 중 해당하는 구독은, 지원되는 업그레이드·다운그레이드 후에도 Stripe와 판매용 서브 계정의 구독 정보를 같게 유지할 수 있어요.

### SaaS V1과 SaaS V2 비교

SaaS V1과 V2는 순서대로 이전해야 하는 버전이 아니라 서로 다른 청구 구조예요. 어느 시스템이 구독을 관리하는지 알면 알맞은 설정, 결제 제공업체, 문제 해결 방법을 고를 수 있어요.

| 구분 | SaaS V1 | SaaS V2 |
| --- | --- | --- |
| 기준 시스템(system of record) | Stripe | 선택한 에이전시 서브 계정을 통한 하이퍼클래스 |
| 결제 제공업체 | Stripe | 에이전시 서브 계정에 연결된 지원되는 결제 제공업체 |
| 상품 관리 위치 | Stripe | 하이퍼클래스 |
| 청구 주기 변경 | V1/Stripe 구독 워크플로우에 따라 처리돼요 | 지원되는 플랜 업그레이드·다운그레이드 과정에서 월간·연간 주기를 바꿀 수 있어요 |
| 플랜 변경 시 일할 계산 | V1/Stripe 청구 흐름으로 처리할 수 있어요 | 등급 변경, 주기 변경, 등급·주기 동시 변경 모두 **지원되지 않음** |

구조 주의 사항: SaaS V1 구독 브리지는 V1의 기준 시스템을 바꾸지 않아요. 지원되는 플랜 변경 뒤에 판매용 서브 계정의 구독이 동기화되더라도, V1 구독은 계속 Stripe가 관리해요.

구조 차이를 더 자세히 알고 싶다면 [SaaS V1 vs SaaS V2: What's the Difference?](saas-v1-vs-saas-v2-what-s-the-difference.md)를 참고하세요.

![SaaS V1·V2 플랜 구조를 보여 주는 SaaS 구성기 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155080791739/original/oKVP0iEdTJ8Pr4vlDVXx0LUwJr00Ryf77w.png?1789248979)

## SaaS 구성기 설정하기

먼저 어느 청구 구조에서 구독을 관리할지 정해야 고객이 알맞은 플랜을 구매할 수 있어요. 가격, 상품, 구독 기록이 의도한 시스템에 연결되도록, 플랜을 만들기 전에 결제 제공업체 설정부터 끝내세요.

### 시작하기 전에

첫 SaaS 플랜을 만들기 전에 필요한 에이전시 권한과 결제 제공업체 설정을 확인하세요. V1을 쓰는지 V2를 쓰는지에 따라 준비할 내용이 달라요.

- **에이전시 관리자** 권한이 있어야 해요.
- SaaS V1: 에이전시에 연결할 Stripe 계정이 있어야 해요.
- SaaS V2: 지원되는 결제 제공업체가 **결제 > 연동**에 설정된 에이전시 서브 계정이 있어야 해요.

### SaaS V1용 Stripe 연결하기

SaaS V1은 Stripe를 청구 기준 시스템으로 써요. V1 플랜과 가격을 만들기 전에 에이전시의 Stripe 연결을 먼저 마쳐야 해요.

1. **에이전시 보기 > 설정 > Stripe**로 이동해요.
2. **Stripe 로 연결**을 클릭하고 안내에 따라 연결을 완료해요.
3. **에이전시 보기 > SaaS 구성기**로 돌아가 플랜 만들기를 이어서 진행해요.

![SaaS V1용 Stripe 연결 설정 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155080791740/original/eDVGERxqfbrobEbDttVkZK1ckaFR7LIgqw.png?1789248995)

### SaaS V2용 에이전시 서브 계정 선택하기

SaaS V2는 지정한 내부 에이전시 서브 계정에서 상품, 구독, 결제를 관리해요. V2 플랜을 만들기 전에 청구 기준 시스템으로 쓸 서브 계정을 선택하세요.

1. **에이전시 보기 > SaaS 구성기 > 구성**으로 이동해요.
2. **Select Sub-Accounts**(서브 계정 선택)를 클릭해요.
3. 에이전시 서브 계정을 고르고 **서브 계정 추가**를 클릭해요.
4. 해당 서브 계정 안의 **결제 > 연동**에 지원되는 결제 제공업체가 설정되어 있는지 확인해요.

![SaaS V2용 에이전시 서브 계정 선택 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155080791748/original/lXfzX3TdKpBrVXh1vuX7ssX763xsJQ_uyQ.png?1789249029)

에이전시 서브 계정이 뭔가요? 에이전시가 소유하고 에이전시 운영에 쓰는 내부 서브 계정이에요. SaaS V2에서는 이 서브 계정이 연결된 SaaS 상품과 구독의 청구 기준 시스템 역할을 해요.

### 플랜 카테고리 만들기

플랜 카테고리는 관련 있는 플랜을 업그레이드·다운그레이드 경로로 묶어 줘요. 호환되는 플랜을 같은 카테고리에 두면, 고객이 나중에 변경할 수 있는 플랜을 정하는 데 도움이 돼요.

1. **SaaS 구성기 > 고급 설정**을 열어요.
2. **새 카테고리**를 클릭해요.
3. 카테고리 이름을 입력하고 **통화**를 선택해요.
4. **저장**을 클릭해요.

통화: 같은 카테고리 안의 플랜은 같은 통화를 쓰는 것이 좋아요. 여러 통화로 판매한다면 카테고리를 따로 만드세요. 그래야 고객에게 호환되는 업그레이드·다운그레이드 옵션만 보여 줄 수 있어요.

플랜 변경: 지원되는 업그레이드와 다운그레이드는 SaaS를 껐다가 다시 켜지 않아도 돼요. 플랜의 카테고리나 레벨을 바꾸면 고객이 선택할 수 있는 플랜 변경 경로가 달라질 수 있으니, 수정하기 전에 카테고리 구조를 꼼꼼히 확인하세요.

![SaaS 플랜 카테고리 만들기 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155080791759/original/-X8x81EQ_vM1X9E7zM-2a_IM3aqJUUMhlw.png?1789249056)

### SaaS 플랜 만들기

SaaS 플랜은 고객이 얼마를 내고 무엇을 받는지 정해요. 가격, 기능 이용 권한, 스냅샷, 애드온, 사용량 규칙이 모두 고객의 구독 경험에 반영되므로 설정을 꼼꼼히 확인하세요.

1. **SaaS 구성기**에서 **Add Your Plan**(플랜 추가)을 클릭해요.
2. 사용할 결제 제공업체나 청구 구조를 선택해요.
3. 필요에 따라 플랜 상세, 카테고리, 가격, 기능, 스냅샷, 애드온, 마켓플레이스 앱, 체험·크레딧, 사용량 청구를 설정해요.
4. 플랜에 상품 기능을 하나 이상 선택해요.
5. 설정을 검토하고 플랜을 저장해요.

| 설정 항목 | 용도 |
| --- | --- |
| **플랜 상세** | 플랜 이름과 고객에게 보이는 플랜 정보 |
| **카테고리** | 관련 업그레이드·다운그레이드 경로 결정 |
| **가격** | 월간 또는 연간 구독 가격 |
| **Features & Snapshot**(기능 & 스냅샷) | 이용 권한 관리와 서브 계정 자동 구성(선택) |
| **애드온** | 고객이 선택할 수 있는 유료 추가 기능(선택) |
| **마켓플레이스 앱** | 플랜에 함께 제공하는 사용 가능한 서드파티 앱 |
| **Trial & Credits**(체험 & 크레딧) | 체험 기간과 무료 크레딧 적용 방식 |
| **Usage Billing**(사용량 청구) | 플랜에 설정한 사용량 기반 또는 단위별 요금 |

기능을 하나 이상 선택해야 해요: SaaS 플랜을 저장하기 전에 기능을 하나 이상 선택하세요. 상품 기능을 선택하지 않으면 플랜을 완료할 수 없어요.

![SaaS 플랜에 기능 선택이 필요하다는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155080791768/original/wKG6o0ot67Mz6XeWrBNzIAx9a7FuN-6zZA.png?1789249089)

## SaaS 판매하기

SaaS 플랜은 브랜드가 적용된 퍼널이나 SaaS 결제 링크로 판매할 수 있어요. V1 상품은 Stripe에서 시작되고 V2 상품은 선택한 에이전시 서브 계정에서 관리되기 때문에, V1과 V2의 판매 과정은 서로 달라요.

### 판매용 서브 계정 퍼널로 SaaS V1 판매하기

V1 퍼널 방식은 Stripe 기반 SaaS 상품을 판매용 서브 계정으로 가져와 주문 폼에 넣을 수 있게 해 줘요. 이 문서 뒷부분에서 설명하는 V1 구독 동기화도 이 판매 방식과 관련이 있어요.

1. SaaS 구독을 판매할 서브 계정으로 전환해요.
2. **결제 > 상품 > Import From Stripe**(Stripe에서 가져오기)로 이동해요.
3. SaaS용 Stripe 상품을 찾아 해당 가격을 가져와요.
4. **사이트 > 퍼널**로 이동해요.
5. 가져온 SaaS 상품을 지원되는 주문 폼에 추가하고 퍼널을 게시해요.

가져오기 방법은 [Import Products / Price From Stripe](../08-결제/import-products-price-from-stripe.md)에서 자세히 볼 수 있어요.

V1 Stripe 가격이 바뀐 경우: 퍼널이나 웹사이트에서 가격을 선택하기 전에, 변경된 가격을 판매용 서브 계정으로 다시 가져오세요. SaaS 플랜이나 Stripe 가격을 업데이트해도, 기존 퍼널 주문 폼에 이미 선택된 상품 가격은 자동으로 바뀌지 않아요.

### 에이전시 서브 계정 퍼널로 SaaS V2 판매하기

V2 상품은 에이전시 서브 계정에서 만들고 관리해요. 그래서 Stripe에서 가져오지 않고, 해당 서브 계정의 결제 도구와 퍼널 도구에서 바로 선택할 수 있어요.

1. 해당 에이전시 서브 계정으로 전환해요.
2. **결제 > 상품**으로 이동해 SaaS 상품이 있는지 확인해요.
3. **사이트 > 퍼널**로 이동해 SaaS 상품을 알맞은 주문 폼에 추가해요.

### SaaS 결제 링크 바로 만들기

퍼널이 필요 없을 때는 결제 링크로 더 빠르게 판매할 수 있어요. 이 링크는 이메일, 제안서, 소셜 채널, 다른 웹페이지의 버튼 등으로 공유할 수 있어요.

1. **SaaS 구성기 > 플랜 & 가격**을 열어요.
2. SaaS 플랜을 찾아요.
3. **Copy Sale Link**(판매 링크 복사)를 클릭해요.
4. 복사한 결제 링크를 고객에게 공유해요.

구독 동기화 범위: 아래에서 설명하는 V1 브리지는 판매용 서브 계정 방식을 쓰는 구독 중 해당하는 구독에 적용돼요. 문서에 따로 안내된 경우가 아니라면, SaaS 구성기의 모든 결제 방식이 같은 판매용 서브 계정 구독 경로를 쓴다고 생각하지 마세요.

## 플랜 변경 후 SaaS V1 구독 동기화

판매용 서브 계정을 통해 판매한 SaaS V1 구독 중 해당하는 구독은 Stripe 구독과, 그 판매용 서브 계정 안의 구독 기록을 함께 가질 수 있어요. 이제 지원되는 SaaS 업그레이드와 다운그레이드는 두 기록을 모두 업데이트해서, 판매용 서브 계정에 예전 플랜 정보가 남지 않아요.

| 이전 | 지원되는 V1 플랜 변경 후 |
| --- | --- |
| SaaS 플랜을 바꿔도 Stripe만 업데이트되고, 판매용 서브 계정의 구독에는 예전 플랜 정보가 남을 수 있었어요. | 지원되는 플랜 변경이 같은 과정에서 Stripe와 판매용 서브 계정의 구독을 함께 업데이트해요. |
| 판매용 서브 계정의 구독이 예전 상품이나 가격을 참조할 수 있었어요. | 현재 상품과 가격이 해당 구독에 동기화돼요. |
| 이후에 발행되는 인보이스에 예전 플랜 정보가 쓰일 수 있었어요. | 판매용 서브 계정의 구독에서 발행되는 인보이스에 현재 플랜 정보가 반영될 수 있어요. |
| 해당하는 세금이 예전 플랜 정보를 기준으로 계산될 수 있었어요. | 세금이 적용되는 경우, 조건에 맞는 플랜 변경 뒤 현재 플랜 정보로 다시 계산될 수 있어요. |

적용되는 V1 패턴: SaaS 플랜 → Stripe 상품 → 판매용 서브 계정으로 가져온 상품 → 해당 판매용 서브 계정에서 판매한 구독 → 지원되는 SaaS 업그레이드 또는 다운그레이드

소급 적용되지 않아요: 이미 어긋나 있는 Stripe와 판매용 서브 계정의 구독 정보는 자동으로 채워지지 않아요. 앞으로 조건에 맞는 업그레이드나 다운그레이드가 일어나면 새 동기화 과정을 통해 두 기록이 모두 업데이트될 수 있어요.

Stripe에서 직접 수정한 경우: Stripe에서 직접 바꾼 내용이 V1 구독 브리지를 자동으로 작동시킨다고 생각하지 마세요. 여기서 설명한 동기화는 지원되는 SaaS 업그레이드·다운그레이드 이벤트와 연결되어 있어요.

## 고객 온보딩

SaaS 온보딩은 구독 결제가 성공한 뒤 고객의 서브 계정, 기능 이용 권한, 설정된 스냅샷을 연결해 주는 과정이에요. 결제할 때 어떤 일이 일어나는지 알면, 처음 설정하는 과정과 이후 업그레이드·다운그레이드 같은 구독 변경을 구분하기 쉬워요.

### SaaS 결제로 들어온 신규 고객

신규 고객이 지원되는 SaaS 결제를 성공적으로 마치면, 설정된 SaaS 워크플로우가 구독과 서브 계정 이용 권한을 만들어 줘요.

1. 해당하는 청구 구조를 통해 결제가 확인돼요.
2. 상황에 따라 서브 계정이 만들어지거나 고객에게 연결돼요.
3. SaaS 플랜에 스냅샷이 연결되어 있으면 설정된 스냅샷이 적용돼요.
4. 온보딩 워크플로우에 따라 고객의 이용 권한이 설정돼요.
5. 플랜 설정에 따라 구독이 활성 상태 또는 체험 상태가 돼요.

온보딩 이후: 판매용 서브 계정 방식으로 판매한 SaaS V1 구독 중 해당하는 구독은, 이후 지원되는 업그레이드나 다운그레이드가 일어나면 Stripe 구독과 판매용 서브 계정의 구독이 함께 업데이트될 수 있어요.

### 기존 서브 계정에 SaaS 수동으로 추가하기

고객에게 이미 서브 계정이 있어서, 결제로 새 로케이션을 만들지 않고 SaaS 플랜에 등록하려면 수동 SaaS 구독 방식을 쓰세요.

1. **에이전시 보기 > 서브 계정**으로 이동해요.
2. 대상 서브 계정을 열고 **고객 관리**를 선택해요.
3. **SaaS** 영역을 열고 **Add a SaaS Subscription**(SaaS 구독 추가)을 선택해요.
4. 사용할 결제 제공업체를 선택해요.
5. 고객 프로필을 선택하거나 새로 만들어요.
6. SaaS 플랜을 선택해요.
7. 필요하면 해당 고객에게만 적용할 **Special Price**(특별 가격)를 설정해요.
8. 구독을 서브 계정에 연결할 수 있도록 결제를 완료해요.

특별 가격: 공개된 플랜 가격은 그대로 두고 해당 고객에게만 적용되므로, 프로모션 가격, 기업 대상 계약, 기존 고객 유지 요금 등에 쓸 수 있어요.

## SaaS V1과 V2 함께 운영하기

에이전시는 V1과 V2 플랜을 동시에 운영할 수 있어요. 두 구조를 따로 유지하면 기존 Stripe 기반 V1 구독은 그대로 이어가고, 새 플랜은 V2 청구 구조가 더 알맞은 경우에 V2로 만들 수 있어요.

- 두 구조 모두 SaaS 구성기에 표시될 수 있어요.
- V1 구독은 계속 Stripe를 청구 기준 시스템으로 써요.
- V2 구독은 선택한 에이전시 서브 계정을 청구 기준 시스템으로 써요.
- V1 구독 브리지는 V1 구독을 V2로 이전하거나 바꾸지 않아요.

![SaaS 구성기에 함께 표시된 SaaS V1·V2 플랜](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155072206393/original/ap8aymH8MT0wjfQmKQJZezy4G72EvQbtmw.png?1779793072)

### 청구 문제는 어디서 확인하나요

문제 확인은 해당 구독의 기준 시스템에서 시작하세요. 그래야 다른 구조에서 청구를 잘못 바꾸는 일을 피할 수 있어요.

| 구조 | 확인을 시작할 곳 |
| --- | --- |
| V1 | Stripe와 SaaS V1 구독 설정 |
| V2 | 선택한 에이전시 서브 계정과 해당 계정의 결제 모듈 |

## 자주 묻는 질문

### 새로 생긴 V1 구독 브리지 때문에 SaaS V1이 SaaS V2와 같아지나요?
아니요. SaaS V1의 기준 시스템은 계속 Stripe예요. 브리지는 지원되는 V1 업그레이드·다운그레이드 뒤에 해당하는 판매용 서브 계정의 구독을 같은 상태로 맞춰 줄 뿐이에요.

### 이미 어긋나 있는 V1 구독 정보도 자동으로 고쳐지나요?
아니요. 이 동기화는 과거 데이터를 소급해서 채우지 않아요. 앞으로 조건에 맞는 업그레이드나 다운그레이드가 일어나면 Stripe와 판매용 서브 계정의 기록이 모두 업데이트될 수 있어요.

### Stripe에서 V1 구독을 직접 수정하면 판매용 서브 계정의 구독도 업데이트되나요?
Stripe에서 임의로 직접 수정한 경우에는 자동으로 업데이트된다고 보장할 수 없어요. 브리지는 지원되는 SaaS 업그레이드·다운그레이드 이벤트를 기준으로 안내된 기능이에요.

### 고객이 플랜을 바꿀 때 SaaS를 껐다가 다시 켜야 하나요?
아니요. 지원되는 업그레이드·다운그레이드 과정에서는, 해당하는 플랜 사이로 고객을 옮기려고 SaaS를 껐다가 다시 켤 필요가 없어요.

### 퍼널에서 쓰는 V1 Stripe 가격을 바꾸면 어떻게 하나요?
변경된 Stripe 가격을 판매용 서브 계정으로 가져온 다음, 해당 퍼널이나 웹사이트에서 선택한 상품 또는 가격을 업데이트하세요.

### SaaS V2 고객도 월간과 연간 결제 사이를 바꿀 수 있나요?
네. SaaS V2는 지원되는 플랜 업그레이드·다운그레이드 과정에서 월간과 연간 청구를 바꿀 수 있어요. 다만 등급 변경, 주기 변경, 등급·주기 동시 변경 시 일할 계산은 지원되지 않아요.

### V1과 V2 플랜을 동시에 운영할 수 있나요?
네. V1과 V2는 SaaS 구성기에서 함께 쓸 수 있고, 각자의 기준 시스템과 결제 방식을 따로 유지해요.
