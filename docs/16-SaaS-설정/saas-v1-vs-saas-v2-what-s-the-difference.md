# SaaS V1과 SaaS V2의 차이

하이퍼클래스는 SaaS 결제 방식을 두 가지로 지원해요. V1은 Stripe를 결제 기준 시스템으로 쓰고, V2는 에이전시 서브 계정을 기준으로 하며 여러 결제 제공업체를 쓸 수 있어요. 이 문서는 에이전시 관리자를 위해 두 방식의 차이를 정리했어요. 결제 설정, 구독 관리, 플랜 변경, 고객 온보딩에 어떤 방식이 맞는지 정할 때 참고하세요.

이 문서에서 다루는 내용은 다음과 같아요.

- SaaS V1과 V2의 차이
- 구독을 관리하는 곳
- 결제 제공업체가 동작하는 방식
- 현재 두 방식에서 서로 다른 결제 기능
- 지원되는 플랜 변경 뒤에 SaaS V1 구독 브리지가 대상 구독 기록을 맞춰 주는 방식

{% hint style="warning" %}
SaaS V2는 SaaS V1의 업그레이드나 대체 기능이 아니에요. 두 방식은 별개의 결제 구조이며 함께 운영할 수 있어요. SaaS V1 구독 브리지는 대상이 되는 V1 구독의 동기화를 개선해 주지만, V1에서 Stripe가 기준 시스템이라는 점은 바뀌지 않아요.
{% endhint %}

## SaaS V1과 SaaS V2는 무엇이 다른가요?

두 방식 모두 반복되는 SaaS 구독을 관리하는 방법이에요. 가장 큰 차이는 구독을 어디에서 소유하고 관리하느냐예요. V1은 Stripe가 기준 시스템이고, V2는 에이전시 서브 계정이 기준 시스템이에요. 이 차이는 결제 제공업체 선택, 구독 관리, 연동, 일부 결제 기능에 영향을 줘요.

| 항목 | SaaS V1 | SaaS V2 |
| --- | --- | --- |
| 기준 시스템 | Stripe | 선택한 에이전시 서브 계정 |
| 상품을 관리하는 곳 | Stripe | 에이전시 서브 계정을 통한 하이퍼클래스 |
| 주된 결제 제공업체 | Stripe | 지원되는 여러 결제 제공업체 |
| 플랜 변경 시 일할 계산 | 지원되는 V1/Stripe 작업 방식에서 사용 가능 | 지원되지 않음 |
| 월 ↔ 연 결제 주기 변경 | 지원되는 V1/Stripe 구독 작업 방식으로 처리 | 조건에 맞는 업그레이드·다운그레이드의 일부로 지원 |

## 두 방식의 차이를 알아 두면 좋은 점

결제 요건에 맞는 방식을 고르면 나중에 구독 관리에서 생기는 문제를 줄일 수 있어요. 차이를 알면 결제를 어디에서 설정하고, 문제가 생겼을 때 어디에서 확인하고, 앞으로의 플랜 변경을 어떻게 관리할지도 쉽게 정할 수 있어요.

- 결제 흐름 파악: 어느 시스템이 구독을 소유하는지, 결제 변경을 어디에서 관리해야 하는지 알 수 있어요.
- 결제 수단 선택: Stripe 기반의 V1을 쓸지, 지원되는 결제 제공업체를 에이전시 서브 계정에서 연결하는 V2를 쓸지 고를 수 있어요.
- 기능 계획: 고객을 받기 전에 V1과 V2에서 다른 결제·구독 유지 기능을 확인할 수 있어요.
- 정확한 플랜 변경: 방식별로 업그레이드, 다운그레이드, 결제 주기, 일할 계산이 어떻게 동작하는지 알 수 있어요.
- 쉬운 문제 해결: V1 결제 문제는 Stripe에서, V2 결제 문제는 해당 에이전시 서브 계정에서 시작하면 돼요.

## SaaS V1 구조

SaaS V1은 오래전부터 있던 Stripe 기반 구조예요. SaaS 구독의 기준 시스템은 계속 Stripe이고, 하이퍼클래스는 고객 서브 계정을 해당 SaaS·결제 설정에 연결해 줘요.

- SaaS V1의 기준 시스템은 Stripe예요.
- 에이전시가 에이전시 수준에서 Stripe를 연결해요.
- V1 SaaS 상품과 가격은 Stripe에서 만들어져요.
- 지원되는 범위에서는 Stripe 고유의 결제 기능을 쓸 수 있어요.
- 일부 V1 판매 흐름에서는 구독을 판매한 서브 계정 안에도 해당 구독 기록이 함께 만들어져요.

추천 대상: 에이전시가 Stripe를 쓰고 있고, Stripe 고유의 결제 기능이나 V2에서 아직 쓸 수 없는 SaaS 기능이 필요하다면 SaaS V1이 잘 맞아요.

## SaaS V2 구조

SaaS V2는 선택한 에이전시 서브 계정에서 SaaS 상품, 구독, 결제 제공업체 설정을 관리해요. 그래서 Stripe를 구독의 기준 시스템으로 두지 않고, 하이퍼클래스의 결제 및 CRM 환경 안에서 SaaS 결제를 직접 운영할 수 있어요.

- 선택한 에이전시 서브 계정이 SaaS V2 결제의 기준 시스템이에요.
- 상품과 구독을 하이퍼클래스에서 관리해요.
- 에이전시 서브 계정에서 설정한, 지원되는 여러 결제 제공업체를 V2에서 쓸 수 있어요.
- 구독 활동을 CRM, 연락처, 워크플로우 등 다른 하이퍼클래스 도구와 더 긴밀하게 연결할 수 있어요.
- 지원되는 플랜 업그레이드·다운그레이드의 일부로 월 결제와 연 결제 주기를 바꿀 수 있어요.

일할 계산: SaaS V2는 등급 변경, 결제 주기 변경, 두 가지를 함께 바꾸는 플랜 변경 모두 일할 계산을 지원하지 않아요.

## 플랜 변경 후 SaaS V1 구독 동기화

일부 SaaS V1 구독은 Stripe 기반 SaaS 상품을 판매용 서브 계정으로 가져온 뒤, 퍼널이나 지원되는 결제 흐름에서 그 상품을 써서 판매해요. 이런 구독에는 Stripe 구독과, 판매용 서브 계정의 해당 구독 기록이 함께 있을 수 있어요. 이제 지원되는 SaaS 업그레이드·다운그레이드를 하면 두 기록이 같은 내용으로 맞춰져요.

| 이전 | 조건에 맞는 V1 플랜 변경 후 |
| --- | --- |
| Stripe는 업데이트되는데 판매용 서브 계정의 구독에는 이전 플랜 정보가 남을 수 있었어요. | 지원되는 같은 플랜 변경 흐름에서 Stripe와 판매용 서브 계정의 해당 구독이 함께 업데이트돼요. |
| 판매용 서브 계정의 기록이 오래된 상품이나 가격을 가리킬 수 있었어요. | 현재 상품과 가격이 일치한 상태로 유지될 수 있어요. |
| 오래된 서브 계정 정보로 만들어진 인보이스가 이전 플랜을 가리킬 수 있었어요. | 이후 인보이스에 동기화된 현재 플랜 정보가 반영될 수 있어요. |
| 해당되는 세금 계산에 이전 플랜 정보가 쓰일 수 있었어요. | 세금이 이미 설정되어 있고 적용 대상이면, 현재 플랜 정보로 다시 계산할 수 있어요. |

적용되는 V1 흐름: SaaS 플랜 → Stripe 상품 → 판매용 서브 계정으로 가져온 상품 → 그 판매용 서브 계정에서 판매한 구독 → 지원되는 SaaS 업그레이드 또는 다운그레이드

소급 적용 안 됨: Stripe와 기존 판매용 서브 계정 구독 사이에 이미 생긴 불일치는 자동으로 채워지지 않아요. 앞으로 조건에 맞는 업그레이드나 다운그레이드를 하면, 지원되는 동기화 흐름으로 두 기록이 함께 업데이트될 수 있어요.

Stripe에서 직접 수정한 경우: Stripe에서 구독을 임의로 직접 바꿔도 이 동기화가 실행된다고 생각하지 마세요. 이 브리지는 지원되는 SaaS 업그레이드·다운그레이드 이벤트에 대해서만 안내되어 있어요.

## 현재 기능 차이

두 방식은 현재 구독 관리 기능이 완전히 같지 않아요. 새 SaaS 플랜에 쓸 방식을 고르기 전에, 내 결제 모델에 중요한 차이를 확인하세요.

| 기능 | SaaS V1 | SaaS V2 |
| --- | --- | --- |
| 지원되는 구독 플랜 변경 시 일할 계산 | 지원되는 V1/Stripe 결제 작업 방식에서 사용 가능 | 현재 지원되지 않음 |
| 다운그레이드·해지 흐름의 쿠폰/할인 디플렉션(deflection) | 지원되는 범위에서 사용 가능 | 현재 지원되지 않음 |
| 셀프 서비스 재활성화 | 지원되는 V1 흐름에서 사용 가능 | 현재 지원되지 않음 |
| 주 구독 결제 수단 업데이트 | 지원되는 V1/Stripe 작업 방식으로 가능 | 활성 상태인 SaaS V2 구독에서 서브 계정의 주 카드를 바꾸면, 그 서브 계정의 SaaS 구독에 쓰는 결제 수단도 함께 바뀌어요. 같은 연락처에 연결된 다른 구독은 업데이트되지 않아요. |
| 월 ↔ 연 플랜 변경 | 해당하는 V1/Stripe 작업 방식으로 지원 | 조건에 맞는 업그레이드·다운그레이드의 일부로 지원, 일할 계산 없음 |

## 어떤 SaaS 방식을 선택해야 하나요?

어느 한쪽이 무조건 더 좋지는 않아요. 쓰는 결제 제공업체, 꼭 필요한 구독 관리 기능, SaaS 결제를 하이퍼클래스의 CRM·결제 환경과 얼마나 가깝게 연결하고 싶은지에 따라 달라져요.

### SaaS V1을 선택하면 좋은 경우

V1은 주로 Stripe를 쓰고, Stripe 고유 기능이나 V1 전용 구독 기능이 필요한 에이전시에 잘 맞아요.

- Stripe를 SaaS 결제 처리업체로 쓰고 싶어요.
- 지원되는 일할 계산 방식이 필요해요.
- 할인/쿠폰 디플렉션 기능을 활용해요.
- Stripe 고유의 구독 관리 기능을 쓰고 싶어요.

### SaaS V2를 선택하면 좋은 경우

V2는 여러 결제 제공업체를 유연하게 쓰고 싶거나, 구독 관리를 에이전시 서브 계정 중심으로 하고 싶은 에이전시에 잘 맞아요.

- Stripe가 아닌 다른 지원 결제 제공업체를 쓰고 싶어요.
- 상품과 구독을 하이퍼클래스에서 관리하고 싶어요.
- CRM, 워크플로우와 더 긴밀하게 연동하고 싶어요.
- 위에서 설명한 V1 전용 기능이 필요하지 않아요.

## 알맞은 SaaS 결제 방식 설정하기

플랜을 만들고 판매하기 전에 결제 방식을 먼저 정하면, 상품, 결제 제공업체, 구독 기록, 이후 플랜 변경 동작을 일관되게 유지할 수 있어요. 첫 플랜을 설정하기 전에 아래 순서로 확인하세요.

1. 필요한 결제 제공업체를 확인하세요. SaaS 결제에 꼭 Stripe를 써야 한다면 V1이 맞을 수 있어요. 다른 지원 제공업체가 필요하다면 V2를 살펴보세요.
2. 필요한 결제 기능을 점검하세요. 일할 계산, 디플렉션, 재활성화 등 특정 방식에만 있는 기능에 의존하는지 확인하세요.
3. V1이라면 에이전시 수준에서 Stripe를 연결하세요. Stripe가 계속 SaaS 구독의 기준 시스템이 돼요.
4. V2라면 에이전시 서브 계정을 선택하세요. 그 서브 계정 안에서 지원되는 결제 제공업체를 설정하세요.
5. 서로 호환되는 플랜 카테고리와 가격을 만드세요. **플랜 계층**에 따라 이후 업그레이드·다운그레이드 경로가 정해져요.
6. 사용할 결제 흐름과 플랜 변경 흐름을 테스트하세요. 설정을 넓히기 전에 구독이 의도한 방식으로 만들어지는지 확인하세요.

두 방식을 함께 운영할 때: 에이전시는 기존 V1 플랜을 유지하면서 V2 플랜도 만들 수 있어요. 각 구독은 계속 자기 방식의 기준 시스템을 따라요.

## 자주 묻는 질문

### SaaS V2가 SaaS V1을 대체하나요?

아니요. 두 방식은 별개의 결제 구조이며 함께 운영할 수 있어요.

### V1 구독 브리지가 V1의 기준 시스템을 바꾸나요?

아니요. SaaS V1의 기준 시스템은 계속 Stripe예요. 브리지는 지원되는 플랜 변경 뒤에 판매용 서브 계정의 해당 구독을 동기화해 줄 뿐이에요.

### 예전 V1 구독의 불일치가 자동으로 고쳐지나요?

아니요. 이미 생긴 불일치는 자동으로 채워지지 않아요. 앞으로 조건에 맞는 업그레이드나 다운그레이드를 하면 두 기록이 함께 업데이트될 수 있어요.

### SaaS V2 고객이 월 결제와 연 결제를 바꿀 수 있나요?

네. 지원되는 V2 업그레이드·다운그레이드의 일부로 월 결제와 연 결제 주기를 바꿀 수 있어요. 일할 계산은 지원되지 않아요.

### Stripe에서 직접 수동으로 바꾸면 항상 V1 판매용 서브 계정 구독에 동기화되나요?

아니요. Stripe에서 임의로 직접 바꿔도 구독 브리지가 실행된다고 생각하지 마세요. 동기화는 지원되는 SaaS 업그레이드·다운그레이드 이벤트에만 적용돼요.

### V1 브리지가 Stripe Tax를 자동으로 켜 주나요?

아니요. Stripe Tax와 해당 세금 설정은 미리 켜고 설정해 두어야 해요. 브리지는 조건에 맞는 플랜 변경 뒤에 현재 플랜 정보가 맞춰지도록 도울 뿐이에요.

### 에이전시가 V1과 V2를 동시에 쓸 수 있나요?

네. 각 구독이 자기 결제 방식과 기준 시스템을 계속 쓰는 한, V1 플랜과 V2 플랜을 함께 둘 수 있어요.
