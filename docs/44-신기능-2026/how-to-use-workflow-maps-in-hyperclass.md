# 워크플로우 맵(Workflow Maps) 사용하기

하이퍼클래스의 워크플로우 맵은 워크플로우, 폴더, 연결된 에셋을 한 화면에서 보여 줘요. 워크플로우를 하나씩 열지 않아도 자동화가 서로 어떻게 맞물려 있는지 알 수 있어요. 의존 관계를 살펴보고, 연락처 여정을 추적하고, 오류를 확인하고, 계정을 정리할 부분을 찾을 수 있어요. 이 문서에서는 워크플로우 맵의 기본 사용법과 주요 기능을 설명해요.

## 워크플로우 맵이란?

워크플로우 맵은 기존 워크플로우와, 워크플로우에 연결된 에셋을 시각적으로 보여 주는 작업 공간이에요. 지원하는 에셋에는 태그, 폼, 캘린더, 파이프라인, 커스텀 필드가 있어요.

예를 들어 폼을 제출하면 워크플로우가 시작되고, 그 워크플로우가 태그를 추가해 다른 워크플로우를 실행할 수 있어요. 워크플로우 맵을 보면 이런 관계를 한눈에 파악하고 전체 자동화 흐름을 이해할 수 있어요.

맵은 기존 워크플로우를 바탕으로 자동으로 만들어져요. 다이어그램을 직접 그릴 필요가 없어요. 서브 계정마다 맵이 따로 있어요.

**가용성:** 출시 시점에는 **에이전시 사용자와 에이전시 관리자**가 워크플로우 맵을 쓸 수 있어요. 출시 시연에서는 **실험실**(Labs) 제공 여부도 언급됐어요. 내 계정에서 실험실을 켜야 하는지 확인하세요.

---

## 워크플로우 맵의 주요 장점

워크플로우 맵을 쓰면 자동화 사이의 관계를 조사하고 계정을 더 깔끔하게 관리할 수 있어요.

- 한눈에 보기: 워크플로우, 폴더, 연결된 에셋을 함께 볼 수 있어요.
- 의존 관계 추적: 어떤 워크플로우가 특정 에셋을 사용하는지 확인할 수 있어요.
- 빠른 이동: 한 작업 공간에서 워크플로우를 검색하고, 필터링하고, 탐색할 수 있어요.
- 연락처 여정 추적: 연락처의 워크플로우 등록 이력을 확인할 수 있어요.
- 오류 조사: 실행에 실패한 워크플로우를 찾고 확인 가능한 세부 정보를 볼 수 있어요.
- 계정 정리: 폴더, 레이아웃, 정리할 만한 항목을 점검할 수 있어요.
- AI 도움: AI 어시스턴트로 내 자동화를 이해하는 데 도움을 받을 수 있어요.

## 워크플로우 맵 사용하기

처음 보는 계정을 파악할 때, 연락처가 겪은 일을 조사할 때, 자동화를 바꾸기 전에 의존 관계를 확인할 때 유용해요.

### 1단계: 워크플로우 맵 열기

1. 해당 서브 계정을 여세요.
2. **자동화 > 워크플로우**로 이동하세요.
3. **Workflow Maps**(워크플로우 맵)를 선택하세요.

**워크플로우 빌더**에서도 **Maps**(맵)를 열 수 있어요.

![워크플로우 맵 열기 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084426944/original/S2DEsxilztDm3JqrEU5uykA0hRmDKpnGkQ.png?1793199612)

### 2단계: 워크플로우 살펴보기

1. 맵에 표시된 워크플로우와 폴더를 확인하세요.
2. **맞춤**을 선택해 전체 화면을 한눈에 보세요.
3. 워크플로우나 에셋을 선택하세요.
4. 표시되는 세부 정보와 연결 관계를 확인하세요.

### 3단계: 특정 워크플로우나 에셋 찾기

1. **검색**을 여세요.
2. 워크플로우, 에셋, 트리거, 액션 중 하나의 이름을 입력하세요.
3. 검색 결과를 선택하세요.
4. 필요하면 **필터**를 적용해 보이는 범위를 좁힙니다.

### 4단계: 연결 관계 확인하기

1. 조사할 워크플로우나 에셋을 선택하세요.
2. 연결된 항목을 확인하세요.
3. **연결된 워크플로우**가 보이면 열어서 관련 워크플로우를 함께 살펴보세요.
4. 수정이 필요하면 **워크플로우 빌더**에서 해당 워크플로우를 여세요.

### 5단계: 연락처 여정 조사하기

1. 연락처 추적 화면을 여세요.
2. 연락처를 검색해서 선택하세요.
3. 확인할 수 있는 등록 이력을 살펴보세요.
4. 대기 중이거나 완료됐거나 실패한 활동을 확인하세요.

### 6단계: 오류와 정리 항목 확인하기

1. 오류 필터나 오류 검토 화면을 사용해 확인이 필요한 워크플로우를 찾으세요.
2. 오류가 난 실행을 확인하세요.
3. 워크플로우를 고쳐야 하면 **워크플로우 빌더**를 여세요.
4. **Cleanup**(정리) 결과가 보이면 확인해서 정리할 부분을 찾으세요.

### 7단계: 추가 도움 받기

1. 사용할 수 있다면 워크플로우 맵의 **AI 어시스턴트**를 여세요.
2. 조사 중인 워크플로우나 에셋에 대해 질문해요.
3. 온보딩 가이드나 **Resources**(리소스)에서 추가 안내를 확인하세요.

{% hint style="info" %}
중요한 에셋을 수정하기 전에 연결된 워크플로우를 먼저 확인하세요. 영향을 받는 곳을 미리 알 수 있어요.
{% endhint %}

## 워크플로우 맵 화면 이해하기

맵은 폴더 안에 워크플로우를 표시하고, 지원하는 에셋과의 관계를 보여 줘요. 각 요소를 알아 두면 변경하기 전에 자동화 사이의 의존 관계를 쉽게 파악할 수 있어요.

| 요소 | 설명 |
| --- | --- |
| 워크플로우 | 서브 계정에 있는 자동화 |
| 폴더 | 관련 워크플로우를 묶은 그룹 |
| 에셋 | 연결된 태그, 폼, 캘린더, 파이프라인, 커스텀 필드 등 지원하는 항목 |
| 연결 | 워크플로우나 에셋과 관련된 관계 |
| 스티커 메모 | 맵을 설명하기 위해 남기는 주석 |

워크플로우나 에셋을 선택하면 세부 정보와 연결 관계를 볼 수 있어요.

![워크플로우 맵 구성 요소 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084428102/original/hxFafz_ufzTQ7gJZ8ncCwNAjoGUjgWuBdQ.png?1793200169)

{% hint style="info" %}
워크플로우 맵은 자동화가 어떻게 설정되어 있는지를 보여 줘요. 특정 연락처가 화면에 보이는 모든 연결을 거쳤다는 뜻은 아니에요.
{% endhint %}

자세한 내용은 [맵 읽기와 연결 관계 이해하기](../07-워크플로우/Workflow-Maps/read-the-map-and-understand-connections.md)를 참고하세요.

## 워크플로우 맵 검색하고 탐색하기

검색과 탐색 기능을 쓰면 특정 워크플로우나 에셋을 찾고, 필요한 연결만 골라 볼 수 있어요.

사용할 수 있는 기능은 다음과 같아요.

- **검색:** 이름으로 워크플로우, 에셋, 트리거, 액션을 찾아요.
- **필터:** 지원하는 조건으로 맵에 보이는 범위를 좁혀요.
- **Pan and Zoom**(이동 및 확대/축소): 맵 안에서 이동하고 세부 내용을 확대해서 봐요.
- **맞춤:** 전체 맵이 보이도록 화면을 조정해요.
- **2D/3D:** 사용할 수 있는 보기 모드를 전환해요.

워크플로우 정보가 바뀌었다면 맵 데이터를 새로고침해서 최신 상태를 확인할 수 있어요.

{% hint style="info" %}
워크플로우나 에셋이 보이지 않으면 적용된 필터를 확인하고 맵을 새로고침한 뒤 계속 진행하세요.
{% endhint %}

자세한 방법은 [워크플로우 맵 탐색, 검색, 필터링하기](../07-워크플로우/Workflow-Maps/navigate-search-and-filter-workflow-maps.md)를 참고하세요.

## 연결된 워크플로우와 에셋 살펴보기

연결된 워크플로우와 에셋을 보면 한 자동화가 다른 자동화에 어떤 영향을 줄 수 있는지 이해할 수 있어요.

에셋을 선택하면 그 에셋과 관계가 있는 워크플로우가 나타나요. 예를 들어 태그를 바꾸기 전에 어떤 워크플로우가 그 태그를 쓰는지 조사할 수 있어요.

### 연결된 워크플로우와 Workflow view

**연결된 워크플로우**를 사용하면 관련 워크플로우를 한 화면에 모아 집중해서 볼 수 있어요.

기존 문서에서는 이 화면을 **Workflow view**(워크플로우 보기)라고 부르고, 출시 안내에서는 *Workflow Canvas*라는 이름도 써요. 하이퍼클래스 화면에 표시된 이름을 기준으로 따라 하세요.

![연결된 워크플로우 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084430958/original/Sy9D3MeVV8S_EyQvz4YDDcZnY1D5IIY0-w.png?1793201510)

![워크플로우 보기 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084431821/original/vh9HuhicxG6GQdUh2dcmSISKpu0EWH2cQA.png?1793201893)

{% hint style="warning" %}
워크플로우 맵은 연결 관계를 조사하는 도구예요. 워크플로우의 트리거, 액션, 내부 로직을 수정하려면 **워크플로우 빌더**에서 해당 워크플로우를 여세요.
{% endhint %}

## 연락처 여정 추적하기

**Contact Journeys**(연락처 여정)를 쓰면 한 연락처가 여러 워크플로우를 거치며 어떻게 진행됐는지 알 수 있어요.

연락처를 검색해서 확인 가능한 등록 이력을 볼 수 있어요. 완료된 활동, 대기 중인 단계, 실패한 실행도 포함돼요.

기존 문서에는 연락처 추적의 이력 조회 기간이 **60일**이라고 나와 있어요.

![연락처 여정 추적 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084432092/original/Szm2_lUgKeJ3fCCBR6SKX1fXw8C46cr-hw.png?1793202048)

{% hint style="info" %}
특정 연락처에게 무슨 일이 있었는지 알아볼 때는 연락처 여정을 쓰세요. 워크플로우가 서로 어떻게 연결되어 있는지 알고 싶을 때는 메인 맵을 보세요.
{% endhint %}

자세한 방법은 [워크플로우에서 연락처 추적하기](../07-워크플로우/Workflow-Maps/trace-a-contact-through-workflows.md)를 참고하세요.

## 워크플로우 오류 해결하기

워크플로우 맵에서 실행에 문제가 있는 자동화를 찾고, 문제가 생긴 단계를 확인할 수 있어요.

오류 표시를 살펴보고, 실패한 실행을 조사하고, 해당 워크플로우를 열어 추가로 문제를 해결할 수 있어요.

![워크플로우 오류 확인 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084432283/original/mi17RZl-2RKH3NmJAD_dky_6ShrOVKOjJw.png?1793202172)

{% hint style="warning" %}
**Mark as read**(읽음으로 표시)를 선택하면 오류 알림 배지만 사라져요. 워크플로우가 고쳐지거나 실패한 실행이 다시 시도되지는 않아요.
{% endhint %}

자세한 안내는 [오류가 있는 워크플로우 검토하기](../07-워크플로우/Workflow-Maps/review-workflows-with-errors.md)를 참고하세요.

## 맵 정리하기와 Cleanup 사용하기

워크플로우 맵에는 복잡한 자동화 환경을 이해하기 쉽게 유지해 주는 정리 도구가 있어요.

### 폴더와 레이아웃 정리하기

에이전시 관리자는 지원하는 워크플로우와 폴더를 정리하고, 배치를 조정하고, 공유 맵 레이아웃을 저장할 수 있어요.

저장한 정리 내용은 같은 서브 계정을 사용하는 다른 사용자에게도 영향을 줄 수 있어요.

{% hint style="info" %}
워크플로우 맵을 볼 수 있다고 해서 공유 레이아웃을 수정하고 저장할 권한까지 있는 것은 아니에요.
{% endhint %}

### Cleanup

출시 안내에서는 **Cleanup**(정리)을 유지 관리가 필요할 만한 항목을 찾는 기능이라고 설명해요. 찾아 주는 항목은 다음과 같아요.

- 기본 이름을 그대로 쓰는 워크플로우
- 최근 등록이 없는 워크플로우
- 비어 있는 폴더

이 결과를 보고 어떤 항목을 손봐야 할지 판단할 수 있어요.

![Cleanup 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084432606/original/pEEL63lbL8okp3izDqUuYyScAWwrausHVw.png?1793202313)

{% hint style="warning" %}
Cleanup의 기준, 권한, 관리 작업은 확인이 필요해요. Cleanup이 무언가를 자동으로 삭제하거나 고쳐 준다고 생각하지 마세요.
{% endhint %}

## AI 어시스턴트, 온보딩, 리소스

워크플로우 맵에는 맵을 이해하고 자동화 환경을 조사하는 데 도움이 되는 안내 기능이 있어요.

### AI 어시스턴트

출시 안내에서는 **AI 어시스턴트**가 워크플로우 연결, 문제 해결, 계정 정리에 관한 질문에 답해 준다고 설명해요.

예를 들어 특정 에셋에 연결된 워크플로우가 무엇인지 물어볼 수 있어요.

![AI 어시스턴트 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084432944/original/pEeT0QRNfwcjfTc-UoFW_KdI9u-kW1gfjA.png?1793202483)

{% hint style="info" %}
어시스턴트가 정확히 무엇을 할 수 있는지는 확인이 필요해요. 워크플로우를 직접 수정하거나 오류를 자동으로 해결해 준다고 생각하지 마세요.
{% endhint %}

### 온보딩과 리소스

온보딩 가이드와 **Resources**(리소스)는 화면 사용법을 익히고, 제공되는 안내 영상이나 참고 자료를 찾는 데 도움이 돼요.

정확한 메뉴와 내용은 기능 제공 상황에 따라 다를 수 있어요.

---

## 자주 묻는 질문

### 워크플로우 맵을 직접 만들어야 하나요?

아니요. 하이퍼클래스가 서브 계정의 기존 워크플로우와 지원하는 에셋 연결을 바탕으로 맵을 자동으로 만들어요.

### 워크플로우 맵은 누가 쓸 수 있나요?

출시 안내에는 출시 시점에 에이전시 사용자와 에이전시 관리자가 쓸 수 있다고 나와 있어요. 정확한 사용 대상과 실험실 활성화 필요 여부는 확인이 필요해요.

### 워크플로우 맵에서 워크플로우 단계를 직접 수정할 수 있나요?

아니요. 트리거, 액션, 내부 로직을 수정하려면 **워크플로우 빌더**에서 해당 워크플로우를 여세요.

### 워크플로우 맵에서 연락처의 전체 이력을 볼 수 있나요?

연락처 추적에서는 확인 가능한 워크플로우 이력을 보여 줘요. 기존 문서에는 이력 조회 기간이 60일이라고 나와 있어요.

### 맵에서 워크플로우가 보이지 않아요. 어떻게 하나요?

필터를 확인하고, 워크플로우를 검색해 보고, 맵 데이터를 새로고침하세요.

### 워크플로우 오류를 읽음으로 표시하면 오류가 해결되나요?

아니요. **Mark as read**는 알림 배지만 지워요. 근본적인 오류는 여전히 조사해야 해요.

### 누구나 맵 레이아웃을 바꿀 수 있나요?

아니요. 기존 문서에는 공유 레이아웃을 정리하고 저장하는 일은 에이전시 관리자 권한이라고 나와 있어요.

### Cleanup이 사용하지 않는 워크플로우를 자동으로 삭제하나요?

출시 안내에서는 Cleanup을 검토가 필요한 항목을 찾는 기능이라고 설명해요. 자동 삭제나 자동 수정은 확인되지 않았어요.

### AI 어시스턴트가 내 워크플로우를 수정할 수 있나요?

출시 안내에서는 자동화를 이해하고 문제를 해결하는 데 도움을 준다고 설명해요. 워크플로우 편집 기능은 따로 확인이 필요해요.
