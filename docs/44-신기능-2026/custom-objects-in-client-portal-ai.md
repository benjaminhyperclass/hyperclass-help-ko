# 클라이언트 포탈 AI에서 사용자 지정 객체 사용하기

클라이언트 포탈 AI가 사용자 지정 객체를 지원해요. 멤버가 입력한 정보를 하이퍼클래스 CRM에 바로 저장하는 포탈을 만들 수 있어요. 원하는 포탈을 문장으로 설명하면 필요한 사용자 지정 객체, 필드, 관계를 AI가 제안하고, 승인하기 전에는 아무것도 만들지 않아요.

## 클라이언트 포탈 AI의 사용자 지정 객체란?

클라이언트 포탈 AI의 사용자 지정 객체를 쓰면 하이퍼클래스 CRM에 저장된 정보를 수집하고 정리해서 보여 주는 멤버용 화면을 만들 수 있어요. 데이터 구조를 하나하나 직접 설정하지 않아도 돼요. 포탈이 어떤 일을 해야 하는지 설명하면, 클라이언트 포탈 AI가 필요한 사용자 지정 객체를 제안해요.

**사용자 지정 객체**(Custom Object)는 연락처, 회사, 기회 같은 기본 레코드에 담기 어려운 정보를 저장하는 CRM 레코드 유형이에요.

예를 들어 코칭 비즈니스에서는 전략 상담 신청서를 관리하는 데 쓸 수 있어요. 부동산 관리 회사에서는 입주자의 서비스 요청을 받는 데 쓸 수 있어요.

## 클라이언트 포탈 AI에서 사용자 지정 객체를 쓰면 좋은 점

사용자 지정 객체를 쓰면 AI가 만든 포탈이 정보를 보여 주기만 하는 화면에서 실제 업무에 쓰는 도구로 바뀌어요. 멤버가 제출한 내용이 CRM에 연결되므로, 데이터 구조를 직접 다 만들지 않아도 정리된 형태로 정보를 모을 수 있어요.

- AI가 설정을 도와줘요: 모으고 싶은 정보를 설명하면 클라이언트 포탈 AI가 알맞은 사용자 지정 객체 계획을 만들어요.
- CRM에 한곳에 모여요: 멤버가 제출한 신청서, 요청, 문의가 하이퍼클래스 서브 계정에 바로 저장돼요.
- 만들기 전에 승인해요: 객체 구조, 필드, 관계, 예시 레코드, 공개 범위를 확인한 뒤에 승인할 수 있어요.
- 데이터를 유연하게 정리해요: 비즈니스에 맞게 필드, 드롭다운 옵션, 연결을 구성한 사용자 지정 객체를 만들 수 있어요.
- 중복 객체가 줄어요: 새로 만들지 않고 쓸 만한 기존 사용자 지정 객체를 다시 활용할 수 있어요.
- 멤버가 레코드에 접근해요: 전용 포탈 페이지에서 멤버가 레코드를 제출하고 볼 수 있어요.
- 레코드 공개 범위를 고를 수 있어요: 개별 레코드, 회사에 연결된 레코드, 모든 레코드의 읽기 전용 접근을 지원해요.
- 결제를 받을 수 있어요: 지원되는 결제 제공업체를 연결하면 **결제**, **구매** 버튼과 하이퍼클래스 인보이스로 결제를 받을 수 있어요.
- 객체 한도를 관리할 수 있어요: 서브 계정이 사용자 지정 객체 한도에 가까워지면 선택할 수 있는 방법을 안내해 줘요.

## 클라이언트 포탈 AI에서 사용자 지정 객체 설정하기

멤버에게 받아야 할 정보를 분명하게 설명하는 것부터 시작해요. 승인하기 전에 AI가 만든 구조를 꼼꼼히 확인하면, 완성된 포탈 페이지와 CRM 레코드가 원하는 업무 흐름에 맞게 만들어져요.

멤버가 제출한 정보를 수집하고 저장하는 포탈을 만들려면 다음 단계를 따르세요.

1. 클라이언트 포탈 AI를 열어요.

   사용자 지정 객체를 만들 서브 계정에서 클라이언트 포탈 AI를 열고 새 포탈 만들기를 시작해요. 작업 중인 서브 계정이 맞는지 꼭 확인하세요.

   ![클라이언트 포탈 AI 시작 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083489441/original/mnnqqBlcAS884zE6DpMwPoqleHphSovA2Q.png?1792143479)

2. 포탈에 필요한 내용을 설명해요.

   포탈이 어떤 일을 해야 하고 멤버가 어떤 정보를 제출해야 하는지 문장으로 입력해요. 예를 들면 이렇게 쓸 수 있어요.

   "에이전시 운영자 8만 명이 있는 코칭 브랜드 Northstar Collective의 멤버 포탈이에요. 멤버는 예정된 워크숍을 둘러보고 1:1 전략 상담을 신청할 수 있어요."

   모으고 싶은 필드를 직접 적으면 더 구체적으로 요청할 수 있어요.

   "멤버가 사업체 이름, 월 매출 범위, 가장 큰 고민, 희망 상담 주제를 넣어 전략 상담 신청서를 제출할 수 있게 해 주세요. 멤버는 자신이 제출한 신청서를 볼 수 있어야 해요."

   요구 사항이 분명할수록 클라이언트 포탈 AI가 알맞은 데이터 구조와 멤버 화면을 제안해요.

   ![포탈 요구 사항을 입력하는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083489546/original/-B6xIDMfHmw7HdQHAZlEdWxHI3vfy5t7BA.png?1792143513)

3. 사용자 지정 객체를 쓸지 확인해요.

   요청에 저장할 정보가 필요하다고 판단하면 클라이언트 포탈 AI가 아래 질문을 보여 줘요.

   **"Use custom objects in your CRM for this?"**(이 작업에 CRM의 사용자 지정 객체를 사용할까요?)

   **예**를 선택하면 클라이언트 포탈 AI가 검토할 사용자 지정 객체 계획을 준비해요. 사용자 지정 객체를 쓰고 싶지 않으면 요청을 거절할 수 있어요.

   ![사용자 지정 객체 사용 여부를 묻는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083489710/original/VXJCQogK57aPE9BO3xFxELdLJGo02ZK2jA.png?1792143604)

4. 제안된 사용자 지정 객체 계획을 검토해요.

   클라이언트 포탈 AI가 만든 구성을 살펴봐요. 특히 다음을 확인하세요.

   - 제안된 사용자 지정 객체 이름
   - 필드와 드롭다운 옵션
   - 연락처, 회사 또는 다른 사용자 지정 객체와의 관계
   - 예시 레코드
   - 멤버의 레코드 공개 범위
   - 기존 객체를 재사용하는지 여부

   이 구조가 비즈니스에서 수집해야 할 정보와 맞는지 확인해요.

5. 필요하면 수정을 요청해요.

   계획에 바꿀 부분이 있으면 문장으로 설명해요. 예를 들면 이렇게 쓸 수 있어요.

   "신청 상태 드롭다운을 추가하고, 옵션은 신규, 검토 중, 승인, 거절로 해 주세요."

   클라이언트 포탈 AI가 제안한 계획을 고쳐 줘요. 수정된 구성을 다시 확인한 뒤에 다음 단계로 넘어가세요.

   ![계획 수정을 요청하는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083490094/original/ZZ45Xv0E_-fYETKn43uyN-pfjixr1hCzKA.png?1792143749)

6. 사용자 지정 객체 계획을 승인해요.

   계획이 요구 사항에 맞으면 승인해요. 그러면 클라이언트 포탈 AI가 승인된 사용자 지정 객체를 서브 계정의 CRM에 만들어요. 아직 진행할 준비가 안 됐다면 **나중에**를 선택해서 만들기를 미룰 수 있어요.

   ![계획을 승인하거나 나중으로 미루는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083490260/original/aXTg42MoTIeZgj0icfb4rt063mYNfSQKsQ.png?1792143834)

7. 만들어진 사용자 지정 객체를 열어요.

   만들기가 끝나면 클라이언트 포탈 AI 응답 아래에 새 사용자 지정 객체로 가는 링크가 보여요. 링크를 열어 CRM에 만들어진 객체를 확인하세요.

   CRM 레코드 관리 방법은 [사용자 지정 객체 레코드 만들기 및 업데이트](../36-기타/리커버리/creating-and-updating-custom-object-records.md)에서 더 자세히 볼 수 있어요.

8. 멤버에게 보이는 포탈 화면을 확인해요.

   만들어진 포탈 화면을 열고 사용자 지정 객체와 연결된 페이지를 찾아요. 다음을 확인하세요.

   - 필요한 사용자 지정 객체 페이지가 모두 있어요.
   - 제출 화면에 의도한 필드가 들어 있어요.
   - 레코드 공개 범위가 승인한 계획과 같아요.
   - 결제 동작이 포함되어 있다면 알맞게 설정되어 있어요.

9. 멤버 제출을 테스트해요.

   테스트용 멤버 계정으로 화면을 확인해요. 샘플 신청서나 요청을 제출한 뒤 CRM의 해당 사용자 지정 객체에 저장됐는지 확인하세요. 실제 멤버를 초대하기 전에 여러 테스트 계정으로 멤버별 공개 범위 규칙도 함께 테스트하세요.

10. 멤버가 포탈을 쓸 수 있게 열어요.

    포탈과 CRM 설정을 검토하고 테스트했다면, 클라이언트 포탈의 접근 및 초대 옵션으로 멤버에게 포탈을 열어 주세요. 포탈 기본 설정, 브랜딩, 도메인 설정, 초대 방법은 [클라이언트 포탈 설정하기](../39-클라이언트-포털/Client-Portal/how-to-set-up-the-client-portal.md)에서 확인할 수 있어요.

## 사용자 지정 객체를 쓸지 판단하는 방식

클라이언트 포탈 AI는 입력한 프롬프트를 보고 요청한 기능이 CRM에 정보를 저장해야 하는지 판단해요. 이 방식을 알아 두면 불필요하게 사용자 지정 객체를 만들지 않고 알맞은 포탈이 나오도록 프롬프트를 쓸 수 있어요.

멤버가 제출한 정보를 저장해야 하는 활동이 프롬프트에 있으면 클라이언트 포탈 AI가 다음 확인 질문을 보여 줘요.

**"Use custom objects in your CRM for this?"**(이 작업에 CRM의 사용자 지정 객체를 사용할까요?)

{% hint style="warning" %}
클라이언트 포탈 AI는 사용자 지정 객체 계획을 세우기 전에 먼저 확인을 요청해요. 프롬프트에 요청이나 신청 같은 활동이 나온다고 해서 객체가 바로 만들어지지는 않아요.
{% endhint %}

## AI가 만든 사용자 지정 객체 계획

사용자 지정 객체 계획은 포탈이 수집하는 정보를 담기 위해 필요한 CRM 구조를 정리한 거예요. 이 계획을 검토하면 멤버 제출 내용이 올바르게 정리되고 알맞은 CRM 레코드에 연결되는지 확인할 수 있어요.

**기존 사용자 지정 객체 재사용**

서브 계정에 알맞은 사용자 지정 객체가 이미 있으면 클라이언트 포탈 AI가 중복해서 만들지 않고 그 객체를 재사용할 수 있어요. 기존 객체를 재사용하면 CRM 데이터 구조를 일관되게 유지하고 남은 사용자 지정 객체 수도 아낄 수 있어요. 기존 객체가 새 포탈의 업무 흐름에 맞는지 제안 내용을 꼼꼼히 확인하세요.

## 사용자 지정 객체 승인과 수정

승인 과정에서 클라이언트 포탈 AI가 어떤 CRM 구조를 만들지 직접 정할 수 있어요. 승인하기 전에 계획을 검토하면 원하지 않는 객체, 불필요한 필드, 잘못된 데이터 관계를 막을 수 있어요. 클라이언트 포탈 AI가 계획을 만들면 구성을 확인하고 다음 중 하나를 선택하세요.

- **변경 요청**: 바꾸고 싶은 내용을 문장으로 설명해요.
- **승인**: 제안된 구성을 받아들이고 클라이언트 포탈 AI가 필요한 객체를 만들게 해요.
- **나중에**: 바로 승인하지 않고 제안된 객체 만들기를 미뤄요.

{% hint style="warning" %}
나중에 하는 변경 요청도 검토 과정을 거쳐요. 기존 사용자 지정 객체에 적용되는 제한도 그대로 유효해요. 예를 들어 하이퍼클래스에서는 객체를 만든 뒤에 기존 객체의 내부 이름이나 대표 표시 필드를 바꿀 수 없어요.
{% endhint %}

## 사용자 지정 객체 레코드와 결제

결제 동작을 쓰면 일부 사용자 지정 객체 흐름에서 멤버 화면 안에서 바로 결제를 받을 수 있어요. 신청, 등록, 요청 과정에서 결제가 필요할 때 유용해요.

클라이언트 포탈 AI는 하이퍼클래스 인보이스로 결제를 시작하는 **결제**, **구매** 버튼을 지원해요. 결제를 처리하려면 먼저 결제 제공업체를 연결해야 해요. 예를 들어 멤버가 유료 서비스 요청을 제출할 수 있는 포탈을 만들 수 있어요.

인보이스 설정은 [첫 인보이스 보내기](../08-결제/인보이스-견적/how-to-send-your-first-invoice-using-hyperclass.md)에서 더 자세히 볼 수 있어요.

## 사용자 지정 객체 한도와 재사용

사용자 지정 객체 한도는 서브 계정에서 유지할 수 있는 레코드 유형의 수를 정해요. 이 한도를 알아 두면 CRM 용량을 불필요하게 쓰지 않고 AI 포탈 기능을 계획할 수 있어요.

하이퍼클래스는 서브 계정당 사용자 지정 객체를 최대 **10개**까지 지원해요. 클라이언트 포탈 AI는 한 계획에서 객체를 최대 3개까지 제안할 수 있지만, 서브 계정 전체 한도는 그대로 적용돼요. 남은 용량이 부족하면 검토 과정에서 다음 옵션을 안내해요.

- 원래 용도로는 더 이상 필요 없는 기존 사용자 지정 객체를 재사용해요.
- 사용 가능한 사용자 지정 객체 슬롯을 비워요.
- 제안된 객체 만들기를 건너뛰어요.

예를 들어 서브 계정에 이미 사용자 지정 객체가 9개 있다면 추가로 만들 수 있는 객체는 1개뿐이에요. 새 객체를 여러 개 포함한 제안은 용량을 정리하거나 기존 객체를 재사용해야 해요.

{% hint style="warning" %}
기존 사용자 지정 객체를 삭제하는 것은 쓰지 않는 설정을 단순히 치우는 것과 달라요. 하이퍼클래스 문서에 따르면 삭제하면 객체와 관련된 레코드, 필드, 연결, 종속된 설정이 영구적으로 삭제돼요. 용량을 확보하려고 객체를 삭제하기 전에 어떤 결과가 생기는지 꼭 확인하세요.
{% endhint %}

자세한 내용은 [모든 요금제에서 사용자 지정 객체 제공 + 한도 상향](../02-연락처/custom-objects-in-all-plans-higher-limit.md)에서 확인하세요.

## 지원 플랫폼과 사용 가능 범위

플랫폼별 지원 범위는 AI가 만든 사용자 지정 객체 기능을 어디에서 쓸 수 있는지 알려 줘요. 포탈을 만들기 전에 지원되는 환경을 확인하면 호환성 문제를 막을 수 있고, 앞으로 출시될 기능도 알 수 있어요.

| 플랫폼 또는 환경 | 지원 여부 |
| --- | --- |
| 클라이언트 포탈 (웹) | 지원 |
| Vibe — Describe it(설명하기) 워크플로우 | 지원 |
| 브랜드 모바일 앱 | 아직 지원하지 않아요 |

## 자주 묻는 질문

### 승인 단계에서 나중에를 선택하면 어떻게 되나요?

**나중에**를 선택하면 제안된 사용자 지정 객체 만들기를 미뤄요. 승인하지 않은 상태이므로 그 제안에 포함된 객체는 만들어지지 않아요. 끝내지 않은 제안이 나중에 다시 열 수 있도록 남아 있는지는 릴리스 노트에 나와 있지 않아요.

### 이미 레코드가 들어 있는 사용자 지정 객체도 클라이언트 포탈 AI가 재사용할 수 있나요?

클라이언트 포탈 AI는 기존 사용자 지정 객체를 재사용하자고 제안할 수 있어요. 승인하기 전에 그 객체의 현재 필드, 관계, 사용 목적이 새 포탈과 맞는지 확인하세요. 재사용 조건이 모두 릴리스에 나와 있지는 않아요.

### 클라이언트 포탈 AI가 사용자 지정 객체를 만든 뒤에 수정할 수도 있나요?

나중에 바꾸려는 내용도 다시 검토 과정을 거쳐요. 다만 CRM에서 허용되는 변경은 하이퍼클래스의 기존 사용자 지정 객체 제한을 그대로 따라요. 내부 이름과 대표 표시 필드를 바꿀 수 없다는 제한도 여기에 포함돼요.

### 클라이언트 포탈 AI로 사용자 지정 객체를 3개보다 많이 만들 수 있나요?

AI는 한 번에 최대 3개의 객체를 제안할 수 있어요. 이것이 서브 계정당 사용자 지정 객체 10개라는 전체 한도를 바꾸지는 않아요. 여러 번에 걸친 계획의 누적 한도를 따로 정하는지는 릴리스에 나와 있지 않아요.

### 회사 단위 공개 범위는 CRM 연결에 따라 달라지나요?

릴리스에서는 회사 단위 레코드 공개 범위와 CRM 관계를 지원한다고 확인해 줘요. 회사 소속과 접근 권한을 판단하는 정확한 규칙은 포탈을 설정할 때 직접 확인하는 것이 좋아요.
