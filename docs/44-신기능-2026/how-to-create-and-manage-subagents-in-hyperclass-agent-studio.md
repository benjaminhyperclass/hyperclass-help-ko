# 에이전트 스튜디오에서 서브에이전트 만들고 관리하기

하이퍼클래스의 **관리형 에이전트**(Managed Agents)는 서브에이전트를 활용해 복잡한 여러 단계의 작업을 팀으로 처리할 수 있어요. 메인 에이전트가 전문 작업을 나눠 맡기고, 서로 관련 없는 작업은 동시에 진행하며, 결과를 검토한 뒤에 응답해요.

이 방식으로 조사, CRM 업데이트 같은 업무를 더 효율적이고 정확하게 자동화하고, 실행 과정도 확인할 수 있어요.

---

## 관리형 에이전트의 서브에이전트란?

서브에이전트는 메인 관리형 에이전트 아래에서 일하는 전문 AI 에이전트예요. 각 서브에이전트는 하나의 구체적인 작업과 그에 필요한 앱, 도구, 정보를 받아요. 메인 에이전트는 전체 실행을 조율하고 결과를 확인해요.

관리형 에이전트 팀은 다음으로 이루어져 있어요.

- 메인 에이전트(조정자): 작업을 계획하고, 업무를 나눠 맡기고, 결과를 검토하고, 응답해요.
- 서브에이전트(전문가): 관련 도구와 앱 연결을 사용해 맡은 작업을 실행해요.
- 작업 보고서: 결과를 조정자에게 돌려보내 검토와 취합을 받아요.

예를 들어 영업 에이전트는 회사 조사와 CRM 분석을 각각 다른 전문가에게 맡기고, 그 결과를 하나로 합쳐 바로 실행할 수 있는 응답을 만들어요.

노드 기반의 시각적 방식으로 오케스트레이션하는 플로우 에이전트(Flow Agents)와 달리, 서브에이전트는 관리형 에이전트 안에서 동작해요.

---

## 서브에이전트의 주요 장점

서브에이전트는 복잡한 작업을 구체적인 작업으로 나눠 불필요한 처리를 줄여요. 그래서 실행 속도, 정확도, 실행 과정의 가시성이 좋아져요.

- 복잡한 작업 자동화: 하나의 긴 실행 대신, 조율된 전문가들이 여러 단계의 작업을 처리해요.
- 빠른 실행: 서로 관련 없는 작업을 동시에 실행해요. 내부 테스트에서 4개 작업을 동시에 실행했을 때 실행 시간이 47% 줄었어요.
- 낮은 모델 비용: 작업별로 짧아진 컨텍스트 덕분에 처리량이 줄어요. 내부 테스트에서 평균 모델 비용이 49% 낮았어요.
- 정확도 향상: 조정자가 응답하기 전에 전문가의 결과를 검토해요. 내부 테스트에서 성공한 실행이 87%에서 91%로 늘었어요.
- 전문 작업 실행: 조사, CRM 분석, 기회 업데이트, Notion 업데이트 등 권한이 있는 작업을 맡길 수 있어요.
- 실행 과정 확인: 전문가의 작업, 보고서, 출처, 상태, 변경 내용을 직접 살펴볼 수 있어요.
- 권한 제어: 서브에이전트가 맡은 일에 필요한 앱, 레코드, 작업만 쓰도록 제한할 수 있어요.

## 성능 결과

2026년 10월에 하이퍼클래스가 내부 테스트를 진행했어요. 같은 작업과 지침을 서브에이전트로 처리했을 때와 단일 에이전트로 처리했을 때를 비교했어요.

| 항목 | 결과 |
| --- | --- |
| 평균 모델 비용 | 49% 낮음 |
| 성공한 실행 | 91% (단일 에이전트 87%) |
| 4개 작업 동시 실행 시 실행 시간 | 47% 감소 |
| 테스트한 커스텀 트리거 에이전트의 모델 비용 | 44% 낮음 |

추가 내부 테스트 정보에 따르면, 일부 트리거 기반 실행에서는 최대 80%까지 절감됐어요.

이 수치는 내부 테스트 결과이며, 비용 절감이나 성능 향상을 보장하는 것은 아니에요. 실제 결과는 작업량, 작업의 복잡도, 사용하는 도구, 실행 조건에 따라 달라져요.

## 서브에이전트에게 업무를 맡기는 과정

메인 에이전트는 요청을 구체적인 작업으로 나누고, 알맞은 전문가에게 맡긴 뒤, 응답하기 전에 결과를 검토해요. 서로 관련 없는 작업은 동시에 실행하고, 앞선 결과가 필요한 작업은 정해진 순서에 따라 실행해요.

1. 계획: 메인 에이전트가 요청을 분석해 해야 할 작업을 정리해요.
2. 위임: 전문가가 구체적인 지시, 관련 컨텍스트, 알맞은 도구 접근 권한을 받아요.
3. 실행: 서로 관련 없는 작업은 동시에 실행하고, 앞선 결과가 필요한 작업은 그 결과를 기다려요.
4. 검토: 메인 에이전트가 전문가의 보고서를 확인하고, 필요하면 추가 작업을 요청해요.
5. 응답: 조정자가 결과를 취합하거나 권한이 있는 작업을 마무리해요.

예시: 관리형 에이전트에게 Orangetheory, F45 Training, Barry's, CorePower Yoga를 비교해 달라고 요청해 보세요. 에이전트가 회사 조사를 전문가들에게 동시에 맡기고, 결과를 검토하고, 필요하면 추가 조사를 요청한 뒤, 하나로 정리한 비교 결과를 돌려줘요.

각 전문가는 전체 대화가 아니라 맡은 작업의 컨텍스트만 사용하기 때문에 불필요한 처리가 줄어요.

## 서브에이전트 설정과 관리

관리형 에이전트는 일상적인 말로 쓴 지시만으로 전문가 팀을 만들고 조정할 수 있어요. 빌더가 업무를 나눠 맡기는 편이 좋은지 판단하고, 요청한 작업에 맞춰 전문가를 구성해요.

### 1. 서브에이전트 만들기

원하는 결과를 빌더에게 설명하세요. 필요한 작업과 앱도 함께 적어 주세요.

예시 프롬프트: "영업 파이프라인을 자동화할 수 있는 영업 에이전트 팀을 만들어 줘."

빌더는 영업 파이프라인 팀을 만들고, 리드 조사 담당(Lead Researcher), 파이프라인 관리 담당(Pipeline Steward) 같은 전문가를 구성할 수 있어요.

**서브에이전트** 행에서 생성된 전문가를 확인하고, 맡은 역할이 맞는지 살펴보세요.

![서브에이전트 행에서 생성된 전문가 확인](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084144126/original/UVj7hyZoO55fDbNjvtSqYA62J5-QtY_fGg.png?1792939480)

### 2. 서브에이전트 추가·수정하기

팀을 바꾸고 싶다면 빌더에게 쉬운 말로 요청하세요.

예시:

- "이 작업을 조사 서브에이전트와 CRM 업데이트 서브에이전트로 나눠 줘."
- "캘린더를 확인하는 서브에이전트를 추가해 줘."
- "기회 레코드를 검토하는 전문가를 만들어 줘."
- "조사 전문가는 읽기 전용으로 바꿔 줘."

변경할 때마다 **서브에이전트** 행에서 바뀐 내용을 확인하세요.

{% hint style="info" %}
모든 요청에 서브에이전트가 필요한 것은 아니에요. 팀을 구성하는 것이 도움이 되는지는 빌더가 판단해요.
{% endhint %}

### 3. 서브에이전트와 커스텀 스킬의 차이

각 기능은 용도가 달라요.

- 서브에이전트: 맡겨진 작업을 실행하는 전문 작업자예요.
- 커스텀 스킬(Custom Skills): 작업을 어떻게 수행할지 정해 둔, 재사용할 수 있는 지침이에요.
- 앱과 도구: 정보를 가져오거나 권한이 있는 작업을 수행할 때 쓰는 연결된 기능이에요.

예를 들어 리드 조사 서브에이전트는 리드 자격 판단 규칙이 담긴 커스텀 스킬을 따라 일할 수 있어요.

자세한 내용은 [관리형 에이전트용 커스텀 스킬 만들기](../13-AI-Employee/Agent-Studio/create-custom-skills-for-managed-agents-in-hyperclass.md)를 참고하세요.

## 서브에이전트 활동 확인하기

서브에이전트 활동에서는 메인 에이전트가 어떻게 업무를 나눠 맡겼는지, 어떤 전문가가 어떤 작업을 마쳤는지, 최종 응답이 어떻게 만들어졌는지 볼 수 있어요. 결과를 검증하고, 바뀐 내용을 파악하고, 실행 중 생긴 문제를 조사하는 데 도움이 돼요.

### 서브에이전트 활동 보기

업무를 맡긴 내용이 포함된 응답 아래에서 **하위 에이전트 활동 보기**를 클릭하세요.

활동 패널에서 다음 내용을 볼 수 있어요.

- **Team Flow**(팀 흐름): 조정자, 전문가 작업, 검토, 최종 응답의 흐름이에요.
- **Task Status and Duration**(작업 상태 및 소요 시간): 실행 상태와 완료까지 걸린 시간이에요.
- **What Changed**(변경 내용): 실행 중 이루어진 작업이나 변경 사항의 요약이에요.
- **Specialist Details**(전문가 상세): 배정된 서브에이전트와 맡은 역할이에요.
- **Task Reports**(작업 보고서): 결과, 출처, 실행 단계, 확인 가능한 지시 내용이에요.
- **Activity Timeline**(활동 타임라인): 업무 위임, 검토, 응답을 시간순으로 보여 줘요.

![서브에이전트 활동 패널](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084144185/original/Yxm-dm5U_YUVd9vTO_cLoOgCfpW9mrn2gg.png?1792939674)

### 개별 작업 검토하기

1. 관리형 에이전트 대화를 여세요.
2. **하위 에이전트 활동 보기**를 클릭하세요.
3. 흐름이나 타임라인에서 전문가 작업을 하나 선택하세요.
4. 확인할 수 있는 범위에서 결과, 단계, 출처, 지시 내용, 전체 보고서를 살펴보세요.
5. 전문가의 조사 결과를 조정자의 최종 응답과 비교하세요.

경쟁사 조사, CRM 업데이트처럼 여러 전문가가 함께한 작업을 검증할 때 유용해요.

![개별 전문가 작업 검토 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084144156/original/4MJtmlcP1jPjtIhfTr5VngMKbsjnyvEn0g.png?1792939643)

### 트리거 및 API 실행

서브에이전트는 지원되는 트리거, 대기, 후속 조치, API 실행에서도 동작해요.

자동으로 실행된 내용은 관리형 에이전트의 **활동** 탭에서 확인하세요. 자세한 실행 단계와 문제 해결은 **에이전트 로그**에서 볼 수 있어요.

자세한 내용은 [관리형 에이전트 활동 피드](../13-AI-Employee/Agent-Studio/managed-agent-activity-feed-monitor-debug-ai-agents.md)를 참고하세요.

## 서브에이전트 권한과 실행 보호 장치

서브에이전트는 작업별 권한을 사용해 불필요한 접근과 허가되지 않은 변경을 제한해요. 메인 에이전트의 앱 연결을 통해 동작하지만, 각 작업은 배정된 범위 안으로 제한돼요.

- 읽기 전용 작업: 조사와 조회 작업은 레코드를 수정할 수 없어요.
- 범위가 정해진 업데이트: 업데이트 작업은 지시 내용과 권한으로 허용된 레코드만 수정할 수 있어요.
- 공유 연결: 서브에이전트는 메인 에이전트에 이미 있는 앱 연결을 사용해요.
- 제한된 도구: Computer(브라우저 조작)와 Custom API 호출은 메인 에이전트만 사용해요.
- 메시지 검토: 전문가가 작성한 고객 메시지는 메인 에이전트가 보내기 전에 확인해요.
- 반복 호출 방지: 진전 없이 같은 도구를 반복해서 호출하는 서브에이전트는 중단될 수 있어요.

예를 들어 조사 서브에이전트는 CRM 레코드를 수정하지 않고 연락처를 분석할 수 있어요. 별도의 업데이트 전문가는 명확히 허용된 기회 레코드만 변경할 수 있어요.

{% hint style="warning" %}
도구를 사용할 수 있는지는 실행 방식에 따라 달라요. Computer 기능은 현재 채팅과 수동 실행에서만 지원되고 트리거에서는 지원되지 않아요. 그렇다고 모든 서브에이전트 업무 위임이 수동 실행으로 제한되는 것은 아니에요.
자세한 내용은 [AI 에이전트용 스킬 플랫폼](../19-에이전시-뷰/skills-platform-for-ai-agents.md)을 참고하세요.
{% endhint %}

## 서브에이전트 비용과 사용량

서브에이전트는 전체 대화를 모든 단계에 끌고 가는 대신 작업별로 짧은 지시를 사용해서 모델 처리 비용을 줄여요. 메인 에이전트는 계획과 검토를 맡고, 전문가는 구체적인 작업을 수행해요. 이때 더 가벼운 모델을 쓸 수도 있어요.

2026년 10월 내부 테스트에서 확인된 내용은 다음과 같아요.

- 테스트한 작업 전체에서 평균 모델 비용이 49% 낮았어요.
- 테스트한 커스텀 트리거 에이전트의 모델 비용이 44% 낮았어요.
- 보완 내부 테스트에 따르면, 일부 트리거 기반 실행에서는 모델 비용이 최대 80% 낮았어요.
- 4개 작업을 동시에 처리한 테스트에서 실행 시간이 47% 줄었어요.

![서브에이전트 비용 및 사용량 비교](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084144203/original/0GQyTmbgfyDRjVRh5C7AbkXMZr4Jhx-39Q.png?1792939708)

서브에이전트 작업은 상위 관리형 에이전트 실행의 일부로 청구돼요. 서브에이전트만의 별도 청구 항목은 없어요.

## 관리형 에이전트에서 서브에이전트 설정하기

관리형 에이전트를 잘 설정하면 전문가에게 알맞은 역할과 권한이 주어져요. 게시하기 전에 테스트하면 업무 위임, 레코드 접근, 최종 응답이 의도한 대로 동작하는지 확인할 수 있어요.

### 1단계: 관리형 에이전트 열기

1. 하이퍼클래스 서브 계정에 로그인하세요.
2. **AI 에이전트 > 에이전트 스튜디오 > Managed**(관리형)로 이동하세요.
3. 기존 에이전트를 열거나 **+ 에이전트 만들기**를 클릭하세요.

![관리형 에이전트 목록 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084144222/original/bRMeapmltsG1gQuijvvpYTddRuqtbxll2Q.png?1792939784)

### 2단계: 작업 설명하기

원하는 워크플로우를 일상적인 말로 입력하세요.

예시: "잠재 고객을 조사하고, CRM 기회를 검토하고, 정체된 딜을 찾아내고, 다음 단계를 추천하는 영업 파이프라인 팀을 만들어 줘."

빌더가 에이전트 구성을 만들고, 전문가가 필요한지 판단해요.

### 3단계: 서브에이전트 팀 검토하기

1. 생성된 에이전트 설명을 확인하세요.
2. **서브에이전트** 행을 찾으세요.
3. 각 전문가의 역할과 책임을 살펴보세요.
4. 팀 구성이 의도한 워크플로우와 맞는지 확인하세요.

![생성된 서브에이전트 팀 확인](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084144284/original/GyONtFt95-9VRahD8KV2e6uSr6zv_XPIOQ.png?1792939957)

### 4단계: 팀 다듬기

전문가를 추가하거나 제거하거나 조정하고 싶다면 빌더에게 요청하세요.

예시: "CRM 업데이트를 추천하기 전에 기존 기회를 확인하는 전문가를 추가해 줘."

바뀐 내용은 **서브에이전트** 행에서 확인하세요.

### 5단계: 앱과 권한 검토하기

1. 메인 에이전트에 연결된 앱과 도구를 확인하세요.
2. 지침과 사용하도록 설정한 커스텀 스킬을 검토하세요.
3. 읽기 전용 권한과 업데이트 권한이 알맞게 설정됐는지 확인하세요.
4. 민감한 작업은 권한이 있는 작업으로만 제한하세요.

서브에이전트는 작업별 제한 안에서 메인 에이전트의 앱 연결을 사용해요.

### 6단계: 에이전트 테스트하기

1. **에이전트 테스트**를 클릭하세요.
2. 실제 업무와 비슷한, 여러 단계가 필요한 요청을 보내세요.
3. 응답과 맡겨진 작업을 살펴보세요.
4. **하위 에이전트 활동 보기**를 여세요.
5. 전문가의 결과, 작업 범위, 최종 응답을 확인하세요.

예시: "이 잠재 고객의 CRM 상세 정보, 진행 중인 기회, 최근 메모, 공개된 회사 정보를 검토해 줘. 그리고 다음에 할 일을 추천해 줘."

### 7단계: 게시하고 실행하기

1. 구성과 권한을 다시 확인하세요.
2. 지원되는 트리거가 있다면 추가하세요.
3. **게시**를 클릭하세요.
4. 채팅이나 다른 지원되는 실행 방식으로 에이전트를 실행하세요.
5. 실행 결과로 나온 활동을 확인하세요.

서브에이전트는 채팅, 해당되는 트리거, 대기, 후속 조치, API 실행을 지원해요. 개별 도구에는 실행 방식에 따라 별도 제한이 있을 수 있어요.

자세한 내용은 [관리형 에이전트의 예약 트리거](../13-AI-Employee/Agent-Studio/scheduled-triggers-for-managed-agents-in-hyperclass.md)를 참고하세요.

### 8단계: 검토하고 개선하기

실행이 끝나면 서브에이전트 활동과 **에이전트 로그**를 살펴보고, 작업 결과와 레코드 변경 내용을 확인하세요. 필요하면 에이전트의 지침이나 전문가의 역할을 다듬으세요. 중요한 변경은 자동화된 워크플로우에 적용하기 전에 테스트하세요.

## 자주 묻는 질문

### 관리형 에이전트의 모든 작업에 서브에이전트가 필요한가요?

아니요. 업무를 나눠 맡기는 것이 도움이 되는지는 빌더가 판단해요. 간단한 요청은 전문가 없이 실행될 수 있어요.

### 여러 서브에이전트가 동시에 일할 수 있나요?

네. 서로 관련 없는 작업은 동시에 실행되고, 앞선 결과가 필요한 작업은 정해진 순서에 따라 실행돼요.

### 서브에이전트가 CRM 레코드를 업데이트할 수 있나요?

네, 권한이 있는 경우에는 가능해요. 읽기 전용 작업은 레코드를 수정할 수 없고, 업데이트 작업은 배정된 범위 안으로 제한돼요.

### 서브에이전트마다 앱을 따로 연결해야 하나요?

아니요. 서브에이전트는 작업별 제한을 적용한 상태로 메인 에이전트의 연결을 사용해요.

### 서브에이전트가 Computer나 Custom API를 직접 사용할 수 있나요?

아니요. 이 기능들은 메인 에이전트만 사용해요.

### 서브에이전트를 자동 트리거로 실행할 수 있나요?

네, 지원되는 트리거 유형에서는 가능해요. 개별 기능에는 실행 방식에 따라 추가 제한이 있을 수 있어요.

### 서브에이전트를 쓰면 항상 비용과 실행 시간이 줄어드나요?

아니요. 내부 테스트에서는 개선 효과가 확인됐지만, 실제 결과는 작업량, 작업의 복잡도, 사용하는 도구, 작업 간 의존 관계에 따라 달라져요.

### 서브에이전트가 같은 도구를 계속 호출하면 어떻게 되나요?

반복 호출 방지 기능이 진전 없이 같은 도구를 호출하는 서브에이전트를 중단시킬 수 있어요. 더 자세히 살펴보려면 **활동** 탭이나 **에이전트 로그**를 확인하세요.

### 서브에이전트별 결과를 따로 볼 수 있나요?

네. 서브에이전트 활동에서 전문가 작업, 확인 가능한 보고서, 출처, 실행 세부 정보를 볼 수 있어요.

### 서브에이전트는 플로우 에이전트, 커스텀 스킬과 어떻게 다른가요?

서브에이전트는 관리형 에이전트 안에서 맡겨진 작업을 실행해요. 플로우 에이전트는 시각적인 워크플로우를 사용하고, 커스텀 스킬은 재사용할 수 있는 지침을 제공해요.
