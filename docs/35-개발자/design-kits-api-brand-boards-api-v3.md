# 디자인 킷 API – 브랜드 보드 API v3

브랜드 보드 REST API v3의 디자인 킷(Design Kits) API로 하이퍼클래스 로케이션(서브 계정)의 디자인 킷을 코드로 관리하는 방법을 안내해요.

디자인 킷 API를 쓰면 마켓플레이스 개발자가 REST 엔드포인트로 로케이션의 디자인 킷을 만들고, 조회하고, 수정하고, 삭제할 수 있어요. 디자인 킷에는 색상, 글꼴 같은 브랜드 디자인 데이터가 담기며, 이 데이터는 하이퍼클래스의 **브랜드 보드**(Brand Boards)에서 쓰여요.

디자인 킷 API 문서는 하이퍼클래스 마켓플레이스 개발자 포털에서 확인할 수 있어요. 이 문서에서는 엔드포인트 6개, 인증 방식, 디자인 킷 API가 브랜드 보드 API v3 전체에서 어떤 위치인지 설명해요.

## 디자인 킷 API란?

디자인 킷 API는 브랜드 보드 API v3에 포함된 공개 REST API예요. 마켓플레이스 개발자는 이 API로 하이퍼클래스 로케이션의 디자인 킷을 코드로 관리할 수 있어요. 디자인 킷에는 색상, 글꼴 같은 시각 요소가 저장되고, 하이퍼클래스 곳곳에서 쓰여요. 특히 **브랜드 보드**와 페이지 제작에서 많이 쓰여요.

하이퍼클래스 화면의 **브랜드 보드**에서 하던 디자인 킷 작업을 이 API로도 똑같이 할 수 있어요. 표준 REST 방식으로 로케이션의 디자인 킷을 만들고, 가져오고, 수정하고, 삭제하고, 기본 디자인 킷으로 지정할 수 있어요.

디자인 킷 API는 앞서 같은 브랜드 보드 API v3 아래에 출시된 브랜드 보이스(Brand Voices) v3 엔드포인트와 함께 쓰면 좋아요. 두 API를 함께 쓰면 로케이션의 브랜드 자산을 코드로 폭넓게 다룰 수 있어요.

## 주요 장점

마켓플레이스 개발자와 연동 파트너는 디자인 킷 API로 다음과 같은 이점을 얻을 수 있어요.

- 코드로 관리: **브랜드 보드** 화면을 직접 조작하지 않고도 디자인 킷을 만들고, 조회하고, 수정하고, 삭제할 수 있어요. 자동화와 일괄 작업에 알맞아요.
- 외부 연동: 외부 개발자 앱과 파트너 앱이 로케이션의 브랜드 디자인 데이터를 직접 관리할 수 있어요. 여러 시스템에 걸친 워크플로우도 구성할 수 있어요.
- 브랜드 전체 제어: 브랜드 보이스 API와 함께 쓰면 콘텐츠(브랜드 보이스)와 디자인(디자인 킷) 양쪽을 모두 코드로 다룰 수 있어요.
- 표준 OAuth 2.0 보안: 다른 하이퍼클래스 마켓플레이스 API와 같은 인증·권한 체계를 써서, 연동 전반에 일관된 보안을 적용할 수 있어요.
- 버전 관리와 문서화: v3 API 목록에 포함되어 있고, 하이퍼클래스 마켓플레이스 개발자 포털에서 자세한 문서를 볼 수 있어요.

## 사용할 수 있는 엔드포인트

디자인 킷 API는 기본 경로 `/brand-boards/locations/:locationId/design-kits` 아래에 REST 엔드포인트 6개를 제공해요. 모든 엔드포인트는 경로 파라미터에 유효한 로케이션 ID가 필요해요.

### 엔드포인트 1

`GET /design-kits` — 로케이션의 디자인 킷 목록 조회

지정한 로케이션에 연결된 디자인 킷을 모두 가져와요. 색상, 글꼴, 그 밖의 시각 설정 같은 브랜드 디자인 데이터가 담긴 디자인 킷 객체를 배열로 반환해요.

### 엔드포인트 2

`POST /design-kits` — 로케이션에 디자인 킷 만들기

지정한 로케이션에 새 디자인 킷을 만들어요. 요청 본문에 디자인 킷 설정 데이터를 담아 보내면, 고유 식별자가 포함된 새 디자인 킷 객체를 반환해요.

### 엔드포인트 3

`GET /design-kits/:designKitId` — ID로 디자인 킷 조회

고유 식별자로 특정 디자인 킷 하나를 가져와요. 모든 브랜드 디자인 속성이 포함된 디자인 킷 객체 전체를 반환해요.

### 엔드포인트 4

`PATCH /design-kits/:designKitId` — ID로 디자인 킷 수정

기존 디자인 킷을 일부만 수정해요. 요청 본문에 포함한 속성만 바뀌어요. 수정된 디자인 킷 객체를 반환해요.

### 엔드포인트 5

`DELETE /design-kits/:designKitId` — ID로 디자인 킷 삭제

로케이션에서 디자인 킷을 완전히 삭제해요. 이 작업은 되돌릴 수 없어요. 삭제에 성공하면 확인 응답을 반환해요.

### 엔드포인트 6

`POST /design-kits/:designKitId/default` — 기본 디자인 킷 지정

특정 디자인 킷을 로케이션의 기본 디자인 킷으로 지정해요. 이전에 기본이던 디자인 킷은 자동으로 해제돼요. 기본 디자인 킷은 브랜드가 적용된 새 자산을 만들 때 자동으로 적용돼요.

## 인증과 권한

디자인 킷 API는 다른 하이퍼클래스 마켓플레이스 API와 같은 표준 OAuth 2.0 인증을 사용해요. API를 요청하기 전에 OAuth 2.0 인증 흐름으로 유효한 액세스 토큰을 먼저 받아야 해요.

모든 API 요청은 Authorization 헤더에 Bearer 토큰 방식으로 액세스 토큰을 담아 보내야 해요. 토큰에는 대상 로케이션의 브랜드 보드 리소스에 접근할 수 있는 스코프가 있어야 해요.

하이퍼클래스 마켓플레이스 API에 OAuth 2.0 인증을 구현하는 방법은 하이퍼클래스 마켓플레이스 개발자 포털의 인증 문서를 참고하세요.
