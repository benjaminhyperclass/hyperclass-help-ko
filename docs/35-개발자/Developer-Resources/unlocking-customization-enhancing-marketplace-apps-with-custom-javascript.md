# 마켓플레이스 앱에 사용자 지정 JavaScript·CSS 추가하기

에이전시가 배포하는 **마켓플레이스 앱**(Marketplace Apps)에 사용자 지정 JavaScript와 CSS를 넣어 기능과 화면을 원하는 대로 바꾸는 방법을 안내해요. 스크립트를 제출하기 전에 지켜야 할 검토 기준과 테스트 방법도 함께 알려 드려요.

## 개요

사용자 지정 JavaScript 기능을 쓰면 **마켓플레이스 앱**에 JavaScript 코드를 추가할 수 있어요. 개발자는 에이전시가 배포하는 앱 안에서 하이퍼클래스의 기능을 개인화하고 확장할 수 있어요.

JavaScript와 CSS를 하이퍼클래스에 넣으면 앱의 기능과 디자인을 더 폭넓게 바꾸고, 화면에서 더 다양한 상호작용을 만들 수 있어요. 다만 하이퍼클래스의 안정성, 보안, 성능을 지키기 위해 모든 사용자 지정 스크립트는 철저한 검토를 거쳐야 배포할 수 있어요.

## 배분 유형

앱에서 사용할 수 있는 **배분 유형**은 다음과 같아요.

- 대상 사용자: 에이전시
- 대상 사용자: 서브 계정, 설치자: 에이전시만

## 검토 절차와 가이드라인

에이전시 배포 앱에 사용자 지정 JavaScript나 CSS를 제출할 때는 아래 가이드라인을 지켜 주세요. 그래야 검토가 순조롭게 진행돼요.

검토의 서비스 수준 협약(SLA)은 최대 10일이에요. 승인된 스크립트는 에이전시 앱에 포함돼요.

### 사용자 지정 스크립트 가이드라인

- 민감한 데이터 접근: 의도하지 않은 데이터 변경이나 충돌을 막기 위해, 스크립트가 민감한 데이터에 접근하면 안 돼요.
- 난독화된 코드: 난독화된 코드는 쓰지 마세요. 보안 위험을 막고 스크립트의 의도를 투명하게 확인할 수 있도록, 읽기 쉬운 코드가 필요해요.
- 데이터베이스 접근: 데이터의 무결성과 보안을 지키기 위해, 스크립트가 데이터베이스에 직접 접근하면 안 돼요.
- 원격 파일 참조: 모든 로직은 스크립트 안에 들어 있어야 해요. 원격 파일을 참조하거나 실행 중에 스크립트를 불러오는 방식은 허용되지 않아요.
- 스크립트 삽입: DOM과 제대로 연동되도록 JavaScript 코드를 `<script>` 태그 안에 넣으세요.
- 콘솔 로그 사용 금지: 코드를 깔끔하고 효율적으로 유지하기 위해 스크립트에 `console.log` 문을 넣지 마세요.

## 제출 전 테스트

문제를 미리 막으려면 제출하기 전에 스크립트를 충분히 테스트하세요. 에이전시 화면의 **설정 > 회사**에 있는 **Custom JavaScript & Custom CSS**(사용자 지정 JavaScript 및 CSS) 섹션에 스크립트를 추가해서 확인할 수 있어요.

에이전시 권한이 없다면 샌드박스 계정을 만들어 같은 환경에서 스크립트를 테스트해 보세요.

이 가이드라인을 지키면 모든 사용자가 안전하고 안정적인 하이퍼클래스를 쓸 수 있어요. 협조해 주셔서 감사해요. 여러분이 만들 새로운 기능을 기대할게요.

## 사용자 지정 JS 래퍼 함수 활용

사용자 지정 JS 래퍼 함수를 사용하는 방법은 하이퍼클래스 고객지원에 문의하세요.
