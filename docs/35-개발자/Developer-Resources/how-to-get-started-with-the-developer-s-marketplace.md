# 개발자 마켓플레이스 시작하기

이 문서는 개발자 마켓플레이스에서 앱을 만들고 OAuth와 웹훅을 설정하는 과정을 안내해요. 용어 정리, OAuth 흐름, 웹훅 설정 단계, 자주 묻는 질문을 함께 담았어요.

CRM 마켓플레이스의 OAuth API는 두 가지 액세스 수준을 제공해요. 위치 수준 액세스(서브 계정)와 에이전시 수준 액세스(회사)예요. 위치 수준 액세스에서는 서브 계정 하나에 해당하는 작업을 할 수 있어요. 에이전시 수준 액세스에서는 에이전시 전체의 데이터를 관리할 수 있어요. 이렇게 나누면 데이터를 효율적으로 다룰 수 있고, CRM 마켓플레이스 API v2.0과의 연동성도 좋아져요.

개발자 지원이 필요하면 하이퍼클래스 고객지원에 문의하세요. 지원 티켓을 만들 때는 가능하면 모든 세부 내용과 Loom 영상을 함께 보내 주세요.

## 용어 정리

- 하이퍼클래스: 기업의 성장과 운영 효율화를 돕는 마케팅, 영업, 자동화 도구를 제공하는 종합 플랫폼이에요.
- 개발자 마켓플레이스(Developer's Marketplace): 하이퍼클래스 안에서 개발자가 하이퍼클래스 API로 앱과 도구를 만들고 연동하는 플랫폼이에요.
- API(Application Programming Interface): 서로 다른 소프트웨어 애플리케이션이 소통하는 데 쓰는 규칙과 프로토콜의 모음이에요. 개발자 마켓플레이스에서는 하이퍼클래스 API로 하이퍼클래스의 기능과 데이터에 접근하고 상호작용해요.
- 액세스 토큰(Access Token): 앱이 사용자나 계정의 보호된 리소스에 접근할 때 쓰는 자격 증명이에요. 개발자는 OAuth 과정을 거쳐 액세스 토큰을 받아요. 이 토큰으로 앱이 하이퍼클래스에 인증된 API 요청을 보낼 수 있어요. 액세스 토큰은 보통 API 요청의 Authorization 헤더에 넣어요.
- 앱 ID(AppID): 마켓플레이스 앱의 고유 식별자예요. 앱 이름 아래에서 확인할 수 있어요.

  ![앱 이름 아래에 표시된 앱 ID](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155069007374/original/D3Rc7vuKH7qc6Kjli70pns2uT60kLt02PA.png?1776076632)
- 대화 제공업체 ID(Conversation Provider ID): 사용자가 설치하는 제공업체 유형의 고유 식별자예요. 앱에 대화 제공업체를 만들었다면 대화 제공업체 이름 아래에서 확인할 수 있어요.
- 리프레시 토큰(Refresh Token): 사용자가 앱을 다시 승인하지 않아도 새 액세스 토큰을 받을 수 있게 해 주는 자격 증명이에요. 더 오래 유지되는 인증 수단이라서 하이퍼클래스 리소스에 계속 접근할 수 있어요. 액세스 토큰이 만료되면 리프레시 토큰으로 새 토큰을 받아요.
- OAuth(Open Authorization): 안전한 앱 승인과 인증을 위한 업계 표준 프로토콜이에요. 사용자가 로그인 정보를 공유하지 않고도 앱이 하이퍼클래스 데이터에 접근하도록 허용할 수 있어요. 사용자는 하이퍼클래스로 이동해 인증하고 앱에 접근 권한을 줘요.
- 리다이렉트 URI(Redirect URI): 사용자가 앱 접근을 승인한 뒤 하이퍼클래스가 사용자를 보내는 URL이에요. OAuth 과정에서 사용자가 권한을 허용하면, 인증 코드나 액세스 토큰이 리다이렉트 URI 뒤에 붙은 채로 앱으로 이동해요.
- 인증 코드(Authorization Code): OAuth 과정에서 사용자가 앱을 승인한 직후 받는, 유효 시간이 짧은 자격 증명이에요. 앱은 이 코드를 액세스 토큰과 리프레시 토큰으로 교환해요.
- 범위(Scopes): 앱이 하이퍼클래스와 상호작용하기 위해 필요한 구체적인 권한과 접근 범위예요. 앱을 만들 때 앱 기능에 맞는 범위를 지정해요. 하이퍼클래스의 여러 리소스에 대한 읽기, 쓰기, 관리 권한이 범위에 포함될 수 있어요.
- 엔드포인트(Endpoint): API 리소스나 기능을 나타내는 특정 URL 또는 URI예요. 하이퍼클래스 API에는 여러 엔드포인트가 있고, 개발자는 이를 통해 특정 작업을 하거나 특정 데이터를 가져와요.
- 요청(Request): 앱이 하이퍼클래스 API에 보내는 통신이에요. HTTP 메서드(예: GET, POST), URL 또는 엔드포인트, 헤더, 필요한 파라미터나 데이터가 들어 있어요.
- 응답(Response): 앱이 보낸 요청에 서버가 보내는 답이에요. 요청한 데이터, 수행한 작업의 확인, 알맞은 상태 코드가 들어 있어요.
- 상태 코드(Status Code): HTTP 요청의 결과를 나타내려고 서버가 돌려주는 세 자리 숫자예요. 흔한 상태 코드로 200(OK), 400(Bad Request), 401(Unauthorized), 422(Unprocessable Entity)가 있어요.
- 배분 유형(Distribution Type): 앱을 하이퍼클래스 사용자에게 어떻게 배포하고 제공할지를 뜻해요. 에이전시 또는 서브 계정 중에서 선택해요. 에이전시 배분은 에이전시 계정 안의 모든 위치에서 앱을 쓸 수 있어요. 서브 계정 배분은 특정 서브 계정이나 개별 위치로 사용을 제한해요.
- 위치 ID(Location ID): 하이퍼클래스 계정 안의 특정 위치에 부여되는 고유 식별자예요. 위치 수준에서 접근을 구분하고 관리할 때 써요.
- 회사 ID(Company ID): 하이퍼클래스 회사 또는 계정에 부여되는 고유 식별자예요. 회사 수준에서 접근을 구분하고 관리할 때 써요.
- 해시된 회사 ID(Hashed Company ID): 예전에 하이퍼클래스 회사나 계정과 연결되어 있던 식별자예요. 지금은 쓰지 않고 단계적으로 없어지고 있어요.
- 라이브 서버(Live Server): 앱이 하이퍼클래스 API 및 실제 사용자 데이터와 상호작용하는 운영 환경이에요. 앱이 배포되어 사용자가 접근할 수 있는 서버예요.
- SDK(Software Development Kit): 특정 플랫폼이나 프레임워크용 애플리케이션을 만들 때 개발자가 쓰는 도구, 라이브러리, 문서의 모음이에요. 하이퍼클래스는 커스텀 앱을 API와 연동하기 쉽게 해 주는 SDK를 제공해요.
- Authorization 헤더(Authorization Header): 액세스 토큰 같은 인증 정보를 API 요청에 담는 HTTP 헤더예요. 보통 `Authorization: Bearer {access_token}` 형태예요.
- API 키(API Key): API 접근 권한이 있는 개발자에게 제공되는 고유 식별자 또는 코드예요. API 요청을 보낼 때 인증 수단으로 쓰여요.
- 콜백 URL(Callback URL): 앱이 콜백이나 응답을 받으려고 지정해 둔 주소예요. 개발자 마켓플레이스에서는 OAuth 과정 중 사용자가 권한을 허용한 뒤 인증 코드나 액세스 토큰을 받는 엔드포인트를 말해요.
- JSON(JavaScript Object Notation): 사람이 읽고 쓰기 쉽고 기계가 분석하고 생성하기도 쉬운 가벼운 데이터 교환 형식이에요. API 요청과 응답의 데이터를 구조화할 때 흔히 써요.
- 파라미터(Parameters): API 요청에 담아 구체적인 지시를 하거나 원하는 데이터를 걸러내는 추가 값이에요. 검색 조건, 정렬 방식, 페이지네이션 옵션을 지정하는 데 쓸 수 있어요.
- 페이지네이션(Pagination): 큰 데이터 집합을 페이지라는 작은 단위로 나누는 방식이에요. API 응답에는 페이지당 항목 수, 전체 페이지 수 같은 페이지네이션 정보가 들어 있는 경우가 많아요. 개발자는 이 정보로 데이터를 나눠서 가져올 수 있어요.
- 속도 제한(Rate Limiting): API가 일정 기간 동안 클라이언트나 사용자의 요청 수를 제한하는 방식이에요. API 성능을 유지하고 남용을 막아 줘요.
- 웹훅(Webhooks): 특정 이벤트나 트리거가 발생할 때 한 애플리케이션이 다른 애플리케이션에 보내는 HTTP 콜백(알림)이에요. 개발자 마켓플레이스에서는 신규 리드나 연락처 정보 같은 데이터를 하이퍼클래스에서 실시간으로 받도록 웹훅을 설정할 수 있어요.
- 이벤트(Event): 애플리케이션이나 시스템 안에서 일어나는 특정 사건이나 동작이에요. 웹훅에서는 이벤트가 웹훅 알림을 보내게 하는 트리거예요.
- 요청(Request): 클라이언트(예: 애플리케이션)가 서버(예: API)에 작업을 시작하거나 데이터를 가져오려고 보내는 HTTP 메시지예요. 요청 URL, 메서드(GET, POST 등), 헤더, 선택 사항인 본문이 들어 있어요.
- 응답(Response): 서버가 클라이언트의 요청에 대한 답으로 돌려주는 HTTP 메시지예요. 요청한 데이터나 요청의 상태와 결과가 들어 있어요.
- GET: 서버의 데이터를 가져오는 HTTP 메서드예요. API에서 리소스나 정보를 가져올 때 흔히 써요.
- POST: 서버에 데이터를 보내는 HTTP 메서드예요. 보통 새 리소스를 만들거나 API가 처리할 데이터를 보낼 때 써요.
- PUT: 서버에 있는 기존 데이터를 업데이트하거나 교체하는 HTTP 메서드예요. 요청에 담은 새 데이터로 리소스 전체를 바꿔요.
- DELETE: 서버에서 리소스를 삭제하는 HTTP 메서드예요. 지정한 리소스를 삭제하라고 서버에 지시해요.
- 프런트엔드 개발(Front-End Development): 소프트웨어 애플리케이션에서 사용자가 보는 부분을 만드는 일이에요. 보통 HTML, CSS, JavaScript로 인터랙티브하고 보기 좋은 인터페이스를 만들어요.
- 백엔드 개발(Back-End Development): 소프트웨어 애플리케이션의 서버 쪽 구성 요소를 다루는 일이에요. 애플리케이션 기능을 뒷받침하는 로직, 데이터 저장, 처리를 구현해요.

## 개발자 마켓플레이스의 OAuth 흐름

개발자 마켓플레이스의 OAuth 흐름은 보통 다음 순서로 진행돼요.

1. 앱 등록: 개발자가 개발자 마켓플레이스에 앱을 등록하고, 필요한 정보를 입력하고 범위를 정해요. 이때 앱의 고유 식별자인 클라이언트 ID와 클라이언트 시크릿을 받아요.
2. 인증 요청: 앱이 사용자(보통 브라우저)를 마켓플레이스의 인증 서버로 보내요. 인증 요청에는 클라이언트 ID, 요청하는 범위, 리다이렉트 URL이 들어가요. 리다이렉트 URL은 사용자가 승인한 뒤 돌아올 앱 안의 위치예요.
3. 사용자 동의: 사용자가 마켓플레이스에 로그인해서, 앱이 접근하려는 정보(범위로 정의된 내용)를 확인해요. 사용자가 동의하면 입력해 둔 리다이렉트 URL로 이동하고, 이때 인증 코드가 쿼리 파라미터로 붙어요.
4. 인증 승인: 앱이 인증 코드를 받아 확인해요. 그다음 인증 코드, 클라이언트 ID, 클라이언트 시크릿을 담아 인증 서버에 POST 요청을 보내요.
5. 액세스 토큰 발급: 보낸 정보가 모두 맞고 인증 코드가 유효하면, 인증 서버가 앱에 액세스 토큰을 발급해요. 앱은 이 토큰으로 사용자를 대신해 API에 요청을 보낼 수 있어요. 앞서 정한 범위 안에서만 가능해요.
6. API 호출: 앱은 API 호출을 할 때 헤더에 액세스 토큰을 넣어요. 액세스 토큰이 유효하고 필요한 범위가 있으면 서버가 요청한 작업을 허용해요.
7. 토큰 갱신: 액세스 토큰은 유효 기간이 있어서, 주기적으로 갱신해야 해요. 인증 서버가 리프레시 토큰을 제공했다면 그 토큰으로 갱신해요. 앱이 리프레시 토큰으로 서버에 요청하면, 토큰이 유효할 때 새 액세스 토큰이 발급돼요.

OAuth는 위임 프로토콜이에요. 사용자의 로그인 정보를 받지 않고 앱이 사용자를 대신해 동작해야 할 때 유용해요. 실제 흐름은 마켓플레이스 구현에 따라 조금 다를 수 있지만, 기본 원리는 같아요.

## PKCE를 사용하는 OAuth 2.0 (Proof Key for Code Exchange)

하이퍼클래스 마켓플레이스는 외부 인증용으로 PKCE를 사용하는 OAuth 2.0도 지원해요. 연동에서 퍼블릭 클라이언트(예: 브라우저 기반 앱이나 모바일 앱)를 쓰거나 OAuth 제공업체가 PKCE를 요구하면 PKCE를 켜세요.

PKCE를 켜면 인증 요청에 `code_challenge`와 `code_challenge_method`(`S256`)가 들어가요. 토큰 요청에는 이와 짝이 맞는 `code_verifier`가 들어가요.

마켓플레이스에서 설정하는 방법은 개발자 문서의 OAuth 외부 인증(ExternalAuthentication) 항목을 참고하세요.

### 활용 사례

- 연락처 관리: 연락처 관리 API로 연락처를 만들고, 수정하고, 검색하고, 삭제해서 고객 관계를 효율적으로 관리해요.
- 대화 관리: 대화 API로 대화를 조회하고, 수정하고, 삭제해서 고객과의 소통을 간소화해요.
- 메시지 자동화: 메시지 API로 이메일과 SMS를 자동으로 보내거나 예약 발송해서 고객 참여와 리드 육성을 높여요.
- 폼 제출: 폼 API로 폼 제출 내용을 수집하고 관리해서 리드를 확보하고 데이터를 모아요.
- 링크 관리: 링크 API로 링크를 만들고, 수정하고, 삭제해서 URL 링크를 효과적으로 추적하고 관리해요.
- 위치 태그 관리: 위치 태그 API로 위치별 태그를 지정하고 관리해서 분류와 필터링을 체계적으로 해요.
- 커스텀 필드 관리: 커스텀 필드 API로 커스텀 필드를 만들고, 수정하고, 삭제해서 데이터를 유연하게 정리하고 맞춤 설정해요.
- 커스텀 값 관리: 커스텀 값 API로 연락처와 연결된 커스텀 값을 만들고, 수정하고, 삭제해서 데이터 개인화를 높여요.
- 템플릿 관리: 이메일·SMS 템플릿 API로 템플릿을 만들고, 조회하고, 수정해서 일관되고 효율적인 메시지를 보내요.
- 기회 관리: 기회 API로 기회를 만들고, 수정하고, 삭제해서 영업 파이프라인을 효과적으로 관리해요.
- 메모 작성: 메모 생성 API로 고객 프로필에 메모를 추가해서 기록과 정보 공유를 쉽게 해요.
- 작업 관리: 작업 API로 작업을 만들고, 수정하고, 삭제해서 작업 추적과 워크플로우 관리를 효율적으로 해요.
- 예약 일정 관리: 예약 API로 예약을 만들고 수정해서 일정과 캘린더를 쉽게 관리해요.
- 주문 처리: 주문 API로 고객 주문을 만들고, 수정하고, 관리해서 주문 처리 과정을 간소화해요.
- 고객 관리: 고객 API로 고객 프로필을 만들고, 수정하고, 삭제해서 고객 관계를 폭넓게 관리해요.
- 사용자 관리: 사용자 API로 사용자 계정을 만들고, 수정하고, 삭제해서 사용자 관리와 접근 제어를 해요.
- 워크플로우 자동화: 워크플로우 API로 워크플로우를 만들고, 수정하고, 삭제해서 업무 프로세스와 작업을 자동화해요.
- 스냅샷 조회: 스냅샷 API로 데이터 스냅샷을 조회하고 관리해서 과거 데이터 분석과 리포팅에 활용해요.

이런 활용 사례를 보면 개발자 마켓플레이스의 API를 여러 실무 상황에 적용해서 생산성을 높이고, 프로세스를 자동화하고, 비즈니스 운영을 최적화할 수 있어요.

## OAuth V2로 앱의 웹훅 설정하기

앱에 웹훅을 설정하려면 아래 단계를 따라 하세요.

### 1단계. 개발자 계정 가입

하이퍼클래스 마켓플레이스에 접속해서, 아직 개발자 계정이 없다면 가입하세요.

### 2단계. 앱 만들기

로그인한 뒤 **My Apps**(내 앱)로 이동해서 **Create App**(앱 만들기)을 클릭하세요. 새 앱이 만들어져요.

### 3단계. 프로필 정보 입력

앱에 필요한 프로필 정보를 모두 입력하세요.

![앱 프로필 정보 입력 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155069008335/original/woSKbTNj5iauTLxrfowRT9ZR2VPIBhcpyQ.png?1776077143)

**앱 이름**

**앱 이름**은 앱에 붙이는 이름이에요. 개발자 마켓플레이스에서 앱을 구분하는 고유한 이름이라서, 사용자가 다른 앱과 쉽게 구별할 수 있어요.

**Search Keywords**(검색 키워드)

마켓플레이스에서 관련 검색어에 앱이 노출되도록, 관련 키워드를 200자까지 추가할 수 있어요. 검색 키워드로 앱을 더 쉽게 찾게 만들 수 있어요. 앱 이름, 태그라인, 회사 이름 같은 다른 등록 정보와 함께 작동해요. 예를 들어 예약 앱이라면 scheduling, calendar, appointments, booking, reminders 같은 키워드를 쓸 수 있어요.

![검색 키워드 입력 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155069008492/original/G-Old1D_0JyragmLFlGR3P8W2jtkMRdPig.png?1776077252)

**앱 유형**: **Public**(공개), **Private**(비공개)

**앱 유형**은 앱의 접근 가능 범위와 공개 여부를 정해요.

- Public 앱: 누구나 사용하고 접근할 수 있는 앱이에요. 개발자 마켓플레이스에 노출되고, 필요한 권한이 있는 사용자가 설치할 수 있어요.
- Private 앱: 특정 그룹이나 개인으로 제한되는 앱이에요. 마켓플레이스에 공개적으로 노출되지 않고, 초대나 승인이 있어야 접근하고 사용할 수 있어요.

**배분 유형**: **Agency**(에이전시), **Sub Account**(서브 계정)

**배분 유형**은 앱을 어떻게 배포해서 사용자에게 제공할지 정해요.

- Agency 배분: 에이전시 배분을 선택하면 모든 계정에서 앱을 쓸 수 있어요. 에이전시 구성원이나 서브 계정 모두 앱을 설치하고 사용할 수 있어요.
- Sub Account 배분: 서브 계정 배분을 선택하면 에이전시 안의 특정 서브 계정으로 앱이 제한돼요. 해당 서브 계정에 속한 사용자만 앱을 설치하고 사용할 수 있어요.

### 6단계. OAuth 엔드포인트 설정

앱에 OAuth 과정을 처리할 GET 엔드포인트를 만드세요.

액세스 토큰을 받는 방법은 개발자 문서의 OAuth 액세스 토큰 가져오기 항목에서 자세히 볼 수 있어요.

앱에서 OAuth용 GET 엔드포인트를 만드는 방법은 다음과 같아요.

- 엔드포인트가 사용할 경로를 정해요(예: `/OAuth/callback/hyperclass`).
- 이 경로로 들어오는 요청을 앱이 받도록 설정해요.
- 사용자가 앱을 승인하면 하이퍼클래스가 `code` 파라미터를 붙여 엔드포인트로 이동시켜요.
- 요청에서 `code` 파라미터를 가져와요.
- 코드를 안전하게 저장해요.
- 코드, 클라이언트 ID, 클라이언트 시크릿, 그랜트 타입, 리다이렉트 URI를 담아 하이퍼클래스의 `/OAuth/token` 엔드포인트에 POST 요청을 보내요.
- POST 요청의 응답을 받아요.
- 응답에서 액세스 토큰, 토큰 유형, 만료 시간, 리프레시 토큰 등 필요한 정보를 꺼내요.
- 액세스 토큰을 앱에 안전하게 저장해요.

이제 이 액세스 토큰으로 하이퍼클래스 API 요청을 인증할 수 있어요.

이 단계대로 하면 GET 엔드포인트가 코드를 액세스 토큰으로 교환하고, 이후 API 호출에 쓰도록 안전하게 저장하는 OAuth 과정을 처리해요.

### 7단계. OAuth 설정 구성

앱 설정의 **OAuthToken 리다이렉트 URL**에 앞 단계에서 만든 엔드포인트를 입력하세요.

![OAuthToken 리다이렉트 URL 설정](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155069018171/original/IeAcURzDbAgrnIwRhRP37Vo02x2OHzkyBg.png?1776082090)

### 8단계. 웹훅 엔드포인트 만들기

웹훅 이벤트를 받아 처리할 POST 엔드포인트를 앱에 만드세요.

이 엔드포인트는 이벤트의 JSON 본문을 처리할 수 있어야 해요.

### 9단계. 웹훅 URL 설정

앱 설정에 웹훅 엔드포인트의 URL을 입력하세요.

### 10단계. 앱에 위치/계정 지정

1. 에이전시 관리자 계정으로 로그인하세요.
2. 새 브라우저 탭을 열고 마켓플레이스에서 내 앱으로 이동하세요.
3. **+ Add App**(앱 추가)을 클릭한 뒤, 웹훅을 추가할 계정/위치를 검색해서 선택하세요.

### 11단계. 인증 코드 확인

앱을 정상적으로 추가하면, URL이 바뀐 마켓플레이스 앱 페이지로 이동해요.

URL에서 쿼리 문자열 파라미터 `code`를 복사하세요(예: `code=c40216d8574eb90abe0c884058fa9f5101085exx`).

### 12단계. 새 브라우저 탭 열기

새 브라우저 탭을 열고 아래 형식의 URL을 입력하세요.

`YOUR_REDIRECT_URL?code=CODE`

`YOUR_REDIRECT_URL`은 앱의 리다이렉트 URL로, `CODE`는 앞 단계에서 복사한 인증 코드로 바꾸세요.

### 13단계. 웹훅 연결 확인

`https://services.leadconnectorhq.com/oauth/token`의 응답이 성공이고 액세스 토큰을 받았다면, 웹훅이 연결된 거예요.

이 단계를 따라 하면 앱에 웹훅을 설정하고 원하는 계정/위치에 연결할 수 있어요. 각 단계의 자세한 내용은 개발자 문서를 참고하세요.

## 마켓플레이스에서 판매 — 자동으로 만들어지는 개발자 계정(에이전시 관리자)

에이전시 관리자가 **마켓플레이스에서 판매**를 선택하면, 시스템이 해당 관리자에게 이미 개발자 계정이 있는지 확인해요.

개발자 계정이 없는 경우 하이퍼클래스는 다음 순서로 진행해요.

1. 기존 계정 정보를 사용해 백그라운드에서 개발자 프로필을 만들어요.
2. 관리자를 로그인 화면으로 보내요.
3. 관리자에게 아래 내용을 요청해요.
   - 비밀번호 입력
   - 개발자 이용약관 동의
   - 이메일로 받은 일회용 비밀번호(OTP) 인증
4. 새 개발자 계정으로 관리자를 로그인시키고, 마켓플레이스 등록 과정을 이어서 진행해요.

개발자 가입 폼을 직접 작성할 필요는 없어요.

## 자주 묻는 질문

### 개발자 마켓플레이스가 무엇인가요?
개발자 마켓플레이스는 하이퍼클래스가 제공하는 플랫폼이에요. 개발자가 하이퍼클래스 CRM에서 쓸 커스텀 애플리케이션과 연동을 만들고 배포할 수 있어요.

### 마켓플레이스 개발자 계정은 어떻게 가입하나요?
마켓플레이스 웹사이트로 이동해서 가입 버튼을 클릭하세요. 안내에 따라 계정을 만들면 돼요.

### 앱 설정에서 말하는 범위가 무엇인가요?
범위는 앱이 하이퍼클래스 CRM과 상호작용하기 위해 필요한 권한과 접근 수준이에요. 앱에 필요한 기능에 맞춰 앱 설정에 알맞은 범위를 추가해야 해요.

### 앱의 클라이언트 자격 증명은 어떻게 만드나요?
앱 설정에 클라이언트 자격 증명을 만드는 옵션이 있어요. 이 옵션을 클릭하면 클라이언트 ID와 클라이언트 시크릿을 받을 수 있고, 인증과 권한 부여에 사용해요.

### 커스텀 애플리케이션의 OAuth 과정을 설명해 주세요.
OAuth는 커스텀 애플리케이션과 하이퍼클래스 CRM 사이에서 안전하게 권한을 부여하는 프로토콜이에요. OAuth 과정을 처리하려면 앱에 GET 엔드포인트를 만들어야 해요. 이 엔드포인트가 `code` 파라미터를 받으면, 그 코드로 하이퍼클래스 API에 액세스 토큰을 요청해요.

### OAuthToken 리다이렉트 URL은 어떤 용도인가요?
OAuth 과정이 성공적으로 끝난 뒤 액세스 토큰을 받는 앱의 엔드포인트예요. 앱 설정에 지정해야 해요.

### 앱에 웹훅 엔드포인트는 어떻게 만드나요?
하이퍼클래스 CRM이 보내는 JSON 페이로드를 받아 처리하도록 앱에 POST 엔드포인트를 만들면 돼요. 이 엔드포인트가 웹훅 이벤트를 처리하고 앱에서 필요한 작업을 실행해요.

### 마켓플레이스 앱에 위치/계정은 어떻게 지정하나요?
에이전시 관리자로서 지정할 수 있어요. 마켓플레이스에서 앱을 열고 **+ Add App**(앱 추가)을 클릭한 뒤, 원하는 계정/위치를 검색해서 선택하면 웹훅 연결이 만들어져요.

### 웹훅 연결 과정에서 인증 코드는 어떤 역할을 하나요?
인증 코드는 웹훅 연결 과정에서 생성되는 고유한 코드예요. 액세스 토큰으로 교환하는 임시 인증 토큰이라서, 앱이 하이퍼클래스 API와 안전하게 상호작용할 수 있어요.

### 웹훅 연결이 잘 됐는지 어떻게 확인하나요?
웹훅 연결 과정을 마치고 액세스 토큰을 받았다면, 웹훅 엔드포인트를 테스트해서 확인할 수 있어요. 하이퍼클래스 CRM에서 테스트 이벤트를 발생시키고, 엔드포인트가 이벤트를 제대로 받아 처리하는지 확인하세요.

### 개발자 마켓플레이스에서 앱을 여러 개 만들 수 있나요?
네, 만들 수 있어요. 앱마다 고유한 프로필, 설정, 웹훅 구성을 따로 가질 수 있어요.

### 앱에 추가할 수 있는 범위 개수에 제한이 있나요?
특별한 제한은 없어요. 다만 불필요한 권한을 줄이고 보안을 높이려면 앱에 꼭 필요한 범위만 넣는 것이 좋아요.

### 앱 프로필 정보는 얼마나 자주 업데이트해야 하나요?
앱 프로필 정보를 최신으로 유지하는 것이 좋아요. 새 기능이나 개선처럼 앱에 큰 변화가 있으면, 잠재 사용자에게 정확한 정보를 전달하도록 프로필을 업데이트하세요.

### 개발자 마켓플레이스를 통해 사용자 데이터에 접근할 수 있나요?
하이퍼클래스 CRM이 제공하는 알맞은 범위와 API를 사용하면 접근할 수 있어요. 다만 사용자 데이터를 책임 있게 다루고 관련 개인정보 보호 규정을 지키는 것이 중요해요.

### 개발자 마켓플레이스의 앱에 외부 서비스를 연동할 수 있나요?
네, 연동할 수 있어요. 연동이 플랫폼 가이드라인을 지키고 필요한 API나 웹훅을 쓸 수 있다면, 외부 서비스와 연결해서 앱 기능을 확장할 수 있어요.

### Private 마켓플레이스 앱의 설치가 막혔어요. 왜 그런가요?
Private 앱은 서로 다른 에이전시 5곳까지만 설치할 수 있어요. Private 앱이 6곳 이상의 에이전시에 설치되면 새 설치가 막혀요(기존 설치는 계속 유지돼요). 새 설치를 다시 허용하려면 앱을 **Public**(목록에 노출)으로 게시하거나 **Security Review**(보안 검토)를 요청하세요. 보안 검토는 6곳 이상의 에이전시에 설치된 뒤에 요청할 수 있어요.
