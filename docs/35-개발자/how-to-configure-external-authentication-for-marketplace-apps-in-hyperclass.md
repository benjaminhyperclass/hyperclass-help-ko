# 마켓플레이스 앱의 외부 인증 설정

마켓플레이스 앱의 외부 인증(External Authentication)을 쓰면 OAuth v2, API 키, Basic Auth 방식으로 앱을 외부 서비스와 연결할 수 있어요. 확장된 프레임워크에서는 다중 계정 연결, 설치 시 입력 필드 설정, **사용자 정보**와 Multi-Auth의 개별 설정, 고급 인증 요청을 위한 JavaScript 코드 모드를 쓸 수 있어요. 인증 인프라를 직접 만들지 않아도 더 다양한 서비스와 연동할 수 있어요.

## 마켓플레이스 앱의 외부 인증이란?

**External Authentication**(외부 인증)은 마켓플레이스 앱이 설치되는 동안 외부 서비스에 안전하게 연결하도록 해 주는 프레임워크예요. 개발자는 사용자가 인증하는 방식, 계정 정보를 식별하는 방식, 지원되는 워크플로우·트리거·액션에서 자격 증명을 관리하는 방식을 설정할 수 있어요.

다음 인증 방식을 지원해요.

- **OAuth v2**: 외부 서비스의 인증 과정을 통해 사용자를 인증하고 액세스 토큰을 관리해요.
- **API 키**: 외부 서비스에서 발급한 API 자격 증명으로 사용자를 인증해요.
- **Basic Auth**: 사용자 이름과 비밀번호 같은 자격 증명으로 사용자를 인증해요.

확장된 프레임워크는 계정별 URL을 쓰거나 설치 중에 추가 입력이 필요한 서비스처럼, 표준과 다른 인증 요건을 가진 서비스도 지원해요.

## 외부 인증의 장점

확장된 인증 프레임워크는 외부 서비스 연동을 단순하게 만들고, 계정 연결과 인증 동작을 더 세밀하게 제어할 수 있게 해 줘요. 별도의 인증 시스템을 만들고 유지하지 않아도 더 많은 서비스를 지원할 수 있어요.

- 다중 계정 연결: 지원되는 OAuth 또는 Basic Auth 설정에서 마켓플레이스 앱 설치 하나에 외부 계정을 여러 개 연결할 수 있어요.
- 계정 식별 개선: 계정명과 이메일 주소를 가져와 연결된 계정을 쉽게 알아보고 관리할 수 있어요.
- 유연한 인증 설정: 앱 요건에 따라 **사용자 정보**를 Multi-Auth와 별개로 설정할 수 있어요.
- 동적 설치 시 입력 필드: 스토어 URL이나 테넌트 식별자처럼 서비스마다 다른 정보를 설치 중에 받을 수 있어요.
- 사용자 지정 인증 로직: 표준과 다른 요건이 있는 서비스는 JavaScript 코드 모드로 인증 요청을 설정할 수 있어요.
- 간편한 자격 증명 관리: 하이퍼클래스의 인증 프레임워크로 지원되는 자격 증명과 토큰 갱신을 관리할 수 있어요.
- 문제 해결 지원: 기본 제공되는 테스트 도구로 인증 응답, 사용자 정보, 실행 로그, HTTP 세부 정보를 확인할 수 있어요.

## Basic Auth의 다중 계정 지원

다중 계정 지원을 쓰면 Basic Auth 마켓플레이스 앱이 설치 하나 안에서 자격 증명 세트를 여러 개 가질 수 있어요. 같은 외부 서비스에서 계정을 여러 개 쓰는 사용자가 앱을 반복해서 설치하지 않고도 각 계정을 연결할 수 있어서 유용해요.

앞서 Multi-OAuth 지원이 OAuth 기반 앱에 다중 연결을 도입했어요. 확장된 프레임워크는 이 기능을 API 키 / Basic Auth 앱까지 넓혀요.

### Basic Auth 다중 연결의 동작 방식

연결 하나는 외부 계정 하나에 연결된 별도의 자격 증명 세트예요. 연결을 구분하기 위해 하이퍼클래스가 외부 서비스에서 식별 정보를 가져와 지원되는 계정 필드에 매핑할 수 있어요.

지원되는 계정 정보 매핑은 다음과 같아요.

| 필드 | 용도 |
| --- | --- |
| **Account ID Path**(계정 ID 경로) | 고유 ID로 외부 계정을 식별해요. |
| **Account Name Path**(계정명 경로) | 연결을 알아볼 수 있는 이름을 가져와요. |
| **Account Email Path**(계정 이메일 경로) | 계정에 연결된 이메일 주소를 가져와요. |

개발자는 이 정보를 두 가지 방법으로 가져올 수 있어요.

1. **Account Info Request**(계정 정보 요청): 계정 정보를 반환하는 서비스 엔드포인트로 보내는 선택 요청을 설정해요.
2. **Authentication Response**(인증 응답): 인증 엔드포인트가 바로 반환한 계정 정보를 그대로 사용해요.

### 예시: 계정 정보 응답

외부 서비스 API가 다음과 같은 계정 정보를 반환할 수 있어요.

```
{
  "account": {
    "id": "account_123",
    "name": "Example Store",
    "email": "admin@example.com"
  }
}
```

이 예시에서는 매핑 경로를 다음과 같이 설정해요.

- Account ID Path: `account.id`
- Account Name Path: `account.name`
- Account Email Path: `account.email`

{% hint style="info" %}
이 응답은 설명을 위한 예시예요. 실제 필드 경로는 외부 서비스의 응답 구조에 따라 달라요.

계정 정보를 올바르게 매핑하면 사용자가 계정을 여러 개 연결할 때 하이퍼클래스가 연결을 알아보기 쉽게 보여 줄 수 있어요.
{% endhint %}

여러 OAuth 연결을 관리하는 방법은 [마켓플레이스 앱의 Multi-OAuth 지원](../27-앱-마켓/multi-oauth-support-for-marketplace-apps.md)을 참고하세요.

## 사용자 정보와 Multi-Auth 설정

이제 **사용자 정보**와 **Multi-Auth**는 서로 독립된 설정이에요. 그래서 다중 계정 연결 없이도 계정 정보를 가져올 수 있어요. 외부 연결이 하나만 필요한 앱에서도 알아보기 쉬운 계정명이나 이메일 주소를 보여 주고 싶을 때 유용해요.

### 사용자 정보

**사용자 정보** 설정을 켜면 외부 서비스에서 식별 정보를 가져와 동기화할 수 있어요. 켠 뒤에는 **User Info Endpoint**(사용자 정보 엔드포인트)를 설정해서 다음과 같은 계정 정보를 가져와요.

- 계정 ID
- 계정명
- 계정 이메일

연결이 하나뿐인 앱에서는 이 정보로 어떤 외부 계정이 연결되어 있는지 알 수 있어요. 예를 들어 알 수 없는 연결로 표시하는 대신, 서비스가 반환한 계정명과 이메일을 보여 줄 수 있어요.

### Multi-Auth

**Multi-Auth**(다중 인증)를 켜면 앱이 설치 하나 안에서 외부 계정 연결을 여러 개 유지할 수 있어요.

**사용자 정보**와 함께 쓰면 서비스에서 가져온 계정 정보로 각 연결을 식별할 수 있어요.

### 설정별 동작

| 설정 | 동작 |
| --- | --- |
| 사용자 정보 켬, Multi-Auth 끔 | 연결 하나의 계정 정보를 가져와요. |
| 사용자 정보 켬, Multi-Auth 켬 | 지원되는 다중 연결의 식별 정보를 가져와요. |
| 사용자 정보 끔, Multi-Auth 켬 | 다중 연결을 지원해요. 계정 식별은 설정된 인증 응답과 매핑 요건에 따라 달라요. |
| 둘 다 끔 | 선택 기능 없이 앱의 표준 인증 설정을 사용해요. |

{% hint style="warning" %}
게시된 앱 버전에서 **User Info Endpoint** 또는 Multi-Auth를 한 번 켜면, 이후 버전에서는 그 설정을 끌 수 없어요. 새 버전을 게시하기 전에 두 설정을 꼼꼼히 확인하세요.
{% endhint %}

## 설치 시 입력 필드 설정

**Install-Time Fields**(설치 시 입력 필드)를 쓰면 외부 인증 과정에서 사용자에게 추가 정보를 받을 수 있어요. 계정별 URL, 스토어 식별자 등 설치마다 달라지는 값이 필요한 서비스에서 이 값으로 인증 요청을 맞춤 설정할 수 있어요.

설치 시 입력 필드마다 다음 속성을 설정할 수 있어요.

| 속성 | 설명 |
| --- | --- |
| **Label**(레이블) | 설치 중에 사용자에게 보이는 이름이에요. |
| **Key**(키) | 필드 값을 참조할 때 쓰는 식별자예요. |
| **Type**(유형) | 값을 받는 입력 유형이에요. |
| **Required**(필수 여부) | 사용자가 값을 꼭 입력해야 하는지 정해요. |
| **추가 지침** | 사용자가 올바른 정보를 입력하도록 돕는 안내예요. |
| **기본값** | 필드에 미리 설정해 두는 값이에요. |

## 인증 요청을 위한 코드 모드

**Code Mode**(코드 모드)를 쓰면 JavaScript로 지원되는 OAuth 인증 요청을 맞춤 설정할 수 있어요. 외부 서비스가 요구하는 요청 매개변수, 헤더, 요청 본문, 인증 로직을 표준 요청 설정만으로 처리할 수 없을 때 유용해요.

![코드 모드 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083835354/original/055aZfFyFpmojk5S_JMuO1FvYOpJ5i0Cxg.png?1792573285)

코드 모드는 다음 OAuth 요청에서 쓸 수 있어요.

| 요청 | 용도 |
| --- | --- |
| **Authorization URL**(인증 URL) | 외부 서비스와 인증을 시작하는 요청을 맞춤 설정해요. |
| 액세스 토큰 | 액세스 토큰을 받는 교환 과정을 맞춤 설정해요. |
| 리프레시 토큰 | 인증 토큰을 갱신하는 요청을 맞춤 설정해요. |
| **Test API**(API 테스트) | 인증을 확인하는 요청을 맞춤 설정해요. |
| **Fetch User Info**(사용자 정보 가져오기) | 외부 계정 정보를 가져오는 요청을 맞춤 설정해요. |

## 마켓플레이스 앱의 외부 인증 설정하기

인증을 제대로 설정해야 사용자가 외부 계정을 연결할 수 있고, 앱도 지원 기능에 필요한 자격 증명과 계정 정보를 가져올 수 있어요. 앱을 테스트하고 게시하기 전에 인증 방식, 선택 계정 설정, 요청 동작을 설정하세요.

1. 하이퍼클래스 개발자 마켓플레이스에 로그인하세요.
2. 설정할 마켓플레이스 앱을 열거나 새 앱을 만드세요.
3. 앱의 **External Authentication** 설정을 여세요.
4. 필요한 인증 엔드포인트 또는 요청 설정을 입력하세요.

   ![인증 엔드포인트 설정 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083834289/original/DD-fWHeLmWE_YmHxfOV1_3vHyXprqO1RNg.png?1792572865)
5. OAuth v2는 해당하는 **Authorization URL**과 토큰 요청을 설정하세요.
6. **API 키 / Basic Auth**는 필요에 맞게 자격 증명 수집 방식과 인증 요청을 설정하세요.

   ![API 키 / Basic Auth 설정 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083834681/original/7iRh1uMAkGHOFkxSfHBf8SOLQ46eHk9i7g.png?1792573010)
7. 서비스가 장기 토큰 교환을 추가로 지원한다면 선택 항목인 **Long-Lived Access Token Request**(장기 액세스 토큰 요청)를 설정하세요.
8. **사용자 정보** 설정을 찾으세요. 앱이 연결된 외부 계정의 식별 정보를 가져와야 하면 **사용자 정보**를 켜세요.
9. **User Info Endpoint** 또는 해당하는 계정 정보 요청을 설정하세요.
10. 반환된 계정 필드를 **Account ID Path**, **Account Name Path**, **Account Email Path**에 각각 매핑하세요.
11. 요청을 테스트해서 기대한 정보가 반환되는지 확인하세요.

### 필요하면 Multi-Auth 켜기

1. **Multi-Auth** 설정을 찾으세요.
2. 사용자가 외부 계정을 여러 개 연결해야 하면 켜세요.
3. Basic Auth 앱은 필요한 계정 식별 요청을 설정하거나, 인증 응답에서 가져올 매핑을 설정하세요.
4. 반환된 계정 정보로 자격 증명 세트를 서로 구분할 수 있는지 확인하세요.
5. 외부 계정을 두 개 이상 써서 설정을 테스트하세요.

Multi-Auth는 계정 연결이 하나만 필요한 앱에서는 선택 사항이에요.

![Multi-Auth 설정 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083834945/original/1U5GWwQVV7IOVDYZKXcNg98EGj6t3-ummQ.png?1792573106)

### 설치 시 입력 필드 추가하기

1. **Install-Time Fields** 설정을 찾으세요.
2. 필드를 하나 추가하세요.
3. 필드의 **Label**과 **Key**를 입력하세요.
4. 지원되는 입력 **Type**을 선택하세요.
5. 필드를 **Required**로 할지 정하세요.
6. 필요하면 **추가 지침**과 **기본값**을 입력하세요.
7. 필드를 더 추가하려면 같은 방법을 반복하세요. 최대 3개까지 추가할 수 있어요.
8. 지원되는 요청 설정이나 코드 모드에서 설정한 값을 참조하세요.

인증을 완료하는 데 필요한 정보만 받으세요.

{% hint style="warning" %}
호환성 관련 주의 사항이에요.

- 새로운 Multi-Auth, 사용자 정보 및 관련 인증 설정은 새 앱이나 새 앱 버전에 적용돼요.
- 기존 앱 설치는 이번 출시로 자동으로 바뀌지 않아요.
- **User Info Endpoint** 또는 Multi-Auth를 켠 채 게시한 버전은 이후 버전에서 그 설정을 끌 수 없어요.
{% endhint %}

연결 관리 방법은 [마켓플레이스 앱의 Multi-OAuth 지원](../27-앱-마켓/multi-oauth-support-for-marketplace-apps.md)과 [마켓플레이스 앱 – 외부 연결 관리](../27-앱-마켓/Workflow-Triggers-and-Actions/marketplace-apps-managing-external-connections.md)에서 자세히 확인하세요.

## 자주 묻는 질문

### 다중 계정 연결 없이 사용자 정보만 켤 수 있나요?
네, 가능해요. **사용자 정보**와 Multi-Auth는 독립된 설정이에요. 연결이 하나뿐인 앱도 다중 연결을 켜지 않고 **사용자 정보**로 계정명과 이메일 주소를 가져올 수 있어요.

### 앱을 게시한 뒤에 사용자 정보나 Multi-Auth를 끌 수 있나요?
아니요. 게시된 앱 버전에서 둘 중 하나를 켜면 이후 버전에서는 끌 수 없어요. 게시하기 전에 이 설정들을 꼭 확인하세요.

### 설치 시 입력 필드를 3개보다 많이 설정할 수 있나요?
아니요. 확장된 프레임워크에서는 앱 설정 하나당 설치 시 입력 필드를 최대 3개까지 설정할 수 있어요.

### 서비스마다 스토어 URL이 달라도 꼭 코드 모드를 써야 하나요?
꼭 그렇지는 않아요. 설치 시 입력 필드의 값은 지원되는 요청 설정과 코드 모드 모두에서 쓸 수 있어요. 코드 모드는 서비스가 표준 설정 옵션을 넘어서는 요청 맞춤 설정을 요구할 때 유용해요.

### 연결된 계정에 잘못된 정보가 표시돼요. 무엇을 확인해야 하나요?
외부 서비스의 계정 정보 응답을 확인하고, 설정한 계정 필드 경로가 반환된 데이터와 일치하는지 살펴보세요. 매핑 문제는 **사용자 정보** 탭과 **Response**(응답) 테스트 탭에서 확인할 수 있어요.

### 인증 코드 모드와 워크플로우 액션 커스텀 코드는 어떻게 다른가요?
인증 코드 모드는 지원되는 OAuth 인증 요청을 맞춤 설정하는 기능이에요. 워크플로우 액션 커스텀 코드는 마켓플레이스 워크플로우 액션이 실행될 때 사용할 맞춤 로직을 구현하는 기능이에요. 두 기능은 서로 별개예요.
