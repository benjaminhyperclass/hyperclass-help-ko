# API 키에서 비공개 연동으로 옮기기: API 마이그레이션 가이드

Zapier, Make, 직접 만든 도구 같은 외부 앱에서 예전 API 키를 쓰고 있다면, 보안이 강화된 비공개 연동 토큰(Private Integration Token, PIT)으로 바꿔야 해요. 이 문서는 그 과정을 단계별로 안내해요.

하이퍼클래스 API v1은 2025년 12월 31일에 지원이 종료되었어요. 기존 v1 연동은 계속 동작할 수도 있지만, 더 이상 관리나 지원을 받지 못해요.

하이퍼클래스는 기존 API 키를 쓰는 사용자에게 비공개 연동으로 옮기도록 안내해요. 비공개 연동은 비공개 연동 토큰(PIT)으로 접근 범위를 제한해서 쓸 수 있어요.

## 시작하기 전에 꼭 알아 둘 규칙

{% hint style="warning" %}
현재 사용 중인 자동화를 수정하거나 편집하지 마세요. 수정하면 지금 쓰는 설정이 깨질 수 있어요.
{% endhint %}

대신 아래 순서로 진행해요.

- 기존 자동화는 그대로 켜 둡니다.
- 새 API로 완전히 새로운 자동화를 따로 만듭니다.
- 새 자동화를 테스트합니다.
- 모든 것이 문제없이 동작하는 것을 확인한 뒤에만 기존 자동화와 기존 API 키를 삭제합니다.

## 단계별 마이그레이션 안내

v1 API 키는 계정 데이터 전체에 넓게 접근할 수 있어요. 비공개 연동은 연동이 접근할 수 있는 범위(스코프)와 권한을 직접 골라서 정할 수 있어요. 비공개 연동은 에이전시 수준과 서브 계정 수준 모두에서 만들 수 있어요.

### 1단계: 기존 API 키를 어디에 쓰고 있는지 확인하기

예전 하이퍼클래스 API 키를 쓰고 있는 외부 도구와 자동화를 찾아보세요.

- 해당 도구를 목록으로 정리해요(예: Zapier, Make, n8n, 직접 만든 웹 폼 등).
- 각 도구가 하는 일을 적어 둬요(예: "Zapier: Facebook에서 들어온 새 리드를 하이퍼클래스에 추가").

### 2단계: 하이퍼클래스에서 비공개 연동 만들기

비공개 연동은 예전 API 키를 안전하게 대체하는 방법이에요. 도구에 계정 전체 접근 권한을 주는 대신, 볼 수 있는 범위를 정확히 정해 줄 수 있어요.

{% hint style="warning" %}
연결하는 도구마다 비공개 연동을 따로 만드세요(예: Zapier용 하나, Make용 하나, n8n용 하나). 하나의 토큰을 여러 도구에서 함께 쓰지 마세요.
{% endhint %}

만드는 방법은 다음과 같아요.

1. 하이퍼클래스에 로그인합니다.
2. **설정**으로 이동해 **비공개 연동**을 찾습니다. 에이전시와 서브 계정 모두에서 쓸 수 있어요.
3. **프라이빗 연동 생성**을 클릭합니다.
4. 알아보기 쉬운 이름(예: "Zapier Lead Sync")과 설명을 입력합니다.
5. **Scopes**(권한 범위)에서 해당 도구에 필요한 권한만 선택합니다. 예를 들어 Zapier가 연락처만 읽는다면 **연락처** 권한만 체크하세요.
6. **저장**을 클릭하면 비공개 연동 토큰이 만들어져요.
7. 이 토큰을 안전한 곳에 바로 복사해서 저장합니다.

{% hint style="warning" %}
토큰은 한 번만 표시되고, 나중에 다시 볼 수 없어요. 반드시 지금 복사해서 안전한 곳에 보관하세요.
{% endhint %}

### 3단계: 외부 도구에서 새 자동화 만들기

운영 중인 기존 자동화를 편집하지 말고, 새로 만들어야 해요.

1. Zapier나 Make 같은 자동화 도구를 엽니다.
2. 완전히 새로운 자동화를 만듭니다. 기존 자동화를 복제해서 백업용으로 남겨 두는 방법도 있어요.
3. 새 자동화에서 2단계에서 복사한 비공개 연동 토큰으로 하이퍼클래스 계정을 연결합니다.

   {% hint style="info" %}
   도구에서 인증 헤더를 요구하면 토큰을 `Authorization: Bearer <YOUR_NEW_TOKEN>` 형식으로 보내세요.
   {% endhint %}

4. 최신 하이퍼클래스 API 엔드포인트로 자동화 단계를 구성합니다. Zapier의 하이퍼클래스 앱처럼 기본 제공 앱 연동을 쓰는 경우에는 사용할 수 있는 가장 최신 액션과 버전을 선택하세요.

   {% hint style="info" %}
   최신 API 문서 주소는 하이퍼클래스 고객지원에 문의하세요.
   {% endhint %}

### 4단계: 새 자동화 테스트하기

전환하기 전에 새 설정이 제대로 동작하는지 테스트하세요.

- 새 자동화에 테스트용 리드나 액션을 한 번 실행해 봅니다.
- 하이퍼클래스에서 데이터가 제대로 들어왔는지 확인합니다.
- 2단계에서 선택한 권한(스코프)이 충분했는지 확인합니다.

### 5단계: 기존 자동화를 끄고 기존 키 삭제하기

새 자동화가 문제없이 동작하는 것을 확인했다면 다음 순서로 마무리해요.

1. 새 자동화를 켜서 실제로 운영합니다.
2. 기존 자동화를 끄거나 일시중지합니다.
3. 외부 도구와 하이퍼클래스 설정에서 기존 API 키를 제거하고 삭제합니다. 이렇게 하면 계정을 안전하게 지키고, 예전 프로세스가 백그라운드에서 계속 실행되는 일도 막을 수 있어요.

## 운영 시 참고할 점과 권장 사항

- 토큰 교체(로테이션): 하이퍼클래스는 보안을 위해 90일마다 새 토큰을 만들어 교체하기를 권장해요.
- 유예 기간: 토큰을 교체하면 기존 토큰과 새 토큰이 7일 동안 함께 활성 상태로 유지돼요. 서비스 중단 없이 새 토큰을 각 도구에 옮겨 넣을 시간이 충분해요.
- 마이그레이션이 인증 방식만 바꾸는 작업이라고 생각하지 마세요. 예전 API와 현재 API는 요청과 응답이 다를 수 있어요.
- 하이퍼클래스의 현재 API는 `Version` 요청 헤더를 사용해요. 새로운 API는 v3처럼 이름이 붙은 버전을 쓸 수도 있어요. 구현하려는 엔드포인트의 문서에 나온 버전을 사용하세요.
