# 하이퍼클래스 개발자 마켓플레이스 CLI 사용 안내

하이퍼클래스 개발자 마켓플레이스 CLI를 쓰면 개발 환경에서 바로 마켓플레이스 앱을 만들고, 설정하고, 검증하고, 게시할 수 있어요. 지원하는 앱 설정은 로컬 JSON 파일에 저장되므로 코드와 함께 버전 관리를 할 수 있어요.

CLI는 터미널에서 직접 쓸 수도 있고, 스크립트·CI 파이프라인·호환되는 AI 코딩 에이전트에서 자동화해서 쓸 수도 있어요. 이 문서에서는 설치, 인증, 로컬 앱 관리, 마켓플레이스 리소스, 자동화, 게시 방법을 안내해요.

## 하이퍼클래스 개발자 마켓플레이스 CLI란?

하이퍼클래스 개발자 마켓플레이스 CLI는 터미널에서 마켓플레이스 앱 작업을 관리하는 `ghl` 명령어를 제공해요.

이 명령어로 다음 작업을 할 수 있어요.

- 앱 만들기 또는 가져오기
- 로컬 설정 편집
- 변경 사항 검증
- 로컬 상태와 마켓플레이스 상태 비교
- 업데이트 푸시
- 게시 조건을 충족한 앱 버전의 게시 또는 제출

CLI는 지원하는 마켓플레이스 설정을 로컬 작업 공간과 개발자 마켓플레이스 사이에서 동기화해 줘요.

## 이런 점이 좋아요

CLI를 쓰면 편집기와 개발자 마켓플레이스를 계속 오가지 않고도 마켓플레이스 앱을 관리할 수 있어요.

- 로컬 설정: 지원하는 앱 설정을 버전 관리가 가능한 JSON 파일에 저장해요.
- 로컬 검증: 지원하는 변경 사항을 마켓플레이스 API로 보내기 전에 확인해요.
- 더 안전한 동기화: 푸시하기 전에 로컬에서 수정한 내용, 마지막으로 가져온 상태, 현재 마켓플레이스 상태를 서로 비교해요.
- 선택적 업데이트: 지원하는 섹션 중 바뀐 부분만 푸시해요.
- 자동화 지원: 스크립트와 CI 워크플로우에서 플래그와 기계가 읽을 수 있는 출력을 쓸 수 있어요.
- AI 에이전트 지원: 자동으로 생성되는 작업 공간 안내 파일이 호환되는 코딩 에이전트가 CLI를 다루는 데 도움을 줘요.

## 사용 전 준비 사항과 제한 사항

CLI를 설치하기 전에 개발 환경과 개발자 마켓플레이스 계정이 준비되어 있는지 확인하세요.

시작하기 전에 다음을 준비하세요.

- Node.js 20.12 이상을 설치하세요.
- 하이퍼클래스 개발자 마켓플레이스 계정에 접근할 수 있어야 해요.
- npm으로 마켓플레이스 CLI를 설치하세요.
- 마켓플레이스 데이터에 접근하는 명령어를 쓰기 전에 인증하세요.

다음 동작도 알아 두세요.

- CLI를 써도 마켓플레이스의 검증·게시 요건은 그대로 적용돼요.
- 지원하는 조회 명령어는 대부분 `--json`을 제공하지만, 제공 여부는 명령어마다 달라요.
- 되돌릴 수 없는 위험한 명령어는 확인 절차가 필요하고, 비대화형 워크플로우에서는 `--force`가 필요할 수 있어요.
- 공개 앱과 비공개 앱은 게시 방식이 달라요.

## 하이퍼클래스 개발자 마켓플레이스 CLI 설정하기

CLI를 설치하고, 인증하고, 개발자 마켓플레이스 계정을 선택한 다음, 앱 작업 공간을 만들거나 가져오세요.

### 1단계: CLI 설치하기

패키지를 전역으로 설치하세요.

```
npm install -g @gohighlevel/marketplace-cli
```

설치가 잘 되었는지 확인하세요.

```
ghl --version
```

나중에 최신 버전으로 업데이트하려면 다음 명령어를 실행하세요.

```
ghl update
```

### 2단계: 로그인하기

인증을 시작하세요.

```
ghl login
```

CLI가 브라우저에서 승인 화면을 열어요.

브라우저가 자동으로 열리지 않게 하려면 다음 명령어를 실행하세요.

```
ghl login --no-browser
```

그런 다음 화면에 표시된 승인 URL을 직접 여세요.

### 3단계: 개발자 계정 선택하기

로그인한 계정으로 쓸 수 있는 개발자 마켓플레이스 계정 목록을 확인하세요.

```
ghl account
```

사용할 계정을 선택하세요.

```
ghl account switch
```

### 4단계: 앱 만들기 또는 가져오기

새 마켓플레이스 앱과 로컬 작업 공간을 만들려면 다음 명령어를 실행하세요.

```
ghl app create
```

이미 있는 앱의 작업 공간을 만들려면 다음 명령어를 실행하세요.

```
ghl app pull <appId>
```

처음 가져온 뒤에는 마켓플레이스에서 지원하는 설정을 새로 받아야 할 때마다 작업 공간에서 `ghl app pull`을 실행하세요.

## 로컬 작업 공간에서 앱 관리하기

로컬 작업 공간에서는 지원하는 마켓플레이스 설정을 애플리케이션 코드 가까이에서 관리할 수 있어요.

작업 공간에는 다음 항목이 들어갈 수 있어요.

- 앱 설정과 리스팅 정보
- OAuth 설정
- 웹훅
- 워크플로우 액션과 트리거
- 결제 설정
- 자동 생성된 스키마와 코딩 에이전트 안내 파일

### 기본 앱 작업 순서

마켓플레이스 앱을 업데이트하는 일반적인 순서는 다음과 같아요.

```
ghl app pull
ghl app validate
ghl app diff
ghl app push
ghl app validate --remote
ghl app publish
```

각 명령어는 동기화와 게시 과정에서 맡은 역할이 달라요.
`ghl app pull`: 마켓플레이스에서 지원하는 로컬 설정을 새로 가져와요.`ghl app validate`: 푸시하기 전에 지원하는 로컬 변경 사항을 확인해요.`ghl app diff`: 로컬 변경 사항을 마지막으로 동기화한 상태, 현재 마켓플레이스 상태와 비교해요.`ghl app push`: 충돌을 확인하면서 지원하는 변경 사항을 보내고, 바뀐 섹션을 업데이트해요.`ghl app validate --remote`: 마켓플레이스 요건에 맞게 게시할 준비가 되었는지 확인해요.`ghl app publish`: 게시 조건을 충족한 비공개 앱을 게시하거나, 조건을 충족한 공개 앱을 마켓플레이스 심사에 제출해요.

{% hint style="info" %}
공개 앱과 비공개 앱은 게시 방식이 달라요. 조건을 충족한 비공개 앱은 바로 게시할 수 있고, 조건을 충족한 공개 앱은 마켓플레이스 심사에 제출돼요.
{% endhint %}

## 마켓플레이스 리소스 관리하기

CLI에서는 자체 설정과 수명 주기를 가진 마켓플레이스 리소스도 다룰 수 있어요.

지원하는 영역은 다음과 같아요.

- OAuth 스코프, 리디렉션, 클라이언트 키
- 웹훅
- 워크플로우 액션과 트리거
- 앱 미디어와 리스팅 정보
- 구독 플랜과 사용량 기반 결제
- 앱 버전과 게시
- 샌드박스 계정

워크플로우 액션과 트리거에는 검증, 동기화, 테스트, 버전 관리, 게시를 위한 전용 워크플로우가 있어요.

전체 명령어, 플래그, 매니페스트 필드, 리소스별 요건은 공식 마켓플레이스 CLI 개발자 문서를 참고하세요.

## 자동화와 AI 코딩 에이전트에서 CLI 사용하기

마켓플레이스 CLI는 CI 파이프라인, 스크립트, 호환되는 AI 코딩 에이전트에서 쓸 수 있는 비대화형 워크플로우를 지원해요.

자동화 워크플로우에서는 다음을 지켜 주세요.

- 대화형 프롬프트에 의존하지 말고 필요한 인수와 플래그를 직접 전달하세요.
- 구조화된 출력이 필요하면 지원하는 조회 명령어에 `--json`을 쓰세요.
- 명령어 출력을 처리하기 전에 프로세스 종료 코드를 확인하세요.
- 변경 계획을 미리 확인하려면 지원하는 명령어에 `--dry-run`을 쓰세요.
- 위험하거나 되돌릴 수 없는 작업을 확인한 뒤에만 `--force`를 쓰세요.

사람이 읽는 진행 상황과 오류는 `stderr`로 출력돼요. `--json`을 쓸 수 있는 명령어는 구조화된 출력을 `stdout`으로 돌려줘요.

![자동화 워크플로우 예시](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155082996456/original/nlsn1CqgUB5Z01ucBL9uRLjkC4lj3CWsWA.png?1791600093)

### AI 코딩 에이전트 안내 파일

CLI 작업 공간에는 `AGENTS.md`와 `CLAUDE.md` 파일이 자동으로 생성될 수 있어요. 이 파일에는 호환되는 코딩 에이전트를 위한 작업 공간 안내와 명령어 참조가 들어 있어요.

이 파일들은 지원되는 코딩 에이전트가 마켓플레이스 작업 공간을 이해하고 CLI 워크플로우를 더 일관되게 쓰는 데 도움이 돼요.

## 자주 묻는 질문

### 마켓플레이스 CLI는 어떤 명령어를 쓰나요?
마켓플레이스 CLI는 `ghl` 명령어를 써요.

### Node.js는 어떤 버전이 필요한가요?
현재 마켓플레이스 CLI 문서 기준으로 Node.js 20.12 이상이 필요해요.

### 이미 있는 마켓플레이스 앱도 CLI로 관리할 수 있나요?
네, 할 수 있어요. 이미 있는 앱의 로컬 작업 공간을 만들려면 다음 명령어를 실행하세요.

```
ghl app pull <appId>
```

### `ghl app diff`는 무슨 일을 하나요?
업데이트를 푸시하기 전에 로컬 변경 사항을 마지막으로 동기화한 상태, 현재 마켓플레이스 상태와 비교해요.

### `ghl app push`를 하면 앱 설정 전체가 바뀌나요?
아니요. CLI가 지원하는 섹션 중 바뀐 부분을 판단해서, 충돌을 확인하며 필요한 업데이트만 푸시해요.

### CI 같은 자동화 환경에서도 CLI를 쓸 수 있나요?
네, 쓸 수 있어요. CLI는 비대화형 워크플로우, 명령어 플래그, 지원하는 명령어의 기계 판독용 출력을 지원해요.

### CLI로 앱을 게시하면 어떻게 되나요?
조건을 충족한 비공개 앱은 바로 게시할 수 있어요. 조건을 충족한 공개 앱은 마켓플레이스 심사에 제출돼요.
