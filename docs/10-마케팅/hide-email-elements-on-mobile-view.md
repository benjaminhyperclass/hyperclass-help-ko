# 모바일 화면에서 이메일 요소 숨기기

이메일의 특정 요소나 레이아웃을 모바일, 데스크톱, 또는 둘 다에서 보이게 할지 정하는 방법을 안내해요. 내용을 지우지 않고도 기기마다 다르게 보여 주고 싶을 때 쓰세요.

기기별 공개 범위는 **모바일 서식**, 조건부 공개 범위와 함께 쓸 수 있어요. 세 가지를 조합하면 화면 크기에 맞춰 더 유연하게 반응하는 이메일을 만들 수 있어요.

---

## 이메일 빌더의 기기별 공개 범위란?

기기별 공개 범위는 이메일 요소나 레이아웃을 데스크톱, 모바일, 또는 둘 다에서 보여 줄지 정하는 기능이에요. 화면에 어떻게 보일지만 정하는 설정이라서, 특정 기기에서 숨겨도 이메일 빌더에서 내용이 삭제되지는 않아요.

기기별 공개 범위로 할 수 있는 일은 다음과 같아요.

- 모바일에서 요소 숨기기
- 데스크톱에서 요소 숨기기
- 데스크톱용과 모바일용 콘텐츠를 따로 보여 주기
- 한 기기에서만 레이아웃 전체 숨기기
- 복잡한 데스크톱 레이아웃이 작은 화면에 나타나지 않게 하기

하이퍼클래스 이메일 요소는 기본적으로 반응형이에요. 그래서 기기별 공개 범위는 특정 기기에서 콘텐츠가 아예 보이지 않아야 할 때 쓰는 것이 좋아요.

---

## 기기별 공개 범위의 장점

캠페인을 따로 만들지 않아도 화면 크기별로 수신자에게 보여 줄 콘텐츠를 조절할 수 있어요.

- **기기별 콘텐츠:** 필요하면 모바일과 데스크톱에서 서로 다른 콘텐츠를 보여 줄 수 있어요.
- **깔끔한 모바일 레이아웃:** 꼭 필요하지 않거나 너무 복잡한 데스크톱 콘텐츠를 작은 화면에서 뺄 수 있어요.
- **간단해지는 반응형 디자인:** 디자인 하나가 여러 기기에서 잘 맞지 않을 때 레이아웃을 따로 만들어 쓸 수 있어요.
- **유연한 콘텐츠 관리:** 숨긴 콘텐츠도 빌더에 남아 있어서 계속 편집하거나 다시 쓸 수 있어요.
- **정교한 제어:** 요소 공개 범위, 레이아웃 공개 범위, **모바일 서식**을 함께 쓰면 반응형 이메일을 더 세밀하게 꾸밀 수 있어요.

---

## 요소 공개 범위와 레이아웃 공개 범위

요소 공개 범위와 레이아웃 공개 범위는 이메일 구조에서 서로 다른 단계를 제어해요. 알맞은 쪽을 고르면 중복 설정을 줄이고 문제도 쉽게 찾을 수 있어요.

**요소 공개 범위**

콘텐츠 요소 하나만 숨기고 싶을 때 써요.

예를 들면 다음과 같아요.

- 텍스트
- 이미지
- 버튼
- 구분선
- 아이콘
- 이메일 빌더에서 지원하는 다른 요소

예를 들어 장식용 배너만 모바일에서 숨기고, 같은 섹션의 나머지는 그대로 보여 줄 수 있어요.

**레이아웃 공개 범위**

여러 요소를 묶어서 한꺼번에 숨기고 싶을 때 써요.

이럴 때 유용해요.

- 데스크톱 레이아웃에 열이 여러 개 있을 때
- 모바일에 맞춘 버전을 따로 만들었을 때
- 프로모션 섹션 전체를 한 종류의 기기에서만 보여 줘야 할 때

상위 레이아웃이 어떤 기기에서 숨겨져 있으면, 그 안의 요소는 자체 요소 공개 범위가 켜져 있어도 해당 기기에서 표시되지 않아요.

---

## 기기별 공개 범위와 모바일 서식

두 기능은 서로 다른 반응형 디자인 문제를 해결해요. 차이를 알면 알맞은 설정을 고를 수 있어요. 콘텐츠가 어떤 기기에서 아예 보이지 않아야 하면 기기별 공개 범위를 쓰세요.

콘텐츠는 그대로 보이되 모바일에서 모양만 달라야 하면 **모바일 서식**을 쓰세요.

예를 들면 다음과 같아요.

- 장식용 이미지를 모바일에서 숨기기 → 기기별 공개 범위
- 이미지는 보이게 두고 간격만 조정하기 → **모바일 서식**
- 데스크톱 전용 CTA(클릭을 유도하는 버튼) 숨기기 → 기기별 공개 범위
- CTA는 두고 정렬이나 모바일 스타일만 바꾸기 → **모바일 서식**

---

## 기기별 공개 범위와 조건부 공개 범위

기기별 공개 범위는 수신자의 기기를 기준으로 콘텐츠를 제어해요. 조건부 공개 범위는 연락처 정보나 지원되는 다른 조건을 기준으로 제어해요.

기기별 공개 범위는 이럴 때 쓰세요.

- 데스크톱 전용 콘텐츠
- 모바일 전용 콘텐츠
- 기기별 레이아웃

조건부 공개 범위는 이럴 때 쓰세요.

- 특정 연락처에게만 보여 줄 콘텐츠
- 개인화 메시지
- 연락처 필드나 규칙에 따라 보이거나 숨겨지는 콘텐츠

고급 개인화는 [조건부 요소로 캠페인 개인화하기](Email-Builder-Capabilities/how-to-personalize-your-campaigns-with-conditional-elements.md) 문서를 참고하세요.

---

## 공개 범위 설정이 적용되는 방식

공개 범위 설정에 따라 선택한 기기 화면에 어떤 콘텐츠가 들어갈지 정해져요. 요소와 상위 레이아웃의 설정을 모두 확인하세요. 상위 레이아웃의 설정이 하위 요소의 설정보다 우선할 수 있어요.

**데스크톱과 모바일에서 모두 표시**

요소나 레이아웃이 모든 기기에서 보여야 할 때 이렇게 설정해요.

**모바일에서 숨김**

데스크톱에서는 보이고 모바일에서는 보이지 않아야 할 때 써요.

**데스크톱에서 숨김**

모바일에서는 보이고 데스크톱에서는 보이지 않아야 할 때 써요.

**숨겨진 레이아웃**

레이아웃이 어떤 기기에서 숨겨지면, 그 안의 콘텐츠도 해당 기기에서 표시되지 않아요. 레이아웃을 데스크톱과 모바일 모두에서 숨기면 두 화면 어디에도 포함되지 않아요.

하이퍼클래스는 레이아웃이 어떤 기기에서 숨겨져 있을 때 회색으로 표시된 기기 아이콘 같은 시각적 표시로 알려 줘요.

---

## 자주 쓰는 기기별 디자인 패턴

기기별 공개 범위는 모바일과 데스크톱에서 정말로 콘텐츠 구조가 달라야 할 때 가장 유용해요. 기본 반응형 동작만으로 충분하면 모든 요소의 버전을 따로 만들지 마세요.

**복잡한 데스크톱 레이아웃 단순화하기**

예를 들어 이렇게 구성할 수 있어요.

**데스크톱**

- 3열 프로모션 레이아웃

**모바일**

- 별도의 1열 레이아웃

이때 다음과 같이 설정해요.

1. 데스크톱 레이아웃을 모바일에서 숨겨요.
2. 모바일 레이아웃을 데스크톱에서 숨겨요.

**꼭 필요하지 않은 장식 콘텐츠 숨기기**

큰 장식 이미지나 배너는 작은 화면에서 공간을 너무 많이 차지할 수 있어요. 이런 요소는 모바일에서 숨기고, 핵심 메시지와 CTA는 계속 보이게 하세요.

**기기별 CTA 만들기**

모바일에서 CTA의 레이아웃이나 표현을 다르게 해야 한다면 버전을 따로 만들고, 기기별 공개 범위로 알맞은 쪽만 보이게 하세요.

---

## 기기별 공개 범위 활용 팁

기기별 콘텐츠는 사용성을 높이되, 메시지에 빈틈이 생기거나 수신자에게 필요한 정보가 가려지지 않아야 해요.

- 데스크톱용과 모바일용 콘텐츠를 따로 만들기 전에 반응형 디자인을 먼저 활용하세요.
- 선택한 기기에서 정말 필요 없는 콘텐츠만 숨기세요.
- 요소에 문제가 생기면 상위 레이아웃의 공개 범위를 확인하세요.
- 중요한 캠페인 정보는 관련된 모든 기기에서 볼 수 있게 두세요.
- 규정 준수 정보나 법적으로 필요한 콘텐츠는 숨기지 마세요.
- 발송하기 전에 두 기기 버전을 모두 테스트하세요.

다음과 같은 필수 정보는 숨기지 마세요.

- 수신거부 링크
- 필수 사업자 정보
- 법적 고지
- 꼭 필요한 가격이나 약관

단, 동등한 내용이 규정에 맞게 계속 표시되는 경우는 예외예요.

---

## 모바일 또는 데스크톱에서 이메일 요소 숨기기

**공개 범위** 설정을 쓰면 요소를 삭제하지 않고 기기별 표시 여부를 정할 수 있어요.

1. **마케팅 > 이메일**로 이동해요.
2. 기존 캠페인이나 템플릿을 열거나, 새로 만들어요.
3. 이메일 빌더에서 이메일을 열어요.
4. 설정할 요소를 선택해요.
5. **공개 범위** 탭을 열어요.  
     
   ![공개 범위 탭 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155082262771/original/wgoUeSqyz-ITIy6WrDEAKegUPrqQyzAzPw.png?1790837768)
6. **Device-Based Visibility**(기기별 공개 범위) 설정을 찾아요.
7. 요소를 어느 기기에서 보여 줄지 선택해요.

   - **데스크톱**
   - **모바일**
   - 둘 다
8. 요소를 숨기려는 기기는 꺼요.
9. 이메일을 저장해요.
10. **데스크톱**과 **모바일** 미리보기를 모두 열어 결과를 확인해요.

---

## 레이아웃 전체 숨기기

관련된 요소 여러 개를 한꺼번에 숨기려면 요소마다 설정하는 것보다 레이아웃 공개 범위를 쓰는 편이 좋아요.

1. 설정할 레이아웃을 선택해요.
2. 레이아웃의 **공개 범위** 설정을 열거나, 보이는 기기 공개 범위 아이콘을 사용해요.
3. 레이아웃을 **데스크톱**, **모바일**, 또는 둘 다에서 보여 줄지 선택해요.
4. 숨긴 상태가 해당 기기 아이콘에 알맞게 표시되는지 확인해요.
5. 이메일을 저장해요.
6. 두 기기 보기를 모두 미리 확인해요.

```
참고: 레이아웃이 어떤 기기에서 숨겨져 있으면, 그 안에 있는 요소의 공개 범위 설정이 상위 레이아웃 설정보다 우선하지 않아요.
```

## 공개 범위 설정 미리 보고 테스트하기

미리보기에서는 빌더에서 의도한 레이아웃을 확인할 수 있어요. 테스트 발송에서는 실제 받은편지함에서 이메일이 어떻게 보이는지 확인할 수 있어요.

**기기별 공개 범위 미리보기**

1. 이메일 미리보기를 열어요.
2. **데스크톱 보기**를 확인해요.
3. **모바일** 보기를 확인해요.
4. 레이아웃을 추가로 확인하려면 **태블릿** 미리보기를 사용해요.
5. 다음 내용을 확인해요.

   - 데스크톱 전용 콘텐츠가 모바일에서 숨겨졌는지
   - 모바일 전용 콘텐츠가 데스크톱에서 숨겨졌는지
   - 레이아웃이 의도한 대로 표시되는지
   - 중요한 콘텐츠가 계속 보이는지

**테스트 이메일 보내기**

미리보기를 확인한 뒤에는 다음과 같이 해요.

1. **테스트 전송**을 선택해요.
2. 실제 받은편지함으로 이메일을 보내요.
3. 데스크톱과 모바일 기기에서 각각 열어 봐요.
4. 공개 범위 규칙이 의도한 대로 동작하는지 확인해요.

테스트 이메일에는 지원되는 공개 범위 설정이 그대로 반영돼요. 그래서 발송 전에 실제 환경에서의 표시 결과를 확인하기에 좋아요.

## 자주 묻는 질문

### 요소를 숨기면 이메일에서 삭제되나요?

아니요. 기기별 공개 범위는 선택한 기기에서 콘텐츠를 보여 줄지만 정해요. 요소는 이메일 빌더에 그대로 남아 있어서 계속 편집할 수 있어요.

### 모바일에서만 요소를 숨길 수 있나요?

네. 데스크톱 표시는 켜 두고 모바일 표시만 끄면 돼요.

### 데스크톱에서만 요소를 숨길 수 있나요?

네. 모바일 표시는 켜 두고 데스크톱 표시만 끄면 돼요.

### 레이아웃 전체를 숨길 수 있나요?

네. 하이퍼클래스는 개별 요소뿐 아니라 레이아웃에도 기기별 공개 범위를 지원해요.

### 상위 레이아웃이 숨겨져 있으면 어떻게 되나요?

그 레이아웃 안의 요소는 개별 요소 공개 범위가 켜져 있어도 해당 기기에서 표시되지 않아요.

### 기기별 공개 범위와 모바일 서식은 같은 기능인가요?

아니요. 기기별 공개 범위는 콘텐츠가 표시되는지를 정해요. **모바일 서식**은 보이는 콘텐츠가 모바일에서 어떤 모양으로 보일지를 바꿔요.

### 조건부 공개 범위와 기기별 공개 범위를 함께 쓸 수 있나요?

지원되는 경우에는 함께 쓸 수 있어요. 기기별 공개 범위는 기기를 기준으로 하고, 조건부 공개 범위는 연락처 데이터나 다른 조건을 기준으로 해요. 개인화 콘텐츠에 문제가 생기면 두 설정을 모두 확인하세요.

### 요소 자체의 공개 범위는 켜져 있는데 왜 숨겨져 있나요?

상위 레이아웃을 확인하세요. 레이아웃이 해당 기기에서 숨겨져 있으면 하위 요소는 표시되지 않아요.

### 공개 범위 설정이 테스트 이메일에도 적용되나요?

네. 지원되는 공개 범위 설정은 테스트 이메일과 실제 발송 이메일에 그대로 반영돼요.

### 요소를 숨기면 빈 공간이 남나요?

현재 하이퍼클래스 도움말에는 모든 개별 요소에 대해 이 동작이 일률적으로 정해져 있지 않아요. 내 디자인에서 간격이 어떻게 보이는지는 미리보기와 테스트 이메일로 확인하세요.

### 링크가 걸린 요소를 숨기면 클릭 추적에 영향이 있나요?

현재 하이퍼클래스 도움말에는 숨긴 링크 요소의 추적 동작이 명확히 정해져 있지 않아요. 기기별 추적 시나리오에 의존하기 전에, 의도한 캠페인 동작을 먼저 테스트하세요.
