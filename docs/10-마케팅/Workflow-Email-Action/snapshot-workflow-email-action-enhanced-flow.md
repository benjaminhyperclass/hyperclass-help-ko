# 스냅샷으로 워크플로우 이메일 액션 옮기기 (향상된 흐름)

하이퍼클래스 [스냅샷](../../19-에이전시-뷰/Snapshots/snapshots-overview.md)으로 저장된 이메일 템플릿을 쓰는 워크플로우를 다른 계정으로 옮길 수 있어요. 이 문서에서는 워크플로우 이메일을 스냅샷으로 옮기고, 확인하고, 안전하게 업데이트하는 방법을 안내해요. 에이전시 관리자만 쓸 수 있어요.

## 향상된 스냅샷 워크플로우 이메일 흐름이란?

스냅샷은 한 서브 계정의 설정 자산 중 선택한 것을 다른 서브 계정으로 복사해요. 가져온 워크플로우가 저장된 이메일 템플릿을 쓰면, 하이퍼클래스가 이메일 액션용 보조 사본과 그 연결을 백그라운드에서 처리해요.

원본 템플릿은 대상 계정의 이메일 템플릿 목록에 그대로 보여요. 워크플로우마다 따로 만들어지는 보조 사본은 별도 템플릿으로 보이지 않아요.

### 향상된 스냅샷 흐름의 장점

원본 템플릿을 워크플로우와 함께 옮기면 옮긴 이메일 액션을 그대로 쓸 수 있고, 대상 계정에 중복 템플릿이 생기는 일도 줄어요.

- 깔끔한 템플릿 목록: 이메일 액션용 보조 사본은 기본 템플릿 목록에 나타나지 않아요.
- 안정적인 템플릿 연결: 연결된 템플릿을 워크플로우와 함께 옮기면 이메일 액션의 연결이 유지돼요.
- 재사용 가능한 자동화: 워크플로우와 이메일 콘텐츠를 여러 서브 계정에 배포할 수 있어요.
- 제어 가능한 업데이트: 스냅샷 전체를 다시 만들지 않고, 선택한 변경 사항만 새로고침해서 반영할 수 있어요.

### 워크플로우 이메일 템플릿은 어떻게 처리되나요?

원본 이메일 템플릿, 이메일 액션용 보조 사본, 워크플로우는 서로 다른 자산이에요. 각각 어디에 나타나는지 알면 스냅샷을 가져온 결과를 확인하기 쉬워요.

- 원본 이메일 템플릿: 대상 계정의 이메일 템플릿 목록에 나타나요.
- 이메일 액션용 보조 사본: 보이는 템플릿 목록을 어지럽히지 않고 백그라운드에서 가져와 연결돼요.
- 워크플로우: **자동화 > 워크플로우**에 나타나요. 각 **이메일 보내기** 액션을 열어 콘텐츠와 템플릿 연결을 확인하세요.

## 요구 사항과 제한 사항

워크플로우 이메일은 연결된 템플릿에 의존해요. 두 자산을 모두 선택하고 올바른 순서로 옮겨야 이메일 액션이 빠지거나 연결되지 않는 문제를 막을 수 있어요.

- 필수 순서: 원본 이메일 템플릿을 워크플로우보다 먼저, 또는 워크플로우와 함께 옮기세요.
- 워크플로우만 옮기는 경우: 템플릿이 없으면 연결된 이메일 액션이 제대로 연결되지 않을 수 있어요. 나중에 템플릿을 옮겨도 연결이 복구되지 않을 수 있어요.
- 연결된 자산: 스냅샷의 폴더와 자산 카테고리를 펼쳐서 워크플로우와 관련 이메일 템플릿이 모두 선택됐는지 확인하세요.
- 이미 있는 자산: **Override**(덮어쓰기)와 **건너뛰기** 선택을 꼼꼼히 확인한 뒤, 대상 계정에서 이메일 액션을 확인하세요.

## 워크플로우 이메일과 템플릿 옮기기

원본 계정에서 스냅샷을 만들 때 워크플로우와 연결된 템플릿을 함께 포함하세요. 그런 다음 가져온 자동화를 켜기 전에 대상 계정을 확인하세요. 자산을 폴더별로 고르는 방법은 [스냅샷의 중첩 자산 선택](../../29-스냅샷/organized-nested-asset-selection-for-snapshots.md)에서 볼 수 있어요.

1. 원본 계정을 준비해요. 각 워크플로우의 **이메일 보내기** 액션을 열고, 어떤 저장 템플릿을 쓰는지 확인하세요.
2. 스냅샷을 만들어요. **에이전시 보기 > 계정 스냅샷**에서 **+ 새 스냅샷 생성**을 클릭하세요. **스냅샷 이름**을 입력하고 원본 서브 계정을 선택하세요.

   ![새 스냅샷 생성 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083356924/original/EhAi_v8nXh3UHNw61BI3mN9b30wB1YNvlQ.png?1792017418)

3. 연결된 자산을 선택해요. 카테고리와 중첩 폴더를 펼치세요. 워크플로우와 해당 이메일 템플릿 자산을 선택하고 **만들기**를 클릭하세요.
4. 대상 계정을 열어요. **에이전시 보기 > 서브 계정**으로 이동하세요. 대상 서브 계정의 점 세 개 메뉴에서 **고객 관리**를 선택한 뒤, **작업 > Load Snapshot**(스냅샷 불러오기)을 선택하세요. 자세한 내용은 [기존 서브 계정에 스냅샷 불러오기](../../19-에이전시-뷰/Snapshots/load-snapshots-into-existing-sub-account.md)에서 볼 수 있어요.

   ![대상 서브 계정에서 스냅샷 불러오기 메뉴](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083357431/original/JpBSDdGI4j51rMQm7OTXAB8k4EnautOJ_w.png?1792018879)

5. 스냅샷을 선택해요. **스냅샷 선택**을 클릭하고 해당 스냅샷을 고른 뒤 **계속하기**를 클릭하세요.
6. 불러올 자산을 선택해요. 원본 템플릿과 워크플로우를 모두 포함하세요. 필요하면 폴더를 펼쳐 선택이 맞는지 확인하고 **계속하기**를 클릭하세요.

   ![불러올 자산 선택 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083357546/original/9GX7GlPbzFz0IplT4rPX2vNhOeBZruv0KA.png?1792019141)

7. 충돌을 해결해요. 이미 있는 자산을 바꾸려면 **Override**(덮어쓰기)를, 그대로 두려면 **건너뛰기**를 선택하세요. 선택한 내용을 확인하고 **계속하기**를 클릭하세요.
8. 불러오기를 확인해요. 안내가 나오면 `confirm`을 입력하고 **계속하기**를 클릭해 스냅샷 불러오기를 시작하세요.

   ![불러오기 확인 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083357412/original/4iXq7DW-d-cpRMYziiT1pvJi4LyX8sFs5g.png?1792018786)

9. 옮겨진 자산을 확인해요. 대상 계정의 이메일 템플릿 목록에서 원본 템플릿을 찾으세요. **자동화 > 워크플로우**로 이동해 가져온 **이메일 보내기** 액션을 하나씩 열고 콘텐츠와 템플릿 연결을 확인하세요. 워크플로우를 켜기 전에 테스트 이메일도 보내 보세요.

{% hint style="warning" %}
**Override**(덮어쓰기)는 대상 계정에 있는 자산을 교체하며, 스냅샷 불러오기로는 되돌릴 수 없어요. 계속하기 전에 충돌 항목과 활성 워크플로우를 확인하세요.
{% endhint %}

## 기존 스냅샷 워크플로우 업데이트하기

원본 서브 계정에서 바꾼 내용은 기존 스냅샷에 자동으로 반영되지 않아요. **새로고침**과 **Push Update**(업데이트 푸시)로 선택한 변경 사항을 이전에 스냅샷을 받은 서브 계정에 반영하세요. 자세한 내용은 [스냅샷 새로고침 및 업데이트](../../19-에이전시-뷰/Snapshots/refresh-or-update-snapshots.md)에서 볼 수 있어요.

1. 원본 워크플로우와 연결된 이메일 템플릿을 수정하세요.
2. **에이전시 보기 > 계정 스냅샷**에서 해당 스냅샷을 찾아 **새로고침**을 클릭하세요. 바뀐 워크플로우와 템플릿을 선택한 뒤 새로고침을 확인하세요. 실패한 자산이 있으면 필요에 따라 다시 시도하세요.
3. **Push Update**(업데이트 푸시)를 클릭하세요. 이전에 연결된 대상 서브 계정과, 반영할 관련 자산을 선택하세요.
4. 업데이트 후 대상 계정의 워크플로우와 **이메일 보내기** 액션을 확인하세요. 이메일 콘텐츠와 템플릿 연결을 확인하고, 필요하면 테스트 이메일을 보내세요.

![스냅샷 새로고침 및 업데이트 푸시 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083357620/original/JkgOFpT2YHpcIrzUOe0E2Bdb-xe_2VLnIA.png?1792019383)

{% hint style="warning" %}
업데이트를 적용하려고 운영 중인 워크플로우를 습관처럼 삭제하지 마세요. 무언가를 지우기 전에 이전의 연결 문제부터 확인하세요. 업데이트로 워크플로우 단계가 사라지면, 그 단계에서 대기 중이던 연락처도 영향을 받을 수 있어요. **Push Update**(업데이트 푸시)는 내 에이전시 안의 서브 계정에만 적용돼요. 외부 에이전시는 업데이트된 스냅샷을 다시 가져와야 해요.
{% endhint %}

## 자주 묻는 질문

### 스냅샷을 불러온 뒤 이메일 보내기 액션이 없거나 연결되지 않아요. 왜 그런가요?

원본 템플릿이 워크플로우보다 먼저, 또는 워크플로우와 함께 포함됐는지 확인하세요. 선택한 자산과 불러오기 결과를 확인하고, 운영 중인 워크플로우를 교체하기 전에 연결 상태부터 살펴보세요.

### 워크플로우를 옮겨도 Sync Edits to Template 설정이 유지되나요?

동기화 가이드에 따르면 이 체크박스 상태는 스냅샷과 복제된 워크플로우에서 유지돼요. 자세한 내용은 [워크플로우 이메일 액션의 Sync Edits to Template](../how-to-use-sync-edits-to-template-in-hyperclass-workflows.md)에서 볼 수 있어요. 대상 계정에서 설정과 템플릿 연결을 모두 확인하세요.

### 옮긴 이메일 템플릿에도 조건부 발송 규칙이 유지되나요?

향상된 흐름 문서에는 **조건부 발송** 규칙이 유지된다고 나와 있어요. 스냅샷을 불러온 뒤 테스트 이메일로 조건부 콘텐츠를 확인하세요.

### 스냅샷 새로고침 중 자산이 실패하면 어떻게 하나요?

하이퍼클래스는 실패한 자산을 따로 표시해요. 다시 시도할 수 있는 실패 자산은 새로고침 전체를 처음부터 다시 하지 않고 재시도할 수 있어요.

### 어떤 스냅샷 버전과 자산을 불러왔는지 어디서 확인하나요?

**에이전시 보기 > 서브 계정**에서 대상 서브 계정을 선택하고 **작업 > 스냅샷 액션 > View snapshot history**(스냅샷 기록 보기)를 여세요. 불러오기 기록을 선택하면 버전과 자산별 상태를 볼 수 있어요. 자세한 내용은 [서브 계정에서 스냅샷 불러오기 기록 보기](../../29-스냅샷/how-to-view-snapshot-load-history-in-a-subaccount.md)에서 볼 수 있어요.

### 스냅샷으로 연락처와 대화도 옮겨지나요?

아니요. 스냅샷은 재사용할 수 있는 설정과 선택한 자산을 옮겨요. 연락처 기록, 대화, 예약, 운영 중인 계정의 이력은 옮기지 않아요.
