# 스냅샷 자산 종속성 — 연결된 자산을 함께 옮기기

스냅샷을 만들거나 새로고침하거나 로드할 때, 선택한 워크플로우와 이메일 템플릿이 필요로 하는 자산을 하이퍼클래스가 함께 챙겨 줘요. 이 문서에서는 종속성이 적용되는 범위, 자동으로 포함되는 자산을 확인하는 방법, 스냅샷을 로드하기 전에 종속성 선택을 관리하는 방법을 안내해요.

```
요약: 스냅샷을 만들거나 새로고침하면, 선택한 자산 중 지원되는 자산의 종속성이 자동으로 포함돼요. 스냅샷을 로드할 때는 자산 단계에서 Auto include dependent assets 를 켜면 그 종속성이 로드 대상으로 선택돼요. 계속하기 전에 View dependencies 로 종속성을 확인하세요.
```

## 스냅샷 자산 종속성이란?

종속성은 다른 자산이 참조하거나, 제대로 작동하려면 필요한 자산이에요. 예를 들어 워크플로우가 이메일 템플릿을 쓰거나, 커스텀 필드를 참조하거나, 태그를 적용할 수 있어요. 이럴 때 워크플로우만 옮기고 필요한 자산을 빼면 자동화의 일부가 비어 있게 돼요.

스냅샷 자산 종속성은 두 시점에 이 문제를 줄여 줘요. 하나는 스냅샷에 자산을 담을 때이고, 다른 하나는 대상 서브 계정에 로드할 자산을 고를 때예요.

예를 들어 선택한 워크플로우가 이메일 템플릿을 참조하면, 하이퍼클래스가 그 템플릿을 스냅샷에 자동으로 포함할 수 있어요. 로드할 때 **Auto include dependent assets**(종속 자산 자동 포함)를 켜면 대상 서브 계정으로 옮길 템플릿도 함께 선택돼요.

![스냅샷 자산 종속성 개요 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084153241/original/GqoiBye7Iy5Pj2-5xQLow_X4ucyxxCMumQ.png?1792978830)

## 스냅샷 자산 종속성의 장점

서로 연결된 자산을 옮길 때 드는 수작업을 줄여 줘요.

- 누락 줄이기: 선택한 워크플로우와 이메일 템플릿이 참조하는 보조 자산을 함께 포함해요.
- 수동 선택 줄이기: 관련된 필드, 값, 태그, 템플릿을 하나씩 찾아 선택하지 않아도 돼요.
- 자산 검토 쉬워짐: 종속성 표시와 툴팁으로 추가 자산이 포함된 이유를 알 수 있어요.
- 안정적인 재사용: 여러 서브 계정에 설정을 배포할 때 종속성 누락 문제가 줄어들어요.

## 지원하는 자산과 종속성

자동 종속성 감지는 초기에는 **워크플로우**와 **이메일 템플릿**에 적용돼요. 자산 선택 화면에서는 이메일 빌더 템플릿이 **이메일 빌더 템플릿** 아래에 표시돼요.

이 자산들이 무엇을 참조하느냐에 따라 종속성에는 이메일 템플릿, 커스텀 필드, 커스텀 값, 태그, 파이프라인과 파이프라인 단계, 커스텀 오브젝트, 트리거 링크, 브랜드 색상이 포함될 수 있어요.

{% hint style="warning" %}
어떤 자산이 종속성으로 포함되는 것과, 그 자산 유형 자체에 자동 종속성 감지가 적용되는 것은 달라요. 예를 들어 선택한 워크플로우가 필요로 해서 태그가 포함될 수는 있지만, 모든 스냅샷 자산 카테고리에 자동 종속성 감지가 적용된다는 뜻은 아니에요.
{% endhint %}

## 종속성이 작동하는 방식

스냅샷을 만들거나 새로고침할 때 스냅샷에 무엇이 담길지 정해져요. 스냅샷을 로드할 때는 그중 어떤 자산을 대상 서브 계정으로 옮길지 정해져요.

| 스냅샷 작업 | 종속성 동작 |
| --- | --- |
| 스냅샷 만들기 | 선택한 자산 중 지원되는 자산의 종속성을 하이퍼클래스가 감지해 자동으로 포함해요. |
| 스냅샷 새로고침 | 선택한 지원 자산을 다시 확인하고, 새로 필요해졌고 찾을 수 있는 종속성을 포함해요. |
| 스냅샷 로드 | **Auto include dependent assets**를 켜면, 로드하려고 고른 자산과 함께 종속성도 자동으로 선택돼요. |

종속성이 그 스냅샷으로 옮겨지려면 스냅샷에 담겨 있어야 하고, 로드 대상에도 포함돼야 해요. 워크플로우만 선택했다면 필요한 보조 자산이 포함됐는지 직접 확인해야 해요.

## 종속성 컨트롤과 표시

자산 선택 화면과 **버전 기록**에서 종속성을 확인할 수 있어요.

| 컨트롤 또는 표시 | 의미 |
| --- | --- |
| **Auto include dependent assets** | 스냅샷을 로드할 때 종속성을 자동으로 선택할지 정해요. 켜면 관련 자산과 함께 종속성이 선택돼요. |
| **Dependencies included** | 현재 로드 선택에 포함된 종속성 개수를 보여 줘요. |
| **Dependencies not included** | 감지된 종속성이 현재 로드 선택에 포함되지 않았다고 알려 줘요. |
| 회색 체크박스 | 자동 포함이 켜져 있을 때 자동으로 선택된 종속성을 나타내요. |
| **정보 아이콘** | 종속성 상세 정보를 보여 줘요. 마우스를 올리면 **Required by Email Builder Templates**(이메일 빌더 템플릿에서 필요)나 **Required by Email Builder Templates, Workflow**(이메일 빌더 템플릿, 워크플로우에서 필요) 같은 메시지가 나타나요. |
| 주황색 경고 아이콘 | 로드 대상으로 선택되지 않은 종속성을 나타내요. 아이콘에 마우스를 올리면 필요한 이유를 확인할 수 있어요. |
| **View dependencies** | 자산 목록을 종속성만 보이도록 걸러 줘요. 목록 위에 **종속성** 필터가 나타나요. |
| **Show all assets** | 종속성만 보던 화면에서 전체 자산 목록으로 돌아가요. |
| **Auto included** | 스냅샷 **버전 기록** 상세에서 자동으로 포함된 자산을 나타내요. |

{% hint style="info" %}
자산 선택 중에 종속성 경고가 나타나도, 그 자산이 스냅샷에 없다는 뜻은 아닐 수 있어요. 자산은 스냅샷에 있지만 이번 로드에 선택되지 않았다는 뜻일 수도 있어요.
{% endhint %}

## 스냅샷 자산 종속성 사용하기

아래 순서대로 종속성을 담고, 확인하고, 스냅샷을 로드할 때 포함해 보세요.

### 종속성을 포함해 스냅샷 만들기

1. **에이전시 보기 > 계정 스냅샷**으로 이동해요.
2. **+ 새 스냅샷 생성**을 클릭해요.
3. **스냅샷 이름**을 입력하고 원본 서브 계정을 선택해요.
4. 담으려는 워크플로우, 이메일 템플릿 등 자산을 선택해요.
5. **만들기**를 클릭해요.

선택한 자산 중 지원되는 자산의 종속성은 하이퍼클래스가 자동으로 포함해요. 종속성을 하나씩 찾아 선택하지 않아도 돼요.

### 스냅샷을 새로고침해 종속성 다시 확인하기

원본 자산을 바꿨다면 기존 스냅샷을 새로고침해서 최신 설정과 종속성을 담으세요.

1. **에이전시 보기 > 계정 스냅샷**으로 이동해요.
2. 스냅샷을 찾아 **새로고침** 아이콘을 클릭해요.
3. 포함하거나 업데이트할 자산을 선택해요.
4. **새로고침**을 클릭해요.

새로고침할 때마다 선택한 지원 자산의 종속성을 다시 확인해요. 새로고침 선택 화면에서 **워크플로우**, **이메일 빌더 템플릿** 같은 카테고리 옆의 **정보 아이콘**을 보면, 종속 자산이 자동으로 포함되며 **버전 기록**에서 확인할 수 있다는 안내가 나와요.

{% hint style="warning" %}
원본 서브 계정에서 바꾼 내용은 스냅샷에 자동으로 반영되지 않아요. 스냅샷을 새로고침하는 것만으로는 그 변경 사항이 대상 서브 계정에 배포되지도 않아요. 새로고침한 뒤에는 해당하는 로드 또는 푸시 업데이트 방법을 사용하세요.
{% endhint %}

![스냅샷 새로고침 자산 선택 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084153268/original/284Kn0eygx6a8NUzwqSDarWWxE9zzWuzQg.png?1792978877)

### 스냅샷을 로드할 때 종속성 포함하기

#### 1단계. 스냅샷 로드 화면 열기

**에이전시 보기 > 계정 스냅샷**에서 스냅샷을 찾아 **Load Updates to Sub-Account**(서브 계정에 업데이트 로드)를 열어요. **대상 서브 계정 선택**에서 서브 계정을 하나 이상 고른 뒤 자산 선택 단계로 이동해요.

**에이전시 보기 > 서브 계정**에서 시작할 수도 있어요. 대상 서브 계정의 점 세 개 메뉴를 열고 **고객 관리**를 선택한 다음 **작업 > Load Snapshot**(스냅샷 로드)을 선택해요. 스냅샷을 고르고 계속 진행하세요.

#### 2단계. 로드할 자산 선택하기

**자산** 단계에서 해당 카테고리를 펼치고, 옮기려는 워크플로우나 이메일 템플릿을 선택해요.

#### 3단계. Auto include dependent assets 켜기

자산 목록 아래의 **Auto include dependent assets**를 켜요. 필요한 종속성이 자동으로 선택되고, 상태 표시에 포함된 종속성 개수가 나타나요.

![Auto include dependent assets 를 켠 자산 선택 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084153275/original/VQOqD8VG9l7TaIsWWdeh6kZfPtjtF0kbBQ.png?1792978928)

#### 4단계. 종속성 확인하기

**View dependencies**(종속성 보기)를 클릭하면 목록에 종속 자산만 보여요. **정보 아이콘**에 마우스를 올리면 어떤 자산 유형이 그 항목을 필요로 하는지 알 수 있어요. 전체 목록으로 돌아가려면 **Show all assets**(모든 자산 보기)를 클릭하세요.

#### 5단계. 충돌 확인 후 로드 완료하기

**Proceed to check conflicts**(충돌 확인 진행)를 클릭하면 로드하기 전에 충돌 가능성을 확인할 수 있어요. 대상 계정의 기존 자산을 교체할지 유지할지 선택하고, 확인 단계를 마무리하세요. 기본 스냅샷 충돌 처리에서는 기존 자산을 덮어쓰거나, 충돌하는 스냅샷 자산을 건너뛸 수 있어요.

화면에는 **Proceed without conflict check**(충돌 확인 없이 진행)도 있어요. 종속성 포함과 충돌 확인은 서로 다른 기능이에요. 종속성을 포함했다고 해서 로드가 기존 자산에 어떤 영향을 줄지 확인하는 과정이 필요 없어지지는 않아요.

#### 6단계. 대상 자산 확인하기

로드가 끝나면 옮겨진 워크플로우와 이메일 템플릿을 살펴보세요. 이메일을 보내는 워크플로우라면 **Send Email**(이메일 보내기) 액션을 열어 템플릿 연결과 내용을 확인하고, 자동화를 활성화하기 전에 테스트 이메일을 보내 보세요.

### 버전 기록에서 자동 포함된 자산 확인하기

**버전 기록**에서 스냅샷 버전에 무엇이 들어 있는지 확인할 수 있어요.

1. **에이전시 보기 > 계정 스냅샷 > 내 스냅샷**으로 이동해요.
2. 스냅샷 이름을 클릭해 자산 보기 화면을 열어요.
3. **버전 기록** 탭을 열어요.
4. **버전 선택**에서 원하는 버전을 선택해 상세 정보를 열어요.

**Auto included**(자동 포함됨)로 표시된 자산을 찾아보세요. 종속성 표시에 마우스를 올리면 어떤 자산 유형이 그 자산을 필요로 했는지 볼 수 있어요. 하나의 종속성을 **이메일 빌더 템플릿**과 **워크플로우**처럼 여러 자산 유형이 함께 필요로 할 수도 있어요.

![버전 기록에서 자동 포함된 자산 확인 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084153304/original/TQqOYDntDDvn3W1SwyD6HpHp0DDFI-AGCw.png?1792978999)

## 알아 두면 좋은 점과 제한 사항

### 자동 종속성 감지는 적용되는 자산 유형이 제한돼요

초기 적용 범위는 워크플로우와 이메일 템플릿이에요. 다른 자산 유형은 모든 연결 관계가 감지될 거라고 가정하지 말고, 보조 자산을 직접 확인하세요.

### 로드할 때 자동 포함을 끌 수 있어요

**Auto include dependent assets**가 꺼져 있으면 종속성이 선택되지 않은 채로 남을 수 있어요. 진행하기 전에 경고 개수와 해당 항목을 확인하세요. 필요한 자산을 빼고 로드하면 대상 계정의 설정이 불완전해질 수 있어요.

### 찾지 못한 종속성은 건너뛰어요

참조된 종속성을 하이퍼클래스가 찾지 못하거나 해결하지 못하면, 해당 항목은 제외되고 나머지 스냅샷 처리는 그대로 진행돼요. 다만 그 항목을 필요로 하는 자산은 의도한 대로 작동하려면 수정이 필요할 수 있어요.

### 로드에 성공했다고 테스트가 필요 없어지지는 않아요

실제 연락처에게 사용하기 전에 대상 계정의 설정을 확인하세요. 워크플로우 이메일은 로드가 끝났다고 자동화가 준비됐다고 단정하지 말고, 가져온 이메일 내용과 템플릿 연결을 직접 확인하세요.

## 자주 묻는 질문

### 관련된 자산을 여전히 하나하나 직접 선택해야 하나요?

지원되는 워크플로우와 이메일 템플릿을 선택했다면, 스냅샷을 만들거나 새로고침할 때 사용 가능한 종속성이 자동으로 포함돼요. 로드할 때는 **Auto include dependent assets**를 켜면 그 종속성이 자동으로 선택돼요.

초기 종속성 감지 범위에 없는 카테고리는 관련 자산을 계속 직접 확인하세요.

### 제가 선택하지 않았는데 체크된 자산이 있어요. 왜 그런가요?

선택한 다른 자산이 필요로 해서 자동으로 선택된 거예요. **정보 아이콘**에 마우스를 올리면 종속성 설명을 볼 수 있어요.

### Dependencies not included 는 무슨 뜻인가요?

감지된 종속성이 현재 로드 선택에 포함되지 않았다는 뜻이에요. **View dependencies**를 클릭해 종속성을 확인한 다음, **Auto include dependent assets**를 켜거나 필요한 항목을 직접 선택하세요.

### 선택한 것보다 스냅샷에 자산이 더 많이 들어 있어요. 왜 그런가요?

지원되는 자산은 다른 자산을 참조할 수 있어요. 하이퍼클래스는 직접 선택한 자산에 더해 이런 종속성도 포함하기 때문에 최종 자산 수가 더 많을 수 있어요. 추가된 항목은 **버전 기록**의 **Auto included** 표시로 확인하세요.

### 필요한 종속성을 찾을 수 없으면 어떻게 되나요?

하이퍼클래스는 찾지 못한 종속성을 건너뛰고 나머지 자산 처리를 계속해요. 영향을 받은 워크플로우나 이메일 템플릿을 사용하기 전에, 원본 자산의 참조를 확인하고 누락된 종속성을 바로잡으세요.

### 기존 스냅샷에 새 종속성을 담으려면 어떻게 하나요?

관련 워크플로우나 이메일 템플릿을 선택해 스냅샷을 새로고침하세요. 새로고침하면 해당 자산의 종속성을 다시 확인해요. 그런 다음 업데이트된 스냅샷을 확인하고, 알맞은 로드 또는 푸시 업데이트 방법으로 변경 사항을 배포하세요. 원본 계정에서 수정한 내용은 기존 스냅샷에 자동으로 반영되지 않아요.

### 종속성을 포함하면 충돌 확인은 건너뛰어도 되나요?

아니요. 종속성 포함은 어떤 보조 자산을 선택할지 정하는 기능이에요. 충돌 확인은 선택한 스냅샷 자산이 대상 계정의 기존 자산을 교체할지, 아니면 건너뛰고 기존 자산을 유지할지 검토하는 과정이에요.
