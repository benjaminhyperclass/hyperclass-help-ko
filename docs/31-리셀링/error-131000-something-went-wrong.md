# WhatsApp 오류 131000(Something Went Wrong) 해결하기

WhatsApp 메시지가 오류 코드 131000으로 실패할 때 원인과 진단 방법, 해결 순서를 안내해요. 이 문서에서 다루는 내용은 다음과 같아요.

- 오류 131000의 의미
- 알려진 원인
- 진단 방법
- 단계별 해결 방법

## 오류 131000이란?

오류 **131000**은 WhatsApp Cloud API 오류예요. 공식 제목은 **"Something Went Wrong"**(문제가 발생했어요)이에요. Meta 쪽에서 알 수 없는 이유로 메시지 발송이 실패했을 때 나타나요. 계정 설정, 액세스 토큰, 템플릿, API 요청에 문제가 있어서 시스템이 더 구체적인 이유를 알려 주지 못할 때도 나타나요. 이때 **HTTP 500**(내부 서버 오류)로 반환돼요.

API 응답에서는 다음과 같이 보여요.

```
"errors": [
  {
    "code": 131000,
    "title": "Something Went Wrong",
    "message": "Message failed to send due to an unknown error."
  }
]
```

오류 131000은 여러 원인을 하나로 묶어서 보여 주는 포괄적인 오류예요. 원인이 달라도 같은 일반 메시지가 나오고, Meta가 더 구체적인 이유를 알려 주지 않아요. 그래서 계정과 API 설정을 여러 곳에서 차례로 확인해야 해요.

```
Meta 공식 문서에 따르면, 오류 131000은 다음과 같은 경우에 발생할 수 있어요. 비즈니스 공개 키의 서명을 API가 처리하지 못할 때, GraphQL 요청이 실패할 때, GraphQL 엔드포인트가 오류를 반환할 때, 서버 측에 일시적인 장애가 있을 때예요. 계정의 설정 문제로도 발생할 수 있어요.
```

## 알려진 원인

확인된 원인과 자주 보고되는 원인을 정리했어요.

### 1. Meta 서버의 일시적인 문제 또는 장애

오류 131000은 Meta 서버의 일시적인 문제로 생기는 경우가 많아요. WhatsApp Business Platform에 다운타임, 성능 저하, 점검이 있으면 설정과 상관없이 모든 메시지에서 이 오류가 나타날 수 있어요. 가장 먼저 배제해야 할 원인이에요.

### 2. 만료되었거나 유효하지 않은 액세스 토큰

API 요청 인증에 쓰는 액세스 토큰이 만료되었거나 취소되었거나, 필요한 권한이 없을 수 있어요. 필요한 권한은 `whatsapp_business_management`와 `whatsapp_business_messaging`이에요. 토큰이 유효하지 않으면 인증 관련 오류 대신 오류 131000으로 API 호출이 실패할 수 있어요.

### 3. WhatsApp 비즈니스 계정(WABA)이 제한되었거나 플래그가 지정된 경우

WABA가 정책 위반, 낮은 품질 등급, 검토 대기 등으로 제한되었거나 플래그가 지정된 상태이면 메시지가 실패할 수 있어요. 이때 더 구체적인 계정 오류 코드 대신 오류 131000이 나타날 수 있어요.

### 4. 승인되지 않았거나 잘못된 상태의 템플릿

**검토 중**, **거절됨**, **일시 중지**, **비활성화됨** 상태인 템플릿을 보내려고 하면 오류 131000이 생길 수 있어요. Meta Business Manager에서 승인된 템플릿과 이름이나 언어 코드가 다를 때도 마찬가지예요.

### 5. 24시간이 지난 뒤 자유 형식 메시지를 보내려는 경우

수신자가 마지막으로 메시지를 보낸 지 24시간이 지났는데 자유 형식(템플릿이 아닌) 메시지를 보내면 API가 오류 131000을 반환할 수 있어요. 고객 서비스 시간(24시간) 밖에서는 승인된 템플릿 메시지만 보낼 수 있어요.

### 6. 잘못되었거나 형식이 맞지 않는 전화번호

수신자 전화번호에 국가 코드가 없거나, 공백이나 특수 문자가 들어 있거나, 그 밖에 형식이 맞지 않을 수 있어요. 이런 번호는 구체적인 유효성 검사 오류 대신 오류 131000이 반환될 수 있어요.

### 7. 비즈니스 공개 키 서명 실패 또는 GraphQL 엔드포인트 오류

Meta 문서에 따르면 비즈니스 공개 키를 설정할 때 API가 서명을 처리하지 못하거나, GraphQL 엔드포인트 요청이 실패하거나 오류를 반환하면 오류 131000이 발생할 수 있어요. 보통 Meta 쪽 인프라 문제예요.

### 8. 앱 또는 API 설정 문제

Meta Developer 앱의 설정이 잘못되었을 때도 메시지를 보내다가 오류 131000이 생길 수 있어요. 예를 들면 웹훅 설정이 잘못되었거나, 시스템 사용자 토큰이 오래되었거나, 전화번호 ID와 앱이 맞지 않는 경우예요.

## 해결 방법

아래 단계를 순서대로 따라 하며 원인을 찾아 해결하세요.

### 1단계. Meta 플랫폼 상태에서 장애가 있는지 확인하기

[metastatus.com/whatsapp-business-api](https://metastatus.com/whatsapp-business-api)에서 WhatsApp 서버에 장애나 성능 저하가 있는지 확인하세요. 진행 중인 장애가 있으면 **Meta가 해결할 때까지 기다린 뒤** 다시 시도하세요. 플랫폼 전체 장애가 확인되었다면 계정별 설정을 계속 점검하지 마세요. 장애가 해소되면 오류도 저절로 사라져요.

### 2단계. 잠시 기다린 뒤 메시지 다시 보내기

장애가 없다면 몇 분 기다린 뒤 메시지를 다시 보내세요. 오류 131000은 서버 측의 일시적인 실패라서 저절로 해결되는 경우가 많아요. 오류가 한 번만 나타나거나 간헐적으로 나타난다면 다시 보내는 것만으로 충분한 경우가 많아요. 계속 반복된다면 다음 단계로 넘어가세요.

### 3단계. 액세스 토큰이 유효하고 권한이 올바른지 확인하기

**Meta Access Token Debugger**([developers.facebook.com/tools/debug/accesstoken](https://developers.facebook.com/tools/debug/accesstoken/))에 들어가 토큰을 붙여 넣고 다음을 확인하세요.

- 토큰이 유효하고 만료되지 않았어요.
- 토큰에 `whatsapp_business_management`와 `whatsapp_business_messaging` 권한이 모두 있어요.
- 토큰이 **영구 시스템 사용자 토큰**이에요. 몇 시간 뒤에 만료되는 단기 사용자 토큰이 아니어야 해요.

토큰이 만료되었거나 권한이 없다면 Meta Developer 대시보드에서 새 영구 액세스 토큰을 만드세요. 그런 다음 CRM 연동에 새 토큰을 업데이트하세요.

### 4단계. WhatsApp 비즈니스 계정 상태 확인하기

**Meta Business Suite**에 로그인해 WhatsApp 비즈니스 계정으로 이동한 뒤 다음을 확인하세요.

- WABA 상태가 **활성**이에요. 제한됨, 플래그 지정됨, **비활성화됨** 상태가 아니어야 해요.
- 전화번호 상태가 **연결됨**이고 품질 등급이 빨간색이 아니에요.
- 계정에 정책 위반 알림이나 처리해야 할 조치가 없어요.

### 5단계. 템플릿 상태와 설정 확인하기

하이퍼클래스 또는 Meta Business Manager에서 **Message Templates**(메시지 템플릿)로 이동해 사용 중인 템플릿이 다음 조건을 만족하는지 확인하세요.

- 상태가 **활성**이에요. **검토 중**, **거절됨**, **일시 중지**, **비활성화됨** 상태가 아니어야 해요.
- API 요청의 템플릿 이름이 Meta Business Manager의 이름과 정확히 같아요(대소문자 구분).
- 요청의 언어 코드가 승인된 템플릿의 언어와 정확히 같아요(예: `en` 이 아니라 `en_US`).

### 6단계. 수신자 전화번호 형식 확인하기

수신자 번호에 올바른 **국제 국가 코드**가 있고, 공백·하이픈·특수 문자가 없는지 확인하세요. 예를 들어 미국 번호는 `+1 (555) 123-4567`이 아니라 `15551234567` 형식이어야 해요. 또 번호가 WhatsApp에 등록되어 있는지도 확인하세요. 유효한 것으로 확인된 다른 번호로 테스트해 보면 알 수 있어요.

### 7단계. 계속된다면 알려진 우회 방법 쓰기: Meta Developer Console에서 새 앱 만들기

위 점검을 모두 통과했는데도 오류가 계속된다면 다음 우회 방법을 써 보세요. 많은 사용자의 문제를 해결했고, Meta 개발자 커뮤니티에서도 확인된 방법이에요.

1. [developers.facebook.com](https://developers.facebook.com)의 **Meta Developer Console**에서 새 앱을 만드세요.
2. 새 앱에 전화번호와 템플릿을 추가하세요.
3. 새 앱의 **영구 액세스 토큰**을 새로 만드세요.
4. 웹훅이 새 앱을 가리키도록 다시 설정하세요.
5. CRM 연동에 새 토큰과 앱 설정을 업데이트한 뒤 테스트하세요.

```
이 우회 방법은 Meta 개발자 커뮤니티에서 검증되었고, 계속 반복되는 131000 사례 대부분을 해결해 줘요. 토큰을 업데이트하는 것만으로는 고칠 수 없는 설정 문제나 앱 수준의 손상을 해결하는 방법이에요.
```

### 8단계. 그래도 해결되지 않으면 고객지원에 문의하기

위 단계로 해결되지 않으면 하이퍼클래스 고객지원에 문의하세요. 다음 정보를 함께 보내 주시면 Meta로 이관해 처리할 수 있어요.

- 실패하는 API 요청 페이로드 전체`fbtrace_id` 값을 포함한 전체 API 오류 응답
- 오류가 처음 나타난 시각과 발생 빈도
- 특정 템플릿, 번호, 수신자에게만 발생하는지 여부
- 위 단계 중 이미 완료한 단계

## 예방 방법

오류 131000을 만날 가능성을 줄이는 방법이에요.

- 영구 시스템 사용자 토큰을 쓰세요. 단기 토큰은 만료되어 인증 실패가 생길 수 있어요. Meta의 System Users에서 영구 토큰을 만들면 인증 관련 오류가 간헐적으로 생기는 일을 막을 수 있어요.
- WABA 상태를 정기적으로 확인하세요. Meta Business Suite에서 계정 상태, 전화번호 품질 등급, 정책 알림을 살펴보면 제한 때문에 메시지가 막히기 전에 알 수 있어요.
- 발신 메시지에는 승인된 템플릿을 쓰세요. 24시간 고객 서비스 시간 밖에 있는 연락처에는 템플릿 메시지만 보내세요. 이 시간이 지난 뒤 자유 형식 메시지를 보내면 실패할 수 있어요.
- 지수 백오프(exponential backoff)를 적용한 재시도 로직을 만드세요. 오류 131000은 일시적인 경우가 많아요. API 연동에 재시도 로직을 넣어, API를 계속 호출하지 말고 재시도 간격을 점점 늘리세요.
- 보내기 전에 전화번호 형식을 검증하세요. 모든 수신자 번호가 올바른 국제 형식인지 확인한 뒤 API에 보내세요.
- Meta 상태 페이지 알림을 구독하세요. [metastatus.com](https://metastatus.com)에서 알림을 설정하면 WhatsApp 플랫폼에 장애가 생겼을 때 바로 알 수 있어요.

## 관련 오류 코드

비슷한 상황에서 만날 수 있는 다른 오류예요.

| 오류 코드 | 제목 | 설명 |
| --- | --- | --- |
| 131005 | Access Denied(액세스 거부) | 권한이 부여되지 않았거나 삭제되었어요. 액세스 토큰 권한을 확인하세요. |
| 131031 | Account Locked(계정 잠김) | 플랫폼 정책 위반으로 WABA가 제한되었거나 비활성화되었어요. |
| 131047 | Re-engagement Message(재참여 메시지) | 수신자가 마지막으로 답장한 지 24시간이 지났어요. 자유 형식 메시지 대신 템플릿 메시지를 사용하세요. |
| 132001 | Template Does Not Exist(템플릿이 존재하지 않음) | 지정한 언어로 된 템플릿이 없거나 아직 승인되지 않았어요. |
| 1 | API Unknown(알 수 없는 API 오류) | 잘못된 요청이거나 서버 오류일 수 있어요. WhatsApp Business Platform 상태 페이지를 확인하고 요청 형식을 점검하세요. |

## 자주 묻는 질문

### 잘 되던 메시지에서 갑자기 오류 131000이 나타났어요. 무슨 일이죠?

변경한 것이 없는데 갑자기 오류 131000이 나타났다면 Meta 서버의 일시적인 문제나 짧은 플랫폼 장애인 경우가 가장 많아요. 먼저 Meta 상태 페이지를 확인하세요. 장애가 보고되지 않았다면 액세스 토큰이 만료되지 않았는지, WABA가 정상 상태인지 확인하세요. Meta가 특정 앱 설정에 영향을 주는 인프라 변경을 했을 때도 이 오류가 갑자기 나타날 수 있어요.

### 오류 131000이 나오면 바로 다시 보내야 하나요?

네. 잠시 기다린 뒤 다시 보내는 것이 오류 131000의 첫 번째 조치예요. 일시적인 서버 측 오류인 경우가 많기 때문이에요. 다만 쉬지 않고 반복해서 재시도하지는 마세요. 첫 재시도는 최소 30~60초 기다린 뒤에 하고, 그 뒤에는 지수 백오프로 간격을 늘리세요. 여러 번 재시도해도 계속된다면 이 문서에 나온 구체적인 원인을 하나씩 확인하세요.

### 오류 131000이 나온 메시지에도 요금이 부과되나요?

아니요. 전달되기 전에 실패한 메시지는 대화를 열지 않고 요금도 부과되지 않아요. 오류 131000이 반환된 메시지에는 요금이 청구되지 않아요.

### 오류 131000이 특정 수신자 한 명에게만 나타나요. 그 사람 쪽 문제인가요?

한 연락처에서만 오류가 난다면 수신자 쪽 문제일 가능성이 높아요. 번호가 WhatsApp에 없거나, 24시간 시간이 지났거나, 번호 형식이 잘못된 경우예요. 같은 번호로 템플릿 메시지를 보내 보고, 유효한 것으로 확인된 다른 수신자에게도 테스트해서 그 연락처만의 문제인지 더 넓은 문제인지 확인하세요.

### Meta가 이 오류에 대한 공식 해결책이 없다는데, 실제로 무엇을 할 수 있나요?

맞아요. Meta는 131000을 알 수 없는 일반 오류로 분류하고, 확실한 해결책도 공개하지 않아요. 하지만 이 문서의 단계를 따르면 도움이 돼요. 특히 액세스 토큰, WABA 상태, 템플릿 상태를 확인하고, 필요하면 새 앱을 만들어 토큰과 웹훅을 다시 설정하는 방법으로 이 문제를 신고한 대다수 사용자가 해결했어요. 그래도 해결되지 않으면 오류 응답의 `fbtrace_id`를 첨부해서 Meta에 Direct Support 티켓을 여세요.

## 요약

{% hint style="info" %}
오류 131000은 여러 원인을 포괄하는 일반적인 HTTP 500 실패예요. 먼저 Meta 플랫폼 상태에서 장애가 있는지 확인한 뒤 잠시 기다렸다가 다시 시도하세요. 계속된다면 액세스 토큰, WABA 상태, 템플릿 상태, 전화번호 형식을 확인하세요. 모두 이상이 없다면 커뮤니티에서 확인된 우회 방법으로, Meta Developer Console에서 새 앱을 만들고 토큰과 웹훅을 다시 설정하세요. 그래도 계속된다면 `fbtrace_id`와 함께 하이퍼클래스 고객지원에 문의하세요.
{% endhint %}
