# 워크플로우 AI 빌더(Workflow AI Builder)로 자동화 만들기

만들고 싶은 자동화를 평소 쓰는 말로 적으면 AI가 워크플로우 전체를 만들어 줘요. 트리거와 액션을 하나씩 설정하는 대신 워크플로우를 생성하고, 내용을 확인한 뒤, AI로 다듬을 수 있어요. 이 문서에서는 열기 방법, 만드는 순서, 수정 방법, 잘 쓰는 요령을 설명해요.

## 워크플로우 AI 빌더란?

워크플로우 AI 빌더는 우리가 적은 문장을 처음부터 끝까지 이어진 워크플로우로 바꿔 줘요. 트리거, 액션, 구조를 AI가 만들어 주니 설정 시간이 줄고, 만들어진 결과를 바로 확인하고 고칠 수 있어요.

명확한 프롬프트를 입력하면 AI가 워크플로우 전체를 생성해요. 여러 경로로 시작할 수 있고, 생성 후에는 대화로 수정하거나, 화면에서 직접 선택해 수정하거나, 만들지 않고 채팅으로 구상만 해 볼 수도 있어요.

프롬프트에 계정에 이미 있는 레코드(폼, 파이프라인과 단계, 이메일 스니펫, 태그, 사용자, 워크플로우, 커스텀 필드)의 이름을 적으면 AI 빌더가 그 레코드를 찾아 각 단계에 설정해 줘요. 워크플로우 생성과 설정이 한 번에 끝나서, 나중에 값을 직접 고를 필요가 없어요.

**AI 빌더 v3의 새로운 점**

AI 빌더 v3는 워크플로우를 만들거나 수정하는 동안 결과를 실시간으로 보여 주고, 단계별 진행 상황도 함께 보여 줘요. 주요 개선 사항은 다음과 같아요.

- 생성·수정 요청 중 진행 상황 카드를 실시간으로 표시
- 한 번의 요청으로 여러 단계 변경 (예: “이름을 바꾸고, 24시간 대기를 추가하고, 재진입을 꺼 줘”)
- 이어서 수정할 때 쓸 수 있는 세션 기억 (예: “그걸 48시간으로 바꿔 줘”)
- 이미 워크플로우가 있는 캔버스에서 새로 시작하기 전에 확인 메시지 표시
- AI 패널을 닫았다가 다시 열어도 이어지는 세션
- **Learn Mode**(학습 모드) 개선: 답변을 실시간으로 보여 주고 후속 질문을 추천
- 화이트라벨에 안전한 출력 (AI가 응답에서 플랫폼 브랜드 용어를 쓰지 않아요)
- 조건에 맞는 모든 단계, 지정한 개수의 단계, 특정 액션·트리거만 골라 한꺼번에 수정하고, 지정하지 않은 단계는 그대로 둠

## 워크플로우 AI 빌더의 장점

장점을 알면 AI로 만들 때와 직접 만들 때를 구분하기 쉽고, 둘을 섞어 쓰면 속도와 세밀한 제어를 함께 얻을 수 있어요.

- 속도: 프롬프트 하나로 워크플로우 전체를 몇 초 만에 생성해요.

{% hint style="info" %}
AI 빌더는 이제 워크플로우를 생성하는 데 평균 30초가 걸리지 않아요(이전에는 약 60초). 품질은 그대로예요.
{% endhint %}

- 간편함: 트리거와 액션 이름을 외울 필요 없이 일상적인 말로 쓰면 돼요.
- 일관성: 구조가 잡힌 초안으로 시작해서 정확해질 때까지 다듬을 수 있어요.
- 유연함: 자연스러운 말로 수정하거나, 특정 단계를 화면에서 직접 골라 수정할 수 있어요.
- 확장성: 프롬프트 템플릿과 모범 사례를 팀 전체에서 재사용할 수 있어요.
- 내 데이터로 설정: 계정에 이미 있는 폼, 파이프라인, 스니펫, 태그, 사용자, 워크플로우, 커스텀 필드를 각 단계에 그대로 써요.

## 워크플로우 AI 빌더 여는 방법

여는 방법을 모두 알아 두면 클릭 수를 줄이고, 지금 있는 화면에서 가장 빠른 경로를 고를 수 있어요. 워크플로우 AI 빌더는 세 가지 방법으로 열 수 있어요.

**자동화 > 워크플로우**로 이동해서 **Build using AI**(AI로 만들기) 버튼을 클릭하세요. 프롬프트를 입력하는 창이 열려요.

**Create Workflow**(워크플로우 만들기)와 **Start from Scratch**(처음부터 시작)를 차례로 클릭하면 워크플로우 빌더 화면으로 바로 들어갈 수도 있어요.

![Create Workflow와 Start from Scratch 선택 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155066106277/original/nJCZEp2c6kCyTJtemUnzwl6yIXNVb18GTg.png?1772549317)

새 워크플로우를 처음부터 만들면 워크플로우 빌더 안에 AI 프롬프트 입력창이 보여요. 만들고 싶은 자동화를 입력하거나, 음성 입력으로 말해서 설명해도 돼요.

![워크플로우 빌더 안의 AI 프롬프트 입력창](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155066106052/original/B5T2A9j4YW9jE-t_Cf4QZSpHTH3yoCCl5g.jpeg?1772549182)

## 첫 AI 워크플로우 만들기

프롬프트 입력, 생성, 검토, 수정 순서로 진행하면 AI 결과를 자동화 목표에 맞출 수 있어요.

### 1단계: 프롬프트 입력하기

위에서 소개한 방법 중 하나로 프롬프트를 입력하거나, 챗봇에게 워크플로우 만들기를 요청하세요. 시작하는 방법은 두 가지예요.

1. 직접 쓰거나 말해서 프롬프트 입력: 필요한 자동화를 내 말로 설명해요.

![직접 입력하는 프롬프트 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155071092860/original/AJYEWZNfARu8XczaYb-Da4RfFcT0lU-qdQ.png?1778569815)

2. 제공되는 템플릿 사용: 화면에 있는, 미리 작성된 프롬프트 템플릿 중에서 골라요.

![프롬프트 템플릿 목록 1](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155055142796/original/kPHEAhJb_FR6ZBf03QWFdqovygq_jkXaVw.png?1759471427)

![프롬프트 템플릿 목록 2](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155055142811/original/xqbopLTDqkvScSWAMU9w4DOp4T6l066aUg.png?1759471444)

**이런 프롬프트를 사용해 보세요.**

- "문의 폼을 작성한 사람에게 웰컴 이메일을 순서대로 보내 줘."
- "생일 리마인더 워크플로우를 만들어서 SMS로 생일 축하 인사를 보내 줘."
- "금액이 큰 기회가 만들어지면 Slack으로 우리 팀에 알려 줘."
- "웨비나가 끝나고 24시간 뒤에 참석자에게 후속 연락을 해 줘."
- "영상 제작 요청 폼이 제출되면 마케팅 파이프라인의 신규 리드 단계에 기회를 만들고 웰컴 이메일 스니펫을 보내 줘."

선택사항으로 다음 내용을 함께 적을 수 있어요.

- 워크플로우 이름
- 적용하고 싶은 워크플로우 설정
- 사용할 도구/앱 (예: “ClickUp에서 작업을 만들어 줘”)
- 이전 액션의 데이터를 어떻게 쓸지 (예: “GPT 출력을 이메일 본문에 넣어 줘”)
- 단계에서 써야 하는 계정 속 레코드의 정확한 이름 (폼, 파이프라인과 단계, 이메일 스니펫, 태그, 사용자, 워크플로우, 커스텀 필드 등)

AI로 관리할 수 있는 워크플로우 설정은 다음과 같아요. 프롬프트에서 AI 빌더에게 아래 설정을 확인, 활성화, 비활성화, 업데이트하도록 요청할 수 있어요.

- **Allow Re-entry**(재진입 허용)

- **Allow multiple Opportunities**(기회 여러 개 허용)

- **Stop on Response**(응답 시 중단)

- **Timezone and Time Window**(시간대 및 시간 범위, 영업시간)

- **Sender Details**(발신자 정보): **From Name**(보낸 사람 이름), **From Email**(보낸 이메일), **From Number**(보낸 번호)

- **Conversations – Mark as Read**(대화 읽음 처리)

- 워크플로우 이름 (생성할 때 이름을 정하거나, 기존 워크플로우 이름을 변경)

프롬프트 예시:

"이 워크플로우 이름을 Appointment Follow Up v2로 바꾸고, 발신 이메일을 support@mybusiness.com으로 업데이트하고, 메시지는 월~금 오전 9시~오후 6시에만 보내도록 제한하고, 재진입이 꺼져 있는지 확인해 줘."

{% hint style="info" %}
위 목록의 **Sender Details**는 워크플로우 설정이에요. 워크플로우 AI 빌더는 범위를 지정한 수정 지시로 모든 이메일 액션, 또는 선택한 이메일 액션의 **From Name**과 **From Email**도 바꿀 수 있어요.
{% endhint %}

![AI로 관리할 수 있는 워크플로우 설정 프롬프트 예시](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155077501233/original/PvtTNgpIW19w4JRmzaVAQZzZ7L2_zLRs_A.png?1785769334)

### 2단계: 워크플로우 생성하기

**Build Workflow**(워크플로우 만들기) 버튼을 클릭하거나, 열었던 경로에 따라 **Send**(보내기)를 누르세요. AI가 요청을 처리하고 워크플로우를 만드는 동안 로딩 표시가 나타나요.

{% hint style="info" %}
워크플로우 생성은 보통 평균 30초 안에 끝나요. 더 오래 걸리면 프롬프트를 단순하게 고쳐서 다시 생성해 보세요.
{% endhint %}

{% hint style="info" %}
Workflow AI에서는 자동 저장을 쓸 수 있어요. 자동 저장을 켜 두면 AI가 만든 워크플로우는 만들어지는 즉시 자동으로 저장되고, 이후 AI로 하는 수정도 백그라운드에서 저장돼요.
{% endhint %}

![워크플로우를 생성하는 중의 로딩 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155055142837/original/y7JgKdDfHRoaAODfK9MqJSw4RRPHKY6SNQ.png?1759471506)

### 3단계: 검토하고 수정하기

AI가 워크플로우 만들기를 마치면 자동화와 함께 생성된 워크플로우의 요약도 볼 수 있어요.

- 첫 번째 방법(워크플로우 목록 페이지)으로 열었다면 워크플로우 빌더 화면으로 이동해요.
- 두 번째나 세 번째 방법으로 열었다면 지금 보고 있는 빌더 화면에 바로 워크플로우가 생성돼요.

![생성된 워크플로우와 요약 화면 1](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155066106384/original/TbrnuGRCWRjg84fuWpxXhr9TELXrMVT0Kw.png?1772549425)

![생성된 워크플로우와 요약 화면 2](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155066106454/original/OUZqQnyP-U1ls_9db5TZunlMjU3Ok4dK1A.png?1772549458)

이제 다음을 할 수 있어요.

- 워크플로우 전체 구조 검토
- 트리거별 설정 확인
- 액션 설정과 파라미터 확인
- 각 단계가 내가 이름을 적은 폼, 파이프라인, 스니펫, 사용자, 필드를 쓰는지 확인

### 4단계: AI로 수정하기

워크플로우를 검토한 뒤에는 AI 챗봇에 자연스러운 말로 요청해서 다듬어요. 바꿀 내용과 적용 범위를 함께 설명하세요. 조건에 맞는 모든 단계에 적용할지, 지정한 개수의 단계에만 적용할지, 특정 액션과 트리거에만 적용할지 알려 주면 돼요. 워크플로우 AI 빌더는 그 범위만 업데이트하고 지정하지 않은 단계는 그대로 둬요.

**If/Else**(조건 분기), **Wait**(대기) 같은 복잡한 액션도 대화로 수정할 수 있어요. 조건 업데이트, 분기 추가·삭제, 대기 설정 변경, 기존 로직 다듬기를 워크플로우 대화에서 벗어나지 않고 할 수 있어요.

AI에게 다음도 요청할 수 있어요.

- 워크플로우 이름 변경
- 워크플로우 설정(재진입, 기회 여러 개 허용, 응답 시 중단, 시간대/시간 범위, 발신자 정보, 대화 읽음 처리) 확인, 활성화, 비활성화
- 이후 액션이 앞선 단계의 출력을 쓰도록 단계 업데이트 (예: AI 출력을 메시지에 넣기)

### AI가 만든 변경 사항 되돌리기·다시 실행하기

현재 편집 세션에서 워크플로우 AI 빌더가 만든 변경 사항은 되돌리거나 다시 실행할 수 있어요.

- Windows에서는 `Ctrl+Z`, Mac에서는 `Cmd+Z`를 누르면 AI가 만든 마지막 변경이 취소되고 이전 워크플로우 상태로 돌아가요.
- Windows에서는 `Ctrl+Y`, Mac에서는 `Cmd+Y`를 누르면 방금 되돌린 AI 변경을 다시 실행해요.

되돌리기와 다시 실행은 액션 추가, 기존 단계 수정, 워크플로우 구조 변경 같은 AI 변경 사항에 적용돼요.

AI로 계속 작업하는 동안 이전 AI 생성 버전은 현재 세션의 되돌리기 기록에 남아 있어요. 워크플로우 빌더의 **Recent Changes**(최근 변경 사항)에서도 최근 수정 내역을 확인할 수 있어요.

## 수정할 수 있는 항목

대화로 수정하는 기능은 현재 다음을 지원해요.

**액션:**

- 워크플로우의 원하는 위치에 새 액션 추가
- 불필요한 액션 제거 (단일 경로와 다중 경로 모두)
- 기존 액션을 다른 액션으로 교체
- 액션 구성과 설정 수정
- 이전 단계의 값을 쓰도록 액션 업데이트 (액션 간 데이터 연결)
- 연동 앱을 쓰는 액션 추가·업데이트 (예: 작업 생성 액션)
- 액션을 워크플로우 안의 다른 위치로 이동

**트리거:**

- 트리거 추가
- 기존 트리거 제거
- 트리거를 다른 유형으로 교체
- 트리거 구성 수정

**복잡한 수정:**

- 한 번의 프롬프트로 여러 변경 사항을 함께 요청할 수 있어요.

**제한 사항:**

- 한 번의 프롬프트로 여러 변경 사항을 함께 요청할 수 있어요.
- **If/Else** 액션은 대화로 수정할 수 있어요. 분기 안의 세그먼트를 추가, 삭제, 업데이트하고, 분기와 세그먼트의 AND/OR 연산자를 바꾸고, 분기를 추가하거나 삭제할 수 있어요. 요청이 복잡하면 AI 빌더가 어느 분기나 세그먼트를 업데이트할지 확인하는 질문을 할 수 있어요.
- **Wait** 액션도 대화로 수정할 수 있어요. 대기 속성 업데이트, 답장 또는 시간 범위 설정 조정, 타임아웃 분기 추가·삭제, 대기 유형 변경이 가능해요.

**대상을 지정한 수정과 일괄 수정:**

지시 하나로 조건에 맞는 모든 단계, 지정한 개수의 단계, 또는 특정 액션과 트리거에 같은 변경을 적용할 수 있어요. 워크플로우 AI 빌더는 내가 정한 범위만 업데이트해요.

지원하는 수정 예시는 다음과 같아요.

- 여러 이메일, SMS 등 지원되는 커뮤니케이션 액션의 문구 업데이트
- 모든 액션과 트리거, 또는 지정한 액션과 트리거의 파이프라인 단계 변경
- 모든 이메일 액션, 또는 선택한 이메일 액션의 From Name과 From Email 설정
- 나머지 액션은 그대로 두고 정해진 액션 그룹에만 정확한 문구 적용

**수정 프롬프트 예시**

- "웰컴 이메일과 후속 이메일 사이에 3일 대기를 추가해 줘."
- "SMS 액션을 Slack 알림으로 바꿔 줘."
- "처음 두 액션의 SMS 문구만 업데이트해 줘."
- "처음 20개 이메일 액션의 문구를 바꾸고, 나머지 이메일 액션은 그대로 둬 줘."
- "트리거를 폼 제출에서 연락처 생성으로 바꿔 줘."
- "연락처가 구매한 적이 있는지 확인하는 if/else 조건을 추가해 줘."
- "이 대기 액션에서 타임아웃 분기를 삭제해 줘."

{% hint style="info" %}
다중 경로 삭제를 요청하면 AI가 의도와 맞는지 확인하는 질문을 할 수 있어요.
{% endhint %}

## Point and Edit(선택 편집)으로 정밀하게 수정하기

지시문에 범위를 적거나 **Point and Edit**을 써서 워크플로우 단계를 지정할 수 있어요. 말로 설명하는 것보다 화면에서 직접 액션을 고르는 편이 더 명확할 때 **Point and Edit**을 쓰세요.

**작동 방식:**

1. AI 챗봇 화면에서 **Point and Edit**을 클릭해 선택 모드를 켜세요.

   ![AI 챗봇에서 Point and Edit 선택 모드를 켠 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155063176154/original/fN9IobkIQuBTC-EAqDyVsxh729kowdfeXw.jpeg?1769009160)
2. 수정할 액션을 선택하세요. 클릭해서 하나를 고르거나, 여러 개를 클릭하거나, `Shift`를 누른 채 드래그해서 범위를 선택할 수 있어요. 선택한 액션은 강조 표시돼요.

   ![수정할 액션을 선택한 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155063176201/original/X_H8hYXTANOYS_fB1dteqL1USDFeqSlF9w.jpeg?1769009179)
3. 채팅에 바꿀 내용을 설명하세요. AI는 선택한 단계에만 변경을 적용해요.

   ![선택한 액션에 변경을 요청하는 채팅 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155063176238/original/zz0xRbfFWU9RLuZbWOzNWuanFgDhO1Wz1A.jpeg?1769009206)

**Point and Edit 사용 예시:**

- 순서대로 이어진 이메일 액션 3개를 선택하고 "이걸 모두 SMS 메시지로 바꿔 줘"라고 말해요.
- 특정 작업 액션을 선택하고 "문구를 좀 더 급하게 바꿔 줘"라고 말해요.
- 한 분기 안의 액션 여러 개를 선택하고 "이걸 전부 태그 액션 뒤로 옮겨 줘"라고 말해요.
- 액션 그룹을 선택하고 "선택한 액션을 삭제해 줘"라고 말해요.

**Point and Edit의 장점:**

- 정밀함: 다른 부분에 영향을 주지 않고 원하는 부분만 수정해요.
- 시각적 명확성: 변경하기 전에 무엇을 수정하는지 눈으로 확인해요.
- 효율성: 선택한 여러 액션을 한꺼번에 바꿀 수 있어요.
- 오류 감소: 비슷한 액션이 많은 복잡한 워크플로우에서 헷갈리는 일을 줄여 줘요.

{% hint style="info" %}
액션이 10개 이상이거나 분기가 여러 개라서 말로만 설명하면 모호할 수 있는 워크플로우에서 **Point and Edit**이 특히 유용해요.
{% endhint %}

## 워크플로우 AI 빌더의 확인 질문 에이전트(Clarifying Agent)

확인 질문 에이전트는 새 워크플로우를 만들거나 기존 워크플로우를 수정하기 전에 빠진 내용을 먼저 물어봐서, 워크플로우 AI 빌더가 더 나은 결과를 내도록 도와줘요. 처음 생성한 결과의 정확도가 올라가고 불필요한 수정이 줄어들며, AI가 실행하기 전에 알맞은 맥락을 갖출 수 있어요.

요청이 너무 넓거나 중요한 내용이 빠져 있으면 워크플로우 AI 빌더가 진행하기 전에 짧은 확인 질문 몇 개를 할 수 있어요. 그러면 워크플로우를 만들거나 수정할 때 AI가 잘못 짐작하는 일을 피할 수 있어요.

다음처럼 핵심 내용이 빠져 있을 때 확인 질문 에이전트가 나타날 수 있어요.

- 워크플로우 트리거가 정해지지 않았을 때
- 메시지 채널이 지정되지 않았을 때
- 시점이 불분명할 때
- 지원하지 않는 채널을 요청했을 때

질문은 빠르고 쉽게 답할 수 있게 만들어져 있어요. 제시된 선택지 중에서 고르거나 직접 답을 입력할 수 있어요. 답하고 싶지 않으면 질문을 건너뛰고 AI가 정하게 할 수도 있어요.

워크플로우 AI 빌더는 계속 진행하기 전에 최대 3개의 확인 질문을 해요.

---

### 확인 질문 에이전트가 나타나는 경우

워크플로우 AI 빌더가 요청에 믿을 만한 결과를 만들 만큼의 내용이 없다고 판단하면 확인 질문 에이전트가 나타나요. 새 워크플로우 요청과 기존 워크플로우의 수정 요청 모두에 해당해요.

**예시:**

- 트리거 없이 "고객에게 후속 연락해 줘"라고 요청한 경우
- 채널 없이 "메시지 시퀀스를 보내 줘"라고 요청한 경우
- 시점 없이 "나중에 알려 줘"라고 요청한 경우
- 지원하지 않는 채널을 요청한 경우

---

### 확인 질문에 답하는 방법

확인 질문은 AI 빌더가 진행하기 전에 내 의도를 좁혀 가도록 도와줘요. 답하면 AI가 더 많은 맥락을 얻어서, 대개 첫 시도부터 더 나은 결과가 나와요.

1. AI 빌더가 보여 주는 질문을 하나씩 읽어 보세요.

2. 제시된 선택지 중 하나를 고르거나, 직접 답을 입력하세요.

3. 질문이 여러 개이면 계속 이어서 답하세요.

4. AI가 정하게 하고 싶은 질문은 건너뛰세요.

5. 추가된 맥락으로 AI 빌더가 워크플로우를 생성하거나 수정하게 하세요.

### 확인 질문이 워크플로우 생성에 도움이 되는 이유

입력이 분명할수록 결과가 좋아져요. 확인 질문 에이전트가 생성이나 실행 전에 빠진 내용을 모아 두면 수정 횟수가 줄고, 워크플로우를 만들고 수정하는 품질이 올라가요.

---

## 채팅 모드(Chat Mode)

**Chat Mode**를 켜면 워크플로우를 만들지 않고 계획만 세울 수 있어요. 변경을 적용하기 전에 AI와 함께 요구 사항을 정리해 보세요.

**Chat Mode 사용 방법**

- AI 패널에서 **Chat Mode**를 클릭해 브레인스토밍 모드를 켜세요.
- AI와 함께 트리거, 액션, 분기, 타이밍을 계획하세요.
- 준비가 되면 **Chat Mode**를 끄고 AI에게 워크플로우를 만들어 달라고 요청하세요.

![AI 패널에서 Chat Mode를 켠 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155055149074/original/noVufQ9GyG5ef2gQ9oXstNQlfjvxvlMzqw.png?1759477034)

**AI와 함께 구상하기**

- 먼저 구상하기: 무엇을 만들지 정하면서 AI를 브레인스토밍 파트너로 활용해요.
- 계획 세우기: AI와 의견을 주고받으며 액션과 트리거 계획을 만들어요.

![AI와 함께 워크플로우를 구상하는 채팅 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155055149108/original/RCloMStLYMCjWWMALAuSk3dPshXr_g5USQ.png?1759477050)

**AI에게 만들어 달라고 요청하기**

- 계획이 정해지면 **Chat Mode**를 끄세요.
- 그다음 AI에게 워크플로우를 만들어 달라고 요청하세요.

![Chat Mode를 끄고 AI에게 생성을 요청하는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155055149127/original/i9bZAdOgepgINy9cgvEUNbCr3V2zJ-bV2A.png?1759477058)

## 생성 후 할 일 목록 (게시하기 전에 완료)

AI가 워크플로우를 만든 뒤에는 할 일 목록(**Complete these steps before executing your workflow**, 워크플로우를 실행하기 전에 이 단계를 완료하세요)을 확인하세요. 자격 증명, 필수 필드, 커스텀 값처럼 아직 직접 입력해야 하는 항목이 나와 있어요.

할 일 항목을 선택하면 해당 액션으로 바로 이동해요. 빠진 내용을 채운 다음 게시하세요. 그러면 완성되지 않은 워크플로우가 실제로 동작하는 일을 막을 수 있어요.

**할 일 목록에 자주 나오는 항목은 다음과 같아요.**

- 연동 자격 증명 연결
- 알맞은 계정 선택
- AI 빌더가 자동으로 정하지 못한 액션 설정 완료
- 필수 필드 값 입력
- 선택지가 여러 개일 때 단계별 설정 지정

![생성 후 할 일 목록 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155071092349/original/lbQFQ93RwRd5KfgI8RLJvUb7rbUrkDZEjg.gif?1778569411)

## 좋은 프롬프트를 쓰는 요령

프롬프트가 분명할수록 정확도가 올라가요. 시점, 채널, 조건, 콘텐츠를 구체적으로 적어야 AI가 기대한 대로 만들어요.

- 구체적이고 명확하게 쓰세요. 예: “연락처가 예약을 하면 24시간 기다린 뒤 확인 이메일을 보내고, 예약 하루 전에 리마인더 SMS를 보내 줘.”
- 핵심 내용을 포함하세요. 시점, 채널, 조건/필터, 콘텐츠 유형을 적으면 돼요.
- 동작을 나타내는 말로 시작하세요. “보내 줘”, “알려 줘”, “만들어 줘”, “업데이트해 줘”, “기다려 줘”, “확인해 줘”처럼 쓰면 돼요.
- 수정 범위를 정하세요. 변경을 조건에 맞는 모든 단계에 적용할지, 정해진 개수의 단계에만 적용할지, 특정 액션과 트리거에만 적용할지 적으세요.
- 레코드의 정확한 이름을 적으세요. 폼, 파이프라인, 단계, 스니펫, 태그, 사용자, 워크플로우, 커스텀 필드 이름을 계정에 표시된 그대로 쓰세요.

---

## 피드백 보내기

피드백은 생성 품질을 높이고 앞으로의 개선에 반영돼요.

- 워크플로우가 만들어지면 피드백 챗봇이 열려요.
- 워크플로우가 기대에 맞았다면 엄지 올리기를, 아니라면 엄지 내리기를 클릭하고 개선할 점을 남겨 주세요.
- 자동화가 의도와 맞았는지, 빠지거나 잘못된 부분은 무엇인지, 제안할 점은 무엇인지 알려 주세요.

---

## 베타 제한 사항

현재의 제한을 알아 두면, 생성된 워크플로우를 활성화하기 전에 어떤 확인을 할지 계획하기 쉬워요.

- 수동 검토 필요: 게시하기 전에 트리거, 액션, 설정을 확인하세요.
- 설정 확인: 복잡한 설정은 직접 조정해야 할 수 있어요.
- 테스트: AI는 워크플로우를 테스트할 수 없어요. 직접 테스트하세요.

---

## 문제 해결

첫 초안이 기대에 못 미치면 프롬프트를 고치고 범위를 좁혀서 AI를 이끌어 주세요.

- 프롬프트 다듬기: 내용을 더 자세히 쓰거나 복잡한 목표를 작게 나눠 보세요.
- 트리거가 잘못된 경우: 프롬프트에 정확한 트리거 유형을 적거나 AI로 수정하세요.
- 액션이 빠진 경우: 원하는 액션을 하나씩 분명히 적거나 대화로 수정해 추가하세요.
- 타이밍이 틀린 경우: “2일 후”처럼 정확한 시간 표현을 쓰세요.
- 엉뚱한 레코드가 선택된 경우: 폼, 파이프라인, 스니펫, 사용자, 필드의 이름을 계정에 표시된 그대로 쓰거나, 대화로 수정하세요.

---

## 빠른 팁

AI로 워크플로우를 만들 때 이 팁을 따르면 설정 시간이 줄고 흔한 실수를 막을 수 있어요.

- 간단한 워크플로우로 시작해서 기능을 익힌 다음, 점점 복잡하게 만들어 보세요.
- 항상 게시하기 전에 테스트하세요.
- 피드백을 남기면 시간이 지날수록 결과가 좋아져요.
- 새 기능과 개선 사항이 있는지 가끔 다시 확인해 보세요.

{% hint style="info" %}
생성된 워크플로우를 게시할 준비가 안 됐다면 AI 패널의 생성 후 할 일 목록을 확인하세요. 아직 직접 입력해야 하는 액션과 트리거를 보여 줘요.
{% endhint %}

## 자주 묻는 질문

### 생성된 워크플로우를 AI로 수정할 수 있나요?

네. 대화로 수정해서 액션과 트리거를 추가, 제거, 교체, 이동, 수정할 수 있어요. **If/Else**와 **Wait** 액션의 다중 경로 구성도 대화로 수정할 수 있어요.

### 수정할 때 특정 단계만 고를 수 있나요?

네. 지시문에서 조건에 맞는 모든 단계, 정해진 개수의 단계, 또는 특정 액션과 트리거를 지정해 범위를 정하세요. 워크플로우 AI 빌더는 그 범위에만 변경을 적용해요. **Point and Edit**으로 워크플로우 액션을 하나 이상 화면에서 직접 선택할 수도 있어요.

### 워크플로우가 내 의도와 다르면 어떻게 하나요?

프롬프트를 더 자세히 고쳐 쓰거나 대화로 수정하세요. 만들기 전에 **Chat Mode**에서 먼저 계획을 세울 수도 있어요.

### 그래도 테스트를 해야 하나요?

네. 활성화하기 전에 항상 실제 테스트로 트리거, 액션, 타이밍, 결과를 확인하세요.

### 워크플로우 AI 빌더를 끄려면 어떻게 하나요?

에이전시 수준 또는 서브 계정 수준에서 끌 수 있어요.

에이전시 관리자는 **설정 > 실험실**로 이동해서 **Workflow AI Builder**(워크플로우 AI 빌더)를 비활성화하세요.

서브 계정에서는 **자동화 > 글로벌 워크플로우 설정 > Workflow AI**(워크플로우 AI)로 이동해서 **AI 빌더** 토글을 끄세요.

### 생성 후 할 일 목록에 항목이 나오는 이유는 무엇인가요?

연동 자격 증명, 계정 선택, 아직 정해지지 않은 액션 설정처럼 직접 입력해야 하는 설정이 남아 있어서 그래요. 게시하기 전에 이 항목을 완료하세요.

### AI가 만든 워크플로우는 바로 게시해도 되나요?

항상 그런 건 아니에요. 생성한 뒤 할 일 목록을 확인하고, 필수 항목을 모두 채운 다음에 게시하세요.

### 계정에 이미 있는 폼, 파이프라인 같은 레코드를 워크플로우 AI 빌더가 쓸 수 있나요?

네. 계정에 표시된 이름 그대로 프롬프트에 적으세요. AI 빌더가 각 레코드를 찾아서 맞는 단계에 설정해 줘요. 예를 들어 트리거의 폼 필터, **Create Opportunity**의 파이프라인과 단계, **Send Email**에 연결할 스니펫, **Create Task**의 담당자, **Update Contact Field**의 필드가 설정돼요.

### 단계에 엉뚱한 레코드가 쓰였어요. 어떻게 하나요?

AI 빌더에게 대화로 수정해 달라고 요청하거나, 액션을 열어서 올바른 레코드를 직접 선택하세요. 게시하기 전에 항상 각 단계를 확인하세요.
