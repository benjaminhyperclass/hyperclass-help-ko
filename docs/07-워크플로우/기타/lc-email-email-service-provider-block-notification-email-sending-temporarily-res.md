# 하이퍼클래스 이메일: ESP 차단 안내 — 이메일 발송 일시 제한 (조치 필요)

새로 도입되는 ESP(이메일 서비스 제공업체) 차단 정책의 전체 내용, 지금 바로 해야 할 조치, 서브 계정이 영구 정지되지 않도록 관리하는 방법을 안내해요.

## 시행 일정

**시행일**: 2026년 2월 12일. 이 ESP 차단 정책은 2026년 2월 12일부터 적용돼요. 현재 사용자에게는 사전 안내가 가기 때문에, 정책이 적용되기 전에 이메일 발송 방식을 점검할 시간이 있어요.

지금 해야 할 일은 다음과 같아요.

- 현재 반송 분류 데이터를 확인하세요.
- 이메일 인증과 권장 모범 사례를 적용하세요.
- 이메일 목록을 정리하고 콘텐츠 품질을 높이세요.
- ESP 차단율을 주의 깊게 모니터링하세요.

{% hint style="warning" %}
**24~48시간 안에 조치가 필요해요.** ESP(이메일 서비스 제공업체) 차단 때문에 서브 계정의 이메일 발송이 일시적으로 제한됐어요. 이는 발신자 평판을 지키고 높은 전달률을 유지하기 위한 스팸 방지 정책의 일부예요.
{% endhint %}

## ESP 차단이란?

Gmail, Yahoo, Outlook 같은 주요 이메일 제공업체가 아래와 같은 이유로 내 이메일을 거부하는 것을 ESP 차단이라고 해요.

- 인증 실패 (DMARC, SPF, DKIM 문제)
- 낮은 발신자 평판
- 스팸처럼 보이는 콘텐츠
- 정책 위반
- 기술 설정 문제

{% hint style="info" %}
ESP 차단은 일반 반송과 따로 계산돼요. 장기적인 이메일 전달률을 보호하기 위해 차단이 걸리면 바로 제한이 적용돼요.
{% endhint %}

## 새로운 ESP 차단 시스템

차단은 일시 차단 3단계로 단계적으로 강화되고, 각 차단 전에 경고 이메일이 발송돼요. 전체 진행 과정은 아래 표와 같아요.

| ESP 차단율 | 조치 | 지속 시간 | 차단 단계 |
| --- | --- | --- | --- |
| 3% | 경고 이메일 발송 | 즉시 알림 | 차단 전 경고 |
| 5% | 이메일 발송 정지 | 12시간 | 1차 차단 |
| 3% (1차 차단 이후) | 긴급 경고 이메일 발송 | 즉시 알림 | 2차 차단 전 경고 |
| 5% (1차 차단 이후) | 이메일 발송 정지 | 24시간 | 2차 차단 |
| 3% (2차 차단 이후) | 최종 경고 이메일 발송 | 즉시 알림 | 3차 차단 전 최종 경고 |
| 5% (2차 차단 이후) | 영구 정지 | 영구 | 3차 차단 — 최종 |

{% hint style="warning" %}
ESP 차단율을 7일 연속으로 1% 미만으로 유지하면 모든 차단이 초기화돼요.
{% endhint %}

{% hint style="info" %}
이번 릴리스에서는 이메일 발송이 영구적으로 비활성화되지 않아요. 각 차단은 일시적이며 24시간까지만 적용돼요.
{% endhint %}

**ESP Block Detected**(ESP 차단 감지)로 이메일 서비스가 차단되면, 해당 서브 계정 안쪽 상단 배너에 다음 오류 메시지가 표시돼요.

"이메일 제공업체의 스팸 차단 건수가 많아 이메일 발송이 차단되었습니다."

![서브 계정 안에 표시되는 ESP 차단 오류 배너](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155064792608/original/5TW75eQ0t8kTt0vQOwFX3kr_-mcIEgdcDQ.png?1770907247)

이 차단은 이메일 전달률을 지키고, 이메일 서비스 제공업체(ESP)에서 평판이 더 나빠지는 것을 막기 위해 적용돼요.

복구 방법은 [ESP 차단 감지 — 이메일 발송 복구를 위한 즉시 조치](lc-email-email-service-provider-block-detected-immediate-action-required-to-rest.md) 문서를 참고하세요.

## 지금 바로 해야 할 일

먼저 즉시 해야 할 3단계를 진행하고, 이어서 3단계 준비 계획을 따르세요.

### 즉시 필요한 조치

#### 1단계: Bounce Classification 기능 열기

1. 서브 계정에 로그인하세요.
2. **설정 > 이메일 서비스 > Bounce Classification**(반송 분류)으로 이동하세요.
3. ESP 차단 카테고리와 오류 상세 내용을 확인하세요.
4. 서브 계정에 영향을 주는 ESP 차단 중 건수가 가장 많은 항목을 찾으세요.

#### 2단계: 주된 문제 파악하기

**Bounce Classification**에서는 다음 정보를 볼 수 있어요.

- ESP 차단 카테고리별 내역 (DMARC 실패, 평판 문제 등)
- 제공업체별(Gmail, Yahoo, Outlook) 오류 건수
- 차단 이유가 정확히 적힌 오류 메시지 상세
- 차단 유형별 권장 조치

#### 3단계: 문제 해결하기

반송 분류 결과를 바탕으로 다음 항목을 개선해야 해요.

- 이메일 인증 설정 (SPF, DKIM, DMARC)
- 콘텐츠와 템플릿 개선
- 목록 관리와 참여도 문제
- 기술 설정 문제

## 새 정책 준비하기

### 1단계: 현재 상태 점검

#### Bounce Classification 대시보드 확인

- **설정 > 이메일 서비스 > Bounce Classification**으로 이동하세요.
- 현재 ESP 차단율과 카테고리를 확인하세요.
- 최근 이메일 캠페인 성과를 검토하세요.
- 개선이 필요한 부분을 기록해 두세요.

#### 과거 데이터 분석

- 지난 30일간의 반송률을 검토하세요.
- ESP 차단의 패턴을 찾으세요.
- 어떤 이메일 제공업체에서 가장 많이 차단하는지 확인하세요.

### 2단계: 이메일 모범 사례 적용

#### 이메일 인증 설정

- 플랫폼의 발송 IP가 포함되도록 SPF 레코드를 설정하세요.
- 내 도메인에 DKIM 서명을 설정하세요.
- DMARC 정책을 적용하세요. 모니터링을 위해 `p=none`으로 시작하세요.
- 모든 DNS 레코드가 올바르게 설정됐는지 확인하세요.

#### 목록 관리와 품질

- 반송됐거나 유효하지 않은 이메일 주소를 모두 제거하세요.
- 신규 구독자에게 이중 수신 동의(double opt-in)를 적용하세요.
- 참여도에 따라 목록을 나누세요.
- 6개월 이상 참여가 없는 비활성 구독자를 제거하세요.

#### 콘텐츠 최적화

- 스팸 유발 단어와 과도한 홍보 문구를 피하세요.
- 텍스트와 이미지 비율을 적절히(60:40) 유지하세요.
- 수신거부 링크를 분명하게 넣으세요.
- 전문적이고 브랜드가 드러나는 이메일 템플릿을 사용하세요.
- 스팸 검사 도구로 콘텐츠를 테스트하세요.

### 3단계: 모니터링과 테스트

#### 적용 전 테스트

- 주요 제공업체(Gmail, Yahoo, Outlook)로 테스트 이메일을 보내세요.
- 전달률과 참여 지표를 모니터링하세요.
- 이메일 테스트 도구로 스팸 점수를 확인하세요.
- 이메일 인증이 올바르게 작동하는지 확인하세요.

#### 지속적인 모니터링

- Bounce Classification 대시보드를 매일 확인하세요.
- ESP 차단율을 주의 깊게 모니터링하세요.
- 참여 지표(열람, 클릭, 수신거부)를 추적하세요.
- 비정상적인 반송 패턴에 대한 알림을 설정하세요.

## 왜 중요한가요?

### 내 비즈니스 보호

- ESP 차단은 발신자 평판에 영구적인 손상을 줘요.
- 평판이 나쁘면 이메일이 스팸함으로 들어가요.
- 전달률이 떨어지면 비즈니스 매출에 영향을 줘요.
- 적절히 조치하지 않으면 회복에 몇 주에서 몇 달이 걸릴 수 있어요.

### 업계 표준

- 주요 ESP는 이메일 품질에 점점 더 엄격해지고 있어요.
- 인증 요건이 이제 필수예요.
- 콘텐츠 필터링이 더 정교해졌어요.
- 발신자 평판은 앞으로의 모든 캠페인에 영향을 줘요.

## 다음 단계

1. **분석**: **Bounce Classification** 기능으로 내 ESP 차단의 구체적인 원인을 파악하세요.
2. **수정**: 자세한 고객지원 문서를 참고해 확인된 문제를 해결하세요.
3. **모니터링**: 반송 분류 대시보드에서 개선 상황을 추적하세요.
4. **확인**: 수정이 제대로 적용됐는지 확인한 뒤 정상적으로 발송을 재개하세요.

## 지원 자료

### Bounce Classification 기능

- ESP 차단 상세 분석을 확인할 수 있어요.
- 오류 카테고리와 건수를 볼 수 있어요.
- 내 서브 계정에 맞는 권장 사항을 받을 수 있어요.
- 개선 진행 상황을 모니터링할 수 있어요.

### 카테고리별 고객지원 문서

반송 분류의 ESP 차단 카테고리마다 자세한 해결 가이드로 연결돼요.

- DMARC 인증 실패
- 도메인/IP 평판 문제
- 콘텐츠 및 스팸 필터링
- 기술 설정 문제
- 그 밖의 카테고리

## 시간이 중요한 조치

### 정책 시행 전

- 이메일 인증 설정을 완료하세요.
- 모든 이메일 목록을 꼼꼼히 정리하세요.
- 이메일 콘텐츠와 템플릿을 최적화하세요.
- 주요 제공업체에서 이메일 전달을 테스트하세요.
- Bounce Classification 대시보드를 매일 확인하세요.

### 경고를 받은 후 24시간 이내

- 반송 분류 데이터를 바로 검토하세요.
- ESP 차단 상위 3개 카테고리를 파악하세요.
- 핵심 문제(인증, 주요 콘텐츠 문제)부터 수정하세요.

### 차단된 후 48시간 이내

- 기술적인 수정을 모두 마치세요.
- 이메일 목록을 정리하고 문제가 되는 콘텐츠를 제거하세요.
- 주요 제공업체에서 이메일 전달을 테스트하세요.

### 상시

- Bounce Classification 대시보드를 매일 확인하세요.
- 이메일 모범 사례를 계속 지키세요.
- 목록 관리와 참여도 모니터링을 정기적으로 하세요.

## 도움이 필요하세요?

### 직접 해결하기

- **Bounce Classification** 기능으로 상세 분석을 확인하세요.
- 카테고리별 고객지원 문서의 단계별 해결 방법을 따라 하세요.
- 이메일 모범 사례 문서를 확인하세요.

### 고객지원 문의

반송 분류 데이터를 해석하거나 문제를 해결하는 데 도움이 필요하면, 하이퍼클래스 고객지원에 아래 내용과 함께 문의하세요.

- 서브 계정 정보
- **Bounce Classification** 기능 화면 캡처
- 확인되는 구체적인 오류 메시지

## 꼭 기억하세요

- ESP 차단은 일반 반송과 별개예요. 바로 조치해야 해요.
- 제공업체마다 요구 사항이 달라요. 반송 분류에서 제공업체별 문제를 확인하세요.
- 사후 수습보다 예방이 낫습니다. 처음부터 올바른 이메일 운영 방식을 적용하세요.
- 시간이 중요해요. 문제 해결이 늦어지면 영구 제한으로 이어질 수 있어요.
- 준비 기간은 30일이에요. 이 기간에 이메일 운영 방식을 최적화하세요.

이메일 전달률과 비즈니스 성과는 지금 하는 조치에 달려 있어요. **Bounce Classification** 기능에서 시작해 새 정책 시행에 대비하세요.

## 자주 묻는 질문

### 새 정책은 언제부터 적용되나요?
ESP 차단 시스템은 2026년 2월 12일부터 시행돼요. 모든 사용자가 30일 동안 이메일 운영 방식을 준비하고 최적화할 수 있어요.

### 지금 걸려 있는 ESP 차단은 어떻게 되나요?
시행일에 ESP 차단 이력이 초기화돼요. 그래도 원활하게 운영하려면 정책이 시작되기 전에 현재 문제를 해결하는 것을 적극 권장해요.

### 차단은 어떻게 초기화되나요?
ESP 차단율을 7일 연속으로 1% 미만으로 유지하면 차단이 초기화돼요. 다만 7일 이내에 차단이 3번 발생하면 영구 정지가 적용돼요.

### 영구 정지를 되돌릴 수 있나요?
영구 정지는 자동으로 해제되지 않아요. 고객지원팀이 직접 검토해야 하고, 해제가 보장되지는 않아요. 이메일 모범 사례를 지켰는지에 따라 달라져요. 그래서 최종 조치 전에 여러 번 경고하고 일시 정지를 먼저 적용해요.

### 차단되기 전에 알림을 받을 수 있나요?
네. ESP 차단율이 3%에 도달하면 경고 이메일을 받아요. 5%가 되어 차단되기 전에 조치할 시간이 생겨요.

### 현재 ESP 차단율이 3%를 넘으면 어떻게 하나요?
2026년 2월 12일 전까지의 준비 기간에 문제를 해결하세요. 시행일 전에는 차단 시스템이 적용되지 않아서 문제를 고칠 시간이 있어요.

### 일반 반송 관리와는 무엇이 다른가요?
ESP 차단은 일반 반송과 따로 계산되고, 별도의 차단 시스템이 적용돼요. 일반 반송(존재하지 않는 주소, 가득 찬 편지함)과 ESP 차단(평판, 인증, 정책 문제)은 처리 방식이 달라요.

이 정책은 발신자 평판을 지키고 장기적으로 이메일 전달률을 높게 유지하기 위한 거예요. 새 요건에 맞게 준비할 수 있도록 하이퍼클래스 고객지원이 도와드려요.
