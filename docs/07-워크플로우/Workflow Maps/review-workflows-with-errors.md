# 오류가 있는 워크플로우 검토하기

오류가 발생한 워크플로우를 찾고, 실패한 실행 내역을 확인한 다음, 워크플로우를 열어 문제가 된 단계를 수정하세요.

## 오류 배지(badge)의 의미

오류 배지는 워크플로우(Workflow)가 최근 실행 중 오류를 겪었다는 것을 나타냅니다. 이 배지를 보고 추가 확인이 필요한 워크플로우를 식별할 수 있어요.

배지는 문제가 있다는 것을 알려줍니다. 실패한 실행 내역을 열어 오류 내용을 확인하고 문제가 발생한 단계를 파악하세요.

## 오류가 있는 워크플로우 찾는 방법

- **Automation(자동화) → Workflows(워크플로우) → Workflow Maps**로 이동하세요.
- **Review workflows with errors(오류가 있는 워크플로우 검토)**를 클릭하세요.
- **Published(발행됨)**와 **Draft(초안)** 워크플로우로 구분된 목록을 확인하세요.
- 워크플로우를 선택해서 실패한 실행 내역을 확인하세요.

맵(map)을 표시된 워크플로우로만 좁혀 보려면 **Has issues(문제 있음)** 필터를 사용하세요.

## 실패한 실행 내역 확인하기

오류 검토 화면에서 워크플로우를 선택하면 실패한 실행 내역, 실패한 단계, 오류 내용을 확인할 수 있어요.

오류 내용은 문제가 발생한 단계와 함께 확인하세요. 예를 들어 웹훅(Webhook) 액션이 실패했다면, 액션을 수정하기 전에 해당 실행의 오류를 먼저 확인하세요.

워크플로우 단계를 확인하고 수정하려면 **Open in builder(빌더에서 열기)**를 사용하세요.

워크플로우 상세 화면에서 과거 실행 내역을 확인하려면 **Total Enrolled(총 등록 수)**를 선택하고 등록 건을 고른 다음, 실패한 액션을 선택해서 **Event details(이벤트 상세)**를 열어보세요.

![](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084352890/original/mOnXgw21UI5mvgDXNZIBj4Q9a1TY3_gEnA.jpg?1793135852)

과거 실행 상세 내역에서는 실패한 액션, 상태, 오류 메시지를 확인할 수 있어요.

## 단계 수정 후 확인 처리하기

- 빌더(builder)에서 문제가 된 워크플로우를 여세요.
- 오류 내용을 확인하고 문제가 된 단계를 수정하세요.
- Workflow Maps로 돌아오세요.
- 문제를 검토한 후 **Mark as read(읽음으로 표시)**를 클릭해서 배지를 없애세요.

**Mark as read**는 알림 배지만 없애줍니다. 워크플로우를 실제로 수정하려면 빌더에서 변경 작업을 해야 하며, 배지를 없앤다고 해서 워크플로우가 자동으로 수정되지는 않아요.

## 자주 묻는 질문

**Q: 표시된 모든 워크플로우를 한 곳에서 볼 수 있나요?**

네. **Review workflows with errors**를 클릭하시면 됩니다.

**Q: Published와 Draft가 왜 따로 분류되나요?**

검토 화면은 표시된 워크플로우를 현재 발행 상태별로 그룹화해서 보여줍니다.

**Q: 맵(map)에서 바로 워크플로우 단계를 수정할 수 있나요?**

**Open in builder**를 사용하면 워크플로우를 수정할 수 있어요.

**Q: Mark as read를 누르면 실패한 실행이 재시도되나요?**

아니요. 이 기능은 배지를 없애는 용도로만 사용되며, 재시도나 복구 기능으로 사용하시면 안 돼요.
