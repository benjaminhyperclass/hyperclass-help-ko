# 오류가 있는 워크플로우 확인하고 고치기

오류가 발생한 워크플로우를 찾아 실패한 실행을 확인하고, 해당 워크플로우를 열어 문제가 된 단계를 고치는 방법을 안내해요.

## 오류 배지가 뜻하는 것

오류 배지는 워크플로우가 최근 실행 중에 오류를 만났다는 표시예요. 확인이 필요한 워크플로우를 찾을 때 활용하세요.

배지는 문제가 있다는 사실만 알려 줘요. 오류 내용과 문제가 된 단계를 알려면 실패한 실행을 열어 보세요.

## 오류가 있는 워크플로우 찾기

1. **자동화 > 워크플로우 > Workflow Maps**(워크플로우 맵)를 여세요.
2. **Review workflows with errors**(오류가 있는 워크플로우 검토)를 클릭하세요.
3. 목록을 확인하세요. 목록은 **게시됨**과 **임시 저장** 워크플로우로 나뉘어 있어요.
4. 워크플로우를 선택해 실패한 실행을 확인하세요.

플래그가 표시된 워크플로우만 맵에 보려면 **Has issues**(문제 있음) 필터를 사용하세요.

## 실패한 실행 확인하기

오류 검토 화면에서 워크플로우를 선택하면 실패한 실행, 실패한 단계, 오류 내용을 볼 수 있어요.

오류 내용과 해당 단계를 함께 살펴보세요. 예를 들어 웹훅 액션이 실패했다면, 액션을 바꾸기 전에 그 실행의 오류부터 확인하세요.

**Open in builder**(빌더에서 열기)를 누르면 워크플로우 단계를 살펴보고 편집할 수 있어요.

워크플로우 상세 화면에서 과거 실행을 확인하려면 다음과 같이 하세요.

1. **Total Enrolled**(총 등록 수)를 선택하세요.
2. 등록 내역 하나를 고르세요.
3. 실패한 액션을 선택해 **Event details**(이벤트 상세)를 여세요.

![과거 실행 상세에서 실패한 액션, 상태, 오류 메시지를 확인하는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084352890/original/mOnXgw21UI5mvgDXNZIBj4Q9a1TY3_gEnA.jpg?1793135852)

과거 실행 상세 화면에서 실패한 액션, 상태, 오류 메시지를 확인할 수 있어요.

## 단계를 고치고 읽음 처리하기

1. 해당 워크플로우를 빌더에서 여세요.
2. 오류 내용을 확인하고 문제가 된 단계를 수정해요.
3. Workflow Maps로 돌아옵니다.
4. 문제를 확인한 뒤 **Mark as read**(읽음으로 표시)를 클릭해 배지를 지우세요.

{% hint style="warning" %}
**Mark as read**는 알림 배지만 지워요. 워크플로우를 고치려면 빌더에서 직접 수정해야 하며, 배지를 지운다고 수정이 적용되지는 않아요.
{% endhint %}

## 자주 묻는 질문

### 플래그가 표시된 워크플로우를 한곳에서 볼 수 있나요?

네. **Review workflows with errors**를 클릭하세요.

### 게시됨과 임시 저장이 따로 나뉘어 있는 이유가 뭔가요?

검토 화면은 플래그가 표시된 워크플로우를 현재 게시 상태에 따라 묶어서 보여 줘요.

### 맵에서 워크플로우 단계를 바로 고칠 수 있나요?

**Open in builder**를 사용해 워크플로우를 편집하세요.

### Mark as read를 누르면 실패한 실행을 다시 시도하나요?

문서에 안내된 동작은 배지를 지우는 것뿐이에요. 재시도나 복구 용도로는 사용하지 마세요.
