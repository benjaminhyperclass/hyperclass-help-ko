# 워크플로우 액션 — Remove Assigned User(할당된 사용자 제거)

**Remove Assigned User**(할당된 사용자 제거) 액션이 무엇인지, 어떤 장점이 있고 어떻게 설정하는지 알아봐요. 실제로 쓰는 사례와 자주 묻는 질문도 함께 정리했어요.

## Remove Assigned User 액션이란

**Remove Assigned User** 액션은 연락처에 배정된 CRM 사용자를 해제해서 연락처를 배정되지 않은 상태로 만들어요. 연락처의 상태나 워크플로우 조건이 바뀌어 더 이상 담당 사용자가 필요 없을 때 특히 유용해요. 할당된 사용자를 제거하면 연락처가 다른 워크플로우에 다시 들어갈 수 있고, 나중에 처리할 때까지 배정되지 않은 상태로 둘 수도 있어요.

## 이 액션의 주요 장점

- 연락처 배정 초기화: 사용자 배정을 지워서 연락처를 다시 응대하거나 다시 배정할 수 있는 상태로 되돌려요.
- 워크플로우 관리 자동화: 작업 완료나 상태 변경 같은 특정 트리거가 발생하면 수동 작업 없이 사용자 배정을 제거해요.
- 사용자 가용성 개선: 더 이상 직접 관리할 필요가 없는 연락처를 빼서 사용자의 부담을 줄여요.
- 워크플로우 운영의 유연성 향상: 충돌하거나 오래된 배정 없이 연락처가 워크플로우 사이를 이동할 수 있어요.

## 액션 설정하기

### 액션 추가

워크플로우 빌더에서 **+** 아이콘을 클릭해 새 액션을 추가하세요.

![워크플로우 빌더에서 + 아이콘을 눌러 액션을 추가하는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155038521773/original/TL9e4deaHxFp0XhEBAZLgY2KpHyqc1kRuQ.png?1734504421)

### 액션 선택

**Select Action**(액션 선택) 목록에서 **Remove Assigned User** 액션을 선택하세요.

![액션 목록에서 Remove Assigned User를 선택하는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155038521354/original/nPGAcmAlHVvuDCLwpW49olfUUYCX2AjH-w.jpeg?1734503829)

### 액션 이름 정하기

워크플로우를 깔끔하게 관리할 수 있도록 알아보기 쉬운 이름을 입력하세요. 예를 들어 "Reset User Assignment"나 "Clear Assigned User"처럼 지으면 돼요.

![액션 이름을 입력하는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155038521793/original/la0nMoZj9cn8Bc-oDlyggFkZIs951sm1og.png?1734504467)

### 액션 저장

따로 설정할 필드는 없어요. 이름을 입력했다면 **Save**(저장)를 클릭하세요.

### 테스트 및 게시

워크플로우를 테스트해서 배정이 의도대로 제거되는지 확인하세요. 그런 다음 **Publish**(게시) 토글을 켜서 워크플로우를 활성화하세요.

## 사용 사례

### 영업 파이프라인 정리

- 시나리오: 연락처의 기회 상태가 고객전환성공 또는 고객전환실패로 바뀌었어요. 영업팀은 더 이상 후속 연락을 하지 않아도 되고, 연락처는 다른 워크플로우를 위해 초기화해야 해요.
- 솔루션:
  - 트리거: **Opportunity Status Changed**(기회 상태 변경)
  - 액션: **Remove Assigned User**
  - 결과: 연락처가 영업 담당자에게서 배정 해제되고, 담당자는 진행 중인 기회에 집중할 수 있어요.

### 고객 지원에서 작업 완료 처리

- 시나리오: 지원 담당자가 티켓 해결처럼 연락처와 관련된 작업을 완료했어요. 작업이 끝나면 연락처에 직접 배정할 필요가 없어요.
- 솔루션:
  - 트리거: **Task Completed**(작업 완료)
  - 액션: **Remove Assigned User**
  - 결과: 담당자의 배정이 해제되어 새 지원 티켓을 효율적으로 처리할 수 있어요.

## 자주 묻는 질문

### 할당된 사용자를 제거하면 연락처는 어떻게 되나요?

할당된 사용자를 제거하면 연락처는 배정되지 않은 상태가 되고, 활성 사용자 배정 없이 시스템에 그대로 남아요. 이후 다른 워크플로우나 트리거를 통해 다시 배정할 수 있어요.

### 한 워크플로우에서 이 액션을 여러 트리거와 함께 쓸 수 있나요?

네, 쓸 수 있어요. **Remove Assigned User** 액션을 **Task Completed**, **Opportunity Status Changed** 같은 여러 트리거와 함께 사용해서 연락처 배정을 상황에 맞게 관리하는 복합 워크플로우를 만들 수 있어요.

### 이 액션을 쓰면 배정 이력도 삭제되나요?

아니요. 할당된 사용자를 제거해도 연락처의 배정 이력은 지워지지 않아요. 이전 사용자 배정은 활동 로그나 리포팅 도구에서 계속 확인할 수 있어요.

### 이 액션이 다른 워크플로우를 방해하지 않게 하려면 어떻게 하나요?

충돌을 막으려면 게시하기 전에 워크플로우를 테스트하고, 모든 트리거의 조건을 꼼꼼히 확인하세요. **Remove Assigned User** 액션은 꼭 필요한 곳에만 적용하세요.

### Remove Assigned User 액션을 쓴 직후에 연락처를 다시 배정할 수 있나요?

네, 가능해요. 현재 배정을 제거한 뒤 워크플로우에 후속 액션으로 **Assign to User**(사용자에게 배정)를 추가하면 연락처를 새 사용자에게 배정할 수 있어요.
