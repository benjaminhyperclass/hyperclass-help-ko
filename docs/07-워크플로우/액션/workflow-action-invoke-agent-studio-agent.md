# 워크플로우 액션 — Invoke Agent Studio Agent(에이전트 스튜디오 에이전트 호출)

**Invoke Agent Studio Agent**(에이전트 스튜디오 에이전트 호출) 액션은 하이퍼클래스 워크플로우와 에이전트 스튜디오(Agent Studio)를 연결해요. 별도 코드 없이 AI 에이전트에 상황 정보를 보내고, 응답을 받아 다음 단계로 이어갈 수 있어요. 요약, 리드 선별, 콘텐츠 생성, 구조화된 출력, 에이전트 결과에 따른 워크플로우 분기에 쓰면 좋아요.

## Invoke Agent Studio Agent란?

**Invoke Agent Studio Agent**는 워크플로우 안에서 선택한 에이전트 스튜디오 에이전트를 실행하는 액션이에요. 워크플로우가 이 단계에 이르면 에이전트가 백그라운드에서 실행되고, 응답을 돌려줘요. 이 응답은 이후 워크플로우 단계에서 쓸 수 있어요. 워크플로우 로직과 에이전트의 판단, 생성된 콘텐츠, 구조화된 데이터를 하나의 흐름으로 묶을 수 있어요.

---

## 주요 장점

워크플로우 안에서 에이전트를 쓰면 단순 자동화에서 판단 기반 자동화로 나아갈 수 있어요. 워크플로우가 상황을 분석하거나, 응답을 만들거나, 정보를 분류하거나, 다음 단계에서 쓸 구조화된 출력을 받아야 할 때 특히 유용해요.

- **AI 기반 워크플로우 실행**: 워크플로우의 원하는 지점에서 에이전트 스튜디오 에이전트를 실행하고, 돌려받은 결과로 자동화를 이어가요.
- **유연한 데이터 처리**: **Message**(메시지) 필드로 지침을 보내고, 워크플로우 데이터를 **Input Variables**(입력 변수)에 연결하고, 응답을 이후 액션에서 다시 쓸 수 있어요.
- **더 나은 후속 자동화**: 에이전트 출력을 이메일, 내부 알림, 필드 업데이트, **If/Else**(조건 분기) 분기, 웹훅에서 쓸 수 있어요.
- **구조화된 의사 결정**: 에이전트가 기계가 읽을 수 있는 JSON을 반환하게 하면 분기가 더 깔끔해지고 자동화 로직이 더 안정적이에요.
- **확장 가능한 운영 워크플로우**: 리드 정보 보강, 요약, 라우팅, 후속 조치 준비, 레코드 업데이트 같은 작업에 같은 워크플로우 패턴을 여러 서브 계정에 적용할 수 있어요.

---

## 사전 준비 및 권한

워크플로우에 추가하기 전에 올바른 권한이 있는지, 에이전트를 알맞은 시작 방식으로 만들었는지 확인하세요. 미리 확인해 두면 워크플로우 액션에서 에이전트가 보이지 않을 때 당황하지 않아요.

이 액션을 쓰기 전에 다음을 확인하세요.

- 에이전트 스튜디오를 쓸 수 있는 AI 직원 애드온이 활성화되어 있어요.
- 에이전트가 **프로덕션**에 게시되어 있어요. 초안(Draft)이나 스테이징(Staging) 버전은 워크플로우 액션의 선택 목록에 나오지 않아요.
- 해당 계정에서 워크플로우와 AI 에이전트를 편집할 권한이 있어요.

{% hint style="warning" %}
**Invoke Agent Studio Agent** 워크플로우 액션으로 에이전트를 실행하려면, 에이전트를 **워크플로우** 트리거로 만드세요. 이 트리거는 워크플로우가 직접 실행하는 에이전트를 위한 것이라서, 입력값을 제대로 넘기고 에이전트의 응답을 받아 이후 단계에서 쓰기가 쉬워요.
{% endhint %}

---

## 워크플로우 액션 설정 항목

액션 패널의 각 설정은 에이전트가 무엇을 받고, 워크플로우가 결과를 이후에 어떻게 쓸지를 정해요. 각 항목을 이해하면 테스트와 문제 해결이 쉽고, 후속 자동화에도 더 잘 활용할 수 있어요.

액션에는 다음 핵심 설정이 있어요.

- **Agent**(에이전트): 워크플로우가 실행할 프로덕션 에이전트를 선택해요.
- **Message**: 이번 실행에 대한 자유 형식 지침을 입력해요. 머지 필드를 쓰면 연락처별 또는 워크플로우별 정보를 보낼 수 있어요.
- **Input Variables**: 워크플로우 값이나 고정 텍스트를 에이전트의 이름 있는 입력에 연결해요. 필수 입력이 빠지면 액션이 정상적으로 완료되지 않을 수 있어요.
- **Store Output As**(출력 저장 이름): 에이전트의 전체 응답을 커스텀 값으로 저장해 이후 워크플로우 단계에서 써요.

---

## 에이전트 출력을 이후 단계에서 쓰기

이 액션의 가치는 에이전트가 응답한 뒤에 나와요. 출력을 저장해 두고 다시 쓰면 워크플로우가 더 똑똑하게 판단하고, 메시지를 개인화하고, 이후 액션이나 외부 시스템에 더 풍부한 데이터를 보낼 수 있어요.

흔히 이렇게 활용해요.

- 요약이나 결과를 커스텀 필드나 메모에 저장해요.
- 에이전트가 반환한 값으로 **If/Else** 조건 분기를 만들어요.
- 응답을 이메일, SMS, WhatsApp, 내부 알림에 넣어요.
- 전체 응답 객체를 웹훅이나 외부 서비스로 보내요.
- 액션 안내에 나오는 에이전트 응답 변수로 이후 워크플로우 단계에서 응답을 참조해요.

---

## 활용 팁과 사용 사례

구조가 잘 잡힌 에이전트 액션은 관리하기 쉽고 결과도 더 일관돼요. 프롬프트를 명확히 쓰고, 변수를 연결하고, 구조화된 출력을 쓰면 오류가 줄고 팀이 워크플로우를 이해하고 개선하기도 쉬워져요.

활용 팁:

- 프롬프트는 간결하게 쓰고, 자세한 정보는 가능하면 연결한 변수로 전달하세요.
- 결과를 분기나 필드 업데이트에 쓸 거라면 에이전트에게 구조화된 JSON으로 반환하도록 요청하세요.
- 한 워크플로우에서 에이전트를 여러 개 쓴다면 각 액션 이름을 알아보기 쉽게 바꾸세요.
- 중요한 후속 액션에 쓰기 전에 에이전트의 출력 형식을 테스트하세요. 에이전트 스튜디오는 테스트와 디버깅을 지원하므로 본격적으로 쓰기 전에 에이전트의 동작을 확인할 수 있어요.
- 에이전트를 수정했다면 **프로덕션에 게시**해야 워크플로우 액션에 반영돼요.

사용 사례:

- 폼 제출 후 리드 정보 보강
- 채팅 종료 후 대화 요약
- 최근 문의를 바탕으로 한 영업 선별
- 서비스 팀을 위한 내부 인수인계 메모
- 웹훅이나 외부 도구로 보내는 구조화된 출력

## 설정 방법

설정은 에이전트 스튜디오에서 시작해 워크플로우 빌더에서 마무리해요. 워크플로우에서 호출할 에이전트를 먼저 만들어 두면, 액션이 올바른 에이전트를 찾고 이후 단계에서 쓸 응답을 안정적으로 받을 수 있어요.

### 1단계. 에이전트 스튜디오에서 에이전트 만들기

에이전트를 어떤 트리거로 만드는지에 따라 시작 방식이 정해져요. 이 용도라면 워크플로우 호출용으로 에이전트를 만들어야, 워크플로우가 의도한 시점에 에이전트를 실행하고 입력 데이터를 넘기고 응답을 받을 수 있어요. 트리거 유형은 에이전트가 특정 이벤트나 진입점에서 어떻게 시작될지를 정해요.

1. **에이전트 스튜디오**(Agent Studio)로 이동하세요.

   ![에이전트 스튜디오 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155068814869/original/7fVjMJU6TsdbZ_dPLMIFndbQ00Ljgm5r5w.png?1775748679)

2. **에이전트 만들기**를 클릭하거나, 사용할 기존 에이전트를 여세요.

   ![에이전트 만들기 버튼](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155068815539/original/w-XD_ReNCv9eboynIXAS5tXH4IEZe6LgcQ.png?1775748983)

3. 트리거 선택 창에서 **워크플로우**를 선택하세요.

   ![트리거 선택 창에서 워크플로우 선택](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155068815348/original/n92qFgRgadhcircZnVRDPnSuD7TH-Xo9Zg.png?1775748910)

4. 워크플로우에서 넘길 데이터에 맞춰 에이전트의 지침, 도구, 입력 변수를 설정하세요. 변수를 쓰면 입력을 개인화하고 재사용할 수 있는 에이전트를 만들 수 있어요.
5. 에이전트를 테스트하고, 출력 형식이 워크플로우에 맞는지 확인하세요. 에이전트를 설정할 때는 테스트와 개선을 반복하는 것이 좋아요.
6. **프로덕션에 게시**를 클릭하세요. 워크플로우 액션의 선택 목록에는 **프로덕션**에 게시된 에이전트만 나와요.

---

### 2단계. 워크플로우 액션 추가하기

액션을 추가하면 에이전트가 자동화 흐름 안에 들어가요. 일반 워크플로우 로직과 에이전트의 응답을 같은 순서 안에서 함께 쓸 수 있어요. 워크플로우는 트리거와 액션으로 만들어져요.

1. **자동화 > 워크플로우**로 이동하세요.

   ![자동화 > 워크플로우 메뉴](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155068816667/original/XyaIrDMqV3s1wRBAeV9fP5lPUFHiEsnS9Q.jpeg?1775749571)

2. 기존 워크플로우를 열거나 새로 만드세요.
3. **+ Add Action**(액션 추가)을 클릭하세요.
4. **Agent Studio**(에이전트 스튜디오) 아래에서 **Invoke Agent Studio Agent**를 선택하세요. 이 액션은 워크플로우 액션 선택 목록에 표시돼요.

   ![Agent Studio 아래 Invoke Agent Studio Agent 선택](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155068817052/original/egUNVtG2pvIlxYIUGmrCV7Es8heQcea4rw.png?1775749746)

---

### 3단계. 워크플로우 액션 설정하기

설정 패널에서는 어떤 에이전트를 실행할지, 워크플로우가 무엇을 보낼지, 돌려받은 데이터를 어떻게 저장할지 정해요. 여기서 꼼꼼히 설정하면 워크플로우가 일관되게 동작하고 이후 액션도 관리하기 쉬워요.

#### Action Name(액션 이름)

액션 이름을 알아보기 쉽게 지으면, 한 자동화에 AI 단계가 여러 개 있을 때 워크플로우를 읽기 편해요. 이 필드는 에이전트의 동작을 바꾸지 않지만, 정리하고 문제를 찾을 때 도움이 돼요.

예시:

- Lead Message Analyzer
- AI Summary Step
- Sales Insight Generator

![Action Name 입력란](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155068817183/original/hIYXvDxK3eupJ2T-VACkUMh-gIeSB9aNXQ.png?1775749793)

#### Select Agent(에이전트 선택) — 필수

**Select Agent** 드롭다운에서 워크플로우가 실행할 에이전트를 선택해요. 선택 목록에는 **프로덕션**에 게시된 에이전트만 나오므로 게시 상태가 중요해요.

이 워크플로우에서 실행할 에이전트를 선택하세요.

원하는 에이전트가 보이지 않으면 다음을 확인하세요.

- 에이전트가 **프로덕션**에 게시되어 있는지 확인하세요.
- 이 용도에 맞게 **워크플로우** 트리거로 만든 에이전트인지 확인하세요.
- 필요하면 빌더를 새로고침하고 액션을 다시 여세요.

![Select Agent 드롭다운](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155068817296/original/0MfHPCtRgx-zmQkcGH8Gy7wr1rD8eO5lDw.png?1775749841)

#### Message — 선택 사항이지만 입력을 권장해요

**Message** 필드는 워크플로우가 이 단계에 이르렀을 때 에이전트가 무엇을 해야 하는지 알려 줘요. 같은 에이전트가 쓰이는 위치에 따라 다른 지침을 처리해야 할 때 유용해요. 이 필드에는 자유 텍스트를 입력할 수 있고, 동적인 값은 머지 필드로 넣을 수 있어요.

예시:

```
Analyze the contact’s last inbound message and provide a short summary along with recommended next actions for the sales team.
```

개인화 예시:

```
Analyze the most recent message from {{contact.name}} and provide a short summary along with recommended next actions for the sales team.
```

![Message 필드](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155068817956/original/pi65Rj8u1xAPFjWnyIGApsv0b9jwzIWOAg.png?1775750162)

### 설정 시 알아둘 점

입력을 정확히 연결하고 에이전트가 무엇을 반환할지 분명히 해 두면 안정적으로 동작해요. 필수 변수와 저장되는 출력을 잘 챙기면 실행 실패를 막고 응답을 나중에 쓰기도 쉬워져요.

- 에이전트에 정의된 필수 입력 변수는 올바르게 연결해야 해요.
- 필수 입력이 빠지면 액션이 실패할 수 있어요.
- 에이전트는 워크플로우가 이 단계에 이르렀을 때 실행돼요.
- 응답은 안내된 에이전트 응답 객체를 통해 이후 단계에서 쓸 수 있어요.
- 이후 워크플로우 단계에서 전체 응답을 쓰려면 **Store Output As**를 사용하세요.

---

### 4단계. 입력 설정 후 저장하기

입력을 올바르게 연결하면 액션이 실행될 때마다 알맞은 정보가 전달돼요. 전체 출력을 저장해 두면 이후 액션을 설정하기도 쉬워져요.

1. 필수 입력 변수를 모두 연결하세요.
2. 필요하면 **Message** 필드에 추가 지침을 입력하세요.
3. 전체 응답을 저장하려면 **Store Output As**를 설정하세요.
4. **Save Action**(액션 저장)을 클릭하세요.

## 자주 묻는 질문

### 드롭다운에 에이전트가 보이지 않아요.

선택 목록에는 조건에 맞는 에이전트만 나와요. 에이전트가 **프로덕션**에 게시되어 있는지, 현재 서브 계정에 속해 있는지, 워크플로우 호출용으로 만들어졌는지 확인하세요. 프로덕션에 게시되어 있어야 한다는 조건은 액션 안내에서 확인할 수 있어요.

### 워크플로우 하나에서 에이전트를 여러 개 호출할 수 있나요?

네. 같은 워크플로우에 **Invoke Agent Studio Agent** 액션을 여러 개 추가할 수 있어요. 순서대로 이어 붙이거나 서로 다른 분기에 배치할 수 있어요.

### 에이전트에서 오류가 나면 어떻게 되나요?

액션이 실패하고, 워크플로우 로그에 오류가 표시돼요. 필요하면 워크플로우 로직으로 실패를 처리하도록 권장해요.

### AI 크레딧이 추가로 차감되나요?

에이전트 실행은 에이전트 스튜디오에서 직접 실행할 때와 같은 방식으로 계량되고, 워크플로우용 추가 요금은 없어요.

### 시간 제한이 있나요?

네. 에이전트는 60초 안에 응답해야 해요.

### Draft 상태의 워크플로우에서도 테스트할 수 있나요?

네. 이 액션은 **Draft**(초안) 모드에서 테스트할 수 있어요. 연락처는 워크플로우를 게시한 뒤에 처리돼요.

### 변수 연결 문제는 어떻게 확인하나요?

워크플로우의 실행 로그를 열고, 에이전트 스튜디오 테스트나 로그에 표시된 입력·출력과 비교해 보세요. 에이전트 스튜디오에는 테스트와 디버깅 안내가 있어요.

### 에이전트가 어떤 형식의 출력을 반환해야 하나요?

결과를 메시지나 메모에 넣을 거라면 일반 텍스트로 반환하세요. 분기, 업데이트, 후속 연동에 쓸 거라면 구조화된 JSON으로 반환하세요. 앞에서 설명한 후속 활용 방식과 같은 기준이에요.
