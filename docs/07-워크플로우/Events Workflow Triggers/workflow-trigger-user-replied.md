# 워크플로우 트리거 - 사용자 답장(User Replied)

사용자 답장(User Replied) 트리거는 팀원(User)이 연락처(Contacts)에게 메시지를 보낼 때마다 실행돼요. 이 트리거를 사용하면 팀의 응답 속도를 측정하고, 사람이 개입하면 자동화를 중단시키고, 발신 활동을 기록하고, 누가 어떤 채널로 답장했는지에 따라 대화를 라우팅할 수 있어요. 이 문서에서는 워크플로우(Workflows)에서 사용자 답장 트리거를 설정하고 사용하는 방법을 안내해 드릴게요.

## 사용자 답장 트리거란?

사용자 답장 트리거는 팀원이 대화(Conversations) 화면에서 연락처에게 메시지를 보낼 때 워크플로우를 시작해요. 이 트리거는 답장 및 응답 활동을 기준으로 하며, 사용자가 보내는 두 가지 유형의 메시지에서 실행돼요.

- **새로운 발신 메시지**: 사용자가 연락처에게 처음으로 메시지를 보내는 경우예요. 예를 들어 연락처가 폼(Form)을 통해 유입되어 담당자가 먼저 연락을 취하는 상황이에요.
- **기존 대화 내 답장**: 연락처가 먼저 메시지를 보냈고, 사용자가 해당 대화 내에서 답장하는 경우예요.

**중요**: 이 트리거는 사용자가 대화 화면에서 직접 보낸 메시지에 대해서만, 그리고 메시지가 전송된 순간이 아니라 실제로 **전달된 시점**에만 실행돼요. 워크플로우 액션(SMS 발송, 이메일 발송 등)이나 대화 AI(Conversation AI)가 보낸 메시지로는 실행되지 않아요. 대화 AI 기반 자동화를 원하신다면 별도의 대화 AI 트리거(Conversation AI Trigger)를 사용하세요. 이 트리거는 특정 메시지가 아니라 사용자가 정의한 조건에 따라 실행돼요.

## 사용자 답장 트리거 사용 시 주요 이점

- **응답 시간 추적**: 담당자가 연락처에게 응답한 순간을 캡처해서 팀의 응답 속도를 측정할 수 있어요.
- **사람이 개입하면 자동화 중단**: 팀원이 직접 답장하는 즉시 드립(Drip) 또는 육성(Nurture) 시퀀스를 종료해서, 연락처가 자동 메시지와 사람이 보낸 메시지를 동시에 받는 일을 방지해요.
- **"대기 후 확인" 흐름 구성**: 이 트리거를 사용자 답장(User Replied) 대기(Wait) 조건과 함께 사용하면, 연락처가 메시지를 보내고 몇 분간 대기했는데 아무도 답장하지 않았을 때 담당자에게 알림을 보내는 전형적인 패턴을 만들 수 있어요.
- **누가, 어디서 답장했는지에 따라 라우팅**: 발신 사용자, 연락처의 담당 사용자, 또는 메시지가 전송된 채널을 기준으로 워크플로우를 분기할 수 있어요.
- **메시지 내용에 따른 액션 실행**: 담당자의 메시지에 "환불 승인"과 같은 문구가 포함되면 기회(Opportunity)를 이동시키거나, 확인 메시지를 보내거나, 태그(Tag)를 적용할 수 있어요.
- **활동 기록**: 모든 발신 답장을 기록하거나, "최종 연락자(Last Contacted By)"와 "최종 연락일(Last Contact Date)" 같은 필드를 최신 상태로 유지할 수 있어요.

## 워크플로우에서 사용자 답장 트리거 사용하는 방법

- 계정에 로그인하세요.
- Automations(자동화) → Workflows(워크플로우) 메뉴로 이동하세요.
- 새 **워크플로우**를 **생성**하거나 기존 워크플로우를 **편집**하세요.
- **+ Add New Trigger**(새 트리거 추가)를 클릭한 다음, 목록(Events 항목 아래)에서 **User Replied**(사용자 답장)를 선택하세요.

![](https://jumpshare.com/share/1fHp8adcptdb0ypSPekL+/GIF+Recording+2026-07-10+at+20.29.33.gif)

- 나중에 쉽게 찾을 수 있도록 명확한 트리거 이름을 입력하세요. 예: "담당자 답장(SLA 타이머)"

- **+ Add Filters**(필터 추가)를 클릭해서 워크플로우가 실행될 조건을 좁혀보세요. 필터를 추가하지 않으면 어떤 채널이든, 어떤 연락처에게든 사용자가 답장할 때마다 트리거가 실행돼요.

- **Save Trigger**(트리거 저장)를 클릭하세요.

- 태그 추가(Add Tag), 이메일/SMS 발송(Send Email/SMS), 사용자 배정(Assign to User), 내부 알림 발송(Send Internal Notification), 기회 업데이트(Update Opportunity) 등 원하는 워크플로우 액션을 추가한 다음, 워크플로우를 **발행(Publish)**하세요.

![](https://jumpshare.com/share/eLWFJFDk9rjFbG13oaXN+/GIF+Recording+2026-07-10+at+21.38.48.gif)

## 트리거 필터

필터를 사용하면 어떤 사용자 답장이 워크플로우를 시작시킬지 조절할 수 있어요. 여러 필터를 조합해서 원하는 만큼 세밀하게 조건을 설정할 수 있어요.

| 필터 | 연산자 | 값 | 설명 |
|---|---|---|---|
| Sent By(보낸 사람) | Is any of(다음 중 하나) | 그룹화된 사용자 선택기(아래 참고) | 다중 선택 가능. 연락처의 담당 사용자 및/또는 특정 사용자를 선택하세요. |
| Message Channel(메시지 채널) | Is any of(다음 중 하나) | SMS, Email, WhatsApp, Facebook Messenger, Instagram DM, Live Chat | 일치시킬 채널을 하나 이상 선택하세요. 일부 채널은 채널별 추가 옵션을 제공해요. |
| Contains Phrase(문구 포함) | Contains(포함) | 자유 텍스트(대소문자 구분 없음) | 지정한 단어나 문구가 메시지에 포함될 때만 실행돼요. 쉼표로 구분된 여러 문구를 지원해요. |
| Exact Match Phrase(정확히 일치하는 문구) | Equals(같음) | 자유 텍스트(대소문자 구분 없음) | 메시지가 정확히 일치할 때만 실행돼요. 비교 전에 공백은 제거돼요. |
| Has Tag(태그 있음) | Has any of(다음 중 하나 있음) | 태그 선택기 | 연락처에 선택한 태그가 있을 때만 실행돼요. |
| Doesn't Have Tag(태그 없음) | Has none of(다음이 없음) | 태그 선택기 | 연락처에 선택한 태그가 없을 때만 실행돼요. |

#### 답장한 사람: 그룹화된 사용자 선택기

Replied By(답장한 사람) 필터는 검색 가능한 단일 다중 선택 드롭다운으로, 두 가지 유형의 옵션을 제공해요.

- **연락처에 배정된 사용자(User assigned to the Contact)**: 항상 목록 맨 위에 표시되는 동적 옵션이에요. 연락처의 담당 사용자가 답장할 때만 트리거를 실행하고 싶을 때 사용하세요.
- **Users(사용자)**: 이용 가능한 모든 사용자가 이름순으로 나열돼요.

**참고**: Replied By(답장한 사람) 필터를 추가하지 않으면, 어떤 사용자가 답장하든 트리거가 실행돼요.

## 채널별 동작 방식

이 트리거는 모든 주요 대화 채널에서 작동해요. 채널마다 대화를 스레드로 묶는 방식이 조금씩 다르기 때문에, 무엇을 새로운 발신 메시지로 볼지 답장으로 볼지도 채널마다 달라져요. 아래 표에서 채널별 동작 방식을 확인하세요.

| 채널 | 새로운 발신 메시지 | 기존 대화에 답장 |
|---|---|---|
| Email(이메일) | 새 제목으로 새 스레드를 시작하는 새 이메일 작성 | 기존 이메일 스레드 내에서 답장 |
| SMS | 이전 메시지가 없는 연락처에게 보내는 첫 SMS | 진행 중인 스레드 내 이후의 모든 SMS |
| WhatsApp(왓츠앱) | 24시간 창(window) 밖에서 템플릿 메시지로 시작 | 24시간 서비스 창 내에서 답장 |
| Facebook Messenger(페이스북 메신저) | 이전 대화가 없는 연락처에게 보내는 첫 메시지 | 진행 중인 스레드 내 이후의 모든 메시지 |
| Instagram DM(인스타그램 DM) | 이전 대화가 없는 연락처에게 보내는 첫 DM | 진행 중인 스레드 내 이후의 모든 DM |
| Live Chat(라이브 채팅) | 해당 없음(방문자가 항상 세션을 먼저 시작) | 활성 세션 내에서 답장 |

이메일은 같은 연락처와 여러 개의 별도 스레드를 동시에 유지할 수 있는 유일한 채널이에요. SMS, Messenger, Instagram DM 같은 단일 스레드 채널에서는 모든 메시지가 하나의 연속된 대화에 그대로 쌓여요.

## 커스텀 값

이 트리거는 워크플로우 액션과 조건 분기(If/Else) 안에서 다음과 같은 값을 사용할 수 있게 해줘요. 알림 개인화, 활동 기록, 대화 라우팅에 활용하세요.

| 이름 | 커스텀 값 | 설명 |
|---|---|---|
| User Name(사용자 이름) | `{{user_replied.senderName}}` | 메시지를 보낸 사용자의 이름 |
| User ID(사용자 ID) | `{{user_replied.userId}}` | 발신자의 내부 사용자 ID. 외부 연동 시 이름보다 더 안정적으로 사용 가능 |
| Message Body(메시지 본문) | `{{user_replied.messageBody}}` | 메시지 내용 |
| Channel(채널) | `{{user_replied.channel}}` | 메시지가 발송된 채널 (SMS, Email, WhatsApp 등) |
| Timestamp(타임스탬프) | `{{user_replied.timeStamp}}` | 메시지가 발송된 시각 |
| Conversation ID(대화 ID) | `{{user_replied.conversationId}}` | 대화 또는 스레드 ID |
| User Email(사용자 이메일) | `{{user_replied.senderEmail}}` | 메시지를 보낸 사용자의 이메일 주소 |

## 활용 사례

**키워드 기반 라우팅**

- 트리거: User Replied(사용자 답장)
- 필터: Contains Phrase(문구 포함)를 "환불 승인"으로 설정
- 액션: 기회(Opportunity)를 새 파이프라인 단계로 이동시키고 확인 메시지를 발송

**발신 활동 기록**

- 트리거: User Replied(사용자 답장)
- 액션: "최종 연락자(Last Contacted By)"를 `{{user_replied.senderName}}`으로, "최종 연락일(Last Contact Date)"를 `{{user_replied.timeStamp}}`로 업데이트하거나, 플랫폼 외부 어딘가에 답장 내역을 기록

## SLA 추적 및 에스컬레이션 설정하기

응답 시간 SLA(서비스 수준 협약)는 이 이벤트를 가장 많이 사용하는 이유예요. 담당자가 목표 시간 내에 답장하도록 보장하고, 그렇지 않을 경우 에스컬레이션하고 싶다면, 트리거를 단독으로 쓰기보다는 사용자 답장(User Replied) 이벤트를 대기(Wait) 조건 및 목표(Goal)와 함께 구성하는 방식으로 만들어야 해요.

패턴은 다음과 같아요.

- 시계를 시작시키는 이벤트로 워크플로우를 시작하세요. 예를 들어 Customer Replied(고객 답장) 트리거를 사용하면 연락처가 메시지를 보냈을 때 실행돼요.
- User Replied(사용자 답장) 조건으로 설정된 대기(Wait) 단계를 추가하고, 5분 등의 타임아웃을 지정하세요.
- 제한 시간 내에 아무도 답장하지 않은 타임아웃 분기에는, 담당자나 매니저에게 알림 보내기, 할 일(Task) 생성하기, 내부 경고 발송하기 같은 에스컬레이션 액션을 추가하세요.
- 담당자가 답장하는 즉시 리마인더나 육성(Nurture) 시퀀스를 중단하려면, User Replied(사용자 답장) 목표(Goal)를 추가해서 연락처가 남은 단계를 건너뛰도록 하세요.

**참고**: 대기(Wait) 조건과 목표(Goal)는 각각 별도의 단계로 설정돼요. 전체 설정 방법은 [워크플로우 액션 - 대기(Wait)](https://help.gohighlevel.com/support/solutions/articles/155000002470-workflow-action-wait) 및 [워크플로우 액션 - 목표 이벤트(Goal Event)](https://help.gohighlevel.com/support/solutions/articles/155000003328-workflow-action-goal-event) 문서를 참고하세요.

## 자주 묻는 질문

**Q: 워크플로우가 보낸 메시지도 이 트리거를 실행시키나요?**

아니요. SMS 발송(Send SMS)이나 이메일 발송(Send Email) 같은 워크플로우 액션에서 나온 자동 메시지는 이 트리거를 실행시키지 않아요. 사용자가 대화 화면에서 직접 보낸 메시지만 인정돼요.

**Q: 콜드 아웃리치나 대량 발신 메시지에도 실행되나요?**

일관되게 실행되지는 않아요. 이 트리거는 답장 및 응답 활동을 기준으로 설계되었으며, 콜드 첫 접촉용 아웃리치를 위한 것이 아니에요.

**Q: 연락처의 담당 사용자가 답장할 때만 실행되도록 할 수 있나요?**

네. Sent By(보낸 사람) 필터를 추가하고 "User assigned to the Contact(연락처에 배정된 사용자)"를 선택하세요.

**Q: 사용자가 여러 메시지를 빠르게 연속으로 보내면 어떻게 되나요?**

워크플로우에서 재등록(re-enrollment)이 제한되어 있지 않는 한, 각 메시지마다 트리거가 개별적으로 실행돼요.

**Q: 연락처가 두 개 이상의 워크플로우에 등록되어 있으면 어떻게 되나요?**

각 워크플로우에서 독립적으로 트리거가 실행돼요.
