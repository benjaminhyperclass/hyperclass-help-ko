# 워크플로우 트리거 — Product Access Removed(상품 접근 권한 제거)

**Product Access Removed**(상품 접근 권한 제거됨) 트리거는 고객의 상품 접근 권한이 회수되거나 제거될 때 자동화를 시작해요. 이 문서에서는 트리거가 하는 일과 장점, 설정 방법, 실제 활용 예시, 자주 묻는 질문을 안내해요.

## Product Access Removed 트리거란?

**Product Access Removed** 트리거는 고객의 상품 접근 권한이 회수되거나 제거될 때 시작돼요. 이 트리거로 고객에게 알림을 보내거나, 연락처 정보를 업데이트하거나, 내부 팀에 알리는 후속 작업을 자동화할 수 있어요. 특정 상품만 골라 적용할 수도 있어서, 고객 관계를 관리하고 운영을 통제할 때 두루 쓸 수 있어요.

## 주요 장점

- **고객 알림 자동화:** 접근 권한이 바뀌면 고객에게 바로 알려 투명하고 전문적인 인상을 줄 수 있어요.
- **운영 효율화:** CRM 기록 업데이트나 접근 권한 관리 같은 행정 업무를 자동화해 시간을 아끼고 실수를 줄여요.
- **고객 유지율 개선:** 구독 갱신이나 고객지원 문의처럼 접근 권한을 되찾는 방법을 고객에게 분명하게 안내할 수 있어요.
- **팀 협업 강화:** 고객지원팀이나 영업팀 같은 내부 팀에 알려 제때 후속 조치와 고객 유지 활동을 할 수 있어요.
- **상황에 맞는 대응:** 필터로 특정 상품만 지정해 비즈니스 상황에 맞게 워크플로우를 구성할 수 있어요.

## 트리거 설정하기

1. **자동화 > 워크플로우**로 이동해요. 새 워크플로우를 처음부터 만들거나, **Product Access Removed** 트리거를 추가할 기존 워크플로우를 선택하세요.
2. **Add New Trigger**(새 트리거 추가)를 클릭하고, 드롭다운 메뉴에서 **Product Access Removed**를 선택하세요.

   ![트리거 목록에서 Product Access Removed 선택](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155039182977/original/9MZXXaCFvBnllrHN4DBMhXUOXCqEiZtzfw.png?1735830609)

3. 트리거 이름을 알아보기 쉽게 입력하세요. 예를 들어 "구독 접근 권한 회수"처럼 쓰면 돼요.

   ![트리거 이름 입력](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155039183043/original/j2LYzecF4uCIeKoL5lXGyRh97RDsV_aDiw.png?1735830660)

4. 필터를 설정해 워크플로우가 시작되는 조건을 좁혀요.
5. **Select Product**(상품 선택)에서 접근 권한이 제거될 때 워크플로우를 시작할 상품을 고르세요.

   ![Select Product에서 상품 선택](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155039183057/original/Ge-bmqeG1uOauaQF64Y2NfJjrqQn2JNuDA.png?1735830680)

6. **Save**(저장)를 클릭해 트리거 설정을 저장하세요.
7. 샘플 데이터로 워크플로우를 테스트해 정상 작동하는지 확인하세요. 확인이 끝나면 **Publish**(게시) 토글을 켜서 워크플로우를 활성화하세요.

## 사용 사례

### 구독 만료 고객에게 알리기

- **시나리오:** 온라인 코스 구독이 만료돼 고객에게 알려야 해요.
- **트리거 설정:**
  - 트리거: **Product Access Removed**
  - 필터: **Select Product** — "고급 마케팅 코스"
- **결과:** 워크플로우가 만료 사실을 알리고 구독을 갱신하는 방법을 안내하는 이메일을 고객에게 보내요.

### 멤버십 회수를 내부 팀에 알리기

- **시나리오:** 프리미엄 멤버십의 접근 권한이 회수돼 고객지원팀이 후속 조치를 해야 해요.
- **트리거 설정:**
  - 트리거: **Product Access Removed**
  - 필터: **Select Product** — "프리미엄 멤버십"
- **결과:** 워크플로우가 고객지원팀에 알리고 CRM을 업데이트해요. 영업팀이 고객을 붙잡을 수 있도록 후속 작업도 만들어요.

### CRM 정보를 정확하게 유지하기

- **시나리오:** 디지털 상품의 접근 권한이 제거돼, 추적을 위해 고객 프로필을 업데이트해야 해요.
- **트리거 설정:**
  - 트리거: **Product Access Removed**
  - 필터: **Select Product** — "전자책 이용권"
- **결과:** 워크플로우가 CRM 기록에 접근 권한 제거를 반영하고, 재참여 캠페인 대상이 될 수 있도록 고객에게 태그를 달아요.

### 접근 권한 제거 후 업셀 기회 만들기

- **시나리오:** 기본 상품의 접근 권한이 회수돼 고객에게 프리미엄 상품으로 업그레이드하도록 권하고 싶어요.
- **트리거 설정:**
  - 트리거: **Product Access Removed**
  - 필터: **Select Product** — "기본 플랜"
- **결과:** 워크플로우가 프리미엄 플랜으로 업그레이드할 때의 장점을 소개하는 이메일을 보내고, 혜택으로 할인 코드를 함께 보내요.

## 자주 묻는 질문

### 같은 상품의 접근 권한이 한 고객에게서 여러 번 제거되면 어떻게 되나요?

접근 권한이 제거될 때마다 트리거가 시작돼요. 같은 작업이 반복되지 않게 하려면 워크플로우에 조건이나 쿨다운 기간(대기 시간)을 설정하세요.

### 필터를 쓰면 워크플로우가 어떻게 더 정확해지나요?

필터로 특정 상품이나 상황을 지정하면 해당 조건일 때만 워크플로우가 시작돼요. 그래서 더 정확하게 동작하고 불필요한 자동화를 줄일 수 있어요.

### 이 트리거를 워크플로우의 다른 트리거와 함께 쓸 수 있나요?

네, 함께 쓸 수 있어요. 예를 들어 **Tag Added**(태그 추가됨)나 **Subscription Expired**(구독 만료) 같은 트리거와 조합하면 더 복잡한 워크플로우를 만들 수 있어요.

### 제거된 상품에 따라 다른 팀에 알릴 수도 있나요?

네, 가능해요. 조건부 액션을 설정하면 제거된 상품에 따라 특정 팀이나 담당자에게 알림을 보낼 수 있어요.
