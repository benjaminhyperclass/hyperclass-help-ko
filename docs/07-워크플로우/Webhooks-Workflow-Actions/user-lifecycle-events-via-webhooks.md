# 사용자 생성·수정·삭제 웹훅 이벤트 (User Lifecycle Events)

하이퍼클래스에서 사용자가 만들어지거나, 수정되거나, 삭제될 때마다 웹훅 이벤트로 실시간 알림을 받을 수 있어요. 개발자는 이 이벤트로 외부 시스템과 데이터를 맞춰 둘 수 있고, 주기적으로 조회하거나 직접 확인할 필요가 없어요.

## 지원하는 사용자 이벤트

아래 웹훅 이벤트를 사용할 수 있어요.
`user.created``user.updated``user.deleted`

하이퍼클래스 안에서 사용자를 만들거나, 수정하거나, 삭제하면 이 이벤트가 발생해요.

## 이벤트별 설명

### user.created

새 사용자가 만들어질 때 발생해요.

주요 활용 사례:

- 외부 계정 생성
- 사용자를 타사 시스템에 동기화
- 온보딩 워크플로우 실행

### user.updated

사용자 정보가 바뀔 때 발생해요.

주요 활용 사례:

- 프로필 변경 내용 동기화
- 권한이나 역할 업데이트
- 외부 CRM과 동기화 유지

### user.deleted

사용자가 삭제될 때 발생해요.

주요 활용 사례:

- 외부 접근 권한 제거
- 권한 회수
- 연결된 하위 시스템 정리

## 이벤트 전송 방식

지원하는 사용자 이벤트가 발생하면 웹훅 이벤트가 실시간으로 전송돼요.

전송과 관련해 아래 기능도 제공해요.

- 전송에 실패하면 자동으로 다시 시도
- 멱등성(같은 이벤트가 여러 번 와도 한 번만 처리하는 것) 처리를 위한 이벤트 ID
- 문제 확인과 진단을 위한 전송 로그

원문의 스크린샷 설명에는 아래 내용이 나와요.

- 수신 웹훅 흐름
- 실시간 이벤트 전송
- 타사 연동 흐름
- 웹훅으로 실행되는 자동화 동작

## 웹훅 보안

사용자 이벤트 웹훅은 서명된 요청을 사용해서 이벤트가 진짜인지 확인할 수 있어요.

보안 기능은 다음과 같아요.

- HMAC 요청 서명
- 중복 방지를 위한 이벤트 식별자
- 실패한 웹훅 전송의 재시도 처리

들어온 웹훅 이벤트를 처리하기 전에 항상 웹훅 서명을 검증하세요.

## 자주 쓰는 활용 사례

개발자는 보통 이 이벤트를 아래와 같은 용도로 써요.

- 여러 플랫폼에 걸쳐 사용자 동기화
- 온보딩과 오프보딩 자동화
- 분석·리포팅 파이프라인 유지
- 계정 프로비저닝 워크플로우 실행
- 외부 시스템을 실시간으로 최신 상태로 유지

## 자주 묻는 질문

### 어떤 사용자 이벤트를 지원하나요?
현재 하이퍼클래스는 `user.created`, `user.updated`, `user.deleted`를 지원해요.

### 웹훅 전송에 실패하면 다시 시도하나요?
네. 실패한 웹훅 전송은 자동으로 다시 시도돼요.

### 웹훅 요청에도 서명이 들어가나요?
네. 사용자 이벤트 웹훅은 HMAC 요청 서명을 지원해요.

### 웹훅 이벤트로 외부 시스템과 사용자 정보를 동기화할 수 있나요?
네. 이 이벤트는 외부 시스템 간 실시간 동기화를 지원하도록 만들어졌어요.

### 웹훅 이벤트에 고유한 이벤트 ID가 포함되나요?
네. 멱등성 처리와 중복 방지를 위해 이벤트 ID가 포함돼요.
