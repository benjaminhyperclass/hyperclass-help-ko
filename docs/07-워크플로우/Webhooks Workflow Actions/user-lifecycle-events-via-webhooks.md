# 웹훅(Webhook)을 통한 사용자 라이프사이클 이벤트

하이퍼클래스는 이제 사용자 라이프사이클 활동에 대한 웹훅 이벤트를 지원하여, 개발자가 사용자가 생성, 수정, 삭제될 때마다 실시간 알림을 받을 수 있도록 해요.

이러한 웹훅 이벤트는 외부 시스템이 폴링이나 수동 확인 없이도 동기화 상태를 유지할 수 있도록 도와줍니다.

---

## **지원되는 사용자 라이프사이클 이벤트**

다음 웹훅 이벤트를 사용할 수 있어요:

- user.created
- user.updated
- user.deleted

이 이벤트들은 하이퍼클래스 내에서 사용자가 생성, 수정, 삭제될 때마다 트리거돼요.

---

## **사용 가능한 웹훅 이벤트**

### **user.created**

새 사용자가 생성될 때 트리거돼요.

일반적인 사용 사례:

- 외부 계정 프로비저닝
- 서드파티 시스템에 사용자 동기화
- 온보딩 워크플로우(Workflow) 트리거

### **user.updated**

사용자 정보가 변경될 때 트리거돼요.

일반적인 사용 사례:

- 프로필 업데이트 동기화
- 권한(Permission) 또는 역할(User Role) 업데이트
- 외부 CRM과 동기화 유지

### **user.deleted**

사용자가 삭제될 때 트리거돼요.

일반적인 사용 사례:

- 외부 접근 권한 제거
- 권한 회수
- 다운스트림 시스템 정리

---

## 이벤트 전달 동작

지원되는 사용자 라이프사이클 액션(Action)이 발생할 때마다 웹훅 이벤트가 실시간으로 전달돼요.

추가 전달 기능은 다음과 같습니다:

- 전달 실패 시 자동 재시도
- 멱등성(idempotency) 처리를 위한 이벤트 ID
- 문제 해결 및 진단을 위한 전달 로그

- 서드파티 연동(Integration) 흐름
- 웹훅으로 트리거되는 자동화 동작

---

## **웹훅 보안**

사용자 라이프사이클 웹훅은 이벤트의 진위 여부를 확인할 수 있도록 서명된 요청을 사용해요.

보안 기능은 다음과 같습니다:

- HMAC 요청 서명
- 중복 방지를 위한 이벤트 식별자
- 웹훅 전달 실패 시 재시도 처리

수신되는 웹훅 이벤트를 처리하기 전에 항상 웹훅 서명을 검증하세요.

---

## **일반적인 사용 사례**

개발자들은 일반적으로 이 이벤트들을 다음과 같은 용도로 사용해요:

- 여러 플랫폼 간 사용자 동기화
- 온보딩 및 오프보딩 자동화
- 분석 및 리포팅 파이프라인 유지
- 프로비저닝 워크플로우 트리거
- 외부 시스템을 실시간으로 최신 상태로 유지

---

## **자주 묻는 질문**

**Q: 어떤 사용자 이벤트가 지원되나요?**
A: 하이퍼클래스는 현재 user.created, user.updated, user.deleted를 지원해요.

**Q: 웹훅 전달이 실패하면 재시도되나요?**
A: 네. 실패한 웹훅 전달은 자동으로 재시도돼요.

**Q: 웹훅 요청은 서명되나요?**
A: 네. 사용자 라이프사이클 웹훅은 HMAC 요청 서명을 지원해요.

**Q: 웹훅 이벤트를 외부 사용자 동기화에 사용할 수 있나요?**
A: 네. 이 이벤트들은 외부 시스템 간 실시간 동기화를 지원하도록 설계되었어요.

**Q: 웹훅 이벤트에 고유한 이벤트 ID가 포함되나요?**
A: 네. 멱등성 처리와 중복 방지를 지원하기 위해 이벤트 ID가 포함돼요.
