# 연동 액션 테스트 — Test Action(액션 테스트)

워크플로우 빌더에서 외부 앱 액션을 게시하기 전에 실제로 실행해 보고 결과를 확인하는 기능이에요. 테스트에 성공하면 응답을 샘플로 저장해 뒤따르는 단계에서 응답 필드를 가져다 쓸 수 있어요.

## 개요

**Test Action**(액션 테스트)은 워크플로우 빌더의 외부 앱 액션 단계마다 쓸 수 있는 실시간 테스트 기능이에요. 액션 설정 카드에서 **Test Action** 버튼을 누르면, 입력값을 실제 값으로 바꾼 뒤 연결된 앱에 진짜 API 호출을 보내요. 이때 쓰는 계정과 실행 경로는 워크플로우가 실제로 돌아갈 때와 같아요.

응답은 오른쪽 **Test Drawer**(테스트 패널)에 두 영역으로 나뉘어 나와요.

- **Data In**(보낸 데이터): 앱으로 보낸 내용
- **Data Out**(받은 데이터): 앱이 돌려준 원본 응답. 주요 필드는 JSON 위에 칩과 카드로 따로 보여 줘요.

테스트에 성공하면 **Use this as sample**(샘플로 사용)을 눌러 응답을 스키마로 고정할 수 있어요. 배열과 중첩 객체를 포함한 모든 필드를 이후 액션 단계와 조건 분기에서 참조할 수 있게 돼요.

## Test Action 알아보기

**Test Action**은 워크플로우 빌더의 핵심 기능이에요. 설치된 모든 연동의 외부 앱 액션에서 쓸 수 있어요. 예전에는 '게시하고, 테스트 연락처를 등록하고, 로그를 확인'해야 했는데, 이제는 빌더 안에서 게시 전에 바로 검증할 수 있어요.

- 사용 가능한 곳: 모든 외부 앱 액션 단계예요. 예를 들면 **Find Contact**(연락처 찾기), **Create Card**(카드 만들기), **Send Message**(메시지 보내기), **Update Record**(레코드 업데이트) 등이 있고, 모든 연동에서 쓸 수 있어요.
- 실행 방식: 실제 앱을 대상으로 한 진짜 API 호출이에요. 워크플로우가 실행될 때 쓰는 것과 같은 **Connected Account**(연결된 계정)를 써요.
- 결과: 옆 패널에 **Data In**, **Data Out**이 나와요. 성공하면 응답을 스키마로 고정하는 옵션도 나타나요.

## 테스트 전에 준비할 것

아래 조건이 모두 갖춰져야 테스트가 실행돼요.

- **Connected Account**: 액션의 **Connected Account** 드롭다운에서 OAuth 또는 API 키로 연동이 연결되어 있어야 해요. 연결이 끊긴 계정으로는 테스트할 수 없어요.
- **Required fields**(필수 필드): 액션의 필수 입력을 모두 채워야 해요. 직접 입력한 값이든 워크플로우 변수든 괜찮아요. 필수 입력이 모두 채워질 때까지 **Test Action** 버튼은 비활성화 상태로 있어요.
- 앞 단계 값 참조 가능: 이 액션이 앞 액션 단계의 출력을 참조한다면, 그 앞 단계에 저장된 샘플이 있거나 그 단계를 먼저 테스트했어야 해요. 없으면 빌더가 샘플을 제공하라고 안내해요.
- 네트워크 연결: **Test Action**은 외부로 나가는 실제 API 호출을 보내요. 앱에 장애가 있거나 계정이 호출 제한에 걸리면 테스트가 실패하고, 패널에 앱이 돌려준 오류 코드가 표시돼요.

## 테스트 실행하기

### 1단계: 액션 설정하기

1. 워크플로우를 열고 테스트할 액션 단계를 클릭해요. 새 액션을 추가해도 돼요.
2. **Apps** 탭에서 연동과 액션을 골라요. 예를 들면 'Find Contact in Klaviyo'나 'Create Card in Trello'가 있어요.
3. 필수 입력을 모두 매핑해요. 직접 입력한 값, 워크플로우 변수, 앞 액션 출력 참조 중 무엇이든 쓸 수 있어요.

### 2단계: Test Action 클릭하기

4. 액션 설정 카드에서 **Test Action** 버튼을 찾아요. 준비 조건이 모두 갖춰지면 활성화돼요.
5. 버튼을 클릭해요. 진행 표시와 함께 **Test Drawer**가 오른쪽에서 열려요.

### 3단계: 부작용이 있는 액션이면 확인하기

6. 연결된 앱의 데이터를 만들거나 바꾸는 액션이면 확인 팝업이 나타나요. 예를 들면 **Create Contact**(연락처 만들기), **Create Card**, **Update Record**, **Send Message** 등이 있어요.
7. 팝업에는 이런 문구가 나와요. "This action will actually perform a live test that may create or modify data in the connected app."
8. 계속하려면 **Yes, Run Test**(예, 테스트 실행)를 클릭하고, 멈추려면 **Cancel**(취소)을 클릭해요. **Cancel**에 기본 포커스가 있어서, 실수로 Enter 키를 눌러도 테스트가 실행되지 않아요.

### 4단계: Data In과 Data Out 확인하기

9. 호출에 성공하면 패널에 **Data In**(앱으로 보낸, 값이 확정된 입력)과 **Data Out**(앱의 원본 응답)이 채워져요.
10. 주요 필드는 JSON 위에 칩과 카드로 나와요. 전체 내용은 펼칠 수 있는 JSON을 스크롤해서 확인해요.
11. 뒤따르는 단계에서 쓸 응답 스키마를 고정하려면 **Use this as sample**을 클릭해요.

### 5단계: 저장하고 이어가기

12. 액션을 저장해요. 이제 뒤따르는 단계에서 고정된 스키마의 모든 필드를 이름으로 참조할 수 있어요.
13. 테스트에 실패했다면 액션 설정에서 강조 표시된 필드를 고친 뒤 **Test Action**을 다시 클릭해요. 재테스트 횟수에는 제한이 없어요.

## Test Drawer 읽는 방법

**Test Drawer**는 위에서부터 세 영역으로 나뉘어요.

- **Status header**(상태 헤더): 결과(**Success**(성공), **Failure**(실패), **In Progress**(진행 중)), HTTP 상태 코드, 호출에 걸린 시간을 보여 줘요.
- **Data In** 영역: 앱으로 보낸 입력이에요. 직접 입력한 폼 값이 아니라, 변수가 실제 값으로 바뀐 뒤의 전송 내용이에요. 변수 치환과 변환이 예상한 대로 처리됐는지 확인할 때 써요.
- **Data Out** 영역: 앱이 돌려준 원본 응답이에요. 주요 필드는 칩과 카드로 보여 주고, 그 아래 펼칠 수 있는 JSON 트리에서 전체 내용을 살펴볼 수 있어요. 응답이 크면 영역 안에서 스크롤돼요.

테스트에 성공하면 패널 아래쪽에 **Use this as sample** 버튼이 나타나요. 테스트에 실패하면 이 버튼 대신 구조화된 오류 카드가 나와요. 자세한 내용은 아래 '테스트 실패 처리'를 참고하세요.
