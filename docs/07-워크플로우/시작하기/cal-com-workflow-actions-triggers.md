# Cal.com 워크플로우 트리거·액션 — Booking Created(예약 생성됨), Create Booking(예약 생성) 등

Cal.com을 하이퍼클래스 워크플로우와 연결하면 별도 웹훅이나 외부 도구 없이 예약 활동을 자동화할 수 있어요. 예약이 생성·변경·취소·종료될 때 워크플로우를 시작하고, 워크플로우 안에서 예약을 만들거나 취소·변경·조회할 수도 있어요. 덕분에 CRM 기록, 고객 커뮤니케이션, 일정 운영을 실시간으로 맞춰 둘 수 있어요.

## Cal.com 워크플로우 트리거·액션이란?

Cal.com 예약 이벤트를 하이퍼클래스 워크플로우 빌더(Workflow Builder)와 연결하는 기능이에요. 트리거는 Cal.com의 예약 이벤트를 하이퍼클래스로 가져오고, 액션은 자동화 안에서 Cal.com 예약을 관리해요.

연동은 양방향으로 작동해요.

- **Cal.com → 하이퍼클래스 워크플로우:** 예약 생성, 예약 변경, 예약 취소, 미팅 종료, 부재 중(OOO) 일정 수정, 새 녹화 같은 이벤트로 워크플로우 자동화를 시작할 수 있어요.
- **하이퍼클래스 워크플로우 → Cal.com:** 워크플로우 액션으로 Cal.com 예약을 만들거나 취소·변경·조회할 수 있어요.

## 주요 장점

Cal.com 워크플로우 자동화를 쓰면 수작업 일정 관리를 줄이고, 예약 변경에 더 빠르게 대응하고, 실제 예약 활동에 맞춰 고객과 소통할 수 있어요.

- **예약 전 과정 자동화:** 예약 생성, 변경, 취소, 완료, 부재 중 일정 수정 같은 주요 이벤트를 자동화할 수 있어요.
- **빠른 이벤트 기반 자동화:** Cal.com 트리거는 웹훅 기반이라 예약 이벤트가 발생하고 몇 초 안에 실행돼요. 확인 메시지, 알림, 후속 조치가 빠르게 이어져요.
- **프로그램을 통한 일정 생성:** **Create Booking**(예약 생성) 액션으로 폼 제출이나 적합 리드 이벤트 같은 워크플로우 데이터를 바탕으로 미팅을 예약할 수 있어요.
- **간편한 필드 매핑:** 최근 Cal.com 예약을 매핑 기준으로 쓰면 이후 단계에서 실제 예약 필드를 그대로 사용할 수 있어요.
- **다양한 예약 데이터:** 예약 이벤트에는 예약 URL, 제목, 시작 시간, 종료 시간, 메모, 이벤트 유형, 참석자, 주최자 같은 정보가 담겨요.
- **한 번 연결해서 계속 사용:** 서브 계정에서 Cal.com을 한 번 연결하면, 이후 모든 워크플로우에서 다시 연결하지 않고 Cal.com 트리거와 액션을 쓸 수 있어요.

## Cal.com 계정 연결하기

워크플로우 단계나 연동 페이지, 어느 쪽에서 연결해도 하이퍼클래스가 Cal.com 예약 이벤트를 안전하게 받고 워크플로우 액션에서 Cal.com API를 호출할 수 있어요. 편한 방법을 고르세요.

1. 하이퍼클래스에서 **자동화 > 워크플로우**를 열고 **Cal.com** 트리거나 액션을 추가하세요.
   - Cal.com이 연결되어 있지 않다면 **Connect Now**(지금 연결)를 클릭하고 Cal.com API 키로 인증하세요. OAuth를 지원하는 경우에는 OAuth로도 인증할 수 있어요. 이어서 하이퍼클래스가 접근할 워크스페이스와 이벤트 유형을 승인하세요.
   - 이미 연결되어 있다면 워크플로우 단계에서 트리거나 액션 필드가 바로 불러와져요.

   ![워크플로우 단계에서 Cal.com 연결하기](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155071854026/original/DpNauJ8A1OE8e3ZAEwTi0Zto8rgZbZHgig.png?1779343040)

2. 다른 방법으로, **서브 계정 설정 > 연동 > Cal.com > 연결**로 이동해 연결할 수도 있어요.

   ![서브 계정 설정의 연동 페이지에서 Cal.com 연결하기](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155071854044/original/rrQ_d45BKxiGMoXOuhRrvtb_yzhpFN2zkg.png?1779343080)

## Cal.com 트리거

트리거는 Cal.com에서 특정 이벤트가 일어날 때 워크플로우를 시작해요. Cal.com의 예약 활동에 따라 연락처를 만들거나 수정하고, 메시지를 보내고, 워크플로우를 분기하고, 작업을 배정하고, 후속 시퀀스를 시작하고 싶을 때 쓰세요.

| 트리거 | 기능 |
| --- | --- |
| **Booking Created**(예약 생성됨) | Cal.com에서 새 예약이 생성되면 워크플로우를 시작하고 예약 데이터를 전달해요. |
| **Booking Rescheduled**(예약 일정 변경됨) | 기존 예약이 새 시작 시간으로 옮겨지면 워크플로우를 시작하고, 이전 시간과 변경된 시간 정보를 전달해요. |
| **Booking Cancelled**(예약 취소됨) | 참석자, 주최자 또는 시스템이 예약을 취소하면 워크플로우를 시작해요. 취소 사유가 입력된 경우 함께 확인할 수 있어요. |
| **Meeting Ended**(미팅 종료됨) | 예약된 종료 시간에 워크플로우를 시작해요. 예약 일정이 변경되면 Meeting Ended 웹훅도 변경된 시간에 맞춰 다시 설정돼요. |
| **OOO Created / Updated**(부재 중 일정 생성/수정됨) | Cal.com에서 부재 중 일정이 생성되거나 수정되면 워크플로우를 시작해요. |

## Cal.com 액션

액션은 워크플로우가 Cal.com에 지시를 보내는 기능이에요. 하이퍼클래스에서 예약을 만들거나 취소·변경하고 싶을 때, 또는 다음 단계 전에 예약 정보를 조회하고 싶을 때 쓰세요.

| 액션 | 용도 |
| --- | --- |
| **Create Booking**(예약 생성) | 선택한 Cal.com 이벤트 유형으로 새 예약을 만들어요. 필수 필드는 Event Type(이벤트 유형), Attendee Name(참석자 이름), Attendee Email(참석자 이메일), **Start Time**(시작 시간)이에요. |
| **Cancel Booking**(예약 취소) | 예약 ID로 기존 예약을 취소해요. 취소 사유는 선택 입력이에요. |
| **Reschedule Booking**(예약 일정 변경) | 기존 예약을 새 시작 시간으로 옮겨요. 캘린더 초대 업데이트와 알림은 Cal.com이 처리해요. |
| **Find Booking**(예약 찾기) | 예약 ID, 참석자 이메일 또는 필터로 예약을 조회하고, 일치하는 예약 데이터를 반환해요. |

Cal.com 액션 4개는 모두 프리미엄 워크플로우 액션이에요. 이 액션이 실행되면 프리미엄 액션 크레딧이 사용돼요.

## Cal.com 트리거와 액션 테스트하기

테스트로 연결이 잘 되는지, 올바른 예약 데이터를 쓸 수 있는지, 이후 단계에서 필드가 제대로 매핑되는지 확인할 수 있어요. Cal.com 예약 데이터를 쓰는 워크플로우는 게시하기 전에 꼭 테스트하세요.

### Cal.com 트리거 테스트하기

#### 1단계: 트리거 추가

- 워크플로우를 열고 **Add Trigger**(트리거 추가)를 클릭하세요.
- **Apps**(앱) 탭으로 이동해 Cal.com을 검색하세요.
- Cal.com 트리거 목록에서 **Booking Created**를 선택하세요.

#### 2단계: 트리거 설정

- **Workflow Trigger Name**(워크플로우 트리거 이름) — 트리거를 알아보기 쉬운 이름으로 지정하세요. 예: '신규 상담 통화 예약'
- 필터 추가(선택) — 이벤트 유형, 호스트, 장소 등 예약 데이터의 어떤 필드로도 트리거 조건을 좁힐 수 있어요. 관련 없는 예약이 워크플로우에 들어오지 않게 막아요.
- **Webhook Status**(웹훅 상태) — 트리거 패널에서 Cal.com 웹훅이 활성 상태인지 보여 줘요. 비활성이 되면 Cal.com 설정에서 연동을 다시 연결하세요.

#### 3단계: 트리거 테스트

- **Test Your Trigger**(트리거 테스트) 패널에서 **Find New Records**(새 레코드 찾기)를 클릭하세요.
- 시스템이 Cal.com에서 조건에 맞는 가장 최근 예약을 가져와요.
- **Records — Select Mapping Reference**(레코드 — 매핑 기준 선택) 드롭다운에서 가져온 레코드 중 하나를 고르세요. 예: `Active: (2026-05-01 10:36:24) Reference 69f434d0e7358049c8b16ded` 이렇게 고르면 데이터 구조가 고정되어, 이후 모든 단계에서 필드를 깔끔하게 매핑할 수 있어요.
- **Trigger Data Response**(트리거 데이터 응답) 패널에서 사용할 필드가 데이터에 들어 있는지 확인하세요. 예: `bookerUrl`, `title`, `startTime`, `endTime`, `additionalNotes`, `type`, `description`, `eventTypeId`, `hideCalendarNotes`, `attendees`, `organizer`
- **Save Trigger**(트리거 저장)를 클릭해 마무리하세요.

### Cal.com 액션 테스트하기

고관심 폼이 제출된 뒤처럼, 워크플로우 안에서 호스트의 캘린더에 미팅을 자동으로 예약하는 과정을 따라 해 볼게요.

#### 1단계: 액션 추가

- 워크플로우 안에서 **Add**(추가)를 클릭해 새 단계를 넣으세요.
- **Apps** 탭을 열고 Cal.com을 선택하세요.
- 액션 목록에서 **Create Booking**을 선택하세요.

#### 2단계: 액션 설정

- **Action Name**(액션 이름) — 단계를 알아보기 쉬운 이름으로 지정하세요. 예: '상담 통화 예약'
- **Event Type**(이벤트 유형, 필수) — 예약할 Cal.com 이벤트 유형을 고르세요. 드롭다운에는 연동이 접근할 수 있도록 승인된 모든 이벤트 유형이 표시돼요.
- **Attendee Name**(참석자 이름, 필수) — 워크플로우 변수를 직접 입력할 수 있어요. 예: `{{contact.full_name}}`
- **Attendee Email**(참석자 이메일, 필수) — 워크플로우 변수를 직접 입력할 수 있어요. 예: `{{contact.email}}`
- **Attendee Timezone**(참석자 시간대) — IANA 형식으로 입력하세요. 예: `America/New_York`, `Europe/London` 입력하지 않으면 서브 계정의 시간대가 기본값으로 쓰여요.
- **Start Time**(필수) — 안내된 형식(예: `12-21-2026 08:30 AM`) 또는 ISO-8601 형식을 사용하세요. 시간은 Attendee Timezone 기준으로 해석되고, 설정하지 않았다면 서브 계정 기본 시간대로 해석돼요.

#### 3단계: 저장하고 결과 사용

**Save action**(액션 저장)을 클릭하세요. 새 예약의 ID와 메타데이터가 워크플로우 출력 변수로 제공돼요. 참석자에게 예약을 확인해 주려면 **Send Email**(이메일 보내기)이나 **Send SMS**(SMS 보내기) 단계를 이어 붙이세요. 이후 조건이 바뀌면 나중에 **Cancel Booking** 또는 **Reschedule Booking** 단계에서 이 예약 ID를 쓸 수도 있어요.

## 워크플로우에서 Cal.com 트리거·액션 설정하기

설정을 깔끔하게 해 두면 예약 이벤트가 워크플로우에 정확히 들어오고, 액션 단계가 Cal.com에 정확한 일정 지시를 보낼 수 있어요. 먼저 간단한 워크플로우로 시작해서 Cal.com 연결이 활성 상태인지 확인하고, 일정 프로세스에 필요한 트리거, 액션, 후속 단계를 차례로 추가하세요.

1. **자동화 > 워크플로우**로 이동해 새 워크플로우를 만들거나 기존 워크플로우를 여세요.

   ![워크플로우 목록에서 새 워크플로우 만들기](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155071854990/original/BPbLYzIFF9cPEnLXm9U-Ug33yrLepmM_hg.png?1779344543)

2. **Add Trigger**를 클릭하고 **Apps** 탭에서 **Cal.com**을 검색한 뒤, 목적에 맞는 트리거를 선택하세요. 예: **Booking Created**, **Booking Rescheduled**, **Booking Cancelled**, **Meeting Ended**

   ![Apps 탭에서 Cal.com 트리거 선택하기](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155071855004/original/fx4bbiH26TBphq-R49A4Qm8h-nMJy4wi2A.png?1779344560)

3. **+** 아이콘을 클릭해 다음 워크플로우 단계를 추가하고, 트리거가 실행된 뒤 수행할 하이퍼클래스 액션이나 Cal.com 액션을 고르세요. CRM 업데이트, 메시지, 태그, 작업, 내부 알림에는 하이퍼클래스 액션을 쓰세요. 워크플로우에서 Cal.com 예약을 만들거나 조회·취소·변경해야 할 때는 Cal.com 액션을 쓰세요.
4. 워크플로우에서 예약을 만들려면 **Cal.com > Create Booking**을 선택하고 필수 필드를 채우세요. 필수 필드는 **Event Type**, **Attendee Name**, **Attendee Email**, **Start Time**이에요. 예약에 참석자의 시간대를 반영하려면 **Attendee Timezone**을 `America/New_York`, `Europe/London` 같은 IANA 형식으로 추가하세요.

   ![Create Booking 액션의 필수 필드 입력하기](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155071855022/original/l0wliRhJXtREhbrhkbOMNYIM85xYewkHFw.png?1779344600)

5. 나머지 후속 단계를 추가하세요. 예를 들어 확인 메시지 보내기, 연락처 태그 추가, 내부 작업 만들기, **If/Else**(조건 분기)로 분기하기, CRM에 예약 정보 기록하기 같은 단계가 있어요.
6. **Save**(저장)를 클릭하고 마지막으로 워크플로우를 테스트해 매핑된 값이 모두 제대로 채워지는지 확인한 다음 **Publish**(게시)하세요.

## 활용 사례

아래 패턴을 활용하면 예약 활동을 일관된 고객 소통과 내부 후속 조치로 이어 갈 수 있어요. 가장 비슷한 사례로 시작한 뒤 필터, 분기, 메시지를 업무 방식에 맞게 바꿔 보세요.

### 사례 1: 신규 예약 → CRM 연락처 + 환영 시퀀스

목표: 신규 예약마다 필요한 정보가 붙은 연락처를 만들고 온보딩까지 자동으로 진행해요.

워크플로우 구성:

- 트리거: **Booking Created**
- 액션: **Create/Update Contact**(연락처 생성/수정) — 참석자 이메일을 기준으로 연락처를 찾아 병합해요.
- 액션: 예약의 이벤트 유형으로 연락처에 태그 추가
- 액션: 미팅 유형에 맞는 준비 자료와 함께 환영 이메일 보내기
- 액션: 미팅 24시간 전에 끝나는 후속 캠페인에 연락처 추가

예시: 잠재 고객이 30분 상담 통화를 예약해요. 워크플로우가 연락처를 만들고 '상담' 태그를 붙인 뒤 맞춤 준비 이메일을 보내고, 통화 전날 리마인더가 나가도록 설정해요.

### 사례 2: 노쇼 회복

목표: 담당자가 일일이 쫓아다니지 않아도 노쇼를 자동으로 회복해요.

워크플로우 구성:

- 트리거: **Meeting Ended**
- 액션: **Find Booking** — 예약 상태를 새로 조회해 노쇼 여부를 확인해요.
- 조건: 참석자가 노쇼였을 때만 다음 단계로 진행
- 액션: 한 번의 클릭으로 다시 예약할 수 있는 맞춤 일정 변경 링크 보내기
- 액션: 48시간 안에 다시 예약하지 않으면 후속 조치용 태그 추가

예시: 미팅이 끝날 때마다 워크플로우가 예약 상태를 확인해요. 참석자가 노쇼였다면 부담 없는 메시지와 한 번에 다시 예약할 수 있는 링크를 보내요. 그냥 놓치는 일이 없어져요.

### 사례 3: 취소 고객 리텐션

목표: 취소를 끝이 아니라 고객을 붙잡는 흐름의 시작으로 활용해요.

워크플로우 구성:

- 트리거: **Booking Cancelled**
- 조건: 취소 사유로 분기(일정 충돌 vs. 흥미 상실)
- 액션: 일정 충돌인 경우 다시 예약할 수 있는 링크가 담긴 리텐션 메시지 보내기
- 액션: 흥미를 잃은 경우 전체 맥락과 함께 CSM에게 넘기기

예시: 잠재 고객이 일정이 겹쳐 데모를 취소해요. 워크플로우가 미리 채워 둔 시간 옵션 두 개와 함께 친근한 일정 변경 메시지를 보내고, 일주일 안에 다시 예약하지 않으면 CSM이 후속 조치할 수 있도록 태그를 붙여요.

### 사례 4: 폼에서 바로 일정 만들기

목표: 관심도가 높은 리드에게 예약 링크를 이메일로 다시 보내고 기다리는 과정을 없애요.

워크플로우 구성:

- 트리거: **Form Submission**(폼 제출) — 희망 시간이 함께 입력되는 폼
- 액션: 배정된 호스트의 이벤트 유형으로 **Create Booking**
- 액션: 확인 메시지 보내기

예시: 리드가 관심도 높은 폼으로 당일 통화를 요청해요. 워크플로우가 배정된 영업 담당자(AE)의 캘린더에서 요청한 시간에 미팅을 예약하고 바로 확인 메시지를 보내요. 수동으로 일정을 잡을 필요도, 리드를 놓칠 일도 없어요.

### 사례 5: 녹화본 자동 전달

목표: Cal Video 녹화본을 알맞은 곳에 자동으로 보내요.

워크플로우 구성:

- 트리거: **Recording Ready**(녹화 준비 완료) — 지원되는 경우
- 액션: AI로 녹화본을 고객이 읽기 쉬운 메모로 요약
- 액션: 녹화본 URL과 요약을 참석자에게 보내기
- 액션: 녹화 링크를 첨부해 CRM 활동 기록 남기기

예시: 녹화 처리가 끝나면 참석자에게 감사 이메일이 가요. 이메일에는 녹화 링크와 AI가 만든 요약이 들어 있어요. CRM 활동 기록에도 같은 내용이 남아 담당자가 확인할 수 있어요.

## 모범 사례

몇 가지 설정 기준을 지키면 매핑 오류, 시간대 문제, 예약 업데이트 실패를 줄일 수 있어요. 워크플로우가 예약을 자동으로 만들거나 바꿀 때 특히 도움이 돼요.

- 지역이 서로 다른 리드를 대신해 예약할 때는 항상 **Attendee Timezone**을 직접 입력하세요. 서브 계정 기본 시간대에 맡기는 방식은 단일 지역으로 운영할 때만 괜찮아요.
- 안내된 **Start Time** 형식(예: `12-21-2026 08:30 AM`)이나 ISO-8601 문자열을 사용하세요. 형식이 모호하면 예약 시간이 몇 시간씩 어긋날 수 있어요.
- **Find Booking**을 **Cancel Booking** 또는 **Reschedule Booking**과 함께 쓰세요. 예약을 바꾸기 전에 예약이 있는지, 예상한 상태인지 확인할 수 있어요.
- 미팅 후 후속 워크플로우의 시작점으로는 **Booking Created**가 아니라 **Meeting Ended**를 쓰세요. Cal.com이 자동으로 일정을 잡고, 예약 일정이 바뀌면 다시 설정해 줘요.
- 트리거 패널의 **Webhook Status** 표시를 살펴보세요. 비활성이 되면 Cal.com 설정에서 웹훅을 다시 연결해야 해요.
- 먼저 트리거를 테스트해 매핑 기준을 고정한 뒤, 가져온 샘플 데이터를 바탕으로 이후 액션을 구성하세요. **Records — Select Mapping Reference** 필드가 깔끔한 필드 매핑의 바탕이에요.

## 자주 묻는 질문

### Cal.com 액션은 프리미엄 워크플로우 액션인가요?

네. **Create Booking**, **Cancel Booking**, **Reschedule Booking**, **Find Booking**은 프리미엄 워크플로우 액션이에요. 실행될 때 프리미엄 액션 크레딧이 사용돼요.

### Cal.com 트리거에서 어떤 데이터를 사용할 수 있나요?

예약 데이터에는 예약 URL, 제목, 시작 시간, 종료 시간, 메모, 이벤트 유형, 참석자, 주최자 같은 정보가 담길 수 있어요.

### Webhook Status는 무슨 뜻인가요?

Cal.com 웹훅이 활성 상태인지 보여 줘요. 비활성으로 바뀌면 Cal.com 연동을 다시 연결하세요.

### Create Booking에서는 어떤 시간대 형식을 써야 하나요?

`America/New_York`, `Europe/London` 같은 IANA 시간대 형식을 쓰세요. 비워 두면 Cal.com이 서브 계정 시간대를 대신 사용해요.

### Start Time은 어떤 형식으로 입력해야 하나요?

표준 날짜·시간 값을 쓰세요. 안내된 형식은 `12-21-2026 08:30 AM`이고, `2026-12-21T08:30:00` 같은 ISO-8601 값도 사용할 수 있어요.

### Cancel Booking을 실행하면 참석자에게 알림이 가나요?

네. Cal.com이 기본 취소 이메일을 보내요. 취소 사유를 입력했다면 이메일에 함께 들어가요.

### Reschedule Booking을 실행하면 변경된 캘린더 초대가 가나요?

네. Cal.com이 기존 캘린더 일정을 취소하고 새 시간에 맞는 초대를 새로 보내요.

### 예약 일정이 변경되면 Booking Created가 다시 실행되나요?

아니요. **Booking Rescheduled**는 별도의 트리거예요. 기존 예약의 일정이 변경되어도 **Booking Created**는 다시 실행되지 않아요.

### 직접 서버에 설치해 쓰는(self-hosted) Cal.com에서도 연동이 되나요?

Self-hosted Cal.com도 같은 웹훅 범위를 지원해요. 다만 일부 환경에서는 **Meeting Started**(미팅 시작됨)나 **Meeting Ended** 동작에 문제가 있을 수 있어요. 실제 운영에 쓰기 전에 실제 예약으로 테스트해 보세요.

### Cal.com 액션 필드에 워크플로우 변수를 쓸 수 있나요?

네. **Attendee Name**, **Attendee Email**, **Start Time** 등 액션이 제공하는 필드에 워크플로우 변수를 직접 입력해서 쓸 수 있어요.
