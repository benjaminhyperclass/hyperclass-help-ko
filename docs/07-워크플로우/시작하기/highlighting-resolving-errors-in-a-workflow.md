# 워크플로우 오류 확인하고 해결하기 — Resolve Errors(오류 해결)

필수 설정이 빠졌거나 잘못 입력되면 워크플로우가 의도대로 동작하지 않을 수 있어요. 하이퍼클래스는 워크플로우 빌더에서 이런 설정 오류를 찾아 표시하고, **Resolve Errors**(오류 해결) 사이드바에 모아 보여 줘요. 이 문서에서는 게시하기 전에 오류를 확인하고 해결하는 방법을 안내해요.

오류가 남아 있어도 작업 내용은 계속 저장할 수 있어요. 다만 게시를 막는 오류는 해결해야 워크플로우를 게시할 수 있어요.

## 워크플로우 오류 표시 및 해결이란?

워크플로우 오류 표시 및 해결 기능은 트리거와 액션에서 지원되는 설정 문제를 찾아 위치를 알려 주고, 고칠 수 있게 도와줘요. 영향을 받는 단계는 워크플로우 캔버스에 표시되고, **Resolve Errors** 사이드바에서는 감지된 문제를 한곳에서 볼 수 있어요. 그래서 문제가 생겼을 때 각 단계를 하나씩 열어 확인하는 시간을 줄일 수 있어요.

지원되는 트리거와 액션에서는 다음과 같은 설정 문제를 찾아낼 수 있어요.

- 빠진 필수 입력란
- 연결이 끊긴 연동
- 덜 끝난 설정

**If/Else**(조건 분기)와 **Wait**(대기) 액션 같은 설정도 검사 대상에 포함돼요.

오류는 워크플로우 캔버스에서 바로 확인할 수 있어요. 게시를 막는 오류가 감지되면 해결해야 워크플로우를 게시할 수 있어요.

## 이 기능의 장점

- **오류를 한곳에서 관리해요:** 화면과 서버에서 확인한 검사 결과가 **Resolve Errors** 사이드바에 모여요.
- **더 안전하게 게시해요:** 게시를 막는 설정 오류는 고쳐야 워크플로우를 게시할 수 있어요.
- **저장은 자유로워요:** 오류가 남아 있어도 수동 저장과 자동 저장을 계속 쓸 수 있어요.
- **한눈에 찾을 수 있어요:** 오류 표시를 보고 문제가 있는 트리거와 액션을 빠르게 찾을 수 있어요.
- **바로 이동할 수 있어요:** **Open step**(단계 열기)을 누르면 오류와 관련된 워크플로우 구성 요소로 바로 이동해요.
- **AI가 도와줘요:** **How to fix**(해결 방법)를 누르면 AI가 지원되는 설정 문제를 이해하고 해결하는 것을 도와줘요.
- **자동으로 정리돼요:** 지원되는 문제를 고치면 오류 표시와 해당 오류 항목이 자동으로 사라져요.

## 워크플로우 오류의 종류

워크플로우 오류는 트리거, 액션, 필수 입력란, 연동 등 자동화의 여러 부분에서 생길 수 있어요. 오류의 원인을 알면 어느 구성 요소를 확인해야 하는지, 어떤 설정을 고쳐야 하는지 알기 쉬워요.

지원되는 오류의 예는 다음과 같아요.

- 트리거나 액션에서 빠진 필수 입력란
- 빠졌거나 올바르지 않은 선택 항목
- 연결이 끊겼거나 사용할 수 없는 연동
- 올바르지 않은 **If/Else** 설정
- 올바르지 않은 **Wait** 액션 설정
- 아직 입력하지 않은 필수 정보

예를 들어 예약 트리거에 캘린더가 없거나, SMS 액션의 메시지 본문이 비어 있거나, 이메일 액션에 제목과 본문이 없을 때 오류로 표시될 수 있어요.

하이퍼클래스는 워크플로우 검사 범위를 계속 넓히고 있어요. 그래서 사용하는 트리거, 액션, 설정에 따라 확인되는 오류가 다를 수 있어요.

## 워크플로우 캔버스의 오류 표시

워크플로우가 커질수록 설정 문제를 찾기가 어려워요. 오류 표시가 있으면 트리거와 액션을 하나씩 열어 보지 않아도, 하이퍼클래스가 확인이 필요하다고 표시한 단계를 캔버스에서 바로 찾을 수 있어요.

지원되는 설정 문제가 감지되면 해당 워크플로우 구성 요소에 오류 표시가 나타나요. 이 표시는 **Resolve Errors** 사이드바의 오류 항목과 서로 대응돼요.

문제를 고치면 오류 표시가 자동으로 사라지고, 오류 목록에서도 해당 항목이 지워져요.

## 오류가 있는 상태로 워크플로우 저장하기

워크플로우 빌더에서 저장과 게시는 하는 일이 달라요. 저장은 작업 중인 변경 내용을 보관하고, 게시는 워크플로우를 실제로 운영할지 정해요. 두 가지가 분리되어 있어서, 감지된 문제를 한 번에 모두 해결하지 않아도 설정이 덜 끝난 워크플로우를 계속 작업할 수 있어요.

오류가 캔버스에 남아 있어도 수동 저장과 자동 저장으로 작업 내용을 보관할 수 있어요. 덜 끝난 워크플로우를 두고 나갔다가 나중에 돌아와서 설정 문제를 마저 해결하면 돼요.

작업하는 동안에도 오류는 계속 검사되어 표시될 수 있어요. 하지만 오류를 모두 해결해야 작업 내용을 보관할 수 있는 것은 아니에요.

## Resolve Errors 사이드바

**Resolve Errors** 사이드바에서는 워크플로우에서 감지된 설정 문제를 한곳에서 볼 수 있어요. 오류가 모여 있으니 무엇을 확인해야 하는지 파악하고, 문제가 있는 트리거나 액션으로 바로 이동하기 쉬워요.

**Review issues**(문제 검토)를 선택하면 **Resolve Errors** 사이드바에 문제가 있는 워크플로우 구성 요소와 해당 오류가 표시돼요.

각 오류에는 두 가지 해결 옵션이 있어요.

- **Open step:** 문제가 있는 트리거나 액션을 열어서 설정을 확인하고 수정할 수 있어요.
- **How to fix:** AI의 도움을 받아 감지된 문제를 설명 듣고 해결 방법을 안내받을 수 있어요.

AI가 오류를 설명하고 해결 방법을 제안해 주지만, 수정한 뒤에는 워크플로우 설정이 의도한 자동화와 맞는지 직접 확인해야 해요.

**Error visibility controls**(오류 표시 제어)를 쓰면 오류 표시가 필요 없을 때 캔버스에서 작업하기가 편해요. 표시를 숨겨도 보이는 방식만 바뀔 뿐 설정 문제가 해결되는 것은 아니에요. 해결하지 않은 문제는 게시하기 전에 확인이 필요할 수 있어요.

## 게시하기 전에 워크플로우 오류 해결하기

게시하기 전에 감지된 설정 문제를 해결하면, 연락처가 자동화에 들어오기 전에 필수 설정이 갖춰져 있는지 확인할 수 있어요. 게시 검사 과정에서는 경고 메시지에서 문제가 있는 워크플로우 구성 요소로 바로 이동할 수 있어서 모든 단계를 일일이 찾아볼 필요가 없어요.

1. **자동화 > 워크플로우**에서 확인할 워크플로우를 열어요.

   ![워크플로우 열기](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155080995251/original/E4jKyqy2k5Z6VIDQuKnRCdB8OkNpz18ScQ.png?1789485952)
2. 워크플로우를 계속 만들고, 필요할 때 저장해요. 감지된 오류가 남아 있어도 괜찮아요.
3. 워크플로우를 실제로 운영할 준비가 되면 **Publish**(게시)를 클릭해요.
4. 해결되지 않은 게시 차단 문제가 감지되면 **Workflow can't be published yet**(워크플로우를 아직 게시할 수 없어요) 창에 나온 구성 요소를 확인해요.

   ![게시할 수 없다는 안내 창](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155080995352/original/HsbjWDimE_QFgUyt6IJAtWg-vtwtxAP-TA.png?1789485997)
5. **Review issues**를 클릭해요. **Resolve Errors** 사이드바에 나온 오류를 확인해요.

   ![Resolve Errors 사이드바에서 오류 확인](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155080995460/original/-QaFVRExr8gDkGJUOPiBF3Y361Poj4pCEg.png?1789486073)
6. 고치려는 트리거나 액션을 찾아요. **Open step**을 클릭하면 해당 설정으로 바로 이동하고, **How to fix**를 클릭하면 AI의 안내를 받을 수 있어요.

   ![Open step과 How to fix 사용 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155080997512/original/qCVTiDFfOqUrbX3EhDwb_6ayIaFWD664BA.gif?1789487013)
7. 확인된 설정을 수정해요.
8. 남은 게시 차단 문제도 같은 방법으로 해결해요. 해당하는 문제를 모두 해결한 뒤 워크플로우를 게시해요.

## 오류 해결 유형

1. 연동 문제

   - **오류:** 인증 정보가 올바르지 않아 Facebook 연동에 실패했어요.
   - **해결:** **AI Assistant**(AI 어시스턴트)가 연동을 다시 연결하거나 다시 인증하라고 안내해요.

2. 빠진 필수 입력란

   - **오류:** 스냅샷 가져오기에 필수 입력란(예: 예약 날짜, 커스텀 필드 등)이 빠져 있어요.
   - **해결:** **AI Assistant**가 빠진 입력란을 알려 주고, 기존 입력란과 연결하거나 새로 만드는 옵션을 제시해요.

## 게시 전 오류와 워크플로우 실행 오류의 차이

설정 검사 오류와 워크플로우 실행 오류는 자동화 진행 단계에서 생기는 시점이 달라요. 어떤 종류의 문제인지 알아야 알맞은 하이퍼클래스 도구를 선택할 수 있어요. 워크플로우가 실행되기 시작한 뒤에 생기는 문제는 게시 전 오류 화면으로 확인할 수 없어요.

| 오류 종류 | 의미 | 확인할 곳 |
| --- | --- | --- |
| **게시 전 설정 오류** | 워크플로우를 만들거나 게시하는 동안 트리거, 액션, 필수 설정에서 지원되는 문제를 찾아 알려 줘요. 이런 문제는 해결해야 워크플로우를 게시할 수 있을 수 있어요. | **워크플로우 캔버스 왼쪽의 오류 패널**에서 확인해요. 게시가 막혔다면 **Review issues**를 클릭해 같은 오류 패널을 열고, 문제가 있는 단계를 확인해요. |
| **실행 오류** | 연락처가 워크플로우를 따라 진행하는 중에 실행 단계에서 문제가 생겨요. 워크플로우가 운영되기 시작한 뒤 무슨 일이 있었는지 확인할 때 도움이 돼요. | 워크플로우 안의 **상단 메뉴 바**에 있는 **Execution Logs**(실행 로그)에서 확인해요. |

{% hint style="info" %}
게시 전 오류를 모두 해결했다고 해서 모든 워크플로우 실행이 성공하는 것은 아니에요. 운영 중인 워크플로우는 필요에 따라 계속 테스트하고 모니터링하세요.
{% endhint %}

## 자주 묻는 질문

### 설정 오류가 남아 있어도 워크플로우를 저장할 수 있나요?
네. 감지된 설정 오류가 남아 있어도 수동 저장과 자동 저장으로 작업 내용을 보관할 수 있어요. 게시는 따로 처리돼요.

### 게시를 막는 오류가 해결되지 않은 상태로 워크플로우를 게시할 수 있나요?
아니요. 하이퍼클래스가 해결되지 않은 게시 차단 설정 문제를 감지하면 게시가 중단돼요. 해당 문제를 먼저 고쳐야 해요.

### 이미 게시한 워크플로우에서 오류가 발견되면 자동으로 **Draft**(초안) 상태로 돌아가나요?
아니요. 기존 하이퍼클래스 도움말에 따르면, 게시된 워크플로우는 오류가 발견되어도 자동으로 **Draft** 상태로 돌아가지 않아요.

### 하이퍼클래스는 게시 전에 워크플로우의 모든 문제를 찾아 주나요?
게시 전 검사가 가능한 모든 문제를 잡아 준다고 생각하면 안 돼요. 검사 범위는 지원되는 설정에 적용되고, 계속 넓어지고 있어요. 게시한 뒤에도 워크플로우를 테스트하고 모니터링하는 일이 중요해요.

### **Open step**과 **How to fix**는 뭐가 다른가요?
**Open step**은 문제가 있는 워크플로우 구성 요소로 바로 이동해서 설정을 수정할 수 있게 해 줘요. **How to fix**는 AI가 감지된 오류를 이해하고 해결하도록 안내해 줘요.

### 오류를 고치면 어떻게 되나요?
지원되는 오류는 문제를 해결하면 오류 표시가 사라지고, 오류 목록에서도 해당 항목이 자동으로 지워져요.

### 오류를 숨기면 해결되나요?
아니요. 오류를 숨기면 보이는 방식만 바뀌고, 근본적인 설정 문제는 그대로예요. 게시를 막는 문제라면 여전히 해결해야 해요.

### **Resolve Errors**에 나오는 문제는 **Execution Logs**에 나오는 오류와 같나요?
꼭 그렇지는 않아요. **Resolve Errors**는 워크플로우를 만들고 게시하는 동안 확인되는, 지원되는 설정 문제를 다뤄요. 워크플로우가 실행될 때 생기는 문제는 **Execution Logs**와 **Error Notifications**(오류 알림)로 확인할 수 있어요. 자세한 내용은 [워크플로우 오류 알림](../빌더/error-notifications-in-workflows.md)을 참고하세요.
