# 워크플로우 트리거 — Order Form Submission(주문 폼 제출)

고객이 퍼널이나 웹사이트의 주문 폼을 제출할 때마다 자동으로 작업을 실행하고 싶다면 **Order Form Submission**(주문 폼 제출) 트리거를 쓰세요. 이 문서에서는 트리거가 하는 일, 장점, 설정 방법, 활용 사례와 자주 묻는 질문을 알아봐요.

## Order Form Submission 트리거란?

**Order Form Submission** 트리거는 고객이 퍼널이나 웹사이트의 주문 폼을 작성해 제출하면 워크플로우를 시작해요. 이 트리거로 주문 확인 메일 발송, 연락처 정보 업데이트, 팀원 알림, 구매 후 업셀 안내 같은 작업을 자동화할 수 있어요. 업무가 빨라지고, 고객은 알맞은 안내를 제때 받을 수 있어요.

## Order Form Submission 트리거의 장점

- 주문 관리 자동화: 확인 이메일 발송, 정보 업데이트, 내부 알림 같은 주문 처리 작업을 자동으로 처리해요.
- 고객 경험 개선: 고객이 주문 확인과 후속 안내를 바로 받아 신뢰와 만족도가 높아져요.
- 유연한 설정: 퍼널, 페이지, 상품, 제출 유형 필터로 원하는 조건에만 자동화를 적용할 수 있어요.
- 판매 기회 확대: 구매한 상품에 맞춰 후속 작업을 실행해서 업셀과 교차 판매 캠페인을 진행할 수 있어요.
- 정확한 데이터 수집: 연락처 정보가 자동으로 업데이트되어 항상 최신 상태로 유지돼요.

## Order Form Submission 트리거 설정하기

워크플로우에 Order Form Submission 트리거를 추가하는 방법이에요.

1. 워크플로우 빌더로 이동해요. 왼쪽 메뉴에서 **자동화 > 워크플로우**를 선택하세요. 새 워크플로우를 처음부터 만들거나, 트리거를 추가할 기존 워크플로우를 선택하세요.
2. **Add New Trigger**(새 트리거 추가)를 클릭하고 목록에서 **Order Form Submission**(주문 폼 제출)을 선택하세요.

   ![트리거 목록에서 Order Form Submission 선택](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155039635087/original/FGH3gbcRkgEf_9jcST7ZPZSusyC6G0m1bg.png?1736519992)

3. 트리거 이름을 입력하세요. 무엇을 위한 트리거인지 알 수 있게 쓰는 것이 좋아요. 예: "John의 라이브 워크숍 주문 폼 제출"

   ![트리거 이름 입력 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155039635120/original/gYUbpEM67ibi2DDKdBLI_NkLEBiCLGKUuw.png?1736520013)

### 필터 설정하기 (선택 사항)

필터를 쓰면 워크플로우가 실행되는 조건을 좁힐 수 있어요.

#### In Funnel/Website

**In Funnel/Website**(퍼널/웹사이트에서) 필터에서는 주문 폼이 있는 퍼널이나 웹사이트를 선택해요. 필터를 더 추가해서 특정 페이지와 특정 상품까지 지정할 수도 있어요.

![In Funnel/Website 필터 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155039701838/original/UK9M7vZu_X3UeefEuNkDrElqorNRcR-tew.png?1736751534)

**Page Is**(페이지가 다음과 같음)

주문 폼이 있는 퍼널이나 웹사이트 안에서 특정 페이지를 선택해요.

![Page Is 필터 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155039701849/original/q9BYYs4LCZgpMtkiKhZVyZIT9PNo6VG9cw.png?1736751563)

**Product Is**(상품이 다음과 같음)

주문 폼에 연결된 상품을 지정하면, 해당 상품일 때만 워크플로우가 실행돼요. 상품은 여러 개 지정할 수 있어요.

![Product Is 필터 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155039701872/original/MY8ie7S8NOwxyoDrkouedSs39uJfJvI8GA.png?1736751601)

#### Submission Type

**Submission Type**(제출 유형) 필터는 고객이 완료한 주문 폼 제출의 종류에 따라 워크플로우를 실행해요. 고객이 구매 과정의 어디까지 진행했는지, 결제 중 어떤 추가 오퍼를 수락했는지에 따라 자동화를 다르게 만들 수 있어요.

제출 유형은 다음과 같아요.

- **Bump**(범프)
  - 의미: 고객이 범프 오퍼를 구매하면 실행돼요. 범프 오퍼는 처음 결제 단계에서 보여 주는 추가 상품이에요.
  - 활용: 추가 상품과 관련된 워크플로우를 추적하고 자동화할 때 좋아요. 예를 들어 맞춤 후속 메시지를 보내거나 관련 상품을 교차 판매할 수 있어요.
- **Opt-In**(옵트인)
  - 의미: 고객이 이름, 이메일 같은 연락처 정보는 입력했지만 주문은 완료하지 않았을 때 실행돼요.
  - 활용: 장바구니 이탈 워크플로우에 알맞아요. 관심은 보였지만 구매를 끝내지 않은 잠재 고객에게 후속 연락을 해서 주문을 마치도록 유도할 수 있어요.
- **Sale**(세일)
  - 의미: 고객이 결제를 마치고 구매를 완료했을 때 실행돼요.
  - 활용: 주문 확인, 감사 이메일 발송, 업셀이나 피드백 요청 같은 구매 후 후속 작업을 자동화할 때 좋아요.
- **Upsell**(업셀)
  - 의미: 고객이 첫 구매 후에 안내된 업셀 오퍼를 수락하면 실행돼요.
  - 활용: 업셀 캠페인을 추적하고 관리하거나, 업셀 주문 정보를 보내거나, 추가 구매를 한 고액 고객을 내부 팀에 알릴 수 있어요.

### 저장하고 워크플로우 활성화하기

1. 필터 설정이 끝나면 **Save**(저장) 버튼을 눌러 트리거 설정을 마무리하세요.
2. 퍼널을 테스트 모드로 바꾸고 가짜 정보로 주문 제출을 직접 해 보세요. 워크플로우가 의도대로 동작하는지 확인할 수 있어요.
3. 테스트가 잘 끝나면 **Publish**(게시) 토글을 켜서 워크플로우를 활성화하세요.

## 사용 사례

이 트리거를 활용하는 예시를 살펴봐요.

### 사용 사례 1. 주문 확인과 연락처 정보 업데이트

시나리오: 구매가 이루어지면 주문 확인 이메일을 자동으로 보내고 고객의 연락처 정보도 업데이트하고 싶어요.

결과: 워크플로우가 고객에게 확인 이메일을 보내고, 주문 내역을 연락처 정보에 업데이트해요. 앞으로의 마케팅 캠페인을 위해 태그도 붙여요.

### 사용 사례 2. 장바구니 이탈 회복

시나리오: 연락처 정보는 입력했지만 주문을 완료하지 않은 고객에게 후속 연락을 하고 싶어요.

결과: 워크플로우가 고객에게 리마인드 이메일을 보내고, 할인 같은 혜택을 제안해 구매를 완료하도록 유도해요.

### 사용 사례 3. 구매 후 업셀 캠페인

시나리오: 구매 직후 업셀을 제안해서 매출을 높이고 싶어요.

결과: 워크플로우가 업셀 상품을 안내하는 이메일을 보내요. 기간 한정 할인을 넣어 바로 행동하도록 유도해요.

### 사용 사례 4. 고가 상품 구매 시 내부 알림

시나리오: 고객이 고가 상품을 구매하면 영업팀이 바로 후속 연락을 할 수 있도록 알려야 해요.

결과: 워크플로우가 영업팀에 내부 알림을 보내 고객에게 연락하도록 안내해요.

### 사용 사례 5. 업셀과 범프 오퍼 추적

시나리오: 결제 과정에서 업셀과 범프 오퍼가 얼마나 효과적인지 추적하고 싶어요.

결과: 워크플로우가 업셀이나 범프 오퍼 수락 내역을 연락처 정보에 기록하고, 고객에게 후속 이메일을 보내요.

## 자주 묻는 질문

### 같은 퍼널에서 제출 유형별로 워크플로우를 따로 실행할 수 있나요?

네, 가능해요. 제출 유형(Opt-In, Sale, Upsell, Bump)마다 해당 필터를 지정해서 워크플로우를 따로 만들 수 있어요.

### 이 트리거로 장바구니 이탈은 어떻게 처리하나요?

**Submission Type** 필터에서 **Opt-In**을 선택하면 구매를 완료하지 않은 고객을 대상으로 지정할 수 있어요. 그 뒤에 리마인드 이메일을 보내거나 할인을 제안하는 워크플로우를 만들어 주문 완료를 유도하세요.

### 업셀 전환을 일반 판매와 따로 추적할 수 있나요?

네, 가능해요. **Submission Type** 필터에서 **Upsell**을 선택하면 업셀 전환만 추적하고 분석하는 전용 워크플로우를 만들 수 있어요.

### 게시하기 전에 워크플로우를 테스트하려면 어떻게 하나요?

퍼널을 테스트 모드로 바꾸고 가짜 카드 정보로 주문 폼 제출을 직접 해 보세요. 워크플로우를 실제로 켜기 전에 제대로 동작하는지 확인할 수 있어요.

### 구매한 상품에 따라 다른 확인 이메일을 보낼 수 있나요?

네, 가능해요. **Product Is** 필터로 상품별 워크플로우를 따로 만들고, 상품마다 확인 이메일 내용을 다르게 설정하세요.
