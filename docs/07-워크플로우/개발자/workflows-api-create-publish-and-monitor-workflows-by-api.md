# 워크플로우 API – API로 워크플로우 생성, 발행, 모니터링하기

**워크플로우 API(Workflows API)**를 사용하면 개발자와 에이전시가 하이퍼클래스 워크플로우를 프로그래밍 방식으로 생성, 관리, 발행, 모니터링할 수 있어요. 외부 애플리케이션에서 워크플로우를 구축하고, 여러 하위 계정(Sub-account)에 자동화를 배포하며, 워크플로우 빌더에서 하나하나 수동으로 관리하지 않고도 실행 로그와 성능 통계를 확인할 수 있습니다.

> **중요:** 워크플로우 API는 현재 선택된 일부 하위 계정에 한해 비공개 베타(private beta)로 제공되고 있어요. 접근 권한을 요청하려면 하이퍼클래스 고객지원에 문의하세요. 접근 권한이 없는 하위 계정은 `WORKFLOW_API_NOT_ENABLED_FOR_LOCATION` 코드와 함께 403 오류가 반환됩니다.

## **워크플로우 API란 무엇인가요?**

워크플로우 API는 외부 애플리케이션 및 연동(Integration)을 통해 하이퍼클래스 워크플로우를 관리할 수 있는 방법을 제공해요.

이 API를 사용하면 워크플로우를 생성하고, 설정 정보를 가져오고, 워크플로우 단계를 수정하고, 발행 상태를 변경하거나, 워크플로우를 삭제할 수 있습니다.

또한 실행 로그와 통계에도 접근할 수 있어서, 개발자가 활동을 추적하고 실패 원인을 조사하며 워크플로우 성능을 측정할 수 있어요.

API를 통해 생성된 워크플로우는 하이퍼클래스 워크플로우 빌더(Workflow Builder)에 표시되며, 다른 워크플로우와 동일하게 관리할 수 있습니다.

---

## **워크플로우 API의 주요 이점**

- **워크플로우 생성 자동화:** 외부 애플리케이션에서 직접 워크플로우를 만들고 배포할 수 있어요.
- **대규모 워크플로우 관리:** 지원되는 하위 계정 전체에 표준화된 워크플로우를 배포할 수 있어요.
- **발행 전 유효성 검사:** 워크플로우를 활성화하기 전에 설정 오류를 미리 확인할 수 있어요.
- **충돌하는 업데이트 방지:** 버전 확인 기능으로 워크플로우 빌더에서 작업한 변경 사항을 보호할 수 있어요.
- **워크플로우 실행 모니터링:** 실행 이력, 실패 내역, 집계 통계를 조회할 수 있어요.
- **API 권한 제어:** 각 연동(Integration)에 필요한 작업에 맞춰 권한 범위(Scope)를 지정할 수 있어요.

---

## **시작하기 전에**

워크플로우 API를 사용하려면 이용 자격이 있는 하이퍼클래스 하위 계정과 인증된 액세스 토큰이 필요해요.

- 본인의 하위 계정이 워크플로우 API 비공개 베타에 접근할 수 있는지 확인하세요.
- 하이퍼클래스 하위 계정에서 `Settings(설정) → Private Integrations(비공개 연동)`으로 이동하세요.
- 비공개 연동(Private Integration)을 만들고 **Scopes(권한 범위)** 항목에서 워크플로우 관련 권한을 찾으세요.
- 연동에 필요한 권한을 활성화하세요.
- 액세스 토큰을 생성하고 안전하게 보관하세요.

![비공개 연동 권한 설정 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084600886/original/AflDswEMedBKDWVe8LPJYfYs0dxrDzxZDQ.png?1793363901)

사용 가능한 권한은 다음과 같아요:

| 권한 | API 권한 범위(Scope) | 용도 |
|---|---|---|
| 워크플로우 보기 | `workflows.readonly` | 워크플로우 정보와 사용 가능한 단계 유형 조회 |
| 워크플로우 편집 | `workflows.write` | 워크플로우 생성, 유효성 검사, 수정 |
| 워크플로우 발행 | `workflows.publish` | 워크플로우 발행 또는 초안 상태로 되돌리기 |
| 워크플로우 삭제 | `workflows.delete` | 기존 워크플로우 삭제 |
| 워크플로우 로그 보기 | `workflows.logs` | 실행 로그 및 통계 접근 |

API 요청에는 적절한 인증 토큰, `Version: v3` 헤더, 그리고 하위 계정의 `locationId`가 필요합니다.

**참고:** 하이퍼클래스 API 요청 도메인은 여전히 `services.leadconnectorhq.com`입니다. 이 도메인을 하이퍼클래스 고객지원 센터나 애플리케이션 도메인으로 바꾸지 마세요.

## **사용 가능한 워크플로우 API 엔드포인트**

워크플로우 API는 워크플로우 관리 및 모니터링을 위한 10개의 엔드포인트를 제공해요.

| 기능 | 메서드 | 엔드포인트 |
|---|---|---|
| 단계 유형 조회 | GET | `/workflows/step-types` |
| 워크플로우 정의 유효성 검사 | POST | `/workflows/definition/validate` |
| 워크플로우 검색 | POST | `/workflows/search` |
| 워크플로우 생성 | POST | `/workflows/` |
| 워크플로우 정의 조회 | GET | `/workflows/{workflowId}/definition` |
| 워크플로우 정의 업데이트 | PUT | `/workflows/{workflowId}/definition` |
| 워크플로우 상태 업데이트 | PUT | `/workflows/{workflowId}/status` |
| 워크플로우 삭제 | DELETE | `/workflows/{workflowId}` |
| 워크플로우 로그 조회 | GET | `/workflows/{workflowId}/logs` |
| 워크플로우 로그 통계 조회 | GET | `/workflows/{workflowId}/logs/aggregate` |

엔드포인트별 파라미터, 요청 스키마, 응답 예시는 [하이퍼클래스 워크플로우 API 문서](https://marketplace.gohighlevel.com/docs/ghl/workflows/workflows/)를 참고하세요.

## **API 요청 테스트하는 방법**

하이퍼클래스 개발자 포털(Developer Portal)에는 워크플로우 API를 테스트할 수 있는 인터랙티브 요청 패널이 포함되어 있어요.

- [워크플로우 API 문서](https://marketplace.gohighlevel.com/docs/ghl/workflows/workflows/)를 여세요.
- **Get Workflow Definition**처럼 테스트하려는 엔드포인트를 선택하세요.
- **Bearer Token** 필드에 액세스 토큰을 입력하세요.
- 해당되는 경우 `workflowId`와 `locationId` 등 필요한 파라미터를 입력하세요.
- **Version** 필드에서 `v3`를 선택하세요.
- **Send API Request** 버튼을 클릭하세요.
- 문서 패널에 표시된 응답 결과를 확인하세요.

**중요:** API 문서에서 전송한 요청은 선택한 하위 계정에 실제로 적용됩니다. 데이터를 수정하거나 삭제하는 작업을 수행하기 전에는 테스트용 워크플로우를 사용하세요.

## **API로 워크플로우 생성 및 발행하는 방법**

다음 단계를 따라 프로그래밍 방식으로 워크플로우를 생성하고 활성화할 수 있어요.

- **사용 가능한 단계 유형 조회하기.** Get Step Types를 사용해 지원되는 워크플로우 트리거(Trigger), 액션(Action)과 필요한 속성을 확인하세요.
- **워크플로우 정의 준비하기.** 워크플로우의 이름, 트리거, 액션, 연결, 설정을 구성하세요.
- **정의 유효성 검사하기.** 저장하기 전에 Validate Workflow Definition으로 설정을 확인하세요.
- **워크플로우 생성하기.** Create Workflow를 통해 정의를 제출하세요. 새로 생성된 워크플로우는 초안(Draft) 상태로 만들어집니다.
- **워크플로우 발행하기.** 유효성 검사를 통과한 후 Update Workflow Status를 사용해 워크플로우를 발행하세요.

![워크플로우 생성 및 발행 과정](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084600932/original/-qOsStr4vB9-ItIIxAvpZmU6uKGd-iz9xg.png?1793363946)

워크플로우를 발행하려면 다음과 같은 상태 값을 제출하세요:

```
{
  "status": "published"
}
```

---

### 유효성 검사 결과 이해하기

유효성 검사 엔드포인트는 워크플로우 정의에서 발견된 오류와 경고에 대한 정보를 반환해요.

- **오류(Errors):** 워크플로우 저장이나 발행을 막는 문제
- **경고(Warnings):** 저장을 반드시 막지는 않지만 주의가 필요한 잠재적인 설정 문제
- **단계 참조(Step references):** 어떤 단계 또는 설정 경로에서 문제가 발생했는지 개발자가 파악할 수 있도록 돕는 정보

유효성 검사 결과를 확인하고 보고된 문제를 수정한 후, 다음 단계로 진행하기 전에 다시 한번 유효성 검사를 실행하세요.

## **기존 워크플로우를 안전하게 업데이트하는 방법**

워크플로우 API는 워크플로우를 수동으로 다시 만들지 않고도 기존 워크플로우 정의를 업데이트할 수 있도록 지원해요.

다음 절차를 따르세요:

- **Get Workflow Definition**으로 현재 워크플로우를 조회하세요.
- 정의를 수정하기 전에 워크플로우를 초안(Draft) 상태로 되돌리세요.
- 유지해야 하는 다른 필수 워크플로우 정보는 그대로 두고 필요한 속성만 업데이트하세요.
- **Update Workflow Definition**을 통해 완전한 정의를 제출하세요.
- 업데이트된 워크플로우의 유효성을 검사하고 발행하세요.

### **버전 충돌 방지**

이 API는 버전 확인 기능을 사용해서 오래된 업데이트가 최신 워크플로우 설정을 덮어쓰지 않도록 방지해요.

업데이트를 제출할 때는 API가 반환한 현재 워크플로우 버전을 함께 포함해야 합니다.

만약 정의를 조회한 이후 다른 사용자가 워크플로우를 변경했다면, API는 오래된 요청을 거부합니다.

이 경우 최신 버전을 다시 조회하고, 변경 사항을 확인한 후, 업데이트된 정의를 다시 제출하세요.

> **중요:** 워크플로우 정의를 업데이트하면 기존 정의 전체가 교체돼요. 워크플로우에 그대로 유지되어야 하는 단계와 연결을 반드시 보존하세요.

## **워크플로우 실행 로그와 통계를 모니터링하는 방법**

워크플로우 API는 워크플로우 활동을 모니터링할 수 있는 두 개의 엔드포인트를 제공해요.

### **워크플로우 로그 조회하기**

이 엔드포인트를 사용해서 워크플로우의 실행 기록을 조회할 수 있어요.

실행 로그를 통해 다음을 파악할 수 있습니다:

- 워크플로우에 진입한 연락처(Contacts)
- 워크플로우 실행 중 처리된 단계
- 실패했거나 오류가 발생한 단계
- 개별 연락처별 실행 상태
- 특정 워크플로우 단계와 관련된 활동

### **워크플로우 로그 통계 조회하기**

이 엔드포인트를 사용해서 워크플로우 실행에 대한 집계 정보를 조회할 수 있어요.

다음과 같은 항목을 분석할 수 있습니다:

- 워크플로우 등록(enrollment) 현황
- 단계별 실행 결과
- 워크플로우 단계별 실패 내역
- 연락처가 워크플로우를 벗어난 이유
- 선택한 기간 동안의 추세

예를 들어, 개발자는 단계별 실패 건수를 조회한 다음, 실행 로그를 사용해 영향을 받은 연락처를 조사할 수 있어요.

**참고:** 실행 로그 요청은 최대 30일 범위의 기간을 지원하며, 최대 60일치 이력 데이터에 접근할 수 있어요.

## **API 요청 제한**

워크플로우 API 요청에는 하이퍼클래스의 공개 API 제한과 엔드포인트별 추가 제한이 적용돼요.

문서화된 제한 사항은 다음과 같습니다:

| 요청 유형 | 제한 |
|---|---|
| 표준 공개 API 요청 | 하위 계정당 10초에 100회, 하루 200,000회 |
| 워크플로우 읽기(Reads) | 하위 계정당 10초에 30회 |
| 워크플로우 쓰기(Writes) | 하위 계정당 10초에 10회 |
| 워크플로우 로그 | 10초에 20회, 분당 60회 |
| 워크플로우 로그 통계 | 10초에 5회, 분당 10회, 하루 1,000회 |

적용 가능한 제한을 초과한 요청은 HTTP 429 응답을 반환합니다.

이러한 제한을 고려해 연동을 설계하고, 적절한 재시도(retry) 로직을 구현하세요.

## **일반적인 사용 사례**

### 1. 하위 계정 전반에 표준화된 워크플로우 배포하기

에이전시는 워크플로우 API를 사용해서 이용 자격이 있는 고객 하위 계정 전체에 표준 자동화 설정을 배포할 수 있어요.

예를 들어, 에이전시는 템플릿 하위 계정에서 워크플로우 정의를 가져온 다음, 각 고객 하위 계정에 동일한 워크플로우를 생성하고 발행할 수 있습니다.

이를 통해 비슷한 워크플로우를 배포할 때 반복되는 수동 설정 작업을 줄일 수 있어요.

### 2. 워크플로우 실패 모니터링하기

개발자는 워크플로우 실행 로그와 통계를 사용해서 자동화 프로세스에 영향을 주는 문제를 파악할 수 있어요.

예를 들어, 연동 시스템이 실패 건수를 조회하고, 영향을 받은 워크플로우 단계를 파악한 다음, 팀을 위한 리포트를 생성할 수 있습니다.

### 3. 외부 애플리케이션에서 워크플로우 생성하기

하이퍼클래스와 연동된 애플리케이션은 외부 시스템의 이벤트나 작업을 기반으로 워크플로우를 생성할 수 있어요.

예를 들어, 신규 고객이 가입을 완료하면 애플리케이션이 온보딩(Onboarding) 워크플로우를 자동으로 생성할 수 있습니다.

이 애플리케이션은 API를 통해 워크플로우 정의의 유효성을 검사하고, 워크플로우를 생성한 다음, 발행할 수 있어요.

## **자주 묻는 질문**

**Q. 워크플로우 API는 누가 사용할 수 있나요?**

워크플로우 API는 현재 비공개 베타에 참여 중인 선택된 하위 계정만 이용할 수 있어요. 접근 권한을 요청하려면 하이퍼클래스 고객지원에 문의하세요.

**Q. 403 오류가 발생하는 이유는 무엇인가요?**

`WORKFLOW_API_NOT_ENABLED_FOR_LOCATION`과 함께 403 응답이 발생하면, 해당 하위 계정이 비공개 베타 접근 권한을 가지고 있지 않다는 의미예요.

그 외의 인증 오류는 토큰 권한이나 하위 계정의 접근 제한 때문에 발생할 수 있습니다.

**Q. API만으로 워크플로우를 생성하고 발행할 수 있나요?**

네. 이용 자격이 있는 연동(Integration)은 워크플로우 정의를 생성하고, 유효성을 검사하고, 초안으로 저장한 다음, 프로그래밍 방식으로 발행할 수 있어요.

**Q. 기존에 발행된 워크플로우를 수정할 수 있나요?**

네. 워크플로우를 초안(Draft) 상태로 변경하고, 현재 정의를 조회한 다음, 업데이트를 적용하고 다시 발행하면 됩니다.

**Q. API가 워크플로우 업데이트 충돌을 방지해 주나요?**

네. 버전 확인 기능이 오래된 업데이트를 거부하므로, 최신 변경 사항이 알게 모르게 덮어써지는 일을 막아줘요.

**Q. 워크플로우 실행 이력을 조회할 수 있나요?**

네. Get Workflow Logs는 실행 단위의 세부 정보를 제공하고, Get Workflow Log Statistics는 집계된 수치를 제공합니다.

**Q. 이 엔드포인트들로 워크플로우에 연락처를 추가할 수 있나요?**

아니요. 워크플로우에 연락처를 추가하거나 제거하려면 별도의 연락처(Contacts) API 엔드포인트를 사용해야 해요.

**Q. 워크플로우 유효성 검사를 하면 워크플로우가 저장되거나 발행되나요?**

아니요. 유효성 검사는 제출된 정의를 확인하고 오류나 경고만 반환할 뿐, 워크플로우를 저장하지는 않습니다.
