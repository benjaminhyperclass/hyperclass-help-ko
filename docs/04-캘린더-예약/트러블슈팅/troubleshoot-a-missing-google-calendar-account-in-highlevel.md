# 하이퍼클래스에서 구글 캘린더 계정이 보이지 않을 때 해결 방법

구글 캘린더 계정이 이미 사용자의 하이퍼클래스 프로필에 연결되어 있는데도 캘린더(Calendars) 설정 시 예상한 곳에 표시되지 않을 수 있어요. 이런 현상은 계정 재인증이 필요하거나, 필요한 구글 권한이 누락되었거나, 동기화할 구글 캘린더가 아직 선택되지 않은 경우에 발생할 수 있습니다. 불필요하게 다른 구글 계정을 새로 연결하기 전에, 먼저 연결 상태와 권한을 확인하면 접근 권한을 복구할 수 있어요.

## 내 구글 캘린더 계정이 하이퍼클래스에 표시되지 않는 이유는 무엇인가요?

하이퍼클래스의 구글 캘린더 연결은 **사용자별(user-specific)**로 설정돼요. 즉, 각 사용자가 자신의 구글 계정을 직접 연결해야 합니다. 구글 계정을 연결하면 하이퍼클래스가 구글 캘린더에 접근할 수 있는 권한을 얻게 되고, 이후 해당 계정에 속한 개별 캘린더를 선택해서 동기화 및 예약 가능 시간(Availability) 설정에 사용할 수 있어요.

중요: 구글 계정의 소유자 본인이 직접 구글 인증(authorization)을 완료해야 해요. 다른 사용자의 구글 계정을 연결할 때 "login as(대신 로그인)" 방식을 사용하면 안 됩니다.

## **구글 캘린더 연결 문제 해결의 주요 이점**

문제의 원인이 계정 연결인지, 구글 권한인지, 아니면 개별 캘린더 접근 문제인지를 파악하면 정확한 해결책을 적용할 수 있어요. 이렇게 하면 이미 정상적으로 설정된 다른 캘린더 구성을 건드리지 않으면서 캘린더 접근 권한을 복구할 수 있습니다.

- 
캘린더 접근 복구: 연결이나 권한에 문제가 있는 경우 올바른 구글 계정을 재인증할 수 있어요.

- 
필수 권한 확인: 하이퍼클래스가 연동에 필요한 구글 캘린더 권한을 가지고 있는지 확인할 수 있어요.

- 
잘못된 연결 방지: 관련 없는 계정을 추가하는 대신, 의도했던 구글 계정을 재연결할 수 있어요.

- 
캘린더 단위 문제 파악: 계정 연결 문제와 특정 구글 캘린더 접근 문제를 구분할 수 있어요.

## **트러블슈팅 전에 확인할 사항**

구글 캘린더 연결은 개별 하이퍼클래스 사용자에게 귀속되므로, 먼저 올바른 사용자와 구글 계정을 확인하면 잘못된 계정을 재연결하는 실수를 막을 수 있어요. 또한 구글 계정을 연결하는 것과, 해당 계정에서 특정 캘린더를 선택해 동기화하는 것은 서로 다른 작업이라는 점을 구분하는 것도 중요합니다.

변경 작업을 하기 전에 다음을 확인하세요:

- 
올바른 하이퍼클래스 사용자로 작업하고 있는지 확인하세요.

- 
해당 사용자가 연결하려는 구글 계정이 무엇인지 알고 있는지 확인하세요.

- 
사용자가 해당 구글 계정에 직접 로그인할 수 있는지 확인하세요.

- 
동기화하려는 구글 캘린더가 해당 계정 소유이거나, 충분한 접근 권한으로 공유되어 있는지 확인하세요.

- 
재인증이 필요한 경우 사용자가 필요한 구글 권한을 승인할 준비가 되어 있는지 확인하세요.

참고: 구글 계정이 연결되어 있다고 해서 그 계정에 속한 모든 구글 캘린더가 이미 하이퍼클래스에서 동기화되도록 설정되어 있다는 뜻은 아니에요.

## **표시되지 않는 구글 캘린더 계정 해결 방법**

현재 연결 상태와 구글 인증 상태를 확인하면, 이전에 연결했던 계정이 예상한 위치에 나타나지 않는 문제를 해결할 수 있어요. 기존 계정이 보이지 않는다고 해서 다른 계정을 새로 연결하기보다는, 사용자가 하이퍼클래스와 함께 사용하려는 동일한 구글 계정을 그대로 사용하세요.

- 
해당 하이퍼클래스 하위 계정(Sub-account)에서 **캘린더(Calendars)** 메뉴로 이동하세요.

- 
**캘린더 설정(Calendar Settings)**을 여세요.

- 
**Connections(연결)** 탭을 선택하세요.

![](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155080995897/original/zj73O15PSpLaEzboGqUsXKo2bOlWYuY5PA.png?1789486217)

- 
원하는 구글 계정이 연결된 캘린더 계정으로 표시되는지 확인하세요.

- 
구글 계정이 연결되어 있지 않다면 **+ Add New(새로 추가)**를 클릭하세요.

![](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155080995957/original/Or65Gm6mxuceZGSNNFFaBNTxa2uoQPp1TQ.png?1789486255)

- 
캘린더 제공업체로 **Google Calendar(구글 캘린더)**를 선택하세요.

![](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155080996061/original/5-HLSPG3Ei89z8YWH-bW-wHcG_U5B1SIkw.png?1789486300)

- 
구글에서 계정을 선택하라는 창이 뜨면, 하이퍼클래스와 함께 사용하려는 동일한 구글 계정을 선택하세요.

- 
구글의 계정 선택 화면에 원하는 계정이 보이지 않으면, 구글에서 제공하는 계정 선택 또는 로그인 옵션을 이용해 해당 계정으로 로그인하세요.

중요: 이전에 연결했던 계정이라고 해서 반드시 다른 구글 계정을 선택할 필요는 없어요. 목표는 현재 하이퍼클래스 사용자에 맞는 올바른 계정을 인증하는 것입니다.

- 
구글의 인증 절차를 완료하고, 구글 캘린더 연동에 필요한 권한 요청을 승인하세요.

- 
인증이 완료되면 하이퍼클래스로 돌아오세요.

- 
**캘린더 설정 > Connections(연결)**에서 해당 구글 계정이 이제 표시되는지 확인하세요.

- 
사용하려는 구글 캘린더가 해당 캘린더 설정에서 선택 가능한지 확인하세요.

## **구글 권한 확인 및 계정 재연결**

구글 계정이 연결된 것으로 표시되더라도, 인증 상태에서 하이퍼클래스에 필요한 모든 권한이 더 이상 제공되지 않을 수 있어요. 계정을 재연결하면 사용자가 하이퍼클래스를 다시 인증하여 필요한 권한을 복구할 수 있으며, 완전히 다른 구글 계정을 추가해야 한다고 단정할 필요는 없습니다.

- 
**설정(Settings) > Integrations(연동)**으로 이동하세요.

- 
**Google(구글)** 연동 항목을 찾으세요.

- 
필요한 권한이 누락되었다는 경고나 표시가 있는지 확인하세요.

- 
하이퍼클래스에서 **Reconnect(재연결)** 옵션을 제공하면 **Reconnect**를 클릭하세요.

- 
올바른 구글 계정을 선택하세요.

- 
구글 인증 절차를 완료하고 필요한 권한을 승인하세요.

- 
**캘린더 > 캘린더 설정 > Connections**로 돌아가세요.

- 
구글 계정과 원하는 캘린더가 이제 사용 가능한지 확인하세요.

권한 취소, 구글 계정 보안 변경, 비밀번호 변경, 또는 인증이 더 이상 유효하지 않은 경우처럼 다양한 변경 사항이 발생한 후에는 구글 연결에 재인증이 필요할 수 있어요.

이런 상황에 대한 자세한 내용은 [구글 캘린더 연동이 끊어지는 이유](https://hyperclass.gitbook.io/hyperclass-docs/support/solutions/articles/48001204159)를 참고하세요.

## **계정이 여전히 표시되지 않을 경우 구글 캘린더 재연동**

권한을 재연결해도 계정이 복구되지 않으면, 구글 캘린더를 완전히 재연동(reintegration)해야 할 수도 있어요. 재연동은 연결 상태를 새로 고치는 작업으로, 일반적인 Reconnect(재연결) 옵션으로 기존 인증을 복구할 수 없을 때 시도하는 다음 단계예요.

기존 연결을 제거하기 전에, 전용 재연동 안내 문서를 먼저 확인하여 적용되는 캘린더 및 동기화 동작 방식을 이해하세요.

현재 재연동 절차는 [사용자의 구글 캘린더 재연동 방법](https://hyperclass.gitbook.io/hyperclass-docs/support/solutions/articles/48001181302)을 참고하세요.

재연결 후:

- 
**캘린더 설정 > Connections**로 돌아가세요.

- 
올바른 구글 계정이 연결됨으로 표시되는지 확인하세요.

- 
원하는 구글 캘린더가 사용 가능한지 확인하세요.

- 
해당 Linked Calendar(연결된 캘린더) 및 Conflict Calendar(충돌 캘린더) 설정을 검토하세요.

- 
필요한 경우 캘린더 동기화를 테스트해서 연결이 정상적으로 작동하는지 확인하세요.

## **연결된 구글 계정 vs 연결된 캘린더**

구글 계정을 연결하는 것과, 동기화할 구글 캘린더를 선택하는 것은 캘린더 설정에서 서로 별개의 단계예요. 이 차이를 이해하면 문제가 구글 인증 때문인지, 아니면 특정 캘린더 설정 때문인지 파악하는 데 도움이 됩니다.

- 
연결된 구글 계정(Connected Google account): 하이퍼클래스가 사용자의 구글 캘린더 계정에 접근할 수 있도록 인증해요.

- 
연결된 캘린더(Linked Calendar): 해당 동기화 동작에 사용되는 외부 캘린더를 결정해요.

- 
충돌 캘린더(Conflict Calendar): 선택한 캘린더의 일정(바쁨 상태)을 참고하여 사용자의 예약 가능 시간을 판단하는 데 사용돼요.

Connections(연결)에 구글 계정이 정상적으로 표시되는데도 예상한 캘린더 동작이 나타나지 않는다면, 구글 계정을 반복해서 재연결하기보다는 Linked Calendar 및 Conflict Calendar 설정을 검토해보세요.

자세한 설정 방법은 [Linked Calendar 및 Conflict Calendar 설정하기](https://hyperclass.gitbook.io/hyperclass-docs/support/solutions/articles/155000002374)를 참고하세요.

## **자주 묻는 질문**

**Q: 구글 계정이 연결되어 있는데 왜 하이퍼클래스에서 원하는 위치에 표시되지 않나요?**

계정 재인증이 필요하거나, 필요한 구글 권한이 누락되었거나, 원하는 특정 구글 캘린더가 아직 해당 캘린더 설정에서 선택되지 않았을 수 있어요. 연결을 제거하기 전에 **캘린더 설정 > Connections**와 **설정 > Integrations > Google** 둘 다 확인해보세요.

**Q: 재연결할 때 동일한 구글 계정을 다시 선택해야 하나요?**

네. 기존 사용자의 구글 캘린더 연결을 복구하려면, 그 사용자가 하이퍼클래스와 함께 사용하려는 구글 계정을 선택하세요. 기존 연결에 재인증이 필요하다고 해서 다른 구글 계정을 선택할 필요는 없습니다.

**Q: 요청받은 구글 캘린더 권한을 모두 허용해야 하나요?**

계정을 인증하거나 재연결할 때는 구글 캘린더 연동에 필요한 권한을 허용해주세요. 필요한 권한이 누락되면 하이퍼클래스가 캘린더 정보에 정상적으로 접근하거나 동기화하지 못할 수 있어요.

**Q: 에이전시(Agency) 관리자가 "login as" 기능으로 다른 사용자의 구글 캘린더를 연결할 수 있나요?**

구글 계정은 반드시 해당 계정의 소유자가 직접 연결해야 해요. 사용자 본인이 자신의 구글 계정에 로그인하고 구글 인증 절차를 직접 완료해야 합니다.

**Q: 구글 계정은 연결되어 있는데 특정 구글 캘린더를 사용할 수 없다면 어떻게 하나요?**

해당 계정이 그 특정 구글 캘린더에 충분한 접근 권한을 가지고 있는지 확인하세요. 다른 구글 계정에서 공유받은 캘린더의 경우 특히 이 부분이 중요할 수 있어요. 추가 트러블슈팅은 [구글 캘린더 쓰기 권한 오류](https://hyperclass.gitbook.io/hyperclass-docs/support/solutions/articles/48001064575)를 참고하세요.

**Q: 구글 계정을 재연결해도 문제가 해결되지 않으면 어떻게 하나요?**

구글 캘린더 재연동 절차를 전체적으로 진행해보세요. 재연동 후에는 캘린더 설정 > Connections에서 계정을 확인하고 캘린더 동기화를 테스트해보세요.

**Q: 구글 계정을 연결하는 것과 Linked Calendar를 선택하는 것은 같은 작업인가요?**

아니요. 구글 계정 연결은 하이퍼클래스가 구글 캘린더에 접근할 수 있도록 인증하는 작업이고, Linked Calendar 설정은 해당 동기화 동작에 어떤 캘린더를 사용할지 결정하는 작업이에요.
