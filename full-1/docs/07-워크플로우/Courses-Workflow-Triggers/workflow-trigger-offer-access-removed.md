# 워크플로우 트리거 — Offer Access Removed(오퍼 접근 권한 제거됨)

**Offer Access Removed** 트리거는 연락처가 특정 오퍼를 이용할 수 있는 권한이 회수되면 워크플로우를 자동으로 시작해요. 이 문서에서는 트리거가 하는 일, 설정 방법, 활용 사례, 자주 묻는 질문을 안내해요.

## Offer Access Removed 트리거란?

**Offer Access Removed**(오퍼 접근 권한 제거됨) 트리거는 연락처의 특정 오퍼 접근 권한이 회수될 때 워크플로우를 시작해요. 이 트리거를 쓰면 연락처에게 안내 메시지를 보내거나, 연락처 정보를 업데이트하거나, 담당 팀에 알리는 후속 작업을 자동으로 처리할 수 있어요. 반복 업무를 줄이고 고객과의 소통도 더 원활하게 할 수 있어요.

## 이 트리거의 장점

- 자동 알림: 접근 권한이 회수되면 연락처와 내부 팀에 바로 알려서 모두가 상황을 알 수 있어요.
- 워크플로우 효율 향상: 연락처 정보 업데이트나 이메일 발송 같은 반복 작업을 자동화해 시간을 아끼고 실수를 줄여요.
- 고객 경험 개선: 접근 권한이 회수된 뒤 연락처에게 상황과 다음 단계를 분명하게 안내해 신뢰를 유지해요.
- 운영 효율화: 자격이 있는 연락처만 특정 오퍼에 대한 접근 권한을 유지하도록 효율적으로 관리해요.
- 맞춤 필터: 필터로 특정 오퍼만 골라 정확하게 자동화할 수 있어요.

## 트리거 설정 방법

### 워크플로우 열기

1. 왼쪽 메뉴에서 **자동화 > 워크플로우**로 이동해요.
2. 새 워크플로우를 처음부터 만들거나, **Offer Access Removed** 트리거를 넣을 기존 워크플로우를 선택해요.

### 새 트리거 추가하기

1. **+ Add New Trigger**(새 트리거 추가)를 클릭해요.
2. 드롭다운 메뉴에서 **Offer Access Removed**를 선택해요.

### 트리거 이름 정하기

트리거 이름을 알아보기 쉽게 입력해요. 예를 들어 "15% 할인 접근 권한 회수"처럼 쓸 수 있어요.

![트리거 이름을 입력하는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155038864757/original/qt6xI_t_fnA3vwwI6rblM3JR_f6Pi0PKlA.png?1735053406)

### 필터 설정하기

**Filters**(필터)로 워크플로우가 시작되는 조건을 좁혀요.

**Offer**(오퍼)에서 접근 권한이 회수될 때 워크플로우를 시작할 특정 오퍼를 선택해요. 예를 들어 "얼리버드 할인"을 선택할 수 있어요.

![Offer 필터에서 오퍼를 선택하는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155038864790/original/pnS-1ClRSqZeDWkKQEFhJ7rsDyIs0wD6-A.png?1735053438)

### 트리거 저장하기

**Save Trigger**(트리거 저장) 버튼을 눌러 트리거를 저장해요.

### 테스트하고 게시하기

1. 샘플 데이터로 워크플로우를 테스트해서 의도대로 동작하는지 확인해요.
2. 확인이 끝나면 **Publish**(게시) 토글을 켜서 워크플로우를 활성화해요.

## 사용 사례

### 할인 접근 권한 회수 안내 이메일

- 시나리오: 고객의 프로모션 할인 접근 권한이 회수되어 고객에게 알려야 해요.
- 트리거 설정
  - 트리거: **Offer Access Removed**
- 필터
  - **Offer**: "15% 얼리버드 할인"
- 결과: 접근 권한이 회수되었다는 사실과 함께 다른 오퍼나 다음 단계를 안내하는 이메일을 워크플로우가 보내요.

### 멤버십 담당 팀 내부 알림

- 시나리오: 연락처의 프리미엄 멤버십 접근 권한이 제거되어 고객 지원팀이 후속 연락을 해야 해요.
- 트리거 설정
  - 트리거: **Offer Access Removed**
- 필터
  - **Offer**: "프리미엄 멤버십"
- 결과: 워크플로우가 지원팀에 알려서, 지원팀이 연락처에게 갱신 옵션을 안내할 수 있어요.

### 접근 권한 추적을 위한 연락처 정보 업데이트

- 시나리오: 기간 한정 오퍼의 접근 권한이 회수되어, 정확한 추적을 위해 연락처 프로필을 업데이트해야 해요.
- 트리거 설정
  - 트리거: **Offer Access Removed**
- 필터
  - **Offer**: "여름 한정 특가"
- 결과: 워크플로우가 연락처 정보에 권한 제거 사실을 반영하고, 리포팅에 쓸 수 있도록 연락처에 태그를 추가해요.

## 자주 묻는 질문

### 한 워크플로우에서 여러 오퍼를 처리할 수 있나요?

네, 필터를 더 추가하거나 조건을 넓게 설정하면 여러 오퍼에 대해 워크플로우가 시작되도록 구성할 수 있어요.

### 같은 오퍼의 접근 권한이 한 연락처에게 여러 번 회수되면 어떻게 되나요?

접근 권한이 제거될 때마다 트리거가 실행돼요. 같은 작업이 중복해서 실행되지 않도록 워크플로우에 조건을 넣어 설계하세요.

### 워크플로우가 올바른 오퍼를 대상으로 하는지 어떻게 확인하나요?

**Offer** 필터로 정확한 오퍼를 지정하세요. 그런 다음 샘플 데이터로 워크플로우를 테스트해서 의도대로 시작되는지 확인하세요.

### 이 트리거를 다른 트리거와 함께 쓸 수 있나요?

네, **Offer Access Removed** 트리거는 **Tag Added**(태그 추가됨)나 **Opportunity Status Changed**(기회 상태 변경됨) 같은 다른 트리거와 함께 쓸 수 있어요. 이렇게 하면 더 정교한 워크플로우를 만들 수 있어요.
