# 워크플로우 트리거 — User Replied(사용자 답장)

**User Replied**(사용자 답장) 트리거는 팀 구성원이 연락처에게 메시지를 보낼 때마다 실행돼요. 팀의 응답 속도를 재거나, 담당자가 직접 나서면 자동화를 멈추거나, 발신 활동을 기록하거나, 누가 어디서 답장했는지에 따라 대화를 나눌 때 쓸 수 있어요. 이 문서에서는 워크플로우에서 이 트리거를 설정하고 활용하는 방법을 안내해요.

## User Replied 트리거란?

팀원이 대화 화면에서 연락처에게 메시지를 보내면 워크플로우가 시작돼요. 답장과 응답 활동을 기준으로 만들어졌고, 사용자가 보내는 두 가지 메시지에서 실행돼요.

- 새 발신 메시지: 사용자가 연락처에게 처음 메시지를 보내는 경우예요. 예를 들어 연락처가 폼으로 들어오고 담당자가 먼저 연락할 때가 여기에 해당해요.
- 기존 대화에 대한 답장: 연락처가 먼저 메시지를 보냈고, 사용자가 그 대화 안에서 답하는 경우예요.

{% hint style="warning" %}
이 트리거는 사용자가 대화 화면에서 보낸 메시지에서만 실행돼요. 또 메시지를 보낸 순간이 아니라 메시지가 전달된 뒤에 실행돼요. 워크플로우 액션(**Send SMS**, **Send Email** 등)이나 대화 AI가 보낸 메시지에서는 실행되지 않아요. 대화 AI를 기준으로 자동화하려면 별도의 **Conversation AI**(대화 AI) 트리거를 쓰세요. 이 트리거는 특정 메시지가 아니라 직접 정한 조건에서 실행돼요.
{% endhint %}

## 이 트리거를 쓰면 좋은 점

- 응답 시간 측정: 담당자가 연락처에게 답한 시점을 기록해서 팀이 얼마나 빨리 답하는지 확인할 수 있어요.
- 사람이 나서면 자동화 중단: 팀원이 직접 답장하는 즉시 드립이나 너처링 시퀀스를 끝낼 수 있어요. 연락처가 자동 메시지와 사람이 보낸 메시지를 동시에 받는 일이 없어져요.
- "기다렸다가 확인하는" 흐름 만들기: 이 트리거를 **Wait**(대기) 단계의 **User Replied** 조건과 함께 쓰면 돼요. 연락처가 메시지를 보내면 몇 분 기다렸다가, 아무도 답하지 않았을 때 담당자에게 알리는 흔한 패턴을 만들 수 있어요.
- 누가, 어디서 답했는지에 따라 분기: 메시지를 보낸 사용자, 연락처에 배정된 사용자, 메시지가 나간 채널을 기준으로 워크플로우를 나눌 수 있어요.
- 메시지 내용에 따라 실행: 담당자의 메시지에 "환불 승인" 같은 문구가 들어 있으면 기회를 옮기거나, 확인 메시지를 보내거나, 태그를 붙일 수 있어요.
- 활동 기록: 모든 발신 답장을 기록하거나 "마지막 연락 담당자", "마지막 연락 날짜" 같은 필드를 최신 상태로 유지할 수 있어요.

## 워크플로우에서 User Replied 트리거 설정하기

1. 계정에 로그인하세요.
2. **자동화 > 워크플로우**로 이동하세요.
3. 새 워크플로우를 만들거나 기존 워크플로우를 여세요.
4. **+ Add New Trigger**(새 트리거 추가)를 클릭하고, 목록의 **Events**(이벤트) 아래에서 **User Replied**를 선택하세요.

   ![User Replied 트리거를 선택하는 화면](https://jumpshare.com/share/1fHp8adcptdb0ypSPekL+/GIF+Recording+2026-07-10+at+20.29.33.gif)

5. **Trigger Name**(트리거 이름)에 나중에 쉽게 찾을 수 있는 이름을 입력하세요. 예: "담당자 답장 (SLA 타이머)"
6. **+ Add Filters**(필터 추가)를 클릭해서 워크플로우가 실행될 조건을 좁히세요. 필터를 추가하지 않으면 모든 연락처, 모든 채널에서 사용자가 답장할 때마다 트리거가 실행돼요.
7. **Save Trigger**(트리거 저장)를 클릭하세요.
8. **Add Tag**(태그 추가), **Send Email/SMS**(이메일/SMS 보내기), **Assign to User**(사용자에게 배정), **Send Internal Notification**(내부 알림 보내기), **Update Opportunity**(기회 업데이트) 같은 액션을 추가한 뒤 **Publish**(게시)를 클릭하세요.

   ![액션을 추가하고 워크플로우를 게시하는 화면](https://jumpshare.com/share/eLWFJFDk9rjFbG13oaXN+/GIF+Recording+2026-07-10+at+21.38.48.gif)

## 트리거 필터

필터로 어떤 사용자 답장에서 워크플로우를 시작할지 정할 수 있어요. 여러 필터를 함께 쓰면 조건을 더 구체적으로 만들 수 있어요.

| 필터 | 연산자 | 값 | 설명 |
| --- | --- | --- | --- |
| **Sent By**(보낸 사람) | Is any of(다음 중 하나) | 그룹형 사용자 선택(아래 참고) | 여러 개를 선택할 수 있어요. 연락처에 배정된 사용자나 특정 사용자를 고르세요. |
| **Message Channel**(메시지 채널) | Is any of(다음 중 하나) | SMS, Email, WhatsApp, Facebook Messenger, Instagram DM, Live Chat | 일치시킬 채널을 하나 이상 선택하세요. 일부 채널은 채널별 추가 옵션이 있어요. |
| **Contains Phrase**(문구 포함) | Contains(포함) | 자유 입력(대소문자 구분 안 함) | 메시지에 지정한 단어나 문구가 들어 있을 때만 실행돼요. 쉼표로 구분해 여러 문구를 입력할 수 있어요. |
| **Exact Match Phrase**(문구 정확히 일치) | Equals(같음) | 자유 입력(대소문자 구분 안 함) | 메시지가 입력한 문구와 정확히 같을 때만 실행돼요. 비교하기 전에 공백은 제거돼요. |
| **Has Tag**(태그 있음) | Has any of(다음 중 하나 보유) | 태그 선택 | 연락처에게 선택한 태그가 있을 때만 실행돼요. |
| **Doesn't Have Tag**(태그 없음) | Has none of(다음 중 어느 것도 없음) | 태그 선택 | 연락처에게 선택한 태그가 없을 때만 실행돼요. |

#### Replied By: 그룹형 사용자 선택

<!-- 검토 필요: 원문 내용이 서로 다름 (필터 표와 FAQ에는 Sent By, 이 섹션에는 Replied By로 표기) -->
**Replied By**(답장한 사람) 필터는 검색할 수 있고 여러 개를 고를 수 있는 드롭다운이에요. 선택지는 두 종류예요.

- **User assigned to the Contact**(연락처에 배정된 사용자): 이 동적 옵션은 항상 맨 위에 있어요. 연락처에 배정된 사용자가 답장할 때만 트리거를 실행하고 싶을 때 쓰세요.
- **Users**(사용자): 선택할 수 있는 모든 사용자가 이름순으로 나와요.

{% hint style="info" %}
**Replied By** 필터를 추가하지 않으면 어떤 사용자가 답장해도 트리거가 실행돼요.
{% endhint %}

![Replied By 필터의 그룹형 사용자 선택 드롭다운](https://jumpshare.com/share/9No5ot74hueMwhSbLob9+/Screen+Shot+2026-07-10+at+21.45.31.png)

## 채널별 동작

이 트리거는 주요 대화 채널 전체에서 작동해요. 채널마다 대화를 묶는 방식이 조금씩 달라서, 무엇이 새 발신 메시지이고 무엇이 답장인지는 채널에 따라 달라질 수 있어요. 아래 표에서 채널별 동작을 확인하세요.

| 채널 | 새 발신 메시지 | 기존 대화에 대한 답장 |
| --- | --- | --- |
| Email | 사용자가 새 이메일을 써요. 새 제목으로 보내면 새 스레드가 시작돼요. | 사용자가 기존 이메일 스레드 안에서 답장해요. |
| SMS | 이전 메시지가 없는 연락처에게 처음 보내는 SMS예요. | 진행 중인 스레드에서 이후에 보내는 모든 SMS예요. |
| WhatsApp | 24시간 창 밖에서 사용자가 템플릿 메시지로 시작해요. | 사용자가 24시간 서비스 창 안에서 답장해요. |
| Facebook Messenger | 이전 대화가 없는 연락처에게 처음 보내는 메시지예요. | 진행 중인 스레드에서 이후에 보내는 모든 메시지예요. |
| Instagram DM | 이전 대화가 없는 연락처에게 처음 보내는 DM이에요. | 진행 중인 스레드에서 이후에 보내는 모든 DM이에요. |
| Live Chat | 해당 없음. 방문자가 항상 세션을 먼저 시작해요. | 사용자가 진행 중인 세션 안에서 답장해요. |

Email은 한 연락처와 여러 개의 별도 스레드를 동시에 이어 갈 수 있는 유일한 채널이에요. SMS, Messenger, Instagram DM처럼 스레드가 하나뿐인 채널에서는 모든 메시지가 하나의 대화에 계속 쌓여요.

## 커스텀 값

이 트리거는 워크플로우 액션과 If/Else 조건에서 쓸 수 있는 값을 제공해요. 알림을 개인화하거나 활동을 기록하거나 대화를 나눌 때 활용하세요.

| 이름 | 커스텀 값 | 설명 |
| --- | --- | --- |
| **User Name**(사용자 이름) | `{{user_replied.senderName}}` | 메시지를 보낸 사용자의 이름 |
| **User ID**(사용자 ID) | `{{user_replied.userId}}` | 보낸 사용자의 내부 사용자 ID예요. 외부 연동에서는 이름보다 더 안정적이에요. |
| **Message Body**(메시지 본문) | `{{user_replied.messageBody}}` | 메시지 내용 |
| **Channel**(채널) | `{{user_replied.channel}}` | 메시지를 보낸 채널(SMS, Email, WhatsApp 등) |
| **Timestamp**(타임스탬프) | `{{user_replied.timeStamp}}` | 메시지를 보낸 시각 |
| **Conversation ID**(대화 ID) | `{{user_replied.conversationId}}` | 대화 또는 스레드 ID |
| **User Email**(사용자 이메일) | `{{user_replied.senderEmail}}` | 메시지를 보낸 사용자의 이메일 주소 |

## 사용 사례

키워드 기반 분기

- 트리거: **User Replied**
- 필터: **Contains Phrase**를 "환불 승인"으로 설정
- 액션: 기회를 새 파이프라인 단계로 옮기고 확인 메시지를 보내요.

발신 활동 기록

- 트리거: **User Replied**
- 액션: "마지막 연락 담당자"를 `{{user_replied.senderName}}`으로, "마지막 연락 날짜"를 `{{user_replied.timeStamp}}`로 업데이트해요. 또는 답장 내용을 플랫폼 밖 다른 곳에 기록해요.

## SLA 추적과 에스컬레이션 설정하기

이 이벤트를 쓰는 가장 흔한 이유는 응답 시간 SLA예요. 담당자가 목표 시간 안에 답장하는지 확인하고, 답하지 않으면 에스컬레이션하려면 트리거 하나만 쓰지 않고 User Replied 이벤트를 **Wait** 조건과 **Goal**(목표)로 구성해요.

구성 방식은 다음과 같아요.

1. 시간 측정을 시작하는 이벤트로 워크플로우를 시작하세요. 예를 들어 [**Customer Replied**(연락처 답장)](workflow-trigger-customer-replied.md)를 쓰면 연락처가 메시지를 보낼 때 워크플로우가 실행돼요.
2. **Wait** 단계를 추가하고 **User Replied** 조건으로 설정하세요. 제한 시간은 5분처럼 정하세요.
3. 제한 시간 안에 아무도 답하지 않은 분기에 에스컬레이션 액션을 추가하세요. 예를 들어 담당자나 매니저에게 알리거나, 작업을 만들거나, 내부 알림을 보낼 수 있어요.
4. 담당자가 답장하는 즉시 리마인더나 너처링 시퀀스를 멈추려면 **User Replied** 목표(**Goal**)를 추가하세요. 연락처가 남은 단계를 건너뛰고 빠져나와요.

{% hint style="info" %}
**Wait** 조건과 **Goal**은 각각 별도의 단계에서 설정해요. 전체 설정 방법은 [워크플로우 액션 — Wait(대기)](../Internal-Tools-Workflow-Actions/workflow-action-wait.md)와 [워크플로우 액션 — Goal Event(목표 이벤트)](../액션/workflow-action-goal-event.md) 문서를 참고하세요.
{% endhint %}

## 자주 묻는 질문

### 워크플로우가 보낸 메시지에도 이 트리거가 실행되나요?

아니요. **Send SMS**, **Send Email** 같은 워크플로우 액션이 보낸 자동 메시지에서는 실행되지 않아요. 사용자가 대화 화면에서 직접 보낸 메시지만 해당돼요.

### 콜드 아웃리치나 대량 발송에서도 실행되나요?

안정적으로 실행되지는 않아요. 이 트리거는 답장과 응답을 기준으로 만들어졌고, 처음 연락하는 콜드 아웃리치용이 아니에요.

### 연락처에 배정된 사용자가 답장할 때만 실행할 수 있나요?

네. **Sent By** 필터를 추가하고 **User assigned to the Contact**(연락처에 배정된 사용자)를 선택하세요.

### 사용자가 메시지를 빠르게 여러 개 보내면 어떻게 되나요?

메시지마다 트리거가 각각 실행돼요. 단, 워크플로우에서 재등록을 제한해 두었다면 그렇지 않아요.

### 연락처가 워크플로우 여러 개에 등록되어 있으면 어떻게 되나요?

트리거가 각 워크플로우에서 독립적으로 실행돼요.
