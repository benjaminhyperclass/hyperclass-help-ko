# 워크플로우 트리거 — Form Submitted(폼 제출)

**Form Submitted**(폼 제출) 트리거는 지정한 폼이 제출될 때 워크플로우를 자동으로 시작해요. 이 문서에서는 트리거가 하는 일과 설정 방법, 활용 사례, 자주 묻는 질문을 안내해요.

## Form Submitted 트리거란?

지정한 폼이 제출되면 **Form Submitted** 트리거가 실행되고, 이어서 자동화 작업이 진행돼요. 데이터 수집, 알림 발송, 레코드 업데이트, 후속 작업 생성 같은 일을 자동으로 처리할 수 있어요. 폼 제출에 빠르게 대응하고 효율적으로 처리할 수 있어서 고객 응대와 내부 업무 관리에 꼭 필요한 트리거예요.

## 주요 장점

- 업무 효율 향상: 폼 제출로 시작되는 반복 업무를 자동으로 처리해서 시간과 수작업을 줄여 줘요.
- 커뮤니케이션 개선: 고객에게 자동으로 응답하고, 팀원에게는 후속 조치를 위한 내부 알림을 보내요.
- 데이터 정확도: 제출된 폼 데이터가 하이퍼클래스에 바로 반영되어 최신 기록을 정확하게 유지할 수 있어요.
- 맞춤형 워크플로우: 필터를 설정해 특정 폼이나 제출 조건에만 맞는 작업을 실행할 수 있어요.
- 확장성: 여러 워크플로우를 함께 운영할 수 있어서 폼 제출이 많아도 무리 없이 처리할 수 있어요.

## 트리거 설정하기

다음 단계를 따라 워크플로우에 폼 제출 트리거를 추가하세요.

1. 왼쪽 메뉴에서 **자동화 > 워크플로우**로 이동해요.
2. 새 워크플로우를 처음부터 만들거나, **Form Submitted** 트리거를 추가할 기존 워크플로우를 선택해요.
3. **Add New Trigger**(새 트리거 추가)를 클릭하고, 드롭다운 메뉴에서 **Form Submitted**를 선택해요.

   ![트리거 목록에서 Form Submitted 선택](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155039463070/original/9PRqjo-q1aQp-Hf1yPsWxa_kivz5xiU4JQ.png?1736332197)

4. 트리거 이름을 알아보기 쉽게 입력해요. 예를 들어 "고객 피드백 폼 제출"처럼 쓰면 돼요.

   ![트리거 이름 입력](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155039463134/original/Qe9odJyYHDOjHhnmsv93-PJjT0loq3HJMg.png?1736332229)

5. 필터를 설정해서 워크플로우가 시작되는 조건을 좁혀요. **Form Is**(폼 지정) 필터에서 워크플로우를 시작할 폼을 지정하세요. 예를 들어 폼 목록에서 "고객 피드백 폼"을 선택해요.

   ![Form Is 필터에서 폼 선택](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155039463171/original/ApmXW_y7okXwmzDDI-6eFI23BASDiiU5DQ.png?1736332250)

6. **Save Trigger**(트리거 저장) 버튼을 클릭해서 설정을 저장해요.
7. 샘플 데이터로 워크플로우를 테스트해서 제대로 작동하는지 확인해요.
8. 확인이 끝나면 **Publish**(게시) 토글을 켜서 워크플로우를 활성화해요.

## 사용 사례

### 고객 정보 수집

시나리오: 온라인 폼으로 고객 정보를 받고, 이를 자동으로 관리하고 싶어요.

트리거 설정:

- 트리거: **Form Submitted**
- 필터: **Form Is** "고객 정보 폼"

결과: 제출된 데이터가 하이퍼클래스에 입력되고, 영업팀에 알림이 가며, 후속 작업이 만들어져요.

![고객 정보 수집 워크플로우 예시](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155039463388/original/51-7JIAcJBNjvbAtjO7MENaaSjvietsngw.png?1736332327)

### 리드 자격 검증

시나리오: 마케팅팀이 폼 제출로 리드를 모으고, 자동으로 자격을 검증하고 싶어요.

트리거 설정:

- 트리거: **Form Submitted**
- 필터: **Form Is** "리드 수집 폼"

결과: 워크플로우가 리드 점수를 매기고, 리드 상세 정보로 하이퍼클래스를 업데이트하며, 영업팀에 다음 조치를 알려요.

### 이벤트 등록 관리

시나리오: 이벤트 주최자가 폼으로 참석자를 등록받고, 안내 과정을 자동화하고 싶어요.

트리거 설정:

- 트리거: **Form Submitted**
- 필터: **Form Is** "이벤트 등록 폼"

결과: 등록한 사람에게 확인 이메일이 발송되고, 등록자의 정보가 하이퍼클래스의 참석자 목록에 추가돼요.

### 고객 피드백 수집

시나리오: 온라인 폼으로 고객 피드백을 받고, 응답을 분석하고 싶어요.

트리거 설정:

- 트리거: **Form Submitted**
- 필터: **Form Is** "고객 피드백 폼"

결과: 워크플로우가 고객에게 감사 이메일을 보내고, 응답 내용을 분석용 피드백 데이터베이스에 추가해요.

### 예약 신청 알림

시나리오: 의료 기관이 폼으로 예약 신청을 받고, 담당 팀에 알리고 싶어요.

트리거 설정:

- 트리거: **Form Submitted**
- 필터: **Form Is** "예약 신청 폼"

결과: 워크플로우가 일정 담당 팀에 알리고, 예약 캘린더를 업데이트하며, 환자에게 확인 이메일을 보내요.

## 자주 묻는 질문

### 한 워크플로우에서 여러 폼을 처리할 수 있나요?

네, 가능해요. 필터를 더 추가하거나 조건을 더 넓게 설정하면 여러 폼에서 워크플로우가 시작되도록 구성할 수 있어요.

### 같은 사용자가 폼을 여러 번 제출하면 어떻게 되나요?

폼이 제출될 때마다 트리거가 실행돼요. 중복 제출은 워크플로우의 조건이나 쿨다운 기간(재실행 대기 시간)을 활용해서 관리하세요.

### 응답 이메일에 폼 제출 데이터를 넣으려면 어떻게 하나요?

이메일 단계에서 연락처 머지 태그와 커스텀 필드 머지 태그를 쓰면 제출된 폼 데이터를 가져올 수 있어요. 예를 들어 폼에서 이름, 이메일, 피드백을 받는다면 `{{contact.name}}`, `{{contact.email}}` 같은 머지 필드나 폼에 연결된 커스텀 필드를 이메일 본문에 넣으세요. 이메일이 발송될 때 이 자리에 폼으로 제출된 실제 데이터가 자동으로 채워져요.

### 필수 정보가 빠진 폼 제출은 어떻게 처리하나요?

워크플로우 안에 조건을 추가해서 필수 항목을 확인하고, 알림을 보내거나 불완전한 제출을 건너뛰는 등 원하는 작업을 지정할 수 있어요.

### 외부 폼 도구에서도 이 트리거를 쓸 수 있나요?

**Form Submitted** 트리거는 하이퍼클래스 안에서 만든 폼에서 작동해요. 외부 도구의 제출 내용을 가져오려면 연동이나 웹훅이 필요할 수 있어요.
