# 워크플로우 액션 — AI Agent(AI 에이전트)

**AI Agent**(AI 에이전트) 액션은 하이퍼클래스 워크플로우에서 여러 단계로 이어지는 작업을 자동으로 처리해요. 안내문(지침)과 사용할 도구만 정해 두면 에이전트가 무엇을 할지, 어떤 도구를 쓸지, 어떤 값을 넣을지 실행 중에 스스로 결정해요. 이 문서에서는 액션의 동작 방식, 설정 방법, 실행 결과를 확인하는 방법을 설명해요.

## 워크플로우의 AI Agent 액션이란?

**AI Agent**는 워크플로우에서 쓰는 AI 액션이에요. 사용자가 쓴 지침과 허용한 도구를 바탕으로 작업을 계획하고 스스로 실행해요. 상황에 따라 유연하게 판단해야 하거나, 도구를 상황에 맞게 골라 써야 하거나, 여러 작업을 차례로 처리해야 할 때 유용해요. 단계마다 액션을 직접 만들 필요가 없어요.

예를 들어 연락처 찾기, 예약 링크 만들기, 날짜 형식 맞추기, 후속 메시지 보내기를 각각 별도의 워크플로우 액션으로 만드는 대신, AI Agent 액션 하나로 전체 과정을 처리할 수 있어요.

---

## AI Agent 워크플로우 액션의 장점

- 자율 실행: 지침을 바탕으로 에이전트가 어떤 도구를 어떤 순서로, 어떤 값으로 쓸지 직접 정해요.
- 빠른 워크플로우 제작: 지원되는 사용 사례에서는 AI Agent 액션 하나가 직접 설정하던 여러 워크플로우 단계를 대신할 수 있어요.
- 유연한 설정: 처음부터 만들 수도 있고, 템플릿으로 시작해서 필요에 맞게 바꿀 수도 있어요.
- 이후 워크플로우 단계 지원: 에이전트가 텍스트 또는 JSON 출력을 돌려주면 뒤따르는 워크플로우 단계에서 쓸 수 있어요.
- 기본 제공 가시성: **Execution Logs**(실행 로그)에서 에이전트의 추론 단계, 도구 사용 내역, 토큰 사용량을 확인할 수 있어요.

## AI Agent 액션 상세 설정

아래 설정으로 AI Agent의 동작 방식을 정해요. 액션을 제대로 설정하는 데 필요한 핵심 항목이에요.

- **Action Name**(액션 이름): 액션에 붙일 이름을 입력해요. 기본 이름은 **AI Agent**예요. 용도에 맞게 이름을 바꿔 두면 워크플로우를 관리하기 쉬워요.
- **Template**(템플릿): 미리 만들어진 템플릿을 고르면 **Instructions**(안내)와 **Tools**(도구) 항목이 자동으로 채워져요. 처음부터 시작하려면 **Build Your Own**(직접 만들기)을 선택하세요. 일부 템플릿은 특정 워크플로우 트리거가 있어야 해요.
- **Instructions**: 에이전트가 무엇을 해야 하는지, 어떻게 판단해야 하는지, 어떤 규칙을 따라야 하는지 적어요. 설정에서 가장 중요한 부분이에요.
- **Enhance Prompt**(프롬프트 개선): 대충 쓴 지침을 더 자세하고 체계적인 프롬프트로 정리해 줘요. 필요하면 개선한 내용을 되돌릴 수 있어요.
- **Model**(모델): 에이전트를 움직이는 AI 모델을 선택해요.
- **Tools**: 에이전트가 실행할 수 있는 액션을 고르는 항목이에요.
- **Conversation Memory**(대화 메모리): 이 단계에서 같은 연락처로 실행했던 이전 기록을 요약해서 이어 가며 사용해요. 에이전트가 맥락을 알고 움직일 수 있어요.
- **Output Format**(출력 형식): 에이전트가 응답을 어떤 형식으로 정리할지 선택해요.

## 모델과 Effort 수준 선택하기

**Model** 드롭다운에서 작업에 가장 잘 맞는 AI 제공업체와 모델을 선택해요. 모델은 Anthropic, Google, OpenAI 같은 제공업체별로 묶여 있어요.

각 모델에는 어떤 용도에 맞는지 알려 주는 짧은 설명이 있어요. 추론을 지원하는 모델에는 thinking 칩이 함께 표시돼요.

지원되는 모델에서는 **Low**(낮음), **Medium**(미디엄), **High**(높음) 중에서 **Effort**(추론 강도) 수준을 고를 수 있어요.

단순한 작업에는 낮은 수준을, 복잡한 작업처럼 더 깊은 추론이 필요할 때는 높은 수준을 선택하세요.

- **Low**: 단순한 작업에서 더 빠른 응답을 우선해요.
- **Medium**: 선택할 수 있는 Effort 옵션이에요.
- **High**: 더 복잡한 작업을 위해 깊이 있게 추론해요.

**OpenAI GPT-6 모델**

OpenAI의 GPT-6 Sol과 GPT-6 Luna 모델을 **Model** 드롭다운에서 선택할 수 있어요.

- GPT-6 Sol: 깊은 추론이 필요한 복잡한 다단계 작업과 워크플로우에 사용해요.
- GPT-6 Luna: 분류, 요약, 태그 지정, 빠른 답장처럼 빠르게 많이 처리해야 하는 작업에 사용해요.

워크플로우의 복잡도와 처리량에 가장 잘 맞는 모델을 고르세요.

## 템플릿

템플릿은 특정 워크플로우 상황에 자주 쓰는 지침과 도구를 미리 채워 줘서 더 빠르게 시작할 수 있게 해요. 이미 알려진 사용 사례에 맞는 출발점이 필요할 때 유용하고, 이후 비즈니스에 맞게 바꿔 쓰면 돼요.

템플릿은 **Instructions**와 **Tools** 항목을 채워 주는, 미리 만들어진 에이전트 설정이에요. 템플릿에 필요한 트리거가 워크플로우에 아직 없으면 해당 트리거를 추가하기 전까지 템플릿을 사용할 수 없는 상태로 표시돼요.

**제공되는 템플릿**

- **Build Your Own**(직접 만들기): 빈 에이전트로 시작해서 지침과 도구를 모두 직접 정해요.
- **Form Lead Follow Up**(폼 리드 후속 조치): 새 폼 리드에게 감사 인사를 보내고, 담당자를 지정하고, 기회를 만들어요. 첫 접점으로 예약 링크가 담긴 개인 맞춤 SMS와 이메일을 보내요.
- **No Show Appointment Recovery**(노쇼 예약 회복): 노쇼 후 첫 접점으로 새 재예약 링크가 담긴 개인 맞춤 SMS와 이메일을 동시에 보내요. 죄책감을 주거나 놓친 예약을 지적하지 않아요.
- **Facebook Lead Nurturing**(Facebook 리드 육성): 유입된 Facebook 리드에게 몇 분 안에 접근해요. 담당자를 지정하고, 연락처 정보를 보강하고, 기회를 만들고, 예약 링크가 담긴 SMS를 먼저 보내요.
- **Stale Deal Nudge Agent**(오래된 딜 알림 에이전트): 딜 금액과 단계를 평가해요. 가치가 높은 기회에는 이메일 + SMS + 담당자 알림 + 작업을 보내고, 일반 딜에는 가벼운 SMS와 알림만 보내요.
- **Lead Research & Enrichment**(리드 조사 및 정보 보강): 인터넷 검색으로 새 연락처와 소속 회사를 조사해요. 조사 결과로 CRM 필드를 채우고, 리드 점수를 매기고, ICP 기준에 맞으면 기회를 만들어요.
- **New Appointment: Enrich & Confirm**(새 예약: 정보 보강 및 확인): CRM 데이터로 연락처 정보를 보강하고, 따뜻한 확인 SMS와 이메일을 보내요. 담당자를 위한 미팅 전 조사 요약을 만들고, 기회 생성을 처리하고, 담당자 배정이 맞지 않으면 표시해 줘요.
- **Quiz Lead Scoring & Routing**(퀴즈 리드 점수 및 배정): 퀴즈 점수를 읽어 리드를 핫, 웜, 콜드로 분류해요. 프로필을 업데이트하고 팀에 내부 알림을 보내요. 연락처에게는 메시지를 보내지 않아요.
- **Call Transcript Summary & Action Items**(통화 녹취록 요약 및 할 일): 통화를 요약하고 할 일을 뽑아요. 모든 내용을 연락처 메모로 기록하고, 담당자의 작업을 만들고, 요약 알림을 보내요.
- **Task Creation from Won Deals**(고객전환성공 딜의 작업 생성): 기회가 고객전환성공으로 바뀌면 ClickUp이나 Asana에 이행 또는 온보딩 작업을 만들어요. 팀에 알리고, 기회에 온보딩 표시를 업데이트해요.
- **Instagram / Facebook Comment-to-DM**(Instagram / Facebook 댓글→DM): 댓글 내용에 맞춰 개인 맞춤 DM을 보내서 연락처를 예약, 구매 또는 다음 단계로 안내해요.
- **Lead Pipeline Tracker**(리드 파이프라인 추적): 파이프라인 단계를 따라 리드를 주기적으로 확인해요. Conversation Memory로 이전 연락 내용을 기억해서 같은 메시지를 반복하지 않아요.

## 지침 작성하기

지침이 좋을수록 에이전트가 더 나은 판단을 하고, 도구를 올바르게 쓰고, 더 믿을 만한 결과를 내요. 안내가 명확할수록 에이전트가 의도한 대로 작업을 수행하기 쉬워요.

**Instructions** 항목은 에이전트가 무엇을 하는지, 어떻게 추론하는지, 제공된 도구를 어떻게 쓰는지 정해요. 작업의 복잡도에 따라 지침을 간단하게 쓰거나 더 자세히 쓸 수 있어요.

좋은 지침에는 보통 다음 내용이 들어가요.

- 역할 설명
- 사용할 수 있는 트리거 데이터에 대한 설명
- 단계별 작업 순서
- if/then 규칙으로 쓴 판단 기준
- 메시지 작성 가이드
- 에이전트가 하지 말아야 할 일에 대한 규칙이나 제약

프롬프트를 어떻게 구성할지 잘 모르겠다면 지침을 일상적인 말로 먼저 적고, **Enhance Prompt**를 눌러 정리하세요.

편집기는 제목, 굵게, 글머리 기호 목록, 번호 목록, 코드 블록, 인용 블록 같은 서식도 지원해요.

## 도구 설정하기

도구는 에이전트가 실행 중에 할 수 있는 일을 정해요. 에이전트에게 알맞은 도구를 주고 어떤 필드를 에이전트가 정할지 선택하면, 유연성과 예측 가능성의 균형을 맞출 수 있어요.

**+ Add Tool**(도구 추가)을 클릭하면 도구 선택 창이 열려요. 도구는 카테고리별로 정리되어 있고 이름으로 검색할 수도 있어요. 선택한 도구는 설정 패널에 나타나고, 도구마다 따로 설정할 수 있어요.

도구를 설정할 때 필드 값을 채우는 방식을 고를 수 있어요.

- **Let AI decide all field values**(AI가 모든 필드 값 결정)를 **ON**으로 두면, 에이전트가 지침과 워크플로우 데이터를 바탕으로 실행할 때 모든 필드의 값을 만들어요.
- **Let AI decide all field values**를 **OFF**로 두면, 일부 값은 직접 입력하고 비어 있는 나머지 필드는 에이전트가 채우게 할 수 있어요.

필드마다 개별 토글도 있어서, 필드별로 AI가 만든 값과 직접 설정한 값 중에서 고를 수 있어요.

### Search Knowledge Base(지식 베이스 검색) 도구

**Search Knowledge Base**를 쓰면 AI Agent가 실행 중에 하이퍼클래스 지식 베이스에서 필요한 비즈니스 정보를 찾아와요. 긴 FAQ 목록이나 비즈니스 정보를 **Instructions**에 붙여 넣지 않아도 돼요.

주로 이런 경우에 써요.

1. 서비스 세부 정보, 가격, 제공 상품
2. 예약 규칙, 서비스 메뉴, 이용 가능 시간
3. FAQ와 정책 정보

#### 설정 방법

1. AI Agent 액션에서 **Add Tool**을 클릭해요.

2. **Search Knowledge Base**를 선택해요.

   ![도구 목록에서 Search Knowledge Base 선택](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155071932326/original/oqE_fkPLZKVlNdrC5Xv47v9AfzY9mBlwKQ.png?1779378840)

3. 에이전트가 검색할 지식 베이스를 선택해요.

4. 검색어를 만드는 방식을 설정해요.

   - **Static Query**(고정 검색어): 도구가 매번 같은 검색어를 사용해요.
   - **Dynamic query (AI decides)**(동적 검색어, AI가 결정): 에이전트가 대화와 워크플로우 맥락을 바탕으로 검색어를 만들어요.

   ![검색어 방식 설정 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155071932412/original/_3GgupQUu-CkLlja5xWa69M1P91HZuPMEA.png?1779378902)

5. 에이전트가 지식 베이스에서 가져올 청크(chunk) 수를 정해요.

**왜 중요한가요?**

Search Knowledge Base는 에이전트가 실행할 때 필요한 정보만 가져오기 때문에 컨텍스트 창을 가볍게 유지해요. 그러면 토큰 사용량이 줄고, 에이전트가 더 정확하고 근거 있는 답을 할 수 있어요.

## Update Custom Value(커스텀 값 업데이트) 도구

**Update Custom Value** 도구를 쓰면 AI Agent가 워크플로우를 실행하는 중에 커스텀 값을 직접 업데이트할 수 있어요. 가능한 모든 경우마다 큰 If/Else 분기를 만드는 대신, 상황에 맞춰 에이전트가 값을 설정하거나 바꾸게 하고 싶을 때 유용해요.

이런 경우에 쓸 수 있어요.

1. 요일에 따라 영업시간 메시지 설정하기
2. 형식에 맞춘 날짜 값 업데이트하기
3. 상황에 맞는 프로모션 코드 지정하기
4. 시간대, 연락처 데이터, 파이프라인 단계에 따라 값 저장하기

**도구 추가 방법**

1. 워크플로우를 열고 **AI Agent** 액션을 추가하거나 편집해요.
2. 도구 목록에서 **Update Custom Value**를 선택해요.
3. 에이전트가 사용할 필드를 설정해요.
4. 도구를 저장하고 워크플로우를 게시해요.

**도구 필드**

**Custom Value**(커스텀 값)

업데이트할 커스텀 값을 선택해요. 다음 중 하나를 고를 수 있어요.

- 특정 커스텀 값을 선택해요.
- **Let AI decide**(AI가 결정)를 사용해서 에이전트가 어떤 커스텀 값을 업데이트할지 고르게 해요.

**New Value**(새 값)

커스텀 값에 기록할 값을 정해요. 다음 중 하나를 고를 수 있어요.

- 고정 값이나 변수를 입력해요.
- **Let AI decide**를 사용해서 에이전트가 프롬프트 지침을 바탕으로 값을 만들게 해요.

특정 커스텀 값을 선택하면 **Current Value**(현재 값)가 함께 표시될 수 있어요. 업데이트하기 전에 기존 값을 확인할 수 있어요.

**자주 쓰는 설정 패턴**

특정 커스텀 값 + AI가 만든 값

필드는 정해져 있지만 그 안에 무엇을 쓸지는 에이전트가 정해야 할 때 사용해요.

AI가 고른 커스텀 값 + AI가 만든 값

어떤 필드를 업데이트할지와 어떤 값을 넣을지를 모두 에이전트가 정해야 할 때 사용해요.

**이 도구를 쓰는 이유**

큰 조건 트리를 AI Agent 단계 하나로 대신할 수 있어서 워크플로우가 단순해져요. 커스텀 값을 동적으로 설정하려고 분기와 반복되는 업데이트 액션이 많이 필요할 때 특히 유용해요.

## AI Agent 워크플로우 액션 설정하기

순서대로 설정하면 알맞은 템플릿을 고르고, 지침을 명확하게 쓰고, 작업에 필요한 도구를 에이전트에게 줄 수 있어요.

1. **자동화 > 워크플로우**로 이동해요.

   ![자동화 > 워크플로우 메뉴](https://jumpshare.com/share/0JWEsWQU9NawnWRXArkh+/Screen+Shot+2026-04-06+at+21.20.01.png)
2. 새 워크플로우를 만들거나 기존 워크플로우를 편집해요.

   ![새 워크플로우 만들기 또는 기존 워크플로우 편집](https://jumpshare.com/share/BXEsCvFYK7i5WsZpbUNj+/Screen+Shot+2026-04-06+at+21.21.45.png)
3. 알맞은 트리거를 추가해요. 예를 들어 **Form Submitted**(폼 제출), **Contact Created**(연락처 생성) 같은 트리거가 있어요. 액션을 설정하는 중에 미리 만들어진 템플릿을 선택해도 돼요.

   ![워크플로우에 트리거 추가](https://jumpshare.com/share/7cvd7EvdDe5EzEzze4Zm+/GIF+Recording+2026-04-06+at+21.28.31.gif)
4. 워크플로우 캔버스에서 **+ Add**(추가)를 클릭하거나 **Please select action**(작업을 선택해 주세요) 자리를 선택해요.
5. **Workflow AI** 섹션에서 **AI Agent** 액션을 선택해요.
6. **Action Name**을 입력해요.

   ![액션 선택 후 Action Name 입력](https://jumpshare.com/share/GBYCnKxPwxf36RdroWew+/GIF+Recording+2026-04-06+at+21.30.12.gif)
7. 처음부터 설정하려면 **Build Your Own**을 선택해요.
8. **Instructions**를 입력해요.
9. 프롬프트 구조를 다듬고 싶다면 **Enhance Prompt**를 클릭해요.
10. 사용할 **Model**을 선택해요.
11. **+ Add Tool**을 클릭하고 에이전트가 쓸 도구를 선택해요.
12. 도구마다 설정해요. AI가 필드 값을 정하게 할지, 특정 값을 직접 설정할지도 정해요.

    ![도구 설정 화면](https://jumpshare.com/share/rL6dUAKMPEV4IVjmBCOG+/GIF+Recording+2026-04-07+at+19.45.24.gif)
13. 또는 **Template**을 선택해도 돼요. 템플릿은 **Instructions**와 **Tools** 항목을 채워 주는, 미리 만들어진 에이전트 설정이에요. 템플릿에 필요한 트리거가 워크플로우에 아직 없으면 해당 트리거를 추가하기 전까지 템플릿을 사용할 수 없는 상태로 표시돼요.

    ![템플릿 선택 화면](https://jumpshare.com/share/K0Y1edlbfPxhdnRFeVYS+/GIF+Recording+2026-04-07+at+19.51.17.gif)
14. **Conversation Memory**를 켜거나 **Output Format**을 설정하려면 **Advanced Options**(고급 옵션)를 열어요. 고급 설정으로 에이전트가 이전 활동을 어떻게 기억할지, 출력을 이후 워크플로우 단계에 어떻게 넘길지 더 세밀하게 정할 수 있어요.

    - **Conversation Memory**: 같은 연락처로 반복 실행해도 에이전트가 맥락을 이어 갈 수 있게 해 줘요. 같은 연락처가 단계에 다시 들어올 수 있고 이전 상호작용에 맞춰 에이전트가 대응해야 하는 워크플로우에 유용해요.

      이 설정은 기본적으로 꺼져 있어요. 켜면 에이전트는 해당 단계에서 같은 연락처로 실행했던 이전 기록의 요약을 이어 가며 사용해요.

      주기적인 리드 후속 조치처럼 반복되거나 여러 번 접촉하는 워크플로우에서 Conversation Memory를 쓰세요. 폼 후속 조치 한 번만 하는 워크플로우처럼 한 번만 실행되는 경우에는 보통 꺼 두어도 돼요.
    - **Output Format**: 에이전트가 이후 워크플로우 단계에서 쓸 수 있는 데이터를 돌려줄지 정해요. 에이전트 실행이 끝난 뒤 그 결과를 워크플로우에서 참조해야 한다면 알맞은 출력 유형을 골라야 해요.

      선택할 수 있는 옵션은 다음과 같아요.

      - **None**(없음): 에이전트가 작업은 수행하지만 이후 단계를 위한 구조화된 출력은 돌려주지 않아요.
      - **Text**(문자): 에이전트가 자유로운 텍스트 응답을 돌려줘요. 이 옵션을 선택하면 **Output Description**(출력 설명) 필드가 나타나서 응답에 어떤 내용이 담겨야 하는지 설명할 수 있어요.
      - **JSON**: 에이전트가 정의된 스키마에 따라 구조화된 데이터를 돌려줘요. 이름, 유형, 선택 사항인 설명이 있는 속성을 추가하면 나중에 워크플로우에서 출력을 더 쉽게 참조할 수 있어요.
15. 액션을 **Save**(저장)해요.

    ![액션 저장 화면](https://jumpshare.com/share/GzSHLAMZcSAIh5XoNLp7+/Screen+Shot+2026-04-07+at+19.53.43.png)

## Execution Logs(실행 로그)

**Execution Logs**를 보면 워크플로우를 실행하는 동안 에이전트가 무엇을 했는지 쉽게 알 수 있어요. 동작을 확인하거나, 도구 사용 내역을 점검하거나, 예상과 다른 결과의 원인을 찾을 때 유용해요.

워크플로우를 실행한 뒤 워크플로우 빌더의 **Execution Logs** 탭을 열고 AI Agent 실행 내역을 선택하면 추적 기록을 볼 수 있어요.

추적 기록에는 다음 내용이 포함될 수 있어요.

1. **Agent Input**(에이전트 입력): 에이전트가 받은 전체 입력이에요.
2. **LLM**: 다음 단계를 추론하기 위해 호출한 모델 호출 내역이에요.
3. **Tool executions**(도구 실행): 에이전트가 호출한 각 도구의 실행 시간과 성공·실패 상태를 포함해요.

각 단계를 펼쳐서 입력과 출력 데이터를 확인할 수 있어요. 로그는 표 형식과 원본 JSON 보기를 모두 지원해요.

## 가격(Pricing)

가격 구조를 알아 두면 실제 운영 중인 워크플로우에서 AI Agent를 쓸 때 비용을 가늠하기 쉬워요. 모델이 다르거나 프리미엄 액션이 포함되는 경우에는 더 그래요.

AI Agent 실행 1회의 비용은 두 가지로 이루어져요.

{% hint style="info" %}
토큰 사용량은 **Execution Logs**에서 확인할 수 있고, 청구 상세 내역은 계정의 청구/결제 영역에서 확인할 수 있어요.
{% endhint %}

1. LLM 토큰 사용량: 에이전트는 실행하는 동안 모델을 한 번 이상 호출할 수 있어요. 전체 토큰 사용량은 지침의 길이, 작업의 복잡도, 필요한 도구 호출 횟수에 따라 달라져요.
2. 프리미엄 액션 실행: 에이전트가 프리미엄 액션을 도구로 사용하면, 그 액션을 단독 워크플로우 액션으로 쓸 때와 같은 실행당 요금이 부과돼요.

**실행 1회당 총 비용** = (모든 LLM 호출에서 소비한 총 토큰 수 × 선택한 모델의 토큰당 요금) + (프리미엄 도구 실행 횟수 × 실행당 요금)

**Send SMS**(SMS 전송), **Update Contact Field**(연락처 필드 업데이트), **Add Tag**(태그 추가) 같은 표준 기본 도구는 일반 플랫폼 사용 요금 외에 프리미엄 액션 실행 요금이 추가로 붙지 않아요.

{% hint style="warning" %}
AI Agent 실행에는 이제 자동 토큰 최적화가 적용돼요. 워크플로우, 모델, 컨텍스트, 사용한 도구에 따라 실행 비용을 최대 50%까지 줄일 수 있어요. 이 최적화는 새 AI Agent 액션과 기존 AI Agent 액션에 자동으로 적용되고, 설정을 바꿀 필요가 없어요.
{% endhint %}

{% hint style="info" %}
AI Agent 실행에는 불필요한 토큰 사용을 줄이는 자동 토큰 최적화가 적용돼요. 이 최적화는 새 AI Agent 액션과 기존 AI Agent 액션에 자동으로 적용되고, 설정을 바꿀 필요가 없어요. 실제 토큰 사용량과 실행 비용은 선택한 모델, 지침, 작업 복잡도, 대화 맥락, 사용한 도구에 따라 달라져요.
{% endhint %}

## 자주 묻는 질문

### 추가할 수 있는 도구 수에 제한이 있나요?
네, 에이전트 하나에 도구를 최대 10개까지 추가할 수 있어요. **Date Calculator**(날짜 계산), **Math Operations**(수학 연산) 같은 내부 도구는 이 제한에 포함되지 않아요.

### 어떤 모델을 써야 하나요?
작업의 종류와 복잡도에 맞춰 모델을 고르세요. 각 모델 아래에 표시된 설명을 보면 어떤 용도에 맞는지 알 수 있어요. 의도 분류, 단순 읽기, 기본 작업처럼 단순한 작업에는 더 빠른 모델과 낮은 Effort 수준(지원되는 경우)을 고려해 보세요. 깊은 추론이 필요한 복잡하거나 여러 단계로 이루어진 작업에는 추론을 지원하는 모델을 고르고, 필요하면 Effort 수준을 높이세요. 모델 제공 여부, 토큰 사용량, 가격은 달라질 수 있어요. 액션을 설정할 때 현재 모델 옵션과 해당 가격을 확인하세요. OpenAI 모델 중 GPT-6 Luna는 빠르게 많이 처리해야 하는 작업에, GPT-6 Sol은 깊은 추론이 필요한 복잡한 다단계 작업에 맞게 만들어졌어요.

### AI Agent를 아무 트리거와 함께 쓸 수 있나요?
네, AI Agent는 모든 워크플로우 트리거와 함께 쓸 수 있어요. 템플릿은 지침이 특정 상황에 맞게 쓰여 있어서 특정 트리거를 권장하는 경우가 있어요.

### Enhance Prompt는 무엇을 하나요?
**Enhance Prompt**는 지침을 더 체계적이고 자세한 프롬프트로 다시 정리해 줘요. 단계가 더 명확해지고 예외 상황 처리도 포함돼요. 필요하면 개선한 내용을 되돌릴 수 있어요.

### 워크플로우에서 실행할 때 AI Agent는 어떤 맥락을 사용하나요?
AI Agent는 사용자가 쓴 지침, 활성화한 도구, 실행 시점에 사용할 수 있는 연락처·워크플로우 데이터를 사용해요. 메시지 맥락이 필요하면 채널 전체에 걸친 연락처의 대화 기록도 가져올 수 있어요.

### Conversation Memory와 Conversation History는 어떻게 다른가요?
- **Conversation Memory**: 같은 연락처로 이 AI Agent 단계를 실행했던 이전 기록을 요약해서 이어 가며 쓰는 기능이에요(선택 사항).
- **Conversation History**(대화 기록): 필요할 때 채널 전체의 메시지 기록을 가져오는 기능이에요(기본 제공).

### JSON 출력 형식은 언제 쓰나요?
이후 워크플로우 단계에서 자격 평가 결과처럼 에이전트 응답의 특정 값이나 구조화된 출력을 참조해야 할 때 JSON을 쓰세요.

### 워크플로우를 실행하는 동안 에이전트가 무엇을 했는지 어떻게 확인하나요?
워크플로우 빌더에서 **Execution Logs** 탭을 열고 AI Agent 실행 내역을 선택하세요. 모델 호출, 도구 실행, 입력, 출력, 토큰 사용량을 포함한 추적 기록을 볼 수 있어요.

### 템플릿을 쓰면 특정 설정에 고정되나요?
아니요. 템플릿은 **Instructions**와 **Tools** 항목을 미리 채워 줄 뿐이에요. 템플릿을 적용한 뒤에도 지침을 편집하고, 모델을 바꾸고, 도구를 추가하거나 제거하고, 고급 옵션을 업데이트할 수 있어요.

### Conversation Memory는 언제 켜야 하나요?
같은 연락처가 에이전트 단계를 두 번 이상 거칠 수 있고 이전 실행 내용에 맞춰 에이전트가 대응해야 할 때 켜세요. 한 번만 실행되는 워크플로우에서는 보통 필요하지 않아요.

### 비즈니스 정보를 Instructions에 넣지 않고 Search Knowledge Base를 써야 하는 경우는 언제인가요?
비즈니스 정보가 지식 베이스에 있고, 에이전트가 실행할 때 필요한 정보만 가져오게 하고 싶다면 **Search Knowledge Base**를 쓰세요. 가격, 정책, FAQ, 예약 규칙 같은 내용이 해당돼요. 프롬프트 크기가 줄고, 저장해 둔 내용을 근거로 응답하게 돼요.
