# 워크플로우 액션 — Create Opportunity(기회 만들기)

워크플로우가 실행될 때 지정한 파이프라인과 단계에 새 기회를 자동으로 만드는 액션이에요. 리드가 들어오면 바로 기회로 이어지게 하고 싶을 때 사용하세요.

## 개요

**Create Opportunity**(기회 만들기) 액션은 지정한 파이프라인과 단계에 새 기회를 만들어요. 기회명, 소스, 상태 같은 정보를 자동으로 채울 수 있어요. 같은 연락처에 이미 기회가 있을 때 새 기회를 또 만들지도 설정할 수 있어요.

특정 워크플로우 조건이 충족될 때마다 기회를 자동으로 만들 수 있어서, 리드를 기회로 전환하는 과정을 간소화하는 데 유용해요.

## 액션 이름

**Create Opportunity**

## 액션 설명

**Create Opportunity** 액션이 실행되면 CRM 또는 영업 파이프라인에 새 기회가 추가돼요. 파이프라인, 파이프라인 단계, 기회명, 소스 등을 설정해 두면 새 기회가 기존 영업 프로세스에 자연스럽게 들어가요.

중복 기회를 허용할지도 연락처 ID를 기준으로 정할 수 있어요. 연락처에 이미 기회가 있고 중복 생성을 끈 상태라면, 그 연락처에는 새 기회가 만들어지지 않아요.

| 항목 | 설명 | 필수 여부 |
| --- | --- | --- |
| **Action Name**(액션 이름) | 워크플로우에서 이 단계를 구분하기 위한 고유한 이름이에요. | 예 |
| **Pipeline**(파이프라인) | 새 기회를 만들 파이프라인이에요. 예: "프로젝트", "영업" | 예 |
| **Pipeline Stage**(파이프라인 단계) | 새 기회를 놓을 단계예요. 예: "새 리드", "자격 검증" 비워 두면 선택한 파이프라인의 첫 번째 단계로 들어가요. | 아니요 |
| **Opportunity Name**(기회명) | 새 기회의 이름이에요. 비워 두면 연락처 이름이 있는 경우 그 이름으로 만들어져요. 커스텀 값과 커스텀 필드로 이름을 자동으로 만들 수도 있어요. 예: `{{contact.first_name}}` | 아니요 |
| **Opportunity Source**(기회 소스) | 기회가 어디에서 시작됐는지 나타내요. 예: "웹사이트", "추천", "이벤트" 비워 두면 기본값 없이 빈 상태로 남아요. | 아니요 |
| **Status**(상태) | 새 기회의 상태예요. 예: "진행 중", "신규", "대기 중" 비워 두면 "진행 중"으로 설정돼요. | 아니요 |
| **Duplicate Opportunity**(중복 기회) | 같은 연락처 ID로 이미 기회가 있을 때 새 기회를 만들지 정해요. 끄면 해당 연락처에 이미 연결된 기회가 있을 때 새 기회를 만들지 않아요. | 해당 없음 |
| **Opportunity Value**(기회 금액) | 기회의 예상 가치를 나타내는 숫자 필드예요. 비워 두면 0으로 설정돼요. | 아니요 |
| **Ownership Settings**(담당자 설정) | **기회 & 파이프라인** 설정에 따라 기회 담당자가 연락처 담당자로 자동 지정되거나 미지정 상태로 남아요. 이 동작은 시스템의 **Customize opportunity settings**(기회 설정 사용자 지정)에서 켜고 끌 수 있어요. | 아니요 |
| **Other Custom Fields**(기타 커스텀 필드) | 새 기회를 만들 때 함께 채우고 싶은 추가 커스텀 필드예요. 대부분의 필드에서 커스텀 값을 선택하거나 입력할 수 있어요. | 아니요 |

{% hint style="info" %}
날짜 필드에는 **Right Now**(지금) 같은 커스텀 값을 사용해 현재 날짜와 시간을 새 기회에 넣을 수 있어요.
{% endhint %}

### 예외 상황

- 연락처 정보가 일부 없는 경우: 연락처에 이름이나 성이 없으면 **Opportunity Name**에 쓸 수 있는 다른 연락처 정보(예: 이메일)를 사용하려고 시도해요.
- 워크플로우에 연락처가 없는 경우: 워크플로우와 연결된 연락처가 없으면(예: 연락처 데이터가 없는 인바운드 웹훅) 기회를 만들 수 없어요.
- 중복 확인: 중복 여부는 기회명이 아니라 연락처 ID를 기준으로 판단해요. 중복 생성을 끈 상태에서 같은 연락처가 이 액션을 다시 실행해도 새 기회는 만들어지지 않아요.

## 예시

시나리오: 웹사이트에서 "프로젝트 문의" 폼을 작성한 새 리드마다 기회를 하나씩 만들고 싶어요.

1. **Trigger**(트리거): 연락처가 "프로젝트 문의" 폼을 제출해요.
2. **Action**(액션): *Create Opportunity*
   - **Action Name**: "Create Opportunity"
   - **Pipeline**: "프로젝트"
   - **Pipeline Stage**: "새 리드"
   - **Opportunity Name**: `{{contact.first_name}} - 프로젝트 문의`
   - **Opportunity Source**: "웹사이트"
   - **Status**: "진행 중"
   - **Opportunity Value**: 0 (따로 지정하지 않은 경우)
   - **Duplicate Opportunity**: 켬 (같은 연락처가 프로젝트 문의를 여러 번 남길 수 있도록 허용)

이 액션이 실행되면 "프로젝트" 파이프라인의 "새 리드" 단계에 새 기회가 만들어져요. 같은 연락처가 문의를 다시 제출했을 때 중복 생성이 켜져 있으면 두 번째 기회가 만들어져요. 중복 생성이 꺼져 있으면 첫 번째 기회만 만들어져요.
