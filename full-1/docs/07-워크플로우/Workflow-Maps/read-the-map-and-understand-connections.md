# 워크플로우 맵 읽는 법 — 폴더·화살표·선·배지 이해하기

워크플로우 맵(Workflow Map)에 나오는 폴더, 워크플로우 칩, 에셋, 화살표, 배지가 각각 무엇을 뜻하는지 알려 드려요. 맵에 표시되는 에셋 종류도 함께 정리했어요.

## 맵 한눈에 보기

| 항목 | 의미 |
| --- | --- |
| 폴더 섬 | 워크플로우 폴더 하나예요. 폴더에 들어 있지 않은 워크플로우는 한곳에 모여 표시돼요. |
| 중첩 폴더 | 다른 폴더 안에 있는 폴더예요. 상위 폴더 섬 안에 표시돼요. 마우스를 올리면 전체 경로가 보여요. |
| 초록색 테두리의 파란색 워크플로우 칩 | 게시된 워크플로우예요. |
| 회색 테두리의 파란색 워크플로우 칩 | 초안 상태의 워크플로우예요. |
| 작은 색깔 에셋 칩 | 워크플로우가 사용하거나, 감시하거나, 변경하는 에셋이에요. 에셋 종류에 따라 색이 달라요. |
| 스티키 노트 | 팀에서 맵 위에 남겨 둔 설명이에요. |

워크플로우를 클릭하면 상세 내용을 볼 수 있어요. 에셋을 클릭하면 그 에셋을 사용하는 워크플로우를 찾을 수 있어요.

폴더를 선택하면 그 폴더의 워크플로우와 에셋을 확인할 수 있어요. 폴더 메뉴에는 정리용 작업이 들어 있어요.

## 화살표의 의미

연결은 점에서 화살촉 방향으로 읽어요.

| 방향 | 의미 | 예시 |
| --- | --- | --- |
| 에셋 → 워크플로우 | 트리거 관계예요. 워크플로우가 그 에셋을 감시해요. | 폼 제출로 워크플로우가 시작돼요. |
| 워크플로우 → 에셋 | 액션 관계예요. 워크플로우가 그 에셋을 변경해요. | 워크플로우가 태그를 추가해요. |
| 에셋 ↔ 워크플로우 | 워크플로우가 그 에셋을 감시하기도 하고 변경하기도 해요. | 트리거와 액션이 같은 태그를 함께 써요. |
| 워크플로우 → 워크플로우 | 직접 액션으로 연락처를 다른 워크플로우에 추가하거나, 다른 워크플로우에서 제거해요. | 한 워크플로우가 연락처를 후속 워크플로우에 추가해요. |

이 연결은 자동화가 어떻게 설정되어 있는지를 보여 줘요. 특정 연락처가 거쳐 간 기록을 보려면 연락처 추적을 이용하세요.

![화살촉은 워크플로우와 에셋 사이에 설정된 관계의 방향을 보여 줘요.](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084352859/original/GzIctBahOpdd79HsFPCA8EtA6cXhFKSxKA.jpg?1793135766)

화살촉은 워크플로우와 에셋 사이에 설정된 관계의 방향을 보여 줘요.

## 선 모양의 의미

| 선 모양 | 의미 |
| --- | --- |
| 실선 | 무언가를 시작하거나 변경할 수 있는 트리거·액션 연결이에요. |
| 점선 | 필터에서 에셋을 쓰는 경우 같은 참조예요. 참조만으로는 아무것도 시작하거나 변경하지 않아요. |
| 폴더 사이를 잇는 곡선 | 같은 에셋이 두 개 이상의 폴더에서 쓰이고 있어요. 각 폴더에 그 에셋의 사본이 표시돼요. |
| 화살표가 움직이는 연한 파란색 선 | 마우스를 올렸거나 선택한 항목의 연결이에요. 화살표는 연결 방향을 따라 움직여요. |
| 두꺼운 파란색 선 | 선택한 연결이에요. 상세 내용이 사이드 패널에 나와요. |

움직이는 화살표는 연결 방향을 강조해서 보여 줘요. 특정 실행 내역을 조사하려면 연락처 기록을 확인하세요.

## 연결 자세히 보기

1. 맵을 완전히 축소해 둔 상태라면 확대해요.
2. 워크플로우나 에셋 위에 마우스를 올려 연결을 강조해요.
3. 살펴볼 선을 클릭해요.
4. 사이드 패널에 나온 트리거와 액션을 확인해요.

맵을 끝까지 축소한 상태에서는 선을 선택할 수 없어요.

## 배지의 의미

| 배지 | 의미 |
| --- | --- |
| **Errors**(오류) | 최근 실행에서 워크플로우에 오류가 발생했어요. |
| **Usage**(사용 현황) | 클릭하면 폴더별로 그 에셋이 어디에 쓰이는지 볼 수 있어요. |
| **Missing asset**(누락된 에셋) | 에셋이 더 이상 없는데, 워크플로우가 아직 그 에셋을 참조하고 있어요. |

오류는 **Review workflows with errors**(오류가 있는 워크플로우 검토)로 확인하세요. 누락된 에셋은 워크플로우의 참조를 살펴보면 어디에서 아직 쓰이는지 알 수 있어요.

## 지원하는 에셋 종류

맵에는 아래 에셋 종류가 표시돼요. 이름은 맵 화면에 보이는 영어 그대로 적고, 처음 나오는 곳에 뜻을 붙였어요.

- 태그와 필드: Tags(태그), Contact Custom Fields(연락처 커스텀 필드), Opportunity Custom Fields(기회 커스텀 필드), Custom Values(커스텀 값), Custom Objects(커스텀 오브젝트)
- 폼과 참여: Forms(폼), Surveys(설문), Facebook Forms, TikTok Forms, Quizzes(퀴즈), Trigger Links(트리거 링크), Chat Widgets(채팅 위젯)
- 일정과 영업: Calendars(캘린더), Users(사용자), Pipelines(파이프라인), Pipeline Stages(파이프라인 단계), Services(서비스)
- 퍼널과 상품: Funnels(퍼널), Funnel Pages(퍼널 페이지), Funnel Products(퍼널 상품), Global Products(글로벌 상품), Global Product Prices(글로벌 상품 가격)
- 멤버십과 콘텐츠: Membership Offers(멤버십 오퍼), Membership Products(멤버십 상품), Membership Categories(멤버십 카테고리), Membership Lessons(멤버십 강의), Videos(비디오)
- 템플릿과 결제: Templates(템플릿), Certificate Templates(수료증 템플릿), Invoice Templates(인보이스 템플릿), Estimate Templates(견적서 템플릿)
- 기타 에셋: Ad Accounts(광고 계정), Workflow Links(워크플로우 링크), AI Studio Projects(AI 스튜디오 프로젝트), Listings(리스팅), Listing Categories(리스팅 카테고리)

위 묶음은 목록을 훑어보기 쉽게 나눈 것일 뿐이에요. 지원하는 에셋 종류는 각 항목의 이름 하나하나예요.

맵에서 검색하고 필터링하는 방법은 [워크플로우 맵 탐색·검색·필터링](navigate-search-and-filter-workflow-maps.md) 문서를 참고하세요.

## 자주 묻는 질문

### 같은 에셋이 왜 여러 폴더에 나오나요?
여러 폴더에서 쓰는 에셋은 해당하는 폴더마다 표시돼요. 곡선이 그 사본들을 이어 줘요.

### **Wait**, **If/Else**, **Go To** 단계가 맵에 안 보여요.
이 단계들은 워크플로우 내부 로직이라 맵에는 나오지 않아요. 워크플로우 빌더를 열면 볼 수 있어요. If/Else 안에서 참조한 태그는 검색으로 찾을 수 있어요.

### 점선은 워크플로우가 에셋을 변경한다는 뜻인가요?
아니요. 필터에서 쓰는 경우처럼, 워크플로우가 그 에셋을 참조한다는 뜻이에요.

### **Missing asset** 배지는 무슨 뜻인가요?
에셋은 삭제되었는데, 워크플로우에는 아직 그 에셋에 대한 참조가 남아 있다는 뜻이에요.
