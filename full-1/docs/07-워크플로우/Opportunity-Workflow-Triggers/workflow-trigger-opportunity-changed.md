# 워크플로우 트리거 — Opportunity Changed(기회 변경됨)

**Opportunity Changed**(기회 변경됨) 트리거는 기회 정보가 바뀔 때마다 워크플로우를 실행해요. 상태뿐 아니라 리드 금액, 단계 이동, 담당자 변경, 커스텀 필드 변경까지 감지하기 때문에, 영업 파이프라인을 실시간으로 관리하고 CRM 자동화를 간단하게 만들 수 있어요. 이 문서에서는 트리거의 장점, 설정 방법, 활용 예시를 안내해요.

## 이 트리거는 무엇인가요?

**Opportunity Changed** 트리거는 기회 정보에 어떤 변경이든 생기면 워크플로우를 실행해요. **Opportunity Status Changed**(기회 상태 변경됨) 트리거는 상태가 바뀔 때만 작동하지만, 이 트리거는 리드 금액, 파이프라인 단계, 담당자, 커스텀 필드 변경에도 반응해요. 덕분에 워크플로우를 간소화하고 CRM 데이터를 항상 최신 상태로 유지할 수 있어요.

## Opportunity Changed 트리거의 장점

- **전체 변경 추적:** 상태뿐 아니라 기회에 생기는 모든 변경을 기준으로 액션을 자동화해요.
- **실시간 알림:** 기회가 업데이트되면 팀원에게 바로 알릴 수 있어요.
- **CRM 정확도 향상:** 기록 관리와 데이터 일관성을 자동으로 지켜요.
- **파이프라인 관리 개선:** 기회가 수정될 때 후속 조치나 작업 배정을 실행해요.
- **맞춤 자동화:** 워크플로우 필터를 적용해 원하는 기회 변경에만 자동화가 작동하게 해요.
- **유연한 필터 연산자:** 이벤트 기반 연산자인 **Has Changed**(변경됨), **Has Changed To**(~(으)로 변경됨), **Equals**(같음)를 사용하면 특정 기회 필드가 업데이트될 때만 워크플로우를 실행할 수 있어요.

## 기존 워크플로우와의 호환성

기존 **Opportunity Changed** 워크플로우는 직접 수정하기 전까지 지금 동작 그대로 유지돼요.

새 연산자나 날짜 필드 지원은 기존 워크플로우에 영향을 주지 않아요.

## Opportunity Changed 트리거 설정하기

이 트리거를 설정하면 CRM의 기회가 업데이트될 때 워크플로우 액션을 자동으로 실행할 수 있어요. 아래 순서대로 따라 하세요.

### 1단계: 워크플로우 빌더 열기

1. 하이퍼클래스 계정에 로그인해요.
2. **자동화 > 워크플로우**로 이동해요.
3. 새 워크플로우를 만들거나 기존 워크플로우를 열어요.

### 2단계: Opportunity Changed 트리거 추가하기

1. **+ Add New Trigger**(새 트리거 추가)를 클릭해요.
2. 트리거 목록에서 **Opportunity Changed**를 검색해요.
3. 찾은 트리거를 선택해 설정을 이어가요.

### 3단계: 트리거 이름 정하기

트리거의 목적이 드러나도록 알기 쉬운 이름을 붙여 주세요. 이름을 잘 지어 두면 자동화가 여러 개일 때 워크플로우를 구분하기 쉬워요.

### 4단계: 필터 적용하기

필터를 쓰면 기회에 특정 변경이 생길 때만 워크플로우가 실행되도록 세밀하게 조정할 수 있어요.

#### Assigned To 필터

**Assigned To**(담당자) 필터는 기회가 다른 팀원에게 재배정될 때 워크플로우를 실행해요. 리드를 함께 관리하는 영업팀·지원팀에 특히 유용해요. 기회의 담당자가 바뀔 때 후속 액션을 자동화하면 팀원 간 인수인계가 매끄러워져요.

사용할 수 있는 연산자는 다음과 같아요.

- **Has Changed**: 담당자가 다른 사용자로 바뀌면 실행돼요.
- **Has Changed To**: 기회가 선택한 특정 사용자에게 배정될 때만 실행돼요.
- **Equals**: 현재 특정 사용자에게 배정된 기회에서 어떤 변경이든 생기면 실행돼요.

예를 들어 가치가 높은 리드가 선임 영업 담당자에게 재배정되면, 워크플로우가 새 담당자에게 알림을 보내고, 내부 기록을 업데이트하고, 후속 시퀀스를 실행할 수 있어요. 담당자가 바뀌는 중에도 기회가 놓치지 않고 관리돼요.

#### Tag 필터

**Tag**(태그) 필터는 이전에 **Has Tag**라는 이름이었어요. 기회에 붙은 태그를 기준으로 **Opportunity Changed** 트리거가 실행될 시점을 정해요.

기회에 특정 태그가 있을 때만 자동화가 작동하므로 워크플로우 실행을 더 세밀하게 조절할 수 있어요.

예를 들어 기회에 "Hot Lead"나 "Follow-Up Needed" 같은 태그가 붙으면 후속 이메일을 자동으로 보내거나, 영업 담당자에게 알리거나, 리드를 다른 파이프라인 단계로 옮기도록 설정할 수 있어요. 리드를 분류하고, 가치가 높은 기회를 우선 처리하고, 분류에 따라 다른 액션을 실행할 때 유용해요.

#### In Pipeline 필터

**In Pipeline**(파이프라인 안) 필터는 특정 파이프라인 안에서 기회에 변경이 생길 때 워크플로우를 실행해요. 선택한 파이프라인에 속한 기회에만 자동화가 작동해서 더 정확하게 대상을 지정할 수 있어요.

사용할 수 있는 연산자는 다음과 같아요.

- **Has Changed**: 기회가 다른 파이프라인으로 이동하면 실행돼요.
- **Has Changed To**: 기회가 선택한 특정 파이프라인으로 이동할 때만 실행돼요.
- **Equals**: 특정 파이프라인 안의 기회에서 어떤 변경이든 생기면 실행돼요.

예를 들어 리드가 영업 파이프라인 안에서 움직일 때만 실행하고 고객 지원 파이프라인에서는 실행하지 않도록 설정할 수 있어요. 영업, 온보딩, 고객 유지처럼 업무마다 파이프라인을 따로 운영하는 경우에 특히 유용해요. 이 필터로 알맞은 상황에서만 워크플로우를 실행하면 불필요한 자동화 실행을 줄이고 효율을 높일 수 있어요.

#### Lead Value 필터

**Lead Value**(리드 금액) 필터는 기회의 금액이 늘거나 줄 때 워크플로우를 실행해요. 예상 매출이 달라질 때 액션을 자동화할 수 있어서, 중요한 변경을 놓치지 않아요.

예를 들어 업셀이나 견적 수정으로 리드 금액이 올라가면, 영업팀에 알리거나, 파이프라인 단계를 조정하거나, 맞춤 후속 이메일을 보낼 수 있어요. 반대로 리드 금액이 줄어들면 담당 매니저에게 검토를 요청하거나 이탈을 막는 유지 전략을 실행할 수 있어요.

![Lead Value 필터 설정 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155041721293/original/i6B2z0QUdLHa5dw3e0vNit3Ny8IeavXOQw.png?1739792952)

#### Lost Reason 필터

**Lost Reason**(고객전환실패 사유) 필터는 기회가 고객전환실패로 표시되고 사유가 지정될 때 워크플로우를 실행해요. 고객전환에 실패한 건을 체계적으로 추적하고 대응할 수 있어서, 영업 방식과 고객 유지 활동을 개선하는 데 도움이 돼요.

필터 연산자는 다음 중에서 고를 수 있어요.

<!-- 검토 필요: 원문 내용이 서로 다름 (Has Changed 항목의 설명이 "Equals: ..." 문장과 뒤섞여 있고, Equals 설명도 두 번 다르게 나옴) -->
- **Has Changed**: 고객전환실패 사유가 바뀌면 실행돼요.
- **Has Changed To**: 사유가 특정 값으로 업데이트될 때만 워크플로우를 실행해요. 예를 들어 사유가 "Price Too High"로 바뀌면 할인 제안이 담긴 후속 이메일을 자동으로 보낼 수 있어요.
- **Equals**: 특정 고객전환실패 사유가 지정된 기회에서 어떤 변경이든 생기면 실행돼요.

#### Status 필터

**Status**(상태) 필터는 기회의 현재 상태를 기준으로 워크플로우를 실행해요. 기회가 파이프라인의 특정 단계에 도달했을 때 액션이 실행되므로, 팀이 영업 진행 상황을 더 효율적으로 추적하고 관리할 수 있어요.

사용할 수 있는 연산자는 다음과 같아요.

- **Is**(다음과 같음): 기회가 선택한 상태와 일치하면 실행돼요. 예를 들어 **Won**(고객전환성공)을 선택하면 기회가 고객전환성공으로 표시될 때만 실행돼요.
- **Is Not**(다음과 같지 않음): 기회가 선택한 상태와 일치하지 않으면 실행돼요. 특정 상태를 제외할 때 유용해요. 예를 들어 **Abandoned**(중단됨) 상태의 기회는 무시하도록 설정할 수 있어요.
- **Has Changed**: 상태가 다른 상태로 바뀌면 실행돼요.
- **Has Changed To**: 상태가 선택한 특정 값으로 바뀔 때만 실행돼요.

연산자를 선택한 뒤에는 드롭다운에서 상태 옵션을 고르세요.

#### Checkbox Fields (Opportunity Custom Field Filters)

체크박스 커스텀 필드의 변경을 기준으로 기회를 필터링해요.

- **Added**(추가됨): 특정 체크박스 옵션이 추가(체크)될 때 실행돼요.
- **Removed**(제거됨): 특정 체크박스 옵션이 제거(체크 해제)될 때 실행돼요.
- **Equals**: 체크박스가 특정 값과 같은 기회에서 어떤 변경이든 생기면 실행돼요.

#### Radio Select Fields (Opportunity Custom Field Filters)

**Radio Select**(라디오 선택) 커스텀 필드의 변경을 기준으로 기회를 필터링해요.

- **Has Changed**: 라디오 선택 값이 다른 옵션으로 바뀌면 실행돼요.
- **Has Changed To**: 라디오 선택 값이 선택한 특정 값으로 바뀔 때만 실행돼요.
- **Equals**: 라디오 선택 값이 특정 값과 같은 기회에서 어떤 변경이든 생기면 실행돼요.

![Radio Select 필드 필터 설정 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155062695732/original/UBngab81d1sn2Uge0-rSxbkzI-FuyYLBPQ.png?1768461203)

#### Dropdown Fields (Single & Multiple in Opportunity Custom Field Filters)

드롭다운 커스텀 필드의 변경을 기준으로 기회를 필터링해요. 단일 선택과 다중 선택 드롭다운 모두 똑같이 작동해요.

- **Has Changed**: 드롭다운 값이 바뀌면 실행돼요.
- **Has Changed To**: 드롭다운이 선택한 특정 값으로 바뀔 때만 실행돼요.
- **Equals**: 드롭다운이 특정 값과 같은 기회에서 어떤 변경이든 생기면 실행돼요.

![Dropdown 필드 필터 설정 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155062695762/original/TDVBnoOy2xQFQ2d9s9LpsZsbJZhnRyGM_g.png?1768461247)

#### Date Fields (Opportunity Custom Field Filters)

이제 **Opportunity Changed** 트리거에서 날짜 커스텀 필드를 완전히 지원해요.

- **Has Changed**: 날짜 필드 값이 바뀌면 실행돼요.
- **Has Changed To**: 날짜 필드가 선택한 특정 날짜로 바뀔 때만 실행돼요.
- **Equals**: 날짜 필드가 특정 날짜와 같은 기회에서 어떤 변경이든 생기면 실행돼요.

### 5단계: 워크플로우 액션 설정하기

<!-- 검토 필요: 원문에서 "Step 4"가 두 번 나와서 이후 단계 번호를 5·6으로 정리함 -->
트리거 설정을 마쳤으면 다음과 같은 액션을 정해요.

1. 이메일 또는 SMS 알림 보내기: 기회가 업데이트되면 영업 담당자에게 알려요.
2. 작업 배정: CRM에 후속 작업을 자동으로 만들어요.
3. 연락처 정보 업데이트: 기회 변경 내용에 따라 고객 정보를 수정해요.
4. 다른 워크플로우 트리거: 이 트리거를 다른 워크플로우와 연결해 더 복잡한 자동화를 만들어요.

### 6단계: 저장, 테스트, 게시하기

1. **Save Trigger**(트리거 저장)를 클릭해 설정을 확정해요.
2. 테스트를 실행해 워크플로우가 제대로 작동하는지 확인해요.
3. 확인이 끝나면 **Publish**(게시)를 클릭해 자동화를 활성화해요.

## 활용 예시

- 기회 상태가 고객전환성공으로 바뀔 때만 워크플로우를 실행해요.
- 기회의 담당자가 바뀌면 팀원에게 알려요.
- 커스텀 설치 날짜가 추가되면 온보딩을 시작해요.
- 체크박스 필드가 체크되면 후속 자동화를 실행해요.

## 자주 묻는 질문

### **Opportunity Changed** 트리거는 **Opportunity Status Changed** 트리거와 어떻게 다른가요?
**Opportunity Changed** 트리거는 담당자, 리드 금액, 파이프라인, 커스텀 필드 등 기회 안에서 일어나는 모든 변경을 추적해요. **Opportunity Status Changed** 트리거는 기회의 상태(예: 진행 중, 고객전환성공, 고객전환실패)가 바뀔 때만 실행돼요.

### 워크플로우 하나에 필터를 여러 개 설정할 수 있나요?
네, 여러 필터를 함께 쓸 수 있어요. 예를 들어 선임 영업 담당자에게 재배정된 가치 높은 리드만 추적하도록 필터를 조합할 수 있어요.

### 워크플로우가 제대로 작동하는지 어떻게 테스트하나요?
트리거를 설정한 뒤 기회를 직접 수정하고, 워크플로우가 예상한 액션을 실행하는지 확인하세요. 문제가 있으면 워크플로우 로그를 확인해 원인을 찾아보세요.

### 이 트리거를 기회 커스텀 필드와 함께 쓸 수 있나요?
네, 기회의 특정 커스텀 필드가 업데이트될 때 실행되도록 트리거를 설정할 수 있어요.

### **Has Changed**, **Has Changed To**, **Equals** 연산자는 어떻게 다른가요?
**Has Changed**는 해당 필드 값이 어떤 값으로든 바뀌면 실행돼요. **Has Changed To**는 필드가 선택한 특정 값으로 바뀔 때만 실행돼요. **Equals**는 해당 필드가 현재 그 특정 값인 기회에서 어떤 변경이든 생기면 실행돼요.

### 이제 날짜 커스텀 필드를 필터로 쓸 수 있나요?
네, 이제 **Opportunity Changed** 트리거에서 날짜 커스텀 필드를 필터로 쓸 수 있어요. **Has Changed**, **Has Changed To**, **Equals** 연산자로 날짜 필드 변경에 따라 워크플로우를 실행할 수 있어요.

### 기존 **Opportunity Changed** 워크플로우가 작동하지 않게 되나요?
아니요. 기존 워크플로우는 직접 수정하기 전까지 지금 동작 그대로 유지돼요.
