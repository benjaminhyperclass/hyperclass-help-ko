# 워크플로우 트리거 — Number Validation(번호 유효성 검사)

**Number Validation**(번호 유효성 검사) 트리거를 쓰면 연락처 전화번호의 유효성 검사 결과에 따라 자동화를 시작할 수 있어요. 이 검사는 해당하는 첫 번째 발신 SMS를 보내기 전에, 수신 번호가 유효하고 SMS를 받을 수 있는지 확인해요.

Number Validation은 하이퍼클래스의 번호 인텔리전스 기능에 포함돼요. 번호 인텔리전스에는 스팸 감지(Spam Detection)와 이름 조회(Name Lookup)도 있어요. 워크플로우에서 검사 결과를 활용하면 연락처를 상황에 맞게 나누고, 유효하지 않거나 SMS를 받을 수 없는 번호로 SMS를 보내려는 시도를 줄일 수 있어요.

{% hint style="warning" %}
Number Validation은 연락처가 메시지 수신에 동의했는지를 판단하지 않아요. 수신 동의(옵트인), 동의 확인, 메시지 규정 준수 요건은 계속 지켜 주세요.
{% endhint %}

---

## Number Validation 트리거를 쓰면 좋은 점

Number Validation을 쓰면 SMS 중심 자동화를 이어 가기 전에 전화번호 검사 결과에 따라 워크플로우가 반응하게 할 수 있어요. 팀이 전화번호 문제를 파악하고 알맞은 다음 작업을 고르는 데 도움이 돼요.

- 유효하지 않은 SMS 시도 줄이기: SMS 중심 프로세스를 진행하면 안 되는 번호를 가려내요.
- 연락처 자동 분류: 검사 결과에 따라 연락처를 다른 경로로 보내요.
- 연락처 데이터 개선: 전화번호 정보를 고쳐야 할 수 있는 연락처에 표시를 남겨요.
- 팀에 알림: 확인이 필요한 전화번호가 있으면 팀원에게 알려요.
- 멀티 채널 후속 연락 지원: SMS를 쓰면 안 될 때 다른 적절한 연락 방법으로 연결해요.

## 사전 준비

Number Validation이 해당하는 발신 SMS 수신 번호를 검사하려면 먼저 번호 인텔리전스를 켜야 해요. 기존 서브 계정은 서브 계정의 전화 시스템 설정에서 이 기능을 관리해요.

기존 서브 계정에서 켜는 방법은 다음과 같아요.

1. **설정 > 전화 시스템**으로 이동해요.
2. **추가 설정**을 열어요.
3. **번호 인텔리전스**를 찾아요.
4. 기능을 켜요.

{% hint style="info" %}
Number Validation, 스팸 감지, 이름 조회는 현재 번호 인텔리전스에 함께 포함되어 있어서 한꺼번에 켜지고 꺼져요.
{% endhint %}

### 새 서브 계정의 기본값

에이전시 관리자는 새로 만든 서브 계정에서 번호 인텔리전스가 자동으로 켜지도록 설정할 수 있어요.

**에이전시 설정 > 전화 연동 > 계정 생성**으로 이동한 다음 **번호 인텔리전스 자동 활성화**를 켜세요.

![계정 생성 화면의 번호 인텔리전스 자동 활성화 설정](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155081311885/original/CMI66eSlsSRGMGdt6Gv_FWdE9t5jQS9Gkw.png?1789742116)

{% hint style="warning" %}
이 설정은 새로 만드는 서브 계정의 기본값을 정해요. 이미 있는 서브 계정에는 소급해서 번호 인텔리전스를 켜 주지 않아요.
{% endhint %}

## Number Validation 트리거가 동작하는 방식

연락처를 만들거나 가져왔다고 해서 Number Validation이 바로 실행되지는 않아요. 하이퍼클래스는 그 전화번호로 보내는 첫 번째 발신 SMS의 검사 단계에 이르렀을 때 해당 검사를 실행해요.

전체 흐름은 다음과 같아요.

발신 SMS 준비 → Number Validation 실행 → 검사 결과 생성 → Number Validation 워크플로우 트리거 가능 → 검사 결과에 따라 SMS 발송 또는 차단

그래서 이미 있는 연락처도 하이퍼클래스가 그 전화번호로 보낼 첫 번째 발신 SMS를 준비하는 시점에 Number Validation 단계에 도달할 수 있어요.

{% hint style="warning" %}
Number Validation 워크플로우 트리거는 번호 인텔리전스의 검사 결과를 기준으로 실행돼요. SMS를 보낸 뒤에 Twilio나 메시지 전송 오류가 발생했다고 해서 트리거되지는 않아요. SMS 전송 오류에 반응하는 자동화가 필요하면 메시지 오류용 워크플로우 트리거를 사용하세요.
{% endhint %}

---

## Number Validation 트리거 설정하기

**Number is**(번호 상태) 필터가 어떤 검사 결과를 워크플로우에 들어오게 할지 정해요. 번호 인텔리전스가 돌려준 결과에 따라 서로 다른 자동화를 만들 수 있어요.

1. **자동화 > 워크플로우**로 이동해요.
2. 새 워크플로우를 만들거나 기존 워크플로우를 열어요.
3. **Add New Trigger**(새 트리거 추가)를 클릭해요.
4. **Number Validation**을 검색해서 선택해요.

   ![트리거 목록에서 Number Validation 선택](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155081312104/original/gvNKP71jzM7rZ1Jv2ZsFeTq7m361v4F1rQ.png?1789742205)
5. **Number is** 필터를 추가해요.
6. 워크플로우 빌더에 표시되는 옵션 중에서 알맞은 검사 결과를 선택해요.
7. 트리거를 저장해요.
8. 해당 검사 결과가 나왔을 때 실행할 워크플로우 액션을 추가해요.
9. 워크플로우를 테스트해요.
10. 워크플로우가 의도대로 동작하면 게시해요.

{% hint style="info" %}
**Number is**를 설정할 때는 현재 워크플로우 빌더에 표시되는 검사 옵션을 사용하세요. 선택할 수 있는 검사 결과는 화면에서 직접 고르면 돼요.
{% endhint %}

## Number Validation 트리거 활용 예시

검사 결과를 활용하면 사용할 수 없는 전화번호가 나왔다고 해서 CRM 기록 전체를 지우지 않고도 연락처를 자동화 안에서 알맞게 이어 갈 수 있어요.

### SMS 수신 가능 여부에 따라 연락처 나누기

검사 결과로 연락처가 SMS 중심 프로세스를 계속 진행해야 하는지 판단해요.

예를 들면 이렇게 쓸 수 있어요.

검사 결과 → SMS를 받을 수 있는 번호 → SMS 워크플로우 계속 진행

또는

검사 결과 → SMS를 받으면 안 되는 번호 → 다른 후속 연락 경로

### 전화번호 문제를 팀에 알리기

검사 결과가 전화번호 정보 확인이 필요하다는 뜻이면 내부 알림을 보내요. 그러면 팀이 연락처 정보를 확인하거나 알맞게 고칠 수 있어요.

### 검사 결과별로 연락처 분류하기

워크플로우 액션으로 다음 작업을 할 수 있어요.

- 태그를 추가해요.
- 커스텀 필드를 업데이트해요.
- 관련 연락처 정보를 추가해요.
- 연락처를 다른 워크플로우로 보내요.

이렇게 하면 전화번호 정보를 추가로 검토해야 할 수 있는 연락처를 팀이 쉽게 구분할 수 있어요.

### 최신 연락처 정보 요청하기

SMS를 보낼 수 없는 전화번호라면 연락처를 올바른 정보를 받아 내는 프로세스로 보내요. 연락처의 수신 권한과 가진 정보에 따라서는 적절한 경우 다른 연락 방법을 쓸 수도 있어요.

{% hint style="warning" %}
전화번호가 유효하지 않거나 SMS를 받을 수 없다는 검사 결과가 나왔다는 이유만으로 CRM 연락처를 자동으로 삭제하지 마세요. 그 연락처에 유용한 정보가 남아 있거나, 다른 적절한 방법으로 연락할 수 있을 수 있어요.
{% endhint %}

## Number Validation과 메시지 오류의 차이

Number Validation과 메시지 오류 트리거는 해결하는 문제가 달라요. 차이를 알아 두면 워크플로우를 올바른 이벤트에서 시작할 수 있어요.

| 트리거 유형 | 사용 목적 |
| --- | --- |
| **Number Validation** | 해당하는 첫 번째 발신 SMS 전에 번호 인텔리전스의 검사 결과에 반응할 때 |
| **Messaging Error / SMS Error** | SMS 전송을 시도하는 중이나 시도한 뒤에 발생한 오류에 반응할 때 |

예를 들어 번호 인텔리전스가 어떤 번호에 SMS를 보내면 안 된다고 판단했다면 **Number Validation**을 사용해요.

SMS를 보내려고 시도했는데 메시지 제공업체가 나중에 전송 오류를 돌려줬다면 해당하는 **Messaging Error** 트리거를 대신 사용해요.

## 자주 묻는 질문

### Number Validation은 언제 실행되나요?
Number Validation은 해당하는 첫 번째 발신 SMS를 그 전화번호로 보내기 전에 실행돼요. 연락처를 만들거나 가져오는 것만으로는 Number Validation이 실행되지 않아요.

### SMS를 보낼 때마다 Number Validation이 실행되나요?
Number Validation은 수신 번호의 해당하는 첫 번째 발신 SMS 검사 이벤트를 기준으로 동작하도록 만들어졌어요. SMS 하나하나마다 새로 검사를 요청하는 것으로 보면 안 돼요.

### Twilio에서 SMS 오류를 돌려주면 Number Validation 트리거가 실행되나요?
아니요. 이 트리거는 번호 인텔리전스의 검사 결과를 기준으로 해요. SMS 전송 오류에 반응하는 자동화가 필요하면 해당하는 메시지 오류 워크플로우 트리거를 사용하세요.

### 기존 연락처에도 Number Validation을 쓸 수 있나요?
네. 하이퍼클래스가 그 전화번호로 보낼 해당하는 첫 번째 발신 SMS를 준비할 때, 기존 연락처도 해당 검사 이벤트에 도달할 수 있어요. 연락처를 만들거나 가져오는 것만으로는 검사가 실행되지 않아요.

### 유효한 전화번호이면 SMS를 보낼 권한이 있다는 뜻인가요?
아니요. Number Validation은 전화번호가 유효한지, SMS를 받을 수 있는지를 확인해요. 연락처가 메시지 수신에 옵트인했는지, 동의했는지는 확인하지 않아요.
