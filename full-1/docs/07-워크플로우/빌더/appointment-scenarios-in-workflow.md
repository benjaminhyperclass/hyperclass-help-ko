# 워크플로우 예약 시나리오 — Customer Booked Appointment(고객 예약 완료) 트리거 동작

고객이 예약하는 상황은 여러 가지예요. 이 문서에서는 상황별로 워크플로우가 어떻게 동작하는지, 연락처가 워크플로우에서 어떤 경로를 거치는지 설명해요.

## 시나리오 1 - 예약했을 때 연락처가 다시 진입하는 경우

고객은 한 번에 여러 건을 예약할 수 있어요. 그래서 **Appointment**(예약) 트리거는 연락처가 이미 워크플로우에 있어도 다시 진입할 수 있어요.

연락처가 예약을 여러 번 할 수 있으므로, **Allow Re-entry**(재진입 허용) 설정이나 이미 워크플로우에 있는지 여부와 상관없이 여러 번 진입할 수 있어야 해요.

## 시나리오 2 - 예약을 취소한 경우

**예시**

- 현재 날짜: 6월 20일
- 예약 날짜: 6월 25일
- 워크플로우 단계: 연락처가 "5일 대기" 단계에 있어요.

**변경 상황:** 고객이 예약을 취소해요.

**예약을 "취소됨"으로 처리하는 경우:** 예약 상태가 **New**(신규)/**Confirmed**(확정)/**Show**(참석)에서 **Cancel**(취소)/**Invalid**(유효하지 않음)/**No Show**(불참)로 바뀌면 예약을 **Cancelled**(취소됨)로 처리해요.

**결과:** 고객은 워크플로우에서 빠지고, 이후 액션은 실행되지 않아요.

**이유:** 연락처가 예약을 취소했으니 더 이상 액션을 실행하지 않아야 해요.

---

## 시나리오 3 - 이후 날짜로 일정을 변경한 경우

**예시**

- 현재 날짜: 6월 20일
- 기존 예약 날짜: 6월 25일
- 새 예약 날짜: 6월 30일
- 워크플로우 단계: 연락처가 "5일 대기" 단계에 있어요.

**변경 상황:** 고객이 예약을 6월 30일로 변경해요.

**예약을 "일정 변경됨"으로 처리하는 경우:** 예약의 **시작 시간**과 **종료 시간**이 바뀌면 **Rescheduled**(일정 변경됨)로 처리해요.

**결과:** 연락처는 워크플로우에서 빠져요. 워크플로우에 **Appointment Status**(예약 상태)가 **Rescheduled**일 때 실행되는 트리거가 있고, 일정이 변경된 예약이 트리거 필터 조건(예: 캘린더, 담당 사용자)을 모두 만족하면 연락처가 워크플로우에 다시 진입해요. 단, 워크플로우 설정에서 **Allow Re-entry**가 켜져 있을 때만 다시 진입해요.

<!-- 검토 필요: 원문 내용이 서로 다름 (시나리오 1은 Allow Re-entry와 상관없이 여러 번 진입한다고 설명하고, 시나리오 3은 Allow Re-entry가 켜져 있어야 다시 진입한다고 설명함) -->

**이유:** 예약 일정이 바뀌면(시작 시간이나 종료 시간 중 하나 또는 둘 다 변경) 예약 상태가 업데이트돼요. 업데이트된 상태가 **Allow Re-entry**를 켠 워크플로우 트리거의 조건과 맞으면, 연락처가 다시 진입해서 새 예약 시간에 맞는 메시지를 계속 받을 수 있어요. 조건이 맞지 않으면 워크플로우에 다시 진입하지 않아요.

---

## 시나리오 4 - 반복 예약

반복 예약은 **Customer Booked Appointment**(고객이 예약함) 트리거로 워크플로우에 진입하지 않아요.
