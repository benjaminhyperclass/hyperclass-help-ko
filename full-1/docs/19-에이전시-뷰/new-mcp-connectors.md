# 새 MCP 커넥터: Clay, Lemlist, Airtable, Composio, Reap 연결하기

Clay, Lemlist, Airtable, Composio, Reap 커넥터를 연결하면 AI 에이전트가 외부 도구를 안전하게 사용해 데이터 보강, 아웃리치 자동화, 레코드 관리, 연결된 앱 사용, 영상 재가공까지 할 수 있어요. 이 문서에서는 새 커넥터의 용도와 설정 방법, 테스트 방법을 안내해요.

## 이 문서에서 알아볼 내용

하이퍼클래스의 MCP 커넥터 카탈로그에 **Clay**, **Lemlist**, **Airtable**, **Composio**, **Reap** 다섯 개 앱이 추가됐어요. 이 커넥터를 쓰면 관리형 에이전트와 AI에게 문의가 CRM 기본 액션을 넘어, 연결한 외부 계정의 도구를 제어된 범위 안에서 사용할 수 있어요.

이 문서에서 다루는 내용은 다음과 같아요.

- 새 커넥터가 각각 어떤 용도인지
- MCP 앱이 관리형 에이전트와 AI에게 문의에서 어떻게 동작하는지
- 에이전트가 사용할 도구를 고르는 방법
- 실제 자동화에 쓰기 전에 커넥터를 테스트하는 방법

## 지금 사용할 수 있어요

Clay, Lemlist, Airtable, Composio, Reap을 MCP 커넥터 카탈로그에서 바로 쓸 수 있어요. 하이퍼클래스 AI 기능에서 쓸 수 있는 기존 외부 연동 목록에 함께 포함돼요.

## 새 MCP 커넥터란?

MCP(Model Context Protocol)는 AI 에이전트가 외부 앱에 연결해 그 앱이 제공하는 도구를 쓸 수 있게 해 주는 표준 방식이에요. 하이퍼클래스에서는 MCP 앱 커넥터를 통해 관리형 에이전트와 AI에게 문의가 인증된 외부 서비스와 함께 일할 수 있어요. 연동을 일일이 직접 만들 필요가 없어요.

MCP 앱을 연결한 뒤에는 AI가 쓸 수 있는 도구를 직접 정해요. 관리형 에이전트는 트리거와 지침에서 필요하다고 할 때 그 도구를 호출해요. AI에게 문의는 사용자가 요청하면 활성화된 커넥터 도구를 사용해 답해요.

커넥터 기본 개념은 [관리형 에이전트용 MCP 커넥터](../13-AI-Employee/MCP-Server/mcp-connectors-for-managed-agents.md) 문서에서도 볼 수 있어요.

### MCP 커넥터의 장점

MCP 커넥터를 쓰면 AI 자동화를 하이퍼클래스 밖의 서비스까지 넓힐 수 있어요. 에이전트가 외부 앱의 기능 중 선택한 것만 안전하게 쓰기 때문에, 활용 사례마다 연동을 따로 만들지 않아도 돼요.

- 더 많은 외부 액션: AI 에이전트가 연결된 외부 앱의 지원 도구를 사용할 수 있어요.
- 도구 접근 제어: 연결한 앱이 제공하는 도구 중 에이전트가 쓸 도구를 직접 골라요.
- 안전한 연결: 에이전트 지침에 인증 정보를 넣지 않고, 커넥터가 지원하는 OAuth 또는 보안 로그인 방식으로 인증해요.
- 여러 앱을 쓰는 에이전트: 하나의 워크플로우가 여러 시스템에 걸쳐 있으면 관리형 에이전트 하나에 MCP 앱을 여러 개 연결할 수 있어요.
- 더 빠른 자동화: 작업마다 API 호출을 직접 설정하지 않고, 미리 만들어진 앱 기능을 추가해요.
- 더 넓은 AI 워크플로우: CRM 이벤트, AI 판단, 외부 앱을 하나의 에이전트 워크플로우로 묶을 수 있어요.

### 새로 추가된 MCP 커넥터 5개

커넥터마다 AI 에이전트가 할 수 있는 일이 달라져요. 에이전트에게 맡기려는 작업이 외부 데이터, 아웃리치, 레코드 관리, 멀티 앱 자동화, 콘텐츠 제작 중 무엇인지에 맞춰 앱을 고르세요.

| 커넥터 | 할 수 있는 일 | 사용 예시 |
| --- | --- | --- |
| Clay | 100개 이상의 출처에서 가져온 회사·연락처 데이터, 보강 워터폴, 아웃바운드 준비 도구로 리드 목록을 만들고 보강해요. | 새로 만들어진 리드를 영업팀에 배정하기 전에 정보를 보강해요. |
| Lemlist | 리드 발굴, 이메일과 LinkedIn을 함께 쓰는 멀티채널 시퀀스, 캠페인 관리 같은 콜드 아웃리치 작업을 해요. | 조건에 맞는 잠재 고객을 알맞은 아웃바운드 캠페인에 추가해요. |
| Airtable | 연결된 Airtable 테이블과 뷰에서 커넥터가 제공하는 도구로 레코드를 읽고, 만들고, 업데이트해요. | 고객이 온보딩을 마치면 프로젝트 레코드를 만들어요. |
| Composio | 하나의 관리형 게이트웨이로 1,000개 이상의 도구에 접근해요. 지원되는 인증을 처리하고, 에이전트가 연결된 앱의 액션을 쓸 수 있게 해요. | 여러 외부 시스템에서 작업해야 하는 에이전트를 만들어요. |
| Reap | 긴 영상을 짧은 클립으로 재가공해요. 자막, 더빙, 번역 기능을 지원해요. | 긴 녹화본을 콘텐츠 워크플로우에 바로 쓸 수 있는 숏폼 자료로 바꿔요. |

{% hint style="warning" %}
**중요:** 사용할 수 있는 도구는 커넥터, 연결한 계정, 외부 서비스의 권한, 이후 커넥터 업데이트에 따라 달라질 수 있어요. 에이전트를 게시하기 전에 설정 중에 표시되는 도구 목록을 확인하세요.
{% endhint %}

## MCP 커넥터와 관리형 에이전트

커넥터는 에이전트에게 외부 도구를 쓸 수 있게 해 줄 뿐이에요. 에이전트가 언제 실행되고 무엇을 할지는 커넥터가 정하지 않아요. 관리형 에이전트는 트리거, 지침, 앱, 기능, 선택 사항인 지식 베이스를 조합해 구성하고, 각 요소가 맡는 역할이 분명해요.

### 트리거는 에이전트가 실행되는 때를 정해요

설정한 이벤트가 일어나면 트리거가 관리형 에이전트를 시작해요. 예를 들어 연락처가 만들어질 때, 기회가 만들어질 때, 리드 확보용 폼이 제출될 때 에이전트가 실행되게 할 수 있어요.

### 앱은 에이전트가 쓸 외부 시스템을 정해요

**앱** 영역에는 관리형 에이전트에 지정한 MCP 커넥터가 모여 있어요. 지침에 따라 여러 외부 앱에서 작업해야 한다면 에이전트 하나에 커넥터를 둘 이상 연결할 수 있어요.

### 지침은 에이전트가 할 일을 알려 줘요

지침에는 외부 도구를 언제 쓸지, 어떤 정보를 넘길지, 어떤 결과를 내야 하는지를 분명하게 적어요. 커넥터에 접근할 수 있다고 해서 실행할 때마다 모든 도구가 호출되는 것은 아니에요.

![관리형 에이전트의 앱 영역 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155080665834/original/cHjstd7zZKESrYYXP1AKrsCTnOj7w9Ftow.png?1789107309)

{% hint style="info" %}
**참고:** 스크린샷에는 Notion이나 HubSpot 같은 기존 커넥터가 예시로 나올 수 있어요. 현재 카탈로그의 커넥터를 추가할 때도 같은 **앱** 설정 흐름을 써요. 도구 개수는 커넥터가 업데이트되면서 달라질 수 있어요.
{% endhint %}

## 관리형 에이전트와 AI에게 문의의 MCP 커넥터 비교

관리형 에이전트와 AI에게 문의 모두 MCP 커넥터를 쓸 수 있지만, 자동화 방식이 달라요. 관리형 에이전트는 트리거에 따라 자율적으로 일하도록 만들어졌어요. AI에게 문의는 사용자의 요청에 따라 연결된 도구를 써요.

| 구분 | 관리형 에이전트 | AI에게 문의 |
| --- | --- | --- |
| 작업이 시작되는 방식 | 설정한 트리거 또는 지원되는 에이전트 이벤트 | 사용자가 AI에게 문의에 작업을 요청 |
| 커넥터를 설정하는 곳 | 관리형 에이전트 안의 **앱** 영역 | **커스터마이징 > 커넥터 > 커넥터 관리** |
| 주로 쓰는 경우 | 반복되거나 이벤트에 따라 실행되는 자동화 | 사용자가 직접 시작하는 대화형 작업 |
| 도구 제어 | 에이전트가 쓸 커넥터 도구를 선택 | 커넥터를 활성화하고 쓸 수 있는 도구를 제어 |

관리형 에이전트, 대화 AI, AI에게 문의의 차이는 [관리형 에이전트, 대화 AI, AI에게 문의: 무엇이 다른가요?](../13-AI-Employee/Agent-Studio/managed-agents-conversation-ai-ask-ai-what-s-the-difference.md) 문서에서 자세히 볼 수 있어요.

## 새 MCP 커넥터 설정하고 사용하기

AI가 작업에 필요한 외부 계정과 도구에만 접근하도록 설정하세요. 앱을 연결하고, 권한을 확인하고, 알맞은 도구를 고른 다음, 실제 운영에 쓰기 전에 동작을 테스트하세요.

### 방법 1: 관리형 에이전트에 MCP 앱 연결하기

관리형 에이전트는 이벤트에 따라 실행되는 자동화에서 MCP 앱을 사용해요. 에이전트의 목적에 맞게 접근 범위를 유지하려면, 도구가 필요한 에이전트에만 앱을 연결하세요.

관리형 에이전트 설정에 대한 전체 안내는 [에이전트 스튜디오에서 관리형 에이전트 설정하고 사용하기](../13-AI-Employee/Agent-Studio/setup-and-use-managed-agents-in-agent-studio.md) 문서를 참고하세요.

#### 1단계: 관리형 에이전트 열기

관리형 에이전트는 에이전트 스튜디오에서 설정해요. 여기서 에이전트의 지침, 트리거, 앱, 기능, 지식 베이스, 테스트, 게시 상태를 정할 수 있어요.

1. **AI 에이전트 > 에이전트 스튜디오**로 이동하세요.
2. **관리형 에이전트**를 여세요.
3. 새 관리형 에이전트를 만들거나 기존 에이전트를 여세요.

#### 2단계: MCP 앱 추가하기

**앱** 영역에서 에이전트가 쓸 수 있는 외부 커넥터를 정해요. 에이전트가 맡을 자동화와 관련 있는 커넥터만 추가하세요.

1. **앱** 영역을 찾으세요.
2. **앱 추가**를 클릭하세요.
3. MCP 카탈로그를 둘러보거나 검색하세요.
4. **Clay**, **Lemlist**, **Airtable**, **Composio**, **Reap** 또는 지원되는 다른 커넥터를 선택하세요.

#### 3단계: 외부 계정 연결하기

인증을 해야 커넥터가 외부 서비스에서 허용한 권한 안에서 동작해요. 커넥터에 표시되는 OAuth 또는 보안 로그인 방식을 따르세요.

1. MCP 앱을 선택하세요.
2. 계정 연결 또는 계정 추가 옵션을 클릭하세요.
3. 해당 외부 서비스 계정으로 로그인하세요.
4. 요청된 접근 권한을 확인하고 승인하세요.

#### 4단계: 에이전트가 쓸 도구 선택하기

도구를 선택하면 에이전트에게 열어 줄 구체적인 액션이 정해져요. 사용 목적에 필요한 도구만 열어 두면 에이전트가 할 수 있는 일을 파악하고, 테스트하고, 관리하기 쉬워요.

1. 커넥터에서 쓸 수 있는 도구를 확인하세요.
2. 에이전트에 필요한 도구를 선택하세요.
3. 필요하지 않은 도구는 비활성화한 채로 두세요.
4. **저장**을 클릭하세요.

![MCP 앱의 도구 선택 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155080665931/original/9wjn7Ig_Odkx_N-vCllS9FJeNsCO2sNPqg.png?1789107339)

#### 5단계: **에이전트 지침** 업데이트하기

커넥터를 언제, 왜 써야 하는지 에이전트에게 분명하게 알려 줘야 해요. 지침이 좋으면 불필요한 도구 호출이 줄고, 기대하는 결과를 테스트하기도 쉬워져요.

지침에는 다음 내용을 넣으세요.

- 어떤 상황에서 외부 앱이 필요한지
- 에이전트가 어떤 데이터를 읽거나 보내야 하는지
- 에이전트가 어떤 액션을 해도 되는지
- 에이전트가 언제 확인 질문을 해야 하는지
- 커넥터가 오류를 반환하거나 결과가 없을 때 에이전트가 어떻게 해야 하는지

#### 6단계: 트리거 설정하기

트리거는 관리형 에이전트가 작업을 시작하는 때를 정해요. 연결한 앱의 액션에 알맞은 맥락을 줄 수 있는 이벤트를 고르세요.

예를 들어 리드 보강 에이전트는 연락처가 만들어질 때 실행되게 하고, 후속 조치 에이전트는 폼이 제출되거나 지원되는 다른 CRM 이벤트가 일어난 뒤에 실행되게 할 수 있어요.

#### 7단계: 에이전트 테스트하기

테스트로 올바른 커넥터와 도구가 선택되는지, 외부 계정이 기대한 정보를 돌려주는지, 에이전트가 지침의 제한을 지키는지 확인해요.

1. **에이전트 테스트**를 클릭하세요.
2. 실제 상황을 대표하는 테스트 데이터를 사용하세요.
3. 올바른 MCP 도구가 호출되는지 확인하세요.
4. 기대한 결과가 외부 앱에 나타나는지 확인하세요.
5. 결과가 맞지 않으면 지침이나 도구 권한을 고치세요.

#### 8단계: 관리형 에이전트 게시하기

게시하면 테스트를 마친 설정이 실제로 실행돼요. 트리거, 외부 계정, 도구 권한, 에이전트 지침이 의도대로 동작하는지 확인한 뒤에 게시하세요.

![관리형 에이전트 게시 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155080665965/original/qRmPY3BS7TJ83n0fVMVrngKs2qHdqTmW1Q.png?1789107359)

### 방법 2: AI에게 문의에서 MCP 앱 연결하기

AI에게 문의의 커넥터는 사용자가 직접 시작하는 작업을 위한 기능이에요. 앱을 한 번 연결하고 활성화할 도구를 정해 두면, 그 계정으로 AI에게 문의에 작업을 요청할 수 있어요.

AI에게 문의의 스킬과 커넥터는 [AI에게 문의 스킬과 커넥터](../13-AI-Employee/Ask-AI/ask-ai-skills-and-connectors.md) 문서에서, AI 에이전트용 스킬은 [AI 에이전트용 스킬 플랫폼](skills-platform-for-ai-agents.md) 문서에서 자세히 볼 수 있어요.

1. **AI에게 문의**를 여세요.
2. **커스터마이징 > 커넥터**로 이동하세요.
3. **커넥터 관리**를 선택하세요.
4. 사용할 MCP 앱을 찾으세요.
5. 해당 외부 서비스 계정을 연결하고 인증하세요.
6. AI에게 문의가 쓸 수 있게 할 도구를 확인하고 활성화하세요.
7. 커넥터를 활성화하세요.
8. 채팅을 시작하고, 연결한 앱이 필요한 요청을 AI에게 문의에 분명하게 전달하세요.

## 보안 및 접근 권한 모범 사례

MCP 커넥터를 쓰면 AI가 외부 시스템에서 실제 작업을 할 수 있어요. 그래서 커넥터 접근 범위는 에이전트가 맡은 일에 딱 맞춰야 해요. 계정, 도구, 지침을 제한하면 불필요한 접근이 줄고, 운영 중인 동작을 점검하기도 쉬워요.

- 필요한 접근 권한만 부여하기: 에이전트의 업무에 필요한 최소한의 외부 서비스 권한만 승인하세요.
- 필요한 도구만 선택하기: 에이전트가 일부 도구만 필요하다면 쓸 수 있는 도구를 전부 켜지 마세요.
- 프롬프트에 인증 정보 넣지 않기: 비밀번호, API 키, 로그인 정보를 에이전트 지침에 넣지 말고 커넥터의 인증 절차를 이용하세요.
- 명확한 가드레일 작성하기: 에이전트가 할 수 있는 액션과, 확인이나 에스컬레이션이 필요한 상황을 알려 주세요.
- 실제와 비슷한 입력으로 테스트하기: 에이전트를 실제 트리거에 연결하기 전에 읽기·쓰기 액션을 확인하세요.
- 외부 서비스의 요구 사항 확인하기: 앱에 따라 별도의 계정, 요금제, 권한, 기능 접근이 필요할 수 있어요.
- 커넥터 업데이트 후 도구 다시 확인하기: MCP 연동이 기능을 추가하거나 바꾸면 사용 가능한 도구 목록도 달라질 수 있어요.

## MCP 커넥터 문제 해결

MCP 커넥터 문제는 대부분 인증, 외부 서비스 권한, 도구 선택, 모호한 에이전트 지침에서 생겨요. 각 단계를 따로 점검해서 연결, 도구, 에이전트 동작 중 무엇을 고쳐야 하는지 찾아보세요.

| 증상 | 확인할 내용 |
| --- | --- |
| 앱은 연결됐는데 에이전트가 쓰지 못해요 | 커넥터가 올바른 에이전트에 연결돼 있는지, 필요한 개별 도구가 활성화돼 있는지 확인하세요. |
| 인증이 실패해요 | 앱을 다시 연결하고, 외부 서비스 계정 정보가 맞는지, 그 계정이 요청된 접근을 승인할 수 있는지 확인하세요. |
| 필요한 도구가 보이지 않아요 | 커넥터의 현재 도구 목록과, 연결한 외부 서비스 계정에 있는 권한이나 요금제를 확인하세요. |
| 에이전트가 엉뚱한 외부 액션을 써요 | 불필요한 도구 접근을 줄이고, 도구별로 언제 써야 하는지 에이전트 지침에 더 분명하게 적으세요. |
| 관리형 에이전트가 실행되지 않아요 | 의도한 트리거가 설정돼 있는지, 에이전트가 게시됐는지, 테스트 이벤트가 트리거 조건과 맞는지 확인하세요. |
| 전에는 잘 되던 커넥터가 이제 실패해요 | 승인이 취소됐거나 만료됐는지 확인한 뒤, 외부 서비스 계정을 다시 연결하고 도구를 다시 테스트하세요. |
| AI에게 문의가 커넥터를 쓰지 않아요 | 커넥터가 활성화돼 있는지, 필요한 도구가 허용돼 있는지, 요청이 연결한 앱이 필요한 액션을 분명하게 요구하는지 확인하세요. |

## 자주 묻는 질문

### Clay, Lemlist, Airtable, Composio, Reap이 기존 MCP 커넥터를 대체하나요?

아니요. 이 앱들은 기존 MCP 커넥터 카탈로그를 넓힐 뿐, 현재 커넥터를 대체하지 않아요.

### 관리형 에이전트 하나가 MCP 커넥터를 여러 개 쓸 수 있나요?

네. 에이전트가 여러 외부 시스템에서 일해야 하면 MCP 앱을 여러 개 연결할 수 있어요. 각 커넥터를 언제 써야 하는지 지침에 분명하게 적어 두세요.

### MCP 커넥터를 추가하면 관리형 에이전트가 자동으로 실행되나요?

아니요. 커넥터는 외부 도구를 제공할 뿐이에요. 에이전트가 언제 실행되고 어떤 액션을 할지는 관리형 에이전트의 트리거와 지침으로 정해요.

### MCP 앱이 에이전트에게 열어 주는 도구를 제어할 수 있나요?

네. 앱을 연결한 뒤 쓸 수 있는 도구 목록을 확인하고, 에이전트의 사용 목적에 필요한 도구만 활성화하세요.

### 외부 앱의 계정이 있어야 하나요?

대체로 외부 서비스에서 자격이 있는 계정을 인증해야 해요. 필요한 요금제, 권한, 기능은 앱마다 다를 수 있어요.

### AI에게 문의에서도 이 MCP 커넥터를 쓸 수 있나요?

네. 이번 업데이트는 관리형 에이전트와 AI에게 문의 모두에 적용돼요. AI에게 문의의 커넥터는 **커스터마이징 > 커넥터 > 커넥터 관리**에서 관리해요.

### 카탈로그 MCP 커넥터와 사용자 지정 MCP 커넥터는 같은 건가요?

아니요. 카탈로그 커넥터는 MCP 앱 카탈로그에서 제공하는, 미리 만들어진 연동이에요. 사용자 지정 MCP 연결은 호환되는 다른 MCP 서버를 연결하는 별도의 설정 방법이에요. 자세한 내용은 [관리형 에이전트용 사용자 지정 MCP 커넥터](../13-AI-Employee/Agent-Studio/custom-mcp-connectors-for-managed-agents-agent-studio.md) 문서를 참고하세요.

### 스크린샷과 커넥터의 도구 개수가 달라요. 왜 그런가요?

커넥터가 업데이트되면서 도구 개수가 바뀔 수 있어요. 에이전트가 쓸 수 있는 액션은 내 계정에 표시되는 현재 도구 목록을 기준으로 확인하세요.
