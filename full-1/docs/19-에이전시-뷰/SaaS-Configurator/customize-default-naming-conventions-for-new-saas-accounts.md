# 새 SaaS 계정의 기본 이름 규칙 설정

**SaaS 구성기**(SaaS Configurator)에서 새 SaaS 서브 계정이 만들어질 때 어떤 이름을 붙일지 정할 수 있어요. 고객 이름과 회사명 중에서 고를 수 있어요. 온보딩 후에 이름을 고치는 일이 줄고, 검색·리포트·고객 안내에서도 계정을 알아보기 쉬워져요. 이 문서에서는 각 옵션의 동작과 설정 방법, 외부 결제 페이지를 쓸 때 필요한 조건을 설명해요.

## 새 SaaS 서브 계정의 기본 이름 규칙이란?

이 설정은 고객이 결제할 때 하이퍼클래스가 **새 SaaS 서브 계정**을 만들면서 붙이는 기본 이름을 정해요. 에이전시는 두 가지 중에 고를 수 있어요.

- **회사명**: 고객이 결제 중에 입력한 회사명을 써요.
- **고객 이름 + ’s Account**: 기존 방식이에요.

선택한 내용은 **이후** 가입 건에만 적용돼요. 이미 있는 계정의 이름은 바뀌지 않아요.

{% hint style="info" %}
이 옵션은 에이전시 수준의 **SaaS 구성기**에 있어요. SaaS 모드를 $497 Founder Plan으로 쓰는 에이전시에서 사용할 수 있어요. Starter나 Unlimited 플랜이라면 Founder Plan으로 업그레이드해야 **SaaS 구성기** 기능을 쓸 수 있어요.
{% endhint %}

## 이 설정을 쓰면 좋은 점

- 명확성 향상: 서브 계정 이름에 구매자 개인 이름만 보이지 않고, 실제로 운영하는 사업체 이름이 나타나요.
- 고객 경험 개선: 원하는 이름 규칙이 자동으로 적용되어, 온보딩 후 직접 이름을 고치는 일이 줄어요.
- 운영 효율: 지원팀과 성공팀이 계정을 검색하고 필터링하고 알아보기가 쉬워져요.
- 유연한 선택: 팀의 업무 방식에 맞춰 **회사명**과 **고객 이름 + ’s Account** 중에서 바꿀 수 있어요.

## 기본 이름 규칙 설정하기

1. 에이전시 화면에서 **SaaS 구성기 > 고급 설정 > 서브 계정 온보딩**을 열어요.
2. **서브 계정 온보딩**에서 둘 중 하나를 선택해요.
   - **회사명**: 사업체 이름이 한눈에 보여서 추천해요.
   - **고객 이름 + ’s Account**: 팀에서 주로 계정 소유자 이름으로 검색할 때 유용해요.
3. **저장**을 클릭해요.

이제 하이퍼클래스 퍼널(그리고 지원되는 외부 결제 페이지)로 만들어지는 새 SaaS 서브 계정에는 선택한 규칙이 적용돼요.

## 이름 규칙 옵션 비교

각 옵션이 어떻게 동작하는지 확인하고, 팀이 새 고객을 구분하고 지원하는 방식에 맞는 기본값을 고르세요.

|  | **회사명** | **고객 이름 + ’s Account** |
| --- | --- | --- |
| 사용하는 이름 | 결제 시 입력한 회사명 | 고객의 개인 이름 |
| 예시 | Acme Dental | Jane Smith’s Account |
| 이런 경우에 적합 | 사업체별로 계정을 정리하는 에이전시 | 계정 소유자별로 계정을 정리하는 에이전시 |
| 대체 이름 | **회사명**이 없으면 고객 이름 + ’s Account | 해당 없음 |

{% hint style="info" %}
결제 중에 **회사명** 필드가 없거나 비어 있으면, 하이퍼클래스는 기본으로 고객 이름 + ’s Account를 사용해요.
{% endhint %}

## 외부 결제 페이지 연동

외부 결제 페이지에서 고객의 회사명을 메타데이터로 하이퍼클래스에 전달하면, 하이퍼클래스 퍼널이 아닌 곳에서도 같은 이름 규칙을 적용할 수 있어요.

- 외부 결제 페이지가 비어 있지 않은 `companyName` 구독 메타데이터 값을 보내도록 설정하세요.
- **SaaS 구성기**를 **Use Company Name**(회사명 사용)으로 유지하세요. 메타데이터가 있으면 회사명이 적용돼요.
- `companyName`이 없거나 비어 있으면 하이퍼클래스는 고객 이름 + ’s Account로 대체해요.

메타데이터 예시(설명용):

```
{
"subscription": {
"metadata": {
"companyName": "Acme Dental"
}
}
}
```

## 동작 방식과 예시

가입 후 에이전시와 고객에게 어떻게 보이는지 간단한 예시로 확인해 보세요.

- **회사명**을 선택했고 결제 때 회사명을 입력한 경우:
  - 만들어지는 서브 계정 이름: Acme Dental
- **회사명**을 선택했지만 결제 때 회사명을 입력하지 않은 경우:
  - 만들어지는 서브 계정 이름: Jane Smith’s Account (고객 이름으로 대체)
- **고객 이름 + ’s Account**를 선택한 경우:
  - 만들어지는 서브 계정 이름: Jane Smith’s Account

{% hint style="info" %}
계정 생성 후에 관리자는 필요하면 위치의 **비즈니스 표시명**을 나중에 수정할 수 있어요. 이름을 나중에 바꿔도, 이미 발송된 확인 메시지나 이메일의 내용은 바뀌지 않아요.
{% endhint %}

## 회사명 수집

하이퍼클래스는 고객이 결제할 때 입력한 회사명을 수집해서 구독 메타데이터의 `companyName`으로 포함해요.

다음 경우에 적용돼요.

- 결제 기능을 사용하는 V2 퍼널 (API로 메타데이터 전달)
- Stripe를 사용하는 SaaS V1 설정 (Stripe로 메타데이터 전달)

## 자주 묻는 질문

### 이 설정이 이미 있는 SaaS 계정에도 적용되나요?
아니요. 설정을 저장한 뒤에 새로 가입하는 SaaS 계정에만 적용돼요.

### 결제 때 회사명을 입력하지 않으면 어떻게 되나요?
하이퍼클래스는 기본으로 고객 이름 + ’s Account를 사용해요.

### 기본 이름 규칙을 나중에 바꿀 수 있나요?
네. **SaaS 구성기**에서 언제든 옵션을 바꿀 수 있어요. 바꾼 옵션은 이후 가입 건부터 적용돼요.

### 외부 결제 페이지에서 쓰려면 어떻게 하나요?
구독 메타데이터에 비어 있지 않은 `companyName`을 보내고, 설정을 **Use Company Name**(회사명 사용)으로 유지하세요.

### 설정을 바꾸면 이미 만들어진 계정의 이름도 바뀌나요?
아니요. 이미 만들어진 계정의 이름은 소급해서 바뀌지 않아요.

### 이 설정이 커뮤니케이션에서 쓰는 `{{location.name}}` 같은 병합 필드에도 영향을 주나요?
계정이 만들어질 때 처음 붙는 위치 이름에 선택한 이름 규칙이 반영돼요. `{{location.name}}`을 쓴 메시지에는 그 이름이 표시돼요. 나중에 **Location settings**(위치 설정)에서 이름을 고치면 고친 이름이 표시돼요.

### 회사명에 특수 문자가 있으면 문제가 생기나요?
가능하면 일반적인 영문자와 숫자를 쓰는 것이 가장 안정적이에요. 외부 결제 페이지에서 이름이 받아들여지지 않거나 이름이 이상하게 표시되면, 계정을 만든 뒤에 **위치 이름**을 수정하세요.
