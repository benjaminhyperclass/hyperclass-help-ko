# IP 평판이 낮을 때: 발송 IP 신뢰도 되살리기

공유 IP와 전용 IP로 이메일을 보내는 분들이 IP 단위의 평판 문제를 진단하고 회복하는 방법을 안내해요. 이메일이 차단되거나 거부될 때 확인해 보세요.

## 어떤 상황인가요?

발송 IP 주소의 평판이 이메일 서비스 제공업체와 보안 서비스에서 나빠져, 이메일이 차단되거나 거부되고 있는 상태예요. 도메인 평판은 도메인에 묶여 있지만, IP 평판은 이메일을 보내는 특정 서버나 인프라에 묶여 있어요. 하이퍼클래스에서는 지금 쓰고 있는 IP 인프라의 평판을 발송 방식 개선과 올바른 목록 관리로 회복해야 한다는 뜻이에요.

IP 평판 문제는 도메인 평판 문제보다 영향이 바로 나타나는 편이에요. 스팸함으로 들어가는 정도가 아니라 아예 차단될 수 있기 때문이에요. 다만 방법만 맞으면 IP 평판은 도메인 평판보다 빨리 회복할 수 있어요.

## 빠른 진단: IP 평판 문제 알아보기

아래와 같은 반송(bounce) 메시지가 보이면 IP 평판 문제일 수 있어요. 실제 반송 메시지는 영어로 표시되므로 원문 그대로 두고 뜻을 괄호로 적었어요.

### Outlook/Microsoft 차단

- "The sending server's IP address is on a block list, causing Outlook to reject the message" (발송 서버의 IP 주소가 차단 목록에 올라 Outlook이 메시지를 거부했어요)
- "The sending server's IP is blocked due to poor reputation or suspicious activity" (평판이 나쁘거나 의심스러운 활동 때문에 발송 서버의 IP가 차단됐어요)
- "The sending server's IP address is blocked or refused due to a history of abuse or suspicious activity" (악용이나 의심스러운 활동 이력 때문에 발송 서버의 IP 주소가 차단되거나 거부됐어요)

### 일반적인 IP 평판 문제

- "The sending server's IP is blocked or blacklisted due to poor reputation or spam reports" (평판이 나쁘거나 스팸 신고가 있어 발송 서버의 IP가 차단되거나 블랙리스트에 올랐어요)
- "The sending server's IP address has a poor reputation, causing the recipient to reject the message" (발송 서버의 IP 평판이 나빠 수신자가 메시지를 거부했어요)
- "The sending server's IP has a history of violating recipient policies, leading to mail being blocked" (발송 서버의 IP가 수신자 정책을 위반한 이력이 있어 메일이 차단됐어요)

### 블랙리스트와 관련된 IP 문제

- "The sending server's IP is on a blocklist, causing rejection by the recipient's email provider" (발송 서버의 IP가 차단 목록에 있어 수신자의 이메일 제공업체가 거부했어요)
- "The sending server's IP address is listed on one or more DNS-based blacklists" (발송 서버의 IP 주소가 하나 이상의 DNS 기반 블랙리스트에 올라 있어요)
- "The sending IP is listed on a reputation blocklist, causing the recipient server to reject the message" (발송 IP가 평판 차단 목록에 올라 수신 서버가 메시지를 거부했어요)
- "The sending IP or domain is listed on public blocklists due to suspected spam or abuse" (스팸이나 악용이 의심되어 발송 IP 또는 도메인이 공개 차단 목록에 올라 있어요)
- "The sending server's IP is blacklisted, causing email rejection" (발송 서버의 IP가 블랙리스트에 올라 이메일이 거부됐어요)

## IP 인프라 이해하기

### IP 구성 방식

#### 공유 IP (기본값, 전문 관리)

- 하이퍼클래스가 IP 평판을 우수하게 유지해요.
- IP 평판을 직접 관리하지 않아도 돼요.
- 대부분의 발송량에 알맞은 경제적인 방식이에요.
- 커뮤니티 전체의 좋은 발송 습관의 덕을 볼 수 있어요.
- 품질 좋은 여러 IP로 자동으로 부하가 분산돼요.
- 워밍업 없이 바로 보낼 수 있어요.
- 전문적인 모니터링과 유지 관리를 하이퍼클래스가 맡아요.

#### 전용 IP (대량 발송자가 사용 가능)

- 내 계정에만 배정되는 단독 IP 주소예요.
- IP 평판을 직접 완전히 관리할 수 있어요.
- 하이퍼클래스 안에서 SNDS 모니터링을 바로 볼 수 있어요.
- 고급 IP 분석과 리포트를 이용할 수 있어요.
- 꾸준히 대량으로 보내는 경우(월 150,000통 이상)에 알맞아요.
- 제대로 성능을 내려면 워밍업 과정이 필요해요.

### IP 평판과 도메인 평판의 차이

| 구분 | IP 평판 | 도메인 평판 |
| --- | --- | --- |
| 기준 | 이메일을 보내는 서버·인프라에 묶여 있어요 | 내가 보내는 특정 도메인에 묶여 있어요 |
| 관리 | 하이퍼클래스가 전문적으로 관리해요(공유 IP) | 내가 직접 관리해요 |
| 회복 | 올바른 방식으로 비교적 빠르게 회복할 수 있어요 | ESP를 바꿔도 그대로 따라다녀요 |
| 영향 | 더 즉각적이에요. 전달 속도에 영향을 줘요 | 받은편지함 도착 여부에 장기적으로 영향을 줘요 |

## 단계별 IP 평판 회복

### 1단계. 내 IP 구성 확인하기

**IP 설정을 확인해요.**

1. **이메일 서비스 열기**
   - **설정 > 이메일 서비스**로 이동하세요.
   - **Postmaster Tools**(포스트마스터 도구) 탭을 쓸 수 있는지 확인하세요.
   - **Microsoft SNDS**(Microsoft의 IP 평판 확인 도구) 섹션이 있는지 확인하세요.
2. **IP 유형 판단하기**
   - **SNDS 데이터가 보이면** 전용 IP를 쓰고 있어요.
   - **"IP not found in your account"가 보이면** 공유 IP를 쓰고 있어요. 공유 IP도 전혀 문제없어요.
3. **이메일 헤더로 확인하기(필요한 경우)**
   - 본인에게 테스트 이메일을 보내세요.
   - 받은 이메일의 원본을 열어 헤더에서 발송 IP를 확인하세요.
   - 다음 줄을 찾으세요: `Authentication-Results: spf=pass (sender IP is [IP])`

### 2단계. 내 구성에 맞는 IP 평판 점검

**공유 IP 사용자(대부분의 사용자):**

{% hint style="info" %}
하이퍼클래스는 모든 공유 IP 사용자를 위해 IP 평판을 우수하게 유지해요. IP 평판 관리는 걱정하지 않아도 돼요. 대신 도메인 평판과 발송 방식에 집중하세요.
{% endhint %}

**전용 IP 사용자:**

- **내장 모니터링**
  - **설정 > 이메일 서비스 > Postmaster Tools**로 이동하세요.
  - 하이퍼클래스 안에서 **Microsoft SNDS** 데이터를 바로 확인하세요.
  - 불만 접수율, 발송량 패턴, 평판 지표를 살펴보세요.
  - 인증 성공률을 추적하세요.
- **외부 평판 확인 도구**
  - Sender Score(Validity 제공): senderscore.org (0~100점)
  - Talos Intelligence(Cisco 제공): talosintelligence.com/reputation\_center
  - Google Postmaster Tools: postmaster.google.com
- **블랙리스트 확인 도구**
  - MXToolbox Blacklist Check
  - Spamhaus Lookup
  - MultiRBL

### 3단계. IP 유형에 맞는 회복 조치

**공유 IP 사용자:**

**집중할 부분:**

- 도메인 인증: SPF, DKIM, DMARC가 올바르게 설정됐는지 확인하세요.
- 목록 품질: 깨끗하고 반응이 있는 이메일 목록을 유지하세요.
- 콘텐츠 품질: 구독자에게 관련성 높고 가치 있는 콘텐츠를 보내세요.
- 참여도: 오픈율과 클릭률을 높이는 데 집중하세요.
- 규정 준수: 이메일 마케팅 모범 사례를 따르세요.

**하이퍼클래스가 맡는 일:** IP 평판 모니터링, 블랙리스트 관리, 인프라 최적화

**전용 IP 사용자:**

1. **SNDS 데이터 모니터링**
   - **설정 > 이메일 서비스 > Postmaster Tools > Microsoft SNDS**를 확인하세요.
   - 불만 접수율을 살펴보세요(목표 0.1% 미만).
   - 발송량 패턴과 인증 성공률을 모니터링하세요.
   - 평판 경고나 알림이 있는지 추적하세요.
2. **블랙리스트 문제 해결**
   - 외부 도구로 블랙리스트에 올랐는지 확인하세요.
   - 해당 블랙리스트 운영처에 삭제 요청을 제출하세요.
   - 개선 조치를 기록해 두세요.
   - 필요하면 하이퍼클래스 고객지원과 함께 진행하세요.
3. **IP 워밍업 진행(필요한 경우)**
   - 반응이 많은 연락처에게 적은 양부터 보내세요.
   - 4~6주에 걸쳐 발송량을 천천히 늘리세요.
   - SNDS 데이터에서 나빠지는 추세가 없는지 살펴보세요.

### 4단계. 발송 방식 개선하기(모든 사용자)

**필수 목록 관리:**

1. **연락처 > 스마트 리스트**로 이동하세요.
2. 다음을 나누어 관리하는 필터를 만드세요.
   - 반응 없는 연락처: 90일 이상 활동이 없는 연락처를 따로 분리해요.
   - 반응이 많은 연락처: 최근에 이메일을 열었거나 클릭한 연락처를 우선해요.
3. **모범 사례 적용**
   - 새 구독자에게는 이중 수신 동의(double opt-in)를 사용하세요.
   - 목록을 정기적으로 정리하세요.
   - 참여도에 따라 세그먼트를 나누세요.
   - 수신 제외 목록을 빠짐없이 관리하세요.

**도메인 인증 강화:**

1. **설정 > 이메일 서비스 > Dedicated Domain and IP**(전용 도메인 및 IP)로 이동하세요.
2. 사용하는 도메인에서 **도메인 인증**을 클릭하세요.
3. **보낸 사람** 도메인을 일관되게 사용하세요.
4. 모든 인증 레코드를 최신 상태로 유지하세요.

## 전용 IP 사용자를 위한 고급 모니터링

### 하이퍼클래스 내장 SNDS 모니터링 사용하기

#### SNDS 데이터 확인하기

1. **설정 > 이메일 서비스 > Postmaster Tools**로 이동하세요.
2. **Microsoft SNDS** 탭을 클릭하세요.
3. 다음 지표를 확인하세요.
   - **Complaint Rate**(불만율): 0.1% 미만이어야 해요.
   - **Trap Hits**(스팸 트랩 적중): 0이어야 해요.
   - **Volume Patterns**(발송량 패턴): 일정한지 살펴보세요.
   - **Authentication Success**(인증 성공률): 95% 초과여야 해요.
4. 정기 모니터링 일정(매일 또는 매주)을 정하세요.
5. 추세와 변화를 기록해 두세요.

**SNDS 데이터 해석:**

- 녹색: 평판이 우수해요. 지금 방식을 유지하세요.
- 노란색: 주의 깊게 살펴보고 발송 방식을 개선하세요.
- 빨간색: 즉시 조치가 필요해요. 모든 발송 방식을 점검하세요.

### Google Postmaster Tools 설정

- postmaster.google.com 에 발송 도메인을 추가하세요.
- 스팸 비율 추세를 모니터링하세요(0.1% 미만 유지).
- 전송 오류 패턴을 추적하세요.
- 인증 성공률을 살펴보세요.
- 성능이 바뀌면 알려 주는 알림을 설정하세요.

## 전용 IP를 고려해야 할 때

### 이럴 때 업그레이드를 고려하세요

- 매달 150,000통을 넘게 꾸준히 보내요.
- 자세한 SNDS 모니터링이 필요해요.
- IP 평판을 직접 완전히 관리하고 싶어요.
- 비즈니스에서 전달률을 최대한 직접 관리해야 해요.
- 발송량을 꾸준히 유지할 수 있어요.
- 고급 IP 분석과 리포트를 쓰고 싶어요.

### 전용 IP의 장점

- 내장 SNDS 모니터링: Microsoft 평판 데이터를 바로 확인할 수 있어요.
- 완전한 관리: 내 발송 방식이 평판에 그대로 반영돼요.
- 고급 분석: 평판을 자세히 추적하고 리포트로 볼 수 있어요.
- 독립된 성능: 다른 발송자의 영향을 받지 않아요.
- 확장성: 대량 발송에 더 알맞아요.

## 모든 사용자를 위한 모범 사례

### 목록 관리

- 참여도 기반 세그먼트: 반응이 있는 연락처와 없는 연락처를 나누세요.
- 정기적인 목록 점검: 매달 연락처 품질을 검토하세요.
- 이중 수신 동의 적용: 구독자가 직접 확인하게 하세요.
- 품질 우선: 목록 크기보다 반응이 있는 구독자를 우선하세요.

### 콘텐츠와 발송 최적화

- 스팸 점수 테스트: 캠페인은 보내기 전에 테스트하세요.
- 명확한 발신자 표시: 알아보기 쉬운 **보낸 사람** 이름을 쓰세요.
- 관련성 있는 콘텐츠: 구독자의 기대에 맞추세요.
- 쉬운 수신 거부: 수신 거부 요청은 바로 처리하세요.
- 일정한 발송 주기: 규칙적인 발송 패턴을 유지하세요.

### 인증과 기술 설정

- 완벽한 인증: SPF, DKIM, DMARC를 설정하세요.
- 도메인 일관성: 인증된 같은 도메인을 사용하세요.
- 모바일 최적화: 모든 기기에서 이메일이 잘 보이게 하세요.
- 정기 점검: 인증 상태를 매달 확인하세요.

## 회복 일정과 기대치

### 공유 IP 사용자

- 즉시: 도메인 평판과 목록 품질에 집중하세요.
- 1~2주: 전달률이 좋아지기 시작해요.
- 1개월: 개선한 발송 방식으로 성능이 안정돼요.
- 진행 중: 좋은 결과를 이어 가려면 모범 사례를 계속 지키세요.

### 전용 IP 사용자

- 1~7일 차: 블랙리스트 문제를 해결하고 발송 방식을 개선하세요.
- 2~6주 차: SNDS 데이터를 모니터링하며 서서히 나아지는지 확인하세요.
- 2~4개월 차: 평판이 완전히 회복되고 성능이 안정돼요.
- 진행 중: 지속적으로 모니터링하고 최적화하세요.

## 고객지원에 문의하기

### 이럴 때 문의하세요

- 공유 IP 사용자: 전달률 전반에 대한 안내와 모범 사례가 필요할 때
- 전용 IP 사용자: SNDS 데이터 해석이나 IP 관련 문제가 있을 때
- 인증 도움: DNS 설정이 어려울 때
- 전용 IP 상담: 업그레이드 옵션과 요건을 알아볼 때
- 성능 최적화: 내 사용 상황에 맞는 권장 사항을 받고 싶을 때

### 문의할 때 알려 주면 좋은 정보

- 내 IP 구성: 공유 IP인지 전용 IP인지
- 성능 지표: 전달률, 참여도 데이터
- 구체적인 문제: 반송 메시지, 전달 문제
- 발송량: 현재 발송량과 계획 중인 발송량
- SNDS 데이터: 대시보드 스크린샷(전용 IP 사용자)

## 문제가 계속되나요?

IP 평판 문제가 계속된다면 다음을 해 보세요.

1. 공유 IP 사용자: 도메인 평판과 발송 방식에 집중하세요. IP 평판은 하이퍼클래스가 자동으로 관리해요.
2. 전용 IP 사용자: SNDS 데이터를 살펴보고 그에 맞게 개선하세요.
3. 모든 사용자: 도메인 인증과 목록 품질을 완벽하게 갖추세요.
4. 하이퍼클래스 고객지원에 문의하세요. 고객지원팀의 전문 지식과 플랫폼 경험을 활용할 수 있어요.
5. 전문 컨설팅을 고려해 보세요. 고급 최적화 전략이 필요할 때 도움이 돼요.

{% hint style="info" %}
하이퍼클래스의 인프라는 공유 IP 사용자의 IP 평판을 자동으로 우수하게 유지하도록 설계되어 있어요. 전용 IP 사용자는 고급 모니터링 도구를 하이퍼클래스 안에서 바로 쓸 수 있고요. 내가 직접 관리할 수 있는 도메인 평판, 목록 품질, 콘텐츠 최적화에 집중하세요.
{% endhint %}

## 자주 묻는 질문

### 공유 IP인지 전용 IP인지 어떻게 정확히 확인하나요?
**설정 > 이메일 서비스 > Postmaster Tools > Microsoft SNDS**를 확인하세요. SNDS 데이터가 보이면 전용 IP예요. "IP not found in your account"라고 나오면 공유 IP예요.

### 공유 IP를 쓰면 다른 발송자의 잘못된 발송 때문에 내 전달률이 나빠질 수 있나요?
하이퍼클래스가 공유 IP 평판을 적극적으로 관리하고 풀(pool)을 모니터링하기 때문에 이런 위험은 최소화돼요. 공유 IP의 평판 관리를 개별 발송자에게 맡기지 않고 하이퍼클래스가 한곳에서 처리하는 것도 이 때문이에요.

### 발송량이 많지 않은데 전용 IP로 바꾸는 게 좋을까요?
대체로 그렇지 않아요. 전용 IP는 건강한 평판을 유지하려면 꾸준한 발송량이 필요하고, 워밍업과 지속적인 모니터링도 해야 해요. 한 달에 대략 150,000통 아래라면 보통 공유 IP가 더 안정적이에요.

### SNDS는 Sender Score나 Talos와 어떻게 다른가요?
SNDS는 Microsoft가 직접 제공하는 도구라서 Outlook/Hotmail에서의 평판만 보여 줘요. Sender Score와 Talos는 여러 제공업체에 걸친 더 폭넓은 평판 신호를 줘요. 전용 IP 사용자는 세 가지를 모두 확인해야 전체 상황을 파악할 수 있어요.

### 한동안 발송을 멈추면 전용 IP의 평판은 어떻게 되나요?
오래 발송하지 않으면 제공업체가 해당 IP를 다시 "처음 보는 IP"로 여겨 평판이 떨어질 수 있어요. 몇 주 넘게 발송을 멈췄다면 갑자기 원래 발송량으로 돌아가지 말고, 발송량을 서서히 늘리며 IP를 다시 워밍업하세요.

### 평판 문제가 계속되면 전용 IP에서 공유 IP로 다시 바꿀 수 있나요?
네, 가능해요. 전용 IP에 필요한 발송량을 유지하기 어려운 경우에는 전문가가 관리하는 공유 IP로 돌아가는 것이 가장 간단한 해결책일 때가 많아요. 내 계정에 가장 알맞은 방법은 하이퍼클래스 고객지원에 문의하세요.
