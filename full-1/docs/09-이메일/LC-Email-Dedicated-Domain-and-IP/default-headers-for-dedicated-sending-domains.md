# 전용 발송 도메인의 기본 헤더와 발신자 이메일 대체 순서

기본 헤더(Default Header)는 전용 발송 도메인에 **From Name**(발신자 이름)과 **From Email**(발신자 이메일)을 정해 두는 기능이에요. 이 글에서는 기본 헤더가 캠페인·워크플로우 설정을 어떻게 덮어쓰는지 알아봐요. 기본 헤더, 캠페인/워크플로우의 **From Email**, **비즈니스 프로필**의 이메일이 모두 비어 있을 때 어떤 주소로 발송되는지도 함께 설명해요.

## 이 글에서 알 수 있는 내용

기본 헤더를 설정하면 그 도메인으로 나가는 모든 캠페인과 워크플로우의 **From Name**과 **From Email**을 **항상 덮어써요**. 캠페인이나 워크플로우에 직접 입력한 값과 상관없이 적용돼요.

이 글에서는 각 단계가 비어 있을 때 어떻게 되는지도 다뤄요. 기본 헤더, 캠페인/워크플로우의 **From Email**, **비즈니스 프로필**의 이메일이 모두 비어 있어도 플랫폼은 자동으로 만든 `reply@<your-subdomain>` 주소로 이메일을 보내요.

## 기본 헤더를 쓰면 좋은 경우

### 활용 사례 1: 모든 발송에 하나의 발신자 정보 적용

도메인 단위로 **From Name**과 **From Email**을 한 번만 설정하면, 그 도메인으로 나가는 모든 캠페인과 워크플로우에 자동으로 적용돼요. 팀원이 개별 캠페인이나 워크플로우에 다른 **From Name**이나 **From Email**을 입력해도, 발송할 때는 기본 헤더가 우선해요.

### 활용 사례 2: 규정 준수가 필요한 경우

금융이나 의료처럼 커뮤니케이션 기준이 엄격한 업종에서는 기본 헤더로 모든 발신 이메일을 승인된 발신자 하나로 고정할 수 있어요. 그러면 개별 캠페인이나 워크플로우가 승인되지 않은 **From Name**이나 **From Email**로 나갈 위험이 없어요.

## 시작하기 전에 확인할 것

기본 헤더를 설정하기 전에 아래 두 가지를 확인하세요.

### 조건 1: 서브 계정에서 작업하고 있어야 해요

기본 헤더는 서브 계정에서 관리하는 전용 발송 도메인에만 설정할 수 있어요. 에이전시 수준 도메인은 서브 계정별 기본 헤더 설정을 지원하지 않아요.

### 조건 2: 전용 발송 도메인이 추가되고 인증되어 있어야 해요

사용자 지정 발송 도메인(예: email.yourbrand.com)의 DNS 설정을 마쳐야 해요. CNAME, DKIM, SPF 레코드가 모두 포함돼요.

**설정 > 이메일 서비스 > SMTP 서비스 > Dedicated Domain and IP**(전용 도메인 및 IP)에서 도메인 옆에 녹색 체크 표시가 보이면 인증이 끝나 사용할 준비가 된 거예요.

## 기본 헤더 설정하기 (From Name & From Email)

기본 헤더는 서브 계정 안에서 전용 도메인마다 따로 설정해요. 아래 경로로 이동하세요.

**서브 계정 설정 > 이메일 서비스 > SMTP 서비스 > Dedicated Domain and IP > Set Headers**(헤더 설정)

![Set Headers 옵션이 보이는 Dedicated Domain and IP 설정 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155044882641/original/l67IXG1nmKTdfTeM8aYyho5Bi4sdRCZDsw.png?1744290467)

1. 위 경로로 이동해요.
2. 인증된 도메인을 찾아 **Set Headers**를 클릭해요. 설정 패널이 열려요.
3. **From Name**과 **From Email**을 입력하고 저장해요.

![From Name과 From Email 입력란이 보이는 Set Headers 폼](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155044882742/original/u4kpWwg9k_Mdzc7Ts-PGYh3_0vTOcvXr5w.png?1744290526)

### 적용 방식

저장하면 이 전용 도메인으로 나가는 모든 캠페인과 워크플로우의 **From Name**과 **From Email**을 기본 헤더가 **항상 덮어써요**. 붙는 조건은 없고, 모든 발송에 적용돼요. 기본 헤더 입력란을 비워 두면 플랫폼은 아래 "모든 항목이 비어 있을 때의 전체 대체 순서"에서 설명하는 대체 순서를 따라 내려가요.

## 덮어쓰기는 실제로 어떻게 동작하나요?

### 1단계: 캠페인 또는 워크플로우 설정

브로드캐스트나 워크플로우 이메일을 만들 때는 평소처럼 캠페인 수준의 **From Name**과 **From Email**을 설정할 수 있어요. 이 값은 발송 도메인에 기본 헤더가 설정되어 있지 **않을 때만** 사용돼요.

### 2단계: 발송 시점에 기본 헤더 확인

이메일을 보내는 순간 플랫폼은 전용 도메인에 저장된 기본 헤더가 있는지 확인해요. 기본 헤더가 있으면 자동으로 우선 적용돼요. 이때 캠페인이나 워크플로우의 **From Name**과 **From Email**은 예비로 쓰이지 않고 무시돼요.

### 3단계: 수신자가 보는 화면

- 기본 헤더가 설정되어 있으면, 캠페인이나 워크플로우에 무엇을 입력했는지와 상관없이 수신자는 항상 그 **From Name**과 **From Email**을 봐요.
- 인증된 발송 도메인의 주소를 쓰기 때문에 이메일이 DMARC 기준을 충족해요. 그래서 반송되거나 스팸으로 분류될 가능성도 낮아져요.

## 모든 항목이 비어 있을 때의 전체 대체 순서

기본 헤더는 플랫폼이 가장 먼저 확인하는 항목일 뿐이에요. 이메일을 보내려면 유효한 **From Name**과 **From Email**이 있어야 해요. 그래서 플랫폼은 4단계 대체 순서를 따라 내려가며 사용할 값을 찾아요. 중간 항목이 모두 비어 있어도 마찬가지예요.

### 1순위 (가장 높은 우선순위): 전용 도메인의 기본 헤더

발송 도메인에 기본 헤더가 저장되어 있으면 항상 이것을 써요. 그 아래 순위는 확인하지 않아요.

### 2순위: 캠페인 또는 워크플로우의 From Name & From Email

기본 헤더가 비어 있으면, 해당 캠페인이나 워크플로우에 직접 입력한 **From Name**과 **From Email**을 써요.

### 3순위: 비즈니스 프로필의 비즈니스 이메일

기본 헤더와 캠페인/워크플로우의 **From Email**이 **둘 다** 비어 있으면, 플랫폼은 **비즈니스 프로필**에 저장된 **비즈니스 이메일**을 확인해요. 저장된 주소가 있으면 그 주소를 이번 발송의 **From Email**로 써요.

### 4순위 (최후의 안전장치): 자동 생성되는 reply@<your-subdomain> 주소

위 세 가지가 **모두** 비어 있으면 플랫폼이 자동으로 발신자 주소를 만들어요. 기본 헤더도, 캠페인/워크플로우의 **From Email**도, **비즈니스 프로필**의 이메일도 없는 경우예요. 이때는 활성 상태로 인증된 발송 서브도메인을 사용해 `reply@<your-subdomain>` 형식으로 주소를 만들고, 그 주소로 이메일을 보내요. 발신자 주소가 설정되어 있지 않다는 이유만으로 발송이 실패하는 일은 없어요.

| 우선순위 | 확인하는 항목 | 사용되는 경우 |
| --- | --- | --- |
| 1 | 기본 헤더 | 도메인에 설정되어 있을 때 (있으면 항상 우선) |
| 2 | 캠페인/워크플로우의 From Name & Email | 기본 헤더가 비어 있을 때 |
| 3 | 비즈니스 프로필 — 비즈니스 이메일 | 기본 헤더와 캠페인/워크플로우의 From Email이 모두 비어 있을 때 |
| 4 | 자동 생성된 `reply@<subdomain>` | 기본 헤더, 캠페인/워크플로우의 From Email, 비즈니스 프로필 이메일이 모두 비어 있을 때 |

{% hint style="warning" %}
이 대체 순서는 어딘가에 발신자 주소를 설정하지 않았다는 이유로 발송이 막히지 않도록 만든 장치예요. 발신자 주소 설정을 건너뛰어도 된다는 뜻은 아니에요. 4순위까지 내려가면 수신자에게는 브랜드 이름 대신 일반적인 `reply@` 주소가 보여요. 그러면 신뢰감이 떨어지고 오픈율에도 나쁜 영향을 줄 수 있어요. 기본 헤더 아래의 안전장치로 **비즈니스 프로필**에 **비즈니스 이메일**이라도 꼭 설정해 두세요.
{% endhint %}

## 예시: 상황별 비교

### 설정값

| 설정 | 값 |
| --- | --- |
| 전용 발송 도메인 | email.yourbrand.com (인증됨) |
| 비즈니스 프로필 — 비즈니스 이메일 | hello@yourbrand.com |
| 캠페인 From Name / Email (입력했을 때) | Jane from YourBrand / jane@email.yourbrand.com |

### 상황별로 수신자에게 보이는 모습

**시나리오 1: 기본 헤더가 설정된 경우**

`From: YourBrand Support <support@email.yourbrand.com>`

캠페인에 입력한 "Jane from YourBrand"라는 이름과 주소는 완전히 무시돼요. 도메인에 맞게 올바르게 설정했더라도 마찬가지예요.

**시나리오 2: 기본 헤더는 비어 있고 캠페인 From Email은 입력한 경우**

`From: Jane from YourBrand <jane@email.yourbrand.com>`

도메인에 저장된 기본 헤더가 없으니 캠페인의 **From Name**과 **From Email**이 설정한 그대로 쓰여요(2순위).

**시나리오 3: 기본 헤더와 캠페인 From Email이 모두 비어 있는 경우**

`From: YourBrand <hello@yourbrand.com>`

두 항목이 모두 비어 있어서 3순위로 내려가요. **비즈니스 프로필**에 저장된 **비즈니스 이메일**을 써요.

**시나리오 4: 기본 헤더, 캠페인 From Email, 비즈니스 프로필 이메일이 모두 비어 있는 경우**

`From: reply@email.yourbrand.com`

위 항목이 모두 비어 있어서 4순위까지 내려가요. 활성 상태로 인증된 발송 서브도메인에 `reply@` 주소를 자동으로 만들어요. 그래서 이메일은 그대로 발송돼요.

### 제대로 적용됐는지 확인하기

1. 캠페인에 설정된 값과 다른 **From Name**, **From Email**으로 기본 헤더를 저장해요. 그다음 테스트 메일을 보내 기본 헤더가 우선 적용되는지 확인해요.
2. 기본 헤더와 캠페인의 **From Email**을 지우되 **비즈니스 이메일**은 저장된 상태로 둬요. 테스트 메일을 보내 **비즈니스 이메일**이 쓰이는지 확인해요.
3. 기본 헤더, 캠페인/워크플로우의 **From Email**, **비즈니스 프로필**의 이메일을 모두 지워요. 테스트 메일을 보내 발신자 주소가 인증된 서브도메인의 `reply@` 주소로 나오는지 확인해요.

## 활용 팁과 고려할 점

### A. 설정하기 전에 먼저 결정하세요 — 모든 것을 덮어써요

기본 헤더는 그 도메인으로 나가는 모든 캠페인과 워크플로우를 덮어써요. 저장하기 전에 이 발신자 정보를 전체에 적용해도 괜찮은지 확인하세요. 기본 헤더가 켜져 있는 동안에는 팀원이 나중에 캠페인에 **From Name**이나 **From Email**을 설정해도 모두 무시돼요.

### B. 안전장치로 비즈니스 이메일을 저장해 두세요

대체 순서 3순위는 **비즈니스 프로필**의 **비즈니스 이메일**을 써요. 평소에 기본 헤더를 쓰더라도 이 항목을 채워 두세요. 그러면 발송이 비즈니스 자체 주소로 대체될지, 자동 생성된 `reply@` 주소까지 내려갈지가 갈려요.

### C. 회신을 확인하세요

기본 헤더의 **From Email**은 발송 도메인에 속한 주소면 무엇이든 쓸 수 있어요. 다만 그 메일함을 실제로 확인하고 있는지, 또는 별칭이 올바르게 설정되어 있는지 확인하세요. 예를 들어 support@yourbrand.com이 담당 팀으로 전달되게 해 두면, 고객 회신을 놓치지 않아요. 자동 생성된 `reply@` 주소도 마찬가지예요. 4순위까지 내려간 적이 있다면 그 메일함도 확인하세요.

### D. 확대하기 전에 테스트하세요

내부용으로 소규모 테스트를 보내 기본 헤더가 적용되는지 확인하세요. 수신자에게 실제로 보이는 **From Name**과 **From Email**이 기본 헤더 설정과 같은지 확인해요. 캠페인이나 워크플로우에 입력한 값이어도 안 되고, 의도하지 않은 대체 순위로 내려간 것이어도 안 돼요.

### E. 팀에 설정 사실을 알려 주세요

기본 헤더는 팀원이 캠페인이나 워크플로우에 설정한 **From Name**과 **From Email**을 조용히 덮어써요. 이 도메인으로 캠페인이나 워크플로우를 만드는 팀원에게 기본 헤더가 켜져 있다고 알려 주세요. 그래야 직접 입력한 발신자 주소가 실제로 쓰이지 않아도 당황하지 않아요.

### F. 서브 계정으로 분리하세요

브랜드나 부서가 여러 개라면 서브 계정을 따로 만드세요. 서브 계정마다 전용 도메인과 기본 헤더를 두면 발송 관리와 평판 관리를 완전히 분리할 수 있어요.

## 자주 묻는 질문

### 기본 헤더는 모든 이메일에 적용되나요, 특정 상황에서만 적용되나요?

기본 헤더는 그 전용 도메인으로 나가는 **모든** 캠페인과 워크플로우 이메일을 덮어써요. 예비용이 아니라 항상 적용돼요. 기본 헤더가 저장되어 있으면 캠페인이나 워크플로우에 설정한 **From Name**과 **From Email**보다 우선해요. 캠페인의 주소를 올바르게 설정했더라도 마찬가지예요. 기본 헤더 입력란 자체가 비어 있을 때만 건너뛰고 다음 대체 순위로 넘어가요.

### 발신자 주소의 전체 우선순위는 어떻게 되나요?

순서는 이래요. (1) 전용 도메인에 설정한 기본 헤더, (2) 해당 캠페인이나 워크플로우에 입력한 **From Name**과 **From Email**, (3) **비즈니스 프로필**에 저장된 **비즈니스 이메일**, (4) 위 세 가지가 모두 비어 있을 때 자동 생성되는 `reply@<your-subdomain>` 주소예요. 자세한 내용은 위의 "모든 항목이 비어 있을 때의 전체 대체 순서"를 참고하세요.

### 플랫폼이 비즈니스 프로필에서 발신자 이메일을 가져오기도 하나요?

네. 전용 도메인에 기본 헤더가 없고 캠페인이나 워크플로우에도 **From Email**이 없으면, 플랫폼은 **비즈니스 프로필**에 저장된 **비즈니스 이메일**을 확인해요. 더 아래로 내려가기 전에 그 주소를 먼저 사용해요.

### 기본 헤더, 캠페인/워크플로우의 From Email, 비즈니스 프로필 이메일이 모두 비어 있으면 어떻게 되나요?

플랫폼은 어떻게든 이메일을 보내야 해서, 활성 상태로 인증된 발송 서브도메인에 `reply@<your-subdomain>` 형식으로 발신자 주소를 자동으로 만들어요. 발신자 주소가 없다는 이유로 발송이 막히지는 않아요. 하지만 수신자에게 보이는 이름이나 메일함을 직접 정할 수 없어요. 그래서 이 방식은 전략이 아니라 안전장치로만 생각하는 것이 좋아요.

### 전용 도메인마다 다른 기본 헤더를 설정할 수 있나요?

네. 기본 헤더는 전용 도메인마다 따로 설정해요. 서브 계정에 인증된 발송 도메인이 여러 개 있으면, 도메인마다 독립적으로 **From Name**과 **From Email** 덮어쓰기를 설정할 수 있어요.

### 기본 헤더는 워크플로우에도 적용되나요, 브로드캐스트 캠페인에만 적용되나요?

둘 다 적용돼요. 기본 헤더와 그 아래의 모든 대체 순위는 그 전용 도메인으로 나가는 모든 이메일에 적용돼요. 브로드캐스트 캠페인이 보내든 워크플로우 액션이 보내든 같아요.

### 기본 헤더가 Reply-To 주소에도 영향을 주나요?

아니요. 기본 헤더는 **From Name**과 **From Email**만 정해요. 캠페인이나 워크플로우에 Reply-To 주소를 설정했다면, 기본 헤더나 어느 대체 순위가 쓰였는지와 상관없이 그 Reply-To가 계속 쓰여요.

### 기본 헤더의 From Email은 인증한 도메인의 주소를 써야 하나요?

네. 기본 헤더의 **From Email**은 인증된 전용 발송 도메인에 속한 주소여야 해요. 예를 들어 도메인이 email.yourbrand.com이라면 support@email.yourbrand.com 같은 주소를 쓰세요. 그래야 설정해 둔 SPF와 DKIM 레코드로 올바르게 인증돼요. 자동 생성되는 4순위 주소도 같은 이유로 항상 활성 상태로 인증된 서브도메인에 만들어져요.
