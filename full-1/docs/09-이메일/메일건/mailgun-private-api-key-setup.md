# Mailgun Private API 키로 이메일 서비스 연결하기

Mailgun 계정을 하이퍼클래스에 연결하면, 인증이 끝난 Mailgun 환경으로 이메일을 보낼 수 있어요. 에이전시 단위 이메일 서비스로 Mailgun을 추가하고, 인증된 US 리전 발신 도메인을 고른 다음, 대상 서브 계정에서 쓸 수 있도록 **활성** 서비스로 지정하는 방법을 안내해요. 에이전시 관리자만 쓸 수 있어요.

이 문서에서는 다음 내용을 다뤄요.

- Mailgun 도메인 준비
- Private API 키로 연결
- 에이전시 단위 발송을 위한 Mailgun 활성화
- 서브 계정의 서비스 우선순위
- 연결 확인과 문제 해결

{% hint style="warning" %}
하이퍼클래스는 이 연동에 Mailgun의 Private API 키(비공개 API 키)를 사용해요. 이 키는 비밀 정보이니, 스크린샷·고객지원 문의·문서·공개 메시지에 절대 노출하지 마세요.
{% endhint %}

## Mailgun API 키 연결이란?

Mailgun을 연결하면 하이퍼클래스가 내 Mailgun 계정과 인증된 발신 도메인으로 이메일을 보내요.

하이퍼클래스는 Private API 키로 Mailgun에 인증해요. 그러면 계정에 있는 인증된 도메인을 설정 중에 고를 수 있어요. 서비스를 저장한 뒤에는 **활성**으로 지정해야 에이전시 기본 서비스가 돼요.

### Mailgun을 연결하면 좋은 점

내 Mailgun 계정을 연결하면 하이퍼클래스 이메일 발송 환경을 더 직접 관리할 수 있어요. 서비스 관리는 에이전시에서 한곳에 모아서 할 수 있어요.

- **내 환경으로 발송:** 이미 쓰고 있는 Mailgun 계정과 인증된 도메인으로 보내요.
- **에이전시 설정 통합:** 자체 서비스가 없는 서브 계정의 기본 서비스로 Mailgun을 쓸 수 있어요.
- **서비스 전환:** 에이전시 단위 이메일 서비스를 여러 개 저장해 두고, 필요할 때 **활성** 서비스를 바꿀 수 있어요.
- **서브 계정별 예외 지원:** 설정해 두면 개별 서브 계정은 다른 서비스를 쓸 수 있어요.
- **답장 라우팅 지원:** Mailgun 수신과 DNS를 알맞게 설정하면, 지원되는 답장이 **대화**로 들어와요.

## 준비 사항과 제한 사항

연결하기 전에 Mailgun을 먼저 준비해 두면 도메인이 보이지 않거나, 인증에 실패하거나, 예상과 다르게 동작하는 문제를 줄일 수 있어요.

시작하기 전에 다음을 준비하세요.

- 사용 중인 Mailgun 계정
- 인증이 끝난 Mailgun 발신 도메인 또는 서브도메인 1개 이상
- US 리전에서 만든 Mailgun 도메인
- Mailgun 설정에 필요한 DNS 레코드 설정 완료
- **에이전시 보기 > 설정 > 이메일 서비스**에 접근할 수 있는 권한
- 알맞은 Mailgun Private API 키

다음 제한 사항도 알아 두세요.

- 하이퍼클래스는 US 리전에 있는, 인증된 Mailgun 도메인만 읽어 와요.
- Mailgun 서비스를 저장해도 자동으로 활성 상태가 되지는 않아요.
- 에이전시 단위 이메일 서비스는 한 번에 하나만 **활성**일 수 있어요.
- 서브 계정에 별도로 지정한 서비스가 에이전시 서비스보다 우선해요.
- 수신 답장을 처리하려면 Mailgun 수신과 DNS를 추가로 설정해야 해요.
- Mailgun 요금, 발송량 제한, 서비스 자체의 제약은 Mailgun에서 관리해요.

## Mailgun 리전과 도메인 조건

도메인이 인증되어 있고 지원되는 Mailgun 리전에 설정되어 있어야 하이퍼클래스에서 도메인이 표시돼요.

- Mailgun 도메인이나 서브도메인은 EU 리전이 아니라 US 리전에서 만드세요.
- Mailgun에서 도메인이 인증됨으로 표시되는지 확인하세요.
- Mailgun 설정에 필요한 DNS 레코드를 모두 설정하세요.
- Mailgun 발송을 기본 도메인의 기존 메일함 설정과 분리하고 싶다면 서브도메인을 쓰세요.

예시: 기본 도메인이 yourdomain.com이면 mg.yourdomain.com 같은 발송용 서브도메인을 쓸 수 있어요. 루트 도메인이 이미 Google Workspace, Microsoft 365 등 다른 메일함 서비스로 메일을 받고 있을 때 특히 유용해요.

![US 리전 설정과 인증 완료 상태가 표시된 Mailgun 도메인 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155053010520/original/wTfs0PssGmngzK3Zuvif__AnMaGOueL_bQ.png?1756904136)

## 에이전시 단위로 Mailgun 연결하기

에이전시 단위로 Mailgun을 연결하고 서비스를 저장해 활성화하면, 대상 서브 계정의 기본 발송 서비스로 쓸 수 있어요.

### 1단계: Mailgun Private API 키 복사하기

Private API 키는 하이퍼클래스와, 인증된 발신 도메인이 있는 Mailgun 계정을 이어 주는 인증 수단이에요.

1. **Mailgun**에 로그인하세요.
2. Mailgun 화면에서 **Settings > API Keys**로 이동하세요.
3. 알맞은 Private API 키가 없으면 새로 만드세요.
4. 키를 안전하게 복사하세요.

{% hint style="warning" %}
Mailgun Private API 키를 스크린샷, 고객지원 문의, 문서, 채팅 메시지에 넣지 마세요. 키가 노출되었다면 Mailgun에서 키를 새로 만들고, 하이퍼클래스에 연결된 이메일 서비스의 키도 바꿔 주세요.
{% endhint %}

### 2단계: 에이전시 이메일 서비스 열기

에이전시의 이메일 서비스 설정은 서브 계정에 별도의 이메일 서비스가 없을 때 쓰는 기본 발송 서비스를 정해요.

1. **에이전시 보기**를 여세요.
2. **설정**을 클릭하세요.
3. **이메일 서비스**를 선택하세요.
4. **SMTP 서비스** 탭을 여세요.

{% hint style="info" %}
사용 중인 화면에 따라 이 설정 영역이 **고급 설정**이라는 이름으로 표시될 수도 있어요.
{% endhint %}

### 3단계: Mailgun 추가하기

Mailgun을 에이전시 단위 이메일 서비스로 추가하고, Mailgun 계정에 연결된 인증 완료 발신 도메인을 선택해요.

1. **+ Add Service**(서비스 추가)를 클릭하세요.
2. **Add your own email service**(내 이메일 서비스 추가) 창에서 **Mailgun**을 선택하세요.
3. Mailgun **API 키**를 입력하세요.
4. 인증된 Mailgun **도메인**을 선택하세요.
5. 이메일 서비스를 저장하세요.

도메인이 보이지 않을 때는 Mailgun에서 도메인 인증이 완전히 끝났는지, 입력한 API 키와 같은 계정의 도메인인지, US 리전에서 만든 도메인인지 확인하세요.

### 4단계: Mailgun을 활성으로 지정하기

서비스를 저장하면 에이전시 계정에 Mailgun이 추가돼요. 하지만 활성으로 지정하기 전에는 에이전시가 기본 서비스로 쓰지 않아요.

1. 추가한 Mailgun 서비스를 찾으세요.
2. **Set as Active**(활성으로 설정)를 클릭하세요.
3. 변경 내용을 확인하세요.

![Mailgun 서비스에서 활성으로 설정을 선택하는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155081373964/original/YaGdCm13j_2gStD7qReJXNidAVQmcJ2Ing.png?1789865086)

## 에이전시와 서브 계정의 이메일 서비스 우선순위

에이전시 단위 설정과 서브 계정별 설정이 둘 다 있으면, 우선순위에 따라 실제로 이메일을 보내는 서비스가 정해져요.

서비스 우선순위

1. 서브 계정에 별도로 지정한 기본 서비스
2. 에이전시 단위의 **활성** 서비스

서브 계정에 자체 서비스가 설정되어 있으면 그 서비스가 우선해요. 설정되어 있지 않으면 해당하는 에이전시의 **활성** 서비스를 써요.

서브 계정별 서비스 지정 현황은 다음 경로에서 확인할 수 있어요.

**에이전시 보기 > 설정 > 이메일 서비스 > Location Settings**(로케이션 설정)

서브 계정이 자체 이메일 서비스를 추가할 수 있는지는 다음 경로에서 에이전시가 정할 수 있어요.

**에이전시 보기 > 설정 > 이메일 서비스 > 고급 설정**

![이메일 서비스 고급 설정 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155081373937/original/gVaSHRsJZe_XDTxoBVlEetelbZSn6E039Q.png?1789864902)

## Mailgun 연결 확인하기

활성화한 뒤에 테스트해 보면, 캠페인·워크플로우·일반 대화에 쓰기 전에 원하는 서비스와 발신 도메인이 잘 동작하는지 확인할 수 있어요.

1. **에이전시 보기 > 설정 > 이메일 서비스**에서 Mailgun이 **활성**으로 표시되는지 확인하세요.
2. 원하는 인증 완료 Mailgun 도메인이 선택되어 있는지 확인하세요.
3. 에이전시 단위 서비스를 써야 하는 서브 계정을 여세요.
4. 내가 받아 볼 수 있는 이메일 주소로 테스트 연락처를 만들거나 여세요.
5. 연락처 대화에서 테스트 이메일을 보내세요.
6. 메시지가 도착했는지 확인하세요.
7. 수신 답장 처리도 테스트하려면 받은 이메일에 답장하세요.
8. 답장이 **대화**에 나타나는지 확인하세요.

발송은 되는데 답장이 오지 않을 때는 Mailgun의 수신 라우트, 웹훅, 수신용 DNS 설정을 확인하세요. API 연결만 성공했다고 해서 수신 답장 라우팅이 설정되지는 않아요.

## 문제 해결

Mailgun 연결 문제는 대부분 도메인 인증, 리전 선택, API 인증, 서비스 우선순위, 수신 라우팅 설정 중 하나에서 생겨요.

### Mailgun 도메인이 보이지 않아요

- 도메인이 API 키와 연결된 Mailgun 계정의 것인지 확인하세요.
- 도메인 인증이 완전히 끝났는지 확인하세요.
- Mailgun의 US 리전에서 만든 도메인인지 확인하세요.
- 필요한 DNS 설정이 모두 끝났는지 확인하세요.

### Mailgun을 저장했는데 다른 서비스로 이메일이 나가요

- 의도한 Mailgun 서비스가 **활성**으로 표시되는지 확인하세요.
- 해당 서브 계정에 자체 기본 서비스가 설정되어 있는지 확인하세요. 서브 계정의 서비스가 에이전시 서비스보다 우선해요.

### API 키로 도메인을 불러오지 못해요

- Mailgun Private API 키를 쓰고 있는지 확인하세요.
- 키가 의도한 Mailgun 계정의 것인지 확인하세요.
- 키가 삭제·교체·폐기되지 않았는지 확인하세요.
- Mailgun의 IP 제한 때문에 하이퍼클래스가 도메인 정보를 불러오지 못한다면, 제한을 잠시 조정하고 연결을 다시 시도하세요. 확인이 끝나면 제한을 원래대로 되돌리세요.

![API 도메인 동기화 문제를 해결할 때 확인하는 Mailgun IP 접근 제한 설정 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155053011609/original/jeX5H0Z7HskxTbYLqBiaDc9sqEipH4BMNQ.png?1756904672)

### 이메일은 발송되는데 답장이 대화에 보이지 않아요

- Mailgun 수신 라우트와 웹훅을 확인하세요.
- 수신 설정에 맞게 Mailgun MX 설정이 올바른지 확인하세요.
- 해당 도메인이 알맞은 서브 계정에 연결되어 있는지 확인하세요.
- 콜드 인바운드 이메일이라면, 수신 메시지가 원하는 곳으로 전달되도록 해당 서브 계정 전용의 고유한 도메인이나 서브도메인을 쓰세요.

## 자주 묻는 질문

### Mailgun Private API 키와 Public API 키 중 어느 것을 써야 하나요?

Private API 키를 쓰세요. Public API 키로는 하이퍼클래스의 Mailgun 서비스 연결 인증이 되지 않아요.

### EU 리전 Mailgun 도메인이 보이지 않아요

하이퍼클래스는 US 리전에 있는 인증된 Mailgun 도메인만 읽어 와요. 이 연동에는 US 리전 도메인이나 서브도메인을 설정해 주세요.

### 인증된 도메인인데 드롭다운에 보이지 않아요

도메인이 API 키와 연결된 Mailgun 계정의 것인지, 인증이 완전히 끝났는지, US 리전에 설정되어 있는지 확인하세요. 도메인 조회를 막을 수 있는 Mailgun IP 제한도 살펴보세요.

### Mailgun 서비스를 여러 개 저장할 수 있나요?

네. 에이전시 단위 이메일 서비스는 여러 개 저장할 수 있어요. 다만 에이전시 단위에서 **활성**인 서비스는 한 번에 하나만 가능해요.

### 에이전시 단위 Mailgun이 모든 서브 계정에 적용되나요?

자체 서비스를 설정하지 않은 서브 계정에는 기본 서비스로 적용돼요. 서브 계정에 별도로 지정한 기본 서비스가 있으면 그 서비스가 우선해요.

### 서브 계정에서 자체 이메일 서비스를 추가할 수 없어요

서브 계정이 이메일 서비스를 추가할 수 있는지는 에이전시가 정해요. **에이전시 보기 > 설정 > 이메일 서비스 > 고급 설정**을 확인하세요.

### Mailgun을 활성화한 뒤에 하이퍼클래스 이메일로 다시 돌아갈 수 있나요?

네. **에이전시 보기 > 설정 > 이메일 서비스**로 돌아가서 하이퍼클래스 이메일 시스템을 에이전시 단위 **활성** 서비스로 지정하세요.

### Mailgun을 연결하면 이메일 답장도 자동으로 설정되나요?

아니요. 답장 처리는 Mailgun 수신 라우트, 웹훅, 수신용 DNS 설정이 알맞게 되어 있어야 해요.

### 같은 Mailgun 도메인을 여러 서브 계정에서 써도 되나요?

지원되는 Mailgun 구성에서는 같은 계정과 발신 도메인을 여러 서브 계정에서 쓸 수 있어요. 콜드 인바운드 이메일이라면 수신 메시지가 올바르게 전달되도록 해당 서브 계정 전용의 고유한 도메인이나 서브도메인을 쓰세요.
