# 콜드 이메일 인바운드 설정 — Mailgun

하이퍼클래스에서 Mailgun으로 도메인의 인바운드 이메일(수신 이메일)을 처리하도록 설정하는 방법을 안내해요. 루트 도메인과 서브도메인의 차이로 생기는 제한도 함께 설명하니, 설정 전에 꼭 읽어 보세요.

## 인바운드 이메일이란?

인바운드 이메일은 내 도메인으로 들어오는 이메일을 받아서 처리하는 기능이에요. Mailgun에서는 받은 이메일을 다음과 같이 처리할 수 있어요.

- 다른 이메일 주소로 전달
- 웹훅으로 전송
- 기록을 남기고 워크플로우 안에서 처리

## 루트 도메인과 서브도메인

인바운드 이메일을 설정하기 전에, 도메인 설정이 어떻게 동작하는지 먼저 알아 두세요.

### 핵심 제한 사항

도메인 하나에는 MX(Mail Exchange, 메일 교환) 레코드를 한 세트만 둘 수 있어요.

그래서 같은 도메인에서 Mailgun과 다른 이메일 서비스(Gmail, Outlook 등)로 동시에 이메일을 받을 수 없어요.

### 실제로는 이런 뜻이에요

| MX 레코드가 가리키는 곳 | 결과 |
| --- | --- |
| Mailgun | Mailgun이 이메일을 처리해요(받은 편지함 없음) |
| Google Workspace / Outlook | 이메일이 내 받은 편지함으로 들어와요(Mailgun은 받을 수 없음) |

Mailgun은 받은 편지함을 제공하지 않아요. 이메일을 전달(라우팅)하는 역할만 해요.

## 루트 도메인에 Mailgun MX 레코드를 추가하면 문제가 생기는 이유

루트 도메인(예: yourdomain.com)이 이미 Google Workspace 같은 이메일 서비스에 연결되어 있다면 다음과 같아요.

- 기존 MX 레코드 옆에 Mailgun MX 레코드를 추가해도 안정적으로 동작하지 않아요.
- 이메일 수신이 실패하거나 예상과 다르게 동작할 수 있어요.

이메일 시스템은 들어오는 이메일을 여러 서비스에 나누어 처리하도록 만들어지지 않았기 때문이에요.

### 권장 설정(모범 사례)

충돌을 피하고 이메일을 안정적으로 받으려면 Mailgun에는 서브도메인을 사용하세요.

예시:

- Mailgun 도메인: mg.yourdomain.com
- 루트 도메인(yourdomain.com): 계속 Gmail 또는 Outlook에 연결

장점:

- Mailgun으로 이메일을 보낼 수 있어요.
- 평소 쓰는 받은 편지함에서 이메일을 받을 수 있어요.
- MX 충돌을 피할 수 있어요.

## 루트 도메인에 Mailgun 사용하기(권장하지 않아요)

루트 도메인에 Mailgun을 설정하려면 다음을 해야 해요.

- 루트 도메인의 MX 레코드를 Mailgun으로 지정

그러면 다음과 같은 결과가 생겨요.

- 기존 받은 편지함을 쓸 수 없어요(Gmail/Outlook으로 이메일이 더 이상 들어오지 않아요).
- 이메일은 Mailgun 라우트로만 처리돼요.

일반적인 받은 편지함 없이 라우팅·전달만 할 수 있어요.

## 인바운드 이메일 설정 단계(Mailgun)

### 1. Mailgun 설정하기

먼저 Mailgun 설정 방법을 확인하세요.

이 예시에서는 agency.com / mg.agency.com 을 Mailgun으로 설정해요.

모든 서브 계정에 같은 Mailgun 계정을 쓸 수 있어요.

예를 들어 agency.com 도메인이 있다면, 서브 계정마다 subaccountname.agency.com 같은 고유한 서브도메인을 만들 수 있어요. 그러면 서브 계정마다 답장을 받는 Mailgun 서브도메인이 하나씩 생겨요.

고객사가 자기 도메인을 가지고 있다면 고객사 전용 도메인이나 서브도메인을 따로 설정할 수도 있어요. 다만 고객사의 메인 도메인이 이미 다른 이메일 서비스에 쓰이고 있다면 이 경우에는 서브도메인을 사용해야 해요.

이렇게 해야 어느 계정으로 이메일을 전달할지 구분할 수 있어요.

### 2. Mailgun 도메인이 서브 계정 한 개에만 설정되어 있는지 확인하기

방금 설정한 Mailgun 도메인에 연결된 서브 계정이 하나뿐이면, 들어오는 모든 이메일이 그 서브 계정으로 전달돼요.

에이전시 관리자만 쓸 수 있는 화면에서 확인해요. **Agency View**(에이전시 보기) > **설정** > **이메일 서비스** > **Location Settings**(로케이션 설정)로 이동하세요.

![에이전시 설정의 이메일 서비스 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155067377057/original/GY8CBptqw6GZALWo8rDOGdD3-MQGRkpeCw.png?1774014342)

같은 서브도메인/도메인을 여러 하이퍼클래스 서브 계정에 쓰고 있으면 문제가 생겨요. 리드가 하이퍼클래스에서 보낸 이메일에 답장하지 않고 회신 주소로 직접 이메일을 보내면, 어느 서브 계정으로 전달해야 할지 알 수 없어요.

![같은 도메인을 여러 서브 계정에 설정한 예시 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155067377058/original/2QfjK-wOOm3Kl6ArJkEaGbSgqLGA_TxK9Q.png?1774014343)

도메인/서브도메인을 서브 계정 한 개에만 설정했는데도 동작하지 않으면, 같은 도메인이 **Domain Services**(도메인 서비스) 탭에도 설정되어 있는지 확인하세요.

![Domain Services 탭 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155067377056/original/oRExe121v81xK0RNZaBO1q1YOwmbGWN_LQ.png?1774014342)

같은 Mailgun 도메인을 선택했던 삭제된 서브 계정이 있었던 것 같다면 하이퍼클래스 고객지원에 문의하세요.

### 3. 테스트하기

domain.com 을 설정했다면 testing@domain.com 으로 들어오는 이메일을 받을 수 있어요. 연락처가 anything@domain.com 으로 이메일을 보내 대화를 시작하면 **대화** 탭에 표시돼요.

mg.domain.com 같은 서브도메인을 설정했다면 anything@mg.domain.com 으로 들어오는 이메일을 받을 수 있어요.

## 설정 예시

### 시나리오 1: 표준 설정(권장)

- 발송 도메인: mg.yourdomain.com
- 받은 편지함: yourdomain.com 의 Google Workspace

이메일을 보내는 것도 받는 것도 문제없이 동작해요.

### 시나리오 2: Mailgun만 사용(고급 사용 사례)

- 루트 도메인의 MX → Mailgun

```
라우트로 이메일 처리

받은 편지함 사용 불가

빠른 선택 가이드
```

| 목표 | 권장 설정 |
| --- | --- |
| 이메일 발송만 | Mailgun 서브도메인 사용 |
| 발송 + 받은 편지함 수신 | 루트 → Gmail, 서브도메인 → Mailgun |
| Mailgun 라우트로 수신 | MX를 Mailgun으로 지정(받은 편지함 없음) |

### 흔히 하는 실수

- 기존 MX 레코드를 지우지 않고 Mailgun MX 레코드를 추가하는 경우
- 같은 도메인에서 Gmail과 Mailgun을 함께 인바운드로 쓰려는 경우
- Mailgun이 메일함을 제공할 거라고 기대하는 경우

### 최종 권장 사항

콜드 이메일과 인바운드 라우팅을 설정할 때는 항상 Mailgun에 서브도메인을 사용하세요.

이렇게 하면 다음과 같은 장점이 있어요.

- 역할이 깔끔하게 분리돼요.
- 기본 받은 편지함에 영향이 없어요.
- 이메일 수신과 라우팅이 안정적이에요.

그래도 도움이 필요하면 하이퍼클래스 고객지원에 문의하거나, DNS 제공업체에 설정을 확인해 보세요.

## 자주 묻는 질문

### 같은 도메인에서 Mailgun과 Gmail을 함께 쓸 수 있나요?

아니요. 도메인 하나에는 이메일 수신용 MX 레코드를 한 세트만 둘 수 있어요. MX 레코드가 Gmail을 가리키면 그 도메인의 이메일을 Mailgun이 받을 수 없고, 반대도 마찬가지예요.

### 루트 도메인에 Mailgun MX 레코드를 추가했는데 왜 안 되나요?

도메인에 이미 Google Workspace나 Outlook 같은 MX 레코드가 있을 가능성이 커요. 이메일 시스템은 들어오는 이메일을 여러 서비스에 안정적으로 나누어 처리하지 못해서, 수신이 실패하거나 고르지 않게 전달될 수 있어요.

### Mailgun으로 루트 도메인에서 이메일을 보낼 수 있나요?

네. 이메일 발송은 MX 레코드와 관계없어요. 루트 도메인이 다른 이메일 서비스에 연결되어 있어도 Mailgun으로 이메일을 보낼 수 있어요.

### Mailgun이 받은 편지함을 제공하나요?

아니요. Mailgun은 메일함 화면을 제공하지 않아요. 들어오는 이메일을 라우트나 웹훅으로 전달하거나 처리하기만 해요.

### 콜드 이메일과 답장에는 어떤 설정을 권장하나요?

Mailgun에는 서브도메인(예: mg.yourdomain.com)을 사용하고, 루트 도메인은 Gmail이나 Outlook에 그대로 연결해 이메일을 받으세요.

### 루트 도메인에 Mailgun을 연결해서 인바운드 이메일을 받을 수 있나요?

네, 하지만 MX 레코드를 Mailgun으로 지정할 때만 가능해요. 이 경우 Mailgun이 들어오는 모든 이메일을 처리하므로 기존 받은 편지함(Gmail/Outlook)은 쓸 수 없게 돼요.

### Mailgun은 왜 서브도메인 사용을 권장하나요?

서브도메인을 쓰면 메인 받은 편지함과 충돌하지 않고, 도메인 평판도 보호하며, 이메일 전달도 안정적으로 유지할 수 있어요.
