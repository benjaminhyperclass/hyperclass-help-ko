# 메일 루프 감지됨 — 이메일 라우팅 충돌 해결

이메일이 메일 서버 사이를 계속 맴돌다 반송될 때 원인을 찾아 고치고, 발송을 안전하게 정상화하는 방법을 안내해요. 순환 라우팅 루프를 진단하고, 근본 원인을 해결한 뒤, 발송을 다시 시작하는 순서로 따라 하세요.

## 무슨 일이 일어난 걸까요?

이메일이 메일 서버 사이를 끝없이 돌면서 전달 시도가 무한히 반복되는 상태예요. 메일 서버는 이런 패턴을 감지하면 시스템 과부하를 막기 위해 메시지를 거부해요. 그 결과 이메일이 전달되지 않고, 빨리 해결하지 않으면 발신자 평판에도 영향을 줄 수 있어요.

이메일 전달 규칙, MX 레코드 설정, 자동 응답이 순환 경로를 만들 때 메일 루프가 감지돼요. 다른 전달 문제와 달리 메일 루프는 빠르게 번져 전체 발송 환경에 영향을 줄 수 있어서 바로 대응해야 해요.

## 빠른 진단: 메일 루프 문제 확인하기

반송 메시지에 아래와 같은 내용이 있으면 메일 루프를 의심해 보세요.

### 대표적인 루프 감지 메시지

- "The message was rejected because it was caught in a routing loop between mail servers."(메일 서버 사이의 라우팅 루프에 걸려 메시지가 거부되었습니다.)

## 메일 루프의 원인

### 흔한 루프 상황

이메일 전달 루프

- 이메일 A가 이메일 B로 전달하고, B가 다시 A로 전달해요.
- 캐치올(catch-all) 주소가 자기 자신으로 전달해요.
- 여러 전달 규칙이 서로를 순환 참조해요.
- 자동 응답기가 자동 메시지에 다시 응답해요.

DNS 및 MX 레코드 문제

- MX 항목이 중복되거나 서로 충돌해요.
- MX 레코드의 우선순위 순서가 잘못되었어요.
- 메일 서버 라우팅이 잘못 설정되었어요.
- DNS 전파 과정에서 충돌이 생겨요.

### 하이퍼클래스에서 확인할 부분

워크플로우 관련 루프

- 워크플로우끼리 서로를 순환하며 트리거해요.
- 이메일 기반 트리거가 끝없이 응답을 만들어요.
- 자동 응답기가 외부 시스템과 충돌해요.
- 대화 이메일 전달이 라우팅 충돌을 일으켜요.

도메인 설정 문제

- 도메인 설정이 덜 끝나서 라우팅 문제가 생겨요.
- 인증 설정이 전달 규칙과 충돌해요.
- 여러 이메일 서비스가 같은 도메인을 두고 경쟁해요.
- 캐시된 라우팅 정보 때문에 루프가 계속돼요.

## 메일 루프 해결 단계

### 1단계. 즉시 진단

도메인 설정을 확인해요.

1. 이메일 서비스 화면으로 이동해요.
   - **설정 > 이메일 서비스 > 전용 도메인**으로 이동하세요.
   - 경고 표시나 끝나지 않은 설정 단계가 있는지 확인하세요.
   - 도메인 인증 상태를 확인하세요.
2. 최근 변경 사항을 살펴봐요.
   - 이메일 전달 규칙을 최근에 바꿨는지 확인하세요.
   - 새로 적용한 워크플로우가 있는지 확인하세요.
   - 대화 이메일 연동에 변경이 있었는지 확인하세요.
3. 반송 리포트를 확인해요.
   - **마케팅 > 이메일 > Reports**(리포트)로 이동하세요.
   - 반송 메시지에 반복되는 패턴이 있는지 찾아보세요.
   - 영향을 받은 도메인이나 이메일 주소를 파악하세요.

### 2단계. 외부 도구로 진단

도메인 설정 문제를 확인할 때 쓸 수 있는 MX 레코드 분석 도구예요.

- MXToolbox.com: 이메일 서버를 종합적으로 테스트해요.
- DNSChecker.org: 전 세계 DNS 전파 상태를 확인해요.
- WhatsmyDNS.net: DNS 조회 결과를 확인해요.
- IntoDNS.com: DNS 상태를 전체적으로 점검해요.

이메일 헤더를 분석하려면 아래 순서로 진행해요.

- 이메일 헤더를 수집해요.
  - 반송된 이메일에서 전체 헤더를 복사하세요.
  - 라우팅 경로를 보여 주는 "Received:" 줄을 모두 찾아보세요.
  - 반복해서 나오는 서버 이름이나 IP 주소를 기록해 두세요.
- 헤더 분석 도구를 사용해요.
  - MXToolbox Email Header Analyzer
  - Google Admin Toolbox Message Header
  - Microsoft Message Header Analyzer

### 3단계. 설정 검토

도메인 인증을 확인해요.

1. **설정 > 이메일 서비스 > 전용 도메인 > [내 도메인] > 인증**으로 이동하세요.
2. SPF 레코드를 확인하세요.
3. DMARC 정책 때문에 거부나 재라우팅이 일어나고 있지 않은지 확인하세요.

워크플로우와 자동화를 검토해요.

1. 자동화 워크플로우를 확인해요.
   - **자동화 > 워크플로우**로 이동하세요.
   - 워크플로우끼리 서로를 순환하며 트리거하는지 찾아보세요.
   - 이메일 기반 트리거와 응답을 검토하세요.
   - 답장 루프를 만들 수 있는 워크플로우가 있는지 확인하세요.
2. 이메일 템플릿을 검토해요.
   - **마케팅 > 이메일 > 템플릿**으로 이동하세요.
   - 자동 응답기 설정을 확인하세요.
   - 자동으로 보내는 이메일 응답이 있는지 검토하세요.
3. 대화 설정을 확인해요.
   - **대화 > 설정 > Email Integration**(이메일 연동)으로 이동하세요.
   - 이메일 전달 설정을 확인하세요.
   - 라우팅 충돌이 있는지 검토하세요.

### 4단계. 외부 환경에서 해결

전달 루프를 없애요.

- 도메인 등록 업체나 호스팅 업체 설정을 점검해요.
  - 도메인 관리 페이지에 로그인하세요.
  - 이메일 전달 규칙과 별칭(alias)을 모두 검토하세요.
  - 순환하는 전달 설정을 제거하세요.
  - 자기 자신으로 전달하는 캐치올 설정을 끄세요.
- 자동 응답기를 정리해요.
  - 자동 메시지에 응답하는 자동 응답기를 끄세요.
  - 답장 루프가 생기지 않도록 필터를 알맞게 설정하세요.
  - 발신자 제외 조건을 적절히 설정하세요.

DNS 레코드를 정리해요.

- MX 레코드를 정리해요.
  - 중복되거나 충돌하는 MX 항목을 제거하세요.
  - 우선순위 순서를 올바르게 맞추세요. 숫자가 낮을수록 우선순위가 높아요.
  - 모든 MX 레코드가 유효한 메일 서버를 가리키는지 확인하세요.
  - DNS 전파를 위해 24~48시간 기다리세요.

## 고급 해결 방법

### 도메인 재설정

일반적인 방법으로 해결되지 않을 때 시도해요.

1. **설정 > 이메일 서비스 > Sending Domains**(발송 도메인)로 이동하세요.
2. 캐시된 라우팅을 초기화하려면 도메인을 삭제한 뒤 다시 추가해 보세요.
3. 다시 추가하기 전에 모든 DNS 레코드가 올바르게 설정되어 있는지 확인하세요.
4. 재설정한 뒤에는 소량으로 먼저 테스트하세요.

### 해결하는 동안 캠페인 관리

- 영향을 받는 캠페인을 일시정지해요.
  - **마케팅 > 캠페인 > [캠페인 이름] > 일시정지**로 이동하세요.
  - 루프 문제가 생긴 캠페인을 잠시 멈추세요.
  - 평판 손상이 더 커지지 않도록 막아요.
- 증거를 기록해 둬요.
  - 반송 메시지와 오류 로그를 수집하세요.
  - 루프 패턴이 보이는 이메일 헤더를 저장하세요.
  - 영향을 받은 도메인과 발송량을 기록하세요.

### 테스트와 검증

소규모로 테스트해요.

1. **마케팅 > 이메일 > 테스트 이메일 전송**을 사용하세요.
2. Gmail, Outlook, Yahoo 등 여러 메일 서비스로 보내 보세요.
3. 이메일 헤더에서 라우팅 경로가 올바른지 확인하세요.
4. 전달 리포트에 루프 징후가 없는지 확인하세요.

캠페인을 단계적으로 재개해요.

- 참여도가 높은 연락처 소규모 그룹부터 시작하세요.
- 전달 지표를 면밀히 살펴보세요.
- 루프가 다시 생기는지 지켜보면서 발송량을 서서히 늘리세요.
- 성공적으로 전달된 패턴을 기록해 두세요.

## 예방 방법과 모범 사례

### 이메일 인프라 관리

- 복잡한 전달 체인을 피하세요. 이메일 경로는 단순하고 직접적으로 유지하세요.
- DNS를 정기적으로 점검하세요. MX 레코드는 분기마다 검토하세요.
- 적용 전에 테스트하세요. 전달 규칙은 항상 소량으로 먼저 테스트하세요.
- 설정을 문서로 남기세요. 모든 이메일 라우팅 설정의 기록을 보관하세요.

### 하이퍼클래스 사용 권장 사항

- 발송 전용 도메인을 사용하세요. 마케팅 이메일과 업무용 이메일을 분리하세요.
- 자동화 워크플로우를 점검하세요. 순환 트리거가 없는지 정기적으로 검토하세요.
- 수신 거부 처리를 올바르게 하세요. 처리 과정에서 답장 루프가 생기지 않는지 확인하세요.
- 상태를 정기적으로 점검하세요. 하이퍼클래스의 모니터링 기능을 활용하세요.

### 조기 경보 체계

- 반송 패턴을 지켜보세요. 캠페인을 바꾸지 않았는데 갑자기 늘어나는지 살펴보세요.
- 전달 시간을 추적하세요. 평소와 다른 지연은 라우팅 문제일 수 있어요.
- 오류 메시지를 검토하세요. "too many hops" 패턴이 있는지 찾아보세요.
- 수신자 피드백을 확인하세요. 같은 메시지가 중복으로 왔다는 불만이 있는지 살펴보세요.

## 복구 일정과 예상 기간

### 즉시 대응 단계 (0~24시간)

- 영향을 받는 캠페인을 일시정지하세요. 루프를 일으키는 발송을 바로 멈추세요.
- 증거를 기록하세요. 반송 메시지와 헤더를 수집하세요.
- 근본 원인을 파악하세요. 전달 규칙 문제인지 DNS 문제인지 확인하세요.
- 수정을 시작하세요. 순환하는 전달 규칙을 제거하세요.

### 기술적 해결 단계 (1~3일)

- DNS 전파: MX 레코드 변경이 반영될 때까지 기다리세요.
- 시스템 캐시 정리: 라우팅 정보가 갱신될 때까지 기다리세요.
- 재설정: 도메인 초기화가 필요하다면 이 단계에서 진행하세요.
- 외부 시스템 업데이트: 호스팅 업체와 협의하세요.

### 검증 및 복구 단계 (3~7일)

- 소규모 테스트: 루프가 해결되었는지 확인하세요.
- 발송량 단계적 증가: 문제가 다시 생기는지 지켜보세요.
- 성과 안정화: 정상적인 전달률로 돌아오게 하세요.
- 평판 모니터링: 오래 남는 영향이 없는지 확인하세요.

## 모니터링과 유지 관리

### 정기 모니터링 일정

매일

- **Reports**(리포트) > **Email Performance**(이메일 성과) > **Delivery Metrics**(전달 지표)에서 **이탈률**을 확인하세요.
- 새로운 오류 메시지 패턴이 있는지 살펴보세요.
- 전달 시간이 일정한지 확인하세요.

매주

- 이메일 자동화 워크플로우가 효율적으로 동작하는지 점검하세요.
- 대화 이메일 연동 설정을 검토하세요.
- 새로 생긴 전달 설정이 있는지 확인하세요.

매월

- DNS 레코드를 전체적으로 검토하세요.
- 이메일 전달 설정을 점검하세요.
- 도메인 인증 상태를 확인하세요.

### 핵심 성과 지표

- 이탈률: 전달 상태가 건강하려면 2% 미만으로 유지해야 해요.
- 전달 시간: 라우팅 문제를 나타내는 지연이 없는지 살펴보세요.
- 오류 메시지 패턴: 반복되는 루프 관련 오류를 추적하세요.
- 캠페인 완료율: 전달 성과가 꾸준한지 확인하세요.

## 고객지원과 함께 해결하기

### 하이퍼클래스 고객지원에 문의해야 할 때

- 루프 문제가 계속될 때: 일반적인 해결 방법으로 해결되지 않는 경우예요.
- 도메인 재설정이 필요할 때: 설정이 복잡한 경우예요.
- 워크플로우 최적화가 필요할 때: 고급 자동화 문제를 해결해야 하는 경우예요.
- 성과 분석이 필요할 때: 전달 지표를 자세히 해석해야 하는 경우예요.

### 고객지원에 전달할 정보

- 구체적인 반송 메시지: 오류 전문과 헤더를 모두 알려 주세요.
- 시간 정보: 루프가 언제부터 생겼는지 알려 주세요.
- 설정 내용: 도메인이나 워크플로우를 최근에 어떻게 바꿨는지 알려 주세요.
- 영향을 받은 발송량: 문제의 규모와 범위를 알려 주세요.
- 시도한 해결 방법: 이미 해 본 조치를 알려 주세요.

## 해결 확인 기준

아래와 같다면 메일 루프 문제가 해결된 거예요.

- 이탈률이 정상으로 돌아와요. 전달 상태가 건강하다면 2% 미만이에요.
- 루프 오류 메시지가 없어요. "too many hops" 오류가 사라져요.
- 전달 시간이 정상이에요. 대부분의 메일 서비스에서 5분 이내예요.
- 도메인 전달이 성공해요. 이전에 문제가 있던 도메인이 메일을 다시 받아요.
- 성과 지표가 안정적이에요. 전달률과 참여율이 꾸준해요.

## 그래도 문제가 해결되지 않나요?

메일 루프 문제가 계속된다면 아래를 확인해 보세요.

1. 모든 전달 규칙을 다시 확인하세요. 순환 참조가 남아 있지 않은지 살펴보세요.
2. DNS 전파를 확인하세요. 변경 사항이 반영되도록 48시간을 충분히 기다리세요.
3. 워크플로우를 검토하세요. 자동화끼리 충돌하지 않는지 확인하세요.
4. 하이퍼클래스 고객지원에 문의하세요. 플랫폼 전문가의 도움을 받을 수 있어요.
5. 전문가 상담을 고려하세요. 인프라 문제가 복잡한 경우에 좋아요.

{% hint style="info" %}
메일 루프는 체계적으로 해결해야 하는 기술 문제예요. 순환 라우팅 패턴을 없애고, DNS 설정을 깔끔하게 유지하고, 자동화 워크플로우에 충돌 가능성이 없는지 계속 살펴보세요.
{% endhint %}

## 자주 묻는 질문

### 메일 루프 때문인지 일반 반송인지 어떻게 구분하나요?
반송 메시지 자체를 살펴보세요. 일반 반송은 잘못된 주소나 가득 찬 메일함처럼 구체적인 이유를 알려 줘요. 루프로 인한 반송에는 라우팅, "too many hops", "caught in a loop between mail servers" 같은 표현이 나와요.

### 도메인을 삭제하고 다시 추가하면 데이터가 사라지나요?
도메인을 삭제하고 다시 추가하면 캐시된 라우팅과 인증 상태는 초기화되지만, 캠페인·연락처·기존 데이터는 삭제되지 않아요. 다만 DNS 레코드를 다시 설정하고 재인증을 기다려야 해요.

### 해결하는 동안 캠페인을 일시정지하면 발신자 평판에 나쁜가요?
아니요. 일시정지는 평판을 지키는 조치예요. 루프가 계속되는 상태에서 발송을 이어 가면, 전달 규칙이나 DNS 문제를 고치는 동안 잠시 멈추는 것보다 평판이 훨씬 더 나빠져요.

### DNS를 고친 뒤 얼마나 기다렸다가 전체 발송을 재개해야 하나요?
DNS 변경이 전파되도록 24~48시간을 주고, 소규모로 테스트 발송해 확인한 다음 발송량을 늘리세요. DNS를 바꾼 직후 바로 전체 발송으로 가면, 아직 완전히 해소되지 않은 루프를 놓칠 수 있어요.

### 자동 응답기 하나만 잘못 설정해도 메일 루프가 생기나요?
네. 자동 메시지나 반송 메시지에 답장하는 자동 응답기는 루프의 가장 흔한 원인 중 하나예요. 자동 응답이 또 다른 자동 응답을 불러오기 때문이에요.

### 도메인 호스팅 업체와 하이퍼클래스 고객지원 중 어디에 먼저 문의해야 하나요?
먼저 이 문서의 단계대로 직접 진단해 보세요. 원인이 도메인 호스팅 업체의 전달 규칙이나 DNS에 있다면 해당 업체에 직접 문의하세요. 원인이 워크플로우나 도메인 설정에 있다면 하이퍼클래스 고객지원에 문의하세요.
