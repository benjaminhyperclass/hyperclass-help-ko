# 수신자 정책 차단 해결 가이드

받는 쪽 메일 서버가 정책을 이유로 이메일을 거부할 때, 원인을 파악하고 단계별로 해결하는 방법을 안내해요. 발송한 이메일이 "정책" 또는 "접근 제한" 때문에 거부됐다는 메시지를 받았을 때 참고하세요.

## 어떤 상황인가요?

받는 쪽 메일 서버가 관리 정책, 보안 제한, 접근 제어 규칙 때문에 이메일을 거부하고 있어요. 기술적인 전송 오류와 달리, 이런 차단은 받는 조직이 원치 않거나 해로울 수 있는 메일로부터 자기 메일 환경을 보호하려고 의도적으로 정한 정책이에요.

## 빠른 진단: 정책 차단 확인하기

자주 보이는 정책 차단 메시지는 다음과 같아요.

- "수신 메일 서버가 관리 정책 또는 정책 제한 때문에 메시지를 차단했습니다"
- "수신 메일 서버가 사용자 없음, 릴레이 거부, 스팸 감지 등 자체 정책에 따라 메시지를 거부했습니다"
- "수신자의 사서함은 승인된 발신자의 메일만 받습니다. 발신 주소가 허용되지 않았습니다"
- "수신 메일 서버가 정책 또는 차단 목록 규칙에 따라 발신자를 거부했습니다"
- "수신 도메인이 자체 정책에 따라 메일을 적극적으로 거부하고 있습니다"
- "수신 조직이 보안 또는 정책상의 이유로 외부 이메일 전달을 차단합니다"
- "수신자가 수신거부했거나 동의를 철회해서 정책에 따라 이메일 전송이 차단되었습니다"
- "그룹 구성원 제한 또는 외부 발신자 제한 때문에 이 그룹에 이메일을 보낼 수 없습니다"
- "수신 메일 서버가 허용된 IP나 인증서를 제한하는 엄격한 커넥터 정책에 따라 메시지를 거부했습니다"

## 수신자 정책 차단 이해하기

{% hint style="warning" %}
알아 두세요.

- 정책 차단은 의도적인 제한이며, 기술적인 오류가 아니에요.
- 이런 차단은 조직을 스팸, 피싱, 원치 않는 메일로부터 보호해요.
- 해결하려면 보내는 쪽과 받는 쪽이 모두 조치해야 하는 경우가 많아요.
- 일부 정책 차단은 조직이 영구적으로 정한 결정이에요.
{% endhint %}

### 정책 차단 유형

발신자 기반 차단

- IP 주소 또는 도메인 블랙리스트 등록
- 발신자 평판 제한
- 인증되지 않은 발신자에 대한 정책

콘텐츠 기반 차단

- 스팸 필터에 걸림
- 콘텐츠 정책 위반
- 첨부파일 제한

접근 제어 차단

- 허용 목록(화이트리스트)만 받는 정책
- 외부 발신자 제한
- 그룹 구성원 요건

## 단계별 해결 방법

### 1단계. 이메일 인증 확인하기

도메인 인증 설정을 확인하세요.

1. 인증 설정 화면으로 이동해요.
   - **설정 > 이메일 서비스 > Sending Domain & IP**(발송 도메인 및 IP)로 이동하세요.
   - SPF, DKIM, DMARC 레코드가 올바르게 설정되어 있는지 확인하세요.
   - 모든 인증 항목이 **인증됨** 상태인지 확인하세요.
2. 외부 도구로도 인증을 점검해요.
   - MXToolbox.com에서 SPF와 DKIM 레코드를 확인하세요.
   - dmarcian.com에서 DMARC 정책 정렬을 확인하세요.

{% hint style="info" %}
인증이 잘 되었다는 신호

- 하이퍼클래스에서 모든 도메인 인증 항목이 통과해요.
- 외부 도구에서도 SPF, DKIM, DMARC 설정이 올바르다고 나와요.
- 인증 관련 반송 메시지가 없어요.
{% endhint %}

### 2단계. 발신자 평판 모니터링하기

발송 평판을 점검하세요.

1. 평판 점수를 확인해요.
   - senderscore.org에서 IP 평판을 확인하세요(80점 이상을 목표로 하세요).
   - Talos Intelligence에서 도메인 평판을 확인하세요.
   - Outlook/Hotmail 사용자에게 보낸다면 Microsoft SNDS도 확인하세요.
2. 지표를 검토해요.
   - **마케팅 > 이메일 마케팅 > 분석**으로 이동하세요.
   - 반송률, 스팸 신고율, 수신 취소율을 확인하세요.
   - 정책 차단 메시지에서 반복되는 패턴을 찾아보세요.

### 3단계. 수신 조직에 연락하기

허용 목록 등록을 요청하세요.

1. 연락할 담당자를 찾아요.
   - IT 관리자나 이메일 보안팀의 연락처를 찾아보세요.
   - 해당 조직의 웹사이트에서 이메일 전송 문의 창구를 확인하세요.
   - 전화, 문자 같은 다른 연락 수단도 활용하세요.
2. 허용 목록 등록 요청서를 준비해요.
   - 발송 도메인과 IP 주소를 적으세요.
   - 업무상 관계와 이메일을 보내는 목적을 설명하세요.
   - 올바른 인증 설정과 규정 준수를 보여 주는 자료를 함께 보내세요.

### 4단계. 이메일 콘텐츠와 발송 방식 개선하기

정책에 걸릴 가능성을 줄이세요.

1. 이메일 콘텐츠를 검토해요.
   - 스팸으로 의심받는 단어와 지나친 홍보 문구를 피하세요.
   - 텍스트와 이미지의 비율을 적절하게 맞추세요.
   - 수신 취소 방법을 분명하게 넣으세요.
2. 리스트를 꾸준히 관리해요.
   - 반송되었거나 수신 취소한 연락처를 주기적으로 정리하세요.
   - 참여도에 따라 리스트를 나누세요.

{% hint style="info" %}
콘텐츠 최적화가 잘 되었다는 신호

- mail-tester.com으로 테스트했을 때 스팸 점수가 낮아져요.
- 참여율이 오르고 신고가 줄어요.
- 이전에 차단하던 도메인에도 꾸준히 전달돼요.
{% endhint %}

## 복구 일정과 기대 효과

| 단계 | 조치 | 기대 결과 |
| --- | --- | --- |
| 1단계: 즉시 조치 (1~3일) | 인증 문제 수정 — 인증 기반 차단은 바로 개선돼요 | 기술적인 인증 문제 해결 |
| 2단계: 평판 쌓기 (2~4주) | 좋은 발송 습관 유지 — 발신자 평판이 서서히 좋아져요 | 평판 기반 필터에 의한 정책 차단 감소 |
| 3단계: 관계 쌓기 (계속) | 허용 목록 등록 요청 — 수신 조직이 얼마나 빨리 응답하는지에 따라 기간이 달라요 | 특정 수신 도메인의 차단을 영구적으로 해결 |

## 예방 방법

사전 모니터링

- 매주 평판 확인: Sender Score와 도메인 평판을 확인하세요.
- 반송 분석: 분석 화면에서 반송 메시지를 매주 살펴보세요.
- 참여도 추적: 오픈율, 클릭률, 신고 건수를 확인하세요.

이메일 발송 모범 사례

- 수신 동의를 받은 리스트만 사용하기: 명시적으로 수신에 동의한 연락처에게만 보내세요.
- 정기적인 리스트 정리: 비활성 연락처와 반송되는 연락처를 매월 제거하세요.
- 발송량 점진적으로 늘리기: 새로운 도메인에는 발송량을 천천히 늘리세요.
- 일정한 발송 패턴 유지하기: 발송 일정과 발송량을 꾸준히 유지하세요.

## 문제가 계속되나요?

정책 차단 문제가 계속된다면 다음을 해 보세요.

1. 패턴을 기록하세요. 어떤 도메인이 차단하는지, 구체적인 오류 메시지가 무엇인지 자세히 적어 두세요.
2. 다른 소통 수단을 고려하세요. 중요한 연락은 전화, 우편, 소셜 미디어를 이용하세요.
3. 이메일 전략을 점검하세요. 지금의 방식이 수신자의 기대에 맞는지 검토하세요.

## 자주 묻는 질문

### 정책 차단은 블랙리스트에 오른 것과 같은 건가요?

아니요. 블랙리스트 등록은 인터넷 전반에서 공유되는 평판 기반 표시예요. 정책 차단은 특정 수신 조직 한 곳이 정한 규칙이어서, 평판이 깨끗하고 블랙리스트에 등록되지 않은 발신자에게도 일어날 수 있어요.

### 수신 조직에서 허용 목록에 등록되기까지 얼마나 걸리나요?

수신 조직의 IT 팀과 내부 절차에 따라 크게 달라요. 며칠 안에 답하는 곳도 있고 몇 주가 걸리는 곳도 있으며, 허용 목록 등록을 아예 제공하지 않는 조직도 있어요.

### 수신 조직이 허용 목록 등록 요청에 답하지 않으면 어떻게 하나요?

전화나 업무상 직접 아는 담당자처럼, 일반 IT 메일함이 아닌 다른 연락 수단을 시도해 보세요. 그래도 답이 없다면 앞으로 그 수신자에게는 다른 소통 수단을 쓰는 것을 고려하세요.

### SPF, DKIM, DMARC를 고치면 모든 정책 차단이 해결되나요?

인증 기반 차단은 해결되지만, 모든 차단이 해결되는 것은 아니에요. 허용 목록만 받는 정책이나 그룹 구성원 제한 같은 접근 제어 차단은 인증 설정과 상관없이 수신 조직이 직접 조치해야 해요.

### 한 도메인에서 받은 정책 차단이 다른 메일 서비스의 발신자 평판에도 영향을 주나요?

한 조직에서 한 번 정책 차단을 받았다고 해서 다른 곳의 평판이 나빠지지는 않는 편이에요. 하지만 리스트 관리 부실 같은 같은 원인 때문에 여러 도메인에서 차단된다면 전반적인 발송 평판에 영향을 줄 수 있어요.

### 계속 정책 차단을 받으면 다른 발송 도메인을 써 봐야 하나요?

도메인을 바꿔도 근본적인 정책이나 평판 문제는 해결되지 않고, 이력이 없는 새 도메인을 쓰게 될 수 있어요. 먼저 근본 원인을 해결하세요. 도메인 변경은 현재 도메인에 회복할 수 없는 문제가 있을 때만 고려하는 것이 좋아요.
