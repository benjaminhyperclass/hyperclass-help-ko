# 올바르지 않거나 제한된 수신자 도메인으로 가는 이메일 차단

수신자 이메일 주소의 도메인이 올바르지 않거나 보안상 제한된 경우, 하이퍼클래스는 이메일을 보내기 전에 발송을 차단해요. 이 문서에서는 차단이 어떻게 동작하는지, 화면에 무엇이 표시되는지, 차단된 주소를 어떻게 해결하는지 알아봐요.

보안 위험을 높이거나 전송 실패로 이어질 수 있는 도메인으로는 이메일이 나가지 않아요. 덕분에 발신자 평판을 지킬 수 있어요.

## 제한 도메인 차단이란?

제한 도메인 차단은 이메일을 보내기 전에 확인하는 발송 전 검증이에요. 연락처 이메일 주소에서 @ 뒤에 오는 도메인이 올바르지 않거나 제한된 도메인이면 이메일을 차단해요. 차단되면 하이퍼클래스는 발송을 시도하지 않아요.

## 이런 점이 좋아요

- 전송 실패를 줄여 줘요. 어차피 전달되지 않을 가능성이 큰 이메일을 미리 막아요.
- 전달률을 지켜 줘요. 하드 바운스가 줄면 발신자 평판에 미치는 위험도 줄어요.
- 보안이 좋아져요. 보안상 제한된 도메인으로는 이메일을 보내지 않아요.

## 동작 방식

1. **수신자 도메인 검증**: 이메일을 보내기 전에 수신자 이메일 주소의 도메인을 검증해요.
2. **올바르지 않거나 제한된 경우 차단**: 도메인이 올바르지 않거나 제한되어 있으면 이메일이 나가기 전에 발송을 막아요.
3. **주소를 수정하기 전에는 사용 불가**: 허용된 도메인의 주소로 바꾸기 전까지는 해당 연락처의 이메일 주소로 이메일을 보낼 수 없어요.

## 화면에 표시되는 내용

차단된 이메일 주소가 있으면 연락처의 **이메일** 필드 아래에 경고 문구가 표시돼요.

> "도메인이 보안상의 이유로 제한되어 있어 올바르지 않은 이메일 주소예요."

![연락처의 이메일 필드 아래에 표시된 제한 도메인 차단 경고](https://jumpshare.com/share/Mm7ljWEF1FhCL3PETxJK+/image+%284%29+%281%29.png)

## 해결 방법

1. 이메일 주소가 맞는지 확인하세요. 특히 @ 뒤의 도메인에 오타가 없는지 살펴보세요.
2. 연락처의 이메일 주소를 허용된 도메인의 올바른 주소로 바꾸세요. 수정하면 이메일 발송이 다시 정상적으로 이루어져요.
3. 꼭 연락해야 하는 수신자라면 하이퍼클래스 고객지원에 문의하세요. 문의할 때 다음 정보를 함께 알려 주세요.
   - 수신자 도메인 (예: example.com)
   - 경고를 본 위치 (연락처 상세 화면, **대화**, **캠페인**, **워크플로우** 등)
   - 서브 계정 이름 또는 ID
   - 발송 방식 (하이퍼클래스 이메일, Mailgun, 사용자 지정 SMTP)

{% hint style="info" %}
앱 안에서 이 차단을 해제하는 방법은 없어요. 발송을 다시 하려면 주소를 허용된 도메인의 주소로 바꿔야 해요.
{% endhint %}

## 자주 묻는 질문

### 이 경고가 표시된 이메일 주소로도 이메일을 보낼 수 있나요?
아니요. 수신자 도메인이 올바르지 않거나 제한되어 있으면 이메일이 시스템을 떠나기 전에 발송이 차단돼요.

### 차단을 해제하거나 우회할 수 있나요?
아니요. 연락처의 이메일 주소를 허용된 도메인의 올바른 주소로 바꿔야 해요.

### 경고는 어디에서 볼 수 있나요?
차단된 주소를 불러오거나 입력할 때마다 연락처의 **이메일** 필드 아래에 경고 문구가 표시돼요.

### 차단되어도 하이퍼클래스가 발송을 시도하나요?
아니요. 이 경고가 표시되면 발송을 시도하지 않아요. 해당 주소로 가는 캠페인, 워크플로우, 수동 발송이 모두 검증 단계에서 차단돼요.

### 이런 일이 생기지 않게 하려면 어떻게 해야 하나요?
수신자 이메일 주소를 받을 때 미리 확인하세요. 폼 유효성 검사, 더블 옵트인, 이메일 검증 서비스를 활용하면 좋아요. 또 발송하기 전에 @ 뒤 도메인의 오타를 미리 고쳐 두세요.

### 모든 발송 방식에 적용되나요?
네. 하이퍼클래스 이메일, Mailgun, 사용자 지정 SMTP 연동 중 어떤 방식을 쓰든 발송 전 검증이 똑같이 실행돼요.

### 차단된 발송도 바운스율에 포함되나요?
아니요. 실제로 발송되지 않기 때문에 차단된 주소는 바운스를 만들지 않아요. 이 점이 이 기능이 발신자 평판을 지켜 주는 방법 중 하나예요.
