# 워크플로우로 커뮤니티 그룹 접근 권한 자동화하기

하이퍼클래스 워크플로우로 커뮤니티 그룹 접근 권한을 확인하고, 부여하고, 회수할 수 있어요. 그룹 접근 권한 트리거는 멤버가 권한을 얻거나 잃은 뒤에 자동화를 시작하고, 그룹 접근 권한 액션은 워크플로우가 직접 권한을 바꿔요. 이 문서에서는 트리거와 액션을 각각 언제 쓰는지, 두 가지 워크플로우를 어떻게 설정하는지 알려 드려요.

## 이 문서에서 알아볼 내용

- 커뮤니티 그룹 접근 권한 트리거와 액션의 차이
- 접근 권한이 바뀔 때 반응하는 워크플로우 만들기
- 접근 권한을 자동으로 부여하거나 회수하기
- 그룹 접근 권한, 가입 요청, 비공개 채널의 구분
- 게시하기 전에 워크플로우 테스트하기

{% hint style="warning" %}
**Group Access Granted**(그룹 접근 권한 부여됨)와 **Group Access Revoked**(그룹 접근 권한 회수됨)는 멤버의 접근 권한이 바뀐 뒤에 동작해요. 접근 권한이 승인되기 전, 대기 중인 가입 요청에는 **Requested to Join Group**(그룹 가입 요청)을 써요. 비공개 채널 접근 권한에는 별도의 커뮤니티 워크플로우 트리거와 액션을 써요.
{% endhint %}

## 커뮤니티 그룹 접근 권한 자동화란?

커뮤니티 그룹 접근 권한 자동화는 하이퍼클래스 커뮤니티와 **워크플로우 빌더**(Workflow Builder)를 연결해요. 멤버의 그룹 접근 권한이 바뀔 때 워크플로우가 반응할 수도 있고, 더 큰 자동화 흐름 안에서 워크플로우가 직접 접근 권한을 바꿀 수도 있어요.

핵심은 접근 권한 변경이 워크플로우를 시작해야 하는지, 아니면 워크플로우가 접근 권한을 바꿔야 하는지예요.

| 유형 | 이름 | 하는 일 |
| --- | --- | --- |
| 트리거 | **Group Access Granted** | 멤버가 커뮤니티 그룹에 대한 접근 권한을 얻은 뒤 워크플로우를 시작해요. |
| 트리거 | **Group Access Revoked** | 멤버의 커뮤니티 그룹 접근 권한이 회수된 뒤 워크플로우를 시작해요. |
| 액션 | **Grant Group Access**(그룹 접근 권한 부여) | 워크플로우가 실행되는 동안 연락처에게 지정한 커뮤니티 그룹의 접근 권한을 부여해요. |
| 액션 | **Revoke Group Access**(그룹 접근 권한 회수) | 워크플로우가 실행되는 동안 연락처의 지정한 커뮤니티 그룹 접근 권한을 제거해요. |

간단한 기준은 이래요. 접근 권한 변경으로 자동화를 시작하고 싶으면 트리거를 쓰세요. 워크플로우가 접근 권한을 바꾸게 하고 싶으면 액션을 쓰세요.

### 커뮤니티 그룹 접근 권한 자동화의 장점

커뮤니티 접근 권한을 자동화하면 반복되는 관리 작업이 줄어들고, 그룹 멤버십을 하이퍼클래스 워크플로우로 관리하는 고객 여정의 일부로 만들 수 있어요.

- 온보딩 자동화: 고객 여정에서 조건에 맞는 다른 이벤트가 일어난 뒤 커뮤니티 그룹 접근 권한을 부여해요.
- 접근 권한 제거 자동화: 워크플로우 조건에 따라 그룹 접근 권한을 회수해요.
- 접근 권한 기반 후속 조치: 그룹 접근 권한이 부여되거나 제거된 뒤 커뮤니케이션이나 내부 작업을 시작해요.
- 일관된 접근 권한 관리: 조건에 맞는 연락처에게 같은 접근 권한 규칙을 적용해요.
- 연결된 자동화: 커뮤니티 접근 권한을 하이퍼클래스 워크플로우에서 지원하는 다른 트리거, 조건, 액션과 함께 써요.

## 시작하기 전에

자동화가 접근 권한 변경에 반응해야 하는지, 접근 권한을 직접 바꿔야 하는지 먼저 정하면 나머지를 만들기 전에 알맞은 커뮤니티 워크플로우 구성 요소를 고를 수 있어요.

시작하기 전에 아래를 준비하세요.

- 워크플로우가 모니터링하거나 관리할 커뮤니티 그룹을 만들거나 정해 두세요.
- 워크플로우가 접근 권한 변경에 **반응**할지, 접근 권한을 **직접 바꿀**지 정하세요.
- 연락처가 워크플로우에 들어오는 계기가 될 이벤트나 조건을 정하세요.
- 더 넓은 범위에 쓰기 전에 대표 테스트 연락처로 먼저 확인하세요.

아래 접근 권한 유형은 서로 구분해서 쓰세요.

- 부여/회수된 접근 권한: Group Access Granted와 Group Access Revoked는 접근 권한이 바뀐 뒤에 반응해요.
- 접근 권한 액션: Grant Group Access와 Revoke Group Access는 워크플로우가 진행되는 동안 연락처의 그룹 접근 권한을 바꿔요.
- 대기 중인 가입 요청: 접근 권한이 승인되기 전에 가입 요청에서 자동화를 시작하려면 Requested to Join Group을 써요.
- 비공개 채널: 비공개 채널 접근 권한에는 별도의 부여/회수 트리거와 액션이 있어요.

## 커뮤니티 그룹 접근 권한 트리거와 액션

커뮤니티 접근 권한 트리거와 액션은 각각 멤버 여정의 다른 시점을 나타내요. 어떤 것을 고르느냐에 따라 워크플로우가 그룹 접근 권한 이벤트를 기다릴지, 직접 접근 권한을 바꿀지가 정해져요.

### Group Access Granted

**Group Access Granted**는 커뮤니티 워크플로우 트리거예요. 멤버가 선택한 그룹의 접근 권한을 얻은 뒤 워크플로우를 시작해요. 접근 권한을 얻는 일이 환영 메시지, 내부 알림, 태그 지정 시퀀스 같은 다른 프로세스의 시작점이 되어야 할 때 쓰세요.

### Group Access Revoked

**Group Access Revoked**는 커뮤니티 워크플로우 트리거예요. 멤버가 선택한 그룹의 접근 권한을 잃은 뒤 워크플로우를 시작해요. 접근 권한을 잃은 일이 후속 자동화의 시작점이 되어야 할 때 쓰세요.

### Grant Group Access

**Grant Group Access**는 커뮤니티 워크플로우 액션이에요. 워크플로우에 들어온 연락처에게 선택한 커뮤니티 그룹의 접근 권한을 부여해요. 조건에 맞는 다른 워크플로우 이벤트의 결과로 커뮤니티 그룹 접근 권한을 줘야 할 때 쓰세요.

### Revoke Group Access

**Revoke Group Access**는 커뮤니티 워크플로우 액션이에요. 워크플로우에 들어온 연락처의 선택한 커뮤니티 그룹 접근 권한을 제거해요. 다른 워크플로우 이벤트나 조건의 결과로 접근 권한을 제거해야 할 때 쓰세요.

## 그룹 접근 권한 트리거 워크플로우 만들기

그룹 접근 권한 트리거 워크플로우는 접근 권한이 이미 부여되거나 회수된 뒤에 반응해요. 접근 권한 변경이 후속 커뮤니케이션, 내부 처리, 다른 워크플로우 액션을 자동으로 시작해야 할 때 이 방식으로 설정하세요.

### 1단계: 워크플로우 만들기

커뮤니티 접근 권한 이벤트가 등록 트리거가 되도록 새 워크플로우로 시작해요.

1. **서브 계정 보기**에서 **자동화**를 클릭하세요.
2. **워크플로우**를 선택하세요.
3. **+ Create workflow**(워크플로우 만들기)를 클릭하세요.
4. **처음부터 시작**을 선택하세요.

![새 워크플로우를 처음부터 만드는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155081371537/original/HyT5J-vz4MuLa_D-hMjWYNDW3BtsByxDbA.png?1789849627)

### 2단계: 커뮤니티 접근 권한 트리거 추가하기

멤버를 워크플로우에 등록할 접근 권한 이벤트를 고르고, 자동화가 모니터링할 커뮤니티 그룹을 선택해요.

1. **+ Add**(추가)를 클릭하세요.
2. **Add trigger**(트리거 추가)를 선택하세요.
3. **Group Access Granted** 또는 **Group Access Revoked**를 검색해서 선택하세요.
4. 모니터링할 커뮤니티 그룹에 맞게 트리거를 설정하세요.
5. 트리거 설정을 저장하세요.

![커뮤니티 접근 권한 트리거를 추가하는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155081371465/original/pYr-GsCn44eaP0-rbvCkNKrCG9hTHZ0nJQ.png?1789849485)

### 3단계: 후속 액션 추가하기

후속 액션은 하이퍼클래스가 그룹 접근 권한 이벤트를 감지한 뒤 무엇을 할지 정해요.

1. 트리거 아래의 **+** 아이콘을 클릭하세요.
2. 다음에 실행할 워크플로우 액션을 선택하고 설정하세요.
3. 프로세스에 필요한 조건, 커뮤니케이션, 액션을 더 추가하세요.

### 4단계: 테스트하고 게시하기

대표 연락처로 테스트하면, 조건에 맞는 연락처에게 워크플로우를 켜기 전에 예상한 경로대로 진행되는지 확인할 수 있어요.

1. 트리거와 모든 워크플로우 액션을 검토하세요.
2. **Test workflow**(워크플로우 테스트)를 클릭하세요.
3. 알맞은 테스트 연락처를 선택하세요.
4. **Run test**(테스트 실행)를 클릭하고 워크플로우가 예상대로 동작하는지 확인하세요.
5. 워크플로우가 준비되면 **Draft**(임시 저장)를 **Publish**(게시)로 바꾸세요.

![워크플로우를 임시 저장에서 게시로 전환하는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155081371469/original/bsG86aZlmBn3gbV1ePYdLFzfSvPhWKTCoA.png?1789849500)

Draft와 Publish의 차이: 워크플로우 변경 내용을 저장해도 자동화가 바로 켜지지는 않아요. **Draft** 상태의 워크플로우는 **Publish**하기 전까지 조건에 맞는 연락처에게 실행되지 않아요.

## 워크플로우로 그룹 접근 권한 부여하거나 회수하기

부여·회수 액션을 쓰면 하이퍼클래스에서 일어난 다른 이벤트에 따라 연락처가 커뮤니티 그룹 접근 권한을 얻거나 잃게 할 수 있어요. 트리거가 고객 여정을 시작하고, 커뮤니티 액션이 접근 권한을 바꿔요.

### 1단계: 워크플로우 트리거 고르기

사용 목적에 맞는 지원되는 트리거라면 무엇이든 워크플로우를 시작할 수 있어요. 하이퍼클래스가 연락처의 그룹 접근 권한 변경 여부를 판단할 시점을 정해 줄 이벤트를 고르세요.

1. **자동화 > 워크플로우**로 이동하세요.
2. 새 워크플로우를 만들거나 기존 워크플로우를 여세요.
3. 연락처를 등록할 트리거를 추가하고 설정하세요.
4. 트리거 설정을 저장하세요.

### 2단계: 그룹 접근 권한 액션 추가하기

워크플로우가 수행할 접근 권한 변경에 맞는 커뮤니티 액션을 추가해요.

1. 트리거나 이전 워크플로우 단계 아래의 **+ Add**를 클릭하세요.
2. **Add action**(액션 추가)을 선택하세요.
3. **Grant Group Access** 또는 **Revoke Group Access**를 검색하세요.
4. 알맞은 커뮤니티 액션을 선택하세요.
5. 접근 권한을 부여하거나 회수할 커뮤니티 그룹을 선택하세요.
6. 액션 설정을 저장하세요.

![그룹 접근 권한 액션을 추가하는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155081371598/original/NBMlyU-4_ZpNkWqomKFxMBAdgo0KoAHHUg.png?1789849851)

### 3단계: 워크플로우를 완성하고 테스트한 뒤 게시하기

나머지 고객 여정을 완성한 다음, 게시하기 전에 그룹 접근 권한 결과를 확인하세요.

1. 프로세스에 필요한 워크플로우 단계를 더 추가하세요.
2. 선택한 커뮤니티 그룹과 접근 권한 액션을 검토하세요.
3. 해당하는 경우 알맞은 연락처로 **Test workflow**를 사용하세요.
4. 예상한 그룹 접근 권한 변경이 일어나는지 확인하세요.
5. 실행할 준비가 되면 워크플로우를 **Draft**에서 **Publish**로 바꾸세요.

## 그룹 접근 권한 워크플로우 활용 팁

트리거 로직을 분명하게 하고, 이름을 알아보기 쉽게 짓고, 테스트를 꼼꼼히 하면 커뮤니티 접근 권한 워크플로우를 이해하기 쉬워지고 의도하지 않은 멤버십 변경도 줄어요.

- 트리거와 액션 구분하기: 접근 권한 이벤트로 자동화를 시작하려면 Group Access Granted 또는 Revoked를 쓰세요. 워크플로우가 접근 권한을 바꾸게 하려면 Grant 또는 Revoke Group Access를 쓰세요.
- 그룹 확인하기: 게시하기 전에 모든 트리거와 액션에서 선택한 커뮤니티 그룹을 확인하세요.
- 알아보기 쉬운 워크플로우 이름 쓰기: 접근 권한 이벤트와 커뮤니티 그룹을 워크플로우 이름에 넣으면 목적을 쉽게 알 수 있어요.
- 대표 이벤트로 테스트하기: 널리 적용하기 전에 워크플로우 등록과 그 결과로 바뀐 접근 권한 상태를 모두 테스트하세요.
- 의도하지 않은 자동화 반복 피하기: 한 워크플로우가 그룹 접근 권한을 바꾸고 다른 워크플로우가 그 접근 권한 변경에서 시작한다면, 연락처가 서로 충돌하는 접근 권한 액션을 반복해서 거치지 않도록 전체 여정을 검토하세요.
- 알맞은 가입 요청 트리거 쓰기: 대기 중인 멤버가 승인되기 전에 자동화를 시작하려면 Requested to Join Group을 쓰세요.
- 비공개 채널 로직 분리하기: 그룹 전체가 아니라 비공개 채널의 접근 권한을 관리하는 워크플로우에는 전용 비공개 채널 트리거와 액션을 쓰세요.

## 자주 묻는 질문

### Group Access Granted와 Grant Group Access는 뭐가 다른가요?

**Group Access Granted**는 접근 권한이 부여된 뒤 자동화를 시작하는 워크플로우 트리거예요. **Grant Group Access**는 연락처가 워크플로우를 진행하는 동안 접근 권한을 부여하는 워크플로우 액션이에요.

### Group Access Revoked와 Revoke Group Access는 뭐가 다른가요?

**Group Access Revoked**는 그룹 접근 권한이 제거된 뒤 워크플로우를 시작해요. **Revoke Group Access**는 워크플로우가 실행되는 동안 연락처의 접근 권한을 제거하는 액션이에요.

### 커뮤니티 그룹 가입 요청도 자동화할 수 있나요?

네, 할 수 있어요. 대기 중인 가입 요청에서 자동화를 시작하려면 별도의 **Requested to Join Group** 트리거를 쓰세요. 이 방식에서는 접근 권한이 부여되기 전에 선택한 그룹과 설정해 둔 멤버십 질문 응답을 활용할 수 있어요.

### 그룹 접근 권한을 얻거나 잃은 뒤에 알림을 보낼 수 있나요?

네, 보낼 수 있어요. **Group Access Granted** 또는 **Group Access Revoked**를 트리거로 쓰고, 워크플로우에 필요한 알림이나 커뮤니케이션 액션을 추가하세요. 지원되는 액션만 쓸 수 있어요.

### 다른 워크플로우 이벤트로 커뮤니티 그룹 접근 권한을 자동으로 부여하거나 회수할 수 있나요?

네, 할 수 있어요. 워크플로우를 시작할 지원되는 이벤트를 설정한 다음, 커뮤니티 액션으로 **Grant Group Access** 또는 **Revoke Group Access**를 추가하세요.

### 이 트리거와 액션으로 비공개 커뮤니티 채널도 관리할 수 있나요?

아니요. 비공개 채널 접근 권한에는 **Private Channel Access Granted**(비공개 채널 접근 권한 부여됨), **Private Channel Access Revoked**(비공개 채널 접근 권한 회수됨), **Grant Private Channel Access**(비공개 채널 접근 권한 부여), **Revoke Private Channel Access**(비공개 채널 접근 권한 회수) 워크플로우 옵션을 따로 써요.
