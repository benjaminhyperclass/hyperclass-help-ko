# 퍼널·웹사이트·웨비나 기본 문제 해결 FAQ

퍼널, 웹사이트, 웨비나를 쓰다가 자주 겪는 문제와 해결 방법을 모았어요. 추적 코드, 커스텀 필드, 이미지, 화면 표시 오류 등을 확인할 때 참고하세요.

## 자주 겪는 문제와 해결 방법

### 1. 헤드 추적 코드가 `<head>` 태그 안에 보이지 않아요

**문제**

헤드·바디 **추적 코드**는 브라우저(클라이언트)에서 삽입돼요. 그래서 페이지 소스의 `<head>` 태그 안에는 보이지 않아요. 페이지 소스에서 보이는 것은 페이지를 그리기 위한 초기 HTML 데이터예요. 하이퍼클래스는 추적 코드를 클라이언트 쪽에서 동적으로 넣기 때문에 정적인 소스 보기에는 나타나지 않아요.

Google Tag Manager(GTM) 같은 별도의 추적 도구를 써도 스크립트는 정상적으로 동작해요. 클라이언트 쪽 삽입 방식은 GTM과 비슷한 도구와 호환돼요.

**해설**

소스 코드에서 보이는 것은 페이지를 그리는 데 쓰는 데이터예요. 동적으로 삽입된 추적 코드는 여기에 나오지 않아요.

**해결 방법**

하이퍼클래스가 헤드·바디 추적 코드를 삽입하는 방식은 영상 설명을 참고하세요.

### 2. 업데이트한 커스텀 필드 값이 미리보기나 사이트에 표시되지 않아요

**문제**

자동화나 워크플로우처럼 백엔드에서 커스텀 필드 값을 업데이트하면 사이트에 그 값이 나타나지 않아요.

**해설**

- 커스텀 필드는 연락처 데이터베이스에 저장돼요. 하지만 사이트는 다음 페이지를 그릴 때 로컬 스토리지나 쿠키에서 필드 데이터를 가져와요.
- 연락처가 폼, 설문, 주문 폼을 제출하면 입력한 값이 로컬 스토리지에 저장돼요.
- 점수나 예상 비용 같은 커스텀 필드 값을 자동화, 워크플로우 등 백엔드 작업으로 업데이트하면 로컬 스토리지에는 저장되지 않아요.
- 화면 표시가 브라우저에 저장된 데이터에 의존하기 때문에 이런 필드는 퍼널 페이지에 표시되지 않아요.
- 이는 의도된 동작이에요. 사용자가 직접 제출한 데이터를 더 빠르게 표시하고 개인화하기 위한 방식이에요.

**해결 방법**

1. 문제가 되는 커스텀 필드가 폼·설문으로 채워지는지, 백엔드 자동화로 채워지는지 확인하세요.
2. 백엔드에서 업데이트한 값이라면 해당하는 로컬 스토리지 항목이 없어서 퍼널 페이지에 나타나지 않아요.
3. 필드가 표시되게 하려면 다음 중 하나를 선택하세요.
   - 해당 필드를 폼이나 설문에 추가해서, 사용자가 입력할 때 값이 로컬 스토리지에 저장되게 하세요.
   - 또는 커스텀 스크립트나 로직으로 백엔드에서 업데이트된 필드 값을 페이지가 그려지기 전에 로컬 스토리지에 넣어 주세요.

{% hint style="info" %}
사용자가 직접 입력해서 업데이트된 커스텀 필드(폼·설문 제출 등)만 로컬 스토리지에 저장되어 퍼널 페이지에 표시돼요.
점수나 CRM 업데이트처럼 백엔드 자동화로 바뀐 필드는 사이트에 표시되지 않아요.
{% endhint %}

### 3. 이미지가 흐리거나 느리게 불러와져요

**문제**

**이미지 최적화** 설정 때문에 일부 이미지가 흐려 보이거나 느리게 로드돼요.

**해설**

**이미지 최적화**는 페이지 속도를 높여 주지만 모든 이미지에 같은 품질 설정을 적용해요. 최적화가 지나치면 일부 이미지는 선명도가 떨어질 수 있어요.

**해결 방법**

- 빌더에서 특정 이미지의 **이미지 최적화**를 끄세요.
- 배경 이미지는 퍼널 **설정**에서 **이미지 최적화**를 끄세요.
- 최적화한 뒤에도 선명하게 보이도록 해상도가 더 높은 이미지를 업로드하세요.

{% hint style="info" %}
**이미지 최적화**를 꺼도 이미지 지연 로딩(lazy loading)은 꺼지지 않아요. 하이퍼클래스는 **이미지 최적화** 사용 여부와 상관없이 이미지 요소에 `loading="lazy"`를 자동으로 적용해요.
{% endhint %}

### 4. 커스텀 값이 깨지거나 미리보기에 표시되지 않아요

**문제**

퍼널에서 커스텀 값이 제대로 표시되지 않아요.

**원인과 해결 방법**

하이퍼링크 문제:

- 텍스트 요소 안의 커스텀 값이 하이퍼링크로 바뀌어 있는지 확인하세요.
- 하이퍼링크가 있으면 화면 표시가 깨지므로, 해당 요소에서 하이퍼링크를 제거하세요.

ChatGPT 응답 형식 문제:

- ChatGPT가 만든 내용에는 `\n` 같은 특수 문자가 들어 있을 수 있어요. 이 문자가 퍼널 페이지를 깨뜨릴 수 있어요.
- ChatGPT 프롬프트를 수정해서 HTML 형식으로 응답하게 하세요.
- 또는 **Text Formatter**(텍스트 서식 변환) 액션으로 `\n`을 `<br/>`로 바꾸세요.

### 5. 라이브 사이트의 퍼널, 페이지, 서브 계정을 확인하려면 어떻게 하나요?

1. 브라우저 개발자 도구에서 네트워크 탭을 여세요.
2. 콘솔을 지우고 XHR 필터를 켜세요.
3. 페이지를 새로고침하세요.
4. 네트워크 로그에서 이벤트 호출을 확인하세요.
5. 페이로드 섹션을 열어 필요한 정보를 찾으세요.

### 6. 사이트가 제대로 표시되지 않아요 (정렬이 어긋나거나 계속 새로고침돼요)

**문제**

요소 정렬이 어긋나거나 페이지가 계속 새로고침되는 등 사이트가 제대로 표시되지 않아요.

**해결 방법**

- 코드 요소 안의 커스텀 코드, 헤더/푸터 **추적 코드**, 커스텀 CSS를 모두 제거하세요.

커스텀 코드 요소를 찾으려면:

1. 빌더를 여세요.
2. 페이지 미리보기를 검사하세요.
3. **Ctrl + F**(Windows) 또는 **Cmd + F**(Mac)를 눌러 `c-custom-code`를 검색하세요.
4. 찾으면 커스텀 코드 요소를 제거하고 문제가 계속되는지 확인하세요.

그 밖에 확인할 것:

- 섹션, 열, 요소에 **고정** 옵션이 켜져 있지 않은지 확인하세요. 고정 CSS는 미리보기 모드에서만 동작해요.
- 만료된 타이머 요소는 표시 문제를 일으킬 수 있으니 제거하세요.
- 브라우저 콘솔을 열어 오류가 있는지 확인하세요.
- 콘솔에 hydration 오류가 나타나면 하이퍼클래스 고객지원에 티켓으로 문의하세요.

### 7. 페이지 속도 점수가 낮거나 페이지가 너무 느려요

**문제**

페이지가 느리게 로드되거나, 속도 분석 도구에서 낮은 성능 점수가 나와요.

{% hint style="info" %}
개발팀은 페이지 속도를 높이기 위한 디버깅을 직접 지원하지 않아요.
{% endhint %}

**추천 도구**

- [PageSpeed Insights](https://pagespeed.web.dev/)
- [GTMetrix](https://gtmetrix.com/)

이 도구들로 페이지 성능을 분석하고 개선할 점을 확인할 수 있어요.

**해결 및 최적화 방법**

- **추적 코드**나 코드 요소로 불러오는 외부 스크립트와 CSS가 있는지 확인하세요.
- 페이지의 길이와 콘텐츠 밀도를 살펴보세요.
- 하이퍼클래스의 **이미지 최적화** 토글을 켜거나, 이미지를 직접 압축해서 최적화하세요.
- 권장 사항: 스크롤 없이 처음 보이는 영역(above the fold)의 이미지는 200kb 이하로 맞추면 모바일에서 좋은 LCP 점수를 받는 데 도움이 돼요.
- **JavaScript 최적화**를 켜면 꼭 필요하지 않은 JS와 추적 코드의 hydration이 늦춰져요. 그러면 TBT(Total Blocking Time)가 개선돼요.
- 서드파티 위젯이나 JavaScript를 삽입하는 커스텀 코드 요소가 있는지 확인하세요.
- 폼, 캘린더, 리뷰 위젯, 지도처럼 무거운 요소는 첫 화면 아래로 옮기세요.

**기준**

잘 최적화한 하이퍼클래스 페이지는 보통 다음 점수가 나와요.

- 모바일 80점 이상
- 데스크톱 95점 이상

추적 코드나 고해상도 이미지가 있는 경우에도 같은 기준이에요.

### 8. 보안 헤더 때문에 사이트 자산이 차단돼요

**문제**

**사이트 > 퍼널** > 문제가 있는 퍼널의 **보안** 탭에 제한이 심하거나 잘못된 **보안 헤더**를 설정하면 페이지나 퍼널 단계에서 스크립트, 이미지, 스타일이 불러와지지 않을 수 있어요.
<!-- 검토 필요: 원문 내용이 서로 다름 (보안 탭 위치: 사이트 > 퍼널 > 해당 퍼널 / 사이트 > 설정 > 보안) -->

**주요 원인**

- `Content-Security-Policy` 값을 잘못 설정했거나 지나치게 제한적으로 설정한 경우
- 헤더 값에 줄바꿈이나 잘못된 문자가 있는 경우
- 제한적인 지시어 때문에 하이퍼클래스 CDN이나 서드파티 연동의 자산이 차단되는 경우
- 헤더를 수정한 뒤 URL 설정이 잘못된 경우

**해결 방법**

1. **사이트 > 설정 > 보안** 탭으로 이동하세요.
2. 설정한 커스텀 헤더(예: `Content-Security-Policy`, `Strict-Transport-Security`, `X-Content-Type-Options`, `X-Frame-Options`)를 검토하세요.
3. 커스텀 헤더를 모두 잠시 제거하거나 비운 뒤 페이지를 새로고침하세요.
   - 페이지가 정상적으로 열리면 헤더 설정 중 하나가 원인이에요.
4. 헤더 값에 줄바꿈이나 새 줄이 없는지 확인하세요.
   - 헤더 값은 한 줄로 이어서 입력해야 해요.
5. 효과를 정확히 알지 못하는 제한적이거나 지원되지 않는 규칙은 쓰지 마세요.
   올바른 형식의 예시:

   ```
   default-src 'self'; img-src *; script-src 'self' https://example.com;
   ```
6. 홈페이지가 계속 열리지 않으면 **다른 URL 경로**를 임시로 지정해 보세요.
7. 수정한 뒤에는 캐시를 지우거나 시크릿 모드(Incognito)에서 테스트해서 해결됐는지 확인하세요.

**확인 팁**

- 각 헤더의 문법을 확인하고, 잘못되었거나 지원되지 않는 지시어가 없는지 살펴보세요.
- 잘못된 값을 다시 입력했다면 지우거나 단순하게 고치세요.

**기준**

보안 헤더를 올바르게 설정한 페이지는 다음과 같아야 해요.

- 하이퍼클래스 자산이 차단 없이 모두 로드돼요.
- 브라우저 콘솔에 "Refused to load"나 "Blocked by CSP" 오류가 나타나지 않아요.

**검증 팁**

설정한 Content-Security-Policy가 올바르고 안전한지 확인하려면 [Google의 CSP Evaluator](https://csp-evaluator.withgoogle.com/)를 사용하세요.
