# 웹사이트 개요

하이퍼클래스 웹사이트에서는 서브 계정 안에서 여러 페이지로 이루어진 사이트를 만들고, 정리하고, 최적화하고, 게시할 수 있어요. 빈 사이트나 템플릿에서 시작해 **페이지** 영역에서 페이지를 관리하고, **웹사이트 빌더**에서 레이아웃을 꾸밉니다. 그다음 모바일 화면을 확인하고, 도메인을 연결한 뒤 준비가 끝나면 게시하면 돼요. 이 문서는 기본 흐름을 다루고, 고급 기능은 별도 가이드를 참고하도록 안내해요.

[동영상](https://www.youtube.com/embed/XYWoix5swXM?&wmode=opaque&rel=0)

## 하이퍼클래스 웹사이트란?

웹사이트는 하이퍼클래스 서브 계정의 **사이트** 메뉴에서 만들고 게시하는, 여러 페이지로 이루어진 웹 페이지 모음이에요. 비즈니스 소개 페이지, 서비스 페이지, 문의 페이지, 콘텐츠 페이지처럼 방문자에게 보여 주는 화면을 만들 때 쓰면 좋아요.

웹사이트는 퍼널과 같은 페이지 제작 환경을 써요. 섹션, 행, 열, 요소를 쌓아 올리고, 반응형 편집, 미리보기, 저장, 게시 기능도 똑같이 쓸 수 있어요.

### 하이퍼클래스 웹사이트의 장점

페이지 제작, 사이트 정리, 게시, 성과 확인을 한곳에 모았어요. 같은 서브 계정에서 웹사이트 운영 전반을 관리할 수 있어요.

- 페이지를 한곳에서 관리: **페이지** 영역에서 웹사이트 페이지를 만들고, 미리 보고, 편집하고, 정리하고, 순서를 바꿀 수 있어요.
- 자유로운 페이지 구성: 섹션, 행, 열, 요소로 레이아웃을 만들고 빌더 설정에서 스타일을 조정해요.
- 반응형 디자인: 데스크톱과 모바일 레이아웃에서 방문자가 보는 화면을 확인하고 꾸밀 수 있어요.
- 안전한 게시: 변경사항을 저장해도 라이브 사이트는 바로 바뀌지 않아요. 미리 확인한 뒤 준비가 되면 게시하세요.
- 사용자 지정 도메인: 브랜드에 맞는 루트 도메인이나 서브도메인을 웹사이트에 연결해 지정할 수 있어요.
- 기본 제공 성과 데이터: 페이지뷰, 옵트인, 판매 같은 웹사이트 성과 데이터를 하이퍼클래스에서 확인할 수 있어요.

### 웹사이트와 퍼널의 차이

웹사이트와 퍼널은 비슷한 제작 도구를 쓰지만, 방문자의 이동 경로에 맞게 다르게 구성돼요. 처음에 알맞은 구조를 고르면 페이지와 리포트를 관리하기 쉬워요.

| 구분 | 웹사이트 | 퍼널 |
| --- | --- | --- |
| 구조 | 방문자가 자유롭게 이동할 수 있는 여러 페이지 사이트 | 특정 방문자 여정에 맞춰 순서대로 이어지는 단계 |
| 주로 쓰는 곳 | 비즈니스 웹사이트, 서비스 페이지, 정보성 콘텐츠 | 리드 수집, 예약, 판매, 캠페인 흐름 |
| **스플릿 테스트** | 웹사이트에서는 사용할 수 없어요 | 퍼널 페이지에서 사용할 수 있어요 |

## 웹사이트 페이지 관리

**페이지** 영역에는 웹사이트 페이지가 한곳에 모여 있어요. 빌더를 일일이 열지 않고도 페이지를 편집하고, 미리 보고, 정리할 수 있어요.

- **웹사이트 빌더**에서 페이지를 열어 편집해요.
- 게시하기 전에 페이지를 미리 봐요.
- 페이지별 설정과 상품을 관리해요. 해당하는 경우에만 쓸 수 있어요.
- 페이지 그리드에서 페이지 카드를 끌어 순서를 바꿔요.

![사이트에 있는 페이지가 표시된 웹사이트 페이지 영역](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155037910569/original/HLnOKuZExHkLfR3mKave12kXfbe6wgwnrg.png?1733510605)

### 웹사이트 페이지 순서 바꾸기

**Page Builder**(페이지 빌더)를 열지 않고도 페이지 그리드에서 순서를 정리할 수 있어요. 페이지를 원하는 위치에 놓으면 새 순서가 자동으로 저장돼요.

1. **서브 계정** 화면에서 왼쪽 메뉴의 **사이트**를 선택하세요.
2. **웹사이트**를 선택하세요.
3. 관리할 웹사이트를 여세요.
4. **페이지** 탭을 선택하세요.
5. 옮기려는 페이지 카드를 클릭한 채로 누르고 있으세요.
6. 페이지 카드를 원하는 위치로 끌어 놓으세요. 커서가 잡는 모양으로 바뀌고, 페이지가 놓일 자리에 표시가 나타나요.
7. 페이지 카드에서 손을 떼세요. 새 순서가 자동으로 저장돼요.

![페이지 카드를 끌어 순서를 바꾸는 모습](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155081947681/original/q9r5seq2HGf0Utz3pHKL_AWk0lZZLjyFDg.gif?1790533351)

순서 변경에 실패하면 하이퍼클래스가 이전에 저장된 페이지 순서로 되돌리고 오류 메시지를 보여 줘요.

## 웹사이트 빌더 한눈에 보기

**웹사이트 빌더**에는 콘텐츠 배치, 페이지 스타일링, 반응형 확인, 게시 준비에 필요한 도구가 모여 있어요.

![주요 편집 기능이 보이는 하이퍼클래스 웹사이트 빌더](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155037892421/original/kOQUF5bxpP2UpxrOWkP2KWui9UhXoHwlQg.png?1733492720)

| 빌더 영역 | 할 수 있는 일 |
| --- | --- |
| 섹션, 행, 열, 요소 | 페이지 콘텐츠를 만들고 배치해요. 요소는 설정에서 이동, 복제, 삭제, 사용자 지정을 할 수 있어요. |
| **Layers**(레이어)와 **페이지** | 중첩된 페이지 콘텐츠를 탐색하고, 편집 중에 다른 페이지로 이동해요. |
| **타이포그래피**와 **배경** | 페이지 전체의 글꼴, 텍스트, 링크, 색상, 배경 스타일을 조정해요. |
| **추적 코드**와 **Custom CSS**(사용자 지정 CSS) | 필요할 때 지원되는 사용자 지정 추적 코드나 스타일을 추가해요. |
| **모바일**/**Desktop**(데스크톱) 컨트롤 | 반응형 레이아웃을 확인하고, 기기별로 지원되는 설정이나 표시 여부를 조정해요. |
| **Versions**(버전), **미리보기**, **저장**, **게시** | 이전 버전을 확인하고, 페이지를 테스트하고, 초안 변경사항을 저장하고, 현재 저장된 버전을 게시해요. |

**저장**은 가장 최근 변경사항을 보관만 하고, 현재 라이브 버전은 바꾸지 않아요. **게시**를 해야 저장된 버전이 방문자에게 공개돼요.

## 웹사이트 설정하는 순서

만들기 → 꾸미기 → 확인 → 도메인 연결 → 게시 순서로 진행하면 설정을 차근차근 관리할 수 있고, 완성되지 않은 내용이 방문자에게 보이는 일도 막을 수 있어요.

### 1단계: 웹사이트 만들기

빈 사이트나 템플릿에서 시작하면 출시 전에 꾸밀 웹사이트 작업 공간과 페이지 구조가 생겨요.

1. **서브 계정** 화면에서 **사이트 > 웹사이트**로 이동하세요.
2. **+ New Website**(새 웹사이트 추가)를 클릭하세요.
3. **From Blank**(빈 사이트에서 시작) 또는 **From Templates**(템플릿에서 시작)를 선택하세요.
4. 웹사이트 이름을 입력하세요.
5. **만들기**를 클릭하고 웹사이트를 여세요.

   ![웹사이트를 새로 만드는 과정](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155081947783/original/N5wWOiPVuv-SAnNyjSMXmoltOypeKV_90w.gif?1790533470)

### 2단계: 페이지 추가하고 정리하기

사이트에 필요한 페이지를 만들고, 알아보기 쉬운 페이지 이름과 경로를 정하세요. 사이트가 어수선해지지 않도록 **페이지** 그리드에서 정리하면 돼요. **Page Builder** 안에서도 페이지를 만들고 전환할 수 있어요.

### 3단계: 페이지별로 구성하고 꾸미기

페이지마다 목적에 맞게 구성하면 방문자가 콘텐츠, 탐색 메뉴, 행동 유도 문구를 이해하고 쓰기 쉬워요.

- 페이지에 필요한 섹션, 행, 열, 요소를 추가하고 배치하세요.
- 텍스트, 이미지, 버튼, 폼, 탐색 메뉴 같은 콘텐츠를 수정하세요.
- 타이포그래피, 간격, 배경, 여러 페이지에 공통으로 쓰는 글로벌 섹션을 점검하세요.
- 게시하기 전에 **미리보기**로 링크와 페이지 동작을 테스트하세요.

### 4단계: 모바일과 SEO 설정 확인하기

게시하기 전에 반응형 레이아웃과 페이지 메타데이터를 확인하세요. 여러 기기에서 사이트를 편하게 쓸 수 있고, 각 페이지가 공유와 검색 노출에 대비할 수 있어요.

- 데스크톱과 **모바일** 보기를 오가며 반응형 동작을 확인하세요.
- 필요하면 지원되는 모바일 전용 설정이나 요소 표시 여부를 조정하세요.
- 게시하기 전에 페이지 제목, 메타 설명 등 해당하는 SEO 설정을 입력하세요.

### 5단계: 도메인 연결하고 게시하기

올바른 도메인을 연결하고 저장된 버전을 테스트한 뒤 게시하면 탐색 오류, 미완성 페이지, 도메인 연결 문제를 막을 수 있어요.

1. 웹사이트에 사용할 루트 도메인이나 서브도메인을 연결하세요.
2. 웹사이트가 올바른 도메인과 기본 페이지에 지정되어 있는지 확인하세요.
3. 빌더에서 최신 변경사항을 저장하세요.
4. 웹사이트를 미리 보고 탐색, 폼, 버튼, 모바일 레이아웃을 테스트하세요.
5. 저장된 버전을 공개할 준비가 되면 **게시**를 클릭하세요.

![버전, 미리보기, 저장, 게시 기능이 있는 웹사이트 빌더](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155037899745/original/JZ482zGgclCyyEaoc3HQdVUgJ0Q_WosZ-A.png?1733498076)

## 웹사이트 설정, 상품, 성과

페이지 디자인을 마쳤다면 웹사이트 관리 도구로 사이트 단위 설정, 판매 옵션, 성과 데이터를 관리하세요. 빌더를 복잡하게 만들지 않아도 돼요.

| 영역 | 용도 |
| --- | --- |
| **Website Settings**(웹사이트 설정) | 사이트 이름, 도메인, 기본 경로, 파비콘, **추적 코드**, 결제 모드, **이미지 최적화** 등 사이트 단위 옵션을 관리해요. |
| **상품** | 웹사이트에 주문이나 결제 화면이 있을 때, 해당하는 페이지에 상품을 연결해요. |
| **통계** | 페이지뷰, 옵트인, 판매, 수익 같은 웹사이트 성과를 확인해요. |
| **결제** | 웹사이트 판매 화면에서 발생한 주문과 거래 중 해당하는 내역을 확인해요. |

![사이트 단위 설정 옵션이 보이는 웹사이트 설정 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155037910737/original/jIEdfFd0u640y20jsUvi04MMBJV3nYwBSA.png?1733511127)

## 자주 묻는 질문

### Page Builder를 나가지 않고 페이지를 만들고 정리할 수 있나요?
네. **Page Builder**에는 페이지 관리 도구가 있어서 편집기 안에서 페이지를 만들고, 전환하고, 검색하고, 정리할 수 있어요.

### AI로 웹사이트 페이지를 만들거나 편집할 수 있나요?
네. **Funnel & Website AI**(퍼널·웹사이트 AI)로 AI의 도움을 받아 페이지를 만들고 편집할 수 있어요.

### 웹사이트 판매와 거래 내역은 어디서 확인하나요?
현재 웹사이트 판매 화면에서 발생한 주문과 거래 기록은 **결제** 영역에서 확인하세요.

### 이전 페이지 버전으로 되돌리려면 어떻게 하나요?
**웹사이트 빌더**의 **Versions**에서 이전에 저장된 버전을 확인하고, 가능한 경우 이전 버전으로 복원하세요. **Undo/Redo**(실행 취소/다시 실행)는 세션 기반이라, 현재 편집 중에 한 최근 수정을 되돌리는 데 더 알맞아요.
