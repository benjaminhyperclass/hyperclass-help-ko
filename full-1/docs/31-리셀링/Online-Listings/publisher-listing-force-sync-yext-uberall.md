# 퍼블리셔 리스팅 강제 동기화 (Yext, Uberall)

강제 동기화(Force Sync)는 멈췄거나 늦어지는 비즈니스 리스팅 업데이트를 지원되는 퍼블리셔에서 먼저 처리하도록 직접 요청하는 기능이에요. 기본 동기화가 너무 오래 걸리거나 멈춘 것처럼 보일 때 쓰세요. 이 문서에서는 하이퍼클래스 **리스팅**(Listings)의 Yext·Uberall 기준으로 사용 가능 범위, 활용 상황, 사용 단계, 주의할 점을 설명해요. 여러 지점의 시급한 업데이트를 관리하는 에이전시에 알맞아요.

[동영상](https://www.youtube.com/embed/saAOaW4YhnA?&wmode=opaque)

## 퍼블리셔 리스팅 강제 동기화란?

강제 동기화는 하이퍼클래스 **리스팅** 안에 있는 우선 처리 요청 도구예요. 리스팅 엔진에 최신 지점 정보를 연결된 디렉터리(퍼블리셔)에 먼저 반영하라고 지시해요. 정해진 동기화 주기를 기다리지 않고, 해당 엔터티(경우에 따라 특정 퍼블리셔)를 빠르게 처리할 대상으로 표시해요.

처리 우선순위는 올라가지만, 실제로 반영되는 시점은 퍼블리셔의 시스템과 정책에 따라 달라져요.

## 강제 동기화의 장점

강제 동기화의 장점을 알면 언제 써야 고객 요청에 더 빠르게 대응할 수 있는지 판단하기 쉬워요. 처리 시간을 줄이고, 상황을 직접 제어하고, 지연될 때도 고객에게 신뢰를 줄 수 있어요.

- 빠른 처리: 일반 주기로는 오래 걸릴 대기 중인 업데이트를 우선 처리해요.
- 더 넓은 제어: 권한이 있는 사용자가 급한 변경을 필요할 때 바로 끌어올릴 수 있어요.
- 지연 감소: 퍼블리셔 대기열에서 멈추거나 느린 업데이트가 넘어가도록 도와요.
- 고객 신뢰: 일정이 중요할 때 적극적으로 관리하고 투명하게 알리고 있다는 점을 보여 줄 수 있어요.

## 사용 가능 범위와 요구 사항

강제 동기화를 어디서 쓸 수 있는지, 옵션이 보이려면 무엇이 필요한지 알아 두면 문제 해결 시간을 아낄 수 있어요.

- 엔진과 적용 범위
  - Yext: 엔터티 단위(모든 퍼블리셔)와 퍼블리셔 단위(엔터티의 퍼블리셔 하나)에서 쓸 수 있어요.
  - Uberall: 엔터티 단위(모든 퍼블리셔)에서만 쓸 수 있어요.
- 사전 조건
  - Yext 또는 Uberall이 연결된, 사용 중인 하이퍼클래스 **리스팅**이 있어야 해요.
  - 필수 프로필 필드가 올바르게 입력된 엔터티(지점)가 있어야 해요. 예를 들어 **회사명**, 주소·전화번호, 해당하는 경우 영업시간이에요.
  - **리스팅**을 관리하고 강제 동기화를 실행할 수 있는 충분한 사용자 권한이 있어야 해요. 관리자이거나 **리스팅** 쓰기 권한이 있는 역할이면 돼요.
- 참고 및 기대 사항
  - 강제 동기화는 업데이트를 우선 처리하지만, 정확한 게시 시각을 보장하지는 않아요.
  - 퍼블리셔 쪽 문제나 정책 문제(예: 계정 정지, 필수 필드 누락)가 있으면 강제 동기화를 해도 게시에 실패할 수 있어요.

## 엔터티 단위 강제 동기화

같은 지점의 여러 퍼블리셔 프로필을 한꺼번에 우선 처리해야 할 때 엔터티 단위 강제 동기화가 가장 알맞아요. 영업시간, 카테고리, 설명처럼 넓은 범위의 정보를 바꾼 뒤에 쓰면 좋아요.

- 선택한 엔터티에 연결된 모든 퍼블리셔에 적용돼요.
- Yext와 Uberall 모두에서 지원돼요.
- 여러 퍼블리셔에 걸친 급한 업데이트(예: 휴일 영업시간, 주소 수정)에 알맞아요.

## 퍼블리셔 단위 강제 동기화 (Yext만 해당)

디렉터리 하나만 뒤처졌다면, 퍼블리셔 단위 강제 동기화로 해당 채널만 대상으로 삼아 불필요한 반영을 줄일 수 있어요.

- Yext의 퍼블리셔 단위에서만 쓸 수 있어요.
- 다른 퍼블리셔는 최신 상태인데 한 곳(예: Bing, Apple Maps)만 맞지 않을 때 써요.
- 범위를 최소한으로 좁혀 필요한 곳에만 적용해요.

![퍼블리셔 단위 강제 동기화 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155066153906/original/VzZTSxuN6M3jI4mJ7Tsb9Mbyy6kmXEP8Mg.png?1772614006)

## 제한 사항과 기대 사항

강제 동기화는 우선순위를 높여 주지만, 퍼블리셔의 규칙이나 누락된 정보를 넘어서지는 못해요. 이 한계를 알면 고객에게 현실적인 일정을 안내할 수 있어요.

- 즉시 게시를 보장하지 않아요. 최종 시점은 퍼블리셔의 대기열과 검토 과정에 따라 달라져요.
- 정책 문제는 해결하지 못해요(예: Google Business Profile 정지, 중복 리스팅, 제한된 카테고리).
- 필수 필드를 건너뛰지 못할 수 있어요. NAP(상호명·주소·전화번호), 카테고리, 필수 속성이 비어 있으면 게시가 막힐 수 있어요.
- 동시 작업: 이미 동기화가 진행 중이거나 퍼블리셔가 점검 중이면, 시스템을 사용할 수 있을 때까지 업데이트가 대기열에 머물 수 있어요.
- 대량·다중 엔터티 작업: 강제 동기화는 엔터티 단위에서 시작해요. 대량 작업은 요금제와 화면 제어에 따라 제한될 수 있어요.

## 강제 동기화 사용 방법

아래 순서대로 하면 강제 동기화를 효과적으로 쓰고 결과도 남길 수 있어요. 여러 팀이 함께 일할 때 특히 도움이 돼요.

1. **리스팅**으로 이동해 우선 처리가 필요한 엔터티(지점)를 선택하세요.
2. 동기화 범위를 고르세요.
   - **Entity Level**(엔터티 단위): 연결된 모든 퍼블리셔를 우선 동기화해요.
   - **Publisher Level**(퍼블리셔 단위, Yext만 해당): 퍼블리셔 목록에서 퍼블리셔 하나를 골라 우선 동기화해요.
3. **강제 동기화 요청**을 클릭하세요.
4. 확인 창의 내용을 살펴보고 **확인**을 클릭하세요.
5. 요청이 대기열에 등록됐다는 성공 알림이 나타나는지 확인하세요.
6. 상태 업데이트를 지켜보고, **Entity History**(엔터티 이력)와 **감사 로그**에서 작업 내역과 반영 결과를 확인하세요.

## 상태와 감사 로그 확인

무엇이 언제 반영됐는지 확인하면 고객에게 진행 상황을 알리기 쉽고, 게시가 계속 늦어질 때 다음 단계를 정하기도 쉬워요.

- **Entity History** 또는 **감사 로그**에서 해당 엔터티(해당하는 경우 특정 퍼블리셔)와 연결된 강제 동기화 기록을 확인하세요.
- 기록된 시각을 비교해 강제 동기화와 이후 퍼블리셔 상태 변화를 연결해서 살펴보세요.
- 퍼블리셔가 오류를 반환하거나 오랫동안 변화가 없으면 아래 문제 해결 단계로 넘어가세요.

## 문제 해결

강제 동기화로 달라지는 게 없다면, 차례대로 점검해 원인이 정보 누락인지, 퍼블리셔 정책인지, 연결 문제인지 찾아보세요.

- 필수 정보 확인: **회사명**, 주소, 전화번호, 카테고리, 영업시간 등 필수 필드를 확인하세요.
- 퍼블리셔 정책 문제 확인: 계정 정지, 중복 리스팅, 제한된 카테고리는 해당 퍼블리셔의 시스템에서 해결해야 해요.
- 대기 중인 제안 처리: **Listings Suggestions**(리스팅 제안)를 쓰고 있다면, 관련 변경 사항을 수락하거나 거절해서 이전 값으로 되돌아가거나 충돌하는 일을 막으세요.
- 토큰이 만료됐다면 해당 퍼블리셔(예: GBP, Facebook)를 다시 연결하거나 재인증하세요.
- **Entity History**와 **감사 로그**에서 최근 오류와 다음 조치를 확인하세요.
- 여러 번 시도해도 퍼블리셔 오류가 계속되면 Yext·Uberall 문서를 참고하거나 하이퍼클래스 고객지원에 문의하세요.

## 자주 묻는 질문

### 강제 동기화를 하면 바로 게시되나요?
아니요. 업데이트를 우선 처리해 주지만, 실제 게시 시점은 퍼블리셔의 대기열과 검토 과정에 따라 달라져요.

### 강제 동기화로 정지된 Google Business Profile을 복구할 수 있나요?
아니요. 정책 문제나 정지 문제는 퍼블리셔에서 직접 해결해야 해요. 계정이 정상 상태가 된 뒤에 강제 동기화를 사용하세요.

### 엔터티 단위 강제 동기화만 보여요. 퍼블리셔 단위는 어디 있나요?
퍼블리셔 단위 강제 동기화는 Yext에서만 쓸 수 있어요. Uberall은 엔터티 단위 강제 동기화만 지원해요.

### 강제 동기화를 쓰려면 특별한 권한이 필요한가요?
네. **리스팅** 관리 권한이 있어야 해요. 옵션이 보이지 않으면 관리자에게 알맞은 역할을 부여해 달라고 요청하세요.

### 강제 동기화를 하면 사진, 속성, 카테고리도 다시 반영되나요?
강제 동기화는 엔터티 또는 퍼블리셔의 동기화 우선순위를 다시 높여 주는 기능이에요. 실제로 어떤 정보가 반영되는지는 퍼블리셔마다 다를 수 있어요. 필수 필드와 미디어가 퍼블리셔 가이드라인에 맞는지 확인하세요.

### 강제 동기화를 취소할 수 있나요?
아니요. 정보를 수정한 뒤 다시 동기화를 요청할 수는 있지만, 이미 실행한 강제 동기화 자체는 취소할 수 없어요.

### 강제 동기화를 얼마나 자주 쓸 수 있나요?
업데이트가 늦어지거나 멈췄을 때 사용하세요. 여러 번 시도해도 해결되지 않으면, 다시 시도하기 전에 문제 해결 항목과 퍼블리셔 정책 문제를 먼저 확인하세요.

### 강제 동기화를 누른 뒤 어떻게 됐는지 어디서 확인하나요?
**Entity History**와 **감사 로그**에서 시각이 기록된 내역을 확인한 다음, 엔터티의 **리스팅** 화면에서 퍼블리셔 상태를 확인하세요.
