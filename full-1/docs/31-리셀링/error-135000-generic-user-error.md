# 오류 135000 — 일반 사용자 오류(Generic User Error)

WhatsApp 템플릿 메시지가 오류 코드 135000으로 발송되지 않을 때 볼 수 있는 문제 해결 가이드예요. 오류의 의미와 원인, 알려진 해결 방법, 예방 방법을 안내해요.

## 오류 135000이란?

오류 135000은 WhatsApp Cloud API 오류로, 공식 이름은 "Generic User Error"(일반 사용자 오류)예요. 요청 값에 알 수 없는 문제가 있거나, Meta 내부 시스템이 보안·정책 제한 때문에 메시지를 걸러 낼 때 템플릿 메시지가 발송되지 않아요.

이 오류가 까다로운 이유는 **Meta가 구체적인 원인을 알려 주지 않기** 때문이에요. Meta 문서에 따르면 보안상의 이유로 걸린 템플릿 제한과 관련된 오류이고, 자세한 내용은 의도적으로 공개하지 않아요.

{% hint style="warning" %}
Meta 지원팀에 따르면 오류 135000은 Meta의 스팸·사기 탐지 시스템이 정상 메시지를 잘못 걸러 내는 오탐(false positive) 때문에 생기기도 해요. 정상적인 템플릿이 잘못 분류될 수 있으므로, 항상 사용자의 실수 때문에 생기는 오류는 아니에요.
{% endhint %}

## 알려진 원인

아래 원인은 Meta 문서, 공식 지원 채널, 개발자 커뮤니티에서 확인되었거나 자주 보고된 내용이에요.

### 1. 템플릿 변수 값에 지원되지 않는 내용이 들어간 경우

가장 흔하게 확인된 원인이에요. 템플릿 변수 `{{1}}`, `{{2}}` 등에 들어가는 값에 WhatsApp이 지원하지 않는 내용이 있으면 오류 135000이 발생해요. 이모지, WhatsApp 링크, 특수문자, 지나치게 긴 문자열이 해당돼요.

### 2. Meta의 스팸·사기 탐지 시스템에 걸린 경우

Meta는 발송되는 템플릿 메시지를 자동으로 보안 검사해요. 스팸, 피싱, 사기와 비슷한 패턴의 템플릿은 정상 템플릿이라도 오탐으로 걸릴 수 있어요. Meta 지원팀이 확인한 문제이고, 아무것도 바꾸지 않았는데 잘 되던 템플릿이 갑자기 걸리기도 해요.

### 3. 템플릿이 WhatsApp 정책을 위반한 경우

템플릿 내용이나 변수 값이 WhatsApp 비즈니스 정책 또는 커머스 정책을 위반할 수 있어요. 금지된 상품을 홍보하거나, 민감한 정보를 포함하거나, 위협적인 표현을 쓰는 경우가 그래요. Meta는 승인할 때뿐 아니라 발송할 때도 이 검사를 해요.

### 4. 요청 값이 잘못되었거나 형식이 틀린 경우

API 요청 자체에 문제가 있어도 오류 135000이 발생할 수 있어요. 파라미터 개수 불일치, 잘못된 구성 요소 유형, 깨진 JSON 등이 해당돼요. 템플릿을 최근에 수정했거나, 요청의 변수 개수가 승인된 템플릿과 다를 때 더 자주 생겨요.

### 5. 템플릿 손상 또는 Meta 내부 동기화 문제

승인되어 잘 쓰던 템플릿이 아무 변경 없이 갑자기 오류 135000을 반환하는 경우가 있어요. Meta 시스템 안에서 템플릿이 손상되었거나 동기화가 어긋나서 생기는 문제예요. 보통 템플릿을 삭제하고 다시 만들면 해결돼요.

## 해결 방법

가장 간단한 방법부터 순서대로 시도해 보세요.

{% hint style="info" %}
오류 135000에는 반드시 통하는 단일 해결책이 없어요. 아래는 Meta 지원팀과 개발자 커뮤니티에서 확인된 해결 방법이에요. 문제가 해결될 때까지 순서대로 진행하세요.
{% endhint %}

### 1단계. 템플릿에 넣는 변수 값 확인하기

템플릿 변수에 들어가는 값을 모두 살펴보고, 아래 내용이 없는지 확인하세요.

변수 값에 넣으면 안 되는 것:

- 이모지
- WhatsApp 링크(wa.me/...)
- # $ % & 같은 특수문자
- 지나치게 긴 문자열
- HTML 또는 마크다운 서식
- 빈 값 또는 null 값

변수 값으로 안전한 것:

- 일반 텍스트만
- 숫자와 날짜
- 이름과 짧은 문구
- 일반적인 영문·숫자 내용
- URL은 템플릿이 URL 변수로 승인된 경우에만

### 2단계. 요청 형식이 승인된 템플릿과 정확히 같은지 확인하기

하이퍼클래스 또는 Meta Business Manager에서 템플릿을 열어 아래 내용을 확인하세요.

- API 요청의 변수 파라미터 개수가 승인된 템플릿의 변수 개수와 같은지
- 요청의 구성 요소 유형(헤더, 본문, 버튼)이 템플릿 구조와 같은지
- 요청의 템플릿 이름과 언어 코드가 Meta Business Manager에 있는 값과 정확히 같은지

### 3단계. 문제가 되는 템플릿을 삭제하고 다시 만들기

위 확인에서 문제가 보이지 않으면 Meta 시스템에서 템플릿이 손상되었거나 잘못 분류되었을 수 있어요. 알려진 방법 중 가장 효과적인 것은 템플릿을 삭제하고 다시 만드는 거예요.

1. 문제가 되는 템플릿의 내용을 각각 복사해 두세요. 스크린샷을 찍거나 안전한 곳에 붙여 넣으면 돼요.
2. 하이퍼클래스에서 **WhatsApp 설정으로 이동**을 클릭해 WhatsApp 설정으로 이동한 뒤, 문제가 되는 템플릿을 삭제하세요.
3. **새 템플릿 만들기**를 클릭해 같거나 비슷한 내용으로 템플릿을 만드세요. 템플릿 이름은 새 이름을 쓰세요.
4. 새 템플릿을 승인 요청하고 Meta의 승인을 기다리세요(최대 24시간).
5. 승인되면 새 템플릿을 테스트하세요.

{% hint style="info" %}
템플릿을 삭제하고 다시 만드는 방법은 여러 비즈니스에서 효과가 확인되었어요. Meta 개발자 커뮤니티 포럼에도 오류 135000에 가장 꾸준히 효과가 있는 해결책으로 정리되어 있어요.
{% endhint %}

### 4단계. 전화번호 삭제 후 다시 추가하기(오류가 계속될 때)

템플릿을 다시 만들어도 해결되지 않으면, WhatsApp 비즈니스 계정에 연결된 전화번호를 삭제하고 다시 추가해 보세요.

1. Meta Business Manager에서 WhatsApp 비즈니스 계정으로 이동하세요.
2. **전화번호**로 이동해 문제가 되는 번호를 선택하고 **삭제**를 클릭하세요.
3. **전화번호 추가**를 클릭하고 설정·인증 단계를 따라 진행하세요.
4. OTP 인증을 마친 뒤 템플릿을 다시 테스트하세요.

{% hint style="warning" %}
전화번호를 삭제하면 WhatsApp 비즈니스 계정에서 해당 번호가 제거돼요. 이 단계를 진행하기 전에 OTP로 다시 인증할 수 있도록 그 번호를 사용할 수 있는지 꼭 확인하세요.
{% endhint %}

### 5단계. 문제가 계속되면 **고객 지원 문의**

위 방법으로도 해결되지 않으면 Meta 쪽에서 처리해야 하는 문제일 가능성이 높아요. 하이퍼클래스 고객지원에 문의하면서 아래 정보를 함께 알려 주세요.

- 문제가 되는 템플릿 이름
- WABA에 연결된 전화번호 ID
- `fbtrace_id` 값이 포함된 전체 API 오류 응답
- 오류가 언제 시작되었는지, 그전에는 템플릿이 정상 작동했는지
- 템플릿이나 계정에 최근 변경한 내용

## 예방 방법

오류 135000이 생길 가능성을 줄이는 방법이에요.

- 변수 값은 단순한 일반 텍스트로 유지하세요. 이모지, 특수문자, WhatsApp 링크, HTML, 지나치게 긴 문자열은 템플릿 변수 값에 넣지 마세요.
- Meta의 템플릿 작성 가이드라인을 따르세요. 템플릿을 만들기 전에 WhatsApp 가이드라인, 특히 콘텐츠 제한과 변수 형식 규칙을 확인하세요.
- 대량 발송 전에 샘플 값으로 테스트하세요. 보낼 변수 값 그대로 테스트 번호에서 정상 작동하는지 확인한 뒤 많은 연락처에 보내세요.
- 거절되었거나 삭제한 템플릿 이름을 다시 쓰지 마세요. 템플릿을 다시 만들 때는 항상 새 이름을 써서 Meta 내부 기록과 충돌하지 않게 하세요.
- 템플릿 내용이 피싱이나 스팸처럼 보이지 않게 하세요. 급박한 표현, 의심스러운 링크, 개인정보 요청처럼 Meta의 자동 탐지에 걸릴 만한 내용은 피하세요.

## 관련 오류 코드

템플릿과 관련해 자주 볼 수 있는 다른 오류예요.

| 오류 코드 | 제목 | 설명 |
| --- | --- | --- |
| 132000 | Template Parameter Count Mismatch(템플릿 파라미터 개수 불일치) | 요청의 변수 개수가 승인된 템플릿과 달라요. |
| 132001 | Template Does Not Exist(템플릿 없음) | 지정한 언어로 된 템플릿이 없거나 아직 승인되지 않았어요. |
| 132007 | Template Content Policy Violation(템플릿 콘텐츠 정책 위반) | 템플릿 내용이 WhatsApp 정책을 위반했어요. 거절 사유를 확인하세요. |
| 132012 | Template Parameter Format Mismatch(템플릿 파라미터 형식 불일치) | 변수 값의 형식이 승인된 템플릿에 지정된 형식과 달라요. |
| 131037 | Display Name Approval Required(표시 이름 승인 필요) | 비즈니스 전화번호에 승인된 표시 이름이 없어요. |

## 자주 묻는 질문

### 템플릿이 잘 작동했고 아무것도 바꾸지 않았는데 갑자기 실패해요. 왜 그런가요?

이미 알려진 문제예요. Meta의 자동 보안 검사가 이전에 승인되어 잘 쓰던 템플릿을 잘못 걸러 내서 갑자기 오류 135000이 나기도 해요. Meta 쪽의 오탐이에요. 템플릿을 새 이름으로 삭제 후 다시 만드는 것이 가장 효과적인 해결 방법이에요.

### 완전히 다른 템플릿을 써야 하나요, 아니면 같은 템플릿을 다시 만들어도 되나요?

같은 내용으로 다시 만들어도 되지만 **템플릿 이름은 반드시 새로 정해야** 해요. 같은 이름을 다시 쓰면 같은 문제가 계속될 수 있어요. 새 템플릿을 만들고 승인을 기다린 다음, 워크플로우나 캠페인에서 새 템플릿 이름을 쓰도록 바꾸세요.

### 이 오류는 항상 제 템플릿에 문제가 있어서 생기나요?

아니에요. Meta 지원팀은 오류 135000이 스팸 탐지 시스템의 오탐으로도 발생할 수 있다고 확인했어요. 이 경우 템플릿과 요청 형식은 올바르고, 문제는 전적으로 Meta 쪽에 있어요. 템플릿과 요청을 꼼꼼히 확인했는데도 문제가 없다면 Meta 쪽 오탐일 가능성이 높아요.

### 오류 135000이 난 메시지에도 요금이 부과되나요?

아니요. 오류 135000으로 실패한 메시지는 전달되지 않고 대화도 열리지 않기 때문에 요금이 부과되지 않아요.

### 이 제한에 대해 Meta에 이의를 제기할 수 있나요?

Meta는 오류 135000만을 위한 공식 이의 제기 절차를 제공하지 않아요. 권장 방법은 템플릿을 다시 만드는 거예요. 그래도 오류가 계속되면 오류 응답의 `fbtrace_id`를 가지고 Meta Business Support에 직접 문의해서 조사를 요청하세요.

## 요약

오류 135000은 Meta의 "Generic User Error"로, 템플릿 제한 때문에 발송이 실패하는 경우를 폭넓게 가리키는 모호한 오류예요. 먼저 변수 값에 지원되지 않는 내용이 없는지 확인하세요. 요청에 문제가 없다면 템플릿을 새 이름으로 삭제 후 다시 만드세요. 그래도 해결되지 않으면 전화번호를 삭제하고 다시 추가해 보세요. Meta 쪽에서 알려진 문제이고, 위 방법으로 대부분 해결돼요. 문제가 계속되면 `fbtrace_id`와 함께 하이퍼클래스 고객지원에 문의하세요.
