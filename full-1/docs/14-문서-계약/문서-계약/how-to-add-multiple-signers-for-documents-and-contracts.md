# 여러 서명자 역할 설정하기 — 문서 & 계약 템플릿

템플릿 하나에 서명자 역할을 최대 6개까지 정의하고, 워크플로우로 여러 사람이 서명하는 계약을 자동으로 보내는 방법을 안내해요.

이 기능을 쓰면 구매자, 판매자, 증인 같은 역할(또는 직접 만든 역할)을 **문서 & 계약** 템플릿에 바로 정의할 수 있어요. 워크플로우로 문서를 보내면 하이퍼클래스가 각 역할의 정보를 자동으로 채워 서명을 요청해요. 이 문서에서는 템플릿에 서명자 역할을 만들고, 역할마다 입력 요소를 지정하고, 워크플로우로 여러 사람이 서명하는 문서를 보내는 방법을 설명해요.

## 여러 서명자 역할이란?

여러 서명자 역할은 **문서 & 계약** 템플릿 하나에 서명자 역할을 여러 개 정의하는 기능이에요. 각 역할은 계약의 당사자를 뜻해요. 구매자, 판매자, 증인처럼 직접 이름을 정한 역할도 만들 수 있어요. 역할마다 서명 상자, 날짜 필드, 텍스트 입력란 같은 입력 요소를 따로 지정할 수 있어요.

템플릿 하나에 역할을 최대 6개까지 설정할 수 있어요. 워크플로우로 문서를 보내면 하이퍼클래스가 각 역할의 정보(이름, 이메일, 전화번호)를 자동으로 채우고, 정해 둔 순서대로 서명을 요청해요.

이전에는 템플릿이 서명자 한 명만 지원해서, 여러 사람이 서명하는 계약마다 나머지 당사자를 직접 입력해야 했어요. 이제는 템플릿에 역할을 한 번만 정의해 두면, 그 템플릿으로 만드는 모든 문서에서 다시 쓸 수 있어요.

## 이럴 때 좋아요

여러 서명자 역할을 쓰면 여러 사람이 서명하는 계약을 보내는 과정이 간단해지고, 직접 입력하다 생기는 실수도 줄어요.

- 여러 당사자가 있는 계약 시간 절약 — 구매자·판매자, 고객·공동 서명자, 임차인·보증인 계약을 보낼 때마다 서명자 정보를 다시 입력하지 않아도 돼요.
- 입력 실수 감소 — 템플릿에 설정한 역할 값이 문서를 보낼 때 자동으로 채워져서, 빠뜨리거나 잘못 입력하는 일이 줄어요.
- 워크플로우마다 유연하게 설정 — 워크플로우 단위에서 역할의 이름, 이메일, 전화번호를 바꿀 수 있어서 템플릿을 복제하지 않아도 여러 거래에 쓸 수 있어요.
- 복잡한 거래 처리 — 부동산, 시공, 서비스 업종처럼 서명이 여러 개 필요한 계약(예: 구매자 + 판매자 + 증인)을 한 번에 보낼 수 있어요.
- 템플릿당 최대 6명 지원 — 계약에 필요한 만큼 역할을 정의할 수 있어요. 템플릿당 최대 6개예요.

## 동작 방식

여러 서명자 역할은 역할을 정의하는 곳(템플릿)과 역할에 값을 지정하는 곳(워크플로우)이 나뉘어 있어요. 덕분에 템플릿 하나를 여러 계약에 재사용하면서도 보낼 때마다 값을 조정할 수 있어요.

1. 템플릿에서 역할 정의하기
   - 템플릿에 서명자 역할(구매자, 판매자, 증인 또는 직접 정한 이름)을 만들고, 역할마다 입력 요소(서명 상자, 날짜 필드, 텍스트 입력란)를 지정해요. 역할에는 고정값이나 커스텀 필드 자리표시자를 넣을 수 있어요. 자리표시자는 문서를 보낼 때 실제 값으로 바뀌어요.
2. 워크플로우에서 템플릿 선택하기
   - 워크플로우에 **Send Document**(문서 보내기) 액션을 추가하고 여러 서명자 역할을 설정한 템플릿을 선택해요. 하이퍼클래스가 템플릿에 정의된 역할을 모두 찾아 워크플로우 액션 설정에 보여 줘요.
3. 자동 입력과 덮어쓰기
   - 템플릿의 역할 값이 워크플로우 액션에 자동으로 채워져요. 계약에 따라 다른 정보가 필요하면 워크플로우 단위에서 역할의 이름, 이메일, 전화번호를 바꿀 수 있어요. 워크플로우에서 입력한 값은 항상 템플릿 기본값보다 우선해요.
4. 문서 전달
   - 워크플로우가 문서를 보내면 하이퍼클래스가 정해 둔 순서대로 각 서명자에게 전달해요. 서명자마다 고유한 서명 링크를 받고, 자신에게 지정된 입력 요소를 작성해요. 워크플로우에 등록된 연락처가 주 수신자가 되고, 나머지 역할은 템플릿에 설정한 값이나 워크플로우 액션에서 바꾼 값으로 채워져요.

## 여러 서명자 역할 설정하는 순서

아래 순서를 따라 **문서 & 계약** 템플릿에 역할을 설정하고, 워크플로우로 문서를 보내 보세요.

### 1단계. 문서 & 계약 템플릿 열기

**결제 > 문서 & 계약 > 템플릿**으로 이동해요. 기존 템플릿을 열거나 새 템플릿을 만들어요.

템플릿에서 어떤 역할이 있는지, 각 역할이 어떤 정보를 입력해야 하는지 정해요. 이 설정에 따라 워크플로우로 문서를 보낼 때 전달 방식이 결정돼요.

![템플릿 목록 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155077844103/original/6ERy16oKZI1l41XuHcZ5Ap2Egb1GbVizMg.png?1786077994)

### 2단계. 템플릿에 입력 요소 추가하기

템플릿 편집기에서 서명 상자, 날짜 필드, 텍스트 입력란 등 지원하는 입력 요소를 추가해요. 방금 추가한 입력 요소를 클릭해요.

모든 역할에는 입력 요소가 하나 이상 지정되어야 해요. 서명자는 문서를 받으면 이 입력 요소를 작성해요.

![템플릿 편집기에서 입력 요소를 추가한 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155077844307/original/MACsaJE0oSgwocuMa59FWEAJan38eU2mbw.png?1786078261)

### 3단계. 새 역할 만들기

서명 요소를 선택한 상태에서 **역할 추가**를 클릭해요. 역할을 만드는 입력 창이 열려요.

이 입력 창에서 서명자가 누구인지(구매자, 판매자, 증인 또는 직접 정한 역할 이름) 정하고, 하이퍼클래스가 연락처 정보를 어떻게 채울지 설정해요.

![역할 추가 입력 창](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155077870251/original/tkKeY9h0uX6gq3MCcUf8b5T1M7gdcmHiNQ.png?1786096043)

### 4단계. 역할 이름과 연락처 세부정보 설정하기

역할 입력 창에서 알아보기 쉬운 **역할 이름**을 입력해요(예: "증인", "구매자", "공동 서명자"). 이 이름은 서명자가 문서를 받을 때 서명 필드 위에 표시돼요.

역할마다 **이름**, **이메일**, **전화번호**를 두 가지 방법으로 설정할 수 있어요.

- **Static Value**(고정값): 값을 직접 입력해요(예: "홍길동" 또는 "john@example.com"). 역할의 정보가 늘 같을 때 쓰세요.
- **커스텀 필드 자리표시자**: 연락처 레코드의 커스텀 필드를 선택해요(예: `{{contact.witness_name}}`, `{{contact.buyer_email}}`). **커스텀 필드 선택**에서 고르면 돼요. 역할의 정보가 연락처마다 달라서, 문서를 보낼 때 하이퍼클래스가 자동으로 채우게 하고 싶을 때 쓰세요.

커스텀 필드 자리표시자를 쓰면 템플릿 하나로 여러 계약을 처리할 수 있어요. 워크플로우가 문서를 보낼 때 하이퍼클래스가 등록된 연락처의 레코드에서 자리표시자 값을 찾아, 올바른 서명자 정보를 직접 입력하지 않아도 채워 줘요.

![역할 이름과 연락처 세부정보 입력 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155077844539/original/QnVPKX6Mpspv1lEdes069BYSa05XuieShQ.png?1786078544)

{% hint style="warning" %}
**연락처** 역할에는 입력 요소가 하나 이상 지정되어야 해요. **연락처** 역할은 주 수신자를 뜻해요. 워크플로우에 등록되어 문서 발송을 시작시키는 연락처예요. **연락처** 역할이 지정되어 있지 않으면 **Send Document** 워크플로우 액션이 제대로 동작하지 않아요.
{% endhint %}

### 5단계. 역할에 서명 추가로 지정하기

역할을 만들면 방금 클릭한 서명이 그 역할에 자동으로 지정돼요. 같은 역할이나 다른 역할에 서명을 더 지정하려면, 템플릿에서 서명 요소를 추가한 뒤 드롭다운에서 역할을 선택하세요.

역할 하나에 서명 요소를 여러 개 지정할 수 있어요. 예를 들어 "구매자" 역할은 서명, 이니셜, 날짜 입력이 모두 필요할 수 있어요. 관련 입력 요소를 알맞은 역할에 지정해 두면 서명자는 자신이 작성할 항목만 보게 돼요.

![서명 요소에 역할을 지정하는 드롭다운](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155077871086/original/CjqMEnjhjDp95CXO62S9Rg0yyeSGJEyPzw.png?1786096458)

### 6단계. 템플릿 저장하기

역할을 모두 추가하고 입력 요소를 지정했다면 **저장**을 클릭해요. 이제 템플릿이 여러 서명자 역할용으로 설정되어 워크플로우에서 쓸 수 있어요.

저장하면 역할 설정이 확정돼요. 이 템플릿을 쓰는 워크플로우는 정의해 둔 역할을 모두 자동으로 찾아서 보여 줘요.

### 7단계. 워크플로우에 템플릿 추가하기

**자동화 > 워크플로우**로 이동해요. 새 워크플로우를 만들거나 기존 워크플로우를 열어요. **Send Document** 액션을 추가하고, 템플릿 드롭다운에서 여러 서명자 역할을 설정한 템플릿을 선택해요.

템플릿이 실제로 쓰이는 곳이 워크플로우예요. 연락처가 이 워크플로우에 등록되면 하이퍼클래스가 모든 역할 값을 채운 문서를 만들어 서명을 요청해요.

![워크플로우에서 Send Document 액션에 템플릿을 선택하는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155077868702/original/Fr3QQ9BsU6MUpD2mx2JJMogzUxefI9khyQ.png?1786095383)

### 8단계. 워크플로우에서 역할 확인하기

여러 서명자 역할을 설정한 템플릿을 선택하면, 워크플로우 액션 설정에 **Assign Roles**(역할 지정) 섹션이 나타나요. 이 섹션에는 템플릿에서 입력 요소가 하나 이상 지정된 역할이 모두 표시돼요.

자동으로 채워진 역할 정보를 확인하세요. 템플릿에서 커스텀 필드 자리표시자를 썼다면 여기에 자리표시자가 그대로 보이고, 워크플로우가 실행될 때 실제 값으로 바뀌어요. 고정값을 썼다면 그 값이 표시돼요.

**Assign Roles** 섹션에서는 문서를 보내기 전에 각 역할이 제대로 설정됐는지 마지막으로 확인할 수 있어요. 이 단계에서 역할 정보를 바꿀 수도 있어요(9단계 참고).

![Assign Roles 섹션에서 역할 정보를 확인하는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155077871351/original/KQ0f0T95gb6HxRBpNKqiBhwFgk3pQZDvnA.gif?1786096609)

### 9단계. 역할 정보 바꾸기(선택)

계약에 따라 역할의 정보를 다르게 해야 한다면, **Assign Roles** 섹션에서 해당 역할 옆의 **Edit**(편집)를 클릭해요. 새 이름, 이메일, 전화번호를 직접 입력할 수 있어요. 워크플로우에서 입력한 값은 항상 템플릿 기본값보다 우선해요.

덮어쓰기를 하면 템플릿을 복제하지 않고도 보낼 때마다 정보를 바꿀 수 있어요. 예를 들어 템플릿의 "증인" 역할에 커스텀 필드 자리표시자를 썼지만 특정 거래에는 다른 증인이 필요하다면, 여기에 그 증인의 정보를 입력하세요. 하이퍼클래스는 이번 발송에만 그 값을 써요.

### 10단계. 워크플로우 저장하고 게시하기

**Send Document** 액션에서 **Save**(저장)를 클릭한 다음, 워크플로우에서 **Publish**(게시)를 클릭해요. 연락처가 이 워크플로우에 등록되면 하이퍼클래스가 문서를 만들고, 모든 역할 값(템플릿 또는 워크플로우에서 바꾼 값)을 채워 각 서명자에게 보내요.

워크플로우에 등록된 연락처가 주 수신자(**연락처** 역할)가 돼요. 나머지 역할은 템플릿에 설정한 값이나 워크플로우에서 바꾼 값으로 채워져요. 워크플로우 액션에서 이메일 알림을 켜 두었다면, 각 서명자는 이메일로 고유한 서명 링크를 받고 자신에게 지정된 입력 요소를 작성할 수 있어요.

게시하면 워크플로우가 활성화돼요. 이때부터 이 워크플로우가 실행되는 모든 연락처에게, 직접 손대지 않아도 모든 역할이 채워진 문서가 전달돼요.

## 워크플로우에서 역할 정보 바꾸기

워크플로우에서 역할 정보를 바꾸면 템플릿을 수정하지 않고도 문서를 보낼 때마다 서명자 정보를 다르게 할 수 있어요. 덕분에 템플릿 하나로 여러 계약을 처리할 수 있어요.

워크플로우 액션 **Send Document**에서 여러 서명자 역할을 설정한 템플릿을 선택하면, 하이퍼클래스가 템플릿의 모든 역할 정보를 **Assign Roles** 섹션에 보여 줘요. 역할 옆의 **Edit**를 클릭하면 워크플로우 액션 설정에서 그 역할의 이름, 이메일, 전화번호를 바로 바꿀 수 있어요. 워크플로우에서 입력한 값은 항상 템플릿 기본값보다 우선해요.

예를 들어 "구매자" 역할에 `{{contact.buyer_name}}` 같은 커스텀 필드 자리표시자를 설정한 템플릿이 있다고 해요. 대부분의 발송에서는 워크플로우가 연락처 레코드에서 자리표시자 값을 찾아 채워요. 그런데 특정 거래에서 다른 구매자에게 보내야 한다면, 워크플로우 액션에 그 구매자의 정보를 직접 입력하세요. 그러면 이번 발송에만 템플릿 기본값 대신 입력한 값이 쓰여요.

{% hint style="info" %}
거의 바뀌지 않는 역할(예: "판매자" 역할에 들어가는 에이전시 이름)에는 템플릿에서 커스텀 필드 자리표시자를 쓰세요. 거래마다 달라지는 역할(예: 구매자, 공동 서명자, 증인)은 워크플로우에서 바꾸는 것이 좋아요. 이렇게 하면 템플릿 복제는 줄이고 유연성은 높일 수 있어요.
{% endhint %}

## 자주 묻는 질문

### 템플릿 하나에 서명자 역할을 몇 개까지 만들 수 있나요?
템플릿당 서명자 역할을 최대 6개까지 만들 수 있어요. 각 역할에는 입력 요소가 하나 이상 지정되어야 해요.

### **연락처** 역할을 템플릿 요소에 꼭 지정해야 하나요?
네. **Send Document** 워크플로우 액션이 제대로 동작하려면 **연락처** 역할에 입력 요소가 하나 이상 지정되어 있어야 해요. **연락처** 역할은 주 수신자, 즉 워크플로우에 등록되어 문서 발송을 시작시키는 연락처를 뜻해요.

### 역할 정보에 커스텀 필드 자리표시자를 쓸 수 있나요?
네. 템플릿에서 역할을 정의할 때 이름, 이메일, 전화번호에 커스텀 필드 자리표시자를 쓸 수 있어요. 문서를 보낼 때 하이퍼클래스가 연락처 레코드에서 자리표시자 값을 찾아 채워요. 필요하면 워크플로우에서 자리표시자를 고정값으로 바꿀 수도 있어요.

### 워크플로우에서 역할 정보를 바꾸면 어떻게 되나요?
워크플로우에서 입력한 값은 항상 템플릿 기본값보다 우선해요. 워크플로우 액션에 이름, 이메일, 전화번호를 입력하면 하이퍼클래스는 해당 발송에만 그 값을 쓰고, 템플릿은 그대로 유지돼요.

### 여러 서명자 역할을 설정한 템플릿 하나를 여러 거래에 쓸 수 있나요?
네. 템플릿 하나로 여러 계약을 처리할 수 있어요. 거의 바뀌지 않는 역할에는 커스텀 필드 자리표시자를 쓰고, 거래마다 달라지는 역할(예: 구매자, 공동 서명자, 증인)은 워크플로우에서 바꾸세요.

### 여러 서명자 문서의 서명 순서는 어떻게 되나요?
템플릿에서 역할을 설정할 때 정한 순서대로 하이퍼클래스가 각 서명자에게 문서를 전달해요. 서명자는 순서대로 문서를 받아 자신에게 지정된 입력 요소를 작성해요.

### 모든 역할에 서명 상자를 지정해야 하나요?
아니요. 역할에는 서명 상자, 날짜 필드, 텍스트 입력란 등 지원하는 입력 요소를 원하는 대로 조합해 지정할 수 있어요. 계약에 필요한 대로 역할마다 필요한 요소를 정하세요.

### 제안서와 견적서에도 여러 서명자 역할을 쓸 수 있나요?
네. **문서 & 계약** 영역의 제안서 템플릿과 견적서 템플릿 모두에서 쓸 수 있어요.

### 보낸 문서에 지정된 역할은 어디에서 볼 수 있나요?
문서를 보낸 뒤 **문서 & 계약**에서 해당 문서 화면으로 이동하세요. 지정된 모든 역할과 서명 상태를 볼 수 있어요. 역할마다 서명자의 이름, 이메일, 서명 완료 여부가 표시돼요.
