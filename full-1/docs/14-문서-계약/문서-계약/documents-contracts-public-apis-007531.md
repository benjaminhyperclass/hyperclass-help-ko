# 문서 & 계약 공개 API

문서 & 계약 공개 API를 쓰면 개발자가 API 요청으로 문서 목록을 조회하고, 기존 문서를 연락처에게 보내고, 템플릿을 조회하고, 템플릿으로 문서를 만들 수 있어요. 외부 시스템과 기록을 맞추거나 문서 발송을 자동으로 실행할 때 쓰며, 프로그래밍으로 사용하는 기능이에요.

문서 & 계약 기능 자체는 [문서 & 계약 사용 방법](../how-to-use-documents-contracts.md)에서 확인하세요.

## 문서 & 계약 공개 API란?

문서 & 계약 공개 API는 앱 화면에서 직접 작업하는 대신 API 요청으로 하이퍼클래스의 문서를 다루는 방법이에요. 하이퍼클래스를 외부 시스템과 연결하거나, 직접 만든 업무 흐름에서 문서를 자동으로 보내거나, 저장해 둔 템플릿으로 문서를 만들 때 유용해요. 이 API는 해당 로케이션(서브 계정) 범위에서 동작해요. 노코드 워크플로우만으로는 부족하고 개발자가 직접 자동화해야 할 때 가장 잘 맞아요.

현재 다음과 같은 핵심 작업을 지원해요.

- 로케이션의 문서 목록 조회
- 기존 문서를 한 명 이상의 연락처에게 보내기
- 로케이션의 템플릿 목록 조회
- 템플릿으로 문서를 만들고 한 번의 요청으로 보내기

---

## 문서 & 계약 공개 API의 장점

문서 & 계약 공개 API를 쓰면 수작업을 줄이고 문서 작업을 다른 업무 도구와 연결할 수 있어요. 문서를 언제 만들고, 보내고, 후속 조치할지 더 세밀하게 관리하고 싶은 비즈니스에 특히 도움이 돼요.

- 문서 발송 자동화: 하이퍼클래스를 직접 열지 않아도 외부 도구, 자체 앱, 사내 시스템에서 문서를 보낼 수 있어요.
- 저장된 템플릿 활용: API 호출 한 번으로 기존 템플릿에서 새 문서를 만들어, 반복되는 업무를 빠르게 처리해요.
- 문서 데이터 동기화: 문서와 템플릿 목록을 가져와 리포팅, 시스템 동기화, 운영 현황 파악에 써요.
- 확장 가능한 워크플로우: API로 보낸 문서를 후속 워크플로우 트리거와 연결해 리마인드, 후속 조치, 상태별 자동화를 구성해요.
- 수작업 오류 감소: 팀, 시스템, 고객 대면 프로세스 전반에서 템플릿을 고르고 보내는 방식을 통일해요.

## 문서 목록 조회

**List Documents**(문서 목록 조회) 엔드포인트는 특정 로케이션에 있는 문서 기록을 가져와요. 문서 목록을 동기화하거나, 다른 시스템에 사용 가능한 문서를 보여 주거나, 추가 작업을 실행하기 전에 이미 어떤 문서가 있는지 확인할 때 유용해요.

**List Documents** 엔드포인트로 다음 작업을 할 수 있어요.

- 로케이션에 있는 문서 가져오기
- 하이퍼클래스와 외부 시스템 간 동기화 지원
- 기존 문서 기록을 참조하는 사내 도구 개발
- 이미 있는 문서를 먼저 확인해 중복 생성 줄이기

## 문서 보내기

하이퍼클래스에 이미 준비해 둔 문서를 적절한 시점에 연락처에게 전달하기만 하면 될 때는 API로 기존 문서를 보내면 편해요. 맞춤 업무 로직, 외부 앱 트리거, 기본 워크플로우 액션으로 처리하기 어려운 개발자 주도 자동화에 쓸 수 있어요.

**문서 보내기** 엔드포인트로 다음 작업을 할 수 있어요.

- 미리 만들어 둔 문서를 연락처에게 보내기
- 외부 폼, 포털, 앱에서 문서 발송 실행
- 맞춤 워크플로우 전반의 문서 발송 방식 통일
- 영업·온보딩 팀의 수동 전달 단계 줄이기

다음 내용을 기억해 두세요.

- 보내려는 문서는 하이퍼클래스에 미리 만들어져 있어야 해요.
- 수신자 동작은 공식 API 문서에 정의된 기능을 따라야 해요.
- API로 문서를 보낸 뒤, 문서를 보냈을 때나 서명됐을 때의 후속 자동화는 워크플로우로 이어서 구성할 수 있어요.

## 템플릿 목록 조회

**List Templates**(템플릿 목록 조회) 엔드포인트를 쓰면 하이퍼클래스 로케이션에서 쓸 수 있는 재사용 가능한 문서 틀을 가져올 수 있어요. 외부 시스템에서 승인된 템플릿 중에 골라 쓰게 하려는데, 매번 같은 내용을 새로 만들고 싶지 않을 때 특히 유용해요.

**List Templates** 엔드포인트로 다음 작업을 할 수 있어요.

- 로케이션에서 쓸 수 있는 템플릿 기록 가져오기
- 외부 앱이나 사내 도구의 템플릿 선택 화면 구성
- 문서를 만들기 전에 템플릿이 있는지 확인
- 팀 전체의 반복 문서 작성 방식 통일

## 템플릿 보내기

**템플릿 보내기** 엔드포인트를 쓰면 저장된 템플릿으로 문서를 만들고 API 호출 한 번으로 바로 보낼 수 있어요. 문서 생성과 발송이 한 번에 처리돼서, 제안서나 계약서처럼 반복되는 문서를 자동화할 때 가장 유용한 방법 중 하나예요.

**템플릿 보내기** 엔드포인트로 다음 작업을 할 수 있어요.

- 템플릿으로 새 문서 만들기
- 만든 문서를 바로 보내기
- 반복되는 계약서·제안서 업무 자동화
- 외부 트리거나 시스템에서 개인화된 문서 발송 지원

다음과 같은 경우에 특히 알맞아요.

- 하이퍼클래스에서 이미 표준 템플릿을 쓰고 있을 때
- 연락처마다 새 문서를 만들어야 할 때
- 업무가 하이퍼클래스 밖에서 시작되지만, 문서 기능은 하이퍼클래스 것을 그대로 쓰고 싶을 때

## 문서 & 계약 공개 API 설정하기

설정을 제대로 해 두면 안전하게 인증하고, 올바른 로케이션을 지정하고, 알맞은 API 엔드포인트를 호출할 수 있어요. 개발을 시작하기 전에 내 사용 사례에 **비공개 연동**이 맞는지, 하이퍼클래스 API 플랫폼이 지원하는 더 넓은 개발자 방식이 맞는지 먼저 확인하세요.

1. 문서 & 계약이 내 업무에 포함되어 있는지, 필요한 문서나 템플릿이 올바른 로케이션에 이미 있는지 확인해요.
2. 하이퍼클래스 **API 문서**를 확인해 엔드포인트 동작, 인증 요건, 요청 상세를 점검해요. 공식 API 문서는 현재 개발자 마켓플레이스 문서 경로에서 제공돼요.
3. 연동에 사용할 인증 방식을 정해요. **비공개 연동**은 안전한 내부 연결을 위한 방식이고, 마켓플레이스 방식의 개발자 흐름은 OAuth 기반 접근을 쓸 수 있어요.
4. API 요청이 올바른 로케이션을 대상으로 하는지 확인해요. 그래야 의도한 계정 영역에서 문서와 템플릿을 가져와요.
5. 필요한 작업별로 요청 흐름을 테스트해요.

   - 문서 목록 조회(List Documents)
   - 문서 보내기
   - 템플릿 목록 조회(List Templates)
   - 템플릿 보내기
6. 문서를 보낸 뒤의 동작이 필요하면, 문서를 보냈을 때, 열람했을 때, 서명했을 때, 완료했을 때 같은 문서 이벤트에 반응하는 워크플로우 자동화에 연결해요. 자세한 방법은 [워크플로우로 계약서·제안서 자동 발송하기](../how-to-create-and-send-document-or-contract-templates-automatically-in-a-workflo.md)에서 확인하세요.

## 자주 묻는 질문

### 문서 & 계약 공개 API는 개발자용인가요?
네. 프로그래밍으로 쓰도록 만든 기능이에요. 하이퍼클래스 문서 업무를 중심으로 연동, 자동화, 맞춤 앱을 만드는 팀에 특히 알맞아요.

### 문서 보내기와 템플릿 보내기는 어떻게 다른가요?
**문서 보내기**는 하이퍼클래스에 이미 있는 문서를 보내요. **템플릿 보내기**는 템플릿으로 새 문서를 만들고 같은 요청에서 바로 보내요.

### 워크플로우 대신 이 API를 써도 되나요?
네. 업무가 하이퍼클래스 밖에서 시작되거나 맞춤 로직이 필요할 때 쓸 수 있어요. 하이퍼클래스 안에서 노코드로 자동화할 때는 워크플로우가 더 낫고, 개발자 주도 연동에는 API가 더 알맞아요.

### 하이퍼클래스에서 이미 만든 템플릿도 이 API로 쓸 수 있나요?
네. 템플릿 관련 엔드포인트는 로케이션의 템플릿을 조회하고, 그 템플릿으로 프로그래밍 방식으로 문서를 만들 수 있게 설계되어 있어요.

### 문서를 보낸 뒤 후속 조치도 자동화할 수 있나요?
네. API로 보낸 문서를 문서 & 계약 **워크플로우 트리거**와 함께 쓰면, 문서 상태에 따라 리마인드, 내부 알림, 후속 작업을 자동으로 처리할 수 있어요.

### 이 API를 쓰려면 비공개 연동이 꼭 필요한가요?
꼭 그렇지는 않아요. **비공개 연동**은 안전한 내부용 사례에 쓸 수 있는 한 가지 방법이에요. 하이퍼클래스는 현재 API 플랫폼과 마켓플레이스 문서를 통한 더 넓은 개발자 접근 방식도 지원해요.

### 이 엔드포인트에서 '로케이션'은 무슨 뜻인가요?
이 엔드포인트는 해당 로케이션 범위에서 동작해요. 그래서 API가 반환하는 문서와 템플릿은 그 로케이션의 데이터에 속해요.

### 문서 작업을 모두 이 공개 API로 처리할 수 있나요?
이 도움말에서 다루는 범위는 문서와 템플릿의 목록 조회, 발송 작업이에요. 가장 최신 엔드포인트 지원 범위는 항상 공식 API 문서에서 확인하세요.
