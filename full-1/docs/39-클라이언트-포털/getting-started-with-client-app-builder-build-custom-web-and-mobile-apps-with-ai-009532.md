# Client App Builder 시작하기: AI로 맞춤형 웹·모바일 앱 만들기

**Client App Builder**(클라이언트 앱 빌더)는 코드를 쓰지 않고 AI로 브랜드에 맞는 웹 포털과 Android 모바일 앱을 만드는 기능이에요. 이 문서에서는 켜는 방법부터 앱 만들기, 미리보기, 게시, 관리까지 차례로 안내해요.

내 비즈니스와 만들고 싶은 경험을 설명하면 AI가 앱을 기획하고 페이지를 디자인해요. 이미 쓰고 있는 하이퍼클래스 기능도 연결해 줘요. 이렇게 만든 앱은 미리 보고, 다듬고, 게시할 수 있어요.

학습 포털, 코칭 플랫폼, 멤버십 경험, 브랜드 모바일 앱 등 무엇을 만들든 지금 쓰고 있는 하이퍼클래스 도구와 데이터를 그대로 활용할 수 있어요.

사용 위치: **Client App Builder**는 서브 계정 수준의 **실험실**에서 사용할 수 있어요.

---

## Client App Builder란?

**Client App Builder**는 고객과 멤버를 위한 맞춤 경험을 만들어 주는 AI 앱 빌더예요.

요소를 하나하나 직접 배치하는 일반 웹사이트 빌더와 달리, 원하는 내용을 일상적인 말로 설명하면 돼요. AI가 디자인, 페이지, 내비게이션, 지원되는 기능을 만들어 줘요.

### 무엇을 만들 수 있나요?

**웹 앱**

브라우저에서 쓰는 맞춤형 클라이언트 포탈을 만들 수 있어요. 멤버는 이 포탈에서 코스를 보고, 커뮤니티에 참여하고, 예약을 관리하고, 공유된 파일을 둘러보고, 내 비즈니스와 소통할 수 있어요.

**모바일 앱**

내비게이션, 레이아웃, 색상, 기본 모바일 기능을 맞춘 브랜드 Android 앱을 만들 수 있어요. 빌더에서 바로 설치용 Android APK도 만들 수 있어요.

### 작동 방식

Client App Builder는 다음 순서로 진행돼요.

1. 설명: 내 비즈니스와 원하는 경험을 AI에게 알려 주세요.
2. 맞춤 설정: 설정 질문에 답하고 브랜딩과 디자인 취향을 고르세요.
3. 빌드: AI가 앱의 페이지, 화면, 지원되는 기능을 만들어요.
4. 수정: 대화나 시각적 편집 도구로 앱을 다듬으세요.
5. 미리보기: 게시하기 전에 앱을 살펴보세요.
6. 게시: 웹 앱을 공개하거나 설치용 Android 앱을 만드세요.

앱은 하이퍼클래스의 기존 클라이언트 포탈 환경을 그대로 사용해요. 멤버 계정, 코스, 커뮤니티, 지원되는 CRM 데이터도 포함돼요.

## Client App Builder 켜기

**Client App Builder**는 현재 **실험실**을 통해 제공돼요.

### 1단계: 기능 켜기

1. 하이퍼클래스 계정을 여세요.
2. **실험실**로 이동하세요.
3. **Client App Builder**를 찾으세요.
4. 내 서브 계정에서 이 기능을 활성화하세요.

![실험실에서 Client App Builder 토글을 켜는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084618562/original/dXNS3LX70fP_CweD6v8S5H9cNNXyezEKwA.jpeg?1793372240)

### 2단계: Client App Builder 열기

기능을 켜면 **멤버십 > Client App Builder**로 들어가세요.

계정의 내비게이션 구성에 따라 **Client Apps**(클라이언트 앱) **> Client App Builder**에 나타날 수도 있어요.

![Client Apps 메뉴 아래의 Client App Builder](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084618567/original/g-g40JXf7xXUlVVgzNFw15fbreIfg-tv0A.jpeg?1793372241)

{% hint style="info" %}
**Client App Builder**는 서브 계정 단위로 작동해요. 한 서브 계정에서 만든 앱은 다른 서브 계정에서 자동으로 쓸 수 없어요.
{% endhint %}

## 첫 번째 앱 만들기

**Client App Builder**를 열면 만들고 싶은 앱을 설명하는 입력창이 보여요.

자세히 설명하며 시작해도 되고, 예약, 이벤트, 에이전시 클라이언트 포탈 같은 추천 아이디어 중에서 골라도 돼요.

![Client App Builder 홈 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084618561/original/2Gq72NjDRGQaQAxGMf6-5L35XW6_1nMMkw.jpeg?1793372240)

### 1단계: 앱 설명하기

예를 들어 이렇게 써 보세요.

"우리 피트니스 스튜디오의 멤버 포털을 만들어 줘. 멤버가 코스를 보고 구매하고, 커뮤니티에 참여하고, 예약하고, 자료를 볼 수 있어야 해. 브랜드 색상을 쓴 깔끔하고 모던한 디자인으로 부탁해."

비즈니스, 대상 고객, 원하는 기능을 구체적으로 알려 줄수록 첫 앱이 내 상황에 더 잘 맞아요.

![앱을 설명하는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084618570/original/kQU7dteaVab2ueXCMg_anM8-gWBW72CalA.jpeg?1793372241)

### 2단계: 웹 또는 모바일 선택하기

만들 앱 유형을 선택하세요.

- **Web**(웹): 브라우저에서 쓰는 클라이언트 포탈이에요.
- **Mobile**(모바일): 브랜드를 입힌 Android 모바일 앱이에요.

입력한 내용을 보고 AI가 앱 유형을 추천할 수 있어요. 앱을 만들기 전에는 바꿀 수 있어요.

{% hint style="warning" %}
앱을 한 번 만들고 나면 웹과 모바일 사이를 바꿀 수 없어요. 다른 형식이 필요하면 앱을 따로 만드세요.
{% endhint %}

![웹 또는 모바일과 시작 방식을 선택하는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084618568/original/E41OefINvMV9-vGtXu6u-0iU_LjUXDtfDw.jpeg?1793372241)

### 3단계: 설정 질문에 답하기

AI가 비즈니스, 앱 이름, 대상 고객, 필요한 기능, 앱에 접근할 수 있는 사람 등을 물어볼 수 있어요.

이 답변을 바탕으로 내 상황에 맞는 앱이 만들어져요.

![설정 질문 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084618566/original/b5r-RiP7DYaRf5mfkUChhHmbKWRUitjMVQ.jpeg?1793372241)

### 4단계: 디자인 고르기

앱 유형과 시작 방식에 따라 추천 디자인 시스템, 색상, 글꼴, 기존 브랜드 보드 중에서 고를 수 있어요.

지원되는 웹 경험에서는 디자인 시스템을 더 살펴보고, 이미지를 첨부해 원하는 분위기를 알려 줄 수도 있어요.

![색상 팔레트와 글꼴을 고르는 디자인 선택 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084618563/original/25Wil6xccz5xYS0IL8j3FWmJ10v_6L81MQ.jpeg?1793372240)

### 5단계: 검토하고 빌드하기

지원되는 웹 빌드에서는 앱을 만들기 전에 AI가 계획을 먼저 보여 줘요.

![빌드 계획을 검토하는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084618572/original/4GQxwN3tOklEXJ2MhRqkG0F6-o83oy7cpw.jpeg?1793372241)

다음 중에서 고를 수 있어요.

- **Approve & build**(승인하고 빌드): 제안된 계획대로 진행해요.
- **Refine**(수정 요청): 빌드 전에 변경을 요청해요.
- **Reject**(거절): 제안된 계획을 받아들이지 않아요.

빌드가 시작되면 진행 상황을 볼 수 있고, 준비되면 미리보기를 열 수 있어요.

![빌드 진행 상황 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084618565/original/4TmXrvrp0rnKz-i9HwX9Fd1E9UPTDzwotQ.jpeg?1793372241)

## 시작 방식 고르기

앱을 만드는 방법은 두 가지예요.

### 옵션 A: **Describe It Instead**(대신 설명하기, Vibe Coding)

AI가 내 설명을 바탕으로 맞춤 경험을 만들어 주길 원할 때 선택하세요.

AI가 비즈니스 요구 사항과 디자인 취향에 맞춰 페이지, 레이아웃, 내비게이션을 만들어요.

기본 클라이언트 포탈 레이아웃이 아니라 나만의 개성 있는 경험을 원할 때 알맞아요.

예를 들어 이렇게 요청할 수 있어요.

"개인 맞춤 환영 대시보드, 예정된 세션, 이용할 수 있는 프로그램, 멤버 커뮤니티가 있는 코칭 포털을 만들어 줘."

지원되는 웹 앱에서는 **비주얼 편집**, AI가 제안하는 다음 단계, 페이지 빌드 프롬프트로 경험을 계속 발전시킬 수 있어요.

### 옵션 B: **ClientPortal Standard**(클라이언트 포탈 스탠다드)

익숙한 하이퍼클래스 클라이언트 포탈에서 시작해 모양과 내비게이션만 바꾸고 싶을 때 선택하세요.

지원되는 기본 페이지를 맞추고, 브랜딩을 조정하고, 레이아웃을 설정할 수 있어요. 전체를 처음부터 다시 만들 필요가 없어요.

표준 웹 앱에서는 대시보드, 상품, 강의, 커뮤니티, 인보이스를 시작 기능으로 쓸 수 있어요. 모바일 앱은 기능이 다를 수 있어요.

![ClientPortal Standard 시작 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084618564/original/Et9Cdngfqw19y7U7PT27kLm7gMa9k_SOaQ.jpeg?1793372241)

어떤 방식을 골라야 할까요?

AI가 만든 더 개성 있는 경험을 원하면 **Describe It Instead**를 선택하세요. 익숙한 포털 구조는 유지하면서 디자인과 내비게이션만 바꾸고 싶다면 **ClientPortal Standard**를 선택하세요.

## AI로 앱 다듬기

첫 빌드는 시작일 뿐이에요.

**Client App Builder**에서는 대화로 경험을 계속 다듬을 수 있어요.

### 채팅으로 변경하기

메시지 입력창에 이런 식으로 요청해 보세요.

- "홈페이지를 더 모던하고 미니멀하게 바꿔 줘."
- "내비게이션 맨 위로 코스를 옮겨 줘."
- "예정된 워크숍 페이지를 추가해 줘."
- "메인 색상을 우리 브랜드에 맞게 바꿔 줘."
- "코스 카드가 더 눈에 띄게 해 줘."

디자인을 새로 바꿔 달라고 따로 요청하지 않으면, 이어지는 요청에서는 대체로 기존 디자인이 유지돼요.

![채팅으로 앱을 다듬는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084618569/original/YOFiepzwBuGLJxXaAk65JUroPgCcDEe3kQ.jpeg?1793372241)

### 비주얼 편집 사용하기

**Describe It Instead**로 만든 웹 앱에서는 미리보기에서 **비주얼 편집**으로 요소를 직접 선택할 수 있어요.

바꾸고 싶은 요소를 선택한 다음 원하는 변경 내용을 설명하세요.

한 번의 비주얼 편집 요청에서 최대 20개까지 요소를 선택할 수 있어요.

### 빠진 페이지 만들기

생성된 웹 앱에 아직 만들지 않은 페이지로 가는 링크가 있으면 **Build this page**(이 페이지 만들기) 옵션이 보일 수 있어요.

이 옵션으로 AI에게 빠진 페이지를 만들어 달라는 요청을 준비하세요.

### 레이아웃과 테마 맞추기

**ClientPortal Standard** 앱에서는 미리보기가 준비된 후 **Customizer**(커스터마이저)에서 더 많은 설정을 쓸 수 있어요.

앱 유형에 따라 다음을 바꿀 수 있어요.

- **브랜드 색상**, 글꼴, 로고, 앱 아이덴티티
- 내비게이션 항목, 아이콘, 순서
- 기본 페이지와 첫 화면
- 모바일 하단 탭, 헤더 스타일, 계정 위치
- 사용자 지정 내비게이션 링크와 지원되는 페이지

모바일 앱에서는 앱을 처음 열 때 라이트 모드로 열지 다크 모드로 열지도 설정할 수 있어요.

![레이아웃 커스터마이저 - 내비게이션](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084618583/original/L76Yk2DmTZ5VyYhVjgYu8ZBJv6IeWzFezQ.jpeg?1793372242)

![테마 커스터마이저](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084618575/original/Fow214H6OEVoC3p1HohfrpLTaJOJ74UWQw.jpeg?1793372241)

{% hint style="info" %}
레이아웃·테마 **Customizer**는 **ClientPortal Standard** 앱에서 쓸 수 있어요. **Describe It Instead**로 만든 앱은 주로 AI 프롬프트와 지원되는 편집 도구로 수정해요.
{% endhint %}

## 하이퍼클래스 기능 연결하기

**Client App Builder**의 큰 장점은 앱에서 하이퍼클래스의 기존 기능을 그대로 쓸 수 있다는 점이에요.

멤버십 환경을 새로 만들거나 멤버 계정을 따로 관리할 필요가 없어요.

### 지원되는 기능

**코스**

멤버가 코스를 둘러보고, 이용할 수 있는 콘텐츠를 구매하고, 강의를 보고, 학습 진행 상황을 확인하고, 지원되는 라이브 세션에 참여할 수 있어요.

**커뮤니티**

커뮤니티 그룹, 피드, 초대, 지원되는 탐색 기능을 이용할 수 있어요.

**예약**

지원되는 클라이언트 포탈 기능을 통해 멤버가 예약 관련 경험을 이용할 수 있어요.

**공유된 파일**

앱에서 멤버에게 자료와 파일을 제공할 수 있어요.

**멤버 계정**

로그인, 회원가입, 비밀번호 찾기 등 기존 클라이언트 포탈 인증을 그대로 쓸 수 있어요.

**CRM 데이터**

지원되는 CRM 정보와 사용자 지정 객체를 활용해 데이터 기반의 인터랙티브한 멤버 경험을 만들 수 있어요.

이 기능들은 하이퍼클래스의 기존 시스템을 통해 작동하므로, 멤버 경험이 내 비즈니스와 계속 이어져요.

## 앱에서 사용자 지정 객체 사용하기

사용자 지정 객체를 쓰면 정보를 보여 주는 데서 한 걸음 더 나아가, 멤버가 하이퍼클래스 CRM에 저장된 레코드를 제출하고 활용하게 할 수 있어요.

예를 들어 멤버가 코칭 신청서, 부동산 문의, 서비스 요청을 제출하는 포털을 만들 수 있어요.

### 사용자 지정 객체가 작동하는 방식

1. 멤버가 제출하거나 관리할 정보를 설명하세요.
2. 요청에 CRM 데이터 저장이 필요하면 AI가 사용자 지정 객체를 쓸지 물어봐요.
3. AI가 필드, 드롭다운 옵션, 지원되는 관계를 포함한 데이터 구조를 제안해요.
4. 제안된 구조, 샘플 레코드, 멤버에게 보이는 범위를 검토하세요.
5. 계획을 승인하거나 변경을 요청하세요.
6. AI가 승인된 객체와 연결된 앱 경험을 만들어요.

![제안된 사용자 지정 객체 구조](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084618587/original/TTb7SQJTLT5wwsAkAERMroXtq1Ik_40aag.jpeg?1793372244)

### 멤버에게 보이는 범위

설정에 따라 멤버가 볼 수 있는 레코드를 다음과 같이 정할 수 있어요.

- 본인의 레코드
- 소속 회사와 연결된 레코드
- 모든 레코드(읽기 전용)

![누가 무엇을 볼 수 있는지 정하는 멤버 공개 범위 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084618574/original/Pdl4IbuzsXcHj9lvo24DJbFE3emi6f5B7Q.jpeg?1793372241)

### 결제와 레코드

결제 제공업체가 연결되어 있으면, 지원되는 웹 경험에서 하이퍼클래스 인보이스를 사용한 결제 동작도 넣을 수 있어요.

사용자 지정 객체는 한 번의 변경에 최대 3개까지 만들 수 있어요. 단, 서브 계정당 CRM 전체 한도인 사용자 지정 객체 10개를 넘을 수 없어요.

{% hint style="warning" %}
사용자 지정 객체는 웹과 모바일 경험에서 모두 쓸 수 있지만, 레코드 기반 결제와 미디어 첨부 등 일부 기능은 현재 웹에서만 쓸 수 있어요.
{% endhint %}

## 웹 앱 미리보기와 게시

### 앱 미리보기

**Client App Builder**는 앱을 만드는 동안 실시간 미리보기를 보여 줘서 경험을 바로 살펴볼 수 있어요.

웹 앱에서는 다음 미리보기 컨트롤을 쓸 수 있어요.

- 데스크톱, 태블릿, 모바일 화면 크기
- 뒤로 가기·앞으로 가기
- 새로고침
- **새 탭에서 열기**
- 미리보기 URL 복사

![웹 앱 미리보기 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084618584/original/X3p0xgnWadd3EkuSJAC_3OZjunbBRAvBXw.jpeg?1793372243)

미리보기를 오래 쓰지 않으면 리소스를 아끼기 위해 일시 중지될 수 있어요. 빌더로 돌아오면 다시 시작돼요.

게시된 앱은 미리보기가 멈춰 있어도 영향을 받지 않아요.

### 웹 앱 게시하기

앱이 마음에 들면 다음 순서로 게시하세요.

1. 게시 컨트롤을 여세요.
2. app.clientclub.net에서 사용할 수 있는 주소를 고르세요.
3. 아직 만들지 않은 페이지로 연결되는 링크가 있다는 경고가 있는지 확인하세요.
4. 빠진 페이지를 만들거나, 그 페이지를 미완성인 채로 게시하기로 선택하세요.
5. 앱을 게시하세요.

![앱 주소와 사용자 지정 도메인을 설정하는 게시 창](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084618571/original/zPxYrla0C9EqnhgD2_k-WqguQmDY6nRr-w.jpeg?1793372241)

나중에 변경 사항을 다시 게시할 수 있고, 필요하면 앱 게시를 취소할 수도 있어요.

### 사용자 지정 도메인 연결하기

게시한 웹 앱에 내 도메인을 연결할 수도 있어요.

**Client App Builder**가 도메인 연결을 단계별로 안내해 주고, 필요하면 DNS를 직접 설정할 수도 있어요.

웹 앱 하나에 사용자 지정 도메인을 최대 10개까지 연결할 수 있어요.

{% hint style="info" %}
이미 서브 계정의 활성 클라이언트 포탈 도메인으로 지정된 도메인은 쓸 수 없어요.
{% endhint %}

## Android 앱 만들고 게시하기

**Client App Builder**는 브랜드를 입힌 Android 모바일 앱도 지원해요.

### 모바일 경험 맞추기

시작 방식에 따라 다음과 같은 모바일 기능을 설정할 수 있어요.

- 앱 이름, 브랜딩, 색상, 글꼴
- 하단 내비게이션 탭과 헤더 레이아웃
- 로그인 후 처음 열리는 화면
- 커뮤니티와 코스 내비게이션
- 사용자 지정 페이지와 외부 모듈
- 카메라, 사진 접근 등 기기 기능

새 멤버는 가입 코드로 가입할 수 있어요.

### 모바일 앱 미리보기

빌더가 모바일 경험을 휴대폰 화면 안에 보여 줘요. 설치용 앱을 만들기 전에 디자인과 내비게이션을 확인할 수 있어요.

### Android APK 만들기

준비가 되면 다음 순서로 진행하세요.

1. 모바일 앱의 게시 컨트롤을 여세요.
2. 필요한 앱 아이덴티티와 브랜딩 자산을 제공하세요.
3. Android APK 빌드를 시작하세요.
4. 빌드 상태를 확인하세요.
5. 준비되면 서명된 APK를 다운로드하세요.

![Android APK 게시 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084618576/original/7BAdh1WGFouePjHSfhka5c-zAWvqqdRK_A.jpeg?1793372241)

APK 빌드는 보통 15~25분 정도 걸려요.

![Android APK 자산과 서명된 APK 빌드 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084618573/original/TxhiNXNevtBuRTUc8202Un0kFn8oFHcX6g.jpeg?1793372241)

### Android에 필요한 자산

| 항목 | 요구 사항 |
| --- | --- |
| 앱 이름 | 1~30자 |
| 앱 아이콘 | PNG, 1024 × 1024픽셀, 최대 5MB |
| 스플래시 화면 | PNG, 1080 × 1920픽셀, 최대 5MB |
| Firebase 구성 | 선택 사항인 google-services.json, 최대 5MB, 패키지 ID와 일치해야 함 |

### 모바일 게시 시 알아 둘 제한 사항

현재 **Client App Builder**에서는 Android APK 다운로드만 지원해요. Google Play나 Apple App Store에 직접 게시하는 기능은 지원하지 않아요.

지금은 앱 하나당 서명된 APK를 하나만 만들 수 있어요.

**ClientPortal Standard** 모바일 앱은 지원되는 디자인·설정 변경을 이미 설치된 앱에 게시할 수 있어요. **Describe It Instead**로 만든 앱에서 AI가 새로 만든 화면은 새 APK가 필요한데, 현재는 지원되지 않아요.

서명된 APK를 만들기 전에 Android 경험을 꼼꼼히 계획하고 테스트하세요.

iOS 앱 생성은 현재 사용할 수 없어요.

## 앱 관리하기

**Client App Builder**에는 앱에 접근하고 관리할 수 있는 프로젝트 대시보드가 있어요.

홈 화면에서 최근 프로젝트를 보거나 **모든 프로젝트**를 열 수 있어요.

다음 관리 기능을 쓸 수 있어요.

- 기존 앱 검색
- 최근 프로젝트와 즐겨찾기한 프로젝트 보기
- 앱 즐겨찾기 추가·해제
- 앱 이름 변경
- 앱 삭제
- 웹·모바일 프로젝트 구분과 상태 확인

![별표, 이름 변경, 삭제가 있는 프로젝트 옵션](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084618578/original/LfHw2SLSm_fc4eYuzvwLVBzrQo5wA9_Kjg.jpeg?1793372241)

### 앱 개수 제한

서브 계정 하나에서 웹과 모바일 프로젝트를 합쳐 앱을 최대 5개까지 만들 수 있어요.

한도에 도달했다면 기존 앱을 삭제해야 새 앱을 만들 수 있어요.

{% hint style="warning" %}
화면에서 앱을 삭제하면 되돌릴 수 없어요. 삭제를 확인하기 전에 신중하게 결정하세요.
{% endhint %}

### 누가 앱에 접근할 수 있나요?

접근 권한은 하이퍼클래스 서브 계정에서의 역할에 따라 달라져요.

- 관리자는 서브 계정에서 만든 앱을 보고, 편집하고, 삭제할 수 있어요.
- 일반 사용자는 앱을 만들고 본인이 소유한 앱을 관리할 수 있지만, 다른 사용자의 앱은 볼 수 없어요.
- 앱을 열 수 있는 사용자는 그 앱의 게시 컨트롤도 쓸 수 있어요.

## 외부 AI 도구(MCP)로 만들기

고급 사용자는 하이퍼클래스의 MCP(Model Context Protocol) 연동을 통해 호환되는 외부 AI 개발 도구로도 웹 앱을 만들 수 있어요.

지원되는 설정 옵션은 Claude, Claude Code, ChatGPT, Codex, Cursor, VS Code예요.

### 작동 방식

1. **Client App Builder**에서 **Build from your editor**(에디터에서 빌드) 섹션을 여세요.
2. 사용할 지원 AI 도구를 고르세요.
3. 화면에 표시되는 MCP 연결 안내를 따라 하세요.
4. 하이퍼클래스에 로그인하세요.
5. 작업할 서브 계정을 선택하세요.
6. 요청된 접근 권한을 승인하세요.

![Build from your editor (MCP) 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155084618577/original/t_r224hcaWwQno1nwk_h6S6mV3rXTKGa_w.jpeg?1793372241)

연결되면 지원되는 도구로 앱을 만들고, 빌드를 시작하고, 진행 상황을 확인하고, 설정 질문에 답하고, 앱 파일을 편집할 수 있어요.

{% hint style="warning" %}
MCP 접근으로는 현재 앱 게시·게시 취소, 시크릿 관리, 프로덕션용 모바일 앱 빌드를 할 수 없어요.
{% endhint %}

## 현재 제한 사항

**Client App Builder**는 계속 발전하고 있어요. 앱을 계획할 때 다음 제한 사항을 참고하세요.

| 기능 | 현재 지원 상태 |
| --- | --- |
| 웹 앱 만들기 | 지원 |
| Android 앱 만들기 | 지원 |
| iOS 앱 만들기 | 아직 사용할 수 없음 |
| Google Play / App Store 게시 | 아직 사용할 수 없음 |
| 사용자 지정 웹 도메인 | 지원, 최대 10개 |
| 서브 계정당 앱 수 | 5개 |
| AI가 만드는 사용자 지정 객체 | 지원, CRM 한도 적용 |
| 업종별 기성 템플릿 | 출시 예정 |
| 웹 앱 복제 | 현재 사용할 수 없음 |
| 웹 버전 기록 및 복원 | 현재 사용할 수 없음 |
| 사용자 지정 서버 측 코드 및 데이터베이스 | 지원되지 않음 |
| 서드파티 npm 패키지 설치 | 지원되지 않음 |
| 사용자 지정 결제 체크아웃 | 지원되지 않음. 지원되는 결제는 하이퍼클래스 인보이스를 사용해요 |
| 데스크톱 앱 및 PWA 생성 | 아직 사용할 수 없음 |
| 빌더 화면 언어 | 영어 |

**Client App Builder**는 하이퍼클래스에서 지원하는 기능 위에 경험을 만들도록 설계되었어요. 범용 백엔드 개발 환경은 아니에요.

## 자주 묻는 질문

### Client App Builder를 쓰려면 코딩 경험이 있어야 하나요?

아니요. 원하는 경험을 일상적인 말로 설명하면 AI가 만들어 줘요. 이후에도 대화와 사용할 수 있는 맞춤 설정 컨트롤로 앱을 계속 다듬을 수 있어요.

### 이미 있는 하이퍼클래스 코스와 커뮤니티를 그대로 쓸 수 있나요?

네. **Client App Builder**는 코스, 커뮤니티, 공유된 파일, 예약, 멤버 계정 등 지원되는 클라이언트 포탈 기능과 연동돼요.

### 웹 앱과 모바일 앱을 둘 다 만들 수 있나요?

네. 한 서브 계정 안에서 두 가지 유형을 모두 만들 수 있어요. 단, 합쳐서 앱 5개까지만 가능해요. 앱은 각각 웹 또는 모바일 중 하나로 만들어야 해요.

### 웹 앱을 나중에 모바일 앱으로 바꿀 수 있나요?

아니요. 앱을 만든 후에는 앱 유형을 바꿀 수 없어요. 다른 플랫폼이 필요하면 앱을 따로 만드세요.

### 내 도메인을 쓸 수 있나요?

웹 앱에서는 쓸 수 있어요. 도메인 요건을 충족하면 앱 하나에 사용자 지정 도메인을 최대 10개까지 연결할 수 있어요.

### Apple App Store나 Google Play에 앱을 게시할 수 있나요?

현재는 안 돼요. Android APK 생성은 지원하지만, 앱 스토어에 직접 게시하는 기능과 iOS 앱 생성은 아직 사용할 수 없어요.

### 게시한 뒤에도 변경할 수 있나요?

네, 프로젝트를 계속 편집할 수 있어요. 웹 앱은 변경 사항을 반영해 다시 게시할 수 있어요.

모바일 앱은 시작 방식에 따라 업데이트 방식이 달라요. **ClientPortal Standard**는 일부 변경을 이미 설치된 앱에 게시할 수 있어요. **Describe It Instead**에서 AI가 새로 만든 화면은 APK를 다시 빌드해야 하는데, 이 기능은 아직 사용할 수 없어요.

### 멤버가 앱에서 정보를 제출할 수 있나요?

네. 사용자 지정 객체를 쓰면 지원되는 폼과 레코드 기반 경험을 만들 수 있고, 제출된 정보는 하이퍼클래스 CRM에 저장돼요.

### 앱에 결제를 추가할 수 있나요?

지원되는 웹 경험에서는 하이퍼클래스 인보이스 기반의 결제 동작을 쓸 수 있어요. 사용자 지정 장바구니, 쿠폰, 독립적인 체크아웃 시스템은 현재 지원되지 않아요.

### 외부 AI 코딩 도구를 쓸 수 있나요?

네. 지원되는 MCP 연동을 통해 호환되는 외부 AI 도구로 웹 앱 프로젝트를 작업할 수 있어요. 게시는 여전히 **Client App Builder**에서 해야 해요.

### AI 빌드가 멈추거나 실패하면 어떻게 하나요?

빌드 상태나 오류 내용을 확인한 다음, 다른 프롬프트를 보내 이어서 진행하거나 문제를 고치세요.

빌드가 중단되면 빌더에서 새 메시지로 이어서 진행하는 옵션이 나와요. 모바일 빌드 점검에서는 문제가 생긴 파일과 위치가 표시될 수도 있어요.

### 미리보기가 느리게 불러와져요

미리보기는 일정 시간 사용하지 않으면 일시 중지될 수 있어요. 다시 돌아오면 빌더가 미리보기 환경을 다시 시작해요. 게시된 앱에는 영향이 없어요.

### 삭제한 앱을 복원할 수 있나요?

삭제한 앱은 현재 **Client App Builder** 화면에서 복원할 수 없어요. 더 이상 필요 없는 앱인지 확인한 뒤에 삭제하세요.
