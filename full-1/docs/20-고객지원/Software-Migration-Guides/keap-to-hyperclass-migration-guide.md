# Keap에서 하이퍼클래스로 이전하기 (마이그레이션 가이드)

Keap에서 하이퍼클래스로 옮길 때 연락처, 커스텀 필드, 자동화, 랜딩 페이지 같은 주요 자산을 어떻게 이전하는지 단계별로 안내해요. 업무가 끊기지 않게 옮기면서 하이퍼클래스의 기능을 최대한 활용하는 것이 목표예요.

## 이전 준비하기

### 1단계: 현재 Keap 설정 검토하기

- 핵심 자산 파악: Keap에 있는 중요한 자산을 모두 정리하세요. 연락처, 커스텀 필드, 파이프라인, 자동화, 랜딩 페이지가 여기에 들어가요.
- 워크플로우 기록: 운영에 꼭 필요한 자동화 시퀀스, 캠페인 등의 워크플로우를 모두 적어 두세요.
- 데이터 규모 확인: 옮겨야 할 데이터(연락처, 커스텀 필드, 자동화)가 얼마나 되는지 확인하세요.

### 2단계: 이전 목표 정하기

- 분명한 목표 설정: 하이퍼클래스로 옮기려는 이유를 정리하세요. 자동화 기능 강화, 통합 CRM, 더 나은 요금제 등이 예가 될 수 있어요.
- 중요한 기능 우선 순위 정하기: 운영이 끊기지 않도록 가장 중요한 기능부터 옮기세요.

### 3단계: 백업 준비하기

- Keap 데이터 내보내기: 연락처 목록, 커스텀 필드, 자동화 시퀀스 등 필요한 데이터를 모두 내보내세요.
- 데이터 백업: 이전을 시작하기 전에 내보낸 데이터를 안전하게 백업해 두세요.

## 연락처와 커스텀 필드 이전하기

### 1단계: Keap에서 데이터 내보내기

- 연락처 내보내기:
  - Keap에서 **Contacts > People**로 이동하세요.
  - 내보낼 연락처를 선택하거나 **Select All**을 사용하세요.
  - **Export**를 클릭하고 연락처 데이터를 CSV 파일로 내려받으세요.
  - 연락처가 1,000개가 넘는 대량 내보내기는 이메일 주소를 입력하면 Keap에서 다운로드 링크를 보내 줘요.
- 커스텀 필드 내보내기: 연락처와 회사에 연결된 커스텀 필드를 모두 문서로 정리하거나 내보내세요. 커스텀 필드는 하이퍼클래스에서 직접 다시 만들어야 해요.
- 자동화 규칙 기록: 자동화 시퀀스, 트리거, 액션을 스크린샷으로 남기거나 직접 문서로 정리하세요.

![Keap 데이터 내보내기 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155033893177/original/HvNSim0JgN9NCS5ricBaXUw_SHeyQF6myw.png?1727798693)

### 2단계: 하이퍼클래스로 데이터 가져오기

- 연락처 가져오기:
  - 하이퍼클래스에서 **연락처 > Import Contacts**(연락처 가져오기)로 이동해 Keap에서 내보낸 CSV 파일을 올리세요.
  - 가져오는 과정에서 Keap의 커스텀 필드를 하이퍼클래스의 필드와 연결(매핑)하세요.
- 커스텀 필드 다시 만들기:
  - 하이퍼클래스에서 **설정 > 커스텀 필드**로 이동하세요.
  - Keap의 커스텀 필드를 하나씩 다시 만드세요. 이때 필드 유형을 알맞게 맞춰 주세요.
- 태그 다시 만들기: Keap에서 쓰던 태그를 하이퍼클래스에서 직접 만드세요. 그래야 연락처를 정확하게 분류할 수 있어요.

## 파이프라인과 딜 이전하기

### 1단계: Keap의 기존 파이프라인 검토하기

- 활성 파이프라인 정리: Keap에서 쓰고 있는 파이프라인을 모두 확인하고, 각 파이프라인의 단계와 딜도 함께 정리하세요.
- 딜 정보 기록: 딜마다 딜 금액, 단계, 연결된 연락처 같은 주요 정보를 적어 두세요.

![Keap 파이프라인 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155033895985/original/nSS4_Sg-LmbzHDVNyEeprpVHG-oylfp1fg.png?1727802228)

### 2단계: 하이퍼클래스에서 파이프라인 다시 만들기

- 파이프라인 설정:
  - 하이퍼클래스에서 **기회 관리**(Opportunities) **> 파이프라인**으로 이동하세요.
  - Keap과 같은 구성으로 파이프라인을 만들고, 단계와 설정도 똑같이 추가하세요.
- 딜 직접 옮기기: 딜 정보를 하나씩 직접 입력해서 하이퍼클래스에 다시 만드세요. 딜 단계와 연결된 연락처도 맞춰 주세요.

## 자동화와 캠페인 이전하기

### 1단계: Keap의 기존 자동화 검토하기

- 활성 자동화 정리: 이메일 시퀀스, 태그, 트리거를 포함해 지금 작동 중인 활성 자동화를 모두 확인하세요.
- 자동화 흐름 기록: 자동화마다 흐름을 자세히 메모하거나 스크린샷으로 남기세요. 하이퍼클래스에서 다시 만들 때 도움이 돼요.

### 2단계: 하이퍼클래스에서 자동화 다시 만들기

- 새 워크플로우 만들기:
  - 하이퍼클래스에서 **자동화 > 워크플로우**로 이동하세요.
  - 하이퍼클래스의 트리거, 조건, 액션을 사용해 Keap과 비슷한 결과가 나오도록 자동화를 다시 만드세요.
- 워크플로우 테스트: 다시 만든 워크플로우가 모두 제대로 작동하는지 꼼꼼히 테스트하고, 필요하면 수정하세요.

## 랜딩 페이지와 폼 이전하기

### 1단계: 하이퍼클래스에서 랜딩 페이지 다시 만들기

- 랜딩 페이지 다시 만들기: 하이퍼클래스의 퍼널 및 **웹사이트 빌더**로 Keap의 랜딩 페이지를 다시 만드세요. 디자인과 내용은 기존 Keap 랜딩 페이지와 최대한 비슷하게 맞춰 주세요.
- 폼 추가: 필요한 랜딩 페이지에 폼을 삽입하세요. 폼에서 필요한 리드 정보를 받고, 알맞은 태그나 자동화가 실행되는지 확인하세요.

### 2단계: 폼 설정하기

- 공개 폼 다시 만들기:
  - 하이퍼클래스에서 **사이트 > 폼**으로 이동해 Keap의 공개 폼을 다시 만드세요.
  - 폼 필드와 설정을 Keap에서 쓰던 것과 똑같이 맞추세요.
- 폼 액션 설정: Keap에서처럼 하이퍼클래스에서도 폼을 제출하면 알맞은 태그가 붙고 워크플로우가 실행되도록 설정하세요.

## 예약과 캘린더 이전하기

### 1단계: Keap의 기존 예약 검토하기

- 활성 예약 유형 정리: 지금 쓰고 있는 예약 유형과 관련 설정(알림, 연동 등)을 모두 확인하세요.
- 예약 설정 기록: 예약 유형마다 진행 시간, 가용 시간, 알림 같은 주요 설정을 적어 두세요.

### 2단계: 하이퍼클래스에서 예약 유형 다시 만들기

- 예약 유형 설정:
  - 하이퍼클래스에서 **캘린더 > Appointment Types**(예약 유형)로 이동하세요.
  - Keap의 예약 유형을 하나씩 다시 만들고, 진행 시간, 장소(Zoom 연동), 가용 시간 같은 관련 설정을 모두 옮기세요.
- 외부 캘린더 연동: Google 또는 Outlook 캘린더를 하이퍼클래스와 연동하세요. 그러면 모든 예약이 동기화되고 일정이 겹치는 일을 막을 수 있어요.

## 최종 점검과 교육

### 1단계: 최종 데이터 확인하기

- 데이터 교차 확인: 연락처, 파이프라인, 자동화, 랜딩 페이지를 포함해 모든 데이터가 제대로 옮겨졌는지 확인하세요.
- 워크플로우 검증: 하이퍼클래스에서 모든 워크플로우와 자동화가 작동하는지 확인하세요.

### 2단계: 팀원 교육하기

- 하이퍼클래스 교육: 팀원들이 하이퍼클래스의 CRM, 자동화, 예약 관리 도구를 쓸 수 있도록 필요한 교육을 해 주세요.
- 지원 자료 활용: 팀원들이 계속 배우고 문제를 해결할 때 하이퍼클래스의 지원 자료를 활용하도록 안내하세요.

### 3단계: 모니터링하고 개선하기

- 성과 모니터링: 하이퍼클래스 설정이 어떻게 작동하는지 계속 살펴보고, 필요하면 조정해서 운영을 개선하세요.
- 지속적인 개선: 사업 상황이 달라지는 만큼 설정이 잘 맞는지 주기적으로 검토하세요.

## Keap 사용 종료하기

### 1단계: 전환 기간 두기

- 병행 운영: 전환하는 동안 Keap과 하이퍼클래스를 함께 운영해 보세요. 운영에 차질이 생기지 않도록 도와줘요.
- 단계적 종료: 하이퍼클래스에 익숙해지는 만큼 Keap에 대한 의존도를 조금씩 줄이세요.

### 2단계: Keap 구독 해지하기

- 최종 데이터 백업: Keap 구독을 해지하기 전에 필요한 데이터를 모두 안전하게 백업했는지 확인하세요.
- 공식 해지: Keap의 해지 절차에 따라 구독과 관련 서비스를 해지하세요.

### 3단계: 이전 후 검토하기

- 성과 평가: 이전이 잘 되었는지 평가하세요. 겪은 어려움과 배운 점도 함께 기록하세요.
- 지속적인 모니터링: 이전 후에도 하이퍼클래스 설정을 계속 지켜보고, 문제가 생기면 바로 해결하세요.
