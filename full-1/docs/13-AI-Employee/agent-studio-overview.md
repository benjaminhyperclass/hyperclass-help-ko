# 에이전트 스튜디오의 Flow Agents(흐름 기반 에이전트) 개요

**에이전트 스튜디오**(Agent Studio)에서는 시각적 빌더로 이미 만들어 둔 흐름 기반 AI 에이전트를 관리하고, 수정하고, 개선할 수 있어요. 새 에이전트는 **관리형 에이전트**로 만드는 것을 권장해요. 에이전트 스튜디오는 기존 흐름 기반 에이전트를 편집하고 유지하는 용도로 계속 쓸 수 있어요. 이 문서에서는 에이전트 스튜디오가 무엇인지, 지금도 무엇을 할 수 있는지, 운영 중인 자동화에 지장 없이 기존 에이전트를 관리하는 방법을 안내해요.

{% hint style="warning" %}
**에이전트 스튜디오**의 흐름 기반 빌더는 새 에이전트를 만드는 용도로는 **관리형 에이전트**로 대체되고 있어요. 기존 흐름 기반 에이전트는 지금처럼 계속 동작하고, 이 에이전트에 이미 연결된 트리거도 계속 실행돼요. 서브 계정에서 기존 흐름 기반 에이전트를 편집, 수정, 관리할 수 있어요. 새 에이전트를 만들 때는 **에이전트 스튜디오**의 **관리형 에이전트**를 이용하세요.
{% endhint %}

## 에이전트 스튜디오란?

에이전트 스튜디오는 시각적 캔버스에서 만든 기존 에이전트가 있는 사용자를 위한 하이퍼클래스의 흐름 기반 AI 에이전트 빌더예요. 자동화를 처음부터 다시 만들지 않고도 에이전트 로직을 관리하고, 노드를 수정하고, 동작을 테스트하고, 버전을 관리하고, 연결된 트리거를 유지할 수 있어요.

새 에이전트는 **관리형 에이전트**에서 만들어야 하지만, 현재 쓰고 있는 흐름 기반 에이전트를 유지하고 개선할 때는 에이전트 스튜디오를 계속 쓰게 돼요.

{% hint style="info" %}
에이전트 스튜디오는 에이전시 관리자/사용자와 서브 계정 관리자/사용자가 사용할 수 있어요.
{% endhint %}

## 에이전트 스튜디오의 주요 장점

- 시각적 흐름 관리: 드래그 앤 드롭 캔버스에서 기존 흐름 기반 에이전트를 수정하고 유지할 수 있어요.
- 유연한 노드 편집: 현재 에이전트 안에서 LLM, API, MCP, 지식 베이스, Web Search(웹 검색) 등 지원되는 노드를 조정할 수 있어요.
- 통제된 업데이트: 변경 사항을 Staging에서 먼저 테스트한 뒤 프로덕션으로 올릴 수 있어요.
- 트리거 유지: 에이전트 로직을 개선하는 동안에도 기존 트리거 기반 자동화가 계속 실행돼요.
- 더 안전한 최적화: 에이전트 전체를 다시 만들지 않고 의사결정 경로, 변수, 출력을 검토하고 다듬을 수 있어요.
- 프로그래밍 방식 접근: 조건을 충족하는 프로덕션 준비 에이전트에서는 지원되는 API 기반 작업을 계속 쓸 수 있어요.

## 드래그 앤 드롭 에이전트 빌더

시각적 빌더를 쓰면 기존 흐름 기반 에이전트가 어떻게 동작하는지, 어디를 고쳐야 하는지 한눈에 파악할 수 있어요. 문제를 찾거나, 응답을 다듬거나, 이미 쓰고 있는 에이전트의 로직을 넓힐 때 특히 편해요.

에이전트 스튜디오 캔버스에서는 다음을 할 수 있어요.

- 기존 에이전트를 시각적으로 열어 확인해요.
- 노드 연결과 의사결정 경로를 따라가며 살펴봐요.
- 프롬프트 로직과 이어지는 액션을 수정해요.
- 기존 에이전트 안에서 지원되는 노드를 추가하거나 고쳐요.
- 에이전트 전체가 어떻게 동작하는지 더 명확하게 확인해요.

## 도구 노드

도구 노드는 에이전트를 데이터, 로직, 외부 액션과 연결해서 에이전트가 할 수 있는 일을 넓혀 줘요. 이 노드를 수정하면 실제 대화 중에 에이전트가 응답하고, 정보를 찾고, 작업을 처리하는 방식을 개선할 수 있어요.

### LLM 노드

LLM 노드는 고급 대규모 언어 모델을 활용해 상황에 맞는 똑똑한 응답을 만들어요. 워크플로우에 맞게 프롬프트, 매개변수, 출력 처리 방식을 설정할 수 있어요.

### MCP 도구 노드

MCP 도구 노드는 Model Context Protocol을 통해 외부 도구를 연동해서 에이전트의 기능을 넓혀 줘요. 외부 데이터 소스에 접근하거나 액션을 실행할 때 유용해요.

### API 도구 노드

API 도구 노드는 API로 데이터를 주고받으며 외부 서비스와 직접 연결돼요. 덕분에 에이전트가 외부 시스템과 유연하게 상호작용할 수 있어요.

### 지식 베이스 도구 노드

에이전트에 지식 베이스를 연결하면 업로드한 문서나 저장된 정보를 바탕으로 응답할 수 있어요. 정확하고 일관된 답변을 하는 데 도움이 돼요.

### Web Search 도구 노드

에이전트가 인터넷에서 최신 정보를 가져오도록 할 수 있어요. 에이전트의 응답을 최신 상태로 유지하고, 관련성과 정확도를 높여 줘요.

## 로직과 흐름 제어

로직과 흐름 제어 기능을 쓰면 에이전트가 복잡한 상황을 처리하고 조건에 따라 판단할 수 있어요.

- 엣지 조건에 따른 분기: 변수 값이나 입력에 따라 서로 다른 경로를 정해요.
- 변수 관리: 전역 변수, 런타임 변수, 입력 변수를 만들어 상황에 맞는 유연한 응답을 만들어요.

## 버전 관리

에이전트 스튜디오는 Draft(초안), Staging(스테이징), **프로덕션** 모드로 구성된 체계적인 수명 주기 관리를 지원해요. 변경 사항을 적용하기 전에 테스트할 수 있어서 운영 중인 에이전트에 문제가 생기는 것을 막아 줘요.

{% hint style="info" %}
에이전트 스튜디오는 버전 관리를 통해 변경 사항이 실제 대화에 영향을 주기 전에 안전하게 테스트할 수 있게 해 줘요.

- **Staging**: 작업 중인 버전이에요. 저장하면 실제 트래픽에 영향 없이 Staging이 업데이트돼요.
- **프로덕션**: 실제 연락처를 대상으로 동작하는 라이브 버전이에요. 프로덕션 버전은 Staging 버전을 승격할 때만 만들어져요.
{% endhint %}

## 에이전트 스튜디오 사용 방법

제대로 설정해 두면 에이전트 스튜디오의 기능을 충분히 활용할 수 있어요. 다음 단계를 따라 시작해 보세요.

1. 하이퍼클래스 대시보드에서 **AI 에이전트** > **에이전트 스튜디오**로 이동하세요.
2. **Flow Agents**(흐름 기반 에이전트)를 클릭해 흐름 기반 에이전트 목록으로 전환하세요.
3. 열고 싶은 기존 흐름 기반 에이전트의 이름을 클릭하세요.

   ![기존 흐름 기반 에이전트 열기](https://jumpshare.com/share/5dR4zt3speKo6Mx4iflj+/GIF+Recording+2026-07-07+at+20.50.25.gif)
4. 워크플로우에 도구 노드(LLM, MCP, API, 지식 베이스, Web Search)를 추가하세요.

   ![도구 노드 추가](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155069612508/original/wSiXh3qQFuAJbkbjBULUNTQTj0FlyWvDkg.gif?1776776712)
5. 노드를 엣지(edge, 노드 사이의 연결선)로 이어서 로직 경로를 정하세요.

   ![노드를 엣지로 연결](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155069612605/original/Sc6xBTNrxbLGbBYv6kNQRP-imNlI6tvpVw.gif?1776776751)
6. 노드 사이에 데이터를 전달하도록 변수를 설정하세요.
7. **Test Tab**(테스트 탭)에서 에이전트의 흐름이 제대로 동작하는지 확인하세요.

   ![테스트 탭에서 에이전트 흐름 확인](https://jumpshare.com/share/dRonbMMHnYYXJjFWuLZ0+/Screen+Shot+2026-07-07+at+20.51.58.png)
8. **저장**을 누른 뒤 **게시**를 눌러 **Staging** 버전을 만들거나 업데이트하세요. 실제로 적용할 준비가 되면 Staging 버전을 **프로덕션**으로 승격하세요.
9. **배포**를 눌러 에이전트를 배포하세요.

   ![에이전트 배포](https://jumpshare.com/share/pxDCISkjAwKnPpnwIsKS+/Screen+Shot+2026-07-07+at+21.00.58.png)

## 자주 묻는 질문

### 에이전트 스튜디오의 흐름 기반 빌더에서 새 에이전트를 만들 수 있나요?
아니요. 새 에이전트는 이제 **관리형 에이전트**에서 만들어요.

### 기존 흐름 기반 에이전트는 어떻게 되나요?
기존 흐름 기반 에이전트는 지금처럼 계속 동작해요. 서브 계정에서 편집, 수정, 관리할 수 있어요.

### 기존 에이전트 스튜디오 트리거는 계속 동작하나요?
네. 현재 흐름 기반 에이전트에 연결된 기존 트리거는 계속 실행돼요.

### 기존 에이전트 안의 노드와 로직도 계속 편집할 수 있나요?
네. 에이전트 스튜디오에서 기존 흐름 기반 에이전트의 노드, 로직 경로, 변수, 관련 설정을 계속 편집하고 관리할 수 있어요.

### 앞으로 새 에이전트는 어디에서 만들어야 하나요?
모든 새 에이전트는 **관리형 에이전트**에서 만드세요.

### 기존 에이전트도 에이전트 스튜디오에서 테스트와 버전 관리를 할 수 있나요?
네. 기존 흐름 기반 에이전트도 제공되는 버전 관리 절차에 따라 테스트하고, 수정하고, 승격할 수 있어요.

### 기존 흐름 기반 에이전트를 지금 바로 모두 관리형 에이전트로 옮겨야 하나요?
기존 에이전트는 지금처럼 계속 동작해요. 새 에이전트는 **관리형 에이전트**로 만들고, 현재 흐름 기반 에이전트는 팀에서 따로 정한 이전 계획이 없다면 에이전트 스튜디오에서 계속 관리하세요.
