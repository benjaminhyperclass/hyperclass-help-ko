# 웹 통화로 음성 AI 에이전트 테스트하기

**웹 통화**를 쓰면 전화번호를 사거나 배정하지 않아도 브라우저에서 바로 하이퍼클래스의 음성 AI 에이전트를 테스트할 수 있어요. 설정 초반에 프롬프트, 대화 흐름, 지원되는 액션, 에이전트의 답변을 미리 확인할 수 있어요. 실제 전화번호로 통화하기 전에 음성 AI의 동작을 먼저 테스트하고 다듬을 수 있어요.

## 웹 통화란?

웹 통화는 하이퍼클래스에서 음성 AI 에이전트를 브라우저로 테스트하는 방법이에요. 일반 전화를 거는 대신 컴퓨터 마이크와 브라우저 오디오로 에이전트와 대화해요.

웹 통화는 테스트와 확인을 위한 기능이에요. 에이전트를 실제 고객 통화에 연결하기 전에 다음을 확인할 수 있어요.

- 에이전트가 어떻게 응답하는지
- 프롬프트를 잘 따르는지
- 지원되는 액션을 어떻게 처리하는지
- 대화 흐름을 어떻게 이끄는지

## 웹 통화의 장점

웹 통화를 쓰면 전화번호를 구매하거나 실제 통신 환경을 확인하기 전에 음성 AI 에이전트를 테스트할 수 있어요. 초기 테스트를 실제 운영과 분리한 채로 설정을 더 빠르게 진행할 수 있어요.

- 전화번호가 필요 없어요: 전화번호를 먼저 구매하거나 배정하지 않아도 음성 AI 에이전트를 테스트할 수 있어요.
- 빠르게 확인할 수 있어요: 브라우저에서 바로 체험 통화를 시작해, 실제 대화에서 에이전트가 어떻게 응답하는지 볼 수 있어요.
- 대부분의 테스트를 할 수 있어요: 프롬프트, 통화 흐름, 액션을 테스트할 수 있어요. 단, 통화 전환은 제외돼요.
- 설정할 때 유용해요: 새 음성 AI 에이전트를 만드는 중에, 전화 기반 통화를 확정하기 전에 먼저 테스트해 볼 수 있어요.
- 결과를 바로 확인할 수 있어요: 테스트가 끝나면 로그, 대화 내용(스크립트), 녹음을 보면서 에이전트를 개선할 수 있어요.

## 웹 통화와 전화 통화 테스트 비교

**웹 통화**와 **전화 통화** 테스트는 목적이 달라요. 실제 고객이 전화하기 전에 확인하려는 부분에 맞는 방법을 고르세요.

**웹 통화**는 이럴 때 좋아요.

- 전화번호 없이 브라우저에서 테스트할 때
- 프롬프트 동작과 대화 흐름을 확인할 때
- 인사말, 응답, 지원되는 설정 액션을 확인할 때
- 전화 설정을 마치기 전에 초기 테스트를 할 때
- 실제 전화 환경에서 확인하기 전에 에이전트 프롬프트를 다듬을 때

**전화 통화**는 이럴 때 좋아요.

- 실제 전화번호 기반 동작을 테스트할 때
- 배정된 전화번호를 확인할 때
- 수신 통화 라우팅을 확인할 때
- 실제 운영과 비슷한 통화 처리를 테스트할 때
- 통화 전환 경로와 실제 통신 동작을 확인할 때

웹 통화가 전화 기반 테스트를 완전히 대신하지는 않아요. 음성 AI 에이전트를 실제 고객 통화에 쓰기 전에, 고객이 사용할 전화번호 설정으로 에이전트를 테스트하세요.

## 권한 및 브라우저 요건

웹 통화는 사용자 권한, 브라우저 오디오, 마이크 권한이 있어야 해요. 테스트 전에 아래 요건을 확인하면 연결 문제, 소리가 나지 않는 문제, 브라우저 통화 실패를 줄일 수 있어요.

웹 통화를 사용하려면 다음이 필요해요.

- 음성 AI 에이전트 테스트 영역에 접근할 수 있는 권한이 있어야 해요.
- 하이퍼클래스에 음성 AI 에이전트가 이미 만들어져 있어야 해요.
- 브라우저에서 마이크 접근을 허용해야 해요.
- 기기 차원의 마이크 권한도 켜야 할 수 있어요.
- 작동하는 마이크가 있어야 해요.
- 다른 앱이 마이크를 쓰고 있으면 웹 통화에 방해가 될 수 있어요.
- 최상의 환경을 위해 지원되는 최신 브라우저를 사용하세요.

마이크 권한이 차단돼 있으면 웹 통화가 시작되지 않거나, 에이전트가 사용자의 음성을 인식하지 못할 수 있어요.

## 웹 통화는 어떻게 작동하나요?

테스트할 때 웹 통화가 어떻게 동작하는지 알면 결과를 더 정확하게 해석할 수 있어요. 하이퍼클래스가 발신자를 어떻게 구분하는지, 어떤 기능이 지원되는지, 통화가 끝난 뒤 테스트 기록이 어디에 남는지 알아 두세요.

- 웹 통화는 음성 AI 에이전트의 테스트 방법으로, 브라우저에서 바로 실행돼요.
- 체험 통화 중에는 로그인한 사용자의 연락처가 발신자 연락처로 자동 사용돼요.
- 대부분의 에이전트 액션을 웹 통화로 테스트할 수 있어요.
- 웹 통화 체험 중에는 통화 전환이 지원되지 않아요.
- 테스트 통화는 나중에 음성 AI 로그에서 대화 내용과 녹음까지 확인할 수 있어요.
- 테스트 통화는 대시보드 분석이나 성과 지표에 포함되지 않아요.

## 지원되는 기능과 현재 제한 사항

웹 통화로 할 수 있는 것과 할 수 없는 것을 알아 두면 알맞은 테스트 방법을 고를 수 있어요. 브라우저 테스트는 빠르게 반복해서 확인하기에 좋지만, 통신과 관련된 일부 동작은 전화로 테스트해야 해요.

### 웹 통화에서 지원되는 기능

웹 통화는 음성 AI 테스트 환경을 최대한 비슷하게 따라가도록 만들어졌어요. 추가 설정 없이 프롬프트, 응답, 전반적인 통화 처리를 확인할 수 있어요.

- 프롬프트 테스트
- 대화 흐름 테스트
- 지원되는 에이전트 동작에 대한 액션 테스트
- 에이전트를 만들고 최적화하는 동안의 빠른 반복 테스트
- 테스트가 끝난 뒤 대화 내용 확인과 로그 열람

### 웹 통화에서 지원되지 않는 기능

일부 기능은 브라우저 기반 체험에서 쓸 수 없는 통신 동작에 의존해요. 그래서 웹 통화는 빠른 테스트용이고, 전체 전화 경로를 확인하려면 **전화 통화** 테스트가 필요해요.

- 웹 통화 체험에서는 통화 전환이 지원되지 않아요.

## 웹 통화 설정하기

설정을 제대로 해 두면 브라우저 테스트에 에이전트의 최신 프롬프트와 구성이 반영돼요. 체험을 시작하기 전에 음성 AI 에이전트를 만들어 두고, 브라우저에서 마이크에 접근할 수 있는지 확인하세요.

1. 하이퍼클래스에서 **AI 직원 > 음성 AI**로 이동하세요.
2. 테스트할 음성 AI 에이전트를 여세요.
3. 에이전트의 테스트 영역을 찾으세요. 하이퍼클래스에서는 **전화 통화**와 **웹 통화** 두 가지 테스트 방법을 쓸 수 있어요.
4. **웹 통화**를 선택하세요. **전화 통화** 테스트와 달리 전화번호를 입력하지 않아도 돼요.

   ![웹 통화 선택 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155067507960/original/IBTs_8k_ouDSK7CoEalGbFsSKHhgRJY_-Q.jpeg?1774275081)

5. 브라우저에서 마이크 접근을 요청하면 허용하세요.
6. 음성 AI 에이전트와 대화하면서 확인하고 싶은 프롬프트, 응답, 액션을 테스트하세요.
7. 통화가 끝나면 음성 AI 로그에서 테스트 결과를 열어 대화 내용과 녹음을 확인하세요.

## 웹 통화 테스트 결과 확인하기

테스트 결과에서 빨리 배우고 에이전트를 개선할 수 있어야 테스트가 쓸모 있어요. 하이퍼클래스는 테스트 통화 내용을 음성 AI 대시보드 로그에 남겨 두기 때문에, 실제 운영 분석에 영향을 주지 않고 대화를 확인할 수 있어요.

- **음성 AI > Dashboard Logs**(대시보드 로그)로 이동해 테스트 통화 기록을 확인하세요.
- 필요하면 **Call Type**(통화 유형) 필터로 **테스트 통화**만 골라 볼 수 있어요.
- 로그 항목을 열어 녹음과 대화 내용을 확인하세요.
- 테스트 통화는 로그에는 보이지만 대시보드 분석과 성과 리포팅에는 포함되지 않아요.

## 자주 묻는 질문

### 웹 통화를 쓰려면 전화번호를 사야 하나요?
아니요. 웹 통화를 쓰면 전화번호를 구매, 배정, 프로비저닝하지 않아도 브라우저에서 음성 AI 에이전트를 테스트할 수 있어요.

### 웹 통화를 실제 고객 통화에 쓸 수 있나요?
아니요. 웹 통화는 하이퍼클래스 안에서 테스트하기 위한 기능이에요. 실제 고객 통화에는 전화번호 기반 설정을 사용하세요.

### 웹 통화로 실제 전화 라우팅을 테스트할 수 있나요?
아니요. 웹 통화로는 실제 전화번호 라우팅, 배정된 번호의 동작, 전체 운영 통신 경로를 확인할 수 없어요.

### 웹 통화로 통화 전환도 테스트할 수 있나요?
<!-- 검토 필요: 원문 내용이 서로 다름 -->
웹 통화는 체험 중 통화 전환 동작 전체를 확인하기 위한 기능이 아니에요. 전환 경로와 실제 통신 동작은 **전화 통화** 테스트로 확인하세요.

### 웹 통화 테스트가 로그에 표시되나요?
네, 웹 통화 테스트는 대화 내용, 녹음, 통화 동작 같은 세부 정보와 함께 음성 AI 로그에 표시될 수 있어요.

### 웹 통화 테스트가 대시보드 분석에 영향을 주나요?
아니요. 웹 통화 테스트 통화는 대시보드 분석이나 실제 성과 지표에 포함되지 않아요.

### 웹 통화 테스트에서는 어떤 연락처가 사용되나요?
웹 통화에서는 로그인한 사용자의 연락처가 발신자 연락처로 사용될 수 있어요. 그래서 실제 외부 발신자와는 맥락이 다를 수 있어요.

### 마이크가 작동하지 않아요.
브라우저나 기기에서 마이크 접근이 차단됐거나, 다른 마이크가 선택됐거나, 다른 앱이 마이크를 쓰고 있을 수 있어요.

### 실제로 운영하기 전에도 전화번호로 다시 테스트해야 하나요?
네. 웹 통화는 초기 테스트에 유용하지만, 음성 AI 에이전트로 실제 고객 통화를 받기 전에는 전화번호 기반 테스트를 권장해요.

### 에이전트 설정을 다 끝내기 전에도 웹 통화를 쓸 수 있나요?
설정하는 중에도 웹 통화를 쓸 수 있어요. 다만 테스트에는 에이전트의 현재 프롬프트, 인사말, 목표, 도구, 저장된 구성만 반영돼요.
