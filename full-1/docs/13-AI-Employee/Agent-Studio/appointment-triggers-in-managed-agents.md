# 관리형 에이전트의 예약 트리거

고객이 예약하거나, 예약을 확정·취소하거나, 예약에 나타나지 않았을 때 AI 에이전트가 자동으로 반응하도록 **에이전트 스튜디오**에서 예약 트리거를 설정하는 방법을 안내해요. 예약, 확정, 취소, 불참 같은 일정 이벤트가 생기면 **관리형 에이전트**(Managed Agents, 이전 명칭 Super Agents)가 바로 시작해서 맞춤 메시지를 보낼 수 있어요.

이 문서에서는 두 가지 트리거 유형, 캘린더·상태 필터, 비주얼 빌더와 **Builder Chat**(빌더 채팅)으로 설정하는 방법을 다뤄요.

## 관리형 에이전트 예약 트리거란?

예약 트리거는 하이퍼클래스 캘린더에서 특정 예약 이벤트가 생길 때 **관리형 에이전트**를 시작하는 조건이에요. 채팅, 폼 제출, 태그 변경에만 반응하는 것이 아니라, 예약이 만들어지거나 예약 상태가 바뀌는 순간 에이전트가 실행돼요. 구매 의사가 높은 연락처에게 적절한 때 안내를 보낼 수 있어요.

이 트리거는 **에이전트 스튜디오**에 이미 있는 실시간 이벤트 방식 그대로 **시작 트리거**에 설정해요. 관리형 에이전트의 시작 노드에 예약 트리거를 연결하면, 에이전트는 캘린더와 상태 같은 예약 정보를 이벤트 데이터로 함께 받아요. 프롬프트와 흐름 로직에서 이 정보를 활용해 연락처에 맞는 응답을 만들 수 있어요.

관리형 에이전트의 시작 조건으로 쓸 수 있는 예약 이벤트는 두 가지예요.

- **Customer Booked Appointment**(고객 예약 완료): 선택한 캘린더에 새 예약이 정상적으로 만들어질 때마다 실행돼요.
- **Appointment Status Changed**(예약 상태 변경): 기존 예약의 상태가 **Confirmed**(확정), **Cancelled**(취소됨), **Showed**(참석), **No Show**(불참), **Rescheduled**(일정 변경) 등으로 바뀔 때마다 실행돼요.

트리거마다 캘린더와 예약 상태를 지정할 수 있어서, 에이전트가 언제 시작할지 세밀하게 정할 수 있어요.

## 주요 장점

예약 트리거를 쓰면 일정 관리 흐름 곳곳을 자동화할 수 있어요. 수작업을 늘리지 않고도 더 빠르게 대응하고, 맞춤 응대를 넓혀 갈 수 있어요.

- 실시간 예약 대응: 고객이 예약하거나, 확정하거나, 취소하거나, 불참했을 때 에이전트가 자동으로 시작해요. 늦게 도는 워크플로우나 수동 후속 연락에 의존하지 않아도 돼요.
- 반응이 가장 좋은 타이밍: 예약 직후, 예약 변경 직후, 불참 직후처럼 연락처의 관심이 높은 순간에 AI 대화를 시작해요. 응답률과 참석률을 크게 높이는 데 도움이 돼요.
- 캘린더와 상태별 정밀 타기팅: 영업 통화, 상담, 서비스 예약 같은 특정 캘린더로 트리거를 제한하고, 필요하면 상태로도 걸러서 불필요한 실행을 막아요.
- 일관되고 재사용 가능한 로직: 예약 관련 로직을 관리형 에이전트 안에 모아 두면, 확정·리마인더·재참여 캠페인 흐름을 여러 캘린더에서 똑같이 쓸 수 있어요.
- 수작업 감소: 수동 연락과 그때그때 보내던 리마인더 대신, 에이전트가 확정, 자주 묻는 질문, 일정 변경 안내, 후속 제안을 처리해요.
- 기존 에이전트 스튜디오 구조 활용: 예약 트리거는 폼, 태그, 채팅 이벤트와 같은 시작 트리거 구조를 써요. 익숙한 테스트, 검증, 게시 흐름을 그대로 쓸 수 있어요.

## 예약 트리거 유형

예약 트리거는 캘린더에서 일어나는 일만 기준으로 관리형 에이전트의 시작 시점을 정해요. 즉시 확정 안내, 상담 전 안내, 불참 후 회복 같은 목적에 맞게 두 유형 중 하나를 고르세요.

### 트리거 유형 1: Customer Booked Appointment (`appointment_booked`)

- 선택한 캘린더에 새 예약이 정상적으로 만들어질 때마다 실행돼요.
- 확정 정보, 예약 전 안내, 사전 확인 질문을 보낼 때 좋아요.
- 특정 캘린더로 제한할 수 있어요(예: "영업 전략 상담", "온보딩 통화", "치아 스케일링").

### 트리거 유형 2: Appointment Status Changed (`appointment_status`)

- 기존 예약의 상태가 바뀔 때마다 실행돼요(예: **Confirmed**, **Cancelled**, **Showed**, **No Show**, **Rescheduled**).
- 결과에 따라 달라지는 흐름에 유용해요.
  - 상태가 **Showed**가 되면 "참석해 주셔서 감사합니다" 메시지를 보내요.
  - 상태가 **No Show** 또는 **Cancelled**가 되면 재참여 또는 재예약 캠페인을 시작해요.
  - 상태가 **Confirmed**로 바뀌면 리마인더나 찾아오는 길을 안내해요.

## 상세 필터

**상세 필터**를 쓰면 예약 이벤트가 워크플로우에 정말 중요할 때만 관리형 에이전트가 실행돼요. 불필요한 실행이 줄어서 AI 사용량을 아끼고, 가치가 큰 상황에 자동화를 집중할 수 있어요.

### 필터 1: 캘린더 (필수)

- 트리거를 저장하기 전에 캘린더를 하나 이상 선택해야 해요.
- 관리형 에이전트는 선택한 캘린더에서 이벤트가 생길 때만 실행돼요.
- 자주 쓰는 방식은 다음과 같아요.
  - 내부용·관리용 캘린더는 빼고 영업이나 상담 캘린더에서만 트리거해요.
  - 서비스 종류별로 흐름을 나눠요(예: 코칭, 치아 스케일링, 냉난방 서비스).

### 필터 2: 예약 상태 (선택)

- `appointment_status` 트리거에서는 **Confirmed**, **Cancelled**, **Showed**, **No Show**, **Rescheduled** 같은 특정 상태로 실행 조건을 좁힐 수 있어요.
- **예약 상태**를 비워 두면, 선택한 캘린더의 예약에서 상태가 바뀔 때마다 관리형 에이전트가 실행돼요.

### 활용 예시

- 잠재 고객이 영업 통화를 확정했을 때만 에이전트를 실행해서 준비 안내 이메일을 보내거나 추가 정보를 받아요.
- 서비스 예약이 취소되거나 **No Show**로 바뀌면 에이전트를 실행해서 재예약을 제안해요.
- 내부 캘린더에서 어떤 상태든 바뀔 때 에이전트를 실행해서 내부 알림이나 리포트 업데이트를 보내요.

## 비주얼 빌더에서 트리거 설정하기

관리형 에이전트의 비주얼 빌더에서는 캔버스 화면에서 몇 번의 클릭으로 예약 트리거를 설정할 수 있어요. 에이전트가 언제, 어떻게 시작할지 눈으로 보면서 정하고 싶을 때 알맞아요. 폼, 태그, 채팅용으로 이미 쓰던 **에이전트 스튜디오** 트리거 설정과 같은 방식이에요.

비주얼 빌더를 쓰면 다음과 같아요.

- 예약 트리거를 관리형 에이전트의 **Start** 노드에 직접 연결해요.
- 트리거 패널 안에서 캘린더와 상태를 바로 설정해요.
- 저장하기 전에 필수 항목(예: 캘린더 한 개 이상)이 채워졌는지 자동으로 검증해요.

설정 순서는 다음과 같아요.

1. 비주얼 빌더에서 관리형 에이전트를 열어요.
2. 캔버스에서 **시작 트리거** 노드를 찾거나 새로 추가해요.
3. **트리거 유형**에서 **Customer Booked Appointment** 또는 **Appointment Status Changed**를 선택해요.
4. 캘린더 드롭다운에서 캘린더를 하나 이상 선택해요.
5. (선택) `appointment_status` 트리거라면 상태를 하나 이상 선택해요. 비워 두면 모든 상태 변경에 트리거돼요.
6. 저장하고 테스트한 뒤 에이전트를 게시해요. 그러면 실제 예약 이벤트가 생길 때 흐름이 시작돼요.

## Builder Chat으로 트리거 설정하기

**Builder Chat**(빌더 채팅)에서는 원하는 자동화를 일상 언어로 설명하면 시스템이 그에 맞는 트리거 설정을 만들어 줘요. 에이전트가 무엇을 해야 하는지는 알지만 설정을 하나하나 클릭하고 싶지 않을 때 편리해요.

**Builder Chat**에는 이렇게 입력할 수 있어요.

- "누군가 영업 캘린더에서 상담을 예약하면 이 에이전트를 시작해 줘."
- "치아 스케일링 예약이 No Show로 표시되면 이 에이전트를 실행해 줘."

빌더는 다음을 자동으로 해요.

- 알맞은 예약 트리거 유형(`appointment_booked` 또는 `appointment_status`)을 고르고,
- 트리거를 알맞은 관리형 에이전트에 연결하고,
- 설명한 내용에 맞춰 캘린더와 상태 필터를 설정해요.

설정이 끝난 뒤에도 비주얼 빌더를 열어서 다음 작업을 할 수 있어요.

- 채팅 빌더가 설정한 캘린더와 상태가 맞는지 확인해요.
- 필터, 프롬프트, 이후 노드를 조정해요.
- 실제로 운영하기 전에 **에이전트 스튜디오**의 기본 테스트 도구로 테스트해요.

## 활동 피드의 예약 이벤트

예약 이벤트로 시작된 관리형 에이전트 실행은 활동 피드에 눈에 띄게 표시돼요. 에이전트가 왜 시작됐고 어떤 예약에 반응했는지 쉽게 알 수 있어요. **에이전트 로그**나 하이퍼클래스의 다른 분석 도구와 함께 쓰면 특히 유용해요.

예약으로 실행된 기록에는 다음이 표시돼요.

- 전용 캘린더 아이콘: 예약으로 시작된 실행을 다른 이벤트 유형과 한눈에 구분할 수 있어요.
- **예약** 이벤트 태그: 채팅, 폼, 태그 변경이 아니라 예약 이벤트로 에이전트가 시작됐다는 것을 바로 알 수 있어요.
- 이벤트 메타데이터: 예약이 속한 캘린더와 에이전트가 시작된 시점의 상태(예: **Confirmed**, **Cancelled**, **No Show**)를 볼 수 있어요.

이 정보로 다음을 할 수 있어요.

- 특정 연락처가 왜 메시지를 받았는지 원인을 확인해요.
- 캘린더와 상태 필터가 의도대로 작동하는지 확인해요.
- **에이전트 로그**와 다른 리포팅 기능으로 불참 회복 흐름이 얼마나 자주 실행되는지 같은 패턴을 살펴봐요.

## 예약 트리거 설정 순서

올바르게 설정하면 관리형 에이전트가 알맞은 예약 이벤트에서 안정적으로 시작하고, 실제 고객에게 영향을 주기 전에 안전하게 테스트할 수 있어요. 아래 단계는 하이퍼클래스 **에이전트 스튜디오**의 기존 트리거 구조를 활용해 처음 설정부터 운영 적용까지 진행하는 순서예요.

### 1단계. 캘린더와 예약 유형 준비하기

- 사용할 캘린더가 서브 계정에 만들어져 있고 활성 상태인지 확인해요.
- 에이전트가 이 설정을 바탕으로 동작하니, 예약 유형, 시간대, 가용 시간이 올바른지 확인해요.
- 필요하면 용도별로 캘린더를 따로 만들어요(예: "영업 데모", "온보딩 통화", "VIP 상담"). 그래야 트리거를 정확하게 지정할 수 있어요.

### 2단계. 관리형 에이전트 열기 또는 만들기

- **AI 에이전트 > 에이전트 스튜디오**로 이동해서 개선하려는 관리형 에이전트를 열어요.
- 새 에이전트를 만든다면 최소한 핵심 흐름을 설계해요. 인사 또는 확정 메시지, 물어볼 질문(예: 자격 확인이나 예약 전 체크리스트), 메모·태그·내부 알림 같은 후속 작업이 핵심 흐름에 들어가요.

  ![에이전트 스튜디오에서 관리형 에이전트를 연 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155077214758/original/-WPvdzWbLujPTlUduzGd3QRwblQIZRCMiw.png?1785403184)

### 3단계. 예약 시작 트리거 추가하기

캔버스에서 **Start** 노드를 찾아요. 없으면 **시작 트리거** 노드를 추가해요.

**트리거 유형**에서 용도에 맞게 **Customer Booked Appointment** 또는 **Appointment Status Changed**를 선택해요.

- 예약 직후의 확정 안내와 육성에는 **Customer Booked Appointment**를 써요.
- 이벤트 이후나 상태별 흐름(예: **No Show** 회복)에는 **Appointment Status Changed**를 써요.

  ![시작 트리거에서 예약 트리거 유형을 선택하는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155077214927/original/NYiLdhIOWFYhvclT-EJm6rwAnxepu6PesA.png?1785403311)

### 4단계. 캘린더와 상태 설정하기

- 트리거 설정에서 이 관리형 에이전트를 실행할 캘린더를 하나 이상 선택해요.
- **Appointment Status Changed**를 선택했다면 에이전트를 시작할 상태만 선택해요(예: **No Show**, **Cancelled**). 상태 목록을 비워 두면 선택한 캘린더의 모든 상태 변경에서 에이전트가 실행돼요.
- 트리거 설정을 저장하고 검증을 통과하는지 확인해요(예: 캘린더를 최소 한 개 선택해야 해요).

  ![캘린더와 예약 상태를 설정하고 저장하는 트리거 설정 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155077215065/original/MyQ9Qbx8770lzmVFyomGNol8rULs94jbcQ.png?1785403380)

### 5단계. 에이전트 안에 예약 정보를 활용하는 로직 만들기

프롬프트와 메시지에 예약 정보를 반영해요. 예를 들어 예약 날짜와 시간, 예약 유형이나 서비스, 상태(**Confirmed**, **Cancelled**, **No Show** 등)를 넣을 수 있어요.

필요한 노드를 추가해요.

- 연락처에 태그를 추가해요(예: "상담 예약 완료", "불참 회복 메시지 발송").
- SMS나 이메일 리마인더를 보내요.
- 내부 팀원에게 알려요.

### 6단계. 운영 전에 테스트하기

**에이전트 스튜디오**의 테스트 도구로 예약 이벤트를 시뮬레이션해요. 알맞은 트리거가 실행되는지, 에이전트가 예상한 예약 데이터를 받는지, 메시지와 작업이 의도대로 동작하는지 확인해요.

원하면 테스트용 캘린더와 테스트용 연락처를 만들어서 실제 고객에게 트리거가 가지 않게 할 수 있어요.

활동 피드와 **에이전트 로그**에서 예약 아이콘, 이벤트 태그, 메타데이터가 올바르게 보이는지 확인해요.

### 7단계. 게시하고 모니터링하기

테스트를 통과하면 관리형 에이전트를 게시해요. 그러면 서브 계정에서 예약 트리거가 활성화돼요.

처음 실행되는 기록을 살펴봐요.

- 의도한 캘린더와 상태에서만 에이전트가 시작되는지 확인해요.
- 기존 리포팅 도구로 참석률, 응답률, 회복률 같은 성과 지표를 살펴봐요.
- 실제 동작을 보면서 프롬프트, 필터, 로직을 계속 다듬어요.

{% hint style="info" %}
팁: 영업 데모나 신규 고객 상담처럼 가치가 큰 캘린더 하나로 시작해서 트리거 로직을 검증해 보세요. 에이전트가 예상대로 동작하는 것을 확인한 뒤 캘린더와 상태를 늘려 가세요.
{% endhint %}
