# 에이전트 스튜디오에서 액션 플랫폼 사용하기

액션 플랫폼은 **에이전트 스튜디오**(Agent Studio)와 CRM을 직접 연결해 줘요. AI 에이전트가 질문에 답하는 데서 그치지 않고, 메시지 보내기·연락처 태그 지정·필드 업데이트 같은 작업까지 직접 실행할 수 있어요. 이 문서에서는 액션 플랫폼이 무엇인지, 왜 쓰는지, 자동화에서 안전하게 쓰려면 어떻게 시작하는지 알려 드려요.

## 액션 플랫폼이란?

액션 플랫폼은 에이전트 스튜디오의 에이전트가 실시간으로 호출할 수 있는 CRM 기본 액션 모음이에요. 별도 코드나 외부 연동 없이도 AI가 기록을 업데이트하고, 메시지를 보내고, 내부 워크플로우를 실행할 수 있어요.

예전에는 AI가 리드와 대화만 했다면, 액션 플랫폼을 쓰면 에이전트가 결과까지 만들어 내는 디지털 비서가 돼요. 후속 SMS를 보내고, 태그를 지정하고, 필드를 만들고, 팀에 알리는 일을 모두 같은 에이전트 스튜디오 캔버스 안에서 처리해요. 에이전트 스튜디오는 이미 노드 기반의 시각적 빌더로 이벤트에 반응하고, 대화를 분기하고, 도구에 연결하는 AI 에이전트를 만들 수 있게 해 줘요. 액션 플랫폼은 여기에 CRM 쪽 작업을 표준 방식으로 실행하는 기능을 더해요. 에이전트 스튜디오 자체가 처음이라면 [에이전트 스튜디오 개요](how-to-setup-flow-agents-in-agent-studio.md)를 먼저 읽어 보세요.

## 액션 플랫폼의 주요 장점

액션 플랫폼은 AI 기반 워크플로우를 더 강력하고, 일관되고, 관리하기 쉽게 만들어 줘요.

- 실시간 CRM 업데이트: 누군가 폼을 제출하거나, 채팅을 보내거나, 워크플로우를 실행하는 즉시 에이전트가 연락처에 태그를 지정하고, 필드를 만들고, 활동을 기록해요. 폴링 스크립트나 수동 업데이트가 필요 없어요.
- 더 똑똑한 후속 연락과 육성: 에이전트가 SMS와 이메일을 직접 보내면, 방금 AI가 나눈 대화를 반영한 메시지로 관심도 높은 리드에게 바로 응답할 수 있어요.
- 별도 연결 작업 감소: 예전에는 API 호출이나 복잡한 워크플로우 조합이 필요했던 많은 사례를, 판단과 실행을 함께 하는 에이전트 하나가 기본 액션으로 처리할 수 있어요.
- 일관된 데이터 관리: 에이전트가 태그, 커스텀 필드, 커스텀 값을 정해진 방식으로 만들고 업데이트해요. 그래서 리포팅과 세분화가 오랫동안 깔끔하게 유지돼요.
- 화이트라벨에 적합: 액션은 CRM 내부에서 보이지 않게 실행돼요. 에이전시는 고객에게 하이퍼클래스 고유 브랜딩을 노출하지 않고도, 의미 있는 작업을 수행하는 "AI 직원"을 제공할 수 있어요.
- 에이전틱 AI에 맞춤: 에이전트 스튜디오의 노드(**AI Agent**(AI 에이전트), **Sequential**(순차 실행), **Router**(라우터) 등)와 함께 쓰면, 다음에 할 일을 스스로 정하고 끝까지 실행하는 "에이전틱" 플로우를 만들 수 있어요.

## 기본 제공 CRM 액션

액션 플랫폼에는 가장 흔한 CRM 작업을 다루는, 화이트라벨에 적합한 액션이 미리 준비되어 있어요. 에이전트가 데이터를 안전하고 예측 가능하게 다루도록, 에이전트 스튜디오 안에서 빠르게 설정할 수 있게 만들어졌어요.

보통은 액션을 실행할 수 있는 노드(예: 에이전틱 노드나 순차 실행 노드)에서 이 액션을 써요. 에이전트가 수행할 CRM 작업을 고르고, 대화에서 나온 변수를 연결하면 돼요.

주로 쓰는 액션은 다음과 같아요.

#### SMS 전송

에이전트가 현재 연락처에게 SMS를 보내요. 이미 설정해 둔 하이퍼클래스 전화나 Twilio를 그대로 써요. 폼 제출이나 채팅 뒤에 즉시 확인 메시지, 알림, 후속 메시지를 보낼 때 알맞아요. SMS 사용량은 기존 **전화 시스템** 요금과 **A2P 규정 준수** 규칙을 그대로 따라요.

예: “예약해 주셔서 감사합니다, `{first_name}`님! 확인 링크는 `{calendar_link}` 입니다.”

#### 이메일 보내기(템플릿 사용 가능)

에이전트 안에서 거래성 이메일이나 육성용 이메일을 보내요. 기존 이메일 템플릿을 쓸 수도 있어요. 브랜딩과 레이아웃은 그대로 유지하고, AI는 변수를 사용해 제목이나 본문 일부만 맞춤으로 바꿔 줘요.

#### 연락처에 태그 지정

대화 결과에 따라 “핫 리드”, “후속 연락 필요”, “데모 요청” 같은 태그를 지정해요. 그러면 다른 워크플로우, 파이프라인, 리포트가 그 태그에 맞게 반응할 수 있어요.

#### CRM에 새 태그 만들기

필요할 때 에이전트가 새 태그를 만들게 할 수 있어요. 이 동작은 사용자가 켠 경우에만 해당해요. 에이전트를 만들 때는 없던 아주 구체적인 캠페인 태그나 주제 태그가 필요한 전략에 도움이 돼요.

#### 커스텀 필드와 커스텀 값 만들기

AI 대화 중에 나온 정보를 “선호 상품”, “예산 범위”, “온보딩 단계” 같은 커스텀 필드로 저장해요. 에이전트 스튜디오는 이미 그래프 전체에서 변수와 커스텀 값을 다룰 수 있어요. 액션 플랫폼을 쓰면 이런 값을 CRM에 남는 데이터로 바꿀 수 있어요.

#### 내부 알림 보내기

가치가 높은 이벤트가 생기면 내부 알림으로 팀원에게 알려요. 예를 들어 리드가 영업팀과 이야기하고 싶다고 하거나, VIP 연락처가 특정 폼을 제출했을 때예요. 담당자가 꼭 필요한 순간에 개입할 수 있어요.

#### 블로그, Facebook 게시글 같은 콘텐츠 생성

AI의 콘텐츠 생성 기능을 반복 가능한 프로세스에 활용해요. 블로그 글, 소셜 미디어 캡션, 광고 문구의 초안을 만든 다음 커스텀 필드에 저장하거나, 검토용으로 팀 받은편지함에 보내거나, 본인이나 고객에게 이메일로 보내요.

## 에이전틱 노드와 의사 결정

에이전틱 AI는 질문에 답하는 데서 끝나지 않아요. 다음에 할 일을 정하고, 필요한 단계를 직접 실행해요. 에이전트 스튜디오는 이런 자동화에 필요한 구성 요소를 제공해요. AI Agent 노드, 라우터, 여러 단계를 순서대로 실행하는 노드가 여기에 속해요.

이 노드들 안에서 액션 플랫폼을 쓰면 이렇게 동작해요.

- AI 노드가 사용자의 의도나 맥락을 파악해요.
- 라우터와 다른 로직 도구가 알맞은 분기를 골라요.
- 액션을 실행할 수 있는 노드가 필요한 CRM 액션을 그대로 실행해요.
- 이 패턴으로 다음과 같은 탄탄한 플로우를 만들 수 있어요.
- 리드가 구매 의향이 높다고 표현하면 태그를 지정하고, 즉시 SMS와 캘린더 링크를 보내요.
- 고객이 환불을 요청하면 지원팀에 알리고, 리포팅을 위해 “환불 요청” 태그를 지정해요.
- 누군가 가격을 물으면 채팅에서 물어본 내용을 요약한 맞춤 후속 이메일을 만들어요.

라우터에 대한 자세한 내용은 [에이전트 스튜디오에서 AI 라우팅으로 대화 플로우 설계하기](../agent-studio-router-tool-ai-conditional-router.md)를 참고하세요.

## 순차 노드와 구조화된 워크플로우

에이전트 스튜디오의 **Sequential**(순차 실행) 노드를 쓰면, 정해진 순서대로 실행해야 하는 여러 단계를 하나로 묶을 수 있어요. 온보딩, 자격 확인, 여러 단계의 후속 연락처럼 반복하는 작은 워크플로우에 잘 맞아요.

액션 플랫폼과 함께 쓰면 순차 플로우로 이런 일을 할 수 있어요.

- CRM 액션을 연달아 실행해요(예: 커스텀 필드 설정 → 연락처 태그 지정 → 이메일 보내기).
- AI 기반 라우팅 같은 판단 단계와 SMS, 내부 알림 같은 구체적인 액션을 섞어 써요.
- "액션 순서"가 끝나면 메인 대화 플로우로 돌아가요. 순차 실행 노드가 라우팅 및 다른 도구와 연동되기 때문이에요.

사용 예시는 다음과 같아요.

**새 리드 시퀀스**

1. 연락처 기록을 만들거나 업데이트해요.
2. “새 리드” 태그를 지정해요.
3. SMS 확인 메시지를 보내요.
4. 예산이나 관심 수준이 기준을 넘으면 내부 알림을 보내요.

**지원 후 후속 연락**

1. 사용자에게 만족도를 물어요.
2. 만족도가 낮으면 담당자에게 연결하고 에스컬레이션 태그를 지정해요.
3. 만족도가 높으면 리뷰 요청 이메일을 보내고 “리뷰 육성” 태그를 추가해요.

## 트리거와 실시간 시작

액션 플랫폼은 에이전트 스튜디오의 에이전트가 실행될 때마다 동작해요. 그래서 AI가 언제 액션을 시작할지는 트리거 설정으로 정해져요.

에이전트 스튜디오 트리거는 에이전트를 이벤트 기반으로 실시간 시작할 수 있게 해 줘요. 지원하는 트리거는 다음과 같아요.

- **폼이 제출되었습니다**: 특정 폼이 제출될 때마다 에이전트를 시작해요.
- **Lead tag added or removed**(리드 태그 추가 또는 제거): 연락처의 태그가 바뀌면 액션을 시작해요.
- **채팅 메시지**: 새 채팅 메시지가 도착하면 에이전트를 시작해요.

트리거 설정 방법은 [에이전트 스튜디오 트리거 설정하기](agent-studio-setting-up-triggers-for-flow-agents.md)를 참고하세요.

에이전트의 **Start**(시작) 노드에 붙이는 트리거 외에도 다음과 같이 쓸 수 있어요.

- 워크플로우에서 **Invoke Agent Studio Agent**(에이전트 스튜디오 에이전트 호출) 액션으로 에이전트를 호출해요. 그러면 일반 워크플로우 자동화가 흐름 중간에 복잡한 판단이나 액션을 에이전트에게 넘길 수 있어요. 자세한 내용은 [워크플로우 액션 — Invoke Agent Studio Agent](../../07-워크플로우/액션/workflow-action-invoke-agent-studio-agent.md)를 참고하세요.
- **AI에게 문의** 질문을 에이전트로 연결해요. 그러면 대화형 채팅이 에이전트 스튜디오에서 만든 더 복잡한 여러 단계 프로세스를 시작할 수 있어요.

액션 플랫폼은 이런 에이전트 안에서 실행돼요. 그래서 에이전트를 시작하는 트리거라면 무엇이든 액션 플랫폼 작업도 시작할 수 있어요. 예를 들어 폼 제출 시 SMS를 보내거나, 채팅에서 연락처가 핵심 문구를 입력하면 태그를 지정하거나, 워크플로우 이벤트에 맞춰 콘텐츠를 생성할 수 있어요.

## 액션 플랫폼으로 콘텐츠 생성하기

콘텐츠 생성 액션을 쓰면 에이전트가 짧은 답변을 넘어, 팀이나 다른 자동화가 다시 쓸 수 있는 자산까지 만들어 낼 수 있어요.

에이전트 스튜디오에서는 전용 노드로 텍스트, 이미지, 기타 미디어를 이미 생성할 수 있어요. 여기에 액션 플랫폼을 연결하면 이런 일이 가능해요.

**생성 후 보내기**

- 블로그 개요나 전체 글을 작성해서 본인이나 고객에게 이메일로 보내요.
- Facebook이나 Instagram 캡션을 만들어, 소셜 팀이 승인할 수 있도록 내부 알림으로 보내요.

**생성 후 저장하기**

- 긴 글을 만들어 연락처의 커스텀 필드나 메모에 저장해요. 다른 워크플로우나 담당자가 나중에 다시 쓸 수 있어요.
- A/B 테스트를 위해 유형이나 캠페인별로 태그를 붙인 여러 콘텐츠 변형을 저장해요.

**생성 후 분기하기**

- AI 라우팅으로 어떤 유형의 콘텐츠를 만들지 정해요(예: 사용자 요청에 따라 "블로그 vs. 소셜 게시글"). 그다음 알맞은 액션을 실행해요.

이 방식을 쓰면 에이전트가 가벼운 콘텐츠 제작 파이프라인이 돼요. 게시와 최종 승인은 여전히 사람이 맡아요.

## 에이전트에 액션 설정하기

액션 플랫폼 설정은 노드, 트리거, 변수를 알맞게 연결해서 에이전트가 CRM 액션을 안전하게 실행하게 만드는 작업이에요.

시작할 때는 다음 단계를 따라 하세요.

### 1. 접근 권한과 사전 조건 확인하기

1. 올바른 서브 계정에서 **AI 에이전트 > 에이전트 스튜디오**에 접근할 수 있는지 확인하세요. 에이전트 스튜디오는 현재 에이전시 관리자와, 적절한 권한이 있는 에이전시 사용자가 쓸 수 있어요.
2. 발송 액션이 성공하도록, 하이퍼클래스에서 기본 SMS/전화 설정과 이메일 설정이 이미 정상 작동하는지 확인하세요.

### 2. 에이전트 열기 또는 만들기

1. 왼쪽 메뉴에서 **AI 에이전트 > 에이전트 스튜디오**로 이동하세요.
2. 새 에이전트를 만들거나(원하면 템플릿으로 시작할 수 있어요), CRM 액션을 추가할 기존 에이전트를 여세요.

![에이전트 스튜디오 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155079451936/original/Vgjz-Ob_359J9RW8BWK50k8Pkj693uuqvg.png?1787834645)

### 3. 플로우에서 액션이 실행될 위치 정하기

1. 캔버스에서 에이전트가 구체적인 액션을 실행할 지점을 정하세요. 예를 들어 자격 확인 질문 뒤, 채팅을 요약한 뒤, 라우터가 결정한 뒤가 있어요.
2. 자주 쓰는 위치는 **Sequential** 노드의 끝, AI 라우터가 의도를 고른 뒤, 사용자에게서 핵심 데이터를 받은 직후예요.

![캔버스에서 액션 위치 정하기](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155079453742/original/0wX_nopQVIsv4eqZTqIQRhD3um_spQhcTw.png?1787835378)

### 4. 액션을 실행할 수 있는 노드 추가 또는 설정하기

1. 액션 플랫폼 작업을 호출할 수 있는 노드를 넣으세요. 예를 들어 "액션을 수행"하도록 설정한 노드나, 여러 CRM 업데이트를 순서대로 실행하는 노드예요.
2. 노드의 설정 패널에서 에이전트가 수행할 액션 유형을 고르세요. 예를 들면 **SMS 전송**, **Send Email**(이메일 보내기), **Tag Contact**(연락처 태그 지정), **Create Custom Field**(커스텀 필드 만들기), **Send Internal Notification**(내부 알림 보내기)이 있어요.

### 5. 변수와 커스텀 값 연결하기

1. 에이전트 스튜디오 변수와 커스텀 값을 사용해, 연락처 이름, 이메일, 전화번호, 대화 앞부분에서 받은 맥락 데이터를 자동으로 채우세요.

연결 예시는 다음과 같아요.

- SMS 메시지: “안녕하세요 , 에 대한 가격 문의 감사합니다.” <!-- 검토 필요: 원문에 변수 값이 비어 있음 -->
- 커스텀 필드 값: “관심 수준”을 로 설정 <!-- 검토 필요: 원문에 변수 값이 비어 있음 -->

### 6. 트리거 연결 또는 확인하기

1. 새 에이전트라면 에이전트의 **Start** 노드에서 트리거를 설정하세요(예: **폼이 제출되었습니다**, **Lead tag added or removed**, **채팅 메시지**).
2. 기존 워크플로우에서 이 에이전트를 호출하려면, 워크플로우에 **Invoke Agent Studio Agent** 액션을 추가하고 게시한 에이전트를 지정하세요.
3. 대화형 어시스턴트(**AI에게 문의**)라면, 필요한 경우 **AI에게 문의**와 **에이전트 스튜디오** 연동으로 에이전트를 연결하세요.

### 7. 에이전트와 액션 테스트하기

1. 에이전트 스튜디오의 기본 제공 테스트 도구와 실행 타임라인으로 트리거를 시뮬레이션하세요. 알맞은 액션이 올바른 데이터로 실행되는지 확인하세요.
2. 다음 항목을 확인하세요.
   - SMS나 이메일이 예상한 내용으로 발송되는지
   - 태그와 커스텀 필드가 올바르게 적용되는지
   - 내부 알림이 원하는 수신자에게 가는지

### 8. 게시하고 모니터링하기

1. 결과가 만족스러우면 에이전트를 게시하세요. 그러면 운영 환경에서 실제 트리거에 반응해요.
2. 연락처 타임라인, 워크플로우 로그, 에이전트 스튜디오 실행 로그를 확인해 액션이 의도대로 동작하는지 살펴보세요. 필요하면 조정하세요.

## 자주 묻는 질문

### 액션 플랫폼이 기존 워크플로우를 대체하나요?

아니요. 액션 플랫폼은 워크플로우를 대체하지 않고 보완해요. 기존 워크플로우 액션은 그대로 쓸 수 있어요. 같은 플로우에서 AI 판단과 CRM 액션이 모두 필요하면, 워크플로우에서 **Invoke Agent Studio Agent** 액션으로 에이전트 스튜디오 에이전트(액션 플랫폼을 사용하는 에이전트)를 호출할 수도 있어요.

### 액션으로 메시지를 보내면 SMS와 이메일 요금은 어떻게 부과되나요?

에이전트가 액션 플랫폼으로 SMS나 이메일을 보내면, 기존 메시징 설정을 통해 요금이 부과돼요. SMS는 하이퍼클래스 전화나 Twilio, 이메일은 설정해 둔 이메일 제공업체를 통해서예요. 액션 플랫폼이 통신사나 이메일 요금을 바꾸지는 않아요. 메시지를 언제, 어떻게 보낼지만 자동화해 줘요.

### 에이전트가 실행할 수 있는 액션을 제어할 수 있나요?

네. 에이전트 스튜디오 플로우에 어떤 노드와 액션을 추가할지는 직접 정해요. 라우터 로직, 조건, 변수로 액션을 제한할 수도 있어요. 그러면 특정 기준을 충족할 때만 태그를 지정하고, 알림을 보내고, 필드를 업데이트해요.

### 모든 서브 계정에서 액션 플랫폼을 자동으로 쓸 수 있나요?

액션 플랫폼 기능은 에이전트 스튜디오 사용 가능 여부와 AI 상품 이용 권한에 따라 달라져요. 에이전트 스튜디오는 현재 에이전시 관리자와 권한이 있는 사용자가 쓸 수 있어요. 에이전트에서 액션을 설정하는 옵션이 보이지 않으면, 에이전시 관리자나 하이퍼클래스 고객지원에 문의해서 이용 가능 여부를 확인하세요.

### 액션 플랫폼으로 에이전트가 연락처를 한꺼번에 만들거나 업데이트할 수 있나요?

액션은 보통 트리거마다, 또는 에이전트 실행마다 한 번씩 실행돼요(예: 폼 제출 한 건, 채팅 한 건). 그래서 실시간 일대일 자동화에 알맞아요. 대량 업데이트, 가져오기, 일괄 태그 지정은 에이전트 하나로 수천 건을 처리하려 하지 말고, 보통 워크플로우, 리스트, 가져오기 도구를 계속 쓰는 편이 좋아요.

### 에이전트가 액션 플랫폼으로 무엇을 했는지 어떻게 확인하나요?

SMS나 이메일을 보내고 태그나 필드를 업데이트한 액션은, 하이퍼클래스가 보통 그런 이벤트를 기록하는 곳에 표시돼요(예: 연락처 타임라인, 워크플로우 로그). 에이전트 스튜디오의 실행 로그와 디버깅 도구를 쓰면, 특정 대화에서 어떤 노드와 액션이 실행됐는지 정확히 볼 수 있어요.

### 액션 플랫폼은 에이전시 재판매에 화이트라벨로 쓸 수 있나요?

네. 기본 제공 액션은 서브 계정 안에서 일반 CRM 작업처럼 보이도록 만들어졌어요. 그래서 고객은 별도의 "액션 플랫폼" 브랜딩을 보지 않고도 자동 메시지, 태그, 업데이트를 경험해요.
