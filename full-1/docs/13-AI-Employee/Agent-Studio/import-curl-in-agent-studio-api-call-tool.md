# 에이전트 스튜디오 API 호출 도구에서 cURL 가져오기

**cURL 가져오기** 기능을 쓰면 cURL 명령어를 붙여 넣는 것만으로 API 요청 설정이 채워져요. 이 문서에서는 **cURL 가져오기**를 찾는 위치, 자동으로 채워지는 항목, 가져온 설정을 확인하는 방법, 에이전트를 게시하기 전에 API 호출을 테스트하는 방법을 안내해요.

## 에이전트 스튜디오 API 호출 도구의 cURL 가져오기란?

**에이전트 스튜디오**(Agent Studio)의 **API 호출** 도구에서 **cURL 가져오기**를 쓰면, cURL 명령어를 붙여 넣어 하이퍼클래스의 API 호출 설정으로 바로 바꿀 수 있어요. HTTP 메서드, 엔드포인트 URL, 헤더, 요청 본문 같은 핵심 정보가 자동으로 채워지므로, 값을 항목마다 따로 복사해 넣지 않아도 돼요.

에이전트 스튜디오는 트리거, 처리 단계, 분기, 액션을 노드로 연결해 AI 에이전트를 만드는 하이퍼클래스의 시각적 작업 공간이에요. **cURL 가져오기**를 쓰면 **API 호출** 도구에서 외부 API를 더 쉽게 연결할 수 있어요.

## cURL 가져오기를 쓰면 좋은 점

API 문서나 개발자가 테스트한 요청을 하이퍼클래스로 옮길 때 시간이 줄어들어요. API 요청을 항목별로 다시 만들 필요 없이 cURL 명령어를 붙여 넣고, 채워진 설정을 확인한 뒤 저장하면 돼요.

- 빠른 API 설정: cURL 명령어를 붙여 넣으면 요청 정보가 자동으로 채워져요.
- 개발자 친화적인 설정: API 문서, 터미널 명령어, API 테스트 도구에서 쓰던 요청을 에이전트 스튜디오로 쉽게 옮길 수 있어요.
- 수동 입력 감소: HTTP 메서드, URL, 헤더, 요청 본문을 항목마다 하나씩 복사하지 않아도 돼요.
- 요청 내용 확인: **cURL 가져오기** 창을 다시 열면 현재 API 설정이 cURL 명령어로 다시 구성되어 보여요.
- 다양한 요청 형식 지원: 리디렉션, 기본 인증, 여러 줄 요청 본문, 백슬래시 줄 이어쓰기 같은 일반적인 cURL 패턴을 쓸 수 있어요.
- 디버깅 개선: 에이전트를 테스트하거나 게시하기 전에 가져온 API 요청 설정을 확인하고 고칠 수 있어요.

## 에이전트 스튜디오에서 cURL 가져오기를 쓸 수 있는 곳

**cURL 가져오기**는 **API 호출** 도구의 설정 패널 안에 있어요. 에이전트가 에이전트 스튜디오 흐름 중에 외부 웹 요청을 보내야 할 때 **API 호출** 도구를 쓸 수 있어요.

**AI 에이전트 > 에이전트 스튜디오**에서 새 에이전트를 만들거나 기존 에이전트를 열어 보세요. 에이전트 스튜디오는 폼 제출, 리드 태그, 채팅 메시지, 워크플로우 기반 시작 같은 실시간 트리거를 지원해요. 이 트리거가 에이전트가 언제 실행을 시작할지 정해요.

![에이전트 스튜디오 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155071228778/original/BMJ8L_xS2FqYVa-dDFMz4ncEGKT1HMSS5g.png?1778673364)

**cURL 가져오기**는 다음과 같은 곳에서 API 호출을 설정할 때 쓸 수 있어요.

- **AI 에이전트** 노드: **API 호출**을 에이전트가 사용하는 도구로 추가해요.
- **순차** 노드: **API 호출**이 정해진 순서에 따라 하나의 처리 단계로 실행돼요.

## cURL 가져오기로 자동으로 채워지는 항목

**cURL 가져오기**는 붙여 넣은 cURL 명령어에서 요청 정보를 읽어 **API 호출** 항목을 채워요. 기존 API 요청을 에이전트 스튜디오로 쉽게 옮길 수 있고, 가져온 뒤에도 설정을 확인하고 편집할 수 있어요.

자동으로 채워지는 항목은 다음과 같아요.

- HTTP 메서드
- API 엔드포인트 URL
- 헤더
- 요청 본문

요청 본문 유형도 자동으로 감지해요. 감지할 수 있는 유형은 다음과 같아요.

- JSON
- HTML
- XML
- Text
- Form Data

다음과 같은 일반적인 cURL 패턴도 지원해요.

- `--location` 리디렉션
- `-u` 기본 인증
- 여러 줄 요청 본문
- 백슬래시 `\` 줄 이어쓰기

## 가져온 API 호출 설정 확인하기

가져온 API 설정은 에이전트를 저장, 테스트, 게시하기 전에 항상 확인하세요. 요청이 정확하고 안전하며 에이전트 흐름에서 실행될 준비가 되었는지 점검할 수 있어요.

cURL 명령어를 가져온 뒤에는 다음 항목을 확인하세요.

- **안내**: API 호출이 무엇을 하는지, AI 에이전트가 언제 사용해야 하는지 적어요.
- **변수 이름**: API 호출 결과가 저장될 위치가 맞는지 확인해요.
- **API 엔드포인트**: HTTP 메서드와 엔드포인트 URL이 맞는지 확인해요.
- **헤더**: 콘텐츠 유형이나 인증 같은 필수 헤더가 있는지 확인해요.
- **요청 본문**: 가져온 페이로드와 본문 형식을 확인해요.
- 인증 값: 토큰, 자격 증명, 키를 바꾸거나 지우거나 안전하게 보관해야 하는지 확인해요.
- **변수**: 요청에 연락처, 대화, 실행 중 데이터를 쓰려면 에이전트 스튜디오의 동적 변수를 추가해요.

에이전트 스튜디오 변수를 쓰면 에이전트 동작을 개인화하고, 프롬프트, 도구 입력, 메시지 카드, 로직 필드에서 같은 값을 다시 쓸 수 있어요.

## cURL 양방향 동기화

양방향 동기화를 쓰면 **cURL 가져오기** 창에 현재 API 호출 설정이 cURL 명령어로 표시돼요. 익숙한 cURL 형식으로 요청을 확인하고, 수정하고, 문제를 찾기 쉬워요.

API 호출을 설정한 뒤 **cURL 가져오기** 창을 다시 열면, 하이퍼클래스가 현재 설정을 cURL 명령어로 다시 구성해서 보여 줘요. 이 명령어로 요청을 확인하고 내용을 고친 다음, 수정한 버전을 API 호출 설정에 다시 가져올 수 있어요.

다음과 같은 경우에 특히 편해요.

- 요청 형식을 확인하고 싶을 때
- 하이퍼클래스 설정을 외부 API 문서와 비교해야 할 때
- 헤더나 요청 본문 내용을 빠르게 고치고 싶을 때
- 에이전트를 게시하기 전에 API 요청의 문제를 찾고 있을 때

## API 호출 도구와 에이전트 스튜디오 공개 API의 차이

API 호출 도구와 에이전트 스튜디오 공개 API는 쓰임새가 달라요. 차이를 알면 상황에 맞는 쪽을 고를 수 있어요.

API 호출 도구는 하이퍼클래스 에이전트가 실행되는 동안 외부 웹 요청을 보내게 해 줘요. 예를 들어 에이전트가 외부 시스템에서 데이터를 가져오거나, 정보를 보내거나, 외부 프로세스를 실행할 수 있어요.

에이전트 스튜디오 공개 API는 외부 애플리케이션이 하이퍼클래스 대시보드에 로그인하지 않고도, 바로 쓸 수 있는 하이퍼클래스 에이전트를 프로그램으로 조회하고 실행하게 해 줘요.

에이전트가 흐름 중에 외부 API를 호출해야 하면 API 호출 도구를 쓰세요. 외부 시스템이 하이퍼클래스 에이전트 스튜디오의 에이전트와 상호작용해야 하면 에이전트 스튜디오 공개 API를 쓰세요.

## 에이전트 스튜디오 API 호출 도구에서 cURL 가져오기 설정하기

가져온 요청이 에이전트 흐름의 알맞은 지점에서 실행되고 결과가 에이전트가 나중에 쓸 수 있는 곳에 저장되도록 설정해야 해요. 게시하기 전에 가져온 항목을 하나씩 꼼꼼히 확인하면, 실제 대화나 자동화에서 API 호출이 기대한 대로 동작해요.

1. 하이퍼클래스에서 **AI 에이전트**로 이동하세요.
2. **에이전트 스튜디오** 탭을 클릭하세요.
3. **에이전트 만들기**를 클릭하거나 기존 에이전트를 여세요.
4. 시작 트리거를 추가하거나 선택하세요. 예를 들어 **채팅 메시지**, **폼이 제출되었습니다**, **리드 태그**, **워크플로우**가 있어요.
5. 캔버스에 **AI 에이전트** 노드 또는 **순차** 노드를 추가하세요.
6. **API 호출** 도구 또는 처리 노드를 추가하세요.
7. API 호출 설정 패널을 여세요.
8. **cURL 가져오기**를 클릭하세요.
9. **cURL Command**(cURL 명령어) 필드에 cURL 명령어를 붙여 넣으세요.
10. **가져오기**를 클릭하세요.
11. 채워진 API 호출 항목을 확인하세요.
    - HTTP 메서드
    - **API 엔드포인트** URL
    - **헤더**
    - **요청 본문**
    - 본문 유형
    - **변수 이름**
    - **안내** (**AI 에이전트** 노드 안에서 쓸 때)
12. 필요한 내용을 수정하세요.
13. **저장**을 클릭하세요.
14. 에이전트를 게시하기 전에 **테스트**로 API 호출을 확인하세요.
15. 에이전트가 준비되면 **게시**를 클릭하세요.

![cURL 가져오기 설정 과정](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155071229463/original/MGUbcWuidnMLL4MUHRnPgoAt7rOk1MKRMg.gif?1778673649)

에이전트 스튜디오에는 **Chat Emulator**(채팅 에뮬레이터)와 **실행 타임라인** 같은 테스트·디버깅 도구가 있어요. 배포하기 전에 에이전트가 어떻게 동작하는지 살펴볼 수 있어요.

## 자주 묻는 질문

### cURL 가져오기는 어떤 기능인가요?
붙여 넣은 cURL 명령어를 메서드, 엔드포인트 URL, 헤더, 요청 본문 같은 API 호출 설정 항목으로 바꿔 줘요.

### cURL 명령어를 가져온 뒤에도 API 호출을 편집할 수 있나요?
네. 가져온 뒤에 채워진 항목을 확인하고 수정한 다음 API 호출을 저장하거나 테스트하세요.

### cURL 가져오기는 여러 줄 명령어도 지원하나요?
네. 여러 줄 요청 본문과 백슬래시 줄 이어쓰기를 지원해요.

### cURL 가져오기는 어떤 본문 유형을 감지하나요?
JSON, HTML, XML, Text, Form Data 본문 유형을 감지해요.

### cURL 명령어를 가져온 뒤에 변수를 쓸 수 있나요?
네. cURL 명령어를 가져온 뒤 채워진 항목을 확인하고, 동적 값이 필요한 곳에 지원되는 에이전트 스튜디오 변수를 추가할 수 있어요.

### 게시하기 전에 API 호출을 테스트해야 하나요?
네. 게시하기 전에 항상 에이전트를 테스트하세요. API 호출에 인증, 변수, 헤더, 요청 본문이 들어 있다면 더욱 그래요.

### cURL 가져오기와 에이전트 스튜디오 공개 API는 같은 건가요?
아니요. cURL 가져오기는 에이전트 안에서 API 호출을 설정하도록 도와줘요. 에이전트 스튜디오 공개 API는 외부 애플리케이션이 하이퍼클래스 에이전트를 프로그램으로 다루는 데 써요.

### 가져온 요청이 동작하지 않으면 무엇을 확인해야 하나요?
엔드포인트 URL, HTTP 메서드, 헤더, 인증 값, 요청 본문, 본문 유형, 요청에 쓴 변수를 확인하세요. 그런 다음 에이전트를 다시 테스트하세요.
