# 관리형 에이전트를 API로 배포하기

**API로 배포**를 사용하면 웹사이트, 제품, 백엔드 애플리케이션에서 하이퍼클래스로 만든 **관리형 에이전트**(Managed Agents)와 대화를 시작하고 이어 갈 수 있어요. 이 문서에서는 API 접근을 설정하고, 바로 쓸 수 있는 cURL·Python·JavaScript 요청을 가져오는 방법을 안내해요.

관리형 에이전트 빌더에서 API 접근을 바로 설정할 수 있고, 게시한 에이전트 하나를 채팅과 API에서 함께 쓸 수 있어요. 외부 소프트웨어를 연결하려고 에이전트나 워크플로우를 따로 만들 필요가 없어요.

## 관리형 에이전트의 API로 배포란?

**API로 배포**는 외부 소프트웨어가 하이퍼클래스의 관리형 에이전트 API로 게시된 관리형 에이전트를 호출하게 해 주는 기능이에요. **API로 호출됨** 트리거를 추가하면 에이전트가 API 대화에 쓰이고, 다른 트리거도 그대로 쓸 수 있어요. API 요청은 항상 에이전트의 게시된 버전으로 실행돼요. 그래서 테스트와 승인을 마친 버전이 애플리케이션에 전달돼요.

API 설정은 두 가지 방법으로 시작할 수 있어요.

- 관리형 에이전트를 열고 **트리거** 행에서 **API로 호출됨**을 추가해요.
- 에이전트의 **⋮** 메뉴를 열고 **API로 배포**를 선택해요.

두 방법 모두 같은 관리형 에이전트의 API 배포 화면이 열려요.

---

## API로 배포의 장점

**API로 배포**는 관리형 에이전트의 추론 능력과 기능을 하이퍼클래스 밖의 소프트웨어와 연결해 줘요. 설정, 게시, 활동 기록은 계속 에이전트 스튜디오에서 한곳에서 관리해요.

- 하나의 에이전트를 여러 곳에서 써요: 에이전트를 따로 만들지 않고도 같은 관리형 에이전트를 채팅, API 호출, 그 밖의 지원되는 트리거에서 실행할 수 있어요.
- 에이전트 스튜디오 안에서 API 접근을 설정해요: 관리형 에이전트 빌더를 벗어나지 않고 필요한 비공개 연동 토큰을 선택하거나 만들 수 있어요.
- 더 빨리 시작해요: 요청을 처음부터 작성하지 않고 미리 만들어진 cURL, Python, JavaScript 요청을 복사해서 쓸 수 있어요.
- 여러 번 주고받는 대화를 이어 가요: 이전 응답에서 받은 `sessionId`를 다음 API 요청에 함께 보내면 같은 대화를 이어 갈 수 있어요.
- 중복 실행을 줄여요: 생성된 요청에는 `Idempotency-Key`가 들어 있어서 같은 요청을 재시도해도 에이전트가 의도치 않게 두 번 실행되지 않아요.
- 게시로 운영 환경 동작을 관리해요: API 호출은 에이전트의 게시된 버전을 쓰기 때문에 변경 사항을 애플리케이션에 반영하기 전에 먼저 테스트할 수 있어요.
- API 실행 내역을 다른 활동과 함께 확인해요: API로 실행된 내역이 관리형 에이전트의 **활동**에 표시되어 팀이 에이전트 동작을 모니터링하고 문제를 해결할 수 있어요.

## API로 호출됨 트리거

**API로 호출됨** 트리거는 외부 소프트웨어가 관리형 에이전트 API로 관리형 에이전트를 시작할 수 있도록 허용해요. 다른 트리거와 함께 쓸 수 있어서, 외부 애플리케이션용으로 에이전트를 복사해 따로 만들 필요가 없어요.

그래서 관리형 에이전트 하나로 여러 용도를 처리할 수 있어요. 예를 들어 팀은 채팅으로 에이전트와 대화하고, 웹사이트나 백엔드 애플리케이션은 같은 에이전트를 API로 호출할 수 있어요.

API는 항상 관리형 에이전트의 **게시된 버전**을 실행해요. 빌더에서 바꾼 내용은 업데이트한 에이전트를 게시하기 전까지 API 요청에 영향을 주지 않아요.

관리형 에이전트를 만들고 게시하는 방법은 [에이전트 스튜디오에서 관리형 에이전트 설정하고 사용하기](setup-and-use-managed-agents-in-agent-studio.md)에서 확인하세요.

## 비공개 연동 토큰 설정

비공개 연동 토큰은 하이퍼클래스 계정과 외부 애플리케이션 사이의 인증된 접근을 위한 토큰이에요. **API로 배포**를 쓰면 관리형 에이전트 빌더에서 기존 토큰을 고르거나 새로 만들 수 있어서 설정이 간단해요.

API 배포 패널에서 **cURL 구성**을 클릭하면 토큰 설정이 시작돼요.

토큰 설정에서 할 수 있는 일은 다음과 같아요.

- 기존 비공개 연동 토큰을 선택해요.
- 빌더를 벗어나지 않고 새 비공개 연동 토큰을 만들어요.
- 기존 토큰에 필요한 관리형 에이전트 스코프가 없으면 추가해요.
- 새 토큰을 만들 때는 미리 선택된 관리형 에이전트 스코프를 그대로 써요.

API 토큰은 **서브 계정 관리자**만 만들 수 있어요. 토큰을 만들 권한이 없으면 하이퍼클래스가 관리자에게 보낼 수 있는 요청 문구를 제공해요. 이때도 자리 표시용 토큰이 들어간 생성 코드를 볼 수 있어서 연동이 어떤 구조인지 미리 알 수 있어요.

비공개 연동 토큰에 대한 자세한 내용은 [비공개 연동: 꼭 알아야 할 내용](../../42-통합/Private-Integrations/private-integrations-everything-you-need-to-know.md)을 참고하세요.

## 토큰 보안과 마스킹

비공개 연동 토큰은 할당된 스코프에 따라 접근을 허용하므로 API 자격 증명을 안전하게 지키는 것이 중요해요. 하이퍼클래스는 설정이 끝난 토큰을 마스킹해서 보여 줘요. 실행 가능한 예시 코드를 만들려고 API 배포 패널에 전체 토큰을 잠깐 붙여 넣어도 그 값은 저장하지 않아요.

토큰 설정 후에는 다음과 같이 동작해요.

- 설정된 토큰은 마스킹되어 표시돼요.
- 이전에 생성된 전체 토큰은 다시 보여 주지 않아요.
- 생성된 예시에 실행 가능한 자격 증명을 넣고 싶으면 보관해 둔 전체 토큰을 패널에 붙여 넣으세요.
- 그 입력란에 붙여 넣은 전체 토큰은 저장되지 않아요.

비공개 연동 토큰은 안전하게 보관하세요. 공개 소스 코드, 클라이언트 측 애플리케이션, 스크린샷, 저장소에 노출되지 않도록 주의하세요.

## 대화 시작과 이어하기

관리형 에이전트는 API로 새 대화와 이어지는 대화를 모두 지원해요. 어떤 요청 유형을 고르느냐에 따라 에이전트가 새 대화 맥락으로 시작할지, 이전 API 응답에서 이어 갈지가 정해져요.

API 배포 패널에는 두 가지 옵션이 있어요.

- **대화 시작**: 관리형 에이전트와 새 대화를 만들어요.
- **대화 이어하기**: 이전 응답에서 받은 `sessionId`를 보내서 기존 대화를 이어 가요.

새로운 상호작용으로 처리해야 하는 요청에는 **대화 시작**을 쓰세요. 관리형 에이전트가 이전 API 주고받기에서 만들어진 맥락을 기억해야 할 때는 **대화 이어하기**를 쓰세요.

응답으로 받은 `sessionId`는 애플리케이션에 저장해 두었다가 다음 이어하기 요청에 포함하세요.

API 배포 패널은 개발자가 요청을 하나하나 직접 조립하지 않고도 애플리케이션을 관리형 에이전트에 연결할 수 있도록 코드 예시를 만들어 줘요. 각 예시는 같은 API 호출을 다른 언어나 형식으로 보여 줘요.

제공되는 예시는 다음과 같아요.

- cURL
- Python
- JavaScript

원하는 예시 옆의 복사 버튼을 누른 다음, 코드를 애플리케이션에 붙여 넣고 구현에 맞게 수정하세요.

이 패널에서는 대화를 시작하는 요청과 이어 가는 요청 모두 예시를 만들어 줘요.

## Idempotency-Key

`Idempotency-Key`는 같은 에이전트 요청이 실수로 여러 번 실행되지 않도록 애플리케이션을 보호해 줘요. 네트워크 문제나 애플리케이션의 재시도로 같은 요청이 다시 전송될 때 특히 유용해요.

생성된 요청에는 `Idempotency-Key`가 들어 있어요. 같은 키로 요청을 재시도하면 관리형 에이전트가 같은 작업을 두 번 실행하지 않아요.

애플리케이션에 맞게 요청을 수정할 때도 생성된 멱등성 동작은 그대로 유지하세요. 단, 고유한 요청 키를 따로 관리하도록 구현한 경우는 예외예요.

## 게시·게시 취소 상태에서의 동작

게시 여부에 따라 관리형 에이전트가 운영 환경의 API 요청에 응답할 수 있는지가 정해져요. 덕분에 애플리케이션은 현재 게시된 설정을 계속 쓰면서, 초안은 따로 편집하고 테스트할 수 있어요.

API 요청은 항상 관리형 에이전트의 **게시된 버전**을 실행해요.

관리형 에이전트를 게시 취소하면 다음과 같이 돼요.

- API 호출이 중단돼요.
- 에이전트로 보낸 요청에 `404`가 반환돼요.
- 에이전트를 다시 게시하면 API 접근이 재개돼요.

게시를 취소해도 에이전트의 지침, 트리거, 지식, 그 밖의 설정은 삭제되지 않아요.

자세한 내용은 [관리형 에이전트 게시 취소하기](how-to-unpublish-a-managed-agent.md)를 참고하세요.

## API 활동 확인과 문제 해결

API로 실행된 내역은 관리형 에이전트의 다른 실행 활동과 함께 기록돼요. **활동**을 확인하면 요청이 에이전트에 도착했는지, 에이전트가 각 실행을 어떻게 처리했는지 알 수 있어요.

API 호출에 문제가 있을 때는 관리형 에이전트를 열고 **활동**을 확인하세요. 실행 중에 무슨 일이 있었는지 조사하는 데 도움이 되는 실행 정보를 볼 수 있어요.

지원되는 AI 상호작용 전반을 더 깊이 살펴보려면 에이전트 로그도 사용할 수 있어요.

관리형 에이전트를 모니터링하는 방법은 [관리형 에이전트 활동 피드: AI 에이전트 모니터링 및 디버깅](managed-agent-activity-feed-monitor-debug-ai-agents.md)과 [에이전트 로그 개요, 장점, 설정](../../44-신기능-2026/agent-logs-overview.md)에서 더 알아보세요.

## API로 호출됨과 워크플로우에서 호출됨 비교

관리형 에이전트를 어디에서 호출해야 하느냐에 따라 호출 방식이 달라요. 알맞은 트리거를 고르면 자동화를 이해하고 관리하기가 쉬워져요.

하이퍼클래스 밖의 소프트웨어가 API로 관리형 에이전트를 호출해야 할 때는 **API로 호출됨**을 쓰세요.

자동화의 일부로 워크플로우가 관리형 에이전트에게 작업을 넘겨야 할 때는 **워크플로우에서 호출됨**을 쓰세요.

두 방식 모두 게시된 관리형 에이전트를 쓰지만 연동 경로가 서로 달라요.

워크플로우 기반 실행은 [워크플로우에서 관리형 에이전트 호출하기](../../07-워크플로우/시작하기/workflow-action-invoke-managed-agent.md)를 참고하세요.

## 관리형 에이전트에 API로 배포 설정하기

먼저 관리형 에이전트를 설정하고 게시하세요. 그다음 알맞은 비공개 연동 토큰을 연결하고 생성된 요청을 애플리케이션에 복사하면, 애플리케이션이 올바른 인증과 대화 방식으로 원하는 게시된 에이전트를 호출해요.

1. **AI 에이전트 > 에이전트 스튜디오**로 이동하세요.
2. API로 쓰려는 관리형 에이전트를 여세요.
3. 에이전트의 지침, 도구, 지식 등 설정이 운영 환경에서 쓸 수 있도록 준비되었는지 확인하세요.
4. 빌더에서 관리형 에이전트를 테스트하세요.
5. 관리형 에이전트를 게시하세요.
6. **트리거** 행에서 **+ Add trigger**(트리거 추가)를 클릭하세요.
7. **API로 호출됨**을 선택하세요.

   ![API로 호출됨 트리거 선택](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155082521122/original/4WkAezqlQyfhVbTDRIgj7CUUgpQbHSQ-Rw.png?1791201019)

8. API 배포 패널을 여세요.
9. **cURL 구성**을 클릭하세요.

   ![cURL 구성 버튼](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155082522257/original/WO_L_qA6Rx9bOWPrBoTqDTqmLKa94CXsjw.png?1791201498)

10. 기존 비공개 연동 토큰을 선택하거나 새 토큰을 만드세요.

    - 새 토큰에는 필요한 관리형 에이전트 스코프가 미리 선택되어 있어요.
    - 기존 토큰에 필요한 관리형 에이전트 스코프가 없으면 제공되는 옵션으로 추가하세요.
    - API 토큰은 서브 계정 관리자만 만들 수 있어요.

## 자주 묻는 질문

### 같은 관리형 에이전트를 채팅과 API에서 함께 쓸 수 있나요?
네. **API로 호출됨**은 채팅 및 지원되는 다른 트리거와 함께 쓸 수 있어서, 관리형 에이전트 하나로 여러 상호작용 방식을 처리할 수 있어요.

### API는 관리형 에이전트의 어떤 버전을 쓰나요?
API는 에이전트의 게시된 버전을 써요. 빌더에서 바꾼 초안 변경 사항은 에이전트를 다시 게시하기 전까지 운영 API 호출에 영향을 주지 않아요.

### 애플리케이션이 호출 중인 관리형 에이전트를 게시 취소하면 어떻게 되나요?
관리형 에이전트를 다시 게시할 때까지 게시 취소된 에이전트로 보낸 API 호출에는 `404`가 반환돼요.

### 관리형 에이전트마다 API 토큰을 새로 만들어야 하나요?
배포 패널에서 기존 비공개 연동 토큰을 선택하거나 새로 만들 수 있어요. 선택한 토큰에는 필요한 관리형 에이전트 스코프가 포함되어 있어야 해요.

### 서브 계정 관리자가 아니면 어떻게 하나요?
API 토큰은 서브 계정 관리자만 만들 수 있어요. 관리자가 아닌 사용자는 하이퍼클래스가 제공하는 요청 문구로 관리자에게 필요한 토큰 설정을 요청할 수 있고, 자리 표시용 토큰이 들어간 생성 코드를 볼 수 있어요.

### API 호출 사이에 애플리케이션이 대화 맥락을 유지하려면 어떻게 하나요?
이전 API 응답에서 받은 `sessionId`를 저장해 두었다가, **대화 이어하기** 요청을 보낼 때 그 값을 함께 보내세요.

### 배포 패널에 붙여 넣은 전체 API 토큰을 하이퍼클래스가 저장하나요?
아니요. 실행 가능한 생성 코드를 채우려고 전체 토큰을 패널에 붙여 넣을 수 있지만, 그 값은 저장되지 않아요. 설정이 끝난 토큰은 계속 마스킹되어 표시돼요.

### 요청에 Idempotency-Key가 왜 들어 있나요?
`Idempotency-Key`는 실수로 재시도된 요청 때문에 관리형 에이전트가 두 번 실행되는 일을 막아 줘요.

### API로 호출됨과 워크플로우에서 호출됨 중 무엇을 써야 하나요?
외부 제품, 웹사이트, 백엔드에서 에이전트를 호출해야 하면 **API로 호출됨**을 쓰세요. 자동화의 일부로 하이퍼클래스 워크플로우가 에이전트를 호출해야 하면 **워크플로우에서 호출됨**을 쓰세요.
