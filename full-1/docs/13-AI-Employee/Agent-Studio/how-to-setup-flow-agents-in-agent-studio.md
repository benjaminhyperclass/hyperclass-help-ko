# 에이전트 스튜디오에서 플로우 에이전트 설정하기

에이전트 스튜디오(Agent Studio)의 구조와 핵심 구성 요소를 소개하는 문서예요. 에이전트 스튜디오를 처음 써 보거나, 복잡한 자동화를 만들기 전에 전체 구조부터 이해하고 싶을 때 읽어 보세요.

[동영상](https://www.youtube.com/embed/kffk-zdHGHg?&wmode=opaque)

**에이전트 스튜디오**는 똑똑한 AI 에이전트를 시각적으로 만드는 하이퍼클래스의 작업 공간이에요. 에이전트가 언제 시작하는지, 정보를 어떻게 처리하는지, 어떤 판단을 내리는지, 어떤 작업을 하는지를 노드 기반 캔버스에서 자유롭게 설계할 수 있어요.

{% hint style="info" %}
**AI 스튜디오**와 **에이전트 스튜디오**는 하이퍼클래스 안에서 쓰임새가 다른 별개의 AI 도구예요.

**AI 스튜디오**는 프롬프트로 웹사이트, 페이지 등 웹 자산을 빠르게 만들어 주는 대화형 AI 빌더예요. **에이전트 스튜디오**는 이벤트에 반응하고, 사용자와 소통하고, 작업을 자동화하는 AI 에이전트를 만드는 시각적 빌더예요.
{% endhint %}

---

## 에이전트 스튜디오란?

**에이전트 스튜디오**는 AI 에이전트를 만드는 시각적 빌더예요. 이렇게 만든 에이전트는 이벤트에 반응하고, 사용자와 대화하고, 정보를 찾고, 콘텐츠를 만들고, 외부 시스템과 연결할 수 있어요.

단순한 규칙 기반 자동화와 달리, 에이전트 스튜디오에서 만든 에이전트는 입력 내용을 해석하고, 상황에 맞게 판단하고, 대화를 상황에 따라 다른 경로로 보낼 수 있어요. 지식 검색이나 API 같은 도구도 쓸 수 있고요.

에이전트는 캔버스 위에서 노드를 연결해 만들어요. 어떻게 시작하고, 정보를 어떻게 처리하고, 작업을 어떻게 마칠지 노드로 정해요.

---

## 에이전트 스튜디오의 장점

- 시각적 AI 빌더: 드래그 앤 드롭 캔버스에서 에이전트의 동작을 설계해요.
- 이벤트 기반 실행: 채팅 메시지, 폼 제출, 리드 태그 같은 CRM 이벤트로 에이전트를 시작해요.
- 유연한 판단 로직: AI가 파악한 의도나 규칙 기반 조건에 따라 대화를 나눠 보내요.
- 지식과 도구 연동: 지식 베이스를 연결하거나, 웹을 검색하거나, API를 호출할 수 있어요.
- 다양한 형태의 결과물: 하나의 플로우 안에서 텍스트, 이미지, 오디오, 동영상을 만들 수 있어요.
- 구조화된 데이터 수집: 대화 중에 이메일, 전화번호, 사용자의 선택 값을 받아요.

## 에이전트 스튜디오 화면 살펴보기

### 에이전트 스튜디오 대시보드

**AI 에이전트 > 에이전트 스튜디오**로 이동하면 계정에 있는 모든 에이전트 목록이 보여요.

대시보드에서는 다음을 할 수 있어요.

- 기존 에이전트 보기
- 상태 확인(초안 또는 게시됨)
- 만든 날짜와 마지막으로 수정한 날짜 확인
- 에이전트를 폴더로 정리
- 새 에이전트 만들기
- 사용할 수 있는 템플릿 둘러보기

AI 에이전트를 한곳에서 관리하는 화면이에요.

### 새 에이전트 만들기

대시보드에서 **에이전트 만들기**를 클릭하세요.

다음 중 하나를 고를 수 있어요.

- **처음부터 시작**
- **템플릿 사용**: **템플릿 라이브러리**의 템플릿으로 시작해요.

**처음부터 시작**을 고르면 빈 캔버스가 열려요. 템플릿을 쓰면 이미 만들어진 구조를 가져와서 내 상황에 맞게 고칠 수 있어요.

### 에이전트 템플릿 라이브러리

**템플릿 라이브러리**에는 자주 쓰는 용도에 맞춰 미리 만든 에이전트 설계도가 모여 있어요.

빈 캔버스에서 시작하지 않고 이렇게 할 수 있어요.

- 카테고리별 템플릿 둘러보기
- 에이전트 구조를 미리보기
- 템플릿을 내 계정에 설치하기
- 설치한 뒤 플로우의 어느 부분이든 수정하기

템플릿에는 보통 트리거, AI 노드, 분기 로직, 액션이 미리 들어 있어요. 처음 쓰는 분이라면 템플릿을 보는 것이 에이전트의 구조와 연결 방식을 이해하는 가장 빠른 방법이에요.

### 빌더 캔버스

에이전트를 열거나 만들면 시각적 빌더 캔버스가 열려요.

캔버스에서는 다음 작업을 해요.

- 노드를 끌어다 놓고 연결하기
- 실행 로직 정하기
- 에이전트의 각 단계 설정하기

에이전트는 왼쪽에서 오른쪽으로 노드를 이어 만들어요. 트리거에서 시작해서 액션이나 완료 지점에서 끝나요. 노드 사이의 연결이 실제 상황에서 에이전트가 어떻게 움직일지를 정해요.

![빌더 캔버스 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155065467643/original/mUl-0JICTLTok7QU4UcJcsOfNe7wSNCLpw.png?1771836930)

### 시작 트리거

모든 에이전트는 **Start Trigger**(시작 트리거)로 시작해요.

시작 트리거는 에이전트가 언제 실행될지 정해요. 자주 쓰는 예는 다음과 같아요.

- **Chat Message**(채팅 메시지)
- **Form Submission**(폼 제출)
- **리드 태그 추가됨**

트리거가 없으면 에이전트는 실행되지 않아요. 정해 둔 조건이 맞을 때만 에이전트가 반응하게 해 주는 장치예요.

트리거 설정은 [에이전트 스튜디오 트리거 설정](agent-studio-setting-up-triggers-for-flow-agents.md) 문서를 참고하세요.

### 노드 종류

에이전트 스튜디오에서는 캔버스 위의 모든 것을 **노드**로 만들어요. 노드는 에이전트 시작, 응답 생성, 정보 수집, 다른 시스템 연결처럼 딱 하나의 기능을 하는 구성 요소예요. 노드를 연결해서 에이전트가 처음부터 끝까지 어떻게 움직일지 정해요.

![노드 종류 목록 화면 1](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155065466013/original/j4oMLxMOzUDEiNY0V7eX1F1IkCKNcPyfeQ.png?1771835869)

- **AI 에이전트**: 플로우의 "두뇌" 역할을 하는 노드예요. 들어온 입력을 읽고 맥락을 파악해서, 내가 정한 지침에 따라 똑똑하게 응답해요. 예를 들어 사용자가 가격을 물으면 질문을 이해하고 알맞은 답을 만들어 줘요.
- **순차**: 여러 단계를 묶어서 정해진 순서대로 실행하는 노드예요. 이메일을 먼저 받고 그다음 확인 메시지를 보내는 것처럼, 작업이 차례대로 일어나야 할 때 유용해요.
- **종료 노드**: 에이전트 실행이 멈추는 지점이에요. 플로우가 이 노드에 도착하면 상호작용이 끝나요.
- **라우터**: 조건이나 AI가 파악한 의도에 따라 에이전트가 갈 경로를 고르는 노드예요. 판단 지점이라고 생각하면 쉬워요. 사용자가 지원을 물으면 한쪽으로, 영업을 물으면 다른 쪽으로 보내요.
- **지식 베이스 검색**: 연결된 **지식 베이스**에 저장된 정보를 에이전트가 찾아보게 하는 노드예요. 예를 들어 회사 문서에서 바로 답을 가져올 수 있어요.
- **Search Web**(웹 검색): 필요할 때 에이전트가 온라인에서 정보를 찾는 노드예요. 공개된 정보나 최신 정보가 필요한 질문에 답할 때 유용해요.
- **MCP 서버**: 지원되는 외부 도구 서버에 에이전트를 연결하는 노드예요. 에이전트가 외부 시스템을 활용해 전문적인 작업을 하는 고급 연동에 쓰여요.

---

![노드 종류 목록 화면 2](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155065466189/original/oilx-pQ2JI0o4w5Q8deexvh1uFZ02VS7Nw.png?1771835998)

- **API 호출**: 에이전트가 다른 애플리케이션과 정보를 주고받게 하는 노드예요. 예를 들어 리드 데이터를 다른 시스템으로 보내거나 고객 정보를 가져올 수 있어요.
- **오디오 생성**: 플로우에 정한 지침에 따라 에이전트가 음성 응답을 만드는 노드예요.
- **이미지 생성**: 설명 프롬프트를 바탕으로 이미지를 만드는 노드예요. 상황에 맞는 시각 콘텐츠가 필요할 때 유용해요.
- **텍스트 생성**: 메시지, 요약, 구조화된 응답 같은 글을 만드는 노드예요.
- **이메일 주소**: 대화 중에 사용자의 이메일 주소를 정해진 형식으로 받는 노드예요.
- **전화번호**: 사용자의 전화번호를 표준 형식으로 받아 정확하게 저장하는 노드예요.
- **단일 선택**: 미리 정해 둔 선택지를 보여 주고 사용자가 하나를 고르게 하는 노드예요. 구조화된 선택을 유도할 때 좋아요.
- **텍스트 입력**: 사용자가 자유롭게 답할 수 있게 하는 노드예요. 에이전트가 자세한 정보를 모을 수 있어요.

### 변수와 전역 프롬프트

빌더 상단에는 에이전트의 전체 플로우에 적용되는 설정 도구가 있어요.

#### 변수

**변수**는 정보를 저장해 두고 다시 쓰는 자리표시자예요. 같은 값을 여러 곳에 반복해서 쓰는 대신, 한 번만 정해 두고 에이전트 전체에서 불러와 쓸 수 있어요. 예를 들어 비즈니스 이름을 저장해 두면 모든 응답에서 일관되게 쓸 수 있어요.

![변수 설정 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155065466863/original/zD8T9uxFzHxMGtXUqX8eUEOonkdo86vetA.gif?1771836435)

#### 전역 프롬프트

**전역 프롬프트**는 에이전트의 행동을 이끄는 전반적인 지침이에요. 에이전트가 모든 대화에서 지켜야 할 말투, 성격, 규칙을 정해요.

![전역 프롬프트 설정 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155065467862/original/SyRStCRC4ePrfe8ujj_lisNlSwj4PLcoUw.gif?1771837088)

### 테스트와 게시

에이전트를 활성화하기 전에 다음을 할 수 있어요.

- **테스트** 기능으로 실행을 시뮬레이션하기
- 변경사항을 초안으로 저장하기
- 준비되면 에이전트 게시하기

실제 트리거에 반응하려면 에이전트를 게시해야 해요.

## 자주 묻는 질문

### 에이전트는 자동으로 실행되나요?
에이전트는 설정한 트리거 조건이 맞을 때만 실행돼요.

### 에이전트 스튜디오는 워크플로우와 어떻게 다른가요?
워크플로우는 미리 정해 둔 자동화 규칙을 따라요. 에이전트는 AI로 입력을 해석하고 상황에 맞게 판단할 수 있어요.

### 에이전트가 동작하려면 꼭 게시해야 하나요?
네. 실제 이벤트에 반응하려면 에이전트를 게시해야 해요.

### 에이전트를 외부 시스템과 연동할 수 있나요?
네. **API 호출** 노드와 **MCP 서버** 노드로 외부 연동을 할 수 있어요.

### 에이전트가 텍스트 말고 다른 콘텐츠도 만들 수 있나요?
네. 에이전트 스튜디오는 이미지, 오디오, 동영상 생성을 지원해요.
