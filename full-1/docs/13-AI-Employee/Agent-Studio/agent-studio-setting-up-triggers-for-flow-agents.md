# 에이전트 스튜디오에서 플로우 에이전트 시작 트리거 설정하기

에이전트 스튜디오의 트리거를 쓰면 연락처의 행동이나 시스템 이벤트가 생길 때 AI 에이전트를 자동으로 시작할 수 있어요. 더 빠르게 응대하고 수작업을 줄일 수 있어요. 이 문서에서는 이미 만들어 둔 플로우 에이전트에 실시간 시작 트리거를 설정하는 방법을 안내해요.

{% hint style="warning" %}
에이전트 스튜디오에는 이제 **관리형 에이전트**와 플로우 에이전트가 있어요. 새 에이전트는 **관리형 에이전트**로 만들어 주세요. 기존 플로우 에이전트는 계속 정상적으로 실행되고, **Flow Agents**(플로우 에이전트) 페이지에서 열고, 편집하고, 관리할 수 있어요.
{% endhint %}

# 플로우 에이전트 트리거란?

플로우 에이전트 트리거는 에이전트의 시작 노드에 붙는 이벤트 감지 장치예요. 지원하는 이벤트가 발생하면 에이전트를 자동으로 실행해요. 폼 제출이나 채팅 전송 같은 실제 사용자 행동에 반응하기 때문에, 외부 API 호출이나 수동 작업 없이 연락처에게 바로 응대할 수 있어요.

---

## 플로우 에이전트 트리거의 장점

- 실시간 응대: 리드가 폼을 제출하거나, 메시지를 보내거나, 태그가 붙는 순간 바로 응답할 수 있어요.

- 손이 덜 가는 확장: 폴링 스크립트나 커스텀 웹훅 없이, 제품 안에서 트리거를 설정하고 게시하면 끝나요.

- 일정한 시작 지점: 에이전트가 시작되는 방식을 통일해서 테스트와 문제 해결이 쉬워져요.

- 기존 설정에 영향 없음: 트리거는 선택 사항이고 기존 기능에 더해지는 방식이에요. API로 실행하던 기존 에이전트도 그대로 작동해요.

- 앞으로의 확장: 이벤트 기반으로 설계되어 있어서 앞으로 이벤트 유형이 늘어날 수 있어요.

---

## 플로우 에이전트 트리거 설정 방법

아래 순서를 따라 하면 처음부터 끝까지 안정적으로 테스트하고 운영에 적용할 수 있어요.

{% hint style="info" %}
**사전 준비 및 접근 권한**

설정이 매끄럽게 진행되고 배포 과정과 맞도록 접근 권한과 환경을 먼저 확인하세요.

올바른 서브 계정에서 **AI 에이전트** → **에이전트 스튜디오**에 들어갈 수 있어야 해요.

캔버스 이동, 테스트, 게시 과정은 "How to Setup Flow Agents in Agent Studio" 문서를 참고하세요.
{% endhint %}

1. 왼쪽 사이드바에서 **AI 에이전트**를 클릭한 다음, 상단의 **에이전트 스튜디오** 탭을 선택하세요.
2. **Flow Agents** 버튼을 클릭하세요.

   ![Flow Agents 버튼을 클릭하는 화면](https://jumpshare.com/share/GHcBJsQLzhbMZnJ8U7Nd+/Screen+Shot+2026-07-08+at+18.27.14.png)
3. 편집할 기존 에이전트의 이름을 클릭하세요.
4. 에이전트 안으로 들어가면 노드와 더하기(+) 버튼이 있는 빌더 캔버스가 보여요. **새 노드 추가**를 눌러 만들기 시작하거나, 기존 플로우의 시작 영역을 찾으세요.
5. 노드 선택 창의 **흐름 제어**에서 **시작 트리거**를 선택하세요. 에이전트를 시작할 이벤트를 감지하는 트리거 타일이 추가돼요.
6. **트리거 선택** 패널에서 **폼이 제출되었습니다**, **리드 태그**, **채팅 메시지**, **워크플로우** 중 에이전트를 시작할 조건을 고르세요. 어떤 것을 고르느냐에 따라 다음에 나오는 설정 항목이 달라져요.

   1. **폼이 제출되었습니다** 트리거: 연락처가 하이퍼클래스에서 추적하는 폼을 제출한 직후 에이전트가 응대하게 하고 싶을 때 써요. 즉각적인 육성, 리드 자격 확인, 라우팅에 알맞아요.

      - 선택한 폼 중 어느 하나라도 제출되면 에이전트가 시작돼요.
      - 제출된 폼 필드를 변수로 제공해서, 이후 단계에서 에이전트가 참조할 수 있어요.
   2. **리드 태그** 트리거(추가 / 제거): 연락처에 태그가 붙거나 제거될 때 맞춤 자동화를 실행해요. VIP 온보딩, 재참여 유도, 이탈 방지 등에 자주 써요.

      - 선택한 태그가 연락처에 **추가**되거나 **제거**되면 에이전트가 시작돼요.
      - 기존 태그와 커스텀 필드를 포함한 연락처 정보를 플로우에 전달해요.
   3. **채팅 메시지** 트리거: 지원하는 채팅 위젯·제공업체로 새 수신 메시지가 도착하는 즉시 에이전트를 시작해요. 즉각 답변, 스마트 라우팅, 자주 묻는 질문 응대에 알맞아요.

      - 추가 설정 없이 트리거를 추가하고 게시하면 돼요.
      - 플로우 로직에 쓸 메시지 텍스트, 발신자 정보, 대화 정보를 제공해요.
   4. **워크플로우** 트리거: 자세한 내용은 "Workflow Action - Invoke Agent Studio Agent" 문서를 참고하세요.

      ![워크플로우 트리거 설정 화면 녹화](https://jumpshare.com/share/VOcHRyGZDNtg9Rs7gUEg+/GIF+Recording+2026-07-08+at+18.48.55.gif)
7. 트리거를 설정하세요.

   - 폼 선택: **폼이 제출되었습니다** 트리거에서는 드롭다운으로 폼을 하나 이상 선택하세요. 아직 폼을 만들지 않았다면 **새로 추가**를 클릭하세요. 선택한 폼 중 어느 하나라도 제출되면 에이전트가 시작돼요.
   - 태그 작업 선택: **리드 태그**에서는 **태그 작업**을 **태그 추가됨** 또는 **태그가 제거되었습니다**로 설정하세요. 연락처에 태그가 붙을 때 에이전트를 시작할지, 태그가 제거될 때 시작할지 정하는 설정이에요.
     - 목록에서 특정 태그를 선택하거나 **새로 추가**로 새 태그를 만드세요. 에이전트는 여기서 선택한 태그의 변화에만 반응해요.
     - 테스트하려고 태그를 한꺼번에 추가할 때는, 에이전트가 한 번에 많이 실행되지 않도록 먼저 작은 테스트 그룹으로 해 보세요.
   - 채팅 트리거 켜기: **채팅 메시지**는 추가 설정이 필요 없어요. 연결된 채팅 채널로 새 수신 메시지가 도착하면 에이전트가 자동으로 시작돼요.

   ![트리거 설정 화면 녹화](https://jumpshare.com/share/uDIC7Gt97CHnFzAx8Odr+/GIF+Recording+2026-07-08+at+19.25.55.gif)
8. 검증하고 라이브로 전환하세요.

   - **테스트**: 선택한 트리거를 안전하게 시뮬레이션해서, 에이전트가 어떤 변수와 페이로드를 받는지 정확히 확인해요. 실제 연락처에는 영향이 없어요. 프롬프트와 노드를 빠르게 고쳐 가며 게시 전에 플로우를 확인할 때 쓰세요.

   - **저장**: 현재 변경 내용을 스테이징 버전으로 저장해서, 작업을 잃지 않고 나중에 이어서 할 수 있어요. 아직 라이브로 전환되지는 않아요. 폼이나 태그를 고르는 등 설정 단계를 마칠 때마다 저장하면 깔끔한 작업 버전을 유지할 수 있어요.

   - **게시**: 현재 에이전트와 시작 트리거를 이 서브 계정에 라이브로 적용해서, 실제 이벤트가 발생하면 곧바로 에이전트가 시작돼요. **테스트**를 성공적으로 마친 뒤에 게시하고, 시작 트리거가 첫 번째 노드에 연결되어 있는지 확인하세요. 에이전트를 **AI에게 문의** 같은 다른 기능에 연결하려면, 보통 프로덕션 상태여야 선택할 수 있어요.

     ![게시 화면](https://jumpshare.com/share/wId879x6RlnN0bG3qxtc+/Screen+Shot+2026-07-08+at+19.29.51.png)

## 자주 묻는 질문

### 실시간 시작 트리거를 쓸 새 플로우 에이전트를 만들 수 있나요?

아니요. 이제 새 에이전트는 **관리형 에이전트**로 만들어야 해요. 기존 플로우 에이전트는 **Flow Agents** 페이지에서 계속 열고, 편집하고, 관리할 수 있어요.

### 기존 플로우 에이전트의 트리거는 계속 작동하나요?

네. 기존 플로우 에이전트와 설정된 트리거는 계속 정상적으로 실행돼요.

### 트리거를 추가하면 API로 실행하던 기존 에이전트의 작동 방식이 바뀌나요?

아니요. 트리거는 기존 기능에 더해지는 방식이에요. 기존 API 플로우는 그대로 작동하고, 트리거는 시작 트리거를 추가한 에이전트에서만 실행돼요.

### 라이브로 전환하기 전에 테스트할 수 있나요?

네. 캔버스의 **테스트** 옵션으로 이벤트를 시뮬레이션해서, 게시 전에 변수와 응답을 확인할 수 있어요.

### 어떤 채팅 소스를 지원하나요?

서브 계정에 연결된 하이퍼클래스의 기존 채팅 위젯과 제공업체에서 작동해요. 시작하는 데 추가 설정은 필요 없어요.

### 트리거가 실행되면 에이전트가 어떤 데이터를 받나요?

폼 제출 시에는 매핑된 폼 필드가, **리드 태그** 이벤트 시에는 연락처 정보가, **채팅 메시지** 이벤트 시에는 메시지 텍스트와 대화 메타데이터가 전달돼요.

### 드롭다운에 폼이나 태그가 보이지 않아요.

올바른 서브 계정에 있는지, 그리고 그 서브 계정에 해당 폼이나 태그가 있는지 확인하세요. 새 폼이나 태그를 만든 뒤에는 빌더를 새로 고침하세요.
