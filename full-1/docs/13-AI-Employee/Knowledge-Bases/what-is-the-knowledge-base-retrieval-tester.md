# 지식 베이스 검색 테스터(Knowledge Base Retrieval Tester) 사용하기

**Knowledge Base Retrieval Tester**(지식 베이스 검색 테스터)는 지식 베이스를 실제 AI 서비스에 연결하기 전에, 테스트 질문에 지식 베이스가 얼마나 잘 답하는지 확인하는 기능이에요. 업로드한 파일, 크롤링한 웹 콘텐츠, 리치 텍스트, 문서, 표 내용을 AI가 제대로 찾아 쓰는지 안전하게 점검할 수 있어요. 이 문서에서는 줄여서 "검색 테스터"라고 부를게요.

[동영상](https://www.youtube.com/embed/sxlUj4\_9Uvw?&wmode=opaque)

## 지식 베이스 검색 테스터란?

지식 베이스에는 문서, 리치 텍스트, 표, 웹 기반 소스 등 여러 종류의 소스를 담을 수 있어요. 하이퍼클래스는 이 콘텐츠를 추출하고 구조화하고 조각으로 나눈 뒤 색인해서, AI 에이전트가 질문에 답할 때 관련 정보를 찾을 수 있게 해요. 자세한 내용은 [지식 베이스 개요](../knowledge-base-overview.md)에서 볼 수 있어요. 검색 테스터를 쓰면 고객이 실제로 이용하기 전에 이 검색 과정이 의도대로 동작하는지 확인할 수 있어요.

검색 테스터로 이런 일을 할 수 있어요.

- 샘플 질문을 입력해 봐요.
- 어떤 소스가 검색되는지 확인해요.
- 빠졌거나 관련 없는 콘텐츠를 찾아내요.
- 지식 베이스를 수정한 뒤 다시 테스트해요.

## 검색 테스터를 쓰면 좋은 점

검색 테스터를 쓰면 짐작에 의존하지 않고 직접 확인하며 준비할 수 있어요. 지식 베이스가 준비됐다고 가정하는 대신, 고객이 할 법한 질문으로 테스트하고 하이퍼클래스가 찾아낸 콘텐츠를 살펴보세요.

- 실시간 테스트: 질문을 입력하면 지식 베이스가 어떻게 응답하는지 바로 볼 수 있어요.
- 소스 단위 확인: 테스트 결과에 사용된 콘텐츠 소스나 청크(조각)를 확인할 수 있어요.
- 빠른 문제 파악: 서비스를 시작하기 전에 빠졌거나, 관련 없거나, 오래됐거나, 구조가 좋지 않은 콘텐츠를 찾을 수 있어요.
- 지식 베이스 품질 향상: 테스트 결과를 보고 문서, 표, 리치 텍스트, 크롤링한 소스를 다듬을 수 있어요.
- 안전한 점검: 읽기 전용 테스트라서 지식 베이스를 바꾸지 않고 실시간 대화에도 영향을 주지 않아요.
- 빠른 개선: 콘텐츠를 수정하고 다시 테스트해서 나아졌는지 확인할 수 있어요.

## 검색 테스터를 사용할 때

AI가 올바른 정보를 찾을 수 있다는 확신이 필요할 때 지식 베이스를 테스트하면 가장 유용해요. 테스트를 꼼꼼히 해 두면 불완전한 답변, 관련 없는 소스 사용, 고객에게 혼란을 주는 상황을 줄일 수 있어요.

이럴 때 검색 테스터를 사용하세요.

- 새 문서, PDF, DOC, DOCX, 리치 텍스트 문서, CSV 표, 웹사이트 소스를 추가했을 때
- 기존 지식 베이스 콘텐츠를 수정했을 때
- 중요한 비즈니스 정보를 AI가 찾을 수 있는지 확인하고 싶을 때
- AI 직원, [대화 AI 봇](../Conversation-AI/conversation-ai-new-knowledge-sources-quality-upgrades.md), [음성 AI 에이전트](../Voice-AI/knowledge-base-integration-for-voice-ai-agents.md)를 시작하기 전에 준비할 때
- AI 응답이 엉뚱한 소스를 쓰거나 기대한 내용이 빠져 있을 때. 대화에서 [AI 응답 정보](../../03-대화/view-edit-ai-response-info-in-conversations.md)를 확인하는 방법도 함께 참고하세요.
- 질문에 따라 어떤 콘텐츠 조각이 검색되는지 비교하고 싶을 때
- 중복되거나 서로 충돌하는 콘텐츠가 검색에 영향을 주는지 확인해야 할 때

## 검색된 소스와 청크 이해하기

검색된 소스는 테스트 질문과 관련 있다고 하이퍼클래스가 판단한 지식 베이스 콘텐츠를 보여 줘요. 결과를 살펴보면 소스 콘텐츠가 명확하고 완전한지, AI가 쓰기 좋은 구조인지 알 수 있어요.

지식 베이스는 소스 콘텐츠를 검색할 수 있는 작은 조각으로 나눌 수 있고, 이 조각을 흔히 청크라고 해요. 예를 들어 [문서 지원](../knowledge-base-document-rich-text-support.md)은 제목과 본문 텍스트를 추출해 AI 에이전트가 관련 구절을 찾게 하고, [표 지원](../ai-employee-knowledge-base-tables.md)은 레코드를 의미 기반으로 색인해서 일상적인 말투의 질문으로도 일치하는 행을 찾을 수 있게 해요.

테스트 결과를 볼 때는 다음을 확인하세요.

- 기대한 소스가 결과에 나타나는지
- 반환된 청크가 질문에 바로 답하는지
- 관련 없거나 오래된 콘텐츠가 검색되는지
- 비슷한 소스끼리 정보가 겹치거나 서로 충돌하는지
- 콘텐츠가 너무 광범위하거나 모호한지, 고객이 쓸 만한 중요한 용어가 빠져 있는지

## 검색 테스터 설정하기

AI 도구가 실제로 사용할 콘텐츠로 테스트하려면 설정을 제대로 해야 해요. 테스트하기 전에 확인하려는 소스가 지식 베이스에 들어 있는지, 색인이나 처리가 끝났는지 확인하세요.

1. **AI 에이전트 > 지식 베이스**로 이동하세요.

   ![AI 에이전트 > 지식 베이스 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155069903368/original/khNY3HXTWddbT4BnRNs7xaDyHcSPAlfeGg.png?1777040279)
2. 테스트할 지식 베이스를 여세요.
3. 확인하려는 소스가 지식 베이스에 들어 있는지 확인하세요. 예를 들면 다음과 같아요.

   - 문서
   - 리치 텍스트 콘텐츠
   - 표
   - 웹사이트 또는 웹 크롤러 콘텐츠
   - 그 밖에 지원되는 지식 베이스 소스 유형
4. 새로 추가하거나 수정한 콘텐츠의 처리·색인이 끝날 때까지 기다리세요.
5. **Knowledge Base Retrieval Tester**(지식 베이스 검색 테스터)를 여세요.

   ![지식 베이스 검색 테스터 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155070024558/original/RCft-P6ODDcQ0gTBl4Yq_IvWTWby4whecg.png?1777290947)
6. 고객이 할 법한 질문을 실제 말투로 입력하세요.

   예: "환불 정책이 어떻게 되나요?", "결제 기한이 지난 인보이스가 있는 고객은 누구인가요?"
7. 답변과 검색된 소스를 확인하세요.
8. 검색된 소스가 하이퍼클래스가 쓰기를 기대한 콘텐츠와 일치하는지 확인하세요.
9. 결과가 없거나, 불완전하거나, 오래됐거나, 관련 없다면 지식 베이스 콘텐츠를 수정하세요.
10. 같은 질문으로 다시 테스트해서 수정한 콘텐츠가 제대로 검색되는지 확인하세요.

## 지식 베이스 테스트 모범 사례

좋은 테스트는 고객, 리드, 내부 사용자가 실제로 할 만한 질문을 사용해요. 완벽한 질문 하나만 테스트하면, 사용자가 다르게 표현할 때 생기는 빈틈을 놓칠 수 있어요.

다음 방법을 따라 보세요.

- 간단하고 직접적인 질문부터 테스트하세요.
- 내부 용어만 쓰지 말고 고객이 쓰는 자연스러운 표현으로도 테스트하세요.
- 같은 질문을 여러 방식으로 물어보세요.
- 특정 문서, 표의 행, 정책이 나와야 하는 질문을 포함하세요.
- 예외 상황, 특수한 경우, 고객에게 영향이 큰 질문을 테스트하세요.
- 생성된 답변만 보지 말고 소스도 확인하세요.
- 최신 콘텐츠와 경쟁하는 오래된 콘텐츠는 삭제하거나 업데이트하세요.
- 검색 결과가 좋지 않으면 너무 길거나 불분명한 콘텐츠를 더 깔끔한 섹션으로 나누세요.
- 지식 베이스를 크게 업데이트할 때마다 다시 테스트하세요.

## 검색 결과 문제 해결

검색 테스트는 약한 부분을 찾아 고치는 데 도움이 될 때 가장 가치가 커요. 결과가 기대와 다르면 검색된 소스를 보고, 콘텐츠 누락, 모호한 표현, 나쁜 구조, 충돌하는 정보 중 무엇이 원인인지 파악하세요.

| 문제 | 의미할 수 있는 원인 | 권장 조치 |
| --- | --- | --- |
| 검색된 소스가 없어요 | 콘텐츠가 색인되지 않았거나, 사용할 수 없거나, 질문과 표현이 충분히 비슷하지 않을 수 있어요. | 색인이 끝났는지 확인한 뒤, 사용자가 질문하는 방식에 맞는 더 명확한 표현을 추가하세요. |
| 엉뚱한 소스가 검색돼요 | 다른 소스가 더 관련 있어 보이거나 겹치는 용어를 포함하고 있을 수 있어요. | 경쟁하는 콘텐츠를 수정하거나 삭제하거나 더 명확하게 다듬으세요. |
| 답변이 불완전해요 | 소스에 필요한 정보가 모두 들어 있지 않을 수 있어요. | 해당 지식 베이스 항목에 빠진 내용을 추가하세요. |
| 오래된 소스가 검색돼요 | 예전 콘텐츠가 지식 베이스에 아직 남아 있을 수 있어요. | 오래된 콘텐츠를 삭제하거나 업데이트하세요. |
| 표 데이터가 나오지 않아요 | 표가 아직 처리 중이거나, 관련 열이 색인되지 않았을 수 있어요. | CSV 설정, 선택한 열, 처리 상태를 확인하세요. |
| 문서 콘텐츠가 빠져 있어요 | 문서가 제대로 분석되지 않았을 수 있어요. | 제목, 서식, 소스 품질을 점검한 뒤 다시 업로드하거나 내용을 수정하세요. |
| 질문을 다르게 표현하니 결과가 좋아져요 | 지식 베이스에 고객이 흔히 쓰는 표현이 없을 수 있어요. | 자연스러운 표현, 동의어, 더 명확한 제목을 추가하세요. |

## 자주 묻는 질문

### 검색 테스터가 지식 베이스를 바꾸나요?
아니요. 검색 테스터는 읽기 전용 시뮬레이션이에요. 지식 베이스 콘텐츠를 편집하거나 삭제하거나 업데이트하지 않아요.

### 테스트가 실시간 고객 대화에 영향을 주나요?
아니요. 테스트는 고객에게 메시지를 보내거나 실시간 대화를 일으키지 않아요.

### 서비스를 시작하기 전에 검색 테스터를 써도 되나요?
네. 검색 테스터는 콘텐츠를 실제 AI 서비스에 연결하기 전에 지식 베이스 품질을 확인하도록 만들어졌어요.

### 대화 AI 봇을 테스트하는 것과 같은 건가요?
아니요. 검색 테스트는 지식 베이스 콘텐츠를 찾아서 반환할 수 있는지 확인해요. 봇 테스트는 봇의 목표, 프롬프트, 액션, 응답 방식까지 포함한 전체 대화 경험을 확인해요.

### 왜 엉뚱한 소스가 검색되나요?
엉뚱한 소스에 표현이 비슷하거나, 정보가 중복되거나, 오래된 내용이 있거나, 더 폭넓은 내용이 들어 있어서 테스트 질문과 더 관련 있어 보일 수 있어요. 겹치는 소스를 살펴보고 올바른 소스를 더 명확하게 다듬으세요.

### 기대한 콘텐츠가 결과에 나오지 않는 이유가 뭔가요?
콘텐츠가 아직 처리 중이거나, 색인되지 않았거나, 분석하기 어려운 형태로 되어 있거나, 질문과 충분히 가까운 표현이 들어 있지 않을 수 있어요.

### 지식 베이스를 수정한 뒤 다시 테스트할 수 있나요?
네. 지식 베이스를 수정하고 처리·색인이 끝나면 같은 테스트 질문을 다시 실행해서 결과가 나아졌는지 확인하세요.

### 어떤 종류의 지식 베이스 콘텐츠를 테스트할 수 있나요?
문서, 리치 텍스트 콘텐츠, 표, 웹 기반 소스처럼 지원되는 지식 베이스 콘텐츠를 검색 테스터로 확인할 수 있어요.

### 검색 테스터에서 보이는 답변이 고객이 받는 답변과 똑같나요?
검색 테스터는 지식 베이스 검색과 소스 사용을 확인하는 데 도움을 줘요. 고객에게 실제로 전달되는 최종 응답은 연결된 AI 도구, 프롬프트, 봇 설정, 대화 맥락, 채널에 따라 달라질 수 있어요.

### 검색된 소스는 맞는데 답변이 부실하면 어떻게 하나요?
소스 콘텐츠에 더 명확한 제목, 직접적인 답변, 예시, 고객 친화적인 표현을 추가해서 개선하세요. 그런 다음 같은 질문으로 다시 테스트하세요.
