# 음성 AI 에이전트 프롬프트에서 커스텀 값 사용하기

**커스텀 값**을 쓰면 하이퍼클래스에 저장된 정보를 음성 AI 프롬프트와 메시지 필드에 넣을 수 있어요. 연락처, 회사, 예약, 캘린더, 계정, 위치 정보로 음성 AI 에이전트가 통화를 맞춤형으로 진행해요. 이 문서에서는 현재 음성 AI 빌더에서 **커스텀 값**을 찾는 위치, 프롬프트에 넣는 방법, 실제 통화에 쓰기 전에 테스트하는 방법을 안내해요.

## 음성 AI 프롬프트에서 커스텀 값이란?

**커스텀 값**은 음성 AI 프롬프트나 메시지 텍스트에 넣을 수 있는 동적 병합 필드예요. 음성 AI 에이전트가 통화 중에 프롬프트를 사용할 때, 하이퍼클래스에 저장된 해당 정보가 값 자리에 채워질 수 있어요.

예를 들어 프롬프트에 `{{location.name}}` 같은 값을 넣으면 에이전트가 통화 중에 비즈니스 이름이나 위치 이름을 말할 수 있어요. 연락처, 예약, 계정마다 프롬프트를 새로 쓰지 않아도 대화를 맞춤형으로 만들 수 있어요.

## 음성 AI에서 커스텀 값을 쓰면 좋은 점

**커스텀 값**을 쓰면 음성 AI 에이전트가 하이퍼클래스에 있는 정보를 활용해 대화를 더 개인화하고 상황에 맞게 이끌 수 있어요. 신중하게 쓰면 프롬프트가 복잡해지지 않으면서 통화 품질을 높일 수 있어요.

- 맞춤형 통화 경험: 연락처, 회사, 예약, 계정 정보 같은 관련 정보를 프롬프트에 넣을 수 있어요.
- 재사용할 수 있는 프롬프트: 값이 있으면 프롬프트 하나로 서로 다른 레코드를 참조할 수 있어요.
- 더 자연스러운 인사: 비즈니스나 연락처 정보로 환영 메시지나 첫 안내를 개인화할 수 있어요.
- 더 나은 통화 맥락: 대화 전이나 대화 중에 에이전트에게 도움이 되는 정보를 줄 수 있어요.
- 수정 작업 감소: 위치, 연락처, 상황마다 프롬프트를 따로 만들지 않아도 돼요.

## 커스텀 값 vs. 지식 베이스, 사용자 지정 액션

**커스텀 값**은 음성 AI가 상황을 더 잘 파악하게 하는 방법 중 하나예요. **커스텀 값**, **지식 베이스**, **사용자 지정 액션**의 차이를 알면 상황에 맞는 도구를 고를 수 있어요.

| 기능 | 용도 | 예시 |
| --- | --- | --- |
| **커스텀 값** | 저장된 동적 정보를 프롬프트나 메시지 텍스트에 넣을 때 | `{{location.name}}`을 넣어 비즈니스 이름을 말하게 해요. |
| **지식 베이스** | 에이전트가 질문에 답할 때 쓸 사실 정보를 제공할 때 | 서비스, 가격, 자주 묻는 질문, 정책, 비즈니스 정보 |
| **사용자 지정 액션** | 통화 중에 에이전트를 외부 시스템이나 워크플로우와 연결할 때 | 외부 데이터 조회, 레코드 생성, 연동 실행 |

에이전트가 프롬프트에서 하이퍼클래스에 이미 있는 데이터를 참조해야 하면 **커스텀 값**을 쓰세요. 질문에 답할 사실 정보가 필요하면 **지식 베이스**를 쓰세요. 통화 중에 다른 시스템과 연결해야 하면 **사용자 지정 액션**을 쓰세요.

## 음성 AI 프롬프트에 커스텀 값 넣기

**커스텀 값**을 넣으면 에이전트가 통화 중에 동적 정보를 말할 수 있어요. 값을 소리 내어 읽었을 때 자연스럽도록 앞뒤 문장을 분명하게 써 주세요.

1. **AI 에이전트 > 음성 AI**로 이동해요. 하이퍼클래스에서 음성 AI 에이전트를 만들고 관리하는 곳이에요.

   ![AI 에이전트 메뉴에서 음성 AI로 이동한 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155073367389/original/zcCMI1_y7WWUZMLNXl3uX93bAuMfgYifRQ.png?1781096087)

2. **Agent List**(에이전트 목록)를 클릭하고 에이전트를 선택해요. 이 목록에는 계정에서 사용할 수 있는 음성 AI 에이전트가 표시돼요. 수정할 에이전트를 클릭하거나, **+에이전트 만들기** 버튼으로 새 에이전트를 만드세요.

   ![에이전트 목록에서 에이전트를 선택하는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155073367787/original/oyk_kQJssys9cXRxQNqSbBzPqZLJquDS6Q.png?1781096306)

3. **빌드** 탭을 열어요. 이 탭에서 에이전트의 목소리, 모델, 언어, 프롬프트, 환영 메시지 등 통화 동작 설정을 구성해요.

   ![빌드 탭 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155073368330/original/v-yXN8TwSruqxiOn7la5F-QdMHXksPLVww.png?1781096648)

4. 값을 넣을 프롬프트나 메시지 필드를 찾아요. **커스텀 값** 버튼이나 아이콘이 보이는 프롬프트·메시지 필드에는 어디든 값을 넣을 수 있어요.

   ![커스텀 값을 넣을 프롬프트 필드 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155073368654/original/pJ3-5sXZ8CmxMa6IKzQGop7hmN3T8H_dkg.png?1781096820)

5. **커스텀 값**을 클릭해요. **커스텀 값** 메뉴가 열려요. 값을 검색하거나 카테고리를 둘러볼 수 있어요.

   ![커스텀 값 메뉴가 열리는 모습](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155073369221/original/FLW0RXlbJIOaPbGqa4TCPU_n__YDHw3pwg.gif?1781097118)

6. 값을 검색하거나 카테고리를 선택해요. 필요한 값을 알면 검색창을 쓰세요. 아니면 **연락처**, **회사**, **사용자**, **예약**, **캘린더**, **Account**(계정), **Right now**(현재) 같은 카테고리를 펼쳐 보세요.
7. 넣을 **커스텀 값**을 선택해요. 값을 선택하면 `{{location.name}}`처럼 병합 필드 형식으로 프롬프트에 들어가요.
8. 커스텀 값 앞뒤 문장을 확인해요. 문장 전체를 소리 내어 읽어 보고 자연스러운지 확인하세요. 음성 AI 프롬프트는 말로 하는 대화에 맞게 써야 해요. 어색한 표현이나 한 문장에 너무 많은 값을 넣는 일은 피하세요.

   예시:

   `{{location.name}}`에 전화해 주셔서 감사합니다. 무엇을 도와드릴까요?

9. **저장**을 클릭해요. 수정한 프롬프트나 메시지 필드가 에이전트에 적용돼요.
10. 에이전트를 테스트해요. **Test Audio**(오디오 테스트) 패널에서 **Web Call**(웹 통화)이나 **Phone Call**(전화 통화)로 커스텀 값이 어떻게 동작하는지 확인하세요.

## 커스텀 값을 활용한 프롬프트 예시

좋은 프롬프트 예시를 보면 말로 하는 통화에서 **커스텀 값**을 자연스럽게 쓰는 방법을 알 수 있어요. 값이 짧든 길든, 값이 없든 앞뒤 문장은 말이 되어야 해요.

### 비즈니스 또는 위치 이름

당신은 `{{location.name}}`을(를) 대신해 전화하고 있습니다. 또렷하고 따뜻하며 전문적으로 말하세요.

### 환영 메시지

`{{location.name}}`에 전화해 주셔서 감사합니다. 무엇을 도와드릴까요?

### 연락처 이름

연락처의 이름을 알 수 있으면 이름을 불러 인사하세요. 알 수 없으면 일반적인 인사를 하세요.

### 예약 정보 활용

예약 정보가 있으면 이를 활용해 예약 날짜와 시간을 확인하세요. 예약 정보가 없으면 도움을 드리는 데 필요한 정보를 발신자에게 물어보세요.

### 할당된 사용자 활용

할당된 사용자가 있으면, 누가 후속 연락을 할지 발신자가 알면 도움이 될 때만 그 사용자를 언급하세요.

## 커스텀 값을 쓸 때 지킬 점

**커스텀 값**은 통화를 더 편리하게 만들어야지 더 복잡하게 만들면 안 돼요. 음성 AI는 프롬프트를 통화 중에 말로 하므로, 값이 소리 내어 읽힐 때 어떻게 들릴지 항상 생각하세요.

- 대화가 나아질 때만 커스텀 값을 쓰세요.
- 한 문장에 커스텀 값을 너무 많이 넣지 마세요.
- 모든 커스텀 값이 채워진다고 가정하지 마세요.
- 값이 없을 때를 대비한 안내를 추가하세요.
- 말투는 자연스럽고 이해하기 쉽게 유지하세요.
- 긴 ID, 내부 코드, 기술적인 값을 에이전트가 읽게 하지 마세요.
- 비즈니스의 사실 정보는 프롬프트에 길게 넣지 말고 **지식 베이스**를 쓰세요.
- 값이 채워진 레코드와 값이 비어 있는 레코드로 모두 테스트하세요.
- 값을 넣은 뒤에는 문장 전체가 여전히 자연스러운지 프롬프트를 다시 확인하세요.

위험한 프롬프트 예시:

안녕하세요, `{{contact.first_name}}`님. `{{location.name}}`에서 `{{user.name}}`님과 `{{appointment.start_time}}`에 예약이 잡혀 있네요.

더 나은 프롬프트:

연락처의 이름과 예약 정보가 있으면 이를 자연스럽게 활용해 통화 상황을 확인하세요. 빠진 정보가 있으면 일반적인 인사로 이어 가세요.

## 커스텀 값 문제 해결

**커스텀 값** 문제는 대부분 레코드 데이터가 없거나, 값을 잘못 선택했거나, 지원하지 않는 필드에 넣었거나, 말로 했을 때 어색한 프롬프트 표현 때문에 생겨요. 아래 표에서 가장 흔한 원인을 확인해 보세요.

| 문제 | 확인할 내용 |
| --- | --- |
| 커스텀 값이 채워지지 않아요 | 선택한 값이 연락처, 계정, 예약 또는 관련 레코드에 있는지 확인하세요. |
| 에이전트가 병합 필드를 그대로 읽어요 | **커스텀 값** 메뉴에서 값을 넣었는지, 제대로 저장했는지 확인하세요. |
| 값이 비어 있어요 | 값이 없을 때 에이전트가 어떻게 해야 하는지 안내를 추가하세요. |
| 사용자에게 커스텀 값이 보이지 않아요 | 지원하는 프롬프트나 메시지 필드를 편집하고 있는지, 올바른 권한이 있는지 확인하세요. |
| 에이전트가 엉뚱한 때에 값을 사용해요 | 값을 언제 써야 하는지 앞뒤 맥락을 더 분명하게 쓰세요. |
| 테스트 통화가 예상과 달라요 | 프롬프트, 선택한 값, 통화 로그를 검토한 뒤 다시 테스트하세요. |

## 자주 묻는 질문

### 음성 AI 프롬프트의 커스텀 값이 뭔가요?
**커스텀 값**은 하이퍼클래스에 저장된 데이터를 지원하는 음성 AI 프롬프트나 메시지 필드에 넣는 동적 병합 필드예요.

### 현재 음성 AI 빌더에서 커스텀 값은 어디에서 찾나요?
음성 AI 에이전트를 열고 **빌드** 탭으로 이동하세요. 지원하는 프롬프트나 메시지 필드를 찾아 **커스텀 값**이나 커스텀 값 아이콘을 클릭하면 돼요.

### 환영 메시지에도 커스텀 값을 쓸 수 있나요?
**환영 메시지** 필드에 커스텀 값 아이콘이 보이면 쓸 수 있어요. 이 옵션이 있는 지원 필드에는 **커스텀 값**을 넣을 수 있어요.

### 커스텀 값이 비어 있으면 어떻게 되나요?
관련 레코드에 값이 없으면 예상대로 채워지지 않을 수 있어요. 에이전트가 자연스럽게 통화를 이어 갈 수 있도록 값이 없을 때를 대비한 안내를 추가하세요.

### 연락처 커스텀 필드도 쓸 수 있나요?
사용할 수 있는 필드는 **커스텀 값** 메뉴와 계정 설정에 따라 달라요. 검색창이나 카테고리에서 지원하는 값을 찾아보세요.

### 에이전트가 변수를 그대로 읽어요. 왜 그런가요?
값이 제대로 채워지지 않았거나, 잘못된 형식으로 직접 입력했거나, 해당 필드에서 지원하지 않는 값일 수 있어요. **커스텀 값** 메뉴에서 값을 넣고 다시 테스트해 보세요.

### 커스텀 값과 음성 AI 사용자 지정 액션은 같은 건가요?
아니에요. **커스텀 값**은 저장된 데이터를 프롬프트나 메시지 텍스트에 넣어요. **사용자 지정 액션**은 통화 중에 에이전트를 외부 시스템이나 워크플로우와 연결해요.

### 비즈니스 자주 묻는 질문에도 커스텀 값을 써야 하나요?
아니에요. 서비스, 가격, 정책, 자주 묻는 질문 같은 비즈니스 사실 정보는 **지식 베이스**를 쓰세요. **커스텀 값**은 레코드를 기반으로 한 동적 정보에 쓰세요.

### 커스텀 값을 추가한 뒤에도 테스트해야 하나요?
네. 값이 채워진 레코드와 비어 있는 레코드로 모두 테스트해서, 두 경우 모두 에이전트가 자연스럽게 말하는지 확인하세요.
