# AI로 워크플로우 커스텀 코드 만들기

**AI로 빌드하기**는 워크플로우의 **커스텀 코드** 액션에 들어갈 JavaScript를 쉬운 말로 설명해서 만들어 주는 기능이에요. 입력 속성을 추가하고 원하는 동작을 설명한 뒤, 생성된 코드를 검토하고 테스트해서 액션을 저장하면 돼요.

이 문서에서는 **AI로 빌드하기**를 안전하게 쓰는 방법과, 워크플로우를 게시하기 전에 생성된 코드를 테스트하는 방법을 설명해요.

[동영상](https://www.youtube.com/embed/62vB4utEb1M?&wmode=opaque)

## 워크플로우 커스텀 코드의 AI로 빌드하기란?

**AI로 빌드하기**는 **커스텀 코드** 액션 안에 있는 AI 코드 생성 옵션이에요. 입력한 프롬프트, 입력 속성, 원하는 출력을 바탕으로 JavaScript를 만들어 줘요.

데이터를 변환하거나, 값의 형식을 맞추거나, 결과를 계산하거나, API 요청을 준비할 때 쓰면 좋아요. 워크플로우 한 단계에 필요한 맞춤 로직도 만들 수 있어요. 다만 워크플로우 전체를 만들어 주지는 않아요. 워크플로우 전체를 AI로 만들거나 편집하려면 **Workflow AI Builder**(워크플로우 AI 빌더)를 사용하세요.

## AI로 코드를 만들면 좋은 점

**AI로 빌드하기**를 쓰면 워크플로우의 맞춤 로직을 더 빠르게 만들 수 있어요. 무엇을 저장하고 게시할지는 계속 직접 결정해요. 생성된 코드는 워크플로우를 실제로 쓰기 전에 꼭 검토하고 테스트하세요.

- 빠른 코드 작성: 쉬운 말로 설명하면 JavaScript를 만들어 줘요.
- 워크플로우 데이터 활용: 워크플로우의 입력 속성을 생성된 코드 안에서 쓸 수 있어요.
- 유연한 로직: 데이터 형식 맞추기, 값 계산, 조건 만들기, API 요청 준비를 할 수 있어요.
- 저장 전 검토: 액션에 쓰기 전에 생성된 코드를 살펴볼 수 있어요.
- 기본 제공 테스트: 워크플로우 액션을 저장하기 전에 코드를 테스트하고 출력을 확인할 수 있어요.
- 재사용 가능한 출력: 이후 워크플로우 액션이 참조할 수 있는 필드를 반환해요.

## 시작하기 전에

커스텀 코드는 워크플로우에서 데이터가 흐르는 방식에 영향을 줄 수 있어요. 코드를 만들거나 저장하기 전에 액션을 꼼꼼히 준비하세요. 프롬프트가 명확하고, 입력 속성이 맞고, 테스트가 성공하면 예상치 못한 동작을 막을 수 있어요.

**AI로 빌드하기**를 쓰기 전에 아래 내용을 확인하세요.

- 워크플로우를 만들거나 편집할 수 있어요.
- **커스텀 코드** 워크플로우 액션을 사용하고 있어요.
- 코드가 어떤 데이터를 써야 하는지 알고 있어요.
- 이후 워크플로우 액션에 필요한 출력 필드를 알고 있어요.
- 워크플로우를 게시하기 전에 생성된 코드를 검토하고 테스트할 거예요.
- **커스텀 코드** 액션은 프리미엄 워크플로우 액션이에요.

## AI로 빌드하기와 Workflow AI Builder의 차이

하이퍼클래스에는 워크플로우용 AI 도구가 여러 가지 있어요. 자동화 전체에 도움이 필요한지, 커스텀 코드 한 단계만 필요한지에 따라 알맞은 도구를 고르세요.

- 트리거, 액션, 전체 자동화 구조까지 포함해 워크플로우 전체를 AI로 만들거나 편집하려면 **Workflow AI Builder**를 쓰세요.
- 워크플로우 한 단계에 필요한 JavaScript만 만들려면 **커스텀 코드** 액션 안의 **AI로 빌드하기**를 쓰세요.

예를 들어 리드 후속 조치 워크플로우는 **Workflow AI Builder**로 만들 수 있어요. 그 워크플로우의 한 단계에서 전화번호 형식을 바꾸거나, 값을 계산하거나, 이메일 주소의 일부를 추출하거나, 다른 시스템에 보낼 데이터를 준비해야 한다면 **AI로 빌드하기**를 쓰세요.

## 커스텀 코드의 입력 속성

입력 속성을 쓰면 **커스텀 코드** 액션이 워크플로우의 값을 사용할 수 있어요. 입력 속성은 JavaScript가 실행될 때 참조할 수 있는 데이터를 정해요.

입력 속성은 키와 값으로 이루어져요. 키는 코드에서 쓰는 이름이고, 값은 그 키에 연결된 워크플로우 데이터예요.

코드 편집기에서는 입력 속성을 아래 두 형식 중 하나로 참조할 수 있어요.

```
inputData.keyName
```

또는

```
inputData['keyName']
```

예를 들어 키가 `email`인 입력 속성을 추가했다면 코드에서 이렇게 참조해요.

```
inputData.email
```

코드를 테스트하기 전에 필요한 입력 속성을 먼저 추가하세요. 생성된 코드가 엉뚱한 필드를 쓴다면 속성 키를 확인하고, 어떤 값을 써야 하는지 프롬프트에 분명하게 적었는지 살펴보세요.

스크린샷: **Property to include in code**(코드에 포함할 속성) 영역에 inputData 안내와 속성 추가 필드가 보이는 화면.

## 커스텀 코드 출력과 Reference output

**커스텀 코드** 액션은 JavaScript 객체나 객체 배열을 반환해야 해요. 반환된 값은 이후 워크플로우 액션이 참조할 수 있는 출력이 돼요.

예를 들면 다음과 같아요.

```
return {  emailDomain: domain,  formattedPhone: formattedPhone };
```

코드 테스트가 성공하면 **Reference output**(참조 출력)에서 사용할 수 있는 출력 필드를 확인하세요. 코드가 기대한 구조로 반환해야만 이후 워크플로우 액션에서 이 필드를 쓸 수 있어요.

출력과 관련해 알아 둘 점이에요.

- JavaScript 객체나 객체 배열을 반환하세요.
- 나중에 출력 필드를 참조할 수 있도록 코드를 테스트하세요.
- 전체 응답 크기는 2MB 미만으로 유지하세요.
- 테스트 후 **Reference output**에서 출력 구조를 확인하세요.

## 워크플로우에서 AI로 커스텀 코드 만들기

**AI로 빌드하기**는 워크플로우 빌더의 **커스텀 코드** 액션 안에 있어요. 필요한 JavaScript를 설명하고, 생성된 코드를 검토하고, 출력을 테스트한 뒤 액션을 저장하세요.

1. **자동화 > 워크플로우**로 이동하세요. 여기에서 워크플로우 자동화를 만들고, 편집하고, 테스트하고, 게시할 수 있어요.

2. 새 워크플로우를 만들거나 기존 워크플로우 초안을 여세요. 생성된 코드를 실험할 때는 테스트용 또는 초안 워크플로우를 쓰세요. 실제로 쓰기 전에 동작을 확인할 수 있어요.

   ![워크플로우 만들기 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155076684439/original/9GBvDPKkml420_z8-vg_pETwd4gVKjBNBg.png?1784806960)

3. **빌더** 탭에서 **Add first step**(첫 단계 추가)에 마우스를 올리고, 워크플로우에서 알맞은 위치의 **액션 추가**를 클릭하세요. 커스텀 로직을 실행할 위치에 맞춰 단계 위치를 고르세요.

   ![액션 추가 버튼](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155076685097/original/gu2leJCbj2bg6KoCN6Cew80kO19y07iSbg.png?1784807207)

4. 액션 패널에서 **커스텀 코드**를 검색하거나 선택하세요. 오른쪽 설정 패널에 액션이 열려요.

   ![커스텀 코드 액션 선택](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155076685404/original/-GPCtesMu1EcGU0sTCzNn0qp4mnsCnJcFg.png?1784807346)

5. **커스텀 코드** 액션 패널의 구성을 확인하세요. 패널에는 액션 이름, 언어 선택, 입력 속성, 코드 편집기, **AI로 빌드하기** 버튼, 테스트 도구, 참조 출력, 저장 버튼이 있어요. **커스텀 코드**가 프리미엄 액션이라는 표시도 보여요.

6. 액션 이름을 입력하세요. 코드가 하는 일을 알 수 있게 이름을 지으세요. 커스텀 코드 단계가 여러 개일 때 나중에 워크플로우를 검토하기 쉬워요.

   이름 예시:

   - 전화번호 형식 변환
   - 이메일 도메인 추출
   - 할인 금액 계산
   - API 전송 데이터 준비

   ![액션 이름 입력](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155076685630/original/Y-mghWWUZRWR7Ff11dcgogBrvBWx_LuSHw.png?1784807478)

7. **언어** 드롭다운이 **Javascript**로 되어 있는지 확인하세요. **커스텀 코드** 액션은 JavaScript로 코드를 생성해요.

   ![언어 선택](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155076685706/original/q2lMDzpudTrlWOc70YN-vfaBf2Th_mSanA.png?1784807533)

8. **Property to include in code**(코드에 포함할 속성)에서 JavaScript가 사용할 데이터를 추가하세요. 알아보기 쉬운 키 이름을 적고, 알맞은 워크플로우 값을 연결하세요.

   예를 들어 이런 키를 추가할 수 있어요.

   - `email`
   - `phone`
   - `amount`
   - `fullName`
   - `opportunityValue`

   그러면 코드에서 `inputData.email`, `inputData.phone`처럼 해당 키 이름으로 값을 참조할 수 있어요.

   ![코드에 포함할 속성 추가](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155076685816/original/xWXMKgef7keSDGmD8qhoRuWwcMQArWVbPg.png?1784807587)

9. **코드** 섹션에서 **AI로 빌드하기**를 클릭하세요. JavaScript를 생성하는 AI 프롬프트 화면이 열려요.

   ![AI로 빌드하기 클릭](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155076686281/original/PpHk7NY7wypLnzWpWnxoo6BOmISD9FXk7w.gif?1784807785)

10. 필요한 코드를 설명하는 프롬프트를 입력하세요. 코드가 무엇을 해야 하는지, 어떤 입력 속성을 쓸지, 어떤 출력 필드를 반환할지 분명하게 적어요.

    좋은 프롬프트에는 이런 내용이 들어가요.

    - 코드의 목표
    - 입력 속성 이름
    - 원하는 출력 필드 이름
    - 형식 규칙
    - 값이 없을 때의 대체 동작
    - API를 쓴다면 엔드포인트, 메서드, 헤더, 페이로드 정보
    - 도움이 된다면 입력 예시와 기대하는 출력 예시

    프롬프트 예시:

    `inputData.email`로 이메일 도메인을 추출해 주세요. 결과는 `emailDomain`으로 반환하세요. 이메일이 없거나 올바르지 않으면 빈 문자열을 반환하세요.

11. 생성된 JavaScript를 검토하세요. 쓰기 전에 코드의 로직이 요청과 맞는지, 입력 속성 키가 정확한지, 출력 필드가 이후 워크플로우 액션에 필요한 것과 일치하는지 확인하세요.

    확인할 항목:

    - 입력 속성 이름이 맞는지
    - 출력 필드 이름이 기대와 같은지
    - 계산이나 형식 변환이 정확한지
    - 값이 없는 경우를 안전하게 처리하는지
    - API 요청이라면 엔드포인트, 헤더, 페이로드가 맞는지

12. 필요하면 코드를 정리하세요. **Format code**(코드 서식 지정)를 누르면 코드 배치가 깔끔해져요. 읽고, 검토하고, 문제를 찾기가 쉬워져요.

    ![코드 서식 지정](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155076686436/original/vIsyCgsgAecf58YePXnFBMDZpcRHajQXYg.png?1784807888)

13. **Test your code**(코드 테스트)를 클릭해 코드가 정상 실행되는지 확인하세요. 워크플로우를 게시하기 전에 액션이 기대한 출력을 반환하는지 테스트로 확인할 수 있어요.

    화면 안내에 따르면 코드를 테스트할 때는 커스텀 값이 전달되지 않아요. 동작을 확인할 때는 알맞은 샘플 값이나 워크플로우 테스트 데이터를 쓰세요.

    ![코드 테스트 실행](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155076686713/original/2Zn44Hgrq0HX8fwUTlTqQOFtIho_Jnrl1Q.gif?1784808033)

14. 테스트 후 반환된 출력이 기대한 구조와 같은지 확인하세요. **Reference output**에서 이후 워크플로우 액션이 쓸 수 있는 필드를 확인하세요.

15. 생성된 코드를 검토하고 테스트했고 기대한 출력이 반환되면 **작업 저장**을 클릭하세요. 저장되지 않은 변경사항은 워크플로우에 반영되지 않을 수 있어요.

16. 워크플로우를 게시하거나 실제로 켜기 전에 전체 워크플로우를 테스트하세요. **커스텀 코드** 액션이 정상 실행되는지, 이후 액션이 기대한 출력을 받는지 확인하세요.

    오류, 누락된 값, 예상과 다른 동작이 있으면 **Execution logs**(실행 로그)나 워크플로우 테스트 결과로 원인을 찾아보세요.

## AI로 빌드하기 프롬프트 예시

프롬프트가 명확할수록 더 쓸모 있는 JavaScript가 만들어져요. 입력 속성 이름과 반환받고 싶은 출력 필드를 정확히 적으세요.

### 이메일 도메인 추출하기

`inputData.email`로 이메일 주소에서 도메인을 추출해 주세요. 결과는 `emailDomain`으로 반환하세요. 이메일이 없거나 올바르지 않으면 빈 문자열을 반환하세요.

### 전화번호 형식 바꾸기

`inputData.phone`의 전화번호를 미국 기준 E.164 형식으로 바꿔 주세요. 결과는 `formattedPhone`으로 반환하세요. 전화번호가 없거나 올바르지 않으면 빈 문자열을 반환하세요.

### 할인 금액 계산하기

`inputData.amount`로 15% 할인을 계산해 주세요. `discountAmount`와 `finalAmount`를 반환하세요. 금액이 없으면 두 값 모두 0으로 반환하세요.

### 전체 이름 나누기

`inputData.fullName`을 `firstName`과 `lastName`으로 나눠 주세요. 이름이 하나만 있으면 `firstName`으로 반환하고 `lastName`은 비워 두세요.

### API 요청 준비하기

`inputData.email`, `inputData.firstName`, `inputData.lastName`을 사용해 지정한 API 엔드포인트로 POST 요청을 보내 주세요. 응답 상태와 응답 ID를 각각 `status`와 `externalId`로 반환하세요.

## 게시하기 전에 AI가 만든 코드 검토하기

AI가 만든 코드는 워크플로우 설정을 빠르게 해 주지만, 실제 자동화에 쓰기 전에 검토해야 해요. 검토하면 데이터 형식 오류, API 호출 실패, 누락된 출력 필드, 예상치 못한 워크플로우 동작을 막을 수 있어요.

저장하거나 게시하기 전에 아래 내용을 확인하세요.

- 코드가 올바른 입력 속성 키를 쓰는지
- 값이 없거나 비어 있는 경우를 안전하게 처리하는지
- 출력 필드 이름이 명확하고 일관된지
- 계산, 날짜 처리, 형식 규칙이 맞는지
- API 엔드포인트, 메서드, 헤더, 인증, 페이로드가 맞는지
- 민감한 값을 코드에 직접 적지 않았는지(사용 환경에 맞는 경우는 예외)
- 이후 워크플로우 액션이 올바른 출력 필드를 참조하는지
- 샘플 레코드로 전체 워크플로우를 테스트했는지

## 생성된 코드 테스트와 문제 해결

테스트를 하면 실제 워크플로우 레코드에 영향을 주기 전에 **커스텀 코드** 액션이 제대로 작동하는지 확인할 수 있어요. 먼저 기본 제공 코드 테스트를 실행하고, 그다음 전체 워크플로우를 테스트하고 실행 결과를 확인하세요.

권장 테스트 순서예요.

- 샘플 입력 속성을 추가하거나 알맞은 워크플로우 테스트 데이터를 사용하세요.
- **Test your code**를 클릭하세요.
- 반환된 출력이 기대한 구조와 같은지 확인하세요.
- 테스트가 성공하면 **Reference output**을 확인하세요.
- **작업 저장**을 클릭하세요.
- 전체 워크플로우를 테스트하세요.
- 워크플로우가 기대대로 동작하지 않으면 **Execution logs**를 확인하세요.

## 자주 묻는 질문

### 커스텀 코드 액션의 AI로 빌드하기는 무엇인가요?
**AI로 빌드하기**는 **커스텀 코드** 워크플로우 액션 안에 있는 AI 옵션이에요. 쉬운 말로 쓴 프롬프트로 JavaScript를 만들어 줘요.

### AI로 빌드하기는 어디에서 찾나요?
**자동화 > 워크플로우**로 이동해 워크플로우를 열거나 새로 만드세요. **커스텀 코드** 액션을 추가한 뒤 **코드** 섹션에서 **AI로 빌드하기**를 클릭하면 돼요.

### AI로 빌드하기와 Workflow AI Builder는 같은 기능인가요?
아니요. **Workflow AI Builder**는 워크플로우 전체를 만들거나 편집해 줘요. **AI로 빌드하기**는 **커스텀 코드** 워크플로우 액션 하나에 쓸 JavaScript를 만들어 줘요.

### 커스텀 코드 액션은 어떤 언어를 쓰나요?
현재 **커스텀 코드** 액션은 **Javascript**를 사용해요.

### AI로 빌드하기에서 이전 워크플로우 단계의 데이터를 쓸 수 있나요?
네. 필요한 값을 입력 속성으로 추가한 다음, 코드에서 `inputData.keyName` 또는 `inputData['keyName']`으로 참조하세요.

### 코드는 무엇을 반환해야 하나요?
이후 워크플로우 액션이 출력을 참조할 수 있도록 JavaScript 객체나 객체 배열을 반환해야 해요.

### 이후 워크플로우 액션에서 출력이 보이지 않아요.
코드를 테스트해서 성공했는지, 기대한 출력 필드를 반환하는지 확인하세요.

### AI로 빌드하기로 API 요청도 만들 수 있나요?
네. 프롬프트에 엔드포인트, 메서드, 헤더, 인증 정보, 페이로드 요구 사항, 기대하는 응답 필드를 적어 주세요.

### AI가 만든 코드는 게시하기 전에 테스트해야 하나요?
네. 워크플로우를 게시하거나 실제로 쓰기 전에 생성된 코드와 전체 워크플로우를 항상 테스트하세요.

### 2MB 응답 제한은 무슨 뜻인가요?
**커스텀 코드** 액션이 반환하는 전체 응답은 2MB 미만이어야 해요.

### 코드를 테스트할 때 커스텀 값도 전달되나요?
화면 안내에 따르면 코드를 테스트할 때는 커스텀 값이 전달되지 않아요. 코드를 확인할 때는 알맞은 샘플 값이나 워크플로우 테스트 데이터를 쓰세요.

### 커스텀 코드 액션은 무료로 쓸 수 있나요?
현재 화면에서는 **커스텀 코드**를 프리미엄 액션으로 표시해요.
