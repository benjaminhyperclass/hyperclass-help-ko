# 전화 시스템 메시징 분석 개요

**메시징 분석**에서는 SMS 전달 현황, 실패 추이, 수신 거부, 오류 원인, 메시징 소스별 성과를 한 화면에서 확인할 수 있어요. 이 문서에서는 대시보드 지표와 필터, 추이 차트, 상세 로그, 사용 방법, 문제 해결 방법을 안내해요.

## 개요

**메시징 분석**은 서브 계정 전체의 SMS 성과를 한곳에서 보여 줘요. 새로 바뀐 화면에는 요약 지표, 이전 기간과의 비교, 실패 추이, 수신 거부 모니터링, 소스 필터, 상세 메시지 로그가 모두 들어 있어요.

전체 메시지 수만 보는 데서 그치지 않아요. 전달 성과가 언제 달라졌는지, 메시지가 왜 실패하는지 확인할 수 있어요. 상태와 오류 코드를 보면서 개별 메시지도 조사할 수 있어요.

{% hint style="warning" %}
대시보드의 실패율과 수신 거부율 기준선은 모니터링용 지표예요. [하이퍼클래스 전화 메시징 정책](../메시징/lc-phone-messaging-policy.md)에 따로 정해진 경고, 발송 한도, 제한 규칙을 대신하지 않아요.
{% endhint %}

## 메시징 분석이란?

**메시징 분석**은 하이퍼클래스 **전화 시스템** 안에 있는 리포팅 화면이에요. SMS 전달 성과, 수신 메시지 활동, 메시지 실패와 그 원인, 수신자의 수신 거부 행동을 파악할 수 있어요.

대시보드는 성과 요약 카드, 추이 차트, 메시지 단위 로그로 이루어져 있어요. 이전 기간과 성과를 비교하고, 갑작스러운 변화를 살펴보고, 발송 활동을 메시징 소스별로 좁혀 볼 수 있어요.

서브 계정 소유자, 관리자, 전달 성과를 모니터링하는 에이전시 팀에 특히 유용해요. 더 큰 규모의 메시징에 영향을 주기 전에 문제를 찾을 수 있어요.

### 메시징 분석의 주요 이점

**메시징 분석**은 메시지 활동 데이터를 실무에 쓸 수 있는 성과 신호로 바꿔 줘요. 이 신호를 정기적으로 확인하면 전달 문제를 더 빨리 찾고, 발신자 평판을 지키고, 메시징 방식을 개선할 수 있어요.

- 성과 한눈에 보기: 발송, 전달, 실패, 수신, 수신 거부 성과를 한 대시보드에서 확인해요.
- 추이 파악: 현재 성과를 이전 기간과 비교하고 일별 변화를 찾아요.
- 실패 원인 진단: 실패 사유와 메시지별 오류 코드로 전달을 막는 요인을 찾아요.
- 소스별 분석: 캠페인, 워크플로우, 대량 메시지의 발송 활동을 비교해요.
- 수신 거부 모니터링: 수신 거부 추이를 보면 수신자의 피로도나 동의 품질 문제를 짐작할 수 있어요.
- 빠른 문제 해결: 요약 지표를 클릭해 개별 메시지, 상태, 활동 날짜, 오류 코드를 확인해요.

### 메시징 분석 V2에서 달라진 점

새 **메시징 분석** 화면에는 이전의 단순 수치 화면에 없던 추이 분석과 진단 정보가 추가됐어요. 메시지가 몇 건 성공하거나 실패했는지뿐 아니라 성과가 언제, 왜 달라졌는지도 알 수 있어요.

| 영역 | 현재 화면 |
| --- | --- |
| 기본 조회 기간 | **최근 30일** |
| 최대 날짜 범위 | 최대 **90일** |
| 요약 지표 | **발송됨**, **전달됨**, **실패**, **수신됨**, **수신 거부율** |
| 성과 비교 | 요약 지표에 이전 기간 대비 비교 표시가 나와요. |
| 추이 분석 | **Failure Rate Trend**(실패율 추이)와 **Opt-Out Rate Trend**(수신 거부율 추이) 차트로 시간에 따른 성과 변화를 찾아요. |
| 실패 진단 | **Failure Reason Breakdown**(실패 사유 분석)이 주요 원인을 묶어 보여 줘서 영향이 큰 문제부터 살펴볼 수 있어요. |
| 상세 로그 | 요약 카드를 클릭하면 연락처, 전화번호, 상태, 활동 날짜, 오류 코드가 담긴 상세 메시지 로그가 열려요. |

오류 30007은 더 이상 별도의 최상위 요약 지표로 보이지 않아요. 통신사 필터링 오류와 그 밖의 실패 코드는 **실패** 메시지 상세, 실패 사유, 상세 메시지 로그에서 확인해요.

## 메시징 분석 대시보드 지표

요약 카드 5개는 선택한 조회 기간의 메시지 활동을 한눈에 보여 줘요. 각 카드를 클릭하면 메시지 단위로 더 자세히 살펴볼 수 있어요.

| 지표 | 의미 | 활용 방법 |
| --- | --- | --- |
| **발송됨** | 시스템이 발송을 시도한 메시지예요. | 발송량과 전달 성과를 평가하는 기준으로 쓰세요. |
| **전달됨** | 수신자에게 성공적으로 도착한 메시지예요. | 기간별, 메시징 소스별로 전달 성과를 비교하세요. |
| **실패** | 잘못된 번호, 통신사 필터링, 수신 거부, 규정 준수 제한 같은 문제로 전달되지 못한 메시지예요. | 카드를 클릭해 오류 코드와 실패 사유를 확인하고 근본 원인을 찾으세요. |
| **수신됨** | 연락처로부터 받은 수신 메시지와 답장이에요. | 발송 성과와 함께 수신 메시지 활동도 파악하세요. |
| **수신 거부율** | STOP 같은 수신 거부 키워드로 답장했거나 구독을 해지한 연락처의 비율이에요. | 수신자 피로도, 타기팅 문제, 동의 품질 문제를 짐작할 수 있는 변화를 모니터링하세요. |

### 이전 기간 대비 비교

요약 카드는 선택한 조회 기간을 바로 이전의 같은 기간과 비교해요. **녹색**과 **빨강** 표시로 좋아졌는지 나빠졌는지 보여 줘서, 차이를 직접 계산하지 않아도 이상한 변화를 확인할 수 있어요.

## 날짜 범위와 메시징 소스 필터

날짜와 소스 필터를 쓰면 계정 전체의 변화와 특정 메시징 활동에 따른 문제를 구분할 수 있어요. 먼저 전체 데이터를 보고, 캠페인·워크플로우·대량 메시지의 성과를 따로 보고 싶을 때 범위를 좁히세요.

### 날짜 범위

- 대시보드는 기본으로 **최근 30일**이 선택된 상태로 열려요.
- 더 넓은 추이를 분석하려면 조회 기간을 **최대 90일**까지 늘릴 수 있어요.

### 메시징 소스 필터

| 필터 | 용도 |
| --- | --- |
| **전체** | 지원하는 모든 소스의 메시징 성과를 봐요. |
| **캠페인** | 캠페인 활동과 관련된 메시지를 확인해요. |
| **워크플로우** | 워크플로우 자동화로 발송된 메시지를 확인해요. |
| **대량 요청** | 대량 메시지 작업으로 보낸 메시지를 확인해요. |

필터를 적용했더니 수신 거부율이 사라졌어요. 왜 그런가요? 수신 거부율은 수신 메시지의 수신 거부 활동을 기준으로 계산해요. 반면 **캠페인**, **워크플로우**, **대량 요청** 필터는 발송 소스를 따로 보여 줘요. 그래서 이 소스 필터를 적용하면 **수신 거부율**이 표시되지 않아요.

## 차트와 추이 보기

추이 차트는 성과가 언제 달라졌고 무엇이 메시지 실패에 영향을 주는지 요약 지표에 더해 보여 줘요. 급증한 시점을 찾고, 반복되는 문제를 가려내고, 개선 조치가 효과가 있는지 확인할 때 활용하세요.

### Failure Rate Trend

**Failure Rate Trend**는 시간에 따른 메시지 **실패율**을 보여 줘요. 막대 하나는 선택한 날짜 범위 안의 하루 실패율이에요. 갑자기 오른 날을 쉽게 찾을 수 있어요.

- 실패가 갑자기 늘어난 날을 찾아요.
- 선택한 기간 안에서 반복되는 패턴을 비교해요.
- 차트의 10% 기준선은 전달 성과를 더 자세히 살펴봐야 한다는 신호로 활용해요.

### Failure Reason Breakdown

**Failure Reason Breakdown**은 실패한 메시지를 유형별로 묶어서 각 원인이 전체 실패에서 차지하는 비율을 보여 줘요. 대표적인 예는 다음과 같아요.

- 인증되지 않은 수신자 부담(toll-free) 번호
- 잘못된 번호 또는 휴대전화가 아닌 번호
- 통신사 필터링 또는 통신사 보호 장치
- 국가 불일치 또는 라우팅 문제

### Opt-Out Rate Trend

**Opt-Out Rate Trend**는 수신자의 수신 거부 행동이 시간에 따라 어떻게 달라지는지 보여 줘요. 수신 거부율이 오르면 타기팅, 동의 품질, 메시지 발송 빈도, 내용을 점검해야 할 수 있어요.

이 차트에는 수신 거부가 높아졌는지 알려 주는 2% 기준 표시가 있어요.

기준선에는 맥락이 필요해요. 실패율 10%와 수신 거부율 2% 선은 분석용 참고 표시예요. 메시징 정책의 경고와 정지는 발송량, 램프 수준, 오류 건수, 수신 거부 성과 같은 요소를 바탕으로 한 별도 기준을 써요. 하이퍼클래스는 일반적으로 수신 거부율 약 0~1%를 양호한 수준으로 봐요.

## 상세 메시지 리포트

요약 지표는 무언가 달라졌다는 사실을 알려 주고, 상세 메시지 로그는 그 변화 뒤에 있는 개별 메시지를 보여 줘요. 로그를 통해 계정 단위 추이에서 특정 연락처, 상태, 활동 날짜, 오류 코드로 내려가 볼 수 있어요.

다음 요약 카드 중 하나를 클릭하세요.

- **발송됨**
- **전달됨**
- **실패**
- **수신됨**
- **수신 거부율**

상세 로그 창에는 다음 항목이 나와요.

| 항목 | 중요한 이유 |
| --- | --- |
| **연락처 이름** | 메시지와 연결된 연락처를 확인해요. |
| **전화번호** | 수신 번호별 문제나 번호 품질 문제를 찾는 데 도움이 돼요. |
| **상태** | 메시지의 전달 상태를 보여 줘요. |
| **활동 날짜** | 개별 메시지를 추이 차트의 급증 시점이나 변화와 연결해 줘요. |
| **오류 코드** | 전달 실패를 해결하는 데 필요한 기술적인 원인을 알려 줘요. |

## 메시징 분석 사용하기

다음 단계를 따라 **메시징 분석**에 들어가서 조회 기간과 필터를 조정하고, 대시보드 지표를 확인하고, 메시징 추이를 분석해 보세요.

### 1단계: 메뉴 위치

1. **설정**으로 이동하세요.
2. **전화 시스템**을 클릭하세요.
3. **메시지** 탭을 여세요.
4. **메시징 분석**을 선택하세요.

![전화 시스템에서 메시징 분석으로 이동하는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155068168666/original/GvUFw0WxkH98WgIVxOfruLIkUsbQf5Knag.png?1774969429)

### 2단계: 날짜 범위와 필터

- 기본 화면에는 **최근 30일**이 표시돼요. 이전에는 7일이었어요.
- 더 넓게 분석하려면 최대 **90일**까지 선택할 수 있어요.
- 필터를 사용해 데이터를 좁히고 보고 싶은 내용에 집중하세요.

![날짜 범위 선택기와 필터 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155068171110/original/w7naEokv3Zbu1NpTFoXBi4BYwGJswvdIHg.png?1774970532)

### 3단계: 대시보드 둘러보기

#### 성과 요약 카드

대시보드 맨 위에 핵심 지표 5개가 나와요.

| 지표 | 설명 |
| --- | --- |
| 발송됨 | 시스템이 발송을 시도한 전체 메시지 |
| 전달됨 | 수신자에게 성공적으로 도착한 메시지 |
| 실패 | 전달되지 못한 메시지(잘못된 번호, 통신사 필터링, 수신 거부, 규정 준수 문제) |
| 수신됨 | 연락처로부터 받은 수신 메시지와 답장 |
| 수신 거부율 | STOP이라고 답장했거나 구독을 해지한 연락처의 비율 |

#### 이전 기간 대비 비교

각 지표에는 이전 기간과의 비교(예: *vs last 30 days*)와 함께 다음 색상 표시가 나와요.

- **녹색** = 개선
- **빨강** = 하락

수동으로 분석하지 않아도 추이를 빠르게 파악할 수 있어요.

![이전 기간 대비 비교가 표시된 성과 요약 카드](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155068174878/original/34JPaXPJ1uTYUnpMjeKhV7aLBF5jqlIB3g.png?1774972424)

#### 메시지 상세 정보 확인하기

이제 모든 요약 카드를 클릭할 수 있어요. **발송됨**, **전달됨**, **실패**, **수신됨**, **수신 거부율**을 클릭하면 상세 로그 창이 열리고 다음 정보를 볼 수 있어요.

- 연락처 이름
- 전화번호
- 상태
- 활동 날짜
- 오류 코드(자세한 의미는 [자주 발생하는 SMS 전달 오류 이해하기](../메시징/understanding-common-sms-delivery-errors.md) 참고)

개별 메시지를 빠르게 조사하고 정확하게 문제를 해결할 수 있어요.

### 4단계: 차트와 추이 보기

#### 차트 1: Failure Rate Trend

**Failure Rate Trend** 차트는 메시지 **실패율**이 시간에 따라 어떻게 달라지는지 보여 줘요. 패턴과 잠재적인 문제를 빠르게 찾을 수 있어요. 막대 하나는 선택한 날짜 범위에서 특정 하루에 실패한 메시지의 비율이에요.

이 차트로 알 수 있는 내용은 다음과 같아요.

- 일별 성과 확인: 전체 평균에만 의존하지 않고 실패가 정확히 언제 발생했는지 볼 수 있어요.
- 급증과 패턴 파악: 갑자기 늘었다면 통신사 필터링, 잘못된 연락처 데이터, 규정 준수 문제를 의심해 볼 수 있어요.
- 일관성 모니터링: 비율이 꾸준하면 안정적이라는 뜻이고, 오르내리면 살펴봐야 할 문제가 있다는 신호일 수 있어요.

기준선 표시: 차트에는 10% 기준선이 빨간 점선으로 표시돼요.

- 10% **미만**이면 메시징 성과가 양호해요.
- 10%를 **넘으면** 통신사 제한이나 계정 제한을 받을 위험이 커져요.

{% hint style="warning" %}
이 기준을 반복해서 넘으면 발신자 평판에 나쁜 영향을 주고 메시징이 정지될 수 있어요.
{% endhint %}

![10% 기준선이 있는 Failure Rate Trend 차트](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155068174468/original/ufX_W0svVMX9nKHeQnnx44l_zQs5GVHDig.png?1774972215)

#### 차트 2: Failure Reason Breakdown

**Failure Reason Breakdown** 도넛 차트는 메시지가 실패한 이유를 보여 줘서, 전달에 영향을 주는 가장 흔한 문제를 한눈에 알 수 있어요. 각 구간은 특정 실패 사유와 그 비율이에요.

대표적인 실패 사유는 다음과 같아요.

- 인증되지 않은 수신자 부담(toll-free) 번호
- 잘못된 번호 또는 휴대전화가 아닌 번호
- 통신사 필터링 또는 보호 장치
- 국가 불일치 또는 라우팅 문제

각 사유가 이전 기간과 비교해 어떻게 달라졌는지도 볼 수 있어요.

![Failure Reason Breakdown 도넛 차트](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155068173839/original/YjS2AlyVj0OtOKmJk83dd4s9an_fcJwVxg.png?1774971987)

활용 방법은 다음과 같아요.

- 실패의 주요 원인을 확인하세요.
- 영향이 가장 큰 문제부터 해결하세요.
- 이전 기간과 비교하면서 개선 정도를 추적하세요.

짐작에 의존하지 않고 정확한 해결책을 찾을 수 있어서 전달 성과를 더 빨리 개선할 수 있어요.

#### 차트 3: Opt-Out Rate Trend

시간에 따라 메시지를 수신 거부하는 수신자가 얼마나 되는지 모니터링해요.

- 2% 기준 표시가 있어요.
- 건강한 참여율을 유지하는 데 도움이 돼요.
- 더 나은 메시징 방식과 규정 준수를 뒷받침해요.

![2% 기준 표시가 있는 Opt-Out Rate Trend 차트](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155068174611/original/e65hP80tLOaN7sW7sYomh7h8YDEOCo-kQw.png?1774972298)

## 메시징 분석으로 성과 개선하기

분석은 각 신호가 구체적인 조사나 개선 조치로 이어질 때 가장 유용해요. 먼저 달라진 추이를 확인하고, 그 뒤에 있는 메시지를 찾은 다음, 영향이 가장 큰 실패나 규정 준수 문제부터 해결하세요.

| 이런 현상이 보이면 | 다음에 할 일 |
| --- | --- |
| 실패율이 갑자기 올라요. | **Failure Reason Breakdown**을 확인한 뒤 **실패** 메시지 로그를 열어 가장 많이 나온 오류 코드를 살펴보세요. |
| 오류 30007이 자주 나와요. | 오류 30007은 통신사 필터링을 뜻해요. 메시지 내용, 발신자 정보, 동의, 통신사 규정 준수 요건을 점검하세요. 자세한 방법은 [통신사 SMS 필터링 방지하기: 오류 30007](../메시징/how-to-prevent-sms-filtering-by-carriers-error-30007.md)을 참고하세요. |
| 잘못된 번호나 휴대전화가 아닌 번호가 실패의 대부분이에요. | 목록 품질을 점검하고 SMS를 받을 수 없는 연락처를 제거하거나 수정하세요. |
| 수신 거부율이 올라요. | 동의 품질, 타기팅, 메시지 발송 빈도, 발신자 표시, 수신 거부 안내 문구를 점검하세요. |
| 특정 소스의 성과만 나빠요. | **캠페인**, **워크플로우**, **대량 요청**으로 필터링해서 해당 소스를 계정 전체 성과와 비교하세요. |
| 실패 추이나 수신 거부 추이가 계속 높아요. | 문제가 되는 메시징 활동을 일시 중지하거나 조정하세요. 대량 발송을 이어 가기 전에 [하이퍼클래스 전화 메시징 정책](../메시징/lc-phone-messaging-policy.md)도 확인하세요. |

## 메시징 분석 문제 해결

대부분의 분석 문제는 메시지 단위의 전달 문제를 살펴보기 전에 조회 기간을 확인하고 소스 필터를 해제하면 범위를 좁힐 수 있어요. SMS 전달 문제를 더 자세히 알아보려면 [SMS 전달 문제 해결](../troubleshooting-sms-delivery.md)도 참고하세요.

### 대시보드에 예상보다 활동이 적게 보여요

선택한 날짜 범위와 메시징 소스 필터를 확인하세요. 필터를 **전체**로 설정하고 필요하면 조회 기간을 늘려 보세요.

### 수신 거부율이 보이지 않아요

**캠페인**, **워크플로우**, **대량 요청** 같은 발송 소스 필터를 적용했을 때는 정상적인 동작이에요. 소스 필터를 **전체**로 되돌리면 전체 **수신 거부율**을 볼 수 있어요.

### 실패율이 높아요

먼저 **Failure Reason Breakdown**을 확인하세요. 그다음 **실패** 지표를 클릭해 개별 오류 코드를 살펴보세요. 재시도하거나 발송량을 늘리기 전에 가장 큰 실패 유형부터 해결하세요.

### 실패한 메시지에 오류 30007이 나와요

오류 30007은 통신사 필터링 응답이에요. 재시도하기 전에 메시지 내용, 동의, 발신자 정보, 등록 요건, 통신사 규정 준수 관행을 점검하세요. 규정 준수 설정은 [SMS 규정 준수 설정 구성하기](how-to-configure-sms-compliance-settings.md)에서 확인할 수 있어요.

### 실패 추이나 수신 거부 추이가 대시보드 기준선 위에 머물러요

기준선을 바로 조사해야 한다는 신호로 받아들이세요. 메시지 소스, 상세 오류 코드, 동의 관행, 목록 품질, 최신 [하이퍼클래스 전화 메시징 정책](../메시징/lc-phone-messaging-policy.md)을 점검하세요. 나쁜 성과가 반복되면 메시징 제한 위험이 커질 수 있어요.

## 자주 묻는 질문

### 메시징 분석은 기본으로 어떤 날짜 범위를 보여 주나요?

새 대시보드는 기본으로 최근 30일을 보여 줘요. 조회 기간은 최대 90일까지 늘릴 수 있어요.

### 캠페인이나 워크플로우로 필터링하면 수신 거부율이 왜 사라지나요?

수신 거부 활동은 수신 메시지를 기준으로 하고, **캠페인**, **워크플로우**, **대량 요청** 필터는 발송 소스를 따로 보여 주기 때문이에요. 이 소스 필터를 적용하는 동안에는 **수신 거부율**이 숨겨져요.

### 실패율이 10%가 되면 계정이 자동으로 정지되나요?

아니요. 10% 선은 실패가 높아졌음을 알려 주는 대시보드의 참고 표시예요. 메시징 정책의 경고와 정지는 발송량, 램프 수준, 오류 건수, 그 밖의 정책 요소에 따라 달라질 수 있는 별도의 기준을 써요.

### 수신 거부율 2% 표시는 무슨 뜻인가요?

수신 거부가 높아져서 살펴볼 필요가 있음을 알려 주는 표시예요. 하이퍼클래스는 일반적으로 약 0~1%를 양호한 수신 거부율로 봐요. 실제 메시징 정책 적용은 별도의 경고·정지 기준을 따라요.

### 메시징 분석 V2에서 오류 30007은 어디서 확인하나요?

오류 30007은 별도의 최상위 요약 카드가 아니라 실패한 메시지의 상세 정보와 오류 코드에서 확인해요. 이 오류는 내용, 발신자 정보, 규정 준수와 관련된 통신사 필터링을 뜻해요.

### 요약 지표를 클릭하면 어떤 정보가 나오나요?

상세 로그에는 연락처 이름, 전화번호, 메시지 상태, 활동 날짜, 해당하는 오류 코드가 표시될 수 있어요.
