# VoIP 데스크폰(SIP) 연결하기

호환되는 SIP 데스크폰을 하이퍼클래스에 연결하는 방법을 안내해요. 수신·발신 설정, 사용자 배정, 등록 테스트, 기기 관리, 통화 전환, 한쪽 방향으로만 통화가 되거나 소리가 안 들릴 때의 문제 해결까지 다뤄요.

## 개요

SIP를 사용하면 호환되는 VoIP 데스크폰을 하이퍼클래스에 연결할 수 있어요. 사용자는 일반 수화기로 업무 전화를 걸고 받으면서, 통화 기록은 CRM에 그대로 남길 수 있어요.

SIP 계정 정보를 입력하는 것만으로는 설정이 끝나지 않아요. 아래 조건이 모두 맞아야 해요.

- 데스크폰이 올바르게 등록되어야 해요.
- 배정된 하이퍼클래스 사용자가 데스크폰으로 통화를 받도록 설정되어야 해요.
- 필요한 경우 수신 라우팅이 그 사용자를 가리켜야 해요.
- 네트워크가 필요한 SIP·RTP 트래픽을 허용해야 해요.

이 문서에서는 기기 등록, 네트워크 요건, 사용자 라우팅, 테스트, 내선 번호 통화, 즉시 전환, 기기 관리를 다뤄요. 수신만 안 되는 경우와 발신만 안 되는 경우의 문제 해결도 따로 정리했어요.

{% hint style="info" %}
한쪽 방향으로만 통화가 되나요?
**수신은 되는데 발신이 안 되면** [수신 통화는 되지만 발신 통화가 안 될 때](#수신-통화는-되지만-발신-통화가-안-될-때)로 이동하세요. **발신은 되는데 데스크폰이 울리지 않으면** [발신 통화는 되지만 수신 통화가 울리지 않을 때](#발신-통화는-되지만-수신-통화가-울리지-않을-때)로 이동하세요.
{% endhint %}

## VoIP 데스크폰(SIP) 연동이란?

VoIP 데스크폰 연동을 쓰면 호환되는 오픈 SIP 수화기를 하이퍼클래스에 등록할 수 있어요. 사용자는 실물 전화기로 통화하면서 하이퍼클래스의 통화 라우팅과 CRM 기록을 그대로 이용해요.

데스크폰마다 SIP 도메인, SIP 사용자명(또는 내선 번호), 비밀번호, 배정된 하이퍼클래스 사용자가 설정돼요. 전화기가 정상적으로 등록되면, 하이퍼클래스는 사용자와 전화번호 설정에 따라 지원되는 통화를 데스크폰으로 연결해요.

통화 녹음과 통화 텍스트 변환 기능을 켜 두었다면 데스크폰 통화에도 그대로 적용돼요. 통화 텍스트 변환은 통화 녹음이 켜져 있어야 쓸 수 있고, 별도로 요금이 청구되는 Voice Intelligence(음성 인텔리전스) 기능이에요.

### 데스크폰을 쓰면 좋은 점

실물 데스크폰을 쓰면 익숙한 수화기로 통화하면서도 음성 활동을 하이퍼클래스 안에서 관리할 수 있어요. 전용 전화기를 선호하는 사무실 팀에게 특히 잘 맞아요.

- 수화기로 통화하기: 호환되는 SIP 데스크폰으로 하이퍼클래스 통화를 걸고 받을 수 있어요.
- CRM과 연결된 통화: 통화 기록이 하이퍼클래스 전화 시스템과 연락처 기록에 남아요.
- 사용자별 라우팅: SIP 기기를 하이퍼클래스 사용자에게 배정하고, 수신·Ring All(전체 연결)·IVR로 들어오는 통화를 어느 채널로 받을지 정할 수 있어요.
- 내선 번호 통화: 다른 데스크폰에 내선 번호로 바로 전화할 수 있어요.
- 데스크폰 간 통화 전환: 지원되는 통화를 다른 데스크폰 내선 번호로 즉시 전환할 수 있어요.
- 기본 제공 테스트: 하이퍼클래스의 **테스트 통화** 메뉴에서 발신 통화와 수신 벨 울림을 모두 확인한 뒤 실제로 쓸 수 있어요.

### VoIP 데스크폰 권한

데스크폰 설정은 전화 시스템의 인증 정보와 사용자 라우팅을 바꾸기 때문에, 관리자 역할에 따라 설정 권한이 달라요.

| 역할 | 권한 |
| --- | --- |
| **에이전시 관리자** | 에이전시 내 서브 계정 전체에서 지원되는 데스크폰을 설정할 수 있어요. |
| 서브 계정 관리자 | 자신이 관리하는 서브 계정 안에서 기기를 설정할 수 있어요. |
| 그 밖의 사용자 | 읽기 전용 액세스만 가능해요. 관리자에게 기기 구성을 요청하라는 안내가 표시될 수 있어요. |

## 기술 요건과 추천 데스크폰

오픈 SIP 기기를 고르고 네트워크를 알맞게 준비하면 등록 오류, 음성 문제, 한쪽 방향 통화 문제를 줄일 수 있어요. 실제로 쓸 기기를 설정하기 전에 아래 요건을 먼저 확인하세요.

### 네트워크·프로토콜 요건

| 요건 | 안내 |
| --- | --- |
| SIP 전송 방식 | UDP, TCP, TLS 기반 SIP를 지원해요. |
| SIP 시그널링 | 아웃바운드 포트 5060/5061을 허용하세요. |
| RTP 오디오 | UDP 10000–20000을 허용하세요. |
| SIP ALG | 등록, 음성, 통화 응답, 수신 통화에 문제가 생기면 SIP ALG를 끄세요. |
| 전원 | PoE를 지원하는 네트워크 연결이나 전화기에 맞는 외부 전원 어댑터를 사용하세요. |

{% hint style="warning" %}
문서에 안내된 아웃바운드 SIP 요건을 공개 포트 포워딩과 혼동하지 마세요. 하이퍼클래스가 안내하는 데스크폰 요건은 아웃바운드 SIP 포트 5060/5061과 RTP용 UDP 10000–20000이에요. 통화가 안 된다고 해서 SIP 포트를 공용 인터넷에 열거나 인바운드 포트 포워딩 규칙을 임의로 추가하지 마세요. 먼저 등록 상태, 하이퍼클래스 라우팅, Keep Alive(연결 유지), SIP ALG, 기기 설정을 확인하세요.
{% endhint %}

### 데스크폰을 고를 때 확인할 점

- 표준 오픈 SIP를 지원하는지 확인하세요.
- 사무실 네트워크가 PoE(Power over Ethernet)를 쓴다면 PoE를 지원하는지 확인하세요.
- 업무 방식에 도움이 된다면 프로그래밍 가능한 라인 키가 2개 이상인 모델이 좋아요.
- 통신사에 묶여 있거나 전용 프로비저닝만 지원해서 SIP 계정을 직접 설정할 수 없는 기기는 피하세요.

### 많이 쓰는 모델

- Yealink T54W / T58W
- Poly VVX 450
- Grandstream GXP 2170
- Snom D785
- Cisco 7841

{% hint style="info" %}
호환성 안내: 제조사마다 모델 메뉴, 항목 이름, 펌웨어 동작, SIP 계정 입력란이 달라요. 표준 SIP 등록을 지원하는 오픈 SIP 기기라면 대부분 쓸 수 있어요. 위 목록은 인증을 받은 전체 모델 목록이 아니에요.
{% endhint %}

## SIP 설정과 네트워크 요건

전화기마다 용어는 다르지만, 모든 기기에는 하이퍼클래스에서 생성한 SIP 서버 정보와 인증 정보를 입력해야 해요. 이 값이 정확히 같아야 등록과 발신이 정상 동작해요.

| 데스크폰 설정 | 입력하거나 확인할 내용 |
| --- | --- |
| Registrar / SIP Server / Server | 하이퍼클래스에서 생성된 SIP Domain / SIP Endpoint를 입력하세요. |
| 사용자명 / 내선 번호 / 사용자 ID | 하이퍼클래스에서 만든 SIP 사용자 또는 내선 번호를 그대로 입력하세요. 해당되는 경우 대소문자를 구분해요. |
| 비밀번호 | 하이퍼클래스에서 만든 SIP 사용자 비밀번호를 입력하세요. 저장된 비밀번호는 나중에 하이퍼클래스에서 다시 볼 수 없으니 안전하게 보관하세요. |
| 전송 방식 | 하이퍼클래스는 UDP, TCP, TLS 기반 SIP를 지원해요. 전화기와 네트워크가 사용하는 전송 방식을 허용해야 해요. |
| Keep Alive(연결 유지) | 수화기에 이 설정이 있다면 켜고 유형을 Options로 설정하세요. 발신은 되는데 수신이 안 될 때 특히 중요해요. |

{% hint style="info" %}
제조사마다 메뉴가 달라요. 데스크폰에 따라 Registrar, Server, Proxy, SIP URI, User ID, Authentication ID 같은 이름을 쓰기도 해요. 기기의 SIP 계정에는 하이퍼클래스에서 생성된 값을 입력하세요. 입력란이 나뉘어 있어서 헷갈리면 수화기 제조사의 설명서를 참고하세요.
{% endhint %}

## VoIP 데스크폰(SIP) 설정하기

SIP 인증 정보, 사용자 배정, 수신 라우팅, 실물 수화기가 모두 같은 설정을 가리키도록 순서대로 진행하세요. 실제 업무에 쓰기 전에 꼭 테스트하세요.

### 1단계: VoIP 데스크폰 설정 열기

1. 해당 서브 계정을 열어요.
2. **설정 > 전화번호**로 이동해요.
3. **고급 설정**을 열어요.
4. **VoIP 데스크폰(SIP)**을 선택해요.
5. **시작하기**를 클릭해요.

![전화 시스템 고급 설정에서 VoIP 데스크폰 SIP와 시작하기가 표시된 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155050093926/original/YS4668PA9CkKqvVzZi-iCSDpL4zwgmAVHw.png?1752866528)

**설정 > 전화번호 > 고급 설정 > VoIP 데스크폰(SIP)**을 열고 **시작하기**를 선택하세요.

### 2단계: SIP 도메인 설정하기

**SIP 설정**에서 추천된 **SIP Domain**(SIP 도메인) / **SIP Endpoint**(SIP 엔드포인트)를 확인해요. 저장하기 전에 조직에 맞는 접두어를 정해요.

{% hint style="warning" %}
SIP 도메인은 한 번만 설정할 수 있어요. 서버 구성을 저장하기 전에 꼼꼼히 확인하세요.
{% endhint %}

![SIP 서버 구성과 SIP 도메인이 표시된 SIP 설정 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155048947940/original/T_RoByQReSUzOcLWvCk_S-OlnygySLa2mg.png?1750964313)

**SIP 서버 구성**에서 실물 데스크폰을 등록할 때 쓰는 **SIP Domain** / **SIP Endpoint**가 만들어져요.

### 3단계: SIP 사용자 만들기

실물 전화기가 하이퍼클래스에 등록할 때 쓸 인증 정보를 만들어요.

- **내선 번호/사용자 이름**: 기기에서 쓸 SIP 사용자명이나 내선 번호를 만드세요.
- 내선 번호 형식 권장: 숫자 내선 번호는 3~5자리로 만드세요.
- 내선 번호 가이드: 0, 1, 9로 시작하지 않는 편이 좋아요. 배정된 사용자의 직통 번호 끝자리와 맞추는 것도 고려해 보세요.
- **비밀번호**: 안전한 SIP 비밀번호를 만들고 따로 보관하세요.

{% hint style="warning" %}
SIP 비밀번호는 지금 꼭 저장해 두세요. 하이퍼클래스는 저장된 비밀번호를 나중에 보여 주지 않아요. 비밀번호를 잃어버렸다면 **기기 관리**에서 재설정한 뒤, 실물 수화기에도 새 비밀번호를 입력하세요.
{% endhint %}

![새 SIP 사용자 만들기 화면의 내선 번호, 사용자 이름, 비밀번호 입력란](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155048947928/original/MgsSV8OV1wJbZoUkMb7urN7BZExwWyiLVQ.png?1750964269)

실물 전화기에 입력할 SIP 내선 번호(또는 사용자명)와 안전한 비밀번호를 만드세요.

### 4단계: SIP 기기를 하이퍼클래스 사용자에게 배정하기

**사용자에게 배정**에서 데스크폰을 쓸 팀원을 선택해 SIP 기기와 연결해요.

![사용자에게 배정 드롭다운이 표시된 SIP 설정 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155048947966/original/L3fI9Oggy2nZ9JE1bPLRwQdMYOycNEvsUw.png?1750964402)

수화기로 전화를 걸고 받을 하이퍼클래스 사용자에게 SIP 기기를 배정하세요.

### 5단계: 사용자의 수신 데스크폰 라우팅 설정하기

SIP 사용자를 만들면 기기가 등록되지만, 수신 통화는 배정된 사용자의 통화 라우팅 설정에 따라 연결돼요.

1. **설정 > 스태프 관리**로 이동해요.
2. 배정된 사용자를 편집해요.
3. **통화 및 음성메일 설정**을 열어요.
4. **착신 전환 대상**에서 직통 전화를 데스크폰으로 받으려면 **데스크폰(SIP)**을 켜요.
5. 공용 Ring All(전체 연결) 라우팅을 쓴다면, 필요에 따라 사용자의 **전체 연결 기본 채널**을 **데스크폰(SIP)**으로 선택해요.
6. IVR로 연결되는 통화를 데스크폰으로 받으려면, 사용자의 **IVR 기본 채널**을 **데스크폰(SIP)**으로 선택해요.

![데스크폰 SIP 착신 전환과 기본 채널이 표시된 사용자 통화 및 음성메일 설정 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155050752109/original/s6wUPXQfAjDIUvnnGnpzS6V7a2bKE_GdjA.png?1753979052)

직접 착신 전환, Ring All, IVR 등 사용자가 받아야 할 수신 경로마다 **데스크폰(SIP)**을 켜세요.

### 6단계: 실물 전화기 설정하기

수화기에서 SIP 계정 설정을 열고, 하이퍼클래스에서 생성된 SIP Domain, 사용자명(또는 내선 번호), 비밀번호를 입력해요. 서버 입력란은 제조사에 따라 Registrar, SIP Server, Server, Proxy 등으로 표시돼요.

전화기의 SIP 계정을 저장한 뒤, 통화를 테스트하기 전에 수화기에 **Registered**(등록됨) 또는 그와 같은 등록 성공 표시가 뜨는지 확인하세요.

### 7단계: 기본 제공 테스트 통화 실행하기

기본 제공 테스트를 쓰면 SIP 등록·네트워크 문제와 전화번호 라우팅 문제를 구분할 수 있어요.

1. **VoIP 데스크폰(SIP) > 테스트 통화**로 이동해요.
2. 테스트할 SIP 사용자를 선택해요.
3. 발신 테스트: 실물 데스크폰으로 화면에 표시된 테스트 번호에 전화를 걸어요. 테스트에 성공하면 확인 메시지가 재생돼요.
4. 수신 테스트: **Test Ring**(벨 울림 테스트) 버튼을 눌러 실물 데스크폰이 울리는지 확인해요.

![발신·수신 SIP 테스트를 할 수 있는 VoIP 데스크폰 테스트 통화 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155050094240/original/q3Ukfp7AIe5rXyIjZpLnTQqSp7uBWzIUUw.png?1752867440)

**테스트 통화** 화면에서 SIP 사용자의 발신 통화와 데스크폰의 테스트 벨 수신 여부를 확인할 수 있어요.

## SIP 기기 관리

**기기 관리**에서 관리자는 SIP 사용자의 비밀번호나 배정을 바꾸고, 더 이상 서브 계정에 등록하면 안 되는 기기를 삭제할 수 있어요.

### SIP 사용자 비밀번호 재설정하기

{% hint style="warning" %}
비밀번호를 바꾸면 등록에 영향을 줘요. 재설정한 뒤 실물 전화기에 새 SIP 비밀번호를 입력하지 않으면 인증에 실패해요.
{% endhint %}

{% hint style="warning" %}

## 데스크폰 간 통화와 전환

설정이 끝난 SIP 데스크폰끼리는 내선 번호로 내부 통화를 할 수 있어요. 외부 업무용 번호로 걸지 않고도 지원되는 즉시 전환 기능으로 데스크폰 사이에서 통화를 넘길 수 있어요.

### 내선 번호로 바로 걸기

설정된 다른 데스크폰에 전화하려면 그 데스크폰의 SIP 내선 번호를 누르세요. 예를 들어 팀원의 내선 번호가 201이라면 내 데스크폰에서 201을 누르면 돼요.

- 내선 통화에는 외부 전화번호가 필요 없어요.
- 두 데스크폰 모두 설정되어 있고 등록된 상태여야 해요.
- 내선 번호 직접 통화는 데스크폰 기능이에요.

### 데스크폰 간 즉시 전환

지원되는 통화 중에 데스크폰의 전환 기능을 시작하고, 받을 사용자의 내선 번호를 입력한 뒤 수화기 화면의 안내에 따라 전환을 마무리하세요.

1. 진행 중인 통화에서 전환을 시작해요.
2. 팀원의 SIP 내선 번호를 눌러요.
3. 수화기에서 전환을 완료해요.

![데스크폰 전환을 위해 내선 번호를 입력한 SIP 데스크폰 소프트웨어 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155065084807/original/hAOdaYjFSw10_XmuBQrArbP9dGoGJGH0Eg.png?1771329355)

전환을 시작할 때 받을 데스크폰의 내선 번호를 입력하세요.

![통화 중 전환 버튼이 표시된 SIP 전화 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155065084806/original/XqWn-AXejIHACYzbx0ChB_iERS33xnIURw.png?1771329355)

실물 전화기나 SIP 클라이언트의 전환 버튼으로 전환을 완료하세요.

{% hint style="info" %}
전환 제한: 실물 SIP 데스크폰은 현재 내선 번호 사이의 즉시 전환(blind transfer)만 지원해요. 데스크폰에서 안내 후 전환(warm transfer)은 아직 지원되지 않아요.
{% endhint %}

## 한쪽 방향 통화 문제 해결

한쪽 방향만 되면, 되는 쪽이 원인을 찾는 중요한 단서가 돼요. SIP 설정이나 방화벽 설정을 한꺼번에 바꾸지 말고, 증상에 맞는 아래 절차를 따라가세요.

### 수신 통화는 되지만 발신 통화가 안 될 때

데스크폰이 전화는 받는데 걸지 못한다면, SIP 계정, 아웃바운드 네트워크 접근, 하이퍼클래스의 기본 제공 발신 테스트부터 확인하세요.

1. SIP 계정이 등록되어 있는지 확인하세요.
   전화기에 Registered 또는 그와 같은 상태가 표시되어야 해요. 등록되지 않았다면 통화 라우팅을 확인하기 전에 SIP Domain, 사용자명(또는 내선 번호), 비밀번호부터 확인하세요.
2. 서버와 인증 정보가 정확한지 확인하세요.
   하이퍼클래스에서 생성된 SIP Domain을 기기의 Registrar / SIP Server에 입력하고, **SIP 설정**에서 만든 SIP 사용자명과 비밀번호를 정확히 입력하세요.
3. 안내된 아웃바운드 SIP 포트를 확인하세요.
   네트워크가 아웃바운드 SIP 시그널링 포트 5060/5061을 허용해야 해요.
4. RTP 오디오 범위를 확인하세요.
   RTP 오디오를 위해 UDP 10000–20000을 허용하세요. 통화는 연결되는데 소리가 없거나 한쪽만 들린다면 이 범위와 SIP ALG를 점검하세요.
5. SIP ALG를 확인하세요.
   라우터나 방화벽의 SIP ALG가 SIP 트래픽을 바꾸거나 등록·통화 응답·음성 문제를 일으킨다면 SIP ALG를 끄세요.
6. 기본 제공 발신 테스트를 실행하세요.
   **VoIP 데스크폰(SIP) > 테스트 통화**로 이동해 SIP 사용자를 선택하고, 실물 전화기로 화면에 표시된 발신 테스트 번호에 전화를 거세요.
7. 401 또는 403 오류가 나오면 인증 정보를 다시 확인하세요.
   이 오류는 대개 SIP 사용자명이나 비밀번호가 하이퍼클래스에 설정된 인증 정보와 맞지 않을 때 나타나요.
8. 기본 제공 발신 테스트가 계속 실패하면, 아래 [고객지원에 문의하기 전에 준비할 정보](#고객지원에-문의하기-전에-준비할-정보)를 모아 하이퍼클래스 고객지원에 문의하세요.

### 발신 통화는 되지만 수신 통화가 울리지 않을 때

발신이 된다면 보통 전화기가 등록되어 SIP 서비스에 연결된 상태예요. 수신이 안 될 때는 기기 테스트를 먼저 하고, 사용자 라우팅, 통화 흐름 우선순위, Keep Alive, 네트워크 동작을 차례로 확인하세요.

1. 하이퍼클래스 수신 테스트를 실행하세요.
   **VoIP 데스크폰(SIP) > 테스트 통화**를 열고 SIP 사용자를 선택한 뒤 수신 **Test Ring**(벨 울림 테스트)을 사용하세요.
2. 테스트 벨이 울리지 않으면 SIP 등록을 확인하세요.
   수화기가 아직 등록되어 있는지, SIP Domain, 사용자명, 비밀번호가 올바른지 확인하세요.
3. SIP 사용자가 올바른 하이퍼클래스 사용자에게 배정되어 있는지 확인하세요.
   **VoIP 데스크폰(SIP) > SIP 설정** 또는 **기기 관리**로 이동해 배정된 사용자를 확인하세요.
4. 사용자의 통화 및 음성메일 설정을 확인하세요.
   **설정 > 스태프 관리**에서 사용자를 편집한 뒤 **통화 및 음성메일 설정**으로 이동하세요. 데스크폰으로 직통 전화를 받아야 한다면 **착신 전환 대상**에서 **데스크폰(SIP)**을 켜세요.
5. Ring All과 IVR 채널을 확인하세요.
   Ring All을 통해 사용자에게 통화가 오면 **전체 연결 기본 채널**을 **데스크폰(SIP)**으로 선택하세요. IVR이 사용자에게 통화를 연결한다면 **IVR 기본 채널**을 **데스크폰(SIP)**으로 선택하세요.
6. 전화를 받은 전화번호의 수신 라우팅을 확인하세요.
   해당 사용자가 그 번호의 통화 흐름에 포함되어 있는지, 팀원 벨이 울리는 단계 전에 IVR이나 음성 AI 같은 다른 경로가 통화를 처리하고 있지 않은지 확인하세요.
7. SIP Keep Alive를 켜세요.
   수화기에 Keep Alive 설정이 있다면 켜고 Keep Alive Type을 Options로 설정하세요. 일부 기기에서는 **Account**(계정) > **Advanced**(고급) 아래에 있어요. 정확한 메뉴는 제조사와 펌웨어에 따라 달라요.
8. 문제가 계속되면 SIP ALG를 끄세요.
   SIP ALG는 일부 발신은 되는 상황에서도 SIP 등록과 수신 시그널링을 방해할 수 있어요.
9. 기본 제공 Test Ring과 실제 수신 통화를 다시 테스트하세요.
   기본 수신 테스트에서는 벨이 울리는데 공개 전화번호로 건 전화는 여전히 데스크폰에 연결되지 않는다면, 수화기 인증 정보를 바꾸지 말고 하이퍼클래스 수신 라우팅부터 점검하세요.

### 고객지원에 문의하기 전에 준비할 정보

- SIP Domain / SIP Endpoint
- SIP 내선 번호 또는 사용자명 (비밀번호는 보내지 마세요)
- 배정된 하이퍼클래스 사용자
- 데스크폰 제조사, 모델, 펌웨어 버전
- 수화기에 표시된 등록 상태
- 기본 제공 발신 테스트 결과
- 기본 제공 수신 Test Ring 결과
- 실패한 통화의 날짜, 시간, 시간대
- 발신 번호와 착신된 하이퍼클래스 번호
- 표시된 SIP 또는 테스트 통화 오류 코드
- 관련 하이퍼클래스 라우팅 설정 화면 캡처
- 네트워크에서 SIP ALG가 켜져 있는지 꺼져 있는지

## 추가 문제 해결

SIP 항목을 한꺼번에 바꾸지 말고 증상부터 확인하세요. 아래 표는 자주 생기는 데스크폰 문제별로 가장 먼저 살펴볼 설정이나 네트워크 영역을 정리한 거예요.

| 증상 | 가능성 높은 영역 | 확인할 내용 |
| --- | --- | --- |
| 401 / 403 Unauthorized | 인증 | SIP 사용자명과 비밀번호를 정확히 다시 입력하세요. 대소문자나 복사·붙여넣기 오류가 없는지 확인하세요. |
| 전화기가 등록되지 않아요 | SIP 서버, 인증 정보, 네트워크 | SIP Domain, 인증 정보, 전송 방식, 아웃바운드 5060/5061 접근, SIP ALG를 확인하세요. |
| 수신은 되는데 발신이 안 돼요 | 아웃바운드 SIP 시그널링 또는 인증 | 발신 테스트를 실행하고, 아웃바운드 5060/5061 접근, 인증 정보, 전송 방식, SIP ALG를 확인하세요. |
| 발신은 되는데 수신이 울리지 않아요 | 사용자 라우팅, Keep Alive, SIP ALG | Test Ring을 실행하고, 배정된 사용자, 데스크폰 라우팅, Ring All/IVR 채널, Keep Alive = Options, SIP ALG를 확인하세요. |
| 소리가 안 들리거나 한쪽만 들려요 | RTP / 방화벽 | UDP 10000–20000을 확인하고, SIP ALG가 미디어를 방해하면 끄세요. |
| 전화기는 울리는데 통화를 제대로 받을 수 없어요 | NAT / SIP ALG / 미디어 | SIP ALG를 끄고, 안내된 SIP·RTP 트래픽을 네트워크가 허용하는지 확인하세요. |
| 기본 Test Ring은 되는데 실제 수신 통화는 안 돼요 | 하이퍼클래스 수신 라우팅 | 전화번호 라우팅, 배정된 사용자, IVR/음성 AI, Ring All, 사용자의 데스크폰 채널을 확인하세요. |
| SIP 도메인을 저장할 수 없어요 | 도메인 구성 | 한 번만 가능한 설정을 완료하기 전에, 추천된 사용 가능한 도메인이나 사용 가능한 다른 이름을 입력하세요. |
| 비밀번호를 재설정한 뒤 전화기가 등록되지 않아요 | 수화기에 저장된 비밀번호 | 새로 저장한 SIP 비밀번호를 실물 수화기에 입력하세요. |

## 자주 묻는 질문

### 발신 통화가 안 될 때 어떤 포트가 필요한가요?

하이퍼클래스가 안내하는 데스크폰 요건은 아웃바운드 SIP 시그널링 포트 5060/5061과 RTP 오디오용 UDP 10000–20000이에요. 네트워크 규칙을 더 바꾸기 전에 SIP Domain, 사용자명/비밀번호, 등록 상태, SIP ALG도 먼저 확인하세요.

### 수신은 되는데 발신이 안 돼요. 무엇부터 확인하나요?

전화기가 등록되어 있는지 확인하세요. 그런 다음 하이퍼클래스 SIP Domain과 인증 정보를 확인하고, 아웃바운드 5060/5061 접근과 미디어용 UDP 10000–20000을 확인하세요. SIP ALG가 방해하면 끄고, 하이퍼클래스의 기본 제공 SIP 발신 테스트를 실행하세요.

### 발신은 되는데 수신 통화가 데스크폰에서 울리지 않아요. 무엇을 확인하나요?

기본 제공 수신 Test Ring을 실행하세요. SIP 사용자가 올바르게 배정되어 있는지 확인하고, 사용자의 **통화 및 음성메일 설정**에서 **데스크폰(SIP)**을 켜세요. Ring All 또는 IVR 채널 선택을 확인하고, 전화번호의 통화 흐름도 점검하세요. 수화기가 지원하면 Keep Alive를 켜고 유형을 Options로 설정하세요.

### 어떤 VoIP 데스크폰이 호환되나요?

표준 SIP 등록을 지원하는 오픈 SIP 전화기라면 대부분 쓸 수 있어요. 현재 하이퍼클래스가 안내하는 예시는 Yealink T54W/T58W, Poly VVX 450, Grandstream GXP 2170, Snom D785, Cisco 7841이에요.

### 기존 PBX와 SIP 트렁킹을 연결할 수 있나요?

아니요. 실물 데스크폰 기능은 개별 SIP 엔드포인트를 설정하는 기능이에요. Asterisk 같은 기존 PBX를 연결하는 SIP 트렁킹은 현재 지원하지 않아요.

### 데스크폰 통화도 자동으로 녹음되고 텍스트로 변환되나요?

녹음과 텍스트 변환은 하이퍼클래스 음성 구성에 따라 달라요. 텍스트 변환은 통화 녹음이 켜져 있어야 쓸 수 있고, 유료 Voice Intelligence 기능이에요. 녹음을 켜기 전에 해당되는 녹음 동의 요건을 확인하세요.

### 실물 데스크폰을 쓰는 데 비용이 없나요?

**전화 시스템**을 통해 걸거나 받은 통화는 해당 음성 요금에 따라 청구돼요. 통화 녹음, 녹음 저장, 텍스트 변환 같은 선택 서비스는 사용 요금이 추가될 수 있어요. 최신 요금은 전화 시스템 요금 및 청구 가이드를 확인하세요.

### 실물 데스크폰에서 안내 후 전환(warm transfer)을 할 수 있나요?

지금은 할 수 없어요. 실물 SIP 데스크폰은 설정된 다른 데스크폰 내선 번호로 하는 즉시 전환만 지원해요. 안내 후 전환은 대신 지원되는 웹 다이얼러 워크플로우에서 쓸 수 있어요.

### 데스크폰의 기본 음성메일 버튼으로 하이퍼클래스 음성메일을 열 수 있나요?

아니요. 수화기 자체의 음성메일 기능은 하이퍼클래스 음성메일과 별개예요. 하이퍼클래스 음성메일과 관련 통화 기록은 하이퍼클래스의 **대화**, 음성메일, **리포팅** 화면에서 확인하세요.
