# 전화번호 변경 보안 알림과 되돌리기

사용자의 전화번호가 추가되거나 바뀌면 보안 알림이 전송돼요. 기존 전화번호가 바뀐 경우에는 알림의 되돌리기 링크로 이전 번호를 직접 복원할 수 있어요. 예상치 못한 변경이 생겼을 때 확인하고 대응하는 방법을 안내해요.

전화번호는 로그인 보안 코드나 2단계 인증(2FA) 코드를 받는 데 쓰일 수 있어서 계정 보안에 중요한 정보예요. 하이퍼클래스는 전화번호가 추가되거나 바뀔 때 보안 알림을 먼저 보내서, 예상 밖의 변경을 빨리 알아챌 수 있게 해요. 또 기존 번호가 바뀐 경우, 대상이 되는 알림에는 이전 번호를 직접 복원할 수 있는 안전한 링크가 들어 있어요. 이 기능으로 보안에 민감한 프로필 변경을 더 잘 파악하고 직접 대응할 수 있어요.

## 전화번호 변경 보안 알림과 되돌리기란?

전화번호 변경 보안 알림은 하이퍼클래스에서 전화번호가 추가되거나 바뀔 때 해당 사용자에게 보내는 알림이에요. 알림을 보면 변경이 예상한 것인지, 본인이 했는지 관리자가 했는지 확인할 수 있어요. 기존 전화번호가 바뀐 경우에는 알림에 1회용 되돌리기 링크가 들어 있어요. 이 링크를 쓰면 로그인하지 않아도 이전 번호를 복원할 수 있어요.

전화번호는 본인 확인과 계정 접근에 쓰일 수 있어서 보안에 민감해요. 하이퍼클래스는 민감한 사용자 계정 변경에 대해 별도의 인증 절차도 적용하고 있어요. 이 알림은 변경이 이뤄진 뒤 한 겹 더 확인할 수 있게 해 주는 장치예요.

전화번호가 추가되거나 바뀌면 해당 사용자는 지원되는 알림 채널로 보안 알림을 받아요.

![전화번호 변경 보안 알림 예시 2](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155081732211/original/hpr1R2IZPWRCNKhLohoC3noqRjHQ485lgg.png?1790240660)

전화번호가 바뀌면 다음 알림이 갈 수 있어요.

- 이메일 알림
- 앱 내 알림
- 이전 전화번호로 보내는 SMS 알림

알림에는 다음 내용이 담겨 있어요.

- 어떤 정보가 바뀌었는지
- 변경이 언제 일어났는지(사용자의 시간대 기준으로 표시)
- 변경을 **본인이** 했는지 **관리자가** 했는지
- 예상하지 못한 변경이었을 때 해야 할 일

## 주요 이점

전화번호 보안 알림을 받으면 인증과 계정 접근에 영향을 줄 수 있는 정보가 바뀌었다는 사실을 바로 알 수 있어요. 기존 번호가 예상치 못하게 바뀌었을 때도 관리자나 고객지원에 의존하는 일이 줄어요.

- **즉시 확인:** 전화번호가 추가되거나 바뀌면 사용자에게 먼저 알려 줘요.
- **여러 알림 채널:** 이메일, 앱 내 알림으로 받을 수 있고, 전화번호가 바뀐 경우에는 이전 번호로 SMS도 받아요.
- **변경 주체 확인:** 본인이 바꿨는지 관리자가 바꿨는지 알 수 있어요.
- **직접 복구:** 예상치 못한 전화번호 변경은 1회용 링크로 되돌릴 수 있어요.
- **로그인 불필요:** 변경 때문에 평소의 인증 방식을 쓰기 어려워도 이전 전화번호를 복원할 수 있어요.
- **기간 제한 보호:** 되돌리기 링크는 7일 동안 유효해요.
- **화이트라벨 지원:** 보안 알림에는 플랫폼 기본 브랜딩이 아닌 에이전시의 브랜딩과 도메인이 쓰여요.
- **감사 가능:** 전화번호 되돌리기는 기록으로 남아서 보안에 민감한 활동을 추적할 수 있어요.

## 전화번호 보안 알림이 전송되는 방식

보안 알림은 계정 정보가 바뀐 당사자가 민감한 전화번호 변경을 알 수 있게 해 줘요. 알림 방식은 번호를 처음 추가하는지, 기존 번호를 바꾸는지에 따라 달라요.

사용자의 전화번호가 추가되거나 바뀌면 하이퍼클래스는 해당 사용자에게 보안 알림을 만들어요.

기존 전화번호가 바뀐 경우에는 다음과 같이 처리돼요.

- 이메일로 보안 알림이 전송돼요.
- 앱 내 보안 알림이 생성돼요.
- **이전 전화번호**로 SMS 보안 알림이 전송돼요.
- 알림에서 변경이 언제, 어떻게 일어났는지 확인할 수 있어요.
- 필요하면 이전 전화번호를 복원할 수 있도록 되돌리기 링크가 들어 있어요.

이전 번호로 SMS를 보내는 것은 특히 중요해요. 그 번호를 쓰던 사람이 예상치 못한 변경을 알아채고 대응할 기회가 되기 때문이에요.

예상한 변경이라면 따로 할 일은 없어요.

## 관리자가 전화번호를 바꾼 경우

관리자가 바꾼 경우에도 사용자가 직접 바꾼 경우와 같은 보안 알림이 가요. 관리자가 대신 보안에 민감한 프로필 정보를 수정해도 사용자가 그 사실을 알 수 있어요.

하이퍼클래스는 에이전시와 서브 계정 두 단계에서 사용자 관리를 지원해요. 에이전시 사용자는 **에이전시 보기 > 설정 > 팀**에서, 서브 계정 사용자는 **서브 계정 > 설정 > 스태프 관리**에서 관리할 수 있어요. 기존 사용자 관리 기능으로 권한이 있는 사용자는 전화번호 같은 프로필 정보를 수정할 수 있어요. 자세한 내용은 [사용자 접근 권한](../../11-설정/user-access.md) 문서를 참고하세요.

관리자가 다른 사용자의 전화번호를 바꾸면 보안 알림에 **관리자가** 변경한 것으로 표시돼요.

그래서 알림을 받은 사용자는 관리자가 바꾼 것인지 본인이 직접 바꾼 것인지 구분할 수 있어요.

보안 알림은 사용자를 대신해 전화번호가 바뀌는 관리자 대리 접속과 사용자 관리 흐름 중 지원되는 경우에도 적용돼요.

## 예상치 못한 전화번호 변경 되돌리기

기존 전화번호가 예상치 못하게 바뀌었다면 되돌리기 링크로 바로 복구할 수 있어요. 되돌리기에는 하이퍼클래스 로그인이 필요 없어요. 바뀐 번호 때문에 평소의 인증 절차를 쓰기 어려운 경우에도 대응할 수 있어요.

대상이 되는 보안 알림에는 각각 **1회용 되돌리기 링크**가 들어 있어요.

이 링크는 다음과 같아요.

- **7일** 동안 유효해요.
- 한 번만 사용할 수 있어요.
- 로그인하지 않아도 돼요.
- 이전 전화번호를 복원해요.
- 되돌리기가 끝나면 확인 화면을 보여 줘요.

전화번호 변경이 예상한 것이라면 따로 할 일은 없어요.

예상치 못한 변경이라면 다음 순서로 진행하세요.

1. 보안 알림을 엽니다.
2. 변경 상세 정보에서 전화번호가 언제 바뀌었는지, 누가 변경했는지 확인합니다.
3. 알림에 있는 되돌리기 링크를 클릭합니다.
4. 하이퍼클래스가 이전 전화번호를 복원합니다.
5. 확인 화면에서 되돌리기가 끝났는지 확인합니다.

## 화이트라벨 에이전시의 보안 알림

화이트라벨 보안 알림은 에이전시의 브랜드 경험을 지키면서 계정 보안에 중요한 정보를 전달해요. 사용자는 관련 없는 플랫폼 브랜딩 대신 에이전시의 브랜딩과 도메인으로 보안 알림을 받아요.

전화번호 변경 알림은 화이트라벨에 맞게 다음을 사용해요.

- 에이전시 로고
- 에이전시 도메인
- 에이전시 브랜딩

화이트라벨 에이전시 환경에서 전달되는 알림에는 플랫폼 제공사의 브랜드 이름이 표시되지 않아요.

그래서 에이전시는 고객에게 일관된 경험을 주면서 보안 알림도 전달할 수 있어요.

## 전화번호 변경과 2단계 인증

전화번호 변경 알림은 보안에 민감한 변경이 일어난 뒤 이를 알려 줘서, 기존 계정 인증 장치를 보완해요. 전화번호는 인증 코드를 받는 데 쓰일 수 있으니, 예상치 못한 전화번호 알림은 가볍게 넘기지 마세요.

하이퍼클래스는 계정 접근과 인증 과정에서 전화 기반 보안 코드를 지원해요. 로그인에 SMS 보안 코드가 필요하다면 관리자가 사용자의 전화번호를 추가해야 한다고 [로그인 문제 해결](../../11-설정/troubleshooting-login-issues.md) 문서에서도 안내하고 있어요.

전화번호 보안 알림과 되돌리기는 전화번호가 바뀐 뒤 한 겹 더 보호하기 위한 기능이에요. 계정 관리 과정에서 쓰는 다른 본인 확인이나 2단계 인증 보호 장치를 대체하지는 않아요.

전화번호 변경이 예상한 것이라면 알림을 변경 확인으로 보면 돼요. 예상치 못한 것이라면 링크가 유효한 동안 되돌리기 링크를 쓸 수 있어요.

## 전화번호 되돌리기 기록 확인

보안에 민감한 계정 활동을 기록해 두면 에이전시가 예상치 못한 변경을 조사하고 책임 소재를 가릴 수 있어요. 하이퍼클래스는 전화번호 되돌리기를 기록해서 계정의 보안 이력으로 추적할 수 있게 해요.

**감사 로그**에는 지원되는 계정 활동이 시간순으로 기록되고, 사용자·모듈·작업·변경 내용 같은 정보가 들어갈 수 있어요. 감사 로그는 에이전시와 서브 계정에서 모두 볼 수 있고, 볼 수 있는 범위는 활동이 일어난 위치에 따라 달라요. 자세한 내용은 [감사 로그](../../11-설정/audit-logs.md) 문서를 참고하세요.

보안 복구 과정에서 이뤄진 전화번호 되돌리기는 모두 기록돼요. 계정 변경을 전반적으로 조사할 때는 권한이 있는 사용자가 다음 위치에서 감사 로그를 볼 수 있어요.

- 에이전시: **설정 > 감사 로그**
- 서브 계정: **설정 > 감사 로그**

사용자, 모듈, 작업 유형, 기간 같은 조건으로 감사 로그를 필터링할 수도 있어요. 단, 해당 필터가 제공되는 경우에 한해요.

![감사 로그 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155081733561/original/AD6uz-ngAGV1tI7aXTeJIB6dcfdr-KdL8Q.png?1790241232)

## 보안 알림을 받았을 때 대응하기

보안 알림에 어떻게 대응할지 알아 두면 정상적인 계정 관리와 예상치 못한 변경을 구분할 수 있어요. 되돌리기 링크는 유효 기간이 있으니 알림을 빨리 확인하는 것이 특히 중요해요.

### 본인이 변경했거나 변경을 예상한 경우

1. 전화번호 보안 알림을 엽니다.
2. 변경 상세 정보를 확인합니다.
3. 변경 시각과 변경 주체가 예상한 것과 맞는지 확인합니다.
4. 더 할 일은 없어요.

### 변경을 예상하지 못한 경우

1. 가능한 한 빨리 보안 알림을 엽니다.
2. 본인이 승인하지 않은 전화번호 변경인지 확인합니다.
3. 알림에 변경 주체가 **본인이**로 표시됐는지 **관리자가**로 표시됐는지 확인합니다.
4. 1회용 되돌리기 링크를 클릭합니다.
5. 처음 변경한 때로부터 **7일** 안에 되돌리기를 마칩니다.
6. 확인 화면에서 이전 전화번호가 복원되었는지 확인합니다.
7. 다른 계정 보안 설정도 점검하고, 예상치 못한 변경을 조사하는 데 도움이 필요하면 에이전시 관리자에게 문의하세요.

## 자주 묻는 질문

### 전화번호 보안 알림을 받으면 꼭 뭔가 해야 하나요?

아니요. 전화번호 변경을 알고 있었고 예상한 일이라면 따로 할 일은 없어요. 알림은 변경이 이뤄졌다는 확인 역할을 해요.

### 되돌리기 링크는 얼마나 유효한가요?

1회용 되돌리기 링크는 7일 동안 유효해요.

### 변경을 되돌리려면 하이퍼클래스에 로그인해야 하나요?

아니요. 되돌리기 링크로 로그인 없이 이전 전화번호를 복원할 수 있어요.

### 같은 되돌리기 링크를 여러 번 쓸 수 있나요?

아니요. 되돌리기 링크는 1회용이에요.

### 왜 이전 전화번호로 SMS가 오나요?

기존 전화번호가 바뀌면, 그 보안 채널을 더는 쓰지 못하게 되는 사람에게 알려 주기 위해 이전 번호로 알림을 보내요.

### 제가 전화번호를 바꿨는지 관리자가 바꿨는지 알 수 있나요?

네. 보안 알림에 변경 주체가 **본인이** 또는 **관리자가**로 표시돼요.

### 화이트라벨 에이전시인데 알림에 플랫폼 브랜딩이 보이나요?

아니요. 화이트라벨 환경에서는 에이전시의 브랜딩과 도메인을 쓰도록 만들어져 있어요.

### 되돌리기 링크가 만료됐어요. 어떻게 하나요?
