# 워크플로우 트리거 — Call Details(통화 상세정보)

**Call Details**(통화 상세정보) 트리거를 쓰면 통화 방향, 통화 결과, 전화번호, 번호 풀, 사용자 지정 처리 결과에 맞춰 후속 작업을 자동으로 실행할 수 있어요. 부재중 통화 후속 조치, 음성 메시지 처리, 영업 콜백, 내부 알림 같은 통화 기반 업무를 자동화할 때 사용하세요.

## Call Details 워크플로우 트리거란?

**Call Details**(통화 상세정보)는 이벤트 기반 워크플로우 트리거예요. 통화 기록이 설정한 조건과 맞으면 연락처를 워크플로우에 등록해요. 통화를 하나씩 확인하고 다음 작업을 직접 정할 필요 없이, 하이퍼클래스가 통화 정보를 판단해서 알맞은 워크플로우를 자동으로 시작해요.

이 트리거는 통화 방향, 통화 상태, 관련 전화번호, 연결된 번호 풀, 사용자 지정 처리 결과를 확인할 수 있어요. 이 조건들을 함께 쓰면 특정 통화 상황에 맞는 자동화를 만들 수 있어요.

{% hint style="info" %}
예시: **수신** 통화의 상태가 **busy**, **voicemail**, **no-answer** 중 하나일 때만 연락처를 등록하는 워크플로우를 만들 수 있어요. 이 워크플로우는 내부 알림을 보내거나, 콜백 작업을 만들거나, 태그를 붙이거나, 다른 후속 시퀀스를 시작할 수 있어요.
{% endhint %}

## Call Details 트리거의 장점

통화 기반 자동화를 쓰면 통화 기록을 하루 종일 지켜보지 않아도 팀이 일관되게 대응할 수 있어요. 필터를 세밀하게 설정하면 통화 상황을 구분해서 알맞은 후속 조치를 자동으로 적용할 수 있어요.

- 자동 후속 조치: 조건에 맞는 통화가 발생하면 콜백, 알림, 작업, 태그 지정, 메시지 발송을 시작해요.
- 정밀한 통화 선별: 통화 방향, 상태, 전화번호, 번호 풀, 사용자 지정 처리 결과로 등록 대상을 좁혀요.
- 일관된 대응: 부재중 통화, 음성 메시지, 그 밖에 설정한 통화 결과가 생길 때마다 같은 방식으로 대응해요.
- 수동 확인 최소화: 통화 기록을 직접 확인하는 대신 워크플로우가 조건에 맞는 통화 이벤트에 반응해요.
- 유연한 영업·지원 자동화: 인바운드 리드, 아웃바운드 영업 통화, 부재중 통화, 콜백 요청 등에 맞춰 워크플로우를 따로 만들 수 있어요.

## Call Details 트리거가 작동하는 방식

조건에 맞는 통화는 트리거에 설정한 필터와 하나씩 비교해요. 필터 종류를 더 추가하면 연락처가 워크플로우에 들어가기 위해 통화가 충족해야 할 조건이 더 좁아져요.

1. 통화가 발생해요 — 하이퍼클래스가 통화와 확인 가능한 통화 상세정보를 기록해요.
2. 트리거 필터를 확인해요 — 통화 방향, 통화 상태, 번호 풀, 사용자 지정 처리 결과, 전화번호 등 설정한 조건과 통화를 비교해요.
3. 연락처가 조건을 충족해요 — 트리거 조건을 만족하고 워크플로우의 등록 규칙도 허용하면 연락처가 워크플로우에 들어가요.
4. 워크플로우 액션이 실행돼요 — 메시지 발송, 작업 만들기, 사용자 알림, 기록 업데이트, 태그 지정 등 설정한 액션이 실행돼요.

### Call Status와 Custom Disposition의 차이

두 필터는 서로 다른 종류의 통화 정보를 나타내요. 알맞은 필터를 골라야 워크플로우가 엉뚱한 결과 데이터를 기준으로 동작하지 않아요.

| 필터 | 나타내는 정보 | 예시 |
| --- | --- | --- |
| **Call Status**(통화 상태) | 시스템이 기록한 통화 결과 | busy, voicemail, no-answer, completed |
| **Custom Disposition**(사용자 지정 처리 상태) | 통화 후 선택한, 직접 정의한 분류 | 후속 연락 필요, 적합, 부재중, 음성 메시지, 콜백 요청 |

{% hint style="warning" %}
사용자 지정 처리 결과는 시스템의 Call Status 값과 별개예요. 상담원이 직접 선택한 통화 결과에 반응하는 자동화를 만들려면 예전 방식의 수동 통화 상태 동작에 의존하지 말고 **Custom Disposition** 필터를 사용하세요.
{% endhint %}

## 사용할 수 있는 Call Details 필터

필터는 워크플로우에 들어올 통화를 정해요. 정상적인 통화가 의도치 않게 제외되지 않도록 자동화에 꼭 필요한 조건만 사용하세요.

| 필터 | 용도 | 예시 |
| --- | --- | --- |
| **Call Direction**(통화 방향) | 수신 통화와 발신 통화를 구분해요. | Incoming |
| **Call Status** | 선택한 시스템 통화 결과와 일치하는 통화를 찾아요. | busy, voicemail, no-answer |
| **In Number Pool**(번호 풀 포함) | 선택한 번호 풀과 연결된 통화로만 트리거를 제한해요. | 유료 검색 추적 풀 |
| **Custom Disposition** | 통화 후 기록한 분류와 일치하는 통화를 찾아요. | 부재중, 음성 메시지 |
| **In Phone Number**(전화번호 포함) | 선택한 전화번호 하나 이상으로 트리거를 제한해요. | 대표 영업 번호 |

{% hint style="info" %}
필터 예시: **Call Direction = Incoming**이고 Call Status에 **busy, voicemail, no-answer**를 포함했다면, 통화가 수신 통화이면서 선택한 통화 상태 중 하나와 일치해야 트리거 조건을 충족해요.
{% endhint %}

## Call Details 워크플로우 트리거 설정하기

트리거를 제대로 설정하면 자동화하려는 통화 상황에서만 연락처가 워크플로우에 들어가요. 워크플로우 빌더에서 트리거를 만들고 필요한 통화 필터를 설정한 다음, 게시하기 전에 워크플로우를 테스트하세요.

### 1단계: 워크플로우 열기 또는 만들기

**자동화 > 워크플로우**로 이동해요. 기존 워크플로우를 열거나 **Create Workflow**(워크플로우 만들기)를 클릭한 다음 **처음부터 시작**을 선택해 새 자동화를 만드세요.

![워크플로우 목록에서 처음부터 시작 선택](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155080157480/original/hZk_OT9HooyMYEF2E4juLiYTlg1JRARYTQ.png?1788561508)

### 2단계: Call Details 트리거 추가하기

워크플로우 빌더에서 **Add New Trigger**(새 트리거 추가)를 클릭해요. **Events**(이벤트) 트리거 카테고리에서 **Call Details**를 선택하세요.

![트리거 목록에서 Call Details 선택](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155080157484/original/fu4JTHxJv3347mT-F-ErBw34qOLo_wc6sA.png?1788561528)

### 3단계: 트리거 이름 정하기

알아보기 쉬운 **Workflow Trigger Name**(트리거 이름)을 입력해요. 이름은 트리거가 실행되는 방식에는 영향을 주지 않아요. 다만 이름이 분명하면 워크플로우를 이해하고 관리하기 쉬워요.

예를 들어 "수신 부재중 통화", "음성 메시지 후속 조치", "통화 상태 변경" 같은 이름을 쓸 수 있어요.

![트리거 이름 입력](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155080157487/original/YdRmOoa1UB30C3NsD-BX4gz-QlphziS9-Q.jpeg?1788561538)

### 4단계: Call Direction 설정하기

워크플로우를 수신 통화나 발신 통화에만 적용하려면 **Call Direction** 필터를 추가하세요. 인바운드 후속 조치와 아웃바운드 영업 프로세스에 서로 다른 자동화가 필요할 때 특히 유용해요.

![Call Direction 필터 설정](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155080157488/original/Focb0LsQfpxO3tc14w2cbYVkwzOTxOacrw.png?1788561550)

### 5단계: Call Status 설정하기

**Call Status**로 조건에 해당하는 시스템 통화 결과를 선택해요. **busy**, **voicemail**, **no-answer** 등 필요한 결과를 고르면 돼요.

![Call Status 필터 설정](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155080157495/original/gjZzcW4OR_J9nDFeOqdJznCNHDQUgM-NIQ.png?1788561561)

### 6단계: 필요하면 번호 풀 필터 추가하기

특정 통화 추적 번호 풀에 속한 통화에만 자동화를 적용하려면 **In Number Pool**을 사용하세요. 캠페인, 유입 경로, 추적 설정별로 자동화를 나눌 수 있어요.

번호 풀을 만들고 관리하는 방법은 [통화 추적(번호 풀) 설정하기](how-to-set-up-call-tracking-number-pool.md)를 참고하세요.

### 7단계: 필요하면 Custom Disposition 필터 추가하기

통화 후 분류에 따라 워크플로우가 반응해야 하면 **Custom Disposition**을 선택하세요. 부재중, 음성 메시지, 후속 연락 필요 등 계정에 설정한 처리 결과를 고를 수 있어요.

![Custom Disposition 필터 설정](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155080157501/original/xUIFiFbgHZx9V5RgfhO8F5r5osgB10WmqA.png?1788561574)

처리 결과를 만들고 사용하는 방법은 [음성 통화의 사용자 지정 처리 결과](../LC-Phone/custom-dispositions-for-voice-calls.md)를 참고하세요.

### 8단계: 필요하면 전화번호로 트리거 제한하기

선택한 전화번호와 연결된 통화에만 워크플로우를 적용하려면 **In Phone Number**를 사용하세요. 업무용 회선마다 다른 통화 자동화가 필요할 때 유용해요.

![In Phone Number 필터 설정](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155080157506/original/lqqrxafBaTe6L5-QZpS2eLj5IHkc4BOMqA.png?1788561588)

### 9단계: 저장하고 테스트한 뒤 게시하기

필요한 필터를 설정했으면 트리거를 저장해요. 등록 후 실행할 워크플로우 액션을 추가하고, 워크플로우 테스트 도구와 대표적인 통화 상황으로 자동화가 의도대로 동작하는지 확인하세요.

테스트를 마쳤으면 워크플로우를 **Draft**(임시 저장)에서 **Publish**(게시)로 바꿔요. 그러면 조건에 맞는 실제 통화로 연락처가 등록돼요.

## 활용 예시

통화 후 무엇을 해야 하는지에 따라 알맞은 트리거 설정이 달라져요. 아래 예시는 통화 정보를 맞춤 후속 자동화로 바꾸는 방법을 보여 줘요.

| 상황 | 트리거 설정 예시 | 실행할 수 있는 액션 |
| --- | --- | --- |
| 부재중 수신 통화 | Direction = Incoming, Status = busy 또는 no-answer | 팀 알림, 콜백 작업 만들기, 후속 메시지 보내기 |
| 음성 메시지 후속 조치 | Status = voicemail | 담당 사용자에게 알림 보내기 또는 후속 작업 만들기 |
| 처리 결과 기반 영업 후속 조치 | Custom Disposition = 후속 연락 필요 또는 콜백 요청 | 작업 만들기, 기회 이동, 후속 메시지 보내기 |
| 캠페인별 통화 | In Number Pool = 선택한 추적 풀 | 캠페인별 태그 지정 또는 내부 라우팅 |
| 전용 업무 회선 | In Phone Number = 선택한 회선 | 해당 부서나 회선 전용 워크플로우 실행 |

## 테스트와 문제 해결

조건에 맞는 통화인데 기대한 자동화가 실행되지 않으면 트리거 조건과 워크플로우의 등록 설정을 모두 확인하세요. 실제 통화 기록을 트리거에 설정한 모든 필터와 비교하면 대부분의 문제를 찾을 수 있어요.

1. 워크플로우가 게시되었는지 확인하세요. 임시 저장 상태의 워크플로우는 게시된 자동화처럼 실시간 트리거 이벤트를 처리하지 않아요.
2. 통화를 트리거의 모든 필터와 비교하세요. 통화 방향, 상태, 번호 풀, 전화번호, 처리 결과 값을 해당되는 대로 확인하세요.
3. 사용자 지정 처리 결과 사용 여부를 확인하세요. 처리 결과 기반 트리거는 기대한 처리 결과가 통화에 실제로 기록되어 있어야 작동해요.
4. **Allow Re-entry**(재진입 허용)를 확인하세요. 조건에 맞는 새 통화가 생겨도 연락처가 자동으로 다시 등록되는 것은 아니에요. 완료했거나 수동으로 제거된 연락처가 다시 들어올 수 있는지는 워크플로우 설정이 정해요.
5. 연락처가 이미 워크플로우에서 진행 중인지 확인하세요. 일반적인 재진입 동작에서는 연락처가 같은 워크플로우에서 진행 중인 동안에는 다시 들어갈 수 없어요.
6. **Enrollment History**(등록 이력)와 **Execution Logs**(실행 로그)를 확인하세요. 이 탭에서 연락처가 워크플로우에 들어왔는지, 이후 액션이 건너뛰어졌거나 실패했는지 알 수 있어요.
7. 필요하면 트리거를 단순하게 만들어 테스트하세요. 불필요한 필터를 잠시 빼서 어떤 조건 때문에 대상이 되지 않는지 찾은 다음, 필요한 필터를 다시 설정하세요.

**Completed** 상태를 사용하나요? 자동화가 **Completed** 상태를 실제 사람과 연결된 통화로 간주해야 한다면 [통화 연결로 정확한 통화 상태 추적하기](../using-call-connect-to-ensure-accurate-call-status-tracking.md)를 확인하세요. **통화 연결**을 사용하면 리포팅과 자동화에 쓰는 통화 결과의 정확도를 높일 수 있어요.
{% endhint %}

{% hint style="info" %}
재진입: 반복 등록 동작을 확인하려면 워크플로우의 **Settings**(설정) 탭을 열고 **Allow Re-entry**를 확인하세요. 현재 재진입 규칙은 [워크플로우 설정 개요](../../07-워크플로우/빌더/workflow-settings-overview.md)를 참고하세요.
{% endhint %}

## 자주 묻는 질문

### Call Details 트리거는 모든 전화에 작동하나요?
아니요. 통화가 트리거에 설정한 조건과 맞아야 해요. 통화 방향, 통화 상태, 전화번호, 번호 풀, 사용자 지정 처리 결과 같은 필터를 추가하면 대상 통화가 좁혀져요.

### 같은 연락처가 Call Details 워크플로우에 여러 번 들어올 수 있나요?
이후에 조건에 맞는 통화가 생기면 또 다른 트리거 이벤트가 만들어질 수 있어요. 다만 다시 등록되는지는 워크플로우의 **Allow Re-entry** 설정에 따라 달라요. 재진입을 켜 두면 워크플로우를 완료했거나 수동으로 제거된 연락처가 다시 들어올 수 있어요. 같은 워크플로우에서 진행 중인 연락처는 보통 다시 들어올 수 없어요.

### Call Status와 Custom Disposition은 어떻게 다른가요?
Call Status는 busy, voicemail, no-answer, completed처럼 시스템이 기록한 결과예요. Custom Disposition은 후속 연락 필요, 적합, 콜백 요청처럼 팀에 맞게 설정한 통화 후 분류예요.

### 통화 상태를 여러 개 선택할 수 있나요?
네. Call Status 필터에서 busy, voicemail, no-answer처럼 해당하는 값을 여러 개 선택할 수 있어요. 다른 필터 행은 전체 트리거 조건을 계속 좁혀요.

### Custom Disposition 워크플로우가 실행되지 않아요.
기대한 처리 결과가 통화에 실제로 기록되었는지, 그리고 계정에 그 처리 결과가 아직 있는지 확인하세요. 워크플로우에서 쓰던 처리 결과가 삭제되었다면 필터를 유효한 처리 결과로 바꾼 뒤 다시 테스트하세요.

### 통화 하나가 여러 워크플로우의 대상이 될 수 있나요?
네. 워크플로우마다 자기 트리거 설정을 따로 판단해요. 통화가 각 워크플로우의 조건을 충족하고 연락처 등록 규칙도 허용하면 둘 이상의 워크플로우에 해당할 수 있어요.

### In Number Pool과 In Phone Number는 어떻게 다른가요?
In Number Pool은 선택한 통화 추적 번호 풀과 연결된 통화를 대상으로 해요. In Phone Number는 특정 전화번호 하나 이상을 대상으로 해요. 계정에서 통화 유입을 정리한 방식에 맞는 필터를 고르세요.

### 트리거는 맞게 설정한 것 같은데 워크플로우가 실행되지 않아요.
워크플로우가 게시되었는지 확인하고, 연락처의 **Enrollment History**를 살펴보세요. 그다음 **Execution Logs**를 확인하고, 해당되면 **Allow Re-entry**도 확인하세요. 마지막으로 실제 통화 데이터를 트리거에 설정한 모든 필터와 비교하세요.
