# 카운트다운 타이머의 코드 복사 기능 사용하기

**코드 복사**를 쓰면 카운트다운 타이머를 웹사이트나 이메일에 넣을 수 있는 코드를 받을 수 있어요. 이 문서에서는 타이머를 만들고 코드를 복사하는 방법과 정렬, 동적 타이머 설정 방법을 안내해요.

카운트다운 타이머는 특별 할인, 행사, 상품 출시까지 남은 시간을 보여 줘서 고객이 빠르게 행동하도록 도와줘요.

## 코드 복사란?

**코드 복사**는 카운트다운 타이머를 다른 플랫폼(웹사이트, 이메일, 다른 빌더 등)에 삽입할 때 쓰는 기능이에요. 이럴 때 사용해요.

1. 하이퍼클래스가 아닌 웹사이트
   - 웹페이지에 카운트다운 타이머를 보여 주고 싶을 때 **코드 복사**로 코드 조각을 받아요. 이 코드를 웹사이트 HTML에 바로 붙여 넣으면 돼요.
   - 기간이 정해진 오퍼, 행사 카운트다운, 상품 출시를 알릴 때 유용해요.
2. 하이퍼클래스가 아닌 이메일
   - 이메일 캠페인을 보낼 때 **코드 복사**로 받은 타이머 코드를 이메일 HTML에 넣을 수 있어요.
   - 받는 사람이 이메일 안에서 바로 카운트다운을 볼 수 있어서 긴박감을 줄 수 있어요.

## 카운트다운 타이머 유형

카운트다운 타이머는 세 가지 유형이 있어요.

- **고정**: 항상 같은 시각에 끝나는 타이머예요. endDate가 필요해요.
- **반복**: 카운트다운이 끝나면 새 시간으로 갱신되어 다시 카운트다운하는 타이머예요. startDate, duration(기간), 반복 횟수(loop count)가 필요해요.
- **동적**: 타이머를 보는 사람마다 마감 시각이 다를 수 있는 타이머예요. uniqueID와 duration(기간)이 필요해요. startDate는 각 사람이 타이머를 시작한 시점에 따라 정해져요.

## 코드를 수정해야 하나요?

| 타이머를 어디에 쓰나요? | startDate=…를 수정해야 하나요? | uniqueID=…를 수정해야 하나요? | 이유 |
| --- | --- | --- | --- |
| 웹사이트 또는 랜딩 페이지(어떤 빌더든) | 아니요. 코드 조각을 그대로 붙여 넣으세요. | 선택 사항이에요. 페이지 단위 분석이 필요하지 않다면 기본값을 그대로 두세요. | 모든 방문자가 같은 마감 시각을 봐요. |
| 정적 이메일(모두에게 같은 마감 시각) | 네. 자리 표시자를 이메일을 보내는 시각으로 바꾸세요(예: 2025‑01‑01T15:30:00Z). | 삭제하거나 무시하세요. 모두 같은 마감 시각을 공유하므로 고유값이 필요 없어요. |  |
| 하이퍼클래스의 동적 이메일(연락처마다 마감 시각이 다름) | 네. 머지 필드 {{right\_now.date\_time\_iso}}로 바꾸세요. | 기본값 {{contact.id}}를 그대로 두거나, 원하면 다른 연락처 필드로 바꾸세요. | 하이퍼클래스가 발송 시점에 이 머지 태그를 채워 줘서 연락처마다 각자의 시계가 만들어져요. |
| 다른 플랫폼의 동적 이메일(예: Mailchimp, HubSpot) | 네. 해당 플랫폼의 '현재 날짜·시간' 머지 태그를 쓰세요(예: `\*NOW\*`). |  |  |

```
핵심 개념:

정적 타이머 = 모두가 같은 마감 시각을 공유하는 타이머

동적 타이머 = 받는 사람마다 마감 시각을 따로 계산하는 타이머.
그래서 개인별 startDate와 개인별 uniqueID가 모두 필요해요.

startDate는 스톱워치를 시작하는 신호예요. 빌더가 '지금'을 자동으로 계산하지 못하면, '지금'이 언제인지 타이머에 직접 알려 줘야 해요.

uniqueID는 스톱워치의 일련번호예요. 이 값이 있어야 모든 받는 사람에게 같은 이미지가 캐시되어 보이는 일을 막을 수 있어요.
```

## 카운트다운 타이머 코드 복사하기

1. **마케팅 > 카운트다운 타이머**로 이동해서 **만들기**로 새 타이머를 만들거나, 기존 타이머를 **편집**하세요.

   ![카운트다운 타이머 목록 화면](https://jumpshare.com/share/rhDnyJHB66lTPazoxTNU+/Screen+Shot+2026-10-21+at+19.58.32.png)
2. 종료 날짜와 시간, 모양, 형식(일, 시간, 분, 초)을 골라 카운트다운 타이머를 설정하세요. 설정이 끝나면 다음 단계로 넘어가세요.
3. **코드 복사** 버튼을 클릭해서 코드를 받으세요.

   ![코드 복사 버튼](https://jumpshare.com/share/ZME83n85awDkHuCHMIzQ+/Screen+Shot+2026-10-21+at+20.00.29.png)
4. 코드를 쓸 곳에 맞춰 **이메일** 또는 **웹사이트**를 선택하고, 타이머의 **Alignment**(정렬)도 고르세요. 페이지나 이메일 디자인에 어울리는 정렬을 선택하면 돼요.

   ![이메일 또는 웹사이트 선택과 정렬 설정](https://jumpshare.com/share/HC57lWWHuJXNnRMFbHJe+/Universal+Agency+Inc+2026-10-21+at+20.13.59.png)
5. (선택) 동적 타이머라면 중괄호 안의 `contact.id`를 알맞은 고유 ID로 바꿔서 사용자마다 다른 카운트다운이 보이게 하세요(예: contactID, userID). 이렇게 하면 사람마다 맞춤 타이머를 볼 수 있어요.

   예시: 강조 표시된 부분을 바꿔야 해요. 고유 ID가 contact.no라면 다음과 같이 써요.

   `...............uniqueID={{contact.no}}&.......`

   ![고유 ID 수정 예시](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083883604/original/RyDiw950Fa6KqGWBJdu4A20vHHD2-6hX6Q.png?1792593946)
6. 빌더의 코드 조각 블록에 타이머를 쓸 때는 시작 날짜(startDate) 필드가 필수예요. <!-- 검토 필요: 원문 내용이 서로 다름 (위 표에서는 웹사이트·랜딩 페이지에서 startDate를 수정하지 않아도 된다고 안내) -->

   하이퍼클래스 이메일 빌더 밖의 이메일에서 코드를 복사했다면, 이메일을 열었는지 클릭했는지와 상관없이 이메일을 보낸 날짜를 넣어야 해요. 이메일을 2025년 1월 1일 오후 3시 30분에 보냈다면, `startDate=YYYY-MM-DDTHH:mm:ss.sssZ`를 `startDate=2025-01-01T15:30:00:00`으로 바꾸면 돼요. <!-- 검토 필요: 원문 내용이 서로 다름 (위 표의 예시는 2025‑01‑01T15:30:00Z 형식) -->

   하이퍼클래스 이메일 빌더 안에서 동적 타이머 코드를 복사했다면, `startDate=YYYY-MM-DDTHH:mm:ss.sssZ`를 `startDate={{right_now.date_time_iso}}`로 바꾸세요.

## 문제 해결 체크리스트

**타이머가 시작되지 않아요** → startDate에 실제 ISO 날짜 또는 {{merge.tag}}처럼 올바른 머지 태그가 들어 있는지 확인하세요.

**모든 사람에게 같은 시간이 보여요** → uniqueID가 받는 사람마다 다른지 확인하세요. 직접 입력한 고정값이 아니라 머지 태그여야 해요.

**시간대가 달라요** → 입력한 날짜가 Z(UTC)로 끝나거나 ‑05:00 같은 시간대 오프셋을 포함하는지 확인하세요.

## 자주 묻는 질문

### 하이퍼클래스 웹사이트에 삽입할 때도 코드를 바꿔야 하나요?

아니요. 모든 방문자가 같은 마감 시각을 공유하므로 기본 코드 조각을 그대로 쓰면 돼요.

### 고유 ID는 정말 선택 사항인가요?

정적 타이머에서만 선택 사항이에요. 동적 타이머에는 꼭 필요해요. 없으면 모든 받는 사람이 같은 캐시된 이미지를 보게 돼요.

### 보내기 전에 동적 이메일 타이머를 테스트할 수 있나요?

네. 자신에게 테스트 이메일을 보내 보세요. 머지 태그가 내 연락처 정보로 채워져서, 실제 받는 사람이 보는 화면을 그대로 확인할 수 있어요.

### 하이퍼클래스의 이메일·사이트 빌더 안에서도 코드 복사를 써야 하나요?

하이퍼클래스 빌더 안에서는 코드 복사가 필요 없어요. 카운트다운 타이머를 바로 삽입하면 돼요.
