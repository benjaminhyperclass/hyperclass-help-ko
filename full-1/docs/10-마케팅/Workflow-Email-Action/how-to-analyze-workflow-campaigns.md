# 워크플로우 캠페인 성과 분석

워크플로우로 자동 발송한 이메일의 성과를 확인하는 방법을 설명해요. 전달, 열람, 클릭, 답장 같은 참여 지표를 보면 자동화 단계마다 연락처가 이메일에 어떻게 반응하는지 알 수 있어요. 하이퍼클래스는 여러 가지 리포트 화면을 제공해요. 워크플로우 이메일끼리 성과를 비교하고, 이메일 액션 하나하나를 살펴보면서 개선할 부분을 찾아보세요.

## 워크플로우 캠페인이란?

워크플로우 캠페인은 하이퍼클래스 워크플로우의 이메일 액션으로 발송한 이메일을 말해요. 자동 발송 시퀀스를 이메일 한 통으로 묶어서 보지 않고, 이메일 액션별로 리포트를 보여 줘요. 그래서 워크플로우 안에서 각 메시지가 어떤 성과를 내는지 알 수 있어요.

워크플로우 이메일 통계는 세 곳에서 볼 수 있어요.

- 통합 이메일 통계 대시보드
- 워크플로우 빌더(Workflow Builder)의 개별 이메일 액션
- 워크플로우 단위 커뮤니케이션 리포트

전체 참여도와 특정 자동 메시지의 효과를 모두 확인할 수 있어요.

---

## 워크플로우 캠페인 분석의 장점

자동 이메일의 성과를 분석하면 어떤 메시지가 연락처에게 잘 도달하고 반응을 얻는지 알 수 있어요. 워크플로우 이메일 통계를 살펴보면 전달 문제를 찾고, 이메일 액션끼리 비교하고, 근거를 바탕으로 자동화 전략을 조정할 수 있어요.

- 통합 이메일 리포팅: 통합 이메일 통계 대시보드 한 곳에서 워크플로우 캠페인을 **이메일 캠페인**, **일괄 작업**과 함께 볼 수 있어요.
- 이메일별 인사이트: 워크플로우 안의 특정 이메일 액션 성과를 추적해서 반응이 좋은 메시지와 그렇지 않은 메시지를 구분할 수 있어요.
- 참여 및 전달 모니터링: 열람, 클릭, 답장, 반송, 거부 이벤트 등 확인 가능한 활동을 보고 연락처가 자동 이메일에 어떻게 반응하는지 파악할 수 있어요.
- 워크플로우 단위 확인: 워크플로우별로 확인 가능한 이메일·SMS 통계를 포함한 커뮤니케이션 성과를 볼 수 있어요.
- 성과 분석: 리포트와 내보낸 워크플로우 이메일 통계를 활용해 결과를 분석하고 자동 커뮤니케이션을 개선할 부분을 찾을 수 있어요.

---

## 워크플로우 캠페인용 통합 이메일 통계

통합 이메일 통계 대시보드에서는 하이퍼클래스 전체의 이메일 성과를 한 화면에서 볼 수 있어요. 대시보드를 워크플로우 캠페인으로 필터링하면 단독 **이메일 캠페인**이나 **일괄 작업**과 섞이지 않고 자동 이메일 활동만 확인할 수 있어요.

대시보드는 다음 구성 요소로 이루어져 있어요.

| 구성 요소 | 용도 |
| --- | --- |
| **Engagement Summary**(참여 요약) | 이메일 전달과 참여 활동을 한눈에 보여 줘요. |
| **Performance Analysis**(성과 분석) | 선택한 기간 동안 확인 가능한 이메일 성과 지표의 추이를 보여 줘요. |
| **Top Performing Emails**(성과 상위 이메일) | 확인 가능한 순위 지표를 기준으로 참여도가 높은 개별 이메일을 보여 줘요. |
| **Source Filter**(소스 필터) | 워크플로우 캠페인만 보거나, 지원하는 이메일 소스끼리 비교할 수 있어요. |
| **Date Range Filter**(기간 필터) | 선택한 기간의 리포트만 보여 줘요. |

**Top Performing Emails에서 워크플로우 결과 이해하기**

**Top Performing Emails**는 워크플로우 전체를 이메일 한 통으로 순위를 매기지 않고, 워크플로우의 이메일 액션을 하나씩 따로 평가해요.

예를 들어 환영 이메일, 리마인더 이메일, 후속 이메일이 들어 있는 워크플로우는 활동량과 선택한 필터에 따라 결과에 항목이 3개로 나뉘어 나올 수 있어요.

덕분에 열람이나 클릭 참여도가 높은 자동 메시지를 쉽게 찾을 수 있어요.

## 이메일 액션별 통계

이메일 액션별 통계에서는 특정 자동 이메일의 성과를 자세히 볼 수 있어요. 지표를 보면 워크플로우의 특정 이메일을 연락처가 받았는지, 열어 봤는지, 클릭했는지, 답장했는지 알 수 있어요.

하이퍼클래스는 다음 워크플로우 이메일 통계를 지원해요. 확인 가능한 리포트 이벤트와 발송 설정에 따라 일부 지표는 보이지 않을 수 있어요.

| 지표 | 설명 |
| --- | --- |
| **Accepted**(접수됨) | 발송 서비스가 처리하려고 접수한 이메일 이벤트예요. |
| **Delivered**(전달됨) | 수신자의 메일 서버에 정상적으로 전달된 것으로 보고된 이메일이에요. |
| **Opened**(열람됨) | 지원되는 추적 방식으로 기록된 이메일 열람 활동이에요. |
| **Clicked**(클릭됨) | 추적 대상 이메일 링크에 대해 기록된 수신자의 클릭이에요. |
| **Replied**(답장됨) | 해당 이메일에 연결된 답장이에요. 발송·추적 설정에서 지원하는 경우에 해당해요. |
| **Bounced**(반송됨) | 정상적으로 전달하지 못한 이메일이에요. |
| **Unsubscribed**(수신 거부) | 구독 취소 방법을 사용해 이메일 수신을 거부한 연락처예요. |
| **Complained**(스팸 신고) | 이메일을 스팸으로 신고한 수신자예요. 해당 이벤트를 확인할 수 있는 경우에 해당해요. |
| **Rejected**(거부됨) | 해당 발송 시스템이 처리 또는 전달 과정에서 거부한 이메일이에요. |

이메일 액션별 워크플로우 이메일 통계 화면은 기본적으로 **최근 30일** 기준으로 보여 줘요.

**이메일 참여도 해석하기**

지표를 서로 비교하면 개선할 부분을 찾을 수 있어요.

- **Accepted** 이벤트는 많은데 **Delivered** 이벤트가 적다면 전달 문제가 있을 수 있어요. 원인을 확인해 보세요.
- 열람은 많은데 클릭이 적다면, 수신자가 이메일에는 관심이 있지만 링크는 누르지 않는다는 뜻일 수 있어요.
- 반송이나 스팸 신고가 많다면 연락처 데이터 품질, 발송 방식, 수신자의 기대와 맞지 않는 내용 중 하나가 원인일 수 있어요.
- 워크플로우 이메일 액션끼리 참여도가 다르다면, 내용이나 콜투액션을 바꿔 볼 만한 메시지를 가려낼 수 있어요.

{% hint style="warning" %}
**중요:** 접수된 이메일이 반드시 전달된 이메일은 아니에요. 열람·클릭 통계도 추적 가능 여부에 따라 달라지므로, 수신자가 메시지를 읽었거나 반응했다는 확실한 증거로 해석하면 안 돼요.
{% endhint %}

## 워크플로우 단위 커뮤니케이션 통계

워크플로우 단위 통계에서는 워크플로우 하나의 커뮤니케이션 활동을 더 넓게 볼 수 있어요. 통합 이메일 통계 대시보드와 달리 이메일과 SMS 성과를 모두 보여 줄 수 있어서, 워크플로우 안에서 각 커뮤니케이션 액션이 어떤 역할을 하는지 평가하기 좋아요.

이 리포트는 워크플로우 목록에서 열 수 있어요.

**워크플로우 단위 통계에 포함되는 내용**

- 이메일 성과: 워크플로우의 이메일 액션에 대해 확인 가능한 전달·참여 결과예요.
- SMS 성과: SMS 액션에 대해 확인 가능한 커뮤니케이션 통계예요.
- 과거 활동: 2023년 1월 1일 이후의 데이터가 포함될 수 있어요.
- 삭제된 액션 이력: 이전에 사용하다 삭제한 이메일·SMS 액션의 통계도 남아 있을 수 있어요.

워크플로우 단위 리포트는 워크플로우 하나하나에 대해서만 볼 수 있고, 워크플로우 폴더 전체에는 제공되지 않아요. 자세한 내용은 [워크플로우 종합 통계](../../07-워크플로우/comprehensive-workflow-stats.md) 문서를 참고하세요.

## 워크플로우 빌더 통계 보기

워크플로우 빌더의 **Stats View**(통계 보기 모드)를 쓰면 워크플로우 캔버스에서 바로 확인 가능한 통계를 볼 수 있어요. 자동화 구조를 살펴보면서 트리거와 커뮤니케이션 액션의 성과를 함께 분석할 수 있어요.

**Stats View**는 두 종류의 리포트를 지원해요.

| 리포트 유형 | 측정 내용 |
| --- | --- |
| 트리거 통계 | 연락처 등록 활동이에요. **Attempted**(시도), **Matched**(일치), **Unmatched**(불일치) 이벤트가 포함돼요. |
| 커뮤니케이션 액션 통계 | 워크플로우 이메일을 포함한 커뮤니케이션 액션에 대해 확인 가능한 전달·참여 정보예요. |

트리거 통계와 이메일 참여 통계는 목적이 달라요. 예를 들어 연락처가 워크플로우 트리거에 일치했다고 해서 이메일이 전달됐거나 열렸다는 뜻은 아니에요.

**편집 제한**

**Stats View**가 켜져 있는 동안에는 워크플로우를 편집할 수 없어요. 이메일 액션이나 다른 워크플로우 구성 요소를 바꾸려면 일반 워크플로우 빌더 편집 모드로 돌아가세요. 워크플로우 탐색과 편집 방법은 [워크플로우 빌더 둘러보기](../../07-워크플로우/기타/workflow-builder-walkthrough.md) 문서를 참고하세요.

## 워크플로우 캠페인 확인 및 분석

하이퍼클래스에서는 여러 방법으로 워크플로우 성과 데이터를 볼 수 있어요. 워크플로우 전체의 자동 이메일 활동을 비교하고 싶은지, 특정 이메일 액션을 자세히 보고 싶은지에 따라 알맞은 리포트 화면을 고르세요.

**통합 이메일 통계 대시보드에서 워크플로우 캠페인 보기**

여러 워크플로우의 자동 이메일 참여도를 확인하거나 선택한 기간의 워크플로우 이메일 성과를 비교하고 싶을 때 유용해요.

1. **마케팅 > 이메일 > 통계**로 이동하세요.
2. 소스 필터를 열고 **Workflow Campaigns**(워크플로우 캠페인)를 선택하세요.
3. 리포트 기간을 선택하세요.
4. **Engagement Summary**, **Performance Analysis**, **Top Performing Emails**를 확인하세요.

![통합 이메일 통계 대시보드에서 워크플로우 캠페인을 선택하는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083544528/original/NrZrnMoMDbW-t12HRUFs-LygZVj7366XwQ.gif?1792170601)

{% hint style="info" %}
**참고:** **Top Performing Emails**는 워크플로우 전체가 아니라 워크플로우의 이메일 액션을 하나씩 평가해요.
{% endhint %}

## 이메일 액션별 통계 확인

이메일 액션별 통계를 보면 특정 자동 메시지의 결과를 살펴볼 수 있어요. 워크플로우에 이메일이 여러 개 있거나, 특정 단계의 참여도가 유난히 낮아 보일 때 유용해요.

1. **자동화 > 워크플로우**로 이동하세요.
2. 분석할 워크플로우를 여세요.
3. 확인할 **Email**(이메일) 액션을 선택하세요.
4. 오른쪽 패널에서 **Statistics**(통계)를 클릭하세요.

![이메일 액션의 오른쪽 패널에서 통계를 여는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083547714/original/SYh6vkOYSgzaFLOwfyI4RGw.png?1792173756)

5. 확인 가능한 이메일 전달·참여 지표를 확인하세요.
6. 리포트 컨트롤이 있으면 사용해서 원하는 기간을 확인하세요.

이메일 액션별 통계는 기본적으로 최근 30일 기준이에요.

## 워크플로우 단위 통계 확인

워크플로우 단위 통계를 쓰면 워크플로우 빌더를 열지 않고도 워크플로우 하나의 이메일·SMS 성과를 확인할 수 있어요.

1. **자동화 > 워크플로우**로 이동하세요.
2. 분석할 워크플로우를 찾으세요.
3. 워크플로우 이름 옆의 펼침 화살표를 클릭하세요.
4. **통계**를 클릭해 해당 워크플로우의 커뮤니케이션 통계를 여세요.
5. 확인 가능한 이메일·SMS 통계를 확인하세요.

![워크플로우 목록에서 워크플로우 통계를 여는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083545441/original/4hZpVEOGhzjqTOPaMghNizPKhsNsqU3uLA.gif?1792171498)

{% hint style="info" %}
**참고:** 워크플로우 단위 통계는 워크플로우 하나하나에 대해서만 볼 수 있고, 폴더 전체에는 제공되지 않아요. 과거 리포트에는 2023년 1월 1일 이후의 활동이 포함될 수 있고, 이전에 삭제한 이메일·SMS 액션의 통계도 포함돼요.
{% endhint %}

## 워크플로우 빌더 통계 보기 모드로 이메일 액션 분석

**Stats View**를 쓰면 리포트 데이터를 자동화 구조와 연결해서 볼 수 있어서, 살펴보고 싶은 액션을 쉽게 찾을 수 있어요.

1. **자동화 > 워크플로우**로 이동하세요.
2. 워크플로우를 여세요.
3. 왼쪽 상단에서 **Stats View**(통계 보기 모드)를 켜세요.

![워크플로우 빌더 왼쪽 상단에서 통계 보기 모드를 켜는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083546709/original/aVC8ens7eUptSX2RXwsRymSnZUe5hAHLSw.png?1792172799)

4. 분석할 **Email** 액션을 선택하세요.
5. 확인 가능한 전달·참여 통계를 확인하세요.
6. 통계 항목을 클릭하면 해당하는 상세 리포트가 열려요. 상세 리포트가 있는 경우에 한해서예요.
7. 워크플로우를 수정하기 전에 **Stats View**를 끄세요.

## 통계를 확인한 뒤 워크플로우 이메일 편집

성과 결과를 바탕으로 이메일을 고치면 자동 커뮤니케이션의 효과를 높이는 데 도움이 돼요. 편집하기 전에 이메일 액션별 지표를 먼저 확인하면, 개선 효과가 클 만한 메시지에 집중할 수 있어요.

1. **자동화 > 워크플로우**에서 워크플로우를 여세요.
2. **Stats View**가 켜져 있으면 꺼서 편집 모드로 돌아가세요.
3. 수정할 **Email** 액션을 선택하세요.
4. 내용, 설정, 관련 추적 설정을 확인하세요.
5. 필요한 부분을 수정하세요.
6. 변경사항을 저장하고, 워크플로우의 게시 상태가 의도한 대로인지 확인하세요.

![이메일 액션을 편집하는 워크플로우 빌더 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083546197/original/iyF6TIdpbSVMYXWlkddFJyDqNmf90UnUjQ.png?1792172294)

사용 중인 리포트 화면에 **Edit Workflow**(워크플로우 편집) 옵션이 있다면, 선택해서 해당 워크플로우의 워크플로우 빌더로 이동할 수 있어요.

{% hint style="warning" %}
**중요:** 이메일 액션을 수정한다고 해서 통계가 바로 좋아진다고 보장할 수는 없어요. 수정한 뒤의 이메일 활동을 지켜보며 참여도가 나아졌는지 평가하세요.
{% endhint %}

## 워크플로우 이메일 통계 내보내기

하이퍼클래스 밖에서 성과를 분석하거나 리포트 데이터를 공유해야 할 때는 워크플로우 이메일 통계를 CSV 파일로 내보낼 수 있어요. 워크플로우 내보내기에는 이메일 액션별 통계가 담겨요.

1. **마케팅 > 이메일 > 통계**로 이동하세요.
2. 소스 필터에서 **Workflow Campaigns**를 선택하고 리포트 기간을 고르세요.
3. **내보내기**를 클릭하세요. 내보내기 유형을 따로 선택하는 창이 나타나면 **Workflows Only**(워크플로우만)를 선택하세요.
4. 리포트를 받을 이메일 주소를 입력하고 내보내기를 요청하세요.
5. CSV 다운로드 링크가 들어 있는 이메일을 여세요.

![워크플로우 이메일 통계를 내보내는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083545135/original/Pt5A1S9goN9ArqfLs6h21HPzCA1GVtE5ZA.png?1792171216)

내보내기 다운로드 링크는 **30일** 동안 유효해요. 자세한 내용은 [이메일 캠페인 데이터 내보내기](../이메일-마케팅/exporting-email-campaign-data.md) 문서를 참고하세요.

## 자주 묻는 질문

### 성과 상위 이메일에 같은 워크플로우가 여러 번 나오는 이유가 뭔가요?

하이퍼클래스는 워크플로우의 이메일 액션을 하나씩 따로 평가해요. 워크플로우에 이메일 액션이 여러 개 있으면, 워크플로우 결과 하나로 합쳐지지 않고 각각 별도의 리포트 항목으로 나타날 수 있어요.

### 워크플로우 이메일 통계가 일부 보이지 않아요.

확인 가능한 지표는 발송 제공업체, 추적 설정, 기록된 이메일 이벤트에 따라 달라져요. 이메일이 실제로 발송됐는지, 선택한 기간이 맞는지, 관련 추적 설정은 어떤지 확인해 보세요. 더 자세한 진단은 [이메일 통계 문제 해결](../../09-이메일/트러블슈팅/troubleshooting-email-statistics.md) 문서를 참고하세요.

### 워크플로우 통계를 보는 중에는 이메일 액션을 편집할 수 없어요.

워크플로우 빌더의 **Stats View**는 워크플로우 활동을 분석하기 위한 모드예요. 이 모드가 켜져 있는 동안에는 편집이 비활성화돼요. 이메일 액션이나 다른 워크플로우 구성 요소를 수정하려면 **Stats View**를 먼저 끄세요.

### 더 이상 활성 상태가 아닌 워크플로우의 이메일 통계도 볼 수 있나요?

워크플로우 이메일 액션의 기존 통계는 해당 리포트 기간과 보관된 이력에 따라 계속 볼 수 있어요. 초안이거나 비활성 상태인 워크플로우는 통계를 본다는 이유만으로 새 자동 발송이 일어나지는 않아요.

### 이메일 액션을 삭제하면 리포트 데이터는 어떻게 되나요?

하이퍼클래스의 워크플로우 단위 리포트는 이전에 사용하다 삭제한 이메일·SMS 액션의 과거 통계를 보관해요. 그래서 해당 액션이 현재 워크플로우에 없어도 과거 커뮤니케이션 활동을 확인할 수 있어요.
