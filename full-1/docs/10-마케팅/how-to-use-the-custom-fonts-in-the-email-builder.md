# 이메일 빌더에서 사용자 지정 폰트 사용하기

사용자 지정 폰트를 쓰면 이메일을 브랜드 분위기에 더 가깝게 꾸밀 수 있어요. 다만 이메일 클라이언트마다 폰트 지원 범위가 달라요. 하이퍼클래스에서는 Google Fonts 추가와 브랜드 보드 폰트 사용 기능을 기본으로 제공해요. 꼭 필요하면 고급 사용자는 사용자 지정 HTML이나 CSS를 쓸 수도 있어요. 일부 이메일 클라이언트는 지원하지 않는 폰트를 대체 폰트로 바꿔 보여 주니, 보내기 전에 꼭 테스트해 보세요.

## 이메일 빌더의 사용자 지정 폰트란?

사용자 지정 폰트를 쓰면 **이메일 빌더**(Email Builder)에서 기본으로 제공하는 글꼴 외에도 브랜드나 캠페인 디자인에 맞는 폰트를 적용할 수 있어요. 이메일 빌더 사용법은 [하이퍼클래스 이메일 빌더 & 인라인 에디터 사용하기](Email-Builder-Capabilities/how-to-use-the-email-builder-and-its-in-line-editor.md) 문서에서 확인하세요.

이메일 폰트를 관리하는 방법은 크게 네 가지예요.

- 기본 제공 폰트: 이메일 빌더에 이미 들어 있는 폰트예요.
- **브랜드 폰트**: 기본 브랜드 보드에 저장해 두면 이메일 빌더의 폰트 선택 목록에 나타나는 폰트예요.
- Google Fonts: 이메일 빌더에서 **폰트 추가**를 눌러 바로 추가할 수 있는 폰트예요.
- 고급 사용자 지정 스타일: 기본 폰트 기능으로 부족할 때 **코드** 요소에 사용자 지정 HTML이나 CSS를 넣어서 적용해요.

사용자 지정 폰트는 모든 수신자에게 똑같이 보인다고 장담할 수 없는 부가 기능이에요. 일부 이메일 클라이언트는 외부 폰트를 불러오지 않고 대체 폰트를 보여 줘요.

## 사용자 지정 폰트의 장점

브랜드에 맞는 타이포그래피를 쓰면 이메일의 시각적 일관성을 높일 수 있어요. 이메일 클라이언트가 지원하는 폰트로 대체되더라도 내용은 읽을 수 있어요.

- 브랜드 일관성: 웹사이트, 퍼널 등 다른 브랜드 자료와 같은 서체를 쓸 수 있어요.
- 더 넓은 디자인 선택지: 이메일 빌더의 기본 폰트보다 다양한 폰트를 쓸 수 있어요.
- 브랜드 스타일 재사용: 기본 브랜드 보드를 설정해 두면 브랜드 보드 폰트를 이메일 빌더에서 바로 쓸 수 있어요.
- Google Fonts 기본 지원: 지원되는 Google Fonts를 CSS를 직접 작성하지 않고 추가할 수 있어요.
- 대체 폰트 지원: 수신자의 이메일 클라이언트가 원하는 폰트를 표시하지 못해도 내용을 읽을 수 있어요.

## 폰트 적용 방법 고르기

하이퍼클래스에서는 이메일 폰트를 관리하는 방법이 여러 가지예요. 가장 간단한 방법부터 시작하면 불필요한 코드를 줄이고 이메일을 관리하기도 쉬워요.

### 기본 제공 폰트

기본 제공 폰트는 이메일 빌더의 텍스트 서식 도구에서 바로 고를 수 있어서 가장 간단해요.

다음과 같은 경우에 기본 제공 폰트를 쓰세요.

- 호환성이 가장 중요할 때
- 브랜드 서체를 정확히 맞출 필요가 없을 때
- 이메일 클라이언트마다 다르게 보이는 문제를 최소화하고 싶을 때

### 브랜드 보드 폰트

브랜드 보드에는 브랜드 색상, 폰트, 로고를 저장해 두고 이메일을 디자인할 때 불러 쓸 수 있어요. 기본 브랜드 보드에 있는 폰트는 이메일 빌더의 **브랜드 폰트** 아래에 나타나요. 자세한 내용은 [이메일 캠페인/템플릿에서 브랜드 보드 사용하기](브랜드-보드/how-to-use-brand-boards-in-email-campaign-templates.md) 문서를 참고하세요. 브랜드 보드를 만드는 방법은 [브랜드 보드 만들기](how-to-create-a-brand-board.md) 문서에 있어요.

팀에서 승인된 서체를 여러 이메일 템플릿과 캠페인에 반복해서 쓰고 싶을 때 브랜드 폰트가 유용해요.

브랜드 폰트를 적용하려면 다음 순서로 진행하세요.

1. **디자인 에디터**(Design Editor)에서 이메일을 열어요.
2. 바꾸려는 텍스트를 선택해요.
3. **글꼴** 드롭다운을 열어요.
4. **브랜드 폰트** 아래에서 원하는 폰트를 선택해요.

### Google Fonts

Google Fonts는 `@font-face` 규칙을 직접 만들지 않아도 이메일 빌더에서 바로 추가할 수 있어요.

Google Font를 추가하려면 다음 순서로 진행하세요.

1. 이메일 빌더에서 이메일 캠페인이나 템플릿을 열어요.
2. 텍스트 요소를 선택해요.
3. **글꼴** 선택 창을 열어요.
4. **폰트 추가**를 클릭해요.
5. 추가할 Google Font를 선택해요.
6. **폰트 추가**를 클릭해요.
7. 글꼴 드롭다운에서 새로 추가한 폰트를 선택해요.

추가한 폰트는 빌더의 글꼴 선택 목록에서 쓸 수 있어요.

## 이메일 클라이언트의 제한과 대체 폰트

이메일 클라이언트마다 사용자 지정 폰트를 표시하는 방식이 달라요. 대체 폰트를 미리 정해 두면 원하는 폰트가 표시되지 않아도 메시지를 읽을 수 있어요.

하이퍼클래스 안내에 따르면 다음과 같은 이메일 클라이언트에서는 Google Fonts가 일정하게 동작하지 않을 수 있어요.

- Gmail
- 여러 플랫폼의 Outlook
- Outlook.com
- Yahoo Mail

원하는 폰트를 쓸 수 없으면 이메일 클라이언트가 다른 폰트로 대신 보여 줄 수 있어요.

그래서 대체 폰트는 다음 조건에 맞는 것으로 고르세요.

- 원하는 폰트와 글자 비율이 비슷해요.
- 굵기가 비슷해요.
- 읽기 쉬워요.
- 폰트가 바뀌어도 레이아웃이 크게 달라지지 않아요.

예를 들어 폰트 스택(우선순위 목록)은 다음과 같이 구성할 수 있어요.

`Brand Font → Helvetica → Arial → sans-serif`

수신자에게 실제로 보이는 폰트는 이메일 클라이언트가 지원하는 폰트에 따라 달라져요.

## 여러 이메일에서 브랜드 폰트 사용하기

브랜드 보드 폰트를 쓰면 여러 템플릿과 캠페인에서 타이포그래피를 일관되게 유지하기 쉬워요. 알맞은 브랜드 보드를 기본값으로 설정해 두면 이메일 빌더에서 불러 쓸 수 있어요.

이메일 빌더의 브랜드 폰트 목록에는 기본 브랜드 보드의 폰트만 나타나요. 기대한 폰트가 보이지 않으면 올바른 브랜드 보드가 기본으로 설정되어 있는지 확인하세요.

브랜드 보드에 저장된 타이포그래피를 바꿔도, 이미 디자인한 이메일 내용의 스타일이 자동으로 바뀌지는 않아요. 브랜드 서체가 바뀌면 기존 텍스트를 검토해서 필요한 부분을 직접 수정하세요.

## 고급 사용자 지정 HTML 또는 CSS 사용하기

이메일 빌더의 기본 설정으로 원하는 디자인을 만들 수 없을 때는 **코드** 요소로 사용자 지정 HTML이나 CSS를 추가할 수 있어요. 이메일 클라이언트는 사용자 지정 코드를 제한적으로만 지원하므로 신중하게 사용하세요.

**코드** 요소는 끌어다 놓는 방식의 요소로, 고급 사용자가 이메일에 사용자 지정 HTML이나 CSS를 추가할 때 써요. 이메일 클라이언트마다 표시 방식이 다를 수 있으니, 사용자 지정 코드는 보내기 전에 꼭 테스트하세요. 자세한 내용은 [이메일 빌더의 코드 요소](Email-Builder-Capabilities/code-element-in-email-builder.md) 문서를 참고하세요.

**코드** 요소를 추가하려면 다음 순서로 진행하세요.

1. **마케팅 > 이메일 > 템플릿**으로 이동해요.
2. 기존 이메일 템플릿을 열거나 새로 만들어요.
3. **요소 추가**(+) 아이콘을 클릭해요.
4. **코드** 요소를 이메일로 끌어다 놓아요.

   ![코드 요소를 이메일로 끌어다 놓는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155082203519/original/Bl89xPi0JXAUskNBTm8ob-xLefu5MiySeQ.png?1790770457)
5. 요소를 선택해 편집 메뉴를 열어요.
6. 필요한 HTML이나 CSS를 입력해요.
7. 보내기 전에 미리보기로 확인하고 테스트해요.

사용자 지정 코드는 다른 이메일 요소에 영향을 주지 않도록 가능한 한 독립적으로 작성하세요.

## 폰트 호스팅과 라이선스 확인

사용자 지정 서체를 쓰려면 기술적으로 호환되어야 하고, 이메일이나 웹에서 쓸 수 있는 권리도 있어야 해요. 데스크톱용으로 라이선스를 받은 폰트가 웹이나 이메일 삽입까지 허용한다고 볼 수는 없어요.

표준이 아닌 폰트를 쓰기 전에 다음을 확인하세요.

- 폰트 라이선스를 검토해요.
- 이메일이나 웹에서 쓰는 것이 허용되는지 확인해요.
- 폰트 제공업체가 요구하는 승인된 호스팅 방식을 써요.
- 라이선스에서 명시적으로 허용하지 않는 한 라이선스가 있는 폰트 파일을 배포하지 않아요.

현재 하이퍼클래스의 이메일 빌더 문서에서 안내하는 기본 방법은 Google Fonts와 브랜드 폰트예요. 퍼널이나 웹사이트 같은 다른 하이퍼클래스 기능에서 쓸 수 있는 폰트 파일 직접 업로드 기능이 이메일 빌더에서도 똑같이 동작한다고 생각하면 안 돼요.

## 이메일 빌더에서 Google Font 추가하기

필요한 폰트를 이메일 빌더에서 고를 수 있다면 기본 Google Fonts 기능을 쓰는 것을 권해요. 폰트를 불러오는 CSS를 직접 작성하는 번거로움이 없어요.

1. **마케팅 > 이메일**로 이동해요.
2. 기존 이메일 캠페인이나 템플릿을 열거나 새로 만들어요.
3. 바꾸려는 텍스트가 들어 있는 **Text Element**(텍스트 요소)를 선택해요. 자세한 내용은 [이메일 빌더의 텍스트 요소](Email-Builder-Capabilities/text-element-in-email-builder.md) 문서를 참고하세요.
4. **글꼴** 선택 창을 열어요.
5. **폰트 추가**를 클릭해요.
6. 목록에서 필요한 Google Font를 선택해요.
7. **폰트 추가**를 클릭해요.
8. 글꼴 선택 창으로 돌아와 선택한 텍스트에 폰트를 적용해요.
9. 데스크톱과 모바일 미리보기에서 이메일을 확인해요.
10. **테스트 이메일 보내기**로 테스트 이메일을 보내서, 주요 수신자가 쓰는 이메일 클라이언트에서 서체가 어떻게 보이는지 확인해요.

## 보내기 전에 사용자 지정 폰트 테스트하기

캠페인이 수신자에게 가기 전에 테스트하면 원하는 폰트가 표시될 때와 대체 폰트로 바뀔 때를 모두 확인할 수 있어요. 미리보기도 도움이 되지만, 이메일 클라이언트마다 HTML과 CSS를 다르게 표시하므로 실제로 테스트 발송도 해 보세요.

캠페인을 보내기 전에 다음을 확인하세요.

- 폰트를 지원하는 곳에서는 원하는 폰트가 표시돼요.
- 사용자 지정 폰트를 쓸 수 없는 곳에서도 대체 텍스트를 읽을 수 있어요.
- 제목이 예상치 못하게 줄바꿈되지 않아요.
- 버튼과 CTA 문구가 상자 안에 알맞게 들어가요.
- 모바일 레이아웃도 읽기 편해요.
- 글자 굵기와 크기가 보기에 알맞아요.
- **코드** 요소가 주변 영역에 영향을 주지 않아요.
- 사용자 지정 폰트를 불러오지 못해도 이메일이 괜찮아 보여요.

이메일 클라이언트마다 HTML과 CSS 지원 수준이 다르므로, 하이퍼클래스에서는 사용자 지정 코드가 들어간 이메일을 미리보기로 확인하고 테스트하라고 안내해요.

## 사용자 지정 폰트 활용 팁

브랜드 일관성과 가독성, 이메일 클라이언트 호환성의 균형을 맞출 때 사용자 지정 서체가 가장 잘 어울려요. 폰트 사용 방식을 단순하게 유지하면 결과를 예측하기 쉬워요.

- 사용자 지정 코드를 쓰기 전에 기본 제공 폰트, 브랜드 보드 폰트, Google Fonts 기능을 먼저 활용해요.
- 항상 대체 폰트를 염두에 둬요.
- 장식용 폰트는 주로 제목이나 짧은 문구에 써요.
- 본문 텍스트는 읽기 쉽게 유지해요.
- 중요한 의미를 사용자 지정 폰트에만 의존해서 전달하지 않아요.
- 데스크톱과 모바일 레이아웃을 테스트해요.
- 중요한 캠페인을 시작하기 전에 여러 이메일 클라이언트로 테스트 이메일을 보내요.
- **코드** 요소를 쓸 때는 사용자 지정 CSS를 최소한으로, 필요한 부분에만 적용해요.

## 자주 묻는 질문

### CSS를 직접 작성하지 않고 Google Fonts를 추가할 수 있나요?

네, 할 수 있어요. 텍스트 요소를 선택하고 **글꼴** 선택 창을 연 다음 **폰트 추가**를 클릭하세요. Google Font를 고르고 추가하면 빌더의 글꼴 선택 목록에서 쓸 수 있어요.

### Gmail이나 Outlook에서 사용자 지정 폰트가 다르게 보여요. 왜 그런가요?

일부 이메일 클라이언트는 Google Fonts나 다른 외부 폰트를 일정하게 불러오지 않아요. 이 경우 수신자에게 대체 폰트가 보일 수 있어요.

### 이메일 캠페인에서 브랜드 보드 폰트를 쓸 수 있나요?

네, 쓸 수 있어요. 기본 브랜드 보드의 폰트는 이메일 빌더의 **브랜드 폰트** 아래에서 선택할 수 있어요.

### 이메일 빌더에 브랜드 보드 폰트가 보이지 않아요.

이메일 빌더의 브랜드 폰트 목록에는 현재 기본 브랜드 보드의 폰트만 나타나요. 올바른 브랜드 보드가 기본으로 설정되어 있는지 확인하세요.

### 브랜드 보드 폰트를 바꾸면 기존 이메일이 자동으로 바뀌나요?

기존 이메일 내용의 스타일이 자동으로 바뀐다고 생각하면 안 돼요. 이미 디자인한 이메일을 검토해서 필요한 곳에 새 폰트를 직접 적용하세요.

### 대체 폰트가 꼭 필요한가요?

네, 필요해요. 일부 이메일 클라이언트는 원하는 사용자 지정 폰트를 표시하지 못할 수 있어요. 읽을 수 있는 대체 폰트를 정해 두면 디자인과 가독성을 지키는 데 도움이 돼요.

### 폰트에 사용자 지정 HTML이나 CSS를 쓸 수 있나요?

네, 고급 사용자는 **코드** 요소로 사용자 지정 HTML이나 CSS를 추가할 수 있어요. 이메일 클라이언트마다 지원 범위가 다르니 보내기 전에 테스트하세요.

### 이메일 빌더에 폰트 파일을 직접 업로드할 수 있나요?

현재 하이퍼클래스 이메일 빌더 문서에서는 기본 제공 폰트, 브랜드 폰트, Google Fonts를 기본 기능으로 안내하고, **코드** 요소를 통한 사용자 지정 HTML/CSS도 안내해요. 퍼널이나 웹사이트에 있는 폰트 파일 직접 업로드 기능이 이메일 빌더에도 있다고 생각하면 안 돼요.

### 본문 텍스트에도 사용자 지정 폰트를 써도 되나요?

쓸 수는 있지만, 대체 폰트로 표시되어도 이메일을 읽을 수 있어야 해요. 중요한 본문 내용은 정확한 서체보다 가독성과 예측 가능한 표시를 우선하세요.
