# Google을 연결해 Gmail로 이메일 주고받기

Gmail 계정을 하이퍼클래스와 연결하면 두 곳의 이메일이 양방향으로 동기화돼요. 이 문서에서는 연결 방법과 동기화가 동작하는 방식, 자주 묻는 질문을 안내해요.

- 기존 연락처와 주고받은 수신·발신 이메일을 하이퍼클래스로 동기화해요.
- Gmail에서 바로 연락처를 만들고 대화를 추가할 수 있어요.
- 이메일이 실시간으로 양방향 동기화되어 더 효율적으로 일할 수 있어요.

{% hint style="warning" %}
**중요:** Gmail 양방향 동기화는 에이전시 대시보드가 아니라 서브 계정 안에서 설정해야 해요. 서브 계정에 직접 로그인하거나, 에이전시 화면에서 **로그인** 기능으로 서브 계정에 들어가세요. 그래야 Gmail 연결이 올바른 하이퍼클래스 로케이션의 대화에 적용돼요.
{% endhint %}

## Gmail 양방향 동기화란?

Gmail 양방향 동기화는 Gmail과 하이퍼클래스 사이에서 이메일을 서로 동기화하는 기능이에요. Gmail 계정을 하이퍼클래스와 연결하면 두 시스템의 이메일이 같은 상태로 유지돼요. Gmail에서 보내거나 받거나 변경한 이메일은 하이퍼클래스에 자동으로 반영되고, 반대도 마찬가지예요. 어느 플랫폼에서 보더라도 이메일을 하나로 통합해 최신 상태로 볼 수 있어요. 이메일 캠페인을 더 간편하게 운영하고 업무 생산성을 높일 수 있으며, 중요한 이메일을 Gmail과 하이퍼클래스 양쪽에서 확인할 수 있어요.

## 하이퍼클래스와 이메일 계정의 양방향 동기화는 어떻게 동작하나요?

동기화가 시작되는 경우는 두 가지예요.

1. 하이퍼클래스에서 연락처에게 이메일을 보내면 두 플랫폼 사이의 동기화가 시작돼요.
2. 하이퍼클래스에 이미 저장된 연락처가 Gmail 양방향 동기화를 연결한 사용자의 Gmail 주소로 이메일을 보내도 동기화돼요. 이 이메일은 **대화** 탭에 들어와요.

{% hint style="info" %}
서브 계정 사용자이기도 한 연락처가 보낸 이메일은 동기화되지 않아요. 서브 계정 사용자를 여러 목적으로 연락처에 추가하는 경우가 많은데, 이런 이메일에는 기밀 정보가 있을 수 있기 때문이에요. 사용자의 이메일 주소가 아니라면 위에서 설명한 대로 동기화돼요.
{% endhint %}

{% hint style="info" %}
**참고:** 한 사용자가 여러 서브 계정에 추가되어 있고, 그 모든 계정에 같은 Gmail 계정으로 Gmail 양방향 동기화를 연결했다고 해 볼게요. 이때 연락처가 보낸 이메일은 해당 서브 계정들의 **대화** 탭에 모두 들어와요. 하지만 사용자가 답장한 서브 계정의 연락처 인스턴스만 유지되고, 나머지 인스턴스는 동기화가 끊겨요. 사용자가 기존 연락처에 담당자로 지정되어 있는지도 함께 확인하기 때문에, 그 연락처가 속하지 않은 서브 계정으로는 대화가 들어가지 않아요.
{% endhint %}

![하이퍼클래스에서 보낸 이메일 대화](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/48287099381/original/5yv1sSHvgI7kZ4JHVVjfZBO59-h2hC2NiQ.png?1678791637)

보낸 이메일은 연결된 Gmail 계정의 보낸편지함에 표시돼요.

![Gmail 보낸편지함에 표시된 이메일](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/48287099648/original/TkUibkPnbsnocvJ7Pe29R3EjDO-IdqMbCg.png?1678791736)

{% hint style="info" %}
**참고:** Gmail은 하루에 약 500통까지만 지원하며, 그 이상은 발송에 실패해요.
{% endhint %}

이메일 스레드의 이후 메시지도 모두 동기화돼요. 내 이메일 계정에서 보낸 이메일은 하이퍼클래스에 반영되고, 반대도 마찬가지예요.

## 그 밖의 기능

### 이메일 변경(Update Email)

기존 연결을 끊지 않고 연결된 이메일 주소를 다른 주소로 바꿀 수 있어요.

![이메일 변경 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/48287100704/original/n1NZvUej6xWS0WzV2yaUOKHk26_hCz7Q_w.png?1678792018)

이후 하이퍼클래스에서 보내는 새 발신 이메일은 새로 추가한 이메일 주소와 동기화돼요. 이전에 연결했던 이메일 주소로 같은 스레드에 들어오는 메시지는 하이퍼클래스와 개인 이메일 사이에서 더 이상 동기화되지 않아요.

### 이메일 연결 해제(Disconnect Email)

연결을 끊고 하이퍼클래스와의 동기화를 중단할 수 있어요. 연결을 해제하면 두 플랫폼 사이에서 이메일이나 메시지가 동기화되지 않아요.

![이메일 연결 해제 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/48287100962/original/TLimKgIGciSFjVlNRy0jRHtoAQdktaxIpA.png?1678792076)

### BCC 주소

Gmail/Outlook에서 이메일을 보낼 때 Cc 또는 Bcc 필드에 **BCC 주소**를 넣을 수 있어요. 그러면 해당 연락처와 대화가 하이퍼클래스에 자동으로 추가되어 소통이 간편해지고, 관련 데이터를 한곳에 모아 둘 수 있어요. 이후로는 이 연락처가 Gmail/Outlook 받은편지함으로 보내는 이메일이 하이퍼클래스와 자동으로 동기화돼요.

![BCC 주소 사용 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155003796789/original/y8e4pNvsjXgTN9G3mDxS0Ro04NP8gkUtfA.png?1690445519)

{% hint style="info" %}
**참고:** BCC 주소를 사용하면 Gmail에서 "Delivery incomplete"(전송 미완료) 오류가 나타날 수 있어요. 하이퍼클래스는 BCC를 기록용으로 사용하는데, Gmail은 BCC 주소로부터 전송 확인을 받지 못하기 때문이에요.

오류가 표시되더라도 메시지는 하이퍼클래스에 정상적으로 등록되었을 수 있어요.
{% endhint %}

## 양방향 동기화는 개별 이메일에만 적용되나요, 대량 이메일과 워크플로우에도 적용되나요?

이메일 종류별로 발신 도메인이 어떻게 연결되는지 알려 드려요.

**개별 이메일:** 개인 이메일 계정(Gmail)을 연결하면, 사용자가 보내는 개별 이메일의 발신 도메인은 연결한 Gmail 주소가 돼요. 양방향 동기화를 켜면 개별 이메일은 Gmail에서 직접 발송돼요. 이 기능에는 Google이 정한 하루 500통 발송 제한이 적용돼요.

**대량 이메일:** 지금처럼 서브 계정에 설정된 이메일 제공업체에서 발송돼요. 양방향 동기화는 영향을 주지 않아요.

**워크플로우 & 자동화:** 자동화된 이메일은 양방향 동기화로 발송되지 않고, 서브 계정에 설정된 제공업체에서 발송돼요. 이렇게 해서 하이퍼클래스의 자동화 워크플로우와 이메일 발송 시스템이 매끄럽게 연결돼요.

{% hint style="info" %}
**참고:** 이 구조 덕분에 일대일 이메일은 양방향 동기화로 보내면서 대량 이메일도 문제없이 보낼 수 있어요. Gmail의 하루 500통 제한은 개별 이메일에만 적용돼요. 그래서 하이퍼클래스 이메일/SMTP로 대량 이메일을 보낼 때는 이 제한을 걱정하지 않아도 돼요. Gmail의 하루 발송 제한에 묶이지 않고 대량 이메일 캠페인을 진행할 수 있어요.
{% endhint %}

## 자주 묻는 질문

### 기존 연락처에게서 받은 이메일은 어떻게 되나요?

기존 연락처에게서 받은 모든 수신 이메일은 하이퍼클래스와 Gmail/Outlook 받은편지함에 모두 반영돼요. 양방향으로 동기화되므로 두 플랫폼 모두에 소통 내역이 빠짐없이 남아요.

### 동기화된 계정을 제거하면 기존 이메일이 삭제되나요?

아니요, 동기화된 계정을 제거해도 기존 이메일은 삭제되지 않아요. 이미 동기화된 이메일은 그대로 남고, 계정을 제거한 뒤에 보내거나 받는 새 이메일만 동기화에 영향을 받아요.

### 계정을 제거한 뒤에도 새 이메일이 동기화되나요?

계정을 제거한 뒤에 보내거나 받는 새 이메일은 하이퍼클래스와 Gmail/Outlook 사이에서 동기화되지 않아요. 기존 이메일은 계속 동기화되고, 새 이메일은 동기화에 포함되지 않아요.

### Gmail에 있는 기존 연락처가 모두 하이퍼클래스와 동기화되나요?

네, 양방향 동기화는 Gmail의 기존 연락처를 찾아 하이퍼클래스로 동기화해요. 이 연락처들이 보내는 수신 이메일은 해당 연락처 아래에 자동으로 채워져요. 다만 연동을 연결하기 전의 과거 이메일은 동기화할 수 없어요.

### 연락처에게서 새 이메일이 오면 어떻게 되나요?

기존 연락처에게서 온 새 수신 이메일은 하이퍼클래스와 Gmail에 새 이메일로 반영돼요. 이미 있는 대화 스레드에 속한 이메일이라면 같은 스레드 안에 새 이메일로 표시돼요.

### 하이퍼클래스나 Gmail에서 보낸 이메일은 어떻게 되나요?

하이퍼클래스에서 보낸 이메일은 동기화된 메일의 보낸편지함에 자동으로 기록돼요. 반대로 동기화된 메일 제공업체에서 보낸 이메일은 하이퍼클래스의 해당 연락처 대화에 자동으로 나타나요.

### 참조(Cc)/숨은참조(Bcc) 수신자는 동기화에서 어떻게 처리되나요?

Gmail에서 사용자가 참조나 숨은참조로 지정되었거나 여러 수신자에 포함된 경우, 이 정보는 하이퍼클래스의 해당 연락처 아래에 반영돼요. 그래서 모든 소통 내역을 빠짐없이 볼 수 있어요. Cc와 Bcc 이메일 주소로는 새 연락처가 만들어지지 않아요.

### 연락처가 다른 사람에게 이메일을 보내면서 하이퍼클래스 사용자를 포함하면 어떻게 되나요?

이 경우 이메일이 하이퍼클래스에 반영되어 해당 연락처와 연결돼요. 그래서 전체 대화 기록이 유지돼요.

### 수신자가 여러 명이면 대화 스레드는 어떻게 관리되나요?

이메일의 받는 사람(To)이 여러 명이면 첫 번째 연락처가 하이퍼클래스의 대화 탭 기준이 돼요. 이후의 모든 이메일은 이 스레드에 나타나요.

### 같은 동기화 이메일 주소에 대해 같은 연락처가 여러 로케이션에 있으면 어떻게 되나요?

하이퍼클래스에서 시작한 이메일은 해당 로케이션에만 반영돼요. 이후의 답장과 소통도 그 로케이션에 한정돼야 해요. 다만 연락처가 하이퍼클래스 사용자에게 보낸 이메일은 모든 로케이션에 반영돼요.

### BCC 주소는 무엇이고 어떻게 동작하나요?

Gmail/Outlook에서 이메일을 보낼 때 Cc 또는 Bcc 필드에 **BCC 주소**를 넣을 수 있어요. 그러면 대화와 연락처가 하이퍼클래스에 자동으로 추가되어 소통과 데이터 관리가 간편해져요. 이후로는 이 연락처가 Gmail/Outlook 받은편지함으로 보내는 이메일이 하이퍼클래스와 자동으로 동기화돼요.

### Gmail 로그인 정보가 바뀌면 보안 연결은 어떻게 처리되나요?

로그인 정보가 바뀌면 보안 연결을 유지하기 위해 하이퍼클래스에서 다시 인증하고 이메일을 다시 동기화해야 해요.

### Gmail에서 이메일을 전달하면 어떻게 되나요?

기존 연락처에게 전달한 이메일은 발신 이메일로 처리되어 하이퍼클래스의 해당 연락처 아래에 동기화돼요.

### 이메일이 여러 연락처에 중복으로 있으면 어떻게 되나요?

여러 연락처에 중복으로 보낸 이메일은 하이퍼클래스에서 가장 먼저 만들어진 연락처와 연결돼요.
