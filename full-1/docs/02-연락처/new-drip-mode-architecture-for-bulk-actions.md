# 일괄 작업의 새 드립 모드

**일괄 작업**(Bulk Actions)의 드립 모드가 새 구조로 바뀌었어요. 대량 발송을 시간 간격을 두고 나눠 보낼 수 있고, 30일을 넘는 일정도 설정할 수 있어요. 일괄 작업 유형이 달라도 똑같이 동작해서, 많은 연락처에 안정적으로 메시지를 보낼 수 있어요.

## 일괄 작업의 드립 모드란?

드립 모드는 큰 연락처 목록에 메시지를 보내거나 정보를 업데이트할 때, 한꺼번에 처리하지 않고 시간 간격을 두고 나눠서 처리하는 방식이에요. 분, 시간, 일 단위로 실행 간격을 정해 반복해요. 이렇게 하면 통신사의 발송 제한을 피하고, 발신자 평판을 지키고, 서버가 느려지는 것도 막을 수 있어요.

2025년 9월 업데이트로 기존 엔진이 모듈형·설정 기반 구조로 교체되었어요. 대량 SMS와 이메일부터 워크플로우 단계까지, 드립 모드를 쓰는 모든 일괄 작업이 같은 엔진으로 동작해요.

## 새 구조의 주요 장점

사용자 요청이 많았던 개선 사항이 이번 업데이트에 담겼어요.

- 연락처가 수십만 명이어도 긴 발송 일정을 효율적으로 처리해요.
- 체크포인트 기능이 좋아져서 발송 도중에 작업이 멈추는 일을 막아 줘요.
- 기존 30일 제한을 넘는 일정도 설정할 수 있어요.
- 설정 기반 엔진을 재사용하므로 모든 드립 모드 사용처(SMS, 이메일, 연락처 업데이트, 워크플로우 단계 등)에서 동작이 똑같아요.
- 코드 중복이 줄어서 앞으로 기능 개선이 빨라지고 오류도 줄어들어요.

## 체크포인트와 자동 복구

이제 배치(한 번에 처리하는 묶음)가 끝날 때마다 진행 상황을 기록해요. 서브 계정 연결이 끊기거나, 전화번호 풀이 교체되거나, 앱이 다시 시작되어도 중단된 지점부터 정확히 이어서 진행해요. 직접 다시 시작하거나 발송이 누락될 일이 없어서 발송 품질 지표를 지키고 시간도 아낄 수 있어요.

## 30일을 넘는 일정 설정

8주 코스나 12주 챌린지 기간 동안 메시지를 나눠 보내야 하나요? 예전에는 일괄 작업을 720시간(약 30일) 이후로 예약할 수 없었어요.

새 엔진에서는 미래의 어떤 날짜든 지정할 수 있어요. 한 학기 동안 이어지는 육성 시리즈, 반복되는 모금 활동, 장기 리텐션 캠페인에 알맞아요.

## 설정 항목

지금까지 쓰던 것과 같은 간단한 폼이 새 엔진에 연결돼요.

- **시작일**: 첫 번째 배치를 시작할 날짜와 시간
- **배치 수량**: 한 번에 처리할 연락처 수 (1~10,000)
- **반복 간격**: 배치 사이의 간격 (분, 시간, 일)
- **Send On**(발송 요일): 발송할 요일 선택
- **Process Between**(발송 가능 시간): 발송을 허용할 시간대 (계정 시간대 기준)
- **종료 시간**: 하루 중 발송을 멈추는 시간

## 지원하는 일괄 작업 유형

드립 모드를 제공하던 모든 일괄 작업이 이제 같은 스케줄러를 써요.

- 대량 SMS·MMS 발송
- 대량 이메일 발송
- 연락처 태그 추가/제거
- 워크플로우/캠페인에 추가
- 기회 업데이트(상태, 파이프라인, 담당자)
- 워크플로우 안의 사용자 지정 **Action – Drip**(액션 – 드립) 단계

## 일괄 작업에서 드립 모드 설정하기

드립 모드 설정은 어렵지 않아요. 몇 분만 더 들여 꼼꼼히 설정하면 발송이 매끄럽게 진행돼요.

1. **연락처**로 이동하세요. 어떤 작업을 할지, 어떤 속도로 진행할지 정하는 설정 화면이 열려요.
2. 일괄로 실행할 작업 유형을 선택하세요. 예를 들어 **SMS 전송**, **이메일 보내기**, **태그 추가**가 있어요. 작업 유형에 따라 캠페인 결과가 달라져요.
3. 대상 연락처를 선택하세요. 기존 **스마트 리스트**를 쓰거나 연락처를 직접 골라도 돼요. 대상 수에 따라 드립 모드가 실행해야 할 배치 수가 정해져요.

   ![대상 연락처를 선택하는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155055003744/original/DRon1ceL6n-c2OZ1z2g9rQD8mTxSL0y1aA.png?1759318989)
4. **전달 방식**에서 **Send in Drip Mode**(드립 모드로 보내기)를 선택하세요. 한꺼번에 보내지 않고 배치로 나눠 천천히 전달하겠다는 뜻이에요.

   ![전달 방식에서 드립 모드를 선택하는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155055003797/original/PVkJyNwbUSbAqgyeE1bo40UHnta5sIJAOQ.png?1759319029)
5. **드립 설정**에서 발송 속도와 일정을 정하세요.
   - **시작일**: 첫 번째 배치를 시작할 날짜와 시간을 선택해요.
   - **배치 수량**: 한 번에 처리할 연락처 수를 정해요. 1~10,000 사이로 입력할 수 있어요.
   - **반복 간격**: 다음 배치를 보내기까지 기다릴 시간을 분, 시간, 일 단위로 선택해요.
   - **Send On**(발송 요일, 선택 사항): 필요하면 특정 요일에만 발송하도록 제한해요. 예를 들어 월요일~금요일만 보낼 수 있어요.
   - **Process Between**(발송 가능 시간): 업무 시간이나 방해받지 않아야 할 시간을 설정해서 적절한 시간에만 메시지가 나가게 해요.
   - **종료 시간**: 하루 발송을 멈출 시간을 정해요. 업무 시간이 끝나면 드립이 멈추고, 다음 발송 가능 시간대에 다시 이어져요.
6. **Action Description**(작업 설명)에 짧은 이름을 입력하세요. 예를 들어 *"Drip SMS – 7월 웨비나 초대"*처럼 쓰면, 나중에 리포트에서 팀원과 함께 캠페인을 쉽게 알아볼 수 있어요.
7. 예상 소요 시간을 확인하세요. 대상 수, 배치 크기, 간격을 바탕으로 작업이 끝나기까지 걸리는 시간이 계산돼요. 캠페인 목표에 맞는 일정인지 한 번 더 살펴보세요.

## 자주 묻는 질문

### 기존에 만든 드립 작업도 새 엔진을 자동으로 쓰나요?
네. 대기 중이거나 일시중지된 작업은 모두 자연스럽게 새 엔진으로 옮겨져요. 따로 바꿀 필요는 없어요.

### 드립이 시작된 뒤에 배치 크기를 바꾸면 어떻게 되나요?
수정할 수 있어요. 아직 처리하지 않은 다음 배치부터 새 수량이 적용되고, 이미 발송된 배치는 그대로 유지돼요.

### 드립을 진행할 수 있는 총 기간에 제한이 있나요?
정해진 제한은 없어요. 개선된 스케줄러 덕분에 캠페인을 몇 달, 길게는 몇 년 동안 드립으로 진행할 수 있어요.

### 드립 캠페인을 일시중지했다가 다시 시작할 수 있나요?
네. **연락처 > 일괄 작업**에서 ⋯ 메뉴를 열고 **Pause**(일시중지)를 선택하세요. 다시 시작하면 마지막으로 완료된 체크포인트부터 이어서 진행돼요.

### 발송 제한은 그대로 적용되나요?
통신사 수준과 플랫폼 안전 제한은 그대로 있어요. 예를 들어 1분 간격이면 분당 SMS 1,000건이 한도예요. 새 엔진은 이 제한을 더 일관되게 적용해요.

### 워크플로우의 **Action – Drip**은 일괄 작업의 드립 모드와 다른가요?
둘 다 같은 백엔드 로직을 쓰기 때문에 배치 크기, 간격, 복구 방식이 똑같아요. 화면이 다를 뿐이에요.

### 워크플로우 기록에 배치별 내역이 남나요?
네. 처리된 배치마다 **Workflow History**(워크플로우 기록)에 별도 실행 내역으로 표시돼서 쉽게 확인할 수 있어요.

### 드립 모드는 방해 금지 시간과 수신거부 설정을 지키나요?
**Process Between**(발송 가능 시간)으로 허용한 시간대를 벗어난 메시지나, 수신거부 상태인 연락처에 가는 메시지는 자동으로 다음 유효한 배치로 미뤄져요.
