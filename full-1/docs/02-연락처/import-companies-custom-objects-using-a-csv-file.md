# CSV 파일로 회사(커스텀 오브젝트) 일괄 가져오기

CSV 파일 하나로 회사 레코드를 한꺼번에 가져올 수 있어요. 다른 곳의 데이터를 옮기거나, 기존 회사 정보를 업데이트하거나, 회사 정보를 하이퍼클래스와 맞출 때 쓰세요.

이 문서에서는 CSV 파일을 업로드하고, 필드를 연결(매핑)하고, 내용을 확인한 뒤 가져오기를 진행하는 방법을 안내해요. 가져오기 마법사가 필드 유효성 검사와 중복 감지를 도와줘서 오류를 줄일 수 있어요. 다른 CRM에서 데이터를 옮길 때도, 기존 레코드를 업데이트할 때도 많은 회사를 한 번에 관리할 수 있어요.

## 회사 일괄 가져오기란?

회사 일괄 가져오기는 CSV 파일을 올려서 새 회사 레코드를 만들거나, 기존 레코드를 업데이트하거나, 두 가지를 동시에 하는 기능이에요. 가져오기 마법사가 파일 준비, CSV 열과 회사 필드 연결, 가져오기 내용 확인 순서로 안내해요. 진행 상황은 **일괄 작업**(Bulk Actions)에서 확인할 수 있어요.

가져오기 방식을 알맞게 고르고 필드를 정확히 연결하면 회사 데이터를 정확하게 유지할 수 있어요. 수작업도 줄고, CRM 전체의 데이터 일관성도 좋아져요.

## 회사 일괄 가져오기의 장점

대량의 데이터를 쉽게 관리하면서, 레코드를 어떻게 만들고 업데이트할지 직접 정할 수 있어요.

- 시간 절약 — 회사를 하나씩 만들 필요 없이 수백, 수천 건을 한 번에 가져와요.
- 유연한 가져오기 방식 — 새 회사 만들기, 기존 회사 업데이트, 둘 다 한 번에 하기를 고를 수 있어요.
- 스마트 필드 매핑 — 가져오기 전에 CSV 열을 하이퍼클래스의 회사 필드와 연결해요.
- 중복 방지 — 레코드 ID와 고유 필드로 불필요한 중복 회사를 막아요.
- 가져오기 전 검토 — 레코드를 처리하기 전에 매핑과 가져오기 설정을 확인해요.
- 가져오기 모니터링 — **일괄 작업**에서 진행 상황, 경고, 오류를 확인해요.
- 상세 리포트 — 리포트를 내려받아 성공한 레코드를 확인하고 실패한 레코드의 원인을 찾아요.

## 시작하기 전에

CSV 파일을 미리 제대로 준비해 두면 유효성 검사 오류가 크게 줄고, 회사 데이터를 문제없이 가져올 수 있어요.

{% hint style="warning" %}
시작하기 전에 회사 모듈에 접근할 권한이 있는지, 계정에서 회사 관리 기능이 켜져 있는지, CSV 파일이 서식 요건을 모두 충족하는지 확인하세요.
{% endhint %}

아래 항목을 확인하세요.

- 회사 모듈에 접근할 권한이 있어요.
- 계정에서 회사 관리 기능이 켜져 있어요.
- CSV 파일이 .csv 형식으로 저장되어 있어요.
- 첫 번째 행에 열 제목(헤더)이 있어요.
- 필수 회사 필드가 포함되어 있어요.
- 데이터가 깔끔하고 형식이 일정해요.
- 값을 가져오려는 회사 커스텀 필드가 이미 만들어져 있어요.

{% hint style="info" %}
회사를 수천 건 가져오기 전에는 5~10건짜리 작은 CSV로 먼저 테스트해서 매핑과 형식을 확인하세요.
{% endhint %}

## CSV 준비할 때 자주 하는 실수

가져오기 오류는 대부분 CSV 파일의 형식 문제에서 생겨요. 미리 데이터를 살펴보면 가져오기 실패와 불필요한 정리 작업을 막을 수 있어요.

{% hint style="warning" %}
가져오기 실패와 데이터 품질 문제를 일으키는 아래 실수를 피하세요.
{% endhint %}

- 필수 필드 누락
- 비어 있는 헤더 행
- 중복된 열 이름
- 잘못된 날짜 형식
- 중요한 값 안에 들어간 불필요한 공백
- 잘못된 이메일 또는 전화번호 형식(해당하는 경우)
- 지원하지 않는 특수문자
- 필요 없는 빈 열

## 가져오기 방식 알아보기

가져오기 방식을 알맞게 고르면 하이퍼클래스가 각 레코드를 의도한 대로 처리해요.

{% hint style="info" %}
새 회사를 추가할지, 기존 회사를 업데이트할지, 둘 다 할지에 따라 가져오기 방식을 신중하게 고르세요.
{% endhint %}

### 방식 1: 만들기

하이퍼클래스에 아직 없는 회사를 가져올 때 **만들기**를 선택하세요. 이 방식은 새 회사 레코드만 만들어요.

예시: 다른 CRM에 있던 회사를 처음으로 하이퍼클래스로 옮길 때

### 방식 2: 업데이트

기존 회사 레코드를 수정할 때 **업데이트**를 선택하세요. 이 방식은 수정할 회사를 정확히 찾기 위해 회사 레코드 ID 같은 믿을 수 있는 식별자가 필요해요.

예시: 새 회사를 만들지 않고 기존 회사의 전화번호나 주소만 업데이트할 때

### 방식 3: 만들기 및 업데이트

CSV에 기존 회사와 새 회사가 섞여 있을 때 **Create & Update**(만들기 및 업데이트)를 선택하세요. 이미 있는 회사는 업데이트하고, 없는 회사는 자동으로 만들어요.

예시: 다른 시스템에서 매달 받는 회사 내보내기 파일에 신규 고객과 기존 고객의 변경 사항이 함께 들어 있을 때

## 회사 가져오는 방법

가져오기 마법사를 따라가면 처리하기 전에 데이터를 검증할 수 있어서 가져오기 오류를 줄일 수 있어요.

### 1단계: 가져오기 시작

1. **연락처**로 이동하세요.
2. **회사**를 선택하세요.
3. **가져오기**를 클릭하세요.

![회사 화면에서 가져오기 버튼 클릭](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155077795160/original/imh1skE8vj94nacg0XT2EI1ejEjO4ColZA.png?1786018925)

알맞은 가져오기 방식(**만들기**, **업데이트**, **Create & Update**)을 선택하고 **다음**을 클릭하세요.

![가져오기 방식 선택 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155077795278/original/aspnbS99kFscr1-ND9QPjkJwELsx1udrCg.png?1786018988)

### 2단계: CSV 파일 업로드

회사 레코드가 들어 있는 CSV 파일을 업로드하세요. 매핑 단계로 넘어가기 전에 하이퍼클래스가 업로드한 파일을 검증해요.

아래 내용을 확인하세요.

- 헤더가 들어 있어요.
- 필수 필드가 있어요.
- 파일 형식이 올바라요.

**다음**을 클릭하세요.

![CSV 파일 업로드 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155077795355/original/w7zC9A9QrUUrXuruCSfqQJxTlImGd0nOYQ.png?1786019046)

### 3단계: 회사 필드 매핑

필드 매핑은 각 CSV 열의 값을 하이퍼클래스의 어느 필드로 가져올지 정하는 단계예요. 연결된 필드를 하나씩 꼼꼼히 확인하세요.

열마다 아래를 확인하세요.

- 자동으로 인식된 회사 필드가 맞는지 확인하세요.
- 필요하면 매핑을 바꾸세요.
- 필요 없는 열은 제외하세요.
- 커스텀 필드가 올바르게 연결됐는지 확인하세요.

![회사 필드 매핑 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155077795486/original/L19SLaoA2tBXnRLlIU7ummwYS3EXN5QZFQ.png?1786019101)

하이퍼클래스는 가능한 경우 열을 자동으로 매핑해요. 확인이 끝나면 **다음**을 클릭하세요.

{% hint style="info" %}
넘어가기 전에 필드 매핑을 꼼꼼히 확인하세요. 매핑이 잘못되면 데이터가 엉뚱한 필드에 들어가거나 가져오기가 실패할 수 있어요.
{% endhint %}

### 4단계: 가져오기 설정 확인

처리를 시작하기 전에 가져오기 요약을 확인하세요.

아래 항목을 확인해요.

- 가져오기 방식
- 레코드 수
- 필드 매핑
- 중복 처리 설정
- **Update Empty Values**(빈 값 업데이트) 옵션

모두 맞으면 **Start Bulk Import**(대량 가져오기 시작)를 클릭하세요.

![가져오기 설정 확인 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155077795612/original/6ta8Ggb4RfsC94fj_5H1xFV_U5L6360XcQ.png?1786019143)

## 레코드 ID 이해하기

레코드 ID는 하이퍼클래스 안에서 각 회사를 구분하는 고유한 값이에요. 업데이트 가져오기에서 레코드 ID를 쓰면 이름이 비슷한 회사가 여러 개 있어도 정확한 회사만 수정돼요.

{% hint style="warning" %}
레코드 ID가 없다면, 가능한 한 중복 확인에 쓸 만한 고유한 회사 필드를 설정하세요.
{% endhint %}

예시:

| 회사 | 레코드 ID |
| --- | --- |
| ABC Manufacturing | 672918 |
| XYZ Logistics | 918234 |

레코드 ID로 업데이트하면 일괄 업데이트할 때 대상이 헷갈릴 일이 없어요.

## 중복 감지와 고유 필드

중복 감지는 같은 회사를 나타내는 레코드가 실수로 여러 개 만들어지는 것을 막아 줘요.

가져오기 방식에 따라 하이퍼클래스는 회사 레코드 ID, 설정된 고유 회사 필드, 기존 회사 레코드를 기준으로 들어오는 레코드를 비교해요.

![중복 감지 설정 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155077795728/original/5GjKt3b9B1MxF3G5S8UFNOIAEhFcsjpDCQ.png?1786019214)

{% hint style="info" %}
중복 충돌이 생기면 처리가 끝난 뒤 가져오기 리포트에서 영향을 받은 레코드를 확인하세요.
{% endhint %}

처리 결과는 다음 중 하나예요.

- 새 회사 생성됨
- 기존 회사 업데이트됨
- 중복 감지됨
- 유효성 검사 오류 발생

## 빈 값 업데이트

**Update Empty Values**(빈 값 업데이트) 옵션은 CSV의 빈 셀이 기존 회사 정보에 어떤 영향을 줄지 정해요.

![빈 값 업데이트 옵션 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155077795817/original/_wHauQ0KR3MqZ4nWgcryc6OyNvkTA8YmYA.png?1786019260)

{% hint style="warning" %}
**Update Empty Values**를 켜면 CSV의 빈 셀이 기존 회사 데이터를 덮어써요. 데이터가 실수로 사라지지 않도록 신중하게 사용하세요.
{% endhint %}

### 켰을 때

빈 값이 기존 회사 데이터를 덮어써요.

예시:

- 현재 전화번호: (555) 123-4567
- CSV의 전화번호: (빈 값)
- 결과: 전화번호가 지워져요.

### 껐을 때

빈 셀은 무시돼요.

기존 회사 값은 그대로 유지돼요. 정기적으로 업데이트하는데 CSV로 정보를 일부러 지울 필요가 없다면 이 옵션을 끄는 것을 권해요.

## 가져오기 진행 상태 확인

**일괄 작업**에서 관리자가 모든 회사 가져오기를 처음부터 끝까지 확인할 수 있어요.

![일괄 작업에서 가져오기 상태 확인](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155077795888/original/cjh0PUjm4gU6kAl6EWeaueavxRmYudk1MQ.png?1786019298)

{% hint style="info" %}
유효성 검사 문제가 생기면 오류 리포트를 바로 내려받으세요. 실패한 레코드를 고쳐서 해당 회사만 다시 가져오기 쉬워요.
{% endhint %}

가져오기마다 아래 정보가 표시돼요.

- 상태
- 처리된 레코드
- 성공한 가져오기
- 경고
- 실패한 레코드
- 완료 시간

사용할 수 있는 작업은 다음과 같아요.

- **상세 보기**
- **Pause**(일시중지)
- **Resume**(재개)
- **취소**(사용할 수 있는 경우)
- **Download Error Report**(오류 리포트 다운로드)
- **Download Success Report**(성공 리포트 다운로드)

## 권장 사용 방법

아래 방법을 따르면 가져오기가 더 정확해지고, 가져온 뒤 정리할 일도 줄어요.

- 대량 업데이트 가져오기 전에 기존 회사 데이터를 내보내세요. 가져온 뒤 정보를 확인하거나 되돌려야 할 때 쓸 수 있는 백업이 돼요.
- 먼저 작은 샘플로 테스트하세요. 회사를 수천 건 처리하기 전에 5~10건으로 테스트 가져오기를 해서 매핑과 형식을 확인하세요.
- 업로드 전에 커스텀 필드를 확인하세요. CSV를 가져오기 전에 회사 커스텀 필드를 먼저 만들어 두세요. 하이퍼클래스는 없는 커스텀 필드를 자동으로 만들지 않아요.
- 매핑을 꼼꼼히 확인하세요. 진행하기 전에 CSV 열이 올바른 CRM 필드에 연결됐는지 다시 확인하세요. 매핑이 잘못되면 데이터가 엉뚱한 필드에 들어가거나 가져오기가 실패할 수 있어요.
- 불필요한 빈 값은 줄이세요. 가져오기 전에 데이터를 정리하고, 데이터가 실수로 사라지지 않도록 **Update Empty Values** 끄기를 고려하세요.
- 가져온 뒤에는 매번 **일괄 작업**을 확인하세요. 진행 상황과 완료 상태를 보고 확인이 필요한 오류나 경고가 없는지 살펴보세요.
- 오류 리포트는 바로 내려받으세요. 유효성 검사 문제가 생기면 오류 리포트를 내려받아 해당 레코드를 고치고, 그 회사만 다시 가져오세요.
- 가져온 회사 몇 건을 직접 확인하세요. 완료된 뒤 가져온 회사 중 일부를 열어 데이터가 제대로 들어왔는지 확인하세요.

## 자주 묻는 질문

### 새 회사와 기존 회사를 동시에 가져올 수 있나요?
네. **Create & Update**(만들기 및 업데이트) 가져오기 방식을 사용하세요.

### 가져오기를 시작한 뒤에 멈출 수 있나요?
가져오기 상태에 따라 **일괄 작업**에서 진행 중인 가져오기를 일시중지하거나 취소할 수 있어요.

### 중복 회사가 발견되면 어떻게 되나요?
하이퍼클래스는 레코드 ID와 설정된 고유 필드로 중복 레코드를 판단해요. 가져오기 설정에 따라 해당 레코드는 업데이트되거나, 건너뛰거나, 표시돼요.

### 회사 커스텀 필드도 가져올 수 있나요?
네. 이미 만들어 둔 회사 커스텀 필드는 필드 매핑 단계에서 연결할 수 있어요.

### 없는 커스텀 필드를 하이퍼클래스가 자동으로 만들어 주나요?
아니요. CSV를 가져오기 전에 회사 커스텀 필드를 먼저 만들어 두세요.

### 가져오기를 시작하기 전에 필드 매핑을 수정할 수 있나요?
네. 필드 매핑 단계에서 매핑을 확인하고 조정한 뒤 가져오기를 확정하세요.

### 일부 레코드가 실패하면 어떻게 하나요?
**일괄 작업**에서 오류 리포트를 내려받아 CSV에서 해당 레코드를 고친 다음, 그 레코드만 다시 가져오세요.

### 업데이트하기 전에 회사를 내보내 두는 게 좋을까요?
네. 기존 회사 데이터를 내보내 두면 가져온 뒤 정보를 확인하거나 되돌려야 할 때 쓸 수 있는 백업이 돼요.

### 회사를 가져오면 연락처나 기회와의 연결도 자동으로 만들어지나요?
아니요. 회사 가져오기는 회사 레코드를 만들거나 업데이트하기만 해요. 연결은 지원되는 범위에서 따로 관리해야 해요.

### 가져오기를 되돌릴 수 있나요?
아니요. 가져오기는 되돌릴 수 없어요. 시작하기 전에 항상 CSV를 먼저 확인하세요.
