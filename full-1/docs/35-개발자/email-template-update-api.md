# 이메일 템플릿 업데이트 API

PATCH /emails/builder/:templateId API 엔드포인트로 기존 이메일 빌더 템플릿과 이메일 설정을 수정하는 방법을 설명해요. 지원하는 필드, 간소화된 에디터 페이로드, 설정 방법, 권장 사항, 자주 묻는 질문을 다뤄요. API 연동으로 템플릿을 관리하는 개발자를 위한 문서예요.

{% hint style="warning" %}
엔드포인트 상세 정보, 요청 파라미터, 응답 정보는 공식 API 문서의 "Update a template with settings"를 참고하세요.
{% endhint %}

## API로 이메일 빌더 템플릿과 이메일 설정 업데이트하기

API를 쓰면 하이퍼클래스 화면에서 직접 편집하지 않고도 기존 이메일 빌더 템플릿을 수정할 수 있어요. PATCH /emails/builder/:templateId 엔드포인트는 템플릿 콘텐츠와 지원하는 이메일 설정을 한 번의 API 호출로 업데이트해요.

에이전시, 개발자, 연동 파트너처럼 이메일 템플릿을 코드로 관리하는 경우에 유용해요. 템플릿 콘텐츠와 이메일 설정을 따로 업데이트하지 않아도 되고, 기존 업데이트 동작은 그대로 유지돼요.

## 이메일 빌더 템플릿 업데이트 엔드포인트

이 엔드포인트는 templateId로 기존 이메일 빌더 템플릿을 업데이트해요. 템플릿 콘텐츠와 함께 이메일 제목, 발신자 정보, 미리보기 텍스트 같은 이메일 설정을 API로 제어해야 할 때 사용해요.

엔드포인트:

PATCH /emails/builder/:templateId

이 엔드포인트는 기존 이메일 빌더 템플릿의 업데이트를 지원해요. 한 번의 요청으로 템플릿 콘텐츠, 이메일 설정, 또는 둘 다 업데이트할 수 있어요.

{% hint style="warning" %}
이 엔드포인트는 기존 이메일 빌더 템플릿을 업데이트해요. 이미 발송한 캠페인, 예약된 캠페인, 워크플로우 안의 이메일 사본까지 함께 업데이트된다고 가정하면 안 돼요. 사용하는 경우에 그렇게 동작하는지 확인된 경우에만 기대하세요.
{% endhint %}

## API로 이메일 빌더 템플릿을 업데이트하면 좋은 점

여러 템플릿, 로케이션, 연동을 함께 관리할 때 API로 템플릿을 업데이트하면 더 효율적이에요. 수동 편집을 줄이고 템플릿 콘텐츠와 설정을 일관되게 유지하기 쉬워요.

- 한 번의 API 호출: 템플릿 콘텐츠와 지원하는 이메일 설정을 따로 바꾸지 않고 함께 업데이트해요.
- 템플릿 전체 제어: API로 기존 이메일 빌더 템플릿의 콘텐츠를 관리해요.
- 이메일 설정 지원: subject, fromName, fromEmail, previewText를 업데이트해요.
- 더 깔끔한 페이로드 구조: 기존의 type, html/dnd, isPlainText 대신 editorType과 editorContent를 사용해요.
- 일반 텍스트 여부 자동 처리: isPlainText가 자동으로 결정되므로 이 값을 직접 보낼 필요가 줄어요.
- 하위 호환성: 간소화된 페이로드를 지원하면서도 기존 업데이트 동작을 유지해요.
- 더 빠른 캠페인 준비: 캠페인이나 다른 이메일 워크플로우에 쓰기 전에 재사용 템플릿을 빠르게 업데이트할 수 있어요.

## 지원하는 이메일 설정

이메일 설정은 수신자가 이메일을 열기 전과 후에 이메일이 어떻게 보이는지 정해요. API로 이 필드를 업데이트하면 템플릿을 쓰기 전에 올바른 발신자 정보, 제목, 미리보기 텍스트를 맞출 수 있어요.

이 엔드포인트에서는 다음 이메일 설정을 업데이트할 수 있어요.

| 필드 | 설명 | 필수 여부 |
| --- | --- | --- |
| `subject` | 수신자의 받은편지함에 표시되는 이메일 제목이에요. | 아니요 |
| `fromName` | 수신자에게 표시되는 발신자 이름이에요. | 아니요 |
| `fromEmail` | 수신자에게 표시되는 발신자 이메일 주소예요. | 아니요 |
| `previewText` | 많은 이메일 서비스에서 제목 옆에 보여 주는 짧은 미리보기 텍스트예요. | 아니요 |

템플릿 설정 필드는 모두 선택 사항이에요. 업데이트하려는 필드만 보내면 돼요.

{% hint style="info" %}
`fromEmail`은 올바른 이메일 형식인지 검증해요. 형식이 잘못된 이메일을 보내면 요청이 검증에 실패할 수 있어요.
{% endhint %}

스크린샷 자리: 하이퍼클래스 화면의 **이메일 빌더** 설정 패널에서 제목, 발신자 이름, 발신자 이메일, 미리보기 텍스트를 설정하는 모습을 캡처해서 넣어 주세요.

## 간소화된 에디터 페이로드

간소화된 에디터 페이로드를 쓰면 템플릿 콘텐츠를 업데이트할 때 보내야 하는 필드가 줄어요. 에디터 유형, HTML 또는 드래그 앤 드롭 콘텐츠, 일반 텍스트 여부를 따로 전달하는 대신 `editorType`과 `editorContent`를 사용해요.

기존 연동에서는 다음과 같은 필드를 썼을 수 있어요.

- `type`
- `html`
- `dnd`
- `isPlainText`

간소화된 구조에서는 다음 필드를 써요.

- `editorType`
- `editorContent`

이번 업데이트로 `isPlainText`가 자동으로 결정돼요. 그래서 간소화된 에디터 페이로드를 쓸 때는 `isPlainText`를 직접 보내지 않아도 돼요.

간소화된 구조 예시:

```
{
  "editorType": "html",
  "editorContent": "<html><body><p>Your updated email content</p></body></html>"
}
```

`editorType` 값은 업데이트할 템플릿이 지원하는 에디터 유형과 맞아야 해요.

스크린샷 자리: `editorType`과 `editorContent`를 강조 표시한 간소화된 페이로드 구조의 스크린샷 또는 다이어그램을 넣어 주세요.

## 템플릿 콘텐츠와 설정 함께 업데이트하기

디자인이나 문구를 바꾸면서 받은편지함에 보이는 정보도 함께 수정해야 할 때 콘텐츠와 설정을 한 번에 업데이트하면 편해요. 예를 들어 본문, 제목, 발신자 이름, 미리보기 텍스트를 동시에 바꿀 수 있어요.

요청 본문 예시:

```
{
  "editorType": "html",
  "editorContent": "<html><body><p>Updated email template content.</p></body></html>",
  "subject": "Updated Email Subject",
  "fromName": "Your Business Name",
  "fromEmail": "sender@example.com",
  "previewText": "A short preview of your updated email."
}
```

템플릿 설정 필드는 모두 선택 사항이라서 바꿀 필드만 넣으면 돼요.

이메일 설정만 업데이트하는 요청 본문 예시:

```
{
  "subject": "New Subject Line",
  "fromName": "Your Business Name",
  "fromEmail": "sender@example.com",
  "previewText": "Updated inbox preview text."
}
```

템플릿 콘텐츠만 업데이트하는 요청 본문 예시:

```
{
  "editorType": "html",
  "editorContent": "<html><body><p>Only the template content is updated.</p></body></html>"
}
```

## 워크플로우 템플릿 사용 시 참고 사항

워크플로우 단계에서 쓰는 이메일 템플릿은 추가한 방식과 편집 내용이 동기화되는지에 따라 동작이 달라질 수 있어요. 저장된 템플릿을 워크플로우에 추가하면 워크플로우 단계 안에 복사본으로 들어갈 수 있어요. 그러면 원본 템플릿을 업데이트해도 그 워크플로우 이메일에는 항상 반영되지 않을 수 있어요.

API 업데이트가 워크플로우 이메일에 적용된다고 믿기 전에 다음을 확인하세요.

- 워크플로우 이메일이 원본 템플릿과 동기화되어 있는지 확인하세요.
- 템플릿을 업데이트한 뒤 워크플로우의 이메일 단계를 검토하세요.
- 자동화를 활성화하거나 의존하기 전에 워크플로우 이메일을 테스트하세요.

워크플로우에서의 동작은 "워크플로우 단계에서 이메일 템플릿 관리하기(Managing Email Templates in Workflow Steps)" 문서를 참고하세요.

## 자주 묻는 질문

### 템플릿 콘텐츠는 그대로 두고 제목만 업데이트할 수 있나요?
네. 템플릿 설정 필드는 모두 선택 사항이라서 제목만 바꾸려면 `subject` 필드만 보내면 돼요.

### 이 엔드포인트로 발신자 정보도 업데이트할 수 있나요?
네. `fromName`과 `fromEmail`을 업데이트할 수 있어요.

### `fromEmail`도 검증하나요?
네. `fromEmail`은 올바른 이메일 형식인지 검증해요.

### 여전히 `isPlainText`를 보내야 하나요?
아니요. 간소화된 페이로드 구조에서는 `isPlainText`가 자동으로 결정돼요.

### 기존 에디터 페이로드 구조는 어떤 필드로 바뀌었나요?
간소화된 페이로드는 기존의 `type`, `html/dnd`, `isPlainText` 대신 `editorType`과 `editorContent`를 사용해요.

### 한 번의 요청으로 콘텐츠와 설정을 모두 업데이트할 수 있나요?
네. 한 번의 API 호출로 템플릿 콘텐츠와 지원하는 이메일 설정을 함께 업데이트할 수 있어요.

### 기존 템플릿만 업데이트할 수 있나요?
네. 이 엔드포인트는 `templateId`로 지정한 기존 이메일 빌더 템플릿을 업데이트할 때 써요.

### 이미 워크플로우에 복사된 템플릿도 자동으로 업데이트되나요?
항상 그렇지는 않아요. 워크플로우 이메일이 원본 템플릿에서 복사된 것인지, 동기화되어 있는지에 따라 동작이 달라질 수 있어요. 템플릿을 업데이트한 뒤에는 워크플로우의 이메일 단계를 검토하세요.

### API로 템플릿을 업데이트한 뒤에는 무엇을 해야 하나요?
하이퍼클래스에서 템플릿을 열어 업데이트된 콘텐츠와 설정을 확인하세요. 그런 다음 이메일을 미리보기하고 테스트한 뒤에 사용하세요.
