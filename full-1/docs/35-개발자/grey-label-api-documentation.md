# 그레이 라벨 API 문서 안내

화이트라벨 파트너가 플랫폼 브랜드 노출을 줄인 그레이 라벨 API 문서를 열고 고객이나 개발자에게 공유하는 방법을 설명해요. 무엇이 달라졌는지, 어떤 경우에 쓰면 좋은지, 그리고 **브랜드 도메인**과 어떻게 다른지도 함께 알려 드려요.

그레이 라벨 API 문서는 [여기](https://marketplace.leadconnectorhq.com/docs/)에서 볼 수 있어요.

## 그레이 라벨 API 문서란?

그레이 라벨 API 문서는 화이트라벨 파트너를 위한 개발자 문서 사이트예요. 에이전시와 파트너는 이 문서를 고객, 개발자, 연동 담당 팀에 공유할 수 있어요. 고객에게 보이는 자료에 플랫폼 고유의 브랜드가 드러나지 않아요.

API 문서가 별도의 문서 사이트에서 제공되면서, 외부 개발·연동 작업을 지원하기가 더 깔끔하고 일관돼졌어요. 브랜드가 반영된 개발자 환경이 필요한 에이전시를 위한 업데이트예요. 기술 담당자는 필요한 API 레퍼런스를 그대로 볼 수 있어요.

## 그레이 라벨 API 문서의 장점

그레이 라벨 API 문서를 쓰면 고객과 외부 개발자에게 더 자연스러운 기술 환경을 제공할 수 있어요. 브랜드 혼선이 줄고, 문서 공유가 쉬워지며, 개발자 작업 환경도 화이트라벨 환경에 맞춰져요.

- 그레이 라벨 개발자 환경: 고객에게 보이는 플랫폼 고유 브랜드 없이 API 문서를 공유할 수 있어요.
- 쉬운 문서 공유: 고객, 개발자, 연동 파트너에게 화이트라벨 사용 사례에 더 잘 맞는 문서 링크를 바로 보낼 수 있어요.
- 일관된 파트너 경험: 개발자 문서를 그레이 라벨·화이트라벨 환경과 맞출 수 있어요.
- 브랜드 노출 감소: 고객이 API 문서를 볼 때 플랫폼 고유의 표기를 보지 않게 도와줘요.
- 연동 작업 개선: 기술 팀이 연동을 만들거나 유지하면서 API 문서를 더 쉽게 찾을 수 있어요.

## 언제 쓰면 좋나요?

파트너가 직접 안내하는 상황, 고객에게 보여 주는 상황, 외부 개발자와 작업하는 상황처럼 그레이 라벨 환경이 좋은 경우에 가장 알맞아요. 기술 담당자는 API 문서를 볼 수 있고, 에이전시는 고객에게 브랜드가 반영된 경험을 계속 줄 수 있어요.

다음과 같은 경우에 그레이 라벨 API 문서를 쓰세요.

- 고객에게 API 문서를 공유할 때
- 외부 개발자나 연동 파트너에게 문서를 줄 때
- 화이트라벨 또는 그레이 라벨 고객 환경을 지원할 때
- 고객의 기술 팀이 API 기능을 살펴보도록 도울 때
- 공유하는 개발자 자료에서 플랫폼 고유의 브랜드 노출을 줄일 때

개발자 자료를 전반적으로 찾아볼 때는 도움말 센터에 있는 기존 API 문서 글과 개발자 리소스 글을 참고해도 좋아요. API 문서의 전반적인 맥락은 계속 도움말 센터의 API 문서 글이 기준이에요. 그레이 라벨 환경이 필요할 때는 위의 문서 링크를 쓰세요.

## 그레이 라벨 API 문서와 API/브랜드 도메인의 차이

그레이 라벨 API 문서와 **API/브랜드 도메인**은 서로 다른 도구예요. 브랜드 환경을 설정하거나 개발자 문서를 공유할 때 헷갈리지 않도록 차이를 알아 두세요.

그레이 라벨 API 문서는 별도로 제공되는 문서 사이트예요. 브랜드 노출을 줄인 API 문서를 보고 공유할 때 써요.

**API/브랜드 도메인**(**브랜드 도메인**)은 시스템이 만드는 링크를 내 브랜드에 맞게 바꿀 때 써요. 시스템이 보내는 메시지에 들어가는 브랜드 링크가 그 예예요. 그레이 라벨 API 문서를 열거나 공유하는 데는 필요하지 않아요. **API/브랜드 도메인** 설정은 '시스템 생성 링크 브랜딩' 도움말에서 따로 안내해요.

{% hint style="warning" %}
그레이 라벨 API 문서를 열려면 DNS나 커스텀 도메인 설정이 필요 없어요.
{% endhint %}

## 그레이 라벨 API 문서 사용 방법

그레이 라벨 API 문서를 쓰려고 하이퍼클래스 안에서 따로 설정할 것은 없어요. 문서 링크를 열고, 필요에 따라 고객, 개발자, 연동 팀에 바로 공유하면 돼요.

그레이 라벨 API 문서를 열고 공유하려면 다음 순서로 진행하세요.

1. [그레이 라벨 API 문서](https://marketplace.leadconnectorhq.com/docs)를 엽니다.
2. 연동이나 개발 목적에 맞는 API 문서를 살펴봅니다.
3. 그레이 라벨 문서 환경이 필요할 때 고객, 외부 개발자, 연동 파트너에게 문서 링크를 공유합니다.
4. 커스텀 연동이나 **마켓플레이스 앱**을 만들 때는 **비공개 연동**, 개발자 마켓플레이스 설정 같은 도움말 센터 자료를 함께 활용합니다. **비공개 연동**은 안전한 커스텀 연결에 쓰고, 개발자 마켓플레이스 자료는 앱 개발 작업을 지원해요.
5. 구현을 시작하기 전에 개발자나 고객에게 필요한 API 영역, 인증 방식, 스코프, 엔드포인트를 확인합니다.

## 자주 묻는 질문

### 이번 업데이트로 기존 API 기능이 바뀌나요?
아니요. 릴리스 노트에 따르면 이번 개선은 문서 호스팅, 브랜딩, 레퍼런스 업데이트에 초점을 맞췄어요. API 동작, 인증, 스코프, 엔드포인트, 기존 연동이 바뀐다는 내용은 없어요.

### 기존 연동을 업데이트해야 하나요?
문서가 별도 사이트에서 제공된다는 이유만으로 기존 연동을 업데이트할 필요는 없어요. 별도의 API 릴리스나 엔드포인트 변경 때문에 필요한 경우에만 개발자가 업데이트하면 돼요.

### 그레이 라벨 API 문서는 누가 쓰면 좋나요?
그레이 라벨 문서 환경이 필요할 때 화이트라벨 파트너, 에이전시, 고객, 외부 개발자, 연동 파트너가 사용할 수 있어요.

### 그레이 라벨 API 문서를 고객에게 공유해도 되나요?
네. 이번 개선의 목적이 바로 파트너가 고객과 개발자에게 API 문서를 직접 공유할 수 있게 하는 거예요. 문서 화면에 플랫폼 고유의 브랜드가 드러나지 않아요.

### 그레이 라벨 API 문서를 쓰려면 커스텀 도메인이 필요한가요?
아니요. 문서는 이미 별도의 문서 사이트에서 제공돼요. 이 문서를 열려고 DNS, **API/브랜드 도메인**, 화이트라벨 도메인을 설정할 필요는 없어요.

### 그레이 라벨 API 문서가 API/브랜드 도메인과 같은 건가요?
아니요. 그레이 라벨 API 문서는 개발자 문서를 보고 공유할 때 쓰고, **API/브랜드 도메인**은 시스템이 만드는 링크를 브랜딩할 때 써요.

### 그레이 라벨 문서와 도움말 센터의 API 문서 중 어느 쪽을 써야 하나요?
고객에게 보이는 화면, 화이트라벨, 그레이 라벨 환경에서 문서를 공유할 때는 그레이 라벨 문서를 쓰세요. 더 폭넓은 안내, 설명, 지원 자료가 필요할 때는 도움말 센터의 API 글을 쓰세요.

### 그레이 라벨 문서에서는 플랫폼 브랜드가 모두 사라지나요?
릴리스 노트에는 그레이 라벨 환경에 맞추기 위해 문서 페이지와 API 레퍼런스에서 플랫폼 고유의 브랜드 표기와 언급을 제거했다고 나와 있어요.
