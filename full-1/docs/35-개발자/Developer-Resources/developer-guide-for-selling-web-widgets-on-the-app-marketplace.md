# 앱 마켓플레이스에서 웹 위젯을 판매하는 개발자 가이드

퍼널 빌더에서 쓸 수 있는 커스텀 위젯을 만들어 **앱 마켓플레이스**(App Marketplace)에 올리는 개발자를 위한 가이드예요. HTML, CSS, JavaScript 또는 Angular, React, Vue 같은 JS 프레임워크로 위젯을 만들고 렌더링하는 방법을 설명해요. 위젯 앱과 퍼널 빌더가 서로 통신하는 방법도 다뤄요.

## 사전 준비

- HTML, CSS, JavaScript에 대한 기본 지식이 있거나 JS 프론트엔드 프레임워크(Angular, React, Vue 등)를 써 본 경험이 있어야 해요.
- iFrame을 알고 있어야 해요.
- 이벤트 기반 프로그래밍을 이해하고 있어야 해요.

## 개요

커스텀 위젯을 쓰면 가격 배너나 인터랙티브 요소 같은 맞춤 요소를 퍼널 빌더에 넣어 기능을 확장할 수 있어요.

## 단계별 가이드

### 1단계: 앱 마켓플레이스에 개발자로 등록하기

1. 앱 마켓플레이스에 개발자로 가입하세요.
2. **Create App**(앱 만들기)을 클릭해 앱 만들기를 시작하세요.

### 2단계: 커스텀 위젯 설정하기

**애플리케이션 만들기**

독립적인 웹 애플리케이션을 개발하세요. 사용자가 이 앱에서 UI 요소를 조작해 설정을 고르면, 앱이 그 설정에 맞는 HTML, CSS, JS(필요한 경우)를 만들어 커스텀 위젯 요소를 렌더링해요.

- 애플리케이션에는 HTML, CSS, JS를 내보내는 다음 함수가 있어야 해요.
  - `createHtml()` => 위젯의 HTML 코드를 반환해요.
  - `createJS()` => 웹사이트에서 위젯을 실행하는 데 필요한 JS 코드를 반환해요(선택).
  - `createCss()` => 위젯 스타일에 필요한 CSS 코드를 반환해요.

퍼널 빌더와 iFrame 통신을 할 때는 `postmate`를 사용하세요. 위젯 코드는 이벤트 emit으로 퍼널 빌더에 보낼 수 있어요.

예시:

```js
parent?.emit('code', {
  html: html as string,
  js: js as string,
  elementStore: elementSettings as Object
})
```

매개변수:

- `html`: 위젯을 렌더링하는 데 필요한 HTML 콘텐츠와 스타일이에요.

  예시:

  ```html
  <style>{Your styles goes here}</style>
  <div class="hl-banner">{Your HTML content goes here}</div>
  ```

- `js`: 위젯을 실행하는 데 필요한 JS 코드예요(선택).

  {% hint style="info" %}
  JS 코드를 `<script />` 태그로 감싸지 마세요.
  {% endhint %}

  {% hint style="info" %}
  JS 기반 애플리케이션이라면, 퍼널/웹사이트 팝업과 상호작용하는 데 필요한 모든 코드와 아래에서 설명하는 다른 JS 이벤트 코드를 부모로 내보내는 JS에 포함해야 해요.
  {% endhint %}

- `elementStore`: 위젯의 설정을 나타내는 모든 변수예요. 변수 이름은 원하는 대로 지어도 돼요.

  예시:

  ```js
  settings: {
    widgetHeight: number
    widgetWidth: number
    image: string
  }
  ```

애플리케이션이 시작되거나 처음 핸드셰이크가 이뤄질 때 다음 페이로드를 받게 돼요.

```js
{ elementStore: Object } // 앱이 코드를 부모로 보낼 때 함께 내보낸 elementStore예요. 사용자가 퍼널 빌더에서 이 위젯에 이미 저장해 둔 설정을 미리 채울 때 사용하세요.
```

그런 다음 미리보기의 초기 상태를 반드시 emit하세요.

```js
parent?.emit('code', {
  html: html as string,
  js: js as string,
  elementStore: elementSettings as Object
})
```

{% hint style="info" %}
초기 상태를 꼭 emit하세요. 받은 데이터가 위젯의 각 설정에 모두 채워지도록 해야, 사용자가 다시 들어왔을 때 이전에 저장한 값을 보여 줄 수 있어요.
{% endhint %}

### 3단계: 퍼널 빌더와 연동하기

1. 마켓플레이스에 업로드하기

   - 프로젝트를 빌드한 뒤 HTML, CSS, JS 파일이나 dist 폴더를 zip으로 압축해 마켓플레이스 앱에 업로드하세요.
   - 플랫폼 가이드라인과 제출 요건을 지켜야 해요.

   {% hint style="warning" %}
   빌드할 때 절대 경로를 쓰지 말고, 프로젝트에서 상대 경로를 쓰세요.
   {% endhint %}

   ```
   apps/
   │
   ├── app1/
   │   ├── index.html
   │   ├── css/
   │   │   └── style.css
   │   └── js/
   │       └── script.js
   │
   └── app2/
       ├── index.html
       ├── css/
       │   └── style.css
       └── js/
           └── script.js
   ```

   index.html 기준:

   ```
   absolute path : css/style.css (Avoid this)
   relative path: ./css/style.css
   ```

   <!-- 검토 필요: 원문 내용이 서로 다름 (css/style.css 를 절대 경로 예시로 표기) -->

2. 퍼널 요소에 커스텀 위젯 추가하기

   - 승인되어 마켓플레이스에 공개되면, 퍼널 빌더의 **Custom Widgets**(커스텀 위젯) 또는 비슷한 섹션에 위젯이 표시돼요.
   - 사용자는 마켓플레이스에서 커스텀 위젯을 설치할 수 있어요.
   - 위젯을 퍼널 빌더로 드래그 앤 드롭해 추가해요.

3. 제한된 설정 구성하기

   - 여백(margin), 패딩(padding), 표시 여부(visibility), 커스텀 클래스 같은 일부 설정은 퍼널 빌더의 설정 영역에서 바로 편집할 수 있게 구성하세요.
   - 위젯의 주요 설정은 애플리케이션이 처리하는 외부 팝업에서 구성하세요.

4. 위젯 렌더링하기

   - 퍼널 빌더가 생성된 HTML, CSS, JavaScript를 해석해 위젯을 렌더링할 수 있는지 확인하세요.

### 4단계: 애플리케이션과 퍼널 빌더 간 통신

iFrame 사용하기

- 설정 애플리케이션을 퍼널 빌더 안의 iframe에 호스팅하세요(호스팅은 자동으로 처리돼요).
- 설정을 조정할 때마다 HTML, CSS, JS 코드를 생성해 퍼널 빌더에 전달하는지 확인하세요.

### 5단계: 이벤트와 JS 연동

커스텀 위젯 이벤트를 쓰면 위젯이 퍼널 미리보기 환경과 통신할 수 있어요. 위젯에서 일어난 동작이 퍼널 미리보기에서 반응을 일으키게 만들 수 있어서, 인터랙티브한 웹 애플리케이션을 더 매끄럽게 구성할 수 있어요.

핵심 개념

- 이벤트 발생(Event Emission): 사용자가 버튼을 클릭하거나 설정을 바꾸는 등 위젯과 상호작용할 때, 위젯이 신호(이벤트)를 보내요.
- 이벤트 처리(Event Handling): 퍼널 미리보기가 이 신호를 받아 팝업을 열거나 퍼널의 다음 단계로 이동하는 등의 동작을 수행해요.

이벤트:

1. `customWidgetOpenPopup`

   설명: 미리보기 쪽에서 팝업을 여는 동작을 실행하는 이벤트예요.

   예시:

   ```js
   var event = new Event('customWidgetOpenPopup');
   window.dispatchEvent(event)
   ```

2. `customWidgetGoToNextStep`

   설명: 퍼널/웹사이트의 다음 단계(페이지)로 이동하는 동작을 실행하는 이벤트예요.

   예시:

   ```js
   var event = new Event('customWidgetGoToNextStGoToNextStep');
   window.dispatchEvent(event)
   ```

   <!-- 검토 필요: 원문 내용이 서로 다름 (이벤트 이름 customWidgetGoToNextStep 과 예시 코드의 이벤트 이름이 다름) -->

프레임워크 라우터를 사용한다면 `createMemoryHistory`에서 사용하세요.

참고 자료는 Vue Router Memory Mode를 확인하세요.

{% hint style="info" %}
CSS: 모바일 기기용 미디어 쿼리를 쓴다면, 퍼널 빌더의 모바일 모드와도 호환되도록 `.--mobile` 접두사가 붙은 클래스를 대상으로 지정하세요.
{% endhint %}

## 위젯 앱을 심사에 제출하기 전 체크리스트

커스텀 위젯을 개발해 퍼널 빌더에 연동할 때는 위젯이 제대로 동작하고, 다른 기능에 방해나 충돌을 일으키지 않는지 확인해야 해요. 심사에 제출하기 전에 아래 체크리스트 기준을 충족하는지 앱을 직접 테스트하세요.

1. 빌더 기능을 방해하지 않는지 확인하세요: 위젯이 매끄럽게 연동되고 퍼널 빌더의 핵심 기능에 영향을 주지 않는지 확인해요.
2. 다른 요소와 충돌하지 않는지 확인하세요: 위젯이 빌더에 이미 있는 다른 요소와 겹치거나 간섭해 화면이나 기능에 문제가 생기지 않는지 확인해요.
3. 외부 스크립트가 포함되어 있지 않은지 확인하세요: 위젯에 의도하지 않은 외부 스크립트가 들어가 있지 않은지 꼼꼼히 살펴요. 특히 그런 스크립트가 필요 없는 위젯이라면 더 신경 써 주세요. 보안 위험이나 기능 충돌이 생길 수 있어요.
4. 화이트라벨 과정을 방해하지 않는지 확인하세요: 앱이 화이트라벨을 지원한다면, 위젯이 이 기능을 그대로 유지하고 브랜드 관련 정보를 의도치 않게 노출하지 않는지 확인해요.
5. 앱 상태가 일관되게 유지되는지 확인하세요: 여러 번 상호작용하거나 다시 들어와도 위젯이 상태를 유지해서, 일관된 사용자 경험을 제공하는지 확인해요.
6. 초기 상태가 올바르게 표시되는지 확인하세요: 위젯을 불러올 때 미리 정의된 설정과 구성이 모두 의도한 대로 정확하게 표시되어야 해요.
7. 모든 설정이 제대로 동작하는지 테스트하세요: 위젯의 설정 항목을 하나씩 확인해서 버그나 예상치 못한 동작 없이 의도대로 작동하는지 확인해요.

이 항목들을 꼼꼼히 확인하면 퍼널 빌더 환경에서 커스텀 위젯의 품질과 안정성을 확보할 수 있어요. 이 체크리스트는 배포 전에 잠재적인 문제를 미리 잡아내는 품질 점검용이에요.

## 파일 업로드 방식

하이퍼클래스 개발자 가이드에 따르면 앱 마켓플레이스에는 파일을 업로드하는 옵션이 **있어요**. 다만 아래 지침을 따라야 해요.

#### ✅ 지원하는 업로드 형식

다음 순서로 진행하세요.

- 위젯 프로젝트(HTML, CSS, JS)를 빌드하세요.
- `.rar`이 아니라 `.zip` 파일로 묶으세요.
- 위젯을 설정하는 과정에서 `.zip` 파일을 앱 마켓플레이스에 업로드하세요.

#### ❌ .rar 등 다른 형식

- `.rar` 파일은 지원하지 않아요.
- 허용하는 압축 형식으로 안내된 것은 `.zip`뿐이에요.

#### 권장 사항

위젯을 만들 때는 다음 사항을 지키세요.

- 에셋에는 상대 경로를 사용하세요.
- 빌드 결과물을 깔끔하게 유지하세요. 불필요한 파일이나 폴더를 넣지 마세요.
- zip으로 압축하기 전에 HTML, CSS, JS가 올바른 디렉터리 구조에 있는지 확인하세요.

React나 Vue 같은 프론트엔드 프레임워크를 쓴다면 전체 프로젝트 디렉터리가 아니라 build/dist 폴더를 압축하세요.
