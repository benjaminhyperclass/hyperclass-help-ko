# 웹훅 로그 대시보드 개발자 가이드

웹훅 로그 대시보드에서는 연동 앱이 보낸 모든 아웃바운드 웹훅을 확인할 수 있어요. 페이로드, 시간, 전송 시도 횟수, 응답 코드를 실시간으로 볼 수 있어서 웹훅 문제를 디버깅할 때 고객지원 문의 없이 직접 원인을 찾을 수 있어요. 이 문서에서는 대시보드의 구성과 사용 방법을 안내해요.

## 웹훅 로그 대시보드란?

웹훅 로그 대시보드는 **Developer Portal**(개발자 포털) 아래 **인사이트 > 로그**에 있는 실시간 모니터링 도구예요. 아웃바운드 웹훅 이벤트마다 페이로드, 응답, 재시도 내역을 기록해요. 그래서 하이퍼클래스가 실제로 무엇을 보냈는지 직접 확인할 수 있어요. 이벤트 발생 여부를 확인하거나, 연동 문제를 진단하거나, 받는 쪽 시스템이 기대한 데이터를 받았는지 점검할 때 꼭 필요한 도구예요.

## 웹훅 로그 대시보드의 주요 장점

복잡한 이벤트 흐름을 점검할 때 특히 도움이 되는 기능들이에요.

- 즉시 전달 확인: 하이퍼클래스가 웹훅을 전달했는지, 재시도했는지 바로 확인할 수 있어요.
- 전체 페이로드 확인: 전체 JSON 페이로드와 헤더를 보면서 정확하게 디버깅할 수 있어요.
- 30일 로그 보관: 지난 로그를 30일 동안 확인할 수 있어서 오래 걸리는 조사에도 쓸 수 있어요.
- 페이로드 전체 부분 문자열 검색: 이메일, 연락처 ID, 이벤트 이름 등 어떤 값이든 바로 찾을 수 있어요.
- 시간대를 반영한 타임스탬프: 원하는 시간대로 로그를 볼 수 있어서 일관되게 점검할 수 있어요.
- 고객지원 의존도 감소: 문의를 접수하지 않고 직접 문제를 해결할 수 있어요.

## 검색과 필터

검색 도구를 쓰면 조사하려는 웹훅 이벤트를 빠르게 좁힐 수 있어요. 특정 연락처 ID, 이메일, 이벤트 유형에 연결된 웹훅을 찾을 때 모두 사용할 수 있어요.

전체 검색창은 페이로드 전체에서 부분 문자열 일치를 지원해요. 값의 일부만 입력해도 이벤트를 찾을 수 있어요. 아래 항목으로 결과를 더 좁힐 수도 있어요.

- Webhook ID
- 이벤트 유형
- 기간
- 상태 코드

## 일부 실패한 웹훅의 재시도 기간 연장

웹훅 로그에서는 전송 시도가 시간에 따라 어떻게 이어지는지 볼 수 있어요. 이제 실패 유형에 따라 재시도 방식이 달라서, 일부 실패한 웹훅 이벤트는 예전보다 더 긴 재시도 기록이 남을 수 있어요.

로그에서 실패한 웹훅 시도를 확인할 때 참고하세요.

- HTTP 429 실패는 기존 재시도 방식을 그대로 따라요.
- 그 밖의 실패한 웹훅 시도는 지수 백오프(exponential backoff)를 사용하기 때문에 더 긴 기간에 걸쳐 재시도될 수 있어요.
- 429가 아닌 실패는 최대 3일까지 계속 재시도될 수 있어요.

덕분에 엔드포인트가 일시적으로 불안정했던 상황을 조사하거나, 실패한 웹훅이 나중에 복구되었는지 확인하기가 더 쉬워요.

## 상세 패널

상세 패널에서는 특정 웹훅 이벤트를 더 자세히 볼 수 있어요. 처리 결과를 검증하고 문제를 해결하는 데 필요한 정보를 한 줄씩 살펴볼 수 있어요.

로그 항목을 선택하면 아래 정보가 담긴 패널이 열려요.

- Webhook ID
- 시도 횟수
- 이벤트 이름
- 타임스탬프 기록(생성, 전달, 재시도)
- HTTP 응답 코드와 전달 상태
- 전체 JSON 페이로드와 원클릭 **복사** 옵션

복사한 페이로드는 Postman이나 Webhook.site 같은 도구에 붙여 넣어 다시 보내 보거나 시뮬레이션할 수 있어요.

## 시간대 설정

익숙한 시간대로 타임스탬프를 보면 이벤트를 진단하거나 팀과 협업할 때 혼동이 줄어요. 사용자마다 원하는 시간대를 직접 고를 수 있어요.

웹훅 로그 대시보드의 기본 시간대는 중부 시간(Central Time)이에요. 페이지 상단의 선택기에서 원하는 시간대로 바꿀 수 있어요. 한 번 선택한 시간대는 기억되어 다음 접속 때도 그대로 적용돼요.

## 보관 기간

웹훅 로그는 30일 동안 자동으로 저장돼요. 최근 활동은 물론, 오래 걸리는 디버깅 작업에서도 로그를 확인할 수 있어요.

30일이 지나면 로그는 영구 삭제돼요. 장기 감사나 컴플라이언스를 위해 보관해야 하는 페이로드는 미리 저장하거나 복사해 두세요.

## 웹훅 로그 대시보드 사용 방법

웹훅 로그 대시보드에 접속하면 웹훅 활동을 바로 확인하고 문제 해결을 시작할 수 있어요. 아래 순서대로 앱에서 발생한 이벤트를 확인해 보세요.

1. 마켓플레이스에 로그인한 뒤 **Developer Portal > 인사이트 > 로그**로 이동하세요.
2. **Webhook Logs**(웹훅 로그) 탭을 선택하세요.

   ![웹훅 로그 탭 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155059717274/original/3s7evYSgDhAUXuTBODI_LUdMv1T8O7rE7g.png?1764686192)

3. (선택) 오른쪽 상단에서 시간대를 현지 시간에 맞게 바꾸세요.
4. 앱에서 이벤트를 발생시켜 테스트 웹훅을 만드세요.
5. 검색창에 이메일 같은 고유 식별자를 입력해 이벤트를 찾으세요.
6. 이벤트 행을 클릭해 상세 패널을 열고 페이로드와 응답을 확인하세요.
7. 추가로 분석하거나 팀에 공유하려면 **복사** 버튼을 사용하세요.
8. 팀과 함께 디버깅할 때는 필요에 따라 Webhook ID나 페이로드를 전달하세요.

## 자주 묻는 질문

### 대시보드에서 실패한 전송 시도도 볼 수 있나요?
네. 실패와 재시도를 포함한 모든 시도가 응답 코드와 타임스탬프와 함께 표시돼요.

### 로그를 내보낼 수 있나요?
직접 내보내기는 지원하지 않아요. 대신 페이로드를 하나씩 복사하거나 API로 웹훅 데이터를 가져올 수 있어요.

### 30일 보관 기간이 지나면 어떻게 되나요?
30일이 지난 로그는 영구 삭제돼요.

### 시간대를 바꾸면 다른 사용자에게도 영향이 있나요?
아니요. 시간대 설정은 사용자별로 저장돼요.

### 서브 계정마다 별도의 대시보드가 있나요?
대시보드에는 내 개발자 계정과 애플리케이션에 연결된 웹훅 이벤트가 표시돼요.

### 페이로드 데이터가 가려지거나 잘려서 보이나요?
아니요. 페이로드는 전달된 그대로 모든 필드가 표시돼요.

### 개발자 권한이 없는 에이전시 관리자도 이 로그를 볼 수 있나요?
Developer Portal 권한이 있는 사용자만 웹훅 로그 대시보드에 접근할 수 있어요.

### 로그를 보면 API 호출 한도에 포함되나요?
아니요. 로그를 확인해도 API 호출이 소모되지 않아요.
