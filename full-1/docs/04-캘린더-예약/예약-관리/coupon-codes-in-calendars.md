# 캘린더에서 쿠폰 코드 사용하기

예약 위젯으로 들어오는 캘린더 예약에 할인 쿠폰 코드를 적용할 수 있어요. 고객이 결제 단계에서 유효한 쿠폰을 입력하면 할인이 적용되고, 그 내역은 예약 창의 **결제** 탭에서 확인할 수 있어요.

## 캘린더 쿠폰 코드 개요

고객은 예약 위젯에서 예약하는 동안 할인 쿠폰 코드를 입력할 수 있어요. 유효한 코드를 적용하면 위젯이 가격을 바로 다시 계산해요. 예약 기록의 **결제** 탭에는 **Discount (Coupon)**(할인(쿠폰)) 항목이 따로 표시돼요. 쿠폰 규칙은 다음 항목으로 직접 정할 수 있어요.

- 퍼센트 할인 또는 고정 금액 할인
- 사용 가능 기간
- 사용 횟수 제한
- 상품이나 캘린더별 적용 대상

## 캘린더 쿠폰 코드의 장점

쿠폰으로 특정 대상을 겨냥한 프로모션을 간편하게 운영할 수 있어요.

- 전환율 상승: 적절한 때에 할인을 제공하면 결제 단계의 부담과 장바구니 이탈이 줄어요.
- 유연한 프로모션: 시즌 행사나 기간 한정 캠페인에 퍼센트 할인이나 고정 금액 할인을 쓸 수 있어요.
- 관리와 타기팅: 연락처별 또는 전체 사용 횟수를 제한해서 쿠폰이 과도하게 쓰이지 않게 할 수 있어요.
- 더 나은 고객 경험: 고객이 예약 위젯에서 바로 코드를 적용하거나 제거할 수 있고, 가격도 즉시 바뀌어요.

## 지원 캘린더와 제한 사항

- 쿠폰 코드는 Neo와 Classic 예약 위젯을 쓰는 모든 캘린더, 그리고 서비스(v2)에서 지원돼요.
- 이전 버전인 서비스 메뉴(v1)에서는 쿠폰 코드를 지원하지 않아요. 더 새로운 예약 흐름과 지속적인 지원, 쿠폰 코드 같은 기능을 쓰려면 서비스(v2)로 옮기시길 적극 권장해요.
- 쿠폰 코드는 예약 위젯에서만 쓸 수 있어요. 앱 안의 예약 창에서 직접 만든 예약에는 적용할 수 없어요. 이 기능은 이후 업데이트에서 지원할 예정이에요.

## 캘린더에서 쿠폰 코드 사용하기

### 1단계. 캘린더에서 Accept Payments와 쿠폰 코드 켜기

쿠폰을 만들기 전에 캘린더에서 결제를 먼저 켜 두세요.

1. **캘린더 설정 > Forms & Payments**(폼 및 결제)로 이동해요.
2. **Accept Payments**(결제 받기)를 켜요.
   - 켜면 **상품** 탭에 *Calendar* 태그가 붙은 **상품**이 자동으로 만들어져요. 이 상품은 삭제할 수 없어요.
3. 아래로 스크롤해서 **쿠폰 코드** 옵션을 **활성화**해요.
   - 예약 위젯에 쿠폰 입력란이 추가돼요.

{% hint style="info" %}
쿠폰을 쓰려는 캘린더마다 각각 켜야 해요.
{% endhint %}

{% hint style="info" %}
서비스의 쿠폰 코드 표시 여부는 전체 설정으로 관리해요. **캘린더 > 서비스 > 글로벌 설정 > 결제 설정**에서 **쿠폰 코드**를 설정하세요. 쿠폰 코드를 끄면 서비스 예약 페이지에서 쿠폰 코드 입력란이 숨겨져요.
{% endhint %}

![캘린더 설정에서 쿠폰 코드를 켜는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155053042348/original/2BmUcD2W08bw34s9w76leLfpB334HvfghQ.png?1756923074)

### 2단계. 쿠폰 만들기

**결제 > 쿠폰**으로 이동해서 **New Coupon**(새 쿠폰)을 클릭하면 다음 항목이 보여요.

- **쿠폰 코드**: 원하는 코드(예: `10OFF`)를 직접 입력하거나 **생성**을 클릭해 자동으로 만들어요.
- **쿠폰 유형**: 아래 중에서 선택해요.
  - **퍼센트 쿠폰** (예: 10% 할인)
  - **고정 금액** (예: $50 할인)
- **제공된 할인**: 할인율이나 할인 금액을 입력해요.
- **Start Date Time**(시작 날짜 및 시간)과 **종료 날짜 및 시간**: 쿠폰을 쓸 수 있는 기간을 정해요.
- **Limit Redemptions**(사용 횟수 제한): 선택 사항이에요. 쿠폰을 전체 몇 번까지 쓸 수 있는지 제한해요.
- **Limit to Products/Offers**(상품/오퍼로 제한): 쿠폰을 적용할 캘린더나 상품을 골라요.
- **Limit to One Use Per Customer**(고객당 1회로 제한): 같은 고객이 여러 번 쓰지 못하게 해요.

저장하면 쿠폰을 고객에게 공유할 수 있어요.

{% hint style="info" %}
쿠폰 만드는 방법을 더 알아보려면 '상품 쿠폰 만들기' 문서를 참고하세요.
{% endhint %}

![쿠폰 만들기 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155053042418/original/w6kgwOtoYOhG_9Kz9DHcjiCAh__kzqBt8g.png?1756923179)

### 3단계. 고객이 보는 화면

- 고객이 캘린더 위젯으로 예약하면 쿠폰 코드 입력란이 보여요.
- 코드가 유효하면:
  - 할인이 바로 적용돼요.
  - 결제하기 전에 할인된 합계가 표시돼요.
- 코드가 유효하지 않으면:
  - 오류 메시지가 나타나요.

**Charge upfront**(선결제)를 켜 둔 경우에는 쿠폰을 적용한 최종 금액에 따라 결제 여부가 정해져요.

- 쿠폰을 적용하고도 금액이 **$0**보다 크면, 고객이 결제 정보를 입력하고 할인된 금액을 결제해요.
- 쿠폰으로 최종 금액이 **$0**이 되면, 카드 정보를 받거나 결제를 처리하지 않고 예약이 이어져요.

![고객이 예약 위젯에서 쿠폰 코드를 입력하는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155053042475/original/22Nepc6ubOIoY2QkZJ9V__078Aw5h90NfA.png?1756923322)

### 4단계. 쿠폰 사용 내역 확인하기

쿠폰과 결제 내역은 예약 창의 **결제** 탭에서 모두 확인할 수 있어요.

- 적용된 쿠폰
- 할인 금액
- 조정된 합계
- 참석자별 결제 내역

## 중요 업데이트: 주문 생성과 $0 거래

2025년 12월 22일 릴리스 이후, 쿠폰 코드와 캘린더 결제가 함께 쓰일 때 주문, 인보이스, 거래가 처리되는 방식이 바뀌었어요. 여기서는 새로운 동작과 함께 **$0 거래**와 **인보이스가 보이지 않는** 경우에 대해 자주 묻는 내용을 정리했어요.

{% hint style="info" %}
이 내용은 미팅 캘린더에만 해당해요. 새 서비스 모듈로 하는 서비스 예약은 일부만 결제된 예약에도 인보이스가 만들어진 적이 없어요.
{% endhint %}

### 1. 인보이스 생성 방식 변경

이전에는 예약에서 일부만 결제되면 일부 결제된 인보이스가 자동으로 만들어졌어요.
이번 릴리스 이후에는 이런 경우에 인보이스가 더 이상 만들어지지 않고, 대신 주문이 만들어져요.

- 결제가 필요하면 주문에 대해 결제를 받을 수 있어요.
- 이 변경으로 플랫폼 전체에서 주문 기준으로 결제를 추적하는 방식이 통일돼요.

### 2. $0 캘린더 예약 결제 방식

**Charge upfront**(선결제)를 켜 두면, 쿠폰이나 할인을 적용하고 난 최종 결제 금액을 기준으로 결제를 받아요.

- 최종 금액이 **$0**보다 크면 고객에게 결제 정보를 요청하고 최종 금액을 결제해요.
- 설정한 예약 금액이 **$0**이면 카드 정보를 요청하지 않고 결제도 처리하지 않아요.
- 쿠폰으로 최종 금액이 **$0**이 되면 카드 정보를 요청하지 않고 결제도 처리하지 않아요.
- 쿠폰으로 가격이 내려가도 **$0**보다 크게 남으면 결제 정보를 요청하고, 할인 후 남은 금액을 결제해요.

그래서 무료 예약을 하는 고객은 불필요한 결제 정보를 입력하거나 **$0 결제 거래**를 거치지 않아도 돼요.

{% hint style="info" %}
예약 중에 결제하지 않고 고객의 카드 정보만 저장하고 싶다면, $0 선결제를 설정하지 말고 **Collect Card on File**(카드 정보 저장)을 사용하세요.
{% endhint %}

### 3. 주문이 만들어지는 경우

- 캘린더에서 **Accept Payments**를 켜 두었다면 주문은 항상 만들어져요.
- 캘린더에서 결제를 켜지 않았다면 주문은 만들어지지 않아요.

예약할 때 바로 결제가 이루어지지 않는 경우에도 같은 방식이 적용돼요.

### 4. 기존 워크플로우에 미치는 영향 (인보이스 트리거)

**Invoice Created**(인보이스 생성됨) 트리거로 만든 워크플로우가 있다면 수정해야 해요.

{% hint style="warning" %}
조치가 필요해요. 워크플로우가 계속 의도대로 실행되도록 **Invoice Created** 트리거를 **Order Created**(주문 생성됨) 트리거로 바꿔 주세요.
{% endhint %}

## 자주 묻는 질문

### 예약 후에 할인 내역은 어디서 보나요?
예약을 열고 **결제** 탭을 확인하세요. **Discount (Coupon)**(할인(쿠폰)), **Amount Paid**(결제 금액), **Remaining Balance**(남은 잔액) 합계가 보여요.

### 쿠폰을 시작한 뒤에도 수정하거나 비활성화할 수 있나요?
네. **결제 > 쿠폰**에서 쿠폰을 열어 사용 제한이나 기간을 바꾸거나 비활성화할 수 있어요. 변경 내용은 이후 예약부터 적용돼요.

### 실제 카드로 결제하지 않고 쿠폰을 테스트하려면 어떻게 하나요?
캘린더의 **결제 모드**를 **테스트**로 설정하고, 결제 게이트웨이의 테스트용 정보(예: Stripe 테스트 카드)로 테스트 예약을 진행하세요. 테스트가 끝나면 **라이브**로 다시 바꾸세요.

### 한 번의 예약에 쿠폰을 두 개 이상 쓸 수 있나요?
아니요. 결제 한 번에 사용할 수 있는 코드는 하나뿐이에요. 고객은 결제하기 전에 코드를 제거하고 다른 코드를 적용할 수 있어요.

### 쿠폰 코드는 대소문자를 구분하나요?
구분하지 않아요. 예를 들어 쿠폰 코드가 'SUMMER25'일 때 고객이 'Summer25'라고 입력해도 쿠폰이 적용돼요.
