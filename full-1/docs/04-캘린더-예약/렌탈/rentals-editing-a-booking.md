# 대여 — 예약 편집하기

**대여**(Rentals)에서 이미 만든 예약을 편집하는 방법을 설명해요. 예약 편집 화면으로 들어가는 방법, 화면의 각 영역, 결제·인보이스 관리, 예약 상태 변경 방법을 알려 드려요. 모든 예약의 기록을 정확하고 최신으로 유지하는 데 도움이 돼요.

## 예약 편집 개요

**Edit Booking**(예약 편집) 페이지에서는 관리자가 기존 예약을 수정하고, 결제를 관리하고, 예약을 만든 뒤에 생긴 변경 사항을 반영할 수 있어요. 고객 정보, 리스팅, 인보이스, 거래 내역, 예약 상태까지 예약의 모든 내용을 한곳에서 볼 수 있어요.

이 페이지에서는 다음 작업을 할 수 있어요.

- 리스팅을 추가·수정·삭제하고, 대여 기간이나 수량을 조정해요.
- 결제, 보증금, 인보이스를 관리해요.
- 모든 금전 거래와 결제 요약을 확인해요.
- 예약과 리스팅의 상태를 바꾸거나, 예약 전체를 취소해요.

이렇게 필요할 때 예약을 수정하면서도 데이터와 금액을 정확하게 유지할 수 있어요.

## 렌탈 예약 편집의 장점

- 유연한 일정: 공개 시간 선택기를 꺼 두었더라도 관리자는 원하는 시작·종료 시간을 직접 지정할 수 있어요.
- 충돌 방지: 버퍼와 재고 기준은 항상 적용돼서, 편집해도 예약이 겹치지 않아요.
- 명확한 금액 관리: **Payment Summary**(결제 요약), **인보이스**, **거래 내역**에서 무엇이 바뀌었고 얼마가 남았는지 정확히 볼 수 있어요.
- 보증금 관리: **Collect Upfront**(선결제)나 **Card on File**(저장된 카드) 방식의 보증금을 지원하고, 필요하면 청구하거나 환불할 수 있어요.
- 여러 리스팅 예약의 정확성: 리스팅이 여러 개 담긴 예약에서 하나만 수정해도 나머지에는 영향이 없어요.
- 즉시 반영: 저장하면 **예약 목록 보기**와 **캘린더 보기**에서 바로 결과를 확인할 수 있어요.

## 예약 편집 화면 살펴보기

예약을 열면 페이지가 여러 영역으로 나뉘어 있어요. 영역마다 예약의 서로 다른 부분을 관리해요.

1. **Booking Summary**(예약 요약) – 예약 식별 정보, 상태, 결제 상태, 대여 날짜를 보여 줘요.
2. **고객 정보** – 예약에 연결된 고객의 연락처 정보를 보여 줘요.
3. **리스팅** – 예약에 포함된 모든 대여 항목을 편집 가능한 필드와 함께 보여 줘요.
4. **내부 메모** – 예약에 남긴 내부 메모를 모두 보여 주고, 메모를 더 추가할 수 있어요.
5. **Payment Summary**(결제 요약), **인보이스**, **거래 내역** – 인보이스와 결제 내역을 포함한 금액 현황을 보여 줘요.
6. **Booking Actions**(예약 작업) – 상태와 결제를 관리하는 버튼이 있어요.
7. 상태 관리 – 예약 상태와 리스팅 상태가 서로 어떻게 연결되는지 설명해요.

아래에서 영역별로 예시와 참고 사항을 함께 자세히 설명해요.

## Booking Summary

**Booking Summary**는 페이지 맨 위에서 예약의 핵심 정보를 한눈에 보여 줘요. 편집하기 전에 예약 내용을 빠르게 파악할 수 있어요.

**포함된 정보:**

- **연락처 정보** – 예약한 연락처의 이름을 보여 줘요. 옆의 툴팁 위로 마우스를 올리면 예약 출처(예: 캘린더 페이지, 예약 페이지)와 예약한 사람도 확인할 수 있어요.
- **예약 ID** – 예약을 추적하는 데 쓰는 고유 식별 번호예요.
- **상태** – 예약의 현재 상태예요. **미확인**, **예약됨**, **활성**, **완료**, **Partial**(부분), **취소됨** 중 하나로 표시돼요.
- **결제 상태** – 전체 결제 진행 상황이에요. **Pending**(대기 중), **부분 결제됨**, **유료** 중 하나로 표시돼요.
- **Booking Source**(예약 출처) – 예약이 만들어진 경로예요(예: 캘린더 페이지, 예약 페이지).
- **시작 날짜 시간** – 예약에 포함된 모든 리스팅 중 **가장 이른 시작 시간**을 보여 줘요.
- **종료 날짜 및 시간** – 모든 리스팅 중 **가장 늦은 종료 시간**을 보여 줘요.
- **시간대** – **글로벌 설정 > 예약**에서 설정한 **비즈니스 시간대**를 보여 줘요.

{% hint style="info" %}
자세히 편집하기 전에 예약 요약에서 예약 일정, 결제 진행 상황, 출처를 먼저 확인해 보세요.
{% endhint %}

## 리스팅

예약에 포함된 리스팅이 세부 정보와 편집 가능한 필드와 함께 이곳에 표시돼요.

**리스팅마다 할 수 있는 작업:**

- 수량을 수정해요.
- 시작·종료 날짜나 시간을 조정해요.
- 해당 리스팅의 총 가격을 확인해요.
- 해당 리스팅에 적용된 보증금을 확인해요.

**사용할 수 있는 버튼:**

- **+ New listing**(새 리스팅 추가) – 예약에 새 리스팅을 추가해요.
- **삭제** – 예약에서 리스팅을 제거해요.

{% hint style="info" %}
편집할 때는 운영 시간, 고정 기간, 예약 가능 기간 같은 기본 제한을 무시하고 변경할 수 있어요. 다만 일정이 정확하고 겹치지 않도록 앞뒤 버퍼는 그대로 적용돼요.
{% endhint %}

{% hint style="warning" %}
리스팅을 수정하거나 새로 추가할 때는 해당 시간대에 재고가 있어야 선택할 수 있어요.
{% endhint %}

## Payment Summary

**Payment Summary**는 예약의 금액 현황을 보여 줘요. 합계, 이미 받은 결제, 남은 금액, 보증금 처리 방식을 확인할 수 있어요.

**표시되는 항목 예시:**

- **Rental Subtotal**(대여 소계): $1069.50
- **Security Deposit Total**(보증금 합계): $50.00
- **총 금액**: $1069.50
- **유료**: $500.00
- **Amount Due**(남은 결제 금액)

<!-- 검토 필요: 원문 내용이 서로 다름 -->

**각 항목의 의미:**

- **Rental Subtotal** – 모든 리스팅 금액을 합친 값이에요.
- **세금** – 리스팅에 적용된 세금이에요(해당하는 경우).
- **보증금** – 예약에 적용되는 보증금 총액이에요. **Collect Upfront** 방식이면 미리 받을 총액의 일부가 돼요. 보증금 방식이 **Card on File**이면, 나중에 파손이나 약관 위반이 생겼을 때 청구할 수 있는 금액을 미리 알려 주는 역할을 해요.
- **Security Deposit Charged**(청구된 보증금) – 보증금을 사용하도록 설정하고 **Card on File**로 지정한 뒤, 보증금을 직접 청구하면 나타나요. 예약에 실제로 청구된 보증금을 보여 줘요.
- **총 금액** – 보증금과 해당되는 기타 요금을 포함해 최종적으로 받아야 할 금액이에요.
- **유료** – 지금까지 받은 총 금액이에요.
- **오늘 마감** – 앞으로 더 받아야 할 남은 금액이에요.

{% hint style="info" %}
**보증금 – Collect Upfront 정책**: 보증금이 소계에 자동으로 포함돼요.

**보증금 – Card on File 정책**: 보증금을 직접 청구한 뒤에만 합계에 나타나요.
{% endhint %}

이 영역에서 결제 진행 상황과 남은 금액을 한눈에 확인할 수 있어요.

## 인보이스

인보이스는 예약마다 자동으로 만들어져요. 요금, 결제, 조정 내역을 항목별로 명확하게 기록해서, 고객과 관리자 모두 예약별 금액 문서를 투명하게 확인할 수 있어요.

**인보이스가 작동하는 방식:**

- 예약을 만들 때 첫 인보이스가 자동으로 생성돼요. 이후의 편집, 결제, 요금은 같은 인보이스에 반영돼요.
- 인보이스에는 예약에 연결된 리스팅과 보증금이 반영돼요.
- 여러 개를 대여하는 리스팅은 인보이스 항목에 예약한 1개 기준의 계산된 비용이 단가로, 실제 예약한 개수가 수량으로 표시돼요. 최종 대여 요금이 어떻게 계산됐는지 확인하기 쉬워요.

  예를 들어 개당 $150인 항목을 4개 예약하면 인보이스에 다음과 같이 표시돼요.

  - **Price**(단가): $150.00
  - **Qty**(수량): 4
  - **Subtotal**(소계): $600.00
- 인보이스는 예약 수량을 곱하기 전의 개당 대여 가격을 계산해서, 최종 항목 합계를 구해요.

## 거래 내역

**거래 내역** 영역에는 예약과 관련된 모든 금전 활동이 나열돼요. 결제, 보증금, 환불을 모두 투명하게 추적할 수 있어요.

**거래마다 표시되는 정보:**

- **날짜 및 시간** – 거래가 발생한 시점이에요.
- **금액** – 청구, 결제, 환불된 금액이에요.
- **상태** – 거래가 성공했는지, 실패했는지, 환불됐는지를 나타내요.

환불은 **결제 > 거래 내역**에서 직접 처리해야 하고, 기록되면 이곳에 반영돼요. 거래 기록으로 예약과 관련된 모든 금전 흐름을 확인할 수 있어요.

![거래 내역 영역](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155073944751/original/WzXMF6BMDBN3CZvmnsa61tat9ix08WDz8w.png?1781769541)

## 내부 메모

오른쪽 열 맨 아래에 **내부 메모** 영역이 있어요. 예약과 관련해 이전에 남긴 내부 메모가 모두 표시되고, 관리자가 새 메모를 추가할 수 있어요.

- 메모 보기: 기존 내부 메모를 스크롤하며 맥락을 확인할 수 있어요. 메모마다 작성자와 작성 시각이 표시돼요.
- **편집** 또는 **삭제**: 내부 메모는 내용을 고치거나, 필요 없으면 삭제할 수 있어요.
- 새 메모 추가: **Add Internal Note**(내부 메모 추가)를 클릭해 업데이트, 알림, 세부 사항을 기록하세요. 이 메모는 고객에게 보이는 페이지나 인보이스에는 나타나지 않아요.

{% hint style="info" %}
특별한 상황, 후속 조치, 팀에 전달할 지침을 기록할 때 내부 메모가 유용해요.
{% endhint %}

## Booking Actions

관리자는 **Edit Booking** 페이지에서 바로 작업 버튼을 눌러 예약 상태를 바꾸고 결제를 관리할 수 있어요.

#### 상태 작업

- **Mark as Confirmed**(확정으로 표시) – 예약이 **미확인** 상태일 때만 나타나요. 모든 리스팅을 **예약됨**으로 바꿔요.
- **Mark as Booked / Active / Complete**(예약됨 / 활성 / 완료로 표시) – 상태를 바꿀 리스팅을 선택하는 창이 열려요.
- **더보기 메뉴(⋯)** – 다음 항목이 들어 있어요.

  - **Revert to Unconfirmed**(미확인으로 되돌리기) – 예약 전체와 모든 리스팅을 **미확인**으로 바꿔요.
  - **Cancel Booking**(예약 취소) – 예약과 그 아래 모든 리스팅을 취소해요.

![상태 작업 버튼](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155073944972/original/VR3s_w44bRk6x-bdsZ8eAqz0oZWNOMhUGQ.png?1781769657)

#### 결제 작업

- **결제 수집** – 온라인으로 결제를 받거나 수동 결제를 기록하는 결제 창이 열려요.
- **Charge Security Deposit**(보증금 청구) – **보증금**을 사용하도록 설정하고 **Card on File**로 지정했을 때만 쓸 수 있어요. 보증금을 직접 청구할 수 있고, 청구한 금액은 합계와 인보이스에 **Security Deposit Charged**로 추가돼요.

## 상태 관리

상태는 예약이나 리스팅이 대여 과정에서 어느 단계에 있는지를 나타내요.

#### 리스팅 단위 상태

리스팅은 진행되는 대로 하나씩 직접 상태를 바꿔야 해요.

- **미확인** – 예약은 만들어졌지만 아직 확정되지 않았어요.
- **예약됨** – 확정되어 시작을 기다리고 있어요.
- **활성** – 현재 진행 중이에요.
- **완료** – 성공적으로 끝났어요.
- **취소됨** – 예약을 취소하면 자동으로 설정돼요.

#### 예약 단위 상태

예약 단위 상태는 리스팅 상태에 따라 자동으로 정해져요.

| 리스팅 조합 | 예약 상태 |
| --- | --- |
| 모두 미확인 | **미확인** |
| 모두 예약됨 | **예약됨** |
| 모두 활성 | **활성** |
| 모두 완료 | **완료** |
| 섞여 있음(예: 예약됨 + 활성) | **Partial** |
| 모두 취소됨 | **취소됨** |

{% hint style="info" %}
**Cancel Booking**을 클릭하면 예약과 모든 리스팅이 즉시 **취소됨**으로 바뀌어요.
{% endhint %}

편집을 마친 뒤에는 이렇게 하세요.

1. 변경한 내용과 금액 정보를 모두 검토하세요.

## 알아 두면 좋은 동작

예약 결제, 편집, 환불을 관리할 때 기억해 두면 좋은 시스템 동작이에요.

- **일부 또는 전액 결제 후 편집**: 예약이 **부분 결제됨**이나 **유료** 상태여도, 수정한 총액이 이미 결제된 금액 이상이면 편집할 수 있어요.
- **환불 처리**: 환불은 **거래 내역**에서 직접 처리해요. 환불해도 인보이스나 결제 요약은 자동으로 바뀌지 않지만, 해당 거래 항목의 상태가 **환불됨** 또는 **부분 환불됨**으로 바뀌어요.
- **양수 잔액 유지**: 정확한 회계를 위해, 그리고 데이터가 어긋나지 않도록 합계는 항상 양수로 유지돼요.

이런 동작 덕분에 예약 금액 관리가 투명하고, 추적하기 쉽고, 일관되게 유지돼요.

## 자주 묻는 질문

### 결제가 끝난 인보이스도 수정할 수 있나요?
수정한 총액이 이미 결제된 금액 이상이면 편집할 수 있어요.

### 일부만 결제된 예약을 편집하면 어떻게 되나요?
새 총액이 이미 결제된 금액과 같거나 그보다 높으면 부분 결제된 예약도 편집할 수 있어요. 변경 사항은 가장 최근 인보이스에 반영돼요.

### 환불하면 예약에 어떤 영향이 있나요?
환불은 **거래 내역**에서 직접 처리해요. 인보이스나 결제 요약의 합계는 바뀌지 않지만, 해당 거래의 상태가 **환불됨** 또는 **부분 환불됨**으로 바뀌어요.

### 전액 결제된 예약에 새 항목을 추가하면 어떻게 되나요?
기존 인보이스가 자동으로 업데이트돼서 새 요금이 기록돼요.

### 합계가 0원 아래로 내려갈 수도 있나요?
아니요. 정확하고 추적 가능한 금액 기록을 위해 합계는 항상 양수로 유지돼요.
