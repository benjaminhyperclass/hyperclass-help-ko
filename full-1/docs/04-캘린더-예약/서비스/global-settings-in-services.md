# 서비스 글로벌 설정

**글로벌 설정**은 서비스 모듈에서 가장 중요한 설정을 한곳에 모아 둔 곳이에요. 예약 페이지, 결제, 일정, 알림, 서드파티 캘린더 동작에 같은 규칙을 한 번에 적용할 때 쓰세요. 이 문서에서는 서비스의 **글로벌 설정**에서 고를 수 있는 옵션을 안내해요.

## 글로벌 설정 한눈에 보기

**글로벌 설정**에서 정한 내용은 모든 서비스에 적용돼요. 설정은 다섯 가지 영역으로 나뉘어요. <!-- 검토 필요: 원문 내용이 서로 다름 --> 

1. **In-App Settings**(인앱 설정): 앱 안에서 쓰는 플랫폼 관련 옵션을 설정해요.
2. **Booking Page**(예약 페이지): 고객에게 보이는 **예약 위젯** 설정을 관리해요.
3. **결제 설정**: 결제 방식과 통화를 정하고 결제 관련 옵션을 모두 관리해요.
4. **Service Settings**(서비스 설정): 서비스 예약과 예약 일정에 관한 옵션을 정해요.
5. **추가 설정**: 부가 기능을 위한 기타 설정이에요.
6. **알림 설정**: 예약 소식을 고객과 직원에게 언제, 어떻게 알릴지 정해요.

## 글로벌 설정을 쓰면 좋은 점

설정을 한곳에서 관리하면 모든 서비스에서 일관되고 매끄러운 예약 경험을 줄 수 있어요.

- 한곳에서 관리: 예약, 결제, 일정, 알림 규칙을 한 곳에서 적용해요.
- 일관된 고객 경험: 예약 페이지의 레이아웃, 문구, 선택지를 모든 서비스에서 똑같이 유지해요.
- 빠른 변경: 직원 선택이나 결제 금액 표시 같은 공통 동작을 서비스마다 고치지 않고 바꿔요.
- 쉬운 확장: 서비스가 늘어나도 기존 리소스를 쓰는 서비스를 추가하면 돼요. 일정 운영 방식을 새로 짤 필요가 없어요.

## In-App Settings(인앱 설정)

- **View Options**(보기 옵션): 캘린더 보기를 어느 요일부터 시작할지 월요일, 토요일, 일요일 중에서 골라요.
- **여러 서브 계정**: 비즈니스를 여러 지점에서 운영한다면 켜세요. 예약 페이지에 지점을 둘 이상 만들어 보여 줄 수 있어서, 고객이 예약할 지점을 고를 수 있어요. <!-- 검토 필요: 화면 이름은 '여러 서브 계정'이지만 원문은 여러 지점(Multiple Locations)을 뜻함 -->
- **Enable Resources**(리소스 활성화): 객실, 공간, 도구 같은 리소스를 쓰는 비즈니스라면 켜서 리소스를 관리하고 추적하세요. 중복 예약을 막고, 서비스에 맞는 리소스가 예약되도록 도와줘요. 켜면 **리소스** 탭이 생기고, 여기서 관련 설정을 해요.
- **Enable Add-ons**(애드온 활성화): 서비스를 예약할 때 애드온이나 추가 상품을 판매한다면 켜세요. 추가 서비스를 판매하는 데 도움이 돼요. 켜면 **애드온** 탭이 생기고, 여기서 설정해요.

## 예약 페이지 설정(Booking Page Settings)

예약 페이지 설정은 4개 영역으로 나뉘어요. 예약 페이지 사용자 지정, 폼, 확인 페이지 등이에요. <!-- 검토 필요: 원문 내용이 서로 다름 -->

### 예약 페이지 사용자 지정(Customize Booking Page)

- **Company Name & Logo**(회사명 및 로고): 회사명을 입력하고 로고를 올리면 예약 페이지에 보여요.
- **Service Images**(서비스 이미지): 예약 페이지에 서비스 이미지를 보여 줄지 정해요.
  - **With Images**(이미지 포함): 서비스 카드에 올려 둔 서비스 이미지를 보여 줘요.
  - **Without Images**(이미지 제외): 서비스 이미지를 숨기고 서비스 정보를 텍스트 중심으로 보여 줘요.  
    이 설정은 서비스 예약 페이지 전체에 적용돼요. 비즈니스에 가장 잘 맞는 표시 방식을 고르세요.
- **Account Slug**(계정 슬러그): 모든 서비스 URL의 기본이 되는 고유 식별자예요.
- **Browse By**(탐색 방식): 고객이 예약 페이지에서 서비스를 찾는 방식을 정해요.
  - **Browse by Category**(카테고리별 탐색): 고객이 먼저 카테고리를 고른 뒤, 그 안의 서비스 중에서 선택해요.
  - **Browse All Services**(전체 서비스 탐색): 고객이 처음부터 모든 서비스를 볼 수 있고, 원하면 카테고리로 목록을 걸러 볼 수 있어요.
- **Booking Page Order**(예약 페이지 순서): 예약 페이지의 진행 순서를 정해요. 지점이 여러 곳이면 고객이 서비스를 먼저 고를지, 지점을 먼저 고를지 선택해요.
- **Booking Page Layout**(예약 페이지 레이아웃): 서비스를 카드 보기나 목록 보기로 보여 주거나, 고객이 원하는 보기를 바로 고르게 할 수 있어요.
- **Filter & Sort Menu Placement**(필터 및 정렬 메뉴 위치): 예약 페이지에서 필터, 정렬 옵션, 서비스 카테고리를 어디에 둘지 정해요. 컨트롤을 위쪽에 가로로 두거나 왼쪽에 세로로 둘 수 있어요. **Top Tabs**(상단 탭)를 고르면 서비스 카테고리가 예약 페이지 위쪽에 탭으로 나란히 보여요.
- **테마**: 예약 페이지를 라이트 또는 다크 테마 중에서 골라요. 헤더, 푸터, 위젯에 적용돼요.
- **언어**: 고객에게 보여 줄 예약 페이지의 언어를 선택해요.
- **기본 색상**: 버튼, 날짜 선택 등 모든 동작 요소의 색을 정해요.
- **배경 색상**: 예약 페이지의 배경 색을 골라요.
- **Service Selection Button Label**(서비스 선택 버튼 레이블): 고객이 서비스를 선택할 때 보이는 버튼 문구를 정해요(예: '예약하기').
- **Final Booking Button Label**(최종 예약 버튼 레이블): 고객이 예약을 마치는 마지막 버튼의 문구를 정해요(예: '예약 확정').
- **미리보기**: 변경한 내용이 적용된 예약 페이지를 미리 봐요.
- **Insert Custom Code**(커스텀 코드 삽입): 커스텀 CSS를 추가해서 예약 페이지의 모양을 더 세밀하게 바꿀 수 있어요. 코드를 붙여 넣고 저장하면 적용돼요.

### 추가 설정

- **Allow customers to pick who they book with**(고객이 예약할 담당자 직접 선택 허용): 예약할 때 고객이 직원을 고르게 하려면 켜세요. 켜지 않으면 가용 시간과 라운드 로빈 방식에 따라 시스템이 직원을 자동으로 배정해요.
- **Hide the “Any Available” option from Staff Selection page**(직원 선택 페이지에서 "Any Available" 옵션 숨기기): 직원 선택을 켠 경우 **Any Available**(가능한 직원 아무나) 옵션을 숨길 수 있어요. 그러면 고객이 항상 특정 직원을 골라야 해요.
- **Allow Multiple Service Selection**(여러 서비스 선택 허용): 기본으로 선택되어 있고, 고객이 한 번의 예약 과정에서 여러 서비스를 예약할 수 있어요. 고객이 한 번에 서비스 하나만 예약하게 하려면 끄세요.
- **Auto-Assign Staff Based On**(직원 자동 배정 기준): 고객이 직원을 고르지 않았을 때 쓰는 기준이에요. 시스템이 이 기준에 따라 직원을 자동으로 배정해요.
- **Allow Customers to Explore Other Services**(고객이 다른 서비스 둘러보기 허용): 기본으로 선택되어 있고, 고객이 처음 연 서비스나 카테고리 밖도 둘러볼 수 있어요. 특정 서비스나 카테고리 링크로 들어온 고객도 같은 예약 과정에서 다른 카테고리의 서비스를 보고 추가할 수 있어요. 고객이 처음 연 서비스나 카테고리 안에만 머물게 하려면 끄세요.

![예약 페이지 추가 설정 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155078080202/original/BWlat3kQ5eavHBg8TfdX2ZHrRsJSMnD7kg.png?1786423197)

### 폼

- **폼 선택**: 서비스를 예약할 때 보여 줄 폼을 골라요. 기본 폼(이름, 성, 전화번호, 이메일)을 쓰거나 **사이트 > 폼**에서 커스텀 폼을 만들어 쓸 수 있어요. 이 폼으로 예약자 정보를 받고, 그 정보로 연락처가 만들어져요.
- **Pre-populate Fields (Sticky Contacts)**(필드 미리 채우기, 스티키 연락처): 브라우저 쿠키로 고객 정보를 기억해요. 다시 방문한 고객의 예약 폼을 미리 채워 줘요. 고객이 직접 폼을 작성할 때만 켜세요. 여러 고객이 같은 브라우저를 쓰면 정보가 덮어써질 수 있어요.
- **Consent Checkbox**(동의 체크박스): 예약 과정에서 고객의 동의를 받으려면 켜세요. 동의 문구를 직접 바꿀 수 있어요. 기본 폼을 쓸 때만 사용할 수 있어요.

![폼 설정 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155047089499/original/dEY6RwUTPlKCTAwhKZ5pUUQfCR0Uiz7eSg.png?1747931046)

### 확인 페이지(Confirmation Page)

예약이 끝난 뒤에 기본 확인 페이지에 사용자 지정 메시지를 보여 주거나, 고객을 다른 페이지로 이동시킬 수 있어요.

![확인 페이지 설정 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155080593638/original/yZ6inPUwOC0Csi_i6HFXIhTR7ipjN2L6sQ.png?1789041038)

**Let a custom form override this with its own rules**(커스텀 폼의 자체 규칙으로 덮어쓰기 허용): 커스텀 폼이 확인 페이지 경험을 직접 정하게 하려면 켜세요. 켜면 다음과 같이 동작해요.

- 폼의 **On Submit**(제출 시) 동작이 **감사 메시지** 또는 **리다이렉트 URL**이면, 그 설정이 확인 페이지로 쓰여요.
- 폼의 **On Submit** 동작이 **Order confirmation**(주문 확인)이거나 적용할 수 있는 **On Submit** 동작이 없으면, 여기에서 설정한 확인 페이지 설정이 대신 쓰여요.
- 리다이렉트, 사용자 지정 메시지, 리드 부적격 처리 같은 폼의 조건 규칙도 예약이 끝난 뒤에 함께 적용돼요.

{% hint style="info" %}
커스텀 폼의 필드 표시/숨김 조건은 이 설정과 상관없이 예약 중에 항상 적용돼요.
{% endhint %}

## 결제 설정

- **테스트 모드 / 라이브 모드**: **테스트 모드**를 켜면 예약과 결제 과정을 시뮬레이션할 수 있어요. 테스트를 마치면 **라이브 모드**로 바꿔서 실제 결제를 받기 시작하세요.
- **통화**: 결제 금액을 표시하고 받을 통화를 골라요. 모든 서비스에 적용돼요. 통화를 바꿀 때는 서비스별 가격도 그에 맞게 수정하세요.
- **결제 옵션**: 고객이 서비스를 예약할 때 결제를 어떻게 처리할지 골라요.
  - **Online Payment**(온라인 결제): 고객이 예약할 때 온라인으로 결제해요. 온라인 결제를 선택하면 **보증금 또는 전액 결제 선택 허용**을 켤 수 있어요. 보증금이 설정된 서비스를 예약할 때 고객이 더 유연하게 고를 수 있어요. 결제 단계에서 고객은 필요한 보증금만 내거나 전액을 먼저 결제할 수 있어요.
  - **Pay in Person**(현장 결제): 고객이 방문했을 때 결제해요. 예약 중에는 카드나 결제 정보를 받지 않고, 결제 단계에도 결제 옵션이 나타나지 않아요.
  - **Card on File Only**(저장된 카드만): 예약 중에 카드 정보를 안전하게 받아 두지만, 예약 시점에는 고객에게 요금을 청구하지 않아요.
- **Hide Payment Amount**(결제 금액 숨기기): 예약 페이지에서 결제 금액을 숨기려면 켜세요. 결제 방식이 **Pay in Person** 또는 **Card on File**일 때만 적용돼요.
- **Coupon Codes**(쿠폰 코드): 고객이 예약할 때 쿠폰 코드를 입력해 적용하게 하려면 켜세요. 켜기 전에 **결제 > Coupon Codes**(쿠폰 코드)에서 유효한 쿠폰을 먼저 만드세요. 이 옵션을 끄면 예약 페이지에서 쿠폰 코드 입력란이 사라져요.
- **세금**: 서비스의 세금은 글로벌 설정이 아니라 개별 서비스나 연결된 상품 단위에서 설정해요. 서비스에 세금을 부과하려면 개별 서비스나 연결된 상품을 열어 해당하는 수동 세율을 설정하세요. 설정하면 예약 상세에 세금이 자동으로 나타나요.
- **Price Display Format**(가격 표시 형식): 서비스에 가격이 여러 개일 때 가격을 어떻게 보여 줄지 골라요.

  **Show Price Range**(가격 범위 표시): 가장 낮은 가격과 가장 높은 가격을 함께 보여 줘요.

  **Show Starting Price**(시작 가격 표시): 가장 낮은 가격만 시작 가격으로 보여 줘요.

  고객이 서비스 옵션이나 애드온을 고르면 표시된 시작 가격이 달라질 수 있어요. 최종 가격은 고객이 고른 내용에 따라 계산돼요.

## 서비스 설정(Service Settings)

- **서비스 간격**: 예약할 수 있는 시간대를 얼마 간격으로 보여 줄지 정해요. 예를 들어 간격을 1시간으로 정하면 가능한 시간이 오전 9시, 10시처럼 1시간마다 나타나요. 30분으로 정하면 오전 9:00, 9:30, 10:00처럼 30분마다 나타나요. 이렇게 정한 간격대로 예약 시간대가 나뉘어요.
- **최소 예약 안내 기간**: 예약 시간 전에 최소한 이만큼의 여유가 있어야 예약할 수 있어요. 예를 들어 2시간으로 정하면, 오전 10시 시간대는 같은 날 오전 8시 이후에는 예약할 수 없어요.
- **Booking Window**(예약 가능 기간): 고객이 얼마나 먼 미래까지 예약 가능 시간을 보고 예약할 수 있는지 정해요. 예약 가능 기간은 두 가지 유형 중에서 골라요.
  - **범위 기반**: 오늘부터 일정한 일수만큼의 가능 시간을 보여 줘요. 시간이 지나면 새로운 날짜가 자동으로 예약 가능해져요. 예를 들어 범위를 30일로 정하면 고객은 언제나 오늘부터 30일 뒤까지 예약할 수 있어요.

    - **Count available days only**(예약 가능한 날만 계산): 예약 가능 기간을 계산할 때 서비스를 운영하고 예약할 수 있는 날만 세려면 켜세요. 켜면 직원 가용 일정을 벗어난 날은 건너뛰고, 최소 예약 안내 기간이 끝난 뒤 처음 예약 가능한 날부터 세기 시작해요. 예약자는 설정해 둔 일수만큼을 항상 볼 수 있어요. 쉬는 날이라 비어 있는 캘린더가 보이지 않아요.  
      끄면 예약 가능 기간은 예약 가능 시간이 없는 날까지 포함해 모든 달력상의 날을 세요. 기본 동작이에요.  

      예시 — 안내 기간이 있을 때 예약 가능한 날만 계산하기  
      - 오늘: 8월 12일 수요일
      - 최소 예약 안내 기간: 2일
      - 가용 일정: 월요일~금요일
      - 예약 가능 기간: 5일(범위 기반)
      - 토글: 켜짐  

        시스템은 안내 기간을 먼저 적용한 다음, 안내 기간이 끝나고 처음 예약 가능한 날부터 가능한 날을 5일 센 날짜를 보여 줘요.  
        **예약 위젯**에는 8월 14, 15, 18, 19, 20일이 나타나요. 가능한 5일이 모두 보여요. <!-- 검토 필요: 원문 내용이 서로 다름 -->
  - **날짜 기반**: 고객이 예약할 수 있는 마지막 날짜를 포함한 특정 기간을 정해요. 계속 이동하는 범위와 달리 시작일과 종료일이 고정돼요.
- **서비스 예약 제목**: 서비스 예약 페이지로 만들어지는 예약의 제목을 정해요. {{contact.name}} 같은 커스텀 값을 쓰면 고객 정보로 예약 제목을 자동으로 맞춤 설정할 수 있어요.
- **Cancellation & Reschedule**(취소 및 일정 변경):
  - **Allow Cancellation**(취소 허용): 켜면 취소 링크의 만료 시간을 정할 수 있어요. 링크는 예약 시간 전에 정해 둔 시점에 만료되어, 직전 취소를 막아 줘요.
  - **Allow Rescheduling**(일정 변경 허용): 취소와 마찬가지로, 켜면 일정 변경 링크의 만료 시간을 정할 수 있어요. 예약 시간 전에 설정한 시점에 만료돼요.
  - **Auto Confirm New Appointments**(새 예약 자동 확정): 새 예약이 기본으로 확정 상태가 돼요. 끄면 예약이 미확정 상태가 되어, 확정하기 전에 직접 검토할 수 있어요.

## 모바일 앱 예약의 서비스 예약 제목

**서비스 예약 제목** 설정은 새 서비스 예약의 제목을 어떻게 미리 채울지 정해요. 예약 채널이 달라도 예약 이름을 일관되게 유지할 수 있어요. 공통 제목 템플릿을 하나만 쓰면 직접 수정할 일이 줄고, 웹 예약과 모바일 예약이 같은 형식으로 맞춰져요.

서비스의 **글로벌 설정**에 **서비스 예약 제목**을 설정해 두면, 모바일 앱에서 만든 새 서비스 예약의 **예약 제목** 필드에 그 제목이 자동으로 들어가요.

**서비스 예약 제목**이 비어 있거나 설정되어 있지 않으면 모바일 앱은 **\<연락처 이름\>**을 대신 써요. 그래서 기존 예약 동작은 그대로 이어져요.

이 설정은 모바일 앱에서 만드는 **새 서비스 예약**에 적용돼요.

## 추가 설정

- **연락처 배정**:
  - **Assign contacts to service staff members upon booking**(예약 시 연락처를 서비스 직원에게 배정): 켜면 연락처의 담당 사용자가 해당 예약을 맡은 직원으로 바뀌어요. 예를 들어 연락처 A의 담당 사용자가 사용자 A인데 연락처 A가 사용자 B와 예약하면, 연락처의 담당 사용자가 사용자 B로 바뀌어요.
  - **Skip assignment if the contact already has an assigned user**(이미 담당 사용자가 있으면 배정 건너뛰기): 켜면 이미 담당 사용자가 있는 연락처는 다시 배정하지 않아요. 현재 담당 사용자가 없는 연락처만 예약의 담당자로 업데이트돼요.
- **Facebook Pixel ID**: 예약 과정에서 발생하는 이벤트를 추적하려면 여기에 Facebook Pixel ID를 입력하세요.
- **예약 페이지에서 시간대 고정**: 예약 페이지에 표시되는 시간대를 고정해서 사용자가 바꾸지 못하게 해요. 현장 방문 서비스에 특히 유용해요. 예약자가 어디에 있든 설정해 둔 시간대로 예약 가능 시간이 표시돼요.

## 알림

알림으로 팀과 고객에게 예약 소식을 전해요. 알림 유형을 다양하게 설정하고, 누가 받을지 정하고, 내용도 필요에 맞게 바꿀 수 있어요.

### 알림 유형

알림 유형은 크게 여섯 가지예요.

1. **예약 완료**(미확정 상태): 예약이 미확정 상태로 만들어지면 바로 전송돼요.
2. **예약 완료**(확정 상태): 예약이 *확정* 상태로 만들어지거나, 기존 예약이 *확정*으로 바뀌면 바로 전송돼요.
3. **Cancellation Email**(취소 이메일): 예약이 취소되거나, 노쇼로 표시되거나, 유효하지 않은 예약으로 처리되면 전송돼요.
4. **Reschedule Email**(일정 변경 이메일): 예약 날짜나 시간이 바뀌면 전송돼요.
5. **Reminder Email**(리마인더 이메일): 예약 전에 지정한 시점에 전송돼요(예: 1일 전, 1시간 전).
6. **Follow-Up Email**(후속 이메일): 예약이 끝난 뒤 설정한 시점에 전송돼요(예: 바로 직후, 1일 뒤).

### 전송 채널

알림은 다음 채널로 보낼 수 있어요.

- **이메일**: 연락처와 담당 사용자에게 보내요.
- **인앱**: 담당 사용자에게 웹과 모바일 앱 안에서 알림을 보여 줘요.
- **SMS**: 연락처와 담당 사용자에게 보내요.
- **WhatsApp**: WhatsApp으로 고객에게 예약 알림과 업데이트를 보내요.

{% hint style="info" %}
WhatsApp 알림은 현재 예약 단위 커스텀 값은 지원하지만, 서비스 단위 커스텀 값은 지원하지 않아요. 예를 들어 고객이 한 번에 서비스 세 개를 예약하면 예약 전체에 대한 정보는 동적으로 넣을 수 있지만, WhatsApp 알림에서 개별 서비스별 동적 값은 아직 참조할 수 없어요.
{% endhint %}

## 서드파티 캘린더 설정

**서드파티 캘린더 설정**에서는 서비스 예약이 Google, Outlook, iCloud 같은 외부 캘린더와 어떻게 연동될지 정해요. 이 설정으로 참석자가 정확한 초대와 업데이트를 자신의 캘린더에서 바로 받을 수 있어요.

- **Calendar Sync & Invites**(캘린더 동기화 및 초대): Google이나 Outlook이 참석자의 캘린더에 예약을 자동으로 추가하도록 허용해요. 예약이 만들어지거나, 일정이 바뀌거나, 취소될 때마다 초대와 업데이트 이메일이 전송돼요.
- **Appointment Notes**(예약 메모): 서드파티 캘린더 초대에 바로 표시될 메모를 추가해요(예: 미팅 링크, 안내 사항, 준비 사항).

{% hint style="info" %}
참석자가 캘린더 일정에서 한눈에 봐야 할 핵심 내용은 **Appointment Notes**에 적어 두세요.
{% endhint %}

## 자주 묻는 질문

### 서비스를 하나씩 수정하지 않고 글로벌 설정을 쓰면 뭐가 좋나요?

**글로벌 설정**은 모든 서비스에 기본값을 적용해요. 그래서 예약, 결제, 일정 동작을 한곳에서 바꿀 수 있어요.

### 글로벌 설정과 개별 서비스 편집 중 어느 쪽을 써야 하나요?

모든 서비스에 공통으로 적용할 기본값은 **글로벌 설정**에서 정하세요(예약 페이지 동작, 결제, 알림, 예약 가능 기간). 가격과 소요 시간, 옵션, 배정된 직원과 리소스, 애드온처럼 서비스마다 다른 내용은 해당 서비스에서 편집하세요.

### 특정 서비스나 직원의 직접 링크에도 글로벌 설정 변경 내용이 반영되나요?

네. 서비스, 직원, 카테고리 공유 링크는 같은 예약 환경을 걸러서 보여 주는 화면이에요. 그래서 **글로벌 설정**을 바꾸면(레이아웃, 폼, 결제, 알림) 자동으로 적용돼요.

### 글로벌 설정을 바꾼 뒤 예약 페이지가 어떻게 보이는지 미리 보려면 어떻게 하나요?

링크를 공유하기 전에 서비스의 예약 페이지 미리보기로 확인하세요. 글로벌 설정 변경 내용이 공개 예약 페이지에 의도한 대로 나타나는지 확인할 수 있어요.

### "Count available days only"는 날짜 기반 예약 가능 기간에서도 쓸 수 있나요?

아니요. 이 토글은 **범위 기반** 예약 가능 기간에서만 적용돼요. **날짜 기반**을 선택하면 시작일과 종료일이 고정되어 있어서 이 토글은 아무 영향이 없어요.
