# 관리형 에이전트의 메모리(Memory) 기능

관리형 에이전트의 메모리를 쓰면 하이퍼클래스 AI 에이전트가 사용자에게 더 맞춤화된 답변을 하고, 반복 작업을 더 효율적으로 처리해요. 에이전트가 사용자의 중요한 정보를 기억하고 재사용할 수 있는 작업 절차를 학습하기 때문에, 같은 질문과 불필요한 단계, 토큰 사용량이 줄어들어요. 저장된 정보는 **Memory**(메모리) 탭에서 확인하고 관리할 수 있어요. 이 문서에서는 메모리가 어떻게 동작하는지, 어떤 점이 좋은지, 어떻게 켜고 관리하는지 안내해요.

## 관리형 에이전트의 메모리란?

관리형 에이전트의 메모리는 하이퍼클래스 AI 에이전트가 사용자별로 필요한 정보를 기억하고, 이전에 끝낸 작업에서 배우도록 해 주는 기능이에요. 에이전트는 대화할 때마다 처음부터 시작하지 않고, 저장된 맥락과 재사용 가능한 절차를 활용해 더 빠르고 일관된 결과를 내요.

메모리는 두 가지 기능으로 이루어져 있어요.

- 사용자 메모리: 개별 사용자의 신원, 선호, 목표, 최근 이벤트 같은 중요한 정보를 기억해요.
- 학습된 절차: 작업을 끝낸 순서를 저장해 두었다가, 비슷한 요청이 오면 다시 사용해요.

두 기능이 함께 작동해서 개인화와 효율이 모두 좋아져요. 예를 들어 사용자가 매주 에이전트에게 주간 매출 요약을 부탁한다고 해 볼게요. 에이전트는 사용자가 선호하는 보고서 형식을 기억하고, 요약을 만드는 데 필요한 순서도 학습해요. 이후 비슷한 요청이 오면 같은 선호를 다시 묻거나 전체 과정을 처음부터 판단하지 않고, 기억한 내용을 바로 적용해요.

메모리는 에이전트와의 대화와, 메모리를 지원하는 자동화에서 사용할 수 있어요. 반복 작업을 할수록 에이전트가 더 효율적으로 일하게 돼요.

## 메모리의 주요 장점

메모리를 쓰면 같은 지시를 반복하거나 불필요한 처리를 하는 일이 줄어요. 개인화된 맥락과 재사용 가능한 작업 절차를 함께 쓰기 때문에, 관리형 에이전트가 더 일관된 경험을 주고 자원도 더 알뜰하게 써요.

- 작업 속도 향상: 비슷한 작업을 요청받을 때마다 순서를 새로 정하지 않고, 이미 학습한 절차를 다시 사용해요.
- 토큰 사용량 감소: 불필요한 추론 단계를 줄이고, 자세한 절차는 필요할 때만 불러와요.
- 개인화된 상호작용: 사용자별 선호, 목표 등 관련 정보를 기억해서 더 맞춤화된 답변을 해요.
- 반복 질문 감소: 저장된 정보를 활용해서 사용자가 이미 알려 준 내용을 다시 묻지 않아요.
- 자동화 효율 향상: 반복되는 자동화 작업에 학습한 절차를 적용해서 불필요한 처리를 줄여요.
- 쉬운 메모리 관리: 한 곳에서 저장된 사용자 정보(팩트)를 보고, 추가하고, 편집하고, 삭제할 수 있어요.
- 투명성: 에이전트가 무엇을 기억하는지, 정보가 어디에서 왔는지, 어떤 절차를 학습했는지 확인할 수 있어요.
- 개인정보 보호와 보안: 사용자별 메모리를 서로 분리해서 보관하고, 민감한 정보가 저장되지 않도록 보호 장치를 적용해요.

## 메모리 설정하기

메모리를 켜면 관리형 에이전트가 사용자 정보를 기억하고 재사용할 수 있는 작업 절차를 학습하기 시작해요. 메모리는 새로운 기능과 변경 중인 기능을 먼저 써 볼 수 있는 **실험실**(Labs)을 통해 제공돼요.

### 1단계. 실험실에서 메모리 기능 찾기

1. 하이퍼클래스 계정에 로그인해요.
2. 에이전시 또는 서브 계정 화면에서 **설정 > 실험실**을 열어요.
3. 관리형 에이전트 메모리 기능을 찾아요.
4. 기능 설명과 사용 조건이 있는지 확인해요.

{% hint style="info" %}
실험실 기능은 에이전시 또는 서브 계정 단위로 설정될 수 있어요. 관리형 에이전트 메모리의 정확한 실험실 위치와 기능 카드 이름은 게시 전에 확인이 필요해요. 실험실 설정과 사용 가능 여부는 [실험실 기능 전체 개요](../19-에이전시-뷰/Agency-Settings/labs-features-complete-overview.md)에서 자세히 볼 수 있어요.
{% endhint %}

### 2단계. 관리형 에이전트 열기

1. **AI 에이전트 > 에이전트 스튜디오 > 관리형 에이전트**로 이동해요.
2. 메모리를 쓰고 싶은 관리형 에이전트를 선택해요.
3. 에이전트의 **Memory** 화면을 열어요.

![관리형 에이전트의 Memory 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083103439/original/_1aOprWEwXgO7Rd-fV02wDcixvL6XPGbhQ.png?1791808671)

### 3단계. 사용자 메모리 확인하기

1. **나에 대한 정보** 영역을 열어요.
2. 저장된 정보가 있으면 확인해요.
3. 화면의 기능을 사용해서 관련 정보를 추가하거나 수정해요.
4. 오래되었거나 잘못된 정보는 필요할 때 삭제해요.

![나에 대한 정보 영역에서 저장된 사용자 정보 확인](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083103884/original/E2RA0EyfXWjVz2wpVbySOtfMwwWafcHcDg.png?1791808734)

### 4단계. 학습된 절차 확인하기

1. **절차** 영역을 열어요.
2. 사용 가능한 절차를 확인해요.
3. 각 절차의 출처와 사용 횟수를 확인해요.
4. 더 이상 필요 없는 절차는 삭제해요.

![절차 영역에서 학습된 절차 확인](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083107312/original/pFNZjx0ONAsDZfVDdsyJR1YfuvRqfHuiZQ.png?1791810202)

### 5단계. 대화에서 메모리 테스트하기

메모리를 켠 뒤에는 간단하고 반복할 수 있는 작업으로 테스트해 보세요.

1. 관리형 에이전트와 대화를 시작해요.
2. 선호하는 보고서 형식처럼 관련 있는 선호를 알려 줘요.
3. 그 선호를 반영해서 작업을 해 달라고 요청해요.
4. 새 대화를 시작하고 비슷한 요청을 해요.
5. 같은 선호를 다시 말하지 않아도 에이전트가 적용하는지 확인해요.
6. **Memory** 탭에서 저장된 정보를 확인해요.

학습된 절차를 테스트하려면 알맞은 작업을 반복한 뒤 **절차** 영역에서 재사용할 수 있는 순서가 저장되었는지 확인해 보세요.

{% hint style="info" %}
메모리와 절차는 정보의 관련성과 완료한 작업에 따라 만들어져요. 모든 메시지나 완료된 작업이 저장된 정보나 절차로 이어지는 것은 아니에요.
{% endhint %}

## 사용자별 메모리와 저장된 정보

사용자별 메모리를 쓰면 관리형 에이전트가 대화 상대마다 관련 정보를 기억해요. 대화가 이어져도 맥락을 유지하고, 사용자 정보는 서로 분리해서 보관해요.

### 사용자 메모리가 동작하는 방식

관리형 에이전트마다 사용자별로 각자의 메모리가 있어요. 한 사용자에 대해 기억한 정보는 다른 사용자와 공유되지 않아요. 한 에이전트가 저장한 정보도 다른 에이전트에 자동으로 공유되지 않아요.

메모리를 켜면 저장된 정보가 관련 맥락으로 자동 포함돼요. 예를 들어 에이전트는 사용자에 대해 이런 내용을 기억할 수 있어요.

- 오스틴 지점을 관리해요.
- 간결한 주간 요약을 좋아해요.
- 분기 매출 목표를 달성하려고 노력하고 있어요.
- 최근 특정 비즈니스 프로젝트를 마쳤어요.

이런 정보 덕분에 사용자가 같은 내용을 반복하지 않아도 에이전트가 이후 답변을 맞춤형으로 할 수 있어요.

### 메모리 카테고리

관리형 에이전트는 저장된 사용자 정보를 네 가지 카테고리로 나눠요.

| 카테고리 | 설명 | 예시 |
| --- | --- | --- |
| **Identity**(신원) | 사용자가 누구인지, 어떤 일을 맡고 있는지에 대한 정보예요. | 오스틴 지점을 관리해요. |
| **Preferences**(선호) | 사용자가 선호하는 업무·소통 방식에 대한 정보예요. | 글머리 기호로 된 짧은 요약을 좋아해요. |
| **Goals**(목표) | 시간이 지나도 계속 중요한 목표나 우선순위예요. | 월간 리드 전환율을 높이고 싶어요. |
| **최근 이벤트** | 이후 대화에 맥락을 줄 수 있는 의미 있는 변화예요. | 최근 새 마케팅 캠페인을 시작했어요. |

에이전트는 이후 대화에 도움이 될 만한 정보를 중심으로 기억해요. 일회성 요청, 가벼운 대화, 반복되는 정보는 영구 메모리로 저장하지 않아요.

예를 들어 반복 워크플로우에서 호출된 관리형 에이전트는 리드 정보를 처리하고 요약하며 이전에 학습한 순서를 다시 사용할 수 있어요. 자동화로 에이전트를 호출하는 방법은 [워크플로우 액션 – 관리형 에이전트 호출](../07-워크플로우/시작하기/workflow-action-invoke-managed-agent.md)에서 확인하세요.

## 자주 묻는 질문

### 메모리는 관리형 에이전트와 주고받은 모든 메시지를 자동으로 저장하나요?

아니요. 메모리는 전체 대화 기록이 아니라 관련 있는 정보를 기억하도록 설계되었어요. 일시적인 요청, 가벼운 메시지, 중복된 정보는 개별 메모리로 저장하지 않아요.

### 관리형 에이전트가 학습한 절차를 다른 종류의 작업에도 쓸 수 있나요?

절차는 비슷한 작업에 쓰도록 만들어져 있어요. 한 프로세스에서 학습한 절차는 관련 없는 요청에는 맞지 않을 수 있고, 에이전트는 설정된 지침과 안전 요건도 계속 따라야 해요.

### 에이전트가 더 이상 맞지 않는 정보를 기억하고 있으면 어떻게 하나요?

저장된 사용자 정보는 **나에 대한 정보** 영역에서 편집하거나 삭제할 수 있어요. 오래된 정보를 바로잡으면 에이전트가 이후 대화에서 더 정확한 맥락을 사용해요.

### 메모리를 켜면 모든 자동화 실행이 빨라지나요?

꼭 그렇지는 않아요. 에이전트가 알맞은 학습된 절차를 재사용할 수 있을 때 개선 효과를 기대할 수 있어요. 관련 절차가 없는 작업은 같은 효과를 보지 못할 수 있어요.

### 메모리를 쓰면 모든 대화에서 토큰 비용이 줄어드나요?

아니요. 메모리는 간결한 요약과 필요할 때만 절차를 불러오는 방식으로 불필요한 토큰 사용을 줄이도록 설계되었어요. 실제 비용은 작업 내용과 필요한 정보에 따라 달라져요.

### 메모리를 끄면 어떻게 되나요?

메모리를 꺼도 이전에 저장된 메모리는 삭제되지 않아요. 기존 정보는 그대로 유지되고, 메모리를 다시 켜면 재사용할 수 있어요. 그래서 저장된 정보를 잃지 않고 메모리를 잠시 꺼 둘 수 있어요.
