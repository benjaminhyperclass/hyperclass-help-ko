# 브랜드 모바일 앱 AI 인증으로 제출 전 오류 확인하기

브랜드 앱 AI 검토 자동화(Branded App AI Review Automation)를 쓰면 하이퍼클래스에서 브랜드 모바일 앱을 제출하기 전에 앱 정보를 몇 초 만에 점검할 수 있어요. 이 문서에서는 **브랜드 모바일 앱 빌더**에서 브랜딩과 앱 정보를 입력하고, 인증 결과를 확인해 문제를 고친 뒤 앱을 제출하는 과정을 안내해요.

예전에는 수동 검토를 최대 5일까지 기다려야 했어요. 이제는 자동 피드백을 바로 받아서 제출 오류를 줄이고, 앱 게시까지 걸리는 시간을 줄일 수 있어요.

## 브랜드 앱 AI 검토 자동화란?

브랜드 앱 AI 검토 자동화는 하이퍼클래스의 **브랜드 모바일 앱 빌더**에 들어 있는 자동 인증 기능이에요. 앱을 제출하기 전에 필수 정보를 확인해서 누락된 정보, 접속할 수 없는 URL, 자격 증명 문제처럼 앱 게시를 늦출 수 있는 문제를 찾아 줘요.

예전에는 앱 세부 정보를 수동으로 검토했고, 최대 5일이 걸렸어요. AI 인증을 쓰면 결과를 몇 초 안에 받고, 지적된 문제를 바로 고칠 수 있어요.

새로 생긴 **인증** 탭에서는 검사 항목별 결과를 보여 주고, 확인이 필요한 문제와 해결하러 가는 버튼을 알려 줘요. 필수 검사를 모두 통과하면 앱 빌드와 스토어 설정의 다음 단계로 앱을 제출할 수 있어요.

제출한 뒤에는 하이퍼클래스가 자동화 시스템 Pilot으로 스토어 설정을 진행해요. 예전처럼 수동 검토를 거치지 않아도 돼요.

{% hint style="info" %}
AI 인증은 앱을 제출하기 전에 이루어져요. Apple과 Google은 각자 앱 검토 절차를 따로 운영하므로, 하이퍼클래스의 검사를 통과했다고 해서 두 스토어의 승인이 보장되지는 않아요.
{% endhint %}

## 브랜드 모바일 앱 빌더 살펴보기

**브랜드 모바일 앱 빌더**는 앱을 준비하고 제출하는 작업 공간이에요. 안내에 따라 진행 상황을 확인하고, 필요한 정보를 입력하고, 앱을 구매한 뒤 사용자에게 공개되기까지 어떤 일이 일어나는지 볼 수 있어요.

하이퍼클래스 서브 계정에서 **사이트 > 클라이언트 포탈 > 브랜드 모바일 앱**으로 이동하면 빌더가 열려요.

빌더에는 주요 탭이 4개 있어요.

- **개요**: 앱 출시 진행 상황과 게시 전에 남은 단계를 보여 줘요.
- **브랜딩**: 앱 아이콘, 캐러셀 이미지, Play 스토어 배너를 올리고 설정해요.
- **앱 설정**: 개인정보, 앱 세부 정보, 개발자 계정 정보를 입력해요.
- **인증**: 자동 검사를 실행하고, 제출 전에 해결해야 할 문제를 알려 줘요.

**개요** 화면에는 앱 출시 전체 과정도 표시돼요.

1. **결제 완료**: 브랜드 모바일 앱 결제가 정상적으로 끝났음을 알려 줘요.
2. **브랜딩 및 세부정보 추가**: 앱을 빌드하고 제출하는 데 필요한 정보를 입력하는 단계예요.
3. **앱을 빌드하고 있습니다**: 하이퍼클래스가 앱을 빌드하고 앱 스토어 제출을 준비하는 단계예요.
4. **스토어 검토**: 앱이 Apple 또는 Google의 검토 단계에 들어갔다는 뜻이에요.

![브랜드 모바일 앱 빌더의 개요 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083702919/original/1OS3PJpLTBaxvSy9Zha7h2xJNMu11_uRoQ.png?1792443858)

{% hint style="info" %}
**팀과 통화 예약** 옵션은 설정 과정에 도움이 필요한 에이전시 사용자 중 해당되는 분께 제공돼요. 자동 인증 요건에는 포함되지 않아요.
{% endhint %}

전체 설정 과정은 [클라이언트 포탈 브랜드 모바일 앱 - 에이전시 전체 설정 가이드](../31-리셀링/Client-Portal-Branded-Mobile-APP/client-portal-branded-mobile-app-full-setup-guide-for-agency.md)에서도 볼 수 있어요.

## 브랜딩 요건

앱 브랜딩은 모바일 기기와 앱 스토어 목록에서 앱이 어떻게 보이는지를 결정해요. 필요한 치수와 형식에 맞춰 이미지를 올리면 브랜딩이 일관되게 표시되고, 해당 인증 검사도 통과하기 쉬워요.

**브랜딩** 탭을 열어 아래 자산을 설정하세요.

### 앱 아이콘

**앱 아이콘**은 iOS와 Android 기기에서 회원님의 브랜드를 나타내요.

아이콘은 아래 요건에 맞춰 올리세요.

- **치수**: 1024 × 1024픽셀
- **파일 형식**: PNG
- **사용량**: iOS와 Android 기기의 기본 앱 아이콘

**아이콘 업로드**를 클릭해 이미지를 선택하세요.

### 캐러셀

**캐러셀** 이미지는 앱의 가입 또는 로그인 화면에 표시돼요. 사용자에게 브랜드를 소개하고 주요 기능을 알리는 역할을 해요.

화면에 표시되는 업로드 요건은 아래와 같아요.

- **치수**: 600 × 800픽셀
- **파일 형식**: PNG

캐러셀 항목마다 이미지와 제목을 설정할 수 있어요. 제목마다 50자 카운터가 표시돼요.

드래그 핸들로 캐러셀 항목의 순서를 바꾸거나, **X** 아이콘으로 항목을 삭제할 수도 있어요.

개선된 브랜딩 화면은 호환성이 더 좋은 이미지 형식을 사용해서, 지원되는 기기에서 캐러셀이 일관되게 보여요.

### Play 스토어 배너

**Play 스토어 배너**는 Google Play 목록에서 앱을 돋보이게 해 줘요.

화면에 표시되는 요건은 아래와 같아요.

- **치수**: 1024 × 500픽셀
- **파일 형식**: PNG 또는 JPG

업로드 영역을 클릭하거나, 지원되는 이미지를 그 안으로 끌어다 놓으세요.

**브랜딩** 화면 오른쪽의 모바일 미리보기에서 앱 브랜딩이 기기에서 어떻게 보이는지 확인할 수 있어요.

![브랜딩 탭에서 앱 아이콘, 캐러셀, Play 스토어 배너를 설정하는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083702929/original/RBlzdtQ8mTurt2gvUN9j-aEEzQxyIxCFCw.png?1792443894)

브랜딩 설정은 [클라이언트 포탈 브랜드 모바일 앱: 앱 브랜딩 설정하기](../39-클라이언트-포털/Client-Portal/client-portal-branded-mobile-app-setting-up-branding-of-your-app.md)에서도 볼 수 있어요.

## 앱 설정 항목

**앱 설정**에서는 브랜드 모바일 앱을 준비하는 데 필요한 비즈니스 정보, 앱 목록 정보, 개발자 정보를 입력해요. 정확하게 입력해야 자동 인증이 제출 내용을 제대로 확인하고, 나중에 고치는 일도 줄어요.

**앱 설정** 탭은 3단계로 이루어져 있어요.

1. **개인정보**
2. **앱 세부 정보**
3. **개발 세부정보**

### 1. 개인정보

**개인정보**에는 앱을 책임지는 담당자 정보와, 사용자가 지원을 받을 수 있는 방법을 입력해요.

아래 필드를 입력하세요.

| 필드 | 설명 |
| --- | --- |
| **Full name**(이름) | 앱 제출을 책임지는 사람의 이름이에요. |
| **전화번호** | 연락 가능한 전화번호예요. 해당 국가 번호도 함께 입력하세요. |
| **Email**(이메일) | 기본 연락용 이메일 주소예요. |
| **지원 이메일** | 기본 이메일과 다른 경우에 입력하는 지원용 이메일 주소예요. |
| **지원 URL** | 사용자가 앱 지원을 받을 수 있는 웹 주소예요. |
| **Address**(주소) | 앱과 관련된 연락처 또는 사업장 주소예요. |

빨간 별표(\*)가 붙은 필드는 필수예요.

**지원 URL**은 누구나 접속할 수 있고 제대로 열려야 해요. 지원 페이지에 접속할 수 없으면 인증에 실패할 수 있어요.

![앱 설정의 개인정보 입력 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083702944/original/JpMyWop5ZNM4OplkeQpY2XH5Sxaz6QrrGw.png?1792443926)

### 2. 앱 세부 정보

**앱 세부 정보**는 앱 스토어에서 사용자가 앱을 찾고 이해하는 방식을 정해요.

아래 정보를 입력하세요.

| 필드 | 설명 |
| --- | --- |
| **앱 이름** | 브랜드 모바일 앱에 표시될 이름이에요. |
| **이용약관 URL** | 앱의 이용약관이 담긴, 누구나 접속할 수 있는 페이지예요. |
| **개인정보처리방침 URL** | 사용자 정보를 어떻게 다루는지 설명하는, 누구나 접속할 수 있는 페이지예요. |
| **앱 배포 국가** | 앱을 제공할 국가나 지역이에요. |
| **앱 간단 설명** | 앱의 목적과 기능을 짧게 요약한 글이에요. |
| **앱 설명** | 앱과 기능을 자세히 설명하는 글이에요. |

화면에 표시되는 글자 수 제한은 아래와 같아요.

- **앱 이름**: 글자, 숫자, 공백을 사용해 최대 30자
- **앱 간단 설명**: 최대 80자
- **앱 설명**: 최대 4,000자

앱을 제공할 국가를 선택하세요. 앱을 배포하고 싶지 않은 국가나 지역은 선택을 해제할 수 있어요.

약관 페이지 URL을 입력할 때는 페이지가 정상적으로 열리고 알맞은 내용이 담겨 있는지 확인하세요. 자동 인증은 여러 언어로 된 약관 페이지도 검토할 수 있어요.

인증 과정에서 약관 페이지의 특정 내용이 지적될 수도 있어요. 예를 들어 화면 예시에서는 결제와 관련된 용어 때문에 이용약관 페이지가 지적되었어요. 화면에 표시되는 오류 메시지를 보고 무엇을 고쳐야 하는지 확인하세요.

![앱 세부 정보 입력 화면과 이용약관 URL 오류 예시](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083702958/original/v2iKcazU-emVv4uTorkSRIEq2g7tJZRHBQ.png?1792443951)

### 3. 개발 세부정보

**개발 세부정보**에서는 Apple과 Google에 앱을 게시하는 데 필요한 정보를 연결해요. 개선된 과정에서는 Apple과 Google 계정 비밀번호를 입력하지 않아도 돼서 설정이 한결 간단해졌어요.

**Google Developer Credentials**(Google Developer 자격 증명)와 **Apple Developer 자격 증명**에서 해당하는 필드를 입력하세요. 각 개발자 계정은 [Apple Developer 계정 설정 가이드](../30-모바일-데스크톱/Whitelabel-Mobile-App/setting-up-an-apple-developer-account-for-your-whitelabel-mobile-app.md)와 [Google Developer 계정 설정 가이드](../30-모바일-데스크톱/Whitelabel-Mobile-App/setting-up-a-google-developer-account-for-your-whitelabel-mobile-app.md)를 참고해 준비할 수 있어요.

**Google Developer Credentials**(Google Developer 자격 증명)

- **Google Developer Email**(Google Developer 이메일): Google Play 개발자 계정에 연결된 이메일 주소예요.
- **Google Developer Account Name**(Google Developer 계정 이름): Google Play 개발자 계정의 이름이에요.

**Apple Developer 자격 증명**

- **Apple Developer 이메일**: Apple Developer 계정에 연결된 이메일 주소예요.
- **Apple Developer 계정 이름**: Apple Developer 계정의 이름이에요.
- **App Store Connect 키 ID**: 필요한 App Store Connect 키의 식별자예요.
- **App Store Connect 키 파일**: App Store Connect 연동을 위해 올리는 키 파일이에요.
- **DUNS 번호**: 개발자 계정에 요청되는 사업자 식별 번호예요.

**계정 관리자 추가**

**계정 관리자 추가** 영역에서는 하이퍼클래스의 앱 담당자에게 필요한 계정 접근 권한을 줄 수 있어요.

**관리자 추가**를 클릭하고 안내에 따라 App Store Connect와 Google Play에 필요한 접근 권한을 부여하세요.

일부 Apple 자격 증명 필드 옆에는 튜토리얼 링크가 있고, 관리자 접근 권한 항목에는 **자세히 보기** 링크가 있어요.

{% hint style="warning" %}
Apple과 Google 계정 비밀번호는 더 이상 필요하지 않지만, 개발자 계정 정보와 알맞은 관리자 접근 권한은 여전히 필요해요.
{% endhint %}

## AI 인증 검사 항목

AI 인증은 앱 설정에서 입력한 정보를 검토하고, 제출 전에 고쳐야 할 문제를 알려 줘요. 별도의 수동 검토를 기다리지 않고 문제를 바로 해결할 수 있어요.

**인증** 탭을 열면 제출 전 점검 목록이 보여요.

인증 화면에서 확인하는 항목은 아래와 같아요.

| 검사 항목 | 확인 내용 |
| --- | --- |
| **개인정보처리방침 URL** | 입력한 개인정보처리방침 페이지가 검증 요건을 충족하는지 확인해요. |
| **이용약관 URL** | 약관 페이지에 접속할 수 있고, 내용이 자동 검사를 통과하는지 확인해요. |
| **지원 URL** | 입력한 지원 페이지가 정상적으로 열리는지 확인해요. |
| **캐러셀 이미지** | 설정한 캐러셀 이미지가 검증을 통과하는지 확인해요. |
| **앱 설명** | 입력한 앱 설명이 검증을 통과하는지 확인해요. |
| **App Store Connect 자격 증명** | 입력한 Apple 개발자 연결 정보가 검증을 통과하는지 확인해요. |
| **계정 관리자 추가** | 필요한 계정 관리자 접근 권한이 검증을 통과하는지 확인해요. |

### 인증 결과 보는 법

**인증** 화면에는 검사 항목마다 상태가 표시돼요.

- 녹색 체크 표시(인증 완료): 해당 검사를 통과했어요.
- 빨간 X(실패): 제출 전에 확인이 필요해요.
- 남은 검사 수: 아직 해결해야 할 검사가 몇 개인지 알려 줘요.

실패한 검사에는 문제 설명과 해당 설정 위치로 이동하는 **수정** 버튼이 표시돼요.

예를 들면 이런 경우가 있어요.

- 이용약관 URL: 약관 내용에 검사에서 지적한 결제 관련 제한 용어가 들어 있으면 실패할 수 있어요.
- 지원 URL: 페이지를 정상적으로 불러오지 못하면 실패할 수 있어요.

문제를 고친 뒤에는 **다시 확인**을 눌러 자동 검사를 다시 실행하세요.

필수 인증 문제가 남아 있으면 **검토 제출** 버튼을 사용할 수 없어요.

![인증 탭의 검사 결과 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083702993/original/FPeH_x931XYlSij7XU2tybaKK6m3YRPvqQ.png?1792444025)

## 브랜드 모바일 앱 설정하고 인증하기

각 단계를 순서대로 진행하면 브랜딩, 앱 정보, 개발자 자격 증명이 자동 인증에 사용돼요. 제출하기 전에 결과를 확인하고 남은 문제를 해결하면 앱 게시가 불필요하게 늦어지는 일을 막을 수 있어요.

### 1단계: 브랜드 모바일 앱 빌더 열기

1. 하이퍼클래스 서브 계정에 로그인하세요.
2. **사이트 > 클라이언트 포탈 > 브랜드 모바일 앱**으로 이동하세요.
3. **개요** 탭을 여세요.
4. 출시 진행 상황을 확인하고, **결제 완료** 단계가 끝났는지 확인하세요.
5. **브랜딩**으로 이동해 앱 설정을 시작하세요.

![개요 탭에서 출시 진행 상황을 확인하는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083703069/original/3qdSjAfJWSyoYNBWl7IppN5gSuHKjOhxRQ.png?1792444149)

### 2단계: 앱 브랜딩 설정하기

1. **브랜딩** 탭을 여세요.
2. 필요한 형식과 치수에 맞춰 **앱 아이콘**을 올리세요.
3. **캐러셀** 이미지와 제목을 추가하세요.
4. 캐러셀 이미지를 원하는 순서로 정렬하세요.
5. **Play 스토어 배너**를 올리세요.
6. 기기 미리보기로 설정한 브랜딩을 확인하세요.

![브랜딩 탭에서 앱 브랜딩을 설정하는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083703073/original/bEoBpuKSeDANiB9WpoOLnp11HhL0qdblqQ.png?1792444166)

### 3단계: 개인정보 입력하기

1. **앱 설정** 탭을 여세요.
2. **개인정보**를 선택하세요.
3. **Full name**(이름), **전화번호**, **Email**(이메일)을 입력하세요.
4. 필요하면 **지원 이메일**을 입력하세요.
5. 누구나 접속할 수 있는 **지원 URL**을 입력하세요.
6. **Address**(주소)를 입력하세요.
7. **저장 및 계속**을 클릭하세요.

![개인정보를 입력하고 저장 및 계속을 클릭하는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083703084/original/hlk46SDDshYHO5yOd9BnzuQAB6atVxKZbQ.png?1792444185)

### 4단계: 앱 세부 정보 설정하기

1. **앱 세부 정보**를 선택하세요.
2. **앱 이름**을 입력하세요.
3. **이용약관 URL**을 입력하세요.
4. **개인정보처리방침 URL**을 입력하세요.
5. **앱 배포 국가**를 선택하세요.
6. **앱 간단 설명**을 입력하세요.
7. **앱 설명**을 빠짐없이 작성하세요.
8. **저장 및 계속**을 클릭해 다음으로 넘어가세요.

![앱 세부 정보를 입력하는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083703089/original/kLnfjzQM25Dh9ncC6ln4u4ya7iFqkvOukQ.png?1792444209)

설명은 화면에 표시된 글자 수 제한을 지키고, 앱 기능을 정확하게 설명해야 해요.

### 5단계: 개발 세부정보 입력하기

1. **개발 세부정보**를 선택하세요.
2. **Google Developer Email**(Google Developer 이메일)과 **Google Developer Account Name**(Google Developer 계정 이름)을 입력하세요.
3. **Apple Developer 이메일**과 **Apple Developer 계정 이름**을 입력하세요.
4. 필요한 **App Store Connect 키 ID**를 입력하세요.
5. **App Store Connect 키 파일**을 올리세요.
6. **DUNS 번호**를 입력하세요.
7. **계정 관리자 추가**를 찾아 **관리자 추가**를 클릭하세요.
8. 안내에 따라 개발자 계정 접근 권한을 부여하세요.
9. 화면에 있는 설정 버튼으로 입력한 정보를 저장하세요.

![개발 세부정보를 입력하는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083703099/original/nMrVZx8FjbgOWbJ9mHKQ9AC-ikfb8t9C8g.png?1792444253)

개선된 과정에서는 Apple이나 Google 계정 비밀번호를 입력하지 않아도 돼요.

### 6단계: AI 인증 결과 확인하기

1. **인증** 탭을 여세요.
2. 자동 점검 목록을 확인하세요.
3. 빨간 X가 표시된 항목을 찾으세요.
4. 실패한 검사마다 오류 메시지를 읽어 보세요.
5. 문제 옆의 **수정**을 클릭해 해당 필드로 이동하세요.
6. 실패 원인이 된 정보를 고치세요.
7. 변경사항을 저장하세요.
8. **인증** 탭으로 돌아가세요.

![인증 탭에서 실패한 검사 항목과 수정 버튼을 확인하는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083703104/original/fai8vKczRJAPNtS-2yrX63dFQ8IG5uiBPQ.png?1792444276)

### 7단계: 인증 다시 실행하기

1. **인증** 화면에서 **다시 확인**을 클릭하세요.
2. 자동 검사가 끝날 때까지 기다리세요.
3. 업데이트된 인증 결과를 확인하세요.
4. 문제가 남아 있으면 수정하고 다시 확인하는 과정을 반복하세요.
5. 필수 검사가 모두 통과로 표시되는지 확인하세요.

AI 인증은 몇 초 안에 결과를 보여 주도록 만들어졌지만, 실제 완료 시간은 달라질 수 있어요.

### 8단계: 브랜드 모바일 앱 제출하기

1. 필수 인증 검사를 모두 통과했는지 확인하세요.
2. 브랜딩과 앱 세부 정보가 정확한지 다시 확인하세요.
3. **검토 제출** 버튼을 사용할 수 있게 되면 클릭하세요.
4. 화면에 마지막 제출 안내가 표시되면 따라 진행하세요.

제출한 뒤에는 하이퍼클래스의 자동화 시스템 Pilot이 스토어 설정 과정을 처리해요. 예전처럼 제출 전에 수동 검토를 거치지 않아요.

앱이 일반 사용자에게 공개되려면 Apple과 Google의 스토어 검토 절차를 여전히 거쳐야 해요.

{% hint style="warning" %}
제출한 세부 정보를 꼼꼼히 확인하세요. 기존 브랜드 모바일 앱 문서에는 제출 후에는 변경할 수 없다고 나와 있어요. 진행하기 전에 정보가 정확한지 꼭 확인하세요.

## 자주 묻는 질문

### AI 인증은 얼마나 걸리나요?

AI 인증은 몇 초 안에 끝나도록 설계되어 있어요. 최대 5일 걸리던 기존 수동 검토를 대신해요. 실제 소요 시간은 달라질 수 있어요.
<!-- 검토 필요: 원문 내용이 서로 다름 (앞부분은 "최대 5일", 이 답변은 "최대 5영업일") -->

### AI 인증을 통과하면 Apple이나 Google 승인도 보장되나요?

아니요. AI 인증은 앱이 스토어 게시 과정에 들어가기 전, 제출 내용을 확인하는 단계예요. Apple과 Google은 각자 검토를 진행하고, 자체 가이드라인에 따라 수정을 요청하거나 앱을 거절할 수 있어요.

### 이용약관 URL이 인증에 실패하면 어떻게 하나요?

실패한 검사 옆에 표시된 오류 메시지를 읽어 보세요. 자동 검토에서 확인이 필요한 특정 내용을 알려 줄 수 있어요. **수정**을 눌러 해당 URL 필드로 이동하고, 연결된 페이지를 살펴 알맞게 고친 뒤 **다시 확인**을 실행하세요. 약관 내용을 바꿀 때는 내용이 정확하고 관련 요건에 맞는지도 함께 확인하세요.

### 지원 URL이 올바른 링크 같은데 인증에 실패해요.

페이지를 사용할 수 없거나, 접근이 제한되어 있거나, 제대로 열리지 않는 경우일 수 있어요. 브라우저에서 URL을 열어 로그인 없이 접속되는지 확인하세요. URL이나 페이지 접속 문제를 고친 뒤 인증을 다시 실행하세요.

### Apple이나 Google 개발자 계정 비밀번호를 알려 줘야 하나요?

아니요. 개선된 과정에서는 Apple이나 Google 계정 비밀번호가 필요하지 않아요. 다만 요청하는 개발자 계정 정보는 입력해야 하고, 알맞은 관리자 접근 권한도 부여해야 해요.

### 영어가 아닌 다른 언어로 쓴 약관 페이지도 AI가 확인할 수 있나요?

네. 이번 업데이트부터 AI 인증은 개인정보처리방침, 이용약관, 지원 페이지 내용을 여러 언어로 확인할 수 있어요.

### 검토 제출 버튼이 비활성화되어 있어요.

**인증** 화면에서 남은 문제가 있는지 확인하세요. 필수 검사를 통과하지 못하면 버튼을 사용할 수 없어요. 지적된 항목을 해결하고 **다시 확인**을 클릭해 결과를 업데이트하세요.

### 앱을 제출한 뒤에 앱 세부 정보를 수정할 수 있나요?

기존 브랜드 모바일 앱 설정 문서에는 제출한 세부 정보를 나중에 변경할 수 없다고 나와 있어요. 제출하기 전에 모든 정보를 꼼꼼히 확인하세요. 나중에 변경이 필요하면 하이퍼클래스 고객지원에 문의하세요.

### 수동 검토 일정을 따로 예약해야 하나요?

이번 업데이트로 제출 전 수동 검토가 자동 AI 인증으로 바뀌었고, Apple과 Google 계정 비밀번호를 제공하는 절차도 없어졌어요. 현재 설정 화면에 나오는 개발자 관리자 접근 권한 단계를 완료하세요. 계정별 접근 권한 요청이 있으면 화면에 표시된 대로 따르세요.
