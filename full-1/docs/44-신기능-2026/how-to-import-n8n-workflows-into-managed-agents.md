# 관리형 에이전트로 n8n 워크플로우 가져오기

n8n에서 만든 자동화를 단계마다 다시 만들 필요 없이 하이퍼클래스로 가져올 수 있어요. **다음에서 가져오기 > n8n** 기능은 n8n 워크플로우 내보내기 파일을 분석해서, 그 안의 트리거·로직·액션을 바탕으로 관리형 에이전트를 준비해 줘요. 에이전트를 만들기 전에 무엇이 그대로 넘어왔는지, 무엇이 바뀌었는지, 무엇을 더 설정해야 하는지 확인할 수 있어요. 이 문서에서는 워크플로우 가져오기, 변환 결과 검토, 설정 마무리, 관리형 에이전트 저장·게시까지 안내해요.

## n8n 워크플로우 가져오기란?

n8n 워크플로우 가져오기는 내보낸 JSON 파일을 이용해 기존 n8n 자동화를 하이퍼클래스 관리형 에이전트(Managed Agents)로 바꿔 주는 기능이에요. 노드를 하나씩 다시 만드는 대신, 가져오기 도구가 워크플로우를 분석해서 지침, 시작 조건, 판단 규칙, 연결된 액션을 갖춘 에이전트를 준비해 줘요.

가져오기 도구는 워크플로우의 각 단계가 하이퍼클래스에서 어떻게 동작할 수 있는지 찾아내요. 예를 들면 이렇게 바뀌어요.

- 조건 분기는 에이전트의 판단 규칙이 돼요.
- AI 노드는 에이전트의 추론에 포함돼요.
- 지원되는 앱 액션은 하이퍼클래스 연동, CRM 액션, API 호출로 처리돼요.

에이전트를 만들기 전에 어떤 단계가 그대로 넘어왔는지, 어떤 단계가 바뀌었는지, 어떤 항목에 추가 확인이 필요한지 볼 수 있어요.

**Review & set up**(검토 및 설정) 화면에서는 필요한 앱 연결, 설정값, 시작 조건도 함께 알려 줘요. 검토를 마치면 에이전트를 초안으로 저장하거나, 만들고 바로 게시할 수 있어요.

가져온 에이전트는 에이전트 스튜디오의 **Imported from n8n**(n8n에서 가져옴) 폴더에 모여요.

## n8n 워크플로우 가져오기의 장점

이미 만들어 둔 워크플로우를 바탕으로 시작할 수 있어요. 검토 과정을 거치면 하이퍼클래스에서 쓰기 전에 그 자동화가 관리형 에이전트로 어떻게 바뀌는지 파악할 수 있어요.

- 수작업 재구성 감소: 내보낸 n8n 워크플로우를 노드와 연결선 하나하나 다시 만들지 않고 관리형 에이전트로 변환해요.
- 투명한 변환 과정: 그대로 넘어온 단계, 바뀐 단계, 추가 확인이 필요한 단계를 검토할 수 있어요. 바뀐 단계에는 동작이 어떻게 달라졌는지 설명이 함께 나와요.
- 안내에 따른 설정: 트리거를 검토하고, 필요한 앱을 연결하고, 빠진 값을 가져오기 화면에서 바로 입력할 수 있어요.
- 자연어 판단 규칙: 조건부 로직과 지원되는 AI 작업은 별도의 워크플로우 노드로 남지 않고 에이전트의 지침과 추론이 돼요.
- 하이퍼클래스 연동: 가져온 에이전트는 지원되는 하이퍼클래스 CRM 액션, 대화, 폼, 캘린더, 지식 베이스, 앱 연결을 쓸 수 있어요.
- 직접 확인한 뒤 에이전트 생성: 제안된 에이전트를 검토한 다음에 초안으로 저장하거나 게시해요. 워크플로우를 분석하는 것만으로는 에이전트가 만들어지지 않아요.

## 사전 준비와 제한 사항

워크플로우를 가져오기 전에 JSON 내보내기 파일을 준비하고, 워크플로우가 의존하는 연결을 점검하세요. 일부 워크플로우 동작은 하이퍼클래스에서 쓰려면 바꾸거나 직접 설정해야 할 수 있어요.

#### 사전 준비

- 기존 n8n 워크플로우: 내보낼 수 있는 n8n 워크플로우가 있어야 해요.
- 워크플로우 JSON: 워크플로우를 `.json` 파일로 내보내거나, 붙여넣을 JSON 내용을 준비하세요.
- 파일 크기: 가져오기 도구는 최대 10 MB까지의 JSON 파일을 올릴 수 있어요.
- 관리형 에이전트 사용: 에이전트 스튜디오의 관리형 에이전트 영역에서 **다음에서 가져오기 > n8n (베타)** 를 찾아보세요. 관리형 에이전트 사용법은 [에이전트 스튜디오에서 관리형 에이전트 설정하고 사용하기](../13-AI-Employee/Agent-Studio/setup-and-use-managed-agents-in-agent-studio.md)를 참고하세요.
- 필요한 연동: 가져온 워크플로우에 필요한 외부 앱을 연결할 준비를 해 두세요.
- 설정 정보: 설정을 마치는 데 필요한 ID, 값, 계정별 정보를 준비하세요.

#### 제한 사항과 알아 둘 점

- 베타 기능: n8n 가져오기 옵션에는 화면에 베타 표시가 있어요. <!-- 검토 필요: 원문에 "[NEEDS CONFIRMATION: Verify current Beta availability, rollout eligibility, and any importer-specific permissions.]" 메모가 남아 있음. 현재 베타 제공 여부, 적용 대상, 가져오기 관련 권한 확인 필요 -->
- 자격 증명은 옮겨지지 않아요: 가져오기 도구는 n8n 자격 증명이나 API 키를 가져오지 않아요. 필요한 앱은 하이퍼클래스에서 직접 연결해야 해요.
- 일부 단계는 바뀌어요: 고정된 워크플로우 로직이 에이전트 지침으로 바뀌거나, 다른 하이퍼클래스 액션이 쓰일 수 있어요. 동작이 에이전트의 추론에 달려 있으면 결과가 달라질 수 있어요.
- 직접 검토가 필요할 수 있어요: 추정된 판단 규칙이나 게시 전에 확인해야 하는 설정 항목이 강조 표시돼요.
- 기존 리소스 ID는 확인해야 해요: 원래 워크플로우의 시트, 채널, 리스트 같은 ID는 그대로 믿고 쓰지 않고 검토 대상으로 표시돼요.
- 분석만으로는 에이전트가 만들어지지 않아요: **초안으로 저장**이나 **Create & publish**(만들고 게시)를 선택해야 에이전트가 만들어져요.

## 관리형 에이전트로 n8n 워크플로우 가져오는 순서

n8n JSON 내보내기 파일에서 시작해 설정이 끝난 관리형 에이전트까지 만드는 과정이에요. 생성된 지침을 검토하고, 변환 결과를 확인하고, 필요한 연결을 마친 뒤에 초안으로 저장할지 게시할지 정하세요.

### 1단계: n8n 가져오기 도구 열기

관리형 에이전트를 만들 서브 계정에서 시작하세요. 가져오기 도구는 에이전트 스튜디오의 **관리형 에이전트** 탭에 있어요.

1. 하이퍼클래스에 로그인해서 해당 **서브 계정**을 여세요.
2. 왼쪽 메뉴에서 **AI 에이전트**를 선택하세요.
3. **에이전트 스튜디오**를 선택하세요.
4. **관리형 에이전트** 탭을 선택하세요.
5. 에이전트 페이지 오른쪽 위의 **다음에서 가져오기**를 클릭하세요.
6. 드롭다운 메뉴에서 **n8n (베타)** 를 선택하세요.

   **다음에서 가져오기 n8n** 창이 열려요.

### 2단계: n8n 워크플로우 JSON 올리거나 붙여넣기

내보낸 n8n 워크플로우를 JSON 파일로 올리거나, JSON 내용을 붙여넣을 수 있어요. 노드를 다시 만들 필요 없이 워크플로우 정의에서 바로 시작할 수 있어요.

1. **다음에서 가져오기 n8n** 창에서 **Drop your n8n workflow export**(n8n 워크플로우 내보내기 파일 놓기)라고 적힌 업로드 영역을 찾으세요.
2. 다음 두 방법 중 하나로 워크플로우를 추가하세요.
   - 내보낸 `.json` 파일을 업로드 영역으로 끌어다 놓거나, 영역을 클릭해서 파일을 찾아 선택하세요.
   - **Paste JSON instead**(대신 JSON 붙여넣기)를 선택해서 워크플로우 JSON을 직접 입력하세요.
3. 파일을 올릴 때는 JSON 내보내기 파일이고 10 MB 이하인지 확인하세요.
4. 워크플로우 JSON을 넣었으면 **Analyze workflow**(워크플로우 분석)를 클릭하세요.

가져오기 도구가 워크플로우 분석을 시작해요. 이 단계에서는 에이전트가 만들어지지 않아요.

![n8n 워크플로우 JSON을 올리는 가져오기 창](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083809041/original/PmC9cv-2H2PsaCt_nQuCS9dQM4GORl1DtA.png?1792543227)

### 3단계: 워크플로우 분석 확인

하이퍼클래스는 내보낸 워크플로우를 분석해서 단계, 필요한 리소스, 관리형 에이전트로 구성할 방법을 찾아내요. 진행 화면에서 가져오기 도구가 원래 자동화를 어떻게 처리하는지 볼 수 있어요.

분석은 다음 순서로 진행돼요.

- **Reading the workflow**(워크플로우 읽는 중): 올린 n8n 워크플로우 정의를 읽어요.
- **Mapping each step**(각 단계 매핑 중): 변환이 필요한 워크플로우 단계를 찾아요.
- **Checking this account's forms, calendars and knowledge bases**(이 계정의 폼, 캘린더, 지식 베이스 확인 중): 서브 계정에서 쓸 수 있는 하이퍼클래스 리소스를 살펴봐요.
- **Planning the agent**(에이전트 계획 중): 워크플로우를 관리형 에이전트로 어떻게 나타낼지 정해요.
- **Writing the agent**(에이전트 작성 중): 분석한 워크플로우를 바탕으로 에이전트 지침과 동작을 작성해요.
- **Checking it against your workflow**(워크플로우와 비교 확인 중): 생성된 에이전트 계획을 원래 워크플로우와 비교해요.

분석 화면에는 확인된 워크플로우 단계 수도 표시돼요.

분석이 끝나면 생성된 에이전트가 검토 화면에 나타나요.

![워크플로우 분석 진행 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083809059/original/qeQpGgYEOgFOmwGRbEbl0uPVS4LF4JaaSw.png?1792543284)

### 4단계: 생성된 에이전트와 변환 결과 검토

생성된 에이전트를 검토하면 원래 n8n 워크플로우와 하이퍼클래스에서 제안한 구현이 어디가 다른지 알 수 있어요.

#### 생성된 에이전트 검토하기

1. **Review & set up**에서 생성된 에이전트 요약을 찾으세요.
2. 에이전트 이름과 설명이 워크플로우의 원래 목적과 맞는지 확인하세요.
3. 표시된 시작 조건, 앱 연결, 기능을 확인하세요.
4. **Agent instructions**(에이전트 지침)를 펼치면 생성된 지침을 볼 수 있어요. 지침에는 에이전트가 무엇으로 시작되는지, 어떤 액션을 하는지, 판단 규칙, 후속 조치, 중단 조건이 나와 있어요.

#### 워크플로우가 어떻게 변환됐는지 검토하기

1. **How your workflow came across**(워크플로우가 넘어온 방식)까지 아래로 스크롤하세요.
2. 몇 단계가 그대로 넘어오고 몇 단계가 바뀌었는지 변환 요약을 확인하세요.
3. 변환 결과를 하나씩 살펴보세요.
   - **Carried over**(그대로 넘어옴): 변환된 에이전트에 그대로 유지된 단계예요.
   - **Adapted**(변경됨): 관리형 에이전트에서 다르게 구현된 단계예요.
   - **Not possible / Not needed**(불가능 / 불필요): 가져오기 도구가 지원되지 않거나 필요 없다고 판단한 단계예요. 해당하는 단계가 있으면 확인하세요.
4. 변경된 단계에 표시된 이유를 확인하세요.

   워크플로우가 시작되는 방식, 단계가 실행되는 시점, 액션이 앱·CRM·API 호출 중 어느 쪽으로 처리되는지가 바뀔 수 있어요.
5. 경고나 사람이 직접 확인해야 한다고 표시된 항목을 확인하세요.

   원래 워크플로우의 일부 규칙은 고정된 코드 대신 에이전트 지침이 될 수 있어요. 이런 규칙은 결과가 조금 다를 수 있으니, 의도한 동작과 맞는지 확인하세요.

### 5단계: 에이전트에 필요한 설정 마치기

**Review & set up** 화면에는 가져온 에이전트가 의도대로 동작하는 데 필요한 설정 항목이 모여 있어요. 필요한 항목은 워크플로우의 트리거, 연동, 데이터 참조에 따라 달라요.

#### 에이전트가 시작되는 방식 설정하기

1. 가져오기 창에서 **Finish setup**(설정 마무리)을 찾으세요.
2. **How it starts**(시작 방식) 아래에서 생성된 시작 조건을 확인하세요.
3. **편집** 버튼이 보이면 선택해서 시작 조건을 확인하거나 필요에 맞게 바꾸세요.

   예를 들어 주기적으로 실행되던 n8n 워크플로우는 **일정** 트리거로 변환될 수 있어요. 일정 트리거에 대해서는 [하이퍼클래스 관리형 에이전트의 일정 트리거](../13-AI-Employee/Agent-Studio/scheduled-triggers-for-managed-agents-in-hyperclass.md)를 참고하세요.
4. 트리거가 원래 자동화의 의도한 실행 시점이나 시작 이벤트와 맞는지 확인하세요.

#### 필요한 앱 연결하기

1. **Apps to connect**(연결할 앱)를 찾으세요.
2. 나열된 앱과 각 앱의 연결 상태를 확인하세요.
3. 앱이 **연결되지 않음**으로 표시돼 있으면 **연결**을 선택하세요.
4. 이미 연결된 앱은 **관리**가 보이면 선택해서 연결을 확인하세요.

   원문 예시에는 HubSpot MCP 연결이 나와요. 이 앱을 연결하기 전에는 해당 앱이 필요한 단계가 건너뛰어지고, 그 사실이 보고돼요.

#### 필수 값 입력하기

1. **Values to set**(설정할 값)을 찾으세요.
2. **입력 필요**로 표시된 필드를 확인하세요.
3. 해당 입력란에 필요한 값을 입력하세요.
4. **저장**을 클릭해서 값을 저장하세요.

예를 들어 가져온 워크플로우에 영업 담당자의 소유자 ID가 필요할 수 있어요.

5. 가져오기 도구가 표시한 원래 리소스 ID가 있으면 확인하세요. 기존 참조를 그대로 둘지, 알맞은 링크나 ID로 바꿀지 정하세요.

#### 추가 요구 사항 확인하기

1. 가져오기 도구가 요청하는 **지식 베이스** 설정이 있으면 마치세요.
2. 게시하기 전에 남아 있는 경고나 설정 요구 사항을 확인하세요.

![설정 마무리 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083809149/original/2VuFGuAndR7CPoc3p3MjhdLl0P5JHaZn9w.png?1792543736)

### 6단계: 초안으로 저장하거나 만들고 게시하기

변환된 워크플로우와 설정을 검토한 뒤, 가져온 에이전트를 나중에 설정하도록 저장할지 바로 게시할지 선택하세요.

1. **Review & set up** 창 맨 아래로 돌아가세요.
2. 남아 있는 설정 요구 사항을 확인하세요.
3. 사용할 수 있는 동작 중 하나를 선택하세요.
   - **초안으로 저장**: 관리형 에이전트를 초안으로 만들어서 나중에 설정을 마무리하거나 다듬을 수 있어요.
   - **Create & publish**(만들고 게시): 필요한 설정을 모두 마친 뒤 관리형 에이전트를 만들고 게시해요.
4. 필수 설정 항목이 끝나지 않았으면 해당 항목이 해결될 때까지 **Create & publish**를 쓸 수 없을 수 있어요.
5. **초안으로 저장**을 선택한 뒤에는 **완료** 화면을 확인하세요.

   초안 완료 화면에는 **Draft agent created**(초안 에이전트 생성됨), 에이전트 이름, 초안 상태, 남아 있는 필수 항목이 표시돼요.
6. 새 에이전트 설정을 이어서 하려면 **Open agent**(에이전트 열기)를 선택하고, 가져오기를 마치려면 **완료**를 선택하세요.

![초안 에이전트 생성 완료 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155083809169/original/cTDcBQQmQCKRTX_lVp2PI1NgemLPsRnmWA.png?1792543797)

### 7단계: 가져온 에이전트 찾아서 설정 마무리

가져온 에이전트는 에이전트 스튜디오의 전용 폴더에 모여요. 에이전트를 초안으로 저장했다면 열어서 AI 빌더로 남은 설정을 마칠 수 있어요. 에이전트 스튜디오의 폴더 사용법은 [에이전트 스튜디오에서 폴더 만들고 관리하기](../13-AI-Employee/Agent-Studio/how-to-create-and-manage-folders-in-agent-studio.md)를 참고하세요.

1. **서브 계정** 화면에서 **AI 에이전트 > 에이전트 스튜디오 > 관리형 에이전트**를 선택하세요.
2. **Imported from n8n** 폴더를 찾으세요.
3. 폴더를 열고 가져온 관리형 에이전트를 선택하세요.

   가져오기 완료 화면에서 **Open agent**를 바로 선택해도 돼요.
4. 에이전트에 남은 설정 항목이 있으면 **Finish setup** 안내를 확인하세요.
5. 표시된 링크나 **교체** 옵션으로 남은 요구 사항을 처리하세요.
6. AI 빌더에게 이렇게 물어볼 수도 있어요.

   **"What's left to set up?"**

   빌더가 남은 설정 항목을 찾아서 체크리스트로 보여 줘요.
7. 남은 작업을 모두 마치면 **Finish setup** 안내를 닫을 수 있어요.

```
수신 웹훅을 사용하는 에이전트

외부 웹훅으로 시작하는 워크플로우를 가져온 경우, 이벤트를 보내는 시스템이 관리형 에이전트의 웹훅 URL을 사용해야 해요.
제공된 URL을 복사해서 이벤트를 보내는 외부 시스템에 등록하세요.
```

## n8n 워크플로우 단계는 어떻게 변환되나요?

가져오기 도구는 원래 노드 그래프를 그대로 다시 만드는 대신, n8n 구성 요소를 관리형 에이전트의 동작으로 바꿔요. 변환 방식을 알아 두면 에이전트의 시작 조건, 판단, 액션이 자동화의 의도와 맞는지 확인하기 쉬워요.

### 트리거와 시작 조건

가져오기 도구는 원래 워크플로우를 시작시키는 요소를 찾아서, 지원되는 관리형 에이전트 트리거로 연결해요.

| n8n 워크플로우 구성 요소 | 관리형 에이전트 변환 결과 |
| --- | --- |
| Webhook 노드 | 자체 URL이 있는 수신 웹훅 트리거 |
| 주기적 확인 | 일정 트리거 |
| 폼 기반 이벤트 | 하이퍼클래스 폼 |
| 예약 이벤트 | 하이퍼클래스 캘린더 |
| 메시지 기반 이벤트 | 하이퍼클래스 대화 |

Stripe, Shopify, HubSpot, Pipedrive 같은 외부 서비스는 지원되는 이벤트를 수신 웹훅으로 보낼 수 있어요.

웹훅 기반으로 가져온 경우, 에이전트 지침에 URL을 어디에 등록해야 하는지, 보내는 시스템이 어떤 이벤트를 전달해야 하는지가 안내돼요.

### 판단 로직, 대기 단계, AI 노드

가져오기 도구는 워크플로우 로직을 에이전트 지침과 후속 동작으로 바꿔요. 덕분에 관리형 에이전트 안에서 원래의 시각적 노드 구조를 따로 유지하지 않아도 돼요.

| n8n 워크플로우 구성 요소 | 관리형 에이전트 변환 결과 |
| --- | --- |
| IF 노드 | 에이전트 지침 안의 판단 규칙 |
| Switch 노드 | 에이전트가 경로를 고르는 방법을 설명하는 판단 규칙 |
| Wait 노드 | 정해진 시점의 후속 조치 |
| OpenAI 노드 | 에이전트 추론 |
| LLM 체인 | 에이전트 추론과 지침 |
| AI Agent 노드 | 에이전트 추론과 지침 |

AI 구성 요소는 원래의 모델 노드 구조 없이 관리형 에이전트 자체의 추론에 포함돼요.

고정된 로직이 지침으로 바뀌면 노드 기반으로 실행하던 때와 동작이 조금 다를 수 있어요.

가져오기 도구가 알려 주는 변경 내용 메모를 읽고, 추가 확인이 필요하다고 표시된 규칙은 직접 확인하세요.

### 앱 연결, CRM 액션, API, 지식 베이스

가져오기 도구는 외부 앱 액션과 데이터 조회를 살펴보고, 관리형 에이전트가 하이퍼클래스를 통해 같은 작업을 하는 방법을 찾아요.

| n8n 워크플로우 구성 요소 | 관리형 에이전트 변환 결과 |
| --- | --- |
| 지원되는 앱 노드 | 마켓플레이스 앱 연결 |
| CRM 관련 액션 | 하이퍼클래스 CRM 액션 |
| 외부 API 작업 | API 호출 |
| 지식 조회 | 하이퍼클래스 지식 베이스 |

일부 액션은 원래 n8n 노드와 다르게 구현될 수 있어요.

가져오기 도구는 이런 변경 사항을 알려 주고, 작업이 앱·CRM·API 호출 중 어느 쪽으로 실행되는지도 설명해 줘요.

영향을 받는 작업이 의도대로 동작하려면 필요한 연동과 계정별 값을 여전히 설정해야 해요.

## 자주 묻는 질문

### n8n 워크플로우를 가져오는 것과 하이퍼클래스 MCP로 n8n을 연결하는 것은 같은 건가요?

아니요. n8n 가져오기는 내보낸 워크플로우를 하이퍼클래스 관리형 에이전트로 변환해요.

기존 하이퍼클래스 MCP 연동은 n8n에서 계속 실행되는 워크플로우와 하이퍼클래스를 연결해요. 두 방식은 서로 달라요. MCP 연동은 [하이퍼클래스 MCP와 n8n으로 워크플로우 자동화하기](../13-AI-Employee/MCP-Server/automate-workflows-with-hyperclass-mcp-and-n8n.md)를 참고하세요.

### 가져온 워크플로우에 필요한 앱이 연결되어 있지 않으면 어떻게 되나요?

가져오기 도구가 **Review & set up** 단계에서 필요한 앱 연결을 알려 줘요.

원문의 HubSpot MCP 예시에서는 앱을 연결하기 전까지 그 연결이 필요한 단계가 건너뛰어지고 보고돼요.

에이전트를 게시하기 전에 연결 요구 사항을 확인하세요.

### 원래 워크플로우의 시트 ID, 채널 ID 같은 참조는 어떻게 되나요?

가져오기 도구는 이런 참조를 자동으로 믿고 쓰지 않고, 검토 대상으로 표시해요.

기존 참조가 맞는지 확인하거나, 다른 링크나 ID로 바꿀 수 있어요.

이렇게 하면 계정마다 다른 참조가 엉뚱한 설정에 들어가는 일을 막을 수 있어요.

### 가져온 에이전트가 원래 n8n 워크플로우와 다르게 동작하는 이유는 무엇인가요?

일부 n8n 단계는 고정된 코드나 명시적인 분기 규칙을 써요. 가져오기 도구는 이런 작업을 에이전트 지침과 판단 규칙으로 바꿀 수 있어요.

검토 화면에서 이렇게 바뀐 부분을 알려 주고, 직접 확인이 필요한 추정 로직을 강조 표시해 줄 수도 있어요.

생성된 에이전트가 의도한 업무 절차를 따르는지 해당 규칙을 꼼꼼히 확인하세요.
