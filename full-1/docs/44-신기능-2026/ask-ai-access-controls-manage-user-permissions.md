# AI에게 문의 — 이용 권한 설정과 사용자 권한 관리

에이전시 관리자는 **이용 권한 설정**에서 'AI에게 문의'를 서브 계정과 사용자별로 어떻게 쓰게 할지 한곳에서 정할 수 있어요. 액세스 수준을 지정하고, 스킬 권한을 설정하고, 사용자에게 열어 줄 AI 기능을 고를 수 있어요.

변경 사항은 한꺼번에 적용할 수 있고, **감사 로그**에서 권한 변경 내역도 확인할 수 있어요. 이 설정으로 민감한 데이터와 작업은 보호하면서 AI의 도움은 계속 받을 수 있어요.

## 이용 권한 설정이란?

**이용 권한 설정**은 에이전시 단위의 설정이에요. 누가 'AI에게 문의'를 쓸 수 있는지, 그리고 'AI에게 문의'가 사용자를 대신해 어떤 작업까지 할 수 있는지를 정해요. 모든 사용자에게 같은 기능을 주는 대신, 담당 업무, 계정 요구 사항, 조직 정책에 맞춰 접근 범위를 나눌 수 있어요.

이용 권한 설정은 다음 관리 옵션으로 이루어져 있어요.

- **에이전시 관리자:** 에이전시 전체의 'AI에게 문의' 액세스를 관리하는 중앙 영역이에요.
- **액세스 수준:** 사용자에게 지정하는 권한 프로필이에요. 기본 제공 수준과 직접 만든 수준이 있어요.
- 스킬 권한: 'AI에게 문의'가 접근할 수 있는 영역과 작업을 정해요.
- **기능:** 에이전시, 서브 계정, 사용자 단위로 켜거나 끌 수 있는 개별 기능이에요.
- 일괄 관리: 여러 서브 계정에 액세스를 지정하고 'AI에게 문의'를 한꺼번에 켜는 도구예요.
- **감사 로그:** 이전 값과 변경된 값을 포함한 권한 변경 기록이에요.

'AI에게 문의'는 각 사용자가 이미 가진 하이퍼클래스 권한도 그대로 따라요. 'AI에게 문의' 액세스 수준을 지정해도, 하이퍼클래스에서 원래 할 수 없던 작업까지 할 수 있게 되지는 않아요.

{% hint style="warning" %}
에이전시 관리자는 'AI에게 문의'를 제한 없이 쓸 수 있어요. **에이전시 관리자** 화면은 에이전시 관리자에게만 보이고, 서브 계정 안이나 지원 모드에서는 나타나지 않아요.
{% endhint %}

## 'AI에게 문의' 액세스 수준 이해하기

액세스 수준은 'AI에게 문의'가 한 사용자를 위해 수행할 수 있는 스킬과 작업의 종류를 정해요. 흔한 업무에는 미리 만들어진 액세스 수준을 쓰고, 더 세밀한 제한이 필요한 팀에는 직접 만든 수준을 쓸 수 있어요.

### 기본 제공 액세스 수준

하이퍼클래스에는 기본 액세스 수준이 세 가지 있어요.

| 액세스 수준 | 설명 | 사용 예시 |
| --- | --- | --- |
| **Assistant**(도우미) | 기록을 수정하지 않고 정보 확인과 도움이 주로 필요한 사용자에게 맞는 수준이에요. | 연락처나 대화 정보를 조회하는 프런트 데스크 직원 |
| **Operator**(운영자) | 'AI에게 문의'가 허용된 운영 작업을 수행하기를 원하는 사용자에게 맞는 수준이에요. | 기회를 업데이트하고 후속 메시지를 보내는 계정 매니저 |
| **Builder**(빌더) | 담당 업무에 더 넓은 범위의 지원 기능이 필요한 사용자를 위한 수준이에요. | 지원되는 업무 프로세스를 설정하고 구축하는 팀원 |

각 수준에서 실제로 쓸 수 있는 작업은 그 수준의 권한 구성과 사용자가 가진 하이퍼클래스 권한에 따라 정해져요.

{% hint style="warning" %}
Assistant, Operator, Builder는 'AI에게 문의' 액세스 수준이에요. 하이퍼클래스의 기본 역할인 에이전시 관리자, 서브 계정 관리자, 사용자를 대신하지 않아요.
{% endhint %}

### 직접 만드는 액세스 수준

직접 만든 액세스 수준을 쓰면 전문 업무나 규정 준수 요건이 있는 팀에 맞게 'AI에게 문의' 권한을 조정할 수 있어요.

직접 만든 수준은 모두 기존 액세스 수준을 복사해서 시작해요. 만들 때 원본 수준이 가진 권한을 넘어설 수 없어요.

예를 들어 Operator 수준을 복사해 "계정 매니저 — 결제 제한"이라는 수준을 만들 수 있어요. 그다음 결제 권한만 빼고 나머지 운영 기능은 그대로 둘 수 있어요.

직접 만든 수준은 이름을 바꾸거나 보관할 수 있지만, 완전히 삭제할 수는 없어요. 액세스 수준 구성과 변경 내역을 나중에도 확인할 수 있도록 하기 위해서예요.

## 스킬 권한 이해하기

스킬 권한은 'AI에게 문의'가 사용자를 위해 접근할 수 있는 하이퍼클래스 작업의 종류를 정해요. 'AI에게 문의'를 통째로 켜거나 끄는 것보다 세밀하게 조정할 수 있어요. 정보 조회 같은 작업은 허용하고, 기록 변경이나 민감한 작업은 제한할 수 있어요.

'AI에게 문의' 권한 정책은 연락처, 대화, 결제, 프로젝트 등 12개 그룹에 걸쳐 58개 스킬 영역과 924개 작업을 다뤄요.

### 스킬 권한 수준

| 권한 | 의미 |
| --- | --- |
| **Off**(끔) | 해당 사용자에게는 'AI에게 문의'가 이 스킬을 쓸 수 없어요. |
| **View**(보기) | 'AI에게 문의'가 허용된 정보를 수정 없이 불러오거나 읽을 수 있어요. |
| **편집** | 'AI에게 문의'가 스킬 영역 안에서 허용된 수정 작업을 할 수 있어요. |
| **삭제** | 'AI에게 문의'가 지원되는 영역에서 허용된 삭제 작업을 할 수 있어요. 해당하는 확인 절차와 권한 요건도 함께 적용돼요. |

지원되는 스킬 영역마다 알맞은 권한 수준을 설정할 수 있어요.

예를 들어 프런트 데스크 사용자는 연락처 정보를 조회할 수 있어야 하지만, 연락처 기록을 수정하거나 삭제할 수는 없어야 해요. 계정 매니저는 기회 편집 권한은 필요하지만 결제 권한은 필요하지 않을 수 있어요.

{% hint style="warning" %}
스킬을 **Off**로 설정하면 그 사용자에게 제공되는 'AI에게 문의' 스킬 목록에서 해당 스킬이 빠져요. 'AI에게 문의'는 꺼진 스킬을 전달받지 못하고, 범위 밖의 요청에 답할 때도 그 스킬을 알려 주거나 제안하지 않아요.
{% endhint %}

일부 스킬 영역은 권한 정책에서 민감 영역 또는 에이전시 전용으로 표시돼요. 더 넓은 액세스를 주기 전에 이 표시를 확인하세요.

## 스킬 권한과 하이퍼클래스 사용자 권한의 관계

'AI에게 문의' 액세스 수준은 기존 하이퍼클래스 권한을 덮어쓰지 않아요.

사용자가 어떤 작업을 요청하면, 'AI에게 문의'는 적용되는 'AI에게 문의' 액세스 정책과 사용자의 하이퍼클래스 권한을 모두 지켜야 해요.

예를 들면 다음과 같아요.

- 'AI에게 문의'에서는 연락처 편집 권한이 있어도 하이퍼클래스에서는 연락처 읽기 전용 권한만 있는 사용자는, 'AI에게 문의'로 연락처 기록을 수정할 수 없어요.
- 하이퍼클래스에서는 기회를 편집할 수 있어도 'AI에게 문의'에서는 **View** 권한만 있는 사용자는, 'AI에게 문의'로 기회를 업데이트할 수 없어요.
- **Off**로 설정한 스킬은 사용자가 하이퍼클래스에서 더 넓은 권한을 갖고 있어도 'AI에게 문의'에 제공되지 않아요.

액세스 정책은 'AI에게 문의'의 텍스트 대화와 음성 대화에 모두 적용돼요. 권한이 없는 작업은 CRM까지 전달되지 않도록 권한을 확인해요.

기본 사용자 권한은 [서브 계정: 사용자 역할, 권한, 할당 데이터](../11-설정/사용자-설정/user-roles-permissions-and-assigned-data-subaccount.md)에서 자세히 확인하세요.

## 'AI에게 문의' 기능 관리하기

**기능**은 액세스 수준으로 지정한 스킬 권한과는 별개로, 'AI에게 문의'의 개별 기능을 쓸 수 있는지를 정해요. 액세스 수준 구성 전체를 바꾸지 않고도 기능별 사용 여부를 조정할 수 있어요.

기능 설정은 세 가지 범위에 적용할 수 있어요.

- **에이전시:** 에이전시 전체의 기능 사용 여부를 정해요.
- **서브 계정:** 특정 서브 계정의 기능 사용 여부를 설정해요.
- **사용자:** 개별 사용자의 기능 사용 여부를 정해요.

기능의 예로는 **브라우저 제어**와 음성이 있어요. 제품 안내 영상에서는 **디스패치**도 기능으로 소개해요.

예를 들어 계정 매니저가 'AI에게 문의'로 CRM 기록을 업데이트하게 하면서, 규정 준수 요건이 더 엄격한 고객사에는 **브라우저 제어**를 꺼 둘 수 있어요.

기능 설정과 스킬 권한은 함께 작동해요. 지원되는 기능을 쓰려면 알맞은 액세스 권한과 해당 기능의 사용 설정이 모두 필요해요.

**브라우저 제어** 설정은 [AI 브라우저 제어 확장 프로그램](../13-AI-Employee/Ask-AI/ai-browser-control-extension.md)에서 자세히 확인하세요.

## 서브 계정과 사용자별 'AI에게 문의' 액세스 관리하기

에이전시 관리자는 서브 계정 단위와 개별 사용자 단위로 'AI에게 문의' 사용 여부를 관리할 수 있어요. 에이전시 전체에는 'AI에게 문의'를 켜 두고, 특정 고객사나 팀원에게만 다른 제한을 둘 수 있어요.

### 서브 계정 액세스

서브 계정마다 이용 권한 설정에서 'AI에게 문의'를 켜거나 끌 수 있어요.

예를 들어 대부분의 고객사에는 'AI에게 문의'를 켜고, AI를 활용한 작업을 아직 승인하지 않은 서브 계정에는 꺼 둘 수 있어요.

### 개별 사용자 액세스

'AI에게 문의'를 켠 서브 계정 안에서는 'AI에게 문의' 스위치와 액세스 수준 지정으로 개별 사용자를 관리할 수 있어요.

예를 들어 같은 서브 계정의 팀원 세 명에게 서로 다른 구성을 줄 수 있어요.

| 사용자 담당 업무 | 구성 예시 |
| --- | --- |
| 프런트 데스크 | 'AI에게 문의' 켬, Assistant 액세스 |
| 계정 매니저 | 'AI에게 문의' 켬, Operator 액세스 |
| 제한 사용자 | 'AI에게 문의' 끔 |

이렇게 하면 다른 사용자의 액세스 구성은 건드리지 않고, 사람마다 'AI에게 문의' 환경을 따로 맞출 수 있어요.

## 일괄 액세스 관리

일괄 액세스 관리를 쓰면 같은 작업을 일일이 반복하지 않고 여러 서브 계정에 'AI에게 문의' 구성을 한꺼번에 적용할 수 있어요. 고객사가 많은 에이전시나 표준 액세스 정책을 도입할 때 특히 편해요.

지원하는 일괄 작업은 다음과 같아요.

- 여러 서브 계정에서 'AI에게 문의' 켜기
- 조건에 맞는 서브 계정의 사용자에게 액세스 수준 적용하기

액세스 수준 일괄 지정은 백그라운드 작업으로 실행돼요. 작업 진행률과 기록을 확인하고, 실패한 행을 살펴보고, 실행 중인 작업을 취소하고, 실패한 지정을 다시 시도할 수 있어요.

### 일괄 작업 상태와 재시도

일괄 작업 추적으로 액세스 관리 변경 결과를 확인할 수 있어요.

- **진행률:** 일괄 작업의 현재 상태를 확인해요.
- **기록:** 이전에 제출한 일괄 작업을 확인해요.
- **Failed Rows**(실패한 행): 정상적으로 완료되지 않은 지정을 찾아요.
- **취소:** 아직 실행 중인 일괄 작업을 멈춰요.
- **재시도:** 성공한 지정은 다시 처리하지 않고, 실패한 지정만 다시 실행해요.

예를 들어 서브 계정이 150개인 에이전시는 일괄 작업으로 선택한 계정에 'AI에게 문의'를 켜고, 계정 매니저에게 Operator 액세스를 지정할 수 있어요.

일부 지정이 실패하면 실패한 행을 확인하고, 전체 작업을 처음부터 다시 하지 않고 그 지정만 재시도하면 돼요.

## 감사 로그로 변경 내역 확인하기

감사 로그에는 'AI에게 문의' 액세스 구성에 대한 관리자 변경 내역이 기록돼요. 예상하지 못한 권한 변경을 조사하거나, 계정 활동을 검토하거나, 액세스 관리 결정의 책임을 확인할 때 쓸 수 있어요.

'AI에게 문의' 액세스와 관련된 변경은 **설정 > 감사 로그**의 **'AI에게 문의' 액세스** 카테고리에 기록돼요.

다음 항목의 변경이 기록돼요.

- 액세스 수준
- 사용자별 액세스 수준 지정
- 기능 구성

각 항목에는 변경한 사람이 표시되고, 상세 정보 창에서 이전 값과 변경된 값을 볼 수 있어요.

예를 들어 고객사의 계정 매니저가 갑자기 어떤 스킬을 쓸 수 없게 됐다면, 에이전시 관리자는 관련 'AI에게 문의' 액세스 이벤트를 열어 무엇이 바뀌었고 누가 변경했는지 확인할 수 있어요.

{% hint style="info" %}
하이퍼클래스 감사 로그 문서에는 보관 기간이 60일이라고 안내돼 있어요. 해당 보관 정책을 따르고, 조직의 규정 준수 요건상 더 오래 증빙이 필요하면 기록을 내보내거나 따로 보관하세요. 자세한 내용은 [감사 로그](../11-설정/audit-logs.md)를 참고하세요.
{% endhint %}

## 자주 묻는 질문

### 에이전시 관리자도 자기 'AI에게 문의' 액세스를 제한할 수 있나요?

현재 액세스 제어 방식에서는 에이전시 관리자가 'AI에게 문의'를 제한 없이 쓸 수 있어요. 관리 설정은 다른 사용자와 서브 계정의 액세스를 관리하는 용도예요.

### 꺼 둔 스킬이 필요한 작업을 'AI에게 문의'에 요청하면 어떻게 되나요?

꺼진 스킬은 사용 가능한 스킬로 'AI에게 문의'에 전달되지 않아요. 사용자에게 허용된 기능 범위 안에서 요청을 처리할 수 없으면, 'AI에게 문의'는 숨겨진 스킬을 알려 주거나 제안하지 않고 중립적으로 답해요.

### 직접 만든 액세스 수준에 복사해 온 수준보다 많은 권한을 줄 수 있나요?

아니요. 직접 만든 액세스 수준은 만들 때 원본 수준이 가진 권한을 넘어설 수 없어요.

### 직접 만든 액세스 수준을 완전히 삭제할 수 있나요?

아니요. 직접 만든 액세스 수준은 이름을 바꾸거나 보관할 수는 있지만 완전히 삭제할 수는 없어요. 과거 액세스 제어 정보를 보존하기 위해서예요.

### 하이퍼클래스에서 연락처를 편집할 수 있는 사용자가 'AI에게 문의' 액세스는 View로 제한돼 있으면, 'AI에게 문의'로 연락처를 편집할 수 있나요?

아니요. 'AI에게 문의'는 적용되는 권한 중 더 제한적인 쪽을 따라요. 요청한 작업을 하려면 두 쪽 모두에서 알맞은 권한이 있어야 해요.

### 실패한 일괄 지정을 재시도하면 이미 성공한 변경이 반복되나요?

아니요. **재시도**는 실패한 지정만 다시 처리해요. 성공한 지정을 불필요하게 반복하지 않아요.

### 'AI에게 문의'를 전부 끄지 않고 브라우저 제어만 끌 수 있나요?

네. 기능 설정으로 지원되는 특정 기능만 끄고, 나머지 허용된 'AI에게 문의' 기능은 그대로 쓰게 할 수 있어요.

### 액세스 수준을 지정하면 사용자의 기본 하이퍼클래스 역할이 바뀌나요?

아니요. 'AI에게 문의' 액세스 수준은 사용자의 'AI에게 문의' 권한만 정해요. 하이퍼클래스의 기본 역할과 세부 권한은 따로 유지되고 계속 적용돼요.
