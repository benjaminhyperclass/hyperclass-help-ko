# 프로젝트 관리 API 설정과 주요 기능

프로젝트 관리 공개 API를 쓰면 다른 애플리케이션에서 하이퍼클래스의 프로젝트와 작업을 만들고 관리할 수 있어요. 이 문서에서는 API로 할 수 있는 일, 동작 방식, 시작하는 방법을 안내해요.

## 프로젝트 관리 공개 API란?

프로젝트 관리 공개 API는 개발자가 다른 애플리케이션에서 하이퍼클래스의 프로젝트와 작업을 관리하게 해 주는 API예요. 8개 API 그룹에 엔드포인트가 모두 45개 있어요. 하이퍼클래스에서 일일이 손으로 바꾸지 않아도 프로젝트 구조 만들기, 작업 수정, 권한 관리, 반복 작업 자동화를 할 수 있어요.

API(Application Programming Interface)는 서로 다른 애플리케이션이 정보를 주고받게 해 주는 방식이에요.

사용 가능 대상: 현재 **프로젝트 관리** 프라이빗 베타가 켜진 서브 계정에서만 쓸 수 있어요.

---

## 프로젝트 구조 이해하기

하이퍼클래스 **프로젝트 관리**는 계층 구조로 작업을 정리해요. 이 구조를 알면 API를 쓸 때 프로젝트와 작업이 어디에 속하는지 쉽게 파악할 수 있어요.

- **스페이스**: 프로젝트를 정리하는 가장 큰 단위예요.
- **폴더**: 관련 **목록**을 묶는 선택 사항 단위예요.
- **목록**: 서로 관련된 작업을 모아 둔 단위예요.
- **작업**: 하나하나의 업무예요.
- **하위 작업**: 다른 작업 안에 있는 더 작은 작업이에요.

예를 들어 에이전시라면 *고객 프로젝트* 스페이스를 만들고, 그 안에 *웹사이트 프로젝트* 폴더와 *웹사이트 런칭* 목록을 만들어 작업을 담을 수 있어요.

{% hint style="info" %}
**폴더** 없이 **스페이스** 안에 바로 **목록**을 만들 수도 있어요.
{% endhint %}

자세한 내용은 [스페이스, 폴더, 목록으로 업무 정리하기](../36-기타/organize-work-with-spaces-folders-and-lists.md)와 [프로젝트 관리 소개](../36-기타/introduction-to-project-management.md)를 참고하세요.

## 스페이스, 폴더, 목록 관리

API로 외부 애플리케이션에서 프로젝트 구조를 만들고 정리할 수 있어요.

할 수 있는 일은 다음과 같아요.

- **스페이스**, **폴더**, **목록**을 만들고, 조회하고, 수정하고, 삭제해요.
- **스페이스**나 **폴더** 안에 **목록**을 만들어요.
- 페이지 나누기(pagination)로 많은 항목을 나눠서 가져와요.
- 직접 부여된 멤버 접근 권한과 상속된 접근 권한을 조회해요.
- `isPrivate`로 비공개 여부를 정해요.
- 멤버의 접근 권한을 부여하거나 회수해요.

{% hint style="info" %}
`userIds`로 멤버를 추가해도 기존 접근 권한이 자동으로 제거되지는 않아요.
{% endhint %}

비공개 설정은 [스페이스, 폴더, 목록을 비공개로 설정하기](../36-기타/make-a-space-folder-or-list-private.md)에서 자세히 볼 수 있어요.

## 작업 상태 관리

상태는 할 일, 진행 중, 완료처럼 팀이 진행 상황을 확인하는 데 쓰여요. API로 이 상태들을 조회하고 관리할 수 있어요.

할 수 있는 일은 다음과 같아요.

- **스페이스**나 **목록**에서 쓸 수 있는 상태를 조회해요.
- **스페이스**의 상태 설정 전체를 교체해요.
- `key`로 상태를 구분하고, `label`로 화면에 표시해요.

작업의 `statusGroup`이 `done`이면 완료된 작업으로 봐요.

---

## 작업과 하위 작업 관리

API로 하이퍼클래스에 직접 입력하지 않고도 작업을 만들고 관리할 수 있어요. 큰 작업은 더 작은 **하위 작업**으로 나눌 수도 있어요.

할 수 있는 일은 다음과 같아요.

- **작업**을 만들고, 조회하고, 수정하고, 삭제해요.
- 최대 10개의 **목록**에 걸쳐 **작업**을 검색하고 필터링해요.
- ID로 여러 **작업**을 한 번에 가져와요.
- `parentTaskId`로 **하위 작업**을 만들어요.
- 커스텀 필드 V2로 **작업**에 커스텀 필드 값을 추가해요.

작업을 검색하면 **하위 작업**을 접은 상태, 펼친 상태, 또는 별도 결과로 받을 수 있어요.

작업 만들기는 [작업 또는 하위 작업 만들기](../36-기타/create-a-task-or-subtask.md), 커스텀 필드는 [작업에서 커스텀 필드 사용하기](../36-기타/use-custom-fields-on-tasks.md)를 참고하세요.

## 여러 목록에 걸친 작업 관리

작업 하나를 작업 복제 없이 여러 **목록**에 표시할 수 있어요. 여러 팀이 같은 업무를 함께 추적해야 할 때 유용해요.

할 수 있는 일은 다음과 같아요.

- **작업**에 연결된 모든 **목록**을 조회해요.
- **작업**을 **목록**에 추가하거나 **목록**에서 제거해요.
- **작업**의 기본 위치인 홈 목록(home List)을 바꿔요.

홈 목록에 따라 그 **작업**에 적용되는 상태 설정이 정해져요.

## 작업 댓글 관리

작업 댓글로 팀원끼리 업무를 논의하고 진행 상황을 공유해요. API를 쓰면 외부 애플리케이션에서도 이 댓글을 관리할 수 있어요.

할 수 있는 일은 다음과 같아요.

- 댓글을 조회하고, 작성하고, 수정하고, 삭제해요.
- 서식이 있는 텍스트와 @멘션을 추가해요.
- 댓글 아래에 한 단계까지 답글을 달아요.

{% hint style="info" %}
댓글은 작성자만 수정하거나 삭제할 수 있어요.
{% endhint %}

## 반복 작업 관리

**반복 작업**은 주간 보고서나 월간 점검처럼 정기적으로 반복되는 업무를 자동화해 줘요.

API로 **반복 작업** 정의를 만들고, 조회하고, 수정하고, 삭제할 수 있어요.

일정은 RRULE 문자열을 직접 쓰지 않아도 되도록 구조화된 반복 옵션으로 설정해요.

지원하는 일정 옵션은 프로젝트 관리 API 문서를 참고하세요. 문서 위치를 모르면 하이퍼클래스 고객지원에 문의하세요.

## 프로젝트 관리 공개 API 시작하기

API를 쓰려면 **프로젝트 관리** 프라이빗 베타 이용 권한, 유효한 인증 정보, 필요한 권한이 있어야 해요.

### 1단계: 프라이빗 베타 이용 권한 확인

API는 **프로젝트 관리** 프라이빗 베타에 등록된 서브 계정에서만 동작해요.

1. 하이퍼클래스 서브 계정을 열어요.
2. **연락처 > 작업**으로 이동해요.
3. 새 **프로젝트 관리** 화면이 보이는지 확인해요.
4. 서브 계정에 프라이빗 베타 이용 권한이 있는지 확인해요.

{% hint style="warning" %}
계정에 **프로젝트 관리**가 보이는 것은 첫 번째 확인 방법일 뿐이에요. API를 쓰기 전에 베타 이용 자격을 따로 확인하세요.
{% endhint %}

### 2단계: 인증 설정

인증은 하이퍼클래스가 연동에 데이터 접근 권한이 있는지 확인하는 절차예요.

API는 세 가지 인증 방식을 지원해요.

- 비공개 연동 토큰(Private Integration Token, PIT): 외부 애플리케이션을 하이퍼클래스에 연결할 때 쓰는 토큰이에요.
- OAuth: 인증 절차를 거쳐 애플리케이션이 하이퍼클래스에 접근하게 하는 방식이에요.
- APP Channel: 지원되는 애플리케이션 연동에서 쓰는 인증 방식이에요.

비공개 연동 토큰을 만드는 방법은 다음과 같아요.

1. 해당 계정 수준에서 **설정 > 비공개 연동**을 열어요.
2. **새 연동 만들기**를 클릭해요.
3. 이름과 설명을 입력해요.
4. 필요한 권한(스코프)을 선택해요.
5. 연동을 만들고 토큰을 안전한 곳에 복사해 두세요.

{% hint style="info" %}
사용할 수 있는 권한은 쓰려는 API 작업에 따라 달라져요. 연동 토큰은 외부에 공개하지 마세요.
{% endhint %}

자세한 방법은 [비공개 연동: 알아야 할 모든 것](../42-통합/Private-Integrations/private-integrations-everything-you-need-to-know.md)을 참고하세요.

### 3단계: API 요청 구성

API 요청은 스페이스 조회, 작업 만들기처럼 하이퍼클래스에서 어떤 작업을 할지 알려 주는 단위예요.

요청을 보내기 전에 다음을 확인하세요.

1. 프로젝트 관리 API 문서에서 필요한 엔드포인트를 선택해요.
2. 인증 정보를 포함해요.
3. 필수 헤더 `Version: v3`를 추가해요.
4. 필요한 파라미터와 권한을 입력해요.

서브 계정은 인증 방식에 따라 다르게 식별돼요.

| 인증 방식 | 서브 계정 식별 방법 |
| --- | --- |
| OAuth | 토큰으로 결정돼요 |
| 비공개 연동 토큰 | 토큰으로 결정돼요 |
| APP Channel | `locationId`를 쿼리 파라미터로 전달해요 |

### 4단계: API 요청 테스트

인증을 설정한 뒤에는 API 작업 하나로 연결을 테스트해 보세요.

1. 프로젝트 관리 API 문서를 열어요.
2. 스페이스 조회 같은 작업을 하나 선택해요.
3. 엔드포인트의 요청 안내를 따라요.
4. 필요한 인증 정보와 `Version: v3` 헤더를 포함해요.
5. API 클라이언트나 연동으로 요청을 보내요.
6. 응답을 확인해 요청이 성공했는지 살펴봐요.

첫 테스트에는 기존 정보를 조회하는 요청이 좋아요. 프로젝트 데이터를 바꾸지 않기 때문이에요.

요청이 실패하면 프라이빗 베타 이용 권한, 권한 설정, 인증, 필수 파라미터를 확인하세요.

## 자주 묻는 질문

### 하이퍼클래스 사용자는 누구나 프로젝트 관리 공개 API를 쓸 수 있나요?
아니요. 현재는 **프로젝트 관리** 프라이빗 베타에 등록된 서브 계정에서만 쓸 수 있어요.

### 코딩을 몰라도 API를 쓸 수 있나요?
API를 직접 쓰려면 API 요청에 대한 기본 지식이 필요해요. 개발자와 함께 연동을 만들 수도 있어요.

### 작업을 자동으로 만들 수 있나요?
네. API로 외부 애플리케이션에서 작업을 만들고, 수정하고, 관리할 수 있어요.

### 같은 작업을 여러 목록에 표시할 수 있나요?
네. 작업 하나가 여러 **목록**에 속할 수 있어요. 이때 홈 목록은 하나로 유지돼요.

### API 요청이 계속 실패해요. 왜 그런가요?
서브 계정에 프라이빗 베타 이용 권한이 있는지, 인증 정보에 필요한 권한이 있는지, 요청에 `Version: v3`가 들어 있는지 확인하세요.

### API를 쓰려면 비공개 연동 토큰이 꼭 필요한가요?
꼭 그렇지는 않아요. OAuth와 APP Channel 인증도 지원해요.

### API 엔드포인트 전체 목록은 어디서 볼 수 있나요?
프로젝트 관리 API 문서에서 엔드포인트 상세, 요청 파라미터, 지원하는 작업을 볼 수 있어요. 문서 위치를 모르면 하이퍼클래스 고객지원에 문의하세요.
