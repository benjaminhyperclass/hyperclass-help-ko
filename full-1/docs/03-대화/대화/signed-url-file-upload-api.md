# 서명된 URL 파일 업로드 API

서명된 URL 파일 업로드는 유효 시간이 정해진 보안 URL을 이용해, 클라이언트에서 Google Cloud Storage(GCS)로 파일을 바로 전송하는 방식이에요. 업로드 속도와 안정성이 좋아지고 서버 메모리 부담이 없어지며, WhatsApp에서는 최대 100MB, 그 밖의 채널에서는 최대 5MB 파일까지 보낼 수 있어요. 이 문서에서 동작 방식과 보안 장치, 3단계 업로드 흐름을 확인하세요.

## 서명된 URL 파일 업로드란?

서명된 URL 파일 업로드는 서버를 거치며 버퍼링하던 기존 업로드 방식을 클라이언트에서 GCS로 바로 전송하는 방식으로 바꾼 인프라 개선이에요. 파일 데이터를 애플리케이션 서버로 보내지 않고, 하이퍼클래스가 발급한 짧은 시간 동안만 유효한 서명된 URL로 직접 업로드해요. 이 구조 덕분에 메모리 부족(OOM, Out-Of-Memory) 위험이 줄고 전송 속도가 빨라지며, 파일 검증과 접근 제어도 적용돼요.

## 서명된 URL 파일 업로드의 장점

메시지나 미디어를 보낼 때 이 방식을 쓸지 판단하는 데 도움이 돼요. 특히 전송량이 많거나 WhatsApp처럼 큰 파일을 보내는 경우에 유용해요.

- 안정성: 파일이 서버 메모리에 쌓이지 않아서 OOM으로 인한 서버 중단이 없어요.
- 대용량 업로드: WhatsApp은 최대 100MB, 다른 채널은 최대 5MB 미디어를 지원해요.
- 성능: 클라이언트에서 GCS로 바로 전송하므로 업로드 경로가 짧아지고 지연 시간이 줄어요.
- 신뢰성: 서명된 URL은 15분 뒤에 만료되고, 만료되면 명확한 오류가 반환돼요.
- 보안: 여러 단계에서 경로 검증, 접근 제어, 콘텐츠 타입 확인을 해요.

## 3단계 업로드 흐름

서명된 URL 방식은 업로드를 요청, 업로드, 완료의 세 단계로 나눠요. 각 단계에서 메타데이터를 검증하고 제한을 적용하며, 서버 메모리에 부담을 주지 않고 오류를 알려 줘요.

1. 시작(Initiate): `POST /conversations/messages/upload/initiate`
   파일 메타데이터를 보내서 유효 시간이 정해진 서명된 URL과 오브젝트 경로를 요청해요.
2. 업로드(Upload): 클라이언트가 서명된 URL(GCS)로 파일을 직접 `PUT`해요.
   URL이 만료되기 전에, 받은 URL로 파일 데이터를 GCS에 전송하세요.
3. 완료(Complete): `POST /conversations/messages/upload/complete`
   하이퍼클래스가 저장된 오브젝트를 확인하고, 메시지에 사용할 공개 URL을 반환해요.

## 채널별 크기 제한

메시지 채널마다 보낼 수 있는 미디어의 최대 크기가 달라요. 제한을 미리 확인하면 낭비되는 데이터 전송을 막고 오류도 더 빨리 알 수 있어요.

- WhatsApp: 최대 100MB
- 그 밖의 모든 채널: 최대 5MB

크기를 사전에 검증하기 때문에, 제한을 넘는 파일은 업로드를 시작하기 전에 거부돼요. 시간과 데이터를 아낄 수 있어요.

## 콘텐츠 타입 검증

정확한 MIME 타입은 업로드를 안전하게 유지하고 호환성을 지키는 데 도움이 돼요. 두 단계로 검증해서, 이후 전달 과정에서 문제를 일으킬 수 있는 위조되거나 맞지 않는 파일을 막아요.

- 시작 단계: 선언한 `contentType`이 파일 확장자와 일치하는지 확인해요.
- 완료 단계: GCS에 저장된 `contentType`이 파일 이름과 일치하는지 확인해요.
- 결과: 콘텐츠 타입 위조와 파일 형식 불일치를 막아요.

## 보안 장치와 접근 제어

저장소 영역을 보호하고, 권한이 있는 사용자만 올바른 대화와 위치에 파일을 업로드하도록 해요.

- 대화가 존재하고 지정한 위치(location)에 속하는지 확인해요.
- 사용자가 해당 위치에 접근할 수 있는지 확인해요.
- 파일 경로가 위치와 대화에 맞는 형식인지 확인해요.
- 서명된 URL은 유효 시간(15분)이 정해져 있어서 오용 가능성을 줄여요.

## 오류 처리와 만료

단계마다 오류가 어떻게 나타나는지 알아 두면, 검증 실패나 URL 만료에서 잘 복구하는 클라이언트를 만들 수 있어요.

- URL 만료: 시작 단계를 다시 실행해서 새 서명된 URL을 요청하세요.
- 파일 크기 초과: 파일을 조정하거나, 제한이 더 큰 채널로 바꾸세요(예: WhatsApp은 최대 100MB).
- 콘텐츠 타입 불일치: 파일 이름의 확장자와 `Content-Type`이 파일을 정확히 나타내는지 확인하세요.
- 권한 또는 경로 오류: 위치 접근 권한과 대화 식별자를 확인하세요.

## 구현 팁

연동할 때 겪는 불편을 줄이고, 큰 파일 업로드의 성공률을 높이는 방법이에요.

- 15분의 유효 시간을 최대한 활용하려면 실제 업로드 시점에 가깝게 시작 단계를 호출하세요.
- `PUT` 요청에는 항상 파일에 맞는 `Content-Type` 헤더를 명시하세요.
- 문제가 생겼을 때 추적할 수 있도록 시작 단계에서 받은 오브젝트 경로를 기록해 두세요.
- WhatsApp 동영상 같은 큰 파일은 불필요한 재시도를 피하세요. 만료가 가까워졌는데 업로드가 멈췄다면 시작 단계부터 다시 하세요.
- 사용자에게 오류를 더 빨리 보여 주려면 시작 단계 전에 클라이언트에서 크기와 MIME 타입을 먼저 검증하세요.

## 자주 묻는 질문

### 완료(Complete) 호출은 꼭 해야 하나요?
네. 완료 단계에서 저장소의 오브젝트를 확인하고, 메시지에 쓸 최종 URL을 반환해요.

### 업로드 중에 서명된 URL이 만료되면 어떻게 되나요?
처음부터 다시 진행하세요. 시작 단계를 다시 실행해 새 서명된 URL을 받은 다음, 업로드하고 완료하세요.

### 완료 후에 오브젝트가 공개되나요?
완료 단계에서 메시지에 사용할 공개 URL이 반환돼요. 공유할 때는 조직의 데이터 취급 정책을 따르세요.

### 크기만 맞으면 어떤 파일 형식이든 업로드할 수 있나요?
아니요. 콘텐츠 타입 검증에서 일치하지 않는 파일은 차단돼요. 파일 확장자와 `Content-Type`이 올바른지 확인하세요.

### WhatsApp 외의 다른 채널도 100MB를 지원하나요?
아니요. 다른 채널은 최대 5MB까지만 지원해요.

### 이 방식은 안정성을 어떻게 높이나요?
파일이 GCS로 바로 전송되고 애플리케이션 서버는 파일 내용을 버퍼링하지 않아서, OOM 위험이 없어요.

### 서명된 URL의 유효 시간은 얼마인가요?
서명된 URL은 15분 뒤에 만료돼요.

### 같은 서명된 URL로 여러 파일을 올릴 수 있나요?
아니요. 시작 단계를 호출할 때마다 특정 파일과 경로, 시간 범위에 맞는 URL이 발급돼요.
