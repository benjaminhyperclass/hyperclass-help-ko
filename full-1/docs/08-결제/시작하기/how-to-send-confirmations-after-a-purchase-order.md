# 구매·주문 확인 메시지 보내기

하이퍼클래스에서는 결제가 일어나는 위치와 필요한 맞춤 정도에 따라 구매 확인 방법을 고를 수 있어요. 지원되는 결제 성공 건에는 기본 제공 판매 영수증을 보낼 수 있어요. 이커머스 스토어 구매에는 스토어 주문 확인 이메일을 쓰고, 구매 후 안내를 직접 꾸미고 싶다면 **Order Submitted**(주문 제출) 워크플로우 트리거를 쓰세요.

상황에 맞는 방법을 고르면 고객은 필요한 거래 정보를 받고, 불필요하거나 중복된 확인 메시지는 피할 수 있어요.

## 구매·주문 확인을 보내면 좋은 점

구매 확인을 보내면 고객은 거래가 끝났다는 것을 바로 알 수 있어요. 사업자는 주문 이후의 다음 단계를 자동화할 수 있어요. 하이퍼클래스의 확인 방법 중에서 표준 거래 내역 안내와 맞춤 구매 후 안내 중 원하는 쪽을 고르세요.

- **즉시 확인:** 지원되는 구매나 주문이 정상적으로 접수되었음을 고객에게 알려요.
- **거래 내용 확인:** 해당되는 주문, 결제, 구매 상품 정보를 보여 줘요.
- **맞춤 후속 안내:** 상품별 이용 안내, 온보딩 정보 등 구매 후 콘텐츠를 보내요.
- **구매 후 자동화:** 주문 이후 내부 작업, 고객 후속 연락, 외부 연동을 실행해요.
- **유연한 확인 방법:** 구매 경로에 따라 기본 영수증, 스토어 확인 이메일, 워크플로우 이메일 중에서 고를 수 있어요.

## 알맞은 확인 방법 고르기

어떤 방법이 알맞은지는 구매가 일어나는 위치와, 표준 거래 영수증이 필요한지 맞춤형 구매 후 안내가 필요한지에 따라 달라요.

| 방법 | 이럴 때 좋아요 | 주요 동작 |
| --- | --- | --- |
| 자동 판매 영수증 | 지원되는 주문 폼, 구독, 캘린더 예약, 인보이스 결제 | 지원되는 결제가 성공하면 표준 거래 내역을 자동으로 보내요 |
| 스토어 주문 확인 이메일 | 이커머스 스토어 주문 | 스토어 전용 확인 메일을 보내고, 해당되는 주문 확인·디지털 상품 제공 경험을 지원해요 |
| Order Submitted 워크플로우 | 맞춤형 구매 후 안내 | 맞춤 이메일, 주문 데이터, 조건 분기, 온보딩, 내부 작업, 외부 자동화를 지원해요 |

{% hint style="info" %}
의도적으로 방법을 여러 개 함께 쓸 수도 있어요. 예를 들어 결제 증빙은 판매 영수증으로, 온보딩 안내는 워크플로우 이메일로 보내는 식이에요. 활성화된 알림을 모두 확인해서 고객에게 불필요한 중복 메시지가 가지 않게 하세요.
{% endhint %}

## 자동 판매 영수증 보내기

자동 판매 영수증(Sales Receipt)을 쓰면 워크플로우를 만들지 않고도 결제 증빙을 보낼 수 있어요. 결제가 성공한 뒤 해당 거래 정보가 담긴 표준 영수증이 필요할 때 알맞아요.

하이퍼클래스는 다음 결제에 대해 자동 판매 영수증을 지원해요.

- 1단계·2단계 주문 폼 구매
- 번들(bump) 구매와 업셀
- 구독
- 캘린더 예약 결제
- 인보이스 결제

기능을 켜 두면 지원되는 결제가 성공한 뒤 영수증이 자동으로 발송돼요. 영수증은 PDF로 첨부되어 연락처의 이메일로 전달될 수 있어요.

판매 영수증 설정에서는 영수증 정보와 이메일 모양도 해당 범위 안에서 맞춤 설정할 수 있어요.

{% hint style="warning" %}
자동 판매 영수증은 지원되는 결제 유형 전체에 공통으로 적용돼요. 특정 상품, 주문 경로, 구매 조건마다 다른 구매 후 안내가 필요하면 Order Submitted 워크플로우를 사용하세요.
{% endhint %}

자세한 설정 방법은 [주문 폼, 캘린더, 인보이스 결제의 판매 영수증 관리하기](../how-to-manage-sales-receipts-for-order-form-calendar-and-invoice-payments.md)를 참고하세요.

## 스토어 주문 확인 이메일 보내기

이커머스 스토어 주문에는 일반 판매 영수증 설정만 쓰지 않고, 전용 주문 확인 이메일이 따로 있어요. 이 이메일로 고객에게 스토어 전용 주문 정보와 구매 후 이용 경험을 안내할 수 있어요.

설정을 확인하려면 다음과 같이 하세요.

1. **결제 > 설정**으로 이동하세요.
2. **알림**을 여세요.
3. **Order Confirmation Email for Stores**(스토어 주문 확인 이메일) 설정을 찾으세요.

   ![결제 설정의 알림 화면에서 스토어 주문 확인 이메일 설정 위치](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155081291225/original/-5IMIzezaYPZNunSAmA8ASTnZfyBnDGR1w.png?1789733656)
4. 필요한 스토어 주문 확인 방식을 설정하세요.

스토어 설정에 따라 확인 이메일에 **주문 보기** 옵션이 들어갈 수 있어요. 고객은 이 옵션으로 자신의 주문 정보를 볼 수 있어요.

디지털 상품을 판매하는 스토어에서 디지털 상품 제공이 설정되어 있으면, 스토어 주문 확인을 통해 구매한 다운로드 상품에 접근하게 할 수도 있어요.

{% hint style="warning" %}
다운로드 상품을 판매한다면 일반 워크플로우 확인 메일만을 유일한 전달 수단으로 삼지 마세요. 해당 스토어의 디지털 상품 제공 설정을 함께 구성하세요. 자세한 내용은 [이커머스 스토어의 디지털 상품 제공하기](../../37-이커머스-스토어/how-to-deliver-digital-products-for-e-commerce-stores.md)를 참고하세요.
{% endhint %}

## Order Submitted 트리거로 맞춤 확인 메시지 보내기

**Order Submitted** 워크플로우 트리거를 쓰면 주문 이후에 일어나는 일을 더 세밀하게 정할 수 있어요. 확인 메시지를 직접 꾸미거나, 상품별 안내, 온보딩, 조건에 따른 후속 연락, 내부 작업, 외부 자동화가 필요할 때 사용하세요. 트리거에 대한 자세한 설명은 [워크플로우 트리거 — Order Submitted](../../07-워크플로우/빌더/workflow-trigger-order-submitted.md)에서 볼 수 있어요.

### 1. 워크플로우 만들기

1. **자동화 > 워크플로우**로 이동하세요.
2. 새 워크플로우를 만들거나, 사용할 워크플로우를 여세요.
3. 워크플로우 트리거로 **Order Submitted**(주문 제출)를 추가하세요.

{% hint style="warning" %}
**Order Submitted**와 **Order Form Submitted**(주문 폼 제출)는 서로 다른 트리거예요. Order Submitted는 주문·구매 이벤트와 연결되어 있어요. Order Form Submitted는 폼 제출을 기준으로 하기 때문에, 구매가 완료되었다고 볼 수는 없어요. 차이는 [Order Submitted와 Order Form Submitted의 차이](../../07-워크플로우/Opportunity-Workflow-Triggers/workflow-trigger-order-submitted-vs-order-form-submission.md)에서 확인하세요.
{% endhint %}

### 2. 주문 필터 추가하기

필터를 쓰면 어떤 구매가 워크플로우에 들어올지 정할 수 있어요. 상품이나 구매 경로에 따라 다른 확인 메시지가 필요할 때 유용해요.

주문 상황에 따라 다음과 같은 필터를 쓸 수 있어요.

- **Product**(상품)
- **Order Source**(주문 출처)
- **Sub-Source**(하위 출처)
- **Funnel or Website**(퍼널 또는 웹사이트)
- **Page**(페이지)
- **Submission Type**(제출 유형)
- **Product Price**(상품 가격)

예를 들어 특정 상품을 구매한 뒤에만 온보딩 안내를 보내려면, 트리거에 그 상품 필터를 걸어 주세요.

### 3. Allow Multiple 확인하기

고객 한 명이 조건에 맞는 주문 이벤트를 여러 번 만들 수 있어요. 특히 결제 과정에 번들 구매나 업셀이 있을 때 그래요. 같은 연락처가 워크플로우에 다시 들어올 수 있는지는 워크플로우 등록 설정에서 정해요.

같은 고객의 이후 구매에도 확인 워크플로우가 실행되게 하려면, 워크플로우 설정에서 **Allow Multiple**(여러 번 허용)을 확인하고 의도한 결제 방식에 맞게 설정하세요.

### 4. 확인 이메일 추가하기

트리거 뒤에 **Send Email**(이메일 보내기) 액션을 추가하고, 고객이 받을 확인 메시지를 만드세요.

맞춤 확인 메시지에는 다음과 같은 내용을 넣을 수 있어요.

- 감사 인사
- 주문 정보
- 고객 정보
- 상품별 이용 안내
- 예약 또는 온보딩 단계
- 지원 정보
- 이어서 할 일

### 5. 커스텀 값으로 주문 상세 정보 넣기

Order Submitted를 워크플로우 트리거로 쓰면, 주문과 관련된 커스텀 값을 이후 워크플로우 액션에서 쓸 수 있어요.

주문 데이터에 따라 다음과 같은 정보를 쓸 수 있어요.

- 주문 ID
- 주문 총액
- 장바구니 총액
- 통화
- 쿠폰 또는 할인 정보
- 주문 일시
- 결제 게이트웨이
- 고객 이름
- 고객 이메일
- 고객 전화

고객에게 도움이 되는 정보만 골라서 쓰세요.

### 6. 장바구니 요소로 구매 상품 보여 주기

이메일에 주문에 포함된 상품을 자동으로 보여 주려면, Order Submitted 워크플로우에서 쓰는 이메일 템플릿에 **Shopping Cart**(장바구니) 요소를 넣으세요.

Shopping Cart 요소는 다음과 같은 정보를 채워 줘요.

- 구매한 상품 항목
- 상품 이미지
- 수량
- 항목별 가격

일반적인 설정 순서는 다음과 같아요.

1. 이메일 템플릿을 만들거나 편집하세요.
2. **Shopping Cart** 요소를 추가하세요.
3. 템플릿을 저장하세요.
4. 워크플로우의 **Send Email** 액션에서 그 템플릿을 사용하세요.
5. 실제 구매와 비슷한 조건으로 워크플로우를 테스트하세요.

## 구매 후 자동화 추가하기

Order Submitted로는 고객에게 확인 이메일을 보내는 것 외에도 할 수 있는 일이 많아요. 워크플로우 액션을 더하면 주문을 받은 뒤 처리해야 하는 업무 단계를 자동화할 수 있어요.

업무 방식에 따라 다음과 같은 액션을 추가할 수 있어요.

- 내부 알림 보내기
- CRM 정보 업데이트
- 태그나 기타 분류 적용
- 온보딩 시작
- 담당 매니저나 배송·처리 팀에 알림
- 웹훅으로 외부 시스템에 주문 정보 전송
- 그 밖에 알맞은 구매 후 액션 실행

예를 들면 이런 흐름이에요.

Order Submitted → 고객 확인 → 내부 알림 → 온보딩 액션

주문 유형에 실제로 필요한 액션만 넣어 워크플로우를 간결하게 유지하세요. 상품마다 처리나 온보딩 경로가 다르면 트리거 필터를 사용하세요.

## 중복 확인 메시지 피하기

하이퍼클래스에서는 여러 곳에서 구매 관련 메시지를 보낼 수 있어요. 설정을 한꺼번에 확인해 두면 고객이 거의 같은 내용의 메시지를 여러 번 받는 일을 막을 수 있어요.

확인 워크플로우를 새로 켜기 전에, 그 구매에서 이미 다음 메시지가 발송되는지 확인하세요.

- 자동 판매 영수증
- 스토어 주문 확인 이메일
- 인보이스 결제 알림 ([인보이스 이메일·SMS 알림 맞춤 설정하기](../customize-email-and-sms-notifications-for-invoicing.md) 참고)
- 캘린더 관련 알림
- 다른 워크플로우의 이메일 또는 SMS

영수증과 맞춤 확인 메시지를 둘 다 받는 것이 의도한 구성일 수도 있어요. 예를 들면 이래요.

판매 영수증: 결제 증빙을 제공해요.

워크플로우 확인: 온보딩 안내와 다음 단계를 제공해요.

목표는 메시지를 꼭 하나만 보내는 것이 아니라, 메시지마다 서로 다른 목적을 갖게 하는 거예요.

## 구매 확인 테스트하기

전체 구매 과정을 테스트하면 트리거, 주문 데이터, 이메일 내용, 후속 액션이 함께 잘 동작하는지 확인할 수 있어요. 실제 고객이 이용할 구매 경로와 같은 조건으로 테스트하세요.

게시하거나 자동화를 실제로 운영하기 전에 다음을 확인하세요.

1. 실제 구매와 비슷한 테스트 구매를 완료하세요.
2. 올바른 워크플로우가 실행되는지 확인하세요.
3. 상품·주문 필터가 맞게 적용되는지 확인하세요.
4. 고객이 의도한 메시지를 받는지 확인하세요.
5. 고객 정보와 주문 커스텀 값을 확인하세요.
6. Shopping Cart 요소를 썼다면 구매한 상품이 제대로 표시되는지 확인하세요.
7. 추가한 워크플로우 액션이 예상대로 실행되는지 확인하세요.
8. 다른 영수증이나 알림이 함께 발송되었는지 확인하세요.
9. 겹치는 메시지가 있으면 필요에 따라 조정하세요.

## 자주 묻는 질문

### 자동 판매 영수증과 Order Submitted 워크플로우 중 어느 것을 써야 하나요?

지원되는 결제가 성공한 뒤 표준 결제 증빙이 필요하면 자동 판매 영수증을 쓰세요. 맞춤 구매 후 안내, 조건 분기, 온보딩, 내부 작업, 외부 자동화가 필요하면 Order Submitted를 쓰세요. 메시지마다 목적이 다르다면 둘을 함께 써도 돼요.

### Order Submitted와 Order Form Submitted는 같은 건가요?

아니요. Order Submitted는 주문·구매 이벤트와 연결되어 있어요. Order Form Submitted는 폼 제출과 연결되어 있고, 구매가 완료되었다는 뜻은 아니에요. 자세한 내용은 [Order Submitted와 Order Form Submitted의 차이](../../07-워크플로우/Opportunity-Workflow-Triggers/workflow-trigger-order-submitted-vs-order-form-submission.md)를 참고하세요.

### 맞춤 확인 이메일에 고객이 구매한 상품을 넣을 수 있나요?

네. 지원되는 Order Submitted 워크플로우에서는 이메일 템플릿에 Shopping Cart 요소를 넣어서, 구매한 상품 항목과 관련 정보를 자동으로 보여 줄 수 있어요.

### 고객이 구매 확인 메시지를 두 번 이상 받았어요. 왜 그런가요?

자동 판매 영수증, 스토어 확인 이메일, 인보이스·캘린더 알림, 워크플로우 설정을 확인해 보세요. 같은 고객 흐름에서 이 중 여러 개가 켜져 있을 수 있어요. 메시지마다 목적이 다를 때만 여러 개를 유지하세요.

### 나중에 주문이 환불되면 어떻게 되나요?

원래 구매 확인 메시지는 이미 발송된 상태예요. 환불은 별도의 단계로 처리돼요. 환불 안내를 보내거나 환불 후 추가 작업을 하려면 하이퍼클래스의 전용 **Refund**(환불) 워크플로우 트리거를 사용하세요. 자세한 내용은 [하이퍼클래스의 Refund 워크플로우 트리거](../../07-워크플로우/Payments-Workflow-Triggers/refund-workflow-trigger-in-hyperclass.md)를 참고하세요.

### Order Submitted 워크플로우가 디지털 상품을 자동으로 전달해 주나요?

그것만으로는 전달되지 않아요. 이커머스 스토어에서 디지털 상품을 판매한다면, 고객이 구매한 상품에 접근할 수 있도록 해당 스토어 주문 확인 이메일과 디지털 상품 제공 설정을 구성하세요. 자세한 내용은 [이커머스 스토어의 디지털 상품 제공하기](../../37-이커머스-스토어/how-to-deliver-digital-products-for-e-commerce-stores.md)를 참고하세요.
