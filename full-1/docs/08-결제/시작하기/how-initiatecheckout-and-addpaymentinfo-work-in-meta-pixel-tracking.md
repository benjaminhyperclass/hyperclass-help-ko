# Meta Pixel 추적에서 InitiateCheckout과 AddPaymentInfo 이벤트가 작동하는 방식

Meta Pixel은 하이퍼클래스의 퍼널, 웹사이트, 스토어에서 일어나는 결제 활동을 추적해요. InitiateCheckout은 구매자가 결제를 시작한 시점을, AddPaymentInfo는 구매자가 결제 단계로 넘어간 시점을 알려 줘요. 이 이벤트로 결제 이탈 현황을 파악할 수 있고, Meta가 캠페인을 최적화하는 데 필요한 정보도 전달돼요.

---

## InitiateCheckout 추적이 작동하는 방식

InitiateCheckout은 구매자가 결제 과정을 시작할 때 발생해요. 발생 시점은 이벤트를 설정한 위치와 구매자가 이용하는 결제 화면에 따라 달라져요.

| 결제 화면 | InitiateCheckout이 발생하는 시점 |
| --- | --- |
| 스토어 결제 페이지 | 결제 페이지가 로드될 때 |
| 페이지 단위 이벤트 설정 | 설정한 페이지가 로드될 때 |
| 퍼널 단위 추적 | 구매자가 주문 폼을 처음 조작할 때 |
| 웹사이트 단위 추적 | 구매자가 주문 폼을 처음 조작할 때 |
| 웨비나 단위 추적 | 구매자가 주문 폼을 처음 조작할 때 |
| 원스텝, 투스텝, 팝업, 새 주문 폼 | 구매자가 처음 클릭, 탭, 키 입력을 할 때 (페이지 단위 추적이 적용되는 경우는 제외) |

InitiateCheckout을 페이지 단위로 설정하면, 주문 폼을 조작하지 않아도 페이지가 로드되는 즉시 이벤트가 발생해요.

### 중복 이벤트를 막는 방법

InitiateCheckout은 페이지를 한 번 방문할 때 최대 한 번만 발생해요. 한 페이지에 주문 폼이 여러 개 있거나 설정된 트리거가 둘 이상이어도 마찬가지예요. 아래 동작은 InitiateCheckout을 발생시키지 않아요.

- 브라우저 자동 완성
- 비밀번호 관리자 자동 완성
- 페이지가 로드될 때 필드에 자동으로 포커스가 가는 경우

### 미완료 장바구니 복구

구매자가 미완료 장바구니 복구 링크로 돌아오면, InitiateCheckout은 저장된 장바구니가 로드될 때까지 기다려요. 그래서 복원된 장바구니의 금액과 상품 정보가 이벤트에 포함돼요.

### 익스프레스 월렛 결제

InitiateCheckout은 Apple Pay 같은 익스프레스 결제 수단을 쓰는 구매자도 추적해요. 이런 구매자는 주문 폼을 조작하지 않기 때문에, 결제가 시작되는 시점에 이벤트가 발생해요.

---

## AddPaymentInfo는 어떤 정보를 보내나요?

AddPaymentInfo는 확인할 수 있는 주문 정보와 고객 정보를 Meta로 보내요.

| 데이터 | 전송되는 정보 |
| --- | --- |
| 주문 금액 | 주문에 해당하는 금액 |
| 통화 | 주문 통화 |
| 상품 ID | 주문에 포함된 상품 식별자 |
| 이메일 | 해시 처리된 고객 이메일 |
| 전화번호 | 해시 처리된 고객 전화번호 |
| 이름 | 해시 처리된 고객 이름 |
| 외부 ID | 해시 처리된 고객 외부 ID |

이 추가 정보는 Meta가 전환 이벤트와 고객을 연결하고 이벤트 기여도를 더 정확하게 파악하는 데 도움이 돼요. 올바르지 않거나 비어 있는 값은 전송되지 않아요. 같은 주문에 속한 이벤트는 같은 통화를 사용해요.

### 무료 주문과 기프트 카드 주문의 AddPaymentInfo

결제 정보가 필요 없는 주문에서는 AddPaymentInfo가 전송되지 않아요. 다만 기프트 카드로 전액 결제된 주문은 이제 주문 금액 `0`으로 AddPaymentInfo를 전송해요.

## 이번 변경이 결제 리포트에 미치는 영향

InitiateCheckout은 이제 결제 과정의 더 이른 시점에 구매자를 포착하기 때문에 이벤트 수가 더 많이 집계될 수 있어요. 이전에는 InitiateCheckout과 AddPaymentInfo가 같은 구매자를 집계하는 경우가 많았어요. 이제는 결제를 시작한 구매자와 결제 단계로 넘어간 구매자를 구분해서 볼 수 있어요.

캠페인 성과를 비교하기 전에 아래 항목이 이번 변경의 영향을 받는지 확인하세요.

- 업데이트 전후의 InitiateCheckout 집계 수
- 결제 이탈률
- InitiateCheckout당 비용
- InitiateCheckout을 기준으로 한 자동화 규칙

InitiateCheckout 이벤트가 늘었다고 해서 구매 완료가 늘었다는 뜻은 아니에요.

---

## Meta Pixel 설정을 바꿔야 하나요?

설정을 바꿀 필요는 없어요. 업데이트된 추적 방식은 InitiateCheckout을 켜 둔 퍼널, 웹사이트, 스토어에 자동으로 적용돼요. InitiateCheckout을 켜지 않았다면 이번 변경은 픽셀의 기존 동작에 영향을 주지 않아요.

### 페이지 단위 변경은 언제 적용되나요?

이미 게시된 페이지에서는 페이지 단위 InitiateCheckout 설정을 바꿔도 적용되기까지 최대 24시간이 걸릴 수 있어요. 바로 적용하려면 페이지를 편집한 뒤 저장하세요.

---

## 쿠키 동의와 Conversions API

이번 업데이트는 기존 쿠키 동의 방식을 바꾸지 않아요. 방문자가 광고 쿠키를 허용하지 않았다면 추적 이벤트는 Meta로 전송되지 않아요.

Conversions API를 켜 두었다면 브라우저 이벤트와 서버 이벤트는 계속 전송되고, Meta 이벤트 관리자에서 중복이 제거돼요. PageView, ViewContent, Purchase 이벤트의 발생 시점은 그대로예요.

## 자주 묻는 질문

### InitiateCheckout 집계 수가 왜 늘었나요?

InitiateCheckout은 이제 구매자가 결제 단계로 넘어갈 때까지 기다리지 않고 결제를 시작하는 시점에 추적해요. 결제를 중간에 그만둔 구매자까지 포함되기 때문에 더 많은 구매자가 집계돼요.

### 같은 페이지에서 InitiateCheckout이 여러 번 발생할 수 있나요?

아니요. 주문 폼이나 트리거가 여러 개 있어도 InitiateCheckout은 페이지를 한 번 방문할 때 최대 한 번만 발생해요.

### 브라우저 자동 완성도 InitiateCheckout을 발생시키나요?

아니요. 브라우저 자동 완성, 비밀번호 관리자, 자동으로 포커스가 가는 필드는 이벤트를 발생시키지 않아요.

### Apple Pay에서도 InitiateCheckout이 작동하나요?

네. 구매자가 주문 폼을 조작하지 않고 익스프레스 결제 수단을 쓰면, 결제가 시작될 때 InitiateCheckout이 발생해요.

### 이번 업데이트로 Purchase 추적이 바뀌나요?

아니요. Purchase는 이전과 같은 시점에 계속 발생해요.

### Meta Pixel을 다시 연결해야 하나요?

아니요. 업데이트는 기존 설정 중 적용 대상에 자동으로 반영돼요.
