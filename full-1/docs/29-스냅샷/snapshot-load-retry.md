# 스냅샷 로드 재시도

스냅샷을 푸시했는데 일부 서브 계정에서 실패했을 때, 실패한 서브 계정만 골라 다시 시도하는 기능이에요. 전체 푸시를 새로 만들 필요 없이 **Load History**(로드 기록)에서 바로 재시도하고, 진행 상황을 실시간으로 확인할 수 있어요. 시간 초과나 계정별 권한 문제처럼 일시적인 오류를 해결할 때 특히 유용해요.

## 스냅샷 로드 재시도란?

스냅샷 로드 재시도는 같은 스냅샷 로드에서 실패한 서브 계정만 다시 가져오는 복구 기능이에요. 재시도가 원래 로드에 묶여 있어서 문제를 찾고, 무슨 일이 있었는지 확인하고, 새 푸시를 만들지 않고도 배포를 마무리하기 쉬워요.

## 스냅샷 로드 재시도의 장점

실패한 스냅샷 로드를 빨리 복구하면 온보딩이 늦어지지 않고, 일부만 실패했을 때 반복 작업도 줄어요.

- 시간 절약: 스냅샷 푸시를 처음부터 다시 만들지 않고 실패한 서브 계정만 재시도해요.
- 수작업 감소: 처음부터 다시 시작하지 않고 몇 번의 클릭으로 실패 건을 다시 실행해요.
- 체계적인 관리: 재시도가 원래 로드 아래에 모여 있어서 점검과 문제 해결이 쉬워요.
- 빠른 복구: 시간 초과, 간헐적 오류, 접근 문제 같은 일시적인 문제를 해결하고 푸시를 더 빨리 끝낼 수 있어요.

## 스냅샷 로드 재시도 위치

로드가 실패했을 때 바로 대응할 수 있도록, 특히 대규모 배포 때 위치를 알아 두면 편해요. 에이전시 뷰에서 쓰는 기능이에요.

1. 에이전시 뷰에서 **스냅샷**으로 이동하세요.
2. **Load History**(로드 기록)를 여세요.

   ![로드 기록 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155065397230/original/4p9YrL90zbh_2DGzlRPz-CALq5Eaaep-1g.png?1771630804)
3. 실패한 서브 계정이 하나 이상 있는 로드를 선택하세요.

   ![실패한 서브 계정이 있는 로드 선택](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155065397240/original/vH--bHcf-QNFBFkYZEcg0QFbXKSzASYOVQ.png?1771630840)
4. 로드 상세 화면을 열어 재시도 옵션을 확인하세요. 실패한 서브 계정을 모두 재시도하거나 선택한 서브 계정만 재시도할 수 있어요.

   ![로드 상세 화면의 재시도 옵션](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155065397252/original/cRtj1yjuLf7gsBu6N2RbVirBSTNuM7D1NQ.png?1771630857)

## 실패한 서브 계정 모두 재시도하기

같은 배치에서 여러 서브 계정이 다시 시도가 필요할 때 가장 빠른 방법이에요. 실패한 서브 계정만 다시 실행하고, 성공한 서브 계정은 그대로 둬요.

1. **스냅샷 > Load History**(로드 기록)를 여세요.
2. 실패한 서브 계정이 있는 로드를 클릭하세요.
3. **Retry All Failed**(실패 항목 모두 재시도)를 클릭하세요.
4. 하이퍼클래스가 배치에서 실패한 항목만 다시 시도하는 동안 상태가 바뀌는 것을 확인하세요.

## 특정 서브 계정만 재시도하기

몇 개의 서브 계정만 실패했을 때, 해당 계정만 골라 재시도하는 방법이에요. 권한 문제처럼 원인을 먼저 고친 뒤 특정 계정만 다시 로드할 때 좋아요.

1. **스냅샷 > Load History**를 열고 해당 로드를 선택하세요.
2. 배치 상세 정보를 펼쳐 서브 계정 목록을 확인하세요.
3. 재시도할 실패 서브 계정마다 옆의 체크박스를 선택하세요.
4. **Retry Selected**(선택 항목 재시도)를 클릭하세요.

## 재시도 진행 상황 확인하기

페이지를 옮기거나 푸시를 새로 만들지 않고도, 어떤 서브 계정이 복구됐고 어떤 계정이 아직 확인이 필요한지 알 수 있어요.

- 재시도가 진행되는 동안 상태 표시가 바뀌어요(예: **진행 중**, **성공**, **실패**).
- 진행 상황이 같은 로드 상세 화면에 표시되므로 작업을 다시 시작할 필요가 없어요.
- 재시도 기록은 원래 로드에 연결된 채로 남아서 나중에 검토하고 문제를 해결하기 쉬워요.

## 재시도할 수 없는 경우

재시도가 안정적으로 동작하고, 오래된 스냅샷 내용이 서브 계정에 다시 로드되지 않도록 아래 제한이 있어요. 다음 경우에는 스냅샷 로드 재시도를 쓸 수 없어요.

- 48시간 제한: 48시간이 지난 로드는 재시도할 수 없어요. 새 로드를 만드세요.
- 스냅샷을 새로 고치거나 수정한 경우: 원래 로드 이후에 스냅샷을 새로 고쳤거나 업데이트했다면 새 로드를 시작하세요. 그래야 가장 최신 스냅샷 버전이 적용돼요.

## 자주 묻는 질문

### 스냅샷을 수정한 내용도 재시도할 때 적용되나요?
아니요. 원래 로드 이후에 스냅샷을 새로 고쳤거나 업데이트했다면 새 로드를 시작하세요. 그래야 최신 스냅샷 버전이 사용돼요.

### 48시간이 지난 스냅샷 로드도 재시도할 수 있나요?
아니요. 재시도는 원래 로드 후 48시간 이내에만 쓸 수 있어요. 그 이후에는 새 로드를 만드세요.

### 재시도하면 처음에 성공한 서브 계정도 덮어쓰나요?
아니요. 재시도는 실패한 서브 계정에만 실행돼요. 성공한 서브 계정은 다시 시도하지 않아요.

### 스냅샷 로드 재시도는 누가 실행할 수 있나요?
에이전시 뷰에서 스냅샷을 푸시하거나 로드할 수 있는 접근 권한이 있는 사용자라면 **Load History**에서 재시도를 실행할 수 있어요.
