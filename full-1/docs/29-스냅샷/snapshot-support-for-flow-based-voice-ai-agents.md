# 플로 기반 음성 AI 에이전트 스냅샷 지원

**플로 빌더**로 만든 플로 기반 음성 AI 에이전트를 스냅샷에 담아 다른 서브 계정으로 복사하는 방법을 안내해요. 노드, 분기, 연결된 액션까지 한 번에 옮길 수 있어서 통화 플로를 처음부터 다시 만들 필요가 없어요.

이 문서에서는 스냅샷이 어디까지 옮겨 주는지, 에이전트를 스냅샷에 담는 방법, 여러 계정에 안정적으로 배포하는 방법을 설명해요.

## 플로 기반 음성 AI 에이전트를 스냅샷으로 옮기면 좋은 점

플로 기반 음성 AI 에이전트를 스냅샷에 담으면, 검증된 통화 플로를 여러 계정에 같은 방식으로 배포할 수 있어요. 내부 로직도 그대로 유지돼요. 고객 온보딩과 음성 경험을 표준화하면서, 필요한 부분은 계정별로 따로 조정할 수 있어요.

- 빠른 고객 온보딩 — 새 서브 계정을 만들 때 플로를 처음부터 다시 만들지 않아도 돼요. 클릭 몇 번이면 바로 쓸 수 있는 음성 에이전트가 준비돼요.
- 지점 간 일관된 음성 경험 — 프랜차이즈, 지점, 브랜드마다 같은 플로 설계와 로직을 재사용해요. 어느 곳으로 전화하든 발신자가 비슷한 수준의 응대를 받아요.
- 대규모 배포 — 플로 기반 음성 AI 에이전트도 다른 스냅샷 자산처럼 다뤄요. 기존 스냅샷 방식 그대로 수십, 수백 개 계정에 배포할 수 있어요.
- 로직과 액션 유지 — 노드, 분기, 버전, 연결된 액션(워크플로우, 트리거 등)이 함께 넘어가요. 그래서 새 계정에서도 같은 방식으로 동작해요.
- 간편한 관리와 업데이트 — 공유, 불러오기, 새로 고침 같은 익숙한 스냅샷 기능으로 플로 기반 음성 AI 템플릿을 계속 관리하고 개선할 수 있어요.

## 요구 사항과 제한 사항

스냅샷으로 무엇이 옮겨지고 무엇이 옮겨지지 않는지 미리 알아 두면, 불러온 뒤에 당황하지 않고 배포를 계획할 수 있어요. 스냅샷은 설정만 옮겨요. 실제 전화 회선이나 과거 데이터는 옮기지 않아요.

### 요구 사항

1. 두 계정 모두 음성 AI 사용 가능
   - 원본 서브 계정과 대상 서브 계정 모두 음성 AI가 활성화되어 있어야 불러온 에이전트가 정상적으로 동작해요.
2. 대상 계정의 하이퍼클래스 전화 또는 Twilio 번호
   - 스냅샷은 번호 자체를 복사하지 않아요. 그래도 음성 AI 에이전트가 전화를 받으려면 대상 계정에 사용할 수 있는 전화번호가 있어야 해요.
3. 연결된 자산 준비
   - 플로에서 참조하는 워크플로우, 트리거 등 연결된 자산은 같은 스냅샷에 포함하거나 대상 계정에 이미 있어야 해요. 그래야 플로가 제대로 연결돼요.

### 제한 사항

1. 전화번호는 옮겨지지 않아요
   - 음성 AI 에이전트에 지정한 전화번호는 스냅샷으로 복사되지 않아요. 대상 계정에서 다시 지정해야 해요.
2. 실시간 데이터는 복사되지 않아요
   - 연락처, 통화 기록, 통화 스크립트 같은 실제 활동 데이터는 원본 계정에 남고 스냅샷과 함께 옮겨지지 않아요.
3. 불러온 뒤에 조정이 필요할 수 있어요
   - 에이전트를 지역에 맞게 쓰려면 현지 전화번호, 영업시간, 지점별 메시지 같은 세부 내용을 불러온 뒤 수정해야 할 수 있어요.
4. 자산 보호가 그대로 적용돼요
   - **Assets Protected Snapshots**(자산 보호 스냅샷)로 스냅샷을 보호했다면, 받는 쪽은 불러온 플로 기반 음성 AI를 사용할 수 있어요. 다만 보호 설정에 따라 일부 자산은 편집하거나 내보낼 수 없을 수 있어요.

## 스냅샷의 음성 AI 자산

스냅샷의 **음성 AI** 자산 카테고리는 프롬프트 기반 에이전트와 플로 빌더 기반 에이전트를 모두 지원해요. 재사용하려는 음성 설정을 한곳에서 관리할 수 있어요.

스냅샷을 만들거나 불러올 때 플로 기반 음성 AI 에이전트는 다른 음성 AI 자산과 함께 표시돼요. 단순한 프롬프트 기반 에이전트든, 복잡한 플로 기반 에이전트든, 둘 다 섞여 있든 새 서브 계정이나 기존 서브 계정으로 옮길 에이전트를 골라서 선택할 수 있어요.

플로 기반 음성 AI 에이전트가 표시되는 위치는 다음과 같아요.

- 스냅샷을 만들 때(원본 계정): **음성 AI** 자산 카테고리 아래에 플로 기반 에이전트가 선택할 수 있는 자산으로 표시돼요.
- 스냅샷을 불러올 때(대상 계정): 같은 에이전트가 **음성 AI** 아래에 표시돼요. 전체를 불러올지, 일부 에이전트만 불러올지 선택할 수 있어요.

![스냅샷의 음성 AI 자산 카테고리에 표시된 에이전트 목록](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155079162327/original/Hcpk6oiXjimVByYriVeKowvym0iT5ABw_w.png?1787575103)

다음처럼 선택할 수 있어요.

- 플로 기반 음성 AI 에이전트만 선택
- 프롬프트 기반 음성 AI 에이전트만 선택
- 플로 기반과 프롬프트 기반 에이전트를 모두 선택하고, 워크플로우·퍼널 같은 다른 스냅샷 자산도 함께 선택해서 바로 쓸 수 있는 완성형 템플릿 만들기

## 플로 기반 음성 AI 에이전트가 계정 간에 옮겨지는 방식

플로 기반 음성 AI 에이전트는 프롬프트 하나가 아니에요. 노드, 분기, 액션 연결로 이루어진 통화 흐름 전체예요. 스냅샷에 담으면 이 구조 전체가 대상 계정의 자산 ID에 맞게 다시 만들어져요. 그래서 전화번호와 마지막 세부 설정만 마치면 바로 쓸 수 있어요.

### 스냅샷에 담으면 유지되는 것

- 전체 플로 구조(모든 노드와 분기)
- 에이전트 설정(이름, 설명, 핵심 설정 등)
- 연결된 액션과 다른 자산에 대한 참조(워크플로우, 트리거, 예약 액션 등). 대상 계정에도 해당 자산이 있을 때 유지돼요.
- 현재 활성화된 플로 설정에 포함된 에이전트 버전

### 대상 계정에서 다시 연결되는 것

- 참조하는 자산(워크플로우, 트리거, 캘린더)의 내부 ID는 대상 계정에 있는 사본으로 다시 연결돼요. 그래서 불러온 플로가 그 계정의 자산을 사용해요.
- 사용할 수 없는 자산에 의존하는 플로 단계는 불러온 뒤 직접 고쳐야 해요. 예를 들어 다른 워크플로우나 캘린더를 지정해야 해요.

{% hint style="info" %}
플로 기반 음성 AI 에이전트는 전체 통화 구조(노드, 분기, 연결된 액션)를 스냅샷으로 옮길 수 있어요. 번호를 지정하면 바로 전화를 받을 수 있어요.
{% endhint %}

## 플로 기반 음성 AI 에이전트를 스냅샷에 담는 방법

플로 기반 음성 AI 에이전트를 스냅샷에 담는 절차는 다른 자산과 같아요. 스냅샷을 만들고 불러올 때 **음성 AI** 카테고리에서 플로 기반 에이전트를 선택하기만 하면 돼요. 스냅샷은 에이전시 보기에서 관리해요.

### 1단계: 원본 계정에서 플로 기반 음성 AI 에이전트 준비하기

1. 플로 기반 음성 AI 에이전트가 있는 서브 계정을 열어요.
2. **음성 AI**로 이동해서 재사용할 에이전트의 **플로 빌더**를 열어요.
3. 다음 내용을 확인해요.
   - 플로가 의도한 대로 동작하는지(테스트 통화가 문제없이 끝나는지)
   - 연결된 워크플로우, 트리거, 캘린더 등 다른 자산이 설정되어 있고 활성화되어 있는지

![원본 서브 계정의 플로 빌더 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155079162749/original/j_AGN7F_kKGSL7mnhqJESbv_3w4oCKUQDw.png?1787575334)

### 2단계: 원본 서브 계정으로 스냅샷 만들기

1. **에이전시 보기로 전환**을 클릭해요.
2. 왼쪽 메뉴에서 **계정 스냅샷**을 클릭해요.
3. **+ 새 스냅샷 생성**(또는 **스냅샷 만들기**)을 클릭해요.
4. 플로 기반 음성 AI 에이전트가 있는 원본 서브 계정을 선택해요.

![계정 스냅샷에서 새 스냅샷을 만드는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155079162506/original/kRuMumleFpaqouYb216K4m6x3wQ7u5kt3Q.png?1787575243)

### 3단계: 플로 기반 음성 AI 에이전트를 스냅샷 자산으로 선택하기

1. 자산 선택 단계에서 **음성 AI** 카테고리를 찾아요.
2. **음성 AI**를 펼쳐서 사용할 수 있는 에이전트를 모두 확인해요.
   - 프롬프트 기반 에이전트
   - 플로 빌더 기반 에이전트
3. 포함할 플로 기반 에이전트 옆의 체크박스를 선택해요.
4. 필요하면 플로가 의존하는 워크플로우, 트리거, 캘린더, 퍼널, 캠페인 같은 관련 자산도 함께 선택해요.
5. **만들기** 또는 **저장**을 클릭해서 스냅샷을 완성해요. 이제 선택한 플로 기반 음성 AI 에이전트가 스냅샷에 포함돼요.

![음성 AI 카테고리에서 플로 기반 에이전트를 선택하는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155079163261/original/C6e9fVXalRQqjeXtfOw5yBCw9MuDlq9LbQ.png?1787575488)

### 4단계: 다른 서브 계정에 스냅샷 불러오기

1. **에이전시 보기 > 계정 스냅샷**에서 만든 스냅샷을 찾아요.
2. **Load**(불러오기)(또는 이에 해당하는 가져오기 옵션)를 클릭해요.
3. 대상 서브 계정을 선택해요.
4. 불러올 자산 목록을 확인하고 **음성 AI > [플로 기반 에이전트 이름]**이 선택되어 있는지 확인해요.
5. 확인한 뒤 불러오기를 시작해요. 하이퍼클래스가 대상 계정에 플로 기반 음성 AI 에이전트를 다시 만들고, 함께 포함한 의존 자산은 그 계정의 자산 ID로 연결해요.

![스냅샷을 대상 서브 계정에 불러오는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155079163445/original/n_0VLi8PkkQAdUIx6tJdXaTCfb0CYQujKw.png?1787575578)

![불러올 자산 목록을 확인하는 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155079163533/original/zZRcdCwdGf0MfBBdXO21PsUr6gZrEKfSsg.png?1787575632)

### 5단계: 대상 계정에서 플로 기반 음성 AI 에이전트 마무리하기

1. 대상 서브 계정으로 전환해요.
2. **음성 AI**를 열고 플로 기반 에이전트가 목록에 있는지 확인해요.
3. 에이전트가 전화를 걸고 받을 수 있도록 사용할 수 있는 하이퍼클래스 전화 또는 Twilio 번호를 지정하거나 확인해요.
4. 영업시간, 주소, 지점별 오퍼처럼 지점마다 다른 내용을 대상 계정의 비즈니스에 맞게 수정해요.
5. 테스트 통화를 몇 번 해서 에이전트가 의도한 대로 동작하는지, 모든 액션이 제대로 실행되는지 확인해요.

{% hint style="info" %}
이제 대상 계정에서 플로 기반 음성 AI 에이전트가 모든 플로 로직, 노드, 분기, 연결된 액션을 그대로 유지한 채 동작해요. 전화번호를 지정하면 바로 통화를 처리할 수 있어요.
{% endhint %}

## 스냅샷으로 플로 기반 음성 AI를 쓸 때의 권장 방법

몇 가지 권장 방법을 지키면 템플릿을 깔끔하게 유지하고, 충돌을 피하고, 불러오기도 순조롭게 할 수 있어요.

- 마스터 플로는 템플릿용 서브 계정에서 관리해요 — 기준이 되는 플로 기반 음성 AI 설계를 전용 템플릿 계정에서 관리하면, 어떤 버전을 스냅샷에 담아 공유해야 하는지 항상 알 수 있어요.
- 에이전트와 자산 이름을 일관되게 지어요 — 음성 AI 에이전트와 이에 연결된 워크플로우·캘린더에 알아보기 쉬운 이름을 붙이면, 불러온 뒤에도 각 자산의 역할을 바로 알 수 있어요.
- 의존 자산을 같은 스냅샷에 담아요 — 플로가 쓰는 워크플로우, 트리거, 캘린더를 함께 포함하면 불러온 에이전트가 수동으로 다시 연결할 부분이 적은 상태로 동작해요.
- 플로를 수정하면 스냅샷을 새로 고쳐요 — 플로 기반 음성 AI 템플릿을 크게 바꿨다면 스냅샷을 새로 고쳐서, 앞으로 불러오거나 푸시하는 계정에 최신 플로 로직이 들어가게 해요.
- 먼저 테스트용 서브 계정에서 확인해요 — 실제 운영 중이 아닌 서브 계정에 스냅샷을 먼저 불러와 동작을 확인한 뒤, 여러 고객 계정에 배포해요.
- 스냅샷 공유와 보호를 함께 써요 — 스냅샷 공유 옵션과 **Assets Protected Snapshots**(자산 보호 스냅샷)를 활용하면, 파트너나 고객에게 플로 기반 음성 AI 템플릿을 배포하면서 필요할 때 지적 재산도 보호할 수 있어요.
