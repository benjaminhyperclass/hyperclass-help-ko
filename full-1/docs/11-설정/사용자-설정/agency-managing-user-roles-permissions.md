# 에이전시 사용자 역할과 권한 관리

에이전시 사용자에게 꼭 필요한 권한만 주면, 불필요한 계정이나 모듈, 민감한 설정이 노출되지 않아요. 하이퍼클래스에서는 에이전시 관리자가 한 곳에서 사용자 유형, 역할, 서브 계정 접근, 모듈 표시 여부, 세부 작업 권한을 관리할 수 있어요.

특정 서브 계정 안에서만 일하는 사용자를 관리하려면 [서브 계정 사용자 역할 및 권한 관리](user-roles-permissions-and-assigned-data-subaccount.md)를 참고하세요.

## 에이전시 사용자 역할과 권한이란?

에이전시 사용자 역할과 권한은 사용자가 어떤 계정, 모듈, 설정, 작업에 접근할 수 있는지를 정해요. 접근 권한은 여러 단계로 나뉘어 있어요.

- **사용자 유형**: 사용자가 일하는 범위를 정해요.
- **역할**: 그 범위 안에서 사용자가 가지는 권한의 수준을 정해요.
- 서브 계정 지정: **계정** 유형 사용자가 접근할 수 있는 서브 계정을 정해요.
- 모듈 권한: 기능이나 모듈 전체를 쓸 수 있는지 정해요.
- 세부 권한: 모듈 안에서 지원되는 개별 작업을 할 수 있는지 정해요.

사용자의 업무에 필요한 최소한의 권한만 주세요. 에이전시 전체에 접근할 필요 없이 일부 고객 계정만 써야 하는 사용자라면, **사용자 유형**을 **계정**으로 하고 필요한 서브 계정만 지정하세요.

사용자 접근에 대한 전반적인 내용은 [사용자 접근 권한](../user-access.md) 문서에서 볼 수 있어요.

## 사용자 유형과 역할

**사용자 유형**은 사용자가 어디에서 일할 수 있는지를, **역할**은 그 범위 안에서 어느 정도의 권한을 가지는지를 정해요.

### 사용자 유형

- **에이전시**: 에이전시 수준의 접근이 필요한 사용자에게 사용해요.
- **계정**: 선택한 서브 계정에만 접근해야 하는 사용자에게 사용해요.

**계정**을 선택하면 사용자에게 필요한 서브 계정만 지정하세요.

### 역할

- **관리자**: 사용자의 접근 범위 안에서 관리 기능을 쓸 수 있어요.
- **사용자**: 해당 사용자에게 설정된 권한에 따라 접근할 수 있어요.

## 특정 서브 계정만 접근하도록 제한하기

에이전시 전체 접근 없이 특정 고객 계정에만 접근해야 하는 사람에게는 **계정** 유형 사용자를 사용하세요.

1. **에이전시 보기**에서 **설정 > 사용자**로 이동하세요.
2. 해당 사용자를 편집하세요.
3. **Roles & Permissions**(역할 및 권한)를 여세요.
4. **사용자 유형**을 **계정**으로 설정하세요.
5. 사용자가 접근할 서브 계정을 선택하세요.
6. 알맞은 **역할**을 선택하세요.
7. 필요한 모듈 권한과 세부 권한을 설정하세요.
8. 변경 사항을 저장하세요.

이 사용자는 자신에게 지정된 서브 계정에만 접근할 수 있어요.

![서브 계정 접근 제한 설정 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155082693950/original/paUo_FpvDvvy9PAPPGU_ZiBT3HbVSs_s5g.png?1791342159)

## 서브 계정 만들기와 삭제 권한

서브 계정을 만들거나 삭제하는 권한은, 이미 있는 서브 계정 안에서 할 수 있는 작업의 권한과 따로 관리돼요.

1. **에이전시 보기**에서 **설정 > 사용자**로 이동하세요.
2. 해당 사용자를 편집하세요.
3. **Roles & Permissions**를 여세요.
4. **서브 계정** 에이전시 모듈을 찾으세요.
5. 사용자가 새 서브 계정을 만들지 못하게 하려면 **Create Sub-Accounts**(서브 계정 만들기)의 체크를 해제하세요.
6. 사용자가 서브 계정을 삭제하지 못하게 하려면 **삭제**의 체크를 해제하세요.
7. 사용자가 서브 계정 모듈에 아예 접근하지 않아야 한다면 모듈 전체를 끄세요.
8. 변경 사항을 저장하세요.

## 모듈 권한과 세부 권한

모듈 권한과 세부 권한은 함께 작동해서, 사용자가 무엇에 접근하고 어떤 작업을 할 수 있는지 정해요.

- 모듈 권한: 사용자가 해당 기능에 접근하지 않아야 한다면 모듈 전체를 꺼요.
- 세부 권한: 켜져 있는 모듈 안에서 지원되는 개별 작업을 제어해요.

모듈이 꺼져 있으면 사용자는 그 모듈에 속한 기능을 쓸 수 없어요.

### 폼, 설문, 퀴즈, QR 코드

**폼**, **설문**, **퀴즈**, **QR 코드**는 사용자별 권한 설정을 지원해요. 모듈 토글과 **View & manage**(보기 및 관리) 권한으로 접근을 제어하세요.

### 제휴 매니저 지급 권한

**Pay Affiliate Manager Payout**(제휴 관리자 지급 처리) 권한은 자격이 있는 관리자가 제휴 지급을 처리할 수 있는지를 정해요.

- 에이전시 관리자: 이 권한은 기본으로 켜져 있고, 켜거나 끌 수 있어요.
- 에이전시 사용자: 제휴 지급을 처리할 수 없어요.

이 권한을 끄면 **제휴 관리자**에서 지급 관련 작업이 보이지 않아요.

## 서브 계정 설정 권한

**서브 계정 설정** 권한으로는 고객 설정, 결제 등 민감한 설정에 영향을 줄 수 있는 관리 영역을 더 세밀하게 제어할 수 있어요.

- **Sub-Accounts List Page**(서브 계정 목록 페이지): 서브 계정 목록과 관련 관리 작업에 대한 접근을 제어해요.
- **고객 관리** 페이지 – **기본 정보**: 지원되는 고객 수준 설정을 제어해요.
- **Sub-Account Billing**(서브 계정 결제): 지원되는 결제 및 금융 작업을 제한해요.
- **Sub-Account Company Settings**(서브 계정 회사 설정): 영향이 큰 회사 설정에 대한 접근을 제한해요.

사용자가 권한이 없는 작업을 하려고 하면, 하이퍼클래스가 현재 권한으로는 그 작업을 할 수 없다는 안내를 보여 줘요.

## 사용자 관리와 로그인 권한

**사용자 관리** 권한은 지원되는 사용자 관리 작업을 제어해요. 자격이 있는 에이전시 관리자가 **로그인** 기능을 쓸 수 있는지도 여기서 정해요.

### Enable Login As

**Enable Login As**(다른 사용자로 로그인 허용) 권한은 자격이 있는 에이전시 관리자가 다른 사용자로 로그인할 수 있는지를 정해요.

- 기본값: 켜져 있어요.
- 끄면: 해당 관리자에게는 **로그인** 옵션이 보이지 않아요.
- 위치: **에이전시 보기 > 설정 > 사용자** > **Edit User**(사용자 편집) > **Roles & Permissions** > **사용자 관리**

새로 바뀐 **사용자** 화면에서는 소유자 역할 처리와 소유권 이전 방법도 더 알기 쉽게 안내해요. 해당 옵션을 쓸 수 있는 경우에 한해서요.

자세한 내용은 [사용자로 로그인(에이전시 관리자 전용)](../에이전시-설정/login-as-user-agency-admin-only.md) 문서를 참고하세요.

## 권한 복사

에이전시 관리자는 권한을 하나씩 설정하는 대신, 기존 사용자의 세부 권한 설정을 다른 사용자에게 복사할 수 있어요. 이 기능은 **권한 복사**에서 쓸 수 있어요.

권한을 복사하기 전에, 받는 사용자의 역할과 업무, 계정 범위가 복사할 설정에 맞는지 확인하세요.

## 서브 계정 접근이 제한된 고객 추가하기

자기 비즈니스에만 접근하면 되는 고객은 **계정** 유형 사용자로 만들고, 해당 서브 계정만 지정하세요. 그러면 에이전시 전체 접근을 막으면서도 고객의 역할, 모듈 권한, 데이터 공개 범위를 설정할 수 있어요.

1. **에이전시 보기**에서 **설정 > 사용자**로 이동하세요.
2. **+ Add User**(사용자 추가)를 클릭하세요.
3. 고객의 이름, 이메일 주소 등 필요한 사용자 정보를 입력하세요.
4. **Roles & Permissions**를 여세요.
5. **사용자 유형**을 **계정**으로 설정하세요.
6. 고객에게 해당하는 서브 계정만 선택하세요.
7. 알맞은 **역할**을 선택하세요.
8. 고객이 접근할 수 있어야 하는 모듈과 개별 권한을 설정하세요.
9. 지원되는 기록의 공개 범위를 해당 사용자에게 할당된 기록으로 제한하려면 **할당된 데이터만**을 켜세요.
10. **저장**을 클릭하세요.

## 대시보드 내보내기 권한

대시보드 권한은 일반적인 계정 접근 권한과 따로 관리할 수 있어요.

- **대시보드 > Export data**(데이터 내보내기): 사용자가 지원되는 대시보드 위젯 데이터를 내보낼 수 있어요.

## 서브 계정 이전 권한

서브 계정을 이전하면 소유권, 접근 권한, 결제, 연동 등 계정의 여러 자원에 영향을 줄 수 있어요. 이전 권한은 권한이 있는 사용자에게만 주세요.

- 기본적으로 에이전시 소유자는 자격이 있는 서브 계정 이전을 요청하거나 완료할 수 있어요.
- 에이전시 소유자는 특정 에이전시 관리자에게 이전 권한을 줄 수 있어요.
- 필요한 권한이 없는 에이전시 관리자는 이전 요청을 제출하거나 승인할 수 없어요.

서브 계정 이전은 선택한 데이터만 옮기는 것이 아니라, 이전 대상 서브 계정 전체를 에이전시 사이에서 옮기는 작업이에요.

자세한 내용은 [서브 계정 이전 가이드](../../23-레거시-자동화/sub-account-transfer-guide.md)를 참고하세요.

## 사용자 관리 API 지원

**강화된 보안** 설정을 켜면 API로 사용자를 관리하는 작업이 영향을 받을 수 있어요.

- **View & Manage Users**(사용자 보기 및 관리): 지원되는 범위에서 사용자를 보고, 만들고, 편집할 수 있어요.
- **사용자 보기**: 더 넓은 사용자 관리 권한 없이, 지원되는 범위에서 사용자를 볼 수만 있어요.

**강화된 보안**을 켜면 영향을 받는 API 기반 사용자 관리 작업이 제한돼요.

에이전시에서 영향을 받는 API 기반 사용자 관리 작업이 필요하다면 다음과 같이 하세요.

1. **에이전시 보기 > 설정 > 회사 > 고급 설정**으로 이동하세요.
2. **강화된 보안**을 찾으세요.
3. 영향을 받는 API 작업이 꼭 필요한 경우에만 이 설정을 끄세요.

자세한 내용은 [강화된 계정 보안](../../35-개발자/Developer-Resources/enhanced-account-security.md) 문서를 참고하세요.

![강화된 보안 설정 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155082694770/original/SARgLEGuK9cUVt7ccz1Dpo-J6MVaPSHKnQ.png?1791344848)

{% hint style="warning" %}
**강화된 보안**을 끄면 계정 보안 위험이 커질 수 있어요. 에이전시에서 영향을 받는 API 기반 작업이 꼭 필요한 경우가 아니라면 켜 두세요.
{% endhint %}

## 에이전시 사용자 역할과 권한 설정하기

먼저 사용자의 접근 범위를 설정한 다음, 개별 권한을 세부적으로 조정하세요.

![역할 및 권한 설정 시작 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155082694030/original/-klzPLdUtzcj4xu3zaNJXvSrDGOyf2kgdw.png?1791342498)

1. **에이전시 보기**에서 **설정 > 사용자**로 이동하세요.
2. 해당 사용자를 선택해 편집 화면을 여세요.
3. **Roles & Permissions**를 선택하세요.
4. 알맞은 **사용자 유형**을 선택하세요.
   - **에이전시**: 에이전시 수준의 접근이 필요한 사용자에게 사용해요.
   - **계정**: 선택한 서브 계정에만 접근해야 하는 사용자에게 사용해요.

![사용자 유형 선택 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155082694010/original/HkdSXF_vNnC-qFvXLq9kAobbSmfIYognBA.png?1791342425)

5. 알맞은 **역할**을 선택하세요.
6. **사용자 유형**이 **계정**이면 사용자가 접근할 서브 계정을 선택하세요.
7. 사용자에게 필요 없는 모듈은 끄세요.
8. 켜져 있는 모듈 안에서 쓸 수 있는 세부 권한을 설정하세요.
9. 민감한 권한은 따로 한 번 더 확인하세요.
10. 사용자 설정을 저장하세요.

![모듈과 세부 권한 설정 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155082694015/original/t73y3D67meiEa4iP98_k_4mrE2EVJE7pnA.png?1791342445)

특히 확인해야 할 민감한 권한은 다음과 같아요.

- 서브 계정 만들기 또는 삭제
- **서브 계정 설정**
- **사용자 관리**
- **로그인**
- 대시보드 내보내기
- **서브 계정 이전**

사용자 권한을 주기적으로 점검하고, 업무가 바뀌면 권한도 함께 수정하세요.

## 자주 묻는 질문

### 사용자 유형과 역할은 어떻게 다른가요?
**사용자 유형**은 사용자가 일하는 범위를 정하고, **역할**은 그 범위 안에서 사용자가 가지는 권한의 수준을 정해요.

### 에이전시 전체 접근 없이 여러 서브 계정에 접근하게 할 수 있나요?
네. 사용자의 **사용자 유형**을 **계정**으로 설정하고, 접근하게 할 서브 계정을 각각 지정하세요.

### 서브 계정은 열 수 있는데 일부 설정은 막혀 있어요. 왜 그런가요?
서브 계정 지정은 사용자가 그 계정에 들어갈 수 있는지를 정해요. 들어간 뒤에 무엇에 접근하고 어떤 작업을 할 수 있는지는 모듈 권한과 세부 권한이 정해요.

### **할당된 데이터만**을 켜는 것과 모듈을 끄는 것은 같은가요?
아니요. 모듈 권한은 사용자가 해당 기능에 접근할 수 있는지를 정해요. **할당된 데이터만**은 지원되는 기록의 공개 범위를 할당 여부에 따라 제한해요.

### 에이전시 관리자라면 누구나 서브 계정을 이전할 수 있나요?
아니요. 기본적으로 에이전시 소유자가 자격이 있는 이전을 요청하거나 완료할 수 있어요. 이전 권한은 특정 에이전시 관리자에게 줄 수 있어요.

### API로 사용자 관리 권한을 업데이트할 수 없어요.
**강화된 보안**을 켜면 영향을 받는 API 기반 사용자 관리 작업이 제한될 수 있어요. 이 설정을 바꾸기 전에 보안에 미치는 영향을 먼저 확인하세요.

### 고객을 에이전시 수준 사용자로 추가해도 되나요?
고객이 자기 비즈니스 계정에만 접근하면 된다면, 해당 서브 계정 안의 사용자로 추가하세요. 그러면 불필요하게 에이전시 수준에서 볼 수 있는 정보가 생기지 않아요.
