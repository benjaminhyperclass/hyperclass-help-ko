# Shopify 스토어를 하이퍼클래스로 옮기기

Shopify의 상품, 컬렉션, 연락처, 주문, 거래 데이터를 하이퍼클래스로 가져오고 이후 동기화까지 설정하는 방법을 안내해요. 이전 전에 준비할 것부터 연결, 데이터 확인, 자동화 다시 만들기, Shopify 운영 종료 전 점검까지 순서대로 따라 할 수 있어요.

Shopify를 하이퍼클래스로 옮기면 이커머스 데이터, 고객 기록, 주문 내역, 마케팅 워크플로우를 한 플랫폼에서 관리할 수 있어요. 하이퍼클래스의 Shopify 연동은 상품, 컬렉션, 연락처, 주문, 거래를 가져오고 동기화해요. 연동 후에는 **Order Submitted**(주문 제출), **Payment Received**(결제 완료) 같은 트리거로 이커머스 자동화도 만들 수 있어요.

{% hint style="info" %}
Shopify 연결 방식이 바뀌고 있어요.

Shopify가 새 연동이 외부 앱과 연결되는 방식을 OAuth 기반으로 바꾸고 있어요. 내용은 다음과 같아요.

1. 이미 Shopify 스토어를 연결했어요
   - 스토어가 OAuth로 연결되어 있다면, 새로 지원되는 고객·주문 동기화 기능을 쓰기 위해 다시 연결할 필요가 없어요.
   - 스토어가 레거시 커스텀 앱 방식으로 연결되어 있다면, 보호된 고객 데이터를 쓰려면 OAuth로 다시 연결하세요.
2. 새 Shopify 스토어이거나 새로 연결해요
   - 2026년 1월 1일부터 일부 새 스토어에는 Shopify에서 커스텀 앱 옵션이 더 이상 표시되지 않아요. 새 OAuth 기반 연결 방식을 쓰면 설정이 더 쉬워요.

새로 나온 점: 새 OAuth 기반 Shopify 연결을 도입했어요. 기존 방식보다 보안이 좋고 설정이 빠르며, Shopify의 최신 기준에 맞아요.
{% endhint %}

## Shopify에서 하이퍼클래스로 이전한다는 건 무슨 뜻인가요?

Shopify의 이커머스 데이터를 하이퍼클래스로 옮겨 연락처, 상품, 주문, 결제, 후속 자동화를 한곳에서 관리하는 것을 말해요. 하이퍼클래스의 Shopify 연동으로 과거 데이터를 가져오고, 선택한 데이터는 앞으로도 계속 동기화해요.

이커머스 운영, 고객 소통, 판매 자동화를 하이퍼클래스로 모으고 싶을 때 쓰면 좋아요. 일부는 Shopify 연동으로 자동 처리되지만, 워크플로우, 스토어 페이지, 결제 설정, 팀 업무 방식은 직접 확인하고 다시 만들어야 해요.

## 이전하면 좋은 점

Shopify 스토어를 하이퍼클래스로 옮기면 플랫폼을 오가는 일이 줄고, 이커머스 활동·연락처·자동화를 한눈에 볼 수 있어요.

- 이커머스 데이터 한곳에 모으기: 지원되는 Shopify 상품, 컬렉션, 연락처, 주문, 거래를 하이퍼클래스로 가져와요.
- 고객 후속 관리 개선: 이커머스 데이터를 하이퍼클래스 CRM 도구와 함께 써서 고객 소통과 세분화를 더 잘할 수 있어요.
- 주문 활동 기반 자동화: Shopify 연동 후 **Order Submitted**, **Payment Received** 같은 트리거로 워크플로우 자동화를 만들 수 있어요.
- 이전 계획 정리: 하이퍼클래스로 완전히 옮기기 전에 Shopify의 데이터, 워크플로우, 결제, 스토어 운영을 점검해요.
- 지속적인 동기화 관리: 처음 가져온 뒤에도 계속 동기화할 Shopify 데이터를 직접 고를 수 있어요.

## 시작하기 전에

필요한 접근 권한과 조건을 미리 확인해 두면 데이터 누락, 가져오기 실패, 동기화 제한을 막을 수 있어요.

이전하기 전에 다음을 준비하세요.

- Shopify 스토어 관리자 권한
- 하이퍼클래스 서브 계정 관리자 권한
- Shopify에서 커스텀 앱을 만들거나 관리할 수 있는 권한
- Shopify **관리자 API 액세스 토큰**을 만들 수 있는 권한
- Shopify 스토어 URL 또는 스토어 이름
- 하이퍼클래스에서 다시 만들어야 할 자동화, 알림, 결제 흐름, 고객 후속 관리 절차 목록

{% hint style="info" %}
Shopify Basic 플랜 지원: Shopify Basic 스토어도 하이퍼클래스의 OAuth 기반 Shopify 연동을 통해 지원되는 보호된 고객 데이터에 접근하고, 고객·주문 정보를 동기화할 수 있어요. 이 동기화 기능을 쓰는 데 Shopify Grow, Advanced, Plus 구독은 필요하지 않아요. 레거시 커스텀 앱 방식으로 연결된 스토어는 새로 지원되는 고객·주문 데이터를 쓰려면 OAuth로 다시 연결해야 해요. 이미 OAuth로 연결된 스토어는 다시 연결하지 않아도 돼요.
{% endhint %}

## Shopify 데이터 중 무엇을 가져오고 동기화할 수 있나요?

Shopify 연동에서는 두 가지를 선택해요. 과거 데이터를 한 번 가져오는 것과, 앞으로의 동기화예요. 차이를 알면 지금 가져올 데이터와 연결 이후에도 계속 업데이트할 데이터를 정하기 쉬워요.

| 일회성 가져오기 옵션 | 이후 동기화 옵션 |
| --- | --- |
| 연락처 | 연락처 |
| 주문 | 주문 |
| 거래 | 거래 |
| 상품 | 상품 |
| 컬렉션 | 컬렉션 |
|  | Order Submitted 트리거 |
|  | Payment Received 트리거 |

{% hint style="info" %}
연락처 가져오기에는 과거에 주문한 적이 있는 Shopify 고객이 포함돼요. 주문한 적이 없는 고객은 Shopify 연락처 가져오기에 포함되지 않을 수 있어요.
{% endhint %}

가져오기와 동기화는 Shopify 스토어 규모와 선택한 데이터 종류에 따라 시간이 걸릴 수 있어요.

### Shopify OAuth 앱으로 연결하기

새로 연결하거나 다시 연결할 때는 모두 OAuth 방식으로 Shopify를 연동해요. 예전에 커스텀 앱으로 연결했다면 기존 연동은 계속 작동해요. 아래 중요 안내를 확인하세요.

| 구분 | OAuth 앱 (권장) | 커스텀 앱 (레거시) — 지원 중단 예정 |
| --- | --- | --- |
| 설정 난이도 | 낮음. Shopify에서 한 번의 클릭으로 설치 | API 토큰을 직접 만들어야 함 |
| 대상 | 모든 새 연결 | OAuth 앱이 나오기 전에 설정한 기존 연동 |
| 보안 | OAuth 2.0. 관리할 API 토큰이 없음 | **관리자 API 액세스 토큰**을 직접 보관해야 함 |
| 제공 여부 | 지금 사용 가능 | 기존 계정에서는 계속 지원 |

{% hint style="warning" %}
레거시 커스텀 앱 방식으로 연결된 기존 Shopify 연동은 계속 작동할 수 있어요. 하지만 이 방식을 쓰는 Shopify Basic 스토어는 보호된 고객 데이터와 지원되는 고객·주문 동기화 기능을 쓰려면 OAuth로 다시 연결해야 해요.

이미 OAuth로 연결된 스토어는 다시 연결하지 않아도 돼요.
{% endhint %}

Shopify OAuth 앱은 몇 단계만 거치면 연결돼요. 커스텀 앱을 만들거나 API 토큰을 발급하거나 Shopify 개발자 설정을 직접 바꿀 필요가 없어요.

#### OAuth 앱으로 연결하는 방법

1. 서브 계정을 열고 **설정 > 연동 > Shopify**로 이동하세요.
2. **연결**을 클릭하세요.
   ![연동 화면에서 연결을 클릭하는 모습](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155072209542/original/eytMtzZyytivLUHscl5e-oKCKWcR0zt8Cw.jpeg?1779794426)
3. Shopify 스토어 URL 또는 스토어 이름을 입력하고 **다음**을 클릭하세요.
   ![Shopify 스토어 URL 입력 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155072209535/original/JPdNPTcbBIkQszmOG653nxn2_J4adxARkA.png?1779794421)
4. **요소 가져오기** 화면에서 일회성으로 가져올 Shopify 데이터를 선택하세요.
   - **연락처 가져오기**
   - **주문 가져오기**
   - **거래 가져오기**
   - **상품 가져오기**
   - **컬렉션 가져오기**

   ![요소 가져오기 화면에서 가져올 데이터를 선택하는 모습](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155072209536/original/F5-I5pd8wQnX_3wiHGcXSUpF5MMU5g_iLA.png?1779794421)
5. **다음**을 클릭해 **동기화 설정** 화면으로 이동하세요. 앞으로도 계속 동기화할 데이터와 트리거를 선택하세요.
   - **연락처 동기화**
   - **Order Sync**(주문 동기화)
   - **주문 접수 트리거**
   - **거래 동기화**
   - **결제 완료 트리거**
   - **상품 동기화**
   - **컬렉션 동기화**

   ![동기화 설정 화면에서 동기화할 데이터를 선택하는 모습](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155072209545/original/hZ-r6lIEzv8Fd1DQRM3wLg_29B5Ka2NAKw.jpeg?1779794427)
   <!-- 검토 필요: 원문 내용이 서로 다름 (원문에서 같은 트리거를 앞에서는 Order Submitted, 여기서는 Order Received Trigger로 표기함) -->
6. **저장**을 클릭하세요. OAuth 승인 과정이 시작되고 Shopify로 이동해요.
7. Shopify의 **Install app** 화면에서 요청된 권한을 확인하고 **설치**를 클릭하세요.
   ![Shopify 앱 설치 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155072209537/original/AWMv3MRLvVz0CH8t_EqPNYUMZzPguLIsHg.jpeg?1779794423)
8. 승인이 끝나면 하이퍼클래스로 돌아오고, Shopify 스토어가 연결돼요.

{% hint style="info" %}
Shopify 스토어를 통째로 옮길 때는 특정 데이터만 필요하다는 계획이 없다면 가져오기와 동기화 옵션을 모두 선택하세요. 지원되는 과거 데이터를 모두 가져오고, 이후 Shopify 활동도 계속 동기화할 수 있어요.
{% endhint %}

## 가져온 상품과 컬렉션 확인하기

상품과 컬렉션은 하이퍼클래스에서 이커머스 카탈로그가 어떻게 구성되는지를 정하는 핵심 데이터예요. 가져온 데이터를 확인해 두면 스토어 설정, 결제 흐름, 고객 경험이 정확한지 오픈 전에 점검할 수 있어요.

가져오기가 끝난 후 다음을 확인하세요.

- **결제 > 상품 > 상품**에서 가져온 상품을 확인하세요.
- **결제 > 상품 > Product Collections**(상품 컬렉션)에서 가져온 컬렉션을 확인하세요.
- 상품 이름, 설명, 이미지, 가격, 재고 정보가 맞는지 확인하세요.
- 상품이 알맞은 컬렉션에 들어가 있는지 확인하세요.
- SEO 필드가 제대로 가져와졌는지 확인하세요.
- 직접 정리해야 하는 상품이나 컬렉션 정보는 수정하세요.

상품과 컬렉션 관련 참고 사항은 다음과 같아요.

- 상품을 가져오거나 동기화할 때 세금은 상품에 연결되지 않아요.
- Shopify의 SEO 정보가 기본 설정 그대로 바뀌지 않았다면, 하이퍼클래스에서는 SEO 데이터가 `null`로 들어올 수 있어요.

## 하이퍼클래스에서 이커머스 운영과 자동화 다시 만들기

Shopify 연동은 지원되는 데이터만 옮겨 줘요. 일부 업무는 하이퍼클래스에서 직접 다시 만들거나 확인해야 해요. 이렇게 해 두면 이전 후에도 팀이 판매, 소통, 후속 관리를 이어갈 수 있어요.

| 확인할 영역 | 다시 만들거나 확인할 내용 |
| --- | --- |
| 이커머스 스토어 페이지 | 스토어 페이지가 하이퍼클래스에 만들어져 있고 잘 정리되어 있는지 확인하세요. |
| 결제 페이지 | 결제 페이지를 다시 만들고, 구매 흐름이 의도대로 작동하는지 확인하세요. |
| 감사 페이지 | 구매 후 보여 줄 감사 페이지를 만들거나 업데이트하세요. |
| 결제 게이트웨이 설정 | 하이퍼클래스에서 결제 처리 설정을 연결하고 확인하세요. |
| 배송 설정 | 배송, 출고 등과 관련된 설정을 필요에 따라 다시 만드세요. |
| 주문 확인 안내 | 구매 후 발송하는 이메일, SMS, 알림을 다시 만드세요. |
| 결제 중단 복구 | 결제를 끝내지 않고 나간 고객을 위한 후속 안내를 설정해 놓친 매출을 되찾으세요. |
| 고객 후속 관리 워크플로우 | 구매 후 안내, 재구매 유도, 리뷰 요청, 업셀 워크플로우를 다시 만드세요. |
| 내부 알림 | 새 주문, 결제, 출고 작업이 생기면 팀에 알림이 가도록 설정하세요. |
| 태그, 세그먼트, 고객 목록 | 세분화와 리포팅에 쓸 고객 분류 규칙을 다시 만드세요. |
| 인보이스, 문서, 템플릿 | 고객 응대나 내부 업무에 필요한 재사용 템플릿을 다시 만드세요. |
| 팀 업무 절차(SOP)와 운영 프로세스 | 하이퍼클래스에서 이커머스 운영을 어떻게 관리하는지 팀이 알 수 있도록 내부 문서를 업데이트하세요. |

이커머스 워크플로우는 **자동화 > 워크플로우**로 이동해 하이퍼클래스에서 계속 필요한 Shopify 워크플로우를 다시 만드세요. 필요하면 **Order Submitted**, **Payment Received** 같은 이커머스 트리거를 쓰세요.

이커머스 운영을 다시 만들 때는 아래 문서를 참고하세요.

- [이커머스 온라인 스토어 웹사이트 설정하기](E-Commerce-Store/how-to-set-up-an-e-commerce-online-store-websites.md)
  하이퍼클래스 이커머스 스토어를 설정할 때 보세요. 스토어 페이지, 결제 페이지, 감사 페이지, 상품, 주문 추적, 출고 설정을 다뤄요.
- [자동 결제 중단 이메일로 놓친 매출 되찾기](E-Commerce-Store/recover-lost-sales-with-automatic-abandoned-checkout-emails.md)
  결제 중단 이메일을 설정해 구매를 마치지 않고 떠난 고객을 다시 불러올 때 보세요.
- [이커머스 스토어와 주문 폼의 수동 결제 수단](E-Commerce-Store/manual-payment-method-in-e-commerce-stores-order-forms.md)
  수동 결제, 오프라인 결제, 직접 결제 완료로 표시해야 하는 주문이 있을 때 보세요.

## 이전 후 동기화 설정 관리하기

Shopify를 연결한 후에도 동기화 설정을 바꿔 하이퍼클래스에서 계속 업데이트할 Shopify 데이터를 조절할 수 있어요. 전환 기간 동안 하이퍼클래스 계정을 Shopify와 맞춰 두는 데 도움이 돼요.

연동을 연결한 후에는 다음을 진행하세요.

- **설정 > 연동 > Shopify**로 돌아가세요.
- 켜져 있는 동기화 항목을 확인하세요.
- 이전 계획에 맞게 이후 동기화 옵션을 켜거나 끄세요.
- 가져온 데이터가 정확한지 살펴보세요.
- 동기화된 새 Shopify 활동이 하이퍼클래스에 나타난 후 워크플로우가 어떻게 동작하는지 확인하세요.

누락된 데이터를 다시 가져오려면 Shopify 연동을 해제했다가 다시 연결한 뒤, 다시 가져올 데이터를 선택하세요. 다시 가져온 후에는 예상한 데이터가 추가되거나 업데이트되었는지 꼼꼼히 확인하세요.

## 검증 후 Shopify 운영 종료하기

Shopify 운영 종료는 하이퍼클래스에서 데이터, 결제 운영, 고객 소통, 내부 업무 절차가 모두 정상 작동하는지 팀이 확인한 후에 하세요. 꼼꼼히 마무리해야 기록 유실, 판매 중단, 고객 후속 관리 누락을 막을 수 있어요.

Shopify를 해지하기 전에 다음을 확인하세요.

- Shopify 상품, 고객, 주문을 마지막으로 한 번 내보내세요.
- 중요한 데이터가 하이퍼클래스에 있는지 확인하세요.
- 하이퍼클래스의 결제 페이지, 결제, 배송, 알림이 설정되어 있는지 확인하세요.
- 워크플로우와 후속 자동화를 테스트했는지 확인하세요.
- 팀원에게 새 하이퍼클래스 업무 방식을 교육하세요.
- 나중에 참고할 수 있도록 SOP와 이전 관련 메모를 저장하세요.
- 이전이 끝났다고 팀이 확신할 때만 Shopify를 해지하세요.

## 자주 묻는 질문

### Shopify 고객 중 어떤 고객이 연락처로 가져와지나요?
연락처 가져오기에는 과거에 주문한 적이 있는 Shopify 고객이 포함돼요. 주문한 적이 없는 고객은 Shopify 연락처 가져오기에 포함되지 않을 수 있어요.

### 특정 Shopify 데이터만 골라서 가져올 수 있나요?
네. 설정할 때 연락처, 주문, 거래, 상품, 컬렉션 등 지원되는 데이터 종류 중 가져올 것을 선택할 수 있어요. 스토어 전체를 옮길 때는 특정 데이터만 필요하다는 계획이 없다면 가져오기와 동기화 옵션을 모두 선택하세요.

### 가져오기와 동기화는 뭐가 다른가요?
가져오기는 설정할 때 선택한 기존 Shopify 데이터를 하이퍼클래스로 한 번 가져오는 거예요. 동기화는 연결을 저장한 후에도 지원되는 Shopify 데이터와 이벤트를 하이퍼클래스에 계속 업데이트할지 정하는 거예요.

### Shopify 상품과 컬렉션이 잘 가져와졌는지 어디서 확인하나요?
가져온 상품은 **결제 > 상품 > 상품**에서, 가져온 컬렉션은 **결제 > 상품 > Product Collections**에서 확인하세요.

### Shopify 세금도 상품과 함께 가져와지나요?
아니요. Shopify 상품을 가져오거나 동기화할 때 세금은 상품에 연결되지 않아요.

### Shopify 주문 상태는 하이퍼클래스에서 어떻게 표시되나요?
동기화된 Shopify 주문 상태는 하이퍼클래스에서 **완료** 또는 **취소됨**으로 표시돼요.

### Shopify 주문 하나에 거래가 여러 개 만들어지나요?
아니요. 동기화된 Shopify 주문 하나당 거래 하나가 만들어져요.

### Shopify에서 연락처가 동기화되지 않아요.
Shopify가 업데이트한 관리자 API에서는 Shopify Basic 플랜이 고객 개인 식별 정보(PII)를 더 이상 제공하지 않을 수 있어요. 고객 PII에는 고객 이름, 이메일 주소, 전화번호, 주소가 포함돼요. 하이퍼클래스는 연락처를 만들거나 업데이트하려면 이 정보가 필요해요.

{% hint style="info" %}
Shopify 연락처를 하이퍼클래스로 동기화하려면 Shopify Grow, Advanced, Plus로 업그레이드해야 할 수 있어요.
{% endhint %}

### Shopify Basic 플랜에서는 어떤 데이터를 동기화할 수 있나요?
Shopify Basic에서도 다음은 가져오고 동기화할 수 있어요.

- 상품
- 컬렉션

다음은 동기화하지 못할 수 있어요.

- 연락처
- 주문
- 거래

연락처, 주문, 거래는 고객 PII를 바탕으로 하는데, Basic 플랜에서는 Shopify의 업데이트된 API로 이 정보를 받지 못할 수 있기 때문이에요.

<!-- 검토 필요: 원문 내용이 서로 다름 (앞부분 Shopify Basic 플랜 지원 안내와 상충) -->

### 예전에는 잘 됐는데 Shopify 연락처, 주문, 거래 동기화가 왜 멈췄나요?
Shopify가 API 접근 규칙을 바꿨고, 모든 플랜에서 고객 PII 접근을 허용하던 예전 Shopify API 버전은 지원이 중단될 예정이에요. 하이퍼클래스가 Shopify의 업데이트된 API로 옮겨 가면서 Shopify 플랜에 따른 제한이 적용될 수 있어요.

이 제한은 관리자 API 접근과 웹훅 데이터 모두에 영향을 줄 수 있어요. Shopify가 API나 웹훅 이벤트로 고객 데이터를 보내 주지 않으면, 하이퍼클래스는 관련 연락처, 주문, 거래 기록을 만들 수 없어요.

### Shopify 앱 권한은 어디서 확인하고 관리하나요?
Shopify 관리자 화면에서 앱 권한을 관리할 수 있어요. 자세한 내용은 [여기](https://admin.shopify.com/store/1phxbv-b1/settings/apps/development/195355017217/configuration)를 참고하세요.

### Shopify 스토어 이름은 어디서 찾나요?
Shopify 관리자에 로그인한 뒤 브라우저 주소창의 URL을 보세요. Shopify 관리자 URL에서 `/store/` 뒤에 나오는 값이 스토어 이름이에요.

예를 들어 URL이 다음과 같다면:

`admin.shopify.com/store/ef760-ef`

Shopify 스토어 이름은 다음과 같아요.

`ef760-ef`
