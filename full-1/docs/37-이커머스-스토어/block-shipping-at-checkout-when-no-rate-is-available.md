# 배송 요금이 없을 때 결제 막기

고객의 배송지에 맞는 배송 방법이 없으면 결제를 완료하지 못하게 막을 수 있어요. 배송할 수 없는 주문이나, 의도하지 않은 무료 배송 주문을 줄이고 싶을 때 쓰세요.

## 이 문서에서 다루는 내용

**Block Shipping at Checkout**(결제 시 배송 차단) 기능으로 유효한 배송 요금이 없을 때 결제를 막고, 주문 처리를 관리하는 방법을 설명해요.

- 설정을 켜는 방법
- **결제 페이지**와 **Upsell Element**(업셀 요소)에서 배송 검증이 이루어지는 방식
- 오류 메시지의 모양을 스토어 브랜딩에 맞게 바꾸는 방법

## Block Shipping at Checkout이란?

**Block Shipping at Checkout**은 고객의 배송지에 맞는 배송 방법이 없을 때 주문을 완료하지 못하게 막는 설정이에요. 배송할 수 없는 지역에서 들어온 주문이나, 요금 조건이 빠져서 의도치 않게 무료 배송이 적용되는 주문 때문에 생기는 문제를 줄여 줘요.

이 설정은 **설정 > 배송**에 있고, 기본값은 꺼져 있어요. 설정을 켜면, 시스템이 배송비를 정상적으로 계산했는데 고객의 장바구니와 배송지에 적용할 요금이 없을 때 결제가 막혀요.

![결제 시 배송 차단 설정 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155080599253/original/K_jCMMXQY4PMuWvLSw-4JGE1CFg1b7lKCA.png?1789043513)

## 주요 장점

**Block Shipping at Checkout**을 켜면 주문 처리와 배송비 계산을 더 정확하게 관리할 수 있어요.

- 처리할 수 없는 주문 방지: 고객의 배송지에 맞는 배송 요금이 설정되어 있지 않으면 결제를 막아요. 배송할 수 없는 주문을 받지 않아도 돼요.
- 의도하지 않은 무료 배송 방지: 요금 조건이 고객의 지역을 포함하지 않을 때, 무료 배송이나 잘못된 배송비로 결제되지 않아요.
- 고객 안내 개선: "Shipping not available"(배송 불가) 메시지를 보여 줘서 고객이 결제할 수 없는 이유를 알 수 있어요.
- 스토어 브랜딩 유지: **결제 페이지**와 **Upsell Element**에 표시되는 오류 메시지 색상을 스토어 분위기에 맞게 바꿀 수 있어요.
- 기존 동작 유지: 기본값이 꺼져 있어서, 직접 켜기 전까지는 지금의 결제 흐름이 그대로 유지돼요.

## 배송 검증 방식

**Block Shipping**(배송 차단)을 켜면 하이퍼클래스는 고객이 주문하는 과정의 두 지점에서 배송 가능 여부를 확인해요. 그래서 어느 단계에서든 같은 경험을 줄 수 있어요.

### 검증 시점 1: 결제 페이지

고객이 **결제 페이지**에서 배송지를 입력하면 시스템이 사용할 수 있는 배송 방법을 계산해요. 장바구니와 배송지 조합에 맞는 요금이 없으면 결제가 막히고 "Shipping not available" 메시지가 표시돼요.

### 검증 시점 2: Upsell Element

고객이 업셀 제안을 수락하면, 시스템이 바뀐 장바구니 내용으로 배송 가능 여부를 다시 확인해요. 업셀 상품을 담은 탓에 고객의 배송지로 배송할 수 없게 되면 "Shipping not available" 메시지가 표시되고 주문을 진행할 수 없어요.

{% hint style="warning" %}
배송비 계산은 성공했지만 적용할 요금이 없을 때만 결제가 막혀요. 시스템 오류로 배송비 계산 자체가 실패한 경우에는 이 설정이 결제를 막지 않아요.
{% endhint %}

## 장바구니 변경과 배송지 수정

배송 불가로 결제가 막히면, 고객은 장바구니 상황에 따라 아래 방법으로 문제를 해결할 수 있어요.

### 장바구니 동작 1: 배송할 수 없는 상품 삭제

장바구니에 상품이 여러 개이고 그중 일부만 배송지로 배송할 수 없다면, 고객은 배송할 수 없는 상품을 삭제하고 나머지 상품으로 결제를 진행할 수 있어요.

### 장바구니 동작 2: 장바구니 비우기

고객은 장바구니를 모두 비우고 처음부터 다시 시작할 수 있어요. 다른 상품을 고르거나 배송지를 바꾼 뒤 상품을 다시 담을 수 있어요.

### 장바구니 동작 3: 배송지 수정

고객이 결제 폼에서 배송지를 바꾸면 하이퍼클래스가 배송 가능 여부를 자동으로 다시 확인해요. 새 배송지가 설정된 배송 요금과 맞으면 결제 차단이 풀리고 고객이 주문을 완료할 수 있어요.

{% hint style="info" %}
디지털 상품만 담긴 장바구니는 이 설정의 영향을 받지 않아요. 디지털 상품은 배송이 필요 없기 때문이에요. 장바구니의 모든 상품이 디지털 상품이면 결제는 평소처럼 진행돼요.
{% endhint %}

## 오류 메시지 모양 바꾸기

스토어 운영자는 "Shipping not available" 오류 메시지의 색상을 스토어 브랜딩에 맞게 바꿀 수 있어요. 이 설정은 **결제 페이지**와 **Upsell Element**에 모두 적용돼서 화면 분위기가 일관돼요.

오류 메시지 색상을 바꾸려면 스토어의 테마 설정에서 오류 텍스트 색상 값을 수정하세요. 선택한 색상은 결제 과정에서 배송 오류 메시지가 나타나는 모든 곳에 적용돼요.

[스크린샷: 배송 검증 메시지의 오류 메시지 색상 선택기가 보이는 테마 사용자 지정 패널]

{% hint style="info" %}
**팁: 켜기 전에 배송 설정을 먼저 테스트하세요.** 실제 스토어에서 **Block Shipping at Checkout**을 켜기 전에, 여러 배송지로 테스트 주문을 해서 **배송 지역**과 요금 조건이 의도대로 동작하는지 확인해 보세요.
{% endhint %}

## Block Shipping at Checkout 켜기

다음 단계를 따라 **Block Shipping** 설정을 켜고, 유효한 배송 요금이 없을 때 결제를 막도록 스토어를 설정해 보세요.

1. 하이퍼클래스 계정에서 **결제 > 설정 > 배송**으로 이동해요. 스토어의 배송 설정 화면이 열려요.

   ![배송 설정 화면으로 이동](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155080599315/original/9l5LuwRTd3_qnYsIiTwl5bz6T0Ber5K_iA.png?1789043550)

2. **Block Shipping**(배송 차단) 토글을 찾아 켜세요. 고객의 배송지에 맞는 배송 방법이 없을 때 결제가 차단돼요.

3. **배송 지역**, 배송 프로필, 요금 조건을 설정해요. 어느 지역으로 배송할 수 있고 어떤 요금을 적용할지 정하는 단계예요. 배송하려는 모든 지역이 설정에 포함되어 있는지 확인하세요.

   ![배송 지역과 요금 설정 화면](https://s3.amazonaws.com/cdn.freshdesk.com/data/helpdesk/attachments/production/155080599352/original/jnl82Yu9RGROnj9jHzoS2iLmdCMxIgU92Q.png?1789043565)

4. **변경사항 저장**을 누르고 스토어를 게시하세요. 그러면 **Block Shipping** 설정이 실제 결제 페이지에 적용돼요. 게시하면 캐시가 지워져서 최신 설정이 반영돼요.

{% hint style="info" %}
팁: 실제 스토어에 설정이 바로 반영되지 않는 것 같으면 페이지나 사이트를 다시 게시해 보세요. 캐시가 새로고침되면서 최신 설정이 적용돼요.
{% endhint %}
