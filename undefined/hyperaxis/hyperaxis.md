# Hyperaxis 시작 가이드 — 연결 방법·작동 원리·사용법

### 1. 작동 원리 — 무엇을 어떻게 계산하나요?

#### 데이터 흐름

```
[결제·주문 데이터]  ─┐
[수주 딜 데이터]    ─┼─▶  Hyperaxis 계산 엔진  ─▶  대시보드
[Meta 광고 성과]   ─┤     (3시간 주기 자동 동기화)      (CAC · LTV · AOV · ROAS
[CSV 광고비 업로드] ─┘                                LTV:CAC · 회수기간 · 광고별 성과)
```

* **매출 측**: 워크스페이스의 결제 주문(또는 수주 딜)을 읽어 신규 고객·재구매·객단가를 집계합니다.
* **비용 측**: Meta 광고계정을 연동하면 일별 광고비·노출·클릭이 자동 수집되고, 그 외 채널은 CSV 업로드로 반영합니다.
* **동기화 주기**: 약 3시간마다 자동. 일 단위 집계는 **한국 시간(KST) 자정** 기준입니다.

#### 핵심 개념: "픽셀 숫자"와 "통장 숫자"

광고 플랫폼이 보고하는 성과(픽셀 기준 전환·ROAS)와 실제 결제로 확인되는 성과는 다를 수 있습니다. Hyperaxis는 두 숫자를 **나란히** 보여줍니다.

| 구분        | 원천             | 예시                            |
| --------- | -------------- | ----------------------------- |
| META (픽셀) | 광고 플랫폼 보고값     | CPA, 플랫폼 ROAS                 |
| 실제 (통장)   | 워크스페이스의 실결제 기록 | TRUE CAC, TRUE LTV, TRUE ROAS |

두 값의 **괴리가 20%를 넘으면 경고 배지**가 표시됩니다 — 픽셀상 승자처럼 보이지만 실제로는 돈을 잃는 광고("가짜 승자")를 걸러내기 위한 장치입니다.

#### 광고별 귀속은 어떻게 되나요?

광고 링크에 심어진 **광고 식별자(ad\_id)** 가 고객의 유입 정보에 기록되고, 그 고객이 나중에 결제하면 해당 광고의 성과로 귀속됩니다. 즉 "이 광고가 데려온 고객이 실제로 얼마를 결제했는가"를 광고 단위로 추적합니다. 이를 위해 아래 3장의 UTM 설정이 필요합니다.

### 2. 연결 방법 — 설치에서 데이터 점등까지

#### ① 앱 설치

1. 마켓플레이스에서 **Hyperaxis**를 설치합니다 (에이전시 계정으로 설치 후 서브계정에 배포).
2. 설치 시 요청되는 데이터 접근 권한(주문·딜·연락처·워크스페이스 정보 읽기)에 동의합니다. **모든 권한은 읽기 전용**입니다 — Hyperaxis는 워크스페이스의 어떤 데이터도 수정하지 않습니다.
3. 설치가 완료되면 좌측 메뉴에 **Hyperaxis CAC·LTV** 가 나타납니다. 첫 동기화는 최대 3시간 내에 자동 실행됩니다.

#### ② Meta 광고계정 연동 (선택 — 광고 지표에 필요)

1. Hyperaxis의 **광고 분석** 탭에서 **Meta 연결** 버튼을 클릭합니다.
2. Meta(Facebook) 로그인 창에서 광고 성과 조회 권한을 승인합니다.
3. 연동할 광고 계정을 선택하면 지출·노출·클릭 등 일별 성과가 자동 수집됩니다.

> 연동은 언제든 해제할 수 있으며, 해제 시 토큰은 즉시 폐기됩니다.

#### ③ UTM 설정 (선택 — 광고별 TRUE CAC·LTV에 필요)

Meta 광고 만들기 화면의 **URL 파라미터** 칸에 아래 한 줄을 붙여넣으세요. 광고가 몇 개든 **똑같은 한 줄**을 쓰면 됩니다 — `{{...}}` 부분은 Meta가 클릭 순간 자동으로 채웁니다.

```
utm_source=meta&utm_medium=paid&utm_campaign={{campaign.name}}&utm_content={{ad.name}}&campaign_id={{campaign.id}}&adset_id={{adset.id}}&ad_id={{ad.id}}
```

주의사항 두 가지:

* **광고 이름은 생성 후 변경하지 마세요** (귀속이 이름과 함께 파손됩니다). 변형을 만들 땐 `_v2`처럼 새 이름을 쓰세요.
* 랜딩 페이지의 **폼 제출이 같은 페이지에서** 일어나야 유입 정보가 보존됩니다.

#### ④ CSV 광고비 업로드 (선택 — Meta 외 채널)

개요 탭의 **채널 효율** 카드에서 월을 선택하고 `채널, 광고비` 형식의 CSV를 업로드하면 해당 채널 비용이 블렌디드 CAC에 반영됩니다. 예: `youtube, 1500000`

#### ⑤ 가정값 입력 (권장 — 5분)

개요 탭 우측의 **가정값** 카드에 매출총이익률(%), 구매빈도, 고객수명(개월), 기타마케팅비를 입력하고 저장하세요. LTV·회수기간·손익분기 ROAS 계산의 정밀도가 올라갑니다.

### 3. 사용법 — 화면별 안내

#### 개요 탭: 내 매장 현황

* **핵심 카드 4종**: CAC·LTV·AOV·ROAS와 전기간 대비 증감. 초록/빨강 배지로 방향을 표시합니다.
* **LTV : CAC 비율**: 이 화면의 최종 판정 숫자입니다. 3:1 이상이면 건강, 1:1 미만이면 위험으로 표시됩니다.
* **매출 vs 광고비 추이**: 30일 흐름을 한눈에.
* **신뢰도 배지**: 신규 고객 표본이 적으면(권장 12명 미만) "낮은 신뢰도"가 표시됩니다 — 표본이 쌓이면 자동으로 사라집니다.

#### 광고 분석 탭: 광고별 성과와 지표 개요

* **지표 개요**: 지출·노출·도달·링크클릭·CTR·CPC·CPM 등 플랫폼 지표와 귀속 신규고객·귀속 매출 등 실결제 지표를 델타 배지와 함께 표시. Number/Rate 토글과 7d/14d/30d 기간 선택을 지원합니다.
* **META ROAS vs TRUE ROAS 대조 카드**: 괴리 20% 초과 시 ⚠️ crosscheck 경고.
* **광고별 시세판**: 광고 하나하나의 지출·TRUE CAC·TRUE LTV:CAC(신호등 🟢🟡🔴)·플랫폼 CPA·ROAS·괴리를 표로 정렬. 표본이 부족한 광고는 "수집 중(n=...)"으로 표시되어 성급한 판단을 막습니다.
* **운영 신호**: CTR 1% 미만, 노출 빈도 4.0 초과(피로) 시 경고 배지 — 크리에이티브 교체 타이밍을 알려줍니다.
* **생애주기 배지**: 🌱 학습 단계 / ✅ 안정 / 🍂 피로 신호.

#### 데모 & 가이드 탭

실데이터가 쌓이기 전에도 전체 기능을 미리 볼 수 있는 30일 데모 데이터가 내장되어 있습니다. 경고 배지가 실제로 발동하는 시나리오까지 재현되어 있으니, 설치 직후 이 탭에서 화면 읽는 법을 익히는 것을 권합니다.

### 4. 자주 묻는 질문

**Q. 설치했는데 숫자가 안 보여요.** 첫 동기화까지 최대 3시간이 걸립니다. 그 사이에는 데모 & 가이드 탭에서 화면 구성을 미리 보실 수 있습니다. 3시간 후에도 비어 있다면 워크스페이스에 결제 주문 데이터가 있는지 확인해 주세요.

**Q. "수집 중 (n=2)"은 무슨 뜻인가요?** 해당 광고로 귀속된 신규 고객이 아직 2명뿐이라 CAC·LTV를 판정하기엔 표본이 부족하다는 뜻입니다. 틀린 숫자를 보여주느니 기다리는 쪽을 택한 설계입니다.

**Q. META ROAS와 TRUE ROAS가 왜 다른가요?** 픽셀은 조회 후 전환·중복 귀속 등으로 실제보다 후하게 계산되는 경향이 있습니다. TRUE ROAS는 워크스페이스에 실제 기록된 결제만 셉니다. 괴리 자체가 정보입니다 — 괴리가 큰 광고일수록 픽셀 숫자를 믿고 증액하면 위험합니다.

**Q. 광고별 성과가 "—"로만 나와요.** 2장의 ③ UTM 설정이 안 되어 있을 가능성이 큽니다. URL 파라미터 한 줄을 넣은 뒤 발생한 클릭부터 귀속이 시작됩니다(과거 소급 불가).

**Q. 데이터를 지우고 싶어요.** 앱을 제거하면 연동 토큰은 즉시 폐기되고 데이터는 30일 내 삭제됩니다. 즉시 삭제는 \[개인정보(데이터) 삭제 요청] 페이지를 참고하세요.
