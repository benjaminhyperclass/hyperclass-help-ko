# 하이퍼클래스 용어집

하이퍼클래스 안에서 자주 보이거나 하이퍼클래스와 관련된 용어와 약어를 알파벳 순으로 정리했어요. 다른 도움말과 함께 보면 소프트웨어를 이해하는 데 도움이 돼요.

## A

### A2P 10 DLC

(전문 용어 약어) Application-to-Person(A2P) 방식의 메시지를 표준 10자리 롱코드(10 DLC)로 보내는 것을 말해요.

### A 레코드(A Record)

A 레코드는 도메인을 그 도메인을 호스팅하는 컴퓨터의 실제 IP 주소에 연결해요. 인터넷 트래픽은 A 레코드를 이용해 도메인의 DNS 설정을 가진 컴퓨터를 찾아요. A 레코드의 값은 항상 IP 주소이고, 도메인 이름 하나에 A 레코드를 여러 개 설정할 수 있어요.

### 제휴(Affiliate)

제휴 파트너는 더 큰 조직에 공식적으로 소속된 개인이나 단체를 말해요. 에이전시 사용자는 하이퍼클래스의 제휴 파트너예요. 제휴 링크로 다른 사람을 하이퍼클래스에 추천하면, 내 제휴 파트너를 늘릴 수 있어요. 추천받은 사람이 소프트웨어를 구매하면 그 추천에 대한 수수료를 받아요. 제휴 프로그램에 대한 자세한 내용은 하이퍼클래스 고객지원 포털의 솔루션 페이지를 확인하세요.

### 에이전시 보기(Agency View)

에이전시 사용자가 플랫폼에 로그인하면 처음 보는 화면이에요. 이곳에서 에이전시는 시스템 전체 설정을 관리하고 하이퍼클래스와 소통해요. 에이전시는 이 화면에서 **마켓플레이스**, **아이디어** 게시판, **대학** 코스, 고객지원에 들어갈 수 있어요. 나머지 기능은 모두 서브 계정 수준에 있어요.

### API

(전문 용어 약어) Application Programming Interface

### API 키(API Key)

API 키는 두 플랫폼 사이에 안전한 연결을 만들 때 쓰는 값이에요. 연결할 때마다 로그인하지 않아도 돼요. Mailgun이나 SMTP 서비스를 설정할 때, 또는 하이퍼클래스에 기본으로 없는 플랫폼과 연동을 만들 때 API 키가 필요한 경우가 많아요.

### 자동화(Automations, Aut)

자동화는 특정 행동을 계기로 시작되는 일련의 이벤트예요. 도미노를 쭉 세워 두고 공을 굴려 첫 번째 도미노를 치면 차례로 넘어가는 모습을 떠올려 보세요. 자동화도 마찬가지로, 연락처가 폼을 제출하거나 예약을 잡는 등 특정 활동을 하면 일련의 메시지와 백엔드 처리가 이어서 실행되도록 설정할 수 있어요. 워크플로우, 캠페인, 트리거가 여기에 포함돼요.

## B

### B2B

(자주 쓰는 약어) Business-to-Business

### B2C

(자주 쓰는 약어) Business-to-Customer

### 일괄 작업(Bulk Actions)

일괄 작업을 쓰면 여러 연락처에 한꺼번에 작업을 적용할 수 있어 편리해요.

### BYOC

(자주 쓰는 약어) Bring Your Own Channel

## C

### 캘린더(Calendar, Cal)

캘린더 기능이 있으면 외부 예약 위젯을 따로 쓰지 않아도 돼요. 고객은 리드와 통화로 전략을 논의하거나 시연을 하거나 서비스를 제공하려는 경우가 많아요. 팀 캘린더에서는 한 명의 사용자가 여러 예약 유형(예: 스파, 살롱)을 제공하게 할 수 있어요. 또는 여러 사용자가 같은 유형의 예약(예: 영업 통화)에 돌아가며 배정되게 할 수도 있어요.

### 캘린더 > Appointments Per Day(하루 예약 수)

**Appointments Per Day**는 하루에 잡을 수 있는 예약의 총 개수예요. 예를 들어 8시간 동안 30분 단위로 예약 시간대가 있으면 하루에 16건이 돼요. 이 수가 원하는 수가 아닐 수도 있어요. 하루 예약 수를 정해 두면 하루에 그 수까지만 예약을 받아요.

### 캘린더 > Appointments Per Slot(시간대당 예약 수)

**Appointments Per Slot**은 한 시간대에 예약할 수 있는 사람 수예요. 보통은 1로 두고, 웨비나처럼 여러 명이 참여하는 이벤트가 있을 때만 늘려요.

### 캘린더 > Buffer Duration(버퍼 시간)

**Buffer Duration**은 예약마다 뒤에 버퍼 시간을 더해서, 예약이 서로 얼마나 가깝게 잡힐 수 있는지를 정해요. 예를 들어 예약 시간대가 30분이고 오전 10시에 예약이 잡혔으며 버퍼가 15분이면, 바로 다음 예약 시간은 오전 10시 45분이에요.

### 캘린더 > 날짜 범위

**날짜 범위**는 예약을 얼마나 먼 미래까지 미리 잡을 수 있는지를 정해요.

### 캘린더 > 최소 예약 안내 기간

**최소 예약 안내 기간**은 원하는 예약 시간보다 최소 얼마 전에 예약해야 하는지를 정해요.

### 캘린더 > Slot Duration(시간대 길이)

**Slot Duration**은 예약 한 건의 길이를 정해요.

### 캘린더 > Slot Interval(시간대 간격)

**Slot Interval**은 예약 가능한 시간대가 얼마나 자주 나오는지를 정해요.

### 캠페인(Campaign)

캠페인은 상품과 서비스를 홍보할 여러 온라인 경로를 설정하는 소프트웨어 영역이에요.

### 채팅 위젯(Chat Widget)

웹사이트에 놓아 두면 연락처 정보를 모으고 그 연락처와의 대화를 만들어 주는 팝업이에요. 이 기능에서는 양방향 채팅이 되지 않아서, 정교한 문의 폼이라고 생각하면 돼요. 후속 연락은 모두 전화나 이메일로 해요.

### CNAME 레코드(CNAME Record)

CNAME(Canonical Name) 레코드는 DNS(Domain Name System) 레코드의 한 종류로, 별칭을 실제 도메인 이름(정식 도메인 이름)에 연결해요. 다시 말해 검색 엔진 크롤러가 찾았으면 하는, 웹사이트 페이지의 '마스터 버전'이에요. 마케팅 캠페인을 시작하고 사용자를 추적하면, 고유한 페이지 URL 끝에 정보가 붙어요. 크롤러가 보기에는 같은 페이지의 여러 버전이 있는데 어느 것이 '맞는' 버전인지 분명하지 않은 거예요. 페이지 HTML에 정식(canonical) URL을 설정하면, 방문자에게 보여 주고 싶은 버전을 검색 엔진에 알려 줄 수 있어요.

### 회사(Company)

**회사**는 고객의 비즈니스 정보를 변경할 수 있는 곳이에요.

### 연락처(Contact, 리드라고도 해요)

플랫폼에서 추적할 수 있는 개인의 프로필이에요. 보통 이름, 연락 방법, 그 사람에 대한 추가 정보, 활동 이력, 예약한 내역이 들어 있어요. 연락처 프로필에서 대화도 할 수 있어요. (리드 항목도 참고하세요.)

### 대화(Conversations, Convo)

많은 회사가 여러 소통 채널(예: SMS, 이메일, Facebook Messenger)을 함께 쓰고 있어요. **대화** 영역에서는 리드가 어떤 플랫폼이나 연락 방법으로 보냈든 모든 메시지를 볼 수 있어요. 고객이 여러 탭과 앱을 오가며 리드와 어떤 말이 오갔는지 찾지 않아도 돼요.

### 전환 리드(Conversion Leads)

Facebook 전환 리드 연동은 Facebook 리드 광고를 리드의 양이 아니라 질에 맞춰 최적화하도록 도와줘요. 사용자가 리드 폼을 제출하면 연락처 정보가 수집되어 하이퍼클래스 CRM에 동기화돼요. 이 연락처 정보로 리드에게 후속 연락을 하고, 리드를 영업 퍼널의 다음 단계로 이끌 수 있어요. 리드가 영업 퍼널을 따라 이동하는 동안, 전환 리드 연동으로 광고주가 리드 상태를 Meta와 공유할 수 있어요. Meta는 이 정보로 리드에서 판매로의 전환이 늘어나도록 리드 광고를 최적화해요.

### CRM

(전문 용어 약어) Customer Relationship Management. CRM은 시스템에 있는 연락처 목록과, 연락처와 소통할 때 쓰는 도구를 말해요. 예약 잡기, 커뮤니케이션 보내기, 개인별 데이터 관리 기능을 제공해요.

### CSS

(전문 용어 약어) Cascading Style Sheets

### CSV

(전문 용어 약어) Comma-separated values

### Custom CSS(커스텀 코딩이라고도 해요)

CSS 코딩으로 플랫폼의 모양을 바꿀 수 있고, HTML 코딩으로 플랫폼의 기능을 바꿀 수 있어요. 하이퍼클래스는 보통 커스텀 코딩 작업을 대신 해 주거나 지원하지 않아요. 대신 이런 서비스를 제공하는 파트너가 여러 곳 있어요.

## D

### 에이전시 대시보드(Dashboard, Agency)

**에이전시 대시보드**에는 Stripe 매출이 표시돼요. 에이전시가 하이퍼클래스로 사업을 키우며 번 금액을 한눈에 보여 주는 화면이에요. 지금의 서브 계정 대시보드처럼, 이 영역에도 앞으로 기능이 더 추가될 예정이에요. 대시보드를 바꿀 수 있는 설정은 없어서, 기능을 더 넣으려면 커스텀 코딩을 써야 해요.

### 서브 계정 대시보드(Dashboard, Sub-Account)

서브 계정의 **대시보드**에는 파이프라인을 기반으로 한 그래프와 지표, 그리고 오늘의 활동을 빠르게 볼 수 있는 항목이 나와요. 모든 파이프라인의 전체 잠재 가치, 플랫폼별 연락처 분포, 소스별 기회 수를 볼 수 있어요.

{% hint style="info" %}
리드 소스 위젯은 **연락처 출처**와는 별개로 기회의 출처를 기준으로 보여 줘요.
{% endhint %}

대시보드에서 **수동 작업**과 **작업**에도 바로 들어갈 수 있어요.

### DB

(자주 쓰는 약어) Database

### DKIM

(전문 용어 약어) Domain Keys Identified Mail

### DMARC

(전문 용어 약어) Domain-based Message Authentication, Reporting, and Conformance

### DNS

(전문 용어 약어) 간단히 말해 DNS(Domain Name System)는 인터넷의 전화번호부예요. 웹사이트 도메인 이름(호스트 이름)을 숫자 값(IP 주소)으로 바꿔 주기 때문에, 웹 브라우저에서 웹사이트를 찾아 불러올 수 있어요.

### 도메인(Domains)

도메인은 누군가가 온라인에서 웹사이트나 웹사이트의 한 페이지를 찾을 때 쓰는 웹 주소의 일부예요. 웹사이트의 숫자 IP 주소와 연결된 문자열이라서, 사람이 기억하고 검색하기가 훨씬 쉬워요. 도메인은 집 주소에 자주 비유해요. 친구가 집에 놀러 올 때 집의 GPS 좌표를 외우지 않고, 휴대폰에 도로명 주소를 입력하잖아요. 웹사이트도 마찬가지예요. 방문자는 웹사이트의 IP 주소를 외우는 대신 브라우저에 도메인을 입력해요.

### Drip Mode(드립 모드)

Drip Mode는 이메일 캠페인을 전체 대상에게 한꺼번에 보내지 않고, 시간 간격을 둔 묶음으로 나눠 보내는 기능이에요. 웹사이트나 퍼널로 들어오는 트래픽을 조절하고, 서버에 걸릴 수 있는 부담을 막아 줘요.

## E

### Eliza

**Eliza 에이전트 플랫폼**은 하이퍼클래스와 파트너가 제공하는 AI 챗봇이에요. 웹사이트에 챗봇을 두면, 고객이 챗봇과 대화하면서 대부분의 질문에 답을 얻을 수 있어요. 챗봇이 어떻게 답해야 할지 모를 때는 사람 전환 기능이 작동해서, 파트너 중 한 명이 채팅을 이어받아요. 그다음 상담원이 챗봇에게 앞으로 어떻게 답할지 가르쳐 줘요. 이렇게 Eliza는 점점 더 정확한 답을 주도록 성장해요. 이 서비스는 월 비용이 있어요.

## F

### F&S

Forms and Surveys(폼과 설문)의 약어예요.

### F&W

Funnels and Websites(퍼널과 웹사이트)의 약어예요.

### Facebook 픽셀(Facebook Pixel, Meta 픽셀이라고도 해요)

Facebook 픽셀은 웹사이트에 넣는 코드 조각이에요. 이 코드가 모은 데이터로 Facebook 광고의 전환을 추적하고, 광고를 최적화하고, 다음 광고에 쓸 타깃 오디언스를 만들 수 있어요. 웹사이트에서 이미 어떤 행동을 한 사람에게는 리마케팅도 할 수 있어요. Facebook 픽셀 ID는 내 계정에 연결된 고유한 ID 번호예요.

### FB

(자주 쓰는 약어) Facebook

### 폼(Forms)

**폼**은 리드가 계정 사용자에게 정보를 전달하게 해 주는 기능이에요. 모든 필드가 한 페이지에 나열되어 보여요.

### 폼 > 커스텀 필드 > 체크박스

**체크박스**는 옵션이 여러 개 나열되고, 체크박스를 여러 개 선택해서 복수 선택할 수 있는 커스텀 필드예요.

### 폼 > 커스텀 필드 > 날짜

**날짜**는 숫자만 입력할 수 있고, 입력한 값을 날짜 형식으로 바꿔 주는 커스텀 필드예요.

### 폼 > 커스텀 필드 > 파일

**파일**은 파일을 업로드할 수 있는 커스텀 필드예요. 이 필드는 특정 파일 형식만 올리도록 제한할 수 있어요.

### 폼 > 커스텀 필드 > Large Text(긴 텍스트)

**Large Text**는 여러 줄을 입력할 수 있는 커스텀 필드예요.

### 폼 > 커스텀 필드 > 금액

**금액**은 숫자만 입력할 수 있고, 입력한 값을 금액 형식으로 바꿔 주는 커스텀 필드예요.

### 폼 > 커스텀 필드 > Multiple Options(복수 옵션)

**Multiple Options**는 드롭다운 목록에서 여러 개를 선택할 수 있는 커스텀 필드예요.

### 폼 > 커스텀 필드 > 숫자

**숫자**는 숫자만 입력할 수 있는 커스텀 필드예요.

### 폼 > 커스텀 필드 > 전화번호

### 폼 > 커스텀 필드 > 서명

### 폼 > 커스텀 필드 > 문자

**문자**는 한 줄만 입력할 수 있는 커스텀 필드예요.

### 폼 > 커스텀 필드 > Textbox List(텍스트 상자 목록)

**Textbox List**는 옵션 목록이 있고, 옵션 옆에 데이터를 입력할 수 있는 텍스트 필드가 함께 있는 커스텀 필드예요. 예를 들어 티셔츠 주문 폼에 스몰, 미디엄, 라지, 엑스트라 라지 같은 사이즈 옵션이 있다고 해 볼게요. 각 사이즈 옆의 텍스트 필드에 사이즈별 수량을 입력할 수 있어요.

### 폼 > Open URL(URL 열기)

**Open URL**은 폼을 제출할 때 다른 웹사이트를 여는 백엔드 처리예요. 이 처리에 열 URL을 지정하지 않으면 페이지가 새로고침돼요. 그러면 고객 입장에서는 제출이 되지 않은 것처럼 보여요.

### 폼 > Sticky Contact(고정 연락처)

하이퍼클래스가 폼을 제출하는 기기와, 폼이나 설문에서 마지막으로 입력한 정보를 기억하는 기능이에요.

### FTP

### 퍼널 이벤트(Funnel Events)

### 리드(Lead)

회사의 상품이나 서비스에 관심을 보인 사람이에요. '리드'는 소매나 소비재보다 B2B(business-to-business) 상품과 서비스를 판매할 때 더 자주 쓰는 용어예요. 리드는 웹사이트에서 문의 폼을 작성한 사용자, 전시회에서 직접 연락처를 남긴 참석자, 리스트 중개업체 같은 다른 회사에서 구매한 목록 등에서 생겨요. 영업·마케팅 담당자는 리드를 한 번 더 검토해서 '적격 리드'인지 가려내요. 이렇게 해서 회사의 구매자 프로필과 얼마나 잘 맞는지에 따라 우선순위를 정해요.

### 리드 이벤트(Lead Events)

하이퍼클래스 CRM은 리드가 파이프라인 단계를 어떻게 이동하는지를 이벤트로 보내요. 예를 들어 어떤 비즈니스가 '리드 생성'이라는 이름의 파이프라인을 만들었다고 해 볼게요. 리드는 신규 리드에서 예약 완료나 이탈한 리드까지 파이프라인 단계를 따라 이동해요. 리드 이벤트를 쓰면 하이퍼클래스 CRM이 Facebook Conversion API로 데이터를 보내요. 이때 CRM이 데이터 소스가 돼요.

### 하이퍼클래스 이메일

하이퍼클래스 이메일 시스템은 Mailgun 같은 타사 이메일 서비스 제공업체에 가입하는 번거로움을 줄이려고 만들었어요. 예전에는 비즈니스가 가입한 뒤 Mailgun이나 다른 이메일 서비스 제공업체와 연동해야 이메일을 보내고 받을 수 있었어요. 하이퍼클래스 이메일은 별도 설정 없이 바로 이메일을 보내고 받을 수 있어요.

### 하이퍼클래스 전화

하이퍼클래스 전화 시스템은 에이전시를 위한, 바로 쓸 수 있는 전화 서비스예요. 에이전시가 타사 SMS 서비스 제공업체에 가입하는 번거로움을 줄이려고 만들었어요. 직관적인 인터페이스와 자동 사용량 청구 기능을 제공해서, 에이전시가 플랫폼 안에서 보낸 메시지 비용을 회수할 수 있어요. 서브 계정은 하이퍼클래스 시스템으로 어떤 기기, 어떤 장소에서든 음성메일 드롭을 보내고, 통화하고, SMS를 보낼 수 있어요.

### Mailgun(MG)

### 리포팅 > Meta Ads(Facebook Ads) 리포트

**Meta Ads(Facebook Ads) 리포트**는 Facebook 플랫폼에 올라간 광고의 다양한 성과 지표를 보여 줘요.

### 리포팅 > Google Ads

**Google Ads**는 Google 플랫폼에 올라간 광고의 다양한 성과 지표를 보여 줘요.

### 평판 관리(Reputation)

### 설정 > 스태프 관리

서브 계정의 **스태프 관리** 설정에서는 그 서브 계정의 팀원을 관리해요. 이 설정에서 팀과 팀 캘린더도 관리할 수 있어요.

### 설정 > 평판 관리

**평판 관리** 설정에서는 맞춤 리뷰 메시지를 설정해요. 그러면 고객에게 일일이 수동으로 메시지를 보내지 않아도 돼요. 이 설정에서 직접 보내거나, 자동화가 보내거나, 빠른 작업으로 보낼 수 있어요. 이메일이나 문자 메시지로 보내도록 설정할 수 있어요. 또 리뷰 위젯을 사용자 지정하고, 그 코드를 웹 페이지에 삽입할 수 있어요.

### 스마트 리스트(Smart Lists)

**스마트 리스트**는 기능이 강화된 연락처 목록이에요. 필터로 여러 조건에 따라 검색하고 정렬할 수 있어요. 보고 싶은 정보 열을 고르고, 타깃 목록을 만들고, 일괄 작업을 적용할 수도 있어요. 연락처 데이터가 업데이트되면 그에 따라 연락처가 타깃 목록에 자동으로 추가되거나 제거돼요.

### SMTP

(전문 용어 약어) Simple Mail Transfer Protocol

### 스냅샷(Snapshot)

**스냅샷**은 특정 시점의 특정 서브 계정을 복사한 것이에요. 사용자가 자동화와 웹 페이지 템플릿(커스텀 값이 들어간 카피 포함)을 갖춘 독립 서브 계정을 만들어 두는 방식이에요. 이렇게 하면 템플릿을 업데이트한 뒤 새 서브 계정이나 기존 서브 계정에 복사할 수 있어요. 템플릿으로 만든 기능이 모두 함께 옮겨져요. 스냅샷은 에이전시가 서브 계정을 설정하는 시간을 크게 줄여 줘서, 고객이 빠르게 상품을 쓰기 시작할 수 있게 해 줘요.

### 스냅샷 > 가져옴

가져온 스냅샷은 복사한 URL 링크나 이메일로 다른 사람에게 받은 스냅샷이에요. 둘 다 가져올 수 있어요. 에이전시 대시보드의 **계정 스냅샷**(또는 설정의 스냅샷) 아래 **가져온 스냅샷** 하위 탭에 표시돼요.

### 스냅샷 > 내 스냅샷

에이전시가 만든 스냅샷은 **내 스냅샷** 탭에 표시돼요.

### 스냅샷 > Vertical(업종별)

하이퍼클래스는 에이전시가 고객 프로필에 쓸 수 있도록 업종별(vertical) 스냅샷을 제공해요.

하이퍼클래스에서 자주 쓰는 용어와 줄임말 중 T부터 Z까지를 정리했어요. 낯선 단어를 만났을 때 찾아보세요.

## T

### 태그(Tags)

태그는 연락처를 분류하는 방법이에요. 연락처 목록의 연락처마다 태그를 하나 이상 붙여 두면 나중에 쉽게 찾을 수 있어요. 태그는 검색, 둘러보기, 정렬, 콘텐츠 정리에 쓰여요. 태그를 기준으로 자동화나 대량 이메일, SMS 발송 등을 실행할 수도 있어요.

### 작업(Tasks)

서브 계정 수준에서 사용자에게 배정되는, 해야 할 일이에요.

### 팀(Team)

팀은 에이전시나 계정에 속한 사용자(직원)로 이루어져요.

- 에이전시 팀원은 권한에 따라 해당 에이전시의 모든 서브 계정에 들어가 고객에게 메시지를 보내거나 설정을 바꾸고 퍼널을 만드는 등의 일을 할 수 있어요.
- 계정 팀원은 계정에 속한 직원이에요. 로그인하면 바로 서브 계정 대시보드로 이동하고, 권한에 따라 서브 계정의 기능을 쓸 수 있어요.

### 템플릿(Templates)

고객에게 메시지를 보낼 때마다 같은 내용을 새로 만들 필요가 없도록, 서브 계정의 **이메일 마케팅** 탭에서 이메일 템플릿과 SMS 템플릿을 만들 수 있어요. 한 번 만들어 두고 계속 다시 쓰는 방식이에요.

일반 텍스트 이메일 템플릿과 SMS 템플릿 외에 그래픽 이메일 빌더도 있어요. 그래픽 이메일 빌더는 드래그 앤 드롭 편집기라서 텍스트, 이미지, 동영상, 버튼을 보기 좋은 레이아웃으로 배치해 메시지를 더 돋보이게 만들 수 있어요.

### 트리거 링크(Trigger Links)

연락처가 특정 행동을 하면 실행되는, 백엔드 처리 과정의 독립된 묶음이에요.

### TS

자주 쓰는 줄임말이에요. 문제 해결(Troubleshooting)을 뜻해요.

### Twilio

Twilio는 API를 통해 인터넷과 기존 통신 인프라를 이어 주는 서비스예요. 통신 과정 전체를 더 쉽게 만들어 줘요.

## U

### UI

자주 쓰는 줄임말이에요. 사용자 인터페이스(User Interface)를 뜻해요.

### 통합 메일함(Unified Mailbox)

이메일, 문자 메시지(SMS) 등 여러 소통 채널의 메시지를 한곳에서 볼 수 있게 해 주는 하이퍼클래스 기능이에요.

### URL

URL(Uniform Resource Locator)은 인터넷에 있는 웹사이트나 웹 페이지의 주소예요. 특정 웹 페이지로 연결해 주는 고유한 웹 주소죠. 인터넷의 모든 페이지에는 저마다 URL이 있어요. 지금 보고 계신 이 페이지도 마찬가지예요.

### 사용자(User)

플랫폼에 접근할 수 있는 사람이에요. 권한에 따라 고객에게 메시지를 보내고, 설정을 바꾸고, 퍼널을 만드는 등의 일을 할 수 있어요.

### UTM

기술 용어 줄임말이에요. Urchin Tracking Module의 약자예요. URL 끝에 붙이는 짧은 텍스트 코드예요. 사용자가 이 URL의 링크를 클릭했을 때 웹사이트 트래픽이 어디서 왔는지 추적하는 데 써요.

## V

### VM

자주 쓰는 줄임말이에요. 음성사서함(Voicemail)을 뜻해요.

## W

### WA

자주 쓰는 줄임말이에요. WhatsApp을 뜻해요.

### 웹 도메인(Web Domain)

웹 도메인, 또는 웹사이트 도메인은 쉽게 말해 웹사이트의 이름이에요. 예를 들어 example.com 같은 것이죠. 웹사이트에 가는 방법이 도메인뿐인 것은 아니에요. 숫자로 된 IP 주소를 외워서 접속할 수도 있어요. 도메인은 이런 숫자 대신 이름으로 특정 웹사이트를 편하게 찾아가도록 해 줘요.

### 웹훅(Webhook)

API로 만든, 서드파티 플랫폼용 독립 플로우예요. 하이퍼클래스의 자동화로 실행할 수 있어요.

### 웹사이트(Website)

탐색 메뉴가 있는 웹 페이지 모음이에요. 리드가 원하는 페이지를 원하는 순서로 볼 수 있어요.

### 화이트라벨(White Label, WL)

한 회사가 제품이나 솔루션을 만들고, 다른 회사가 이를 구매해 자기 브랜드로 바꿔서 자기 고객에게 제공하는 방식이에요.

### 워크플로우(Workflow)

연락처가 미리 정해 둔 행동을 하면 자동으로 일어나는, 외부 커뮤니케이션과 백엔드 이벤트의 묶음이에요.

### WP

자주 쓰는 줄임말이에요. WordPress를 뜻해요.

## Z

### Zapier

Zapier는 웹 앱끼리 작업을 자동화해 주는 도구예요. Zap이라고 부르는 자동 워크플로우가 한 앱의 정보를 다른 앱으로 보내 줘요.

## 단계(Stages) 

단계는 리드를 고객전환성공까지 옮기는 과정에서 거치는 각 지점이에요.

## 서브 계정(Sub-Account)

계정(Account) 또는 로케이션(Location)이라고도 불러요. 이 화면에서 CRM을 관리하고, 퍼널과 웹사이트를 만들고, 예약 위젯을 설정하는 등 여러 작업을 할 수 있어요. 에이전시가 이런 기능을 직접 쓰려면 에이전시용 서브 계정이 따로 필요해요.

## 설문 > 복수 선택 질문 > 조건부 로직(Conditional Logic)

설문으로 연락처에게 설문을 만들어 보낼 수 있어요. 설문 빌더에서는 조건부 로직 질문으로 연락처를 안내할 수 있어요. 특정 질문에 대한 답에 따라 설문이 정해진 경로로 이어진다는 뜻이에요. 이 기능은 **체크박스**, **라디오**, 단일 선택 옵션에서만 작동해요.
